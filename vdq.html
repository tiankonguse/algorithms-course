值域分治

把整个值域一分为二，左半边递归、右半边递归，再单独处理“跨过半边”的贡献 —— 借此把一类“按值域问贡献”的问题压到 O(n log n)。

一、从一个问题说起

有一个长度为 n 的数组 a，问：数组里有多少个 逆序对？所谓逆序对，就是满足 i < j 且 a[i] > a[j] 的下标对 (i, j)。

例如 a = [3, 1, 4, 1, 5, 9, 2, 6]，其中 (3,1)、(3,1)、(4,1)、(4,2)、(5,2)、(9,2)、(9,6) 等，一共 8 个。

更一般的，这类问题都可以写成“对每对 (i, j)，把 a[i] 和 a[j] 之间的关系翻译成一次贡献”：

  • 逆序对：a[i] > a[j] 时贡献 1；
  • “两数之和 ≥ X”：a[i] + a[j] ≥ X 时贡献 1；
  • “两数之积 ≤ X”：a[i] × a[j] ≤ X 时贡献 1。

共同特点：贡献只跟 a[i]、a[j] 的值有关，跟下标关系（顺序）无关。

二、先试试朴素做法

枚举所有下标对，判断是否构成逆序对：

long long naive(int a[], int n) {
    long long ans = 0;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            if (a[i] > a[j]) ans++;
    return ans;
}

这是 O(n²)。当 n = 10⁵ 时就是 10¹⁰，太慢。

矛盾在哪？ 每一对都要单独算一遍。能不能让“左边的数”和“右边的数”各管各的，最后再合到一起？

三、归并排序的副产物

在归并排序里，我们已经把数组对半分：

void mergeSort(int l, int r) {
    if (l >= r) return;
    int mid = (l + r) / 2;
    mergeSort(l, mid);          // 左半边排好序
    mergeSort(mid + 1, r);    // 右半边排好序
    merge(l, mid, r);          // 把两段有序数组合并
}

合并时，左右两边都已经排好序。当我们从右半边里拿出 a[j]，塞回大数组时，左半边里所有还没被拿出、且 a[i] > a[j] 的 a[i]，都和它构成一个逆序对。

由于左半边有序，只要知道“右半边当前元素 a[j] 在左半边应插入的位置”，就能在 O(1) 时间数出这次合并新增多少逆序对。

于是就有了这样一个改动 —— 只在 merge 时多维护两个指针：

long long ans = 0;
void merge(int l, int mid, int r) {
    int i = l, j = mid + 1, k = l;
    while (i <= mid && j <= r) {
        if (a[i] <= a[j]) { tmp[k++] = a[i++]; }
        else {
            tmp[k++] = a[j++];
            ans += mid - i + 1;          // 左半边从 i 到 mid 都比 a[j] 大
        }
    }
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= r)   tmp[k++] = a[j++];
    for (int p = l; p <= r; p++) a[p] = tmp[p];
}

合并这一步仍然是 O(右 - 左 + 1)，但顺手把“左半边和右半边之间”的逆序对数了出来。整棵树高度 O(log n)，每层加起来仍是 O(n)。

四、为什么叫“值域”分治？

上面这个套路其实是“按值域一分为二”。每一次递归，数组虽然按“下标”切成了两半，但合并时利用的是两半各自已经有序——也就是“按值排好了”。

所以更抽象的写法是：

  • divide：把“值域”或“数组”对半切；
  • conquer：左右两边分别递归；
  • merge：处理“跨过半边”的那部分贡献。

只要“跨过半边”的部分能在 O(区间长度) 内算出来（比如借助有序、双指针、树状数组），整体就是 O(n log n)。

对比三种分治：分块按“下标位置”切、莫队按“查询顺序”排，而值域分治是按“值的大小”切。切的对象不同，但“分-合”的骨架是相通的。

六、复杂度分析

  • 递归分层：每次对半切，共 ⌈log₂ n⌉ 层。
  • 每层开销：每个区间 [l, r] 的合并是 O(r-l+1)，同一层所有区间加起来正好是 O(n)。
  • 总时间：O(n log n)。
  • 额外空间：需要一个临时数组 tmp 配合 merge，大小 n，即 O(n)。
操作时间复杂度
朴素（双重循环）O(n²)
归并排序O(n log n)
单层 mergeO(n)
总时间O(n log n)
额外空间O(n)

当 n = 10⁵ 时，朴素 10¹⁰，归并版只有约 1.7 × 10⁶，快了近 4 个数量级。

七、完整代码

#include 
using namespace std;

const int N = 100005;
int a[N], tmp[N];
long long ans = 0;

void mergeSort(int l, int r) {
    if (l >= r) return;
    int mid = (l + r) / 2;
    mergeSort(l, mid);
    mergeSort(mid + 1, r);

    // 合并，并在合并中数逆序对
    int i = l, j = mid + 1, k = l;
    while (i <= mid && j <= r) {
        if (a[i] <= a[j]) {
            tmp[k++] = a[i++];
        } else {
            tmp[k++] = a[j++];
            ans += mid - i + 1;       // 左半边 [i, mid] 都比 a[j] 大
        }
    }
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= r)   tmp[k++] = a[j++];
    for (int p = l; p <= r; p++) a[p] = tmp[p];
}

int main() {
    int n;
    cin >> n;
    for (int i = 0; i < n; i++) cin >> a[i];
    ans = 0;
    mergeSort(0, n - 1);
    cout << ans << endl;
    return 0;
}
把“求和”换成其他问题： 上面的 ans += mid - i + 1 是“数一数左半边还有几个 a[i] > a[j]”。如果题目问的是“a[i] + a[j] ≥ X 的对数”，可以先把数组排序，再用双指针；如果问“a[i] × a[j] ≤ X 的对数”，可以按值排序再用 two pointers。骨架都是「分-合」。

八、小结

  • 值域分治的本质是：按值切一半，递归下去，把跨半边贡献在合并时统一算。
  • 它最常见的载体是归并排序：合并左右两段有序子数组时，“右段当前元素落到左段哪里”就是这次合并的“跨半边贡献”。
  • 时间 O(n log n)，空间 O(n)，比朴素 O(n²) 快几个数量级。
  • 换一种“贡献规则”（如求和、乘积、距离），只要把合并那一行换成对应的计数方式即可。
