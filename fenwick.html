树状数组

用二进制的 lowbit 把前缀和拆成 O(log n) 段，让“区间查询”和“单点修改”都能快速完成。

一、从同一个问题说起

还记得分块那一节的问题吗：有一个长度为 n 的数组 a，需要反复进行两种操作——

  • 查询：求区间 [l, r] 的和；
  • 修改：把某个 a[i] 改成新数。

分块用“整块打包、零散逐个”做到了查询 O(√n)、修改 O(1)。这一节换一个更精巧的工具——树状数组（又叫二叉索引树 / Fenwick Tree），它能让查询和修改都做到 O(log n)，而且代码非常短。

二、先想到前缀和，但它的修改太慢

既然要“区间和”，最自然的想法是前缀和：prefix[i] = a[1] + a[2] + … + a[i]。那么区间和只要一次减法：

区间和 [l, r] = prefix[r] - prefix[l-1]

查询瞬间变成 O(1)，但修改却变慢了：一旦 a[i] 变了，prefix[i]、prefix[i+1]、…、prefix[n] 全都要跟着改，最坏要改 n 个，是 O(n)。

矛盾在哪？ 朴素做法是“查询慢、修改快”，前缀和是“查询快、修改慢”。树状数组想两头都占：不让每个位置从头到尾都存一遍，而是让每个位置只“管一段”，且管得很有规律，于是查询、修改都只扫 O(log n) 段。

三、lowbit：二进制最低位的 1

树状数组的“规律”藏在二进制里。先认识一个小工具 lowbit：

lowbit(x) = x 的二进制里最低位的那个 1 所代表的数

  • x = 6 = 110₂，最低位的 1 在右起第 2 位，代表 2，所以 lowbit(6) = 2；
  • x = 12 = 1100₂，所以 lowbit(12) = 4；
  • x = 8 = 1000₂，所以 lowbit(8) = 8；
  • 奇数末位一定是 1，所以 lowbit(奇数) = 1。

代码上一行就搞定：

int lowbit(int x) { return x & (-x); }
这里的 -x 是计算机里的补码，它有个奇妙的性质：x & (-x) 恰好只把最低位的 1 留下、其余位全变成 0。初中阶段可以先把这个公式当成“取最低位 1”的黑盒直接使用。

四、c[i] 管一段：树状数组的结构

有了 lowbit，树状数组规定：c[i] 存的是从 a[i-lowbit(i)+1] 到 a[i] 这一段的和，长度正好是 lowbit(i)。

例如 lowbit(6)=2，所以 c[6] = a[5] + a[6]；lowbit(8)=8，所以 c[8] = a[1] + … + a[8]。拖动滑块，看看每个 c[i] 到底“管”着哪一段：

这样一安排，每个 c[i] 恰好“向上”贡献给 c[i + lowbit(i)]，整张结构像一棵倒挂的二叉树，所以叫“树状数组”。

五、怎么查前缀和：一路向下减 lowbit

想求 prefix[i] = a[1] + … + a[i]，从 i 开始：累加 c[i]，然后 i -= lowbit(i)，直到 i 变成 0。

为什么对？因为 c[i] 管的正是“以 i 结尾、长度 lowbit(i)”的那一段；累加它之后，还没算的区间就只剩 [1, i-lowbit(i)]，规模一下子缩小了。由于每步至少去掉一个二进制 1，最多跳 O(log n) 次就到 0。拖动滑块观察这一“向下跳”的过程：

演示 ③　前缀和 prefix(i)：向下减 lowbit
13
要算的前缀 a[1..i] 累加到的 c 节点

有了前缀和，区间和就是一次减法：rangeSum(l, r) = query(r) - query(l-1)。

六、怎么单点修改：一路向上加 lowbit

要把 a[i] 加上 delta，哪些 c 会受影响？答案是：凡是“管到了 i”的 c 节点。规律和查询正好相反——从 i 开始，每次 i += lowbit(i)，直到超过 n。这条链上的 c 全部加上 delta。拖动滑块观察这条“向上跳”的链：

七、复杂度分析

  • 前缀和查询：每步 i -= lowbit(i)，i 的二进制里 1 的个数最多 log n 个，所以最多跳 log n 次，是 O(log n)。
  • 单点修改：每步 i += lowbit(i)，i 至少翻倍，所以最多跳 log n 次，也是 O(log n)。
  • 区间查询：两次前缀和相减，O(log n)。
操作时间复杂度
预处理 buildO(n log n)
前缀和 queryO(log n)
区间和（两次前缀和）O(log n)
单点修改 updateO(log n)

空间方面，只需要一个 c 数组（大小 n+1），即额外空间 O(n)。

对比一下三种做法：朴素查询 O(n)，分块 O(√n)，树状数组 O(log n)。当 n 很大时，log n 比 √n 还要小得多。

八、完整代码

#include <bits/stdc++.h>
using namespace std;

const int N = 16;
int a[N + 1] = {0, 3,1,4,1,5,9,2,6,5,3,5,8,9,7,9,3};
int n = N;
int c[N + 1];                      // 树状数组

int lowbit(int x) {                // 最低位的 1
    return x & (-x);
}

void update(int i, int delta) {   // 单点修改：a[i] += delta
    while (i <= n) {
        c[i] += delta;
        i += lowbit(i);
    }
}

int query(int i) {                 // 前缀和：a[1]+…+a[i]
    int s = 0;
    while (i > 0) {
        s += c[i];
        i -= lowbit(i);
    }
    return s;
}

int rangeSum(int l, int r) {     // 区间和 [l, r]
    return query(r) - query(l - 1);
}

void build() {                      // 预处理
    for (int i = 1; i <= n; i++) update(i, a[i]);
}

int main() {
    build();
    cout << rangeSum(1, 8) << endl;  // 31
    update(5, -2);                  // a[5]：5 → 3
    cout << rangeSum(1, 8) << endl;  // 29
    return 0;
}

九、小结

  • 树状数组用 lowbit 把前缀和“拆成 O(log n) 段”：查询一路向下减 lowbit，修改一路向上加 lowbit。
  • 单点修改、区间查询都能做到 O(log n)，比朴素、比分块都更快。
  • 它只擅长“单点修改”；如果要“整段区间一起加”，就要进阶到差分 + 树状数组，或者线段树。
