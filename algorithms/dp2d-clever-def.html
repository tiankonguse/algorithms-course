二维动态规划的巧定义：有效涂色与删字符变子串

两道题照着题面直接定状态都做不出来。第一题要自己把「用了几种颜色」塞进状态；第二题的目标是个子串，起点不定、还要求连续，得把定义里的「子串」换成「某个前缀的后缀」才推得动。这两处转换就是这两题的全部内容。

零、先把题面摆出来

有效涂色：n 个格子排成一排，每个格子从 m 种颜色里挑一种涂。涂满 n 个格子并且 m 种颜色都用上了，才算一种有效方法，问有多少种。1 ≤ n, m ≤ 5000，答案对 1000000007 取模。

删字符变子串：给两个串 s1 和 s2，s1 至少删掉几个字符，能变成 s2 的子串。

一、有效涂色：把「用过几种颜色」放进状态

n = 3、m = 2 时答案是 6。三个格子每个两种颜色，一共 2³ = 8 种涂法，扣掉全涂第一种和全涂第二种这两种没用全的，剩 6 种。

照题面直接数是不行的：8 这个数在 n = 5000 时是 2⁵⁰⁰⁰，连存都存不下。得换个办法数。

定义 dp[i][j]：一共 m 种颜色可选，前 i 个格子涂满 j 种颜色的方法数。注意 j 是「用过几种」，不是「第几种颜色」。题面里「m 种都用上」这个约束，被塞进状态里变成了 j 必须等于 m。

看最后一个格子怎么涂，只有两种情况：

  • 涂已经出现过的颜色：前 i−1 个已经用了 j 种，这种涂法有 j 种选择，贡献 dp[i−1][j] × j；
  • 涂一种还没出现过的颜色：前 i−1 个只用了 j−1 种，新颜色从剩下 m − (j−1) = m−j+1 种里挑，贡献 dp[i−1][j−1] × (m−j+1)。

边界只有一句：dp[i][1] = m，不管几个格子，只用一种颜色的话就是「选哪一种」，m 种。i = 1 时 j ≥ 2 全是 0，一个格子涂不出两种颜色。所以 j > i 的格子永远是 0，m > n 时答案直接是 0。

// dp[i][j] : 一共 m 种颜色可选，前 i 个格子涂满 j 种颜色的方法数
    int ways(int n, int m) {
        const int MOD = 1000000007;
        static int dp[5001][5001];
        for (int i = 1; i <= n; i++) {
            dp[i][1] = m;                            // 只用一种颜色：选哪种有 m 种
        }
        for (int i = 2; i <= n; i++) {
            for (int j = 2; j <= m; j++) {
                dp[i][j] = (int)((long long)dp[i - 1][j] * j % MOD);       // 第 i 格涂已用过的颜色
                dp[i][j] = (int)(((long long)dp[i - 1][j - 1] * (m - j + 1) + dp[i][j]) % MOD); // 或者涂一种新颜色
            }
        }
        return dp[n][m];
    }

表里第 5 行第 3 列是 150，正好是 3! × 25，而 25 是把 5 个格子分成 3 个非空组的分法数。这背后是个组合恒等式：答案就是 m! × S(n, m)，S 是第二类斯特林数。n = m = 7 时答案是 5040 = 7!，因为七个格子用七种颜色只能是一一对应。

这题还有一条更快的路：容斥。答案 = Σk=0..m (−1)k · C(m, k) · (m−k)n，n = 5、m = 3 时是 243 − 3 × 32 + 3 × 1 = 150。它只要 O(m log n)，比这张 O(n·m) 的表快得多，代价是取模下要处理减法（减之前先加一个 MOD）。这里讲动态规划的版本，是因为「把约束塞进状态」这个手法在别的地方更常用，尤其在容斥写不出来的题上。

二、涂色问题的空间压缩

两个来源都是上一行，j 倒着走就能压成一维：dp[j] 是上一行的 dp[i−1][j]，dp[j−1] 因为还没被这一行碰过，还是 dp[i−1][j−1]。循环上界取 min(i, m)，j > i 的那些格子本来就永远是 0。

// 空间压缩：j 倒着走，dp[j-1] 才还是上一行的
    int waysRoll(int n, int m) {
        const int MOD = 1000000007;
        vector<int> dp(m + 2, 0);
        for (int i = 1; i <= n; i++) {
            for (int j = min(i, m); j >= 1; j--) {
                if (j == 1) {
                    dp[j] = m;
                } else {
                    dp[j] = (int)(((long long)dp[j] * j + (long long)dp[j - 1] * (m - j + 1)) % MOD);
                }
            }
        }
        return dp[m];
    }

实测 n = 5000、m = 4877：二维版用静态数组 int dp[5001][5001]，95 MB，33.38 ms，答案 949690752；一维版 20 KB，19.37 ms。二维版在这个数据范围下内存吃紧，一维版顺手就省掉了。

新颜色那个系数写成 (m − j) 是最容易犯的错，实测 8000 组随机里错 3370 组（42.13%）。记住它的含义：前 i−1 个用了 j−1 种，没用过的还剩 m−(j−1) 种。

三、删字符变子串：为什么定义里得是「后缀」

s1 = "abcde"、s2 = "ace" 时答案是 2，删掉 b 和 d。s1 = "abc"、s2 = "xabcx" 时答案是 0，"abc" 本来就是 s2 的子串，一个都不用删。

麻烦在「子串」这两个字上。子串要求连续，还要求起点，可起点是浮动的。要是定义成 dp[i][j] = s1 前 i 个变 s2 前 j 个的「某个子串」，转移没法写：s1[i−1] 配上 s2[j−1] 之后，前面那段到底是接着配还是重新起头，状态里没记。

换个说法就能推了：

dp[i][j]：s1 前 i 个至少删几个字符，能变成 s2 前 j 个的某个后缀串。

「后缀」两个字是关键：它强制最后一个字符必须落在 s2[j−1] 上，起点在哪不用管。这么一改，转移只剩两行：

  • s1[i−1] == s2[j−1]，配上它，dp[i][j] = dp[i−1][j−1]；
  • 不等，s1[i−1] 一定留不住（留着它就不是以 s2[j−1] 结尾的后缀了），dp[i][j] = dp[i−1][j] + 1。

第 0 列是 i：s2 前 0 个是空串，只能全删光。

答案怎么取？看最后一行，min(dp[n][0], dp[n][1], …, dp[n][m])。理由有两条，缺一不可：s2 前 j 个的后缀一定是 s2 的子串；反过来，s2 的任意一个子串，一定是以某个位置结尾的，也就是 s2 某个前缀的后缀。两个方向一对，最后一行取最小值就等价于在整个 s2 里找子串。

// dp[i][j] : s1 前 i 个至少删几个，能变成 s2 前 j 个的某个后缀串
    int minDelete(string s1, string s2) {
        int n = s1.size(), m = s2.size();
        vector<vector<int>> dp(n + 1, vector<int>(m + 1, 0));
        for (int i = 1; i <= n; i++) {
            dp[i][0] = i;                            // s2 是空的，全删
            for (int j = 1; j <= m; j++) {
                if (s1[i - 1] == s2[j - 1]) {
                    dp[i][j] = dp[i - 1][j - 1];     // 配上，不用删
                } else {
                    dp[i][j] = dp[i - 1][j] + 1;     // s1 这个字符留不住，删掉
                }
            }
        }
        int ans = n;
        for (int j = 0; j <= m; j++) {
            ans = min(ans, dp[n][j]);                // 落在 s2 的哪个位置都行
        }
        return ans;
    }

四、不换定义要付多少代价

不玩这个技巧也能做：枚举子串的起点 p（m 种），每个起点做一遍「s1 与 s2[p..] 的最长匹配」，那一遍是 O(n · m)，总共 O(n · m²)。n = m = 200 实测 6.41 ms，而上面那张表是 0.051 ms，差 125 倍；两个量级差着一层 m，n = m = 3000 时朴素做法是 2.7 × 10¹⁰ 次操作，跑不动。

两个定义上的坑。一是字符不等时写 dp[i−1][j−1] + 1（顺手取了左上角），实测 8000 组里错 3592 组（44.90%）；二是答案只取 dp[n][m]，那等于要求匹配到 s2 的末尾，实测错 3483 组（43.54%）。

五、复杂度分析

题目时间复杂度空间复杂度压缩后
有效涂色O(n · m)O(n · m)O(m)
删字符变子串O(n · m)O(n · m)O(m)

n 是格子数（或 s1 长度），m 是颜色数（或 s2 长度）。两题都是 (n+1) × (m+1) 的表，每格常数次算术，时间 O(n · m)。

空间上二维表 O(n · m)：涂色题 n = m = 5000 时是 5001 × 5001 个 int，95 MB，一张表就快把内存吃完了；压成一维后 20 KB。删字符那题只依赖上一行和左上角，同样能压成 O(m)，只是压缩后「最后一行取最小」变成了「这个一维数组里取最小」，写法反而更简单。

六、总结

两道题的共同点是：题面里的约束（m 种颜色都用上、结果得是子串）进不了转移式，只能塞进状态的定义。涂色题塞的是「用了几种颜色」，于是答案变成 dp[n][m]；删字符题塞的是「哪个前缀的后缀」，于是答案变成最后一行取最小。

判断一个定义好不好用，试一句转移就知道了：如果写到一半发现「前面那段的状态没记」，说明少放了一个约束。涂色题的容斥解也顺手提一句：同一个问题常有组合解法和动态规划解法，谁快用谁，但动态规划那一套在约束更复杂时还能继续加维度。
