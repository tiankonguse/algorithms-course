拓扑序上的 DP：并行课程的最少完成月份

n 门课有先修关系，每门课要花 time[i] 个月，任意门课可以同时上，求完成全部课程的最少月份。答案不是「把所有课的时间加起来」，而是先修链上最长的那条，因为所有课并行，瓶颈决定工期。

零、最少月份为什么是「最长链」

一门课必须等它的所有先修课都完成才能开始。所以课 u 能完成的最早时间是：max(先修课完成时间) + 自己的时长。所有课可以并行，总工期就是所有课里完成时间最大的那个。

这个递推式在 DAG 上成立，但先修关系是任意的，不是树。处理顺序有讲究：必须先算完 u 的所有先修，才能算 u。拓扑排序天然给这个顺序，这就是拓扑序上的 DP。

一、样例 1 的完整计算

n=3，先修关系 1→3、2→3，time=[3,2,5]。1 和 2 没有先修，可以同时开工：1 花 3 个月、2 花 2 个月。3 要等两个都完成，最早在第 3 个月末尾开始，再花 5 个月，第 8 个月完成。答案是 8。

把递推写成代码：cost[cur] 先加上自己的 time[cur-1]，更新答案；然后对每个下游 next，cost[next] = max(cost[next], cost[cur])。cost 数组记的是「cur 的最早完成时间」，推给下游时取 max，因为下游要等所有先修。

二、先修取 max，不是累加

样例 2 更能说明问题：n=5，先修 1→5、2→5、3→5、3→4、4→5，time=[1,2,3,4,5]。3 的完成时间是 3（先修无），4 等 3 完成后 3+4=7，5 要等 1、2、3、4 全部完成，最晚的是 4 的 7，所以 5 的完成时间是 7+5=12。

注意 5 的先修里 1、2、3 的完成时间分别是 1、2、3，都比 4 的 7 小，它们不影响 5。这正是取 max 的意义：一门课的工期只被它最慢的先修决定，其余先修快慢无所谓。

复杂度 O(n+m)。代码里 cost 和 ans 都用 int，题目数据范围保证不溢出；如果要卡大值域，换成 long long 也一样写。

#include <bits/stdc++.h>
    using namespace std;

    namespace ParallelCourses {
    // 完成时间 = 自己的时长 + 先修课里的最大完成时间
    int minimumTime(int n, const vector<vector<int>>& relations, const vector<int>& time) {
      vector<vector<int>> graph(n + 1);
      vector<int> indeg(n + 1, 0);
      for (auto& e : relations) {
        graph[e[0]].push_back(e[1]);
        indeg[e[1]]++;
      }
      vector<int> que(n);
      int l = 0, r = 0;
      for (int i = 1; i <= n; i++) {
        if (indeg[i] == 0) que[r++] = i;
      }
      vector<int> cost(n + 1, 0);
      int ans = 0;
      while (l < r) {
        int cur = que[l++];
        cost[cur] += time[cur - 1];
        ans = max(ans, cost[cur]);
        for (int next : graph[cur]) {
          cost[next] = max(cost[next], cost[cur]);
          if (--indeg[next] == 0) que[r++] = next;
        }
      }
      return ans;
    }
    } // namespace ParallelCourses

总结

拓扑序 DP 的模板：入度 0 的点入队，出队时先结算自己（加上自己贡献、更新答案），再把结果按 max 或加法推给下游。结算发生在出队，是因为出队保证所有先修都已结算。

和上一页的「推送消息」是同一件事：那里是路径计数和最值覆盖，这里是完成时间取 max。共同点都是「u 出队时信息已定稿」。
