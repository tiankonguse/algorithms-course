分组背包：每组只挑一件

01 背包里每件货物至多拿一次，完全背包里每件拿任意次，分组背包夹在中间：货物先分好组，同一组里最多挑一件，不同组互不干涉。转移比 01 背包只多一层组内枚举，代价还是货物数乘容量。压缩版把 j 的方向写反，答案会凭空变大，那是同一组里的东西被挑了不止一次。

零、问题

背包容量 m，n 件货物，每件有自己的体积、价值和一个组号。同一组的货物最多挑一件，不同组之间没有限制，问不超过容量时能拿到的最大价值。

如果不管分组，这就是 01 背包。分组这一条限制把它卡在 01 背包和完全背包之间：组内的货互斥，组与组独立。

枚举所有合法挑法要多少种？假设有 g 组，第 i 组有 si 件，那么总数是 ∏(si + 1)，光是「每组两件」就已经是 3g。换一种问法：只看前 i 组，容量不超过 j，最大价值是多少。记成 dp[i][j]。

一、把「一组」当成一次决策

填 dp[i][j] 时，第 i 组只有 si + 1 种下场：一件都不挑，或者挑组里的第 1 件、第 2 件……第 si 件。每件都试一遍，取最大的那个。

dp[i][j] = max( dp[i-1][j], max over 组内每件 k 的 dp[i-1][j - vol[k]] + val[k] )

括号里第一项是「不挑这一组」，后面的一项是「挑了这一组里的某一件」。和 01 背包比，唯一的变化是第二项从一个候选变成了组内件数那么多候选。

这里有个容易忽略的点：枚举量会升阶吗？不会。所有组内件数加起来正好是 n，所以「每组枚举一遍组内」这件事，总的枚举次数还是 n，复杂度仍是 O(n · m)。分组本身不增加计算量，它只改变了哪些组合是合法的。

// 货物按组号排好序后，同一组落在连续一段 [start, end) 上
    // dp[i][j]：只看前 i 组，每组至多挑一件，容量不超过 j 时的最大价值
    int groupKnapsack2d(int m, vector<array<int,3>>& a, int n) {
        int teams = 1;
        for (int i = 2; i <= n; i++)
            if (a[i-1][2] != a[i][2]) teams++;      // 组号一变就多一组
        vector<vector<int>> dp(teams + 1, vector<int>(m + 1, 0));
        for (int start = 1, end = 2, g = 1; start <= n; g++) {
            while (end <= n && a[end][2] == a[start][2]) end++;
            for (int j = 0; j <= m; j++) {
                dp[g][j] = dp[g-1][j];              // 第 g 组一件都不挑
                for (int k = start; k < end; k++)   // 组内每件都试一遍
                    if (j - a[k][0] >= 0)
                        dp[g][j] = max(dp[g][j], dp[g-1][j - a[k][0]] + a[k][1]);
            }
            start = end;
            end++;
        }
        return dp[teams][m];
    }

代码里 a[i] = {体积, 价值, 组号}，下标从 1 开始。[start, end) 是当前组的连续区间，g 是组的序号。第一层循环每次处理一整组，处理完把 start 挪到 end，也就是下一组的开头。

二、先按组号排序，让同一组连成一段

上面那段代码依赖一个前提：同一个组号的所有货物在数组里是连续的。输入的货物顺序是任意的，所以得先按组号排一遍序。

排序的代价是 O(n log n)，和 O(n · m) 的填表比可以忽略。n = 2000、m = 1000 时，排序大约两万次比较，填表是两百万格。

不排序行不行？不行。代码用「相邻两件组号是否相同」来找组，组号散着放的话，同一个组会被切成好几段，每段被当成独立的一组，等于允许同一组里挑多件。实测两万组随机样本，忘了排序的版本有 84.59% 的答案和正解不同（值域小时），和「直接当 01 背包做」的错误率一样高。

三、空间压缩：j 照样从大到小

二维表里第 i 组那一行只依赖第 i − 1 组，所以可以压成一维。dp[j] 在刷之前表示「前 i − 1 组、容量 j 的最大价值」，刷完之后表示「前 i 组、容量 j 的最大价值」。

j 必须从大到小走。原因和 01 背包一模一样：dp[j - vol[k]] 要读的是还没考虑本组的旧值，j 从大到小保证 j - vol[k] 本轮的还没被碰过。从小到大走，j - vol[k] 已经是本轮写过的，于是同一组里的同一件被挑了第二次。

// 压缩成一维：dp[j] 的右端从「前 i 组」变成「前 i 组 + 当前这一组挑了一件」
    int groupKnapsack1d(int m, vector<array<int,3>>& a, int n) {
        vector<int> dp(m + 1, 0);
        for (int start = 1, end = 2; start <= n; ) {
            while (end <= n && a[end][2] == a[start][2]) end++;
            for (int j = m; j >= 0; j--)            // 每个组只刷一轮，j 照样从大到小
                for (int k = start; k < end; k++)
                    if (j - a[k][0] >= 0)
                        dp[j] = max(dp[j], dp[j - a[k][0]] + a[k][1]);
            start = end;
            end++;
        }
        return dp[m];
    }

内层两层循环的顺序可以对调（先枚举组内每件、再枚举 j），只要 j 是倒着走就行。压完只剩 m + 1 个 int。

这题的错误率对值域很敏感。用两万组随机样本测（容量不超过 60，货物不超过 12 件，组数不超过 4），几种错法各自和正解比：

值域小的时候几种错法都大面积现形，值域一大就都缩回去了。原因是随机数据里「挑同一组两件」很容易被容量卡住，值域越大，卡住的概率越高，错版和正解自然就撞到同一个答案上。所以别拿大随机数据当测例，对数器的样本值域要开小。

还有一种错法是忘了按组排序。忘了排序，每件货自成一组，组内又只挑一件，算出来的答案和「当 01 背包」一模一样，五档值域的出错率逐位相同，图上就没重复画一条。

顺带一提，四种错法里「正序 j」在 V = 5 时有 96.34% 现形，比「直接当 01 背包」还高。因为 01 背包至少还保住了「每件只挑一次」，只是允许多挑几个组；正序 j 连同一件都能重复挑，错得更远。

五、从若干个栈的顶部取硬币

有一张桌子，上面摆了若干个硬币栈，每个栈从顶到底是一列面值。每次操作从任意一个栈的顶部取走一枚硬币，问恰好做 m 次操作能取到的最大面值和。

关键在于一个栈里拿走 k 枚，拿的必然是从顶部数的前 k 枚。栈只能从顶上拿，你没法跳过顶上去拿下面的。所以每个栈的决策只有「一共拿走几枚」这一个自由度，这就是分组背包：每个栈是一组，组里「挑一件」换成了「挑一个前缀」。

把「前 k 枚的和」预处理成前缀和数组 pre[k]，枚举 k 的时候就是一次数组访问。不预处理的话，每次枚举 k 都要把前 k 枚重新加一遍，组内枚举的代价从 O(t) 变成 O(t²)。

实测：1000 个栈、每栈 200 枚、m = 1000 时，前缀和版 57.893 毫秒，每次重算版 887.947 毫秒，差 15.3 倍。栈和 m 都再小一个数量级时差 15.9 倍，倍数基本由组内平均长度决定。

// piles 里每一组是从顶到底的硬币面值，必须恰好取 m 枚
    // dp[i][j]：只看前 i 组，一共取走 j 枚时的最大面值和
    int maxValueOfCoins2d(vector<vector<int>>& piles, int m) {
        int n = piles.size();
        vector<vector<int>> dp(n + 1, vector<int>(m + 1, 0));
        for (int i = 1; i <= n; i++) {
            vector<int>& team = piles[i-1];
            int t = min((int)team.size(), m);
            vector<int> pre(t + 1, 0);              // pre[k] = 从顶部数前 k 枚的和
            for (int k = 0, sum = 0; k < t; k++) {
                sum += team[k];
                pre[k+1] = sum;
            }
            for (int j = 0; j <= m; j++) {
                dp[i][j] = dp[i-1][j];              // 这一组一枚都不拿
                for (int k = 1; k <= min(t, j); k++)
                    dp[i][j] = max(dp[i][j], dp[i-1][j-k] + pre[k]);
            }
        }
        return dp[n][m];
    }
int maxValueOfCoins1d(vector<vector<int>>& piles, int m) {
        vector<int> dp(m + 1, 0);
        for (vector<int>& team : piles) {
            int t = min((int)team.size(), m);
            vector<int> pre(t + 1, 0);
            for (int k = 0, sum = 0; k < t; k++) {
                sum += team[k];
                pre[k+1] = sum;
            }
            for (int j = m; j > 0; j--)
                for (int k = 1; k <= min(t, j); k++)
                    dp[j] = max(dp[j], dp[j-k] + pre[k]);
        }
        return dp[m];
    }

压缩版的 j 还是倒着走，注意上界写 j >= 1，j = 0 一格永远不可能拿东西，留着不用动。题面保证 m 不超过所有栈的硬币总数，所以答案一定能取到。

六、复杂度分析

做法时间额外空间说明
枚举所有挑法∏(si + 1)O(1)组数一多就炸，只能当对拍参考
分组背包二维表O(n · m)O(组数 · m)n = 2000、m = 1000 实测 0.986 毫秒、0.77 MB
分组背包压缩O(n · m)O(m)同上 1.345 毫秒；两者时间相当，二维略快是访存更集中
取硬币 + 前缀和O(硬币总数 · m)O(m)1000 栈 × 200 枚、m = 1000 实测 57.893 毫秒
取硬币 + 每次重算O(Σ ti2 · m)O(m)同一组数据 887.947 毫秒，慢 15.3 倍

时间那一栏，二维和压缩都是 n · m 量级。二维版本更快是因为它每次写的是 dp[g][j] 这个位置本身，读的是上一行的 dp[g-1]，一整行的访存是连续的；压缩版每次都要读改同一个数组，没省时间。压缩的意义在空间：组数乘容量可能开不出来，m 只有一维时一定开得出。

取硬币那题，注意枚举总量是「所有栈里的硬币总数」，不是「栈数乘容量」。因为一个栈最多拿 m 枚，超过 m 的部分枚举不到。

七、总结

分组背包的骨架：在 01 背包外面套一层组，dp[i][j] 从「不挑本组」和「挑组内某一件」里取最大。

几个要点：

1）先按组号排序，让同一组落在连续区间上。忘了排序会被当成「组被打散」，实测 84.59% 的样本现形。

2）压缩版 j 从大到小，和 01 背包同一条理由。写反了同一组内可以重复挑，V = 5 时 96.34% 现形，V = 10 时 93.11%。

3）组内枚举不会让复杂度升阶：所有组内件数加起来是 n，总量仍是 O(n · m)。

4）「一个栈只能从顶部取」这类题，把「取几枚」当成组内的选择，再用前缀和把组内枚举从 O(t²) 压到 O(t)。

下一类题里每种货物都能拿任意个，转移方程只差一个循环方向，代价是二维表再也开不出来。
