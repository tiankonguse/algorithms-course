贪心：小根堆盯住当前最小

扫一堆东西的时候，常常要反复回答同一个问题：还留着的东西里，最小的是哪个。会议室要问「已经开完的那几场什么时候结束」，接棒材要问「还没接的棍子里最短的两根是哪两根」。这两件事一个小根堆就够。

零、会议室什么时候空出来

给定一批会议的时间安排 [开始, 结束]，问最少要准备几间会议室。

题目换个说法就好懂了：同一时刻最多有几场会议在同时开。这个数就是会议室的下界，也一定够用，因为有空房间的时候把新会议塞进去、没有才新开一间，就恰好达到这个数。

朴素的数法是对每一场会议，去数还有多少场跟它重叠，O(n²)；或者按时间点扫，时间轴多大就有多慢。

顺序处理的办法是：先把会议按开始时间排序，用一个容器保存「正在开的会议的结束时间」。处理新会议之前，把容器里所有已经结束的（结束时间早于等于新会议开始的）拿出来，它们占的房间空出来了；然后把新会议的结束时间放进去。容器的大小就是此刻同时进行的会议数。

容器只需要支持「取出最小值」和「插入」，小根堆正好。为什么不用别的：这里的峰值由容器大小决定，而容器里留下的全是结束时间，只关心谁先结束。

这里有个细节：弹出条件是 heap.top() <= 新会议开始时间，等号不能省。一场 5 点结束、另一场 5 点开始，房间是能接上的。

拿 [[1,5],[5,6]] 试一下就现形：正解 1 间，写成严格小于会答 2 间。这个错法在随机数据里的抓取率很依赖值域。

值域 0 到 6 时错 70.67%，因为这种小范围里平均每份随机数据里有 6.35 对「A 的结束时间等于 B 的开始时间」；值域放到 106 就只剩 0.01%。交题时别指望拿随机数据验证这一条。

// intervals[i] = {开始时刻, 结束时刻}，问同一时刻最多有几场会议
    int minMeetingRooms(vector<vector<int>>& intervals) {
        int n = intervals.size();
        sort(intervals.begin(), intervals.end(), [](const vector<int>& a, const vector<int>& b) {
            return a[0] < b[0];
        });
        // 正在开的会议，只留结束时间，最小的在堆顶
        priority_queue<int, vector<int>, greater<int>> heap;
        int ans = 0;
        for (int i = 0; i < n; i++) {
            while (!heap.empty() && heap.top() <= intervals[i][0]) {
                heap.pop();
            }
            heap.push(intervals[i][1]);
            ans = max(ans, (int)heap.size());
        }
        return ans;
    }

等价写法是把所有开始时间、所有结束时间分别排序，两个指针扫一遍：正在进行的开始时间小于最早要结束的结束时间，会议数加一，否则减一。样例 [[1,5],[5,6]] 两个版本都给 1，因为结束数组里的 5 不比开始数组里的 5 小。

实测 n=100000 场耗时 12.09 ms，n=1000000 场 155.05 ms，瓶颈在排序上，堆的操作总共只有 O(n log n) 次。

一、两根棍子接起来

第二题：有一些长度为正整数的棍子，每次可以把两根长度为 x 和 y 的接成一根 x+y，代价 x+y，直到只剩一根，问最小总代价。洛谷 P1090 是同一道题的「合并果子」版本。

先看接法为什么会影响结果。[1,2,3,4,5] 的答案是 33，可要是每次都挑最长的两根接，得到的是 50。差额来自同一个长度被反复计入的次数不同。

把合并过程画成一棵树：每根原始棍子是叶子，每次合并生成一个父节点，根就是最后那根。总代价等于所有内部节点的值之和，也就等于「每个原始长度 × 它在树里的深度」之和。

这就说清楚了：短的长度应该待在深处，长的应该待在浅处。每次从还没接的棍子里挑最短的两根接起来，正是把最短的两个往深处推。这就是哈夫曼编码里那套合并规则。

做法与会议室如出一辙：先把所有长度压进小根堆，循环取出最小的两个、相加、累加代价、把新棍子压回去，直到堆里只剩一根。

// 每次把两根长度 x、y 的棍子接成 x+y，代价 x+y，求接成一根的最小总代价
    long long connectSticks(vector<int>& sticks) {
        priority_queue<int, vector<int>, greater<int>> heap(sticks.begin(), sticks.end());
        long long cost = 0;
        while (heap.size() > 1) {
            int a = heap.top();
            heap.pop();
            int b = heap.top();
            heap.pop();
            cost += a + b;
            heap.push(a + b);
        }
        return cost;
    }

两个错法：每次接最长的两根，在值域 1 到 20 的两万组随机数据里错 83.33%，[1,2,3,4,5] 上给 50；按输入顺序把相邻两根依次合并，错 76.06%。后者的长相很像前缀和，实际上相当于强制按数组顺序搭一棵固定形状的树。

还有个容易忽略的地方：累加和会长得很快。n=100000 根长度全是 10000 的棍子，代价是 16689280000，用 32 位累加会得到 −490589184。LC 的数据范围里答案还在 int 内，把范围放大就必须换 64 位。

洛谷那题要自己处理输入输出，那才是真正的瓶颈。手写一个小根堆比 priority_queue 在这种场景下更稳，只有上浮和下沉两个函数：

// 手写小根堆，只有上浮和下沉两件事，数组开在全局
    int heap[10005];
    int sz;

    void push(int x) {
        heap[sz] = x;
        int i = sz++;
        while (heap[i] < heap[(i - 1) / 2]) {
            swap(heap[i], heap[(i - 1) / 2]);
            i = (i - 1) / 2;
        }
    }

    int pop() {
        int ans = heap[0];
        swap(heap[0], heap[--sz]);
        int i = 0, l = 1;
        while (l < sz) {
            int best = (l + 1 < sz && heap[l + 1] < heap[l]) ? l + 1 : l;
            if (heap[best] >= heap[i]) {
                break;
            }
            swap(heap[i], heap[best]);
            i = best;
            l = i * 2 + 1;
        }
        return ans;
    }

实测 n=100000 的接棒材耗时 8.04 ms，n=500000 是 48.70 ms，n=1000000 是 111.36 ms，大致是 O(n log n) 的样子。

三、复杂度分析

题目关键操作时间空间
会议室 II按开始时间排序 + 扫描时堆的插入弹出O(n log n)，每个结束时间最多进堆出堆各一次O(n)，堆最坏装下所有会议
连接棒材堆里 n 次取出两次插入O(n log n)O(n)

两题的堆操作次数都是 O(n) 次、每次 O(log n)，加一次排序，总体 O(n log n)。会议室那题堆里留的只是「还没结束的会议」，最坏情况下（所有会议同时开）才会到 n。

四、总结

1）需要反复知道「当前留下的东西里最小的是谁」，就用小根堆。会议室留的是结束时间，棒材留的是长度，容器里装的东西不同，问的问题一样。

2）会议室那题的关键是「先排序再扫」：按开始时间排完，同一时刻的重叠数才能被逐场推出来。弹出条件是 <=，等号代表房间可以接上，这条随机数据几乎验证不出来。

3）接棒材那题的关键是换个角度算代价：把它看成合并树里每个长度的深度加权和，最短两根先接的道理就出来了。

4）两题的累加和都可能超出 32 位，写的时候顺手用 64 位，不用等出错再改。

后面两道题的堆用法不一样：一个是「选进来还能反悔」，一个是干脆整条笨路都不用走。
