线段树：区间加与懒更新

区间加不落到每个叶子上，而是在完全覆盖的节点上记一笔 add，等真正要往下走时再补发。同一套形状既能维护和也能维护最大值，差别只在 up 怎么合并、lazy 怎么加工。

零、背景

先问一个比「线段树长什么样」更接近成本的问题：一次区间加，线段树到底碰了几个节点？

n = 10⁶、操作 10⁶ 次，实测平均每次 75.87 次记账加 35.90 次回填，合起来不到 112 个节点。换成逐叶修改，一次就要动 n / 3 个位置，也就是三十多万次。

省下来的这一大截，全靠一个很小的动作：整段覆盖时不停下，只在节点上欠一笔账。

一、问题

长度为 n 的数组 a，两种操作交替出现，一共 m 次。

  • 修改：区间 [l, r] 里每个数都加 v。
  • 查询：区间 [l, r] 的累加和。

洛谷 P3372 就是这个问法，n、m 到 10⁵，数组里的数和 v 都在 ±10⁵ 以内。

区间加是被树状数组挡住的第一道坎。树状数组的 c[i] 管 [i − lowbit(i) + 1, i] 这么一段固定范围，形状由下标说了算，想整段整体地改一次，只能一个点一个点地改。

暴力做也不是不能过小数据。拿同一个随机序列跑 n = m = 10⁵：

做法耗时备注
逐点修改 + 逐点求和427.1 ms每次操作平均扫 n / 3 个位置，约 3.3 × 10⁹ 次加法
线段树31.3 ms同一批操作，答案逐条一致

10⁵ 上只差 13 倍，看着还能忍。但暴力的代价是 n 乘 m，n 和 m 各自再乘 10，乘出来是 100 倍；线段树这边是 n log n 的量级，加一个数量级只是线性地涨。

二、信息数组要开 4n

节点不用指针，躺在数组里：父范围的信息写在 sum[i]，左范围写 sum[2i]，右范围写 sum[2i + 1]，根是 1 号。范围 [l, r] 与下标 i 的对应关系由递归参数维护，不需要额外记录。

那么 1 到 n 的线段树，数组开多大才够？满二叉树的层数上界是 log₂n + 2，这一层的节点数达到 2 的 log₂n + 2 次方，也就是 4n。所以 4n 是安全边界。

这个上界偏宽松。把范围 1 到 200000 全扫一遍，实际出现的最大编号与 n 的比值最大是 3.9844（n = 131328 时需要 523265 个位置），四点几倍的情况一次都没出现过。

// 范围 1~n 的线段树，信息数组要开多大？
    // 返回递归展开过程中出现过的最大下标
    int maxi(int l, int r, int i) {
      if (l == r) {
        return i;
      }
      int mid = (l + r) >> 1;
      return max(maxi(l, mid, i << 1), maxi(mid + 1, r, i << 1 | 1));
    }

    // 把 1 到 200000 全扫一遍，看最大倍数落在哪
    void scanSpace() {
      int bestN = 0, bestSpace = 0;
      double best = 0;
      for (int n = 1; n <= 200000; n++) {
        int space = maxi(1, n, 1);
        double times = (double)space / n;
        if (times > best) {
          best = times;
          bestN = n;
          bestSpace = space;
        }
      }
      printf("最大倍数: n = %d 需要 %d 个位置, %.4f 倍\n", bestN, bestSpace, best);
    }

4n 是行业里最通行的开法，多出来的那点空间换来「不用算」。

三、懒信息是一笔欠账

整段加 v 之后，节点上要维护的信息能不能 O(1) 算出来？这是决定能不能用懒标记的判据。

  • 累加和：整段加 v，和就加了 v 乘元素个数，一步到位。
  • 最大值：整段加 v，最大值也就是加了 v，一步到位。
  • 出现次数最多的数：整段加 v 之后谁最多，跟原来的众数没有关系，加工不出来。

能满足这个判据的信息，就可以只改当前节点、不动儿子，然后在节点上记一笔「这段每个数还欠 v」。

void lazy(int i, ll v, int len) {
  sum[i] += v * len;
  add[i] += v;
}

add 数组就是账本。两次重叠的区间加落在同一个节点上，账本上是 add[i] = 3 再变成 add[i] = 5，累加即可，不需要关心中间经过了几次。

四、down 与 up

有了账本，一次区间加只有三步。

  1. 任务范围把当前范围整个包住，就懒住：改 sum、记 add，不再往下。
  2. 包不住，就把当前节点积压的账往下发一层，这一步是 down。发完清空自己的账本。
  3. 看任务落在左半边还是右半边，分别递归。递归回来用左右儿子的信息把当前节点的 sum 重算一遍，这一步是 up。

被发下去的账，时间一定早于父节点的其它账。同理，查询也要走 down：不完全包含时先把账还清，再去问儿子，否则儿子手里的数字是旧的。

#include <bits/stdc++.h>
    using namespace std;

    typedef long long ll;

    const int MAXN = 100001;

    int n;
    ll arr[MAXN];
    ll sum[MAXN << 2];
    ll add[MAXN << 2];

    // 查询信息的汇总: 父范围的和 = 左范围和 + 右范围和
    void up(int i) {
      sum[i] = sum[i << 1] + sum[i << 1 | 1];
    }

    // 当前范围收到「整段每个数加 v」的懒更新，len 是元素个数
    void lazy(int i, ll v, int len) {
      sum[i] += v * len;
      add[i] += v;
    }

    // 父范围的懒信息往下只发一层
    void down(int i, int ln, int rn) {
      if (add[i] != 0) {
        lazy(i << 1, add[i], ln);
        lazy(i << 1 | 1, add[i], rn);
        add[i] = 0;
      }
    }

    void build(int l, int r, int i) {
      if (l == r) {
        sum[i] = arr[l];
      } else {
        int mid = (l + r) >> 1;
        build(l, mid, i << 1);
        build(mid + 1, r, i << 1 | 1);
        up(i);
      }
      add[i] = 0;
    }

    // [jobl, jobr] 上每个数加 jobv
    void rangeAdd(int jobl, int jobr, ll jobv, int l, int r, int i) {
      if (jobl <= l && r <= jobr) {
        lazy(i, jobv, r - l + 1);
      } else {
        int mid = (l + r) >> 1;
        down(i, mid - l + 1, r - mid);
        if (jobl <= mid) {
          rangeAdd(jobl, jobr, jobv, l, mid, i << 1);
        }
        if (jobr > mid) {
          rangeAdd(jobl, jobr, jobv, mid + 1, r, i << 1 | 1);
        }
        up(i);
      }
    }

    // [jobl, jobr] 的累加和
    ll query(int jobl, int jobr, int l, int r, int i) {
      if (jobl <= l && r <= jobr) {
        return sum[i];
      }
      int mid = (l + r) >> 1;
      down(i, mid - l + 1, r - mid);
      ll ans = 0;
      if (jobl <= mid) {
        ans += query(jobl, jobr, l, mid, i << 1);
      }
      if (jobr > mid) {
        ans += query(jobl, jobr, mid + 1, r, i << 1 | 1);
      }
      return ans;
    }

拿 n = 8、a = [3, 1, 4, 1, 5, 9, 2, 6] 走一次 [2, 6] 加 4，看每个节点上的账本。

每个节点上排是和，下排是最大值，右上角的橙色小字是节点上欠的 add。

五、把信息换成最大值

区间加这一段骨架不用改，只把两处换掉。

up 从求和改成取最大。lazy 里那句 v 乘 len 要去掉：和是整个范围加起来的总量，得乘元素个数；最大值是这个范围里最大的那一个数，加 v 就是加 v，跟范围有多长没关系。down 也就跟着少传两个参数。

// 查询信息换成最大值: 父范围的最大值 = max(左, 右)
    void up(int i) {
      mx[i] = max(mx[i << 1], mx[i << 1 | 1]);
    }

    // 整段每个数加 v，最大值也就加了 v
    // 这里不需要 len: 最大值是这个范围里最大的那一个数
    void lazy(int i, ll v) {
      mx[i] += v;
      add[i] += v;
    }

    // 最大值版本没有长度参数要传
    void down(int i) {
      if (add[i] != 0) {
        lazy(i << 1, add[i]);
        lazy(i << 1 | 1, add[i]);
        add[i] = 0;
      }
    }

    void rangeAdd(int jobl, int jobr, ll jobv, int l, int r, int i) {
      if (jobl <= l && r <= jobr) {
        lazy(i, jobv);
      } else {
        int mid = (l + r) >> 1;
        down(i);
        if (jobl <= mid) {
          rangeAdd(jobl, jobr, jobv, l, mid, i << 1);
        }
        if (jobr > mid) {
          rangeAdd(jobl, jobr, jobv, mid + 1, r, i << 1 | 1);
        }
        up(i);
      }
    }

    ll query(int jobl, int jobr, int l, int r, int i) {
      if (jobl <= l && r <= jobr) {
        return mx[i];
      }
      int mid = (l + r) >> 1;
      down(i);
      ll ans = LLONG_MIN;
      if (jobl <= mid) {
        ans = max(ans, query(jobl, jobr, l, mid, i << 1));
      }
      if (jobr > mid) {
        ans = max(ans, query(jobl, jobr, mid + 1, r, i << 1 | 1));
      }
      return ans;
    }

六、复杂度分析

操作时间空间
建树 buildO(n)两个 4n 数组
区间加O(log n)递归栈 O(log n)
区间查询O(log n)递归栈 O(log n)
整体O((n + m) log n)O(n)

O(log n) 说的是量级，常数值得单独记一笔：n = m = 10⁶ 时六种模板各自跑完是 0.61 秒到 0.73 秒；建树 n = 10⁶ 只要 7.12 ms。区间加的访问节点数在平均 112 个左右，比 2 log n 的 40 大，因为部分相交的节点要两侧都递归下去。

七、总结

懒标记的全部机制就是一本存欠账的 add 数组：整段覆盖时只记账不往下走，真正要访问儿子时再补发一层，回程重算父节点。区间加能这么做，是因为「整段加 v」对累加和与最大值都能 O(1) 加工出来；换成区间众数这类信息，同一套骨架就撑不住了。

同一个骨架里换掉 up 的合并方式和 lazy 的加工方式，就能换一种查询信息，这是线段树最值得先摸熟的灵活性。下一步把修改从「加」换成「重置」，lazy 的含义就从一笔可以累加的账变成一个具体的值，账本还得再配一位开关。
