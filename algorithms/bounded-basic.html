多重背包：每种货物有数量上限

01 背包每种最多拿一件，完全背包每种不限量。多重背包正好卡在中间：每种货物给了一个数量 c[i]。朴素解在容量之外再枚举一遍「拿几件」，复杂度里就多出一个 c 因子。二进制分组把这个因子折成 log c，办法是把 c 件拆成 1、2、4、8 … 加一个零头，每一包当成一件独立的 01 商品。

零、问题

n 种货物，背包容量 t。第 i 种有重量 w[i]、价值 v[i]，并且最多只能拿 c[i] 件。求不超过容量时能拿到的最大价值。这就是洛谷 P1776 宝物筛选。

三种背包只差转移里 k 的取值范围：

01 背包　　dp[i][j] = max( dp[i-1][j], dp[i-1][j-w[i]] + v[i] )　　k ∈ {0, 1}
完全背包　dp[i][j] = max( dp[i-1][j], dp[i][j-w[i]] + v[i] )　　　k 任意
多重背包　dp[i][j] = maxk=0…c[i]( dp[i-1][j-k·w[i]] + k·v[i] )　　k ≤ c[i]

下标写得最清楚的是多重背包这一行：它不新开表，只是在原表上多套了一层 max。麻烦的地方在于这个 max 下面有 c[i] + 1 个候选。

一、朴素做法：多一层枚举

直接照着转移写就是三层循环。前两层和 01 背包一样，第三层把「拿 0 件、1 件、2 件……」逐个试过去。二维表和一维压缩版都照这个写，压缩版的内层 j 依然从大到小，因为每一格读的是「上一行的左侧」，第三层的 k 是额外加的。

时间复杂度 O(n · t · 平均个数)。这个平均个数不是常数，题目给多大就是多大。看实测，n = 100、t = 40000 时：

耗时基本跟着 c 线性涨，多出来的每一倍 c 就是多一遍内层枚举。P1776 的时间限制是 1 秒，c 再大一点就直接超。

// dp[i][j]：只在前 i 种货物里挑，容量不超过 j 时的最大价值
    // 第 i 种：价值 v[i]、重量 w[i]、最多 c[i] 件
    int bounded2d(int n, int t, vector<int>& v, vector<int>& w, vector<int>& c) {
        vector<vector<int>> dp(n + 1, vector<int>(t + 1, 0));
        for (int i = 1; i <= n; i++) {
            for (int j = 0; j <= t; j++) {
                dp[i][j] = dp[i - 1][j];                        // 第 i 种一件都不拿
                for (int k = 1; k <= c[i] && k * w[i] <= j; k++)   // 拿 k 件
                    dp[i][j] = max(dp[i][j], dp[i - 1][j - k * w[i]] + k * v[i]);
            }
        }
        return dp[n][t];
    }
    // 空间压缩，第三层照样枚举件数；这里是 1、2、3 … 一件一件地试
    int bounded1d(int n, int t, vector<int>& v, vector<int>& w, vector<int>& c) {
        vector<int> dp(t + 1, 0);
        for (int i = 1; i <= n; i++)
            for (int j = t; j >= 0; j--)
                for (int k = 1; k <= c[i] && k * w[i] <= j; k++)
                    dp[j] = max(dp[j], dp[j - k * w[i]] + k * v[i]);
        return dp[t];
    }

二、二进制分组：拆成 1、2、4、8 … 加零头

换个角度想，第 i 种货物「拿几件」这个决定，本质上是在问：从 0 到 c[i] 里挑一个数。二进制分组把 0..c[i] 这段用尽量少的「包」表示出来：拆出 1、2、4、8 …，最后剩下的零头单独做一包。

拿 c[i] = 13 举例，拆出来是 1、2、4、6 四包。前三个是 2 的幂，1 + 2 + 4 = 7；零头是 13 − 7 = 6。于是：

每一包当成一件独立的 01 商品，价值是 k 件乘单件价值，重量是 k 件乘单件重量。整题就变回了一个 m 件商品的 01 背包，m = Σ(⌊log₂ c[i]⌋ + 1)。

c 从 10 涨到 100000，涨了一万倍，包数只从 4 涨到 17。原来要枚举 c 次的地方，现在只枚举 log c 次。

// 把每种货物的 c[i] 件拆成 1、2、4、8 … 和剩下的零头
    // 每一包当成一件独立的 01 商品，整题就变回 01 背包
    int binarySplit(int n, int t, vector<int>& v, vector<int>& w, vector<int>& c) {
        vector<int> nv(1), nw(1);                    // 打包后的商品，下标从 1 开始
        for (int i = 1; i <= n; i++) {
            int cnt = c[i];
            for (int k = 1; k <= cnt; k <<= 1) {
                nv.push_back(k * v[i]);
                nw.push_back(k * w[i]);
                cnt -= k;
            }
            if (cnt > 0) {                           // 剩下的零头单独一包
                nv.push_back(cnt * v[i]);
                nw.push_back(cnt * w[i]);
            }
        }
        int m = nv.size() - 1;
        vector<int> dp(t + 1, 0);
        for (int i = 1; i <= m; i++)                 // 01 背包的空间压缩模版
            for (int j = t; j >= nw[i]; j--)
                dp[j] = max(dp[j], dp[j - nw[i]] + nv[i]);
        return dp[t];
    }

三、为什么拼得出来又不重复

「0 到 13 都能拼出来」这件事值得单独看一眼，它是这套拆法能用的理由。

1、2、4 这三包按二进制能拼出 0 到 7 的每个张数，这是 2 的幂的性质。再补一个 6，就有两条路：不用 6 的时候拿到 0..7，用上 6 的时候拿到 6..13。两段拼起来是 0..13，中间 6 和 7 重叠，重叠是允许的（同一个张数有两种拼法，取价值大的那种就行），真正要防的是「漏」。而 6 的起点是 6，小于等于已经能拼到的上界 7，所以中间不会空。

这段逻辑翻译成代码就是那个循环：for (int k = 1; k <= cnt; k <<= 1) 里先放 k，再把 cnt 减掉 k；循环结束时如果还有剩，就是零头，单独补一包。零头必须是「剩下的全部」，不能四舍五入，它承担的是二进制的最高位那部分。

四、写错的代价

三个最容易犯的错，都拿两万组随机小数据测过（n ≤ 4、t ≤ 60、每种 2 到 8 件，值域从 3 一直开到 105）：

1）当 01 背包做，不打包也不枚举，每件只拿一次，错 87.5%。这是最狠的一种，等于把多重退化成 01，只要 c ≥ 2 就有机会错。

2）当完全背包做，忽略 c 直接正序刷，错 60.3%。方向上和上一种相反，它会多拿。

3）if (cnt > 0) 那一句漏掉，只放 2 的幂不补零头，错 54.6%。c 恰好是 2 的幂时会漏掉一整块。

有个反直觉的地方：这三种错的出错率跟价值值域几乎没关系。值域从 3 开到 105，三档错误率都在小数点后一位以内浮动。因为错的都是「能不能多拿几件」这件结构上的事，跟价值大小无关。

五、复杂度分析

做法时间额外空间说明
朴素二维表O(n · t · c̄)O(n · t)c̄ 是每种的平均数量，跟着输入涨
朴素压缩一维O(n · t · c̄)O(t)n = 100、t = 40000、c ≤ 300 时 544.72 ms
二进制分组O(t · Σ log c[i])O(t + Σ log c[i])同一组数据 13.22 ms，比朴素快 41 倍

二进制分组的时间复杂度严格说比 O(n · t) 大一档，因为 Σ log c[i] 比 n 大。但 log 涨得极慢，c 翻倍才多一包，所以实际用起来和 O(n · t) 是一个量级。c 特别大的时候还有单调队列版，能把 c 彻底从复杂度里拿掉。

六、总结

多重背包 = 01 背包 + 一层「拿几件」的枚举，复杂度多一个 c 因子。

几个要点：

1）二进制分组：把 c 件拆成 1、2、4、8 … 加零头，1 + 2 + 4 + … ≥ 零头 − 1 保证拼出 0..c 不漏。

2）零头必须补满，漏掉 if (cnt > 0) 那一句会让 54.6% 的样本出错。

3）转换完就是一个标准的 01 背包压缩模版，内层 j 仍然倒序，不需要再改任何东西。

4）三种常见错法：当 01 错 87.5%，当完全错 60.3%，漏零头错 54.6%，且都与价值值域无关。

5）P1776 这种规模，二进制分组就够用了；数量再大一档，就该换单调队列。
