优化枚举：K 个逆序对数组

数一数 1 到 n 的排列里，恰好有 k 个逆序对的排列有多少个。转移写出来是一段连续区间的求和，这段区间随 j 只挪一格，于是整个内层循环变成一个变量做一次加法。

零、状态怎么定

排列的长度就是 n，逆序对的个数就是 k，两个量都是题目给的。所以状态直接取前缀：dp[i][j] 表示「用 1 到 i 这些数字排成一列，恰好 j 个逆序对的排列有几个」。

从 i − 1 到 i，多出来的数字是 i。i 比 1 到 i − 1 全都大，把它插进一个已有的排列里，插在哪个位置决定了新增多少逆序对：插在最末尾，一个都不新增；插在最前面，后面 i − 1 个数都比它小，新增 i − 1 个。

也就是说，新增的数量 t 可以取 0 到 i − 1 中的任意一个，插的位置就是从右往左数第 t 个缝。于是：

dp[i][j] = dp[i−1][j] + dp[i−1][j−1] + ... + dp[i−1][j−(i−1)]

下标小于 0 的项直接丢掉。写成代码就是两层循环外面再套一层求和。

// dp[i][j] : 1、2...i 这些数字形成的排列中，恰好有 j 个逆序对的排列数
    int kInversePairs1(int n, int k) {
        const int MOD = 1000000007;
        vector<vector<int>> dp(n + 1, vector<int>(k + 1, 0));
        dp[0][0] = 1;
        for (int i = 1; i <= n; i++) {
            dp[i][0] = 1;
            for (int j = 1; j <= k; j++) {
                if (i > j) {
                    for (int p = 0; p <= j; p++) {                   // 窗口还没满，从头加到 j
                        dp[i][j] = (dp[i][j] + dp[i - 1][p]) % MOD;
                    }
                } else {
                    for (int p = j - i + 1; p <= j; p++) {           // 窗口满了，左边界跟着 j 走
                        dp[i][j] = (dp[i][j] + dp[i - 1][p]) % MOD;
                    }
                }
            }
        }
        return dp[n][k];
    }

边界是 dp[0][0] = 1（什么都不排，一种），每行 dp[i][0] = 1（逆序对为 0 的只有升序那一种）。

一、观察：求和的区间是随 j 滑动的窗口

把上面那个式子里的下标范围写清楚，p 从 max(0, j − i + 1) 走到 j：

  • i > j 时，j − i + 1 ≤ 0，窗口左端贴着 0，长度是 j + 1；
  • i ≤ j 时，窗口长度固定为 i，左端是 j − i + 1。

j 往右挪一格，左端和右端同时往右挪一格。所以 dp[i][j] 与 dp[i][j−1] 相比，差的就是「右端新进来的 dp[i−1][j]」减去「左端出去的 dp[i−1][j−i]」。

这一步做完，内层那个循环没了，只剩一个 window 变量。这个结构不用真的建什么东西，一个 int 就够。

// 窗口累加和：dp[i][j] 就是上一行某一段的和，那段随 j 右移一格，加减各一次
    int kInversePairs2(int n, int k) {
        const int MOD = 1000000007;
        vector<vector<int>> dp(n + 1, vector<int>(k + 1, 0));
        dp[0][0] = 1;
        for (int i = 1; i <= n; i++) {
            dp[i][0] = 1;
            long long window = 1;                                    // j = 0 时窗口里只有 dp[i-1][0]
            for (int j = 1; j <= k; j++) {
                if (i > j) {
                    window = (window + dp[i - 1][j]) % MOD;          // 右端进来一个
                } else {
                    window = ((window + dp[i - 1][j]) % MOD - dp[i - 1][j - i] + MOD) % MOD;
                }                                                    // 右端进来一个，左端出去一个
                dp[i][j] = (int)window;
            }
        }
        return dp[n][k];
    }

i > j 那一支不减东西，是因为窗口左端还压在 0 上，没有元素要出去。两支不能合并，否则 j 很小的时候会减到负下标。

三、跟暴力对一下：答案长什么样

n 小的时候可以把排列全列出来数一遍。n = 5 时按逆序对个数 k 分组，得到 1、4、9、15、20、22、20、15、9、4、1，两头对称。对称是必然的：把一个排列里每个数 x 换成 n + 1 − x，逆序对个数就从 j 变成 n(n−1)/2 − j。

四、写错的地方

窗口写法只有两行是新的，错也都错在这两行。随机 2 万组（n ≤ 8，k 取 0 到 n(n−1)/2）实测：

写法与正确解不一致的比例错在哪
窗口只加不减73.31%窗口左端该出去的没出去，j 越大偏得越多
减的下标写成 j − i + 173.31%左端差一位，等价于多留了一格

「只加不减」的抓取率随 n 上升：n = 4 时 85.72%，n = 6 时 93.51%，n = 8 时 96.85%。n 越大，i ≤ j 那一支走的次数越多，减的那一项越躲不掉。

这两个错法在小 k 上都不现形，因为 i > j 的分支根本不减东西。验的时候要专门挑 k 接近 n(n−1)/2 的样本。

五、代价对比

n = k = 1000 时，三层枚举 947.22 ms，窗口版 4.656 ms，差 203 倍。加法次数 334333000 对 1000000，差 334 倍。耗时差比次数差小，是因为窗口版每格还要取模。

窗口版还能再压空间：dp[i][j] 只用到 dp[i−1][·]，滚成两个一维数组就够，表里那些行列只是讲的时候方便看。

六、复杂度分析

版本时间空间说明
三层枚举O(n·k·min(n, k))O(n·k)每格求和长度是 min(i, j + 1)
窗口累加和O(n·k)O(n·k)每格一次加法，必要时再减一次
窗口 + 滚动数组O(n·k)O(k)只留上一行

表里第二行的时间是填 (n+1)·(k+1) 个格子、每格 O(1)。题目给的范围 n ≤ 1000、k ≤ 1000，一百万格，窗口版跑 4.656 ms。

七、总结

这题的优化不靠查询结构，靠看出「求和区间是一个随 j 平移的定长窗口」。三层循环里最内层那一段，相邻两个 j 之间只差两个端点，把它记成一个变量就是了。

写的时候分清两支：i > j 只加，i ≤ j 加减都要做，减的是 dp[i−1][j−i]。取模别忘了，减完要加一次 MOD 再取。

同样的手法在别的题上还会出现：只要转移写成「上一行一段连续区间求和」，且区间端点单调移动，就可以用窗口替掉枚举。区间长度不固定、端点乱跳的那类，得换成前缀和数组或线段树。
