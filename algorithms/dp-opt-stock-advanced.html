优化枚举：买卖股票（下）

把交易次数从「最多两笔」换成参数 k，枚举层就从一层变成两层。这一页讲 k 笔、手续费、冷冻期三道题。k 笔那道的优化和上一类股票题是同一套动作，只是候选集合从一维数组换成了二维表的一行。

零、最多 k 笔：二维表里的一层枚举

设 dp[i][j] 是「用不超过 i 笔交易、只看 0..j 天」的最优值。第 i 笔要么在第 j 天之前就结束了，要么正好在第 j 天卖出。

把「正好在第 j 天卖出」展开：买入日设为 p，p < j，那么前 i−1 笔必须在第 p 天之前收完，也就是 dp[i−1][p]。于是

dp[i][j] = max( dp[i][j−1], max over p<j 的 ( dp[i−1][p] + prices[j] − prices[p] ) )

这个内层 p 又要枚举。k 行、n 列、每格再扫 n 次，是 O(k·n²)。

// 最多 k 笔：dp[i][j] 是「用前 i 笔、在 j 之前」的最优，转移里枚举上一笔的卖出位置
    int maxProfit(int k, vector<int>& prices) {
        int n = prices.size();
        if (k >= n / 2) return freeTrade(prices);      // 无限次，见下一节
        vector<vector<int>> dp(k + 1, vector<int>(n, 0));
        for (int i = 1; i <= k; i++) {
            for (int j = 1; j < n; j++) {
                dp[i][j] = dp[i][j - 1];
                for (int p = 0; p < j; p++) {                          // 枚举买入日 p
                    dp[i][j] = max(dp[i][j], dp[i - 1][p] + prices[j] - prices[p]);
                }
            }
        }
        return dp[k][n - 1];
    }

规模感：n = 4000、k = 50 实测 21.7 ms；k 拉到 800 是 349 ms，二维表本身要 12.2 MB。k 再大就要超时了。

一、观察：把内层搬到「扫 j 的路上」

和上一类题一样，把内层的括号拆开，dp[i−1][p] − prices[p] 跟 j 没关系。固定第 i 行往下扫 j，新增的候选只有 p = j−1 这一个，维护一个变量就够：

best = max( dp[i−1][p] − prices[p] ), p < j

顺序上要注意：先用 best 算 dp[i][j]，再把 p = j 这个候选并进去。写反了就把「第 j 天买入又在第 j 天卖出」当成一次真实交易，实测 24.86% 出错。

// 内层要的是 max(dp[i-1][p] - prices[p])，p 从小到大扫，它就是上一轮的一个后缀最大值
    int maxProfit(int k, vector<int>& prices) {
        int n = prices.size();
        if (k >= n / 2) return freeTrade(prices);
        vector<vector<int>> dp(k + 1, vector<int>(n, 0));
        for (int i = 1, best; i <= k; i++) {
            best = dp[i - 1][0] - prices[0];               // 先放进 p = 0
            for (int j = 1; j < n; j++) {
                dp[i][j] = max(dp[i][j - 1], best + prices[j]);
                best = max(best, dp[i - 1][j] - prices[j]); // 再把 p = j 这个候选加进来
            }
        }
        return dp[k][n - 1];
    }

内层没了，O(k·n²) 变 O(k·n)。同一批数据上 O(k·n) 是 0.13 ms，差一百多倍。

二、剪枝：k 大到一定程度就不用管了

无限次交易的答案就是把所有上坡加起来。什么时候 k 笔能吃到所有上坡？只要交易次数够多，多到能一笔一段上坡。

相邻两天之间最多形成一段上坡，所以上坡段数不超过 n/2 段。于是 k ≥ n/2 时答案和无限次完全一样，可以直接调题 2 的一次遍历返回。这一步是严格等价的。

实测：n = 4000 时 k = n/2 = 2000 触发剪枝，两个版本都掉到 0.001 ms 以下；k = 1999 不触发，O(k·n²) 还是 875 ms。

三、空间压缩

第 i 行只读第 i−1 行的 dp，加上 prices。既然如此，一行就够。

唯一要小心的是 dp[j] 被覆盖前先存下来，因为算 best 时要用旧值，它代表的是第 i−1 行的 dp[j]。写成先更新 best 再算 dp[j]，读到的就是本行的值了。

// 第 i 行只读第 i-1 行的 dp 和 prices，滚动一维：先取旧值，再写新值
    int maxProfit(int k, vector<int>& prices) {
        int n = prices.size();
        if (k >= n / 2) return freeTrade(prices);
        vector<int> dp(n, 0);
        for (int i = 1, best, tmp; i <= k; i++) {
            best = dp[0] - prices[0];
            for (int j = 1; j < n; j++) {
                tmp = dp[j];                              // tmp 是第 i-1 行的 dp[j]
                dp[j] = max(dp[j - 1], best + prices[j]);
                best = max(best, tmp - prices[j]);
            }
        }
        return dp[n - 1];
    }

空间从 O(k·n) 降到 O(n)。k = 800、n = 4000 时那张二维表占 12.2 MB，一维只要 16 KB。

四、含手续费：两个状态就够

交易次数回到无限，但每笔交易要交一次手续费。这次不去数上坡，改用两个状态：

  1. prepare：手上持股、并且收益里已经扣掉买入价和手续费的最好情况；
  2. done：已经落袋的最好收益。

第 i 天能做的只有两件事：把手里的卖掉，或者拿落袋的钱再买一手。

// 含手续费：prepare 是「手上持股」的最好情况，done 是「已经落袋」的最好情况
    int maxProfit(vector<int>& prices, int fee) {
        int prepare = -prices[0] - fee;               // 第 0 天买入，付一次手续费
        int done = 0;
        for (int i = 1; i < (int)prices.size(); i++) {
            done = max(done, prepare + prices[i]);    // 今天卖出
            prepare = max(prepare, done - prices[i] - fee); // 今天买入
        }
        return done;
    }

done 先用旧的 prepare 更新，prepare 再用新的 done 更新，两行顺序不能反。手续费在买入那一侧扣，所以 prepare 的初值就带着 −fee。

两处漏 fee 的写法：更新那一行忘了减，实测 71.29% 出错；初值忘了减，实测 42.41% 出错。前者错得更狠，因为每次买入都少算一次手续费。

五、含冷冻期：把依赖挪到 i−2

规则改成卖出的第二天不能买。prepare 和 done 的含义不变，变的只有一条：第 i 天买入，只能接在第 i−2 天卖出的收益后面。

done[i] = max( done[i−1], prepare[i−1] + prices[i] )
prepare[i] = max( prepare[i−1], done[i−2] − prices[i] )

冷冻期就卡在这一个下标上：写成 done[i−1]，等于允许卖出的第二天就买回，实测 64.20% 出错。

// 含冷冻期：pre[i] 和 done[i] 的定义不变，只是买入要用 i-2 的 done
    int maxProfit(vector<int>& prices) {
        int n = prices.size();
        if (n < 2) return 0;
        int prepare = max(-prices[0], -prices[1]);
        int done2 = 0, done1 = max(0, prices[1] - prices[0]);
        for (int i = 2, curDone; i < n; i++) {
            curDone = max(done1, prepare + prices[i]);
            prepare = max(prepare, done2 - prices[i]); // 冷冻期就卡在这一个下标上
            done2 = done1;
            done1 = curDone;
        }
        return done1;
    }

这里有个细节。把 done[i] 和 prepare[i] 的计算顺序调换，先算 prepare[i]、再算 done[i]，答案一点不变。因为多进来的那一项是「第 i 天买入又第 i 天卖出」，收益正好是 0，不会把答案抬上去。这处实测 0.00% 差异，属于「看着像错、其实等价」。

复杂度分析

做法时间空间
最多 k 笔·枚举买入日O(k·n²)O(k·n)
最多 k 笔·best 变量O(k·n)O(k·n)
最多 k 笔·滚动一维O(k·n)O(n)
k ≥ n/2（剪枝后）O(n)O(1)
含手续费O(n)O(1)
含冷冻期O(n)O(1)

手续费和冷冻期两道题只有常数个滚动变量，空间是 O(1)。k 笔那道题的空间从 O(k·n) 压到 O(n)，压不掉的 n 来自「同一行从左往右扫」这个方向本身。

总结

k 笔这道题就是「两笔」的推广。内层要的还是那个和 i 无关的量 dp[i−1][p] − prices[p]，只是它现在躺在上一行，扫 j 的时候顺手维护即可。

剪枝值得单独记一笔：k ≥ n/2 时问题退化成无限次交易，可以直接掉头走题 2 的 O(n) 写法。理由是上坡段数不超过 n/2，多出来的交易次数没有东西可买。

手续费和冷冻期把「观察」的对象从转移式换成了状态本身：一个状态不够，就拆成持股和落袋两个；一条依赖被规则挡住，就往回挪一格。这两道题各自的错法也都在状态上：漏手续费在买入侧，冷冻期在 done[i−2] 那个下标上。

还有一处提醒：prepare 的初值、done 和 prepare 的更新顺序，这两处看起来是细节，实测加起来能覆盖七成以上的随机数据。写这类滚动 dp 时先把这两处的依赖关系在纸上画一遍，比事后调输出快得多。
