单调队列配前缀和：最短子数组与最大价值

数组里掺了负数，滑动窗口那套「和大了就缩 l」立刻失效：l 该往哪缩没有单调性。前缀和把「子数组和」变成「两个前缀和的差」，问题就转成找一对前缀和：早的尽量小、晚的尽量大。单调队列在中间维护候选，两个维度（值要小、下标要早）一个靠队尾淘汰、一个靠队头结算。

零、背景

数组全正时，「和至少为 K 的最短子数组」用双指针就能扫：和不够 r 右移，够了 l 左移收缩。加入负数后这套全崩：l 收缩后和可能变大（因为甩掉了负数），也可能变小，没有单调性可依赖，暴力只能枚举所有子数组。

先看前缀和。定义 sum[i] 为前 i 个数的累加和，子数组 [l, r) 的和就是 sum[r] - sum[l]。于是问题变成：找 l < r，sum[r] - sum[l] >= K，让 r - l 最小。

对固定的 r，要凑出 sum[r] - sum[l] >= K，sum[l] 越小越容易；要长度短，l 越靠后越好（r - l 小）。这两个要求打架：越早的 l 离得远但可能很小，越晚的 l 离得近但可能不够小。

一、单调队列维护前缀和候选

从 l 的角度想：一个候选 l，如果被后来的 l' 全面压制（sum[l'] <= sum[l] 且 l' > l），那 l 永远等不到出场：l' 值更小更容易凑够 K，下标更晚长度更短。留着 l 没有意义，弹掉。

单调队列里存的就是这样一条「前缀和递增」的候选链：从头到尾下标递增、值也递增。值越大的越靠后，一旦出现更小的，前面所有更大的全部淘汰。

结算发生在队头：r 扫描到每个位置，看队头候选能不能凑够（sum[r] - sum[队头] >= K）。能凑够就结算 r - 队头并弹出队头：它已经以最短长度完成任务，留着只会让后面的 r 更长。弹出后下一个队头继续试。

每个前缀和入队一次、出队至多一次，总代价 O(n)。实测 n=1e5、值域 [-1e4, 1e4]、K=5000 的随机数组，单调队列 1.40ms；暴力扫 O(n²) 在 n=5000 就要 12.77ms。

二、题 1 代码

#include <bits/stdc++.h>
    using namespace std;

    // 和至少为K的最短子数组
    // 前缀和 + 单调队列（队头是最早且最小的前缀和候选）

    const int MAXN = 100001;
    long long sumArr[MAXN];
    int dq[MAXN];
    int h, t;

    int shortestSubarray(vector<int>& arr, int K) {
        int n = (int)arr.size();
        for (int i = 0; i < n; i++) {
            sumArr[i + 1] = sumArr[i] + arr[i];
        }
        h = t = 0;
        int ans = INT_MAX;
        for (int i = 0; i <= n; i++) {
            while (h != t && sumArr[i] - sumArr[dq[h]] >= K) {
                ans = min(ans, i - dq[h]);
                h++;
            }
            while (h != t && sumArr[dq[t - 1]] >= sumArr[i]) {
                t--;
            }
            dq[t++] = i;
        }
        return ans != INT_MAX ? ans : -1;
    }

    int main() {
        int n, k;
        cin >> n >> k;
        vector<int> arr(n);
        for (int i = 0; i < n; i++) cin >> arr[i];
        cout << shortestSubarray(arr, k) << endl;
        return 0;
    }

两个 while 各司其职：前一个结算队头，后一个维护「递增」结构。注意结算用 >=，等于 K 也算达标；答案没更新过就返回 -1。

样例：K=3 的 [2,-1,2]，前缀和 [0,2,1,3]，答案 3（整个数组）；[1,2] K=4 无解返回 -1；[84,-37,32,40,95] K=167 答案 3（[32,40,95]）。

三、题 2：满足不等式的最大值（LeetCode 1499）

点按 x 排序，对 i < j 有 xj > xi，绝对值号直接去掉：yi + yj + xj - xi，整理成 (xj + yj) + (yi - xi)。前一半属于当前点 j，后一半是之前某个点 i 的贡献，还带约束 xj - xi <= k。

对每个 j，要的是「x 距离不超过 k 的 i 里 yi - xi 最大」。这又是候选问题：候选 i 的价值是 yi - xi，越大越好；距离约束是 x 差 <= k，超窗就过期。

队列从队头淘汰过期（队头 x + k < 当前 x），队头就是窗口内 yi - xi 最大的候选，直接结算；从队尾淘汰「价值更差」的候选（新候选的 y - x 更大，旧的留着没用）。

复杂度 O(n)，额外空间 O(n)。实测 n=1e5、x 递增、y 值域 [-1e6, 1e6]、k=1e4，单调队列 1.02ms；暴力 O(n²) 在 n=3000 就要 2.34ms。

四、题 2 代码

#include <bits/stdc++.h>
    using namespace std;

    // 满足不等式的最大值
    // 点按 x 排序，yi + yj + |xi - xj| = (xi + yi) + (yj - xj)
    // 单调队列维护 y-x 递减的候选，队头过期条件 x 距离超过 k

    const int MAXN = 100001;
    int dq[MAXN][2];
    int h, t;

    int findMaxValueOfEquation(vector<vector<int>>& points, int k) {
        h = t = 0;
        int n = (int)points.size();
        int ans = INT_MIN;
        for (int i = 0; i < n; i++) {
            int x = points[i][0];
            int y = points[i][1];
            while (h < t && dq[h][0] + k < x) {
                h++;
            }
            if (h < t) {
                ans = max(ans, x + y + dq[h][1] - dq[h][0]);
            }
            while (h < t && dq[t - 1][1] - dq[t - 1][0] <= y - x) {
                t--;
            }
            dq[t][0] = x;
            dq[t][1] = y;
            t++;
        }
        return ans;
    }

    int main() {
        int n, k;
        cin >> n >> k;
        vector<vector<int>> points(n, vector<int>(2));
        for (int i = 0; i < n; i++) cin >> points[i][0] >> points[i][1];
        cout << findMaxValueOfEquation(points, k) << endl;
        return 0;
    }

队列元素是 (x, y)，比较口径是 y - x。入队时机在结算之后：当前点结算完自己，再作为候选供后面的点使用。

样例：[[1,3],[2,0],[5,10],[6,-10]] k=1 答案 4（点 0 和点 1）；[[0,0],[3,0],[9,2]] k=3 答案 3（点 0 和点 1）。

总结

两题共享一个骨架：候选有两个维度，一个维度「值更优」靠队尾淘汰维护单调性，一个维度「不超窗」靠队头过期处理。题 1 的窗口是前缀和下标（最短长度约束），题 2 的窗口是 x 坐标差，本质是同一件事。

题 1 里队列单调递增、结算在队头弹「达标」的候选；题 2 里队列单调递减、结算在队头弹「过期」的候选。方向不同，是因为题 1 要最短（早达标早结算），题 2 要最大（候选存活到过期）。

题 3 把同一个队列用进二分答案的贪心检查，是单调队列的另一个去处，下一页单独讲。
