Manacher：最长回文子串与回文子串数量

回文半径数组 p 填好之后，这两道题都是一遍扫。麻烦的地方在于答案不总是 p 值本身：最长回文子串要返回那个串，得把扩展串上的下标换算回原串；回文子串数量要弄明白同一个中心到底贡献几个不同的回文，因为半径多一格并不一定多出一个回文。

零、两道题

最长回文子串要求返回最长的那个回文子串本身，回文子串数量要求返回 s 里回文子串的个数，不同位置算不同的子串，长度 1 的也算。

两个题的 |s| 都不超过 1000，从每个中心往外扩的平方做法交上去也能过。要看 Manacher 到底省了什么，把串放大才看得出来：全 a 的串长 16000，中心扩展要 66.56 毫秒，Manacher 0.11 毫秒，差了 600 倍。

下面几张图都拿 "abacaba" 举例，它的扩展串长 15，整串本身就是回文，数字好看。

一、半径换成真实长度

扩展串的下标 0 到 2m，原串第 k 个字符落在下标 2k + 1 上，偶数下标全是 '#'。

以 i 为中心、半径 p[i] 的回文在扩展串里占 [i − p[i] + 1, i + p[i] − 1] 这一段，两端必然是 '#'，夹在中间的字母个数就是真实回文长度，也就是 p[i] − 1。

为什么两端一定是 '#'？扩展停下来的原因只有两种：对称的两格字符不等，或者某一侧出了界。不等的那两格在扩展串里相差 2p[i] 格、奇偶性相同，而两个 '#' 之间不可能不等，所以这一对只能是两个字母，那么回文真正的右端点是它们左边那一格，还是 '#'。出界的情形更直接：右边出界说明右端点就是扩展串最后一个下标 2m，左边出界说明右端点是 2i，两者都是偶数。

二、长度有了，位置还得换来

长度只是答案的一半，题目要的是那个子串。回文在扩展串里最右那格的下标是 i + p[i] − 1，它是个偶数的 '#'。一个偶数的 '#' 左边压着几个真实字符，它就落在真实串的哪个下标上，所以

end = (i + p[i] − 1) / 2

就是真实回文结束位置的后一格。起点是 end − (p[i] − 1)，答案就是 s.substr(end − mx, mx)。

拿 "abacaba" 的数走一遍：i = 7 时 p[7] = 8 最大，end = (7 + 8 − 1) / 2 = 7，mx = 7，起点 7 − 7 = 0，取前 7 个字符，正好是整串。

偶长度的回文一样走这条路。"cbbd" 的最长回文是 "bb"，中心落在下标 4 那个 '#' 上，p[4] = 3，end = (4 + 3 − 1) / 2 = 3，起点 3 − 2 = 1，取的正是 [1, 3)。

三、一个中心贡献几个回文

数量那道题看着更简单，其实是这里最容易想错的地方。以 i 为中心的半径从 1 一直数到 p[i]，每种半径都是一个回文，那是不是贡献 p[i] 个？不是。半径 r 和 r + 1 在真实串上常常是同一个回文：半径加一格，扩展串两端各多出一个字符，这两个字符的奇偶性相同，要么都是 '#'，要么都是字母。都是 '#' 时真实回文长度没变，只有都是字母时才长了 2。

所以半径两两折成一个长度，半径 1 那个折出来是空串，不算。分开看两种中心：

1）中心落在 '#' 上（偶数下标）：p[i] 是奇数，对应长度 2, 4, …, p[i] − 1，共 (p[i] − 1) / 2 个。

2）中心落在字母上（奇数下标）：p[i] 是偶数，对应长度 1, 3, …, p[i] − 1，共 p[i] / 2 个。

两种情形写成一个式子都是 ⌊p[i] / 2⌋。每个回文子串的中心唯一，所以把 n 个中心的值加起来，不重不漏。

"abacaba" 的答案是 12，拆开看：7 个长度 1、3 个长度 3（"aba" 两个、"bab" 一个）、1 个长度 5（"bacab"）、1 个长度 7（整串）。

逐格读半径数组

每点一步算一个中心：蓝底是这一格盖住的回文范围，橙框是中心。下面分开记真实长度 p[i] − 1 和这一格贡献的个数 ⌊p[i] / 2⌋。

四、代码

扩展串和主循环还是那两段，跑完 p 数组就有了。

// 扩展串：原串相邻字符之间、以及两端各插一个 '#'，长度 2n + 1
    const int MAXN = 1001;              // 题目上限 |s| <= 1000

    char ss[MAXN << 1];
    int p[MAXN << 1];
    int n;

    void manacherss(const string &a) {
        n = (int)a.size() * 2 + 1;
        for (int i = 0, j = 0; i < n; i++) {
            ss[i] = (i & 1) == 0 ? '#' : a[j++];
        }
    }
// 主循环：c、r 记住最靠右的那段回文，每个中心先白拿一段再往外扩
    void manacher(const string &str) {
        manacherss(str);
        for (int i = 0, c = 0, r = 0, len; i < n; i++) {
            len = r > i ? min(p[2 * c - i], r - i) : 1;
            while (i + len < n && i - len >= 0 && ss[i + len] == ss[i - len]) {
                len++;
            }
            if (i + len > r) {
                r = i + len;
                c = i;
            }
            p[i] = len;
        }
    }

最长回文子串在扫描时顺手记下最大的半径，同时把结束位置换算出来。

// 最长回文子串：边跑边记最大的半径，以及在扩展串里的回文右端
    string longestPalindrome(const string &s) {
        manacher(s);
        int mx = 0, end = 0;
        for (int i = 0; i < n; i++) {
            if (p[i] - 1 > mx) {
                mx = p[i] - 1;                  // 真实长度
                end = (i + p[i] - 1) / 2;       // 真实回文结束位置（开区间右端）
            }
        }
        return s.substr(end - mx, mx);
    }

数量那道题只要一行累加。

// 回文子串数量：每个中心贡献 p[i] / 2 个不同的回文子串
    long long countSubstrings(const string &s) {
        manacher(s);
        long long ans = 0;
        for (int i = 0; i < n; i++) {
            ans += p[i] / 2;
        }
        return ans;
    }

五、两个错法

一是把结束位置写成 (i + p[i]) / 2。20000 组随机串上跑下来 0.00% 有差别，原因是 i + p[i] − 1 恒为偶数，i + p[i] 恒为奇数，整数除法向下取整后两个式子给出同一个数。这次是看着不像同一回事，算下来真的等价。

二是把贡献个数写成 p[i]，也就是把半径当长度用，20000 组里 100% 出错。写成 (p[i] − 1) / 2 也一样 100%，因为 p[i] 是奇数时这两个数差 1，是偶数时差得更多。

六、复杂度分析

做法关键操作时间空间
中心扩展2n − 1 个中心各自往外扩O(n2)O(1)
读半径数组填一遍 p，再扫一遍取答案O(n)O(n)

两道题都只比 Manacher 多扫一遍 p，常数可以忽略。空间上按 |s| ≤ 1000 的开法，ss 与 p 各 2003 格，几 KB 的事；就算把上限放大到 106，ss 是 2 MB 字符、p 是 8 MB int，加起来也就 10 MB。全 a 串 n = 106 实测 6.72 毫秒，回文子串总数 500000500000 个，这个数超过了 int 的范围，返回值要用 64 位。

总结

真实回文长度是 p[i] − 1，回文在扩展串里最右的 '#' 落在偶数下标 i + p[i] − 1 上，除以 2 就换算回真实串的结束位置。

以 i 为中心的不同回文子串有 ⌊p[i] / 2⌋ 个，多出来的那部分半径折在同一个回文上，中心唯一保证了累加不重不漏。

两道题都是 O(n) 时间、O(n) 空间。半径数组拿到手，能读出的东西就这么两类：一个最大值，和一份按中心的计数。下一道题开始要在它上面做筛选。
