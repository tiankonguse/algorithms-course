大于 n/k 与子数组海王

大于 n/k 的数最多有 k−1 个，那就开 k−1 个计数器一起摩尔投票。再把整棵投票树搬进线段树，静态数组上的区间查询每次只摸 log n 个结点。

零、背景

大于 n/2 的水王数只是个头，一般形态是大于 n/k：数组里出现次数超过总数 k 分之一的数。这类数在流式算法里有个名字叫重元素。k=2 时只有一个计数器，就是上一门的摩尔投票。

还有一个更尖锐的问题：数组给定之后不再变动，反复询问某个子区间里出现次数够 t 的数。区间每次都不同，每次从头数一遍太慢，要把投票的结果预先存下来。

一、大于 n/k 的最多 k−1 个

答案的个数有上界。假设有 k 个不同的值，每个都出现大于 n/k 次，加起来就超过 n，装不下。所以大于 n/k 的值最多 k−1 个，开 k−1 个计数器就够装。

这个上界是硬的：k−1 个计数器不是拍脑袋定的，是答案个数的上限。反过来说，计数器个数少于 k−1 也可能碰巧答对，但数据一构造就漏。

二、k−1 个计数器一起投票

每个新元素进来，按顺序问三件事。一，有没有计数器存的正是它且血量大于 0？有就血量加 1，收工。二，有没有空位（血量为 0 的计数器）？有就住进去，血量置 1。三，前两问都不行，说明 k−1 个计数器都活着且都不是它：所有计数器各减 1，这个元素丢弃。

#include <bits/stdc++.h>
    using namespace std;

    // 新来一个数, k-1 个计数器三步更新
    void update(vector<pair<int, int>>& cands, int k, int num) {
        // ① 有计数器正是 num 且血量大于 0
        for (int i = 0; i < k; i++) {
            if (cands[i].first == num && cands[i].second > 0) {
                cands[i].second++;
                return;
            }
        }
        // ② 有空位, num 入住
        for (int i = 0; i < k; i++) {
            if (cands[i].second == 0) {
                cands[i] = make_pair(num, 1);
                return;
            }
        }
        // ③ 没有空位, 所有计数器各减 1, num 丢弃
        for (int i = 0; i < k; i++) {
            if (cands[i].second > 0) {
                cands[i].second--;
            }
        }
    }

    // 返回所有出现次数大于 n/k 的数
    vector<int> moreThanNK(vector<int>& nums, int K) {
        int k = K - 1;
        vector<pair<int, int>> cands(k, make_pair(0, 0));
        for (int num : nums) {
            update(cands, k, num);
        }
        vector<int> ans;
        for (int i = 0; i < k; i++) {
            if (cands[i].second > 0) {
                // 活着的只是候选, 真实次数要再数一遍
                int real = 0;
                for (int num : nums) {
                    if (num == cands[i].first) {
                        real++;
                    }
                }
                if (real > (int)nums.size() / K) {
                    ans.push_back(cands[i].first);
                }
            }
        }
        return ans;
    }

第三步为什么是所有计数器各减 1，而不是挑一个减？因为无从挑。减一个等于宣布「它和某一个候选抵消」，可这个元素和谁都不相等；全部减 1，相当于它同时和 k−1 个不同候选各抵消一次，这才是「两边都不沾」的公平做法。

演示：大于 n/k 的计数器台

逐个元素处理，看每次走的是匹配、占位还是全减，最后一屏把活着的候选逐个数一遍真实次数。k 可以选 2 到 5，数据可以切换四组固定或一组随机。

三、账本：真正的水王一定活着

为什么活着的候选里一定包含所有答案？算一笔账。记最终所有计数器血量之和为 H，全减一共发生了 R 次。每个元素的去处只有三种：让某个计数器加 1（匹配或占位）、在全减里当那个被丢弃的元素、在全减里当被削血的 k−1 个之一。一次全减动用 k 个元素（k−1 个计数器各削 1 点血，外加丢弃的这个），所以 n = H + kR。

对任意值 v，它的每一次出现，要么给自己计数器加过血，要么在某次全减里被削掉一次（要么是被丢弃的那个，要么是 k−1 个被削计数器之一）。每次全减至多削 v 一次，所以 v 的出现次数不超过 hp_v 加 R。v 若不是最终候选，hp_v 等于 0，次数不超过 R = (n−H)/k，不超过 n/k。所以大于 n/k 的值一定活着，一定在最终候选里。

活着只是候选，血量不是次数。把「收集时信血量、不数真实次数」这个错法拿出来实测：k=3、值域 20 上 72.58% 的随机数组答错，k=4 时 79.70%。血量的意义只是「抵消后还剩多少」，和真实次数之间隔着一整个 R。

还有一个看着像错其实等价的变体：第一步匹配时不判血量大于 0，匹配到死槽位也算匹配。死槽位的值恰好等于新元素时，加血和占位效果一样，只是占的槽位编号不同；收集阶段读的是一组（值，血量），与编号无关。实测 k 取 3 和 4、值域 2/3/5/20 八档共 40000 组随机数组，答案 0 例不同。

四、子数组里的海王数

题意：数组 arr 不动，实现一个查询 query(l, r, t)，返回 arr[l..r] 里出现次数至少 t 的数，没有返回 -1。关键约束是 2t 大于区间长度，也就是阈值 t 恒为区间长度的严格一半以上。

这个约束一加，「出现次数够 t」就成了「区间上的严格众数」：够 t 次必然超过长度的一半。严格众数若存在，一定是摩尔投票的候选。于是查询拆成两步：先在区间上跑摩尔投票拿候选，再数它的真实次数，够 t 就返回，不够返回 -1。

区间上跑摩尔投票不是遍历区间，那样一次查询 O(n)。把数组按线段树切开，每个结点存这段区间的（候选，血量），合并规则同加异减，和分段并发投票用的是同一条。查询时从根往下走，走过的结点只有 O(log n) 个，沿途把结果合并出来。实测 n=2×10⁴ 时一次查询平均摸 37.2 个结点，最多 49 个，而 log₂n 约 14.3。

演示：线段树上的海王查询

先看查询区间与 2t 大于长度的保证，然后从根往下摸结点合并出候选，再在（值，下标）排序表上两次二分数出真实次数，最后和阈值比较。可以切换五组固定查询或一组随机查询。

五、数出现次数：排序加两次二分

拿到候选 c，还要数它在 [l, r] 里的真实出现次数。预处理时把（值，下标）二元组按值排序，bs(v, i) 一次二分回答「小于 v 的个数，加上等于 v 且下标不超过 i 的个数」。区间计数就是两次二分相减：cnt(l, r, v) = bs(v, r) − bs(v, l−1)。

二分的比较条件「小于 v，或者等于 v 且下标不超过 i」正好把同一段值按下标切成两半。排序一次 O(n log n)，之后每次查询两次二分各 O(log n)。

#include <bits/stdc++.h>
    using namespace std;

    struct MajorityChecker {
        int n;
        vector<vector<int>> nums; // (值, 下标) 按值排序
        vector<int> cand, hp;     // 线段树: 每段范围的候选与血量

        MajorityChecker(vector<int>& arr) {
            n = arr.size();
            nums.resize(n);
            for (int i = 0; i < n; i++) {
                nums[i] = {arr[i], i};
            }
            sort(nums.begin(), nums.end(), [](vector<int>& a, vector<int>& b) {
                return a[0] != b[0] ? a[0] < b[0] : a[1] < b[1];
            });
            cand.assign(4 * n, 0);
            hp.assign(4 * n, 0);
            buildTree(arr, 1, n, 1);
        }

        // arr[0..i] 上, (小于 v) 加 (等于 v 且下标不超过 i) 有几个
        int bs(int v, int i) {
            int left = 0, right = n - 1, find = -1;
            while (left <= right) {
                int mid = (left + right) >> 1;
                if (nums[mid][0] < v || (nums[mid][0] == v && nums[mid][1] <= i)) {
                    find = mid;
                    left = mid + 1;
                } else {
                    right = mid - 1;
                }
            }
            return find + 1;
        }

        // v 在 [l, r] 上的出现次数
        int cnt(int l, int r, int v) {
            return bs(v, r) - bs(v, l - 1);
        }

        void up(int i) {
            int lc = cand[i << 1], lh = hp[i << 1];
            int rc = cand[i << 1 | 1], rh = hp[i << 1 | 1];
            cand[i] = lc == rc || lh >= rh ? lc : rc;
            hp[i] = lc == rc ? lh + rh : abs(lh - rh);
        }

        void buildTree(vector<int>& arr, int l, int r, int i) {
            if (l == r) {
                cand[i] = arr[l - 1];
                hp[i] = 1;
            } else {
                int mid = (l + r) >> 1;
                buildTree(arr, l, mid, i << 1);
                buildTree(arr, mid + 1, r, i << 1 | 1);
                up(i);
            }
        }

        // 在 [jobl, jobr] 上合并出候选, 走过的结点数是 O(log n)
        pair<int, int> findCandidate(int jobl, int jobr, int l, int r, int i) {
            if (jobl <= l && r <= jobr) {
                return make_pair(cand[i], hp[i]);
            }
            int mid = (l + r) >> 1;
            if (jobr <= mid) {
                return findCandidate(jobl, jobr, l, mid, i << 1);
            }
            if (jobl > mid) {
                return findCandidate(jobl, jobr, mid + 1, r, i << 1 | 1);
            }
            auto L = findCandidate(jobl, jobr, l, mid, i << 1);
            auto R = findCandidate(jobl, jobr, mid + 1, r, i << 1 | 1);
            int c = L.first == R.first || L.second >= R.second ? L.first : R.first;
            int h = L.first == R.first ? L.second + R.second : abs(L.second - R.second);
            return make_pair(c, h);
        }

        int query(int l, int r, int t) {
            auto ch = findCandidate(l + 1, r + 1, 1, n, 1);
            return cnt(l, r, ch.first) >= t ? ch.first : -1;
        }
    };

六、2t 大于长度这个保证不能少

题目里 2t 大于区间长度这条约束，是整套方法成立的前提。去掉它，候选可能压根不是答案。实测 5000 组小数组、每组 20 次随机查询：满足 2t 大于长度的 59121 次查询漏答 0 次；不满足的 40879 次里漏答 2200 次，错误率 5.38%。

漏答的形状长这样：[1,2,3,2] 问 t=2。2 出现 2 次，够 t，可区间长度 4、2t 等于 4 并不大于 4。摩尔投票的候选是 3，数出来只有 1 次，查询返回 -1，把真正的答案 2 漏掉了。根子在上一步那条不变式：非候选值的出现次数不超过 (区间长度 减 血量) 除 2，t 落进这个范围时，够 t 的数未必是候选。

七、复杂度分析

项大于 n/k子数组海王
预处理O(n·k)O(n log n)
单次查询—（一轮扫描出全部答案）O(log n)
验证计数O(k·n)O(log n)
空间O(k)O(n)

大于 n/k 一遍扫描每个元素要扫 k−1 个槽位，时间 O(nk)；它赢在空间，k−1 个计数器和值域无关。实测 n=10⁶、值域 1000：k=3 时 3.038ms，哈希计数 2.798ms，时间上已经打平，k=5 时 3.866ms 反而更慢，省空间才是它的地盘。

子数组海王预处理排序加建树 1.512ms（n=2×10⁴），10⁴ 次查询共 2.605ms；同样的查询每次暴力数一遍要 3921.520ms。空间按题目上限算：排序数组 2n 个整数、线段树 4n 对（候选，血量），都是 O(n)。

八、总结

大于 n/k 的数最多 k−1 个，k−1 个计数器分三步更新：匹配加血、占位入住、全减丢弃。不变式 n = H + kR 保证真正的水王一定活着，但血量不是次数，收集时必须逐个数一遍，实测信血量的错法错率超过七成。

子数组海王靠题目里 2t 大于区间长度的保证：够 t 次就是严格众数，摩尔候选一定命中。线段树每个结点存（候选，血量），查询走 O(log n) 个结点；（值，下标）排序后两次二分数出真实次数。去掉 2t 的保证，漏答率 5.38%，有保证时 0。

从 n/2 到 n/k 再到线段树，变的只是计数器个数和存放位置，配对抵消的内核没有动。凡是能两两抵消的信息，都能照这个套路合并且预先存进树里。
