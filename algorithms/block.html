分块算法

把数组切成若干块，整块的和预先算好。查询时整块直接取，只有两端的零散元素才逐个处理。

零、背景

比赛里经常遇到这种题：一个数组，改一改，查一查，两种操作混着来，做几万次。

线段树和树状数组能处理，复杂度是 O(log n)，但代码长，常数也不小。

分块是另一条路。思路直白，代码短，复杂度是 O(√n)。n 在 10⁵ 以内，或者对常数比较敏感的时候，往往够用。

下面从一个具体问题出发，把分块是怎么来的推一遍。

一、问题

有一个长度为 n 的数组 a，要支持两种操作。

  • 查询：给一个区间 [l, r]，求 a[l] 到 a[r] 的和。
  • 修改：把 a[i] 改成新值 x。

两种操作交替出现，一共 m 次。

举例用下面这个数组，n = 16。

a = [3, 1, 4, 1, 5, 9, 2, 6, 5, 3, 5, 8, 9, 7, 9, 3]

后面的图和演示都用这一份数据。

二、朴素做法

查询的时候，从 l 一路加到 r。

int query(int l, int r) {
    int ans = 0;
    for (int i = l; i <= r; i++)
        ans += a[i];
    return ans;
}

修改不用循环，直接赋值 a[i] = x。

可以发现，查询最坏要加 n 个数，是 O(n)；修改是 O(1)。m 次操作里大部分是查询时，总时间就是 O(nm)。n 和 m 都到 10⁵，这个量级跑不完。

三、分块

查询慢在一个一个地加。

那能不能先把一部分和算好存起来，查询时直接取？可以。把数组切成若干段，每段叫做一个块，然后预先算出每个块的和 block_sum。

切法很随意，按位置每 B 个元素切一刀就行，最后一个块可以不满。第 i 个元素属于第几块，就是 i / B。

预处理只要扫一遍数组，把每个元素加到它所在块的和上，O(n)。

四、查询

现在看查询 [l, r]。区间里的元素按块分成三类。

第一类是完整块，整个块都落在 [l, r] 里面，直接把 block_sum 加上，一步到位。

第二类是左端的零散元素。l 不一定正好在块首，它所在块里位于 l 之前的元素不属于区间，所以这一整块不能拿来用，只能从 l 一个一个加到块尾。

第三类是右端的零散元素，同理，从块首一个一个加到 r。

具体来说，l 恰好在块首时左端没有零散元素，r 恰好在块尾时右端没有零散元素。l 和 r 落在同一个块里时，整个区间都是零散元素，一个完整块也取不到。

于是查询就按这三段依次处理，代码也是这三段的直接翻译。

int query(int l, int r) {
    int ans = 0;
    while (l <= r && l % BS != 0) {    // 左端零散元素，逐个加
        ans += a[l]; l++;
    }
    while (l + BS - 1 <= r) {            // 完整块，直接取块和
        ans += block_sum[bid(l)]; l += BS;
    }
    while (l <= r) {                     // 右端零散元素，逐个加
        ans += a[l]; l++;
    }
    return ans;
}

完整块最多 n / B 个，两端零散元素加起来最多 2B 个，所以一次查询是 O(n/B + B)。

五、修改

改 a[i] 时，把它所在块的和加上新旧值的差就行。

void update(int pos, int val) {
    block_sum[bid(pos)] += val - a[pos];  // 加上新旧值的差
    a[pos] = val;
}

这里有个细节，得先算差值再覆盖，顺序反了旧值就丢了。代价是 O(1)。

六、块大小取多少

一次查询的代价是 n/B + B。

B 取得太小，块就多，完整块那一半 n/B 变大；B 取得太大，零散元素那一半 2B 变大。

可以发现，两边相等时总和最小，也就是 n/B = B，得 B = √n，此时查询是 O(√n)。

实际做题不必严格卡在 √n。题目对修改和查询的偏重不一样，取 √n 附近的整数往往更快，例如 400、700 这类常见值，按实测调。

七、代码

#include <bits/stdc++.h>
using namespace std;

const int N = 16;
int a[N] = {3, 1, 4, 1, 5, 9, 2, 6, 5, 3, 5, 8, 9, 7, 9, 3};
int n = N;

int BS, BN;
int block_sum[N];            // 块数不会超过 n，按 n 开够用

int bid(int i) {              // 第 i 个元素属于第几块
    return i / BS;
}

// 预处理：算好每个块的和
void build() {
    BS = (int)sqrt(n);            // 块大小，√16 = 4
    BN = (n + BS - 1) / BS;       // 块数
    for (int i = 0; i < n; i++)
        block_sum[bid(i)] += a[i];
}

// 修改：改一个元素，同步更新它所在块的和
void update(int pos, int val) {
    block_sum[bid(pos)] += val - a[pos];
    a[pos] = val;
}

// 查询：区间 [l, r] 的和
int query(int l, int r) {
    int ans = 0;
    while (l <= r && l % BS != 0) {  // 左端零散元素，逐个加
        ans += a[l]; l++;
    }
    while (l + BS - 1 <= r) {          // 完整块，直接取块和
        ans += block_sum[bid(l)]; l += BS;
    }
    while (l <= r) {                   // 右端零散元素，逐个加
        ans += a[l]; l++;
    }
    return ans;
}

int main() {
    build();
    cout << query(2, 12) << endl;   // 4+1 + 22 + 21 + 9 = 57
    update(0, 10);
    cout << query(0, 3) << endl;    // 16
    return 0;
}

八、复杂度分析

设 n 为数组长度，B 为块大小，块数是 n/B。

预处理是扫一遍数组把每个块的和累加起来，O(n)。查询前一半是完整块，最多 n/B 个，后一半是两端零散元素，最多 2B 个，合起来 O(n/B + B)。修改只动一个元素和一个块和，O(1)。

操作时间复杂度
预处理 buildO(n)
查询 queryO(n/B + B)，B = √n 时是 O(√n)
修改 updateO(1)
m 次操作总计O(n + m√n)

空间上只多开了一个 block_sum，长度是块数 n/B，取 B = √n 时是 O(√n)。原数组本身不算额外开销。

对比一下，朴素做法 m 次查询是 O(nm)，分块把每次查询从 O(n) 压到 O(√n)，这就是它带来的收益。

九、最后

分块的价值不在复杂度有多低，而在通用。

只要块内的信息能快速合并、又能快速重建，同一个骨架就能套到不同问题上。求区间和时块内存的是和，求区间最大值时块内存的是最大值，求区间众数时块内存的是计数表，查询的写法都是两端零散逐个处理、中间整块直接取。

代价是复杂度只有 O(√n)，n 到 10⁵ 以上就吃力了，那时候还是得上线段树或者树状数组。
