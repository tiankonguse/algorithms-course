dfn 序求 LCA

欧拉序把树拍成长度 2n - 1 的序列，表也跟着变大。这一节换成 dfn 序：只记录每个点进入的时刻，序列长度就是 n，存的内容也从「节点」改成「父亲」。常数砍到欧拉序的一半，查询依旧 O(1)。

零、背景

上一节的欧拉序做法里，序列每个位置存的是节点本身，比较「谁更上方」靠 first 时刻。那套流程完全正确，但表建在 2n - 1 长度上，n = 5 × 10⁵ 时序列就有约 10⁶ 项，乘上 log 层，内存不小。

可以发现一个事实：查询时需要的只是「区间里谁最靠上」，而这个候选集合里根本不含两个查询点自己。既然如此，序列换成 dfn 序（每个点只出现一次）、存值换成「它的父亲」，区间最靠上的父亲同样给出 LCA。表长直接从 2n - 1 降到 n。

一、问题

题目和上一节完全相同：n 个节点、n - 1 条边组成一棵树，给定树头 root，m 条查询 u v，打印最低公共祖先。1 ≤ n、m ≤ 5 × 10⁵。测试链接：https://www.luogu.com.cn/problem/P3379。

朴素做法不再重复。这一节关心的是：同样 O(1) 查询的框架下，怎么把预处理和空间的常数压下去。

二、dfn 序和「父亲表」

DFS 时给每个点编号：进入 u 的时刻记为 dfn[u]，从 1 到 n 各不相同。这个编号就是 dfn 序。

关键设计在表里存什么。rmq[dfn[u]][0] 存的不是 u，而是 u 的父亲 fa。rmq[i][p] 的含义变成：dfn 序第 i 到第 i + 2^p - 1 号位置上，所有节点的父亲里，最上方的那个父亲。

「最上方」的判定也换了个比较对象：getUp(x, y) 返回 dfn[x] < dfn[y] 的那个。和上一节一样，单独两个节点之间「dfn 小 = 深度浅」并不总成立；成立的是区间性质：查询区间里所有节点的父亲，要么是 LCA 本身，要么是 LCA 的严格后代，后者的 dfn 都比 LCA 大。所以按 dfn 取小，正好挑出 LCA。root 的父亲记为 0，dfn[0] 初始化为 0。这个 0 只出现在第 1 号位置（root 自己那格），而查询区间左端至少是 2，永远盖不到第 1 号位置，所以 0 从不参与比较，也不会被误当成答案。

三、为什么「区间最上父亲」就是 LCA

考虑查询 u ≠ v，设 dfn[u] < dfn[v]。查区间 [dfn[u] + 1, dfn[v]]，注意左端从 u 的下一位开始。区间里的节点全在 LCA 的子树里，LCA 自己不在其中，因为它比 u 进入得早，dfn 更小。

这些节点的父亲里，一定有一个是 LCA：u 的子树走完后，DFS 进入的下一个分支顶端，父亲正是 LCA，而 v 就在这个分支里。其余的父亲都是 LCA 的严格后代，dfn 都比 LCA 大。所以区间里按 dfn 取最小的父亲，取到的正是 LCA。

左端为什么 +1？把 u 自己排除在区间外。这样区间里的节点都是 u 之后进入的，父亲全是 LCA 或 LCA 的后代，上面的论证干干净净。

四、必须特判 u 等于 v

欧拉序做法里 u = v 不用管；这里不行。若 u = v，区间左端 dfn[u] + 1 会越过右端 dfn[v]，查表完全落空。

所以 getLCA 开头一行：x 等于 y 直接返回。这是 dfn 序做法唯一需要特判的地方，也是最容易漏的一处。

五、建表与查询

建表流程和欧拉序那版同构：先 DFS 拿 dfn 和第 0 层父亲表，再逐层倍增。唯一的差别是序列长度换成 n，lg2 只需预处理到 n。

查询时把两点换算成 dfn，令 x < y，x 自增 1，然后在 [x, y] 上做标准稀疏表查询：k = lg2[y - x + 1]，两段长 2^k 的区间各取一次 getUp。前面说过，两段重叠没关系，「取最上」这个操作幂等。

完整代码：

#include <bits/stdc++.h>

    using namespace std;

    const int MAXN = 500001;
    const int MAXP = 20;
    int n, m, root;

    int headg[MAXN];
    int nextg[MAXN << 1];
    int tog[MAXN << 1];
    int cntg;

    int dfn[MAXN];
    int lg2[MAXN];
    int rmq[MAXN][MAXP];
    int cntDfn;

    void addEdge(int u, int v) {
        nextg[++cntg] = headg[u];
        tog[cntg] = v;
        headg[u] = cntg;
    }

    int getUp(int x, int y) {
        return dfn[x] < dfn[y] ? x : y;
    }

    void dfs(int u, int fa) {
        dfn[u] = ++cntDfn;
        rmq[dfn[u]][0] = fa;
        for (int e = headg[u]; e > 0; e = nextg[e]) {
            int v = tog[e];
            if (v != fa) {
                dfs(v, u);
            }
        }
    }

    void buildRmq() {
        dfs(root, 0);
        for (int i = 2; i <= n; i++) {
            lg2[i] = lg2[i >> 1] + 1;
        }
        for (int pre = 0, cur = 1; cur <= lg2[n]; pre++, cur++) {
            for (int i = 1; i + (1 << cur) - 1 <= n; i++) {
                rmq[i][cur] = getUp(rmq[i][pre], rmq[i + (1 << pre)][pre]);
            }
        }
    }

    int getLCA(int x, int y) {
        if (x == y) {
            return x;
        }
        x = dfn[x];
        y = dfn[y];
        if (x > y) {
            swap(x, y);
        }
        x++;
        int k = lg2[y - x + 1];
        return getUp(rmq[x][k], rmq[y - (1 << k) + 1][k]);
    }

    int main() {
        ios::sync_with_stdio(false);
        cin.tie(nullptr);
        cin >> n >> m >> root;
        for (int i = 1, u, v; i < n; i++) {
            cin >> u >> v;
            addEdge(u, v);
            addEdge(v, u);
        }
        buildRmq();
        for (int i = 1, u, v; i <= m; i++) {
            cin >> u >> v;
            cout << getLCA(u, v) << '\n';
        }
        return 0;
    }

六、各种 LCA 算法对比

到这里，静态树求 LCA 的几条路都齐了，放在一张表里看：

做法预处理时间预处理空间单次查询
树上倍增O(n log n)O(n log n)O(log n)
Tarjan 离线O(n + m)O(n + m)均摊 O(1)，只能离线批处理
重链剖分O(n)O(n)O(log n)
欧拉序 + 倍增表O(n log n)O(n log n)O(1)
dfn 序 + 倍增表O(n log n)O(n log n)O(1)，常数约欧拉序的一半

可以发现没有全胜的做法：重链剖分预处理最省但查询带 log；Tarjan 查询快但只能离线；两种序配倍增表把查询压到 O(1)，付出的都是 O(n log n) 的预处理。按「在线还是离线、查询多不多、内存紧不紧」三个问题选型就行。

顺带一提，序 + 稀疏表这条路还能继续走到 ±1 RMQ，把预处理也压成 O(n)，不过那套实现复杂，竞赛里 dfn 序 + 倍增表已经够用。

七、复杂度分析

和欧拉序版本逐项对比，结构相同，规模减半。

步骤时间复杂度空间复杂度
DFS 求 dfn 与第 0 层父亲表O(n)O(n log n)
预处理 lg2 数组O(n)
倍增表逐层递推O(n log n)
单次查询 getLCAO(1)O(1)

表的行数是 n 而不是 2n - 1，层数是 log n 而不是 log(2n - 1)，时间与空间的常数都约为欧拉序做法的一半。查询侧两版完全一样：一次换算、一次比较、两次查表。

八、最后

dfn 序求 LCA 是欧拉序那套的「减脂版」：序列砍一半、存值换成父亲、多一行 u = v 特判，其余分毫不差。两节连起来看，「树 → 序列 → 区间最值 → O(1) 查询」这条主线就完整了。

这些做法都只对静态树成立。树会变形时求最低公共祖先，LCT 是经典方案之一，后面的课程会专门安排。
