树上启发式合并

每棵子树的统计各问一遍，最直白的做法是对每个点从头数一遍，整棵树 O(n²)。树上启发式合并换了个思路：重儿子的统计留着复用，只有轻儿子才重新扫一遍。于是每个点被重复扫的次数不超过 log n。

零、先说启发式合并本身

从一个简单的问题开始。假设一共有 n 个人，初始时每个人各自成一个集合，期间不断有合并集合的行为发生。任意两个集合进行合并时，小集合里的每个人都会喊一次「呼哈」。所有人都在一个集合时过程停止。问最多能听到多少次「呼哈」。

答案是 O(n log n)。关键在于谁喊：喊的人永远来自小集合，喊完他就落进了一个至少大两倍的新集合。一个人下一次再喊，说明他所在的集合又被人合并了，而那时他的集合至少翻了一倍。集合大小从 1 开始，翻 log n 次就到 n 了，所以每个人最多喊 log n 次。

三层加起来 4 + 4 + 4 = 12 次。n = 8 时上界是 8 × 3 = 24。这个「小集合往大集合里倒」的动作就是启发式合并，后文所有复杂度都建立在这一个观察上。

一、把这件事放到树上

树上启发式合并（dsu on tree）适用的问题有两个特征：

  1. 没有修改操作。
  2. 可以通过遍历子树、建立信息统计，得到所有查询的答案。

核心是一个函数 dfs2(u, keep)。u 是当前节点，keep 表示 dfs 结束时是否保留子树 u 对信息的贡献。过程分成六步：

  1. 先遍历所有轻儿子的子树，遍历结束时消除对信息的贡献：dfs2(轻儿子, 0)。
  2. 再遍历唯一重儿子的子树，遍历结束时保留对信息的贡献：dfs2(重儿子, 1)。
  3. 考察单个节点 u，对信息进行贡献。
  4. 再遍历所有轻儿子的子树，上面的每个节点都重新对信息进行贡献。
  5. 得到子树 u 的答案。
  6. 如果 keep == 0，消除子树 u 的贡献；如果 keep == 1，保留。

这里的重儿子就是树链剖分里那个儿子：子树最大的那个。dfs1 先跑一遍，把 fa、siz、son 都记下来。

void dfs1(int u, int f) {
        fa[u] = f;
        siz[u] = 1;
        for (int e = head[u], v; e > 0; e = nxt[e]) {
            v = to[e];
            if (v != f) {
                dfs1(v, u);
            }
        }
        for (int e = head[u], v; e > 0; e = nxt[e]) {
            v = to[e];
            if (v != f) {
                siz[u] += siz[v];
                if (son[u] == 0 || siz[son[u]] < siz[v]) {
                    son[u] = v;
                }
            }
        }
    }

第 1 步为什么要取消贡献？因为不希望这个轻儿子的信息干扰到别的子树。第 4 步又为什么要把它们加回来？因为子树 u 的答案要统计整个子树，一个都不能少。

这里有个细节值得停下来看一眼：第 6 步的 cancel 看上去只负责消除子树 u 自己的贡献，实际上它一定会把全局统计清空。原因是所有轻儿子都先于重儿子被处理完了，此时「全局」里剩下的东西恰好就是子树 u 的全部。

走完一遍可以发现三件事。第一，处理 3 和 4 的时候，桶每次都被清空了，因为它们是轻儿子，keep 传的是 0。第二，处理重儿子 2 的时候，桶里一直留着 2、6、10、5 四个点，因为 keep 是 1，这份统计直接被 1 号拿去用了。第三，1 号自己只在最后贡献了一次，它的两个轻儿子 3 和 4 各被扫了两遍（一遍取消、一遍重新贡献），重儿子 2 一次都没有重扫。

三、复杂度为什么是 O(n log n)

担心的地方有两处：每个轻儿子遍历完要重新贡献一遍，取消时又要扫一遍，这两趟加起来的复杂度会不会太高。

不会。因为一个节点只有在某个轻儿子里时，重新贡献和取消贡献的行为才会发生；而每经过一次轻边往下走，所在子树的大小至多减半，反过来从下往上看，它每次被重扫时所在的集合都至少翻倍。

于是每个节点被 effect 和 cancel 扫到的总次数是 O(log n)，全部节点加起来 O(n log n)。加上每个节点自己被贡献一次、每个答案被记录一次，整个过程就是 O(n log n)。

四、题目1：模版题

一共有 n 个节点，编号 1 到 n，给定 n − 1 条边，所有节点连成一棵树，1 号节点为树头。每个节点给定一种颜色值。一共有 m 条查询，每条查询给定参数 x，打印以 x 为头的子树上一共有多少种不同的颜色。1 ≤ n、m、颜色值 ≤ 10⁵。测试链接：U41492。

信息统计就是三样东西：colorCnt[c] 记颜色 c 出现了几次，diffColors 记当前有几种颜色的计数非零，ans[u] 记答案。贡献一个节点时把它的颜色计数加一，如果加完之后是 1，说明这是一种新出现的颜色，diffColors 跟着加一。

void effect(int u) {
        if (++colorCnt[arr[u]] == 1) {
            diffColors++;
        }
        for (int e = head[u], v; e > 0; e = nxt[e]) {
            v = to[e];
            if (v != fa[u]) {
                effect(v);
            }
        }
    }

cancel 的写法有两种。上面那个模版题用的是「直接清零」：既然 cancel 被调用时全局统计恰好是子树 u 的内容，把经过的每个颜色计数置 0 就够了。另一种写法是严格做 effect 的逆操作，下一节的颜色平衡题会用到。两种都对，区别在于信息统计是不是「可逆」的：如果维护的是 max 之类的东西，就只能整体清零。

void cancel(int u) {
        colorCnt[arr[u]] = 0;
        for (int e = head[u], v; e > 0; e = nxt[e]) {
            v = to[e];
            if (v != fa[u]) {
                cancel(v);
            }
        }
    }

然后是 dfs2 本身。六步和前面列的完全一致：轻儿子不保留、重儿子保留、自己贡献一次、轻儿子重新贡献、记答案、按 keep 决定清不清理。

void dfs2(int u, int keep) {
        for (int e = head[u], v; e > 0; e = nxt[e]) {
            v = to[e];
            if (v != fa[u] && v != son[u]) {
                dfs2(v, 0);
            }
        }
        if (son[u] != 0) {
            dfs2(son[u], 1);
        }
        if (++colorCnt[arr[u]] == 1) {
            diffColors++;
        }
        for (int e = head[u], v; e > 0; e = nxt[e]) {
            v = to[e];
            if (v != fa[u] && v != son[u]) {
                effect(v);
            }
        }
        ans[u] = diffColors;
        if (keep == 0) {
            diffColors = 0;
            cancel(u);
        }
    }

这里有个容易看漏的地方：effect(v) 和 cancel(u) 都是递归整棵子树，不是只处理一个点。它们看起来是 O(子树大小) 的，但按上一节的分析，这两个函数在整个 dfs 里被调用的总次数是 O(n log n)。

main 里先 dfs1(1, 0) 算出 siz 和 son，再 dfs2(1, 0)，之后查询直接查 ans 数组，单次 O(1)。

复杂度分析

环节复杂度
dfs1 求 siz、sonO(n)
dfs2 全部调用O(n log n)
effect / cancel 的累计代价O(n log n)
单次查询O(1)

空间：head/to/nxt 前向星存 2(n−1) 条边，fa/siz/son/colorCnt/ans 各 n 个 int，全部是 O(n)。dfs2 的递归深度最坏是链长 O(n)，n = 10⁵ 时在本机默认栈上通常过不去，需要开大栈或者改成迭代。

最后

整套框架里，唯一会随着题目变化的就是「信息统计」这四个字具体指什么。模版题里它是一个颜色计数数组加一个计数器。下一节换成两个，一个记录「出现 k 次的颜色有几种」，一个记录「当前最大出现次数是多少」，去回答颜色平衡的子树和主导颜色累加和。
