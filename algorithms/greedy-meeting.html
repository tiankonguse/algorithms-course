贪心：会议的两种排法

一堆会议摆在时间轴上，要你尽量多参加。规则有两种：一种要求整段时间独占，另一种只用从会期里抽出一天。两种规则看着接近，做法却差得远：前者排一次序扫一遍就完，后者要拿一个堆盯着谁快过期。

零、独占整段：先试试最直觉的排法

先看规则一：给若干会议的开始、结束时间，参加某个会议的那段时间里不能参加别的会议，求最多能参加几个。

边界先定清楚：[1,3] 和 [3,4] 可以连着参加。前一个 3 点结束，后一个 3 点开始，中间没有重叠。这个「正好接上」的细节后面要用。

最顺手的想法是按开始时间排序，能塞就塞。看一组数据就知道不行。

[0,5] 排在最前面，先把它收下，时间就被占住 0 到 5。接下来 [1,2]、[2,3] 全撞在它身上，只剩 [5,10] 还能接上，一共 2 个。换成按结束时间排，同样四个会议能参加 3 个：[1,2]、[2,3]、[5,10]。

这个错法在随机小数据上被抓到的比例是 31.58%，不算低，说明它错得挺稳定。

一、按结束时间排，扫一遍

换判据：每次都在还能参加的会议里，挑结束最早的那个。理由一句话就够：结束得越早，留给后面的时间越多。

把会议按结束时间从小到大排，用一个变量 cur 记住上一次参加的会议结束在几点，然后顺着扫：开始时间不小于 cur 就参加，cur 换成它的结束时间；否则跳过，接着看下一个。

为什么这样就对，可以用一次交换说清楚。设最优解里第一个会议是 x，而按结束时间排在最前面的是 e。e 的结束时间不会比 x 晚，所以把 x 换成 e 之后，最优解里的第二个会议照样接得上。也就是说，一定存在一个包含 e 的最优解。把 e 摘掉、对剩下的会议重做同一件事，归纳下去就是整个贪心。

代码于是只剩两件事：排序，扫描。

// 会议必须独占时间段：meeting[i] = {开始时间, 结束时间}
    // 按结束时间从早到晚看，能塞进去就塞，塞不进去直接跳过
    int maxMeeting(vector<vector<int>>& meeting) {
        sort(meeting.begin(), meeting.end(), [](const vector<int>& a, const vector<int>& b) {
            return a[1] < b[1];
        });
        int ans = 0;
        for (int i = 0, cur = -1; i < (int)meeting.size(); i++) {
            if (cur <= meeting[i][0]) {
                ans++;
                cur = meeting[i][1];
            }
        }
        return ans;
    }

二、数据量一上来，排序就不划算了

同一个题面换个数据范围，做法要跟着换。会议数量到 106、开始和结束时间也到 106 时，按结束时间排序要做 O(n log n) 次比较。

但时间是 106 这个量级，意思是可以直接开数组按时间扫，根本不排。

记 latest[e] 为「所有在 e 时刻结束的会议里，最晚的开始时间」，没有会议在 e 结束就记 −1。同一批在 e 结束的会议里，开始得越晚越有机会被塞进去，所以只留最晚的那个就够了。

然后让 end 从 0 往上扫，cur <= latest[end] 就参加一个，cur 变成 end。

实测 n=106：排序 64.90ms，计数扫描 2.01ms，差大约 32 倍，两边答案都是 1112。代价是开一个长度等于时间上界的数组，106 个 int 就是 4MB。

// 会议数量到 10^6、时间也到 10^6 时，排序不再划算：用计数数组代替排序
    // latest[e] = 结束时间是 e 的所有会议里最晚的开始时间，-1 表示没有会议在 e 结束
    int maxMeetingFast(vector<vector<int>>& meeting, int maxTime) {
        vector<int> latest(maxTime + 1, -1);
        for (int i = 0; i < (int)meeting.size(); i++) {
            int s = meeting[i][0], e = meeting[i][1];
            latest[e] = max(latest[e], s);
        }
        int ans = 0;
        for (int cur = 0, end = 0; end <= maxTime; end++) {
            // 同一结束时间的一批会议里，开始得越晚越有可能塞进去
            if (cur <= latest[end]) {
                ans++;
                cur = end;
            }
        }
        return ans;
    }

三、会议只占一天

规则二：会议的召开期还是 [开始, 结束]，但你只需要从会期里抽出一天参加；参加的那一天不能同时参加别的会议。

答案和上一题没有直接关系，思路也换了：按天走，每天处理当天到期的会议。

小根堆里放「已经开了、还没参加」的会议的结束时间，堆顶是最快过期的那个。从最早的一天扫到最晚的一天，每天做三件事：

1）把当天开始的会议全部压进堆；

2）把结束时间早于今天的会议丢掉，它们已经过期，再也参加不了；

3）堆非空就弹出堆顶，参加掉它，数量加一。

每天挑最快过期的，理由和上一题同源：它最急，今天不参加就作废。而今天这个名额留给截止更晚的会议也不吃亏，那些会议明天还有机会。

样例走一遍：[[1,2],[2,3],[3,4]] 是 3；[[1,1],[1,2],[1,3],[1,4]] 是 4，四场会议的截止时间是 1、2、3、4，正好一天一场；[[1,2],[2,3],[3,4],[1,2]] 也是 4。实测 105 场会议、天数也在 105 以内，用时 9.34ms。

// 会议只占一天：events[i] = {开始时间, 结束时间}，参加的这一天只能参加这一个会议
    // 按天扫过去，每天先收下当天开始的会议，把已经过期的丢掉，还剩就挑一个参加
    int maxEvents(vector<vector<int>>& events) {
        int n = events.size();
        sort(events.begin(), events.end(), [](const vector<int>& a, const vector<int>& b) {
            return a[0] < b[0];
        });
        int maxDay = events[0][1];
        for (int i = 1; i < n; i++) {
            maxDay = max(maxDay, events[i][1]);
        }
        // 小根堆放会议的结束时间，堆顶是当前最早过期的会议
        priority_queue<int, vector<int>, greater<int>> heap;
        int i = 0, ans = 0;
        for (int day = events[0][0]; day <= maxDay; day++) {
            while (i < n && events[i][0] == day) {
                heap.push(events[i++][1]);
            }
            while (!heap.empty() && heap.top() < day) {
                heap.pop();
            }
            if (!heap.empty()) {
                heap.pop();
                ans++;
            }
        }
        return ans;
    }

五、对数器怎么抓错

独占整段那题，随机小数据 5000 组，各错法的抓取比例：

错法抓取比例
按开始时间排序31.58%
按结束时间从晚到晚排（降序）70.48%
按会议持续时间从短到长排47.38%
判据写成 cur < start，把「正好接上」判成冲突29.26%

最后那条随值域变化很快，因为「两个会议正好首尾相接」本身就是小值域才常见的事：

开始、结束时间的值域写成 < 的抓取比例
0 到 265.82%
0 到 547.60%
0 到 1128.74%
0 到 497.72%
0 到 9990.58%

值域一放宽，两个会议恰好相邻的概率就掉下去，写错等号也很难被抓出来。所以验证边界时，数据要往小值域里造。

只占一天那题，同样 5000 组：

错法抓取比例
每天挑堆里结束最晚的18.84%
只把会议安排在每个会议开始的那一天49.94%
过期会议不清理3.04%（值域 0 到 5）

「过期不清理」这条只在窄值域下露馅：值域放到 0 到 49 就掉到 0.00% 了。会议只有几个、可用天数却很多的时候，怎么安排都能全参加完，错法也就看不出差别。

复杂度分析

题目关键操作时间空间
独占整段（排序版）按结束时间排序 + 一次扫描O(n log n)O(1)，只多一个 cur
独占整段（计数版）填 latest 数组 + 按时间扫描O(n + T)，T 是时间上界O(T)，计数数组
只占一天按开始时间排序 + 每天一次堆操作O(n log n + D log n)，D 是天数O(n)，堆里最多 n 个结束时间

计数版是拿空间换时间：时间上界 T 不大的时候，O(n + T) 明显比 O(n log n) 划算；T 到 109 就不能这么开了。

只占一天那题的天数是「最大结束时间 − 最小开始时间」，并不等于 n，所以 D 可以远大于 n，写代码时要按数据的最大值来循环，而不是按会议数量。

总结

两题排序依据不同，推理方式却是同一个：把「先做哪一个」缩到两个候选上比一比。独占整段比的是结束时间，早结束的先做；只占一天因为一天只能塞进一个会议，比的是谁先过期，最急的先做。

顺带记下两个数据量带来的分岔。时间上界不大的时候，计数数组能把排序整个省掉，106 规模下快了 32 倍；而边界判据一定要在小值域上验证，否则等号写错也抓不出来。
