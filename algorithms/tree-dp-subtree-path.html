树型 dp：子树聚合与最长路径

树型 dp 的返回值不一定是复杂结构。有时候只要一个数：这棵子树里有几个人、从自己往下最长能走多远。父节点把这个数和自己这边的数合一下，答案就往上滚一层。

零、返回值可以只是一个数

树上的依赖关系简单：子树算完，父节点就有原料了。有一类题的返回值干脆退化成单个整数。

单整数好写，是因为合并规则就那么两条：子节点返回子树人数，父节点把几个人数加起来；子节点返回一条链的长度，父节点取最长的再加一。

麻烦在另一处。答案不一定落在根上。一条最长路径可能整条躲在某个子树里，根本不过根。所以返回值里常常要顺带揣一个「已经算出来的最优值」，每合一个儿子就更新一次。

这一页的两道题都是这个形状，第二道还多一层：拼两条链的时候，得记住最长的两条，只记一条会漏掉答案。

一、到达首都的最少油耗

给一棵 n 个节点的树，0 号是首都。每个城市里有一个人，都要去首都。每座城市有一辆车，一辆车有 seats 个座位，人可以在中途换乘别人的车。相邻城市之间跑一趟烧一升油，问所有人到齐最少烧多少油。

先看一条边。把树以 0 为根，边 (u, v) 里 v 是 u 的儿子。v 下方有多少个人，就有多少个人必须从这条边往上走，一个都少不掉。

这些人都得上车。一辆车 seats 个座，所以至少需要 ceil(sv / seats) 辆车，其中 sv 是 v 这棵子树里的人数。

关键观察在这里：一条边要派几辆车，只取决于它下方的人数，和别人怎么坐车没关系，各条边互不干扰。于是总油耗就是所有边的车次数之和。

算这个和只要知道每棵子树里有多少人。返回值就定成这个数。合并分三步：

  1. 先算所有儿子，各自返回自己子树的人数 sv；
  2. 边 (u, v) 贡献 ceil(sv / seats) 辆车，加进 u 的账上；
  3. u 这棵子树的人数，是自己的 1 个加上所有儿子的 sv。

儿子的账先算完，再往上并，这就是一次后序遍历。

// 返回以 u 为根的子树里有几个代表；顺带把子树内的油耗累加进 cost
    int f(vector<vector<int>>& g, int seats, int u, int p, vector<long long>& cost) {
        int sz = 1;
        for (int v : g[u]) {
            if (v == p) continue;
            int sv = f(g, seats, v, u, cost);
            sz += sv;
            // 边 (u,v) 下方有 sv 个人要过，需要 ceil(sv / seats) 辆车
            cost[u] += cost[v] + (sv + seats - 1) / seats;
        }
        return sz;
    }

    long long minimumFuelCost(vector<pair<int, int>>& roads, int seats) {
        int n = roads.size() + 1;
        vector<vector<int>> g(n);
        for (auto& r : roads) {
            g[r.first].push_back(r.second);
            g[r.second].push_back(r.first);
        }
        vector<long long> cost(n, 0);
        f(g, seats, 0, -1, cost);
        return cost[0];
    }

向上取整写成 (sv + seats - 1) / seats。别图省事写 sv / seats，那是向下取整，会少派车。实测在随机小树上，把向下取整混进去的版本 75.42% 出错：只要某棵子树的人数不是 seats 的整数倍，油耗就偏小。

二、相邻字符不同的最长路径

给一棵树，每个节点分到一个字符 s[i]。找一条路径，要求路径上任意一对相邻节点的字符都不同，返回这条路径的节点数。

朴素做法是枚举两个端点，再把它们之间的路径拉出来逐对比较字符，一棵 n 个点的树大致要 O(n³)。

换成 dp，返回值放两个数：

  • fromHead：一定要从自己出发往下走、且相邻字符都不同的最长链长度，含自己；
  • best：这棵子树内部最长路径的长度。

合并时，best 先继承所有儿子的 best，这三条路都不过 u。还有第四条：路径在 u 这里拐一下，从两个儿子各接一条链下来。

要接就得挑两条最长的。挑的时候有个限制：儿子 v 的字符必须和 s[u] 不同，接上去才合法。所以要维护可接的两条链：最长的那条，和次长的那条。

漏掉次长链，就等于默认答案的那条路径只从 u 往一个方向走。实测在字母表只有 2 个字符的随机树上，这个版本 42.23% 出错；字符表放宽到 4 个，出错率反而升到 62.12%，因为字符越杂，「两条链在 u 处拼起来」的机会越多。至于忘记字符必须不同这条限制，84.71% 出错。

struct Info {
        int fromHead;  // 从自己往下、相邻字符都不同的最长链，含自己
        int best;      // 整棵子树里最长的那条
    };

    Info f(vector<vector<int>>& g, string& s, int u) {
        if (g[u].empty()) return {1, 1};
        int max1 = 0, max2 = 0, best = 1;
        for (int v : g[u]) {
            Info nx = f(g, s, v);
            best = max(best, nx.best);
            if (s[u] != s[v]) {
                if (nx.fromHead > max1) {
                    max2 = max1;
                    max1 = nx.fromHead;
                } else if (nx.fromHead > max2) {
                    max2 = nx.fromHead;
                }
            }
        }
        // 最长的一条往下递，两条最长的一起在 u 处接起来当候选
        best = max(best, max1 + max2 + 1);
        return {max1 + 1, best};
    }

叶子节点返回 {1, 1}：只有一个点时，从自己出发的链就是自己，子树内最长的也是自己。这个基数挑错，往上合的时候整条链的长度都会差一个。

复杂度分析

题目时间空间
到达首都的最少油耗O(n)O(h)
相邻字符不同的最长路径O(n)O(h)

两题都是每个节点进一次、出一次，合并是常数次加法或比较，时间 O(n)。空间是递归栈，深度等于树高 h；一棵链状树 h = n，空间 O(n)。

递归深度是实测过的边界。本机 8 MB 栈下，油耗那版（带 vector 引用参数和一层循环）在链上最多撑到 73228 层；如果嫌不够，把遍历改成显式栈，或者干脆按 dfn 倒序迭代，都能绕开。

总结

返回值可以是单个整数。子树人数装进返回值，父节点一加就得到了自己的人数，顺带把边上的车次算进账里。

聚合量往上合的时候，答案常常顺手就出来了。油耗的答案在每条边上单独累加，最后落在根上。

另一类返回值要带一条「从自己往下」的量，比如最长路径里的 fromHead。这种题的通病是忘记跨过当前节点的那条路径，只继承了子树里的答案。

跨过当前节点的候选，往往要拼接两条链或两个区间。这时候记住最长的两条，比只记一条重要。字符、边权之类的限制还会决定「哪几条能拼」，漏掉限制条件，样例照样过。

把树拍成一段连续区间之后，还能换一种 dp 的角度：子树变成区间，节点的下属关系变成区间包含。下一类题就是这么做的。
