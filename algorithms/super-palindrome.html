超级回文数

L 和 R 用字符串给，范围到 1e18。逐个判断要一百多年，但题目把两个条件一起给了：它自己是回文数，同时还是一个回文数的平方。把「平方」这一步反过来用，候选就从 1e18 掉到 20 万。

零、背景

超级回文数的定义有两半：一个正整数本身是回文数，同时它还是一个回文数的平方。

121 = 11²，11 是回文数，121 也是，所以 121 达标。169 = 13²，169 不是回文数；196 是回文数吗？196 也不是，两边总得都满足才行。9 = 3²，3 和 9 都是回文数，所以 9 是最小的两位以下达标值。

这样的数非常稀疏。1e18 以内一共只有 70 个，在 long long 的整个范围内也只有 86 个。

一、问题

给定两个正整数 L 和 R，都以字符串形式给出，长度不超过 18，返回闭区间 [L, R] 里超级回文数的个数。

两个细节先记住：一是 L、R 用字符串给，说明它们可能大到接近 1e18；二是问的是个数，不是清单。

二、朴素做法

从 L 扫到 R：每个数先判回文，再开方，看根是不是整数、根自己是不是回文数。这个骨架没错，问题只在区间有多大。

本机扫 1e8 个数、只做最便宜的那一步（判回文）要 0.421s。同一个速度扫到 1e18 是 1e10 倍，约 133 年。

去掉「不是回文数」的那些能省下多少？1e18 以内的回文数约 21 亿个，占千亿分之二。就算只扫这 21 亿个，每个还要开方、再判一次回文，几十秒起步，而预算只有 1 秒。

所以「筛选」这一步救不了，得换掉枚举的对象。

三、把平方反过来用

题目给的区间是「平方之后的值」。换个说法：num² 落在 [L, R] 里，并且 num 和 num² 都是回文数，这样的 num 有几个。

num² ≤ R ≤ 1e18，于是 num ≤ √R ≤ 1e9。枚举的对象就从 1e18 个数换成了 1e9 以下的回文数，一共 109998 个。

这 11 万个候选逐个平方、判回文、看落不落在区间里，一次跑完 1.85ms。

回文数 ≤ 1e9 的个数可以按位数算出来：一位 9 个、两位 9 个、三位 90 个、四位 90 个、五位 900 个，往后每多两位乘 10，加起来 109998 个。

四、先把回文数造出来

怎么枚举 1e9 以下的回文数？「回文数字」那一页讲过路子：不去检查一个数是不是回文，而是直接造。左半边定下来，右半边就是它的镜像，没有自由度。

一个种子能造两个回文数：把种子翻一倍接在后面得到偶数长度，丢掉最后一位再翻一倍接上得到奇数长度。

比如种子 12：补成偶数长度是 1221，补成奇数长度是 121。造出来的两个数都是回文，接着平方看结果。

1221² = 1490841，翻过来是 1480941，两边不一样，这个候选不达标。121² = 14641，正反都是 14641，达标。

五、种子要走到多远

种子从 1 开始往上走。种子的位数越多，造出来的回文越长，两个函数都是随种子单调增的，所以走到「奇数长度那一支已经不小于 limit」就能停，这里 limit = √R。

R = 1e18 时 limit = 1e9，种子走到 100000 停：一共 10 万颗种子、20 万个候选，命中 70 个。

六、代码

判回文这里用除法取最高位，不用乘法，是为了避开溢出。

// 判断 num 是不是回文：先求出最高位的权重，再首尾成对往中间收
    bool isPalindrome(long long num) {
        long long offset = 1;
        while (num / offset >= 10) offset *= 10;   // 用除法找最高位，乘法会溢出
        while (num != 0) {
            if (num / offset != num % 10) return false;
            num = (num % offset) / 10;             // 掐掉头尾各一位
            offset /= 100;
        }
        return true;
    }

两个扩容函数，一个补偶数长度，一个补奇数长度。

// 种子补成偶数长度回文：123 -> 123321
    long long evenEnlarge(long long seed) {
        long long ans = seed;
        while (seed != 0) {
            ans = ans * 10 + seed % 10;
            seed /= 10;
        }
        return ans;
    }

    // 种子补成奇数长度回文：123 -> 12321
    long long oddEnlarge(long long seed) {
        long long ans = seed;
        seed /= 10;                    // 最后一位留在中间，不参与镜像
        while (seed != 0) {
            ans = ans * 10 + seed % 10;
            seed /= 10;
        }
        return ans;
    }

主循环就三件事：造两个候选、平方、判回文。守卫放在平方之前。

const long long SAFE = 3037000499LL;   // floor(sqrt(LLONG_MAX))，超过它平方就溢出

    int superpalindromesInRange(string left, string right) {
        long long l = stoll(left), r = stoll(right);
        long long limit = (long long)sqrt((double)r);   // 只需要枚举到根号 r
        long long seed = 1, num = 0;
        int ans = 0;
        do {
            num = evenEnlarge(seed);
            if (num <= SAFE &&
                num * num >= l && num * num <= r && isPalindrome(num * num)) ans++;
            num = oddEnlarge(seed);
            if (num <= SAFE &&
                num * num >= l && num * num <= r && isPalindrome(num * num)) ans++;
            seed++;
        } while (num < limit);
        return ans;
    }

七、溢出这道坎

候选里有一半是长号码。种子走到 100000 时，偶数长度那一支造出来的是 100000000001，平方是 1e22，早就超了 long long 的 9.22e18。

C++ 里 long long 溢出是未定义行为，编译器换个优化档位，结果都可能不一样。所以平方之前先挡一道：3037000499 是 √(long long 最大值) 向下取整，超过它的候选直接当无效跳过。

Java 那边溢出是明确定义的取模回绕。实测拿 2 万个区间对拍，回绕出来的值一个都没落进区间，答案一次都没被改过。这是巧合，不是可以不写的理由。

八、顺带一个打表法

答案实在太稀：long long 范围内 86 个，1e18 以内 70 个。把这 86 个数提前算好排成清单，一次查询就是在清单上找左右边界，连二分都省了。

// record 是预先算好的 86 个超级回文数（从小到大），一次查询只在清单上走两个指针
    int superpalindromesInRange2(string left, string right) {
        long long l = stoll(left), r = stoll(right);
        int i = 0;
        while (i < 86 && record[i] < l) i++;
        int j = 85;
        while (j >= 0 && record[j] > r) j--;
        return j >= i ? j - i + 1 : 0;
    }

1e18 内有 70 个，1e18 到 9.22e18 之间还有 16 个。清单只跑一次，之后每次查询都是扫 86 个数。

复杂度分析

做法时间额外空间说明
逐个检查O(R·log R)O(1)1e18 个数，实测扫一遍要 133 年
枚举回文数O(R1/4·log R)O(1)种子约 √(√R) 颗，每个候选的平方与回文判定是 O(log R)；R=1e18 实测 1.85ms
打表O(86) 查询O(86)清单离线算一次，之后每次查询扫一遍

空间是常数：造回文、平方、判回文都是就地算的，只有几个临时变量。

总结

候选从 1e18 掉到 20 万，靠两步。平方那一步把根压到 √R 以内；回文数在剩下这一段里只占万分之一。

造回文靠种子加镜像，一颗种子出两个长度，长度随种子单调增，走到 limit 就停。

C++ 里平方之前必须挡溢出，3037000499 是 √(long long 最大值) 向下取整。

答案非常稀疏，1e18 以内 70 个、long long 以内 86 个，直接打表也完全够用。
