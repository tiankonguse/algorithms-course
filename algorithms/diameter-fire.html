消防：在直径上选一段路

给定一个长度上限 s，在树上选一条总长不超过 s 的路径建消防站，让最远居民走到消防站的距离尽量短。结论有点反直觉：最优的那条路一定在某条直径上。于是问题变成在直径上开一个窗户，左右一滑，答案就出来了。

零、背景

前两课把直径求了出来，这一课用它。树上很多「选一条路」的问题，最优的那条路都能落到直径上，消防是其中最经典的一个：它要在直径上滑窗，还要一个单调队列帮忙。

一、问题

消防：n 个点的树，n − 1 条边，边权非负。给定非负整数 s，选一条长度不超过 s 的路径，在路径上的点建消防站，每个居民可以去这条路径上的任何消防站。目标让最远居民的步行距离尽量少，返回这个最小值。n 不超过 3×10⁵。

居民到消防站的距离，就是他到路径上最近那个点的距离。所以题目就是：选一条长 ≤ s 的路径 Q，最小化 max(所有点到 Q 的距离)。

二、结论：最优路径可以取在直径上

先说结论再给理由。一定存在一条最优路径，整条落在某条直径上。

理由是这样。设直径 D 的端点是 start 和 end，Q 是任意一条长不超过 s 的路径，a、b 是它的两个端点。把 a、b 分别沿树连到直径上，落点记为 pa、pb。取直径上 pa 到 pb 的那一段作为窗口 [l, r]（靠 end 一侧的叫 l，靠 start 一侧的叫 r）。这个窗口跟 Q 比，三头都亏不了：

1）长度。窗口长 dist(pa, pb)，而 a 到 b 的唯一路径必然经过 pa、pb 之间的那段直径，所以 dist(pa, pb) ≤ dist(a, b) ≤ s，窗口合法。
2）两侧。Q 上离 end 最近的点恰好就是 l：Q 从 a 爬到 pa、沿直径走到 pb、再爬下去到 b，挂在直径上的那两段只会离 end 更远。所以 dist(end, l) = dist(end, Q)。同理 dist(r, start) = dist(start, Q)。
3）窗口里面。对挂在窗口内某个直径点 p 上的任意居民 v，v 到 Q 上任何一点的路都要经过 p（Q 在直径上含 p，挂枝里的点要出来必须先到 p），而 p 自己就在 Q 上，所以 dist(v, Q) = dist(v, p)。也就是说，挂在窗口内的居民到 Q 的距离恰好等于到窗口的距离。

三路合起来：窗口的「最远居民距离」不超过 Q 的。既然任意 Q 都能被直径上的一段窗口顶掉，最优解一定能在直径上取到。

三、直径上的一段路，答案怎么算

窗口 [l, r] 定下来之后，最远居民分三类，各有一个代表距离：

1）住在 l 的 end 侧（含 end 自己）：最远的不会超过 dist(end, l)。
2）住在窗口里的直径点挂出来的树枝上：最远的是窗口内各点 maxDist 的最大值，maxDist[p] 表示从 p 出发不进直径能走的最远距离。
3）住在 r 的 start 侧（含 start 自己）：最远的不超过 dist(r, start)。

第 1、3 条能成立，靠的是一条支配引理：挂在直径点 p 上的树枝，长度不会超过 p 到任一端点的距离。要是比 dist(p, end) 还长，树枝尖走到 end 就超过直径了，自相矛盾。实测 5000 棵随机树上的 33000 个直径点，0 个违反。

所以窗口 [l, r] 的答案 = max(dist(end, l), 窗口内 maxDist 的最大值, dist(r, start))。注意第 3 项还顺手把 r 点自己的 maxDist 兜住了：r 上的树枝再长也长不过 dist(r, start)。

四、滑窗加单调队列

窗口要短（≤ s），又要尽量长：把窗口拉长只会覆盖更多点，最远距离不会变大。所以对每个 l，r 能塞多远就塞多远。而 l 往 start 侧走的时候，允许的 r 也只会越来越远，两个指针都只朝一个方向动，合起来每边走一遍。

麻烦在窗口内 maxDist 的最大值：l 一动，窗口进出都要更新。单调队列维护「下标递增、maxDist 递减」，队首就是窗口最大值，进出均摊 O(1)。

// 消防前置：两遍dfs定直径，再算每个直径点的两个量
    // pred[i] 是i到它在直径上前一个点的距离；maxDist[i] 是从i不进直径能走的最远距离
    void dfs(int u, int f, int w) {
        last[u] = f;
        dist[u] = dist[f] + w;
        pred[u] = w;
        for (int e = head[u]; e != 0; e = nxt[e]) {
            if (to[e] != f) {
                dfs(to[e], u, weight[e]);
            }
        }
    }

    // 不能走向直径路径上的节点，能走出的最大距离
    int maxDistanceExceptDiameter(int u, int f, int c) {
        int ans = c;
        for (int e = head[u], v; e != 0; e = nxt[e]) {
            v = to[e];
            if (!diameterPath[v] && v != f) {
                ans = max(ans, maxDistanceExceptDiameter(v, u, c + weight[e]));
            }
        }
        return ans;
    }

    void distance() {
        for (int i = ed; i != 0; i = last[i]) {
            diameterPath[i] = true;
        }
        for (int i = ed; i != 0; i = last[i]) {
            maxDist[i] = maxDistanceExceptDiameter(i, 0, 0);
        }
    }

滑窗本体：

// 滑窗：l 从直径一端走向另一端，r 是第一个放不进窗口的点
    // 窗口里的点建消防站，答案 = max(左侧距离, 窗口内maxDist, 右侧距离)
    // 单调队列维护窗口内的maxDist最大值
    int compute() {
        int suml = 0, sumr = 0;
        int h = 0, t = 0;
        int ans = INT_MAX;
        for (int l = ed, r = ed; l != 0; l = last[l]) {
            while (r != 0 && sumr - suml + pred[r] <= s) {
                while (h < t && maxDist[que[t - 1]] <= maxDist[r]) {
                    t--;
                }
                sumr += pred[r];
                que[t++] = r;
                r = last[r];
            }
            // 队列空时补 0：单点窗口的答案只由两侧距离决定
            int qmax = (h < t) ? maxDist[que[h]] : 0;
            ans = min(ans, max(max(suml, qmax), diameter - sumr));
            if (que[h] == l) {
                h++;
            }
            suml += pred[l];
        }
        return ans;
    }

代码里两个细节值得停一下。其一，队列里存的是 [l, r)，不含 r；候选值里的 dist(r, start) 已经把 r 点自己的 maxDist 兜住了（第三节的支配引理），所以不漏。其二，l 追上 r 时窗口缩成单点 {l}，队列空出来，队首要补一个 0 再读。单点窗口的答案本来就是 max(dist(end, l), dist(l, start))，maxDist[l] 被两侧距离兜住，补 0 不影响结果；不补的话读到的是上一轮留下的旧值，实测 6000 组小 s 的随机树加不加这个保护答案完全一致，但没必要赌这个。

递归深度还是那个老问题：算 maxDist 的 dfs 深度等于树高，链上就是 n。本机 g++ -O2、8MB 栈下实测这个递归约 13 万层见顶（每帧约 64 字节），n = 3×10⁵ 的链会爆栈。求直径那两趟 dfs 同理。稳妥做法是都改成显式栈，把「当前遍历到第几条边」压进栈里，弹栈时接着走。

拉出来实测一下差距。n = 2×10⁵ 的梳状树（主链 10 万，每个主链点挂一片叶子）、s = 10⁵：滑窗版 0.20ms，不用单调队列、每个 l 都重扫一遍窗口的朴素版 1936.26ms，差 9000 多倍，答案一致。换成 n = 6 万的链、s 大到覆盖整条直径（朴素版的最坏情况）：0.43ms 对 740.14ms，1700 多倍。单调队列在这里是能不能过的分界线。

空间按题目上限 n = 3×10⁵ 算：链式前向星三个 int 数组，dist、last、pred、maxDist 各一个，直径标记一个 bool 数组，单调队列一个，都是 O(n)。

六、总结

要点三条。其一，最优路径一定能落到直径上：把路径两个端点在直径上的落点之间的那段取出来，长度只减不增，而路径上离直径两端最近的点恰好就是窗口边界，挂在窗口内的居民到路径的距离恰好等于到窗口的距离，三头都不亏。其二，窗口答案 = max(左侧距离, 窗口内 maxDist 最大值, 右侧距离)，依据是「挂在直径点上的树枝长不过它到较近端点的距离」这条支配引理，33000 个直径点实测 0 违反。其三，l 每进一步就取最远的 r（路径拉长不会变差），单调队列把窗口最大值均摊到 O(1)，整体 O(n)；n = 2×10⁵ 上比朴素重扫快 9000 倍。

七、最后

这道题的手感在于「先证明能枚举什么，再想怎么枚举」。直径上一共 n 个窗口端点，看着很多，但两个指针各走一遍就扫完了。类似的「先缩范围再滑窗」在树上网问题、树形 dp 的题目里还会反复出现。
