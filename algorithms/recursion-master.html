递归与 Master 公式

递归的执行过程可以完全拆开看。函数调用自己，底层就是系统栈在帮你压栈、弹栈。把调用图画出来、把栈帧拆开看，递归就变成了一件可以精确分析的事。这一讲从一个求最大值的例子出发，看清楚递归怎么执行、栈怎么涨、怎么改成非递归，最后用 Master 公式一把算出复杂度。

零、背景

写递归的人常犯两个毛病。一是觉得递归「自己调自己」很神秘，跑起来全靠脑补，出了 bug 不知道从哪查。二是写完递归就不管了，数据量一大直接段错误，还以为是编译器的问题。

这两个毛病的根源是同一个：没把递归的执行过程看清楚。递归函数的每一次调用，系统都会在栈上压一帧，里面存着参数、局部变量、返回地址。调用到最深的地方开始返回，一帧一帧弹回来。把这个过程画成图，递归就和循环一样直白。

一、一个最简单的递归

求一个数组的最大值。最直接的写法是扫一遍，但这里故意用递归写：把数组从中间切成两半，分别求左半和右半的最大值，再取两者较大的那个。

int f(int* arr, int l, int r) {
        if (l == r) {
            return arr[l];
        }
        int m = (l + r) / 2;
        int lmax = f(arr, l, m);
        int rmax = f(arr, m + 1, r);
        return max(lmax, rmax);
    }

    int maxValue(int* arr, int n) {
        return f(arr, 0, n - 1);
    }

这段代码的关键在 f(arr, l, r) 这个函数。它的含义是「arr[l..r] 范围上的最大值」。终止条件是 l == r，范围里只剩一个数，它自己就是最大值。否则切成左右两半，各递归一次，最后 max 一下。

作为对照，遍历写法长这样：

int maxValue(int* arr, int n) {
        int ans = arr[0];
        for (int i = 1; i < n; i++) {
            if (arr[i] > ans) {
                ans = arr[i];
            }
        }
        return ans;
    }

两种写法的结果完全一样，但代价差很多。n=100 万时，递归版要 2.7ms，遍历版只要 0.087ms，差了约 30 倍。递归慢在函数调用上，每切一次就要压栈、弹栈，n 个元素要调用 2n-1 次函数。遍历版只有一个循环，硬件分支预测器还能帮上忙。

那为什么还要写递归？因为有些问题用递归写出来只有三行，用循环写要自己维护一堆状态。后面的归并排序、快速排序、二叉树遍历、线段树，全都是递归写起来最自然。

三、底层是系统栈

调用树是从「全局」看递归。从「局部」看，每一次函数调用都会在系统栈上压一帧。帧里存着参数（arr、l、r）、局部变量（m、lmax、rmax）、还有返回地址，等子调用回来后从哪条指令继续执行。

系统栈的空间不是无限的。macOS 默认给主线程的栈是 8176 KB，递归帧大约 32 字节一个（参数 + 局部变量 + 返回地址 + 对齐），算下来约 26 万层就会把栈撑爆，触发段错误。前面二叉树递归那讲实测过：260937 层能过，261000 层直接段错误。

链状递归最容易踩这个坑。比如求链表长度、沿一条路径往下走，递归深度就是数据规模本身。n=10 万的链表用递归写，在评测机上大概率段错误。这时候要么改成循环，要么自己在堆上开一个栈来模拟。

四、递归改非递归：自己压栈

任何递归都能改成非递归。做法是把系统栈做的事，自己用一个数据结构（通常是 vector 或 std::stack）模拟出来。每个栈帧存当前执行到哪一步了（state）、以及中间结果。

以求最大值为例，手动栈版本长这样：

struct Frame {
        int l, r, state;
        int lmax;
    };

    int maxValueManual(int* arr, int n) {
        vector<Frame> stk;
        stk.push_back({0, n - 1, 0, 0});
        int retval = 0;
        while (!stk.empty()) {
            Frame& top = stk.back();
            if (top.state == 0) {
                if (top.l == top.r) {
                    retval = arr[top.l];
                    stk.pop_back();
                } else {
                    top.state = 1;
                    int m = (top.l + top.r) / 2;
                    stk.push_back({top.l, m, 0, 0});
                }
            } else if (top.state == 1) {
                top.lmax = retval;
                top.state = 2;
                int m = (top.l + top.r) / 2;
                stk.push_back({m + 1, top.r, 0, 0});
            } else {
                retval = max(top.lmax, retval);
                stk.pop_back();
            }
        }
        return retval;
    }

核心是 state 这个字段。state=0 表示刚进入这个范围，要先算左半；state=1 表示左半算完了，返回值存在 retval 里，存进 lmax，接着算右半；state=2 表示右半也算完了，合并 max(lmax, retval) 再往上抛。

手动栈比系统栈慢一点，因为每一步都要自己判断 state、压栈弹栈，编译器没法像优化递归调用那样做内联和寄存器分配。std::stack 更慢，因为它默认基于 deque，每次 push/pop 都有额外的内存分配开销。用 vector 当栈是最划算的。

工程上几乎一定要把递归改成非递归，除非你确定数据量再大递归也不会深。归并排序、快速排序、线段树、平衡树，这些数据结构的递归深度都是 O(log n)，n 到 10⁹ 也才 30 层，递归没问题。但链状递归、图的 DFS（最坏一条链走到底），就必须改。算法比赛里能过就不改，工程代码里能改就改。

五、Master 公式

递归的复杂度怎么算？如果所有子问题的规模都相同，就可以用 Master 公式一把算出来。公式长这样：

T(n) = a · T(n/b) + O(nc)

其中 a 是子问题个数，b 是每个子问题相对原问题的缩小比例，nc 是当前层除了递归之外要做的工作量。a、b、c 都是常数。

比较 logba 和 c 的大小，分三种情况：

条件复杂度典型例子
logba < cO(nc)二分搜索：T(n)=T(n/2)+O(1)，a=1,b=2,c=0，log₂1=0 < 0？等于，看下一行
logba > cO(nlogba)递归求最大值：T(n)=2T(n/2)+O(1)，a=2,b=2,c=0，log₂2=1 > 0 → O(n)
logba == cO(nc · log n)归并排序：T(n)=2T(n/2)+O(n)，a=2,b=2,c=1，log₂2=1 == 1 → O(n log n)

记忆方法很简单：谁大听谁的。子问题那边的总工作量是 nlog_b a（每层 a 个子问题、共 log_b n 层，叶子总数 alog_b n = nlog_b a），当前层的工作量是 nc。哪边大，复杂度就是哪边；一样大，就再乘一个 log n（每一层工作量相同，共 log n 层）。

一个补充情况

Master 公式的标准形式里，额外工作量是 O(nc)。如果额外工作量带了 log n，比如：

T(n) = 2·T(n/2) + O(n · log n)

这时候 log_b a = 1，c = 1，但额外项多了一个 log n。结果是 O(n · (log n)2)。证明过程比较复杂，记住结论就行。直觉上：每一层工作量是 n·log(当前层规模)，共 log n 层，加起来就是 n·(log n)2。

六、不能用 Master 公式的情况

Master 公式只适用于「所有子问题规模相同」的递归。如果子问题规模不一样，就不能直接套。

最典型的是汉诺塔和斐波那契。汉诺塔 T(n) = 2T(n-1) + O(1)，两个子问题规模都是 n-1，看起来 a=2、b 呢？n 到 n-1 不是除以一个常数 b，而是减 1，所以 b 不存在。斐波那契 T(n) = T(n-1) + T(n-2)，两个子问题规模还不一样，更不能用 Master。

这两类的复杂度都是 O(2n)。汉诺塔 n=30 要移动约 10 亿次，实测 1.8 秒；斐波那契 fib(40) 要调用 3.3 亿次，实测 0.35 秒。n 每加 5，时间大约翻 3 倍，这就是指数增长的样子。

递归的空间复杂度容易被忽略。系统栈上的帧数就是递归深度，求最大值是 O(log n)，链状递归是 O(n)。写递归时除了算时间，还要算栈深会不会爆。

总结

递归的执行过程可以完全拆开看：每调用一次压一帧，每返回一次弹一帧，帧里存着参数、局部变量和返回地址。把调用树画出来、把栈帧列出来，递归就和循环一样可分析。

几个要点：第一，递归深度等于系统栈帧数，macOS 默认 8MB 栈约撑 26 万层，链状递归要警惕段错误。第二，任何递归都能改成非递归，自己用 vector 当栈模拟 state 机，工程上能改就改，比赛里能过就不改。第三，子问题规模相同时用 Master 公式算复杂度，比较 log_b a 和 c，谁大听谁的，相等乘 log n；子问题规模不同时（汉诺塔、斐波那契）不能用 Master，通常是指数级。

后面讲归并排序、快速排序、二叉树遍历、线段树时，递归会反复出现。到时候再遇到递归函数，先画调用图、再套 Master 公式，复杂度和执行过程就都清楚了。
