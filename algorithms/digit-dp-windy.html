数位 dp：状态里带上一位数字

windy 数的定义只管相邻两位，可正是这个「相邻」，让递归参数里必须额外记住上一位填了什么。这一页讲的就是这件事：把「前一位」塞进状态，再用一个哨兵值把「还没填过任何一位」和「填了个 0」分开。分开这两件事，是这类题最容易写错的地方。

零、windy 数

不含前导零、且相邻两个数字之差至少为 2 的正整数叫 windy 数。给 a 和 b，问 [a, b] 上有多少个 windy 数，a 和 b 最大到 2×10⁹。

逐个判断是二十亿次，不行。区间计数照例先拆成 cnt(b) − cnt(a−1)，问题变成求 [0, num] 上的个数。

一位数和两位数都好数，麻烦在于位数一多，「相邻」这个约束会把每一位和它前后的位全串起来。

一、填到第 i 位时，需要知道什么

从高位往低位填。填第 i 位时能不能填 x，取决于第 i−1 位填的是什么，跟再往前的位没关系。所以递归参数里除了「还剩几位」，必须带上一位的数字，记作 pre。

pre 是 3 的时候，这一位能填 0、1、5、6、7、8、9；中间的 2、3、4 差不到 2，划掉。

约束只牵扯相邻两位，所以「前面所有位的完整内容」不用记，记一个 pre 就够。这是数位 dp 里最常见的一次压缩：状态只保留对未来还有影响的那一小部分。

另外两件照旧的活儿是上界和前导零。上界还是那个 free：前面的位已经比 num 小了，后面随便填；还贴着 num，这一位就不能超过 num 的当前位。

二、前导零，用一个哨兵分开

num 是 20 的时候，7 也是 windy 数，可 7 只有一位，比 num 短。处理办法是允许「这一位什么都不填」：跳过去，剩下的位接着填，7 就被写成跳过十位、个位填 7。

跳过之后必须记住「前面一位都没填过」。要是顺手把它记成 0，下一位填数字 1 时就会拿 |1 − 0| = 1 去判，1 开头的短数全被判成不合法。所以 pre 的取值范围不是 0 到 9，而是 0 到 10，多出来的 10 是哨兵，专门表示「从来没填过数字」。

最高位还有一处要小心：pre 是哨兵的那一支，填数字的循环从 1 起步，不是从 0 起步。从 0 起步就会造出前导零，同一个数被数两遍。

三、代码

整个递归就是「还剩 len 位、前一位是 pre、free 是几」这三个参数，加上 num 和 offset 用来取当前位的数字。

// offset 完全由 len 决定，方便提取 num 中某一位数字
    // 从 num 的高位开始，还剩下 len 位没有决定
    // pre 是前一位的数字，pre == 10 表示从来没有选择过数字
    // free == 1 表示之前的位已经确定比 num 小，接下来的数字可以自由选择
    // free == 0 表示之前的位和 num 一样，接下来的数字不能超过 num 当前位
    // 返回 <= num 的 windy 数有多少个
    ll f(ll num, ll offset, int len, int pre, int free) {
        if (len == 0) {
            return 1;
        }
        if (dp[len][pre][free] != -1) {
            return dp[len][pre][free];
        }
        int cur = num / offset % 10;
        ll ans = 0;
        if (free == 0) {
            if (pre == 10) {
                // 来到 num 的最高位，之前既没有比 num 小，也没选过数字
                ans += f(num, offset / 10, len - 1, 10, 1); // 一个数字也不要
                for (int i = 1; i < cur; i++) {
                    ans += f(num, offset / 10, len - 1, i, 1);
                }
                ans += f(num, offset / 10, len - 1, cur, 0);
            } else {
                for (int i = 0; i <= 9; i++) {
                    if (i <= pre - 2 || i >= pre + 2) {
                        if (i < cur) {
                            ans += f(num, offset / 10, len - 1, i, 1);
                        } else if (i == cur) {
                            ans += f(num, offset / 10, len - 1, cur, 0);
                        }
                    }
                }
            }
        } else {
            if (pre == 10) {
                ans += f(num, offset / 10, len - 1, 10, 1); // 还是可以不选数字
                for (int i = 1; i <= 9; i++) {
                    ans += f(num, offset / 10, len - 1, i, 1);
                }
            } else {
                for (int i = 0; i <= 9; i++) {
                    if (i <= pre - 2 || i >= pre + 2) {
                        ans += f(num, offset / 10, len - 1, i, 1);
                    }
                }
            }
        }
        dp[len][pre][free] = ans;
        return ans;
    }

free == 1 那一半没有上界，循环直接跑满 0 到 9；free == 0 那一半只跑到 num 的当前位，等于 num 当前位时 free 继续是 0，小于它时变成 1。

入口把 num 的位数和最高位的权值先算出来，缓存清成 −1，然后从 (len, 10, 0) 出发。dp 的第二维开 11，就是为了装那个哨兵。

const int MAXLEN = 21;              // 加强版到 10^20，普通版 11 就够
    ll dp[MAXLEN][11][2];               // pre 取 0~9，外加 10 这个「没选过」的哨兵

    void build(int len) {
        for (int i = 0; i <= len; i++) {
            for (int j = 0; j <= 10; j++) {
                dp[i][j][0] = -1;
                dp[i][j][1] = -1;
            }
        }
    }

    // 求 0 ~ num 范围上 windy 数的个数
    ll cnt(ll num) {
        if (num == 0) {
            return 1;                   // 0 是 windy 数，它根本没有相邻的两位
        }
        int len = 1;
        ll offset = 1;
        ll tmp = num / 10;
        while (tmp > 0) {
            len++;
            offset *= 10;
            tmp /= 10;
        }
        build(len);
        return f(num, offset, len, 10, 0);
    }

    ll compute(ll a, ll b) {
        return cnt(b) - cnt(a - 1);
    }

四、缓存到底填了几格

状态空间是 len × 11 × 2，看着不小，实际走一遍只会碰到其中一部分。下图是 num = 99999 时真正被算过的格子，颜色深的那些。

44 格对 110 格，还不到一半。原因是 free == 0 这条链在每个 len 上最多只留一个格子，剩下的格子全是 free == 1 那一支撑起来的。

不挂缓存的裸递归就难看了：num = 9 是 11 次调用，99 是 85 次，999 是 622 次，9999 是 4500 次，99999 是 32503 次，每多一位大约乘 7。位数到 10 就是二十多万次，还能扛；位数再多就得挂缓存了。

五、写错的地方

下面四种错法各跑两万组随机区间（a、b 在 10⁶ 以内），看有多少组答案和正解不一样。

漏掉「一个数字也不要」那一支，是所有短位数的 windy 数全部数不到，58.58% 的样本会现形，答案平均虚高 4.78 倍。

把前导零当成真的 0 参与判定，等于宣布「首位不能是 1」，43.34% 的样本会现形。

差值写成至少 3 或者至少 1，都是改了题目条件，两万组里九成九都会错。不过错的方向不一样，一个偏小一个偏大，随机对拍很好抓。

具体反例：[2, 20] 正解 16，四种错法给出 7、9、14、18；[2, 200] 正解 122，给出 49、65、90、170；[2, 2000] 正解 897，给出 361、478、530、1547。

八、加强版：int 装不下

原题 a、b 到 2×10⁹，[1, 2×10⁹] 的答案是 127322182，int 装得下。加强版把上界放到 10²⁰，答案就得用 long long：光是 [1, 10¹¹] 就已经是 3966222144，超过 2147483647 了。

改起来只有两处：dp 数组和返回值从 int 换成 long long，MAXLEN 从 11 提到 21。递归逻辑一个字都不用动。

顺带可以看出答案的增长速度：每多一位大约乘 7.2，比 10 慢。因为每一位大约要排除掉 3 个数字，10 个候选里只剩 7 个左右。

九、复杂度分析

项目值
状态数len × 11 × 2，len 是 num 的位数
每格枚举0 到 9，常数 10
时间O(len × 11 × 2 × 10) = O(len)，len ≤ 10 时约 220 次转移
额外空间O(len × 11 × 2)，即 dp 数组，21 × 11 × 2 个 long long ≈ 3.7 KB

空间这一项跟 num 的大小完全无关，只跟位数有关。位数是对数量级，10²⁰ 也只有 21 位。

十、总结

相邻约束的处理办法是往状态里塞「前一位」，这一位就够了，不需要整段前缀。

前导零和「填了个 0」必须当成两件事，多开一个哨兵值 10 是最省事的做法。判断条件写成 pre == 10，循环起点跟着从 1 开始。

位数少的数靠「跳过这一位」覆盖，跳多少次都不改变状态里的 pre，所以 11 个取值足够。

加强版只改类型不改逻辑，这是数位 dp 的一个好处：复杂度挂在位数上，上界放大几个数量级也不影响写法。
