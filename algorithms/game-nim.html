博弈：尼姆与反尼姆

地上有几堆石子，每轮挑一堆拿走任意正数颗，拿走最后一颗的人赢。把每堆的数量全部异或起来，结果不为 0 就是先手胜，这一条撑得起整道题，因为它两头都堵死了。反尼姆只改一个词：拿走最后一颗的人输，答案里多出一处全 1 的特判。

零、两题各自要什么

第一题：n 堆石子，两人轮流进行，轮到的人挑一堆非空的、从里面拿走任意正数颗，谁拿走最后一颗谁获胜。给一个局面，返回先手是不是必胜。

第二题：规则一模一样，唯一的变化是拿走最后一颗的人输。先手赢输出 John，后手赢输出 Brother。

第一步能走的选择比巴什博弈多得多：n 堆里挑一堆、再在 1 到那一堆之间挑一个数，状态空间是指数级的，把表打出来都放不下。好在结论比巴什还短，只看一个异或值。

一、异或为 0 的局面一定必败

记这个异或值为 X。两条推理一合，结论就出来了。

1）X 等于 0 时，无论动哪一堆，X 都会变成非 0。因为动一堆就是把这一堆换成一个不同的数，异或里只有这一项变了，前后的差值就是「原来的数 异或 新的数」，两个不同的数异或一定不为 0。

2）X 不等于 0 时，一定能一步把它变成 0。看 X 最高那个 1 在第 k 位，堆里一定有一堆的第 k 位也是 1，否则 X 的第 k 位不会出现 1。把这一堆从 a 改成 a ^ X：a 与 X 在第 k 位同为 1，异或后第 k 位变 0，更高的位原样不动，所以改完的数一定比 a 小，是合法的一步。改完以后整局的异或变成 X ^ a ^ (a ^ X) = 0。

再加上最小的局面：没有石子时谁都走不了，异或为 0，而输的正是轮到的人。两条推理把 0 封成了唯一的必败态，X 为 0 就是先手必败。

拿 3、5、6 试一遍。三个数写成二进制是 011、101、110，两两抵消，异或为 0，这个局面先手必败，怎么拿都会被对手推回 0。换成 3、5、7：111 与 110 差在最低位，异或等于 1。最高位是第 0 位，三堆在这一位都是 1，挑 5 改成 5 ^ 1 = 4，局面变成 3、4、7，异或重新回到 0。

异或那一趟扫描是在线的，不需要把 n 堆都存下来，读到一堆就往累加器里异或进去。实测 106 堆跑完 0.0357ms。顺带还能把修复的那一步一起算出来：本次随机数据里异或是 424564478，最高位是第 28 位，找到第 7 堆（358173079）在这一位上是 1，改成 358173079 ^ 424564478 = 202841961，比原来小，确实走得通。

// 尼姆博弈：n 堆石子，每人从任意一堆拿走任意正数颗，拿走最后一颗的人获胜
    // 把每堆的数量全部异或起来，结果不为 0 就是先手必胜
    bool nimGame(vector<int> piles) {
        int eor = 0;
        for (int x : piles) {
            eor ^= x;
        }
        return eor != 0;
    }

这里有个细节：符合条件的堆可能不止一堆，第 k 位是 1 的那些堆都能改。挑哪一堆都行，改完之后异或都是 0，只是留给对手的残局不同。

二、反尼姆：先数 1，再看异或

把「拿走最后一颗的人赢」换成「输」，最后一颗石子从奖品变成了烫手山芋，结论要分成两支。

第一支：所有堆的大小都是 1。这时每轮的走法被逼死了，只能拿走一整堆，也就是每手恰好拿走 1 颗。整局正好走 n 手，第 n 手拿走最后一颗，而那一手的人是输家。所以堆数为奇数时先手输、偶数时先手赢。

第二支：至少有一堆大于 1。这时异或的判据照旧成立，异或非 0 先手胜、为 0 先手输，和尼姆一字不差。

两支的分界线就在全 1 上。全 1 且堆数是奇数，异或是 1（非 0），按第一支是输，按第二支的判据是赢，两者正好撞在一起，所以必须单独挑出来。

几个例子对一下。1、1 全是 1、堆数 2，先手赢；1、1、1 全是 1、堆数 3，先手输；2、2 有一堆大于 1、异或为 0，先手输；1、2 有一堆大于 1、异或等于 3，先手赢。

// 反尼姆博弈：规则和尼姆一样，只是拿走最后一颗的人输
    // 全是 1 的堆单独判：堆数是奇数时先手必输、偶数时先手必胜
    // 只要有一堆大于 1，异或的判据和尼姆完全一样
    string antiNimGame(vector<int> stones) {
        int eor = 0, ones = 0;
        for (int x : stones) {
            eor ^= x;
            ones += x == 1 ? 1 : 0;
        }
        if (ones == (int)stones.size()) {
            return stones.size() % 2 == 1 ? "Brother" : "John";
        }
        return eor != 0 ? "John" : "Brother";
    }

四、对数器怎么抓错

两题的暴力都是记忆化搜索：状态就是各堆大小的有序元组，每次枚举「挑哪一堆、拿走多少」递归下去。堆数取到 5、每堆不超过 5 的时候，跑几千组能对得很干净。

题目写法随机数据出错比例
尼姆用总和的奇偶代替异或值域 0~1 时 0.00%，值域 0~3 时 25.33%，值域 0~999 时 49.71%
尼姆用「最大堆比其余加起来还多」值域 0~1 时 14.29%，值域 0~999 时 45.72%
尼姆用按位与是不是 032.02% 到 53.67%
尼姆把先手后手判反100.00%
反尼姆照搬尼姆，不判全 1值域 1~2 时 19.43%，值域 1~10 时 2.19%，值域 1~100000 时 0.00%

尼姆每档两万组，堆数 1 到 5，值域分别取 0~1、0~3、0~7、0~999；反尼姆每档二十万组，值域取 1~2、1~4、1~10、1~100、1~100000。

「总和的奇偶」在值域只有 0 和 1 的时候一次都不错，因为那时每堆非 0 即 1，异或结果本身就是 1 的个数的奇偶。值域一旦拉开就立刻崩到一半左右，异或看的是一位一位的独立抵消，和求和的进位完全是两回事。

反尼姆那条错法错得很有意思：出错比例几乎就等于「全 1 局面出现的比例」。值域 1~2 时每一堆有一半机会是 1，全 1 的局面不少见，错 19.43%；值域拉到 1~100000 以后，凑出一堆全 1 几乎不可能，出错比例掉到 0.00%，但错误本身还在，只是随机数据碰不到。这种「测试数据碰不到」的漏洞只能靠专门构造的全 1 用例补上。

复杂度分析

题目关键操作时间空间
尼姆一趟异或，可以边读边算O(n)O(1)
反尼姆一趟异或，外加数 1 的个数O(n)O(1)
构造出那一步找最高位再扫一遍找那一堆O(n)O(1)

判胜负不需要保存任何一堆石子的数量，读一个异或进去一个就行，所以额外空间是常数。106 堆求异或实测 0.0357ms，把「最高位、改哪一堆、改成多少」也一起算出来还是 0.0357ms，因为两者在同一趟里做完。

总结

尼姆的必败态是异或为 0。两条推理各管一头：动一堆一定会把 0 变成非 0，非 0 时按最高位挑一堆改成 a ^ X 就能变回 0，再加「没有石子可走就是输」这个底，0 就被封住了。

反尼姆和尼姆只在全 1 的局面分岔：所有堆都是 1 时，每人每轮只能拿走 1 颗，胜负由堆数的奇偶决定；只要有一堆大于 1，异或的判据一字不改。分支的原因是全 1 且堆数奇数时，异或非 0 而先手却输。

结论短，但它是构造性的：算出异或非 0 之后，改哪一堆、改成多少都能立刻推出来，这比只给一个胜负值有用得多。下一讲把「每堆能拿多少」这条限制彻底拿掉，换成 SG 函数和 SG 定理，通用的算表办法就来了。
