带修莫队

操作里混着修改，查询就不只是区间，还带一个时间点。给查询排三维序、块长换成 n 的 2/3 次方，总移动量 O(n 的 5/3 次方)。

零、背景

前面五个题的数组全程不变，查询只是换个区间。一旦中间夹着「把某个位置改成某个值」，窗口就不只在下标这一维上动了：回答第 5 条查询时，数组得是执行完前 3 次修改的样子，回答第 9 条时又得是执行完前 7 次的样子。

于是每条查询多出一个坐标：它发生在第几次修改之后。

一、问题

长度为 n 的数组，m 条操作两种。（P1903）

操作 Q l r：打印 [l, r] 上有几种不同的数。操作 R pos val：把 arr[pos] 改成 val。n、m 都到 2 × 10⁵。

查询依然是离线的，全部拿到手再一起回答。

二、朴素做法

每条查询先把数组重放到它那个时间点，再扫一遍 [l, r]。重放最坏 O(m)，扫一遍 O(n)，m 条查询 O(m(n + m))。

浪费还是重复：相邻两条查询的时间点往往只差几次修改，却每次都从头重放。同理，前一条查 [2, 6]、这一条查 [3, 7]，也没必要从头扫。

三、三维与块长

给每次修改分配一个时间点，从 1 开始编号。查询写成 [jobl, jobr, jobt]，jobt 是它前面有多少次修改。

窗口也跟着变成两个：下标窗口 [winl, winr]，时间窗口 wint，表示数组已经改到第 wint 次修改。两者一起决定当前答案。

排序改成三个关键字：l 所在块 → r 所在块 → t 升序。注意第二关键字也分块，普通莫队那里是直接用 r 的数值排。

块长为什么是 n 的 2/3 次方。设块长为 B，块数 n/B，组数 (n/B)²。

同一组内 l 和 r 都只在自己那块里动，每次查询最多各走 B 步，m 条查询合计 mB。换组时 r 最多跳一整个数组，组有 (n/B)² 个，合计 n³/B²。每组内 t 是升序的，走完一组最多 m 步，组数同样是 (n/B)²，合计 m·n²/B²。

把 B = n 的 2/3 次方代进去，三项分别是 n 的 5/3 次方、n 的 5/3 次方、n 的 5/3 次方，再加换 l 块时那点 n²/B，总代价是 O(n 的 5/3 次方)。取更小或更大的 B 都会让其中某一项变大。

四、时间指针怎么走

时间往前走是执行下一次修改，往后走是撤销上一次。写两个函数容易出错，用一个交换技巧就够：执行 update[t] 时，把 arr[pos] 的旧值换进 update[t].val。

还有一个判断：这次改的位置如果不落在当前下标窗口里，答案不受影响，只改数组就行；落在窗口里，就要先 del 掉旧值、再 add 新值。

五、代码

下面是带修莫队的完整模版，答案维护的是不同数字个数。

    
#include <bits/stdc++.h>

    using namespace std;

    struct Query {
        int l, r, t, id;
    };

    struct Update {
        int pos, val;
    };

    const int MAXN = 200001;
    const int MAXV = 1000001;
    int n, m;
    int arr[MAXN];
    int bi[MAXN];

    Query query[MAXN];
    Update update[MAXN];
    int cntq, cntu;

    int cnt[MAXV];
    int kind;

    int ans[MAXN];

    bool QueryCmp(Query &a, Query &b) {
        if (bi[a.l] != bi[b.l]) {
            return bi[a.l] < bi[b.l];
        }
        if (bi[a.r] != bi[b.r]) {
            return bi[a.r] < bi[b.r];
        }
        return a.t < b.t;
    }

    void del(int num) {
        if (--cnt[num] == 0) {
            kind--;
        }
    }

    void add(int num) {
        if (++cnt[num] == 1) {
            kind++;
        }
    }

    void moveTime(int jobl, int jobr, int tim) {
        int pos = update[tim].pos;
        int val = update[tim].val;
        if (jobl <= pos && pos <= jobr) {
            del(arr[pos]);
            add(val);
        }
        int tmp = arr[pos];
        arr[pos] = val;
        update[tim].val = tmp;
    }

    void compute() {
        int winl = 1, winr = 0, wint = 0;
        for (int i = 1; i <= cntq; i++) {
            int jobl = query[i].l;
            int jobr = query[i].r;
            int jobt = query[i].t;
            int id = query[i].id;
            while (winl > jobl) {
                add(arr[--winl]);
            }
            while (winr < jobr) {
                add(arr[++winr]);
            }
            while (winl < jobl) {
                del(arr[winl++]);
            }
            while (winr > jobr) {
                del(arr[winr--]);
            }
            while (wint < jobt) {
                moveTime(jobl, jobr, ++wint);
            }
            while (wint > jobt) {
                moveTime(jobl, jobr, wint--);
            }
            ans[id] = kind;
         }
    }

    void prepare() {
        int blen = max(1, (int)pow(n, 2.0 / 3));
        for (int i = 1; i <= n; i++) {
            bi[i] = (i - 1) / blen + 1;
        }
        sort(query + 1, query + cntq + 1, QueryCmp);
    }

    int main() {
        ios::sync_with_stdio(false);
        cin.tie(nullptr);
        cin >> n >> m;
        for (int i = 1; i <= n; i++) {
            cin >> arr[i];
        }
        char op;
        int l, r, pos, val;
        for (int i = 1; i <= m; i++) {
            cin >> op;
            if (op == 'Q') {
                cin >> l >> r;
                cntq++;
                query[cntq].l = l;
                query[cntq].r = r;
                query[cntq].t = cntu;
                query[cntq].id = cntq;
            } else {
                cin >> pos >> val;
                cntu++;
                update[cntu].pos = pos;
                update[cntu].val = val;
            }
        }
        prepare();
        compute();
        for (int i = 1; i <= cntq; i++) {
            cout << ans[i] << '\n';
        }
        return 0;
    }

读入时顺手给每条查询记下 t = 当前的修改条数。排序用 QueryCmp，比较函数里第二关键字是 r 的块号，这是和普通莫队唯一的结构差别。

六、出现一次的数有几种

统计出现 1 次的数（SP30906 / ADAUNIQ）：操作 1 pos val 是修改，操作 2 l r 问 [l, r] 上有多少种数恰好出现一次。下标从 0 开始，代码里统一加 1 转成 1 起。

维护量换成 curCnt：出现次数恰好为 1 的数的种类数。加一个数时，次数从 0 变 1 就多一种，从 1 变 2 就少一种；删一个数时反过来。

    
void del(int num) {
        if (cnt[num] == 1) {
            curCnt--;
        }
        if (cnt[num] == 2) {
            curCnt++;
        }
        cnt[num]--;
    }

    void add(int num) {
        if (cnt[num] == 0) {
            curCnt++;
        }
        if (cnt[num] == 1) {
            curCnt--;
        }
        cnt[num]++;
    }

七、出现次数集合的 mex

机器学习（CF940F）：查询 [l, r] 上每种数字的出现次数构成一个集合，打印这个集合里没出现过的最小正数。

还是两层计数。cnt1[x] 是 x 出现几次，cnt2[c] 是出现次数为 c 的数有几种，答案就是最小的 c 使 cnt2[c] 为 0。

找这个空档直接暴力从 1 往上扫。窗口长度是 len，出现次数大于 √len 的数最多 √len 个，能填上的大于 √len 的档位也就这么几个，所以扫到 √n 量级必定停下，单次 O(√n)。

    
void del(int num) {
        cnt2[cnt1[num]]--;
        cnt1[num]--;
        cnt2[cnt1[num]]++;
    }

    void add(int num) {
        cnt2[cnt1[num]]--;
        cnt1[num]++;
        cnt2[cnt1[num]]++;
    }

回答时那几行就是暴力扫。

    
        int ret = 1;
            while (ret <= n && cnt2[ret] > 0) {
                ret++;
            }
            ans[id] = ret;

这里离散化要把修改里出现的值也收进来，否则改出来的新值没有下标可用。

八、复杂度分析

设块长 B = n 的 2/3 次方，n 与 m 同阶。

操作时间复杂度
预处理：块号与排序O(m log m)
下标移动一步（add / del）O(1)
时间移动一步（moveTime）O(1)
l、r 在组内移动合计O(mB) = O(n 的 5/3 次方)
r 跨组跳转合计O(n³/B²) = O(n 的 5/3 次方)
t 移动合计O(m·n²/B²) = O(n 的 5/3 次方)
m 次查询合计O(n 的 5/3 次方)

题 8 每次回答多一个 O(√n) 的 mex 扫描，m 次是 O(m√n)，比 n 的 5/3 次方小一档，不影响总量级。

空间上要存查询数组、修改数组、答案数组，各 O(m)，加上计数数组 O(V)，额外空间 O(V + m)。

九、最后

带修莫队和普队的差别只有两处：排序多一个时间关键字、块长从 √n 换成 n 的 2/3 次方。窗口的 add / del 照旧按题目设计。

后面还会遇到只用加、不好删的维护量，那时要靠回滚来避开删除，是另一套改法。
