Manacher：长度前 k 名的奇数回文长度乘积

数回文的时候只关心奇数长度，而且要按长度排序取前 K 个再乘起来。逐个回文去数显然不行，回文最多能有 n2 / 2 个。半径数组里藏着一个包含关系：一个中心的最长回文是 p[i] − 1，那么比它短的那些奇数长度，在这个中心上也各出现了一次。抓住这一点，按长度分桶就够了。

零、题目

给定长度为 n 的串 s 和正整数 K，把所有长度为奇数的回文子串按长度降序排，取前 K 个，求这 K 个长度的乘积对 19930726 取模的结果；如果奇数长度回文子串总数不到 K 个，输出 −1。

数据范围 n ≤ 106、K ≤ 1012。样例是 n = 5、K = 3、"ababa"：奇数回文按长度排下来是 5、3、3、3、1、1、1、1、1，前三个乘起来 5 × 3 × 3 = 45。

一、奇长度只认字母中心

扩展串奇数下标放的是原串的字符，偶数下标放的是 '#'。中心落在字母上的回文，两端剥掉相同个数的字符后还是回文，真实长度一定是奇数；中心落在 '#' 上的回文长度一定是偶数。

所以只扫奇数下标：for (int i = 1; i < n; i += 2)。这一步挑错就把两种长度的回文混在一起了，而偶长度的回文本来一个都不该算。

二、一个中心给出一整档长度

以 i 为中心的最长回文长度是 p[i] − 1。把这段回文两端同时剥掉一层，剩下的还是回文，长度少 2。一路剥到只剩中心那个字符，得到的长度依次是 1、3、5、…、p[i] − 1。

也就是说，每个奇中心给出的是一整列长度：从 1 到这个上界的所有奇数长度各一次。反过来说，「长度恰好是 len 的回文有几个」等于「最长长度不小于 len 的奇中心有几个」，长度的取值向下封闭，这两个数其实是同一个。

于是不用记每层的次数，只把最长的那一档记进桶：cnt[p[i] − 1]++，然后从最长的长度往下走，边走边累加。累加值 sum 的含义就变成了「长度恰好是 len 的回文个数」。

取前 K 个的时候按长度从大到小走，第 len 档上有 sum 个（累积值），能全拿就全拿，剩下不到 sum 个就只拿剩下的那几个。每拿 t 个长度 len，就把 lent 乘进答案，K 减掉 sum。K 减到不大于 0 就停；走完所有档 K 还有剩，说明总数不够，返回 −1。

三、幂用快速幂算

乘进去的幂次可能非常大：K 到 1012，同一个长度可能被拿走上亿次。一次一次乘是不行的，一次乘法取一次模，1012 次乘就是 1012 次取模。快速幂把指数拆成二进制，每一位平方一次底数、是 1 就乘一次答案，复杂度降到 O(log K)，约 40 次乘法。

实测 power(3, 107)：快速幂 0.0001 毫秒，朴素乘 31.50 毫秒，差三十万倍。指数从 107 涨到 1012，快速幂只多十几步，朴素乘直接没得跑。

四、代码

先跑 Manacher 拿到 p，再把奇数中心的桶填上，然后从长到短扫一遍。

// cnt[len] 记「最长回文恰好是 len 的中心」有几个，从长到短累加就是长度 >= len 的个数
    int topKProduct(const string &s, long long k) {
        int m = (int)s.size();
        manacher(s);
        for (int i = 1; i < n; i += 2) {        // 奇数下标是字母，只有它们能给出奇长度回文
            cntLen[p[i] - 1]++;
        }
        long long ans = 1, sum = 0;
        for (int len = ((m & 1) == 1) ? m : (m - 1); len >= 1 && k > 0; len -= 2) {
            sum += cntLen[len];
            ans = ans * power(len, min(k, sum)) % MOD;
            k -= sum;
        }
        return k > 0 ? -1 : (int)ans;
    }

幂单独写一个函数，注意中间乘积要用 64 位。

// 快速幂：指数最大 10^12，一次一次乘是跑不完的
    long long power(long long x, long long e) {
        long long ans = 1;
        while (e > 0) {
            if ((e & 1) == 1) {
                ans = ans * x % MOD;
            }
            x = x * x % MOD;
            e >>= 1;
        }
        return ans;
    }

五、几个数字

模数是 19930726，不是常见的 109 + 7，抄错一位就全错。桶的下标是长度，最长到 n，按题目上限开 106 个 int 就够。

中间乘积 ans × lent 与底数平方 x × x 都在模数以内两次相乘，最大约 199307262 ≈ 4 × 1014，bool 与 int 都接不住，必须 unsigned 之外的 64 位整数，写成 int 会悄悄截断。

n = 106 全 a、K = 1011 实测 23.56 毫秒，答案 9965363。

六、两个错法

一，桶的下标写成 p[i] 而不是 p[i] − 1，长度整体多算 1，20000 组随机串上 100% 出错。

二，扫中心的时候连偶数下标一起扫。看着像是把偶长度的回文也算进来了，实测却 0.00% 有差别：偶中心的 p[i] − 1 一定是偶数，只会落进偶数下标那些桶，而从长到短扫长度时只走奇数长度，偶数桶根本读不到。这是个真的等价写法，只是白扫了一半的中心。

按长度取前 K 个

每点一步走到下一个更短的长度档：看累积个数怎么涨、这一步乘进去几个 len、乘积变成多少。乘积用 BigInt 算，模 19930726。

七、复杂度分析

做法关键操作时间空间
枚举所有奇数回文再排序回文最多 n2 / 2 个，排一遍O(n2 log n)O(n2)
桶 + 从长到短填桶 O(n)，每档一次快速幂 O(log K)O(n + n log K)O(n)

从长到短最多走 n / 2 档，每档一次快速幂最多 40 步乘法，所以是 O(n log K)，n 的系数很小。空间上按 n = 106 算：ss 是 2 × 106 个 char（2 MB），p 是 2 × 106 个 int（8 MB），桶是 106 个 int（4 MB），合计 14 MB 上下。

总结

奇数长度的回文只认字母中心，扫中心时下标步长写 2。

每个中心给出的是从 1 到 p[i] − 1 的一整列奇数长度，所以只需要把最长的那一档记进桶，再用从长到短的累加把「不超过上界的中心数」变成「长度不小于 len 的个数」。

幂次用快速幂，中间乘积用 64 位。整体是 O(n log K)、O(n) 空间。桶这一招换个问法照样能用，只要问题关心的是「按长度分批计数」。
