转移式的公式加工：把 j 和 i 拆开

上一节的转移天生就是 max(dp[j]) + w(i)，队列直接套上去就行。这一节的三道题没那么顺：转移里 j 和 i 乘在一起或者减在一起，队列看不出该维护什么。共同的解法是先做一次代数变形，把转移改写成「只含 j 的指标」加上「只含 i 的补项」，指标那一半就能进队列了。

零、判据：能不能拆成两半

设转移写成 dp[i] = max{ F(j) + G(i) }，j 在一个随 i 平移的区间里。F 只含 j、G 只含 i，那么 G(i) 可以提到 max 外面，剩下的 max F(j) 就是滑动窗口最大值，队列直接上。

反过来，如果变形之后还剩下一项同时含 i 和 j（比如 i × j），队列就救不了，那属于斜率优化的活。

所以每道题的动作是同一套：先老老实实写出带枚举的转移，再把含 i 的因子拎出来，看剩下那堆是不是只含 j。这一节的三道题分别变形出 dp[p−1] − sum[p]、dp[i−1][k] − pi × k、dp[i−1][j−1] − sum[j−1] 三种指标。

一、不超过连续 k 个元素的最大累加和

给一个长度为 n 的数组，随便挑数字，但连续挑的个数不能超过 k 个，问最大累加和。n、k 到 10⁵，arr[i] 非负。

直接按「最后一个数选不选」建状态是最自然的想法，但那样状态里得多一维。换个角度：最后选中的那一段是从 p + 1 到 i 的连续区间，长度 i − p ≤ k，而且 p 这个位置必须没选。于是：

dp[i] = max{ dp[p−1] + (sum[i] − sum[p]) }，p 从 i − k 到 i。

p = i 这一项就是「第 i 个不选」，此时 sum[i] − sum[p] = 0，值退化为 dp[i−1]。这一步是整个变形里最巧的地方：不选的那条分支和选的那条分支共用同一个式子，不用分开写。

把 sum[i] 提出来：

dp[i] = sum[i] + max{ dp[p−1] − sum[p] }

花括号里那一项只含 p，就是队列要维护的指标。下标范围 [i − k, i] 随 i 平移，形状跟上一节一模一样。

// f[i] : 前 i 个的最优，且第 i 个不选
    // g[i] : 前 i 个的最优，且第 i 个选
    long long chooseLimit1(int n, int k, vector<long long>& a) {
        const long long NEG = -(long long)4e18;
        vector<long long> sum(n + 1, 0);
        for (int i = 1; i <= n; i++) sum[i] = sum[i - 1] + a[i];
        vector<long long> f(n + 1, NEG), g(n + 1, NEG);
        f[0] = 0;
        for (int i = 1; i <= n; i++) {
            f[i] = max(f[i - 1], g[i - 1]);
            for (int c = 1; c <= k && c <= i; c++) {            // 枚举最后这段的长度
                g[i] = max(g[i], f[i - c] + sum[i] - sum[i - c]);
            }
        }
        return max(f[n], g[n]);
    }

朴素版这么写，内层枚举 k 次，总共 O(n × k)，n = k = 10⁵ 时是一百亿次。

// dp[i] : 前 i 个的最优
    // 队列里存 p，指标 value(p) 从队首到队尾递减
    long long chooseLimit2(int n, int k, vector<long long>& a) {
        vector<long long> sum(n + 1, 0), dp(n + 1, 0);
        for (int i = 1; i <= n; i++) sum[i] = sum[i - 1] + a[i];
        auto value = [&](int p) -> long long {
            return p == 0 ? 0 : dp[p - 1] - sum[p];             // p 位置断开：p 不选
        };
        vector<int> q(n + 2);
        int l = 0, r = 0;
        q[r++] = 0;
        for (int i = 1; i <= n; i++) {
            while (l < r && value(q[r - 1]) <= value(i)) r--;
            q[r++] = i;                                         // p = i 就是「不选 i」
            if (l < r && q[l] == i - k - 1) l++;                // 连续段长度超过 k 的断开点
            dp[i] = value(q[l]) + sum[i];
        }
        return dp[n];
    }

三个容易写错的点。第一，指标里是 dp[p−1] 不是 dp[p]：p 这个位置必须断开，用 dp[p] 的话前面那段的尾巴可能正好压在 p 上，连续长度就超了 k。第二，p = 0 的指标是 0，不能走 dp[−1]。第三，「第 i 个不选」这条分支是靠把 i 塞进队列实现的，别再另外写一遍 dp[i] = max(dp[i], dp[i−1])，写了就重复。

二、粉刷木板：上界是常量的窗口

n 块木板排成一排，m 个工人。第 i 个工人带着三个参数：最多刷 li 块、每刷一块得 pi 元、刷的那段必须包含 si 号木板。每块木板最多被刷一次，问最多能得多少钱。n ≤ 16000，m ≤ 100。

先把工人按 si 从小到大排。设 dp[i][j] 是前 i 个工人刷前 j 块木板的最多钱。第 i 个工人可以不出场，那就是 dp[i−1][j]；出场的话，他刷的是 [k+1, j]：

dp[i][j] = max{ dp[i−1][k] + pi × (j − k) }，k 满足 k + 1 ≤ si ≤ j 且 j − k ≤ li。

把 pi × j 提出来，指标是 dp[i−1][k] − pi × k。k 的范围 [j − li, si − 1] 里，上界 si − 1 跟 j 没关系，是常量；下界 j − li 随 j 抬升。

这就带来一个和上一节不同的动作：队列只在开头建一次，把 [max(0, si − li), si − 1] 全装进去，之后每列只从队首丢元素，不再往里加。因为候选集合只会越用越小。

// dp[i][j] : 前 i 个工人刷前 j 块木板，最多能拿多少钱
    // 工人按 si 从小到大排；队列存 k，指标 value(k) = dp[i-1][k] - pi * k
    int painting(int n, int m, vector<Worker>& w) {
        sort(w.begin(), w.end(), [](Worker& a, Worker& b) { return a.s < b.s; });
        vector<vector<int>> dp(m + 1, vector<int>(n + 1, 0));
        vector<int> q(n + 2);
        for (int i = 1; i <= m; i++) {
            int li = w[i].l, pi = w[i].p, si = w[i].s;
            auto value = [&](int k) -> long long { return (long long)dp[i - 1][k] - (long long)pi * k; };
            int l = 0, r = 0;
            for (int k = max(0, si - li); k < si; k++) {        // k 的上界恒为 si - 1
                while (l < r && value(q[r - 1]) <= value(k)) r--;
                q[r++] = k;
            }
            for (int j = 1; j <= n; j++) {
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]);
                if (j >= si) {
                    if (l < r && q[l] == j - li - 1) l++;       // k 的下界随 j 抬升
                    if (l < r) dp[i][j] = max(dp[i][j], (int)(value(q[l]) + (long long)pi * j));
                }
            }
        }
        return dp[m][n];
    }

注意 j < si 的列什么都不做，保留 dp[i−1][j] 和 dp[i][j−1] 传下来的值。还有 dp[i][j] = max(dp[i−1][j], dp[i][j−1]) 这一行必须在取队首之前写：工人不刷 j 这块，或者干脆不出场，两种不刷都要算进去。

取一组小数据验证：n = 8，工人分别是 (l = 3, p = 2, s = 3) 和 (l = 2, p = 3, s = 6)。第一个工人最多刷 3 块、必须覆盖 3 号，最优是刷 [1, 3] 拿 6 元；第二个工人最多刷 2 块、必须覆盖 6 号，最优是刷 [5, 6] 拿 6 元。总共 12 元，两块工人之间不能重叠，[1,3] 和 [5,6] 正好不冲突。

三、最小移动总距离：把 sum 换成距离前缀和

工厂和机器人都排在一条数轴上，第 i 个工厂在位置 f[i][0]、能修 f[i][1] 个机器人，机器人位置是 robot 数组。每台机器人去一个工厂，距离取绝对值，工厂不能超容量，问最小总距离。

先把工厂按位置排、机器人按位置排。排完之后有个朴素但重要的结论：每台机器人只会去它左右相邻的工厂，不会「跨过去」配对。所以按工厂从前往后、机器人从前往后推进就够了。

设 dp[i][j] 是前 i 个工厂修完前 j 台机器人的最小距离，sum[j] 是前 j 台机器人到第 i 个工厂的距离前缀和。第 i 个工厂负责 [s, j] 这一段时：

dp[i][j] = min{ dp[i−1][s−1] + (sum[j] − sum[s−1]) }，j − s + 1 ≤ cap。

提出 sum[j]，指标是 dp[i−1][s−1] − sum[s−1]，s 的范围 [j − cap + 1, j]，两端都随 j 平移。这题是取最小值，所以队列改成递增。

// dp[i][j] : 前 i 个工厂修好前 j 个机器人的最小总距离
    long long minimumTotalDistance(vector<int>& robot, vector<vector<int>>& factory) {
        sort(factory.begin(), factory.end());
        sort(robot.begin(), robot.end());
        int n = factory.size(), m = robot.size();
        const long long INF = (long long)4e18;
        vector<vector<long long>> dp(n + 1, vector<long long>(m + 1, 0));
        for (int j = 1; j <= m; j++) dp[0][j] = INF;
        vector<long long> sum(m + 1, 0);                        // j 个机器人到 i 号工厂的距离前缀和
        vector<int> q(m + 2);
        for (int i = 1; i <= n; i++) {
            int cap = factory[i - 1][1];
            for (int j = 1; j <= m; j++) {
                sum[j] = sum[j - 1] + llabs((long long)factory[i - 1][0] - robot[j - 1]);
            }
            auto value = [&](int j) -> long long {              // i 号工厂从 j 号机器人开始修
                if (dp[i - 1][j - 1] == INF) return INF;
                return dp[i - 1][j - 1] - sum[j - 1];
            };
            int l = 0, r = 0;
            for (int j = 1; j <= m; j++) {
                dp[i][j] = dp[i - 1][j];                        // i 号工厂一个都不修
                if (value(j) != INF) {
                    while (l < r && value(q[r - 1]) >= value(j)) r--;
                    q[r++] = j;
                }
                if (l < r && q[l] == j - cap) l++;              // 超过容量的起点出队
                if (l < r) dp[i][j] = min(dp[i][j], value(q[l]) + sum[j]);
            }
        }
        return dp[n][m];
    }

和前两题不一样的地方有三处。一是 sum 每个工厂都要重算一遍，它是「到第 i 个工厂的距离」的前缀和，不是固定数组。二是 dp[i][j] = dp[i−1][j] 这一行不能省，它代表第 i 个工厂一台都不修。三是容量可能是 0，这时 q[l] == j − 0 会立刻把刚加进去的 j 弹掉，只剩「不修」那条路，是对的。

实测一组：工厂在 2 和 6，容量 2 和 3；机器人在 1、3、5、7。机器人 1、3 去工厂 2（各 1），机器人 5、7 去工厂 6（各 1），总距离 4，也是最优解。

六、写错的地方

随机两万组小数据（n ≤ 12，k ≤ 5，arr 取 −5 到 14）实测，几种典型错法与正确解不一致的比例：

题目错法不一致比例错在哪
连续 k 个指标写成 dp[p] − sum[p]74.52%p 位置没断开，连续长度可能超 k
连续 k 个队列不弹过期42.20%等于取消 k 的限制，答案偏大
粉刷木板k 的上界写成 j − 117.23%忘了那段必须包含 si
粉刷木板工人不按 si 排序19.79%dp 的行顺序和木板的顺序对不上
粉刷木板忽略长度 li64.03%一个工人刷了整排，答案虚高
修机器人过期判断差一位46.83%工厂多修一台，超出容量
修机器人漏掉「这个工厂不修」100.00%必选最后一个工厂，容量不够时直接算不出来

最后一行值得多说一句：dp[i][j] = dp[i−1][j] 看起来只是「照抄上一行」，实际上它是唯一的「跳过这个工厂」通道。漏掉之后每个工厂都得至少修一台，容量不足的组合全部变成无穷大，一万两千组数据里没有一组侥幸对上。

粉刷木板的两个低比例错法（17%、20%）也别被数字骗了：它们不是「小概率出错」，而是「只在特定数据形状下出错」。k 上界写错只在 si 靠左时才现形，不排序只在输入本来就有序时才对。

七、复杂度分析

题目朴素写法队列写法空间说明
连续 k 个O(n × k)O(n)O(n)dp、sum、队列各一个数组
粉刷木板O(m × n × l) O(m × n)O(m × n)16000 × 100 约 160 万格
修机器人O(n × m × cap)O(n × m)O(n × m)滚动后 O(m)，sum 每轮重算

空间按题目上限算：连续 k 个 n ≤ 10⁵，dp 与 sum 都是 long long 数组，约 1.6 MB；粉刷木板 16001 × 101 格 int 约 6.4 MB；修机器人 n、m ≤ 100，表本身可以忽略，sum 数组 O(m)。

三道题的队列都是摊还 O(1)：每个下标进一次出一次，while 循环看着吓人，总次数是线性的。

八、总结

这一节的共同动作只有一个：把转移里的 i 和 j 拆开。具体做法是先把含 i 的项（sum[i]、pi × j）提到 max 外面，剩下的定义为指标，然后看指标的合法下标区间是不是随 i 平移。是就上队列，不是就得换工具。

三道题给出的三种变形各有各的细节：连续 k 个把「不选」也编成了同一个指标；粉刷木板的窗口上界是常量，队列只出不进；修机器人要把 sum 换成「到当前工厂的距离」前缀和，而且必须留一条「这个工厂不修」的通道。

再往下走会遇到拆不开的转移，比如指标里剩下一个 i × j。那时候队列不够用了，得把候选点看成平面上的点、把 max 看成一条直线的截距，那是斜率优化的范围。
