囚徒与 100 个盒子

100 个犯人编号 0 到 99，100 个盒子编号 0 到 99 排成一排，监狱长把盒子里的编号随机打乱。每个犯人单独进屋，可以打开 50 个盒子找自己的编号，全程不能交流、不能留下记号。只要有一个犯人没找到自己的编号，100 个人全部处决。所有人事先可以商量策略。随口一算的成功率是两人各猜一次硬碰硬，概率低到写不出来；换个思路之后，成功率能到 31.18%。

零、两个数字差 30 个数量级

先说最自然的想法：每个人进屋之后随机挑 50 个盒子打开，50 个盒子里恰好有自己编号的概率是 1/2。100 个人互相独立，全体成功的概率是 (1/2)100 ≈ 7.89×10−31。

这个数字小到什么程度？拿 20 万次模拟跑一遍，一次都没成功过。就算把模拟次数提到 1020 次也未必见得到一次。

而最终给出的策略，成功率是 0.31183。也就是说同样 100 个人、同样只能各开 50 个盒子，活下来的概率差了 30 个数量级。差别不在运气，在于每个人打开盒子的顺序是互相牵连的。

一、把盒子看成置换

先给这堆盒子找一个准确的描述。「盒子 i 里装着编号 a[i]」，这句话定义了一个从 0 到 99 的排列 a。因为每个编号恰好出现在一个盒子里，a 是一个置换。

置换有一个天然的结构：从任意一个位置出发，沿着 a 一路跳下去，一定会回到起点（因为每一步都是被唯一决定的，不可能走到两个地方去，也不可能永远不回头）。跳过的那些位置构成一个环。

举个 6 个盒子的例子。盒子 0 里是 2，盒子 2 里是 5，盒子 5 里是 0，这三个盒子构成一个长度 3 的环；盒子 1 里是 1，自己成环；盒子 3 里是 4、盒子 4 里是 3，构成一个长度 2 的环。整个置换被拆成 3 + 1 + 2 = 6，一个不落。

1 号犯人查自己的编号，只需要打开盒子 1，一眼就看到，这叫长度 1 的环。0 号犯人要打开盒子 0、2、5 才能找到，这条环长 3。

二、跟着盒子里的编号走

策略只有一句话：犯人 p 先打开盒子 p。如果里面是 q，下一步就打开盒子 q；如果里面是 p，收工。他不需要背任何表，每一步的下一步都由盒子里那张纸条直接告诉他。

为什么这条路线有效？因为 p 从盒子 p 出发，沿着置换的环走，走的正是 p 所属的那个环。而 p 一定在这个环上（环的定义就是从 p 出发能回到 p），所以走满一圈必然经过装着 p 的那个盒子，剩下的只是「在 50 步以内走到」。

// 盒子 i 里装着编号 a[i]。从 i 出发，a[i] 指向下一个盒子，一路走回去就是一个环
    // 每个位置只管把自己归位，走完一个环整段都归位，总代价 O(n)
    int maxCircle(vector<int> a) {
        int n = a.size(), mx = 1;
        for (int i = 0; i < n; i++) {
            int cur = 1;
            while (i != a[i]) {                 // 还没走到自己
                swap(a[i], a[a[i]]);            // 把身上这个数送回家
                cur++;
            }
            mx = max(mx, cur);
        }
        return mx;
    }

把 100 个盒子分成若干个环，每个犯人在自己那个环上走。环长就是他要打开的盒子数。所以 100 个人全部成功的条件可以精确地写出来：置换里最长的那个环，长度不超过 50。

注意这里省略了什么。犯人在打开的盒子里看到的是别人的编号，他没有破坏任何结构，只是把一个只读的置换沿着自己那条环走了一遍。100 个人各自走各自的环，互不干扰，也不会改变盒子内容。这个策略之所以允许「事先商量」，是因为所有人用的是同一条规则，而不是共享运行时信息。

三、最长环恰好是 r 的概率

现在问题变成一个纯计数题：n 个元素的随机置换里，最长环恰好等于 r 的概率是多少。

先数「最长环恰好是 r」的置换有多少个。选定这个环上的 r 个元素有 C(n, r) 种选法；这 r 个元素排成一个环有 (r−1)! 种排法（圆排列）；剩下 n−r 个元素随便排，有 (n−r)! 种。乘起来：

C(n, r) × (r−1)! × (n−r)! = n! / r

全部置换有 n! 个，所以概率是 1/r。100 个元素的置换里，最长环等于 51 的概率是 1/51。

这个推导有一个前提：r 要大于 n/2。两个长度都超过 n/2 的环加起来必然超过 n，不可能同时存在于同一个置换里。所以在这个范围内，「存在长度 r 的环」和「最长环恰好是 r」是同一件事，各 r 之间互不相容，概率可以直接相加。

于是死亡概率就是 1/51、1/52 一直到 1/100 这些项加起来，活下来的概率是它的补：

// 存活 ⟺ 最长环不超过每人能开的盒子数
    // 最大环恰好是 r 的排列有 n!/r 个，所以概率是 1/r，r > n/2 时互不相容可以直接相加
    double escape(int people, int tries) {
        double dead = 0;
        for (int r = tries + 1; r <= people; r++) dead += 1.0 / r;
        return 1 - dead;                        // 100 人开 50 个：1 - (1/51 + ... + 1/100) = 0.31183
    }

100 万次模拟的实测分布和 1/r 对得上：最长环等于 51 的时间里，实测 1.94640%、公式 1.96078%；等于 60 的实测 1.66080%、公式 1.66667%；等于 100 的实测 1.01070%、公式 1.00000%。都在百万次抽样的涨落范围内。

公式里那句「一定要保证每人尝试的次数不少于人数的一半」现在有了出处：一旦允许打开的次数少于一半，就可能有两个环都超过这个次数，两个事件不再互不相容，直接相加会把它们重复算一遍。实测 n = 100 时，允许开 20 个盒子的公式会给出 −0.58964 这样一个负数概率，而模拟的真实存活率是 0.00049。

四、31.18% 是怎么来的

把公式算出来：死亡概率是 1/51 + 1/52 + … + 1/100 = 0.688172，存活概率 1 减去它就是 0.311828。

10 万次模拟：存活 31178 次，频率 0.31178，和公式的 0.31183 差 0.00005。同一批数据里「最长环超过 50 的置换」占 0.68822，公式给的死亡概率 0.68817。

模拟次数和公式的贴合程度也在数据里：100 次模拟给出 0.28，1000 次 0.293，1 万次 0.3128，10 万次 0.30988，100 万次 0.31173。每一档都在往 0.31183 靠。

五、人越多，越接近 1 − ln2

把 100 换成一般的 n，每人允许打开 n/2 个盒子，存活概率就是 1 − (H(n) − H(n/2))，H 是调和数。当 n 很大时，H(n) − H(n/2) 趋近于 ln2，存活概率趋近于 1 − ln2 = 0.306853。

n = 100 时是 0.311828，n = 1000 时 0.307353，n = 10 万时 0.306858，n = 100 万时 0.306853，四位小数已经不动了。

这个收敛有个直观解释。死亡的条件是「存在一个长度超过 n/2 的环」，而单个环长度恰好是 r 的概率是 1/r。长度超过一半的那些 r 加起来，正好是一个被截断的调和级数，n 变大时它从上面逼近 ln2。也就是说犯人再多，成功率也不会掉到 30% 以下，反过来说也涨不过 31.2%。

复杂度分析

操作时间空间
求最长环（就地归位）O(n)，每个位置只归位一次O(1) 额外空间
一个犯人按环走O(环长)，最坏 O(n)O(1)
公式算存活概率O(n)，n 个调和项相加O(1)

求最长环那个实现值得看一眼：它在数组上原地交换，把每个位置的数送回家，走完一个环整段就都归位了，所以 100 个位置总共只走了 100 步，不是 100×100。代价是它破坏原数组，如果还需要原排列就得先复制一份。

公式版则是 O(n) 时间、O(1) 空间，一行循环搞定，比模拟快无数倍。缺点是有前提：每人尝试次数必须不少于人数的一半，否则要把各 r 之间的容斥补回来。

总结

这道题的关键观察是「盒子与编号构成一个置换」。看清这一点之后，随机开盒的 (1/2)100 和跟着环走的 0.3118 之间的差距就有了出处：随机开盒时每个人的 50 个盒子各不相干，跟着环走时 100 个人共用同一份环结构，一个人走对了，同一个环上的其他人也顺路走对。

剩下的全是计数：最长环恰好是 r 的置换有 n!/r 个，概率 1/r；r 超过 n/2 时各档互不相容，死亡概率就是 1/51 到 1/100 的和 0.6882。100 万次模拟实测每一档都贴着 1/r，总和也对得上。

每人允许开 n/2 个盒子时，存活率随 n 收敛到 1 − ln2 = 0.306853，n = 100 的 0.311828 已经离极限不远。用这个公式时别忘了那个前提：尝试次数少于一半，直接相加会重复计数，n = 100 开 20 个盒子时公式甚至能算出负概率。
