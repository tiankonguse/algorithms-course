归并排序

把数组切成两半，各自排好序，再合成一个有序数组。递归和非递归两种写法，时间 O(n log n)，额外空间 O(n)。归并排序的 merge 过程还能直接拿来解决逆序对、区间和等一批问题。

零、背景

n=10000 的随机数组，插入排序平均要比 2501 万次，归并排序只要 12 万次。差了 208 倍。

差距不在常数，在结构。插入排序每比一次，最多交换一对相邻元素，也就是最多消掉一个逆序对。n 个元素最多有 n(n−1)/2 个逆序对，所以比较次数绕不开 O(n²)。

归并排序不一样。它比一次，就决定哪个元素进入 help 数组的下一个格子，这个元素在当前合并段里的位置就定了。比较本身就是决策，没有浪费。

这一讲先把归并排序本身讲透，下一讲用 merge 过程去解决更复杂的问题。

一、merge 过程

归并排序的核心在 merge，递归只是组织方式。假设数组的左半段 arr[l..m] 和右半段 arr[m+1..r] 已经各自有序，怎么把它们合成一个整体有序的 arr[l..r]？

三个指针：a 从 l 出发扫左半段，b 从 m+1 出发扫右半段，i 从 l 出发往辅助数组 help 里写。每一步比较 arr[a] 和 arr[b]，谁小就把谁拷进 help[i]，然后对应的指针往前走。

一定有一边先耗尽。左边先耗尽就把右边剩下的依次拷进去，右边先耗尽同理。最后把 help[l..r] 整体拷回 arr[l..r]。

写条件的时候用 arr[a] <= arr[b] 而不是 <。相等时先取左边的，原始顺序就保住了，这是归并排序稳定的根源，第五节细讲。

merge 本身只扫一遍 l..r，时间 O(r−l+1)。下面是完整实现。

void merge(int l, int m, int r) {
        int i = l;
        int a = l;
        int b = m + 1;
        while (a <= m && b <= r) {
            help[i++] = arr[a] <= arr[b] ? arr[a++] : arr[b++];
        }
        while (a <= m) {
            help[i++] = arr[a++];
        }
        while (b <= r) {
            help[i++] = arr[b++];
        }
        for (i = l; i <= r; i++) {
            arr[i] = help[i];
        }
    }

二、递归实现

有了 merge，排序就变成一句话：把左半段排好、把右半段排好、然后 merge。

递归函数 mergeSort1(l, r) 做三件事：取中点 m=(l+r)/2，递归排 [l..m]，递归排 [m+1..r]，最后 merge(l, m, r)。l==r 时只有一个元素，天然有序，直接返回。

用 Master 公式算复杂度。T(n) = 2·T(n/2) + O(n)，a=2，b=2，c=1。log_b a = log₂2 = 1，和 c 相等，所以时间复杂度 O(n^c · log n) = O(n log n)。上一讲刚推过 Master 公式，这里正好对上。

递归深度是 ⌈log₂n⌉。n=100 万时深度只有 20，离爆栈远得很（上一讲实测 macOS 默认栈能撑 26 万层）。

void mergeSort1(int l, int r) {
        if (l == r) {
            return;
        }
        int m = (l + r) / 2;
        mergeSort1(l, m);
        mergeSort1(m + 1, r);
        merge(l, m, r);
    }

三、非递归实现

递归写法好懂，但有人不喜欢函数调用的开销，或者担心栈深。非递归版用一个 step 变量从 1 开始翻倍：step=1 时把相邻两个元素合并，step=2 时把相邻两个长度为 2 的有序段合并，step=4 时合并长度为 4 的段，直到 step >= n。

每一轮里，l 从 0 出发，m = l + step − 1 是左段末尾，r = min(l + 2·step − 1, n−1) 是右段末尾。merge 完一段，l 跳到 r+1 继续下一段。如果 m+1 >= n，说明剩下的元素凑不齐右半段，直接 break，它们已经在前面的轮次里排好了。

n=1000 时一共 10 轮（⌈log₂1000⌉=10），每轮总共合并 O(n) 个元素，总时间还是 O(n log n)。

非递归版没有递归调用，也不用担心栈深。写法上比递归版多了几个边界判断，但逻辑是一样的。

void mergeSort2() {
        for (int l, m, r, step = 1; step < n; step <<= 1) {
            l = 0;
            while (l < n) {
                m = l + step - 1;
                if (m + 1 >= n) {
                    break;
                }
                r = min(l + (step << 1) - 1, n - 1);
                merge(l, m, r);
                l = r + 1;
            }
        }
    }

四、为什么比 O(n²) 快

前面说了，插入排序每次比较最多消一个逆序对。选择排序更绝，每次比较只用来找最小值，找到之后还要交换，比较次数恒为 n(n−1)/2，跟数据长什么样没关系。

归并排序的每次比较都在做决策：arr[a] 和 arr[b] 谁小，谁就进 help[i]。这个元素在当前合并段里的最终位置就定了，后面不会再动它。一次比较锁定一个元素的位置，n 个元素要锁定 n 次，每一层合并总共 O(n) 次比较，一共 log n 层，所以 O(n log n)。

下面这张图是实测的比较次数（200 组随机数组取平均），纵坐标是对数刻度。n=10000 时，插入排序的柱子已经顶到 2500 万，归并排序还在 12 万。

归并排序的比较次数还很稳定。n=1024 时，最好情况（已排序）5120 次，最坏情况（交错排列）7424 次，随机平均 8947 次。最好最坏只差 1.45 倍。插入排序在已排序时只要 n−1 次比较，逆序时就要 n(n−1)/2 次，差了 5000 倍。

代价是额外空间。help 数组要开 n 格，所以空间复杂度 O(n)。这个空间能不能省掉？能，但不值得，下一节说。

五、稳定性与原地归并的坑

归并排序是稳定的。相等元素的相对顺序在排序后不变。靠的就是 merge 里那句 arr[a] <= arr[b]：相等时先取左边的，左边的原始下标更小，顺序就保住了。

写成 < 会怎样？相等时先取右边的，两个相等元素的顺序就可能反过来。1500 组随机测试（小值域制造大量相等元素），<= 版零次打乱，< 版经常出问题。一个等号之差，稳定性就没了。

有些资料提到「原地归并排序」，声称可以把额外空间降到 O(1)。不要在这上面花时间。原地归并确实能省掉 help 数组，但合并时要在原数组上做元素搬移，时间复杂度会退化到 O(n²)。省了 O(n) 空间，丢了 O(n log n) 时间，这笔买卖不划算。竞赛里写归并排序，老老实实开一个 help 数组。

七、总结

归并排序的核心是 merge：两个有序段合成一个，谁小拷谁，一次比较锁定一个元素的位置。递归版按 Master 公式 T(n)=2T(n/2)+O(n) 得到 O(n log n)，非递归版用 step 翻倍实现同样的分层合并。

三个要点：第一，merge 里写 <= 不写 <，差一个等号稳定性就没了。第二，额外空间 O(n) 是值得的，原地归并会退化成 O(n²)，别学。第三，比较次数稳定在 n log n 附近，最好最坏只差 1.45 倍，这是 O(n²) 排序做不到的。

归并排序不只是一个排序算法。merge 过程本身（两个有序序列按大小合并）能直接拿来算逆序对、区间和、统计满足条件的数对。下一讲就用这套手法解决更复杂的问题。
