造公园与巡逻：直径会随合并和加边怎么变

会求直径之后，问题往上长一层：树自己在变，直径跟着怎么动？一种是合并，两棵树连成一片，要求连完之后直径尽量小；一种是加边，树上新修几条捷径，每趟巡逻必须各走一次，问最少走多少条边。两件事看着不搭，其实都只在问「最长路径被这次修改动了哪一块」。

零、背景

这一课的两个道具都现成：并查集维护「谁和谁连通」，树形 dp 求直径。新东西只有一条公式和一个小 trick。

一、问题：造公园

HXY 造公园：n 个休息点、m 条边，边权都是 1，所有点形成若干连通区，每个连通区保证是树。两种操作。操作 1 x：返回 x 所在连通区的直径长度。操作 2 x y：如果 x、y 已经连通就忽略；否则在 x 所在区域和 y 所在区域各选一个点连一条边，并且要让连成的大区域直径长度最小。n 与 q 都不超过 3×10⁵。

注意操作 1 问的是整个连通区的直径，跟 x 是谁无关，所以每个区维护一个直径值就够了，不用算每个点的偏心距。

二、初始直径与合并

读入的 m 条边两两 union，然后对每个并查集根跑一遍树形 dp，把直径记在根上。这就是集合打标签：数据挂在集合代表元上，集合一合并，标签搬到新代表元上。

操作 2 是关键。两棵树直径分别是 d1、d2，中间连一条边，新直径有多大？先看上界。新树里的路径分两种：完全留在原来某棵树里的，最长 max(d1, d2)；过了那条新边的，形状是「A 里某点 u → 新边 → B 里某点 v」，长度 ecc_A(u) + 1 + ecc_B(v)，ecc 是树内最远距离。一棵直径为 d 的树，ecc 最小能压到 ⌈d/2⌉，站在直径中点上就够，所以过新边的路径至多 ⌈d1/2⌉ + 1 + ⌈d2/2⌉。

再看能不能取到。把两条直径的中点用新边连起来，从 A 的直径某一端出发，经过 A 的中点、新边、B 的中点，到 B 的直径某一端，长度正好 ⌈d1/2⌉ + 1 + ⌈d2/2⌉。三者取最大就是新直径。

// 造公园：并查集维护「每个连通区的直径」，初始各区跑一遍树型dp
    int find(int i) {
        if (i != father[i]) {
            father[i] = find(father[i]);
        }
        return father[i];
    }

    // 树型dp：diameter[u] 记「路径过u」的最大和，dist[u] 记从u往下的最大深度
    void dp(int u, int f) {
        for (int e = head[u], v; e != 0; e = nxt[e]) {
            v = to[e];
            if (v != f) {
                dp(v, u);
            }
        }
        for (int e = head[u], v; e != 0; e = nxt[e]) {
            v = to[e];
            if (v != f) {
                diameter[u] = max(diameter[u], max(diameter[v], dist[u] + dist[v] + 1));
                dist[u] = max(dist[u], dist[v] + 1);
            }
        }
    }

    // 合并两个连通区：把两条直径的中点连起来，新区直径取三者最大
    // 点权都是1，直径D的树半径就是 ceil(D/2)
    void merge(int x, int y) {
        father[x] = y;
        diameter[y] = max((diameter[x] + 1) / 2 + (diameter[y] + 1) / 2 + 1,
                          max(diameter[x], diameter[y]));
    }

公式能背，但最好量一遍。随机森林加随机操作，跟「真的把两棵树按各种跨块连边方案拼起来、全源 BFS 算直径取最小」的暴力对答案，300 组 0 组不符，连中点确实最优。

造公园操作台：连中心，看直径怎么长

选一片森林点「下一步」，跟着操作序列走：合并时把两条直径的中点连起来，查询时直接报连通区的直径。

当前操作的连通区 直径中点与新边 其余点

查询就是取根上的直径值。整个题目：初始每个区一遍树形 dp 是 O(n)，每次合并 O(1)，路径压缩摊下来总计 O(n + q)。

三、问题：巡逻

巡逻：n 个点的树，每条边双向。警察局在 1 号点，警车每天从 1 号出发，一定要走过树上所有的边，最后回到 1 号。为了少走路，可以新建 k 条边，把树上任意两点直接相连，每条新边每天必须正好经过一次。求巡逻走边数量的最小值。n 不超过 10⁵，k 不超过 2。

先想不加新边：从 1 出发再回到 1，每条边至少走一次，实际上每条边都得走两遍（过去再回来），总共 2(n−1)。

四、k = 1：省下整条直径

新建一条边 (a, b)，它必须走一次。走法是这样：从 1 出发，a 到 b 的树路径上的边走一遍，其余边走两遍，中间用新边跳一次。这样每条树边不少于一遍、新边正好一遍、最后回得到 1，总数是 2(n−1) − dist(a,b) + 1。

dist(a,b) 最大就是直径 d1，所以 k = 1 的答案是 2(n−1) − d1 + 1。新边相当于把最长的那条链从「两遍」改成「一遍」。

五、k = 2：第二条捷径与直径重合的部分白搭

两条新边就要讲究了：两条捷径省下来的边不能重叠。同一条边省过一次，就不能再省第二次。

设第一条捷径取直径 D，长 d1。第二条取路径 P，它跟 D 重合的部分是白搭的：P 的长度 |P| 里，重合的每一段都省不下来，所以第二条的净节省是 |P| − 2|P ∩ D|。重合边自己不算节省，还把第一条已经省下的抵掉一份。

把这笔账记到边权上：直径上的边记 −1，其余边记 +1，跑一遍树形 dp 求最大路径权值和，拿到的 d2 就是第二条捷径的净节省。答案是 2(n−1) − d1 − d2 + 2。

// 巡逻：k=1 直接省掉整条直径；k=2 要把直径上的边权记成 -1 再跑一遍树型dp
    void dfs(int u, int f, int w) {
        last[u] = f;
        dist[u] = dist[f] + w;
        for (int e = head[u]; e != 0; e = nxt[e]) {
            if (to[e] != f) {
                dfs(to[e], u, 1);
            }
        }
    }

    void road() {
        dfs(1, 0, 0);
        start = 1;
        for (int i = 2; i <= n; i++) {
            if (dist[i] > dist[start]) start = i;
        }
        dfs(start, 0, 0);
        ed = 1;
        for (int i = 2; i <= n; i++) {
            if (dist[i] > dist[ed]) ed = i;
        }
        diameter1 = dist[ed];
    }

    // 第二遍dp：直径上的边记 -1，其余记 1，路径权值和的最大值就是第二条捷径
    void dp(int u, int f) {
        for (int e = head[u], v; e != 0; e = nxt[e]) {
            v = to[e];
            if (v != f) {
                dp(v, u);
            }
        }
        for (int e = head[u], v, w; e != 0; e = nxt[e]) {
            v = to[e];
            if (v != f) {
                w = (diameterPath[u] && diameterPath[v]) ? -1 : 1;
                diameter2 = max(diameter2, dist[u] + dist[v] + w);
                dist[u] = max(dist[u], dist[v] + w);
            }
        }
    }

    int compute() {
        road();
        if (k == 1) {
            return 2 * (n - 1) - diameter1 + 1;
        }
        for (int i = ed; i != 0; i = last[i]) {
            diameterPath[i] = true;
        }
        for (int i = 1; i <= n; i++) {
            dist[i] = 0;
        }
        dp(1, 0);
        return 2 * (n - 1) - diameter1 - diameter2 + 2;
    }

拿一棵毛毛虫算细账。主链 1 到 8，在 4 上挂三条边、在 5 上挂三条边，共 14 个点。直径 d1 = 7（8 到 14 那一侧）。第二条最优路径从 1 走到 14，长 7，跟直径重合的只有 4 到 5 那一条边，净节省 7 − 2×1 = 5。答案 = 2×13 − 7 − 5 + 2 = 16。跟「枚举加倍边集 + 新边点对、按奇偶模型取最小」的暴力对拍，2000 组随机树 k = 1 与 k = 2 全部吻合。

想当然会写成「跟直径没有公共边的最长路径」。这个口径在毛毛虫上只给出 3（短枝够不着），比正确的 5 小两条边。随机树上也站不住：5000 棵 12 点单位权随机树里，两种口径有 103 棵（2.06%）算得不一样。差在「重合一段、但换来一条长得多新路」这种情况，−1 技巧把它算成净赚，边不相交的口径直接判了死刑。

六、新边不是越多越好

链 n = 10：k = 1 答案 10，k = 2 答案 11。多加一条边反而多走一步。每条新边都必须正好走一次，捷径省不动时它就是纯开销。

星形（3 条臂各长 3，n = 10）：d1 = 6，d2 = 3，k = 1 答案 13，k = 2 答案 11。这种树加上第二条边才划得来。所以拿到题先看树形，再决定要不要把第二条边用满。

巡逻操作台：新边怎么省，警车怎么走

选一棵树和 k，点「下一步」：先定直径，再算出每条边走几遍，最后真的走一遍 Euler 回路，数数总共几步。

直径与只走一遍的边 当前这一步 走两遍的边 / 新边

七、复杂度分析

题目时间空间
造公园：初始各区树形 dpO(n)O(n)
造公园：每次合并 / 查询O(1)（路径压缩摊还）
巡逻：两遍 dfs + 第二遍 dpO(n)

空间按题目上限算。造公园 n = 3×10⁵：链式前向星 head、nxt、to 加上并查集 father、dp 的 dist 与 diameter，六个 int 数组，几十 MB 量级。巡逻 n = 10⁵ 多一个 diameterPath 标记，同样是 O(n)。

八、总结

要点三条。其一，合并两棵树时把两条直径的中点连起来，新直径 = max(⌈d1/2⌉ + 1 + ⌈d2/2⌉, d1, d2)，并查集根上存标签、合并时搬标签，300 组随机对拍证实连中点最优。其二，巡逻 k = 1 省下整条直径，k = 2 还要再省一条，重合的部分白搭，把直径边记 −1 跑树形 dp 就是第二条的净节省。其三，−1 技巧和「与直径边不相交的最长路径」是两回事，2% 的随机树就能分出高下；新边也未必越多越好，链上 k = 2 比 k = 1 还多走一步。

九、最后

这两道题共用同一个习惯：先问「最长路径被这次修改动了哪一块」。合并动的是两条直径的中间那段，加边动的是被捷径跳过的树路径。抓住这块，公式都是顺水推舟。

《完》
