A* 算法：给启发式一个上界

网格上求两点之间的最短步数，Dijkstra 会把小半个棋盘翻一遍。A* 只改一处：堆里排的数从「起点到这里的距离」换成「起点到这里的距离，加上这里到终点的预估距离」。流程和 Dijkstra 一模一样，边权非负的要求也一样。

零、Dijkstra 在网格上做无用功

301 行 301 列的网格，三成格子是障碍，从左上角 (0,0) 走到右下角 (300,300)，Dijkstra 一共弹出了 62386 个格子。终点在右下角，而左上、左下、右上三片离终点很远的格子也被挨个弹了一遍。

这些格子对答案没有贡献。弹到它们的时候，终点其实早就可以确定，只是堆里还压着一批键更小的记录，得先清掉才能轮到终点。键是「起点到当前格的距离」，离起点近的格子键小，于是搜索从起点开始均匀地往外铺，不管终点在哪一边。

要让搜索偏着往终点走，得先能回答一个问题：这个格子离终点大概还有多远。

一、把预估值加进堆的键

记 g 是起点到当前格的已知距离，h 是当前格到终点的预估距离。Dijkstra 拿 g 当堆键，A* 拿 g + h 当堆键。弹出规则、visited 判断、d 表的维护全部不动。

键换了，弹出顺序就变了：同一个 g 下，h 小的格子在堆里更靠前，也就是离终点近的那些先被处理。弹到终点时返回 d 表里的值，和 Dijkstra 给出的是同一个数。

落到代码上只改两个地方：起点入堆的键，和每个邻居入堆的键。

#include <bits/stdc++.h>
    using namespace std;

    int mv[5] = {-1, 0, 1, 0, -1};

    // 曼哈顿距离：只能上下左右走时，它恰好是两点之间的真实最短距离
    int f1(int x, int y, int tx, int ty) {
        return abs(tx - x) + abs(ty - y);
    }

    // A*：除了堆里排的是「起点到当前点的距离 + 当前点到终点的预估距离」，其余和 Dijkstra 一模一样
    int minDistance2(vector<vector<int>>& grid, int sx, int sy, int tx, int ty) {
        if (grid[sx][sy] == 0 || grid[tx][ty] == 0) {
            return -1;
        }
        int n = grid.size(), m = grid[0].size();
        vector<vector<int>> distance(n, vector<int>(m, INT_MAX));
        vector<vector<bool>> visited(n, vector<bool>(m, false));
        distance[sx][sy] = 1;
        priority_queue<array<int, 3>, vector<array<int, 3>>, greater<array<int, 3>>> heap;
        heap.push({1 + f1(sx, sy, tx, ty), sx, sy});
        while (!heap.empty()) {
            array<int, 3> cur = heap.top();
            heap.pop();
            int x = cur[1], y = cur[2];
            if (visited[x][y]) {
                continue;
            }
            visited[x][y] = true;
            if (x == tx && y == ty) {
                return distance[x][y];
            }
            for (int i = 0; i < 4; i++) {
                int nx = x + mv[i], ny = y + mv[i + 1];
                if (nx >= 0 && nx < n && ny >= 0 && ny < m && grid[nx][ny] == 1 && !visited[nx][ny]
                    && distance[x][y] + 1 < distance[nx][ny]) {
                    distance[nx][ny] = distance[x][y] + 1;
                    heap.push({distance[nx][ny] + f1(nx, ny, tx, ty), nx, ny});
                }
            }
        }
        return -1;
    }

切到空旷网格（预设 B）时，两种键弹的格子数一样多：没有障碍，条条大路都是最短路，谁先弹都一样。

二、预估距离不能超过真实距离

唯一的要求是：对任意格子，h 都不能大于该格子到终点的真实最短距离。

超了会发生什么。堆里的键被人为抬高，一条本来更优、只是 h 估得偏大的路径被压到了后面；终点带着一个次优的键先弹出来，函数直接返回，那条更优的路再也没机会被走到。

实测（本机 clang -O2，20000 组 2 到 13 行的随机网格，障碍率 30%）：三种合规的预估函数与 Dijkstra 的答案 0 处不符；把键改成 g 加两倍曼哈顿距离，127 组答案偏大，占 0.64%；改成五倍，345 组，占 1.73%。

网格放大到 30 到 70 行、3000 组用例时，两倍曼哈顿错 1439 组（48.0%），五倍错 1810 组（60.3%）。图越大，一条被高估的路压在终点后面的机会越多。

h 取 0 就是 Dijkstra，一定对但一点没提速；h 越贴近真实距离，弹出的格子越少；h 一旦越过真实距离，速度可能更快，答案开始出错。

三、三种常见的预估函数

曼哈顿距离 |dx| + |dy|：只能上下左右走的时候，它恰好是两点之间的真实最短距离，这是最紧的合规下界。

对角线距离 max(|dx|, |dy|)：允许斜着走时最紧；四方向移动时偏小，dx = dy = 8 时它给出 8，真实要走 16 步。

欧式距离 sqrt(dx² + dy²)：允许朝任意方向走时用它；四方向移动时同样偏小。

// 曼哈顿距离：只能上下左右走时最紧，它就是真实距离
    int f1(int x, int y, int tx, int ty) {
        return abs(tx - x) + abs(ty - y);
    }

    // 对角线距离：允许斜着走时最紧，四方向移动时会偏小
    int f2(int x, int y, int tx, int ty) {
        return max(abs(tx - x), abs(ty - y));
    }

    // 欧式距离：允许朝任意方向走时的自然选择，四方向移动时同样偏小
    double f3(int x, int y, int tx, int ty) {
        return sqrt((double)(tx - x) * (tx - x) + (double)(ty - y) * (ty - y));
    }

三个都合规，答案都对，差别只在弹多少格。还是那张 301×301、障碍率 30% 的网格，从 (0,0) 到 (300,300)，最短路是 601 步。

曼哈顿版弹出 7886 格、1.6ms，Dijkstra 弹出 62386 格、9.4ms，弹出量压到不足八分之一。对角线版 54362 格、8.3ms，欧式版 53988 格、7.6ms，几乎退回 Dijkstra。原因很直白：终点在对角，对角线和欧式给的都是 300 上下，真实距离是 600 上下，估得太松，吸引力就弱。曼哈顿给的是 600，差的那 1 是起点自己占的格子，d 表把起点记成 1。

换个反例。网格完全没有障碍时，三个预估函数的弹出格数都是整格 90601。任何一条只向右、向下的路径都是最短路，所有格子的 f 都相等，堆怎么排都得把它们弹完。启发式能起作用，靠的是障碍把路挤窄。

网格放大到 3000×3000，Dijkstra 648ms，A* 曼哈顿版 33ms，约 20 倍；弹出 204142 格，占全部 900 万格的 2.3%。

总结

A* 和 Dijkstra 的差别只有堆键：g 换成 g + h，其余一行不改。

h 不超过真实距离是正确性的全部条件。h 越紧、弹得越少；越过这条线，速度可能更快，答案就开始偏大。四方向的网格上曼哈顿最紧，对角线、欧式都偏松，省不下来多少。

启发式也有失灵的时候。空旷网格上每条路径都是最短路，f 全相等，A* 只能把整格弹完。想让搜索更快，功夫下在设计 h 上，把 h 调大只会换来错误答案。
