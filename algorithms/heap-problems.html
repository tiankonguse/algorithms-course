堆结构的常见题

堆最大的价值在于「反复取当前最值」：看一眼堆顶就知道谁最大，拿走和放回各要 O(log n)，排序只是它顺手的产出。这一讲用三道题把这个动作练熟。

零、背景

一堆候选摆在那儿，每次要挑出当前最大（或最小）的那个，处理完还可能冒出新的候选。数组里找最值要扫一遍，O(n)；这个动作要重复成千上万次，每次都扫一遍就太亏了。

堆把这件事拆成两步：看最值 O(1)（就是堆顶），删最值加插新值 O(log n)（上浮或下沉一层层走）。本讲的三道题，动作完全一样，只是堆里存的东西不同：

  • 合并 K 个有序链表：堆里存每条链当前的头，弹出最小的接进结果链，把它后面那个补进去。
  • 线段最多重合：堆里存「已经开始、还没结束」的线段的右端点，堆的大小就是当前点上的重合数。
  • 数组和减半：堆里存所有数的当前值，弹出最大的砍一半再放回去，直到砍够总和的一半。

一、合并 K 个有序链表

给 k 条已经排好序的链表，合成一条有序链表。记 N 是节点总数。

最直接的写法是两两合并：第一条和第二条合并，结果再和第三条合并，依次做下去。第 i 轮要扫过前 i 条链的所有节点，总代价 O(N·k)。实测 N = 100 万、k = 1000 时要 1664.86ms，k = 10000 时 35277.90ms，三十五秒。

另一个写法是把 N 个值全收进数组排序，再串成链表，O(N log N)。实测同一批数据 15.79ms，比堆版还快一点。排序赢在连续内存：一次 sort 是顺序扫描加归并，堆版每弹一个节点要跳一次指针，再走 O(log k) 层上浮下沉。代价是要多开一个 O(N) 的数组，而且必须先把 k 条链全遍历一遍才能开始排。

堆版只要 O(k) 的额外空间，而且弹一个就能输出一个。做法是：堆里放每条链当前的头节点（最多 k 个），弹出值最小的那个接到结果链尾部，如果它有后继，把后继补进堆。

实测把 N 固定成 100 万，k 从 10 涨到 20 万，堆版耗时的变化（g++ -O2，复用节点、不开新内存）：

k 从 10 涨到 10000，log k 从 3.3 涨到 13.3，堆版的耗时从 28.03ms 只涨到 37.56ms；k = 10 万、20 万时是 76.29ms、69.69ms。堆版的瓶颈在指针跳转和比较器调用，不在 log k 这一项上。

三个实现细节：

  • 堆里存的是节点编号，比较的是节点的值，所以要写一个比较器（比较器的写法在「哈希表、有序表与比较器」那一讲）。
  • 空链不能进堆。k 条链里可能有空的，进堆之前先判一下。
  • 先弹出一个节点当总头，再进循环。这样结果链的头就定下来了，循环里只管往尾部接。

弹出来的节点直接复用，不开新节点，全程没有内存分配。这也是链表题的惯例：能改指针就别 new。

// 数组版链表：val[i] 是节点 i 的值，nxt[i] 是后继编号，-1 表示没有
    const int MAXN = 1000005;
    int val[MAXN], nxt[MAXN];

    struct Cmp {
        bool operator()(int a, int b) const { return val[a] > val[b]; }
    };

    // heads[0..k-1] 是 k 条升序链表的头节点，返回合并后的头节点
    int mergeKLists(int heads[], int k) {
        priority_queue<int, vector<int>, Cmp> heap;
        for (int i = 0; i < k; i++) {
            if (heads[i] != -1) heap.push(heads[i]);
        }
        if (heap.empty()) return -1;
        int head = heap.top();
        heap.pop();
        int pre = head;
        if (nxt[pre] != -1) heap.push(nxt[pre]);
        while (!heap.empty()) {
            int cur = heap.top();
            heap.pop();
            nxt[pre] = cur;
            pre = cur;
            if (nxt[cur] != -1) heap.push(nxt[cur]);
        }
        nxt[pre] = -1;
        return head;
    }

二、线段最多重合问题

给 n 条线段 [l, r]，问某个点上最多有多少条线段同时盖着它。

暴力写法是枚举每条线段的左端点 x，数一数有多少条线段盖住 x，O(n²)。实测 n = 20000 时 38.92ms，n 再大一个数量级就到 4 秒了。

只看左端点就够了吗？够。覆盖数 f(x) 只在端点处变化，两个相邻端点之间它是常数；取到最大值的那段常数区间，它的左端点一定是某条线段的左端点。所以只需检查 n 个左端点。

堆的做法把这件事变成一遍扫描：按左端点从小到大排序，小根堆里存「已经开始、还没结束」的线段的右端点。处理到 [l, r] 时：

  1. 把所有 ≤ l 的右端点弹掉，这些线段在 l 处已经结束了；
  2. 把 r 压进堆；
  3. 堆的大小就是 l 这个点上的重合数，拿它更新答案。

为什么弹的是「右端点 ≤ l」：小根堆的堆顶是结束最早的那条，堆顶都大于 l 说明剩下的全都还没结束，可以停了。每条线段的右端点进堆一次、出堆一次，所以是 O(n log n)。

这里有个等号要选。写 heap.top() <= l 表示「右端点等于 l 的线段已经结束」，也就是 [1,4] 和 [4,5] 可以严丝合缝接在一起，不算重合；写成 < 就认为它们在 4 这个点上重合。两种题面都真实存在（会议室安排是一类，区间分组是另一类），代码只差一个等号。

值域不大而且是整数时，还有更快的做法：开一个差分数组，每条线段 d[l]++、d[r+1]--（或者按另一种题面写 d[r]--），最后求前缀和的最大值，O(M + n)。实测 n = 20 万、值域 10⁶ 时，堆版 15.11ms，差分约 1ms。但值域到 10⁹ 时差分数组要 3.7 GB，根本开不出来，堆版照样跑：n = 10 万、值域 10⁹ 时 5.74ms。堆版的代价跟值域没关系，这是它相对差分的优势。

// 线段最多重合：seg[i] = {l, r}，认为 [1,4] 与 [4,5] 可以严丝合缝接在一起，不算重合
    int maxCover(vector<pair<int, int>>& seg) {
        sort(seg.begin(), seg.end());
        priority_queue<int, vector<int>, greater<int>> heap;  // 小根堆，存已经开始的线段的右端点
        int ans = 0;
        for (auto& s : seg) {
            while (!heap.empty() && heap.top() <= s.first) heap.pop();
            heap.push(s.second);
            ans = max(ans, (int)heap.size());
        }
        return ans;
    }

    // 另一种题面：[1,4] 与 [4,5] 认为在 4 这个点上有重合，只差一个等号
    int minGroups(vector<pair<int, int>>& seg) {
        sort(seg.begin(), seg.end());
        priority_queue<int, vector<int>, greater<int>> heap;
        int ans = 0;
        for (auto& s : seg) {
            while (!heap.empty() && heap.top() < s.first) heap.pop();
            heap.push(s.second);
            ans = max(ans, (int)heap.size());
        }
        return ans;
    }

三、让数组和减半的最少操作次数

n 个正数，每次操作挑一个数砍掉一半（奇数时砍出小数也没关系），问最少几次能让总和降到原来的一半以下。

贪心：每次砍当前最大的那个。砍 x 能减掉 x/2，挑最大的减掉得最多；砍完它变成 x/2，可能就不再是最大的了。用交换论证可以说清楚：最优解的第一步如果砍的不是最大值 x，换成砍 x，减掉的量更多，之后面对的是同样形状的子问题，不会更差。

接下来就是堆的活儿：大根堆存所有数，弹出最大的砍一半，把砍剩下的放回去，累加已经砍掉的量，直到砍够总和的一半。

实测 n = 1 万时堆版 0.51ms，暴力写法（每次线性扫一遍找最大值）71.74ms，差 140 倍；n = 10 万时堆版 8.14ms，暴力已经到几十秒了。

答案有多大？随机值 1 到 10⁴ 时答案约 0.77n（n = 10 万时 77315 次）；n 个数全相等时恰好是 n（每个都要砍一次，砍完一轮总和正好减半）；一个巨大值配一堆小数时只要 2 次。实测还量了「单个元素最多被砍几次」，n 从 100 到 10 万都是 2 次。

写的时候有两种写法。第一种直接用 double：总和和已砍掉的量都用 double，砍一半就是除以 2。第二种把每个数左移 20 位塞进 long long，砍一半写 /= 2，全程没有浮点。实测 7300 组随机数据，两种写法的答案完全一样。

整数版的左移位数决定了「一个元素被砍多少次才开始丢精度」：左移 20 位意味着第 21 次砍半时才会因为整数除法丢掉东西，而前面实测单个元素最多被砍 2 次。double 那边也不用担心：题目值域下总和最多 10⁹ 量级，double 能精确表示的整数到 2⁵³ ≈ 9 × 10¹⁵。

// 每次挑当前最大的数砍掉一半，问最少砍几次让总和降到原来的一半以下
    int halveArray(vector<int>& nums) {
        priority_queue<double> heap;  // 大根堆
        double sum = 0;
        for (int x : nums) {
            heap.push((double)x);
            sum += x;
        }
        sum /= 2;  // 这就是要砍掉的总量
        int ans = 0;
        for (double minus = 0; minus < sum; ans++) {
            double cur = heap.top() / 2;
            heap.pop();
            minus += cur;
            heap.push(cur);
        }
        return ans;
    }
const int MAXH = 100005;
    long long heapArr[MAXH];
    int heapSize;

    void heapify(int i) {
        int l = i * 2 + 1;
        while (l < heapSize) {
            int best = l + 1 < heapSize && heapArr[l + 1] > heapArr[l] ? l + 1 : l;
            best = heapArr[best] > heapArr[i] ? best : i;
            if (best == i) break;
            swap(heapArr[best], heapArr[i]);
            i = best;
            l = i * 2 + 1;
        }
    }

    // 整数版：每个数左移 20 位，砍一半就是 /= 2，全程没有浮点
    int halveArray2(vector<int>& nums) {
        heapSize = (int)nums.size();
        long long sum = 0;
        for (int i = heapSize - 1; i >= 0; i--) {
            heapArr[i] = (long long)nums[i] << 20;
            sum += heapArr[i];
            heapify(i);
        }
        sum /= 2;
        int ans = 0;
        for (long long minus = 0; minus < sum; ans++) {
            heapArr[0] /= 2;
            minus += heapArr[0];
            heapify(0);
        }
        return ans;
    }

五、复杂度分析

题朴素做法堆做法额外空间说明
合并 K 个有序链表O(N·k) 顺序合并O(N log k)O(k)N 个节点各进堆出堆一次，堆里最多 k 个
线段最多重合O(n²) 枚举端点O(n log n)O(n)排序 O(n log n)，每条线段的右端点各进出堆一次
数组和减半O(ans·n) 每次扫一遍O(ans·log n)O(n)ans 实测在 n 的量级，整体 O(n log n)

三道题的额外空间都是「堆的容量」：分别是 k、n、n。堆本身可以就地开在原数组上（数组和减半那题就是这么做的），也可以另外开一个数组。

排序这一步只在第二题里有，O(n log n)，跟堆的部分同阶，不额外增加量级。如果输入本来就有序，这一步可以省掉。

总结

堆解决的是「反复取最值」这个循环：看堆顶 O(1)，删最值加插新值 O(log n)。三道题都是这一个动作，区别在于堆里存什么：合并链表存每条链当前的头（k 个），线段重合存还没结束的右端点（最多 n 个），数组减半存所有数的当前值（n 个）。

几个容易写错的地方：空链不能进堆；线段重合那道题的等号决定「严丝合缝算不算重合」，值域小的时候它直接决定对错；数组减半那道题用 double 写最省事，改成整数版要记得左移足够多位。

合并 K 个有序链表还有个分治写法（两两合并，每轮规模翻倍），复杂度一样是 O(N log k)，常数比堆版小，因为它不跳指针。堆版的优点是可以一边弹一边输出，不用等全部候选到齐。后面的图论题里还会反复用到这个「一边弹一边输出」的形状。
