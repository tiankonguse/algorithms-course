字符串哈希：把串变成数

两个串比相等要按长度付代价，把它们各乘成一个 64 位整数之后，比较就只剩一次整数判断，代价与串长无关。代价是偶尔会撞。这一页先把模板推一遍，再看两个最直接的用法：给一堆字符串去重，以及在长串里找模式串。

零、谁更快，取决于串长什么样

std::string 的 == 先比长度，长度一样再逐字节比，发现不同就停。两个随机串之间，第一个字符不同的概率是 61/62，比较几乎立刻结束。

实测：10000 个长 1500 的随机串扔进 set<string> 去重，5.96 毫秒；换成先把每个串算成一个 64 位整数、再排序去重，21.78 毫秒，慢了三倍多。算哈希要把 1500 个字符全乘一遍，而逐字节比较只看了第一个字节。

把数据换成共享 90 个字符前缀的串（日志、URL、DNA 都长这样），名次反过来：100000 个长 100 的串，哈希 18.66 毫秒，set<string> 69.64 毫秒，哈希快 3.7 倍。这时每次比较都要先跳过 90 个相同字符。

所以哈希的价值不在「比较一次」，在于一次比较的代价和串长脱钩。要反复拿同一段去比（滑窗那种），或者要比的段特别长，它才开始划算。

一、哈希函数要满足的四条性质

哈希函数的用处是把复杂样本变成数字，以后样本之间的对比就变成数字之间的对比。四条性质：

1）输入的可能性是无限的，输出的范围相对有限，这里是 264 个值。

2）输入同样的样本一定得到同样的输出，函数里没有任何随机机制。

3）输入不同的样本也可能得到同样的输出，这叫哈希碰撞。

4）大量不同的输入，得到的输出会几乎均匀地铺满整个输出域。这条最要紧。

碰撞理论上躲不掉，输出只有 264 个格子，输入却有无限多个，抽屉原理摆在那里。好的哈希函数能做的是让它低到可以忽略：两个不同的串撞上的概率约 1/264，10000 个串两两比较也只有大约 2.7×10-12。

二、自然溢出就是对 264 取模

unsigned long long 只有 64 位，加减乘的结果超出范围会丢掉高位，标准里写得很清楚：结果等于数学上的真值对 264 取模。

要的是「取模」这个动作本身，模数是不是质数无所谓，因为哈希值只用来判相等，不做除法也不求逆元。

这里写 unsigned long long 而不是 long long：有符号整数溢出在标准里是未定义行为，编译器有权做任何事；无符号的溢出是明确定义的。两者算出来的位模式其实一样，写 unsigned 是让代码说的是自己想说的话。

三、把串当成 499 进制数

每个字符映射成一个正整数当数字，整串看成一个 base 进制数。从左往右用秦九韶法累乘，一位一位接上去：

hs[i] = hs[i-1] * base + 值(s[i])

字符映射按数字、大写、小写排开，一共 62 个：'0' 到 '9' 是 1 到 10，'A' 到 'Z' 是 11 到 36，'a' 到 'z' 是 37 到 62。

细节一：每一位的值从 1 开始，不从 0 开始。从 0 开始的话前导零不贡献位权，"0" 和 "00" 都会算出 0。在字符表只有「0、1」、串长不超过 12 的随机数据上实测，改成从 0 开始有 58.85% 的用例数出来的不同串个数是错的。

细节二：base 要大于映射之后的最大值。这里最大值是 62，所以 base 至少取 63，499 是个常用的质数。base 太小会「进位」撞到低位去：base 取 10、字符表是 62 个字符时有 0.33% 的用例出错；base 取 1 时所有串的哈希退化成各位数字相加，出错率跳到 25.75% 到 81.26%，已经不能用了。

四、pw 与 hs 两个数组

要做到「任意子串的哈希值 O(1) 取出来」，需要两个数组：pw[i] 记 base 的 i 次方，hs[i] 记前缀 s[0..i] 的哈希值。

子串 s[l..r] 的哈希值就是把 hs[r] 减掉前 l 个字符贡献的那部分。hs[l-1] 乘上 base 的 (r-l+1) 次方之后，它的每一项刚好和 hs[r] 的前几项对齐，相减只剩中间段：

getHash(l, r) = hs[r] - hs[l-1] * pw[r-l+1]

乘的幂次是 r-l+1，也就是子串长度。

下面是完整模板。数组开成全局的，多个查询共用一份：

// 模板：pw 记 base 的各次方，hs 记前缀哈希值，都是 64 位自然溢出
    const int MAXN = 100005;
    const int base = 499;

    unsigned long long pw[MAXN], hs[MAXN];

    void build(const string &s) {
        int n = s.size();
        pw[0] = 1;
        for (int i = 1; i < n; i++) {
            pw[i] = pw[i - 1] * base;
        }
        hs[0] = s[0] - 'a' + 1;
        for (int i = 1; i < n; i++) {
            hs[i] = hs[i - 1] * base + s[i] - 'a' + 1;
        }
    }

    // 返回 s[l...r] 的哈希值
    unsigned long long getHash(int l, int r) {
        unsigned long long ans = hs[r];
        if (l > 0) {
            ans -= hs[l - 1] * pw[r - l + 1];
        }
        return ans;
    }

五、题 1：统计有多少个不同的字符串

洛谷 P3370，n 个字符串，长度不超过 1500，问有多少个两两不同。做法就是把这套映射用一遍：每个串算一个哈希值塞进数组，排序，数相邻不同的段数，代码里没有第二处技巧。

// 数字 + 大写 + 小写，一共 62 个字符，映射到 1 到 62
    int v(char c) {
        if (c >= '0' && c <= '9') {
            return c - '0' + 1;
        } else if (c >= 'A' && c <= 'Z') {
            return c - 'A' + 11;
        } else {
            return c - 'a' + 37;
        }
    }

    // 整个字符串的哈希值
    unsigned long long value(const string &s) {
        unsigned long long ans = v(s[0]);
        for (int i = 1; i < s.size(); i++) {
            ans = ans * base + v(s[i]);
        }
        return ans;
    }

    // 把 n 个哈希值排序，再数有几段不同的
    int cnt(unsigned long long *nums, int n) {
        sort(nums, nums + n);
        int ans = 1;
        for (int i = 1; i < n; i++) {
            if (nums[i] != nums[i - 1]) {
                ans++;
            }
        }
        return ans;
    }

这题换 set<string> 也能过。两种写法的差距要等规模上去才明显：100 万个长 12、字符表 4 的串，unordered_set<unsigned long long> 563 毫秒，set<string> 1154 毫秒，都数出 970756 个不同串。手工算哈希再排序只比哈希表慢一点，还省掉一次扩容。

六、题 3：用子串哈希替代 KMP

题意是找出模式串在文本串里第一次出现的位置，找不到返回 -1。有了上面的模板，做法只剩三句话：把文本串的 pw 与 hs 建出来，把模式串整串的哈希值算出来，然后从左往右滑一个等长的窗口逐个比。

// 在 s1 里找 s2 第一次出现的位置，找不到返回 -1
    int strStr(const string &s1, const string &s2) {
        int n = s1.size(), m = s2.size();
        build(s1);
        unsigned long long h2 = s2[0] - 'a' + 1;
        for (int i = 1; i < m; i++) {
            h2 = h2 * base + s2[i] - 'a' + 1;
        }
        for (int l = 0, r = m - 1; r < n; l++, r++) {
            if (getHash(l, r) == h2) {
                return l;
            }
        }
        return -1;
    }

实测 10000 个字符的文本串配 5000 个字符的模式串、保证找不到：哈希版 0.056 毫秒，KMP 0.105 毫秒。把规模加到 200000 与 100000，哈希 0.827 毫秒，KMP 2.095 毫秒。

标准库的 string::find 比两者都快（同样规模 0.024 毫秒），它先用 memchr 找模式串首字符出现的位置，大多数位置只看一个字节就跳到下个候选。哈希版的意义是能往两边长：判断回文、求最长公共前缀、随便两段比一比，用的都是同一个 getHash，函数体不用改。

两个容易写错的地方：一是相减时乘的幂次写成 pw[r-l]，少了一次方，15% 到 40% 的用例会答错；二是忘了 l > 0 才减 hs[l-1] * pw[...]，直接写成永远减，l = 0 的窗口就全错了。前者是细节写错，后者是边界写错，出错的用例比例差不多。

哈希计算台

每点一步往下算一格 hs：hs[i] = hs[i-1] × 499 + 值(s[i])。整串算完之后，选一段子串看它的哈希值是怎么减出来的。数字都是 64 位自然溢出的真值。

七、复杂度分析

做法关键操作时间空间
题 1　统计不同字符串每个串乘一遍，再排序数段O(总长度 + n log n)O(n)
题 3　找子串位置建两个数组，再滑一遍窗口O(n + m)O(n + m)

题 1 的排序比较的是 8 字节整数，一次比较的代价固定；要是改用哈希表，期望 O(总长度)。题 3 建数组是 O(n)，扫窗口是 O(n) 个窗口各摊一次减法，与模式串长度无关。空间按题目上限开：题 1 的 MAXN 取 10005，题 3 取 100005，两个数组各 8 字节一格，加起来不到 2 MB。注意 pw 与 hs 只依赖被查的那一个串，多个查询共用一份就够。

总结

四位映射里第 4 条最要紧，碰撞躲不掉，好的 base 把它压到 2-64 量级。

自然溢出就是对 264 取模，写 unsigned long long，模数不必是质数。

每一位从 1 开始、base 大于映射后的最大值（这里是 62），499 是常用质数。

子串公式里乘的是 base 的 r-l+1 次方，也就是子串长度。

题 1 是整串哈希加排序去重，题 3 是子串哈希滑窗，把 KMP 干的活接了过来。到这里任意子串的哈希值都能 O(1) 取出来了，后面几道题就是拿这个能力去换东西：换掉一整轮逐位比较，或者换掉一个窗口里的词频表。
