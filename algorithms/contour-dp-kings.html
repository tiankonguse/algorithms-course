轮廓线 dp：摆放国王与被覆盖掉的邻居

前面三道题需要的邻居都在轮廓线上，读一位就够。摆放国王要往左上多看一格，而那一格的信息在走到当前位置时已经被轮廓线自己覆盖掉了。这一讲讲的就是这种「位不够用」的情况怎么处理。

零、背景

国王能攻击周围 8 个方向。按行优先扫到 (i, j)，这 8 个方向里有 4 个还没走到：右、右下、下、左下。剩下 4 个是左、左上、上、右上。

左、上、右上这三个都还在轮廓线上，分别对应第 j−1、j、j+1 位。麻烦的是左上：它是 (i−1, j−1)，在轮廓线上占的也是第 j−1 位，跟「左」是同一位。

一、问题

n × n 的棋盘上摆 k 个国王，任何两个国王不能互相攻击，也就是 8 个方向上都不能有别的国王。返回摆放方法数。n 不超过 9。

这题比前三道多两样东西：一是要数国王的个数，二是要往左上看一格。

二、左上那一格去哪了

走到 (i, j−1) 的时候，第 j−1 位装的是 (i−1, j−1) 的决定，也就是那时还没用掉的「上」。等走到 (i, j)，第 j−1 位已经被改成了 (i, j−1) 的决定，原来的信息没了。

信息不能丢，那就只能额外带一个参数。状态变成 (i, j, s, leftup, k)：leftup 单独表示 (i−1, j−1) 有没有国王，k 是还剩几个国王没摆。

转移的时候有个现成的便宜：走到 (i, j+1) 时，它的「左上」就是当前的「上」。所以下一层的 leftup 直接填 up 就行，不需要额外算。

// 来到 (i, j)，轮廓线是 s，leftup 单独当参数带进来
    int left    = j == 0 ? 0 : get(s, j - 1);   // (i, j-1)   本行左侧
    int up      = get(s, j);                    // (i-1, j)   正上方
    int rightup = get(s, j + 1);                // (i-1, j+1) 右上方

    // 不放：走到 (i, j+1) 时，它的「左上」就是现在的 up
    long long ans = dp[j + 1][set(s, j, 0)][up][k];

    // 放：四个方向都得空着，还要有余额
    if (k > 0 && left == 0 && leftup == 0 && up == 0 && rightup == 0) {
        ans += dp[j + 1][set(s, j, 1)][up][k - 1];
    }
    dp[j][s][leftup][k] = ans;

这里有个细节：rightup = get(s, j + 1) 在 j = n−1 时取的是第 n 位，而 s 只有 n 位，那一位恒为 0。这正好对上「棋盘外面没有格子」，不用单独判断边界。

换行的地方也一样：dp[n][s][0][k] 和 dp[n][s][1][k] 都填成同一个值。新一行的第 0 列没有左邻，leftup 是 0 是 1 都不影响，索性两个都给同一个数，免得判边界。

三、多出来的那一维

k 这一维跟轮廓线没关系，纯粹是题目要求「恰好 k 个」。做法和背包一样：状态里加一维记还剩几个，摆一个就减一，全走完时只有 k = 0 的那格算 1。

prepare 的初值写成了 k == 0 ? 1 : 0，这就是那个「全走完」的边界：棋盘都扫完了，还剩国王没摆的方案不算数。

long long dp[MAXN + 1][1 << MAXN][2][MAXK];
    long long prepare[1 << MAXN][MAXK];

    long long compute() {
        for (int s = 0; s < maxs; s++)
            for (int k = 0; k <= kings; k++) prepare[s][k] = (k == 0 ? 1 : 0);
        for (int i = n - 1; i >= 0; i--) {
            for (int s = 0; s < maxs; s++)
                for (int k = 0; k <= kings; k++) {
                    dp[n][s][0][k] = prepare[s][k];
                    dp[n][s][1][k] = prepare[s][k];
                }
            for (int j = n - 1; j >= 0; j--)
                for (int s = 0; s < maxs; s++)
                    for (int leftup = 0; leftup <= 1; leftup++)
                        for (int k = 0; k <= kings; k++) {
                            int left    = j == 0 ? 0 : get(s, j - 1);
                            int up      = get(s, j);
                            int rightup = get(s, j + 1);
                            long long ans = dp[j + 1][set(s, j, 0)][up][k];
                            if (k > 0 && left == 0 && leftup == 0 && up == 0 && rightup == 0)
                                ans += dp[j + 1][set(s, j, 1)][up][k - 1];
                            dp[j][s][leftup][k] = ans;
                        }
            for (int s = 0; s < maxs; s++)
                for (int k = 0; k <= kings; k++) prepare[s][k] = dp[0][s][0][k];
        }
        return dp[0][0][0][kings];
    }

四维状态填起来是四层循环，加上状态数 2n，n = 9 时一次求解要跑 10 × 512 × 2 × 82 格。本机实测把 k 从 0 到 81 全部求一遍是 114.41 毫秒，单个 k 大概 1.4 毫秒。

四、摆国王台

选一个规模和 k，点「放」或「不放」逐个格子决定。四个参照方向用颜色标出来了：蓝是左，橙是左上（单独带的那一位），绿是上，紫是右上。

摆国王台：看 leftup 怎么跟着走

「放」这个按钮在四个方向任何一个有国王、或者 k 已经是 0 的时候会变灰。右边那排格子是轮廓线，下面单独那一小格是 leftup，它不在轮廓线上，是另外带进来的。

五、实测

n = 9 时 k 从 0 一路摆到 25，答案先涨后落，最多的是 k = 13 的 57647295377 种。k = 25 只剩 1 种，就是那个 5 × 5 的错位棋盘。k 再大就没地方摆了，ceil(9/2) × ceil(9/2) = 25 是上限。全部 k 加起来是 269718819131 种。

内存这块，空间压缩只救回来 8 倍，比前面几题的几十倍差得远。原因是 leftup 和 k 这两维没法压：四维全留是 dp[9][9][512][2][82]，51.9 MB；压掉行号那一维是 dp[10][512][2][82]，6.41 MB。

顺带量了一个错法的抓取率：不单独带 leftup，直接拿 get(s, j - 1) 当左上用。n 取 2 到 5、k 随机，500 组里有 145 组答案对不上，抓取率 29.00%。这个数不算高，说明光靠随机小数据不一定能抓出来，写的时候得自己想清楚。

复杂度分析

n × n 的棋盘，状态数 S = 2n，K 是国王个数。

写法时间复杂度空间复杂度n = 9 时的规模
轮廓线 dp（四维全留）O(n² · S · K)O(n² · S · K)9 × 9 × 512 × 2 × 82，51.9 MB
轮廓线 dp + 空间压缩O(n² · S · K)O(n · S · K)10 × 512 × 2 × 82，6.41 MB

空间按题目上限算：n ≤ 9，所以 S = 512、K ≤ 82（n² + 1 = 82）。表里 long long 是 8 字节，第一维留 n + 1 = 10 层。转移本身是 O(1)，四个方向各读一次，所以时间就是表的格子数。

总结

这道题给轮廓线 dp 补上了一条：状态里的位会被后面走到的格子覆盖，需要的信息必须在覆盖之前取出来另存。具体到这里就是 leftup，它和「左」共用第 j−1 位，走到 (i, j) 时那一位已经被本行的决定改掉了。好消息是补的参数不用重新算，走到 (i, j+1) 时它的「左上」就是当前的「上」，直接传下去。加上题目要求「恰好 k 个」，状态就变成 (i, j, s, leftup, k) 五样。

再往后是轮廓线 dp 里更难的一支：插头 dp，也叫连通性状压 dp。它要在状态里维护轮廓线上各个插头属于哪个连通块，编码和处理都比这里复杂得多。
