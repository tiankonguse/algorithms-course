Morris 遍历：原理与先序中序

递归和自己拿栈的写法，额外空间都跟着树高走。Morris 遍历把节点自己的空闲右指针借来当线索，用完就还原，全程不开栈也不递归。代价是每个节点最多被到达两次，时间仍然是 O(n)。

零、背景

前两种写法的额外空间都是 O(h)，h 是树高。链上 h = n，本机系统栈 8176 KB，递归一帧约 93 字节，实测一路向左的链 85000 个节点能跑完，90000 个直接段错误。

一路向右的链反倒不崩：递归函数里第二个调用 f(cur->right) 处在尾位置，开了 -O2 编译器把它换成循环，110 万个节点的右偏链照样跑完。把优化关掉（-O0）立刻现原形，25 万层能过、30 万层段错误。这份便宜是编译器给的，跟算法没关系。

Morris 遍历压根不碰栈。递归不用，显式栈也不开，全程只有 cur 和 mostRight 两个指针变量，代价是遍历过程中会临时改树，走完再改回来。

节点定义沿用前面，三个字段，没孩子写 nullptr。

struct TreeNode {
        int val;
        TreeNode* left;
        TreeNode* right;
        TreeNode(int v) : val(v), left(nullptr), right(nullptr) {}
    };

下面全程用这棵 7 节点满二叉树做例子，节点值就是 1 到 7。

一、空闲指针藏在哪

一棵 n 个节点的二叉树有 2n 个指针字段，其中 n−1 个指着孩子，剩下 n+1 个是空的。Morris 只用得上其中一类，而且这类空指针一定有：有左子树的节点，它左子树的那个最右节点，右指针必然是空的，否则它就不是最右了。

把这个空指针临时指回当前节点，等于在树上留一根线，写着「往左下去的这棵子树走完，顺着这根线能爬回来」。爬回来之后把线拆掉，树跟没动过一样。

顺着这根线回来的时候，当前节点就被到达了第二次。这就是整套方法的全部机关。

7 个节点里，1、2、3 有左子树，各被到达两次；4、5、6、7 没有左子树，只可能被顺着父节点的指针到达一次。合计 10 次，正好是 n 加上「有左子树的节点个数」。

二、三条分支

整个循环只有三个出口，把它们摆在一起看最清楚。

写成代码就是下面这样。判断第二次到达的依据是 mostRight->right 已经等于 cur，而不是等于空。

// Morris 遍历的骨架：cur 为空时停，其余只有三条分支
    // 借左子树最右节点的右指针当线索，用完立刻还原
    void morris(TreeNode* head) {
        TreeNode* cur = head;
        TreeNode* mostRight = nullptr;
        while (cur != nullptr) {
            mostRight = cur->left;
            if (mostRight != nullptr) {                 // cur 有左树
                while (mostRight->right != nullptr && mostRight->right != cur) {
                    mostRight = mostRight->right;       // 一路向右找到底
                }
                if (mostRight->right == nullptr) {      // 第一次到达 cur
                    mostRight->right = cur;             // 把空指针借来指回 cur
                    cur = cur->left;
                    continue;
                } else {                                // 第二次到达 cur
                    mostRight->right = nullptr;         // 用完必须还原
                }
            }
            cur = cur->right;                           // 无左树、或第二次到达，都往右
        }
    }

还原那一步不能省。省了以后 mostRight->right 一直指着 cur，下一轮找最右节点时又走到它，又把它指回 cur，循环再也出不来。这个错法不用测错误率，跑起来就卡死。

内圈那个 while 的条件也要写全。mostRight->right != nullptr 单独用会在第二次到达时一路绕回 cur 再往下走，同样停不下来。&& mostRight->right != cur 这半句是刹车。

三、先序：打印放在第一次到达

先序是「根 左 右」，根要在进左子树之前打印。Morris 里正好有两个落脚点：有左子树的节点在第一次到达时打印，没有左子树的节点只有那一次机会，也得打印。

// 先序：有左树的节点在第一次到达时打印，无左树的节点只能到这一次
    vector<int> preorderTraversal(TreeNode* head) {
        vector<int> ans;
        TreeNode* cur = head;
        TreeNode* mostRight = nullptr;
        while (cur != nullptr) {
            mostRight = cur->left;
            if (mostRight != nullptr) {
                while (mostRight->right != nullptr && mostRight->right != cur) {
                    mostRight = mostRight->right;
                }
                if (mostRight->right == nullptr) {
                    ans.push_back(cur->val);
                    mostRight->right = cur;
                    cur = cur->left;
                    continue;
                } else {
                    mostRight->right = nullptr;
                }
            } else {
                ans.push_back(cur->val);
            }
            cur = cur->right;
        }
        return ans;
    }

漏掉 else 那一支是最常见的写法错误：所有没有左子树的节点都不会进答案，而任何一棵非空树的最右节点一定没有左子树。2 万组随机小树（n 取 1 到 9）实测，这个错法 100% 被抓。把打印挪到第二次到达处，抓取率 82.03%。

四、中序：写在循环体末尾

中序是「左 根 右」，根要在左子树走完之后打印。在 Morris 里这对应两个时机：有左子树的节点在第二次到达时，以及没有左子树的节点在被到达时。

这两个时机可以合并。第一次到达走的是 continue，不会落到循环体末尾，所以把 push_back 写在 cur = cur->right 前面，两个时机就自动都覆盖了。

// 中序：写在循环体末尾，第二次到达与「无左树直达」都从这里过
    vector<int> inorderTraversal(TreeNode* head) {
        vector<int> ans;
        TreeNode* cur = head;
        TreeNode* mostRight = nullptr;
        while (cur != nullptr) {
            mostRight = cur->left;
            if (mostRight != nullptr) {
                while (mostRight->right != nullptr && mostRight->right != cur) {
                    mostRight = mostRight->right;
                }
                if (mostRight->right == nullptr) {
                    mostRight->right = cur;
                    cur = cur->left;
                    continue;                           // 第一次到达不打印
                } else {
                    mostRight->right = nullptr;
                }
            }
            ans.push_back(cur->val);                    // 中序位置：左树已走完
            cur = cur->right;
        }
        return ans;
    }

反过来把打印写在第一次到达处，得到的就是先序，2 万组里 76.78% 能对上差别。写在第二次到达处与写在末尾完全等价，2 万组一组都不差，这两种写法随便挑。

顺带说一句，else 那一支同样不能省，漏了也是 100% 被抓。

五、为什么还是 O(n)

内圈 while 看着像每个节点要花 O(h)，这是最容易误判的地方。实际上每条向右的边最多被走两遍：一遍是顺着往下找 mostRight，另一遍是从线索爬回来时经过它。总步数有 2n 的上界。

链状树是个极端：所有节点都没有左子树，内圈一次都不进，总到达次数就是 n。完全二叉树和随机树都稳定在 1.5n 附近，因为有左子树的节点大约占一半。

速度上没有惊喜。n = 10⁶ 的随机树上，递归先序 23.41ms、显式栈 18.59ms、Morris 22.84ms，同一个量级。链状 n = 10⁶ 上 Morris 1.96ms、显式栈 2.38ms。买 Morris 是为了那 O(1) 的空间，别指望它更快。

复杂度分析

写法时间额外空间空间花在哪
递归三序遍历O(n)O(h)系统栈，深度等于树高，链上 n 层会崩
显式栈三序遍历O(n)O(h)自己开的栈，n = 10⁶ 随机树上峰值 28 个指针
Morris 遍历O(n)O(1)只有 cur 与 mostRight 两个指针变量

时间那栏的常数要拆开看：Morris 里每个节点被到达 1 到 2 次，总到达次数在 n 到 2n 之间，具体是 n 加上有左子树的节点个数；内圈 while 的累计步数不超过 2n。所以 O(n) 前面那个常数在 3 附近，比递归的 1 大，实测下来两者耗时同量级。

空间是严格的 O(1)，与树高无关。改的是树上已有的指针字段，没有新开节点，也没有新开数组。

总结

Morris 遍历的全部机关只有一句：有左子树的节点，它左子树的最右节点右指针必定空着，把这个空指针临时指回自己，就能判断是第几次到达。

要点列一下：循环三个出口，无左树直接右移、第一次到达借指针往左、第二次到达拆指针往右；先序打印在第一次到达与无左树处，中序打印在循环体末尾；还原和内圈的 != cur 刹车漏一个就死循环；总到达次数是 n 加有左子树的节点个数，内圈累计不超过 2n。

先序和中序都能在「到达时顺手记一笔」解决。后序要等左右两边都处理完，Morris 只到两次，那里得换一套办法。
