换根 dp：染色收益与首都，转移式只有一行

换根的骨架一旦定下来，剩下的活就是设计「第一趟收什么」和「递过去的式子长什么样」。这一页两道题，式子都只有一行加减，难的是先把题目语言翻译成子树上的量：一道要先证明收益跟染色顺序无关，另一道要把「翻几条边」翻译成「有几条边指向根」。

零、背景

深度和那道题的子树信息是 sz 加上子树内的深度和。信息收什么完全由题目决定，但有两件事每次都一样：第一趟只在固定根底下收集，第二趟只读不改；换根后的变化只发生在边的一侧，所以转移永远是一句「扣掉旧的、加上新的」。

这一页的两道题把「变化量」压到了极致：一个变化量就是子树大小本身，另一个变化量干脆只有 ±1。

一、问题

题一是洛谷 CF1187E 染色的最大收益。n 个点的树，初始时全是白点。第一次操作可以选任意一点染黑，之后每次必须选一个已经染黑的点的相邻点继续染黑，一直到所有点都被染完。每一步都获得「当前被染色点的白色连通块大小」作为收益，求能拿到的最大收益和。

题二是洛谷 CF219D 首都。n 个点的树，但每条边都是有向的。要选一个城市做首都，要求首都能走到任何一个城市；为此可能要翻转一些边的方向，希望翻转的数量尽量少。打印最少翻转数和所有取到最小值的首都编号。

二、题一：收益与染色顺序无关

先解决「收益到底怎么算」。设第一次染的是 r。之后每一次都是从一个黑点走到一个白点，所以黑点集合任何时候都是连通的。

现在轮到染 x。它至少有一个邻居已经黑了。这个邻居不可能是 x 的儿子：以 r 为根看，如果 x 的某个儿子先黑了，那么从那个儿子一路回到 r 的路径全是黑的，而这条路径要经过 x，x 早该黑了。所以先黑的邻居只能是 x 的父亲。

父亲黑着，儿子们全白，x 的白色连通块正好是 x 的整棵子树。也就是说染 x 这一步拿到的收益恒等于以 r 为根时 x 的子树大小，跟颜色是按什么顺序铺过来的毫无关系。于是

以 r 为起点的总收益 = Σ sz[x]    // sz 是以 r 为根时的子树大小

图 1 是九个点的小树，以 8 号做起点，角上标的是每个点的子树大小，加起来 40。

把这句结论拿去跑模拟也对得上：固定起点反复换染色顺序，4000 组随机树的各 8 种顺序，收益全部一致，跟上面这个求和式也一组不差。

三、题一的换根

dp[u] 记 u 做起点时的总收益。换根从 u 到 v，只有两处子树大小变了：v 的子树从 sz[v] 变成 n，多了 n − sz[v]；u 的子树从 n 变成 n − sz[v]，少了 sz[v]。其余点的子树不受影响，于是

dp[v] = dp[u] + (n - sz[v]) - sz[v] = dp[u] + n - 2 * sz[v];

括号里的东西还是第一趟那个 sz，第二趟不动它。图 2 把这两处变化画了出来。

顺带能读出结论：只有 sz[v] 不到一半时，把起点换到 v 才会让收益变大。树越「细」，往枝叶上挪收益越高。

四、题二：翻转几条边

以 1 为根把树定下来。一条从 u 到儿子 v 的边，题目给的方向只有两种：

方向是 u → v，也就是顺着「父亲指向儿子」走。以 u 做首都时这条边不用翻；一旦换到 v 做首都，v 要往 u 走，就得把它翻过来，代价 +1。

方向是 v → u，从儿子指向父亲。以 u 做首都时它挡在路上了，得翻，代价 +1；换到 v 做首都之后这条边正好顺着走，代价 −1。

于是「某个点做首都需要翻几条」等于「有多少条边的方向指向根」。第一趟收 reverse[u]：以 1 为根时 u 的子树内，方向朝上的边有几条。第二趟每条边只贡献 ±1。图 3 是一棵八条边的有向树。

五、模板代码

// 收益与染色顺序无关：染 x 的那一刻，x 的子树里还没有黑点
    // 所以白块大小恰好是以起点为根时 x 的子树大小
    void dfs1(int u, int f){
        sz[u] = 1;
        dp[u] = 0;
        for (int e = head[u], v; e != 0; e = nxt[e]){
            v = to[e];
            if (v != f){
                dfs1(v, u);
                sz[u] += sz[v];
                dp[u] += dp[v];
            }
        }
        dp[u] += sz[u];        // 染自己这一下，白块就是整棵子树
    }

    // 换根：起点的子树里每个点少算 sz[v] 次，其余 n - sz[v] 个点多算 sz[v] 次
    void dfs2(int u, int f){
        for (int e = head[u], v; e != 0; e = nxt[e]){
            v = to[e];
            if (v != f){
                dp[v] = dp[u] + n - sz[v] - sz[v];
                dfs2(v, u);
            }
        }
    }

首都那道题建图时按方向给边标权重：读入一条 u 到 v 的边，正向记 0、反向记 1。这样第一趟的 + w 和第二趟的 +1 / −1 用同一个 w 就分清楚了。

// weight[e] = 0 表示记录的边是 u -> v，weight[e] = 1 表示是 v -> u
    // 建图：读入 u v（方向 u 指向 v）
    addEdge(u, v, 0);
    addEdge(v, u, 1);

    // reverse[u] : 以 1 为根时，u 的子树内朝根方向（需要翻转）的边数
    void dfs1(int u, int f){
        reverse[u] = 0;
        for (int e = head[u], v, w; e != 0; e = nxt[e]){
            v = to[e]; w = weight[e];
            if (v != f){
                dfs1(v, u);
                reverse[u] += reverse[v] + w;
            }
        }
    }

    // 换根：边 u -> v 本来顺着走，换到 v 就得反过来，代价 +1
    //       边 v -> u 本来就是反的，换到 v 反而顺了，代价 -1
    void dfs2(int u, int f){
        for (int e = head[u], v, w; e != 0; e = nxt[e]){
            v = to[e]; w = weight[e];
            if (v != f){
                dp[v] = dp[u] + (w == 0 ? 1 : -1);
                dfs2(v, u);
            }
        }
    }

七、复杂度分析

环节题一（染色收益）题二（首都）
第一趟收集O(n)O(n)
第二趟换根O(n)O(n)
合计O(n)O(n)
空间O(n)O(n)
朴素（每个根重算）O(n²)O(n²)

空间按题目上限算。题一 n ≤ 2×10⁵，head、sz 各 n 个 int，nxt、to 各 2n 个 int，dp 一个 n 长的 long long，加起来约 4.4MB。题二同样是 2×10⁵ 量级，只多一个同长的 weight。收益最大是 O(n²) 级别（链上约 (n+1)n/2），要用 long long。

实测：n = 10⁵ 时题一换根 2.65ms，n = 2×10⁵ 是 5.92ms；题二 n = 2×10⁵ 是 58.88ms，比题一慢一个数量级，因为每条边要走两次指针跳转、还要多读一个权重。两份代码都是纯线性的，慢的这十来倍是常数。

顺便记两个实测分布。题一从 1 号出发平均能拿到最优的 67.37%，最差的一棵树只有最优的 45%，所以「随便挑个起点」远不如老老实实换根。题二在 n = 2×10⁵ 的随机有向树上，最少要翻 99738 条边，占了全部边的 49.87%，和「每条边一半概率反向」对得上；而在随机的十二点小树上，最优首都只有 1 个的占 58.88%，2 个的占 27.98%。

八、总结

要点三条。其一，换根的式子从来不难推，难的是先想清楚「题目要的量是子树上的什么」。题一花了整整一节证明收益就是子树大小，题二花了一节把翻转数翻译成朝上的边数，两处翻译做完，转移各只剩一行。其二，当题目有两种方向、两种状态时，把其中一种记成 0、另一种记成 1，两趟代码就能共用同一个权重。其三，答案并列时题目要求打印全部编号，扫最小值那一趟收集而不是提前 break。

再往下走，子树信息就不一定是一个数了。下一道题要一次性带上 k 个距离的权值和，转移式里出现一个容斥的减法项。

九、最后

题一那节的顺序无关性，接受结论之前建议自己拿一棵五个点的树手动试两种顺序。看着「收益和顺序有关」的直觉很强，但把黑点集合连通的约束摆出来就会发现没有第二种可能。题二那个 ±1 的方向最容易写反，写反之后样例往往还能过，因为一条边两端最优值互换这种事在对称的树上恰好不明显；和第一趟的 reverse 值交叉验一遍最稳。

《完》
