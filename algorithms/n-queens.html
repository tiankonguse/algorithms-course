N 皇后问题：位运算剪枝

数组版把每行皇后的位置记在 path 里，位运算版把「哪些列还能放」压进三个 int。两版探索同一棵搜索树，常数差近 19 倍。

零、背景

8 皇后有多少种摆法？92 种。n=16 是 14,772,512 种。n=14 也有 365,596 种，到 n=15 跳到 2,279,184。

问题一句话：n×n 棋盘上放 n 个皇后，任意两个不能互相攻击。皇后走直线和斜线，所以任意两个皇后不能同列，也不能在同一条 45° 斜线上。同一行的限制不用管，一行放一个就消掉了。

LeetCode 52 只问摆法数，答案是一个整数。这题的经典解是回溯：一行一行放，放完前 i 行再看第 i+1 行能放哪。框架谁都会写，差别全在「判断当前行能放哪些列」这一步。这一页先写数组版，再换成三个 int 的位运算版，量一量两者差多少。

一、数组路径版

path[i] 记第 i 行皇后放在第几列。来到第 i 行，0..i-1 的皇后都摆在 path 里，对要试的列 j 做 check：跟每个已有皇后比两件事，同列（j == path[k]），或者行差等于列差（|i-k| == |j-path[k]|），后者说明两个点在同一条斜线上。

每到一个节点要干的活是：对 0..n-1 全部 n 列各做一次 check，每次 check 从第 0 行扫到第 i-1 行。n=16 时，数组版累计做了 180 亿次 check 调用（实测计数）。这些工作大部分是白做的，多数列跟最近几行的皇后一碰就冲突，可 check 还是要从头扫一遍才肯放弃。

#include <bits/stdc++.h>
    using namespace std;

    // path[i] 记录第 i 行皇后放在哪一列，0..i-1 已定，正在试第 i 行第 j 列
    bool check(const vector<int>& path, int i, int j) {
        for (int k = 0; k < i; k++) {
            // 同列，或行差 == 列差（同在一条斜线上）
            if (j == path[k] || abs(i - k) == abs(j - path[k])) return false;
        }
        return true;
    }

    // i 当前行，n 总行数；返回 0..i-1 已放好的前提下还能找到几种摆法
    int f1(int i, vector<int>& path, int n) {
        if (i == n) return 1;           // n 行都放完，找到一种摆法
        int ans = 0;
        for (int j = 0; j < n; j++) {   // 0..n-1 列逐个试
            if (check(path, i, j)) {
                path[i] = j;
                ans += f1(i + 1, path, n);
            }
        }
        return ans;
    }

回溯本身没问题，慢的是每步的判断。能不能把「扫已有行」这件事变成 O(1)？能，把每行的位置信息换成三个数字。

二、位运算版

三个 unsigned 各用一个位代表一列：col 记正下方被占的列，left 记被左下斜线占的列，right 记被右下斜线占的列。皇后在 (i, j)，正下方向占住 (i+1, j)、(i+2, j)……所以 col 从放下去那一刻起不变；斜线会随行数下移而平移一格，左下那条每下一行偏左一格，右下那条每下一行偏右一格。

limit = (1u << n) - 1u，低 n 位是 1，之后每次 & limit 把候选范围锁死在 n 列里。

到一个节点，先把三条线的位合起来：ban = col | left | right。limit & ~ban 就是还没被占的列，记成 candidate。接下来逐位取候选：place = candidate & -candidate，取的是最右侧那个 1（031 讲过的 lowbit 写法），取完 candidate ^= place 消掉它，带着新状态递归下一行。

col == limit 的时候每一列都有皇后了，找到一种摆法，返回 1。

#include <bits/stdc++.h>
    using namespace std;

    // col 正下、left 左下斜线、right 右下斜线：一个位代表一列被占
    // limit 的低 n 位是 1，把候选列限制在 n 列棋盘内
    int f2(unsigned limit, unsigned col, unsigned left, unsigned right) {
        if (col == limit) return 1;          // 每一列都有皇后了，找到一种摆法
        unsigned ban = col | left | right;   // 三条线合起来占掉的列
        unsigned candidate = limit & (~ban); // 剩下的就是还能放的列
        int ans = 0;
        while (candidate != 0) {
            unsigned place = candidate & (-candidate); // 取最右侧的 1
            candidate ^= place;                        // 这个候选列用掉了
            ans += f2(limit, col | place,
                      (left | place) >> 1,   // 左下斜线到下一行偏左一格
                      (right | place) << 1); // 右下斜线到下一行偏右一格
        }
        return ans;
    }

位运算版搜索逐帧：三个 int 陪着递归走完整棵树

三、两个版本差在哪

先说结论：两个版本探索的是同一棵搜索树。它们都只深入合法的放置，节点数完全一样，n=16 都是 1,141,190,303 个节点。差别在常数，数组版每个节点 O(n·i)，位版 O(1)。

实测（本机 g++ -O2）：n=14 数组版 2.29s、位版 0.13s，快 17.7 倍；n=16 数组版 105.2s、位版 5.65s，快 18.6 倍。16 皇后用位运算版能在 10 秒内跑完，这台机器上 5.65s 就跑完了。

倍数还随 n 变大：n=8 约 10 倍，n=14 起稳定在 18 倍上下。原因在数组版每节点的代价随深度 i 增长，n 越大深层节点占的比例越高。

还有一个被低估的好处：位版枚举候选列只走能放的列，数组版却要对全部 n 列都做一次 check。n=16 实测每个节点平均候选列只有 1.01 个，绝大多数节点只剩一个可放列，数组版为了试那一列，先要在 n 列里逐个试、每试一次还从头扫 i 行。

剪枝力度可以量化：完全不判冲突，16 皇后要试 16! ≈ 2.1×10¹³ 种排列；剪枝后只探 1.14×10⁹ 个节点，缩到约 1/18000。

答案与代价对照：n 从 6 涨到 16，两个版本差多少

四、复杂度分析

版本时间（最坏）额外空间说明
数组路径版O(n!·n²)O(n)path 数组 + 递归栈；每节点对 n 列 check、每列扫 i 行
位运算版O(n!)O(n)三个 int 是 O(1)，空间全在递归栈；每节点 O(1)

两版搜索树相同，节点数上界按最坏口径是 O(n!)。实际运行远小于这个上界，剪枝把搜索空间压到约 1/18000（n=16）。

五、总结

三件套：col、left、right 各一个 int，一个位代表一列被哪条线占住；ban = col|left|right 合并，limit & ~ban 得到候选列。

取候选：place = candidate & -candidate 取最右 1，candidate ^= place 消掉，循环里逐个试。

斜线平移：传下一层时 (left|place)>>1、(right|place)<<1，新皇后的两条斜线一起带下去。

两版同树，差的是常数：n=16 数组版 105 秒、位版 5.6 秒。位运算把「n 列的状态」压进一个 int，这套手法在后面的状态压缩 dp、子集枚举里会整个搬走。
