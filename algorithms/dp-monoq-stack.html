单调栈优化：管辖区间与变序和

单调队列管的是「下标区间随 i 平移」，栈管的是另一件事：谁在哪一段里当最值、一段递减的公差能压住多长。这一节两道题，一道用栈划出每个元素的管辖区间，把 O(n²) 个子数组按最小值归类；另一道用栈压住变序后的递减段，把 O(n × V) 的 dp 压到 O(n)。

零、栈在这里管的是「管辖区间」

先回顾一个基本操作：对每个下标 m，找出左边第一个比 arr[m] 小的位置 l，和右边第一个不大于 arr[m] 的位置 r。那么所有满足 l < i ≤ m ≤ j < r 的子数组 [i, j]，最小值恰好是 arr[m]。这个 (l, r) 就是 m 的管辖区间。

单调递增栈一次扫描就能把所有 m 的管辖区间都找出来：扫到 i 时，所有栈顶比 arr[i] 大的元素，它们的右边界就是 i，弹出来结算；弹完之后的新栈顶就是左边界。

相等的时候怎么办？左边用「严格小于」、右边用「不大于」，也就是弹出条件写 >=。这样两个相等的值不会互相抢对方的子数组，每个子数组只会被算一次。写成 > 和 >= 的其它组合也能过，只要左右两边一个是严格一个是宽松。

一、巫师力量和

给一个长度为 n 的数组，一个子数组的指标定义为「子数组的累加和 × 子数组里的最小值」，求所有子数组的指标之和，对 10⁹ + 7 取模。n 到 10⁵，值到 10⁹。

子数组有 n(n+1)/2 个，逐个算是 O(n²)。换成贡献法：不枚举子数组，而是枚举「谁当最小值」。m 的管辖区间 (l, r) 一旦定下来，以 arr[m] 为最小值的子数组就是左端点在 [l+1, m]、右端点在 [m, r−1] 的所有组合，一共 (m − l) × (r − m) 个。

剩下的问题是怎么把这些子数组的累加和一次性加起来。设 pre[k] 是前 k 个数的前缀和，那么子数组 [i, j] 的和是 pre[j] − pre[i−1]。对固定的 m 求所有 i ∈ [l+1, m]、j ∈ [m, r−1] 的 pre[j] − pre[i−1] 之和：

所有 pre[j] 各被加了 (m − l) 次，所有 pre[i−1] 各被减了 (r − m) 次。于是只要能快速求「pre 在一段区间上的和」，就完事了。这就是前缀和的前缀和：ss[k] = pre[0] + pre[1] + ... + pre[k]。

记 A = ss[r−1] − ss[m−1]（右半边 pre 的和）、B = ss[m−1] − ss[l−1]（左半边 pre 的和），m 的贡献就是 (A × (m − l) − B × (r − m)) × arr[m]。

// arr[m] 当最小值的管辖范围是 (l, r)：左边第一个更小的在 l，右边第一个不大于的在 r
    int totalStrength(vector<int>& arr) {
        int n = arr.size();
        const int MOD = 1000000007;
        vector<int> ss(n);                                      // ss[i] = 前 i+1 个前缀和的和
        long long pre = 0;
        for (int i = 0; i < n; i++) {
            pre = (pre + arr[i]) % MOD;
            ss[i] = ((i ? ss[i - 1] : 0) + pre) % MOD;
        }
        auto gain = [&](int l, int m, int r) -> long long {
            long long L = ((ss[r - 1] - (m >= 1 ? ss[m - 1] : 0) + MOD) % MOD) * (m - l) % MOD;
            long long R = (((m >= 1 ? ss[m - 1] : 0) - (l >= 1 ? ss[l - 1] : 0) + MOD) % MOD) * (r - m) % MOD;
            return ((L - R + MOD) % MOD) * (arr[m] % MOD) % MOD;
        };
        vector<int> st(n);
        int top = 0;
        long long ans = 0;
        for (int i = 0; i < n; i++) {
            while (top > 0 && arr[st[top - 1]] >= arr[i]) {     // 相等也弹：右边界取「不大于」
                int m = st[--top];
                ans = (ans + gain(top ? st[top - 1] : -1, m, i)) % MOD;
            }
            st[top++] = i;
        }
        while (top > 0) {                                       // 剩下的以 n 为右边界
            int m = st[--top];
            ans = (ans + gain(top ? st[top - 1] : -1, m, n)) % MOD;
        }
        return (int)ans;
    }

下标为 −1 的那些项当 0 处理，这是三处三元表达式的全部作用。取模要在每一步做，特别是 A 和 B 相减之后要先加一次 MOD 再取。

拿 arr = [1, 3, 1, 2] 手算一遍。四个位置的管辖区间和贡献：

marr[m]管辖区间 (l, r)覆盖的子数组贡献
01(−1, 2)[0,0]、[0,1]1 + 4 = 5
13(0, 2)[1,1]9
21(−1, 4)[0,2]、[0,3]、[1,2]、[1,3]、[2,2]、[2,3]5 + 7 + 4 + 6 + 1 + 3 = 26
32(2, 4)[3,3]4

加起来 5 + 9 + 26 + 4 = 44。把十个子数组逐个算一遍也是 44。注意 0 号和 2 号的值相等，0 号的右边界停在 2，2 号的右边界一直到 4，这就是弹出条件写 >= 的效果：相等的两个位置各自管一半，不重不漏。

二、子数组最大变序和

第二题来自一道大厂笔试。定义一个数组的变序和：每个数只能减小或者不变，要求整个数组变成严格升序，问变完之后的累加和最大是多少。比如 [1, 100, 7] 变成 [1, 6, 7]，变序和 14；[5, 4, 9] 变成 [3, 4, 9]，变序和 16。要求的是所有子数组的变序和里最大的那个。

先解决单个数组怎么算。从右往左贪心：最后一个数不动，往前每个数取「原值」和「后一个数减 1」里较小的那个，一旦上界掉到 0 就停。这个贪心是对的，因为每个位置只会给左边留下一个上界，让它尽量大不吃亏。

于是 dp 就出来了：dp[i] 是以 i 结尾的子数组的最大变序和。从 i 往左，值按 arr[i]、arr[i] − 1、arr[i] − 2 一路递减，遇到一个原值比这个上界小的位置就被卡住，从那里开始改用它的原值继续递减。

朴素写法是二维的 dp[i][p]（p 是上界），复杂度 O(n × V)，V 到 10⁶ 直接爆掉。观察一下被卡住的位置有什么规律：如果 arr[p] < arr[i] − (i − p)，那 p 会截断这一段；否则这一段一路递减下来都能盖过 p。而「arr[p] ≥ arr[i] − (i − p)」这个条件整理一下是 arr[p] + p ≥ arr[i] − i，或者说 arr[p] + p 随 p 递减。用单调栈维护那些「arr[p] + p 递增」的位置，就只会留下真正能截断的候选。

// seg(mx, cnt) : mx + (mx-1) + ... 一共 min(mx, cnt) 项
    long long seg(long long mx, long long cnt) {
        cnt = min(mx, cnt);
        return ((mx * 2 - cnt + 1) * cnt) / 2;
    }

    // dp[i] : 以 i 结尾的子数组，最大变序和
    long long maxOrderSum(vector<int>& arr) {
        int n = arr.size();
        vector<int> st(n);
        int top = 0;
        vector<long long> dp(n, 0);
        long long ans = 0;
        for (int i = 0; i < n; i++) {
            int curIdx = i, curVal = arr[i];
            while (curVal > 0 && top > 0) {
                int preIdx = st[top - 1];
                if (arr[preIdx] >= curVal) {
                    top--;                                      // 这一段被 curVal 整个压住
                    continue;
                }
                int gapIdx = curIdx - preIdx, gapVal = curVal - arr[preIdx];
                if (gapVal >= gapIdx) {                         // 递减还没到底就能接上
                    dp[i] += seg(curVal, gapIdx) + dp[preIdx];
                    curVal = 0;
                    break;
                }
                dp[i] += seg(curVal, gapIdx);                   // 先吃掉往下 gapIdx 个
                curVal -= gapIdx;
                curIdx = preIdx;
                top--;
            }
            if (curVal > 0) dp[i] += seg(curVal, curIdx + 1);   // 一路减到只剩自己
            st[top++] = i;
            ans = max(ans, dp[i]);
        }
        return ans;
    }

循环里的三种分支对上三种情况：栈顶原值比当前上界还大，说明这一段被当前值整个压住，弹掉；差值 gapVal 够跨过 gapIdx 个位置，说明递减到栈顶时还没低于栈顶原值，可以接上 dp[preIdx]，收工；否则先吃掉这一段的部分和，把上界和位置挪到栈顶，继续下一轮。

seg(mx, cnt) 是等差数列求和，取 min(mx, cnt) 项，因为值减到 0 就停了，不能再减成负数。

跑一下 [1, 4, 2]：dp[0] = 1；dp[1] 接上位置 0，得 4 + 1 = 5（变序 [1, 4]）；dp[2] 时栈顶 4 被弹掉，从位置 0 跨过来，gapVal = 1 < gapIdx = 2，只能吃掉 2 + 1 = 3，接不上 dp[0]，得 3（变序 [0, 1, 2]）。答案是三个里的最大值 5，来自子数组 [1, 4]。

这里有个容易误解的地方：dp[i] 是「以 i 结尾的子数组」，不要求从头开始，所以 [1, 100, 7] 的答案是 101（子数组 [1, 100]），比整个数组的 14 大得多。

五、复杂度分析

题目朴素写法栈写法空间说明
巫师力量和O(n²)O(n)O(n)栈、ss、pre 各一份
最大变序和O(n × V)O(n)O(n)栈与 dp 各一份，V 是值域

空间按题目上限算：巫师力量 n ≤ 10⁵，ss 与栈各一个数组，约 0.8 MB；变序和 n、值域都到 10⁶，dp 是 long long 数组约 8 MB，栈是 int 数组约 4 MB。

两道题的 O(n) 都来自「每个下标进栈一次、出栈一次」。变序和那题的 while 循环看着有三层嵌套，但每次迭代要么弹出一个元素、要么直接 break，总次数还是 O(n)。

六、总结

栈在 dp 里的用法可以概括成一句话：把「哪些下标还有资格影响后面」压成一个单调序列。巫师力量那题，有资格的是还没找到右边界的最小值候选；变序和那题，有资格的是还能截断递减段的位置。想清楚「资格」是什么，弹出条件就出来了。

实现上两个坑：相等元素的处理要一边严格一边宽松，否则子数组会被重复计算或者漏掉；变序和的 seg 要在值减到 0 时截断，不能减成负数。

这两题的栈还可以往下滑：把「求 max」换成「求一条直线在一堆点上的最大截距」，就走到斜率优化了，栈变成凸包。那条路上的分析和这里的管辖区间是同一套思路，只是比较的对象从数值变成了斜率。
