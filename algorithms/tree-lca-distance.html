三点集合：树上距离与中位点

三个人站在树上的三个点，要挑一个点碰头，让三人走过的边数总和最小。这个点不用搜：把三对点的最低公共祖先算出来，落单的那个就是集合点，最小花费是三个深度的一次加减。

零、背景

树上两点 a、b 的距离可以只用深度写出来。记 dep[u] 是根到 u 路径上的点数（根自己算 1），c 是 a 与 b 的最低公共祖先，那么

dist(a, b) = dep[a] + dep[b] − 2 × dep[c]

根到 a 那条链与根到 b 那条链，从 c 往上的一段完全重合，减掉两次 dep[c] 就把重合段删干净，剩下的正是 a 到 b 那条路上的边数。有了它，两点距离不再需要搜一遍树，一次 LCA 加三次减法就够。

一、问题

一棵 n 个节点的树，从一个点到另一个点的路径上有几条边就要花几个金币。每条查询给出 a、b、c 三个点，三个人分别站在上面，要选一个点集合，使三人花费之和最小；打印集合点和最小花费。1 ≤ n、m ≤ 5 × 10⁵，m 是查询条数。

朴素做法是枚举集合点：对每条查询，把 n 个点挨个当候选，算 dist(a,x) + dist(b,x) + dist(c,x) 取最小。一条查询 O(n)，m = 5 × 10⁵ 时是 2.5 × 10¹¹ 次距离计算。实测 n = 2000、m = 5000 的随机数据上，枚举要 1159 ms，而下面这套做法只要 0.56 ms。

二、三个 LCA 里落单的那个

把三个点两两配对，算出 h1 = lca(a,b)、h2 = lca(a,c)、h3 = lca(b,c)。这三个值里一定有两个相等，剩下那个比它们更深；也有三者全相等的时候。集合点就是那个落单的。

为什么。设 x 是三条路径 a–b、a–c、b–c 的公共点，把 x 从树里挖掉，树裂成几块：x 的每个儿子领一块，x 的父方向还有一块。三条路径都经过 x，等价于 a、b、c 落在三块不同的地方（或者某个点就是 x 自己）。于是只有两种摆法：

1）三点分处 x 的三个儿子子树。这时任意两点的 LCA 都是 x，三个值全相等。
2）两点在两个儿子子树里，第三点在父方向那一块（或者它就是 x）。前两点的 LCA 是 x，涉及第三点的两对 LCA 都等于 lca(x, 第三点)，那是 x 的祖先或者 x 自己。

两种摆法都落在同一句话上：三个值里两个相等，落单的那个是 x，而且它不比另外两个浅。三点在同一块里的摆法不会出现——那样 x 就不在其中一条路径上了。

随机树上取 4000 组三点实测：三个 LCA 全相等的占 15.87%，剩下 84.13% 都是两个相等、第三个更深。所以右图那种形态才是常态。

三、最小花费为什么是这一串减法

三条路径 a–b、b–c、a–c 拼起来看，会发现「三人走到集合点 x」经过的每条边都被走了恰好两遍。于是

dist(a,b) + dist(b,c) + dist(a,c) = 2 × (dist(a,x) + dist(b,x) + dist(c,x))

左边用深度公式展开，dep[a]、dep[b]、dep[c] 各出现两次：

2·(dep[a] + dep[b] + dep[c]) − 2·(dep[h1] + dep[h2] + dep[h3])

而 {h1, h2, h3} 里有两个是浅的那个（记作 high）、一个是深的那个（记作 low），除以 2 就得到

最小花费 = dep[a] + dep[b] + dep[c] − 2 × dep[high] − dep[low]

这也解释了代码里为什么要按 h1 与 h2 是否相等分两支：不相等时 h3 一定等于两者中较浅的那个，落单的是较深的那个，直接比深度就能挑出来；相等时落单的只可能是 h3（三者全相等时 h3 也等于它们，取谁都一样）。

实测里，这个公式在 4000 组随机三点上与「枚举全部 n 个点取最小」逐组一致，0 组不符。

四、建表与查询

跳表还是那张 stjump[u][p]：u 往上跳 2p 步落在谁身上。LIMIT 取 19 覆盖了 n = 5 × 10⁵（219 = 524288）。这里有个细节：power 的求法是 while ((1 << ans) <= (n >> 1)) ans++，得到的是不超过 n 的最大 2 的幂对应的指数，用来当跳表的最高层。

const int MAXN = 500001;
    const int LIMIT = 19;

    int power;
    int head[MAXN];
    int edgeNext[MAXN << 1];
    int edgeTo[MAXN << 1];
    int cnt;
    int deep[MAXN];
    int stjump[MAXN][LIMIT];

    int log2(int n) {
        int ans = 0;
        while ((1 << ans) <= (n >> 1)) {
            ans++;
        }
        return ans;
    }

    void build(int n) {
        power = log2(n);
        cnt = 1;
        memset(head + 1, 0, n * sizeof(int));
    }

    void addEdge(int u, int v) {
        edgeNext[cnt] = head[u];
        edgeTo[cnt] = v;
        head[u] = cnt++;
    }

    void dfs(int u, int f) {
        deep[u] = deep[f] + 1;
        stjump[u][0] = f;
        for (int p = 1; p <= power; p++) {
            stjump[u][p] = stjump[stjump[u][p - 1]][p - 1];
        }
        for (int e = head[u]; e != 0; e = edgeNext[e]) {
            if (edgeTo[e] != f) {
                dfs(edgeTo[e], u);
            }
        }
    }

LCA 的两段循环照抄模板：先把深的那个抬到与浅的同层，再让两个一起往上跳，跳到「再跳一格就到同一个点」为止。

int lca(int a, int b) {
        if (deep[a] < deep[b]) swap(a, b);
        for (int p = power; p >= 0; p--) {
            if (deep[stjump[a][p]] >= deep[b]) {
                a = stjump[a][p];
            }
        }
        if (a == b) return a;
        for (int p = power; p >= 0; p--) {
            if (stjump[a][p] != stjump[b][p]) {
                a = stjump[a][p];
                b = stjump[b][p];
            }
        }
        return stjump[a][0];
    }

三条查询合起来就是三次 LCA 加一次代入。cost 要用 long long：n = 5 × 10⁵ 时三个深度之和是 1.5 × 10⁶，int 还装得下，但减去 dep[high] * 2 的中间值写成 int 再赋给 long long 就白算了——顺手把第一项 cast 掉最省事。

int togather;
    long long cost;

    void compute(int a, int b, int c) {
        int h1 = lca(a, b), h2 = lca(a, c), h3 = lca(b, c);
        int high = h1 != h2 ? (deep[h1] < deep[h2] ? h1 : h2) : h1;
        int low = h1 != h2 ? (deep[h1] > deep[h2] ? h1 : h2) : h3;
        togather = low;
        cost = (long long)deep[a] + deep[b] + deep[c]
               - (long long)deep[high] * 2 - deep[low];
    }

五、复杂度分析

步骤时间复杂度空间复杂度
DFS 建跳表O(n log n)O(n log n)
单次 LCAO(log n)
一条查询（三次 LCA + 一次代入）O(log n)
合计O((n + m) log n)O(n log n)

空间按题目上限算：n = 5 × 10⁵、LIMIT = 19 时，stjump 是 9.5 × 10⁶ 个 int，约 36 MiB；邻接表用链式前向星，head 500001 个、edgeNext 与 edgeTo 各 10⁶ 个，再加约 10 MiB。这就是洛谷上只有 C++ 能全过的直接原因——同样的逻辑用 Java 写，光对象头就把内存吃超了。

六、最后

这一页的三件事：距离等于三个深度的一次加减；三对 LCA 里落单的那个是三条路径的公共点，也就是集合点；三对距离之和是最小花费的两倍，展开后只留下「减两次 high、减一次 low」。

枚举集合点的做法在 n、m 都是 5 × 10⁵ 时是 2.5 × 10¹¹ 次距离计算，换成三次 LCA 之后是 3 × 10⁷ 次跳表访问，差了四个数量级。

同一张跳表还能在每一格上多挂一份沿路累计的信息——最小值、和、哈希，换掉挂在上面的东西就能回答另一批路径问题，那是这一讲后面几页的内容。
