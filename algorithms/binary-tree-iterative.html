二叉树三序遍历的非递归实现

递归版的三种遍历，栈是系统给的，看不见也管不着。自己拿一个栈重写一遍，每步压什么、弹什么都要写出来，顺带还能看出「递归深度等于树高」这句话到底在说什么。

零、背景

上一节的三种遍历都写在递归里，栈由函数调用自己维护：进入 f(head->left) 时压一层，返回时弹一层，栈里始终是「根到当前节点」这条路径。

这套东西有个硬上限。系统栈的大小是固定的，本机 8176 KB，一帧大约 32 字节，实测 260937 层能跑完、261000 层直接段错误。树一旦退化成链，节点数超过 26 万递归就崩了，跟你的代码写对写错没关系。

迭代版把这个栈搬到自己手里（vector 开在堆上），n = 100 万的左偏链照样跑完：先序 8.05ms、中序 6.05ms、后序一栈 8.87ms，一个都不崩。这是学迭代最实在的理由。

至于速度，别抱期望。n = 10⁶ 的完全二叉树上，递归先序 3.25ms，迭代先序 2.41ms、迭代中序 2.83ms、后序一栈 3.49ms，同一个量级。迭代买到的是不爆栈，速度上没便宜可占。

节点定义沿用上一节，三个字段，没孩子写 nullptr。

struct TreeNode {
        int val;
        TreeNode* left;
        TreeNode* right;
        TreeNode(int v) : val(v), left(nullptr), right(nullptr) {}
    };

下面全程用这棵 7 节点满二叉树做例子，节点值就是 1 到 7。

一、先序：弹出就打印，先压右再压左

先序是「根 左 右」。栈里装的是「还没处理的子树根」：弹出一个就打印它，再把它的两个孩子压回去。

压的顺序有讲究。栈是后进先出，想让左孩子下一轮先出来，就得后压它，所以代码里先写 right 再写 left。

// 先序：栈里装的是「还没处理的子树根」
    // 弹出就打印，然后先压右、再压左，左在栈顶，下一轮先出来
    void PreOrder(TreeNode* head) {
        if (head == nullptr) {
            return;
        }
        vector<TreeNode*> st;
        st.push_back(head);
        while (!st.empty()) {
            TreeNode* cur = st.back();
            st.pop_back();
            cout << cur->val << " ";
            if (cur->right != nullptr) {
                st.push_back(cur->right);
            }
            if (cur->left != nullptr) {
                st.push_back(cur->left);
            }
        }
    }

循环次数一眼看得出：每个节点进栈一次、出栈一次，总共恰好 n 次。实测左偏链 n = 10⁶，循环 1000000 次。

栈峰值（栈同时装过的最大元素数）跟树形关系很大。完全二叉树 n = 10⁶ 时峰值 20，等于树高；而左偏链和右偏链上峰值恒为 1：弹一个才压一个，栈里从来不留存货。

二、中序：一路向左压栈，压不动了再弹

中序是「左 根 右」。换个思路：从根开始，只要当前节点不空就一直往左走，路过的每个节点都压进栈；走到空了，说明左边到头，弹出栈顶打印，然后转向它的右孩子。

// 中序：cur 一路往左压栈，压不动了就弹一个打印，再转向它的右子树
    void InOrder(TreeNode* head) {
        vector<TreeNode*> st;
        TreeNode* cur = head;
        while (!st.empty() || cur != nullptr) {
            if (cur != nullptr) {
                st.push_back(cur);
                cur = cur->left;
            } else {
                cur = st.back();
                st.pop_back();
                cout << cur->val << " ";
                cur = cur->right;
            }
        }
    }

循环条件写成 !st.empty() || cur != nullptr：两个都成立才结束。栈空但 cur 指向右子树时还得继续，cur 空但栈里还有祖先时也得继续。

循环次数是 2n：每个节点压一次、弹一次。实测左偏链 n = 10⁶ 循环 2000000 次。

栈峰值在这里露出差别。左偏链 n = 1000 时，一路向左把 1000 个节点全压进去，峰值 1000；换成右偏链，每步都是「弹一个、转向右」，峰值只有 1。同一份代码，换个树形差三个数量级。

这也顺带说明了为什么额外空间是 O(h) 而不是 O(n)：h 本身就是树高，链上 h = n，那 O(h) 就是 O(n)，没矛盾。

三、后序：两个栈，好写但费空间

后序是「左 右 根」，用栈直接写比较绕，先给一个取巧的办法。

把先序的压栈顺序反过来（先压左、再压右），栈的弹出顺序就变成「根 右 左」。后序是「左 右 根」，正好是它的逆序。于是拿第二个栈把弹出的节点接住，最后一次性倒着弹出来。

// 后序：两个栈。第一个栈走「根 右 左」，倒进 collect 后逆序弹出就是「左 右 根」
    void PosOrderTwoStacks(TreeNode* head) {
        if (head == nullptr) {
            return;
        }
        vector<TreeNode*> st;
        vector<TreeNode*> collect;
        st.push_back(head);
        while (!st.empty()) {
            TreeNode* cur = st.back();
            st.pop_back();
            collect.push_back(cur);
            if (cur->left != nullptr) {
                st.push_back(cur->left);
            }
            if (cur->right != nullptr) {
                st.push_back(cur->right);
            }
        }
        while (!collect.empty()) {
            cout << collect.back()->val << " ";
            collect.pop_back();
        }
    }

7 个节点的例子上，第一个栈的弹出顺序是 1 3 7 6 2 5 4（根右左），collect 从底到顶也是这个顺序，倒着弹出就是 4 5 2 6 7 3 1。

写法上它是最省心的，问题在空间：collect 最后装着全部 n 个节点，一个都不少。n = 10⁶ 时实测就是 1000000，额外空间是 O(n) 而不是 O(h)。

时间上它反而不吃亏。n = 10⁶ 的完全二叉树，两栈版 3.27ms，一栈版 3.49ms。一栈版每一步都要 peek 再判断，两栈版是纯粹地弹。差的这点时间换来 O(n) 的空间，多数时候不划算，但真不在乎空间时它是最好写的。

四、后序：一个栈，靠 last 判断

省掉 collect 的关键，是要能回答「这个节点的右子树处理完没有」。用一个变量 last 记住上一次打印的节点就够了。

last 是刚被打印的节点，它一定是某棵子树里最后打印的那个，也就是那棵子树的根。所以判断规则是：

  1. last == cur->left：左子树刚刚整棵处理完；
  2. last == cur->right：右子树也处理完了，轮到 cur 自己；
  3. 两者都不是：cur 的孩子还没碰过。
// 后序：一个栈。last 是「上一次打印的节点」，用它判断右子树处理完了没有
    void PosOrderOneStack(TreeNode* h) {
        if (h == nullptr) {
            return;
        }
        vector<TreeNode*> st;
        st.push_back(h);
        TreeNode* last = h;          // 还没打印过任何节点时，last 就是头节点自己
        while (!st.empty()) {
            TreeNode* cur = st.back();
            if (cur->left != nullptr && last != cur->left && last != cur->right) {
                st.push_back(cur->left);       // 有左树，且左树没处理完
            } else if (cur->right != nullptr && last != cur->right) {
                st.push_back(cur->right);      // 左完了，右树没处理完
            } else {
                cout << cur->val << " ";       // 左右都没有，或者都处理完了
                last = st.back();
                st.pop_back();
            }
        }
    }

三个分支按顺序判断，每次只看栈顶（st.back()），不弹出。

第一个分支里的 last != cur->right 不能省。如果 last 已经是右孩子，说明右子树刚做完，这时只看「last != cur->left」会成立，左子树被压进去重走一遍，栈再也空不了。

last 的初值取头节点 h，是个哨兵：一个节点都没打印时，需要一个「既不是左孩子也不是右孩子」的值。头节点自己不可能当自己的孩子，用它是安全的。

循环次数是 2n−1，与树形无关。每个节点在栈顶出现的次数等于「1 + 它的孩子个数」（最后一次是打印并弹出），全部加起来就是 n + (n−1)。用 2000 组随机二叉树验过，一次不差。

栈峰值恒等于树高：栈里就是根到 cur 的这条路径，一个节点最多在栈里待到自己被打印为止。

五、栈里最多装了几个

把四种写法放在四种树形上跑一遍，栈峰值如下（n = 10⁶ 的完全二叉树与随机 BST，n = 1000 的两条链）。

树形节点数 n树高 h递归深度先序栈中序栈后序一栈
完全二叉树10000002020202020
随机 BST10000005252303152
左偏链100010001000110001000
右偏链100010001000111000

三行结论：

  1. 后序一栈的峰值跟递归深度一模一样，因为两者存的都是「根到当前的路径」。
  2. 先序在链上只要 1 个格子，是四种里最省的；中序在左偏链上要把整条链压进去。
  3. 两栈版的 collect 不在这张表里，它恒等于 n，与树形无关。

六、复杂度分析

写法时间额外空间循环次数栈峰值
先序 · 一栈O(n)O(h)n≤ h，链上为 1
中序 · 一栈O(n)O(h)2n≤ h，左偏链上为 n
后序 · 两栈O(n)O(n)n（再弹 n 次）≤ h，另有一个 n 格的 collect
后序 · 一栈O(n)O(h)2n−1= h
递归三序O(n)O(h)2n+1 次调用= h，系统栈 26 万层崩
Morris 遍历O(n)O(1)—0

时间一律是 O(n)：每种写法里，每个节点被压进栈有限次、弹出一次，没有嵌套。实测 n = 10⁶ 的完全二叉树，五种写法落在 2.4ms 到 3.7ms 之间，线性得不能再线性。

额外空间是 O(h)，h 是树高。完全二叉树 h = ⌈log₂(n+1)⌉，n = 10⁶ 时只有 20；随机 BST 的期望高度约 4.3 ln n（自然对数，n = 10⁶ 的渐近值约 60，有限 n 实测 52）；退化成链时 h = n，这时 O(h) 就是 O(n)。树本身那 n 个节点是省不掉的，表里说的是遍历过程额外要的。

还有一类写法能把额外空间压到 O(1)：Morris 遍历，靠临时把中序前驱的右指针借来当线索，用完再还原。它不进本节范围，知道有这条路就行。

七、总结

几个要点：

  1. 先序：弹出就打印，先压右再压左，保证左孩子下一轮先出栈。
  2. 中序：cur 一路向左压栈，压不动了弹栈顶打印，再转向它的右孩子；循环条件是「栈非空 或 cur 非空」。
  3. 后序两栈：第一个栈走「根右左」，collect 接住后逆序弹出。好写，但 collect 恒装 n 个节点，额外空间 O(n)。
  4. 后序一栈：只看栈顶不弹，用 last（上次打印的节点）判断左右子树处理完没有。三个分支的顺序别乱，第一分支的 last != cur->right 漏了会死循环。
  5. 循环次数：先序 n、中序 2n、后序一栈 2n−1，都是与树形无关的常数倍。
  6. 额外空间 O(h)，h 是树高。链上 h = n，且递归会在 26 万层崩掉，这就是迭代版存在的理由。
  7. 迭代不比递归快，n = 10⁶ 上两者同为几毫秒，别为了提速去改写法。

再往后是把空间压到 O(1) 的 Morris 遍历，以及「给两种序重建整棵树」这类反过来用性质的问题。
