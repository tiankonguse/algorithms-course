哈希表、有序表与比较器

写算法题时最常用的三种容器：哈希表增删改查 O(1) 但无序，有序表 O(log n) 但能回答「比 x 小的最大数」，比较器则决定了谁排在前面。三者经常配合使用，选对了能省一半代码。

零、背景

算法题里反复出现的一个动作是「存一批东西，然后快速找到某个」。数组下标访问是 O(1)，但前提是 key 本身就是下标；如果 key 是字符串、是大整数、是自定义结构体，数组就用不了了。

这时候有两条路：哈希表把 key 映射成数组下标，增删改查都是 O(1)，但丢了顺序；有序表把 key 排成一棵平衡树，增删改查 O(log n)，但能回答 floor、ceiling 这类和顺序有关的问题。

至于「谁排在前面」这件事，哈希表不管，有序表和堆都管。管的方式就是比较器：返回 true 就把第一个排到第二个前面。

一、哈希表

C++ 里哈希表有两个：unordered_set 只存 key，unordered_map 存 key-value 对。底层是同一个东西，区别只是有没有伴随数据。

基本操作就四个：insert 插入、count 查存在、erase 删除、[] 读写。都是 O(1) 均摊。

unordered_set<string> s;
    s.insert("Hello");
    cout << s.count("Hello") << endl;  // 1
    s.erase("Hello");

    unordered_map<string, string> mp;
    mp["Hello"] = "World";
    cout << mp["Hello"] << endl;       // World
    cout << mp.count("你好") << endl;   // 0
    mp.erase("Hello");

大常数是真的大

O(1) 不代表快。哈希函数要算、冲突要处理、桶是链表或开放寻址，每一步都比数组的直接下标访问多好几条指令。实测插入 100 万元素，数组几乎不花时间，unordered_map 要 50ms。

所以笔试里有一条铁律：key 的范围固定且可控时，用数组替代哈希表。比如 key 是 0 到 99 的整数，开一个 100 格的数组就行，比 unordered_map 快几十倍。

// key 范围固定可控时，数组直接替代哈希表
    int arr[100] = {0};
    arr[56] = 7285;
    arr[34] = 3671263;
    cout << arr[56] << endl;  // 7285
    // 插入 100 万元素：数组 0.00ms vs unordered_map 50.82ms
    // 查找 100 万次：数组 1.66ms vs unordered_map 12.11ms（7.3 倍）

查找也是一样：100 万次查找，数组 1.66ms，unordered_map 12.11ms，差 7.3 倍。这个差距在 n 小的时候不明显，但到了 10⁶ 级别就能决定 TLE 还是 AC。

自定义类型按什么比较

int、string 这些内置类型，哈希表默认按「值」比较：两个内容相同的 string 被认为是同一个 key。但自定义结构体默认按内存地址比较，两个字段完全相同的对象会被当成两个不同的 key。

算法竞赛里几乎不用自定义类型当哈希表的 key，所以这条知道就行。真要用的时候，给结构体写一个 hash 函数和相等判断，或者换成有序表（自定义类型写比较器更简单）。

二、有序表

C++ 里有序表是 set 和 map，底层是红黑树。增删改查都是 O(log n)，比哈希表慢一个 log 因子，但多了一堆和顺序有关的操作。

map<int, string> mp;
    mp[5] = "这是5"; mp[7] = "这是7"; mp[1] = "这是1";

    cout << mp.begin()->first << endl;   // 1（最小 key）
    cout << mp.rbegin()->first << endl;  // 7（最大 key）

    // floor(4)：<= 4 且最近的 key
    auto it = mp.upper_bound(4);
    if (it != mp.begin()) { --it; cout << it->first << endl; }  // 3

    // ceiling(4)：>= 4 且最近的 key
    it = mp.lower_bound(4);
    if (it != mp.end()) cout << it->first << endl;  // 5

    set<int> s;
    s.insert(3); s.insert(3); s.insert(4);
    cout << s.size() << endl;  // 2，有序表会去重

floor 和 ceiling 是有序表独有的

哈希表回答不了「比 4 小的最大 key 是什么」，因为它根本不维护顺序。有序表可以，用 lower_bound 和 upper_bound 组合一下就行。

有序表会去重，堆不会

set 里插入两个 3，size 还是 1，比较器认为相等的元素只留一份。map 同理，同一个 key 重复 put 会覆盖旧值。

堆（priority_queue）不去重，push 两个 3 就有两个 3。这是两者最容易搞混的地方：需要「每个元素只出现一次」用 set，需要「允许重复但每次取最小」用堆。

实测 20 万次插入、值域只有 1000：set 最终大小 1000（全去重了），multiset 大小 200000（一个没丢）。

unordered_map 还是 map

不需要顺序就用 unordered_map，需要 floor/ceiling 或按 key 范围遍历就用 map。实测插入 100 万元素，unordered_map 26ms，map 217ms，差 8.4 倍。这个差距在 n=10⁵ 时是 2ms vs 18ms，也已经能感觉到了。

三、比较器

比较器决定「谁排在前面」。sort 要用、priority_queue 要用、set/map 也要用。规则只有一条：比较器返回 true，就把第一个参数排在第二个前面。

struct Employee { int company; int age; };

    // 比较器：返回 true 表示 a 排在 b 前面
    struct CmpAge {
        bool operator()(const Employee& a, const Employee& b) const {
            return a.age < b.age;
        }
    };

    sort(arr.begin(), arr.end(), CmpAge());          // 按年龄升序
    sort(arr.begin(), arr.end(), [](auto& a, auto& b) {
        return a.age > b.age;                         // lambda：按年龄降序
    });

    // 多级比较：先公司升序，再年龄升序
    sort(arr.begin(), arr.end(), [](auto& a, auto& b) {
        if (a.company != b.company) return a.company < b.company;
        return a.age < b.age;
    });

    // 比较器用在 set 上：比较器认为相等就去重
    set<Employee, CmpAge> s;

多级比较

实际题目里很少只按一个字段排。员工先按公司编号排，公司相同再按年龄排，这就是多级比较。写法是先比第一维，不等就返回结果，相等再比第二维。

维度可以继续加：公司、年龄、入职时间、工号……每多一维就多一行 if。原则是「前面的维度优先级更高」，只有前面相等时才看后面。

比较器和去重

set 用比较器判断两个元素是否相等：比较器(a,b) 和 比较器(b,a) 都返回 false，就认为 a 和 b 相等，去重。

所以上面那个只按年龄比较的 CmpAge，两个年龄相同的员工会被当成同一个人，set 里只留一个。不想去重就加更多比较维度，比如把对象地址也比进去，保证任何两个不同对象都不相等。

字典序

字符串的默认比较就是字典序：从左到右逐字符比，第一个不同的字符决定大小；如果一个是另一个的前缀，短的更小。

"abcde" 和 "ks" 比，第一个字符 'a' < 'k'，所以 "abcde" 更小。"abc" 和 "abcd" 比，前三个字符相同，"abc" 更短，所以 "abc" 更小。

四、怎么选

选容器的决策树很简单：

1. key 是整数且范围可控 → 数组。没有比这更快的。

2. key 不可控但只需要增删改查 → unordered_set / unordered_map。O(1) 均摊。

3. 需要 floor/ceiling、按范围遍历、按 key 排序输出 → set / map。O(log n)。

4. 需要「每次取最小/最大」且允许重复 → priority_queue。比 set 简单且常数小。

5. 需要自定义顺序 → 写比较器。sort、堆、有序表通用同一套规则。

哈希表的 O(1) 是均摊，极端情况（所有 key 哈希到同一个桶）会退化成 O(n)，但竞赛数据一般不会专门卡这个。有序表的 O(log n) 是最坏保证，红黑树任何操作都不会退化。

总结

1. 数组最快但 key 受限，哈希表 O(1) 但无序且常数大，有序表 O(log n) 但能回答 floor/ceiling。

2. key 范围固定可控时优先用数组，实测比 unordered_map 快 7~50 倍。

3. set/map 会去重，priority_queue 不会；需要唯一用 set，需要重复取极值用堆。

4. 比较器规则统一：返回 true 则第一个排在前面；多级比较从高优先级维度开始，相等才看下一维。

5. 比较器认为相等的元素在 set 里会被去重，不想去重就加更多比较维度。
