从递归到动态规划：斐波那契数与最低票价

动态规划听着吓人，做起来只有一件事：把递归里重复算的那部分记下来。这页拿斐波那契数把「暴力递归、记忆化搜索、严格位置依赖、空间压缩」这四步走一遍，再用最低票价看一个真题目里第一版递归该怎么设计。

零、递归慢在重复调用

F(0) = 0，F(1) = 1，F(n) = F(n-1) + F(n-2)。照着定义写递归，一行都不用多想。算 F(4) 的时候调用过程长这样：

九个节点里有五个是重复的：F(2) 算了 2 遍，F(1) 算了 3 遍，F(0) 算了 2 遍。真正不同的子问题只有 5 个，多出来的四次全是白跑。

实测的调用次数（本机 clang -O2）：n = 5 是 15 次，n = 10 是 177 次，n = 20 是 21891 次，n = 30 是 2692537 次，n = 40 是 331160281 次。规律是 2·F(n+1) − 1，每一项都翻着跟头往上长。

对应的耗时：n = 30 用 2.91ms，n = 35 用 33.58ms，n = 40 用 354.24ms。同一个 n，填表的写法是 0.0008ms 这个量级，差了五个数量级。递归本身不慢，慢在它把同一件事做了几亿遍。

这里有个判据：展开递归时如果总在重复调用同一个子问题，改成动态规划就有收益；如果每次展开都是新的子问题，那改了也是白改。

一、第一步永远是写出暴力递归

别一上来就想状态转移方程。先回答一个问题：f(i) 的含义是什么。斐波那契里 f(i) 就是「第 i 项的值」，含义清楚了，递归体就是定义本身。

#include <bits/stdc++.h>
    using namespace std;

    // 暴力递归：完全照定义写
    int f1(int i) {
        if (i == 0) return 0;
        if (i == 1) return 1;
        return f1(i - 1) + f1(i - 2);
    }

    int fib1(int n) {
        return f1(n);
    }

这版代码除了慢没有别的毛病，而它正是后面三版的草稿。写错尝试的代价很低，删掉重写就行；反过来，直接硬想转移方程，想错了往往察觉不到。

二、记忆化搜索：算过的记下来

加一个 dp 数组，dp[i] 记 f(i) 的答案，用 −1 表示「还没算过」。递归体不变，只在开头加一句查表、结尾加一句写表。

#include <bits/stdc++.h>
    using namespace std;

    // 记忆化搜索：dp[i] == -1 表示 i 这个位置还没算过
    int f2(int i, vector<int>& dp) {
        if (i == 0) return 0;
        if (i == 1) return 1;
        if (dp[i] != -1) return dp[i];
        int ans = f2(i - 1, dp) + f2(i - 2, dp);
        dp[i] = ans;
        return ans;
    }

    int fib2(int n) {
        vector<int> dp(n + 1, -1);
        return f2(n, dp);
    }

实测调用次数：n = 5 变成 9 次，n = 10 是 19 次，n = 20 是 39 次，n = 30 是 59 次，正好 2n − 1。每个 i 被真正计算一次，剩下那次是它作为别人孩子时被查表挡回来的。

记忆化搜索也叫从顶到底的动态规划。它的好处是不用管计算顺序：递归到哪算哪，算过的立刻记下。如果每个状态的枚举代价很低，到这一步就可以交了。

三、严格位置依赖：从底到顶

再看一眼递归体：f(i) 只依赖 f(i-1) 和 f(i-2)。既然依赖关系是固定的，那就别递归了，从 2 一路填到 n，算 dp[i] 时它依赖的两个值已经在表里。

#include <bits/stdc++.h>
    using namespace std;

    // 严格位置依赖：dp[i] 只依赖 dp[i-1] 和 dp[i-2]，那就从 2 一路填到 n
    int fib3(int n) {
        if (n == 0) return 0;
        if (n == 1) return 1;
        vector<int> dp(n + 1, 0);
        dp[1] = 1;
        for (int i = 2; i <= n; i++) {
            dp[i] = dp[i - 1] + dp[i - 2];
        }
        return dp[n];
    }

这版叫从底到顶的动态规划。它省掉了递归调用的开销，更重要的是把「每个位置依赖谁」摆到了明面上，接下来的优化都建立在这张明面上。

四、空间压缩

dp[i] 只用到 dp[i-1] 和 dp[i-2]，更早的那些格子填完就再也没人看。那么数组整个可以不要，两个变量轮着滚。

#include <bits/stdc++.h>
    using namespace std;

    // 空间压缩：dp[i] 只用到前两项，两个变量就够
    int fib4(int n) {
        if (n == 0) return 0;
        if (n == 1) return 1;
        int lastLast = 0, last = 1;
        for (int i = 2, cur; i <= n; i++) {
            cur = lastLast + last;
            lastLast = last;
            last = cur;
        }
        return last;
    }

实测（n = 2×10⁷，值会溢出 int，这里只比时间）：dp 数组版 10.91ms、占 76 MB；滚动变量版 4.99ms、占几个字节。省空间的同时也快了一倍，因为少写了一整片内存。

一维动态规划的空间压缩基本都是这个套路：先写出 dp[i] 依赖哪几个位置，再看哪些位置可以用变量替掉。

五、最低票价：递归怎么设计

一年里某些天要出行，日子记在 days 数组里。通行证有三种：1 天期 costs[0]、7 天期 costs[1]、30 天期 costs[2]，买一张就能连着走那么多天。问覆盖所有出行日的最小花费。

照上一节的规矩，先定义 f(i)：把 days[i] 以及它后面所有出行日都覆盖掉，最少花多少钱。i 走到 days.length 时，后面没有出行日了，返回 0。

在 i 这个位置只有三种选择，买哪种票都行。买第 k 种票能盖住 days[i] 到 days[i] + durations[k] − 1，那么下一个要操心的出行日就是第一个 ≥ days[i] + durations[k] 的那个，记成 j。

j 用 while 往后推，最多推 30 次就到头了，所以这一层枚举可以当成 O(1)。三种票取最小，就是 f(i) 的答案。

#include <bits/stdc++.h>
    using namespace std;

    int durations[3] = {1, 7, 30};

    // days[i...] 这些旅行日全都覆盖掉，最少花多少钱
    int f1(vector<int>& days, vector<int>& costs, int i) {
        int n = days.size();
        if (i == n) return 0;
        int ans = INT_MAX;
        for (int k = 0, j = i; k < 3; k++) {
            // 买第 k 种票，它能盖住 days[i] + durations[k] 之前的所有日子
            while (j < n && days[i] + durations[k] > days[j]) j++;
            ans = min(ans, costs[k] + f1(days, costs, j));
        }
        return ans;
    }

    int mincostTickets1(vector<int>& days, vector<int>& costs) {
        return f1(days, costs, 0);
    }

实测调用次数（出行日连续 1 到 n）：n = 10 时暴力 49 次、记忆化 31 次；n = 15 是 157 对 46；n = 20 是 502 对 61；n = 25 是 1552 对 76。记忆化稳定在 3n + 1，暴力那边是指数级。LeetCode 的样例 days = [1,4,6,7,8,20]、costs = [2,7,15]，暴力 40 次、记忆化 19 次，答案 11。

六、最低票价的从底到顶

f(i) 依赖的 j 都比 i 大，所以倒着填表：dp[n] = 0，i 从 n−1 填到 0。

#include <bits/stdc++.h>
    using namespace std;

    int durations[3] = {1, 7, 30};

    // 从底到顶：dp[i] 只依赖下标更大的 dp[j]，倒着填即可
    int mincostTickets3(vector<int>& days, vector<int>& costs) {
        int n = days.size();
        vector<int> dp(n + 1, INT_MAX);
        dp[n] = 0;
        for (int i = n - 1; i >= 0; i--) {
            for (int k = 0, j = i; k < 3; k++) {
                while (j < n && days[i] + durations[k] > days[j]) j++;
                dp[i] = min(dp[i], costs[k] + dp[j]);
            }
        }
        return dp[0];
    }

样例 days = [1,4,6,7,8,20]、costs = [2,7,15] 的填表过程（j 那一列是三种票各自跳到的下标）：

答案是 11：第 1 天买 7 天期（7 块，盖到 1~7），第 8 天买 1 天期（2 块），第 20 天买 1 天期（2 块）。

两处容易写错的地方，实测各有对应的抓取率（2 万组随机数据，对照组是按天做的独立 dp）：while 的条件写成 days[i] + durations[k] >= days[j]，多吞一天，16.23% 的样本答案偏小；只枚举 1 天和 7 天两种票，28.61% 的样本答案偏大。

这里的枚举只有 3 个分支，改动态规划之后复杂度是 O(n)，n 是出行日的个数，一年最多 365。

八、总结

四步的顺序不能颠倒：先写出含义清楚的暴力递归，再加 dp 数组做记忆化，再看依赖位置改成从底到顶，最后按依赖范围压空间。

判断要不要改动态规划，看递归展开时有没有重复调用同一个子问题；斐波那契重复得离谱，最低票价重复得温和一点，但记忆化之后都从指数掉到了 O(n)。

斐波那契还有个 O(log n) 的矩阵快速幂解法，属于另一条路子，后面会专门讲。这一页的四步才是动态规划的通用起手式，后面所有一维、二维的题都是在这四步上继续加东西。
