替罪羊树：失衡就推倒重建

AVL 树靠旋转救失衡，跳表靠随机层数拆耦合，替罪羊树换了个更暴力的思路：发现哪棵子树不平衡，就把这棵子树整个拆散，按中序排好，再二分重建成标准平衡树。每次重建的代价是整棵子树的规模，听着吓人，但均摊下来每次操作还是 O(log n)。

零、背景

要实现的有序表还是那六个操作：增加 x（重复算多个）、删除 x（只删一个）、查询 x 的排名（比 x 小的个数 + 1）、查询排名为 x 的数、查询 x 的前驱后继。操作次数 ≤ 1e5，值域 −1e7 到 1e7。

二叉搜索树最怕有序输入：按 1、2、3… 的顺序插入，树退化成一条向右的链，O(log n) 的操作全变成 O(n)。前面几课给出两种解法：AVL 旋转保持严格平衡，跳表用随机层数让结构不依赖数据顺序。替罪羊树是第三种：平时不管平衡，一旦发现失衡就把整棵子树推倒重建。

实现上它只有一个 rebuild 函数，没有左旋右旋那套转来转去的代码，常数时间也小。代价是扩展性弱，想在节点上挂区间和之类的衍生信息不好做。算法竞赛里它是「必带模板」的有序表结构之一，跟 Treap、FHQ Treap、Splay 并列。

一、平衡因子与重构

每棵子树记一个存活节点数 aliveSiz。以 i 为根的子树，只要出现

max(aliveSiz[左], aliveSiz[右]) > ALPHA * aliveSiz[i]

就认为失衡。ALPHA 是平衡因子，取值范围 (0.5, 1.0)，取 0.5 以下或 1.0 以上没有意义：等于 0.5 时树必须完美均衡，重构频繁得吓人；等于 1.0 时任何形状都算「平衡」，重构永远不触发，树高随输入放飞。0.7 是实测最常用的值。

重构分三步：中序收集子树上所有存活节点，把节点序号收进数组；对这个数组二分建树，中间那个当根，左半边递归建左子树，右半边递归建右子树；把新树挂回原来的父节点，或者当整棵树都失衡时直接当新根。重建完就是一棵标准平衡树。

平衡因子直接决定树高和重建频率的取舍。实测：把 1 到 100000 按顺序插入，α 越大树越深，α 越小越接近满二叉树：

平衡因子 α0.550.600.700.800.900.95
树高（顺序插入 10 万）181922273347

α = 0.5 时树高接近理论最优，但插入过程中隔几步就整棵重建一次；α = 0.95 时几乎不重建，但树高涨到 47，查询多走一倍路。0.7 在两边都说得过去：顺序插入 10 万，树高才 22，比 log₂(100000) ≈ 17 高一点点。

二、死亡节点与 aliveSiz

先看这个实现怎么处理删除。删除 x 不真的从数组里抹掉节点，只是把 alive 标成 false：节点死了，但空间还占着。新插入的数字会优先复用死亡节点（add 时 aliveSiz == 0 的子树直接当空树，新建节点顶上去）。

aliveSiz[i] = (alive[i] ? 1 : 0) + aliveSiz[左] + aliveSiz[右]，up 一步算完。新增节点走到的路径上 aliveSiz 一路 +1，删除节点走到的路径上一路 −1，都是就地可算。

这里有个关键剪枝：aliveSiz == 0 的子树直接无视。查询走进去等于走空树，插入时这棵子树直接被新节点替换。它保证死亡节点不会拖慢操作：整棵子树死光了，代码根本不碰它。

这个设计跟经典的替罪羊树不一样。经典版维护两个量：allSiz 是节点总数（含死亡），aliveSiz 是存活数；重构触发也有两个条件，除了左右失衡，还要求子树里存活比例低于阈值；重建后要上溯整条祖先链修正 allSiz。我这份实现只维护 aliveSiz，新增 +1 删除 −1，重建后不用回修任何祖先。经典版最麻烦的一步，这里直接省掉了。

三、带词频的经典版本

课上先讲了一个带词频压缩的版本，结构上是三个数组：key_count 是节点词频，siz 是子树里的数字总数（含词频），diff 是子树里不同 key 的个数。判断平衡用 diff：ALPHA * diff[i] >= max(diff[左], diff[右])；查询排名用 siz 累加：key 比 num 小的时候把 siz[左] + key_count[i] 全算进去。

词频压缩省节点：同一个 key 只占一个节点，重复插入只是 key_count++。但它有两个别扭的地方。第一，删除时 key_count--，减到 0 节点还留着，得等下次重建才清掉，死亡判定比 Better 版的 alive 布尔啰嗦。第二，平衡判定只数不同 key 数（diff），如果某个 key 重复了几十万次，它的词频不影响平衡判定，排名查询却要走 siz，量级容易脱节。

Better 版不做词频压缩：每个插入的数字单独建节点，重复 key 就是两个节点，词频就是两个节点的 aliveSiz 贡献。想统计「一共有多少个数」，直接看 aliveSiz[root]。实现更简单，代价只是重复 key 多时数组多用一点空间，MAXN 开够就行。

四、查询与删除

查询沿着 key 走，四种都是递归：

small(i, num) 数「比 num 小的数有多少个」：num 不大于 key[i] 走左子树；否则答案 = aliveSiz[左] + (alive[i] ? 1 : 0) + 右子树的 small。getRank(num) = small + 1。index(x) 找第 x 小的数：x 不大于左子树存活数走左；大于左子树 + 当前节点就算完，减去这个量走右。

前驱后继一个套路：pre(num) 先 getRank(num)，排名是 1 说明没有比它小的，返回 INT_MIN，否则 index(排名 − 1)。post(num) 走 getRank(num + 1)：这招把「大于 num 的最小数」变成「大于等于 num + 1 的最小数的排名」，排名等于存活总数 + 1 就返回 INT_MAX，否则 index(这个排名)。

删除有个绕弯的地方，注释里写得很明白。删除按排名删，不按值删。原因是：替罪羊树会重构，值相同的一批节点（重复插入的同一个 key），重建时选出的头 h 之后，这批节点可能分到 h 的左侧也可能分到右侧。再按 key 的大小关系找删除目标，方向没法确定走左还是走右。先求出这个数的排名，再按排名一路走下去，方向就是确定的。

remove(num) 还有个存在判定：getRank(num) != getRank(num + 1) 才删。两个排名相等说明 multiset 里根本没有 num，删了个寂寞。

五、复杂度论证

要回答三个问题：死亡节点会不会残留一堆拖慢重构？死亡节点会不会连成长链拖慢查询？均摊 O(log n) 怎么保证？

第一条：活着才有资格被收集。中序收集和查询都带剪枝，aliveSiz == 0 的子树整棵跳过，等于不存在。

第二条是核心：每次增删后所有子树都满足 ALPHA * aliveSiz[i] >= max(aliveSiz[左], aliveSiz[右])。设存活节点总数是 k，沿一条从上到下的路径，存活节点数就是 O(log k)。再看死亡节点：一个死亡节点必须有两个含存活节点的儿子，否则它所在子树必失衡、被重构清掉。所以死亡节点都是「连接件」，k 个存活节点最多需要 k − 1 个死亡节点来连接，而且它们的连接方式也近乎平衡：要是连成长链，同样会触发重构。于是整棵树节点总量 O(k)，路径上存活 O(log k)、死亡也 O(log k)。

实测验证一下：随机插入 10 万个数，再随机删掉能删的（值域 2e7 很稀疏，实际删掉 251 个），然后跑 5 万次查询，平均每条查询路径上遇到存活节点 4.28 个、死亡节点只有 0.01 个。死亡节点要么被重构清掉，要么整棵子树被剪枝无视，路径上基本见不到它们。

α 越小树越矮、重构越频繁；α 越大越容易拖成高树。红色圆是本次插入后触发重建的子树根，死亡节点不会出现在这个演示里。

六、题 1：普通平衡树

洛谷 P3369 就是上面六操作，按课程实现写入口。结构函数一字不动，main 换成 P3369 的标准读法。

#include <bits/stdc++.h>

    using namespace std;

    const int MAXN = 2000001;

    int cntn;
    int root;
    int key[MAXN];
    int ls[MAXN];
    int rs[MAXN];

     // 节点是否存活，删掉就算死亡
    bool alive[MAXN];

     // 子树的存活节点数量
    int aliveSiz[MAXN];

    double ALPHA = 0.7;
    int top;
    int father;
    int side;
    int collect[MAXN];
    int collectSiz;

    int init(int num) {
        key[++cntn] = num;
        ls[cntn] = rs[cntn] = 0;
        alive[cntn] = true;
        aliveSiz[cntn] = 1;
        return cntn;
    }

     // 汇总存活节点数量
    void up(int i) {
        aliveSiz[i] = (alive[i] ? 1 : 0) + aliveSiz[ls[i]] + aliveSiz[rs[i]];
    }

    void inorder(int i) {
        // 增加剪枝：整棵树上没有存活节点也跳过
        if (i != 0 && aliveSiz[i] != 0) {
            inorder(ls[i]);
            if (alive[i]) {
                collect[++collectSiz] = i;
            }
            inorder(rs[i]);
        }
    }

    int build(int l, int r) {
        if (l > r) {
            return 0;
        }
        int m = (l + r) / 2;
        int h = collect[m];
        ls[h] = build(l, m - 1);
        rs[h] = build(m + 1, r);
        up(h);
        return h;
    }

    void rebuild() {
        if (top != 0) {
            collectSiz = 0;
            inorder(top);
            int newRoot = build(1, collectSiz);
            if (father == 0) {
                root = newRoot;
            } else if (side == 1) {
                ls[father] = newRoot;
            } else {
                rs[father] = newRoot;
            }
        }
    }

    bool balance(int i) {
        return ALPHA * aliveSiz[i] >= max(aliveSiz[ls[i]], aliveSiz[rs[i]]);
    }

     // 返回头节点编号
    int add(int i, int f, int s, int num) {
        // 增加剪枝：整棵树上没有存活节点就算空树
        if (i == 0 || aliveSiz[i] == 0) {
            return init(num);
        }
        if (num <= key[i]) {
            ls[i] = add(ls[i], i, 1, num);
        } else {
            rs[i] = add(rs[i], i, 2, num);
        }
        up(i);
        if (!balance(i)) {
            top = i;
            father = f;
            side = s;
        }
        return i;
    }

    void add(int num) {
        top = father = side = 0;
        root = add(root, 0, 0, num);
        rebuild();
    }

    int small(int i, int num) {
        // 增加剪枝：整棵树上没有存活节点，就算空树
        if (i == 0 || aliveSiz[i] == 0) {
            return 0;
        }
        if (num <= key[i]) {
            return small(ls[i], num);
        } else {
            return aliveSiz[ls[i]] + (alive[i] ? 1 : 0) + small(rs[i], num);
        }
    }

    int getRank(int num) {
        return small(root, num) + 1;
    }

    int index(int i, int x) {
        if (x <= aliveSiz[ls[i]]) {
            return index(ls[i], x);
        } else {
            int less = aliveSiz[ls[i]] + (alive[i] ? 1 : 0);
            if (less < x) {
                return index(rs[i], x - less);
            }
        }
        return key[i];
    }

    int index(int x) {
        return index(root, x);
    }

    int pre(int num) {
        int kth = getRank(num);
        if (kth == 1) {
            return INT_MIN;
        } else {
            return index(kth - 1);
        }
    }

    int post(int num) {
        int kth = getRank(num + 1);
        if (kth == aliveSiz[root] + 1) {
            return INT_MAX;
        } else {
            return index(kth);
        }
    }

     // 注意remove方法
     // 因为替罪羊树会重构，所以值相同的一批节点，重构时假设选出的头为h
     // 那么这批节点，有可能在h的左侧，也有可能在h的右侧
     // 所以删除时，如果h已经被删，还要继续寻找其他key值相同的节点
     // 此时只根据key值的大小关系，方向无法确定是左还是右
     // 所以先求出目标的排名，再按排名删除，这样移动方向是确定的
    void remove(int i, int f, int s, int rank) {
        int lsiz = aliveSiz[ls[i]];
        if (rank <= lsiz) {
            remove(ls[i], i, 1, rank);
        } else {
            int cur = alive[i] ? 1 : 0;
            if (alive[i] && rank == lsiz + cur) {
                alive[i] = false;
            } else {
                remove(rs[i], i, 2, rank - lsiz - cur);
            }
        }
        up(i);
        if (!balance(i)) {
            top = i;
            father = f;
            side = s;
        }
    }

    void remove(int num) {
        int rank1 = getRank(num);
        int rank2 = getRank(num + 1);
        if (rank1 != rank2) {
            top = father = side = 0;
            remove(root, 0, 0, rank1);
            rebuild();
        }
    }
    int main() {
        ios::sync_with_stdio(false);
        cin.tie(nullptr);
        int m;
        cin >> m;
        for (int i = 1, op, x; i <= m; i++) {
            cin >> op >> x;
            if (op == 1) {
                add(x);
            } else if (op == 2) {
                remove(x);
            } else if (op == 3) {
                cout << getRank(x) << "\n";
            } else if (op == 4) {
                cout << index(x) << "\n";
            } else if (op == 5) {
                cout << pre(x) << "\n";
            } else {
                cout << post(x) << "\n";
            }
        }
        return 0;
    }

值得记的细节：add 里如果 i == 0 或 aliveSiz[i] == 0，直接 init(num) 返回新节点，这就是「整棵子树死光直接替换」的剪枝在插入里的体现；rebuild 只在整次操作结束后执行一次，取的是路径上最上方的失衡节点 top，所以一次插入最多重建一棵子树。

七、总结

替罪羊树拿「推倒重建」换掉了旋转：失衡判定就一个不等式，重建就一个中序收集加二分建树，增删改查全是递归沿路径走。理解难度低、代码好写、常数小，是实现普通有序表的稳妥选择。

三个数字记牢：平衡因子取 0.7；查询与重构均摊 O(log n)；死亡节点总数不超过存活节点数，路径上更见不到几个。可扩展性弱是它唯一的短板，需要区间信息时换 FHQ Treap 或 Splay。
