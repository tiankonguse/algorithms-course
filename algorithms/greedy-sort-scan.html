贪心：排序之后一遍扫

一道题要把数组切成 k 组，每组的平均值向下取整再求和；一道题要算做完所有任务至少需要多少初始电量。两道题都先排一次序，再用一趟线性扫描把答案扫出来。

零、两道题各自要什么

第一题：给一个长度为 n 的数组和一个数字 k，把数组划分成 k 个非空集合，每个数只能进一个集合。每个集合取平均值向下取整，求这 k 个值的和的最小值。

拿 arr = [1, 2, 3, 4, 5]、k = 2 走一遍。分成 {1} 和 {2,3,4,5}：第一个集合的平均值是 1，第二个是 14 ÷ 4 = 3（向下取整），加起来 4。换个分法 {1,2} 与 {3,4,5} 得到 1 + 4 = 5，更大。

第二题：每个任务有两个参数，需要耗费的电量、以及至少多少电量才能开始这个任务。所有任务都得做完，求至少需要多少初始电量。

两道题的答案都藏在一个顺序或一个切点上，而找它的手段都是排序。

一、平均值最小累加和：最小的几个单独成组

把数组排好序，答案的形状就能直接看出来：最小的 k − 1 个数各自单独成一个集合，剩下的 n − k + 1 个数全部合进一个集合。

为什么单元素组要挑最小的那些？设某个单元素组是 {c}，而那个大集合里还有一个比 c 更小的数 y。把这两个换一下位置：单元素组变成 {y}，c 挪进大集合。

单元素这一边少了 c − y；大集合那边总和多了 c − y，而它的平均值最多涨 (c − y) ÷ 大集合大小。向下取整之后，涨的还不够 c − y（大集合至少有两个数），所以总和不会变大。也就是说，只要大集合里还留着比单元素组更小的数，就该换过来。

剩下的是「为什么只留一个大集合」。两个大集合摆在一起时，它们的平均值都会被大量别的数往里拉；把两个大集合合成一个、再从里面挑最小的一个数单独成组，组数不变，而合起来的那一组拿到的是更大的分母、向下取整又只会往下压。

这个形状用对数器扫过几万组随机数据，从来没错过。落地的时候有两处容易写错：大集合的个数是 n − k + 1，不是 n − k；除法是先求和再除，不是每个数先除再往下取整。

// 平均值最小累加和：把数组分成 k 个非空集合，每个集合的平均值向下取整，求和最小
    long long minAverageSum(vector<int> arr, int k) {
        sort(arr.begin(), arr.end());
        int n = arr.size();
        long long ans = 0;
        for (int i = 0; i < k - 1; i++) {
            ans += arr[i];  // 最小的 k-1 个数各自单独成一个集合
        }
        long long sum = 0;
        for (int i = k - 1; i < n; i++) {
            sum += arr[i];  // 剩下的全部合进一个集合
        }
        return ans + sum / (n - k + 1);
    }

二、执行所有任务的最少初始电量

第二题要从最后一个任务往前倒着想。做完整串任务之后电量可以刚好见底，所以倒着读任务更顺。

假设已经算好「做完后面那些任务，动手之前至少要有 ans 的电」。现在轮到一个任务：耗费 c、至少 m。做它之前既要把后面要的 ans 备足，又要留够自己的耗费，还要满足自己的门槛，所以需要的电量是 max(ans + c, m)。

倒推的顺序有讲究。两个任务 i、j 挨在一起时，谁先做更好？把这两个位置单独拎出来看：i 在前，这一段的需求是 max(mi, ci + mj)；j 在前是 max(mj, cj + mi)。前者不超过后者，当且仅当 ci − mi ≤ cj − mj。

验证一下：如果 ci − mi ≤ cj − mj，那么 ci + mj ≤ cj + mi，而它显然不超过右边那个 max；另一项 mi 也不超过 cj + mi。左边两项都被右边压住，i 在前不亏。

所以真实执行顺序是按 c − m 升序，也就是「门槛高、自己耗电少」的任务先做。代码里是倒推，倒推的顺序正好反过来，于是排序依据写成 c − m 降序。

// 执行所有任务的最少初始电量：每个任务 = {耗费电量, 至少电量}
    long long atLeastEnergy(vector<pair<long long, long long>>& jobs) {
        // 耗费电量减至少电量，差值大的排在前面，再按这个顺序往回倒推
        sort(jobs.begin(), jobs.end(), [](const pair<long long, long long>& a,
                                          const pair<long long, long long>& b) {
            return a.first - a.second > b.first - b.second;
        });
        long long ans = 0;
        for (auto& job : jobs) {
            ans = max(ans + job.first, job.second);
        }
        return ans;
    }

复杂度分析

题目关键操作时间空间
平均值最小累加和排序 + 前缀和与整段求和O(n log n)O(1) 额外
执行所有任务的最少初始电量排序 + 一趟累加取 maxO(n log n)O(1) 额外

两道题都是「排序定顺序 + 一趟线性扫」，扫描本身只占 O(n)，时间全在排序上。n = 105 实测：平均值 3.51ms，电量 3.78ms。

平均值那题还要当心 32 位溢出。n = k = 105、每个数都是 105 时，求和要到 1010，超过了 2147483647。实测把它塞进 32 位整数会得到 1410065408，差了三倍还多。电量那题反而安全：按题面范围，答案不超过 sum(耗费) + max(至少) = 109 + 105，32 位装得下，但用 64 位写更省心。

总结

平均值那题的答案形状是「k − 1 个单元素组 + 1 个大组」，单元素组挑最小的那几个，靠的是「把大组里更小的数换出来不会变差」这条交换论证；大组只留一个，靠的是平均值的稀释效应。切点定好之后，剩下的只是一次遍历求和。

电量那题先想清楚倒推的递推式 max(ans + c, m)，再用相邻两项交换把排序依据推出来：按耗费减至少升序执行。两道题都指向同一个习惯，先让顺序或切点确定下来，答案就是一遍线性扫描的事。
