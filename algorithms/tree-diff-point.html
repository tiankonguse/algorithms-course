树上点差分：路径修改四次单点改完

树上有一连串操作，每个把 a 到 b 路径上所有点加上同一个数，操作全打完问每个点的点权。顺着路径一条条爬是最容易想到的办法，代价是操作次数乘上路径长度。点差分把每次操作拆成四个点各改一次，最后一趟后序累加收拢出全部答案。

零、背景

数组上的差分是现成的：区间 [l, r] 加 v，只在 l 处记 +v、r 的下一个位置记 −v，最后做一次前缀和，每个位置拿到的就是答案。树上没有「下一个位置」，却有对应的结构：每个点往上到根有一条祖先链。把标记打在点上，让它们沿着祖先链往上冒，冒到某个点时剩下的净和，就是这个点的答案。

一、问题

洛谷 P3128 最大点权。n 个点的一棵树，一开始点权全为 0；m 个操作，每个把 a 到 b 路径上所有点加 1；所有操作完成后，打印树上最大的点权。n 到 5×10⁴，m 到 10⁵。

二、四个加减

先给结论。设一次操作是 (x, y) 加 v，l 是 x 与 y 的 lca，打标只有四步：

num[x] += v;  num[y] += v;  num[l] -= v;  num[l 的父亲] -= v;

所有操作打完，从根做一次后序遍历，每个点把全部子节点的 num 收拢进来，收完 num[u] 就是 u 的最终点权。

为什么这四步就对？把每份标记看成一股要往上冒的流量。+v 放在 x，会流经 x 到根的整条链；+v 放在 y，同理。两股在 l 处汇合，再往上就重复计量了，所以在 l 处放一个 −v 拦一道。只拦 l 还不够：l 自己是路径上的点，该剩 v，两股 +v 减一个 −v 正好剩 v；l 上方的点两股都流过、却不在路径上，要靠 l 的父亲处那个 −v 再拦一道。图 2 把这股流量画了出来。

后序遍历一次实现全部冒泡。num[u] 收拢完子节点，等于 u 子树内标记之和，也就是 u 收到的全部流量。两个视角说的是同一件事，代码里选后者，一遍 dfs 就够。

三、模板代码

前置只会用到 lca，倍增和 tarjan 都行，模板题的数据范围下倍增足够。

// 倍增求 lca：dfs1 记深度与 2 的幂次祖先，lca 先把深的提平再一起上跳
    void dfs1(int u, int f) {
        deep[u] = deep[f] + 1;
        stjump[u][0] = f;
        for (int p = 1; p <= power; p++) {
            stjump[u][p] = stjump[stjump[u][p - 1]][p - 1];
        }
        for (int e = head[u]; e != 0; e = nxt[e]) {
            if (to[e] != f) dfs1(to[e], u);
        }
    }

    int lca(int a, int b) {
        if (deep[a] < deep[b]) swap(a, b);
        for (int p = power; p >= 0; p--) {
            if (deep[stjump[a][p]] >= deep[b]) a = stjump[a][p];
        }
        if (a == b) return a;
        for (int p = power; p >= 0; p--) {
            if (stjump[a][p] != stjump[b][p]) {
                a = stjump[a][p];
                b = stjump[b][p];
            }
        }
        return stjump[a][0];
    }

打标与收拢是两个函数，加起来十几行：

// 树上点差分：一条路径 (u, v) 全部加 val，拆成四个点各改一次
    void addPath(int u, int v, int val) {
        int l = lca(u, v);
        int lf = stjump[l][0];
        num[u] += val;
        num[v] += val;
        num[l] -= val;
        num[lf] -= val;
    }

    // 后序累加：每个点收拢子节点的标记，剩下的就是它的最终点权
    void collect(int u, int f) {
        for (int e = head[u]; e != 0; e = nxt[e]) {
            if (to[e] != f) collect(to[e], u);
        }
        for (int e = head[u]; e != 0; e = nxt[e]) {
            if (to[e] != f) num[u] += num[to[e]];
        }
    }

main 里只做四件事：建图、dfs1、对每个操作调一次 addPath、collect 完扫最大值。四个加减漏一个都会错，而且错得不声张。实测两万组随机小数据（n 从 2 到 12，m 从 1 到 12，跟爬路径的暴力对答案）：漏掉 lca 父亲处那个 −1，68.30% 的组答案偏大；把 lca 处写成 −2v（那是边差分的口径），77.86% 的组偏小；两个都不减，100% 错。漏减只在某个操作的 lca 有父亲时现形：lca 是根时，那个标记落在 0 号点上，累加范围之外，减不减一个样。

四、复杂度分析

环节时间空间
倍增预处理（dfs1）O(n log n)O(n log n)（stjump 表）
每次操作打标（含求 lca）O(log n)
后序收拢与扫最大值O(n)
合计（m 个操作）O(n log n + m log n)

空间按题目上限算。n = 5×10⁴ 时 stjump 是 5×10⁴ × 16 个 int，约 3.2MB；链式前向星的 nxt、to 各 2n 个 int，加上 num、deep，总共几条 int 数组，十 MB 以内。

实测：链形树 n = m = 10⁴，差分 0.4ms，同样数据朴素爬路径 110.3ms，差着两百多倍；n = m = 10⁵ 时差分 8.5ms，朴素是 10¹⁰ 次爬步，跑不完。

递归深度也提一句。收拢的递归深度等于树高，链上就是 n。本机 g++ -O2、8MB 栈下实测 10⁵ 层能过、1.5×10⁵ 层段错误。模板题 n 到 5×10⁴，递归稳稳的；数据到 3×10⁵ 的题要换显式栈，把「当前遍历到第几条边」一起压栈，弹栈时接着走。

五、总结

要点三条。其一，点差分的本质是让标记沿祖先链上冒：路径上的点净收 v，路径外的点进多少出多少。lca 处 −v 保住 lca 自己，lca 父亲处 −v 拦住汇合后继续上冒的部分，两道拦截各管一段。其二，后序累加一遍实现全部冒泡，子树内标记和就是终值，不需要真的一个个点往上传。其三，代价从「操作数 × 路径长」变成 n log n + m log n，瓶颈全在求 lca；lca 换 tarjan 能把预处理降到近乎 O(n)，总复杂度不变。

差分只解决了「路径修改」这一半。标记打在点上得到点权，打在边上得到边权，后者 lca 处要减两次；打标方式都能用同一套冒泡视角推出来。

六、最后

写这个模板只有两个地方容易翻车：四个加减漏一个，以及收拢时把「先递归儿子再合并」写成「边递归边合并」。前者靠对拍抓，后者会让 num[u] 并入还没收拢完的子树，树一大就错。模板本身十几行，值得默写。

《完》
