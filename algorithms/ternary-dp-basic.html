三进制状压：状态编码与网格幸福感

状压 dp 默认每位两个取值，遇到一个格子有三种取值就装不下了。凑合的办法是每格给两个 bit，可 m = 5 时状态数会从 243 涨到 1024，多出来的 781 个状态一个也用不上。按 3 的幂直接拼，状态数就回到 243，取位只剩一次除法和一次取模。

零、背景

一个整数有 32 个二进制位，每一位装「第 i 个样本用没用过」，状态数就是 2 的 n 次方。这套写法顺手的前提是每格只有两种取值。

题目一旦给出三种取值，最先想到的通常是每格分配两个 bit，用 00、01、10 表示三种情况，11 空着不用。能跑，代价写在状态数里：m 个格子从 3m 变成 4m。

浪费的倍数看着是常数，可它是乘在整个状态空间上的。本机量了一遍 m 从 1 到 5 的变化：1.33、1.78、2.37、3.16、4.21 倍，m 每加 1 就再翻 1.33 倍。m = 5 时两种写法是 243 对 1024，多出来 781 个状态，填表的时候还得给它们留位置。

换成三进制之后，取位和置位不再是位运算，是一次除法和一次取模。慢一点，但状态数少了 4 倍，这笔买卖划算。

一、问题

最大化网格幸福感。m × n 的网格，有 in 个内向的人、ex 个外向的人，由你决定住进去多少人、各住哪一格，不必让所有人都住进来。每个人的幸福感这样算：

1）内向的人起手 120 分，每有一个邻居减 30 分；

2）外向的人起手 40 分，每有一个邻居加 20 分。

邻居只算上下左右四个方向。全网格的幸福感是所有人的分数之和，返回最大可能值。m、n 不超过 5，in、ex 不超过 6。

内向的人怕邻居，外向的人要邻居，两种人往同一张网格上摆，摆法正好相反，只能把所有摆法都试一遍。

二、三进制的两个操作

把状态 s 当成一个 m 位的三进制数，第 j 位的权是 3 的 j 次方。取第 j 位就是先除以这个权、再对 3 取余；改第 j 位就是把原来的值减掉、再加上新值。

// 把 s 当成 3 进制数，返回第 j 位（bit 是 3 的 j 次方）
        int get(int s, int bit) {
            return s / bit % 3;
        }

        // 把第 j 位改成 v，其余位不动，返回新状态
        int set(int s, int bit, int v) {
            return s - get(s, bit) * bit + v * bit;
        }

变量 bit 是 3 的 j 次方，跟着递归一路往下传，走一格乘一次 3。它不算关键可变参数，因为它的值完全由 j 决定。

三、朴素做法要试多少次

每个格子三种选择，5 × 5 一共 25 格，全部枚举是 325 = 847288609443 种摆法。这个数字比宇宙里的恒星数量还大两个量级，跑到天亮也出不来。

能省的地方在于：做 (i, j) 的决定时，需要知道的只有左邻和上邻住了什么人，右面下面还没走到，不用管。这就是轮廓线 dp 的入口。

四、轮廓线接上三进制

按行优先扫到 (i, j) 时，已经定下来的格子是「i−1 行整行」加「i 行的 0 到 j−1 列」。拿一个 m 位的状态装下这条分界线：第 0 到 j−1 位装本行左侧，第 j 到 m−1 位装上一行右侧。

于是 (i, j) 要的两个邻居都在状态里：上方是第 j 位，左方是第 j−1 位。走完 (i, j) 把第 j 位改成这次的决定，往右挪一格，轮廓线跟着往前推。

这里有个细节：j = 0 时没有左邻居，代码里直接取 0。这个 0 既表示「空着」又表示「没有」，在本题里恰好等价，因为空邻居不产生任何分数上的影响。换成别的题就不一定了。

五、一次转移里的三笔账

当前格有三种选择，每一种要算的账不一样。先取出两个邻居：

const int MAXN = 5, MAXM = 5, MAXS = 243, MAXP = 7;
        int dp[MAXN][MAXM][MAXS][MAXP][MAXP];
        int n, m;

        // 当前来到 i 行 j 列，bit = 3 的 j 次方
        // s 是轮廓线的状态，能读出左邻和上邻放了什么人
        // 内向的人还剩 a 个，外向的人还剩 b 个
        // 返回 i 行 j 列及其之后能得到的最大幸福感
        int f(int i, int j, int s, int a, int b, int bit) {
            if (i == n) return 0;
            if (j == m) return f(i + 1, 0, s, a, b, 1);
            if (dp[i][j][s][a][b] != -1) return dp[i][j][s][a][b];
            // 分支1：这个格子空着
            int ans = f(i, j + 1, set(s, bit, 0), a, b, bit * 3);
            int up = get(s, bit);                      // (i-1, j) 上方邻居
            int left = j == 0 ? 0 : get(s, bit / 3);   // (i, j-1) 左方邻居
            int neighbor = 0, pre = 0;
            if (up != 0) { neighbor++; pre += up == 1 ? -30 : 20; }
            if (left != 0) { neighbor++; pre += left == 1 ? -30 : 20; }
            // 分支2：放内向的人
            if (a > 0) {
                ans = max(ans, pre + 120 - neighbor * 30 + f(i, j + 1, set(s, bit, 1), a - 1, b, bit * 3));
            }
            // 分支3：放外向的人
            if (b > 0) {
                ans = max(ans, pre + 40 + neighbor * 20 + f(i, j + 1, set(s, bit, 2), a, b - 1, bit * 3));
            }
            dp[i][j][s][a][b] = ans;
            return ans;
        }

三笔账要分开算，混在一起就错了：

1）neighbor 是老邻居对新来的人的影响，内向的人每有一个邻居减 30，外向的人每有一个邻居加 20；

2）pre 是新来的人对老邻居的影响，方向正好反过来：老邻居是内向的人就减 30，是外向的人就加 20；

3）自己那份起手分，内向 120、外向 40。

漏掉 pre 是最容易犯的一个。随机小数据上量了 2 万组，这一项写漏会让 46.80% 的用例答案不对。

六、推进台

选一个网格和人数，一格一格往前推。右边那排格子是轮廓线，橙色框是正要处理的第 j 位，它左边那格是左邻。下面那行「从这里走完最优」是记忆化算出来的值，你走的每一步都可以拿它对照。

推进台：网格幸福感的逐格决策

「放内向」和「放外向」在人用完时会变灰。走完 25 格之后，下面会给出这条路径的分数和这一局的最优值，两者相等就说明每一步都踩在最优点上。

七、实测

本机 g++ -O2、5 × 5 网格、in = ex = 6 跑了一遍：答案是 1240，记忆化只填了 105529 格，占整张表 297675 格的 35.45%，耗时 4.016 毫秒。整张表 25 × 243 × 7 × 7 个 int，1.14 MB。

复杂度分析

时间 O(n × m × 3m × in × ex)。状态是 (行、列、轮廓线、剩余内向人数、剩余外向人数)，m = 5、in = ex = 6 时上界是 5 × 5 × 243 × 7 × 7 = 297675，每个状态三种分支，常数次转移。

空间是同一张 dp 表，O(n × m × 3m × in × ex)，按题目上限 5 × 5 × 243 × 7 × 7 个 int 算，1.14 MB。人数那一维可以省掉，因为人数变化只发生在放人的分支上，代价是失去记忆化带来的剪枝。

总结

每格取值数不是 2 的幂时，按 k 的幂直接拼状态，取位是一次除法加一次取模，写起来和二进制一样短。m = 5 时三进制比「每格两 bit」省下 4.21 倍的状态。轮廓线那套位布局照搬二进制的版本，只是每位存 0、1、2：上邻在第 j 位，左邻在第 j−1 位，权差一个 3。算分时记得新来的人也会影响老邻居，那一笔是反着算的。再往后是同一套编码用在更大的 n 上，那时要处理的是行与行的接力和状态预处理。
