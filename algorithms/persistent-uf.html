可持久化并查集

并查集要支持「回到第 x 号版本」。办法是把 father 和 siz 两个数组换成可持久化数组，同时取消路径压缩，只留小挂大。一次合并只改两个位置，历史版本就自然留下了。

零、背景

普通并查集有两个优化：路径压缩和按大小合并。压缩会把查找路径上每个点的 father 直接指向集合头，一次 find 改多少个位置根本不可控。可持久化要求「每次修改只碰常数个位置」，所以压缩必须先去掉。

去掉之后只剩小挂大。这时任何点到集合头的距离是 O(log n)，因为一个点每被挂一次，它所在集合的节点数至少翻倍。这个性质后面要反复用。

一、题目1：可持久化并查集模版题

数字从 1 到 n，一开始每个数字所在的集合只有自己。第 i 条操作发生后，所有数字的状况记为 i 版本，操作一共 m 次：

  • 操作 1 x y：基于上个版本，把 x 的集合与 y 的集合合并，生成当前版本
  • 操作 2 x：拷贝第 x 号版本，生成当前版本
  • 操作 3 x y：拷贝上个版本，生成当前版本，查询 x 和 y 是否属于一个集合

1 ≤ n ≤ 10⁵，1 ≤ m ≤ 2 × 10⁵。测试链接：P3402。

二、朴素做法为什么不行

最直接的想法是每个版本留一份完整的 father 和 siz。操作 1 先拷一份再改，操作 2 直接拷第 x 份。一次拷贝 O(n)，m 次操作就是 O(n·m)，n = 10⁵、m = 2 × 10⁵ 时是 2 × 10¹⁰。

能省的地方很明确：一条操作只改动 father 和 siz 里的一两个位置，其余 n − 2 个数字一个都没动。可持久化数组做的就是这件事，一次修改只新造 O(log n) 个节点，没动的部分和历史版本共用。

三、路径压缩改的是一大片

所以这里不做压缩。find 就沿着 father 链一层一层往上跳，一次都不改 father。

四、只做小挂大

集合的节点数记在 siz 里，只有集合头的 siz 有意义。合并时比一下两个头的 siz，决定谁挂谁。

五、father 与 siz 都是可持久化数组

合并是单点修改 father 或 siz，查询是单点查询。两个数组都是「单点修改、单点查询」的数组，于是各用一棵可持久化线段树存（可持久化数组的做法见可持久化线段树那一节）。build 建出版本 0：father[i] = i、siz[i] = 1。

rootfa[v] 和 rootsiz[v] 分别是第 v 版本的 father 树根和 siz 树根。操作 2「拷贝第 x 号版本」就是把 rootfa[x]、rootsiz[x] 抄过来，O(1) 完成，一个节点都不用造。

六个数字、六条操作的版本演化

n = 6。操作依次是合并 1 2、合并 3 4、合并 2 3、查询 1 4、回到版本 2、查询 1 4。点「下一步」看每个版本的 father 长什么样。

集合头（father 指向自己） 本次被改动的位置 当前版本

六、代码

两棵树的 build 分开写，因为初值不同：father 填下标，siz 填 1。

int buildfa(int l, int r) {
        int rt = ++cnt;
        if (l == r) {
            val[rt] = l;
        } else {
            int mid = (l + r) / 2;
            ls[rt] = buildfa(l, mid);
            rs[rt] = buildfa(mid + 1, r);
        }
        return rt;
    }

    int buildsiz(int l, int r) {
        int rt = ++cnt;
        if (l == r) {
            val[rt] = 1;
        } else {
            int mid = (l + r) / 2;
            ls[rt] = buildsiz(l, mid);
            rs[rt] = buildsiz(mid + 1, r);
        }
        return rt;
    }

update 是标准的单点修改，query 是标准的单点查询，都返回新根或值。

int update(int jobi, int jobv, int l, int r, int i) {
        int rt = ++cnt;
        ls[rt] = ls[i];
        rs[rt] = rs[i];
        if (l == r) {
            val[rt] = jobv;
        } else {
            int mid = (l + r) / 2;
            if (jobi <= mid) {
                ls[rt] = update(jobi, jobv, l, mid, ls[rt]);
            } else {
                rs[rt] = update(jobi, jobv, mid + 1, r, rs[rt]);
            }
        }
        return rt;
    }

    int query(int jobi, int l, int r, int i) {
        if (l == r) {
            return val[i];
        }
        int mid = (l + r) / 2;
        if (jobi <= mid) {
            return query(jobi, l, mid, ls[i]);
        } else {
            return query(jobi, mid + 1, r, rs[i]);
        }
    }

find 不压缩，一路跳到 father[i] == i。Union 里改两个位置：被挂的那个头的 father，以及新头的 siz。

int find(int x, int v) {
        int fa = query(x, 1, n, rootfa[v]);
        while(x != fa) {
            x = fa;
            fa = query(x, 1, n, rootfa[v]);
        }
        return x;
    }

    void Union(int x, int y, int v) {
        int fx = find(x, v);
        int fy = find(y, v);
        if (fx != fy) {
            int xsiz = query(fx, 1, n, rootsiz[v]);
            int ysiz = query(fy, 1, n, rootsiz[v]);
            if (xsiz >= ysiz) {
                rootfa[v] = update(fy, fx, 1, n, rootfa[v]);
                rootsiz[v] = update(fx, xsiz + ysiz, 1, n, rootsiz[v]);
            } else {
                rootfa[v] = update(fx, fy, 1, n, rootfa[v]);
                rootsiz[v] = update(fy, xsiz + ysiz, 1, n, rootsiz[v]);
            }
        }
    }

主循环里每轮先把上一版本的两个根抄过来，再按操作类型决定是合并、换根还是查询。

int main() {
        ios::sync_with_stdio(false);
        cin.tie(nullptr);
        cin >> n >> m;
        rootfa[0] = buildfa(1, n);
        rootsiz[0] = buildsiz(1, n);
        for (int v = 1, op, x, y; v <= m; v++) {
            cin >> op;
            rootfa[v] = rootfa[v - 1];
            rootsiz[v] = rootsiz[v - 1];
            if (op == 1) {
                cin >> x >> y;
                Union(x, y, v);
            } else if (op == 2) {
                cin >> x;
                rootfa[v] = rootfa[x];
                rootsiz[v] = rootsiz[x];
            } else {
                cin >> x >> y;
                if (find(x, v) == find(y, v)) {
                    cout << 1 << "\n";
                } else {
                    cout << 0 << "\n";
                }
            }
        }
        return 0;
    }

复杂度分析

find 要沿链跳 O(log n) 层，每层一次 query 是 O(log n)，所以 find 是 O(log² n)。Union 两次 find 加两次 update，也是 O(log² n)。

操作时间说明
build 版本 0O(n)两棵树各建一次
findO(log² n)跳 O(log n) 层，每层一次 O(log n) 查询
UnionO(log² n)两次 find 加两次 update
操作 2 拷贝版本O(1)只把两个根编号抄过来
总体O(n + m log² n)m = 2 × 10⁵、n = 10⁵ 时约 6 × 10⁷
空间O(m log n)每次 update 造 O(log n) 个节点，最多 2m 次 update

代码里 MAXT 开到 8 × 10⁶ 就是这么算的：m = 2 × 10⁵，每次合并最多两次 update，每次 update 造约 ⌈log₂ 10⁵⌉ + 1 ≈ 18 个节点，2 × 2 × 10⁵ × 18 ≈ 7.2 × 10⁶。n = 10⁵ 时树高上限 17，这条链不会更长。

最后

可持久化并查集的难点全在「数组可持久化」，并查集这边只是去掉压缩、换成小挂大。下一节换个更省的结构：不要任意版本，只要能退回上一步，那就用不着线段树，一个栈就够了。
