树型 dp：每个节点的几种状态

上一页的返回值装的是客观量：最大值、最小值、子树和。这一页的题型关心的是决策，节点选不选、摄像头放不放，于是返回值从一个数变成「每种决策各一个答案」。

零、状态就是决策的枚举

前一类题里，父节点想知道子树「是什么」；这一类的父节点想知道子树「在某种安排下最好能到什么程度」。

「某种安排」能枚举几个，返回值就分几个分量。职员只有来和不来两种，答案就分两份；监控里的节点有没覆盖、被覆盖没摄像头、有摄像头三种，答案就分三份。

分完之后，把「父节点在每种安排下取哪些孩子的哪一种」写清楚，转移方程通常只有两三行。难的地方不在写，在于状态分得对不对：少一个状态，有些局面就没法表达。

一、没有上司的舞会

某大学有 n 个职员，每人有一个快乐指数。他们的从属关系是一棵树，父亲是儿子的直接上司。宴会上，如果一个职员的直接上司来了，他就不来。求邀请哪些职员能使快乐指数总和最大。

每个职员只有来和不来两种选择，于是定义两个数组：

  • yes[u]：u 来，以 u 为头的子树能拿到的最大快乐指数；
  • no[u]：u 不来，以 u 为头的子树能拿到的最大快乐指数。

转移就两行：

  • yes[u] = happy[u] + Σ no[v]。u 来了，每个直接下属都不能来，只能取他们「不来」的那份；
  • no[u] = Σ max(no[v], yes[v])。u 不来，下属随意，各取大的那份。

答案取 max(no[root], yes[root])。树的根是输入里唯一没有被标成「下属」的那个职员。

两处高频写错都在累加的那一边。yes 里写成 max(no[v], yes[v])，实测在两万个随机小树上 58.03% 出错；no 里写成 min(no[v], yes[v])，93.50% 出错。第二处更隐蔽，因为 min 看上去像是在「避免冲突」，其实冲突已经被 yes 那一边挡掉了，这里只负责挑好的。

vector<vector<int>> g;
    vector<int> happy;
    int no[MAXN];
    int yes[MAXN];

    void f(int u) {
        no[u] = 0;
        yes[u] = happy[u];
        for (int v : g[u]) {
            f(v);
            no[u] += max(no[v], yes[v]);
            yes[u] += no[v];
        }
    }

    int bestHappy(int root) {
        f(root);
        return max(no[root], yes[root]);
    }

二、监控二叉树

给一棵二叉树，在节点上装摄像头。每个摄像头监视它的父节点、自己、以及直接子节点。求覆盖全部节点所需的最少摄像头数量。

先想贪心的方向。叶子自己装最亏，一个摄像头只罩住两个节点；装在自己的父亲身上，就能顺带罩住兄弟。所以从叶子往上推：谁的某个孩子没被覆盖，谁就必须装。

把这个「往上推」写成返回值，每个节点有三种状态：

  1. 0：这个节点没被覆盖（但它下面的节点都覆盖了）；
  2. 1：这个节点被覆盖，它身上没有摄像头；
  3. 2：这个节点被覆盖，它身上有摄像头。

转移三条：

  1. 两个孩子里有 0，自己必须装，ans++，返回 2；
  2. 两个孩子都是 1，自己被覆盖着但没有摄像头，只能指望父亲，返回 0；
  3. 其余情况返回 1（说明至少有一个孩子带着摄像头，把自己也罩住了）。

空节点返回 1。它把「这个位置没有孩子」当成「这个位置已经被覆盖」，父节点就不会因为一个空缺位置去装摄像头。

递归里有个前提假设：x 的上方一定有父亲。没有这句，「返回 0 等着上面管」就无从谈起，根节点也正是靠它才需要最后补一刀。

收尾别忘了：算完根之后，如果根返回 0，说明没人管它，得自己装一个。漏掉这一步实测 13.72% 出错。

另外两处更狠。空节点返回 0 的版本 100% 出错，它会误判「这里必须有人来管」，一路往上多装一堆；漏掉「两个孩子都是 1」这一支也 100% 出错，因为这一支正是把「等着父亲」表达出来的唯一出口。三个状态少一个都转不动。

int ans;

    int f(Node* x) {
        if (x == nullptr) return 1;
        int L = f(x->left);
        int R = f(x->right);
        if (L == 0 || R == 0) {
            ans++;
            return 2;
        }
        if (L == 1 && R == 1) return 0;
        return 1;
    }

    int minCameraCover(Node* root) {
        ans = 0;
        if (f(root) == 0) ans++;
        return ans;
    }

三、结构决定答案

三状态的转移里，节点只要能「指望父亲」，就不会急着装摄像头。这直接决定了答案跟着树形走。

链和完全二叉树给出的数值一样，都是「一个摄像头管三个节点」的密度。随机树的答案落在这两者附近，因为它既有长链又有分叉，两种机会都能用上。

复杂度分析

题目时间空间
没有上司的舞会O(n)O(h)
监控二叉树O(n)O(h)

两题都是每个节点进一次出一次，每个孩子只看一眼，时间 O(n)；空间是递归栈，深度等于树高 h。多叉树用邻接表建图，边数是 n − 1，也是 O(n)。

规模实测：n = 10⁶ 的多叉随机树上跑舞会，vector 邻接表 57.68 ms；同样是 10⁶ 个节点的随机二叉树，监控一遍 12.87 ms。

总结

状态就是把节点的决策枚举出来。两种决策两个分量，三种决策三个分量，少一个就有局面表达不了。

写转移时只问一句：父节点在这种安排下，能取到孩子的哪一种安排。舞会的 yes 要孩子的 no，no 要孩子的最大值；监控里孩子有 0 就必须装，孩子全是 1 就往上推。

空节点的返回值是哨兵，要挑一个「不逼着父节点做多余动作」的值。舞会里空节点不存在，不用管；监控里空节点返回 1，把空位当成已覆盖。

三状态这类写法里，「指望父亲」是一条真实存在的转移。只要题目允许父节点替子节点兜底，状态 0 就必须留着。
