欧拉序求 LCA

树上倍增求一次 LCA 要 O(log n)，查询多起来就吃力。这一节把整棵树拍成一条欧拉序，两点各自第一次出现的位置夹住一段区间，区间里最靠上的那个点就是 LCA。配上倍增表，单次查询降到 O(1)。

零、背景

前面已经讲过两条路：树上倍增，预处理 O(n log n)，单次查询 O(log n)；重链剖分，预处理 O(n)，单次查询 O(log n)。这两条路都是「查询时往上跳」，跳的步数带了 log。

想做到 O(1) 查询，得换思路：把「跳」变成「查表」。树上的祖先关系如果能压到一段连续区间上，区间最值就是现成的 RMQ 问题，而 RMQ 有经典的 O(1) 查询做法，稀疏表。

欧拉序就是那个「把树压成区间」的序列。代价是序列长度变成 2n - 1，预处理空间和时间都是 O(n log n)，而且树不能动。静态树、海量查询，正是它的主场。

一、问题

题目：一共有 n 个节点，给定 n - 1 条边，所有节点组成一棵树，给定树头 root。一共有 m 条查询，格式 u v，打印 u 和 v 的最低公共祖先。1 ≤ n、m ≤ 5 × 10⁵。测试链接：https://www.luogu.com.cn/problem/P3379。

朴素做法就是每次查询都从两点往上走：把 u 到根的路径全打上标记，再让 v 一直往父走，第一个碰到标记的点就是 LCA。一次查询最坏走满树高，链形树上是 O(n)，m 次查询就是 O(nm)，5 × 10⁵ 的规模直接超时。

倍增法把单次查询压到 O(log n)，但 m = 5 × 10⁵ 时这个 log 仍然可观。目标很明确：预处理 O(n log n) 不变，单次查询 O(1)。

二、欧拉序是什么

对树做一遍 DFS。每到一个节点就把它写进序列；每从一个孩子回回来，再把当前节点写一遍。走完整棵树，写出来的长度恰是 2n - 1 的序列就是欧拉序。

可以发现一个关键性质：任何点在欧拉序里可能出现多次，但它的所有出现都落在自己子树对应的那段连续区间里。第一次出现的位置记为 first[u]，最后一次出现的位置就是子树段的右边界。

以这棵树为例，欧拉序是「1 2 4 2 1 3 1 5 6 5 7 9 7 5 1 8 10 8 1」。注意 5 这个点：孩子 6 走完回一次，孩子 7 的整棵子树走完又回一次，所以 5 出现了三次。

序列长度是 2n - 1：每个点进入时写一次共 n 次，每个非根点回溯到父时父再写一次共 n - 1 次，加起来 2n - 1 项。这棵 10 个点的树写了 19 项，正好对上。

三、为什么区间最浅就是 LCA

设 u ≠ v，看欧拉序里 first[u] 和 first[v] 夹住的那段（不妨设 first[u] < first[v]）。这段序列记录的是：从进入 u 开始，绕行到进入 v 为止的完整路径。

这段路上经过的深度最浅的点，恰好是 LCA(u, v)。可以发现，绕行路径的最高点只可能是 LCA：比 LCA 更浅的点在这段路上根本不会出现，比 LCA 深的点又顶多和 LCA 的孩子持平。区间深度最浅那个点，就是 LCA 本尊。

区间含两端点是有讲究的。如果 u 是 v 的祖先，那么 first[u] < first[v]，区间右端就是 v 自己，途中不再回到 u，但 u 已经作为左端点在区间里了，最浅点正是 u，答案正确。所以查询不需要任何特判，u 等于 v 时区间长度为 1，查出来就是自己。

四、倍增表怎么建

「最上方的节点」可以直接比：getUp(x, y) 返回 first 更小的那个。这里有个容易误解的地方：单独拎出两个节点，「first 小」并不等于「深度浅」，别的子树里先进入的深点就是反例。真正成立的是区间性质：欧拉序的任何连续一段里，最上方的节点必然是这一段里 first 最小的，其余节点都是它走下去再回来的后代，进入都更晚。倍增表合并的子区间都落在查询区间内，这个性质一路保持。

这里有个细节：两个点的 first 相同是不可能的，first 是唯一的进入时刻。所以比较函数无需并列处理。

rmq[i][p] 的含义：从欧拉序第 i 项开始、往右长度 2 的 p 次方的区间里，最上方的节点。转移就是两个半区拼起来：

rmq[i][cur] = getUp(rmq[i][pre], rmq[i + (1 << pre)][pre]);

查询 [l, r] 时取 k = lg2[r - l + 1]，两段长 2 的 k 次方的区间重叠覆盖即可，单次 O(1)。lg2 预处理成数组，避免查询时调用库函数。

完整代码：

#include <bits/stdc++.h>

    using namespace std;

    const int MAXN = 500001;
    const int MAXP = 20;
    int n, m, root;

    int headg[MAXN];
    int nextg[MAXN << 1];
    int tog[MAXN << 1];
    int cntg;

    int first[MAXN];
    int lg2[MAXN << 1];
    int rmq[MAXN << 1][MAXP];
    int cntEuler;

    void addEdge(int u, int v) {
        nextg[++cntg] = headg[u];
        tog[cntg] = v;
        headg[u] = cntg;
    }

    int getUp(int x, int y) {
        return first[x] < first[y] ? x : y;
    }

    void dfs(int u, int fa) {
        first[u] = ++cntEuler;
        rmq[first[u]][0] = u;
        for (int e = headg[u]; e > 0; e = nextg[e]) {
            int v = tog[e];
            if (v != fa) {
                dfs(v, u);
                rmq[++cntEuler][0] = u;
            }
        }
    }

    void buildRmq() {
        dfs(root, 0);
        for (int i = 2; i <= cntEuler; i++) {
            lg2[i] = lg2[i >> 1] + 1;
        }
        for (int pre = 0, cur = 1; cur <= lg2[cntEuler]; pre++, cur++) {
            for (int i = 1; i + (1 << cur) - 1 <= cntEuler; i++) {
                rmq[i][cur] = getUp(rmq[i][pre], rmq[i + (1 << pre)][pre]);
            }
        }
    }

    int getLCA(int x, int y) {
        x = first[x];
        y = first[y];
        if (x > y) {
            swap(x, y);
        }
        int k = lg2[y - x + 1];
        return getUp(rmq[x][k], rmq[y - (1 << k) + 1][k]);
    }

    int main() {
        ios::sync_with_stdio(false);
        cin.tie(nullptr);
        cin >> n >> m >> root;
        for (int i = 1, u, v; i < n; i++) {
            cin >> u >> v;
            addEdge(u, v);
            addEdge(v, u);
        }
        buildRmq();
        for (int i = 1, u, v; i <= m; i++) {
            cin >> u >> v;
            cout << getLCA(u, v) << '\n';
        }
        return 0;
    }

五、查询的正确路径

getLCA 先把两点换算成 first 位置，令 x < y，然后在欧拉序的 [x, y] 闭区间上查「最上方的节点」。整个流程没有一行特判，u 等于 v 时区间长度为 1，查出来就是自己。

预处理那侧有两个容易写错的地方。一是 rmq 的第二维要开到 lg2[2n - 1]，欧拉序长度接近 2n；二是 dfs 里回溯写 rmq[++cntEuler][0] = u，这条语句在「每个孩子走完」之后执行一次，漏写会把序列长度和区间全部搞错。

六、复杂度分析

全流程只有「建表」和「查表」两种操作，规模都由欧拉序长度 2n - 1 决定。

步骤时间复杂度空间复杂度
DFS 生成欧拉序O(n)O(n log n)
预处理 lg2 数组O(n)
倍增表逐层递推O(n log n)
单次查询 getLCAO(1)O(1)

空间是这套做法的主要代价：rmq 开到 (2n - 1) × log(2n - 1)，n = 5 × 10⁵ 时约 10⁶ 行 × 20 层。每次查询只做两次比较函数调用加一次数组访问，常数极小。

和树上倍增对比：预处理同是 O(n log n)，但查询从 O(log n) 降到 O(1)。查询次数越多，这笔换来越划算。

七、最后

欧拉序求 LCA 的链条是：树 → 欧拉序 → first 区间 → RMQ → 稀疏表。每一步都不难，串起来就把「树上跳祖先」变成了「区间查最浅」。

适用前提也说清楚：树是静态的，改动会废掉整张表；空间吃得下 O(n log n)。动态树上求 LCA，后面讲 LCT 时会专门处理。

欧拉序的表建在长度 2n - 1 的序列上，还能再省一半。下一讲用 dfn 序求 LCA，序列长度只有 n，常数砍半，思路如出一辙。
