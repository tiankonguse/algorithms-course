带权重的重心：牛群聚在哪一站

每个农场养着不同数量的牛，每条路有长短，要把所有牛赶到同一个农场，总路程最小的那个点要按牛数来算，跟「树上最中间的点」常常差着一个身位，混用的代价可以直接量出来。

零、背景

上一页的重心按点数算：挖掉一个点，剩下的块里点数最多的是多少。现在点有了重量，把「点数」换成「牛数」就是这一页的定义。

记 cowSum 是全树的牛总数。以 u 为根，u 的每个方向上的牛数（儿子方向是该儿子子树的牛数，父亲方向是 cowSum 减去 u 子树的牛数）都不超过 cowSum / 2，u 就是带权重心。cow[i] 全取 1 时，它退化成上一页的重心。

这里有个细节：cow[i] 允许为 0。某个农场没牛，它在「分块」时照样占位置，但在「重量」上一克都没有，重心会往牛多的那一侧偏。

一、问题

牛群聚集：n 个农场、n − 1 条路连成一棵树，每个农场有 cow[i] 头牛，每条路长度 w。选一个农场把所有牛聚过去，使「每家的牛数 × 它到汇聚点的距离」之和最小，打印这个最小值。n ≤ 10⁵。

朴素做法是枚举汇聚点 x，对每个 x 跑一遍从 x 出发的遍历算总距离。一趟 O(n)，n 个候选就是 O(n²)，n = 10⁵ 时是 10¹⁰ 次访问。实测 n = 10⁵ 的随机树上，正解跑完只要 6.5 ms，暴力那一路根本跑不完。

二、挪一步，总路程差多少

设当前聚在 u，考虑挪到它的邻居 v，中间那条边长 c。挪动只影响一件事：v 那侧的牛少走 c，其余牛多走 c。记 v 那侧的牛数是 sub[v]，于是

D(v) − D(u) = (cowSum − sub[v]) × c − sub[v] × c = (cowSum − 2 × sub[v]) × c

边权 c 是正数时，这个差值的正负只由 cowSum − 2 × sub[v] 决定：sub[v] 超过半数，挪过去总路程下降；不超过半数，挪过去反而变贵。所以最优点就是「所有方向都不超过半数」的那个点，也就是带权重心。

这条式子还顺手说明了另一件事：牛数恰好等于半数时差值为 0，两侧一样好。这就是最优点不唯一的唯一来源。

三、两趟 dfs

重心定下来之后，剩下的事是从重心出发铺一遍距离，把每家的牛数乘上它的距离加起来。找重心这趟递归的写法和上一页几乎一样，重量换成了牛数：

// 牛的数量才是重量，不是节点数
    // sz[u] 记的是「以 u 为头的子树里一共有多少头牛」
    void findCenter(int u, int f) {
        sz[u] = cow[u];
        for (int e = head[u], v; e != 0; e = nxt[e]) {
            v = to[e];
            if (v != f) {
                findCenter(v, u);
            }
        }
        // 遍历完儿子再做统计，改迭代版时这一刀切得干净
        int maxsub = 0;
        for (int e = head[u], v; e != 0; e = nxt[e]) {
            v = to[e];
            if (v != f) {
                sz[u] += sz[v];
                maxsub = max(maxsub, sz[v]);
            }
        }
        maxsub = max(maxsub, cowSum - sz[u]);
        if (maxsub < best) {
            best = maxsub;
            center = u;
        }
    }

第二趟从重心出发，把距离写进 path，最后累加：

// 从重心出发铺一遍距离，答案 = 每家的牛数 × 到重心的距离
    void setPath(int u, int f) {
        for (int e = head[u], v; e != 0; e = nxt[e]) {
            v = to[e];
            if (v != f) {
                path[v] = path[u] + weight[e];
                setPath(v, u);
            }
        }
    }

    long long compute() {
        for (int i = 1; i <= n; i++) {
            cowSum += cow[i];
        }
        findCenter(1, 0);
        path[center] = 0;
        setPath(center, 0);
        long long ans = 0;
        for (int i = 1; i <= n; i++) {
            ans += (long long)cow[i] * path[i];
        }
        return ans;
    }

注意 ans += (long long)cow[i] * path[i] 这个强转。n = 10⁵、每家 100 头牛、边长 1000 时，极端情况的总距离能到 10¹⁵ 量级，int 只有 21 亿的容量，中间结果一溢出答案就整个错了。实测 n = 10⁵ 的随机数据上答案是 3.3 × 10¹⁰，已经是 int 装不下的量级。

四、权重用错会错多少

最容易犯的错是：求重心时按节点数算，最后又拿牛数去乘距离。树的形状和牛的分布没关系的时候这两者才会重合。

实测四千组随机树（n 取 4 到 40，每家牛数 0 到 100，边长 1 到 30）：按牛数算出的重心与按节点数算出的重心有 15.53% 不是同一个点；其中 620 组（15.5%）按节点数取重心会算出更大的总路程，平均高出 6.224%，最坏的一组高出 204%。把树缩小到 4 到 22 个点再跑三千组，答案不同的比例升到 23.50%，平均高出 11.149%。

每六到七组就有一组直接算错，这个比例不算小。

五、递归换成迭代

n = 10⁵ 的树如果长成一条链，递归深度就是 10⁵。本机栈 8 MB，链上 86000 层还能正常返回，87000 层直接段错误。这道题的数据正好允许长链，递归版交上去是赌评测机的栈够不够大。

改法和上一页那套 dfs 一样：手写栈，第一次来到 u 时记 e == -1，之后再回来就从 nxt[e] 接着走，边走完了才做统计。

// 迭代版：ufe 是手写栈，e == -1 表示第一次来到 u
    void findCenter(int root) {
        stackSize = 0;
        push(root, 0, -1);
        while (stackSize > 0) {
            pop();
            if (e == -1) {
                sz[u] = cow[u];
                e = head[u];
            } else {
                e = nxt[e];
            }
            if (e != 0) {                     // 还有没走完的边
                push(u, f, e);                // 先把自己和当前边压回去
                if (to[e] != f) {
                    push(to[e], u, -1);       // 再压儿子
                }
            } else {                          // 边走完了，做统计
                int maxsub = 0;
                for (int i = head[u], v; i != 0; i = nxt[i]) {
                    v = to[i];
                    if (v != f) {
                        sz[u] += sz[v];
                        maxsub = max(maxsub, sz[v]);
                    }
                }
                maxsub = max(maxsub, cowSum - sz[u]);
                if (maxsub < best) {
                    best = maxsub;
                    center = u;
                }
            }
        }
    }

六、边权允许为 0 的时候

代价差 (cowSum − 2 × sub[v]) × c 里 c 是那条边的长度。c = 0 时，不管两侧牛数差多少，挪过去都不亏也不赚，最优点于是变成一整片。

实测四千组边长允许取 0 的随机树：重心给出的总路程全部等于全局最小值，0 例失败；同时有 2069 组（51.7%）存在不止一个最优点。换成边长全部为正的数据再跑四千组，最优点不唯一只剩 47 组（1.18%），全都是「某棵子树的牛数恰好等于总牛数一半」的情形。

所以这道题求的是最小值本身，重心给不给得出唯一位置无关紧要。

复杂度分析

找重心一趟 dfs 走遍 n − 1 条边，每个点回溯时把它的边扫一遍；铺距离也是一趟。两趟都是 O(n)。

环节时间空间
找带权重心（dfs）O(n)O(n)
从重心铺距离O(n)
累加答案O(n)
合计O(n)

空间按题目上限 n = 10⁵ 算：head 100001 个 int 约 0.4 MB，nxt、to、weight 各 200002 个约 2.4 MB，sz 与 path 各 100001 个 long long 约 1.6 MB，加上 cow 与迭代栈 ufe（100001 × 3 个 int）约 1.6 MB，总共 6 MB 出头。迭代栈这一份是递归版省掉的交换。

实测 n = 10⁵ 的随机树，两趟 dfs 加累加共 6.5 ms。

总结

要点三条。其一，挪一步的代价差是 (cowSum − 2 × sub[v]) × c，边权为正时最优点等价于「每个方向牛数不超过半数」的带权重心。其二，求重心的重量必须是牛数，换成节点数之后四千组随机树里有 15.5% 算出更大的答案，平均高出 6.224%。其三，答案量级能到 10¹⁵，int 装不下，累加时老老实实用 long long。

边权允许为 0 时重心依然给出最小值，只是最优点可能不止一个，这不影响题目要的那个数。

七、最后

这一页的套路比结论更值钱：先用一个「挪一步会怎样」的差值把最优点刻画出来，再回头看这个刻画对应哪个能在 O(n) 里算出来的量。树上许多「选一个点使某某最小」的问题都吃这一套，带权、不带权只是把重量换一换。
