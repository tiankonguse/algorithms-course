双端队列：双链表与环形数组

队列只能尾进头出，栈只在头顶进出。四个口一起打开，就是双端队列：两头都能进，两头都能出。容量固定还要回答得干脆：满了返回 false，空了返回 false。这一节给两种内部实现：双链表版，和一个固定长度的循环数组版。

一、四个口，六个方法

LeetCode 641 的接口一共六个方法：两头各一个插入、各一个删除，外加取队首、取队尾。返回值约定也很直接：插满了返回 false，删不出来返回 false，空队列去取值返回 -1。

这里有个细节要盯住：false 是说「这步没做成」，队列里的东西一个都没动。调用方拿到 false 之后的正确动作是继续别的分支，而不是以为删掉了一个。

六个方法凑齐之后，队列和栈都是它的退化版本：只用 insertLast 加 deleteFront，就是普通队列；只用同一侧插删（比如都用右侧），就是栈。也就是说一份实现可以同时满足两种结构的用法。

反过来不成立。前面用两个栈拼队列，是因为栈只有一头的口。现在给了两头，就没必要再拼一次。

二、双链表版：两个哨兵吃掉边界

改成两端都要操作，链表也得两条方向相反的指针才走得动，所以是双链表。每个节点记住前驱和后继，往哪一头插入都是四行指针改动。

真正的省心处是头尾各放一个哨兵节点。空的时候 head->next == tail、tail->pre == head，真实节点永远夹在两个哨兵中间。这样一来，插入和删除都不需要写「如果原来为空」「如果只剩一个」的分支，边界被哨兵吃掉了。

#include <bits/stdc++.h>
    using namespace std;

    // 双链表版：头尾各放一个哨兵节点，真实元素永远夹在中间
    struct Node {
        int val;
        Node* pre;
        Node* next;
        Node(int v) : val(v), pre(nullptr), next(nullptr) {}
    };

    class MyCircularDeque {
    public:
        Node* head;  // 头哨兵，head->next 是队首
        Node* tail;  // 尾哨兵，tail->pre 是队尾
        int size;
        int limit;

        MyCircularDeque(int k) {
            head = new Node(0);
            tail = new Node(0);
            head->next = tail;
            tail->pre = head;
            size = 0;
            limit = k;
        }

        bool isEmpty() { return size == 0; }

        bool isFull() { return size == limit; }

        bool insertFront(int value) {
            if (isFull()) {
                return false;
            }
            Node* cur = new Node(value);
            cur->pre = head;
            cur->next = head->next;
            head->next->pre = cur;
            head->next = cur;
            size++;
            return true;
        }

        bool insertLast(int value) {
            if (isFull()) {
                return false;
            }
            Node* cur = new Node(value);
            cur->pre = tail->pre;
            cur->next = tail;
            tail->pre->next = cur;
            tail->pre = cur;
            size++;
            return true;
        }

        bool deleteFront() {
            if (isEmpty()) {
                return false;
            }
            Node* cur = head->next;   // 要摘掉的节点
            head->next = cur->next;
            cur->next->pre = head;
            size--;
            return true;
        }

        bool deleteLast() {
            if (isEmpty()) {
                return false;
            }
            Node* cur = tail->pre;
            cur->pre->next = tail;
            tail->pre = cur->pre;
            size--;
            return true;
        }

        int getFront() {
            if (isEmpty()) {
                return -1;
            }
            return head->next->val;
        }

        int getRear() {
            if (isEmpty()) {
                return -1;
            }
            return tail->pre->val;
        }
    };

数一下赋值次数：插入要改四处指向（新节点的两个指针，加上旧邻居的两个），删除只改两处。都是常数次，跟队列里有多少个元素无关。

代价全在 new 上。本机实测：sizeof(Node) 是 24 字节，一个 int 是 4 字节，等于给每个元素付了六倍内存；连续 new 一百万个节点要 15.18 毫秒，而环形数组同样一百万次操作连 4 毫秒都不到。滑窗场景（每轮 insertLast 一个数、deleteFront 一个数）跑一百万轮：

窗口大小std::deque环形数组·三元式环形数组·取模双链表·new
82.29 ms3.58 ms7.54 ms27.10 ms
20002.41 ms1.20 ms4.06 ms17.26 ms

慢的那一份慢在两件事上：每个节点单独向系统要一块内存，以及这些节点在堆上东一块西一块，顺着 next 走一步就换一个缓存行。

三、环形数组版：l 和 r 都是真下标

数组版更快，写法也更绕。绕的地方集中在下标语义上。

单端环形队列里常用 [l, r)：l 指着队首元素，r 指着队尾后面那个空位。这个约定搬到双端队列就麻烦了，从左边插入时没有人会告诉你 r 该往哪挪，因为 r 守的位置跟前半段完全无关。

双端队列改成 [l, r]：l 指队首元素，r 指队尾元素，两个都是有用的下标。getFront 取 data[l]，getRear 取 data[r]，左右两端对称，四个操作各管自己那一端的指针。

空和满这里用 size 判，不拿 l 和 r 的关系做文章。原因前面讲环形队列时提过：只靠两个指针，空的时候和满的时候会撞出同一个样子，分不开。

#include <bits/stdc++.h>
    using namespace std;

    // 环形数组版：l 指向队首元素，r 指向队尾元素，两个都是真实下标
    class MyCircularDeque {
    public:
        vector<int> data;
        int l, r, size, limit;

        MyCircularDeque(int k) {
            data.assign(k, 0);
            l = r = size = 0;
            limit = k;
        }

        bool isEmpty() { return size == 0; }

        bool isFull() { return size == limit; }

        bool insertFront(int value) {
            if (isFull()) {
                return false;
            }
            if (isEmpty()) {
                // 空队列：两端在同一个格子，l 和 r 都要回到 0
                l = r = 0;
                data[l] = value;
            } else {
                l = l == 0 ? limit - 1 : l - 1;
                data[l] = value;
            }
            size++;
            return true;
        }

        bool insertLast(int value) {
            if (isFull()) {
                return false;
            }
            if (isEmpty()) {
                l = r = 0;
                data[r] = value;
            } else {
                r = r == limit - 1 ? 0 : r + 1;
                data[r] = value;
            }
            size++;
            return true;
        }

        bool deleteFront() {
            if (isEmpty()) {
                return false;
            }
            l = l == limit - 1 ? 0 : l + 1;
            size--;
            return true;
        }

        bool deleteLast() {
            if (isEmpty()) {
                return false;
            }
            r = r == 0 ? limit - 1 : r - 1;
            size--;
            return true;
        }

        int getFront() {
            if (isEmpty()) {
                return -1;
            }
            return data[l];
        }

        int getRear() {
            if (isEmpty()) {
                return -1;
            }
            return data[r];
        }
    };

删除那两行值得多看一眼：deleteFront 只把 l 往前挪一格，deleteLast 只把 r 往后退一格，格子里的旧值原地留着。格子里的旧值原地留着是有意为之：size 已经说了哪些格子算有效，写回一句 0 只是浪费时间。

四、绕回，以及「空队列插入」那一刀

指针走到数组边界就绕回另一头。insertFront 时 l 从 0 绕到 limit - 1，insertLast 时 r 从 limit - 1 绕到 0。

绕回有两种写法。三元式是 l = l == 0 ? limit - 1 : l - 1，取模版是 l = (l + limit - 1) % limit。前者快一倍（窗口 8 时 3.58 毫秒对 7.54 毫秒），因为 % 是一次整数除法。

取模版有个坑不能踩：千万别写 (l - 1) % limit。C++ 里负数的余数是负数，l == 0 时算出 -1，下一步就是往 data[-1] 里写。实测这种写法在一半以上的随机序列里会往数组外写。

还有一种写法可以连「插入时是不是空队列」的判断都省掉。开头让 l 和 r 处于「空」的位置（比如 l = 0、r = limit - 1，等价于 r = -1），之后四个操作各自 +1 或 -1 再取模。空的时候 l 永远停在 r 后面一格，这个关系不会被任何操作破坏。

#include <bits/stdc++.h>
    using namespace std;

    // 环形数组版（不变式写法）：空的时候 l = r + 1，四个操作各写一行
    class MyCircularDeque {
    public:
        vector<int> data;
        int l, r, size, limit;

        MyCircularDeque(int k) {
            data.assign(k, 0);
            l = 0;
            r = k - 1;      // 等价于 -1，空
            size = 0;
            limit = k;
        }

        bool isEmpty() { return size == 0; }

        bool isFull() { return size == limit; }

        bool insertFront(int value) {
            if (isFull()) {
                return false;
            }
            l = (l + limit - 1) % limit;   // 先退一格再写
            data[l] = value;
            size++;
            return true;
        }

        bool insertLast(int value) {
            if (isFull()) {
                return false;
            }
            r = (r + 1) % limit;           // 先进一格再写
            data[r] = value;
            size++;
            return true;
        }

        bool deleteFront() {
            if (isEmpty()) {
                return false;
            }
            l = (l + 1) % limit;           // 逻辑删除，格子里的旧值留着
            size--;
            return true;
        }

        bool deleteLast() {
            if (isEmpty()) {
                return false;
            }
            r = (r + limit - 1) % limit;
            size--;
            return true;
        }

        int getFront() {
            if (isEmpty()) {
                return -1;
            }
            return data[l];
        }

        int getRear() {
            if (isEmpty()) {
                return -1;
            }
            return data[r];
        }
    };

两种写法都对。选哪个看习惯：三元式快一点、行数多一点；取模版四行写完，代价是每次操作一次除法。笔试现场写哪个都行，别在一份代码里混着用。

五、六种笔误，量一下抓得到吗

下面是六个常见的写法错误。每个都做成一份代码，跟正确的实现对着跑：随机生成操作序列，六个操作等概率，容量 k 从 {1, 2, 3, 5, 8} 里取，每组序列最多 200 步，一旦出现返回值不一致就停。每种错误跑两万组。

编号错在哪抓取率平均第几步现形
①insertFront 时空队列没把 l、r 重置到 025.11%10.39
②deleteFront 忘了 size--100%14.89
③getRear 取 data[(r - 1 + limit) % limit]80%12.30
④insertLast 先写值再挪 r100%15.13
⑤insertFront 写成 (l - 1) % limit80%（全是数组越界）16.80
⑥双链表 insertFront 只接了一半指针99.89%16.64

① 号单独拿出来看更说明问题：按容量拆开，k = 1 时抓取率是 0%，k 取 2 到 200 都在 31% 上下。容量是 1 的双端队列里，插入和删除排着队轮流来，那个被写错的分支永远进不去。

这六种错误的暴露方式不一样。② 和 ④ 一跑就炸，因为 size 和 r 的状态立刻连锁到后面每一步。③ 和 ⑤ 只有八成，前者是只有 getRear 被问到时才暴露，后者要恰好在队非空且 l == 0 的时候从左端插入。① 号剩下那七成多的序列，从头到尾就没在队列为空的时候从左端插过。

六、静态数组版的双链表

双链表慢在 new，那就把节点换成预先开好的数组下标。val[]、pre[]、nxt[] 三个数组凑成一个节点池，head 和 tail 是两个空出来的下标，当哨兵用。

#include <bits/stdc++.h>
    using namespace std;

    // 静态数组版双链表：节点下标代替指针，head、tail 是两个空出来的哨兵下标
    const int MAXN = 2000005;   // 上限要看「总共插入过多少次」，不是「同时在队列里多少个」

    int val[MAXN], pre[MAXN], nxt[MAXN];
    int head, tail, tot, size, limit;

    void build(int k) {
        limit = k;
        size = 0;
        tot = 2;
        head = 1;
        tail = 2;
        nxt[head] = tail;
        pre[tail] = head;
    }

    void addNode(int x, int y, int cur, int v) {   // 把新节点 cur 插到 x 和 y 之间
        val[cur] = v;
        nxt[x] = cur;
        pre[cur] = x;
        nxt[cur] = y;
        pre[y] = cur;
    }

    bool insertFront(int v) {
        if (size == limit) {
            return false;
        }
        addNode(head, nxt[head], ++tot, v);
        size++;
        return true;
    }

    bool insertLast(int v) {
        if (size == limit) {
            return false;
        }
        addNode(pre[tail], tail, ++tot, v);
        size++;
        return true;
    }

    void removeNode(int cur) {
        nxt[pre[cur]] = nxt[cur];
        pre[nxt[cur]] = pre[cur];
    }

    bool deleteFront() {
        if (size == 0) {
            return false;
        }
        removeNode(nxt[head]);
        size--;
        return true;
    }

    bool deleteLast() {
        if (size == 0) {
            return false;
        }
        removeNode(pre[tail]);
        size--;
        return true;
    }

    int getFront() { return size == 0 ? -1 : val[nxt[head]]; }

    int getRear() { return size == 0 ? -1 : val[pre[tail]]; }

这里有个坑跟数组版队列一样：tot 只增不减，删掉的节点不会回到池子里。所以数组上限要看「总共插入过多少次」，跟「同时在队列里多少个」无关。MAXN 按后者开，跑到一半就越界了。

真想复用节点也很简单：删的时候把下标压进一个空闲栈，下次自增之前先看栈里有没有存货。

那什么时候用链表版？队列的个数会变、或者要同时维护好几条队列时，一个数组就框不住了，链表版的 new 换来的是「要多大给多大」。个数确定且追求常数，数组版赢。

七、复杂度分析

四种实现的每步操作都是常数次：

实现前端插删后端插删取首尾空间
双链表·newO(1)O(1)O(1)O(k) 个节点，每个 24 字节
静态数组双链表O(1)O(1)O(1)O(插入总次数) 个槽位
环形数组·三元式O(1)O(1)O(1)O(k)，一次性分配
环形数组·取模O(1)O(1)O(1)O(k)，每多一次 %

额外空间都是 O(容量) 这一档：容量写了多少就得准备多少个槽位，元素个数超不过它。链表版多出来的部分只是每个节点 24 字节对 4 字节的常数差距，以及不肯把删掉的节点还给系统的 new 版。

八、总结

双端队列本身只有一句话：两头各配一对插删，加上 size 判空满。剩下的篇幅都在互换实现带来的细节。

要注意的地方：

第一，r 的语义。单端环形队列的 r 是开区间，双端队列的 r 是队尾元素本身。混用这两种约定，getRear 第一次就答错。

第二，负数取模。(l - 1) % limit 在 l == 0 时给出 -1，往数组外写。要加 limit 再取模，或者直接用三元式。

第三，双链表两头哨兵干的活是实打实的。没有它，插入和删除都得补一段「如果为空」的分支；有了它，边界永远存在。

第四，越界的源头常常不在最热闹的那几个操作里。size 少减一次，报错的位置会离出错的那一步很远。

往后做题时，双端队列更常见的出场方式是带着一条单调性约束出现的（滑动窗口的最值就是最典型的那一类）：从队尾把破坏单调性的元素一路弹掉，队首就是当前窗口的答案。那时候它就是主结构，本节这份实现可以直接搬过去用。
