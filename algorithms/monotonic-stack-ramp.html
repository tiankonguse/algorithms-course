最大宽度坡与去除重复字母：单调栈存候选

上一页的单调栈回答「最近的更小在哪」。这一页的两题不问位置，问的是「哪些对象还有资格当答案」。栈里存候选，按规则把没资格的淘汰掉，剩下的在合适的时机结算。

零、背景

单调栈的总纲只有四条：栈里的对象按规定的单调性组织；新对象进来时，从栈顶开始淘汰对后续求解没帮助的对象；每个对象从栈顶弹出的那一刻结算它参与的答案，之后不再参与；先分析出单调性，再去实现。

上一页的「两侧最近更小」里，单调性来自问题本身：值比它小的才有资格当边界。这一页的两个题，淘汰规则不那么直白。坡问题要淘汰「永远当不了左端点」的下标，去重字母要淘汰「放着以后还能放」的字符。两题都不边扫边出全部答案，先把候选留好。

一、最大宽度坡

给定数组 A，坡是 (i, j)，要求 i < j 且 A[i] <= A[j]，宽度是 j - i。找最大宽度，不存在返回 0。数据规模 5 × 10⁴。

直接做是枚举所有 (i, j) 对，O(n²)。n = 5 × 10⁴ 时有 1.25 × 10⁹ 对，跑不完。问题在于大量 (i, j) 一眼就知道不可能最优，枚举它们纯属浪费。

先看左端点。如果 i < j 且 A[i] >= A[j]，那 i 永远当不了最优左端点：j 更靠右，值还更小，任何能满足 A[j] <= A[x] 的 x，A[i] 一定也满足，而且 j 到 x 的宽度更大。所以左端点的候选，从左往右看必须是严格递减的。

这个观察直接给出构建方法：从左往右扫一遍，只有比栈顶值更小的下标才入栈。这样栈里存的就是「严格递减前缀」的下标，别的都淘汰。拿 [6, 0, 8, 2, 1, 5] 走一遍：6 入栈，0 比 6 小入栈，8、2、1、5 都比栈顶 0 大，全部没资格。

候选有了，结算从右往左扫 j。只要栈顶那个下标的 A 值 <= A[j]，就弹出并更新 ans = j - 栈顶。为什么从右往左：j 越大宽度越大，每个候选第一次被弹出时，遇到的 j 是它能达到的最大值；之后再弹它，宽度只会更小，不用管。

拿 [6, 0, 8, 2, 1, 5] 结算：j = 5 时 A[5] = 5，栈顶 1 号的 0 <= 5，弹出，ans = 5 - 1 = 4。后面 j = 2 时弹出 0 号，ans = max(4, 2 - 0) = 4。答案 4，就是 (1, 5) 这一对。

演示 1 · 最大宽度坡逐帧：先筛候选，再从右往左结算

// 最大宽度坡：找 i < j 且 arr[i] <= arr[j]，返回最大 j - i
    int maxWidthRamp(vector<int>& arr) {
        int n = arr.size();
        int stk[MAXN];                    // 存「可能当左端点」的下标，值严格递减
        int r = 1;                        // 0 号先进栈
        stk[0] = 0;
        for (int i = 1; i < n; i++) {
            if (arr[stk[r - 1]] > arr[i]) {
                stk[r++] = i;             // 更小才入栈：前面已有更小更靠左的，它没资格
            }
        }
        int ans = 0;
        for (int j = n - 1; j >= 0; j--) {
            while (r > 0 && arr[stk[r - 1]] <= arr[j]) {
                ans = max(ans, j - stk[--r]);   // 弹出即结算，j 从右往左保证第一次弹出时最宽
            }
        }
        return ans;
    }

复杂度 O(n)：构建一趟、结算一趟，每个下标入栈一次、出栈最多一次。空间 O(n) 是栈。

实测：n = 5 × 10⁴ 随机数组一趟 0.06ms，暴力枚举 O(n²) 在 n = 2000 时要 1.69ms，外推到 5 × 10⁴ 约 1 秒，差约一万七千倍。递减数组（没有坡）0.19ms，递增数组（答案就是 n - 1）0.06ms。

二、去除重复字母

给一个字符串，去掉重复字母，让每个字母只出现一次，保持原有相对顺序，要求结果的字典序最小。比如 "bcabc" 变成 "abc"，"cbacdcbc" 变成 "acdb"。

「字典序最小」的意思是：从左往右比，能放更小的字符就先放更小的。直接贪心每次挑当前能放的最小的字符，会破坏相对顺序，而且「后面还有没有」没查清楚。

单调栈的思路是把结果序列当栈维护。扫每个字符 cur：如果 cur 已经在栈里，跳过。否则看栈顶：栈顶字符比 cur 大，而且这个栈顶字符在后面还会再出现，那就把栈顶弹出。弹出不亏，因为后面还能再放它，而现在放 cur 能让字典序更小。一直弹到栈顶比 cur 小，或者栈顶字符后面没有了，才把 cur 放进去。

两个数组伺候：cnts 记录每个字符在当前位置右边还剩多少次（弹栈顶时判断「后面还有没有」），enter 记录每个字符是否已在栈里（避免重复入栈）。

拿 "bcabc" 走一遍：b 入栈；c 比 b 大，入栈；轮到 a，栈顶 c 比 a 大且 c 后面还有，弹出，再看 b 比 a 大且后面还有，弹出，a 入栈；b 再入栈；c 入栈。栈里就是 "abc"。关键在第二步：c、b 后面都还有，先腾位置给更小的 a，等 a 放好再把它们放回来，相对顺序也没破坏。

演示 2 · 去除重复字母逐帧：栈顶更大且后面还有就弹出

// 去除重复字母：每个字母只留一次，保持相对顺序，字典序最小
    string removeDuplicateLetters(string str) {
        int cnts[26] = {0};        // 每种字符在当前位置右边还剩下多少次
        bool enter[26] = {false};  // 是否已经在栈里
        char stk[26];
        int r = 0;
        for (char c : str) cnts[c - 'a']++;
        for (char cur : str) {
            if (!enter[cur - 'a']) {
                while (r > 0 && stk[r - 1] > cur && cnts[stk[r - 1] - 'a'] > 0) {
                    enter[stk[r - 1] - 'a'] = false;  // 栈顶后面还会出现，先弹出，以后还能放
                    r--;
                }
                stk[r++] = cur;
                enter[cur - 'a'] = true;
            }
            cnts[cur - 'a']--;
        }
        return string(stk, r);
    }

复杂度 O(n)：每个字符入栈一次、出栈最多一次，扫描一遍。空间 O(1)：栈和计数都只有 26 个槽位，不随输入长度涨。

实测：n = 10⁶ 的随机小写字母串 2.52ms。字母表只有 26 个，答案长度最多 26，栈深度有天然上限，这也是空间 O(1) 的底气。

三、复杂度分析

两题都是每个对象入栈一次、出栈最多一次，总操作 O(n)。区别在结算时机：坡问题留到第二趟从右往左结算，去重字母在扫描中边走边弹。

四、总结

单调栈存候选的两个套路：坡问题先证明「更小更靠右的能顶掉更靠左的」，筛出严格递减候选，再从右往左结算，每个候选第一次弹出时拿最大宽度；去重字母把结果当栈，栈顶更大且后面还能再放就弹出，先放更小的字符字典序才最小。

坡问题的「从右往左结算」和去重字母的「弹出不亏」都是先想清楚淘汰规则再写代码。下一页的两个题把扫描方向反过来：大鱼吃小鱼从右往左压栈记轮数，全 1 子矩形把矩阵逐行压成一维再结算。
