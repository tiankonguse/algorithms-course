贪心：堆里挑当前最赚的

一个班拿到天才之后通过率会变，下一份天才再给它就不一定划算了；工人也一样，换一个人进来，成本里的两个因子都会动。两道题都在一遍扫描里反复问同一句话：当前最值得动手的是谁。

零、两道题

第一道给 classes[i] = [pass, total]，每个班总人数 total，其中 pass 人通过。另外还有 extraStudents 个必定通过考试的天才，每人要安排进一个班，让所有班级的平均通过率最大。

第二道给 quality 和 wage 两个数组，第 i 个工人的工作质量是 quality[i]，最低期望工资是 wage[i]。要雇 k 个人，工资按质量比例发放，每人都不能低于自己的期望。求最小的总支出。

两题的规模都在 105 量级，穷举一个都过不去。形状却很像：一边扫描，一边从候选里挑出当前最优的那一个改掉它，改完再放回去。这种「反复取最值、改完再塞回去」的活儿，标准工具是一个堆。

一、最大平均通过率：比的是「再来一个人能涨多少」

把天才给一个班，这个班的通过率从 a / b 变成 (a + 1) / (b + 1)，两者的差就是这次安排带来的提升：

gain(a, b) = (a + 1) / (b + 1) - a / b

答案是所有班通过率之和除以班数，班数是固定的，所以只要让提升的总和最大。每次给谁都看 gain 最大的那个班，先把最大的提升拿到手。

这个贪心站得住，靠的是 gain 的两个单调性质。第一，同一个班连续拿天才时，每多给一个人，gain 只会更小，因为分母在变大、分子每轮只加一。第二，同一轮里比较不同班时，当前通过率越低的班，同样加一个人的提升越大。

于是做法就定下来了：先一次性把 n 个班的 (gain, a, b) 压进大根堆，堆顶就是当前最值得给的班。每给一个人，把它弹出来、人数都加一、重算 gain、再压回去。分配给 m 个人之后，把堆里的通过率加起来除以 n。

堆的键必须是 gain。换成「当前通过率最大的班先给」看起来也像那么回事，实际上会把天才堆在本来就好的班上：通过率 0.9 的班再涨也很有限，通过率 0.1 的班给一个人能涨一大截。这个错法在 20000 组随机用例里抓出 73.65% 到 78.20%。

二、雇佣 K 名工人：排序定基准，堆留最小的 k 个质量

第二道题的难点在「按比例付钱」这件事上。组里的实际比例记作 p，第 i 个工人拿到的钱是 p × quality[i]，同时要求 p × quality[i] ≥ wage[i]，也就是 p ≥ wage[i] / quality[i]。所有人的 ratio[i] = wage[i] / quality[i] 都要满足，所以 p 至少是组内最大的那个 ratio。

p 取大只会多花钱，所以一组人的最优 p 就是组内最大的 ratio。把「谁是组里 ratio 最大的那个」当成枚举对象：按 ratio 升序排好，依次让第 i 个人担任这个角色，那么组里其余的人都得排在它前面。此时成本是 ratio[i] × 组内 quality 之和，ratio 已经定死，只能让 quality 之和尽量小。

于是每一步要回答的问题是：前 i 个人里，quality 最小的 k 个之和是多少。这正好是一个大根堆的活。堆里只留 quality 最小的 k 个，堆顶是其中最大的那个；新人进来时跟堆顶比，比它小就顶掉它，同时维护 quality 之和。堆里凑满 k 个之后，每一步都能算出一个候选成本，取最小值就是答案。

两个改法各自能抓住一批用例。把排序改成 ratio 降序，基准就跑到了组的另一头，抓取率 73.31% 到 92.58%；堆满了还继续往里塞、忘记弹掉堆顶，quality 之和会越滚越大，抓取率 15.82% 到 23.87%。后一个错法在小值域下更明显：值域一大，多算进去的那部分被 ratio 放大之后反而可能撞出更大的成本，两边偶尔也会撞上同一个答案。

// 最大平均通过率：每个班再来一个天才的提升是 (a + 1) / (b + 1) - a / b
    // 提升最大的那个班最值得给，而且给完之后提升只会更小
    double maxAverageRatio(vector<vector<int>> classes, int m) {
        int n = classes.size();
        // 大根堆，堆顶是当前提升最多的班：{提升量, 通过人数, 总人数}
        priority_queue<array<double, 3>> heap;
        for (vector<int> c : classes) {
            double a = c[0];
            double b = c[1];
            heap.push({(a + 1) / (b + 1) - a / b, a, b});
        }
        while (m-- > 0) {
            array<double, 3> cur = heap.top();
            heap.pop();
            double a = cur[1] + 1;
            double b = cur[2] + 1;
            heap.push({(a + 1) / (b + 1) - a / b, a, b});
        }
        double sum = 0;
        while (!heap.empty()) {
            array<double, 3> cur = heap.top();
            heap.pop();
            sum += cur[1] / cur[2];
        }
        return sum / n;
    }
// 雇佣 K 名工人的最低成本
    // 按 薪水 / 质量 的比例升序排，依次让每个工人当组里比例最大的那个
    struct Employee {
        double ratio;
        int quality;
    };
    double mincostToHireWorkers(vector<int> quality, vector<int> wage, int k) {
        int n = quality.size();
        vector<Employee> employees(n);
        for (int i = 0; i < n; i++) {
            employees[i] = {(double) wage[i] / quality[i], quality[i]};
        }
        sort(employees.begin(), employees.end(), [](const Employee &x, const Employee &y) {
            return x.ratio < y.ratio;
        });
        // 大根堆，只留质量最小的 k 个人
        priority_queue<int> heap;
        int qualitySum = 0;
        double ans = 1e18;
        for (int i = 0; i < n; i++) {
            int cur = employees[i].quality;
            if ((int) heap.size() < k) {
                qualitySum += cur;
                heap.push(cur);
                if ((int) heap.size() == k) {
                    ans = min(ans, qualitySum * employees[i].ratio);
                }
            } else if (heap.top() > cur) {
                // 新来的比堆里最大的那个还小，换掉他
                qualitySum += cur - heap.top();
                heap.pop();
                heap.push(cur);
                ans = min(ans, qualitySum * employees[i].ratio);
            }
        }
        return ans;
    }

两道题的实测开销都花在堆和排序上：最大平均通过率在 n = m = 105 时跑完 22.99ms，雇佣工人在 n = 104、k = 103 时 0.54ms。

三、两个演示

天才一个个分配

每次算出所有班的提升量，把天才给提升最大的那个班。

边扫描边换人

按 ratio 升序看每个工人，堆里留下 quality 最小的 k 个，每次堆满就算了成本。

四、对数器怎么抓错

第一道题的暴力直接枚举分配：m 个天才，每人有 n 个去处，把 nm 种分法全试一遍，取平均通过率最大的那个。n 取 4、m 取 5 时一共 1024 种，随便跑。

第二道题枚举 k 元子集：n 取 9，每个子集算出组内最大 ratio 和质量之和，成本就是两者相乘。

第一、三、五行每行两万组，n 取 2 到 5（第二道题 n 取 2 到 9、k 随机在 1 到 n 之间）。带浮点的答案比较用 1e-9 的容差。

两道题的暴力都跟实现用了完全不同的路子，一个枚举分配、一个枚举子集，所以它们能独立地把贪心判下来。用对数器验证贪心，参考实现越不像正解越可靠。

复杂度分析

题目关键操作时间空间
最大平均通过率n 次入堆 + m 次弹出压回O((n + m) log n)，n 是班数、m 是天才数O(n)

雇佣题里堆的规模被 k 卡住，如果 k 很小，堆那部分的常数比排序还小。n = m = 105 时第一道 22.99ms，n = 104、k = 103 时第二道 0.54ms。

总结

两道题都是「扫描 + 堆」：候选放进堆里，每轮取最值、改完再放回去。区别在于堆里的键是什么。

最大平均通过率的键是边际提升 (a + 1) / (b + 1) - a / b，用当前通过率当键会把天才堆错地方。雇佣工人先按 wage / quality 排序定下基准比例，再用大根堆盯着 quality 最小的 k 个，忘记弹堆顶会让质量之和虚高。

接下来换一类形状：顺序得在做背包之前就定下来，堆在这里插不上手。
