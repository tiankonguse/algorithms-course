换根 dp：留一个次大值，改造成重心与送人回家

前面几页换根时递过去的都是一个数，最多是一整条桶。这一页的两道题要多留一个值：换根时能用的「最大的那一块」，如果恰好落在正在递的这一支里面，就得退而用次大的。留次大不难，难的是记下最大的那一块来自哪个儿子。

零、背景

换根的转移式一直是「父亲的答案，减去这一支的贡献，再补上新的贡献」。当补的那一项是「某一侧的最大值」时，会出现一个新情况：父亲的最大值有可能就藏在正在递的这一支里，那样它根本不该被算进去。

处理办法只有一种，同时维护最大值与次大值，并且次大值必须来自另一个儿子。下面两道题都要这么做，一道判重心，一道算路程。

一、问题一：哪些点可以改造成重心

CF708C Centroids。n 个点的树，一个点是重心当且仅当砍掉它之后，剩下每块连通块的大小都不超过 n/2。允许做一次操作：删一条边、再加一条边，图仍然是一棵树。对每个点回答，做完这次操作之后它能不能变成重心。n 到 4 × 10⁵。

那个操作换个说法更直观：从树上切下一块大小不超过 n/2 的连通块，再把它挂到某个点下面。挂在 u 下面，目的就是让 u 砍掉之后最大的那一块变小。

二、只有一块可能超标

砍掉 u 之后剩下的块，是「每个儿子那一侧」加上「u 的上面那一侧」，它们的大小加起来是 n − 1。两块都超过 n/2 的话总和就超过 n − 1，不可能。所以超标的块最多只有一块。

这一块有两种可能：一是某个儿子的整棵子树，取最大的那个儿子就行；二是「上面」那一侧，大小是 n − sz[u]。两个候选，取超过 n/2 的那个。

能被救回来的条件也就清楚了：从超标的那块里再切下一块 P，要求 |P| ≤ n/2，并且切完之后剩下的也 ≤ n/2。|P| 越大越容易满足，所以问题变成「超标块里能整块切下来、且大小不超过 n/2 的最大一块是多少」。

图里那棵树一共 9 个点，n/2 = 4。8 号是叶子，砍掉它之后剩下 8 个点连成一整块，远超过 4。切下 {2,5,6,7} 这 4 个点挂到 8 下面之后再砍 8，剩两块各 4 个点，都不超标。

三、往里再切一层

先固定 1 号做根，第一趟自底向上。对每个儿子 v，能在 v 那一侧整块切下来、且大小不超过 n/2 的最大块是这样算的：v 整棵子树如果本来就不超过 n/2，那就是 sz[v]；否则要往 v 的里面再切一层，也就是 inner1[v]。

int innerSize = sz[v] <= n / 2 ? sz[v] : inner1[v];   // 太大就往里再切一层

u 的 inner1[u] 是所有儿子里 innerSize 的最大值，inner2[u] 是第二大，并且规定它必须来自另一个儿子；choose[u] 记下最大的那个来自谁。维护方式和「边扫边求最大次大」完全一样，只是多记一个来源。

注意 inner1[u] 只覆盖「儿子那一侧」。上面那一侧要单独判，它的大小是 n − sz[u]，能整块切下来的最大块记为 outer[u]，由第二趟补出来。

四、往子树外找，要绕开自己这一支

第二趟自顶向下。从 u 递到儿子 v 时，v 的「上面」是 u 这一整侧，它由两部分组成：u 自己上面那一侧，以及 u 除 v 以外的其他儿子那一侧。能整块切下来的块只可能来自这两处。

分三种情况写：

  • 如果 n − sz[v] ≤ n/2，那 u 这一整侧就能直接整块切下来，outer[v] = n − sz[v]。
  • 否则要往里找，先拿 u 上面那一侧的 outer[u]。
  • 再拿 u 其他儿子里的最大可切块。choose[u] ≠ v 时它就是 inner1[u]；choose[u] 正好是 v 时，最大的那块就在 v 里面，不能用，只能退到次大的 inner2[u]。

最后一步就是这一页标题说的「留一个次大值」。少了 inner2，遇到 choose[u] == v 就只能把 v 自己的子树当成外面能切的块，答案会虚高。

两幅小图是同一棵树。8 号借到了 {2,5,6,7} 整块，outer 到了 4，8 − 4 = 4 刚好压线；6 号每一步都只能拿次大，outer 停在 2，8 − 2 = 6 还是超过 4。同一个 outer 递推，走法不同结果就差了 2。

五、判定

四个量都算完之后，逐点判一次。先看儿子那一侧超不超标，超标就从里面切走 inner1[maxsub[u]]；否则看上面那一侧，超标就切走 outer[u]；都不超标说明它本来就是重心。

// u 能不能变成重心：唯一可能超标的就是「最大的那一块」
    // 超标了就从里面切一刀，切下来的那一块要 <= n/2，且剩下的也要 <= n/2
    bool check(int u){
        if (sz[maxsub[u]] > n / 2){
            return sz[maxsub[u]] - inner1[maxsub[u]] <= n / 2;
        }
        if (n - sz[u] > n / 2){
            return n - sz[u] - outer[u] <= n / 2;
        }
        return true;
    }

完整的第一趟与第二趟如下。maxsub[u] 是「最大的那个儿子」，只在 sz 更大的时候更新，不是「最大的那一块」。

// sz[u]      : 以 1 为根时 u 的子树大小
    // maxsub[u]  : u 最大的那个儿子是谁
    // inner1[u]  : u 的儿子里，能整块切下来且大小 <= n/2 的最大一块
    // inner2[u]  : 同上第二大，且必须来自另一个儿子
    // choose[u]  : inner1[u] 来自哪个儿子
    // outer[u]   : u 子树之外，能整块切下来且大小 <= n/2 的最大一块
    void dfs1(int u, int f){
        sz[u] = 1;
        for (int e = head[u], v; e != 0; e = nxt[e]){
            v = to[e];
            if (v != f){
                dfs1(v, u);
                sz[u] += sz[v];
                if (sz[maxsub[u]] < sz[v]) maxsub[u] = v;
                int innerSize = sz[v] <= n / 2 ? sz[v] : inner1[v];   // 太大就往里再切一层
                if (inner1[u] < innerSize){
                    choose[u] = v; inner2[u] = inner1[u]; inner1[u] = innerSize;
                } else if (inner2[u] < innerSize){
                    inner2[u] = innerSize;
                }
            }
        }
    }

    void dfs2(int u, int f){
        for (int e = head[u], v; e != 0; e = nxt[e]){
            v = to[e];
            if (v != f){
                if (n - sz[v] <= n / 2) outer[v] = n - sz[v];         // u 那一整侧本来就够小
                else if (choose[u] != v) outer[v] = max(outer[u], inner1[u]);
                else outer[v] = max(outer[u], inner2[u]);             // 最长那块在 v 里，只能用次长
                dfs2(v, u);
            }
        }
    }

六、问题二：聚会之后送每个人回家

洛谷 P6419 Kamp。n 个点的带权树，有 k 个人分别住在 k 个点上。所有人先各自去聚会点，聚会结束后一起上车，车把每个人送回家；送完最后一位乘客，车不用回到聚会点。对每个点 i 求，聚会点定在 i 时车要跑多远。n 到 2 × 10⁵，k 不超过 n，边权到 10⁹ 量级。

换成人话就是：从 u 出发，把 k 位乘客分别送到各自的家，最后停在任意位置，求最短总路程。

七、代价 = 两倍边权减去最长链

固定出发点 u，要走的路是「u 到每位乘客的路径的并」，这个并是一棵子树。里面的每条边都要走两遍，进去再出来；只有最后一段例外，送完最后一位乘客就不用回来了。

于是代价是两倍的边权和，减掉最后那一段的路程。要让减掉的尽量多，最后送的应该是离 u 最远的那位乘客。

这里有个细节值得单独说：被减掉的是「u 到最远乘客的距离」，不是「最远的两个乘客之间的距离」。最后一段必须从 u 起步，只能是一条以 u 为端点的链。

八、两套量的换根式

和前面重心的题一样分两趟，只是每一点上要维护两个数：一个是代价，一个是到最远乘客的距离。

第一趟以 1 为根自底向上。people[u] 是 u 子树里的乘客数；incost[u] 是从 u 出发送完子树内所有乘客再回到 u 的代价，只对 people[v] > 0 的儿子累加 incost[v] + 2w；inner1[u] 是从 u 往下到最远乘客的距离，inner2[u] 是来自另一个儿子的次长，choose[u] 记最长链来自哪个儿子。

第二趟自顶向下补 outcost[u] 与 outer[u]，含义分别是「送完子树外所有乘客再回到 u 的代价」和「从 u 往子树外走，到最远乘客的距离」。从 u 递到 v 时，只在 k − people[v] > 0，也就是 v 外面确实还有人时才需要算。

outcost[v] 分两种写法。v 子树里没人时，v 外面的人就是「u 外面的」加「u 子树里的全部」，来回各走一次边 (u, v)，于是 outcost[v] = outcost[u] + incost[u] + 2w。v 子树里有人时，incost[u] 里已经含了 incost[v] + 2w 那一份，扣掉它之后来回那两步 w 正好抵消，于是 outcost[v] = outcost[u] + incost[u] − incost[v]。

outer[v] 与前面重心的 outer 是同一个形状：最远的乘客要么在 u 的上面（outer[u] + w），要么在 u 的其他儿子里（choose[u] ≠ v 时用 inner1[u]，否则用 inner2[u]，再加 w）。最后把两趟的结果合起来。

// people[u] : 以 1 为根时 u 的子树里有几位乘客
    // incost[u] : 从 u 出发送完子树内所有乘客再回到 u 的代价（每条通往乘客的边走两次）
    // inner1[u] : 从 u 往下送乘客的最长链，inner2[u] 是来自另一个儿子的次长链
    // choose[u] : 最长链来自哪个儿子
    // outcost[u]: 从 u 出发送完子树外所有乘客再回到 u 的代价
    // outer[u]  : 从 u 往子树外送乘客的最长链
    void dfs1(int u, int f){
        for (int e = head[u], v, w; e != 0; e = nxt[e]){
            v = to[e]; w = weight[e];
            if (v != f){
                dfs1(v, u);
                people[u] += people[v];
                if (people[v] > 0){
                    incost[u] += incost[v] + 2LL * w;
                    if (inner1[u] < inner1[v] + w){
                        choose[u] = v; inner2[u] = inner1[u]; inner1[u] = inner1[v] + w;
                    } else if (inner2[u] < inner1[v] + w){
                        inner2[u] = inner1[v] + w;
                    }
                }
            }
        }
    }

    void dfs2(int u, int f){
        for (int e = head[u], v, w; e != 0; e = nxt[e]){
            v = to[e]; w = weight[e];
            if (v != f){
                if (k - people[v] > 0){                              // v 外面确实还有人
                    if (people[v] == 0) outcost[v] = outcost[u] + incost[u] + 2LL * w;
                    else outcost[v] = outcost[u] + incost[u] - incost[v];
                    if (v != choose[u]) outer[v] = max(outer[u], inner1[u]) + w;
                    else outer[v] = max(outer[u], inner2[u]) + w;
                }
                dfs2(v, u);
            }
        }
    }

    // 最后一段路不用回来，减掉最长的那一条
    for (int i = 1; i <= n; i++){
        cout << incost[i] + outcost[i] - max(inner1[i], outer[i]) << '\n';
    }

九、换根台

下面逐个点走第二趟，面板里列出每一位是怎么递出来的，用到次大值的那一步单独标出来。前三个预设是重心的题，后三个是送人回家。

换根台：点「下一步」看 outer 怎么往外递

圈里的数字是点号，橙圈是当前做根的点或车上的乘客，蓝圈是正在递过去的点，绿边是正在走的那条边。重心题里点下面一行是 sz，第二行是 outer；送人回家那题里是 incost 与 outcost，末帧换成答案。

这张图解释了对拍要怎么造数据。随机树上几乎找不到可行的点，光跑随机数据很可能一棵都抓不出错；链和星是两个极端，一个全都可以、一个几乎全都不行，两边各来一批才分得清。

空间按题目上限算。重心那题 n = 4 × 10⁵ 时，sz、maxsub、inner1、inner2、choose、outer 六个 int 数组加 head、to、nxt，合计约 17.6MB。送人回家那题 n = 2 × 10⁵ 时，incost 与 outcost 是 long long，加上 people、inner1、inner2、choose、weight 与建图数组，合计约 12MB。送人回家那题的答案必须开 long long：边权到 10⁹、n 到 2 × 10⁵，代价是 10¹⁴ 量级。

实测：重心那题 n = 10⁵ 时 3.37ms，n = 4 × 10⁵ 时几次实测在 24.76 到 32.36ms 之间。送人回家那题 n = 2 × 10⁵、k = 1000 时 7 到 8ms；朴素做法对每个点各做一次树形 dp，n = 20000、k = 1000 就要 3395.04ms，而换根在同一份数据上是 0.76ms，差了四千多倍，两万个点上的答案一个都不错。

错法抓取率。重心那题，n = 16、8000 棵随机小树上，「太大就当成切不动、往里再切一层那句写成取 0」有 41.25% 的树答案会变；「outer 递推不避开 choose[u] == v、一律用 inner1」有 38.02%。送人回家那题，n = 20000、k = 50、400 组随机数据上，outer 不避 choose 的有 98.00% 组答案会变；outcost 不区分 people[v] == 0、一律写成减法的是 100.00%。另外忘掉最后减最长链，答案平均会膨胀 4.34%。

十一、总结

要点三条。其一，换根时补的那一项如果是「某一侧的最大值」，就必须同时留着次大值和它的来源，因为最大值有可能正好落在正在递的这一支里。其二，两道题的 outer 是同一个形状：父亲那一侧去掉 v 这一支之后的全体，能用的信息分成「父亲继承来的」与「父亲另外几个儿子的」两类，后者在 v 恰好是最优儿子时降级为次大。其三，重心那题里「超标的最多一块」是整道题的支点，它把逐块检查压成只查一块。

「留次大」这个动作不只出现在换根里。求树的直径、求删点后的最大连通块，凡是要把自己这一支排除在外的地方，都要留它。

十二、最后

最容易写错的是 inner1 与 inner2 的更新时机。只有 inner1 真的被刷新时才把旧值让给 inner2；写成「先赋 inner2 再更新 inner1」，在两个儿子给出相同值的时候会把同一个儿子记两遍，choose 也就跟着错了。另外 choose[u] 的初值是 0，而 sz[0] 与 inner1[0] 都是 0，靠全局数组默认清零就行，不用另外初始化。

对拍的时候把 n 压到 7 到 16，链和星各造一批。链上每个点都能改成重心，星上只有中心可以，这两个极端能在几组数据里就分出对错；随机树上可行的点只有万分之几，单独用它反而看不出问题。
