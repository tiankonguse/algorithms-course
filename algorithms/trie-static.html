前缀树：静态数组实现

类描述实现每插一个字符就 new 一个节点，几十万个节点就是几十万次堆分配。静态数组把「节点」换成预先开好的一段二维数组，新节点只是数组里下一个下标，全程没有一次 new。

零、背景

类描述实现慢在哪？new。插入 50 万随机单词，约 87 万个节点，就是 87 万次堆分配，加上 87 万次指针跳转。

本机实测这三份实现，同样的 50 万词：

静态数组 19.79ms，类描述数组路 62.84ms，哈希路 138.65ms。静态是数组路的 3 倍快，是哈希路的 7 倍。

内存差得更多。每个类描述节点实测 216 字节：2 个 int 加 26 个指针；87 万节点吃掉 187MB 堆。静态数组每个节点只要 112 字节，而且是一段连续内存，没有碎片。

哈希路为什么最慢：每个字符一次哈希查找，节点在内存里散着，缓存一路落空。它省下的是「没有的槽位」，可这棵树上用到的路越密，哈希的劣势越明显。

一、把节点放进数组

类描述的节点是 new 出来的对象，访问靠指针。静态数组把「指针」换成「编号」，把「对象」换成数组下标。

三样东西：

tree[MAXN][26]：tree[i][j] 是节点 i 的 j 号路指向的节点编号，0 表示没有路。pass[MAXN] 和 end[MAXN] 存每个节点的两个计数器。cnt 是已分配的节点数，新节点就是 ++cnt。

build() 把 cnt 置 1，1 号是根。0 号整行都是 0，正好当「没有路」的哨兵，树空的时候不用清任何东西。

二、四个操作

insert：cur 从 1 开始，先 pass[cur]++。逐字符走：tree[cur][path] 是 0，就分配 tree[cur][path] = ++cnt；cur 走过去，pass[cur]++。走完 end[cur]++。

search 和 prefixNumber 是同一条路：逐字符走，没路返回 0，走完分别读 end 和 pass。

erase 是唯一多一步的：先 search 确认 word 存在，再沿路把 pass 逐个减一。

// tree[i][j]：节点 i 的 j 号路指向的节点编号，0 表示没有路
    static const int MAXN = 150001;
    static int tree[MAXN][26];
    static int pass[MAXN];
    static int end[MAXN];
    static int cnt;

    // 1 号是根。0 号整行都是 0，正好当「没有路」的哨兵
    void build() {
        cnt = 1;
    }
void insert(string word) {
        int cur = 1;
        pass[cur]++;
        for (int i = 0, path; i < word.size(); i++) {
            path = word[i] - 'a';
            if (tree[cur][path] == 0) {
                tree[cur][path] = ++cnt;    // 没路就分配一个新节点
            }
            cur = tree[cur][path];
            pass[cur]++;
        }
        end[cur]++;
    }

    int search(string word) {
        int cur = 1;
        for (int i = 0, path; i < word.size(); i++) {
            path = word[i] - 'a';
            if (tree[cur][path] == 0) {
                return 0;
            }
            cur = tree[cur][path];
        }
        return end[cur];
    }

    int prefixNumber(string pre) {
        int cur = 1;
        for (int i = 0, path; i < pre.size(); i++) {
            path = pre[i] - 'a';
            if (tree[cur][path] == 0) {
                return 0;
            }
            cur = tree[cur][path];
        }
        return pass[cur];
    }

    // C++ 里 delete 是关键字，删词函数叫 erase
    void erase(string word) {
        if (search(word) > 0) {
            int cur = 1;
            pass[cur]--;
            for (int i = 0, path; i < word.size(); i++) {
                path = word[i] - 'a';
                if (--pass[tree[cur][path]] == 0) {
                    tree[cur][path] = 0;    // pass 减到 0：后面的路整个剪掉
                    return;
                }
                cur = tree[cur][path];
            }
            end[cur]--;
        }
    }

三、erase 剪枝

erase 沿路走时，每到一个节点就把下一个节点的 pass 减一。减到 0，说明没有任何单词还经过这条路，后面整段都可以剪掉：tree[cur][path] = 0。

插 apple、app、apply，删 apple：root 的 pass 3 变 2，a、p、p、l 的 pass 各减 1。l 的 pass 从 2 变 1，因为 apply 还经过它；e 的 pass 从 1 变 0，l 到 e 的路被剪断，e 节点整体作废。

实测行为：插 abc、abcd 后删 abc，search(abc) = 0，prefix(ab) = 1，search(abcd) = 1；再删 abcd，整棵树空。三类实现加朴素计数表，30 万组随机操作对拍，0 处不一致。

四、空间开多少

MAXN 要开「总字符数 + 1」。题目数据范围会告诉你总共多少个字符，直接照开。

牛客这题 MAXN = 150001，三份数组加起来 16.8MB，放全局，稳过。

哈希路「省空间」是假象：路的槽位是省了，但每个节点多一个哈希表对象，对象本身的开销比省下的槽位还大。

复杂度分析

操作时间说明
insertO(len)逐字符走，分配节点是数组赋值，O(1)
search / prefixNumberO(len)走完读 end / pass
eraseO(len)先查一次，再沿路减 pass

空间 O(总字符数 × 26)，MAXN 一次性开在全局，运行中不增不减。

总结

静态数组就是类描述的数组路版本：new 换成 ++cnt，指针换成编号，其余逻辑一字不改。

实测快 3 倍、每节点省一半内存，而且没有堆碎片，比赛里这是稳过的保障。
