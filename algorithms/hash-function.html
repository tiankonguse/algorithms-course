哈希函数：性质与均匀性

哈希函数把任意长的样本压成一个定长的数，输出只有固定那么多种，输入却无限多，碰撞躲不掉。好在只要输出够均匀，碰撞率就能低到可以忽略。这一页把四条性质讲清楚，拆开 MD5 看一眼，再用 100 万个串把「均匀」量出来。

零、同一批串，两个函数给出两种分布

把 1048576 个互不相同的 20 位二进制串喂给 MD5，得到 1048576 个哈希值，一个都没撞。再把它们对 13 取余扔进 13 个抽屉，最多的那个装了 81065 个，最少的 80252 个，与平均值 80659.69 差不到 1%。

换成只看首字符的哈希函数，同一个集合全挤进 2 个抽屉，另外 11 个空着。两个函数都是「把串变成数」，结果的差别全在第四条性质上。

一、四条性质

哈希函数的用处很直接：把复杂样本变成数字，往后样本之间的比较就变成数字之间的比较。它要满足四条性质。

1）输入的可能性是无限的，输出的取值范围相对有限，比如 128 位只有 2128 个格子。

2）输入同样的样本一定得到同样的输出。函数里没有任何随机机制，同一个串今天算和明天算结果一样。

3）输入不同的样本也可能得到同样的输出，这叫哈希碰撞。

4）大量不同的输入，得到的输出会几乎均匀地铺满整个输出域。

第四条最要紧。碰撞理论上躲不掉，抽屉原理摆在那里：格子有限、样本无限。好的哈希函数能做的是把碰撞率压到可以忽略，办法就是让输出尽量均匀。可以这么直观理解：不管输入有没有规律、彼此多相似，一堆不同的输入算出来的输出，从分布上看熵最大。

二、MD5 长什么样

工程上常用的哈希函数有一长串名字：MD5、SHA-1、SHA-256、SHA-512、SHA3 系列。它们的输出长度不同，内部结构都是「把字节流分块，每块揉进一个固定大小的状态里」。看一个最小的：MD5，输出 128 位。

状态是 4 个 32 位整数，初值写死在标准里。消息按 64 字节分块，每块都参与 64 轮四则运算与循环移位，轮函数有四种形状（与或非、异或、选择），轮数和移位量也都是固定表。揉完所有块，把 4 个状态字按小端序拼成 32 个十六进制位，就是哈希值。

// 压缩函数：读 64 字节，把 4 个状态字揉 64 轮
    void md5Block(const u8* p, u32 st[4]) {
        u32 M[16];
        for (int i = 0; i < 16; i++)
            M[i] = (u32)p[i * 4] | ((u32)p[i * 4 + 1] << 8)
                 | ((u32)p[i * 4 + 2] << 16) | ((u32)p[i * 4 + 3] << 24);
        u32 A = st[0], B = st[1], C = st[2], D = st[3];
        for (int i = 0; i < 64; i++) {
            u32 F; int g;
            if (i < 16)      { F = (B & C) | (~B & D); g = i; }
            else if (i < 32) { F = (D & B) | (~D & C); g = (5 * i + 1) & 15; }
            else if (i < 48) { F = B ^ C ^ D;          g = (3 * i + 5) & 15; }
            else             { F = C ^ (B | ~D);       g = (7 * i) & 15; }
            u32 tmp = D; D = C; C = B;
            B = B + md5rol(A + F + MD5_K[i] + M[g], MD5_S[i]);
            A = tmp;
        }
        st[0] += A; st[1] += B; st[2] += C; st[3] += D;
    }

补位是它对外接口里唯一有点绕的地方。消息长度要先补到 64 的整数倍减 8，空出来的最后 8 字节写原消息的比特长度。补位的第一步永远是补一个 1，也就是 0x80。

// 补位 + 分块 + 输出：md5 的对外接口就这三步
    string md5hex(const string& s) {
        u32 st[4] = {0x67452301, 0xefcdab89, 0x98badcfe, 0x10325476};
        string msg = s;
        u64 bits = (u64)s.size() * 8;          // 原串的比特长度，最后 8 字节要写它
        msg.push_back((char)0x80);             // 先补一个 1
        while (msg.size() % 64 != 56) msg.push_back((char)0);   // 再补 0 到 56
        for (int i = 0; i < 8; i++) msg.push_back((char)((bits >> (8 * i)) & 0xff));
        for (size_t i = 0; i < msg.size(); i += 64) md5Block((const u8*)msg.data() + i, st);
        const char* hx = "0123456789abcdef";
        string out;
        for (int w = 0; w < 4; w++) for (int b = 0; b < 4; b++) {
            int v = (st[w] >> (8 * b)) & 0xff;  // 小端序输出
            out.push_back(hx[v >> 4]); out.push_back(hx[v & 15]);
        }
        return out;
    }

拿标准测试向量验一下：空串得到 d41d8cd98f00b204e9800998ecf8427e，"abc" 得到 900150983cd24fb0d6963f7d28e17f72，与公开值一致。

这套结构带来一个反直觉的现象：改一个字符，输出的一半左右都会变。下面 7 个串只在个别位置不同（第 2 到第 6 个与第 1 个分别差 1、1、1、2、2 个字符），MD5 值彼此看不出半点关系。

三、均匀性怎么量

「几乎均匀」是可以量出来的：拿一堆样本算哈希，对 m 取余落进 m 个桶，看每个桶装了多少。桶的大小应该都在样本数除以 m 附近。实测用的样本集合是全部 1048576 个 20 位二进制串。

// 把一堆样本按哈希值对 m 取余落桶，看最大最小差多少
    vector<int> cnt(m, 0);
    for (const string& s : strs) cnt[md5_64(s) % m]++;

    int mx = *max_element(cnt.begin(), cnt.end());
    int mn = *min_element(cnt.begin(), cnt.end());
    double avg = (double)strs.size() / m;
    printf("平均 %.2f，最大 %d (%+.2f%%)，最小 %d (%+.2f%%)\n",
           avg, mx, (mx - avg) / avg * 100, mn, (mn - avg) / avg * 100);

偏差随桶数变大而变大，这是采样涨落的必然。单个桶里的数量标准差是它均值的 1/√(1048576/m)：m=13 时是 0.35%，m=200 时是 1.38%。桶数越多、每桶的平均值越小，相对涨落就越大，实测的最多桶落在两三个标准差之内，这已经是均匀哈希函数能给出的最好结果了。

五、均匀性拿来分组

性质 4 的工程价值在于「均匀分组」。同一个样本的哈希值是固定的，把哈希值对文件数取余，就能保证同一类样本一定进同一个文件，同时不同种类的样本被均匀摊开。

经典场景：一台机器内存只有 4G，硬盘上放着 100 亿行字符串，每行 100 字节，要统计出现次数最多的那一个。100 亿行就是 1012 字节，整整 1TB，读都读不完，更别说在内存里建表。

办法是把文件拆成 1000 份。逐行读原文件，算这一行的哈希值，对 1000 取余决定它写进哪个小文件。每个小文件约 1GB，内存装得下一份，逐份读进内存用哈希表统计出各自的冠军，再在 1000 个候选里比一次就完了。

「同一个串一定进同一个文件」保证了统计的正确性，均匀性保证 1000 份文件的大小差不多、不会有一份特别大拖慢整轮。同一台机器上的内存和硬盘之争，就这么变成了一次文件切分。多台机器分片也是同一套逻辑，把「对 1000 取余」换成「对 1000 台机器取余」而已。

复杂度分析

操作时间空间
对一个长度 k 的样本求哈希O(k)O(1) 状态（MD5 固定 4 个 32 位字）
MD5 补位与分块O(k)，消息长度补到 ≤ k+72O(k) 拷贝（可以直接改原串则不额外占）
按哈希值把 N 个样本分成 m 组O(N·k)O(N) 样本 + O(m) 计数

空间上有个容易忽略的点：MD5 的状态是定长的 128 位，与样本长度无关，所以「算一次哈希额外要多少空间」是 O(1)；真正随样本增长的是读入这份样本本身，以及实现里那份补位拷贝。

总结

四条性质里只有第四条需要刻意设计：输入无限、输出有限，碰撞必然存在，均匀分布才让碰撞率低到能用。MD5 用固定长度的状态加 64 轮混合达到这个效果，改一个字符输出就面目全非。

均匀性可以量化，办法是按余数落桶看偏差。1048576 个样本落在 13 个桶里，MD5 的偏差在 1% 以内；只看首字符的哈希只剩 2 个桶能用，字符求和只剩 21 个。那个差值直接决定它能不能用。

工程上要抗篡改（防伪造签名）还得挑抗碰撞的算法，MD5 和 SHA-1 在这条线上已经失守了；但竞赛和内存索引要的是均匀与快，这两件事是两回事。下一个用得上均匀性的地方是哈希表，桶的数量和扩容策略直接决定它的实际速度。
