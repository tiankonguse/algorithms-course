蓄水池采样：袋子只有那么大

一台机器不停吐球，1 号、2 号、3 号一路吐下去；手边只有一个能装 10 个球的袋子，每个球要么当场收下，要么永远扔掉。要求是：不管机器什么时候停下，已经吐出的那些球里，每一个留在袋子里的概率都相同。球数和未知的将来搅在一起，看上去无处下手；两行规则就能解掉，而且这条规则顺手解决了「一天里所有登录用户等概率中奖」。

零、袋子装不下，还不能反悔

先把题目的约束摆清楚。袋子 10 个位置，机器吐到第几个球是未知的，扔掉的球不能捡回来。如果按「前 10 个先收下」办，第 11 个球开始就没地方放了，后面永远没有球能进袋，这显然不行。

如果按「每个球都以固定的概率留下」办，也不行。留下概率设成 1/2，袋子会在几十个球之后被塞满；设得再小一点，袋子又长期装不满，白白浪费容量。留下概率必须跟着「已经吐了多少个」走。

还有一个容易先入为主的判断：第 1 个球是不是应该稳稳留下？不是。停在 41 号球的时候，1 号球留在袋里的概率和 41 号球一样，都是 10/41。

一、两行规则

第 i 个球到来时，只看一件事。

1）如果 i ≤ m，袋子还没满，直接放进去，占第 i 个位置。

2）如果 i > m，先在 [0, i) 里取一个随机整数，小于 m 就收下这个球，再从 m 个位置里均匀随机挑一个，把原来那个球扔出去。

第 2 步的两个随机数缺一不可。第一个决定「要不要」，概率恰好是 m/i；第二个决定「顶掉谁」，概率是 1/m。两个动作乘起来，任意一个旧球被顶掉的概率是 1/i，和它的编号、和它进袋的早晚都无关。

mt19937_64 rng(107);
    // 返回 [0, i) 上的均匀整数：用乘高位，不吃取模偏差
    int rnd(ll i) { return (int)((__uint128_t)rng() * (unsigned long long)i >> 64); }

    struct Pool {
        int m;                      // 袋子能装几个
        vector<int> bag;
        Pool(int s) : m(s), bag(s, 0) {}
        void enter(ll i) {          // i 号球吐出来了
            if (i <= m) { bag[i - 1] = (int)i; return; }   // 前 m 个先占满
            if (rnd(i) < m) bag[rnd(m)] = (int)i;          // 以 m/i 的概率进来，再随机踢掉一个
        }
    };

rnd(i) 返回 [0, i) 上的均匀整数，实现放在第四节说。整个结构只有一个数组和一个整数，空间就是 m 个位置。

二、为什么这就等概率

用归纳法看「处理完第 i 个球之后，每个球在袋里的概率」。记这个概率为 P(i)。

i = m 时，前 m 个球都在袋里，P(m) = 1 = m/m。

假设 P(i−1) = m/(i−1)，来看第 i 个球进来之后发生了什么。

新来的第 i 个球：留下来的概率是 m/i。

已经在袋里的旧球 x：它被顶掉，需要第 i 个球成功进袋（概率 m/i），同时随机挑位置时挑中它（概率 1/m），乘起来是 1/i。所以它留下的概率是前一时刻的 P(i−1) 乘以 (1 − 1/i)。把式子写开：P(i) = m/(i−1) × (i−1)/i = m/i。

新旧两种球在同一个时刻的概率都等于 m/i，归纳成立。

这里有个细节值得停下来看一眼：旧球被顶掉的概率是 1/i，这个数和新球的留存概率 m/i 只差一个 m 的倍数。正是这个配合让两边同时收敛到 m/i。如果第二个随机数是在 i 个位置里挑（而不是 m 个位置），旧球被顶掉的概率就变成 m/i × 1/i，概率会一路偏掉。

三、任意时刻停下都成立

上面证明的是「处理完第 i 个球」。所以机器吐到第 k 个球时按下暂停，每个已吐出的球留在袋里的概率就是 min(1, m/k)：袋子没装满之前是 1，装满之后是 m/k。

袋口 10 个，吐到 41 号球停下，理论概率 10/41 = 0.243902。跑 10 万次实验，把每次袋里那 10 个球都记下来，41 个球各自的入选频率是：

停在第 k 个球理论概率 min(10,k)/k第 1 个球的实测频率偏离最大的球
120.83330.8333第 4 个，0.8344（+0.13%）
150.66670.6667第 6 个，0.6649（−0.27%）
200.50000.5006第 5 个，0.4980（−0.40%）
300.33330.3324第 5 个，0.3346（+0.38%）

每组 30 万次实验，最大偏离都在 1% 以内，而且偏离最大的那个球每次都不一样，没有「早来的球更稳」这种系统性偏差。

规模放大到 10 万个球、袋口 1000 个，每个球的理论概率是 0.01。跑 5000 轮，每个球平均被选中 50.0000 次，实测的标准差是 7.0396 次，按二项分布算是 √(5000 × 0.01 × 0.99) = 7.0356 次。10 万个球的频率都落在同一个分布里，没有哪一个球被系统性地偏待。

四、随机数怎么取

「以 m/i 的概率收下」这句话在代码里是 随机数 < m，随机数要落在 [0, i) 上。最常见写法是 rand() % i，它有个能算出来的偏差。

设随机源在 [0, R] 上均匀，一共 R+1 个取值。对 i 取余，余数 0 到 (R+1) mod i − 1 会各多出现一次，其余余数少一次。差值能有多大？看一张精确枚举的表（用 15 位随机源，R = 32767，要判「落在前 3 个位置」）：

i理论概率 3/i取模的实测概率偏差
10000.0030000.003021+0.71%
80000.0003750.000458+22.07%
200000.0001500.000183+22.07%
300000.0001000.000183+83.11%

偏差的量级是 i/(R+1)：i 越接近随机源的上界，偏得越狠。i = 30000、R = 32767 时，前 2768 个余数每个都能被两个不同的取值撞到，剩下的只能被一个撞到，于是小概率事件被高估了八成。

换一个高精度随机源，这一层偏差就没了。用 31 位的 rand()（R = 2147483647）时，i 在 10 万以内的偏差量级是 4.66×10−5，可以直接忽略；但 i 涨到 108，偏差又回到 4.66×10−2，也就是百分之五。所以「随机数够不够用」这件事要拿 i 和随机源上界比一比，别默认它没问题。

真正的均匀整数用乘法取高位：把随机源的 64 位值乘以 i，取乘积的高 64 位。这一步把 [0, 264) 切成 i 段等长的区间，误差只有 2−64 量级。袋口只有几十几百个位置、球数最多到十亿量级，这个精度绰绰有余。

顺带说一句规模：10 亿个球、袋口 10 个位置，整段处理下来 2.67 秒，每个球摊到 2.7 纳秒，主要开销就是那两个随机数。

五、抽奖系统是同一件事

换个说法就是抽奖：一天里所有登录的用户机会均等，最后开 100 个名额。用户什么时候来、一天来多少个，事先都不知道。

照搬上面的规则：第 i 个用户到来时，如果池子没满就放进去；满了就以 100/i 的概率把他放进去，再随机顶掉池里一个人。收工时池子里的 100 个用户就是中奖名单。

// 一天里陆续登录的用户，每人恰好 M/N 的中奖概率；N 是收工时才知道的
    // 第 i 个用户到来时，以 M/i 的概率把他放进池子，放进来就随机顶掉一个
    struct Lottery {
        int m; vector<int> pool; int filled = 0;
        Lottery(int s) : m(s), pool(s, -1) {}
        void login(ll i) {                       // 第 i 个用户
            if (filled < m) { pool[filled++] = (int)i; return; }
            if (rnd(i) < m) pool[rnd(m)] = (int)i;
        }
    };

这套做法的好处是全程不需要知道总人数 N。第 i 个用户被留下的概率是 100/i，而这个概率在后续每一次替换中又不断调整，最终每个人都收敛到 100/N。跑一遍 2000 个用户、100 个名额、2 万次实验：理论概率 0.05，第 1 个用户实测 0.0505，最后一个用户 0.0515，2000 个人里偏离最大的是 +11.10%、最小的是 −10.30%，都在抽样涨落范围内（每人期望中奖 1000 次，标准差 31 次）。

如果按人编号先来后到地分配、或者把一天切成一万个时间片各自抽一个中奖者，用户就得赌运气：早上的用户和深夜的用户不在同一个池子里比。蓄水池的做法把所有时刻的用户放进同一个池子，只用一个袋子就完成了全局等概率。

复杂度分析

操作时间空间
收下第 i 个球O(1)，两次随机数O(1)
处理 n 个球O(n)O(m)，袋子本身
抽奖池收一个用户O(1)O(M)，M 是名额数

这里的空间是整套做法最值钱的地方：不管机器吐多少个球，袋子始终只有 m 个位置。10 亿个球、10 个位置，内存占用是 40 字节。时间也没得挑，每个球只做一次概率判断，连球号都不用存下来。

要注意的是「不能反悔」这条约束是白送的：一旦决定扔掉就真的扔掉了，不需要记住扔过谁，也不需要回看历史。这正是 O(1) 的原因。凡是需要回看历史才能补救的算法，空间都省不下来。

总结

蓄水池采样只有两条规则：前 m 个球直接占满袋子，之后每个球以 m/i 的概率进来、进来时均匀随机顶掉一个位置。归纳一下就能看出，处理完第 i 个球时每个球留在袋里的概率都是 m/i，任意时刻停下来统计，得到的是一份等概率样本。

两个随机数各管一件事，第一个管收不收（m/i），第二个管顶掉谁（1/m），乘起来的 1/i 是整段证明的关键。随机数本身的精度也要算一笔账：取模在 i 接近随机源上界时能偏出八成，31 位随机源配 10 万量级的 i 才算太平，乘法取高位是更稳的写法。

把球换成登录用户，这套规则就是「每人等概率中奖」的抽奖系统，而且不需要预先知道总人数。往后需要「从一个不知道多大、还在增长的集合里取样本」的场景，第一反应都应该是它。
