字符串哈希：逐个起点往下看

这两道题都不只是「找一段」。第一道要从每个起点一路往右扩，边扩边看子串里各个数字的个数是不是一样，扩的过程中判据会来回变；第二道允许 k 个位置不同，靠哈希加二分一次跳过整段对得上的部分，把逐位比较压成 k 次二分成。

零、两道题

题 2（LeetCode 2168）：s 只由数字组成，长度不超过 1000。数一数 s 里有多少个不同的子串，满足其中每个出现过的数字出现次数都相同。"1212" 的答案是 5，分别是 "1"、"2"、"12"、"21"、"1212"。

题 6（洛谷 P3763 DNA）：给长 n 的源串 s（n 不超过 105）、长 m 的模式串 p，还有正数 k（本题固定 k = 3）。定义 s 中一段与 p 匹配是指长度相同且最多 k 个位置字符不同，问有多少段匹配。

一、题 2：从每个起点往右扩

枚举起点 i，再从 i 往右一格一格延长 j。延长时只多进来一个数字，所以整段的信息可以增量维护，用三个量就够：

1）maxCnt：所有数字里出现次数的最大值。

2）allKinds：这段里出现过几种数字。

3）maxCntKinds：达到 maxCnt 的数字有几种。

判据是 maxCntKinds == allKinds。它成立时，每一种出现过的数字都刚好出现 maxCnt 次，每种和最大值打平，没有谁少。反过来如果某个数字少于 maxCnt，达到最大值的种类数就一定小于种类总数。

这里有个反直觉的地方：合法不合法没有单调性。往后多一个字符可能让一段从不合法变合法，也可能从合法变不合法。「1122」里 "11" 合法，加一个 2 变成 "112" 就不合法，再加一个 2 变成 "1122" 又合法了。所以判定不成立时不能停，必须继续往后扩。

去重要用子串的哈希值。只把「maxCnt、allKinds、长度」这三个数塞进集合是不行的：不同的子串可以是同样的三个数，比如 "12" 和 "21" 都是两个数字各一次，它们是两个不同的子串，要各记一个。

// 独特子串的数量：子串里每个数字出现的次数都一样才算
    int equalDigitFrequency(const string &str) {
        unordered_set<unsigned long long> seen;
        int n = str.size();
        int cnt[10];
        for (int i = 0; i < n; i++) {
            memset(cnt, 0, sizeof(cnt));
            unsigned long long h = 0;
            int curVal = 0, maxCnt = 0, maxCntKinds = 0, allKinds = 0;
            for (int j = i; j < n; j++) {
                curVal = str[j] - '0';
                h = h * base + curVal + 1;
                cnt[curVal]++;
                if (cnt[curVal] == 1) {
                    allKinds++;
                }
                if (cnt[curVal] > maxCnt) {
                    maxCnt = cnt[curVal];
                    maxCntKinds = 1;
                } else if (cnt[curVal] == maxCnt) {
                    maxCntKinds++;
                }
                if (maxCntKinds == allKinds) {
                    seen.insert(h);
                }
            }
        }
        return seen.size();
    }

三个容易写错的地方：哈希值从 0 开始算，前导零不贡献位权，不同子串会塌进同一个哈希值（实测在字符表 2、串长 10 的随机数据上 80.24% 的用例数错）；判据写成 maxCnt × allKinds == len，这其实和原判据完全等价，20000 组随机数据上一处差别都没有；维护 maxCntKinds 时漏掉「等于最大值也要加一」的那一支，只在刷新最大值时重置，漏掉这一支以后 80% 到 96% 的用例都会数错。

二、题 6：哈希配二分跳段

朴素做法是把每个起点都逐位比一遍，每个起点 O(m)，总共 O(n × m)。n = 105、m = 104 时实测 691 毫秒，交上去过不了。

题目只问「不同位置的个数有没有超过 k」，不要求把具体个数数出来。那就没必要逐位看：从头开始，二分找出当前还能对上多长，直接把这一段跳过去，跨过一个不同的位置，再来一次。重复到发现第 k+1 处不同就能判否，或者整段走完都不到 k+1 处就判是。

二分能用的原因是前缀相同具有单调性：能对上 5 个字符，那前 4 个也一定对得上。二分的判据交给哈希：same(l1, l2, len) 判断两段长度 len 的区间哈希值是否相等，一次比较 O(1)，与区间长度无关。

建表和取值还是模板那套，只是 s 与 p 各建一份，取值时把数组当参数传进去：

const int MAXN = 100001;

    unsigned long long pw[MAXN], hs[MAXN], hp[MAXN];

    void build(const string &s, const string &p) {
        pw[0] = 1;
        for (int i = 1; i < MAXN; i++) {
            pw[i] = pw[i - 1] * base;
        }
        hs[0] = s[0] - 'a' + 1;
        for (int i = 1; i < s.size(); i++) {
            hs[i] = hs[i - 1] * base + s[i] - 'a' + 1;
        }
        hp[0] = p[0] - 'a' + 1;
        for (int i = 1; i < p.size(); i++) {
            hp[i] = hp[i - 1] * base + p[i] - 'a' + 1;
        }
    }

    unsigned long long getHash(const unsigned long long *h, int l, int r) {
        unsigned long long ans = h[r];
        if (l > 0) {
            ans -= h[l - 1] * pw[r - l + 1];
        }
        return ans;
    }

    // s[l1...l1+len-1] 与 p[l2...l2+len-1] 是不是一模一样
    bool same(int l1, int l2, int len) {
        return getHash(hs, l1, l1 + len - 1) == getHash(hp, l2, l2 + len - 1);
    }

核心是下面这段。跳的时候是 l1 += len + 1，加的那个 1 用来跳过刚刚发现的不同位置；结束条件是 l1 > r1 或者欠的个数超了 k：

// s[l1...r1] 与 p[0...r1-l1] 这两段上，不同的位置是不是不超过 k 个
    bool check(int l1, int r1, int k) {
        int diff = 0;
        int l2 = 0;
        while (l1 <= r1 && diff <= k) {
            // 二分找出还能对上多少个字符
            int l = 1;
            int r = r1 - l1 + 1;
            int m, len = 0;
            while (l <= r) {
                m = (l + r) / 2;
                if (same(l1, l2, m)) {
                    len = m;
                    l = m + 1;
                } else {
                    r = m - 1;
                }
            }
            if (l1 + len <= r1) {
                diff++;                       // 相同的前缀后面还压着一个不同的位置
            }
            l1 += len + 1;                    // 跳过这个不同的位置，接着比下一段
            l2 += len + 1;
        }
        return diff <= k;
    }
// s 中有多少子串改不超过 k 个位置就能变成 p
    int compute(const string &s, const string &p, int k) {
        int n = s.size(), m = p.size();
        if (n < m) {
            return 0;
        }
        build(s, p);
        int ans = 0;
        for (int i = 0; i <= n - m; i++) {
            if (check(i, i + m - 1, k)) {
                ans++;
            }
        }
        return ans;
    }

每个起点最多做 k+1 次二分，每次二分 O(log m)，所以一个起点 O(k log m)，总共 O(n × k × log m)。k 是常数 3，m = 104 时一次二分十四步，一个起点几十次操作。

实测 n = 105：m = 100 时哈希版 13.06 毫秒，暴力逐位 8.51 毫秒，暴力反而更快；m = 1000 时变成 19.34 对 76.58；m = 10000 时 24.25 对 691.43。暴力每个起点都要看 m 位，m 一大立刻起飞；哈希版的时间里 log m 涨得很慢，所以 m 越小它越不划算。

两个错法：循环条件写 diff < k，等于要求差异必须少于 k 个，恰好 k 处的那些段全被判掉，在 k = 1 的数据上 77.11% 的用例出错；if (l1 + len <= r1) 写成 <，最后一段整体对上时也会多记一处差异，答案偏大。还有一条不是出错率的问题：把 l1 += len + 1 写成 l1 += len，碰上不同的位置时指针原地不动，程序直接卡死，这种错法不用跑随机数据也能看出来。

独特子串：一格一格往右扩

每点一步 j 往右挪一格，看 cnt 表、三个计数与判据的变化。判定成立时把这个子串的哈希值塞进集合，集合里有多少个元素就是答案的一部分。

二分跳段：一次跳一整段

每点一步做一次二分（橙色是二分试的长度，绿色是最后认定的相同前缀），跨过一个不同位置就记一次差异。差异超过 k 这个起点就否掉，整段走完没超就是答案。

三、复杂度分析

做法关键操作时间空间
题 2　枚举起点往右扩n 个起点各自扩到底，每步 O(1)O(n2)O(n2) 个哈希值
题 6　逐位比对每个起点看 m 位O(n × m)O(1)
题 6　哈希加二分每个起点最多 k+1 次二分O(n × k × log m)O(n + m)

题 2 的 n 上限是 1000，子串总数 500500，平方做法足够，实测全同串 2.54 毫秒、随机串 0.96 毫秒。空间上哈希集合里最多装 500500 个 64 位整数，约 4 MB；cnt 只有一个 10 格的数组。题 6 的 n 上限 105，pw、hs、hp 三个数组各 8 字节一格，加起来约 2.4 MB。k 是常数，所以复杂度里真正起作用的是 log m，m 再大也只是把二分多加一步。

总结

题 2 的判据是「达到最大值的数字种类数等于出现过的数字种类数」，合法与否没有单调性，判定不成立也要继续往右扩。

去重必须用子串的哈希值，判据状态本身会撞车，「12」和「21」的频率统计一模一样但是两个子串。

题 6 把「有几个位置不同」换成「什么时候超过 k 个」，配哈希二分的相同前缀判定，每个起点只看 k+1 段。

两道题分别用了哈希的两面：题 2 用它给子串发身份证，题 6 用它回答「这两段一模一样吗」。同一个 getHash，一个进集合去重，一个喂给二分当判据。
