完全背包：每种可以拿任意个

01 背包的压缩版把 j 从大到小刷，为的是让每件货物只被拿一次。把方向反过来，同一件货物就能在同一个状态里反复出现，这就是完全背包，每种货物拿几个都行。转移只改一个循环方向，二维表却要按 GB 算，本机根本开不出来。

零、问题

背包容量 t，m 种货物，每种有花费 cost[i] 和价值 val[i]。每种货物可以取任意多个（0 个、1 个、一亿个都行），问不超过容量时能拿到的最大价值。

和 01 背包的差别只有一句话：每种的个数不限。就这一句话，让转移方程的右端下标从 i − 1 变成了 i。

01 背包　　dp[i][j] = max( dp[i-1][j], dp[i-1][j-cost[i]] + val[i] )
完全背包　dp[i][j] = max( dp[i-1][j], dp[i][j-cost[i]] + val[i] )

右端那个 dp[i][j-cost[i]] 的含义是：已经允许用前 i 种货物了，再腾出 cost[i] 的空间，这时还能不能再拿一个第 i 种。既然它自己已经允许拿第 i 种，那么加上这次就是第二个、第三个、任意多个。一个下标之差，把「至多一次」换成了「不限次数」。

一、反向的循环，正序的 j

把二维压成一维之后，dp[j] 在刷新前是「前 i − 1 种、容量 j」，刷新后是「前 i 种、容量 j」。要让 dp[j-cost[i]] 读到本轮已经刷过的值（也就是允许重取），j 就得从小到大走。

对照着看就清楚了。只有一件货物 cost = 3、val = 5，t = 8：

正序那行 dp[8] = 10，是拿了两个（3 + 3 装不满，但 6 ≤ 8，第二次是从 dp[5] 加上来的，而 dp[5] 本轮已经被写成了 5）。倒序那行 dp[8] = 5，只拿了一个，多出来的 5 点容量空着，它其实退化成 01 背包了。

// dp[i][j]：只用前 i 种货物，容量不超过 j 时的最大价值
    long long unbounded2d(int t, int m, vector<int>& cost, vector<int>& val) {
        vector<vector<long long>> dp(m + 1, vector<long long>(t + 1, 0));
        for (int i = 1; i <= m; i++) {
            for (int j = 0; j <= t; j++) {
                dp[i][j] = dp[i-1][j];              // 第 i 种一件都不拿
                if (j - cost[i] >= 0)
                    dp[i][j] = max(dp[i][j], dp[i][j - cost[i]] + val[i]);
            }                                       // 注意右端是 dp[i] 不是 dp[i-1]
        }
        return dp[m][t];
    }
// 和 01 背包只差循环方向：一行循环，一个不等号的方向
    long long unbounded1d(int t, int m, vector<int>& cost, vector<int>& val) {
        vector<long long> dp(t + 1, 0);
        for (int i = 1; i <= m; i++)
            for (int j = cost[i]; j <= t; j++)      // j 从小到大
                dp[j] = max(dp[j], dp[j - cost[i]] + val[i]);
        return dp[t];
    }

二维版的内层 j 从 0 到 t 都可以，因为它写的是 dp[i][j]，读的是同一行的 dp[i][j-cost[i]]，两者天然是本轮的关系，不存在读到旧值的风险。压缩版把这个「同一行」压没了，只能靠循环方向把顺序还原回来。

二、二维表为什么开不出来

这题的容量上限是 107，货物种数是 104，二维表的格子数是 1011。用 long long 存，按 8 字节算就是 745 GB。一维表只有 t + 1 格，同样用 long long 是 76 MB，能开。

时间上真正的开销在内层循环的总次数，也就是 m × t 那一栏。实测 t = 106、m = 1000（109 次内层）用 334.213 毫秒；t = 106、m = 2000（2×109 次）用 605.276 毫秒；t = 107、m = 100（也是 109 次）用 355.419 毫秒。三组数基本跟着内层次数走，跟容量和种数各自多大没关系。

还有一小段可以省：j 只需要从 cost[i] 开始，比 cost[i] 小的容量根本放不下这一种，那一格的字不会变。

三、写反的代价

把 j 写成从大到小，程序不会报错，答案会变成一个合法但更小的值，就是每种货物至多拿一次的最优解。这就是 01 背包的答案，它永远不超过完全背包的答案。

两万组随机样本里，值域小的时候 94.46% 现形，值域一大就掉到 4.95%。原因和分组背包那边一样：值域大了以后，「同一种拿两个」很容易被容量卡住，错版和正解撞到同一个答案。想验证自己有没有写反，样本值域要压小，或者直接拿「每种都一样的花费、且 t 是花费的整数倍」这种构造数据。

四、至少买够 h 磅干草，最少花多少钱

有 n 家公司卖干草，第 i 家一次卖 val[i] 磅、收 cost[i] 元，每家可以买任意次。你要买至少 h 磅，问最少花多少钱。

把「花的钱」当价值求最小，把「买到的磅数」当容量，这就是一个完全背包，只差一处：「不超过容量」变成了「不低于 h」。

记 dp[j] 为「买到严格 j 磅的最少花费」。填法和完全背包一样，j 正序。麻烦在答案：合法的 j 是 h, h+1, h+2, …… 一直到无穷，表不可能开到无穷。这里要停下来想一下：最优解会不会多买很多？

不会。假设最优解买了总量 V ≥ h + maxv（maxv 是所有公司里单次给得最多的那一家）。那它一定在某一家买过至少一次，退掉这一次，总量还剩 V − 某次 ≤ V − 1，但仍然 ≥ h + maxv − 1 ≥ h（因为 maxv ≥ 1），钱少了，还合法。所以最优解的总量一定控制在 h + maxv 以内，表开到 m = h + maxv 就够了，答案取 dp[h..m] 的最小值。

const int INF = 1e9;

    // 至少买够 h 磅干草，最少花多少钱
    // 每次多买的量不会超过 maxv，否则退掉一次买得更多，所以容量开到 h + maxv 就够
    int hay2d(int n, int h, vector<int>& val, vector<int>& cost) {
        int maxv = 0;
        for (int i = 1; i <= n; i++) maxv = max(maxv, val[i]);
        int m = h + maxv;
        // dp[i][j]：前 i 家公司里挑，买到严格 j 磅干草的最少花费
        vector<vector<int>> dp(n + 1, vector<int>(m + 1, INF));
        dp[0][0] = 0;
        for (int i = 1; i <= n; i++)
            for (int j = 0; j <= m; j++) {
                dp[i][j] = dp[i-1][j];
                if (j - val[i] >= 0 && dp[i][j-val[i]] != INF)
                    dp[i][j] = min(dp[i][j], dp[i][j-val[i]] + cost[i]);
            }
        int ans = INF;
        for (int j = h; j <= m; j++) ans = min(ans, dp[n][j]);   // 超过 h 的都算买够
        return ans;
    }
int hay1d(int n, int h, vector<int>& val, vector<int>& cost) {
        int maxv = 0;
        for (int i = 1; i <= n; i++) maxv = max(maxv, val[i]);
        int m = h + maxv;
        vector<int> dp(m + 1, INF);
        dp[0] = 0;
        for (int i = 1; i <= n; i++)
            for (int j = val[i]; j <= m; j++)       // j 从小到大：一家公司能买任意次
                if (dp[j-val[i]] != INF)
                    dp[j] = min(dp[j], dp[j-val[i]] + cost[i]);
        int ans = INF;
        for (int j = h; j <= m; j++) ans = min(ans, dp[j]);
        return ans;
    }

实测上界取不对比错多少：把 m 写成 h（也就是只算恰好 h 磅），两万组样本里有 53.40% 到 97.55% 出错，值域越大错得越多。值域大了，恰好拼出 h 的概率降低，越来越多的样本要靠「超过 h」才能拿到最优解。把 m 写成 h + maxv − 1 则是 0% 出错，说明 h + maxv − 1 就够；代码里写 h + maxv 是顺手多留一格。

规模上，n = 100、h = 50000、maxv = 4918、m = 54918 时实测 2.510 毫秒。这里还藏着一个坑：dp 的初值是无穷大，转移前必须判 dp[j-val[i]] != INF，否则「无穷大加 cost」在 int 下会溢出成负数，被当成一个很小的花费。

三张表的时间复杂度都没有比 01 背包升阶，多出来的只有常数：完全背包多的是「同一格被反复刷新」，干草多的是「容量上限从 h 抬到 h + maxv」那一部分。

六、总结

完全背包和 01 背包只差一个循环方向，背后是「右端用不用本轮的值」这件事。

几个要点：

1）压缩转移写 dp[j] = max(dp[j], dp[j-cost[i]] + val[i])，j 必须正序。写成倒序就退回 01 背包，答案偏小，V = 5 时 94.46% 的样本现形。

2）二维表下标是 dp[i][j-cost[i]]，不是 dp[i-1]。差一个 i，含义完全不同。

3）容量 107 的题只能开一维。二维表的格子数是 1011，没得商量。

4）遇到「至少买够」「不低于某个量」的题，把容量上限抬到 h + maxv，再在尾段取最小值。抬多少由「最优解多买的量不会超过一次采购的量」这条定。

5）dp 初值取无穷大时，转移前要判来源格子是否可达，否则加号会溢出。

分组背包和完全背包都讲完了。接下来看两道字符串匹配题，它们的 * 让「前一个字符重复任意次」，转移里正好长出一个完全背包。
