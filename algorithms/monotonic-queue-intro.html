单调队列：窗口里的最大值

滑动窗口每挪一步就要一次最大值，暴力每个窗口扫一遍是 O(nk)。单调队列把「窗口内最大值」维护成一条从队头到队尾单调递减的队列，每个下标进队一次、出队至多一次，总代价 O(n)。

零、背景

窗口滑动时，r 右移进新元素、l 右移出旧元素，这期间随时要窗口里的最大值。最直接的想法是维护一个「当前最大值」变量，但这有个坑：最大值跟着 l 一起出窗口之后，你不知道下一个最大的是谁，得重新扫。

每个窗口都扫一遍是 O(nk)，k 和 n 同阶就是 O(n²)。n=1e5、k=5e4 的随机数据，暴力实测 102ms，而单调队列只要 0.66ms。

队列里为什么能淘汰：如果队列里有一个靠前的元素 x，后面来了个 x' ≥ x 且下标更大，那 x 永远当不上最大值：x' 值更大，而且更晚过期。留着 x 没有意义，弹掉。

一、单调队列的结构

队列存下标，队内值从队头到队尾单调不增。新元素从队尾进，进之前把队尾所有值 ≤ 它的全部弹出；队头就是窗口最大值；窗口左移时如果队头下标等于 l，说明它过期了，弹出。

每个下标最多进队一次、出队一次，所以窗口滑完整个数组，队列调整的总次数是 O(n)，均摊到每次窗口操作 O(1)。

二、题 1：滑动窗口最大值（LeetCode 239）

先把前 k-1 个元素入队形成窗口骨架，然后 l 从 0 到 n-k 逐窗口：r 位置的元素入队（弹队尾）、收集队头为答案、检查队头是否等于 l（过期弹出）。

弹出条件用 ≤ 而不是 <：值相等时旧的让位给新的。新下标更晚过期，两个同样大的值，留新的一定不会更差。

复杂度：每个下标进出队各一次，O(n)，额外空间 O(k)（队列最多装 k 个下标）。实测 n=1e6、k=1000 的随机数组 6.8ms。

三个高频错法，随机数据下的抓取率：

忘掉过期检查，队头可能已经是窗口外的元素，52.23% 算错；从队尾取答案，队尾是队列里最小的值，87.22% 算错；先弹出 l 再收集答案，把窗口内最大值提前扔了，60.47% 算错。

三、代码

vector<int> MaxSlidingWindow(vector<int>& nums, int k) {
        int n = (int)nums.size();
        vector<int> deque(n);
        int h = 0, t = 0;
        for (int i = 0; i < k - 1; i++) {
            while (h < t && nums[deque[t - 1]] <= nums[i]) t--;
            deque[t++] = i;
        }
        int m = n - k + 1;
        vector<int> ans(m);
        for (int l = 0, r = k - 1; l < m; l++, r++) {
            while (h < t && nums[deque[t - 1]] <= nums[r]) t--;
            deque[t++] = r;
            ans[l] = nums[deque[h]];
            if (deque[h] == l) h++;
        }
        return ans;
    }

总结

单调队列的本质是「淘汰永远当不上候选的元素」：值更小且下标更早的元素，被后面值更大下标更新的元素顶掉。这样队头永远是当前窗口的最大值，过期检查只发生在队头。

窗口同时要最大值和最小值时，开两个单调队列，队头一个取最大一个取最小。下一页的两道题都是这个套路。
