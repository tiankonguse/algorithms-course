多维费用背包：一和零与盈利计划

背包的容量本来只有一个上限。一和零里上限有两条：0 的个数不超过 m、1 的个数不超过 n；盈利计划里限制换成「员工不超过 n」加「利润不少于 minProfit」。递归的参数因此多了一个，表从一张变成一叠。改法还是写递归、加记忆化、改严格位置依赖这三步，只是压掉最外层那一维时，另外两维都得倒着扫。

零、两个额度就是两条容量轴

先看一和零：给一堆只含 0 和 1 的字符串，从中挑出一个子集，要求整个子集里 0 的总数不超过 m、1 的总数不超过 n，问最多能挑几个。

01 背包挑不挑第 i 件物品，看的是「重量够不够」。这里够不够要两个条件同时成立，所以状态里得同时带着「还剩多少个 0 的额度」和「还剩多少个 1 的额度」。额度是消耗品，挑一个字符串就按它自己的用量扣，两条轴各扣各的。

状态里只要出现「还剩多少额度」这种量，它就是容量维度。一维容量出一条轴，二维容量出两条轴，轴的条数就是可变参数的个数。

一、先把递归写出来

定义 f1(strs, i, z, o)：strs[i..] 自由选择，0 的额度还剩 z、1 的额度还剩 o，最多能选几个。

// 统计一个字符串里 0 和 1 的数量
    int zeros, ones;

    void countZerosOnes(const string& s) {
        zeros = ones = 0;
        for (char c : s) {
            c == '0' ? zeros++ : ones++;
        }
    }

    // strs[i..] 自由选择，0 的额度是 z、1 的额度是 o，最多能选多少个
    int f1(vector<string>& strs, int i, int z, int o) {
        if (i == (int)strs.size()) {
            return 0;
        }
        int p1 = f1(strs, i + 1, z, o);
        int p2 = 0;
        countZerosOnes(strs[i]);
        if (zeros <= z && ones <= o) {
            p2 = 1 + f1(strs, i + 1, z - zeros, o - ones);
        }
        return max(p1, p2);
    }

两个分支就是选和不选。不选 strs[i]，额度原样交给后面；选它，先看两个额度够不够，够就各扣掉它自己的用量，答案再加一。每个字符串会数一遍 0 和 1 的个数，这一步是 O(字符串长度)，跟状态数比可以忽略。

这份递归的分支是指数级的，因为同一组 (i, z, o) 会被从不同的路径反复到达。实测 m = n = 5：

n = 10 时调用 1485 次，n = 25 时 313911 次。每加五个字符串调用次数涨四到十倍，而状态其实只有 len × 6 × 6 个。

二、三个可变参数，就是一叠表

加一张同形状的三维表，初始全填 −1，递归开头先查一下。表的大小是每个可变参数的可能性数量相乘：len × (m+1) × (n+1)。

// 记忆化搜索：可变参数是 (i, z, o)
    int f2(vector<string>& strs, int i, int z, int o, vector<vector<vector<int>>>& dp) {
        if (i == (int)strs.size()) {
            return 0;
        }
        if (dp[i][z][o] != -1) {
            return dp[i][z][o];
        }
        int p1 = f2(strs, i + 1, z, o, dp);
        int p2 = 0;
        countZerosOnes(strs[i]);
        if (zeros <= z && ones <= o) {
            p2 = 1 + f2(strs, i + 1, z - zeros, o - ones, dp);
        }
        return dp[i][z][o] = max(p1, p2);
    }

LeetCode 的满规模是 600 个字符串、m = n = 100，表里 601 × 101 × 101 = 6130801 个 int，合 23.4 MiB。注意 i == strs.length 那一层不用存，它整层都是 0，这就是后面能压掉一维的入口。

三、严格位置依赖：从最后一层往前填

记忆化还带着递归。把依赖画出来就能改成循环：dp[i][z][o] 只读 dp[i+1] 那一层的两个格子，跟 dp[i][z][o] 自己在同一层的邻居没有任何关系。

// 严格位置依赖：第 i 层的表由第 i+1 层推出来
    int findMaxForm3(vector<string>& strs, int m, int n) {
        int len = strs.size();
        vector<vector<vector<int>>> dp(len + 1, vector<vector<int>>(m + 1, vector<int>(n + 1, 0)));
        for (int i = len - 1; i >= 0; i--) {
            countZerosOnes(strs[i]);
            for (int z = 0; z <= m; z++) {
                for (int o = 0; o <= n; o++) {
                    int p1 = dp[i + 1][z][o];
                    int p2 = (zeros <= z && ones <= o) ? 1 + dp[i + 1][z - zeros][o - ones] : 0;
                    dp[i][z][o] = max(p1, p2);
                }
            }
        }
        return dp[0][m][n];
    }

    // 空间压缩：i 这一维滚掉，只剩 z、o 一张二维表，两个额度都倒着扫
    int findMaxForm4(vector<string>& strs, int m, int n) {
        vector<vector<int>> dp(m + 1, vector<int>(n + 1, 0));
        for (const string& s : strs) {
            countZerosOnes(s);
            for (int z = m; z >= zeros; z--) {
                for (int o = n; o >= ones; o--) {
                    dp[z][o] = max(dp[z][o], 1 + dp[z - zeros][o - ones]);
                }
            }
        }
        return dp[m][n];
    }

蓝色那条是「不选」，两个额度都不动，直接抄下一层的同一格；橙色那条是「选」，两个额度各减掉当前字符串的用量。i 从 len−1 递减，让 i+1 层永远先算好。

四、空间压缩：把字符串那一维滚掉

既然本层只读下一层，那第 i+2 层及以前就永远用不到了。整叠表可以只留一张 (m+1) × (n+1) 的二维表，让它在每一轮里换一次身份。

先记下当前字符串用了几个 0、几个 1，然后两个额度都从大到小扫。写成一行就是 dp[z][o] = max(dp[z][o], 1 + dp[z−zeros][o−ones])。

倒着扫的理由和 01 背包完全一样：等号右边的 dp[z−zeros][o−ones] 必须是上一层留下的旧值。正着扫会读到本层刚写好的新值，等于同一个字符串被挑了两次。

实测（600 个字符串、m = n = 100）：三维表 8.1 ms、23.4 MiB；压缩版 2.2 ms、39.8 KiB。空间差 601 倍，时间还快了 3.7 倍，因为 23.4 MiB 的表早就跑出 CPU 缓存了，而 39.8 KiB 塞得进 L1。

压缩版的内层循环次数也从 6120600 降到 3578630，因为 z < zeros、o < ones 的那些格子根本不用进循环。

五、盈利计划：第三个维度是「还差多少利润」

再给一道同形状的题。集团里有 n 名员工，第 i 种工作需要 group[i] 个人、产生 profit[i] 的利润，同一个人不能同时做两项工作。选出一个工作子集，要求用工总数不超过 n、利润至少 minProfit，问有多少种选法，答案对 1e9+7 取模。

员工那一头是「不能超」，跟一和零的两个额度一样，用了就减；利润那一头是「不能少」，于是把参数定义成「还差多少」。三个可变参数 (i, r, s)：来到 i 号工作，员工还剩 r 个，利润还差 s 才达标。

const int MOD = 1000000007;

    // i 号工作，员工还剩 r 个，利润还差 s 才达标，返回方案数
    int f2(vector<int>& g, vector<int>& p, int i, int r, int s, vector<vector<vector<int>>>& dp) {
        if (r <= 0) {
            return s == 0 ? 1 : 0;
        }
        if (i == (int)g.size()) {
            return s == 0 ? 1 : 0;
        }
        if (dp[i][r][s] != -1) {
            return dp[i][r][s];
        }
        long long ans = f2(g, p, i + 1, r, s, dp);
        if (g[i] <= r) {
            ans += f2(g, p, i + 1, r - g[i], max(0, s - p[i]), dp);
        }
        return dp[i][r][s] = ans % MOD;
    }

这里有个必须处理的细节：s − p[i] 要夹到 0。不夹的话 s 会一路减成负数，dp 表的下标跟着越界；夹到 0 之后，「还差 0」就等于「已经达标」，判定从 s <= 0 简化成 s == 0。

员工用光了（r ≤ 0）也直接返回，因为再做不了任何工作。这个分支和 i == g.length 那个分支的判定条件是一样的，谁先命中都行。

严格填表时，i 从 m−1 递减，r 和 s 也都从大到小扫。初始状态是「一件工作都不选」，这时候只要利润要求不大于 0 就算达标，所以 dp[r][0] = 1，从 r = 0 铺到 r = n。

// i 这一维滚掉：只剩「还剩多少员工 r」和「利润还差多少 s」
    int profitableSchemes(vector<int>& group, vector<int>& profit, int n, int minProfit) {
        vector<vector<int>> dp(n + 1, vector<int>(minProfit + 1, 0));
        for (int r = 0; r <= n; r++) {
            dp[r][0] = 1;
        }
        for (int i = (int)group.size() - 1; i >= 0; i--) {
            for (int r = n; r >= 0; r--) {
                for (int s = minProfit; s >= 0; s--) {
                    long long p1 = dp[r][s];
                    long long p2 = group[i] <= r ? dp[r - group[i]][max(0, s - profit[i])] : 0;
                    dp[r][s] = (p1 + p2) % MOD;
                }
            }
        }
        return dp[n][minProfit];
    }

实测（100 项工作、n = 100、minProfit = 100）：记忆化三维 1.1 ms、3.9 MiB；压缩二维 0.76 ms、39.8 KiB。这题的规模小一号，空间从 3.9 MiB 降到 39.8 KiB，省了 100 倍。

六、两道题压掉的是同一维

一和零压掉的是字符串下标 i，盈利计划压掉的是工作下标 i。两道题里这一维都排在最外面，而且都满足「本层只读下一层」，所以它是唯一能被滚掉的一维。另外两维是额度和要求，它们互相之间有依赖，压缩版里必须留在表上，而且要倒着扫。

反过来说，如果状态定义成 (z, o, i)、把 i 放在最里层，那谁也压不掉，只能老老实实开整叠表。谁在最外层不是随便定的。

两道题的时间复杂度都没变，压缩只动空间。这两个 O 里的 n 含义不同：一和零里是 1 的额度，盈利计划里是员工总数，别混着比较。

八、总结

容量维度有几个，可变参数就有几个，这是三维动态规划最直接的一类来源。写递归、加记忆化、改成严格位置依赖，这三步和二维完全一样。

压缩的对象是最外层那一维，判据是「本层只读下一层」。压完剩下两维还在同一张表上，只要它们之间存在依赖，就必须倒着扫，这条规矩从一维背包一路沿用到三维。

两个容易漏的地方：一个是 s 这类「要求」维度要夹到 0，不夹就下标越界；另一个是状态定义里谁放在最外层，放错了就没有可压的维度。

后面「每个格子的枚举代价不是 O(1)」这一类的题会越来越多，三维表也一样：表的大小乘上每格的枚举量，才是真实的时间。
