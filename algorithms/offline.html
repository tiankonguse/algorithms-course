离线查询

m 个询问「区间 a[l..r] 里大于 v 的数有几个」，把询问按 v 排序后只扫一遍数组，用树状数组在 O((n+m) log n) 内把所有答案一起算出来。

零、背景

前面几节的写法都是「来一个答一个」：分块、树状数组、线段树，接到查询就立刻算，算完再等下一个。这种叫在线。

这一节反过来：所有询问先全部读进来，按自己方便的顺序处理，算完再按原顺序输出。这种叫离线。

莫队也是离线，它重排的是询问的「处理次序」，换来两个指针少走点路。这里要重排的是另一个东西，询问里的阈值 v，换来的是数组的扫描状态能在询问之间接着用。

一、问题

有一个长度为 n 的数组 a，给 m 个询问，每个询问是三元组 (l, r, v)：

a[l..r] 中，有多少个数严格大于 v？

例子还是那个数组，下标从 1 开始：

a = [3, 1, 4, 1, 5, 9, 2, 6]

逐个看：#1 的区间是 [3, 1, 4, 1, 5]，大于 2 的是 3、4、5；#2 的区间是 [1, 4, 1, 5, 9, 2, 6]，大于 4 的是 5、9、6；#3 大于 5 的只剩 9 和 6。

要求的是 m 个询问一起给答案，而且 m 和 n 都能到 10⁵。

二、朴素做法

最直接的想法：每个询问都把 [l, r] 走一遍，数一数大于 v 的。

for (int k = 0; k < m; k++) {
    int ans = 0;
    for (int i = q[k].l; i <= q[k].r; i++)
        if (a[i] > q[k].v) ans++;
    out[k] = ans;
}

每个询问 O(n)，总共 O(n·m)。n = m = 10⁵ 时是 10¹⁰，做不动。

浪费在重复上：位置 3 被三个询问各扫了一次，但它是 4 这件事从头到尾没变过。

三、先把「大于 v」翻过来

在区间 [l, r] 里，「大于 v」和「小于等于 v」刚好互补：

「> v」的个数 = (r − l + 1) − 「≤ v」的个数

区间长度一眼就能算出来，于是问题变成求「a[l..r] 里有多少个数 ≤ v」。

这一步看着只是换个说法，其实很关键。「大于 v」这个集合随着 v 变大是缩小的，元素只能往外删；「小于等于 v」随着 v 变大是扩大的，元素只增不减。只增不减的集合，才好用「一个个加进来」的方式维护。

四、按 v 排序，只扫一遍

把所有询问按 v 从小到大排，把数组元素也按 a[i] 从小到大排，然后用一根指针在元素序列上从左往右走。

处理一个询问时，指针把值 ≤ v 的元素全部加进来；因为 v 是递增的，加进来的东西对后面的询问依然有效，指针从不回头。

可以发现，8 个元素在这三个询问里一共只被加入 6 次，剩下的两个压根没碰过。不是每个询问重新扫一遍，而是所有询问合起来扫一遍。

五、加进来的是位置，问的是区间

加进来的东西是「元素的位置」，不是元素的值。于是「[l, r] 里 ≤ v 的个数」就变成「已加入的位置里，落在 [l, r] 的有几个」。

这是个前缀和的事：把位置 i 记成 1，求区间和就是 sum(r) − sum(l−1)。而位置是动态加进来的，所以前缀和结构用树状数组，单点加 1、查前缀和都是 O(log n)。

写下来就是这几行：

// 1. 数组元素按值升序排，记下每个元素原来的位置
// 2. 询问按 v 升序排
// 3. 一根指针扫过去
ptr = 0;
for 每个询问 q (按 v 升序):
    while (ptr < n and 元素[ptr].值 ≤ q.v):
        tree.add(元素[ptr].位置, 1);    // 把这个位置标进树状数组
        ptr++;
    le = tree.sum(q.r) - tree.sum(q.l - 1);  // ≤ v 的个数
    q.答案 = (q.r - q.l + 1) - le;            // > v 的个数

七、代码

#include <bits/stdc++.h>
using namespace std;

const int N = 100005;
int n, m;
int a[N];
int c[N];                     // 树状数组

int lowbit(int x) { return x & (-x); }

void add(int i, int delta) {
    while (i <= n) { c[i] += delta; i += lowbit(i); }
}

int sum(int i) {
    int s = 0;
    while (i > 0) { s += c[i]; i -= lowbit(i); }
    return s;
}

struct Elem { int val, pos; };             // (值, 位置)
struct Query { int l, r, v, id; };         // (l, r, v, 原询问编号)

bool cmpE(const Elem& x, const Elem& y) { return x.val < y.val; }
bool cmpQ(const Query& x, const Query& y) { return x.v < y.v; }

int ans[N];

int main() {
    cin >> n >> m;
    for (int i = 1; i <= n; i++) cin >> a[i];
    vector<Elem> elems;
    elems.reserve(n);
    for (int i = 1; i <= n; i++) elems.push_back({a[i], i});
    sort(elems.begin(), elems.end(), cmpE);

    vector<Query> qs;
    qs.reserve(m);
    for (int i = 0; i < m; i++) {
        int l, r, v; cin >> l >> r >> v;
        qs.push_back({l, r, v, i});
    }
    sort(qs.begin(), qs.end(), cmpQ);

    int ptr = 0;
    for (const auto& q : qs) {
        while (ptr < n && elems[ptr].val <= q.v) {
            add(elems[ptr].pos, 1);
            ptr++;
        }
        int le = sum(q.r) - sum(q.l - 1);   // 区间 [l, r] 内 ≤ v 的个数
        ans[q.id] = (q.r - q.l + 1) - le;  // > v 的个数
    }

    for (int i = 0; i < m; i++) cout << ans[i] << '\n';
    return 0;
}

三个示例询问跑出来是 3、3、2，和第一节那张图一样。

八、复杂度分析

操作时间复杂度
元素按值排序O(n log n)
询问按 v 排序O(m log m)
加入元素（共 n 次，每次 add）O(n log n)
回答 m 个询问（每个两次 sum）O(m log n)
总时间O((n + m) log n)
朴素做法（对照）O(n·m)
额外空间O(n + m)

加入元素那一步为什么不乘 m：内层 while 看着像嵌套在询问循环里，但指针 ptr 全程只从 0 走到 n，加起来是 n 次，不是 m·n 次。

空间上，树状数组 O(n)，元素副本 O(n)，询问副本 O(m)，加起来 O(n + m)。

n = m = 10⁵ 时，从朴素的 10¹⁰ 降到 3×10⁶ 上下，差了三个多数量级。

九、换个问法

问「大于等于 v」「小于 v」的个数，改的是 while 里的比较符号和最后的减法，骨架不动。

问「等于 v」的个数，跑两遍：一遍算 ≤ v，一遍算 < v，两个结果相减。或者干脆按值相等分组，排序时把值相同的元素放在一块，用两个指针相减，一遍就够。

如果题目还带单点修改，就得把修改也一起离线下来，加一维时间，那是 CDQ 分治的事，已经超出这一节。

十、最后

这一套能成立，靠的是两个东西：一是把「大于 v」翻成「小于等于 v」，让集合随 v 单调增长；二是把这个增长过程摊到所有询问上，指针只走一遍。剩下的只是「区间内有多少个已加入的位置」，交给树状数组。

和莫队放一起看会更清楚：两者都是离线，都是重排询问，只是重排的维度不同。莫队按 l 所在的块和 r 排，省的是指针移动；这里按 v 排，省的是重复扫描。遇到「一堆询问 + 一个可以排序的维度」时，先想想能不能这样重排，往往就是突破口。

它的边界也明显：必须能先把所有询问读进来。如果题目要求「边改边问」、必须立刻回答，离线就用不上了。
