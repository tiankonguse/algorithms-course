国旗计划：环上的覆盖与倍增

一圈上有 n 条线段，题目保证它们盖满了整个环，而且谁也不完全包住谁。现在逐条问：一定要选我，那至少还得再选几条才能盖满一圈。n 到 2×10⁵，每条都要答一次。

零、问题

环上有 m 个点，编号 1 到 m，顺时针排列，m 号点的下一个是 1 号点。给定 n 条线段，第 x 条写成 (a, b)，表示从点 a 顺时针走到点 b 的这一段。两个保证：所有线段合起来能盖满整个环；任何一条线段都不完全在另一条内部。

对每条线段 x 求 ans[x]：一定选 x 的情况下，至少选几条线段能盖满整个环。n 条线段要逐个答一遍。

「互不包含」这个条件看着别扭，其实它是整套做法的地基。按左端点排序之后，右端点也跟着严格递增。否则左端点靠后却右端点更靠前的那条，就整个落在前一条里面了。有了单调性，后面那个双指针才成立。

一、破环成链：把绕圈写成一段直线

环上「顺时针从 a 到 b」有两种情况。a 不超过 b 时就是普通的一段；a 大于 b 时说明这段跨过了 m 号点回到 1 号点，把 b 加上一圈的长度 m 就拉直了。

拉直之后每条线段都变成 l < r 的一段，而且右端点不超过 l + m - 1：一段不会绕超过一整圈。按左端点排序，得到一串左端点递增、右端点也递增的线段。

接下来把每条线段整体右移一圈复制一份：第 i 条的复制品是 l + m 到 r + m，跟在第 i + n 号位置。这样「从第 i 条出发顺时针走一整圈」就变成了「在 2n 条线段组成的直线上往右走一段」，环不见了。

二、跳一步：双指针凑出第 0 列

现在的问题是：站在第 i 条线段上，下一根接力棒交给谁。贪心的答案是「左端点不超过我的右端点、且右端点最远的那条」，因为线段已经按左端点排好序，右端点又递增，这个「最远」就是左端点不超过 line[i].r 的最后一条。

所有 i 的这个问题的答案，一趟双指针就全出来了。指针 arrive 只进不退：i 往右走时 line[i].r 也单调不减，能接上的范围只会往右扩，不会缩回去。

点「下一步」一条一条扫过去，橙色是当前正在处理的线段，蓝色是 arrive 停的位置。右边一栏是「跳 1 步到哪」填出来的第 0 列。

arrive 从头到尾最多前进 2n 次，实测 n 等于 2×10⁵ 时它前进了 399999 次，正好等于 2n 减 1。这一步是 O(n) 的，也是整个算法里唯一一趟线性扫描。

三、倍增：一次跳过 2 的 p 次方条

有了「跳 1 步到哪」，就能造出「跳 2 的 p 次方步到哪」：stjump[i][p] = stjump[ stjump[i][p-1] ][p-1]。p 最大取到 floorLog(n)，n 等于 2×10⁵ 时是 17，数组开 18 列。

每条线段的答案从它的左端点出发：目标是盖满一圈，也就是从 line[i].l 一路盖到 line[i].l + m。p 从大到小试，跳过去之后右端点还没够着目标就真的跳。

// 一定选 i 号线段，至少再选几条能把整个环盖满
    int jump(int i) {
        int aim = line[i].l + m;      // 盖满一圈：从自己的左端点再走一整圈
        int cur = i, ans = 0;
        for (int p = power; p >= 0; p--) {
            int next = stjump[cur][p];
            // 跳 2 的 p 次方步之后右端点还没够着 aim，这一跳就值得走
            if (next != 0 && line[next].r < aim) {
                ans += 1 << p;
                cur = next;
            }
        }
        // ans 条跳过的 + 最后跨过 aim 的那条 + 自己
        return ans + 1 + 1;
    }

换一条起点线段，点「下一步」看 p 从 2 降到 0 的每一档：橙色是当前所在行与正在查的那一列，蓝色是这一档的落点。表右边三列就是倍增表本身。

最后那个 +1 +1 值得数一遍：循环里累加的 ans 是「跳过的线段条数」，循环结束时还差一条才能跨过目标，那是第一个 +1；自己这条从头到尾都算在答案里，那是第二个 +1。少写任何一个，全部答案都会少 1，实测抓取率 100%。

const int MAXN = 200001;
    // n 条线段复制一份是 2n 条，n = 2 * 10^5 时 power = 17，开 18 列
    const int LIMIT = 18;
    struct Seg { int id, l, r; };
    Seg line[MAXN << 1];
    int stjump[MAXN << 1][LIMIT];
    int n, m, power;

    void build() {
        for (int i = 1; i <= n; i++) {
            // 跨 0 点的线段：右端点补上一圈的长度，变成 l < r 的形式
            if (line[i].l > line[i].r) {
                line[i].r += m;
            }
        }
        sort(line + 1, line + n + 1, [](const Seg &a, const Seg &b) {
            return a.l < b.l;
        });
        for (int i = 1; i <= n; i++) {         // 复制一份，整体右移一圈
            line[i + n].id = line[i].id;
            line[i + n].l = line[i].l + m;
            line[i + n].r = line[i].r + m;
        }
        int e = n << 1;
        // 双指针：arrive 只进不退，凑出每条线段「跳 1 步」能到的最远线段
        for (int i = 1, arrive = 1; i <= e; i++) {
            while (arrive + 1 <= e && line[arrive + 1].l <= line[i].r) {
                arrive++;
            }
            stjump[i][0] = arrive;
        }
        for (int p = 1; p <= power; p++) {
            for (int i = 1; i <= e; i++) {
                stjump[i][p] = stjump[stjump[i][p - 1]][p - 1];
            }
        }
    }

四、复杂度分析

环节时间空间
跨 0 点线段补 m 并排序O(n log n)O(n)
复制一份O(n)O(n)
双指针求第 0 列O(n)O(n)
倍增填 2n 行表O(n log n)O(n log n)
n 次跳跃查询O(n log n)O(1)

总时间 O(n log n)，瓶颈在排序和填表。空间按题目上限算：n 等于 2×10⁵ 时表是 40 万行 × 18 列 = 720 万个 int，27.5 MB，加上线段数组（40 万 × 3 个 int，4.6 MB）和答案数组，合起来 32 MB 出头。

实测 best-of-3：n 等于 2×10⁵ 全程 25.75 毫秒，n 等于 10⁵ 是 11.35 毫秒。每条线段的查询要试 18 档（power + 1），其中真的跳出去平均 10.83 次，剩下 7 档是「够着了不动」。

五、几个会写错的地方

小数据（n 在 2 到 8、m 在 6 到 30）跑了一万一千多次查询，把常见笔误挨个灌进去量抓取率。

写法出错比例说明
忘记把跨 0 点的线段右端点加 m100.00%排序后右端点不再单调，双指针直接失效
末尾只写 +1100.00%答案整体少 1，每一条都错
判据写成 r <= aim7.35%恰好够着时多跳一次，只在边界上现形
累加写成 ans++1.09%只有 p 大于 0 的跳跃才看得出差别
arrive 每轮重置为 i0.00%与只进不退完全等价，右端点单调时两种写法逐格一致

最后一条值得留意。它看起来像 bug，实测一万一千多次查询一条都没错：右端点单调递增时，「从 i 开始一路推进」和「从上一次的 arrive 继续推进」到达的是同一个位置。留着它只是白跑一些循环，改掉它也不会更对。

前两条是真正的硬伤，而且错得一模一样：要么全部答案偏小，要么整张表的语义崩掉。写完之后拿一个跨 0 点的小样例手算一遍，这两类问题立刻现形。

六、总结

这道题的骨架是三步：跨 0 点的线段补 m 之后排序，把环拉成链；复制一份，让「绕一圈」变成「往前走一段」；双指针一趟凑出「跳 1 步到哪」，剩下的交给倍增。

「互不包含」这个条件在这里起了两个作用：它保证了排序后右端点单调，双指针才成立；也保证了复制之后整串 2n 条线段依旧按右端点递增，arrive 只进不退才安全。题目给的条件在这两步里都用得上。

答案的口径要盯住：ans + 1 + 1 里，第一个 1 是跨过目标的那条，第二个 1 是自己。跳跃判据是「跳过去还不够着」，恰好够着时不跳。
