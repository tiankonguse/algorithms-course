连续结构与跳转结构

数据结构名目太多了，从链表、队列、栈一路列到可持久化线段树、树链剖分、后缀数组。往回退一步看，它们的零件其实只有两种：一块挨着放的内存，和一个「下一个是谁」的跳转。这一讲把这两种零件拆开。

零、背景

先说一件跟选题有关的事。算法可以粗分成两类。一类精确求解，算出来就是唯一答案；另一类不追求精确，只要足够接近，而且时间可控。

前者叫硬计算类。大厂的算法笔试面试、ACM 以及形式类似的比赛，考的都是这类。后者叫软计算类，模糊逻辑、神经网络、进化计算、概率理论、群体智能都在里面。

本讲往后的内容都属于硬计算类。它们的零件意外地少。

数据结构看着千变万化，底下其实只有两样东西：连续结构，跳转结构。任何一个数据结构都一定是这两个拼出来的，没有例外。

一、连续结构

连续结构就是数组：申请一块连续的字节，元素挨着放。

一个 int 是 4 个字节。所以第 i 个元素的地址是起始地址加上 i 乘 4，一次乘法一次加法就到了，中间不用经过任何别的元素。

代价在另一头。要往中间塞一个元素，后面的所有元素都得往后挪一格，挪出来的那一格才轮到新元素。

还有一个好处容易被忽略：元素挨着放，读第 i 个的时候，它后面那十几个往往已经被一起取进缓存了。顺序往下走几乎不用再等内存。

二、跳转结构

跳转结构不要求挨着。每个节点自己记住「下一个是谁」，节点待在哪儿无所谓。

好处是插入不动别人：改两个指针就够了，前后的元素原地不动。

代价还是在一头。地址公式没了，要拿第 k 个，只能从头一个一个跳过去。

散得有多彻底可以量出来。实测往链表里连续取相邻两个节点的地址，差值是 +16、−368、+16、−224、+16 ， 有的正好挨着，有的隔了几百字节，方向还前后反。

每个节点的开销也不一样。n 个 int 连续放是 4n 字节；struct Node { int val; Node* next; } 一个节点 sizeof 出来是 16 字节，n 个就是 16n 字节，整整四倍。多出来的 12 字节里，8 字节是指针，4 字节是内存对齐补的空位。

三、代价各落在另一头

两种结构到底差在哪，跑一遍最直观。下面四组都是在同一台机器上实测的耗时。

取第 k 个，数组赢四万倍。随机访问一亿次花 17.85 毫秒，折算两万次约 0.004 毫秒；链表做同样的事平均要跳 10018 步（n = 20000 时平均就是 n/2），两万次花掉 195.7 毫秒。

往头部插二十万个数，结果反过来。数组每插一个都要把已有的全部后移，累计搬了 19999900000 个元素，也就是 n(n−1)/2，耗时 1232 毫秒；链表每次只改两个指针，2.93 毫秒。差 420 倍。

换成往随机位置插十万个数，又翻回来了。两种结构移动的量都是 n²/4 ≈ 25 亿，数组 145 毫秒，链表 15000 毫秒。搬移是一整块连续字节被整段搬走，跳转是一步一步走，每一步都可能扑空。这里数组反而快了两个数量级。

顺序遍历也一样：连续数组走完二百万个元素 0.10 毫秒，new 出来的链表走同样长要 2.17 毫秒，22 倍。

把这四组收成一句话：两种结构的区别不在于哪个更快，而在于各自把代价藏在了哪一步。数组藏在搬移上，链表藏在寻址上。

四、用连续结构拼出跳转结构

竞赛里几乎不写 new Node。一是慢，二是散落在堆上的节点没法预判占多少。常见做法是拿三个数组把链表拼出来：val[] 存值，next[] 存「下一个的下标」，head 存第一个的下标。

跳转关系本来只需要一个「指向谁的编号」，而编号天然可以做下标。于是连续结构直接把跳转结构装了进去。

注意这里的 next 存的是下标而不是地址，所以 −1 就能表示「后面没有了」，判断起来比空指针还省事。

// 跳转结构的节点：值和「下一个是谁」分开存也能写，这里合并成一个结构体数组
    struct Node {
        int val;
        int next;      // -1 表示后面没有了
    };

    const int MAXN = 1000005;
    Node node[MAXN];
    int head = -1;     // 第一个节点的下标，-1 表示空表
    int tot = 0;       // 已经用掉多少个下标

    // 头部插入：新节点指向老的头，再让 head 指向新节点
    void pushFront(int v) {
        node[tot].val = v;
        node[tot].next = head;
        head = tot;
        tot++;
    }

    // 删除第一个值等于 v 的节点：先找到它，改它前驱的 next
    void eraseFirst(int v) {
        int cur = head, pre = -1;
        while (cur != -1 && node[cur].val != v) {
            pre = cur;
            cur = node[cur].next;
        }
        if (cur == -1) {
            return;                 // 没找到
        }
        if (pre == -1) {
            head = node[cur].next;  // 删的是头节点
        } else {
            node[pre].next = node[cur].next;
        }
    }

三个数组都是连续结构，head 和 next 合起来是跳转关系。它既是上一节说的跳转链表，又整整齐齐躺在一块内存里。

实测这么拼出来的链表，顺序遍历二百万个节点只要 0.59 毫秒 ， 比 new 出来的版本快三倍多，只比纯数组慢一点。付出的代价是必须提前知道最多要用多少节点。

四步里没有一步移动过已有的元素。所谓「插入 O(1)」，说的就是这四步都不随长度变化。

五、剩下的结构都是这两样拼的

认零件的方法很简单：先找哪些东西是按挨着放的，再看剩下的关系是走过去的还是算出来的。

二叉堆：连续 + 算出来的跳转

堆是一棵完全二叉树。完全二叉树的形状是固定的，所以可以塞进一个连续数组，父子关系不用指针，拿下标算。

// 二叉堆：完全二叉树的形状天然适合塞进连续数组
    // 下标 i 的父亲是 i >> 1，两个儿子是 i << 1 和 i << 1 | 1
    const int MAXN = 1000005;
    int heap[MAXN];
    int siz = 0;

    // 上浮：新元素放在末尾，一路跟父亲比
    void push(int v) {
        heap[++siz] = v;
        int i = siz;
        while (i > 1 && heap[i] < heap[i >> 1]) {
            swap(heap[i], heap[i >> 1]);
            i >>= 1;
        }
    }

    // 下沉：拿末尾补上堆顶，一路跟较小的儿子比
    int pop() {
        int top = heap[1];
        heap[1] = heap[siz--];
        int i = 1;
        while ((i << 1) <= siz) {
            int j = i << 1;
            if (j + 1 <= siz && heap[j + 1] < heap[j]) {
                j++;
            }
            if (heap[j] >= heap[i]) {
                break;
            }
            swap(heap[i], heap[j]);
            i = j;
        }
        return top;
    }

i >> 1 是父亲，i << 1 和 i << 1 | 1 是两个儿子。跳转关系被压缩成了一次位移。

Trie：每一行连续，层与层之间跳转

Trie 的每个节点要接 26 条边。写成二维数组的每一行是一个节点，26 个格子连续放；从 u 走到 son[u][c] 是一次跳转。

// Trie：每个节点是连续的一行 26 个格子，走到儿子是一次跳转
    const int MAXN = 500005;
    int son[MAXN][26];   // son[u][c] = 0 表示 u 没有 c 这条边
    int cnt[MAXN];       // 以这个节点结尾的单词数
    int tot = 1;         // 根节点是 1，tot 从 1 开始

    void insert(const string& s) {
        int u = 1;
        for (int i = 0; i < (int)s.size(); i++) {
            int c = s[i] - 'a';
            if (son[u][c] == 0) {
                son[u][c] = ++tot;
            }
            u = son[u][c];
        }
        cnt[u]++;
    }

    int query(const string& s) {
        int u = 1;
        for (int i = 0; i < (int)s.size(); i++) {
            int c = s[i] - 'a';
            if (son[u][c] == 0) {
                return 0;
            }
            u = son[u][c];
        }
        return cnt[u];
    }

son[u][c] == 0 表示这条路没有。这里 0 同时是「空」和「根节点是 1」的原因，跟上一节 next 用 −1 是同一个手法。

并查集：只剩跳转

并查集连值都不存，整个结构就是一条跳转关系。每个点记住自己的父亲，根节点的父亲是自己。

// 并查集：只有一条 int 数组，跳转关系全靠下标
    const int MAXN = 1000005;
    int fa[MAXN];

    void build(int n) {
        for (int i = 1; i <= n; i++) {
            fa[i] = i;
        }
    }

    // 找代表节点，顺手把路径上所有点直接挂到根上
    int find(int x) {
        if (fa[x] != x) {
            fa[x] = find(fa[x]);
        }
        return fa[x];
    }

    bool merge(int x, int y) {
        int rx = find(x), ry = find(y);
        if (rx == ry) {
            return false;
        }
        fa[rx] = ry;
        return true;
    }

find 那一行递归回来的时候顺手把沿途所有点直接挂到根上，这叫路径压缩。跳转的步数被压短了，后面再走几乎是一步到顶。

图的邻接表是这四个里最实用的一个：head[u] 是连续的一维数组，一个下标就能定位到点 u 的第一条边；to[] 和 next[] 是跳转链。点数到 10⁶、边数到 10⁶ 的图，靠的就是这个拼法。

六、怎么选

第一条判据是「要不要按下标访问」。需要 nth_element 式的随机访问，连续结构没有别的选择。

第二条是「插在哪儿、由谁给出」。如果每次插入的位置已经给到了节点本身（比如在某个已知节点后面接一条边），跳转结构的插入是 O(1)；如果给的是下标，跳转结构还得先花 O(k) 走过去。

第三条是常数。前面实测已经给过反例：理论复杂度同为 O(n²) 的两种写法，往随机位置插十万个数，数组比链表快两个数量级。数量级对得上还不够，常数差得远时结果完全相反。

第四条是能不能预估规模。能预估就开静态数组，既快又省；预估不了再考虑动态申请。

复杂度分析

把这一讲出现的结构和操作列在下面。n 是元素个数，k 是要访问或插入的下标。

操作连续结构（数组）跳转结构（链表）说明
取下标为 k 的元素O(1)O(k)，最差 O(n)数组一次乘法算地址；链表要从头跳 k 步，平均 n/2 步
往头部插入O(n)O(1)数组要把已有的 n 个全部后移；链表改两个指针
往下标 k 处插入O(n − k)O(k) 寻址 + O(1) 接入两者的移动量都随位置变化，方向相反
删除下标 k 的元素O(n − k)O(k) 寻址 + O(1) 断链删除本身都是常数，贵的是找位置和收拾空位
顺序扫一遍全部 n 个O(n)O(n)同为 O(n)，实测常数差 22 倍（new 版），静态数组版只差 6 倍
额外空间每个元素 4 字节每个节点 16 字节（new）静态数组版每个节点 8 字节，但要一次性预估上限

建表本身都不超过 O(n)：三组数组一次性开好，head 置 −1、fa[i] = i、heap 的 siz 置 0，之后的每次操作才是上面表里的代价。

七、最后

后面讲链表、栈、队列、堆、并查集、Trie、邻接表的时候，可以顺手认一下哪部分是连续结构、哪部分是跳转结构。零件认出来了，它的复杂度基本也就跟着出来了。
