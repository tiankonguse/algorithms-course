链表的原地改造：k 组反转、复制随机指针、链表排序

上一讲的三个题只在指针速度上做文章，这一讲的三道题要动结构：把一段一段的链翻过来、把副本穿进原链再拆出来、把相邻有序段两两合并。全程不借容器，节点一个都不新建（复制题除外）。

零、背景

这三道题有个共同点：用容器都能解，而且都很短。k 组反转可以收进数组再重建，复制随机指针可以开哈希表，排序可以把值收进数组排完写回。

题目真正的要求是额外空间 O(1)。链表能做到这一点，靠的是它的结构本身就是可以拆装的：改一个 next 指针就能把一段链翻过来，数组上做不到这种事。

一、每 k 个节点一组反转

给一条链和一个 k，从头开始每 k 个节点一组反转，最后剩下不足 k 个的那截保持原样。

拆成两个动作。teamEnd 从 s 往下数 k 个节点，返回这一组的尾巴；不够 k 个就返回空。reverse 负责把 [s, e] 这一段原地翻转。

reverse 的写法值得看一遍：先把 e 往后挪一格（e = e->next），再从 s 开始走标准的三指针反转，循环条件是 cur != e。反转结束时 s 变成了这一组的尾巴，把它接到 e 上，也就是接到下一组的开头。

第一组要单独处理，因为它的尾巴决定整条链的新头：head = end。之后的每组都是同样的收尾动作：反转完把上一组的尾巴 lastTeamEnd 接到这一组的新头 end 上。

代价很好估：每个节点一次 cur->next = pre，每组一次 s->next = e。n = 10、k = 3 时是 12 次赋值（9 + 3）。n = 100 万实测 k = 2 用 2.51ms、k = 3 用 2.07ms、k = 100 用 2.00ms，几乎不随 k 变。

两个写错的地方，我都试过。

1）最后不足 k 个的那截也反转。n = 10、k = 4 时的正确结果是 [4,3,2,1,8,7,6,5,9,10]，错版给出 [4,3,2,1,8,7,6,5,10,9]。随机 3000 组（k 从 2 到 6）里有 35.07% 能抓到这个差别。

2）reverse 里漏掉 s->next = e。这一组的尾巴悬空，n = 10、k = 3 时整条链只剩 [3,2,1]，后面 7 个节点全丢了。这个错反而好，一眼看得出来。

struct ListNode {
        int val;
        ListNode* next;
    };

    // 当前组的开始节点是 s，往下数 k 个找到当前组的结束节点返回
    ListNode* teamEnd(ListNode* s, int k) {
        while (--k != 0 && s != nullptr) s = s->next;
        return s;
    }

    // s -> a -> b -> c -> e -> 下一组的开头
    // 调整成 : e -> c -> b -> a -> s -> 下一组的开头
    void reverse(ListNode* s, ListNode* e) {
        e = e->next;
        ListNode* pre = nullptr;
        ListNode* cur = s;
        ListNode* next = nullptr;
        while (cur != e) {
            next = cur->next;
            cur->next = pre;
            pre = cur;
            cur = next;
        }
        s->next = e;                          // 原来的头接上下一组
    }

    ListNode* reverseKGroup(ListNode* head, int k) {
        ListNode* start = head;
        ListNode* end = teamEnd(start, k);
        if (end == nullptr) return head;      // 第一组就不够 k 个
        head = end;                           // 第一组要换头
        reverse(start, end);
        ListNode* lastTeamEnd = start;        // 翻转后 start 成了这一组的尾
        while (lastTeamEnd->next != nullptr) {
            start = lastTeamEnd->next;
            end = teamEnd(start, k);
            if (end == nullptr) return head;  // 剩下不足 k 个，保持原样
            reverse(start, end);
            lastTeamEnd->next = end;          // 上一组的尾接这一组的新头
            lastTeamEnd = start;
        }
        return head;
    }

二、复制带随机指针的链表

每个节点除了 next 还有一个 random，指向链上任意一个节点或者空。要复制出一条结构完全相同的新链，新节点必须是新申请的。

哈希版最直接：第一遍建「老节点 → 新节点」的映射，第二遍连 next 和 random。额外空间 O(n)。

穿插版三步走，一步都不需要额外结构。

1）在每个老节点后面插一个同值副本，链表变成 1 → 1' → 2 → 2' → …

2）借这个位置关系设 random：老节点 cur 的 random 往后走一个就是它的副本，所以 copy->random = cur->random->next。

3）拆成两条链：老节点接老节点，副本接副本。

实测 n = 100 万：穿插法 22.5ms，哈希法 382.9ms，差 17 倍。哈希表的桶数组单独占 12.6 MB，副本本身 22.9 MB（sizeof 是 24 字节，一个 int 加两个指针）。

穿插法的代价是它临时改了原链表。别的线程正在读这条链时不能用；单线程里用完拆回去，调用方看不出区别。5000 组随机数据里两法结果一致，拆分之后原链表也完好。

struct Node {
        int val;
        Node* next;
        Node* random;
    };

    // 三步：穿插副本 -> 借位置关系设 random -> 拆开
    Node* copyRandomList(Node* head) {
        if (head == nullptr) return nullptr;
        Node* cur = head;
        Node* next = nullptr;
        while (cur != nullptr) {                          // 1) 1 -> 1' -> 2 -> 2' -> ...
            next = cur->next;
            cur->next = new Node(cur->val);
            cur->next->next = next;
            cur = next;
        }
        cur = head;
        Node* copy = nullptr;
        while (cur != nullptr) {                          // 2) 老节点的 random 的下一个就是副本的 random
            next = cur->next->next;
            copy = cur->next;
            copy->random = cur->random != nullptr ? cur->random->next : nullptr;
            cur = next;
        }
        Node* ans = head->next;
        cur = head;
        while (cur != nullptr) {                          // 3) 拆成两条链
            next = cur->next->next;
            copy = cur->next;
            cur->next = next;                             // 老链恢复
            copy->next = next != nullptr ? next->next : nullptr;
            cur = next;
        }
        return ans;
    }
// 用哈希表：一遍建映射，二遍连指针，额外空间 O(n)
    Node* copyRandomListHash(Node* head) {
        unordered_map<Node*, Node*> mp;
        mp[nullptr] = nullptr;
        Node* cur = head;
        while (cur != nullptr) {
            mp[cur] = new Node(cur->val);
            cur = cur->next;
        }
        cur = head;
        while (cur != nullptr) {
            mp[cur]->next = mp[cur->next];
            mp[cur]->random = mp[cur->random];
            cur = cur->next;
        }
        return mp[head];
    }

三、在链表上排序

要求三条：时间 O(n log n)，额外空间 O(1)，还要稳定。数组上凑不齐这三条：归并要 O(n) 的辅助数组，快排不稳定而且最坏是 O(n²)。链表上可以，因为合并两段有序链只需要改指针。

自底向上归并：step 从 1 开始每轮翻倍，每轮把相邻的两个长为 step 的有序段合并成 2·step。n = 100 时走 7 轮，n = 10 万时 17 轮，也就是 ⌈log₂ n⌉。

递归版不能用。递归归并要 O(log n) 的栈，正卡在空间要求上。

merge 的过程就是归并排序那个 merge：先挑小的当头，之后每次比较取小的接上，一侧耗尽就把另一侧整段接上去。稳定性全在那个等号上：相等时取左边的，原始的先后顺序就保住了。

等号写成 < 会怎样？实测 3000 组随机数据，值域 V = 2 时 2962 组顺序被打乱，V = 3 时 2935 组，V = 5 时 2902 组。写成 <= 时 0 组。

主循环里第一组单独处理，因为合并出来的头就是整条链的新头；后面每组的头都要靠 lastTeamEnd->next 接上。某轮最后剩下一截凑不成一组时，直接接在末尾就完事。

比较次数实测：n = 10 万 1466427 次，约 0.86·n·log₂n。

时间（n = 100 万）量了三档：自底向上 157.5ms，递归版 91.1ms，收集进数组用 std::sort 排完再写回 44.9ms。数组版最快，但它用了 O(n) 的数组；自底向上比递归版慢 1.7 倍，慢在每轮都要从头扫一遍找分组边界，还要反复断开重连。省下的那 O(log n) 栈，是拿常数换的。

ListNode* start;   // merge 之后整段的头
    ListNode* end;     // merge 之后整段的尾

    // 包括 s 在内往下数 k 个节点返回，不够就返回最后数到的非空节点
    ListNode* findEnd(ListNode* s, int k) {
        while (s->next != nullptr && --k != 0) s = s->next;
        return s;
    }

    // l1...r1 与 l2...r2 是两段有序链，原地合并，头尾写进 start / end
    void merge(ListNode* l1, ListNode* r1, ListNode* l2, ListNode* r2) {
        ListNode* pre;
        if (l1->val <= l2->val) {             // 取等号，相等时先拿左边，稳定
            start = l1; pre = l1; l1 = l1->next;
        } else {
            start = l2; pre = l2; l2 = l2->next;
        }
        while (l1 != nullptr && l2 != nullptr) {
            if (l1->val <= l2->val) { pre->next = l1; pre = l1; l1 = l1->next; }
            else { pre->next = l2; pre = l2; l2 = l2->next; }
        }
        if (l1 != nullptr) { pre->next = l1; end = r1; }
        else { pre->next = l2; end = r2; }
    }

    ListNode* sortList(ListNode* head) {
        int n = 0;
        ListNode* cur = head;
        while (cur != nullptr) { n++; cur = cur->next; }
        ListNode *l1, *r1, *l2, *r2, *next, *lastTeamEnd;
        for (int step = 1; step < n; step <<= 1) {
            l1 = head;                        // 第一组要决定整条链的头，单独处理
            r1 = findEnd(l1, step);
            l2 = r1->next;
            r2 = findEnd(l2, step);
            next = r2->next;
            r1->next = nullptr;
            r2->next = nullptr;
            merge(l1, r1, l2, r2);
            head = start;
            lastTeamEnd = end;
            while (next != nullptr) {
                l1 = next;
                r1 = findEnd(l1, step);
                l2 = r1->next;
                if (l2 == nullptr) { lastTeamEnd->next = l1; break; }   // 不足一组直接接
                r2 = findEnd(l2, step);
                next = r2->next;
                r1->next = nullptr;
                r2->next = nullptr;
                merge(l1, r1, l2, r2);
                lastTeamEnd->next = start;
                lastTeamEnd = end;
            }
        }
        return head;
    }

四、复杂度分析

题目时间额外空间说明
每 k 个一组反转O(n)O(1)赋值 n + ⌊n/k⌋ 次；n = 100 万约 2ms，与 k 无关
复制随机指针（穿插）O(n)O(1)三趟扫描；n = 100 万 22.5ms
复制随机指针（哈希）O(n)O(n)两趟扫描；n = 100 万 382.9ms，桶数组 12.6 MB
链表排序（自底向上）O(n log n)O(1)⌈log₂ n⌋ 轮，每轮扫一遍；n = 100 万 157.5ms
链表排序（递归归并）O(n log n)O(log n)栈深度 log₂ n；n = 100 万 91.1ms，比自底向上快
链表排序（数组辅助）O(n log n)O(n)std::sort；n = 100 万 44.9ms，最快但不满足要求

三个题的时间都是线性的或者 n log n，要记的是空间那一列。O(1) 的写法要求你把每一组、每一个副本的位置关系都想清楚。

五、总结

k 组反转：teamEnd 找组尾，reverse 翻转后把这一组的老尾巴接到下一组开头。第一组要换头，最后不足 k 个的那截不动。

复制随机指针：把副本插在老节点后面，random 就变成了「老 random 的下一个」，拆开时两链各自还原。比哈希法快 17 倍，代价是临时改原链表。

链表排序：自底向上归并，step 翻倍，merge 里取 <= 保证稳定。这是数组上做不到、链表上能做到的一个例子。

链表类的问题就到这里。快慢指针这套手法后面在数组和图上还会再见到，比如判环推广到判重复、找中点推广到分治。
