堆结构和堆排序

把一棵完全二叉树塞进数组里，每个节点都不小于它的所有后代，就得到了大根堆。靠两次调整就能把任意数组排成有序，整体 O(n log n)，额外空间 O(1)。

零、背景

堆的底层是一棵完全二叉树，但存的时候不用指针，直接按层序放进数组。这样做的好处是父子关系全靠下标算，不需要额外存地址。

下标从 0 开始时，节点 i 的父亲是 (i−1)/2，左孩子是 2i+1，右孩子是 2i+2。整数除法自动向下取整，根节点 i=0 的父亲算出来还是 0，不会越界。

一、大根堆

大根堆的要求只有一条：每个节点的值都不小于它的所有后代。根节点是整棵树里最大的，每个子树的根也是那棵子树里最大的。

小根堆反过来，每个节点不大于所有后代。两者的调整逻辑完全对称，把比较符翻个方向就行。后面统一按大根堆讲。

维持堆性质靠两个操作：新元素进来时往上浮（heapInsert），某个元素变小时往下沉（heapify）。单次调用都是 O(log n)，因为完全二叉树的高度是 ⌊log₂n⌋。

二、向上调整 heapInsert

新元素放在数组末尾，也就是树的最后一个位置。然后不断跟父亲比：比父亲大就交换，爬到父亲的位置继续比；直到不比父亲大，或者已经到了根。

循环条件写 arr[i] > arr[(i−1)/2]，i=0 时父亲也是 0，自己跟自己比不成立，循环自然停，不用单独判越界。

void heapInsert(int i) {
        while (arr[i] > arr[(i - 1) / 2]) {
            swap(i, (i - 1) / 2);
            i = (i - 1) / 2;
        }
    }

三、向下调整 heapify

当某个位置的元素变小了（比如堆顶被拿走后，把末尾元素挪到堆顶），它可能比孩子小，需要往下沉。做法是：在左右孩子里挑较大的那个，如果它比当前元素大，就交换，当前元素落到孩子的位置继续比；直到两个孩子都不比它大，或者已经没有孩子。

先算左孩子下标 l=2i+1，右孩子就是 l+1。best 先取较大的孩子，再跟当前元素比，取三者中最大的下标。如果 best 就是 i，说明当前元素已经比两个孩子都大，停。

void heapify(int i, int size) {
        int l = i * 2 + 1;
        while (l < size) {
            int best = l + 1 < size && arr[l + 1] > arr[l] ? l + 1 : l;
            best = arr[best] > arr[i] ? best : i;
            if (best == i) break;
            swap(best, i);
            i = best;
            l = i * 2 + 1;
        }
    }

四、堆排序

堆排序分两步：先把整个数组建成大根堆，然后不断把堆顶的最大值换到末尾、缩小堆范围、对新堆顶做一次 heapify。每一轮都把当前最大值放到它的最终位置，n−1 轮后整个数组有序。

建堆的两种写法

第一种是从左到右逐个 heapInsert，相当于把元素一个一个插进堆里。第 i 个元素最多上浮 log₂i 层，总代价是 log₁1 + log₂2 + … + log₂n，放缩后是 O(n log n)。

void heapSort1() {
        for (int i = 0; i < n; i++)
            heapInsert(i);
        int size = n;
        while (size > 1) {
            swap(0, --size);
            heapify(0, size);
        }
    }

第二种是从右到左倒着对每个位置做 heapify。叶子节点（下标大于 n/2 的）没有孩子，天然满足堆性质，不用管。从最后一个非叶节点开始倒着来，处理某个节点时它的左右子树已经是堆了，一次下沉就能让整棵子树成堆。

void heapSort2() {
        for (int i = n - 1; i >= 0; i--)
            heapify(i, n);
        int size = n;
        while (size > 1) {
            swap(0, --size);
            heapify(0, size);
        }
    }

两种写法建好的堆是同一个，但代价差不少。实测 n=100 万时，顶到底建堆做了约 228 万次比较，底到顶只做了约 188 万次，比值约 1.21。n 越大差距越明显，因为顶到底的上浮路径集中在树的高层（路径长），底到顶的下沉路径集中在树的低层（路径短）。

调整阶段

建堆之后，堆顶是全局最大值。把它和数组末尾交换，最大值就到了最终位置。然后堆的有效范围缩小一格（size−−），新堆顶是刚才换上来的末尾元素，对它做一次 heapify 就能恢复堆性质。重复 n−1 次，数组从后往前依次被最大值填满。

这一步的代码在两个 heapSort 里完全一样，都是 while(size > 1) { swap(0, --size); heapify(0, size); }。每轮 heapify 最多下沉 log n 层，n−1 轮就是 O(n log n)。

五、为什么底到顶建堆是 O(n)

直觉上 n 个节点各做一次 heapify，每次 O(log n)，应该是 O(n log n)。但大部分节点的下沉距离很短。

把树按层看：倒数第一层（叶子）有 n/2 个节点，下沉距离 0；倒数第二层有 n/4 个，最多下沉 1 层；倒数第三层有 n/8 个，最多下沉 2 层。总代价是 n/4×1 + n/8×2 + n/16×3 + …，这是一个等比级数，加起来小于 n。

实测 n=100 万时，底到顶建堆的总下沉距离约 105 万 = 1.05n，跟理论上界 2n 对得上。顶到底建堆则是约 228 万 = 2.28n，而且它的复杂度是 Θ(n log n)，n 变大时比值会继续增长。

堆排序是原地排序，额外空间只有几个临时变量。它不稳定：交换堆顶和末尾时，相等元素的相对顺序可能被打乱。实测 n=100 万时 heapSort2 约 48ms，std::sort 约 43ms，差距不大；但堆排序的缓存不友好（heapify 跳着访问数组），实际常数比快排大。

总结

堆的本质是完全二叉树塞进数组，父子关系全靠下标算。大根堆要求每个节点不小于所有后代，靠 heapInsert（上浮）和 heapify（下沉）两个操作维持。

堆排序分两步：建堆 + 调整。建堆有两种写法，顶到底逐个 heapInsert 是 O(n log n)，底到顶倒着 heapify 是 O(n)。后者快在大部分节点下沉距离很短，等比级数加起来小于 n。调整阶段每轮把堆顶最大值换到末尾，n−1 轮后有序，O(n log n)。

整体 O(n log n)、额外空间 O(1)、不稳定。堆结构本身比堆排序更有用，后面讲优先队列、Top-K、合并多路有序链表时会反复用到 heapInsert 和 heapify。
