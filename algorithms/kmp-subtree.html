另一棵树的子树：把树拍成序列再匹配

判断 root 里有没有和 subRoot 结构、节点值都一样的子树。笨办法是把 root 的每个节点都当起点做一次全等递归，六万节点的链上要跑 5321 ms。先把两棵树都拍成先序序列，判定就变成「s2 是不是 s1 的子串」，KMP 上场，2.033 ms 收工。

零、先看看暴力有多贵

暴力的写法是两层递归：外层枚举 root 的每个节点当起点，内层做一次「这两棵树是不是完全一样」的判断。两边都空算一样，一边空一边不空算不一样，都不空就比完当前值再递归比左右孩子。

// 暴力：t1 的每个节点都当一次起点，做一次「两棵树是否完全一样」的递归
    bool same(vector<int> val, vector<int> left, vector<int> right, int a, int b) {
        if (a == -1 && b == -1) {
            return true;
        }
        if (a == -1 || b == -1) {
            return false;
        }
        return val[a] == val[b]
            && same(val, left, right, left[a], left[b])
            && same(val, left, right, right[a], right[b]);
    }

    bool isSubtree(int t1, int t2) {
        if (t2 == -1) {
            return true;
        }
        if (t1 == -1) {
            return false;
        }
        return same(t1, t2) || isSubtree(left[t1], t2) || isSubtree(right[t1], t2);
    }

root 有 n 个节点、subRoot 有 m 个节点时，外层 n 个起点、内层每个最多 m 次，代价 O(n · m)。链状的树能把这一项吃满：n = 60000、m = 30000 时实测 5321.653 ms。

一、先序序列化，空指针也要记

先序遍历人人会写：先读当前节点，再递归左右子树。要把树变成序列，只多一件事：遇到空指针也要写一个占位符进去。

拿 root = [3,4,5,1,2] 说，先序走下来是 3、4、1、两个空、2、两个空、5、两个空，一共 11 项。subRoot = [4,1,2] 是 7 项，它正好是前一段序列里从下标 1 开始的连续 7 项。

序列长度有个定值：非空节点数为 c 时，序列恰好是 2c + 1 项。c 个节点各写一项，剩下的是空指针；c 个节点一共 2c 个孩子位，其中 c − 1 个被别的节点占掉，空着的正好是 c + 1 个。

这个 2c + 1 后面要用。它保证「一段长度恰好是 2c + 1 的序列」和「一棵有 c 个节点的完整子树」是一回事。

二、占位符不能省

省掉空指针的写法很常见，也很容易踩坑。看这一对：root = [1,2]，subRoot = [1,null,2]。前者的 2 是左孩子，后者的 2 是右孩子，结构完全不同，真值是「不是子树」。可省掉空指针后两条序列都写成 1、2，子串匹配会说是。

2 万组随机树对上，省掉空指针的错法有 13.72% 跟真值对不上。补上占位符之后，上面那对分别是 1 2 # # # 和 1 # 2 # #，第三项就分开了。

用 int 存 token、拿一个哨兵值表示空是同一个坑的另一副样子：节点值一旦能取到那个哨兵，两者就分不开了。用 string 或者可空类型把「值」和「空」分成两个类型，这类问题一次消失。

三、子树为什么等价于序列里的一段

先序序列里，某个节点的整棵子树一定占着连续的一段，这是先序遍历的性质。麻烦的是反方向：KMP 在 s1 中间找到 s2，凭什么说那个位置是一棵子树的根？

这里有个细节值得推一遍。设 s1[p..p+L−1] 与 s2 完全一致，L = 2c₂ + 1。s1[p] 不可能是占位符（s2 第一项是 subRoot 的值），它是某个节点 u。

先证 L 不会更小。如果 s1[p..p+L−1] 是 u 子树序列的真前缀，那这一段里占位符的个数不会比节点值多。理由是先序遍历走到中途时，总有至少一个孩子位还空着没填，也就是「1 + 已写节点数 − 已写占位符数 ≥ 1」，化简得占位符数 ≤ 节点值数。可 s2 是一棵完整树的序列，它的占位符恰好比节点值多一个。两边矛盾。

再证 L 不会更大。如果 L > 2 · size(u) + 1，那 u 子树的完整序列就成了 s2 的真前缀，把上一段的论证反过来说一遍，同样矛盾。

于是 L = 2 · size(u) + 1，s1[p..p+L−1] 正是 u 的整棵子树，而它每一项都和 s2 相等。所以「s2 出现在 s1 里」与「subRoot 是 root 的某棵子树」等价，一个不多一个不少。

四、KMP 上场

序列里的每一项不再是字符，换成了一个值或者一个空。比较函数先分类型再比值，剩下的主流程和 next 数组一个字都不用改。

// 先序序列化，空指针也要记一个占位符
    // 用 vector<string> 存，空指针写成 "#"，节点值写成它的十进制串
    void serial(vector<int> val, vector<int> left, vector<int> right,
                int u, vector<string>& path) {
        if (u == -1) {
            path.push_back("#");
            return;
        }
        path.push_back(to_string(val[u]));
        serial(val, left, right, left[u], path);
        serial(val, left, right, right[u], path);
    }
// 两个 token 相等：都为空，或者都不空且串相同
    bool isEqual(string a, string b) {
        if (a == "#" && b == "#") {
            return true;
        }
        if (a != "#" && b != "#") {
            return a == b;
        }
        return false;
    }

    int kmp(vector<string>& s1, vector<string>& s2) {
        int n = s1.size(), m = s2.size(), x = 0, y = 0;
        vector<int> next = nextArray(s2);
        while (x < n && y < m) {
            if (isEqual(s1[x], s2[y])) {
                x++;
                y++;
            } else if (y == 0) {
                x++;
            } else {
                y = next[y];
            }
        }
        return y == m ? x - y : -1;
    }

next 数组的构造同样只改比较那一行。字符版比的是 s[i−1] == s[cn]，这里换成 isEqual(s[i−1], s[cn])。这也是把 KMP 写成泛型比较函数的好处：换比较方式，不动骨架。

五、复杂度分析

阶段时间复杂度空间
两棵树先序序列化O(n + m)O(n + m) 存序列
构造 subRoot 的 nextO(m)O(m)
在 s1 里匹配 s2O(n + m)，实际是 O(2n + m)O(1) 额外
合计O(n + m)O(n + m)

这里的 n 和 m 是节点数，序列长度分别是 2n + 1 和 2m + 1，常数因子多一倍，渐进不变。序列本身要 O(n + m) 的空间，省不掉；想省的话可以边序列化边匹配，那是另一个话题。

链状（每个节点只有一个左孩子，subRoot 是它的一段）的三组：n = 4000、m = 2000 时暴力 26.942 ms 对 KMP 0.104 ms；n = 20000、m = 10000 时 601.020 ms 对 0.676 ms；n = 60000、m = 30000 时 5321.653 ms 对 2.033 ms。

满二叉上结论反过来。8191 个节点的满二叉、subRoot 是与它同样形状但最右叶差一个值的树：暴力 0.294 ms，KMP 0.806 ms。如果 subRoot 的值全不一样，暴力只要 0.023 ms，KMP 还是 0.246 ms。

原因是暴力的内层比较在满二叉上几乎是 O(1)：头一个节点的值对不上就返回，n 个起点各花一次比较。KMP 却必须把 2n + 1 项序列整个扫完，还要先建 next 数组。形状决定谁快，链状树和满二叉正好是两个极端。

六、总结

把树拍成先序序列、空指针写成占位符，子树判定就变成子串匹配，交给 KMP 做到 O(n + m)。序列长度恒为 2c + 1，这个定值加上「真前缀里占位符不多于节点值」的观察，保证了匹配上的那一段一定对应一棵完整的子树。占位符不能省，省掉之后 [1,2] 和 [1,null,2] 会变得一模一样；哨兵值表示空同样有撞车的风险。最后一条：链状树上 KMP 快三个数量级，满二叉上暴力更快，选哪个要看树的形状。

序列化加字符串匹配的组合不止能做子树判定，树上路径匹配、结构相同的子树计数、以及把一族树当模式库去批量查询，走的都是同一条路子。
