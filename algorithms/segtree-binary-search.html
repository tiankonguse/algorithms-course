线段树：在答案上二分

「第 k 个空瓶在哪个位置」这种问法，线段树没有一个操作能直接答。但线段树能给出任意区间的和，而「[s, mid] 里的空瓶数够不够 k 个」恰好是一个随 mid 单调的判据。判据单调，就能二分。

零、背景

n 个瓶子排成一排，编号 0 到 n−1，一开始全是空的，每个瓶子最多插一朵花。两种操作：

  • 操作 1 from flower：从 from 开始往右插，有花的瓶子跳过，插满 flower 朵或者到头就停。返回这次插的头尾两个位置；一个都没插上就打印 Can not put any one.
  • 操作 2 left right：把 [left, right] 清空，返回清掉的花的数量。

瓶子只有空和满两态，[l, r] 上有花的瓶子数就是区间和。区间和线段树是最好写的那一种：懒标记是「整段赋值」，lazy(i, v, len) 把 sum 直接写成 v × len。

麻烦全在操作 1 上。它要的是两个具体位置，不是一个数。

一、先数出够不够

from..n−1 这一段里还有多少个空瓶，是 (n − from) − query(from, n)。这个数等于 0 就一个都插不进去，直接打印那句话。

剩下的花可能比空瓶多，实际能插的是 min(zeros, flowers) 朵。于是问题变成：找 from..n−1 上的第 1 个空瓶，和第 min(zeros, flowers) 个空瓶。

二、拿区间和当判据去二分

固定起点 s，看 [s, mid] 这一段。mid 往右挪，这段里的空瓶数只会增加不会减少。所以要找「空瓶数 ≥ k 的最靠左的 mid」，标准的二分答案。

// s..n 上第 k 个空瓶的位置，没有就返回 0
    // 判据带等号：要的是「满足 >= k 的最靠左的那个」
    int findZero(int s, int k) {
        int lo = s, hi = n, ans = 0, mid;
        while (lo <= hi) {
            mid = (lo + hi) >> 1;
            if (mid - s + 1 - query(s, mid, 1, n, 1) >= k) {
                ans = mid;
                hi = mid - 1;
            } else {
                lo = mid + 1;
            }
        }
        return ans;
    }

判据里那个等号不能省。要的是最靠左的那一个满足 ≥ k 的位置，写成 > k 就会在正好相等时继续往右，找到的就不是第一个。

三、主流程

// 题目给的 from 从 0 开始，线段树从 1 开始，进出各加减一次
    pair<int, int> insertFlower(int from, int flowers) {
        from++;
        int start, end;
        int zeros = n - from + 1 - query(from, n, 1, n, 1); // from..n 还有几个空瓶
        if (zeros == 0) {
            start = 0;
            end = 0;
        } else {
            start = findZero(from, 1);                       // 第一个空瓶
            end = findZero(from, min(zeros, flowers));        // 第 min 个空瓶
            update(start, end, 1, 1, n, 1);
        }
        return {start - 1, end - 1};
    }

两次二分各自 O(log n) 轮，每轮一次 O(log n) 的区间查询，合起来是 O(log²n)。n = 50000 时实测 findZero 平均调用 14.12 次区间查询，log₂50000 是 15.61。

下标换算这一步也容易错：题目给的 from 从 0 开始，线段树从 1 开始，进函数时加 1、出函数时减 1，两边都要做。

演示：二分找到第 k 个空瓶

每一步是一次二分探查，橙色区间就是被查询的 [from, mid]。「跑到本操作结束」直接跳到本次操作落定。

四、直接顺着树往下走

外层二分把树当成一个只会回答区间和的黑盒，每次都从根重新走一遍。其实判据要的那个数在树上是可以边走边攒的：到了某个节点，先看左半边里落在查询范围内的空瓶够不够 k 个，够就往左，不够就往右并把 k 减掉这一段的量。

// 在树上直接往下走：左半边空瓶够就往左，不够就往右并把 k 减掉
    int findZeroOnTree(int s, int k, int l, int r, int i) {
        if (l == r) return l;
        int mid = (l + r) >> 1;
        down(i, mid - l + 1, r - mid);
        int leftZero = 0;
        if (s <= mid) {
            int used = query(s, mid, l, mid, i << 1);
            leftZero = (mid - max(s, l) + 1) - used;
        }
        if (leftZero >= k) return findZeroOnTree(s, k, l, mid, i << 1);
        return findZeroOnTree(max(s, mid + 1), k - leftZero, mid + 1, r, i << 1 | 1);
    }

这样一次只走树高，是 O(log n)。代价是代码里要自己算「左孩子在 [s, mid] 范围内的长度」，比外层二分的四行判据啰嗦。

同样二十万次 findZero。n 越大比值反而越小，因为树上二分每次要多算一次左孩子的长度，这个常数在 n 小的时候占比更明显。

要不要换？n = 50000、m = 50000 的混合操作实测 76.37 ms，外层二分完全够。真要卡常再换树上二分，别一上来就写那个要手算长度的版本。

int 够用：瓶子数 ≤ 50000，区间和最大就是 n。四个字节一个数组，四倍开是 0.8 MB。

六、几种写错的样子

每组 20000 个随机输入，四档是「瓶数 / 操作数」= 5 / 4、12 / 8、30 / 20、80 / 50。百分比是和暴力模拟逐行不一致的比例。

「zeros 忘了减区间和」这一行在小数据上只有 26%，因为瓶子少的时候 from 后面往往整段是空的，减不减都一样。瓶子一多，前面插过的花就会让这两个数分道扬镳。

「清空时先改后查」是个挺典型的顺序错：先赋值成 0 再查，查到的永远是 0。返回的是清掉的数量，顺序反了就归零。

七、总结

线段树不能直接答「第 k 个是誰」，但区间和随手可得，而「前 mid 个里够不够 k 个」随 mid 单调。把树当黑盒、在外面二分答案，是把一个不会做的查询拆成一串会做的查询的通用路子。

外层二分的代价是 log 的平方，实测比树上二分慢 6 到 15 倍，但 n = 50000 时也就 76 ms，先写它。要提速就顺着树往下走，边走边攒左半边的量，一次只走树高。

这个「在答案上二分」的形状后面还会见到：判据换成前缀和、换成最大值、换成某个计数，只要它单调，套的就是同一层壳。

最后

三件容易翻车的小事。一是判据的等号，找最靠左的满足位置必须用 ≥，用 > 会整体右移一位。二是下标基准，题目 0 起、线段树 1 起，进和出各换一次，只换一边就全错。三是 findZero 在 k 超过实际空瓶数时返回 0，调用方要么先算 zeros 挡一道，要么拿到 0 时按「一个都插不进」处理，别直接拿 0 去 update。
