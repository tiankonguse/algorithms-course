逆序对增量与树上路径

上一节的外层是树状数组、内层是开点权值线段树，一个查询就是在「下标 × 值域」这个二维平面上数一个矩形里的点。这一节把这个矩形用到两个地方：一是交换两个位置时逆序对怎么变，二是把下标从数组换成树的 dfn 序。

零、二维矩形计数

先统一一下记号。query(al, ar, numl, numr) 回答的是：下标落在 [al, ar]、值落在 [numl, numr] 里的元素有多少个。外层树状数组把下标拆成 O(log n) 个桶，每个桶的内层权值线段树查一次值域区间，加起来。一次是 O(log n · log s)。

一、题目6：排队

给定一个长度为 n 的数组，i < j 且 arr[i] > arr[j] 时 (i, j) 是一个逆序对。先打印原始数组的逆序对数量，然后 m 次操作，每次给出 a、b，交换这两个位置的数并打印新的逆序对数量。n ≤ 2 × 10⁴，m ≤ 2 × 10³。测试链接：P1975。

初始逆序对的做法是常规操作：从左往右扫，位置 i 贡献的是「i 左边比 arr[i] 大的个数」，也就是 query(1, i - 1, arr[i] + 1, s)。

交换才是要算的。设 a < b，交换 arr[a] 和 arr[b]。位置在 (a, b) 之外的点，跟 a、b 两个位置的相对顺序没变，跟彼此的相对顺序也没变，所以只有三类配对会变：

  • arr[a] 与 (a, b) 里每个点的配对：原来在前，inverse 条件是 arr[a] > arr[x]；换到 b 之后变成在后，条件变成 arr[a] < arr[x]
  • arr[b] 与 (a, b) 里每个点的配对：正好反过来
  • (a, b) 这一对本身：交换前是 arr[a] 在前，交换后还是 a 位置在前，但两个值换了位置，逆序关系翻转一次

前两类各是一次矩形计数，第三类是一次比较。合起来就是代码里的五行。

int query(int al, int ar, int numl, int numr) {
        int ans = 0;
        for (int i = ar; i > 0; i -= lowbit(i)) {
            ans += innerQuery(numl, numr, 1, s, root[i]);
        }
        for (int i = al - 1; i > 0; i -= lowbit(i)) {
            ans -= innerQuery(numl, numr, 1, s, root[i]);
        }
        return ans;
    }

    void compute(int a, int b) {
        ans -= query(a + 1, b - 1, 1, arr[a] - 1);
        ans += query(a + 1, b - 1, arr[a] + 1, s);
        ans -= query(a + 1, b - 1, arr[b] + 1, s);
        ans += query(a + 1, b - 1, 1, arr[b] - 1);
        if (arr[a] < arr[b]) ans++;
        else if (arr[a] > arr[b]) ans--;
        add(a, -1);
        add(b, -1);
        swap(arr[a], arr[b]);
        add(a, 1);
        add(b, 1);
    }

这里有个细节：离散化时往 sorted 里塞了 −INF 和 +INF 两个哨兵，于是 arr[a] - 1 和 arr[a] + 1 一定是合法的离散下标，不用额外判断越界。INF 取 1000000001，比题面的 10⁹ 大一点。

还有一处容易看漏：compute 里先做完四项修正，最后才 add(a, -1)、add(b, -1)。因为四项查的是「交换之前」的中间区间，顺序反了就会查到已经被改过的结构。

三、题目7：网络管理

一棵 n 个点的树，每个点有点权，m 次操作：操作 0 x y 把 x 号点的点权改成 y；操作 k x y（k > 0）打印 x 到 y 路径上第 k 大的值，路径上不够 k 个点就打印 invalid request!。n、m ≤ 8 × 10⁴，点权 ≤ 10⁸。测试链接：P4175。

路径查询本来该用树链剖分拆成 O(log n) 段。这里换个办法：把「点权」变成 dfn 序上的一维差分。

对每个点 i，在 dfn 位置 dfn[i] 放一个 +wi，在 dfn[i] + siz[i] 放一个 −wi。做了这个差分之后，对 dfn 求前缀和时，位置 p 上落着的正好是「所有子树包含 p 的点」的权，也就是根到 p 这条路径上的全部点权。

于是树上差分就能用了：x 到 y 的路径 = prefix(dfn[x]) + prefix(dfn[y]) − prefix(dfn[lca]) − prefix(dfn[fa[lca]])。四个前缀各是一次「多棵权值线段树同时下潜」，第 k 大等于第 (num − k + 1) 小，num 是路径上的点数。

void add(int i, int val, int cnt) {
        for (; i <= n; i += lowbit(i)) {
            root[i] = innerAdd(val, cnt, 1, s, root[i]);
        }
    }

    void update(int i, int v) {
        add(dfn[i], arr[i], -1);
        add(dfn[i] + siz[i], arr[i], 1);
        arr[i] = kth(v);
        add(dfn[i], arr[i], 1);
        add(dfn[i] + siz[i], arr[i], -1);
    }

    int query(int x, int y, int k) {
        int xylca = lca(x, y);
        int lcafa = stjump[xylca][0];
        int num = deep[x] + deep[y] - deep[xylca] - deep[lcafa];
        if (num < k) return -1;
        cntadd = cntminus = 0;
        for (int i = dfn[x]; i; i -= lowbit(i)) {
            addTree[++cntadd] = root[i];
        }
        for (int i = dfn[y]; i; i -= lowbit(i)) {
            addTree[++cntadd] = root[i];
        }
        for (int i = dfn[xylca]; i; i -= lowbit(i)) {
            minusTree[++cntminus] = root[i];
        }
        for (int i = dfn[lcafa]; i; i -= lowbit(i)) {
            minusTree[++cntminus] = root[i];
        }
        return sorted[innerQuery(num - k + 1, 1, s)];
    }

add(dfn[i] + siz[i], arr[i], -1) 在 dfn[i] + siz[i] 超过 n 时什么也不做，for (; i <= n; ...) 一次都不进。这正好对应「根节点的子树就是整棵树，没有地方需要抵消」。num < k 时直接返回 −1，主函数里打印 invalid request!。

每行是一个点的子树区间 [dfn[i], dfn[i] + siz[i])，区间左端放 +w、右端放 −w。竖线 p 覆盖到的行就是 prefix(p)。

加进来的前缀（蓝色竖线） 减掉的前缀（橙色竖线） 本次不参与

把四个前缀合起来：prefix(7) = {5, 8, 2, 6}，prefix(8) = {5, 8, 2, 4}，prefix(6) = {5, 8, 2}，prefix(5) = {5, 8}，相减之后只剩 {2, 4, 6}，正是路径 7-6-8 上的三个点权。num = 3，第 1 大就是 6。

复杂度分析

两道题的内层都一样，差别只在「一次查询要调用几次 query」。

项目时间空间
单次 query(al, ar, numl, numr)O(log n · log s)—
题6 初始逆序对O(n log n · log s)O(n log n · log s)
题6 单次交换O(log n · log s)同上
题7 建树与打点O(n log n · log s)O(n log n · log s)
题7 单次 LCAO(log n)O(n log n)
题7 单次查询O(log n · log s)同上

题6 的 n 只有 2 × 10⁴，但每次交换要在四个矩形上各做一次二维计数，所以常数不算小。题7 的 n、m 到 8 × 10⁴，开点数组按 (n + m) · log n · log s 估，代码里开的是 MAXN * 110，它比题4 少，是因为每个点只在两个 dfn 位置打点，进入的树状数组桶数比「每个位置一个元素」要少一些。

最后

树套树到这里收尾。回头看这七道题，真正在变的只有两件事：外层用什么拆范围，内层维护什么信息。剩下的工作，离散化、开点、多棵树同时下潜，都是为了把空间压到能开得下、把常数压到能过。
