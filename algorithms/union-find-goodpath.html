好路径的数目：代表节点当集合的最值

树上两点之间只有一条路。给每个点一个值，把「两端值相同、路上每个点的值都不超过端点的值」的路径叫好路径，数总数。做法是给并查集加一条规矩：谁的值大谁当代表，于是代表节点的值就是整个集合的最大值。

零、问题

一棵 n 个点的树，vals[i] 是点 i 的值。路径的起终点值要相同，路径上所有点的值都要 ≤ 起点的值。反向路径算同一条，单个点也算一条。求好路径数。

朴素的数法是把所有点对都拿出来，端点值相等就沿着树上的唯一路径走一遍，看最大值是不是等于端点的值。点对是 O(n²) 个，每个点对走一遍路径最坏 O(n)，n 到 30000 就完全跑不动了。

换个角度。假设我们现在有一堆「值 ≤ w 的点」，只在这些点之间连边，能互相到达的点，路径上的值肯定都 ≤ w。反过来也成立：路径上的值都 ≤ w，那条路上的每条边自然都满足「两端最大值 ≤ w」，边全在。所以：

两个值都是 w 的点之间是好路径 ⟺ 把所有「两端最大值 ≤ w」的边都加起来之后，这两个点连通。

一、按边的最大值从小到大加边

把边按 max(vals[u], vals[v]) 升序排好，依次加入并查集。加完所有键值 ≤ w 的边之后，连通块恰好就是「路径上的值都 ≤ w」的点集。

于是每条边被处理时只要看一件事：它两端所在集合的最大值是不是相等。不相等，这条边不会产生任何好路径；相等，说明两边各有一批值等于这个最大值的点，这批点和那批点两两配起来就是新的好路径。

树的特殊性在这里很关键：树上没有环，每条边处理时两端一定在**不同**的集合里，合并必然发生，不会像一般图那样出现「两端已经连通、这条边白加」的情况。也因此，键值相同的边谁先谁后不影响答案。

二、谁的值大谁当代表

并查集一般用「小挂大」控制树高，这里不能这么干。这题需要代表节点的值等于整个集合的最大值，所以要按值来决定方向：

（1）vals[fx] > vals[fy]，让 fx 当代表；

（2）vals[fx] < vals[fy]，让 fy 当代表；

（3）相等，谁当都行，此时产生 maxcnt[fx] × maxcnt[fy] 条新路径，然后把 maxcnt 相加。

maxcnt 记的是这个集合里值等于最大值的点有几个。前两种情况下 maxcnt 不用动，因为被挂上去的那棵树里根本没有值更大的点。只有第三种情况才要相乘再相加。

代价是这棵树可能长歪，所以扁平化必须写，好在均摊下来还是 O(α)。少了小挂大，树高最坏能到 O(n)，但每次合并都扁平化到根，实测 n = 10 万随机树跑 10.73 ms，n = 3 万跑 3.01 ms，压力不大。

四种写法最容易错的地方：按 min 排序（31.15% 的样例出错）、相等时不累加 maxcnt（65.16%）、贡献写成加法而不是乘法（84.46%）、代表节点取小值的那个（41.48%）。

#include <bits/stdc++.h>
    using namespace std;

    // 代表节点一定是整个集合里值最大的那个点
    vector<int> father;
    // maxcnt[代表] : 这个集合里最大值出现了几次
    vector<int> maxcnt;

    void build(int n) {
        father.resize(n);
        maxcnt.assign(n, 1);
        for (int i = 0; i < n; i++) {
            father[i] = i;
            maxcnt[i] = 1;
        }
    }

    // 这个并查集只有扁平化，没有小挂大 : 谁做代表由值说了算
    int find(int i) {
        if (i != father[i]) {
            father[i] = find(father[i]);
        }
        return father[i];
    }

    // 返回这次合并新产生的好路径条数
    int unionSet(int x, int y, vector<int>& vals) {
        int fx = find(x);
        int fy = find(y);
        int path = 0;
        if (vals[fx] > vals[fy]) {
            father[fy] = fx;
        } else if (vals[fx] < vals[fy]) {
            father[fx] = fy;
        } else {
            // 两个集合的最大值一样 : 左边每个最大值配右边每个最大值
            path = maxcnt[fx] * maxcnt[fy];
            father[fy] = fx;
            maxcnt[fx] += maxcnt[fy];
        }
        return path;
    }

    int numberOfGoodPaths(vector<int>& vals, vector<vector<int>>& edges) {
        int n = vals.size();
        build(n);
        // 单个节点自己是合法路径
        int ans = n;
        // 边按「两端较大的那个值」从小到大处理
        sort(edges.begin(), edges.end(), [&](const vector<int>& a, const vector<int>& b) {
            return max(vals[a[0]], vals[a[1]]) < max(vals[b[0]], vals[b[1]]);
        });
        for (auto& e : edges) {
            ans += unionSet(e[0], e[1], vals);
        }
        return ans;
    }

三、换个角度看阈值

上面那套流程等价于：把阈值 w 从最小的值一路抬上去。抬到某一档 w，所有「两端最大值 ≤ w」的边都已经在并查集里了，这时候数一数值恰好等于 w 的点：它们在连通块里两两配对，每一对就是一条新的好路径。

为什么不重复：两个值都是 w 的点如果在更小的阈值 w′ 下就连通了，那它们路径上的值都 ≤ w′ < w，和两端都是 w 矛盾。所以每个等值点对只会在自己那一档被数到一次。

ans 初值取 n，代表 n 个单点路径；把每一档新数出来的对加进去，扫完所有边答案就出来了。下面这个演示可以直接切换阈值，看每一档新增多少对。

四、复杂度分析

指标值
时间复杂度O(n·log n + n·α(n))，n 个点 n−1 条边
额外空间O(n)（father 与 maxcnt）

大头在给边排序 O(n·log n)，之后每条边常数次并查集操作，均摊 O(α)。点数 30000 时排序 1 万次比较级别，实测整段跑 3.01 ms。

五、总结

这题的钥匙是「按边的最大值排序 + 代表节点存集合最大值」。排序决定了并查集在什么时机长大，代表节点决定了合并时怎么读出「两边最大值一样」这个信号，maxcnt 决定了两边各有多少个值相等的点可以配对。

好路径从单点开始数，每合并一次加一批，没有重复也没有遗漏。想让并查集带上别的统计量，套路是一样的：想清楚信息挂在哪个节点上（代表节点）、合并时怎么把两边的信息合成一个、查询时怎么读。
