质数筛：埃氏筛与欧拉筛

要 1 到 n 里所有的质数，一个个试除是 O(n 根号 n)。筛法把这件事反过来：不去认质数，而是把合数一笔一笔划掉，剩下的就是质数。埃氏筛从 i×i 开始划，代价 O(n · log log n)；欧拉筛让每个合数只被它的最小质因子划一次，代价 O(n)。

零、把合数划掉

从 2 开始，2 没被划过，它是质数，于是把 4、6、8… 全划掉。下一个没被划掉的是 3，划掉 6、9、12…。再往下 4 已经划掉了，跳过；5 没划掉，划掉 10、15、20…。一路走完，没被划掉的就是质数。

划的时候不从 2×i 起，从 i×i 起就够了。原因是：i 的倍数 i×2、i×3、…、i×(i-1) 早就作为 2、3、…、i-1 的倍数被划过了，第一次轮到 i 自己动手的，是 i×i。实测 n = 107 时，从 2i 起划要 23492028 次，从 i×i 起只要 22850051 次。

循环上界也只要根号 n：i > 根号 n 之后，i×i > n，已经没有倍数可划了。而没被划掉的数还留在表里，最后数一遍就有全部质数。

// 埃氏筛：返回 0 ~ n 范围内质数的数量，O(n * log(logn))
    int ehrlich(int n) {
    	// visit[i] = true，代表 i 是合数
    	// visit[i] = false，代表 i 是质数
    	vector<char> visit(n + 1, false);
    	int cnt = 0;
    	for (int i = 2; i * i <= n; i++) {
    		if (!visit[i]) {
    			// i 是质数，划掉 i 的倍数
    			// 从 i * i 开始即可，i * 2、i * 3 ... 早就作为更小质数的倍数被划掉了
    			for (int j = i * i; j <= n; j += i) {
    				visit[j] = true;
    			}
    		}
    	}
    	for (int i = 2; i <= n; i++) {
    		if (!visit[i]) {
    			cnt++;
    		}
    	}
    	return cnt;
    }

一个合数会被它的每个不同质因子各划一次。12 会被 2 划一次、被 3 划一次，一共两次。实测 n ≤ 105 时，单个数最多被划 6 次；划掉总次数除以 n 从 1.04（n=100）涨到 1.93（n=105），这个增长就是 log log n 那一层。

一、欧拉筛：每个合数只划一次

埃氏筛的浪费在于重复划。想让每个合数只被划一次，就得规定「谁有资格划它」，最自然的一条是：只让它的最小质因子划它。

欧拉筛维护一张已经找到的质数表 prime，然后遍历 i 从 2 到 n：

  1. 若 i 还没被划掉，把 i 加进 prime。
  2. 依次拿 prime 里的每个质数 p 去划 i×p，划完就换下一个；一旦 i 能被 p 整除，立刻 break。

那个 break 是整个算法的全部机关。i % p == 0 说明 p 是 i 的最小质因子（prime 是升序的，第一个整除 i 的就是最小的）。这时候如果继续用更大的质数 q 去划 i×q，这个数的最小质因子仍然是 p 而不是 q，它应该留给后面某一轮去划。具体留给谁：令 i' = i / p × q，i' > i，而 i×q = i'×p，等外层走到 i' 时，p 那一次会把它划掉。

实测 n = 200000：欧拉筛一共划了 182015 次，正好等于 2 到 200000 之间合数的个数（200000 − 17984 个质数 − 1 = 182015），而且每一次的划线者都恰好是该数的最小质因子，182015 次里 0 次例外。

// 欧拉筛（线性筛）：返回 0 ~ n 范围内质数的数量，O(n)
    // 关键在 break：一旦 i % prime[j] == 0，prime[j] 就是 i 的最小质因子
    // 再往后乘，最小质因子就不再是 prime[j] 了，留给它自己那轮去划
    int euler(int n) {
    	vector<char> visit(n + 1, false);
    	vector<int> prime(n / 2 + 1);
    	int cnt = 0;
    	for (int i = 2; i <= n; i++) {
    		if (!visit[i]) {
    			prime[cnt++] = i;
    		}
    		for (int j = 0; j < cnt; j++) {
    			if (i * prime[j] > n) break;
    			visit[i * prime[j]] = true;
    			if (i % prime[j] == 0) break;
    		}
    	}
    	return cnt;
    }

顺带说一句：欧拉筛顺手就把 prime 表建好了，所以后面要「枚举 n 以内的质数」时它比埃氏筛更直接。埃氏筛最后得再扫一遍数组才能收集出表来。

二、只计数的话，埃氏筛还能再省

题目常常只要「有几个质数」而不要表。那就先把偶数全部去掉（2 留着），计数初值取 (n+1)/2，之后只在奇数里划：外层 i 每次加 2，内层步长改 2i，这样划到的都是奇数倍的奇数，偶数倍本来就不算质数。实测 n = 107 时划掉次数从 22850051 降到 4335421，少了八成。

// 只计数的话，埃氏筛还能再省：先把所有偶数去掉（但算上 2），然后只划奇数倍的奇数
    int ehrlich2(int n) {
    	if (n <= 1) return 0;
    	vector<char> visit(n + 1, false);
    	// 初始认为所有奇数都是质数，偶数都不是
    	int cnt = (n + 1) / 2;
    	for (int i = 3; i * i <= n; i += 2) {
    		if (!visit[i]) {
    			// 步长 2i：跳过偶数倍，它们本来就已经不算质数了
    			for (int j = i * i; j <= n; j += 2 * i) {
    				if (!visit[j]) {
    					visit[j] = true;
    					cnt--;
    				}
    			}
    		}
    	}
    	return cnt;
    }

三、真要比速度，埃氏筛不一定输

把四种写法放在 n = 106 和 n = 107 上量一遍（划掉次数 / 耗时）：

埃氏筛（从 i×i 起划）21220480.84 ms2285005110.08 ms

欧拉筛9215011.67 ms933542015.88 ms

欧拉筛划掉的次数最少，正好是合数个数，可它比两种埃氏筛都慢。原因是每轮内层都要做一次 i % prime[j] 的取模来判 break，而埃氏筛的内层只是一次加法和一次写标记。「O(n) 一定比 O(n · log log n) 快」这句话在 n = 107 这个量级上不成立，实测倒过来。日常掌握埃氏筛（含只划奇数那一版）完全够用，欧拉筛的价值在于它顺手给出了 prime 表，以及它那套「最小质因子」的划分思路在别的地方还要用。

埃氏筛那个 log log n 来自调和级数在质数上的求和：Σp ≤ n n/p = n · log log n + O(n)。实测划掉总次数 / n 从 1.04（n=100）涨到 1.93（n=105）、2.29（n=107），而 log log n 分别是 1.53、2.44、2.78。空间上四种写法都是一张长度 n+1 的标记数组，另外欧拉筛还要存 prime 表（约 n / ln n 个）。

总结

筛法的共同点是反过来做：不判断谁是质数，而是把合数划掉。埃氏筛从 i×i 起划，因为更小的倍数早被更小的质数划过了；循环上界到根号 n 为止。

欧拉筛让每个合数只被最小质因子划一次，机关是那句 if (i % prime[j] == 0) break;：i 能被 p 整除时 p 就是 i 的最小质因子，再往后乘得到的最小数仍归 p 管，留给 i 变大之后那一轮。实测 n = 200000 时划掉次数恰好等于合数个数，一次不多一次不少。

但 O(n) 不等于更快。实测 n = 107 时欧拉筛 15.88 ms，埃氏筛（只划奇数）只要 8.40 ms，多出来的时间花在每轮那次取模上。写题的时候埃氏筛够用，欧拉筛的用处更多在它给出的 prime 表和最小质因子这套划分。

质数筛出来的表往后用途很多：分解质因数时可以直接拿表里的质数去试，判断大数质数时那 12 个底也是一批小质数。
