最长公共子序列：从 dp 表倒着走回方案

不少 dp 题目要的是达到最优值的那个具体选择，光给出一个数还不够。表还是那张表，多一步把决策路径读出来而已。

零、问题

给两个字符串 str1、str2，输出它们的一个最长公共子序列；如果为空，输出 -1。

只问长度的话，二维 dp 表填完就结束了。现在要的是把那个子序列本身打出来，于是表里除了长度，还得留下「当初是怎么走到这一格的」这条信息。好消息是这条信息不用额外存：长度之间的大小关系已经把它记下来了。

一、表还是那张表

dp[i][j] 是 str1 前 i 个字符与 str2 前 j 个字符的最长公共子序列长度。最后一个字符相等就接上，不等就在「放弃 str1 的末位」和「放弃 str2 的末位」里取大的。

    
// dp[i][j] : str1 前 i 个字符与 str2 前 j 个字符的最长公共子序列长度
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) {
            if (s1[i - 1] == s2[j - 1]) {
                dp[i][j] = 1 + dp[i - 1][j - 1];       // 最后一个字符相同，一定可以接上
            } else {
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]);
            }
        }
    }

填完 dp[n][m] 就是答案长度 k。这张表一共 (n+1)·(m+1) 格，每格 O(1)。

二、从右下角往回走

反推的起点是 (n, m)，手里还差 len = k 个字符。每一格只有两种来历，看一眼就知道该做什么。

第一种来历是「最后一个字符相等」。这一格的值是 1 + dp[i-1][j-1]，说明这个字符被接进了子序列，取下来写进答案，然后斜着走到 (i-1, j-1)。

第二种是「取 max 得到的」。这一格的值等于 dp[i-1][j] 和 dp[i][j-1] 里大的那个，往大的那边走，剩下的长度不变；往小的那边走会掉长度。

    
// 从右下角倒着走回来，len 是还差几个字符
    void lcs() {
        k = dp[n][m];
        for (int len = k, i = n, j = m; len > 0;) {
            if (s1[i - 1] == s2[j - 1]) {              // 这一格是「相等」来的，取字符
                ans[--len] = s1[i - 1];                // 先减再写，答案是从后往前攒的
                i--;
                j--;
            } else {                                   // 这一格是 max 来的，往大的那边走
                if (dp[i - 1][j] >= dp[i][j - 1]) {
                    i--;
                } else {
                    j--;
                }
            }
        }
    }

注意 ans[--len] 是先减再写。反推是从后往前遇到字符的，最先拿到的是子序列的最后一个字符，得写进答案数组的尾部。写成 ans[len--] 会得到整个串的逆序。

三、两个方向为什么这么选

先看「相等就取」为什么不会亏。设 str1[i-1] == str2[j-1] == c，这一格按转移写成 1 + dp[i-1][j-1]。另外两个方向的值不会超过它：dp[i-1][j] 最多是 1 + dp[i-1][j-1]（右边多出来的那个 c 最多贡献 1），dp[i][j-1] 同理。所以取 c 之后剩下的 dp[i-1][j-1] 恰好比当前少 1，长度一点没丢。

随机 2 万组字符串（长度 1 到 12、字母表 2 到 5）实测：27 万多个「末位相等」的格子里，1 + dp[i-1][j-1] 不小于另外两个方向的比例是 100%。所以相等时取字符不需要跟别的情况比较，直接取就行。

再看「不等往大的那边走」。相等的情况会先被第一种处理掉，剩下的格子里 dp[i][j] = max(dp[i-1][j], dp[i][j-1])，大的那个跟当前值相等，走过去剩下的长度正好不变。两边一样大时走哪边都对，只是得到的串不同。

平局其实很常见：随机样本里 60.07% 的反推过程至少碰到一次两边相等，平局步数占「走分支」总步数的 42.62%。这也解释了为什么同一个题会有多个正确答案，判题器一般只验长度和合法性。

六、写错的地方

位置写法与正确解不一致的比例
反推末位相等时不取，继续走 max 分支79.65%
反推ans[--len] 写成 ans[len--]53.68%（答案长度 ≥ 2 的样本里 77.14%）
反推起点写成 i = n-1, j = m-158.13%
反推不等时往小的那边走65.15%

第二条只在答案长度至少为 2 时看得出来，而且是「串本身左右对称」的那些样本看不出来。剩下 22.86% 正好是 aa、aba 这类。

第三条最容易被忽略：起点必须是 (n, m)，因为 dp[n][m] 才是完整答案。从 (n-1, m-1) 起步会直接把两个串的最后一个字符排除在外。

七、留全表的代价

只要长度的话可以压成滚动数组，两行就够，dp[i][j] 只依赖上一行和本行左边。要方案就必须留整张表，因为反推会往任意方向跳。

n = m = 5000 实测：表有 25,010,001 格，按 int 算是 95.41 MB；反推只走了 6,740 步，其中取字符 3,260 步、走分支 3,480 步。也就是说为了最后这 6,740 步，前面要付 2500 万格的账。

滚动数组这边 2·(m+1)·4 字节，是 40 KB，差 2400 倍。所以「要不要方案」这个问题在开数组之前就得想清楚。

八、复杂度分析

阶段时间空间
填 dp 表O(n·m)O(n·m)
反推方案O(n + m)O(k)，k 是答案长度
只求长度（滚动数组）O(n·m)O(m)

反推的 O(n+m) 是怎么来的：每一步要么 i--，要么 j--，要么两个一起减，i+j 严格单调下降，最多 n+m 步就到边界。加上答案数组 O(k)，k ≤ min(n, m)。

整道题的瓶颈在填表，反推是零头。n = m = 5000 时填表加反推一共 32.13 ms。

九、总结

这类题目的分工很清楚：dp 表负责算出最优值，反推负责把这个值对应的那条路径读出来。读的办法是站在终点，用「这一格当初是从哪个格子来的」反复问自己，每问一次就往前挪一格。

值得记的两个细节：答案是倒着攒的，写进数组要先减下标；起点和循环条件要跟表的定义对齐，别从 n-1 起步。

还有一种形态是顺着决策顺序正着走：状态里带着「当前考虑第几个」，判断依据就变成「最优值有没有在这一步变小」。
