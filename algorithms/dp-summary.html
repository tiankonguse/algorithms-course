动态规划总结：判据、五步与复杂度

动态规划这一大块收尾。三件事值得单独拎出来：什么样的递归才改得动，改的顺序是什么，改完复杂度怎么算。这三件事一起决定一道题最后能不能过。

零、背景

动态规划解决的是递归里的重复计算。同一个参数会被不同的路径走到很多次，把每次算出来的返回值记下来，下次直接取。

拿斐波那契做例子。裸递归写出来就三行，但 fib(40) 实测要 331160281 次函数调用，耗时 350ms（-O2）。而参数只有 0 到 40 这 41 种取值。前一个数字是「走到的路径条数」，后一个数字是「状态个数」，差了近七个数量级。

把 41 个状态各算一次，fib(40) 只要 0.048 微秒（实测 -O2，重复一百万次取的平均）。省下来的这些东西，来源就一句话：同一个参数被算了很多次。

一、什么样的递归改得动

判断一个递归能不能改成动态规划，看一眼形参列表就够了：可变参数的类型要简单，不比 int 更复杂。

一个 int 参数，状态数是 O(n)；两个 int 参数，状态数是 O(n·m)；再加一个 k 位的掩码，状态数是 O(n·2k)。这些都能枚举出来，表格开得下。

反过来，参数里带数组、字符串、链表这类结构就不行了。它们的取值有无数种，每一种都是一个状态，表还没开就没了。

还有一条关于路径的判据。递归沿路收集信息时，看这些信息简单不简单。

要枚举所有路径的，别改。N 皇后要的是全部摆法，输出本身就是天文数字，动态规划帮不上忙。

路径信息看起来复杂、但装得下的，可以改。数位 dp 要记住「已经用过哪些数字」，听着是路径信息，可是阿拉伯数字只有 10 个，压成一个 10 位的二进制数就装进了 int。状压 dp 同理，n 个物品用过没用过压成 n 位。

路径信息能不能压成一个不大的整数，这才是关键。

二、三个性质

重叠子结构说的是同一个参数会被不同路径走到。这是记忆化有意义的前提；要是每个参数只会被走一次，记下返回值也没人再来读。

最优子问题说的是大问题的最优值能由子问题的最优值拼出来。表里因此只存「最优值」这一份，而不是所有可能的取值，状态数才不会爆。

无后效性说的是状态一旦确定，往下怎么走只跟状态本身有关，跟怎么走到这里无关。这条最容易漏看，写完转移方程回头检查一下：状态里少一个量，多半栽在这。

三条一起看：没有重叠，记忆化白加；没有最优子问题，表里得存集合，那是搜索；没有无后效性，状态得把走过的路一起带上，那又退回搜索了。

三、五步：从尝试到优化

动态规划的实现有一套固定顺序，从最粗糙的递归一路改到能过题。

第 1 步，想出设计优良的递归尝试。这一步定下状态和转移，后面全部照它走。尝试策略写出来就是转移方程。

第 2 步，记忆化搜索，从顶到底。就是在第 1 步的递归上挂一张缓存表，代码改动最小，也最容易写对。斐波那契为例：

// 裸递归：算 fib(n) 时把 fib(n-1) 和 fib(n-2) 各走一遍
    long long fib(int n) {
        if (n <= 1) return n;
        return fib(n - 1) + fib(n - 2);
    }
// 记忆化：同一个参数只真正算一次，后面直接读书
    long long memo[64];

    long long fib(int n) {
        if (n <= 1) return n;
        if (memo[n]) return memo[n];
        return memo[n] = fib(n - 1) + fib(n - 2);
    }

两个函数的形状一样，只多了一句「算过就直接读」。

第 3 步，严格位置依赖，从底到顶。把表按依赖方向排好，用循环替代递归。递归有函数调用开销：栈帧、参数传递、返回值，都是常数因子。同一道 01 背包，n=300、V=10000 共 3×10⁶ 个状态，记忆化递归 27.6ms，改成循环 2.0ms（-O2）；-O0 下是 55.2ms 对 15.0ms。差 3 到 14 倍，看优化档位，量级不变。

斐波那契的第 3 步和第 4 步可以一次做完：

// 严格位置依赖 + 空间压缩：fib(i) 只用到 fib(i-1) 和 fib(i-2)
    long long fib(int n) {
        long long pre = 0, cur = 1;
        for (int i = 2; i <= n; i++) {
            long long nxt = pre + cur;
            pre = cur;
            cur = nxt;
        }
        return n <= 1 ? n : cur;
    }

第 4 步，空间压缩。第 i 行只依赖第 i-1 行时，前面那些行可以扔掉。这一步只动空间，不动时间，fib(40) 从 41 个格子压到两个变量。

第 5 步，优化枚举行为。前面四步动的都是常数和空间，只有这一步会改复杂度本身，代价是题目得对得上它的条件。

五、复杂度分析

动态规划的时间有一个统一算法：状态数量乘每个状态的枚举代价。

最长递增子序列（二分）nlog nO(n log n)O(n)
01 背包（二维表）n·V1O(n·V)O(n·V)

空间是这样来的：状态数量乘上每个状态占几个字节，再乘上要留几层历史。压缩掉旧行，整张表的层数从 n 掉到 1，空间就从 O(n·V) 掉到 O(V)。

拿最长递增子序列的朴素版对上这个公式：状态数是 n，每个状态要往下枚举 n 个前驱，乘起来 n²。

// 状态数 n，每个状态往下枚举 n 个前驱：乘起来就是 n²
    int lengthOfLIS(int* a, int n) {
        int dp[100005], best = 0;
        for (int i = 0; i < n; i++) {
            dp[i] = 1;
            for (int j = 0; j < i; j++)
                if (a[j] < a[i]) dp[i] = max(dp[i], dp[j] + 1);
            best = max(best, dp[i]);
        }
        return best;
    }

实测 n=10000 时内层走了 49995000 次，正好是 n(n−1)/2，-O2 82.5ms、-O0 329ms。把枚举换成二分，代价从 n 掉到 log n，同一道题就是 O(n log n)。

01 背包是另一个极端：状态数 n·V，每个状态的枚举代价只有 1，所以时间几乎全压在状态数量上。

状态数从 10⁷ 涨到 10⁹，-O2 的耗时依次是 2.5ms、25.0ms、158.3ms，-O0 是 36.3ms、355.1ms、3.32s。10⁹ 个状态按 -O0 算要三秒多，多数题的时限撑不住。

这里有个细节：格数按 n·V 算，实际内层走不满。容量比当前物品还小的那些格子不用枚举，n=1000、V=100000 时表有 10⁸ 格，内层只走了 4.9×10⁷ 次。算复杂度照 n·V 算，真要卡时限，这点差额还能再宽一点。

七、空间压缩：背包的例子

01 背包的二维写法里，第 i 行只用到第 i-1 行。这个依赖关系一看出来，前面所有行都可以扔。

// 二维表：dp[i][j] 表示只看前 i 件、容量 j 的最大价值
    int dp[1005][10005];

    int knapsack(int n, int V, int* w, int* v) {
        for (int i = 1; i <= n; i++)
            for (int j = 0; j <= V; j++) {
                dp[i][j] = dp[i - 1][j];
                if (j >= w[i]) dp[i][j] = max(dp[i][j], dp[i - 1][j - w[i]] + v[i]);
            }
        return dp[n][V];
    }

表开成 dp[n+1][V+1]。n=1000、V=10⁶ 时（也就是 10⁹ 个状态），这张表要 3.7GB，本机开不出来。

// 空间压缩：第 i 行只依赖第 i-1 行，一维数组倒着扫就够
    int dp[100005];

    int knapsack(int n, int V, int* w, int* v) {
        for (int i = 1; i <= n; i++)
            for (int j = V; j >= w[i]; j--)
                dp[j] = max(dp[j], dp[j - w[i]] + v[i]);
        return dp[V];
    }

一维版必须倒着扫。j 正着走时，dp[j - w[i]] 已经被本轮更新过，等于同一件物品拿了两次，那算出来的是完全背包。

压缩前后时间没变（n=1000、V=10⁶ 都是 -O2 158.3ms、-O0 3.32s），空间从 3.7GB 掉到 3.8MB，千分之一。

八、优化枚举的手段

第 5 步要动的是「每个状态往下枚举多少下」。手上能用的手段分两批。

这一阶段已经用过

  • 二进制分组、单调队列、滑动窗口：把「每种拿几个」这类枚举压成 O(log n) 甚至 O(1)。
  • 观察并优化转移方程：先写出带枚举的转移，再回头看内层到底在求什么，多数时候只是一个前缀最大值、一段区间和，或者只有两个分支值得走。
  • 状态设计优化：换一维当状态，表的大小就从放不下变成放得下。
  • 高效查询结构：枚举本身躲不掉时，用二分或者预处理结构把每次查询降下来。

后面还会接着讲

  • 单调栈、树状数组、线段树，以及更多预处理结构。
  • 状态设计优化的续集。
  • 单调性优化：斜率优化、四边形不等式。
  • 和动态规划拼在一起的其它内容：树上倍增、换根 dp、启发式合并、树上差分、轮廓线 dp、容斥原理。

九、总结

把这一块收一收，四件事。

其一，能不能改看形参：可变参数是几个 int，或者一个装得下的掩码，就改得动；参数里带数组、字符串，就改不动。路径信息也一样，能压成一个不大的整数就没事。

其二，实现按五步走：递归尝试、记忆化、严格位置依赖、空间压缩、优化枚举。前四步只动常数和空间，第五步才动复杂度。

其三，复杂度就是状态数量乘每个状态的枚举代价，空间是状态数量乘每个状态的字节数。看到题先算这两个数，再看数据量放不放得下：10⁸ 个状态 -O2 二十几毫秒，10⁹ 就要按秒算了。

其四，优化枚举的路子是观察。先把带枚举的转移写出来，再回头看清内层在求什么，多数时候能换成前缀、区间或者二分。

再往后，动态规划会和更多结构叠在一起，上面预告的那些词会逐个兑现。
