扰乱字符串：区间长度当第三维

扰乱字符串问的是：把一个串反复从中间切开、每层的两段可以换位置，能不能拼出另一个串。递归的参数看着是两对区间端点，一共四个数，但「两段要能比较」这个条件把它们的长度绑在一起，自由的只剩三个。第三维就是这个区间长度，填表时按长度从小到大递进。

零、切一刀，再决定换不换位置

从一个字符串里挑一个位置切开，得到左右两段。这两段可以保持原序接回去，也可以先交换位置再接。拼出来的串接着做同样的事，一直切到每段只剩一个字符。这样做能得到的所有串，都叫原串的扰乱串。

看 great：从第 2 刀切开是 gr | eat。保持原序还是 great，交换一下就是 eatgr。两条路都还没到底，因为 gr 和 eat 自己还要继续切。

要判的是反过来的一步：给定 s2，问它是不是 s1 的扰乱串。

一、四个参数的递归

照定义直接翻译。定义 f1(s1, l1, r1, s2, l2, r2)：s1 的 [l1, r1] 这一段和 s2 的 [l2, r2] 这一段是不是扰乱关系。

长度为 1 的时候，两段都只剩一个字符，直接比字符是否相等。长度大于 1 的时候枚举切分点 i，两种对齐各试一次：一种是不交错，s1 的左段对 s2 的左段；一种是交错，s1 的左段对 s2 的右段。

两个 for 循环就是全部了。

// s1[l1..r1] 和 s2[l2..r2] 是不是扰乱关系，四个可变参数
    bool f1(char s1[], int l1, int r1, char s2[], int l2, int r2) {
        if (l1 == r1) {
            return s1[l1] == s2[l2];
        }
        // 不交错：s1 的左半对 s2 的左半
        for (int i = l1, j = l2; i < r1; i++, j++) {
            if (f1(s1, l1, i, s2, l2, j) && f1(s1, i + 1, r1, s2, j + 1, r2)) {
                return true;
            }
        }
        // 交错：s1 的左半对 s2 的右半
        for (int i = l1, j = r2; i < r1; i++, j--) {
            if (f1(s1, l1, i, s2, j, r2) && f1(s1, i + 1, r1, s2, l2, j - 1)) {
                return true;
            }
        }
        return false;
    }

注意到递归调用里带的全是区间端点。四个端点各减一次，参数空间是四维的。

二、长度相等，四个参数退化成三个

两段要能比出结果，长度必须相等。这个条件一加，r1 和 r2 就都不自由了：r1 = l1 + len − 1，r2 = l2 + len − 1。四个端点里真正独立的只有三个数：两个起点和一个长度。

换成 (l1, l2, len) 之后，交错那一支的索引也就好写了。s1 的左段长度取 k，这一段被放到了 s2 的右边，对应 s2 里从 l2 + len − k 开始的 k 个字符；s1 剩下的那段从 l1 + k 开始，长度 len − k，对应 s2 从 l2 开始的那一段。

// 左右两段长度相等，四个参数退化成三个：(l1, l2, len)
    bool f2(char s1[], char s2[], int l1, int l2, int len) {
        if (len == 1) {
            return s1[l1] == s2[l2];
        }
        for (int k = 1; k < len; k++) {
            if (f2(s1, s2, l1, l2, k) && f2(s1, s2, l1 + k, l2 + k, len - k)) {
                return true;
            }
        }
        for (int i = l1 + 1, j = l2 + len - 1, k = 1; k < len; i++, j--, k++) {
            if (f2(s1, s2, l1, j, k) && f2(s1, s2, i, l2, len - k)) {
                return true;
            }
        }
        return false;
    }

第二个循环里 j 从 l2 + len − 1 往回走、i 从 l1 + 1 往前走，两个游标一进一退，正好把「左段对右段」这件事写完。这么写比每次现算 l2 + len − k 少一次加法，也更好读。

三、这段搜索撑不住

三个参数看着不多，len 固定时 l1 和 l2 各只有 O(n) 种取值，位置总数是个多项式。可递归调用的次数完全不是这个量级：同一个 (l1, l2, len) 会在不同的分支里被反复算，而且每算一次都要重新枚举一遍切分点。

拿三组字母、随机长度测一下，调用次数是这样的：n = 10 是 2466 次，n = 12 是 19485 次，n = 14 是 724472 次，n = 16 已经到 3928694 次。每加两个字符，调用次数翻十倍还多。

n 只要再大一点就跑不动了。而字符串题的长度动辄上千，这个增长必须掐掉。

四、加记忆化：三态表

重复的状态就是可压的地方。开一张 dp[l1][l2][len]，用 0 记「没算过」、1 记 true、−1 记 false，进入函数先查表，算出结果顺手写回去。

// dp[l1][l2][len]：0 没算过，1 是 true，-1 是 false
    bool f3(char s1[], char s2[], int l1, int l2, int len, vector<vector<vector<int>>>& dp) {
        if (len == 1) {
            return s1[l1] == s2[l2];
        }
        if (dp[l1][l2][len] != 0) {
            return dp[l1][l2][len] == 1;
        }
        bool ans = false;
        for (int k = 1; k < len && !ans; k++) {
            ans = f3(s1, s2, l1, l2, k, dp) && f3(s1, s2, l1 + k, l2 + k, len - k, dp);
        }
        for (int i = l1 + 1, j = l2 + len - 1, k = 1; k < len && !ans; i++, j--, k++) {
            ans = f3(s1, s2, l1, j, k, dp) && f3(s1, s2, i, l2, len - k, dp);
        }
        dp[l1][l2][len] = ans ? 1 : -1;
        return ans;
    }

三态比 bool 数组多出来的那一档就是「没算过」，省掉了再开一张访问标记表。

实测 n = 30 的随机数据：合法的槽位一共 9455 个（把每个 len 的 (n − len + 1)² 加起来），真正被写过的只有 2835 个。也就是说还有一大半位置从头到尾没人碰过。

演示一：一个状态内部在试什么

下面的表列出 dp[0][0][n] 这一格试过的每一个切分点。先把不交错的对齐全部试完，再试交错的；哪一刀的左右两段同时成立，这一格就是 true，后面的切分点不用再试。

五、严格填表：按 len 从小到大

len 这一维的依赖很干净：算长度为 len 的段时，用到的子段都比 len 短。所以只要按 len 递增的顺序填，填到某一层的时候它要读的层都已经就绪，不存在前向依赖。

// 按 len 从小到大填，长度 len 只依赖更短的段
    bool isScramble(char s1[], char s2[], int n) {
        vector<vector<vector<bool>>> dp(n, vector<vector<bool>>(n, vector<bool>(n + 1, false)));
        for (int l1 = 0; l1 < n; l1++) {
            for (int l2 = 0; l2 < n; l2++) {
                dp[l1][l2][1] = s1[l1] == s2[l2];
            }
        }
        for (int len = 2; len <= n; len++) {
            for (int l1 = 0; l1 <= n - len; l1++) {
                for (int l2 = 0; l2 <= n - len; l2++) {
                    for (int k = 1; k < len && !dp[l1][l2][len]; k++) {
                        dp[l1][l2][len] = dp[l1][l2][k] && dp[l1 + k][l2 + k][len - k];
                    }
                    for (int i = l1 + 1, j = l2 + len - 1, k = 1; k < len && !dp[l1][l2][len]; i++, j--, k++) {
                        dp[l1][l2][len] = dp[l1][j][k] && dp[i][l2][len - k];
                    }
                }
            }
        }
        return dp[0][0][n];
    }

外层是 len，里面两层是 l1 和 l2，最里面才是枚举 k。这个顺序和记忆化版本用的是同一个式子，区别在「谁来访问」：记忆化只算被问到的状态，填表把每一格都算一遍。

实测 n = 200：记忆化 56.2 ms，严格填表 140.5 ms。两边都是 O(n⁴) 的量级，填表的常数更稳定，因为它没有递归调用、也没有查表的哈希开销，代价是所有格子都得填满。

演示二：按 len 逐层往上填

每一帧是表里的一层。格子 (l1, l2) 上写的是「s1 从 l1 开始、s2 从 l2 开始，各取 len 个字符」这一段的判定结果。l1 或 l2 加上 len 越过末尾的格子没有定义，直接灰掉。

六、复杂度分析

做法时间复杂度空间复杂度说明
四参数递归指数级O(n) 递归栈四个端点全靠枚举
三参数递归指数级O(n) 递归栈实测 n = 16 调用 392 万次
记忆化搜索O(n⁴)O(n³)n = 30 只写到 2835 个状态
严格填表O(n⁴)O(n³)n = 200 表里 804 万格

O(n³) 是状态数：len 有 n 种，每种 len 下 (l1, l2) 有 (n − len + 1)² 对，加起来是 O(n³)。每个状态内部枚举 k，代价 O(len)，于是总时间 O(n⁴)。

加记忆化之后复杂度从指数级掉到多项式级，这一步是关键。至于记忆化还是填表，两者同阶，按手感挑就行。

七、总结

扰动字符串这一类题，第三维常常是从已有的参数里挤出来的，被挤掉的是两个右端点，因为它们等于左端点加长度。

找第三维有个笨办法：数一数状态里真正独立的自由度。四个数里有两组「起点加长度」，那自由度就是三，表也只要三维。

依赖方向决定填表顺序。这题的 len 维是单行道，所以按长度递增填；如果哪天第三维的依赖绕回去了，那就得换别的顺序，或者干脆留在记忆化形式上不动。

状态内部的枚举也不能漏算。n³ 个状态每个都要扫一遍切分点，真实时间是两个量相乘的结果，光看状态数会低估一个 n。
