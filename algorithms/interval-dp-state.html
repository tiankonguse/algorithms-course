区间 dp：状态里多带一个量

有些区间问题光知道「是哪一段」还不够，还得知道这段里「谁最后完成」。把这件事塞进状态，多开一维，转移就顺下来了。这一页两道题分别多带一个「最后插入在哪端」和一个「前面还挂着几个」。

零、一个区间，两种收尾

前面做题，状态就是 [l, r] 两个下标，答案是一个数。到了这页，两者都不够用。

合唱队里，一段人是从两端往里一个个凑出来的，最后插进来的那个人站在左端还是右端，直接影响下一步能不能接上。同一个人群区间，收尾在左和在右是两码事，得分开记。移除盒子里，一段盒子被消掉之前，可能还有几个同色的盒子挂在它前面等着一起消，这几个「外债」不算进区间里，却决定这段消掉能拿多少分，也得单独记。

共同点就一句话：区间本身的信息不够，补一个「上下文」维度进去。

一、合唱队

有一排人，身高两两不同。他们按某个初始顺序依次入场，每个人入场时和前一个人比身高：比前一个人高就站到队伍最右边，矮就站到最左边，第一个人直接站好。给定最后排成的队伍（一列身高），问有多少种初始顺序能排出它。

样例 1701 1702 1703 1704 的答案是 8。

状态：dp[l][r][0] 表示拼出 a[l..r] 这一段、并且最后插入的人站在 l 位置的方案数；dp[l][r][1] 则是最后插入的人站在 r 位置的方案数。

转移：已知最后插入的人站在 l（左端），那在它插进来之前，队伍是 [l+1, r]，而那次插入的上一个人只能站在 l+1 或 r。新人是站到左边，说明他比上一个人矮，于是条件是 a[l] < a[l+1] 或 a[l] < a[r]。站在右端对称。

四类转移摆在一起就清楚了。每一类都从「比自己少一个人的那个区间」接过来，能不能接取决于两个端点的高度比较：

const int MOD = 19650827;

    // dp[l][r][0]：拼出 a[l..r]，最后插入的人站在 l 位置
    // dp[l][r][1]：拼出 a[l..r]，最后插入的人站在 r 位置
    int choir(const vector<int>& a) {
        int n = a.size() - 1;                       // a 从下标 1 开始，a[0] 不用
        if (n == 1) return 1;
        vector<vector<vector<int>>> dp(n + 1, vector<vector<int>>(n + 1, vector<int>(2, 0)));
        for (int i = 1; i < n; i++) {
            if (a[i] < a[i + 1]) dp[i][i + 1][0] = dp[i][i + 1][1] = 1;
        }
        for (int l = n - 2; l >= 1; l--) {
            for (int r = l + 2; r <= n; r++) {
                if (a[l] < a[l + 1]) dp[l][r][0] = (dp[l][r][0] + dp[l + 1][r][0]) % MOD;
                if (a[l] < a[r])     dp[l][r][0] = (dp[l][r][0] + dp[l + 1][r][1]) % MOD;
                if (a[r] > a[l])     dp[l][r][1] = (dp[l][r][1] + dp[l][r - 1][0]) % MOD;
                if (a[r] > a[r - 1]) dp[l][r][1] = (dp[l][r][1] + dp[l][r - 1][1]) % MOD;
            }
        }
        return (dp[1][n][0] + dp[1][n][1]) % MOD;
    }

最容易写错的地方是右上角那个条件。站在左端的新人要和「上一个人」比，而上一个人可能是 l+1，也可能是 r；把跨端的那条 a[l] < a[r] 手滑写成近端的 a[l] < a[l+1]，就漏掉了一种接法。实测这个错法在长度 3 时错 33.2%，长度 5 错 30.6%，长度 11 还有 10.3%。

l 这一维其实可以压掉。固定 l，从右往左扫，每一轮只用到「l+1 那一行」的数据，边扫边覆盖即可。规模 n = 1000 时，三维版本 54.5 ms，压缩版 1.86 ms，差距主要来自三维 vector 一层层指针跳转，省的是内存布局不是渐进阶。

// 把 l 那一维压掉，dp[r][0/1] 跟着 l 从右往左滚动
    int choir(const vector<int>& a) {
        int n = a.size() - 1;
        if (n == 1) return 1;
        vector<vector<int>> dp(n + 1, vector<int>(2, 0));
        if (a[n - 1] < a[n]) dp[n][0] = dp[n][1] = 1;
        for (int l = n - 2; l >= 1; l--) {
            if (a[l] < a[l + 1]) { dp[l + 1][0] = 1; dp[l + 1][1] = 1; }
            else                 { dp[l + 1][0] = 0; dp[l + 1][1] = 0; }
            for (int r = l + 2; r <= n; r++) {
                int x = 0, y = 0;
                if (a[l] < a[l + 1]) x = (x + dp[r][0]) % MOD;
                if (a[l] < a[r])     x = (x + dp[r][1]) % MOD;
                if (a[r] > a[l])     y = (y + dp[r - 1][0]) % MOD;
                if (a[r] > a[r - 1]) y = (y + dp[r - 1][1]) % MOD;
                dp[r][0] = x;
                dp[r][1] = y;
            }
        }
        return (dp[n][0] + dp[n][1]) % MOD;
    }

二、移除盒子

一排盒子，颜色用正整数表示。每一轮可以移除一段连续且同色的盒子，长度记 k，得 k² 分，移完左右两边的盒子会靠到一起。问把盒子全移完最多能得多少分。

得分是平方，也就是说凑在一起一次消掉最划算：两个单独的盒子各消一次得 2 分，攒成一对一起消得 4 分。

这题难点在于「攒」。1 2 1 里两个 1 想凑一对，得先把中间的 2 消掉，它们才靠到一起；可要是先消掉一个 1，就永远攒不上了。

状态：f(l, r, k) 表示要消掉 boxes[l..r]，且 boxes[l] 前面还挂着 k 个和它同色的盒子，这种局面下最多得多少分。这多出来的 k 就是前面说的「外债」。

转移：先把 l 开始那段连续同色并起来，长度是 s−l+1，加上前缀 k 个，这一整坨同色共 cnt = k + s − l + 1 个。接下来两条路：

  1. 这坨先消：拿 cnt²，再递归算 f(s+1, r, 0)；
  2. 先别消，留着跟后面某个同色的块拼成更大的一坨：找一个 m，boxes[m] 和 boxes[l] 同色，把中间 [s+1, m−1] 先消干净（f(s+1, m−1, 0)），这一段消完 cnt 个就并到了 m 前面，问题变成 f(m, r, cnt)。

两条取最大。k 就是在这两条路之间传下去的：走第二条路时，前缀从 0 变成 cnt，这就是它存在的意义。

// boxes[l..r] 要消掉，前面还挂着 k 个和 boxes[l] 同色的盒子
    int f(const vector<int>& boxes, int l, int r, int k, vector<vector<vector<int>>>& dp) {
        if (l > r) return 0;
        if (dp[l][r][k] > 0) return dp[l][r][k];
        int s = l;
        while (s + 1 <= r && boxes[l] == boxes[s + 1]) s++;      // 先把 l 开始的一段同色并进来
        int cnt = k + s - l + 1;                // 前面 k 个 + 这一段，一共 cnt 个同色
        int ans = cnt * cnt + f(boxes, s + 1, r, 0, dp);         // 可能性一：这一段连着前 k 个一起消
        for (int m = s + 2; m <= r; m++) {      // 可能性二：留着，跟后面某个同色的块一起消
            if (boxes[l] == boxes[m] && boxes[m - 1] != boxes[m]) {
                ans = max(ans, f(boxes, s + 1, m - 1, 0, dp) + f(boxes, m, r, cnt, dp));
            }
        }
        return dp[l][r][k] = ans;
    }

    int removeBoxes(const vector<int>& boxes) {
        int n = boxes.size();
        vector<vector<vector<int>>> dp(n, vector<vector<int>>(n, vector<int>(n + 1, 0)));
        return f(boxes, 0, n - 1, 0, dp);
    }

如果不带 k（每条路都把前缀当 0），括号里那两个 1 就攒不起来，长度 10 时 66.3% 的随机数组会算错。

三、复杂度分析

量规模说明
合唱队状态O(n²)每格两个数；n=1000 时约 100 万格
合唱队时间O(n²)转移是常数条，n=1000 压缩版 1.86 ms
移除盒子状态O(n³)多一维 k，取值 0..n
移除盒子时间O(n⁴)状态 O(n³)，每格还要枚举 m 是 O(n)；n=60 时 0.35 ms
空间O(n²) / O(n³)合唱队可压到 O(n)；移除盒子要开三维表

多带一个量，状态空间就乘一档。合唱队那个量只有 0/1 两种，代价是常数倍；移除盒子那个量是 0 到 n，直接把状态从 O(n²) 顶到 O(n³)。

四、总结

  1. 当「区间本身」不足以决定后续时，把上下文补进状态：合唱队记最后插入在哪端，移除盒子记前面挂着几个同色。
  2. 合唱队的两个端点高度比较要分清对象：站在左端的新人比的是「上一个人」，那可能是 l+1，也可能是 r。
  3. 移除盒子的 k 负责在「先消」和「留着跟后面拼」两条路之间传递前缀，少了它，同色块永远攒不成大块。

状态里多带一个量的思路，后面很多树上 dp、博弈 dp 都会再用一次。
