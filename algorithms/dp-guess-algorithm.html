数据量一报，做法就得换：排列的 LCS 与严格递增

两道题都有一张「理所当然」的 dp 表：一个是 n×n 的 LCS 表，一个是「位置 × 数组里的值」的表。题目把数据量一报，两张表都开不出来。能救命的做法是把状态换掉，优化常数在这里没有用。

零、两道题

第一道：给出 1 到 n 的两个排列，求最长公共子序列的长度，n 到 105。

第二道：给你 arr1 和 arr2，每一步可以从 arr2 里挑一个数覆盖到 arr1 的某个位置上，问让 arr1 严格递增最少要几步，做不到返回 -1。两边长度都到 2000，值到 109。

两道题的共同点：脑子里第一张表都不大，但把 n 和值域代进去，格子数就变成 1010 量级。先算这笔账，再决定要不要动手写。

一、先算第一张表：n×n 的 LCS

最长公共子序列的经典写法是 dp[i][j]，两个下标各走一个串。n = 105 时格子数是 1010，一个格子 4 字节就是 40 GB。就算只用滚动数组把空间压到 O(n)，时间还是 1010 次比较。

实测滚动数组版：n = 2000 时 8.8 ms，n = 104 时 291.3 ms。按平方增长，n = 105 要 29 秒左右。这条路彻底堵死。

所以必须换个角度。题目给的是两个排列，这个结构一定要用上，不能当成两个任意数组来做。

二、把 b 换成「它在 a 里的位置」

记 where[x] 是数字 x 在排列 a 里的下标，然后把 b 里每个数换成它在 a 里的位置，得到数组 c。

为什么这样换有用？看一段公共子序列是什么意思：在 a 里挑若干个位置、在 b 里挑若干个位置，两边的数字一一对应且相对顺序一致。

现在换成位置来说：在 a 里挑的位置必须递增，而在 b 里挑的位置也递增，等价于它们对应的 where 值递增。

关键观察在这里：b 里一段递增的下标，取出来的 where 值必须递增；而 b 的子序列是按顺序取的，所以「b 的一个子序列」就是 c 的一个子序列，要求它递增。

于是 LCS 变成：求 c 的最长递增子序列。n = 105 的 LIS，用二分写法是 O(n log n)。

代码主要是两次遍历加一个二分：

// where[x] : 数字 x 在排列 a 里的下标
    for (int i = 0; i < n; i++) { where[a[i]] = i; }
    // b 换成「它在 a 里的位置」：公共子序列就是一段递增的位置
    for (int i = 0; i < n; i++) { c[i] = where[b[i]]; }

    // ends[k] 是长度 k+1 的递增子序列能取到的最小结尾
    int len = 0;
    for (int i = 0; i < n; i++) {
        int find = bs(len, c[i]);                  // 第一个 >= c[i] 的位置
        if (find == -1) { ends[len++] = c[i]; }
        else { ends[find] = c[i]; }
    }
    return len;

三、LIS 的二分写法

ends[k] 的含义是：所有长度为 k+1 的递增子序列里，结尾最小的那个值。

它一定是递增的。长度为 k+1 的序列结尾都比长度为 k 的小，那就把它截短成 k，矛盾。

来一个新数 num，在 ends 里找第一个大于等于它的位置：找到了就把它替掉，说明用 num 结尾、同样长度的子序列结尾更小；找不到说明 num 比所有结尾都大，直接接在最后，长度加一。

// ends[0..len-1] 严格递增，找第一个 >= num 的位置，没有返回 -1
    int bs(int len, int num) {
        int l = 0, r = len - 1, ans = -1;
        while (l <= r) {
            int mid = (l + r) / 2;
            if (ends[mid] >= num) { ans = mid; r = mid - 1; }
            else { l = mid + 1; }
        }
        return ans;
    }

这里有个细节值得说。因为 c 是 0 到 n-1 的一个排列，取值互不相同，二分里写 >= 还是写 > 结果完全一样。两万组随机排列实测，两种写法的 LIS 长度一次都没差过。

换成有重复值的 LIS，这两个符号就不等价了，所以别拿这条结论去改别的题。

实测这个转化够快：n = 104 时 0.48 ms，n = 105 时 1.77 ms，n = 106 时 21.0 ms。原本 29 秒的活，现在毫秒级。

五、第二张表：拿 arr1 的值当状态

回到严格递增那道题。看到「前一位是多少」会影响后面能不能保留，很容易想出一个状态：f(i, pre) 表示 arr1[i...] 在「前一位是 pre」的前提下最少还要换几次，pre 就是数组里的值。

值域到 109。状态数是 n × 109，第二维根本没法按下标开。

能救命的观察是：pre 其实不用记。规定 dp 的定义里带上一条约束，前一位不许被替换，那 pre 就只能是 arr1[i-1]，被状态里的 i 唯一确定了。

于是状态缩减成一维：dp[i] 表示 arr1[0..i-1] 已经严格递增、且 arr1[i-1] 没被替换时，arr1[i...] 最少还要换几次。

六、枚举「第一个不替换的位置」

有了 dp 的定义，转移就好写了：枚举 j，i 到 j-1 全部替换掉，j 保留，那么 arr1[j] 必须大于替换之后的那个数。

替换值是现成的：把 arr2 排序去重，从「刚比 pre 大的那个」开始往后取，一个个往上顶，天然严格递增，而且是能取到的最省钱的取值。

挑「刚比 pre 大的那个」要二分，所以内层每走一步就 find++，不用重新找。

// arr2[0..m-1] 严格递增，找第一个比 num 大的位置，没有返回 -1
    int bsGreater(int num) {
        int l = 0, r = m - 1, ans = -1;
        while (l <= r) {
            int mid = (l + r) / 2;
            if (arr2[mid] > num) { ans = mid; r = mid - 1; }
            else { l = mid + 1; }
        }
        return ans;
    }
// dp[i] : arr1[0..i-1] 已经严格递增、且 arr1[i-1] 没有被替换时，
    //         arr1[i...] 这一段最少还要换几次
    int f(int i) {
        if (i == n) { return 0; }
        if (dp[i] != -1) { return dp[i]; }
        int ans = INF;
        int pre = i == 0 ? INT_MIN : arr1[i - 1];
        int find = bsGreater(pre);                    // arr2 里刚比 pre 大的位置
        for (int j = i, k = 0; j <= n; j++, k++) {    // 枚举第一个不替换的位置 j
            if (j == n) {
                ans = min(ans, k);                    // i 后面全换
            } else {
                if (pre < arr1[j]) {                  // i 到 j-1 全换掉，j 留下
                    ans = min(ans, k + f(j + 1));
                }
                if (find != -1 && find < m) { pre = arr2[find++]; }   // 替换值只能一个个往上顶
                else { break; }
            }
        }
        return dp[i] = ans;
    }

上面这段是记忆化版。把它翻成严格位置依赖是一个方向的事，因为 dp 的定义决定了 f(i) 只依赖下标更大的状态，从右往左推就行：

// 严格位置依赖：i 从右往左推，j 的答案在表里已经填好了
    for (int i = n - 1; i >= 0; i--) {
        int ans = INF;
        int pre = i == 0 ? INT_MIN : arr1[i - 1];
        int find = bsGreater(pre);
        for (int j = i, k = 0; j <= n; j++, k++) {
            if (j == n) { ans = min(ans, k); }
            else {
                if (pre < arr1[j]) { ans = min(ans, k + dp[j + 1]); }
                if (find != -1 && find < m) { pre = arr2[find++]; }
                else { break; }
            }
        }
        dp[i] = ans;
    }
    return dp[0] == INF ? -1 : dp[0];

实测两个版本都在毫秒级：n = m = 500 时 0.09 / 0.11 ms，1000 时 0.26 / 0.38 ms，2000 时 0.86 / 1.32 ms。arr1 本来就递增时 1.35 ms 出 0。

八、写错的地方

1）排列 LCS 忘了映射，直接对 b 求 LIS。答案会看着挺像，两万组随机排列里 56.48% 出错。

2）严格递增里二分找「刚比 pre 大」写成「大于等于 pre」。两万组随机数据里抓出 9.80%，比想象中少，因为 arr2 里的值要正好落在 pre 上才会出错；值域越小越容易撞上。

3）替换值不往前走，内层枚举 j 的时候忘了 find++。这样后面几次替换会重复取同一个值，做不出严格递增。抓取率 58.37%，是这道题里最容易被抓的一条。

4）dp 定义里漏掉「arr1[i-1] 没被替换」这条约束，直接写成 dp[i] = min(dp[i+1], 1 + dp[i+1])。这时 pre 不再由 i 决定，状态信息不够，答案会偏小。

两个实现（记忆化与严格位置依赖）对拍过四千组随机小数据，另外单独用暴力（枚举每个位置保留或换成 arr2 里任一更大的值）验过同样的四千组，0 处不一致。

九、复杂度分析

问题做法时间空间
两个排列的 LCS经典 n×n 表O(n²)O(n²)，滚动后 O(n)
两个排列的 LCS映射成位置 + 二分 LISO(n log n)O(n)
严格递增的最小操作数值当状态（不可行）—O(n × 值域)
严格递增的最小操作数下标当状态 + 内层枚举 + 二分O(n·m + n log m)O(n + m)

严格递增那题的 n 和 m 都到 2000，O(n·m) 是 4×106，实测 1.3 ms。先确认 O(n·m) 这个量级本身够用就够了，不用急着把它优化成 O(n log m)。

十、总结

两道题各记一条。排列的 LCS：题目给的是排列，就要把「值」换成「位置」，公共子序列变成递增子序列，O(n²) 降成 O(n log n)。严格递增：把「前一位是多少」从状态里赶出去，办法是在 dp 的定义里加一条「前一位不许被替换」的约束，可变参数被下标锁死，值域再大也不进状态。

两道题的判断顺序都一样：先把想法的表格子数算出来，跟数据量对一遍，再动手写代码。下一道题会走到这一步的尽头：连 dp 都摆不下，只剩一个构造。
