Manacher：最长回文子串

求一个串里最长的回文子串，暴力做法是从每个中心往两边扩。中心有 2n − 1 个，每个中心最多扩 n 次，平方级。Manacher 把它压到线性：算到某个中心时，前面那段最靠右的回文能直接搬来一半答案，只有撞上它的右边界才需要真的往外扩。

零、中心扩展

回文子串的中心有两种：一个字符（回文长度是奇数），或者两个字符之间的缝（长度是偶数）。一个长度 n 的串有 2n − 1 个中心，从每个中心往两边扩，扩到字符不等或者出界为止，取最大的那个长度。

n = 16000 的全 a 串实测 87.52 毫秒，n = 2000 时只要 1.14 毫秒。n 每翻一倍耗时乘 4，是标准的平方级。按这个速度推到 5.5×106，要 104 秒量级。

一、扩展串

偶长度的回文没有中心字符，写代码时就得分成两套循环，先跑一遍奇数再跑一遍偶数。把奇偶两种情形统一起来的办法，是在相邻两个字符之间、以及串的两端各塞一个分隔符。

分隔符用什么字符都行，只要它和原串里的字符都不相等，并且与它自己相等。取 '#' 最省事，扩展串长 2n + 1。原串里的每个字符落在扩展串的奇数下标上，每两个字符之间多出一个 '#'。

这样一来，任何回文在扩展串里都有一个字符中心。奇数长度的回文中心是原串的某个字符，偶数长度回文的中心是夹在两个字符中间的那个 '#'。

分隔符的位置关系也得对：'#' 与 '#' 相等，'#' 与字母不等，正好还原出原始回文里「隔一个比一个」的比较。

扩展串建好了，后面就只有一个数组要填。

// 扩展串：原串相邻字符之间、以及两端都插一个 '#'
    const int MAXN = 11000001;

    char ss[MAXN << 1];
    int p[MAXN << 1];
    int n;

    void manacherss(const string &a) {
        n = (int)a.size() * 2 + 1;
        for (int i = 0, j = 0; i < n; i++) {
            ss[i] = (i & 1) == 0 ? '#' : a[j++];
        }
    }

二、回文半径数组

p[i] 是以 i 为中心在扩展串里能往两边扩多少步，算上中心那一格。以 i 为中心的最长回文在扩展串里覆盖 [i − p[i] + 1, i + p[i] − 1] 这一段。

扩展串里两端都是 '#'，所以半径一定是奇数；每往里走一格就跨过一个 '#' 或者一个字母。原串里的真实回文长度和它差一倍：

真实长度 = p[i] − 1。

拿 "abacaba" 的数：扩展串是 "#a#b#a#c#a#b#a#"，下标 7 上是 'c'，p[7] = 8，最长回文长度就是 8 − 1 = 7，也就是整个串。

填 p 的顺序是从左到右。填到 i 时，前面所有中心的 p 值都已经算完，这里就是能偷懒的地方。

三、最靠右的那段回文

两个变量：c 和 r。已经算完的回文里，右端点最靠右的那一个，记它的中心为 c，r 是它右边第一个没被覆盖的位置，也就是 r = c + p[c]。

为什么只记最靠右的那个？因为 i 从小到大走，只有最靠右的那段才有可能覆盖到当前这个 i。

来到中心 i 时先看 i 和 r 的位置关系，分两类。

1）i 没有被 r 包住（i ≥ r）。i 右边没人在前头替它算过，只能老老实实从 len = 1 往外扩。

2）i 被 r 包住（i < r）。以 c 回文对称，i 在 c 左边有一个镜像位置 j = 2c − i。j 的 p[j] 早就算完了，而 j 处的回文和 i 处的回文在同一段对称结构里，p[j] 能直接拿来用。

不过只能搬一部分：i 的回文一旦越过 r，右边就出了大回文的范围，信息不够了；左边越过 L = 2c − r 也一样。所以搬的是 min(p[j], r − i)。

把这三种情况画出来就好记了。

最右边的 r 每轮都要更新：如果这一轮扩出来的回文超出了原来的 r，就把 c 和 r 一起换掉。

四、一个 while 吃掉四种情况

按上面三种情况分开写，代码会长出三个分支。Manacher 的写法把它们压成两行：先给 len 一个初值，再让一个 while 无条件地往外扩。

len 的初值就是 min(p[2c − i], r − i)，i 没被覆盖时给 1。关键在于这个初值永远不会比真实半径大。镜像点 j 的回文没有越过左边界时，白拿的值就是 i 的真实半径，while 第一圈就发现两边字符不等，白拿的那个值原样留下；j 的回文越过左边界、或者 i 本来就在界外时，初值偏小，while 会一圈一圈把它补到真正的边界。

初值给的是「保守的下界」，while 负责补差额，两种情况自动接上，不需要分辨自己身处哪一种。

// 主循环：c、r 记住目前最靠右的那段回文，每次先白拿一段再往外扩
    int manacher(const string &str) {
        manacherss(str);
        int maxlen = 0;
        for (int i = 0, c = 0, r = 0, len; i < n; i++) {
            len = r > i ? min(p[2 * c - i], r - i) : 1;
            while (i + len < n && i - len >= 0 && ss[i + len] == ss[i - len]) {
                len++;
            }
            if (i + len > r) {
                r = i + len;
                c = i;
            }
            maxlen = max(maxlen, len);
            p[i] = len;
        }
        return maxlen - 1;
    }

n = 5.5×106 的串跑一遍 35 毫秒上下。随机 0/1 串 n = 106、2×106、4×106 分别 11.89、33.40、75.42 毫秒，随 n 线性。

逐格跑 Manacher

每点一步处理一个中心，蓝底是这一格扩出来的回文区间，橙框是这一格的中心。切到错误版本，看答案从哪一步开始偏。

写的时候有三处容易错。

一，返回值必须减 1。p 是在扩展串上量的，每个真实回文在扩展串里都多出一圈 '#'，直接返回最大值会大 1。这个错法在任何输入上都错，实测 20000 组随机小串，100% 与正解不同。

二，扩展串要隔位插分隔符。只在最左边插一个 '#' 的话，奇长度回文还能算，偶长度回文全部漏掉，实测也是 100% 出错。

三，白拿的时候要夹 r − i。只写 p[2c − i] 的话，i 靠近 r 时会把超出范围的半径也搬过来，答案偏大。值域小的时候这个错法特别容易现形：字符表取 3、串长 40 时 47.39%，字符表取 26、串长 200 时只剩 9.60%。

反过来有一处看着像错，其实改不改一样：更新 r 的那一行写成 if (i + len >= r)，答案和 p 数组都一模一样，实测 0.00% 差异。原因是 i + len 恰好等于 r 时，r 的值没变，只是把中心 c 换成了 i，而 i 到 r 的这段上镜像点的取值和原中心给出的一样。

五、复杂度分析

做法关键操作时间空间
中心扩展2n − 1 个中心各自往外扩O(n2)O(1)
Manacher每个中心白拿一段再补扩O(n)O(n)

线性的理由是：while 每成功一圈就把 r 往右推一格，而 r 只增不减，最多推 n 步；白拿的那部分不花时间。所以整趟循环里 while 成功执行的次数加起来不超过 2n，是摊还 O(n)。空间上 ss 与 p 各开 2n + 1 格，按题目上限 |s| = 1.1×107 算，扩展串 2200 万格：ss 是 22 MB 的字符数组，p 是 88 MB 的 int 数组。

总结

扩展串把奇偶两种回文合成一种，长度 2n + 1，任何回文都有唯一的字符中心；真实回文长度就是 p[i] − 1。

加速靠 c 和 r 这两格：c 是当前最靠右回文的中心，r 是它右边第一个没覆盖的位置。i 被 r 包住时先白拿 min(p[2c − i], r − i)，再让 while 补差额。初值永远不超过真实半径，所以不用分辨自己属于哪一种情况。

时间和空间都是 O(n)，n = 5.5×106 实测 35 毫秒；同规模的中心扩展要平方级的时间。把回文半径数组完整留下来之后，还能回答「以每个位置为中心的回文有多少个」这类问题。
