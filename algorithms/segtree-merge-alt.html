线段树：接缝条件与固定点查询

同一副骨架搬到别的问题上时，会碰到两种变化。接缝能不能拼，有时得看原始数组上挨着的两个格子，而不是左右两个结点里的量。另一种查询问的是「某一栋房子往两边能连出去多远」，跟「某个区间里最长的一段」完全是两回事，这时候连最长那个量都可以不要。

零、背景

「连续 1 最长」的那副骨架有两个组成部分：结点上存三个量，合并时取三个候选里的最大。这两个部分是可以拆开换的。

先换接缝条件。数 1 的时候，判断接缝能不能拼只看「左儿子的后缀有多长、右儿子的前缀有多长」，因为「能拼」这件事等价于左右都是 1。把数字换成两个交替出现的字符之后，「能拼」等价于接缝两侧的两个字符不一样，这个条件在左右两个结点的量里读不出来，得回头看一眼原始数组。

再换查询。有一种问法是从某个位置出发往两边走，问能走多远。这种问法只关心贴着这个位置的那一段，最长的那一段反而没人问，于是结点上少存一个量，多出来的是查询时从根往下找落点。

一、题目一：最长 LR 交替子串

最长 LR 交替子串（洛谷 P6492）：长度 n 的字符串，一开始全是 L。有 q 次修改，每次指定一个位置 i，是 L 就改成 R，是 R 就改成 L。一个子串如果相邻字符两两不同，就称它有效。每次修改后输出当前整个字符串里最长有效子串的长度。

n 和 q 都到 2 × 10⁵。每次修改之后都要重新回答，逐格扫一遍是 O(nq)，扛不住。

把 L 记成 0、R 记成 1，问题就变成「相邻两数不同的最长连续段」。同一个位置上字符来回改，所以每次修改都是单点操作，不需要懒标记，也就不需要往下推。

二、接缝条件：看挨着的两个格子

三个量的定义照搬：len 是这一段里最长的有效子串长度，pre 是从最左边开始的有效前缀长度，suf 是贴到最右边的有效后缀长度。

合并时，先按普通方式取 len 的两个候选（左儿子的、右儿子的），然后看接缝。接缝能拼的判据只有一个字符的比较：arr[mid] 和 arr[mid + 1] 是否不同。相同就什么都不做，不同才有第三个候选，长度是左儿子的 suf 加右儿子的 pre。

这一步是这道题最特别的地方。up 里必须能看到原始数组，或者至少在结点上多存两个字符（左边界那个、右边界那个）供比较。左右两个结点各自维护得再完整，也判断不出接缝两侧的字符是否相同。

三、前缀和后缀往外伸的条件

pre 的更新同样分两种情况，判据是「左儿子自己整段都是有效的」，也就是 len[左] 等于左儿子的长度。成立时 pre 等于左儿子长度加上右儿子的 pre，不成立时就是左儿子自己的 pre。

两个条件不能弄混。接缝能拼是第三个候选出现的前提，左右两边各自整段有效则是前缀、后缀能往外伸的前提。接缝拼得上，但左儿子内部有断点，前缀照样伸不出去。

const int MAXN = 200001;

    int arr[MAXN];          // 0 表示 L，1 表示 R
    int len[MAXN << 2];     // 这一段里最长的交替子串有多长
    int pre[MAXN << 2];     // 这一段里，从最左边开始能交替多长
    int suf[MAXN << 2];     // 这一段里，贴到最右边能交替多长

    // 交替不交替，只看拼起来的那两个字符
    void up(int l, int r, int i) {
        len[i] = max(len[i << 1], len[i << 1 | 1]);
        pre[i] = pre[i << 1];
        suf[i] = suf[i << 1 | 1];
        int mid = (l + r) >> 1;
        int ln = mid - l + 1, rn = r - mid;
        if (arr[mid] != arr[mid + 1]) {
            len[i] = max(len[i], suf[i << 1] + pre[i << 1 | 1]);
            if (len[i << 1] == ln) {
                pre[i] = ln + pre[i << 1 | 1];
            }
            if (len[i << 1 | 1] == rn) {
                suf[i] = rn + suf[i << 1];
            }
        }
    }

    // 单点取反，一路上会改的只有包含这一位的那些结点
    void flip(int jobi, int l, int r, int i) {
        if (l == r) {
            arr[jobi] ^= 1;
        } else {
            int mid = (l + r) >> 1;
            if (jobi <= mid) {
                flip(jobi, l, mid, i << 1);
            } else {
                flip(jobi, mid + 1, r, i << 1 | 1);
            }
            up(l, r, i);
        }
    }

因为每次修改都是单点取反，flip 递归到底之后一路 up 回来就行，没有任何懒标记。

四、题目二：地道相连的房子

地道相连的房子（洛谷 P1503）：n 栋房子排成一排，编号 1 到 n，一开始每相邻两栋之间都有地道。三种操作：

  • D x：摧毁 x 号房子，它两侧的地道一并毁掉。
  • R：恢复上一次被摧毁的房子，它两侧的地道一并恢复。
  • Q x：问 x 号房子能到达的房子数量，包括它自己。

n 和 m 都到 50000。地道是相邻两栋之间连的，所以「能到达」就是「处在一段连续的完好房子里」。问 x 能到几栋，等于问包含 x 的那一段完好房子有多长。

R 恢复的是「上一次被摧毁的那一栋」，所以得拿一个栈把摧毁过的编号按顺序记下来，R 就弹出栈顶。这一点跟线段树无关，但漏了就没法做。

五、只要两个量

存三个量是为了回答「这一段里最长的一段有多长」。这道题不问这个，问的是「包含某个位置的那一段有多长」，所以 len 可以不存。

少一个量带来的好处在合并那一步：pre 和 suf 的更新完全不依赖 len，判断条件直接写成「左儿子的 pre 是否等于左儿子的长度」，比「len 是否等于长度」还直白。

const int MAXN = 50001;

    int pre[MAXN << 2];     // 这一段里，从最左边开始有多少栋连着的完好房子
    int suf[MAXN << 2];     // 这一段里，贴到最右边有多少栋连着的完好房子
    int stk[MAXN];          // 摧毁过的房子按顺序记下来，恢复操作要用

    // 只要两个量：最长的那个没人问，问的是「从某一点能连出去多远」
    void up(int l, int r, int i) {
        pre[i] = pre[i << 1];
        suf[i] = suf[i << 1 | 1];
        int mid = (l + r) >> 1;
        if (pre[i << 1] == mid - l + 1) {
            pre[i] += pre[i << 1 | 1];
        }
        if (suf[i << 1 | 1] == r - mid) {
            suf[i] += suf[i << 1];
        }
    }

    // 把 jobi 号房子改成 jobv：0 是摧毁，1 是恢复
    void update(int jobi, int jobv, int l, int r, int i) {
        if (l == r) {
            pre[i] = suf[i] = jobv;
        } else {
            int mid = (l + r) >> 1;
            if (jobi <= mid) {
                update(jobi, jobv, l, mid, i << 1);
            } else {
                update(jobi, jobv, mid + 1, r, i << 1 | 1);
            }
            up(l, r, i);
        }
    }

六、查询：从固定点往两侧扩

查询是这道题真正的难点。不能把 [1, x] 和 [x, n] 当成两个区间分别查再相加，因为那样会把断点前后的两段都算进来。要问的是恰好包含 x 的那一段。

做法是从根往下走，一路把范围缩到只剩 x 附近的接缝处。设当前走到 [l, r]，中点是 mid。

如果 x 落在左半边，就看 x 是不是落在左儿子的后缀里，判据是 x > mid - suf[左]。成立说明从 x 一直连到 mid 全是完好的，这一段还会接上右儿子的前缀，答案就是 suf[左] + pre[右]。不成立说明包含 x 的那一段整个都在左儿子里面，往左儿子递归。

x 落在右半边时对称：判据是 mid + pre[右] >= x。

两个判据的边界都只差一格，值得单独说一句。左儿子的后缀占的是 mid 往左数的 suf[左] 个位置，最左那一格是 mid - suf[左] + 1。x 落在里面等价于 x >= mid - suf[左] + 1，两边同减 1 就是 x > mid - suf[左]。写成 >= 会把紧挨着后缀左边的那一格也算进去，那一格其实是断的。右边同理，>= 是对的，写成 > 会漏掉恰好等于的那一格。

// 已知 jobi 落在 l..r 里，返回它往两侧能连出多少栋房子
    // 潜台词：jobi 连出的那一整段，一定不会伸到 l..r 外面去
    int query(int jobi, int l, int r, int i) {
        if (l == r) {
            return pre[i];
        }
        int mid = (l + r) >> 1;
        if (jobi <= mid) {
            // jobi 落在左半边的后缀里，答案要跨过接缝
            if (jobi > mid - suf[i << 1]) {
                return suf[i << 1] + pre[i << 1 | 1];
            }
            return query(jobi, l, mid, i << 1);
        } else {
            // jobi 落在右半边的前缀里，答案同样要跨过接缝
            if (mid + pre[i << 1 | 1] >= jobi) {
                return suf[i << 1] + pre[i << 1 | 1];
            }
            return query(jobi, mid + 1, r, i << 1 | 1);
        }
    }

递归下去的时候有一个前提一直成立：x 能连出的那一整段不会伸到当前范围之外。每往下一层，范围都收了一半，而 x 一定还在里面。所以递归到底返回 pre 就是答案（叶子上的 pre 只有 0 和 1 两种取值）。

七、复杂度分析

项最长 LR 交替子串地道相连的房子
建树O(n)O(n)
单次修改O(log n)：单点取反，无懒标记O(log n)：单点改动
单次查询O(1)：直接读根上的 lenO(log n)：沿一条路径往下走
全程总代价O((n + q) log n)O((n + m) log n)
空间O(n)：三个四倍长度的 int 数组O(n)：两个四倍长度的 int 数组，加一个长度 n 的栈

实测开销，g++ -O2。交替子串 n = q = 2 × 10⁵ 时 27.69 ms；同样这份代码在 n = q = 2 × 10⁴ 时 1.95 ms，逐格重扫的暴力是 104.97 ms，差 54 倍。

地道 n = m = 5 × 10⁴ 时 3.24 ms。这道题的暴力快不快，全看查询占多少：摧毁操作占四成、查询也占四成时，暴力只要 0.91 ms，比线段树还快；查询占到九成以上时，暴力要 583.27 ms，线段树 0.33 ms，差约 1770 倍。暴力每次查询要向两边一格一格走，查询越多越吃亏。

空间按题目上限算：交替子串 MAXN 取 200001，四倍就是 800004 个结点，三个 int 数组 9.16 MiB，加上存初值的数组 0.76 MiB，合计 9.92 MiB；地道 MAXN 取 50001，四倍 200004 个结点，两个 int 数组 1.53 MiB，加上长度 50001 的栈 0.19 MiB，合计 1.72 MiB。

八、几种写错的样子

每档 3000 组随机操作，n 分别是 4、8、16、64。表里是「错版答案与正解不同」的比例。

写错的地方n = 4n = 8n = 16n = 64

前缀不往外伸100.00%100.00%100.00%98.50%
后缀不往外伸100.00%99.97%100.00%98.87%
地道左边界 x 大于 mid 减后缀，写成大于等于81.30%85.50%78.40%45.90%
地道右边界，写成大于65.80%73.33%72.07%47.70%

前两行几乎必错，因为它们改的是每次都要读走的量：交替串的答案就是根上的 len，接缝条件写反相当于把「相邻不同」变成了「相邻相同」。

后两行到 n = 64 掉到 45.90% 和 47.70%，道理在值域上。判据差的那一格只在 x 恰好等于边界时才体现出来，n 越大，随机取到的 x 正好压在这一格上的机会越少。比例掉下来不等于错法变对，小数据上的高比例和大数据上的低比例都不能互相替代。

九、总结

同一副骨架能套到不同问题上，靠的是把「接缝能不能拼」和「前缀后缀能不能伸出去」当成两个独立的开关。前者有时能只靠左右结点的量判断（连续 1 里看长度对不对得上），有时必须回头看原始数组（交替串里比挨着的两个字符）。后者永远是在问「左儿子自己整段是否符合要求」。

查询只要能落在一个点上，就可以把「最长」这个量整个拿掉，只留前缀和后缀，然后沿一条路径往下走到接缝处，答案是两个量相加。这条路走到底只要 O(log n) 步，而且每一步的判断都只看当前结点的两个儿子。

两个问题的代码都没有懒标记。单点修改一路往下、回来时把路径上的结点重算一遍，就足够了。

最后

三点。一是交替串的 up 必须能读到原始数组，比较 arr[mid] 和 arr[mid + 1]；把这两个字符当成结点上的附加信息存起来也行，但那样每个结点都要多存两位。

二是地道的两个边界判据只差一格，写成 >= 或 > 都会把紧挨着的断点算进来或漏掉。x > mid - suf[左] 和 mid + pre[右] >= x 这两句值得单独核一遍。

三是 R 操作恢复的是上一次摧毁的那一栋，必须用栈按顺序记下来，不能恢复编号最大或最小的那栋。
