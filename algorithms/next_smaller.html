下一个更小元素

给一个数组，求每个位置 i 右侧第一个小于 nums[i] 的位置，从右往左扫一遍，用一个单调栈把候选留下来，整道题压到 O(n)。

零、背景

前面几节处理的都是「给一个区间，问这个区间的答案」：分块按位置切、莫队按查询排序、值域分治按值拆开。

这一节换一类问题：不问区间，而是对每个位置单独问一句，它右边第一个满足某个条件的位置在哪。

这类问题有个共同点：条件只跟「大小」有关，跟「距离多远」无关。只要抓住这一点，就能一遍扫完。

一、问题

给定一个长度为 n 的数组 nums，对每个位置 i，找它右侧第一个小于 nums[i] 的位置 j；不存在就记 -1。

例子沿用前面几节那个数组：

nums = [3, 1, 4, 1, 5, 9, 2, 6]

逐个看一遍：位置 0 的 3，右边第一个比它小的是位置 1 的 1；位置 4 的 5 和位置 5 的 9，右边第一个比它们小的都是位置 6 的 2；位置 1、3 的 1 右侧没有更小的，位置 6 右侧只有一个 6，位置 7 右侧没有元素，答案都是 -1。

要的是对所有位置同时给出答案，而不是单个查询。

二、朴素做法

对每个位置 i，从 i+1 一路向右扫到第一个比它小的数：

for (int i = 0; i < n; i++) {
    ans[i] = -1;
    for (int j = i + 1; j < n; j++) {
        if (nums[j] < nums[i]) {
            ans[i] = j;
            break;
        }
    }
}

可以发现，位置 3 的 1 和位置 1 的 1 都要把右边整个尾巴走一遍才知道「没有」。而位置 4 扫过 9 之后才碰到 2，位置 5 又重新扫了一遍同样的 9 和 2。

重复就出在这里：右边这段到底有没有更小的数、第一个更小的是谁，其实跟 i 是谁没关系，只跟 nums[i] 有多大有关。

三、从右往左扫

既然每次问的都是「右边第一个比我小的」，那就倒着走：先处理最右边，一路往左，处理到 i 时，i 右边的所有位置都已经看过了。

看过的这些位置里，并不是每个都需要留着。比如下标 k 和 i 满足 i < k 且 nums[i] ≤ nums[k]，那么 k 就可以扔掉了。

理由是：假设某个 p ≤ i 的答案本来是 k，也就是 nums[k] < nums[p]，且 k 是右边第一个满足的。可是 i 在 p 和 k 之间，nums[i] ≤ nums[k] < nums[p]，i 也满足，而且离 p 更近。矛盾。所以 k 不可能成为任何 p ≤ i 的答案。

于是维护一个栈，里面只放「还没被扔掉」的下标。处理 i 时做三件事：

  1. 把栈顶所有满足 nums[k] ≥ nums[i] 的下标弹出，按上面的理由，它们以后用不上了。
  2. 弹完之后栈顶如果还在，它的值一定 < nums[i]，而且它是剩下这些里最靠左的，正是 i 右侧第一个更小的位置，记进 ans[i]。
  3. 把 i 压进栈，留给更左边的位置用。

这里有个细节：弹出某个下标，不代表它的答案丢了，它的答案在上一步已经写进 ans 了。弹的是「它作为别人 candidate 的资格」。

四、栈是什么形状

从右往左走，先压进去的下标大、后压进去的下标小，所以从栈底到栈顶，下标是递减的。

再看值：每次压入 i 之前，所有 ≥ nums[i] 的都被弹掉了，留下来的都比 nums[i] 小，压进去之后 nums[i] 就变成了栈里最大的那个。所以从栈底到栈顶，值是递增的。

两个方向合起来：栈底是最靠右、最小的那个，栈顶是最靠左、最大的那个。这就是「单调栈」这个名字的来历。

栈顶是「最靠左、值最大」的那个，所以它也是第一个可能挡不住 nums[i] 的位置。弹出之后剩下的栈顶，就是值小于 nums[i] 的里面最靠左的，正是要找的答案。

七、代码

#include <bits/stdc++.h>
using namespace std;

// 示例：与上文同一数组
int nums[] = {3, 1, 4, 1, 5, 9, 2, 6};
int n = sizeof(nums) / sizeof(nums[0]);
int ans[100];                  // 答案：ans[i] = 右侧第一个 < nums[i] 的下标，没有则 -1

void next_smaller() {
    vector<int> st;            // 单调栈，存下标；对应的 nums[st[...]] 严格递增
    for (int i = n - 1; i >= 0; i--) {
        // 1. 弹出栈顶所有 >= nums[i] 的下标（它们不可能成为 i 的答案）
        while (!st.empty() && nums[st.back()] >= nums[i])
            st.pop_back();

        // 2. 此时栈顶（如果存在）就是 i 右侧第一个更小的位置
        ans[i] = st.empty() ? -1 : st.back();

        // 3. 把 i 入栈，留给左侧的位置用
        st.push_back(i);
    }
}

int main() {
    next_smaller();
    for (int i = 0; i < n; i++)
        cout << "ans[" << i << "] = " << ans[i] << endl;
    return 0;
}

输出是 1, -1, 3, -1, 6, 6, -1, -1，与第一节那张图一致。

八、复杂度分析

操作时间复杂度
遍历 i（从 n-1 到 0）O(n)
入栈合计（每个下标一次）O(n)
出栈合计（每个下标至多一次）O(n)
单次比较（只比栈顶）O(1)
整体O(n)
朴素做法（对照）O(n²)

出栈次数为什么是 O(n)：下标一旦弹出就再也不会回到栈里，而入栈总共只有 n 次，所以弹出次数不可能超过 n。while 循环看着像嵌套，摊下来是常数。

空间上，栈里最多同时放 n 个下标，答案数组 n 个 int，额外空间 O(n)；不算答案数组的话是栈的 O(n)。

九、最后

这套写法能用的前提是：条件只跟「大小」有关，而且要的是「第一个」，不是「第几个」也不是「一共有几个」。求第 k 个更小、或者统计右边比它小的有多少个，单调栈给不出答案，那类问题得用树状数组或归并。

换个条件基本是照抄：求「右侧第一个大于」，把 >= 改成 <=，栈就变成值递减；求「左侧第一个小于」，把循环改成从左往右，其余不动。

一个常见用法是两边各扫一次：比如直方图最大矩形，对每个柱子求左、右两侧第一个比它矮的位置，就把它能撑开的宽度定下来了。两次单调栈，整体还是 O(n)。
