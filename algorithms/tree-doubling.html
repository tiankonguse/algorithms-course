树上倍增：跳表、k 级祖先与 LCA

树上一个点往上走 k 步落在哪、两个点的最低公共祖先是谁，这两个问题共用同一张表：stjump[u][p] 记「从 u 往上跳 2^p 步落在哪个节点」。表建一次 O(n log n)，两个问题都压成 O(log n) 一次查询。

零、背景

parent 数组只回答「上一级是谁」。顺着 parent 一路往上，问「第 k 个祖先」要走 k 次，问「两点的最低公共祖先」要先爬到同一层再一起往上挪。n = 5 × 10⁵ 的链上，一次查询平均要爬 25 万层，m = 5 × 10⁵ 条查询就是 1.25 × 10¹¹ 次跳跃。

跳表把「一步一步走」换成「按 2 的幂整块跳」。这和 ST 表是同一个想法：预处理所有长度为 2 的幂的区间，查询时把跨度拆成二进制，最多 log n 块拼出来。

一、问题

题目一，树节点的第 K 个祖先：n 个节点编号 0 到 n − 1，根节点是 0 号，parent 数组给出每个点的父亲。反复调用 getKthAncestor(i, k)，返回从 i 往上跳 k 步到的节点，不存在返回 −1。n 上限 5 × 10⁴。

题目二，最近公共祖先：n 个点、n − 1 条边、指定根 root，m 条查询 u v，每条打印 u 和 v 的最低公共祖先。n、m 上限都是 5 × 10⁵。

两道题的输入形态不一样（一个给 parent 数组、一个给边表），但解法的核心完全是一张表。

二、朴素做法的真实代价

先把「一步步往上爬」的账算清楚，才知道跳表到底省在哪。链形数据 n = 5 × 10⁵，随机 m 组点对，逐格爬 405.57 微秒一次，跳表 1.43 微秒一次，283.5 倍；n = 10⁵ 的链是 98.72 对 0.16 微秒，627 倍。

换个树形结论就翻过来了。星形（所有点都挂在根下）n = 5 × 10⁵，逐格只要 0.0063 微秒，跳表要 0.1791 微秒，反过来慢 28 倍。原因很直接：星上所有点都在第 2 层，逐格只走一步；跳表不管树多深，每档都老老实实试一遍，power = 18 就是 19 次判断。

这条结论值得记住：跳表换来的是 O(log n) 这个上界，代价是每档都要试一遍。深度本身就小于 log n 的时候，这笔账是亏的。

三、跳表长什么样

两张表。deep[u] 记 u 在第几层，根算第 1 层。stjump[u][p] 记从 u 往上跳 2^p 步落在哪个节点。

第 0 列就是父亲：stjump[u][0] = parent[u]。后面的列递推：往上跳 2^p 步，等于先跳 2^(p−1) 步落到一个中间点，再从中间点跳 2^(p−1) 步。写成式子就是 stjump[u][p] = stjump[ stjump[u][p−1] ][p−1]。

四、power 取多少

列数 = power + 1，power 取 ⌊log₂ n⌋。写成代码是这样：

// 一个数用二进制表示需要几位，反过来问：<= n 的最大 2 的幂是 2 的几次方
    // 它就是跳表的列数减一，整个预处理只算这一次
    int floorLog(int n) {
        int ans = 0;
        // 判据必须写成 (1 << ans) <= (n >> 1)
        // 写成 <= n 会溢出：ans 涨到 31 时 1 << 31 在 int 里是负数，照样满足判据
        while ((1 << ans) <= (n >> 1)) {
            ans++;
        }
        return ans;
    }

判据里为什么是 (n >> 1) 而不是 n？ans 涨到 31 时 1 << 31 在 int 里是 −2147483648，照样满足「≤ n」，循环停不下来。先右移一位就把最高位空出来了。

实测取值：n = 8 得 3、n = 50000 得 15、n = 500000 得 18、n = 10⁶ 得 19。注意 n = 500000 时 2¹⁸ = 262144 比 n 小，但这够用：任何 k ≤ n 的二进制最高位不会超过 ⌊log₂ n⌋，拼得出来。

题目二上限 n = 5 × 10⁵，power = 18，19 列。stjump 就是 500001 × 19 × 4 B = 36.24 MB，加 deep 1.91 MB、建图 9.54 MB，一共 47.69 MB。

五、存图与一次 dfs 填两张表

树是无向图，用链式前向星存：head[u] 是 u 的边链表的头，nxt 指向下一条边，边从 1 号开始编号，0 表示没有下一条。

// 链式前向星：同一个点的所有边串成一条链，head[u] 是链头，nxt 指向下一条
    const int MAXN = 500001;
    const int LIMIT = 21;

    int head[MAXN], nxt[MAXN << 1], to[MAXN << 1], cnt;
    int deep[MAXN];             // deep[i] : 节点 i 在第几层，根节点是第 1 层
    int stjump[MAXN][LIMIT];    // stjump[i][p] : 从 i 往上跳 2^p 步到的节点
    int power;

    void build(int n) {
        power = floorLog(n);
        cnt = 1;
        for (int i = 1; i <= n; i++) {
            head[i] = 0;
        }
    }

    void addEdge(int u, int v) {
        nxt[cnt] = head[u];
        to[cnt] = v;
        head[u] = cnt++;
    }

填表的一次 dfs 顺手把 deep 也算了。三行：先定层号，再填第 0 列，然后从第 1 列滚到第 power 列，最后才往下走儿子。

// 一次 dfs 同时把深度表和跳表都填上
    // 当前来到 u 节点，u 的父亲是 f
    void dfs(int u, int f) {
        deep[u] = deep[f] + 1;
        stjump[u][0] = f;
        // 跳 2^p 步 = 先跳 2^(p-1) 步，落到中间点，再从中间点跳 2^(p-1) 步
        for (int p = 1; p <= power; p++) {
            stjump[u][p] = stjump[stjump[u][p - 1]][p - 1];
        }
        for (int e = head[u], v; e != 0; e = nxt[e]) {
            v = to[e];
            if (v != f) {
                dfs(v, u);
            }
        }
    }

这里有个细节：根的父亲记成 0，deep[0] 保持 0。这样「跳出去」的落点是 0 号，deep[0] = 0 比任何合法层号都小，后面所有「deep[落点] ≥ s」的判据都会自动把它挡住，不必单独写越界判断。

六、第 k 个祖先

目标是第 s = deep[i] − k 层。从大到小试每一档，跳过去还在第 s 层或更深就跳，否则留着。

// 返回 i 的第 k 个祖先，不存在返回 -1
    int getKthAncestor(int i, int k) {
        // deep 从 1 起算，往上最多只能走 deep[i] - 1 步
        if (deep[i] <= k) {
            return -1;
        }
        int s = deep[i] - k;            // 目标层号
        for (int p = power; p >= 0; p--) {
            // 跳过去不能越过第 s 层：跳完还在 s 层或更深才跳
            if (deep[stjump[i][p]] >= s) {
                i = stjump[i][p];
            }
        }
        return i;
    }

为什么从大到小？每档都是「能跳就跳」，大的先挑走，剩下的用小档补齐，这正是二进制拆分。反过来从小档开始试会先把小步数用掉，大档反而跳不过去。

从某个点往上跳 k 步

题目一的口径：根是 0 号，deep[0] = 1。选起点和 k，逐档看哪几档真的跳了。

七、LCA 的两阶段

第一步对齐：把深的那个抬到和浅的同一层，用的就是上一段那一句判据，只是 s 换成了 deep[b]。

第二步同步跳：a 和 b 同层之后，从大到小试每一档，只要两者的 2^p 级祖先不一样就一起跳。跳到两个祖先相同为止，此时 a、b 的父亲就是答案。

int lca(int a, int b) {
        // 先保证 a 是更深的那个
        if (deep[a] < deep[b]) {
            int tmp = a; a = b; b = tmp;
        }
        // 第一阶段：把 a 抬到和 b 同一层
        // 从大到小试，跳过去不能比 b 还浅
        for (int p = power; p >= 0; p--) {
            if (deep[stjump[a][p]] >= deep[b]) {
                a = stjump[a][p];
            }
        }
        if (a == b) {
            return a;                  // b 本来就是 a 的祖先
        }
        // 第二阶段：a 和 b 同深度，一起往上跳
        // 只要 2^p 级祖先还不一样就跳，说明答案还在更上面
        for (int p = power; p >= 0; p--) {
            if (stjump[a][p] != stjump[b][p]) {
                a = stjump[a][p];
                b = stjump[b][p];
            }
        }
        // 循环结束时 a、b 的父节点是同一个，那就是答案
        return stjump[a][0];
    }

「不一样就跳」这个判据怎么理解？如果 a、b 的 2^p 级祖先相同，说明答案在它们下面（或者就是它），这一档跳上去会越过答案，不跳；如果不同，说明答案还在更上面，跳上去不会跨过答案。

阶段一结束时如果 a 已经等于 b，直接返回 b 就行：说明 b 本来就是 a 的祖先。漏掉这一句不会算错，只是白跑一遍阶段二。

八、递归改迭代

题目二的 n 上限是 5 × 10⁵，链形数据递归必然爆栈。实测：这条 dfs 在链上 13 万层还能正常返回，13.05 万层就段错误（exit 139）。本机栈上限 8176 KB，一帧约 64 字节。

改成迭代的办法是自己在数组里开栈，栈里压三样东西：当前处理的点 u、它的父亲 f、处理到第几号边 e。e = −1 是「第一次来到 u」，e = 某个边号是「回来接着走」，e = 0 是「边都走完了」。

// 栈里压三样东西：u 当前处理的点、f 它的父亲、e 处理到几号边了
    // e == -1 表示 u 的边一条都没处理过，e == 0 表示 u 的边都处理完了
    int ufe[MAXN][3];
    int stackSize, u, f, e;

    void push(int uu, int ff, int ee) {
        ufe[stackSize][0] = uu;
        ufe[stackSize][1] = ff;
        ufe[stackSize][2] = ee;
        stackSize++;
    }

    void pop() {
        --stackSize;
        u = ufe[stackSize][0];
        f = ufe[stackSize][1];
        e = ufe[stackSize][2];
    }

    void dfs(int root) {
        stackSize = 0;
        push(root, 0, -1);
        while (stackSize > 0) {
            pop();
            if (e == -1) {
                deep[u] = deep[f] + 1;                 // 第一次来到 u，干进递归前该干的事
                stjump[u][0] = f;
                for (int p = 1; p <= power; p++) {
                    stjump[u][p] = stjump[stjump[u][p - 1]][p - 1];
                }
                e = head[u];                           // 接下来从 u 的第一条边开始
            } else {
                e = nxt[e];                            // 回来一次，往下挪一条边
            }
            if (e != 0) {
                push(u, f, e);                         // 这条边还要用，先把自己压回去
                if (to[e] != f) {
                    push(to[e], u, -1);                // 儿子是新点，e 用 -1 标记「第一次来」
                }
            }
            // e == 0 时什么都不压，等价于递归里函数返回
        }
    }

对照递归版看：递归里「进函数先干的事」放在 e = −1 那一支，「函数返回」对应 e = 0 时不把 u 压回去。e 从 −1 变成 head[u]，再每次回来变成 nxt[e]，和递归里 for 循环的推进一模一样。

迭代版跑同样的数据不会爆栈，因为栈开在全局数组里。n = 5 × 10⁵ 的链，ufe 数组 500001 × 3 × 4 B = 5.72 MB，和跳表比是小头。

「power 少一档」在 n = 8 上是 0.00%：2² = 4 已经盖得住 8 个点的树，缺的那一列根本没被用到。这种「在小数据上试不出来、上线就挂」的错，只能靠边界数据（链、n 恰好是 2 的幂）去撞。

「p 从小到大」在两道题里都能被抓出来，抓取率还随 n 上升。这一点和 ST 表那边的直觉相反：ST 表的两个区间谁左谁右无所谓，跳表的档位是有方向的，先试小档会把大档该走的路堵死。

十、复杂度分析

步骤时间复杂度空间复杂度
一次 dfs 填 deep 与第 0 列O(n)O(n log n)
跳表逐列递推O(n log n)
第 k 个祖先单次查询O(log n)O(1)
LCA 单次查询O(log n)O(1)
题目二整体（n 点 m 查）O((n + m) log n)O(n log n)

空间按题目上限算（n = m = 5 × 10⁵，power = 18）：跳表 500001 × 19 × 4 B = 36.24 MB，deep 1.91 MB，建图 head 1.91 MB 加 nxt/to 两条 7.63 MB，合计 47.69 MB。题目一上限 n = 5 × 10⁴，power = 15，跳表只有 3.05 MB。

查询侧没有额外分配，两个函数都只用几个临时变量，所以单次查询的空间是 O(1)。

十一、总结

跳表把「往上走」这件事从按步数计价改成按二进制位数计价，第 k 个祖先和 LCA 是同一张表的两种用法。三件事值得单独记住：power 取 ⌊log₂ n⌋ 就够，不必凑到不小于 n；判据里的等号（deep[落点] ≥ s）不能换成大于，换掉之后对齐阶段就会停在答案下一层；递归版在链形数据上会爆栈，线上要交迭代版。

这一节的做法是在线的：查询可以一条一条来，来一条答一条。下一节换个设定，m 条查询一次给全，换取 O(n + m) 的总代价。
