算法笔试中的输入输出处理

同样读 300 万个整数，cin 默认要 2.7 秒，scanf 要 0.17 秒，手写快读只要 0.024 秒，差了 110 倍。算法写对了却 TLE，问题往往出在 IO 上，不在复杂度。

零、背景

笔试和比赛里，程序的时间是从进程启动算到退出的。读数据、写答案都算在里面。

一个常见的错觉是「我的算法是 O(n) 的，n 才 100 万，肯定不会超时」。但如果用 cin 默认方式读这 100 万个数，光读入就要花接近 1 秒，留给算法的时间所剩无几。输出同理，cout 配合 endl 每次都强制 flush，200 万行输出能拖到 2.7 秒。

这一页不讲算法，讲怎么把数据读进来、把答案写出去，以及怎么分配空间才不浪费时间。这些东西每道题都要用，写错一次就是全场 TLE。

一、两种提交风格

在线评测有两种模式。

填函数风格：平台已经帮你写好了 main，读入了数据，调用你写的那个函数。你只需要实现函数体，不用管输入输出。LeetCode 和部分牛客题是这种。好处是不用操心 IO，坏处是看不到完整的数据流。

ACM 风格：你写完整的 main，自己读数据、自己输出。笔试和比赛绝大多数是这种。数据可能有多组，读到 EOF 为止。这是这一页的重点。

填函数风格的代码长这样，类名和函数签名是平台规定的，你往里面填逻辑：

class Solution {
    public:
        int maxSumSubmatrix(vector<vector<int>>& mat) {
            int n = mat.size(), m = mat[0].size();
            int ans = INT_MIN;
            for (int i = 0; i < n; i++) {
                vector<int> arr(m, 0);
                for (int j = i; j < n; j++) {
                    for (int k = 0; k < m; k++)
                        arr[k] += mat[j][k];
                    ans = max(ans, maxSubarray(arr));
                }
            }
            return ans;
        }
        int maxSubarray(vector<int>& arr) {
            int ans = INT_MIN, cur = 0;
            for (int x : arr) {
                cur += x;
                ans = max(ans, cur);
                cur = max(cur, 0);
            }
            return ans;
        }
    };

ACM 风格的代码长这样，自己读 n、m，自己读矩阵，自己 printf 答案：

int main() {
        int n, m;
        while (scanf("%d %d", &n, &m) == 2) {
            vector<vector<int>> mat(n, vector<int>(m));
            for (int i = 0; i < n; i++)
                for (int j = 0; j < m; j++)
                    scanf("%d", &mat[i][j]);
            printf("%d\n", maxSumSubmatrix(mat, n, m));
        }
        return 0;
    }

上面这份是「动态空间」版本：每组数据都 new 一个 vector<vector<int>>。能跑，但不是最快的写法。下一节说为什么。

二、读入：四种方式，速度差 110 倍

读入是最容易出问题的环节。下面是在同一台机器上读 300 万个随机整数的实测耗时：

读入方式300 万 int 耗时相对速度评价
cin（默认）2730 ms1×别用
cin（关同步）2258 ms1.2×有限提升
scanf173 ms15.8×日常够用
fread 快读24 ms113×数据量大时用

cin 默认慢的原因是它和 C 标准IO保持同步，每次 cin 操作都要和 stdin 的缓冲区对齐，这个对齐开销很大。加上 ios::sync_with_stdio(false) 和 cin.tie(nullptr) 能关掉同步，但在部分评测环境上提升有限（上面这台机器只快了 17%），而且一旦关了同步就不能混用 scanf 和 cin。

scanf 是最稳妥的日常选择。格式字符串写清楚类型，编译器帮你解析，173 ms 读 300 万，绝大多数题够用。

快读的原理是用 fread 一次性把大块数据读进自己的缓冲区，然后在缓冲区里逐字符解析整数。跳过了 C 库的格式解析层，所以快。代价是要自己写十几行代码，但这段代码是固定的，每道题抄一遍就行。

三、输出：endl 是隐形陷阱

输出比读入更容易踩坑，因为有个东西叫 endl。

cout << x << endl 做了两件事：输出 x，然后强制刷新缓冲区。每次输出都刷新一次，相当于每次都等操作系统把数据真正写出去。200 万行输出，就是 200 万次刷新。

换成 '\n' 就只是输出一个换行符，缓冲区满了才自动刷新。下面是实测：

输出方式200 万行耗时相对速度评价
cout + endl~2690 ms1×别用 endl
cout + '\n'（默认）228 ms11.8×一般
cout + '\n'（关同步）205 ms13.1×可以
printf106 ms25.4×日常够用
fwrite 快写17 ms158×数据量大时用

endl 比 '\n' 慢了 12 倍。这个差距纯粹来自「每次都 flush」。记住一条：写算法题用 '\n'，不用 endl。程序结束前缓冲区会自动 flush，不会丢数据。

四、空间：动态分配 vs 静态复用

ACM 风格里，每组测试数据都需要一块空间存输入。有两种做法。

动态分配：每组数据 new 一个 vector，用完自动释放。写法简单，vector 帮你管内存。但 new 和 delete 是有代价的，要走系统分配器，可能触发锁、可能触发页错误。

静态复用：在全局区开一个足够大的数组（比如 int mat[201][201]），每组数据直接覆盖写。全局数组在程序启动时就分配好了，运行期间没有分配开销。

实测 10 万组数据（每组约 100×100 的矩阵），动态分配每组花 6.1 微秒，静态复用每组花 1.2 微秒，差了 5 倍。组数越多，差距越大。

静态复用有一个必须注意的点：辅助数组要自己清空。上一组数据在 arr 里留下了值，这一组如果只覆盖前 m 个元素、后面的旧值还在，就会算出错误结果。正确做法是每组开始时 fill(arr, arr + m, 0)，只清需要用到的部分。

推荐的写法：全局静态数组 + 全局 n/m 变量 + 辅助数组手动清空：

const int MAXN = 201, MAXM = 201;
    int mat[MAXN][MAXM], arr[MAXM];
    int n, m;

    int maxSubarray() {
        int ans = INT_MIN, cur = 0;
        for (int i = 0; i < m; i++) {
            cur += arr[i];
            ans = max(ans, cur);
            cur = max(cur, 0);
        }
        return ans;
    }

    int maxSumSubmatrix() {
        int ans = INT_MIN;
        for (int i = 0; i < n; i++) {
            fill(arr, arr + m, 0);
            for (int j = i; j < n; j++) {
                for (int k = 0; k < m; k++)
                    arr[k] += mat[j][k];
                ans = max(ans, maxSubarray());
            }
        }
        return ans;
    }

    int main() {
        while (scanf("%d %d", &n, &m) == 2) {
            for (int i = 0; i < n; i++)
                for (int j = 0; j < m; j++)
                    scanf("%d", &mat[i][j]);
            printf("%d\n", maxSumSubmatrix());
        }
        return 0;
    }

这份代码里，mat 和 arr 都是全局的，n 和 m 也是全局的。maxSumSubmatrix 和 maxSubarray 不需要传参，直接用全局变量。每组数据覆盖写 mat，arr 在每次 i 循环开始时 fill 清零。

五、没有数据规模时：按行读

有些题不告诉你有多少个数，只说「每行若干个整数，求每行的和」。这种情况没法用「先读 n 再读 n 个」的模式，只能按行读。

做法是 getline 读一整行，用 stringstream 切成一个个数：

int main() {
        string line;
        while (getline(cin, line)) {
            stringstream ss(line);
            int x, sum = 0;
            while (ss >> x) sum += x;
            cout << sum << '\n';
        }
        return 0;
    }

stringstream 的效率不如直接 scanf，但按行读的题数据量通常不大，够用。如果数据量真的很大（比如每行几十万个数），可以用快读版本的按行读，自己在缓冲区里找换行符再切分。

六、快读快写模板

当数据量超过 100 万时，scanf 和 printf 也可能成为瓶颈。这时候上快读快写。

原理很简单：用 fread 把整块数据读进自己的 char 数组，在数组里逐字符拼整数；输出时把数字转成字符塞进自己的 char 数组，攒够了用 fwrite 一次性写出去。

static char ibuf[1 << 20];
    static int iLen = 0, iPos = 0;
    inline int gc() {
        if (iPos >= iLen) {
            iLen = fread(ibuf, 1, sizeof(ibuf), stdin);
            iPos = 0;
            if (iLen <= 0) return -1;
        }
        return ibuf[iPos++];
    }
    inline int readInt() {
        int x = 0, f = 1, c = gc();
        while (c != -1 && (c < '0' || c > '9')) {
            if (c == '-') f = -1;
            c = gc();
        }
        while (c >= '0' && c <= '9') {
            x = x * 10 + c - '0';
            c = gc();
        }
        return x * f;
    }

    static char obuf[1 << 20];
    static int oPos = 0;
    inline void flushOut() {
        fwrite(obuf, 1, oPos, stdout);
        oPos = 0;
    }
    inline void writeInt(int x) {
        if (oPos > (1 << 20) - 32) flushOut();
        if (x < 0) { obuf[oPos++] = '-'; x = -x; }
        char tmp[12]; int len = 0;
        if (x == 0) tmp[len++] = '0';
        while (x) { tmp[len++] = '0' + x % 10; x /= 10; }
        while (len) obuf[oPos++] = tmp[--len];
        obuf[oPos++] = '\n';
    }

这段代码可以直接抄。readInt 返回一个 int，writeInt 把一个 int 写进输出缓冲区，程序结束前调用 flushOut。需要 long long 版本时把 x 的类型和中间变量改一下就行。

八、复杂度分析

操作时间空间说明
cin / cout（默认）O(n)，常数极大O(1)同步开销大，数据超 10 万就别用
scanf / printfO(n)，常数中等O(1)日常首选，300 万 int 约 0.17 秒
fread / fwrite 快读快写O(n)，常数极小O(缓冲区)数据超 100 万时使用，比 scanf 快 7 倍
动态分配（vector/new）O(n) 分配 + O(数据)O(数据)每组 6 微秒分配开销，组数多时明显
静态全局数组复用O(数据)O(MAXN × MAXM)每组 1.2 微秒，比动态快 5 倍

空间方面，静态数组的代价是「占着不用的内存」。题目说 n ≤ 200，你开 201×201 就是 160KB，完全可以接受。如果题目 n ≤ 10⁵，开 int[100001] 是 400KB，也没问题。只有当题目规模到 10⁷ 以上时，才需要考虑动态分配省内存。

九、总结

1. 别用 cin 默认和 endl。cin 默认读 300 万要 2.7 秒，endl 每次 flush 让输出慢 12 倍。

2. 日常用 scanf + printf，格式清晰、速度够用，300 万 int 0.17 秒。

3. 数据超 100 万上快读快写，fread + 逐字符解析比 scanf 再快 7 倍，模板固定可以直接抄。

4. 空间用全局静态数组复用，比动态分配快 5 倍；辅助数组每组记得 fill 清零。

5. 没有数据规模就按行读，getline + stringstream 切分。

这些是每道题的地基，比算法本身更基础。地基打稳了，后面的算法才跑得动。下一讲开始回到具体的算法问题。
