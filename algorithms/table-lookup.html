打表找规律：先暴力，再观察

输入是简单类型、输出也是简单类型的问题，别急着推公式。先用最暴力的实现把入参不大时的答案全跑出来打印成表，规律往往一眼可见，再把规律变成代码。

零、背景

什么样的题适合打表？输入参数是简单类型（一个 int、一个 long），返回值也是简单类型（int、bool、string）。这种题没有输入结构，暴力只需要最基本的递归能力，前置是 038 那套递归套路。

过程固定三步：① 最暴力实现，求入参不大时的答案；② 打印这些答案，观察规律；③ 把规律变成代码。

这一课的四道题依次演示：苹果问题的规律来自奇偶性和 18 以上的周期，吃草问题的规律藏在模 5，连续数和问题的规律是「只有 2 的幂不行」。规律各不相同，流程完全一样。

一、买苹果：最少几个袋子

有装 8 个苹果的袋子和装 6 个的袋子，必须全部装满。给定 n 个苹果，返回至少要几个袋子；不存在每个袋子都装满的方案返回 -1。

暴力怎么写？f(rest) 表示还剩 rest 个苹果时的最少袋数：拿一个 8 袋，剩下 f(rest - 8)；拿一个 6 袋，剩下 f(rest - 6)。rest 小于 0 是无效解，rest 等于 0 结束。答案取两个分支的较小值。

// 当前还有 rest 个苹果，每个袋子必须装满，返回至少几个袋子
    // 装不下返回一个"无效解"标记
    const int INF = INT_MAX;

    int f(int rest) {
        if (rest < 0) {
            return INF;
        }
        if (rest == 0) {
            return 0;
        }
        // 用 8 规格的袋子，剩下的交给递归
        int p1 = f(rest - 8);
        // 用 6 规格的袋子，剩下的交给递归
        int p2 = f(rest - 6);
        if (p1 != INF) p1 += 1;
        if (p2 != INF) p2 += 1;
        return min(p1, p2);
    }

    // 买 apple 个苹果，返回最少袋子数，无解返回 -1
    int bags1(int apple) {
        int ans = f(apple);
        return ans == INF ? -1 : ans;
    }

把 0 到 40 的答案打出来，两个规律直接写在表上。

第一个规律：奇数全 -1。6 和 8 都是偶数，任意整袋组合的总苹果数必然是偶数，奇数个苹果不可能装满。

第二个规律：18 以下能解的值只有 6、8、12、14、16；18 以上每多 8 个苹果加 1 袋。

// 打表之后的最优解
    int bags2(int apple) {
        // 6 和 8 都是偶数，奇数个苹果永远装不满
        if ((apple & 1) != 0) {
            return -1;
        }
        if (apple < 18) {
            if (apple == 0) return 0;
            if (apple == 6 || apple == 8) return 1;
            if (apple == 12 || apple == 14 || apple == 16) return 2;
            return -1;
        }
        // 18 起每多 8 个苹果加 1 袋
        return (apple - 18) / 8 + 3;
    }

为什么 18 以上就稳定循环？看 18 到 24：18 = 6+6+6、20 = 6+6+8、22 = 6+8+8、24 = 8+8+8，四个值把 6 和 8 能表达的偶数全盖住。之后每次加 8 回到同样的位置，所以 (apple - 18) / 8 + 3。

暴力递归没有记忆化，调用节点数指数涨：apple=20 时 17 个节点，60 时 1041，100 时 56315，120 时 413793。这就是为什么必须打表：公式对 1e9 也是一次除法，暴力连几百都跑不动。

二、吃草：谁会赢

草有 n 份重量，A 牛先吃、B 牛后吃，每只牛在自己回合只能吃 4 的幂：1、4、16、64…。谁在自己的回合正好把草吃完谁赢，输入 n 返回 A 赢还是 B 赢。

博弈递归：f(rest, cur) 表示还剩 rest 份草、当前选手是 cur 时最终谁赢。rest 小于 5 是出口：rest 为 0 或 2 时轮到谁谁输，rest 为 1、3、4 时当前选手直接赢。rest 不小于 5 就试吃 1、4、16、64…，只要有一种吃法让对手面对必败局面，当前选手就赢。

// rest : 还剩多少草
    // cur  : 当前选手的名字
    // 返回 : 最终谁赢（"A" 或 "B"）
    string f(int rest, string cur) {
        string enemy = cur == "A" ? "B" : "A";
        if (rest < 5) {
            // 0 和 2 是必败局面：轮到谁谁输
            return (rest == 0 || rest == 2) ? enemy : cur;
        }
        // rest >= 5：试试吃 1、4、16、64...，
        // 只要有一种吃法让对手面对必败局面，当前选手就赢
        int pick = 1;
        while (pick <= rest) {
            if (f(rest - pick, enemy) == cur) {
                return cur;
            }
            pick *= 4;
        }
        return enemy;
    }

    string win1(int n) {
        return f(n, "A");
    }

打表 0 到 30，每 5 个一组完全重复。

规律一句话：n 除以 5 余 0 或 2 时 B 赢，否则 A 赢。

// 打表之后的最优解
    string win2(int n) {
        if (n % 5 == 0 || n % 5 == 2) {
            return "B";
        } else {
            return "A";
        }
    }

暴力节点数同样指数涨：n=30 时 2670，40 时 32577，50 时 397146。n 到 1e9 暴力不可行，公式照样 O(1)。

三、连续正整数和

判断一个数字能否写成大于 1 个连续正整数的和。暴力枚举起点 start，从 start 开始累加，加到 num 命中返回，超过 num 换下一个起点。

// 暴力：枚举起点 start，从 start 起累加连续的正整数
    bool is1(int num) {
        for (int start = 1; start <= num; start++) {
            int sum = start;
            for (int j = start + 1; j <= num; j++) {
                if (sum + j > num) {
                    break;
                }
                if (sum + j == num) {
                    return true;
                }
                sum += j;
            }
        }
        return false;
    }

打表 1 到 64，只有 2 的幂是 F，其余全是 T。

规律写成代码就是一行：num 不是 2 的幂，等价于 num 的二进制里不止一个 1。

// 打表之后的最优解：只有 2 的幂不能表示
    bool is2(int num) {
        return (num & (num - 1)) != 0;
    }

为什么 2 的幂不行？连续 k 个正整数之和 S = k·(2a + k − 1)/2。k 是奇数时 S 含奇因子 k；k 是偶数时 S = (k/2)·(2a + k − 1)，而 2a + k − 1 是奇数且大于 1。所以任何能表示的数都必须含大于 1 的奇因子，2 的幂一个都没有。

非 2 的幂为什么行？它总有奇数因子，构造可行。看几个例子：6 = 1+2+3、10 = 1+2+3+4、14 = 2+3+4+5、18 = 3+4+5+6、20 = 2+3+4+5+6。

代价差距：is1 判断 2^24 要扫全部起点，实测 91ms；is2 一次位运算，与 num 无关。

三个暴力的共同点：入参大一档，时间翻好几倍。苹果 f 的节点数从 17 涨到 413793（apple 20 → 120），吃草从 2670 涨到 397146（n 30 → 50）。公式把这种增长整个抹平。

总结

打表三步：暴力实现 → 打印小范围答案 → 规律变代码。适用条件是输入输出都是简单类型。

三题的规律分别是：苹果按奇偶性和 18 以上的 8 周期；吃草按 n mod 5；连续数和按「是否 2 的幂」。

规律到手前，暴力节点数已经指数增长；规律到手后，公式对 1e9 都 O(1)。用最小成本的暴力，换一个能撑住最大入参的结论。
