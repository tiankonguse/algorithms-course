贪心：按到站时间排队

武器一次只能打掉一只怪，充能还要整整一分钟。于是第 0 分钟打一只、第 1 分钟打一只、第 2 分钟再打一只……开枪的顺序是被时间表卡死的，能选的只有打谁。

零、题目要什么

给 dist 和 speed 两个数组，第 i 只怪离城市 dist[i]，速度 speed[i]。武器开局就是满电的，每开一枪之后要 1 分钟充能。怪物从 0 时刻开始走，任何一只到达城市就输，恰好在某一分钟开始时到达也算输。

问在输掉之前，最多能消灭多少只。

一、先把每只怪的到达时间算出来

距离 dist、速度 speed，走完全程用 dist / speed 分钟。到达的时刻就是这个商向上取整：dist = 3、speed = 2 的怪在第 1.5 分钟到，它进城门的时刻落在第 1 分钟和第 2 分钟之间，所以按第 2 分钟算。

写起来是 (dist[i] + speed[i] - 1) / speed[i]。整数除法天生向下取整，先加上除数减一，除出来的结果就变成了向上取整。没有浮点，也就没有精度问题。

向上取整这个动作看起来只是收尾的细节，漏掉它的代价却不小：dist = 1、speed = 3 的怪到达时间是 1，写成 dist / speed 会得到 0，等于替这只怪把到城时间推后了一分钟。用随机数据测，值域取 [1, 2] 时 71.98% 的用例会给出不同答案，值域放宽到 [1, 100] 涨到 96.16%。

二、出手时刻和到达时刻差着一格

第 i 次开枪发生在时刻 i，第 0 次就是开局那一击。要在第 i 次开枪时打掉一只怪，前提是它还没到城，也就是它的到达时间严格大于 i。

这里正好接住题面那句「恰好在某一分钟开始时到达也算输」。到达时间等于 i 的怪，在你抬手的那一瞬间已经进城了。所以判断得写成 time[i] <= i 就结束，写成 time[i] < i 就放走了一批卡点的怪。这个改动在小值域下 93.72% 的用例会算错，值域放到 [1, 100] 也有 81.06%。

两个边界都很容易想岔：一个是把到达时间算小（向下取整），一个是把出手亏欠的时间算少（<）。它们的方向恰好相反，一个让怪物显得来得更晚，一个让武器显得出手更早。

三、排序之后一一对齐

剩下的问题是第 i 次开枪该打谁。答案是：打还没打掉的怪里到达时间最小的那只。

理由可以这样看。假设第 i 次你放着最急的那只不打，去打了一只更晚到的。最急的那只还活着，而它到城的时刻不晚于你打掉的这只，所以这个交换不会让局面更安全。把这两次开枪换一下顺序，最先要处理的怪被提前处理了，后面的位置只是往后挪，都不会更早撞线。一次交换不亏，一路换下去，得到的顺序就是按到达时间从小到大排。已经打掉的怪不用再排，排序后第 i 个位置（从 0 数）就是第 i 分钟的目标。

于是整段代码就是排序加一次扫描：从头往后看，第一次遇到 time[i] <= i 就返回 i，一路都没踩线就返回 n。

// 消灭怪物的最大数量：武器每 1 分钟充能一次，第 i 次出手的时刻就是 i
    // 先把每只怪的到达时间算成向上取整的分钟数
    int eliminateMaximum(vector<int> dist, vector<int> speed) {
        int n = dist.size();
        vector<int> time(n);
        for (int i = 0; i < n; i++) {
            // 向上取整：(a + b - 1) / b，整数除法本身是向下取整
            time[i] = (dist[i] + speed[i] - 1) / speed[i];
        }
        sort(time.begin(), time.end());
        for (int i = 0; i < n; i++) {
            // 出手时刻是 i，到达时间必须严格大于 i，等于 i 也算输
            if (time[i] <= i) {
                return i;
            }
        }
        return n;
    }

实测 106 只怪，整个函数跑完 61.37ms，其中排序一个人吃掉 66ms 量级的开销（同样的数据单跑 std::sort 是 66.38ms），后面那次扫描只花 0.28ms。这题的时间都花在排队上。

四、逐分钟走一遍

按时出手

上排是每只怪的到达时间，下排是每一分钟的目标。点「下一步」推进一分钟：先看有没有活着的怪已经到城，有就结束，没有就打掉到达时间最小的一只。

五、对数器怎么抓错

这题的暴力可以直接枚举：把所有击杀顺序都试一遍，每个顺序逐分钟模拟。第 m 分钟先检查「还没打掉的怪里有没有到达时间 ≤ m 的」，有就当场输掉；没有就打掉顺序里的下一只。

这里有个坑要单独说。暴力不能只检查被杀的怪来不来得及，还要检查没排上号的那些是不是已经到城了。漏掉后半句，暴力会心安理得地把没打的怪忽略掉，答案算得比正解大。我第一版就是这么写的：正解返回 1，它返回 3。

写法数据出错比例
到达时间用 dist / speed（向下取整）dist、speed 均在 [1, 2]71.98%
到达时间用 dist / speeddist、speed 均在 [1, 100]96.16%
扫描边界写成 time[i] < idist、speed 均在 [1, 2]93.72%
扫描边界写成 time[i] < idist、speed 均在 [1, 100]81.06%

每行两万组，n 取 2 到 8。两处错法都随值域上升而更容易被抓到，原因是值域一大，dist < speed 和 dist / speed 除不尽的比例都跟着上升，两个错法各自依赖的条件都更容易出现。

这类错法的抓取率方向不统一，不能照搬别的题的直觉。有的题是值域越小越容易现形，这题正好反过来。判断标准只有一个：这个错法依赖的条件在什么数据上才会出现。

复杂度分析

题目关键操作时间空间
消灭怪物的最大数量算一遍到达时间 + 排序 + 一趟扫描O(n log n)，n 是怪物数量O(n)

到达时间数组和排序各占 O(n) 空间，扫描不额外开销。n = 106 时，61.37ms 里几乎全是排序。

总结

两个数字先算准：每只怪的到达时间是 (dist + speed - 1) / speed，第 i 次开枪的时刻是 i，到达时间必须严格大于 i。

第 i 次该打谁，按到达时间从小到大排好之后就是第 i 个位置。交换论证说明违背这个顺序不会更好，于是暴力之外只剩排序一遍。

写对数器的时候记得检查「没打的怪也可能已经到城」，这一条漏了，暴力会比正解更乐观，反而把正解判错。下一节继续看贪心里另一类常见形状：数一遍再拼。
