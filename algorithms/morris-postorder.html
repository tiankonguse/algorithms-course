Morris 后序遍历与搜索二叉树判定

先序和中序都能在「到达时顺手记一笔」解决，后序不行，它要等左右两边都处理完，而 Morris 里一个节点最多被到达两次。后序得换个单位来打印：第二次到达 cur 时，cur 左子树的右边界逆着数，正好是这一段的输出顺序。搜索树判定则是中序的另一个用法，边走边跟上一个比。

零、背景

递归版三种序的差别只是打印语句放在第几次到达。一个节点在递归里能被到达三次：刚进到它、左子树回来、右子树回来。先序打在第一次，中序打在第二次，后序打在第三次。

Morris 只有两次。第一次是顺着父节点的指针下来，第二次是顺着自己左子树留下的线索爬回来。少掉的这一次让「左右都处理完」这个时机在 Morris 里根本不存在。

这里有个要说清楚的边界：递归能解的题，Morris 不一定能解。凡是必须回到一个节点三次才能凑出答案的问题，Morris 遍历做不了。哪些能做只能具体问题具体分析，本节这两道都属于能做的那一类。

一、后序：换个单位打印

后序是「左 右 根」。第二次到达 cur 的时候，左子树刚走完，右子树还没开始，这时候打印 cur 明显太早，打印整个左子树又太晚。

把注意力从单个节点挪到一条链上。从某个节点出发一路向右走到头，这条右边界上的节点，在后序里的相对顺序恰好跟自上而下的顺序相反。理由是右边界上每个节点的右孩子也在这条边界上，而右子树在后序里排在它自己前面，所以越靠下的节点排得越靠前。

于是得到一个整段收集的办法：把这条右边界的 right 指针原地翻个向，顺着翻完的链走一遍就是自下而上，收集完再翻回来。三次翻转，链上的节点一个都不用新开。

放到 Morris 的骨架里，时机就是第二次到达 cur：这时候 cur 的左子树整棵走完，右子树还没动，把 cur->left 的右边界收一遍正好。整棵树的右边界没有第二次到达来触发它，循环结束后要单独补一次。

// 后序：第二次到达 cur 时，cur 左子树的右边界逆着数正好是这一段该输出的顺序
    vector<int> postorderTraversal(TreeNode* head) {
        vector<int> ans;
        morrisPostorder(head, ans);
        return ans;
    }

    void morrisPostorder(TreeNode* head, vector<int>& ans) {
        TreeNode* cur = head;
        TreeNode* mostRight = nullptr;
        while (cur != nullptr) {
            mostRight = cur->left;
            if (mostRight != nullptr) {
                while (mostRight->right != nullptr && mostRight->right != cur) {
                    mostRight = mostRight->right;
                }
                if (mostRight->right == nullptr) {
                    mostRight->right = cur;
                    cur = cur->left;
                    continue;
                } else {
                    mostRight->right = nullptr;
                    collect(cur->left, ans);            // 注意是 cur->left，不是 cur
                }
            }
            cur = cur->right;
        }
        collect(head, ans);                             // 整棵树的最右边界，别忘了
    }

    // 以 head 为头的树，把右边界逆序收集进 ans
    void collect(TreeNode* head, vector<int>& ans) {
        TreeNode* tail = reverseRight(head);
        TreeNode* cur = tail;
        while (cur != nullptr) {
            ans.push_back(cur->val);
            cur = cur->right;
        }
        reverseRight(tail);                             // 翻回来，树要还原成原样
    }

    // 只动 right 指针，把一条右链原地翻转，返回新头
    TreeNode* reverseRight(TreeNode* from) {
        TreeNode* pre = nullptr;
        TreeNode* next = nullptr;
        while (from != nullptr) {
            next = from->right;
            from->right = pre;
            pre = from;
            from = next;
        }
        return pre;
    }

参数写错成 collect(cur, ans) 是常见的手误，它会连 cur 自己和 cur 的右子树一起收，2 万组随机小树里 80.26% 对不上。忘记最后那次 collect(head, ans) 更彻底，整棵树的最右路径一个都进不了答案，抓取率 100%，因为任何非空树都有一条非空的最右路径。

翻转的代价是常数级的。n = 10⁶ 的树，不管随机形状、链状还是完全二叉树，收集到的元素总数都是 10⁶，翻转赋值总步数都是 2×10⁶，正好是两次翻转各走一遍全部边界。每个节点恰好被收集一次。

二、搜索二叉树：中序必须严格递增

搜索二叉树的中序序列严格递增，这条性质递归版和 Morris 版都能用，而且只需要记住上一个节点，连序列都不用存。

// 搜索二叉树的中序严格递增：Morris 中序里只留一个 pre，边走边比
    bool isValidBST(TreeNode* head) {
        TreeNode* cur = head;
        TreeNode* mostRight = nullptr;
        TreeNode* pre = nullptr;                        // 中序里的上一个节点
        bool ans = true;
        while (cur != nullptr) {
            mostRight = cur->left;
            if (mostRight != nullptr) {
                while (mostRight->right != nullptr && mostRight->right != cur) {
                    mostRight = mostRight->right;
                }
                if (mostRight->right == nullptr) {
                    mostRight->right = cur;
                    cur = cur->left;
                    continue;
                } else {
                    mostRight->right = nullptr;
                }
            }
            if (pre != nullptr && pre->val >= cur->val) {
                ans = false;                            // 相等也不行，这里是 >= 不是 >
            }
            pre = cur;
            cur = cur->right;
        }
        return ans;
    }

比较符是这里唯一容易写错的地方。中序里出现相等的两个值就已经不合法了，所以判据是 pre->val >= cur->val。写成 > 会把相等放过，随机数据能不能抓到全看值域：n 取 1 到 9 各跑 2 万组，值域 2 时抓取率 18.86%，值域 5 时降到 6.51%，值域 20 只剩 1.60%。

值域越大，随机出的相邻节点值越难撞上，这个错越难现形。想测它就专门造相等值，别指望随机样例。

复杂度分析

算法时间额外空间说明

Morris 判定搜索二叉树O(n)O(1)只多一个 pre 指针和一个 bool
递归后序 / 递归判定O(n)O(h)系统栈，链上 n 层会崩

后序那栏的时间要拆开算：Morris 骨架走 O(n)，每次 collect 里翻转两遍右边界，所有 collect 涉及的边界长度加起来是 n，翻转赋值总步数 2n。两项都是 O(n)，合起来还是 O(n)。

空间是严格的 O(1)。reverseRight 只用 pre、next 两个局部指针，collect 多一个 tail，加上主循环的 cur 与 mostRight，一共五个指针变量，跟 n 和 h 都没关系。

总结

后序在 Morris 里的解法是换单位：不打印单个节点，而是把一条右边界翻个向整段收集，收集完翻回来。触发时机是第二次到达 cur 时收 cur->left 的右边界，循环结束后补一次 collect(head, ans)。

要点列一下：右边界自上而下的顺序与后序里的相对顺序相反，这是整套做法的依据；每个节点恰好被收集一次，翻转赋值总步数恒为 2n；collect 的参数写错、收尾漏掉，是两道抓取率 80% 和 100% 的高频错题。

搜索树判定是中序的另一个用法，只记 pre 一个指针就够，比较符必须用 >=。递归能解的题 Morris 不一定能解，本节这两道能做，是因为它们要的信息在两次到达之内就齐了。下一节看两道要维护跨节点信息的题。
