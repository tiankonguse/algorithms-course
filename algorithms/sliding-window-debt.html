最小覆盖子串：欠债模型

上一页的窗口只维护一个 sum。这道题的约束是「窗口里每种字符都要凑够」，一张计数表加一个总债务就能撑起整个窗口：右扩还债，债务清零后收缩左边界拿回盈余。

零、背景

「窗口里 A 至少 2 个、B 至少 1 个」这类约束，sum 一个数记不住。开一张 256 长的计数表 cnts，用负数表示欠债、正数表示盈余：cnts[c] < 0 说明还缺 c，cnts[c] > 0 说明 c 多出来了。

总债务 debt 记「还差几个字符才全部凑齐」。窗口右扩时如果拿到一个正欠着的字符（cnts++ 之前是负数），debt 减一；debt 归零说明窗口已经覆盖全部要求，这时收缩左边界不会破坏覆盖，因为 l 位置的字符是盈余（cnts > 0）才能拿回去。

一、题 3：最小覆盖子串（LeetCode 76）

s 中找最短子串，覆盖 t 的所有字符（每种字符个数 ≥ t 里的个数）。初始化把 t 的每个字符在 cnts 里减一（欠债），debt = t.length。r 每走一步：cnts[s[r]]++，如果加之前是负数说明这笔债还上了，debt--。

debt == 0 时窗口达标，但这不一定是当前 r 结尾的最短窗口，还要收缩：while (cnts[s[l]] > 0) 把 l 右移并 cnts--。收缩停在 l 位置字符欠债或刚好（cnts ≤ 0）的地方，此时窗口仍然覆盖 t，长度最短。

两个高频错法：右扩时用 cnts[s[r]]++ <= 0 判断还债（等于 0 时也减 debt，债务提前清零，窗口其实没覆盖全），随机数据 81.81% 算错；收缩条件写成 cnts[s[l]] >= 0（把刚够的字符也拿走），69.42% 算错，且窗口缩空后还会越界访问。

二、题 5：替换子串得到平衡字符串（LeetCode 1234）

字符串只含 Q/W/E/R，长度 n 是 4 的倍数。平衡指四种字符各恰好 n/4 个。替换一个子串让整体变平衡：被替换的子串可以换成任何内容，所以「替换后平衡」等价于「子串外面四种字符各自 ≤ n/4」。外面的不足，替换的子串能补；外面的超了，替换救不回来。

于是问题变成：找最短子串，使窗口外每种字符 ≤ n/4。cnts 的初始化跟题 3 略有不同：统计完四种字符后，超出 n/4 的记成 n/4 - cnts[i]（负数，欠债），不足的记 0（不欠，也不能拿）。debt 累计所有负值。如果本身已经平衡，debt 就是 0，直接返回 0。

之后的主循环和题 3 一模一样：右扩还债，debt == 0 后收缩拿回盈余，更新最短长度。比如 "QQQQ"，n=4，per=1，Q 超出 3 个，要替换掉 3 个才能平衡，答案 3。

错法集中在初始化：把不足的字符也记成 n/4 - cnts[i] 的正数盈余，debt 的账就全乱了，随机数据 97.91% 算错。

三、复杂度与实测

两题骨架相同：r 走 n 步，l 总共 ≤ n 步，cnts 与 debt 更新 O(1)，总 O(n)，额外空间 O(256)。

实测（g++ -O2，macOS aarch64）：题 3 在 n=1e6 的随机字符串上找覆盖 "abcdabcd" 的最短窗口 3.86ms；题 5 n=1e6 随机 QWER 串 8.53ms。暴力枚举子串是 O(n²·字符集)，n 上万就秒级了。

四、代码

题 3：

string MinWindow(const string& str, const string& tar) {
        vector<int> cnts(256, 0);
        for (char cha : tar) cnts[(unsigned char)cha]--;
        int len = INT_MAX, start = 0;
        int debt = (int)tar.size();
        for (int l = 0, r = 0; r < (int)str.size(); r++) {
            if (cnts[(unsigned char)str[r]]++ < 0) debt--;
            if (debt == 0) {
                while (cnts[(unsigned char)str[l]] > 0) {
                    cnts[(unsigned char)str[l++]]--;
                }
                if (r - l + 1 < len) {
                    len = r - l + 1;
                    start = l;
                }
            }
        }
        return len == INT_MAX ? "" : str.substr(start, len);
    }

题 5 的初始化与主循环：

int BalancedString(const string& str) {
        int n = (int)str.size();
        vector<int> s(n);
        vector<int> cnts(4, 0);
        for (int i = 0; i < n; i++) {
            char c = str[i];
            s[i] = c == 'W' ? 1 : (c == 'E' ? 2 : (c == 'R' ? 3 : 0));
            cnts[s[i]]++;
        }
        int debt = 0;
        for (int i = 0; i < 4; i++) {
            if (cnts[i] < n / 4) {
                cnts[i] = 0;
            } else {
                cnts[i] = n / 4 - cnts[i];
                debt -= cnts[i];
            }
        }
        if (debt == 0) return 0;
        int ans = INT_MAX;
        for (int l = 0, r = 0; r < n; r++) {
            if (cnts[s[r]]++ < 0) debt--;
            if (debt == 0) {
                while (cnts[s[l]] > 0) {
                    cnts[s[l++]]--;
                }
                ans = min(ans, r - l + 1);
            }
        }
        return ans;
    }

总结

欠债模型的三个要点：负数记账、debt 计数、盈余才能拿回。cnts 的正负号是「欠」还是「盈」的判据，debt 归零是「达标」的信号，收缩条件 > 0 保证拿走的都是多余的。

题 3 和题 5 是同一副骨架的两道题，差别只在初始化：题 3 从 t 的字符计数出发，题 5 从「窗口外 ≤ n/4」转化而来。下一页的题把窗口从「最长/最短」玩到「计数」和「环上」，单调性的判断要更细。
