最小栈

栈只有一个口，手只能伸进栈顶。上一讲把队列和栈互相实现的写法都过了一遍，这一讲往栈上加一个要求：随时问「栈里现在最小的数是多少」，而且每次都要在常数时间里答出来。

零、背景

栈里压了 10 万个数，现在问一句最小值是多少。最直白的办法是从底到顶全看一遍，代价是 O(n)。问一次无所谓，问 10 万次就是 1010 次比较。

实测一遍（min_element 扫全栈，栈里 n 个、问 n 次）：

栈内元素 n问 n 次，全扫问 n 次，min 栈比值
1 0001.137 ms0.0042 ms273 倍
10 00052.008 ms0.0170 ms3 067 倍
100 0002 499.650 ms0.0250 ms100 154 倍

比值是随着 n 一起涨的，因为一边是 n2 一边是 n。不过反过来也要说一句：如果从头到尾只问一次，栈里 100 万个数全扫一遍只要 0.250 毫秒，这时候专门维护一个 min 栈就是白费力气。要不要维护，先看问多少次。

一、问题

LeetCode 155，设计一个栈，四个操作全部 O(1)：

  • push(val)：把 val 压进栈顶
  • pop()：删掉栈顶
  • top()：返回栈顶
  • getMin()：返回栈里最小的元素

前三个是栈本来就有的动作，第四个才是要解决的问题。

难点在于栈会弹。如果只往里加，用一个变量记最小值就够了；弹出去的那个正好是当前最小值时，新的最小值没人知道是多少，得提前留好。

二、每个深度存一份答案

既然弹回去之后还得知道答案，那就别只存一个值，改成每一层都存一份：开两个栈，data 存真正的数，mn 存「压到这一层为止见过的最小值」。

写下来就是一条不变式：mn[i] = min(data[0], data[1], …, data[i])。第 i 层的 mn 永远等于从第 0 层到第 i 层的最小值。

有了这条，push 和 pop 该干什么就是被逼出来的：push 时新一层的 mn 等于 min(val, 上一层 mn)，pop 时两个栈一起弹，长度始终相同。getMin() 直接读 mn 的栈顶。

代码短得有点意外：

struct MinStack {
        vector<int> data, mn;

        void push(int val) {
            data.push_back(val);
            if (mn.empty() || val <= mn.back()) {
                mn.push_back(val);
            } else {
                mn.push_back(mn.back());
            }
        }

        void pop() {
            data.pop_back();
            mn.pop_back();
        }

        int top() { return data.back(); }

        int getMin() { return mn.back(); }
    };

val <= mn.back() 经常被人写成 val < mn.back()，写错的人不少，但两种写法结果完全一样：else 分支压的是 mn.back()，val 等于它的时候，压 val 和压 mn.back() 落进栈的是同一个数。跑了 20 000 组随机序列，两个版本 mn 栈的内容零次不同。

真正要紧的等号在下一节的省空间版里，那里 mn 栈不再跟 data 等长，重复的最小值会被记漏。

三、mn 栈只记刷新过的那些

同步版每层都存一份，mn 栈和 data 一样长，空间是 2n。可 mn 栈里大部分是重复值：压进来的数比当前最小值大时，mn 栈只是把上一个值又抄了一遍。

换个记法：mn 栈只在「来了个严格更小的值」时压栈，弹出时靠 data 的值判断要不要一起弹。重复出现的最小值必须记份数，所以再配一个 cnt 栈，跟 mn 栈一起长一起短。

struct MinStack {
        vector<int> data, mn, cnt;

        void push(int val) {
            data.push_back(val);
            if (mn.empty() || val < mn.back()) {
                mn.push_back(val);
                cnt.push_back(1);
            } else if (val == mn.back()) {
                cnt.back()++;
            }
        }

        void pop() {
            int val = data.back();
            data.pop_back();
            if (val == mn.back()) {
                if (--cnt.back() == 0) {
                    mn.pop_back();
                    cnt.pop_back();
                }
            }
        }

        int top() { return data.back(); }

        int getMin() { return mn.back(); }
    };

pop 里那个 --cnt.back() == 0 就是关键：只有最后一个同值元素被弹走，这一档最小值才真的消失。

拿 push 3, 1, 1, 2 再 pop, pop 走一遍就明白了。正确写法里 mn 栈是 [3, 1]、cnt 是 [1, 2]，弹掉一个 1 之后 cnt 从 2 变 1，栈里还剩 [3, 1]，getMin 答 1。省略计数、只压严格更小值的写法里 mn 栈只有 [3, 1] 这一份 1，弹第一个 1 时它被当作唯一的最小值弹掉了，getMin 答 3。

这个错有多容易被随机数据抓到？序列长度 ≤ 20，边弹边查，每组值域跑 20 000 次：

值域 V23510100
出错序列占比45.22%58.55%60.22%50.22%8.94%

值域越小、重复越多，越容易撞上；值域拉到 100，重复值少了，八成序列都看不出错。顺便量了另一种常见错法：同步版 pop 忘了弹 mn 栈，20 000 组里 76.36% 会现形。

四、mn 栈到底有多长

省空间版的 mn 栈长度等于「前缀最小值被刷新的次数 + 1」。随机数据下这个次数是调和级数的量级：第 i 个数刷新前缀最小值的概率是 1/i，所以期望刷新次数是 Hn = 1 + 1/2 + … + 1/n ≈ ln n。

值域有限时刷新迟早会停，实际长度更接近 Hmin(n, V)。实测（每组 300 次）：

n值域 V实测 mn 栈长度Hmin(n,V)占 n 的比例

100 000 个数、值域 1 000 时，mn 栈平均只有 7 项出头。同步版这时要开 100 000 个 int，省空间版只开 7 个，加上 cnt 也不过 14 个。

三种极端形状也值得记一下（n = 1 000）：全相等时 mn 栈恒为 1 项；严格递增时最小值在最底下，mn 栈还是 1 项；严格递减时每来一个都刷新，mn 栈长到 1 000，等于退回了同步版。

五、一个变量加一个栈

还有种写法连 mn 栈都不开，只用一个变量 curMin 记当前最小值，栈里存差值 diff = val - curMin。

压栈时 diff 非负表示这个数没刷新最小值，负数表示它成了新的最小值。

弹栈时如果 diff 是负的，说明弹走的正是当前最小值，得把旧的那个算回来：oldMin = curMin - diff。diff 本来就是 val - oldMin，而 val 就是现在的 curMin，移项即可。

读栈顶时同理：diff <= 0 说明这个数就是 curMin，否则是 curMin + diff。

struct MinStack {
        vector<long long> diff;
        long long curMin;

        void push(long long val) {
            if (diff.empty()) {
                diff.push_back(0);
                curMin = val;
            } else {
                diff.push_back(val - curMin);
                if (val < curMin) curMin = val;
            }
        }

        void pop() {
            if (diff.back() < 0) {
                curMin = curMin - diff.back();
            }
            diff.pop_back();
        }

        long long top() {
            return diff.back() <= 0 ? curMin : curMin + diff.back();
        }

        long long getMin() { return curMin; }
    };

一个坑：差值要用 long long。INT_MAX - INT_MIN 在 int 里算出来是 -1，符号直接反过来，后面的判断全错，换成 64 位才是 4 294 967 295。

六、预先开好定长数组

笔试和竞赛里常见的写法是两个定长数组加一个 size，省掉动态扩容：

const int MAXN = 8001;

    struct MinStack {
        int data[MAXN], mn[MAXN], size;

        MinStack() { size = 0; }

        void push(int val) {
            data[size] = val;
            if (size == 0 || val <= mn[size - 1]) {
                mn[size] = val;
            } else {
                mn[size] = mn[size - 1];
            }
            size++;
        }

        void pop() { size--; }

        int top() { return data[size - 1]; }

        int getMin() { return mn[size - 1]; }
    };

这里 MAXN 要按题目给的上界开，开小了越界，开大了浪费。至于扩容本身有多贵：vector 从空长到 1 000 000，扩容 21 次，累计搬走 1 048 575 个 int，正好约等于 n 个，摊到每次 push 上是一次拷贝。实测 300 万次混合操作，定长数组版 30.27 ms、vector 版 33.10 ms。差别不大，定长版的价值是写法简单、上限写死了不会突然 realloc，别指望靠它提速。

时间上四个版本都是 O(1)，拼的是空间。省空间版在随机数据下 mn 栈只有 Hmin(n,V) 项，实测 n = 105、值域 103 时是 7 项；差值法省掉了 mn 栈，但每个元素从 4 字节变 8 字节，n = 106 时算下来正好和同步版打平，白折腾。

栈本身存 n 个元素的空间是省不掉的，所有写法都要开 O(n)。

八、总结

几个要点：

  • 同步 mn 栈靠一条不变式成立：mn[i] 等于从第 0 层到第 i 层的最小值，push 和 pop 都必须同步，漏掉 pop 里的弹栈在 20 000 组随机序列里有 76.36% 会现形。
  • 同步版里 <= 写成 < 无所谓，两种写法压进去的是同一个数。等号要紧的地方是省空间版，那里重复的最小值要记份数。
  • 省空间版的 mn 栈期望长度是 Hmin(n,V) ≈ ln n，严格递减时退化回 n。
  • 差值法的 diff 必须开 long long，int 下 INT_MAX - INT_MIN 会溢出成 -1。
  • 只问一次最小值时全扫就够了（100 万个只要 0.250 ms），别一上来就上 mn 栈。

这套「每一层存一份前缀答案、弹出时同步回滚」的思路后面还会遇到：单调栈、直方图最大矩形、滑动窗口的最大值，用的都是同一个记账办法。下一讲换成问最大值的窗口，栈要换成能两头出队的双端队列。
