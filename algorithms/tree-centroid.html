树的重心：一次 dfs 与三个等价定义

把树里某个点连同它的边一起挖掉，剩下的部分会裂成几块。让最大那一块尽量小的点叫重心，一棵树最多两个，两个还一定挨着。求它只需要一次 dfs，而且「最大块最小」「每块不超过一半」「所有人走过来最省力」说的是同一件事。

零、背景

树上一个点 u，把 u 和它连着的所有边都删掉，剩下的点会按 u 的邻居分成若干块：u 的每个邻居领一块。记这几块里点数最多的是 maxsub[u]，也就是「以 u 为根时最大的那棵子树有多少点」。

比如一条 8 个点的链，挖掉第 4 个点，左边剩 3 个、右边剩 4 个，maxsub[4] = 4；挖掉第 1 个点，剩下的 7 个点挤成一整块，maxsub[1] = 7。前者比后者均匀得多。

一、问题

题目一（平衡行为）：一棵 n 个点的树，打印重心点的编号，以及该点的 maxsub。有多个重心时打印编号最小的那个。n ≤ 20000，多组数据。

最直接的写法是挨个试：对每个点 u，把 u 挖掉，再对每个邻居做一次 flood fill 数出那一块有多大，取最大。一次数块是 O(n)，n 个点就是 O(n²)，n = 20000 时是 4 × 10⁸ 次访问。对每组数据都这么跑一遍，铁定超时。

可以发现浪费在哪：u 挖掉之后，每个邻居领的那一块，除非邻居在 u 的「上方」，恰好就是「以 1 号为根时那个邻居的子树」。而子树大小是所有点一次性就能算出来的东西。

二、一次 dfs 算完所有点

任取 1 号点当根做 dfs，sz[u] 是 u 的子树大小。现在看任意点 u：

1）u 的儿子 v 方向那一块，恰好是 v 的整棵子树，大小 sz[v]；
2）u 的父亲方向那一块，是整棵树减掉 u 的子树，大小 n − sz[u]。

两类取最大就是 maxsub[u]。注意第 2 类只有一项，却特别容易忘写，漏掉它之后每个点的读数都偏小，取 min 时选出来的点也就跟着错了。

题目一要的是「maxsub 最小的点，并列时取编号最小」，顺着 dfs 一路比就行：

// 当前来到 u 节点，父亲节点是 f
    // 顺便记下「以 u 为根时最大子树有多少点」，取最小的那个 u
    void dfs(int u, int f) {
        sz[u] = 1;
        int maxsub = 0;                       // u 的儿子方向最大的那一棵
        for (int e = head[u], v; e != 0; e = nxt[e]) {
            v = to[e];
            if (v != f) {
                dfs(v, u);
                sz[u] += sz[v];
                maxsub = max(maxsub, sz[v]);
            }
        }
        maxsub = max(maxsub, n - sz[u]);      // 父亲方向那一块别落下
        if (maxsub < best || (maxsub == best && u < center)) {
            best = maxsub;
            center = u;
        }
    }

主流程是建图、dfs、打印。多组数据要记得把 head 清干净、best 复位：

int main() {

三、三个定义说的是同一件事

重心有三种常见说法，求出来的点一模一样：

1）以它做根时，最大子树的点数最少；
2）以它做根时，每棵子树的点数都不超过总点数的一半；
3）树上所有点都走向它，走过的总边数最少。

先看 1 和 2 为什么是一回事。设 u 有一个方向上的块 B 大小超过 n/2，B 挨着 u 的那个点是 v。v 的各个方向：儿子方向全在 B 里面，加起来也不过 |B| − 1；父亲方向是 n − |B|，比 n/2 还小。于是 maxsub[v] 的两类来源都严格小于 |B|，而 maxsub[u] ≥ |B|，v 严格优于 u。所以「最大块最小」的点不可能有哪个方向超过半数。

反过来，若 u 的每个方向都不超过 n/2，取任意 v ≠ u，看 u 到 v 路径上 u 那一侧的块 B（它包含 v），|B| ≤ n/2。v 朝 u 的那一块是整棵树减掉 v 这一侧，大小至少 n − |B| ≥ n/2 ≥ maxsub[u]，v 不可能更好。等号只在 |B| 恰好等于 n/2 时成立，这就是两个重心并存的由来。

再看 1 和 3。设所有点都走向 u，总边数是 D(u)。把集合点从 u 挪到它的邻居 v：v 那一侧的点少走一条边，其余点多走一条边，于是

D(v) − D(u) = (n − sz[v]) − sz[v] = n − 2 × sz[v]

这里的 sz[v] 是以 u 为根时的子树大小。只要某个方向超过 n/2，往那边挪一步总边数就下降；所有方向都不超过 n/2 时，往哪挪都不下降。所以「总边数最少」和「每块不超过一半」抓的是同一批点。

随机树上跑了两万组（n 取 2 到 30），三个定义给出的集合一次都没对不上；单重心 16699 组（83.50%），双重心 3301 组（16.50%），而双重心的两组永远相邻。

四、四条补充性质

4）一棵树最多两个重心，有两个时它们一定相邻。
5）树上增加或者删掉一个叶节点，重心最多移动一条边。
6）把两棵树用一条边连起来，新重心一定落在原来两个重心的路径上。
7）边权都为正时，不管边权怎么分布，所有点走向重心的总距离最小。

第 4 条的形状最好认：两个重心之间那条边把树分成两半，各 n/2 个点，n 必然是偶数。链的中间两个点就是这种局面。

第 5 条听着像玄学，实测一下就踏实了：两万组随机树上各挑一个点挂上新叶，新老重心的距离累计 4294 条边、平均每次移动 0.215 条，最大就是 1，没有一次跳过两格；删叶的 8000 组同样 0 次超过一条边，平均只挪 0.035 条。第 6 条也量过，八千组「两棵树连起来」的样本里，9333 个新重心没有一例跑到原两重心的路径之外。

第 7 条要带权才讲得透，下一页拿它做整道题。

五、题目二：把所有重心都打印出来

题目二（教父）要的是全部重心，n ≤ 50000。这时候别在 dfs 里急着挑，把每个点的 maxsub 留下来，最后按定义 2 扫一遍：

// 这一次不急着挑，把每个点的答案留在 maxsub 里
    void dfs(int u, int f) {
        sz[u] = 1;
        maxsub[u] = 0;
        for (int e = head[u], v; e != 0; e = nxt[e]) {
            v = to[e];
            if (v != f) {
                dfs(v, u);
                sz[u] += sz[v];
                maxsub[u] = max(maxsub[u], sz[v]);
            }
        }
        maxsub[u] = max(maxsub[u], n - sz[u]);
    }
// 重心可能有两个，两个都要打印
    int m = 0;
    int centers[2];
    for (int i = 1; i <= n; i++) {
        if (maxsub[i] <= n / 2) {
            centers[m++] = i;
        }
    }
    for (int i = 0; i < m; i++) {
        printf("%d%c", centers[i], i + 1 == m ? '\n' : ' ');
    }

判定条件是 maxsub[i] <= n / 2，这里的等号不能省。实测三万组随机树（n 取 4 到 24）：写成 < n / 2 时 42.40% 的样本少打点，而在 n 为偶数的树上这个比例是 100%；写成 <= (n + 1) / 2 时 n 为奇数的树上有 25.67% 会多打点，n 为偶数时它和 n / 2 完全一样、0 例出错。数字看着只差一个 1，落在实际代码上就是一整类样例全错。

题目一那个 u < center 的并列判断用得上：上面三万组里有 16.73% 的树真的存在两个重心，正好等于双重心的占比。

复杂度分析

一次 dfs 走遍 n − 1 条边，每个点在回溯时把它的边扫一遍，合计 O(n)；题目二最后那次扫描也是 O(n)。

环节时间空间
dfs 求 sz 与 maxsubO(n)O(n)
扫一遍挑重心O(n)
合计O(n)

空间按题目上限算。题目一 n = 20000：head 20001 个 int 约 78 KB，nxt、to 各 40002 个约 156 KB 各，sz 再来 78 KB，合起来不到 0.5 MB。题目二 n = 50000 时约 1.1 MB。

速度上，n = 10⁵ 的随机树跑一遍求重心，递归写法 2.69 ms、迭代写法 3.48 ms；链和星更快，分别是 0.99 ms 与 0.40 ms。递归有个绕不开的隐患：本机栈 8 MB，链上 86000 层还扛得住，87000 层直接段错误。n = 10⁵ 的链正好卡在这条线上，所以碰到长链形态的数据，迭代版更稳。

总结

要点三条。其一，以 1 号为根做一次 dfs，任意点 u 的 maxsub 就是「儿子子树的最大值」与「n − sz[u]」这两个数取大，后者最容易被漏掉。其二，「最大块最小」「每块不超过一半」「总边数最少」是同一个点集的三种说法，两万组随机树上 0 例不符，双重心永远相邻且各占 n/2。其三，判定条件写 <= n / 2 不能改成 < 或 <= (n + 1) / 2，三万组实测里这两处分别有 42.40% 与 25.67% 的样本会出错。

带上点权和边权之后，这套东西还能回答「所有牛聚到哪一站最省力」，那是下一页的内容。

六、最后

树的重心本身不难，难在它是后面一整批算法的地基：静态点分治每次都要先找到重心再下手，树上距离类题目也常常先定位重心再展开。这一页的四个数字（两个来源、n/2 这条线、最多两个、最多移动一条边）值得记住，后面反复会用到。
