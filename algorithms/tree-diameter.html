树的直径：两遍 dfs 与树形 dp

树上任意两点之间只有一条路。把所有点两两配对，距离最大的那一对之间的路径就是直径。求直径有两种经典写法，一种遍历两遍树，一种遍历一遍；边权带负时只有一种还对。直径身上还藏着一道题：所有直径共享同一段中间路径，这段公共部分的边数也能数出来。

零、背景

先约定口径：路径长度是沿途边权之和，路径至少要经过一个点（停在原地算长度 0）。两个点的距离就是它们之间唯一那条路径的长度。

直径是树上最长的链，很多题看着跟直径无关，绕到最后都在问它。离某个点最远的点跑不出直径端点的范围；让最远距离最小、或者选一段路建点什么，最优选择往往就落在直径上。这一课先把直径求出来，再看它身上的结构。

一、问题

树的直径模板：给定一棵树，边权可能为负，求直径长度。n 不超过 5×10⁵，数据来自洛谷 U81904。这道题同时要求写出两种求法，正好把它们摆在一起看。

二、两遍 dfs

第一遍从任意一点（代码里取 1 号）出发 dfs，记录每个点的距离，取最远的点 x；第二遍从 x 出发再 dfs 一次，这次的最远距离就是直径。

第二遍为什么一定对，靠的是一条结论：从任意点出发的最远点，一定是某条直径的端点。证明不长，值得跟着走一遍。

设直径是 a 到 b，长度 D。任取一个点 v，设它连到直径路径上的点是 q（v 本来就在直径上时 q 就是 v）。v 伸出去的那一截长度不可能超过 min(dist(q,a), dist(q,b))：要是比 dist(q,a) 还长，v 走到 b 就是 dist(q,v) + dist(q,b) > D，跟「a 到 b 是直径」矛盾。

再看从 u 出发的最远点 x，设它连在直径的 p 点上。因为 x 最远，dist(u,x) ≥ dist(u,a)。u 到 x 和 u 到 a 的路都经过 p，两边的 dist(u,p) 抵消，得到 dist(p,x) ≥ dist(p,a)。于是 dist(x,b) = dist(x,p) + dist(p,b) ≥ dist(p,a) + dist(p,b) = D。x 到 b 已经不比直径短，那就正好等于 D，x 就是直径端点。第二遍从 x 出发，最远距离自然是 D。

// 两遍 dfs：第一遍从任意点出发找最远点，第二遍从这个点出发再找最远点
    void dfs(int u, int f, int w) {
        last[u] = f;
        dist[u] = dist[f] + w;
        for (int e = head[u]; e != 0; e = nxt[e]) {
            if (to[e] != f) {
                dfs(to[e], u, weight[e]);
            }
        }
    }

    void road() {
        dfs(1, 0, 0);
        start = 1;
        for (int i = 2; i <= n; i++) {
            if (dist[i] > dist[start]) {
                start = i;
            }
        }
        dfs(start, 0, 0);
        ed = 1;
        for (int i = 2; i <= n; i++) {
            if (dist[i] > dist[ed]) {
                ed = i;
            }
        }
        diameter = dist[ed];
    }

两遍 dfs 的代价是树被遍历两遍，换来的是信息全：第二趟结束后 last[] 里留着整条直径路径，两个端点、沿途每个点、每个点到端点的距离都拿得到。后面很多题要用这些。

三、负权下两遍 dfs 会垮

边权可能为负时，上面这套推理在第一步就出错了。

距离可以是负的，「原地不动」的距离 0 反而经常是最大值。第一遍从 1 号出发，如果走到每个点的距离都是负的，最远点就选中了 1 号自己，第二遍还在 1 号里打转，答案报 0。最小的反例只要三个点：1 到 2 权 -3，2 到 3 权 3。直径是 2 到 3，长度 3；从 1 出发，到 2 是 -3、到 3 是 0，都不比自己所在的 1 号远，两遍 dfs 报出来是 0。

错得到处都是吗？实测一下。随机树、边权在 [-V, V] 上均匀取，跟全源距离的暴力对答案，每种规模 5000 组：

点数 nV = 2V = 5V = 10V = 100
410.60%10.68%10.54%11.36%
815.22%15.90%16.94%16.82%
1615.38%16.18%15.90%16.88%

n = 8 起大约每六棵树错一棵，n = 16 还是这个量级，跟值域 V 几乎无关。问题出在符号结构上，跟幅度没什么关系。再拿 20000 组 n = 8、V = 5 的树细看：错 3193 次，全是把直径算小，没有一次算大。两遍 dfs 在负权树下只会低估，它找到的确实是某条真实路径，只是短了一些。

所以这道题得换法子。

四、树形 dp

树形 dp 只遍历一遍树，对每个点记两个量。dist[u]：从 u 开始必须往下走、能走出的最大距离，也可以一步都不走。ans[u]：路径必须经过 u 的情况下，最大路径和。

后序回来时，u 的每个儿子 v 都有两个选择：把 v 的最长向下路径接上来，更新 dist[u]；或者把它和 u 已经接上的另一条向下路径拼起来，经过 u，更新 ans[u]。直径就是所有 ans[u] 里的最大值。

// 树型dp：dist[u] 从u往下走的最大增益(可以不选边)，ans[u] 路径过u的最大和
    void dp(int u, int f) {
        for (int e = head[u], v; e != 0; e = nxt[e]) {
            v = to[e];
            if (v != f) {
                dp(v, u);
            }
        }
        for (int e = head[u], v; e != 0; e = nxt[e]) {
            v = to[e];
            if (v != f) {
                ans[u] = max(ans[u], dist[u] + dist[v] + weight[e]);
                dist[u] = max(dist[u], dist[v] + weight[e]);
            }
        }
    }

    // 答案就是所有 ans[u] 里的最大值
    int diameter = 0;
    for (int i = 1; i <= n; i++) {
        diameter = max(diameter, ans[i]);
    }

这套写法对边权的符号没有要求。dist[u] 初始为 0 而不是负无穷，意思是「可以不选任何边」；ans[u] 初始也是 0，所以边权全负的树答案是 0（停在原地）。拿全源距离的暴力对拍 3000 组（正权负权各半），树形 dp 0 组不符。

五、正权树上的两条结论

边权都为正时，直径身上还挂着两条常用结论。

其一，如果有多条直径，它们一定拥有共同的中间部分，可能是一个公共点，也可能是一段公共路径。其二，从树上任意一点出发，与它相隔最远的点构成一个集合，直径的两个端点至少有一个在这个集合里。

第一条正是下一题要数的东西。

求直径操作台：两遍 dfs 逐步走，树形 dp 一旁对照

选一棵树点「下一步」，看两遍 dfs 怎么两趟找出直径；负权那棵会在最后一步露出分歧。

六、所有直径的公共部分

给定一棵边权都为正的树，打印直径长度，以及所有直径的公共部分有几条边。n 不超过 2×10⁵，数据来自洛谷 P3304。

先两遍 dfs 定下一条直径，把路径上的点打上标记。然后只看直径路径上的点，从终点那一端往起点走，对每个点 i 算一个量：h(i) 是从 i 出发、不进直径能走出的最远距离。

h(i) 有两种取等，各自把公共部分的一侧边界钉住：

1）h(i) == diameter - dist[i]，i 上挂着的树枝正好补上 i 到终点那段。这时「起点到树枝尖」是一条新直径，它绕开了 i 靠近终点那一侧，于是那些点不在公共部分里。从终点往起点扫，最后一个满足条件的 i 就是公共部分的右端 r。
2）h(i) == dist[i]，对称的情况：树枝尖到终点是一条直径，不经过 i 靠近起点那一侧。第一个满足条件的 i 是公共部分的左端 l。

两个条件在同一个 i 上同时成立，说明公共部分缩成了一个点，答案 0。

数边数就从 r 顺着 last[] 走到 l，走几步就是几条边。

// 公共部分：先两遍dfs定出直径，再对直径上每个点算「不进直径的最大距离」
    void dfs(int u, int f, long long c) {
        last[u] = f;
        dist[u] = c;
        for (int e = head[u]; e != 0; e = nxt[e]) {
            if (to[e] != f) {
                dfs(to[e], u, c + weight[e]);
            }
        }
    }

    // 不能走向直径路径上的节点，能走出的最大距离
    long long maxDistanceExceptDiameter(int u, int f, long long c) {
        long long ans = c;
        for (int e = head[u], v; e != 0; e = nxt[e]) {
            v = to[e];
            if (!diameterPath[v] && v != f) {
                ans = max(ans, maxDistanceExceptDiameter(v, u, c + weight[e]));
            }
        }
        return ans;
    }

    void compute() {
        dfs(1, 0, 0);
        start = 1;
        for (int i = 2; i <= n; i++) {
            if (dist[i] > dist[start]) start = i;
        }
        dfs(start, 0, 0);
        ed = 1;
        for (int i = 2; i <= n; i++) {
            if (dist[i] > dist[ed]) ed = i;
        }
        diameter = dist[ed];
        for (int i = ed; i != 0; i = last[i]) {
            diameterPath[i] = true;
        }
        int l = start, r = ed;
        for (int i = last[ed]; i != start; i = last[i]) {
            long long maxDist = maxDistanceExceptDiameter(i, 0, 0);
            if (maxDist == diameter - dist[i]) {
                r = i;
            }
            if (maxDist == dist[i] && l == start) {
                l = i;
            }
        }
        if (l == r) {
            commonEdges = 0;
        } else {
            commonEdges = 1;
            for (int i = last[r]; i != l; i = last[i]) {
                commonEdges++;
            }
        }
    }

代码里两个细节值得停一下。l 只在第一次取等时记，r 每次取等都覆盖，所以 l 是「最靠终点」的那个、r 是「最靠起点」的那个，方向别搞反。另外直径路径要单独存一份标记，算 h(i) 的递归靠它绕开直径上的其他点。

实测 5000 棵 12 个点的正权随机树：平均只有 1.20 条直径，83.22% 的树直径唯一（这时公共部分就是整条直径），0.30% 的树公共部分缩成一个点。跟「枚举每条直径路径再求边集交集」的暴力对拍 3000 组，0 组不符。

最后提一句递归深度。这一路的 dfs 深度等于树高，链上就是 n。本机 g++ -O2、8MB 栈下实测这个递归约 13 万层见顶（每帧约 64 字节），n = 2×10⁵ 的链会爆栈。换到评测机不一定，但余量确实不大。稳妥做法是把 dfs 改成显式栈：把「当前遍历到 u 的第几条边、走到 u 的距离」一起压栈，弹栈时接着往下走。

// dfs 改迭代：把「当前遍历到u的第几条边、走到u的距离」一起压栈
    // 弹栈时接着往下走，递归深度从此不受栈大小限制
    int ufeStack[MAXN][3];
    long long distStack[MAXN];
    int stackSize;
    int u, f, e;
    long long c;

    void push(int u, int f, int e, long long c) {
        ufeStack[stackSize][0] = u;
        ufeStack[stackSize][1] = f;
        ufeStack[stackSize][2] = e;
        distStack[stackSize] = c;
        stackSize++;
    }

    void pop() {
        --stackSize;
        u = ufeStack[stackSize][0];
        f = ufeStack[stackSize][1];
        e = ufeStack[stackSize][2];
        c = distStack[stackSize];
    }

    void dfs(int root) {
        stackSize = 0;
        push(root, 0, -1, 0);
        while (stackSize > 0) {
            pop();
            if (e == -1) {
                last[u] = f;
                dist[u] = c;
                e = head[u];
            } else {
                e = nxt[e];
            }
            if (e != 0) {
                push(u, f, e, c);
                if (to[e] != f) {
                    push(to[e], u, -1, c + weight[e]);
                }
            }
        }
    }
公共部分操作台：一条条直径试过来，公共段就缩出来了

七、复杂度分析

环节时间空间
两遍 dfs 求直径O(n)（两遍）O(n)
树形 dp 求直径O(n)（一遍）
公共部分：h(i) 逐个算 + 数边O(n)
合计O(n)

空间按题目上限算。题1 n = 5×10⁵：head 一个 int 数组，nxt、to、weight 各两个 int（每条边存正反两份），dist、last 各一个，合计十几个 int 数组，几十 MB 量级。题2 n = 2×10⁵ 时 dist 要开 long long：边权到 10⁴ 时直径能到 2×10⁹，int 装不下。

八、总结

要点四条。其一，正权树上两遍 dfs 求直径，依据是「任一点的最远点一定是直径端点」，证明的关键是挂在直径路径上的树枝长不过它到两端的较小值。其二，负权下这条推理在第一步就垮了，距离能为负时最远点可能选中出发点自己，实测 n = 8 的随机树约六分之一答错，且只会低估、不会高估。其三，树形 dp 只遍历一遍，对符号没有要求，dist 与 ans 初始为 0 还顺带定下了「路径可以不走边」的口径。其四，所有直径共享中间路径，公共部分的两端由 h(i) 的两种取等钉住：h(i) == diameter - dist[i] 定右端，h(i) == dist[i] 定左端，同时成立就缩成一个点。

顺带一句，直径求出来只是开始。合并两棵树、新加几条边、在直径上选一段路，这些变形在造公园、巡逻、消防三道题里挨个出现，思路都是把「最长」这件事重新配方。

九、最后

两个模板都不难写，难的是记住各自的适用边界：两遍 dfs 图的是信息全，端点、路径、距离一起到手；树形 dp 图的是遍历一遍且不怕负权。拿到题先看边权符号，再挑模板，比写完再调要快。
