AC 自动机：fail 指针与直通表

一个前缀树上，给每个节点再补一条指向「最长可接的后缀」的边，一堆目标串就能和文章一次对完。这条边怎么定、建的时候怎么不绕圈、匹配的时候怎么让它彻底不出现，是这一页的三件事。

零、从 KMP 到多串匹配

判断一篇文章里有没有一个目标串，KMP 把主串指针压成只往前走，线性时间。目标串从一个变成 n 个，逐个跑 KMP 就是「文章长度 × n」的代价，n = 2×105、文章 106 时跑不完。

自动机是确定有限状态自动机的简称，对信号序列做判定的数学模型。前缀树是自动机的一种实现，KMP 也能看成一台两状态的自动机。把两者拼起来，就是 AC 自动机：前缀树 + fail 指针。

前缀树负责存：所有目标串插进同一棵树，从根往下走一条路径，就拼出某个目标串的一个前缀。fail 指针负责接：某个位置走不下去了，从哪个节点接着往下走，才可能不丢掉已经对上的那段。

整节课要用的前置有三块：前缀树、链式前向星（存 fail 反图用）、KMP 的失配回退思想。下面按顺序推。

一、fail 指针的含义

树上一个节点 a 对应一个前缀串 s。fail 指针要指向的节点 t 满足三个条件：

1）t 是某个目标串的前缀，也就是树上真实存在的一个节点；

2）t 对应的串与 s 的某个后缀完全一样；

3）在所有满足前两条的 t 里，长度最大，而且 t 不等于 s 本身。

拿 "she" 试。它的真后缀有三个候选："he"、"e"、空串。目标是 {"he","she","his","hers"}，"he" 是目标串 "he" 的前缀，在树上就是节点 2；"e" 不是任何目标串的前缀，树上没有这个节点；空串谁都接得住，对应根。三个候选里最长的合法项是 "he"，所以 "she" 的 fail 指向节点 2。

为什么要求 t 不能等于 s？自己指自己没有任何信息量，还容易在建表时把指针接成环。

这条边的意义就一句话：保留所有匹配成功的可能性。在文章里某个位置，我们刚刚走完的这段字符可能同时是好几件事——字符串匹配失败，但它的后缀说不定正要开始某个目标串。fail 链把你的「已经匹配到哪」从 s 逐级降到它的最长后缀、次长后缀，直到根。KMP 的 next 数组干的是同一件事，只是模式串只有一个，这条链退化成一条直线。

这张图里有两条边值得盯一下。"she" 的 fail 指向 "he"，说明读到 "she" 时，如果后面接不上，站在 "he" 这个前缀上继续读照样有机会。"his" 的 fail 指向节点 "s"，说明 "his" 的尾巴正好是 "she" 的开头，这两段在文章里可以重叠。

二、建 fail：按层推，空边补成直通边

根的孩子 fail 都是根，因为它们没有更短的真后缀。剩下的节点按层序推：父亲的 fail 一定已经算好了，用它推孩子。

处理节点 u 的时候扫它的 26 条边：

1）这条边是空的，就把 tree[fail[u]][i] 写进去。写完之后它不再表示「没有边」，而是表示「从 u 读入字符 i 之后该站在哪个节点」。

2）这条边是实的，就把 fail[tree[u][i]] = tree[fail[u]][i]，然后把孩子入队。

两句话合起来，就是一次遍历里同时办完两件事：给每个孩子定 fail，给每个空位填直通边。填的时候不用沿 fail 往上找，因为 tree[fail[u]][i] 在父亲那一层就已经是补好的直通边了。

拿 "sh" 这个节点举例。它的 fail 是 "h"，而 "h" 的 'i' 边通向 "hi"。给 "sh" 读一个 'i'，按直通边就落到 "hi" 上：文章里出现 "shis" 这种串时，"his" 才不会被漏掉。

实测一下这一步省了多少：20000 个长度 10 的随机串（总字符 20 万，建出 152266 个节点），按层推加直通表 4.87 毫秒；同样这棵树，逐条边沿 fail 往上找 20.89 毫秒，一共走了 7334182 步。

匹配阶段更直接。补完直通边之后，走文章只剩一行：

// 走文章：每一步都只是一次数组访问，fail 指针不再出现在循环里
    void match(const string& text, int n) {
        for (int u = 0, i = 0; i < (int)text.size(); i++) {
            u = tree[u][text[i] - 'a'];
            hits[u]++;
        }
    }

fail 指针在这个循环里一次都不出现。所有回退在建机时已经摊平到每条边上，落到哪个节点由 tree 直接回答。106 个字符平均 15.97 毫秒。

写错这一步的方式很典型：只设 fail、不补空边，匹配时照样写 u = tree[u][c]。少了那条直通边，本该落在 "sh" 子树里的字符直接掉回根，成片的命中消失。4000 组随机数据（字母表 2~3 个字符、模式长 ≤ 4、文章长 ≤ 40）里，83.97% 的组答案不一样。

三、建机与匹配的代码

插入目标串就是普通前缀树，多带一个「这个节点是哪几个目标串的结尾」的记录：

// 把目标串插进前缀树，顺带记下它的结尾节点编号
    void insert(int i, const string& s) {
        int u = 0;
        for (int j = 0; j < (int)s.size(); j++) {
            int c = s[j] - 'a';
            if (tree[u][c] == 0) {
                tree[u][c] = ++cnt;
            }
            u = tree[u][c];
        }
        endv[i] = u;
    }

建 fail 的两句话，加上队列，就是全部的建机代码：

// 按层推 fail：空边走直通边，实边往下推的同时把孩子塞进队列
    void setFail() {
        int l = 0, r = 0;
        for (int i = 0; i < 26; i++) {
            if (tree[0][i] > 0) {
                box[r++] = tree[0][i];
            }
        }
        while (l < r) {
            int u = box[l++];
            for (int i = 0; i < 26; i++) {
                if (tree[u][i] == 0) {
                    tree[u][i] = tree[fail[u]][i];
                } else {
                    fail[tree[u][i]] = tree[fail[u]][i];
                    box[r++] = tree[u][i];
                }
            }
        }
    }

四、复杂度分析

做法关键操作时间空间
逐个目标串跑 KMP每个目标串扫一遍文章O(文章长度 × 目标串个数)O(最长串长)
AC 自动机建机每个节点扫一遍 26 条边O(26 × 总字符数)O(26 × 总字符数)
AC 自动机匹配每个字符一次数组访问O(文章长度)O(1) 额外
不补直通边，每步沿 fail 退每个字符可能退若干层最坏 O(文章长度 × 最长串长)O(1) 额外

建机那一步的 26 是字母表大小，写成常数就是 O(总字符数)。20 万字符建出 152118 个节点（前缀共享省掉了 47882 个），tree 表 152118 × 26 个 int 约 15.1 MB，所以模板题的 MAXS 直接开到 2×105。匹配阶段每个字符固定一次访问，106 个字符 15.97 毫秒；不补直通边的写法在 a1~a200 那族数据上多退 999800 步、1.15 毫秒对 0.52 毫秒，数据一换成「失配要退满链长」的形状，差距还会拉开。

总结

fail 指针指向「某个目标串前缀」里，与当前节点串的某个后缀相同、长度最大、且不等于自己的那一个。三个条件缺一不可，最后一条是防环的。

建机的顺序是层序：根的孩子指向根，其余用 tree[fail[u]][i] 一次推出孩子的 fail，同时把空边填成直通边。填边不用绕圈，这正是它比逐条边往上找快的地方，同样一棵 152266 节点的树 4.87 毫秒对 20.89 毫秒。

匹配就是 u = tree[u][c] 加一次计数，O(文章长度)，写错成「不补直通边还一步走」有 83.97% 的随机数据会给出不同答案。

这一页只解决了「走到哪个节点」。走到一个节点只说明有个短目标串在这里结束，长一点的、把它当后缀的那些串的次数还躺在 fail 链的下游，下一节把这笔账一次算清。
