优化枚举：规划兼职工作

有 n 份兼职，每份从 startTime[i] 做到 endTime[i]，报酬 profit[i]，时间重叠的两份不能同时做，问最大报酬。带枚举的转移写出来是 O(n²)，但前驱的位置有单调性，一层二分就能把枚举整段拿掉。

零、先把转移写出来

这题的状态不好定义成「第 i 天」，因为时间是稀疏的。换个角度：把工作按结束时间从早到晚排序，dp[i] 表示「只在前 i + 1 个工作里挑，最多能拿多少」。之所以按结束时间排序，是因为只有排在前面的工作才可能排在它前面做。

转移有两条路：不选第 i 个工作，答案是 dp[i−1]；选它，那前面能接的只剩那些 endTime ≤ startTime[i] 的，挑其中 dp 最大的一个加上 profit[i]。

这里有个细节值得单独说：题目写「如果你选择的工作在时间 X 结束，那么你可以立刻进行在时间 X 开始的下一份工作」，所以条件是 endTime ≤ startTime，等号要留着。随机数据里「某份工作的结束时间正好等于另一份的开始时间」这种情况占 68.52%，等号写掉的后果比想象中严重。

// 暴力版：工作按结束时间排好序，dp[i] 表示只考虑前 i+1 个工作能拿到的最大报酬
    int jobBrute(vector<int>& st, vector<int>& en, vector<int>& pr) {
        int n = st.size();
        vector<Job> jobs(n);
        for (int i = 0; i < n; i++) jobs[i] = { st[i], en[i], pr[i] };
        sort(jobs.begin(), jobs.end(), [](const Job& a, const Job& b) { return a.e < b.e; });
        vector<long long> dp(n, 0);
        for (int i = 0; i < n; i++) {
            long long best = jobs[i].p;                              // 只做第 i 个工作
            for (int j = 0; j < i; j++) {                            // 枚举所有可能的前驱
                if (jobs[j].e <= jobs[i].s) {
                    best = max(best, dp[j] + jobs[i].p);
                }
            }
            dp[i] = (i == 0) ? best : max(best, dp[i - 1]);          // 不选第 i 个，继承前面的答案
        }
        return (int)dp[n - 1];
    }

内层那个 for (int j = 0; j < i; j++) 就是全部的代价来源。n = 20000 时它要走 199990000 次。

一、观察：能接在前面的工作是一段前缀

排完序之后 endTime 单调不降。对固定的第 i 个工作，条件「endTime[j] ≤ startTime[i]」在 j 从 0 往右走时，先是成立，某个位置之后一直不成立。所以满足条件的 j 是连续的一段前缀，不会中间断掉。

而这个前缀里的 dp 值，dp[0..i−1] 本身单调不降（dp[i] = max(best, dp[i−1])），所以「前缀里 dp 最大的」就是前缀的最右端那一个。

两件事合起来：内层扫描不需要看每个 j，只要找到「endTime ≤ startTime[i] 的最右下标」，这是有序数组上的经典二分。

// jobs[0...i] 上找结束时间 <= start 的最右下标；排过序，endTime 单调不降，可以二分
    int find(vector<Job>& jobs, int i, int start) {
        int ans = 0, l = 0, r = i, m;
        while (l <= r) {
            m = (l + r) / 2;
            if (jobs[m].e <= start) {                                // 注意是 <=，相接的工作可以连着做
                ans = m;
                l = m + 1;
            } else {
                r = m - 1;
            }
        }
        return ans;
    }

外层循环把 find 换进去，O(n²) 变 O(n log n)。排序本身也是 O(n log n)，整体不变。

struct Job { int s, e, p; };

    // 最优解：排序 + 二分定位前驱，O(n*logn)
    int jobScheduling(vector<int>& st, vector<int>& en, vector<int>& pr) {
        int n = st.size();
        vector<Job> jobs(n);
        for (int i = 0; i < n; i++) jobs[i] = { st[i], en[i], pr[i] };
        sort(jobs.begin(), jobs.end(), [](const Job& a, const Job& b) { return a.e < b.e; });
        vector<long long> dp(n, 0);
        dp[0] = jobs[0].p;
        for (int i = 1; i < n; i++) {
            long long best = jobs[i].p;
            if (jobs[0].e <= jobs[i].s) {
                best += dp[find(jobs, i - 1, jobs[i].s)];            // 一次二分替代整个前驱枚举
            }
            dp[i] = max(best, dp[i - 1]);
        }
        return (int)dp[n - 1];
    }

if (jobs[0].e <= jobs[i].s) 这一句是省掉二分的一种写法：连最早结束的那个工作都接不上，后面更不可能。二分本身能正确处理这种情况（ans 初值 0 会给出错的值），所以这层判断不能省。

五、复杂度分析

版本时间空间说明
排序 + 枚举前驱O(n²)O(n)排序 O(n log n) 被内层盖过
排序 + 二分定位O(n log n)O(n)每个 i 一次二分，dp 只开一维

空间只有 jobs 和 dp 两个数组，都是 O(n)。dp 只用到 dp[i−1] 和 dp[find(...)]，而 find 的结果不固定，压不成单个变量，一维数组是必要的。

六、总结

这题的优化链条是：先排序让 endTime 单调 → 前缀条件连成一段 → 段内的 dp 又单调 → 整个枚举退化成「找最右的合法位置」→ 二分。每一步观察都把搜索范围砍掉一半以上。

写的时候注意三处：条件是 ≤ 不是 <；dp[i] 要与 dp[i−1] 取最大；排序依据必须是结束时间。用大值域随机数据验不出等号的问题，专门造几组端点相接的样本更省事。

后面几道题会继续用同样的路子：先写出带枚举的转移，再盯着枚举的那一段看它有没有规律。规律不一样，换的查询结构也不一样。
