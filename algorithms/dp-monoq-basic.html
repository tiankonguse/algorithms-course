单调队列优化：跳跃与收集

有一类 dp 的转移长成 dp[i] = max(dp[j]) + w(i)，j 的取值范围是一个区间，而且这个区间随 i 只往右挪一格。这个时候内层那层枚举是浪费的：候选集合在滑动，用一个队列记住「谁还可能当最大值」就够了。两道题看下来，这个结构怎么认、队列怎么维护，就清楚了。

零、转移里那层 max

先看一个具体的转移。位置从 0 开始排到 n，一开始站在 0，每次可以往右跳 a 到 b 之间的任意整数格，落到 i 就拿到 arr[i] 的分，跳过 n 就停下。问最多能拿多少分。

设 dp[i] 是「恰好落在 i 位置时，累计的最大得分」。能跳到 i 的前一个位置 j 必须满足 i − b ≤ j ≤ i − a，于是：

dp[i] = max{ dp[j] } + arr[i]，j 走遍 [i − b, i − a] 里所有合法落点。

区间长度是 b − a + 1，n 到 2 × 10⁵、b − a 也能到 2 × 10⁵，直接枚举是 O(n × (b − a))，跑不动。

关键在于 i 加 1 的时候，这个区间的两个端点同时加 1。里面大部分元素没变，只是右边进来一个、左边出去一个。

滑动窗口的最大值是个老问题，解法也是老解法：队列里存下标，让对应的 dp 值从队首到队尾严格递减。新来的 j 如果 dp 值比队尾大，队尾就永远不可能再当最大值了，直接弹掉；队首滑出窗口就丢掉。取答案只看队首。

一、向右跳跃：队列里留什么

先写枚举版，对照着看更清楚。

// dp[i] : 到达 i 位置时，能拿到的最大得分；到不了的位置记负无穷
    int jumpRight1(vector<int>& arr, int n, int a, int b) {
        const int NA = -1000000000;
        vector<int> dp(n + 1, NA);
        dp[0] = arr[0];
        for (int i = 1; i <= n; i++) {
            for (int j = i - b; j <= i - a; j++) {              // 枚举上一跳的落点
                if (j < 0 || dp[j] == NA) continue;
                dp[i] = max(dp[i], dp[j] + arr[i]);
            }
        }
        int ans = NA;
        for (int i = n + 1 - b; i <= n; i++) ans = max(ans, dp[i]);
        return ans;
    }

三个边界要提前想好：dp[0] = arr[0]（起点就站着，先拿一份）；i < a 的位置跳不到，保持负无穷；答案不是 dp[n]，而是所有「再跳一次能出界」的位置里的最大值，也就是 i 从 n + 1 − b 到 n。

最后这一点容易写错。能出界的条件是存在某个 d ∈ [a, b] 让 i + d > n，取最大的 b 最容易满足，所以判据是 i + b > n，不是 i + a > n。

改成单调队列，外层不变，内层那层枚举换成「一端进、一端出、取队首」：

// dp[i] : 到达 i 位置时，能拿到的最大得分
    // 队列里存落点，对应的 dp 值从队首到队尾递减
    int jumpRight2(vector<int>& arr, int n, int a, int b) {
        const int NA = -1000000000;
        vector<int> dp(n + 1, NA), q(n + 1);
        int l = 0, r = 0;
        dp[0] = arr[0];
        for (int i = 1; i <= n; i++) {
            int come = i - a;                                   // 这一轮进窗口的落点
            if (come >= 0 && dp[come] != NA) {
                while (l < r && dp[q[r - 1]] <= dp[come]) r--;  // 比它小的全弹出
                q[r++] = come;
            }
            if (l < r && q[l] == i - b - 1) l++;                // 滑出窗口的落点
            if (l < r) dp[i] = dp[q[l]] + arr[i];
        }
        int ans = NA;
        for (int i = n + 1 - b; i <= n; i++) ans = max(ans, dp[i]);
        return ans;
    }

这里有个细节：进出队都只看队首队尾，所以过期判断写成 q[l] == i − b − 1 就够了。因为入队的 j 是递增的，窗口左端每轮最多跨过一个下标，队首最多有一个过期。写成 while 也对，只是没必要。

还有一个细节：dp[come] == NA 的位置不入队。它们不是「值很小」，而是「根本到不了」，放进去会污染队首。

二、跟朴素写法对一遍

拿 n = 7, a = 2, b = 3，arr = [1, 3, −2, 5, −1, 4, 2, −3] 走一遍。dp 依次是：

i01234567
dp[i]1到不了−16−21087

i = 4 这一格值得看：窗口是 [1, 3]，队列里当时只有落点 2（dp = −1），因为落点 0 已经被 i − b − 1 = 0 弹出去了。所以 dp[4] = −1 + (−1) = −2。手算容易把 0 算进去，那就得到 1 + (−1) = 0，是错的。

答案是 dp[5]、dp[6]、dp[7] 里的最大值 10，对应路线 0 → 3 → 5 → 出界，得分 1 + 5 + 4 = 10。

随机 2 万组（n ≤ 12，a、b 各自随机，arr 取 −20 到 20）实测，队列版与枚举版的结果一次都没对不上。

三、向下收集：一行也是一个数组

第二题把一维换成二维：n 行 m 列的区域，一些格子上放着能量点。从第 1 行任意位置出发，每步必须往下一行，横向偏移不能超过 t，也就是从 (i−1, p) 能走到 (i, j) 当且仅当 |p − j| ≤ t。走到最后一行停下，问最多能收集多少能量。

设 dp[i][j] 是走到 i 行 j 列的最大能量，那么：

dp[i][j] = val[i][j] + max{ dp[i−1][p] }，p 走遍 [j − t, j + t] 并且不越界。

j 加 1，区间两个端点同时加 1，还是同一个形状。n、m、t 都到 4000，朴素写法 O(n × m × t) 是 640 亿次，队列版把 t 这一层拿掉，变成 O(n × m)。

代码上唯一的区别是窗口两端都要动，而上一行是现成的，所以每行的队列重新建一次：

// dp[i][j] : 走到 i 行 j 列时，能收集到的最大能量
    int collect1(int n, int m, int t, vector<vector<int>>& dp) {
        for (int i = 2; i <= n; i++) {
            for (int j = 1; j <= m; j++) {
                int best = 0;
                for (int p = max(1, j - t); p <= min(m, j + t); p++) {
                    best = max(best, dp[i - 1][p]);             // 枚举上一行能来的列
                }
                dp[i][j] += best;
            }
        }
        int ans = 0;
        for (int j = 1; j <= m; j++) ans = max(ans, dp[n][j]);
        return ans;
    }

换成队列之后，每列做三件事：右端进一个、左端出一个、取队首。

// dp[i][j] : 走到 i 行 j 列时，能收集到的最大能量
    // 队列里存上一行的列号，dp 值从队首到队尾递减
    int collect2(int n, int m, int t, vector<vector<int>>& dp) {
        vector<int> q(m + 2);
        int l = 0, r = 0;
        auto push = [&](int row, int col) {
            if (col > m) return;
            while (l < r && dp[row][q[r - 1]] <= dp[row][col]) r--;
            q[r++] = col;
        };
        for (int i = 2; i <= n; i++) {
            l = r = 0;
            for (int j = 1; j <= t; j++) push(i - 1, j);        // j = 1 时窗口是 [1, t+1]
            for (int j = 1; j <= m; j++) {
                push(i - 1, j + t);                             // 右端进来一格
                if (l < r && q[l] == j - t - 1) l++;            // 左端出去一格
                dp[i][j] += dp[i - 1][q[l]];
            }
        }
        int ans = 0;
        for (int j = 1; j <= m; j++) ans = max(ans, dp[n][j]);
        return ans;
    }

初始化那段循环把 [1, t] 先塞进去，是因为 j = 1 时窗口是 [1 − t, 1 + t]，截到合法范围就是 [1, 1 + t]，长度 t + 1。之后每列右端加一个 j + t，正好接上。

push 里 col > m 直接返回这一句不能省：j 走到 m 附近时，j + t 早就超过 m 了，那些列不存在。

六、复杂度分析

题目朴素写法队列写法空间说明
向右跳跃O(n × (b − a + 1))O(n)O(n)每个下标进队一次出队一次
向下收集O(n × m × t)O(n × m)O(m) 或 O(n × m)每行队列重建，滚动数组可压到 O(m)

空间按题目上限算：向右跳跃 n ≤ 2 × 10⁵，dp 与队列各一个 int 数组，约 1.6 MB；向下收集 n、m ≤ 4000，整表 1600 万个 int 约 64 MB，滚成两行就降到 O(m)。

队列写法的时间是摊还的：看起来有 while 循环，但每个下标一生只进一次、出一次，n 个下标总操作数是 O(n)。

七、总结

认这个结构的办法是看转移式：dp[i] 依赖 dp[j] 的最大值，j 的合法范围写成 [L(i), R(i)] 之后，L 和 R 都随 i 单调不减，那就可以上单调队列。两道题的 L、R 分别是 [i − b, i − a] 和 [j − t, j + t]，都是这个形状。

写的时候三件事别漏：到不了的位置不进队；过期只在队首判断一次；答案是「还能再跳一次」的位置集合，不是最后一格。

下一类题会麻烦一点：转移式里 j 和 i 缠在一起，得先做一次代数变形，把它们拆成「只含 j 的部分」加「只含 i 的部分」，才能套上同样的队列。
