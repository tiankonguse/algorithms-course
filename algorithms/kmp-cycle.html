循环节与反复删除

一个串由某个块反复拼成，最短的块有多长；一个串里每看见一次模式串就删掉，删到删不动还剩什么。前一个问题只看串自己，后一个问题边扫边删，落点却是同一张表：next 数组。把它算出来，之后每一步都只是查表退位。

零、最短循环节

题目给一个字符串 s，它一定由某个循环节不断自我复制拼成，至少重复 2 次，最后一段可能不完整，问这个循环节最短能有多短。

朴素做法是从块长 L = 1 开始试，检查 s[i] 与 s[i % L] 对每个 i 是否都相等，第一个通过的 L 就是答案。n = 106 时最坏要比较 n2 次，跑不完。

next 数组的最后一项 nxt[n] 是整串「最长的真前缀等于真后缀」的长度，也就是串首与串尾最长能重叠多少。拿它减一下就是答案：L = n − nxt[n]。

拿 "abcabcab" 试。n = 8，最长的重叠是前 5 个字符 "abcab" 与后 5 个字符 "abcab" 相同，nxt[8] = 5，答案 8 − 5 = 3，循环节就是 "abc"。

为什么减出来的这个 L 一定对？两个方向各说一句。

1）L = n − nxt[n] 是合法块长。设 k = nxt[n]，串首 k 个字符与串尾 k 个字符相同，也就是 s[i] = s[i + (n − k)] = s[i + L] 对所有 0 ≤ i < k 都成立。这条等式说的正是：把 s 按 L 切开首尾相接，接缝处的字符对得上，整串就是 s[0..L−1] 不断重复的前缀。

2）比 L 更短的块不存在。设 L′ 是某个合法块长，同样有 s[i] = s[i + L′]，于是前 n − L′ 个字符与后 n − L′ 个字符相同，nxt[n] 至少是 n − L′。把它代回去就得到 L′ ≥ n − nxt[n]。

两个方向一夹，答案只能等于 n − nxt[n]。

// s 下标从 0 起：nxt[i] 是 s[0..i-1] 里最长的「真前缀等于真后缀」长度
    void nextArray(const string& s, int n, vector<int>& nxt) {
        nxt.assign(n + 1, 0);
        nxt[0] = -1;
        nxt[1] = 0;
        int i = 2, cn = 0;
        while (i <= n) {
            if (s[i - 1] == s[cn]) {
                nxt[i++] = ++cn;
            } else if (cn > 0) {
                cn = nxt[cn];
            } else {
                nxt[i++] = 0;
            }
        }
    }

last 一项算出来，整题就剩一次减法。

// 整串的最长前后缀长度 nxt[n] 一旦拿到，答案就是 n - nxt[n]
    int minCycleLen(const string& s, int n) {
        vector<int> nxt;
        nextArray(s, n, nxt);
        return n - nxt[n];
    }

n = 106 的串跑一遍 next 数组在 1 毫秒上下：每 7 个字符一个块的周期串 0.7 毫秒，随机 0/1 串 4.7 毫秒。回退那一行看着像隐患，实际几乎不触发，"aaab" 循环 106 个字符只退了 2 次。

逐格求 next，再减出答案

每点一步填一格 nxt，右边的标注是这一步在比哪两个字符。切到两个错误版本，看答案在哪一步开始偏。

写的时候有两处容易错。

一，减法用的是 nxt[n]，不是 nxt[n−1]。nxt[n] 让长度 n 的前缀与长度 n 的后缀去重叠，nxt[n−1] 只重叠到长度 n−1，答案会偏大。随机周期串上这个错法有 99.12% 与正解不同。

二，cn = nxt[cn] 那一行不能省。省掉之后 next 数组记的不再是最长重叠，只是某一次能对上的长度，平时看不出问题（随机数据抓取率 2.75%），因为多数位置根本不需要回退，需要的时候就是真错。

一、反复删除

给定 s1 和 s2，只要 s1 里出现 s2 就删掉最左的这一次出现，删完剩下的字符重新拼接，再看有没有，如此反复，输出最后剩下的字符串。

朴素做法是一遍遍地查再删。看起来每次删除都在让串变短，开销却全在搬字符上：n = 106 的周期串删 2 个字符的模式，实测 3552 毫秒。

难点在于删除会让后面的字符和前面接上，接缝处可能拼出一个新的 s2。删一次之后要重新检查的位置不止被删掉的那一段，前后都要看。

要维护的状态只有一个：当前已经匹配上 s2 的前几个字符。扫 s1 时准备一个栈，每读一个字符 x：

1）它与 s2[y] 相等，就把 (x 的下标, y) 压栈，x 与 y 各自加一；

2）y 已经是 0 还对不上，说明这个字符连 s2 的首字符都不是，压一个 (x 的下标, −1) 进栈，x 加一；

3）其余情况沿 next 把 y 退一格再比，这个字符先不入栈。

y 涨到 m 时，栈顶刚压进去的 m 个字符正好拼出 s2，把它们一起弹掉，栈长度减 m。

弹出之后那个 y 从哪来？不能归零。栈顶现在记着前一个保留下来的字符当时匹配到 s2 的第几个位置，新的 y 就是它加一。回到图 3 的例子里，第一次弹出后栈顶是 s1[0] = 'b'，它的匹配位置是 0，于是 y 变成 1；下一个字符 'a' 正好对上 s2[1]，又拼出一个 "ba"。y 归零就拿不到这第二次匹配，最后会留下一个 "ba"，而正确答案是空串。

入栈时把「首字符都对不上」记成 −1 是同一件事的另一面：弹出后加一正好回到 0，表示从头开始比。三种写错方式在随机数据上的抓取率分别是 6.16%、6.03%、6.79%，数字都不高，可一旦发作就是把该删的漏掉了。

// 边匹配边入栈；删掉一次匹配的同时，把匹配位置接回栈顶记录的那一个
    string deleteLoop(const string& s1, const string& s2) {
        int n = s1.size(), m = s2.size();
        vector<int> nxt(m + 1, 0);
        nxt[0] = -1;
        if (m > 1) nxt[1] = 0;
        int i = 2, cn = 0;
        while (i < m) {
            if (s2[i - 1] == s2[cn]) nxt[i++] = ++cn;
            else if (cn > 0) cn = nxt[cn];
            else nxt[i++] = 0;
        }
        vector<int> keep1(n), keep2(n);
        int size = 0, x = 0, y = 0;
        while (x < n) {
            if (s1[x] == s2[y]) {
                keep1[size] = x;
                keep2[size] = y;
                size++;
                x++;
                y++;
            } else if (y == 0) {
                keep1[size] = x;
                keep2[size] = -1;
                size++;
                x++;
            } else {
                y = nxt[y];
            }
            if (y == m) {
                size -= m;
                y = size > 0 ? keep2[size - 1] + 1 : 0;
            }
        }
        string res;
        for (int k = 0; k < size; k++) res += s1[keep1[k]];
        return res;
    }

二、复杂度分析

做法关键操作时间空间
最短循环节，枚举块长每个 L 扫一遍整串O(n2)O(1)
最短循环节，next 数组一遍求 next 后做一次减法O(n)O(n)
反复删除，反复查再删每次删除都要搬动后面的字符O(n2 / m) 量级O(n)
反复删除，栈加 next每个字符压栈一次、弹出一次O(n + m)O(n + m)

求 next 的循环看着像两层，内层那次回退每次至少把 cn 减小 1，而 cn 一共只涨 n 次，所以整趟的回退总次数不超过 n。栈做法里每个字符恰好压栈一次、最多弹出一次，总操作数是 2n 量级。空间上两张 int 表跟着 n 走，n = 106 时各 4 MB。

总结

最短循环节的答案就是 n − nxt[n]，两个方向都能推出来：nxt[n] 保证按这个长度切开能首尾相接，而任何合法块长都会让 nxt[n] 至少到 n − L′。算的时候盯住 nxt[n] 这一项，别用 nxt[n−1]。

反复删除要把删除之后的影响接住。栈里同时存字符下标与它当时的匹配位置，弹出 m 个之后 y 取新栈顶记录加一；把首字符失配记成 −1，弹出后加一正好回到 0。

两题时间都是 O(n + m)，空间 O(n + m)。朴素做法在 n = 106 上分别是平方级和 3552 毫秒，换掉之后一次遍历就够。

把 next 当成一个转移函数之后，匹配这件事还能被塞进树上的路径与数位 dp 的状态里，代码骨架不用换。
