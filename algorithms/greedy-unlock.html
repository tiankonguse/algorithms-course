贪心：双堆解锁与差值闭包

一道题要在资本够得着的项目里挑利润最高的，一道题要反复把两数的差值塞进数组，塞到塞不动为止。两道题都不像排队问题，却都在做同一件事：先把手里能用的东西攥住，等条件变好了再回头补。

零、能做的和想做的

先看第一题。有 n 个项目，第 i 个有纯利润 profits[i] 和启动资金 capital[i]。你手上最初有 w 块钱，做完一个项目就把它的利润拿到手，资本变大，于是可能有新项目变得做得起。最多做 k 个不同项目，求最终资本最多是多少。

拿一组数据走一遍：k=2、w=0、profit=[1,2,3]、capital=[0,1,1]。

一开始资本是 0，只有门槛为 0 的那个项目做得起，做完拿到 1，资本变成 1。这一步之后，门槛是 1 的两个项目同时解锁，挑利润 3 的那个做，最终资本是 4。

这里藏着一个容易忽略的顺序：利润最高的项目往往一开始做不了。所以每一步都得分两件事：先把新够得着的项目捞出来，再从捞出来的里面挑利润最高的。

一、两个堆分工

第一个堆按启动资本放小根堆，堆顶是「最容易解锁」的那个项目。

第二个堆按纯利润放大根堆，堆顶是「解锁之后最值得做」的那个。

每一轮做三件事：把锁住的堆顶里资本门槛不高于当前 w 的全部搬进利润堆；利润堆空了就停，说明没有项目做得起了；否则弹出利润堆顶做掉，w 加上它的利润，k 减一。

为什么每轮挑「做得起的里面利润最大的」不会错过更好的结果？

关键在于做得起这件事只跟资本有关，而资本只增不减。先做哪个项目，都不会让别的项目变得做不起。所以顺序的选择不影响「哪些项目最终能做」，那就每一轮都拿当前回报最高的。

反过来说，顺序颠倒就会出错。假如不看资本门槛、直接挑利润最大的项目做，第一步就会去碰一个做不起的项目。实测这个错法在随机数据上的抓取率是 29.08%；换成「每次都挑启动资本最低的」也有 26.54%。

// IPO：最多做 k 个项目，初始资本 w，做完项目拿到纯利润
    // 两个堆分工：锁住的项目按启动资本排队，解锁的项目按利润排队
    int findMaximizedCapital(int k, int w, vector<int>& profit, vector<int>& cost) {
        int n = profit.size();
        // 启动资本小根堆：还没做的项目，资本最小的在堆顶
        priority_queue<pair<int, int>, vector<pair<int, int>>, greater<pair<int, int>>> locked;
        // 利润大根堆：已经做得起的项目，利润最高的在堆顶
        priority_queue<int> unlocked;
        for (int i = 0; i < n; i++) {
            locked.push({cost[i], profit[i]});
        }
        while (k > 0) {
            while (!locked.empty() && locked.top().first <= w) {
                unlocked.push(locked.top().second);
                locked.pop();
            }
            if (unlocked.empty()) {
                break;
            }
            w += unlocked.top();
            unlocked.pop();
            k--;
        }
        return w;
    }

二、第二题：反复加差值

给一个非负数组。每一轮，把所有两两之间的差值取绝对值，凡是数组里还没有的，都加进去，每个值只加一份。然后对新的数组继续做同样的事，直到数组大小不再变化。返回最终的长度。

这题连「选哪个」都没有，它是问一个过程什么时候停。先照题面走一遍 arr = [4,10]。

差值是 6，加进去得到 {4,6,10}；再算差值出现 2、4、8，其中 2 和 8 是新的，加进去得到 {2,4,6,8,10}；再算一遍，所有差值都已经在里面了，停下。最终长度 5。

照着题面一轮一轮加当然能算出来，但每一轮都要把所有元素两两配一次，元素一多就很重。看一组极端数据：arr = [1, 1000000]，最终集合是 1 到 1000000 全部整数，长度 106，可暴力做法要比较约 5×1011 对。

好在最终集合的形状是可以直接写出来的。

三、最终集合就是一张倍数表

记数组里所有正数的最大公约数为 g，最大值为 mx，有两个方向的观察：

1）一开始每个数都是 g 的倍数，而两个 g 的倍数的差还是 g 的倍数，所以新加进来的数也全是 g 的倍数。也就是说，最终集合里的正数只可能是 g 的倍数。

2）反过来，能凑出来的最小正数就是 g（它是所有正数的最大公约数），而从 g 出发反复做差，可以把 g 的每个倍数都凑出来。所以 g 到 mx 之间的每个 g 的倍数都会出现。

两头一夹，最终集合的正数部分就是 {g, 2g, 3g, …, mx}，一共 mx/g 个。这一段的计算是 O(1) 的，不用真的去加。

答案要比 mx/g 多一些，还有两处要补。

四、重复值和 0 要单独算

题面说的是往数组里加，不是往集合里加。原数组里出现多次的值会一直留在里面，所以每个值出现 c 次，就比只留一份多出 c−1 个位置。

另一个是 0。两个相等的数差值就是 0，所以只要数组里有重复值，0 一定会被加进来；如果 0 本来就在数组里，那它早就占好位置了。不管哪种情况，0 都不在 {g, …, mx} 这一段里，得单独数。

核对几组：[6,9] 是 3（{3,6,9}）；[4,10] 是 5；[0,7,7] 是 1 + 1 + 1 = 3；[5,5] 是 1 + 1 + 1 = 3，这里的 0 是重复值自己造出来的；[8,12] 是 3。

还有一组要单独兜：全是 0 的时候，最大公约数求不出来（0 不能参与），直接返回原数组长度，[0,0] 就是 2。

int gcd(int m, int n) {
        return n == 0 ? m : gcd(n, m % n);
    }

    // 加入差值绝对值直到长度固定：返回数组最终的长度
    // 结论：所有正数的最大公约数是 g，最大值是 mx，最终一定会凑出 {g, 2g, ..., mx}
    // 再去数重复值和 0 各自占了几格
    int len(vector<int>& arr) {
        int mx = 0;
        int g = 0;
        for (int i = 0; i < (int)arr.size(); i++) {
            mx = max(mx, arr[i]);
            if (arr[i] != 0) {
                g = arr[i];
            }
        }
        if (g == 0) {
            return arr.size();
        }
        map<int, int> cnts;
        for (int i = 0; i < (int)arr.size(); i++) {
            if (arr[i] != 0) {
                g = gcd(g, arr[i]);
            }
            cnts[arr[i]]++;
        }
        int ans = mx / g;
        int maxCnt = 0;
        for (map<int, int>::iterator it = cnts.begin(); it != cnts.end(); it++) {
            if (it->first != 0) {
                ans += it->second - 1;
            }
            maxCnt = max(maxCnt, it->second);
        }
        map<int, int>::iterator zero = cnts.find(0);
        ans += zero != cnts.end() ? zero->second : (maxCnt > 1 ? 1 : 0);
        return ans;
    }

每一轮都盯着「本轮解锁」这一栏：它列出来的项目，才是这一轮有资格竞争的。

演示 B　差值一轮一轮加下去

绿色的数字是这一轮新加进来的。走到底之后再看答案行，手算出来的长度和公式给的长度是同一个数。

六、对数器怎么抓错

项目那题 5000 组随机数据（n ≤ 7，k ≤ 7）：

做法抓取比例
完全不看资本门槛，直接挑利润最大的 k 个29.08%
每次都挑启动资本最低的26.54%
按利润从高到低排，挑第一个做得起的0.00%

最后一行值得单独说：它其实就是同一个贪心的另一种写法，把「解锁」和「挑最大」合成一步，按利润降序扫，第一个资本够得着的就是这一轮该做的项目。5000 组里答案一次没差，两种写法等价，用堆只是跑得快些。

差值那题，n ≤ 8、值域 0 到 11 的 5000 组：

错法抓取比例
只返回 mx/g，不管重复值和 062.94%
一律返回 mx/g + 187.78%

第二个错法错得更狠，因为数组里没有重复值时 0 根本不会出现（[6,9] 就是 3 而不是 4）。这也说明这题的边界不在数值大小，而在数组里有没有重复值。

复杂度分析

题目关键操作时间空间
项目解锁每个项目进出两个堆各一次，最多 k 次取堆顶O(n log n + k log n)O(n)，两个堆
差值闭包扫一遍求最大值和最大公约数 + 数重复O(n log mx)O(n)，计数表

项目那题的堆操作次数是死的：每个项目只会从锁住的堆搬进利润堆一次，也只会被弹出一次，所以总次数和 k 无关。n=105、k=105 实测 10.27ms。

差值那题的每次取余都来自辗转相除，摊下来的代价是 O(log mx)。同一个输入规模下，暴力做法 2 万组要 517.38ms，写成公式只要 66.82ms，而且元素越多、倍数表越长，差距越大。

总结

两题都没有排序，但都在回答「现在该动哪一个」。项目那题把项目分成两拨，够得着才进候选，候选里挑利润最高的，靠的是资本只增不减；差值那题干脆没有选择，它问的是过程什么时候停，答案落在最大公约数上：最终集合一定是 {g, …, mx} 这张倍数表。

处理这类题有两个习惯值得记住。一个是先分清「手里的」和「想要的」，中间那道门槛要单独维护；另一个是遇到反复迭代的过程，先别急着模拟，看看最终形态能不能直接写出来。
