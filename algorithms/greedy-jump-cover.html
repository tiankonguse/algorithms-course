贪心：一步之内能走到哪

一道题在数组上跳，一道题让水龙头往两边浇水。两题的骨架是同一个：cur 是这一层能到的最右位置，next 是再多一层能到的最右位置，扫到越界就记一次数。

零、两道题各自要什么

第一题：给一个整数数组 nums，站在 0 下标，nums[i] 表示能从 i 往右跳的最大距离。求跳到 n-1 的最少跳跃次数，数据保证到得了。

第二题：花园是实轴上从 0 到 n 的一段，水龙头一共有 n+1 个，第 i 个在坐标 i 上，打开后浇的范围是 [i - ranges[i], i + ranges[i]]。求盖满整段花园的最少水龙头数目，盖不满返回 -1。

两题都在一条线上从 0 往右推进，每一步想要的都是「再往前一步能到的最远处」。差别只在开始之前要不要先把数据收拾一遍。

一、跳跃游戏 II：cur 和 next 两条边界

先看慢办法。想知道每个位置的最少步数，可以从每个位置往它够得到的地方推：dp[j] = min(dp[j], dp[i] + 1)，j 取遍 [i, i + nums[i]]。这是 O(n2)。

换个角度：跳 k 步能到达的是一段连续的下标区间。第 0 步是 [0, 0]，就在起点站着；第 1 步是 [0, nums[0]]；再往后，每一层的右端点是「上一层区间里所有位置各自能跳到的最远处」中的最大值。

于是只需要两个数。cur 是当前步数以内的最右位置，next 是再多一步能到的最右位置。从左往右扫一遍 i：先把 next 更新成 max(next, i + nums[i])，再看 i 有没有超过 cur。超过了就说明 i 这个位置在 cur 步以内到不了，得多跳一步，步数加一、cur 推到 next。

这里有个细节：更新 next 要放在判断之前。cur 上那个位置本身也是这一层的成员，它的 nums[i] 同样能用来扩 next，放到后面就漏了它。

拿 [2,3,1,1,4] 走一遍。i=0 时 next 变成 2，此时 i 追上 cur=0，步数记 1、cur 变成 2。i=1 时 next 变成 max(2, 1+3) = 4。i=2 时 next 不变。i=3 时 i 超过 cur=2，步数记 2、cur 变成 4。i=4 时 next 变成 8，扫完了，答案是 2。

// 跳跃游戏 II：从 0 下标出发，nums[i] 是能从 i 往右跳的最大距离，求跳到 n-1 的最少次数
    // cur 是当前步数以内能到的最右位置，next 是再多一步能到的最右位置
    // 走到 i 发现 i 已经超出 cur，就说明必须多跳一步，此时把 cur 推到 next
    int minJumps(vector<int> arr) {
        int n = arr.size();
        int cur = 0;
        int next = 0;
        int ans = 0;
        for (int i = 0; i < n; i++) {
            if (cur < i) {
                ans++;
                cur = next;
            }
            next = max(next, i + arr[i]);
        }
        return ans;
    }

每一层只走一步，这就是「当前状态下最好的选择」：还在这一层里不用额外跳，跨过边界才记账。实测 n = 106、每个位置随机 1 到 5，答案是 290152，跑完 1.20ms。

二、灌溉花园：先把水龙头按左边界归拢

直接想「打开哪几根水龙头」会很乱：同一段范围可能有好几根都能浇到，选哪根是一堆组合。把选择推迟到扫描的时候再做，先只留下一张表。

记 right[l] 表示所有左边界恰好是 l 的水龙头里，右端点的最大值。左边界算的是 max(0, i - ranges[i])，花园从 0 开始，浇到负数没有意义；右端点不用截断，超过 n 只是多浇了一点。

有了这张表就是上一节的扫描：i 从 0 走到 n-1，next = max(next, right[i])，i 撞上 cur 就把 cur 推到 next 并记一次数。左边界到 i 的水龙头，才有资格接上当前这层覆盖。

断开的情况也在这个骨架里：i 等于 cur，而 next 没有比 i 更远，说明 [0, i] 已经是能盖到的极限，右边接不上，直接返回 -1。

这里有个细节：花园是实轴上连续的一段，判定断开看的是下一段能不能接上，整数点被盖住并不代表接上了。[0,1,2,0,0,0,0,2] 这组 ranges 里，第 2 根浇 [0,4]、第 7 根浇 [5,7]，0 到 7 每个整数点都有着落，可是 (4,5) 那段空着，正确答案是 -1。

// 灌溉花园的最少水龙头数目：水龙头 i 灌溉 [i - ranges[i], i + ranges[i]]，求盖满 [0, n] 的最少个数
    // right[i] 记下所有左边界在 i 的水龙头里最远能盖到哪，左边界到了才能接上现在的覆盖范围
    // 一路往右扫，扫到盖不满的位置说明中间断开，返回 -1
    int minTaps(int n, vector<int> ranges) {
        vector<int> right(n + 1, 0);
        for (int i = 0, start; i <= n; i++) {
            start = max(0, i - ranges[i]);
            right[start] = max(right[start], i + ranges[i]);
        }
        int cur = 0;
        int next = 0;
        int ans = 0;
        for (int i = 0; i < n; i++) {
            next = max(next, right[i]);
            if (i == cur) {
                if (next > i) {
                    cur = next;
                    ans++;
                } else {
                    return -1;
                }
            }
        }
        return ans;
    }

实测 n = 106、每个水龙头半径在 0 到 5000 之间随机，答案是 102，跑完 3.07ms。两趟扫描都是线性的，代价大头在把 n+1 根水龙头摊进表里。

四、对数器怎么抓错

两题的暴力都好写。跳跃题的暴力按位置推 dp；水龙头题的暴力枚举所有子集，把区间排序合并起来看能不能连成 [0, n]，所以它天然认得出图 2 那种「整数点都盖住、中间却空着」的情况。

题目写法随机数据出错比例
跳跃游戏 II每步只跳到 i + nums[i] 那个位置，不看整层12.31%
跳跃游戏 II边界判断写成 cur ≤ i100.00%
灌溉花园断开判断写成 next ≥ i6.63%（小值域、n ≤ 30 时 42.84%）
灌溉花园同一左边界只留最后写进去的那一根0.64%（小值域时 0.00%）
灌溉花园右端点也截断到 n0.00%

跳跃题两万组随机数据，数组长 2 到 12、每个位置 1 到 5；水龙头题二十万组，n 取 1 到 10、半径 0 到 3，另有一组 n ≤ 30、半径 0 到 2 作对照。

cur ≤ i 那个写法每次都错。站在 cur 上的位置本来就已经到了，不需要再跳一步，所以只要 n 大于 1 就会多算一次。反过来，把右端点截断到 n 完全测不出来：答案只关心有没有盖到 n，盖过头的部分本来就用不上，改不改都一样。

「同一左边界只留最后一根」在小半径数据上抓不到。半径都在 0 到 3 之间时，左边界相同的几根水龙头半径常常也一样，留哪根都没差别，半径拉大之后才开始出错。

复杂度分析

题目关键操作时间空间
跳跃游戏 II一趟扫描，每个位置两次比较O(n)O(1)
灌溉花园摊一张 right 表 + 一趟扫描O(n)O(n)

跳跃题只用三个整数变量，除输入数组本身不额外占空间；水龙头题的 right 表长度是 n+1，扫描过程本身是常数空间。两题都没有排序和二分，实测 n = 106 分别是 1.20ms 和 3.07ms。

总结

两题共用一个骨架：cur 是这一层能到的最右位置，next 是下一层能到的最右位置。扫到 i 超过 cur 就跨层，步数加一、cur 推到 next；更新 next 必须放在判断之前，否则会漏掉边界位置上那一跳。

跳跃题的每一层由 nums 直接给出来；水龙头题先按左边界归拢出一张「每个左边界最远能到哪」的表，再套同一个骨架。归拢这一步是有用的，同一个左边界上的水龙头，只有右端点最远的那根值得留。

两题的失败信号都是「推不动了」：水龙头题里 i 撞上 cur 而 next 没有更远，说明覆盖断在 i 到 i+1 之间。花园是连续的一段，别拿整数点有没有被盖住代替接得上接不上。
