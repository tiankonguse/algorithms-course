整体二分：原理与两种写法

一堆查询都在问「第 k 小」「第几轮之后达标」，每条查询各自二分答案太慢。整体二分把它们放到一起分：一轮操作做完，所有查询共享这个局面，达标的往左走、不达标的往右走，各自递归下去。这一页讲原理、两种写法和第一道模版题。

零、背景

前置只有两样：二分答案法，一维树状数组。整体二分就是「二分答案」的批量版本，判定时用的数据结构还是树状数组那一套。

本讲是整体二分的上半节，讲清原理、两种常见写法，以及三道模版题：区间内第 k 小、矩阵内第 k 小、陨石雨。下一节再把它和别的内容结合起来用。

三道题用的树状数组形态各不相同：题目 1 是单点修改、范围查询；题目 2 换成二维；题目 3 反过来，范围修改、单点查询。这一页覆盖原理、两种写法和题目 1，后两道题各占一页。

一、题目1：区间内第 k 小

给定一个长度为 n 的数组，接下来有 m 条查询，格式如下。

  • 查询 l r k：打印 [l..r] 范围内第 k 小的值。

1 ≤ n、m ≤ 2 × 10⁵，1 ≤ 数组中的数字 ≤ 10⁹。测试链接：洛谷 P3834。这题也是可持久化线段树的模版题，这里换一条路走。

二、朴素做法为什么慢

一条查询二分答案的做法是这样：猜一个值 mid，扫一遍 [l..r] 数出 ≤ mid 的个数，个数不少于 k 说明答案还能更小，往左走；否则往右走。值离散化之后有 n 个候选，二分 log n 轮，每轮扫整个区间。

单条查询 O(n log n)，m 条就是 O(n·m·log n)，n 和 m 都在 2 × 10⁵ 时直接超时。主席树能把单条压到 O(log n)，代价是多开 n log n 个结点。

可以发现浪费的地方：m 条查询在同一个数组上做同样的二分，每次都从头扫一遍。左右走向不同的查询，本来可以在同一轮扫描里一起判定。

三、整体二分的思路

先说清楚什么样的题能用它。应用场景是这四条。

  1. 单个问题的答案具有单调性。答案固定时，要求可能得到满足，也可能得不到满足。
  2. 要求得到满足时，答案变差依然满足，此时去找更好的答案。
  3. 要求无法满足时，答案变好也无法满足，此时去找更差的答案。
  4. 问题数量较多，没法对每个问题都跑一次二分答案，但所有查询允许离线处理。

基本思想对应的也是三条：让修改操作适配当前的答案范围，把局面调好之后再看每个查询达不达标；多个查询共享这一轮的修改操作，避免重复劳动；达标的问题去左组，不达标的问题去右组，左右分别递归，直到所有问题解决。

因此整体二分的形状是：一层里所有查询看同一个局面，局面由「答案范围左半对应的那些操作」构成。层数只有 log n 层，每层每条查询只被检查一次。

四、标准过程

写成一个递归 compute(ql, qr, vl, vr)：当前这批问题用 [ql..qr] 表示，这批问题的答案落在 [vl..vr] 上。答案范围上的每个位置，背后都对应着一组修改局面的操作。

过程一共九步。前两步是边界，中间四步是核心，最后三步是递归。

第 4 步里有个细节：不达标的问题不是空着手进右组。它在这一轮已经拿到了 satisfy 个贡献，进入右组之后看到的局面不含这部分，所以要把要求的 k 减掉 satisfy。写不写这一步，正是下面两种写法的分界线。

五、写法一：范围操作 + 撤销

题目 1 里，「答案范围上的一个位置」就是排序后的第 i 个数，「对应的操作」是把它按原下标放进树状数组，add(arr[i].i, 1)。执行 [vl..mid] 上的操作，就是把这一段的数都放进去。

查询的判定是数 [l..r] 里已经放进去几个：satisfy = query(l, r)。达标（satisfy ≥ k）说明第 k 小不超过 arr[mid].v，去左组；否则 k 减去 satisfy，去右组。

注意进出对称：进入时把 [vl..mid] 加进去，划分完之后原样减掉，交还给上一层时局面没变。这样每一层的检查都只看自己那半边的贡献，所以 k 必须减。

    
#include <bits/stdc++.h>

    using namespace std;

    struct Number {
        int i, v;
    };

    bool NumberCmp(Number x, Number y) {
        return x.v < y.v;
    }

    const int MAXN = 200001;
    int n, m;

    Number arr[MAXN];

    int qid[MAXN];
    int l[MAXN];
    int r[MAXN];
    int k[MAXN];

    int tree[MAXN];

    int lset[MAXN];
    int rset[MAXN];

    int ans[MAXN];

    int lowbit(int i) {
        return i & -i;
    }

    void add(int i, int v) {
        while (i <= n) {
            tree[i] += v;
            i += lowbit(i);
        }
    }

    int sum(int i) {
        int ret = 0;
        while (i > 0) {
            ret += tree[i];
            i -= lowbit(i);
        }
        return ret;
    }

    int query(int l, int r) {
        return sum(r) - sum(l - 1);
    }

    void compute(int ql, int qr, int vl, int vr) {
        if (ql > qr) {
            return;
        }
        if (vl == vr) {
            for (int i = ql; i <= qr; i++) {
                ans[qid[i]] = arr[vl].v;
            }
        } else {
            int mid = (vl + vr) >> 1;
            for (int i = vl; i <= mid; i++) {
                add(arr[i].i, 1);
            }
            int lsiz = 0, rsiz = 0;
            for (int i = ql; i <= qr; i++) {
                int id = qid[i];
                int satisfy = query(l[id], r[id]);
                if (satisfy >= k[id]) {
                    lset[++lsiz] = id;
                } else {
                    k[id] -= satisfy;
                    rset[++rsiz] = id;
                }
            }
            for (int i = 1; i <= lsiz; i++) {
                qid[ql + i - 1] = lset[i];
            }
            for (int i = 1; i <= rsiz; i++) {
                qid[ql + lsiz + i - 1] = rset[i];
            }
            for (int i = vl; i <= mid; i++) {
                add(arr[i].i, -1);
            }
            compute(ql, ql + lsiz - 1, vl, mid);
            compute(ql + lsiz, qr, mid + 1, vr);
        }
    }

    int main() {
        ios::sync_with_stdio(false);
        cin.tie(nullptr);
        cin >> n >> m;
        for (int i = 1; i <= n; i++) {
            arr[i].i = i;
            cin >> arr[i].v;
        }
        for (int i = 1; i <= m; i++) {
            qid[i] = i;
            cin >> l[i] >> r[i] >> k[i];
        }
        sort(arr + 1, arr + n + 1, NumberCmp);
        compute(1, m, 1, n);
        for (int i = 1; i <= m; i++) {
            cout << ans[i] << '\n';
        }
        return 0;
    }

排序之后 arr[i].v 就是第 i 小的候选值，vl == vr 时直接写 ans[qid[i]] = arr[vl].v。qid 是「当前这批问题的编号列表」，划分后就地重排成左组在前、右组在后，递归只需要 ql、qr 两个端点。

六、写法二：指针滚动

写法一每一层都要正着加一遍、反着减一遍。改法很直接：别撤销，用一个全局指针 used 表示「当前树状数组里放了排序后的前 used 个数」，进入 compute 时把 used 挪到 mid。

挪动的方式是：used 小于 mid 就往后加，大于 mid 就往前撤。检查完之后不撤销，递归交给子调用自己挪。左递归想把 used 挪小，右递归想把 used 挪大，各自挪各自的。

写法二里 k 全程不变，代码比写法一少一行。判别用的计数是「前缀里有多少个数落在 [l..r]」，随着 used 增大单调不减，二分的前提仍然成立。

下面只贴和写法一不同的部分：used 的声明和 compute 函数，其余完全一样。

    
int used = 0;

    void compute(int ql, int qr, int vl, int vr) {
        if (ql > qr) {
            return;
        }
        if (vl == vr) {
            for (int i = ql; i <= qr; i++) {
                ans[qid[i]] = arr[vl].v;
            }
        } else {
            int mid = (vl + vr) / 2;
            while (used < mid) {
                used++;
                add(arr[used].i, 1);
            }
            while (used > mid) {
                add(arr[used].i, -1);
                used--;
            }
            int lsiz = 0, rsiz = 0;
            for (int i = ql; i <= qr; i++) {
                int id = qid[i];
                int satisfy = query(l[id], r[id]);
                if (satisfy >= k[id]) {
                    lset[++lsiz] = id;
                } else {
                    rset[++rsiz] = id;
                }
            }
            for (int i = 1; i <= lsiz; i++) {
                qid[ql + i - 1] = lset[i];
            }
            for (int i = 1; i <= rsiz; i++) {
                qid[ql + lsiz + i - 1] = rset[i];
            }
            compute(ql, ql + lsiz - 1, vl, mid);
            compute(ql + lsiz, qr, mid + 1, vr);
        }
    }

两种写法怎么选。写法一的每一层是封闭的：进去加、出来撤，只要操作能成对地正着做和反着做，就能套进来，改成别的数据结构也不用动递归框架。写法二少掉了每层的一遍加法，常数更小，代价是要求局面能「整体前移和后移」，而且树状数组里存的是前缀而不是当前层那一段。三道题两种写法都能写，后面两页会把两份代码都给出来。

七、演示：题目1 的递归全过程

数组 [4, 2, 6, 1, 5, 3]，四条查询：Q1 [1,6] k=3、Q2 [2,4] k=2、Q3 [1,3] k=2、Q4 [3,6] k=1。用写法一跑一遍，看每一层加了什么、每条查询数出多少、往哪边走。

整体二分：一层一层把查询分开

点「下一步」逐步执行：加入 [vl..mid] 的数 → 逐条检查 → 划分成左右组 → 撤销 → 递归。

八、复杂度分析

设答案范围大小为 n（离散化后的候选个数），查询数量为 m，单次修改或查询的代价记为 T。题目 1 里 T = O(log n)，题目 2 是 O(log² n)，题目 3 是 O(log n)。

递归一共 log n 层。同一层里所有节点的答案范围互不重叠，写法一在每个节点上加的区间长度加起来不超过 n，撤销再乘一个常数，所以每层修改的总次数是 O(n)；写法二的指针在一层里左右挪动的总距离也是 O(n) 量级。每层的查询检查次数是 O(m)，每条查询在每一层只被检查一次。

操作时间复杂度空间复杂度
按值排序、建立「值 ↔ 原下标」的对应O(n log n)O(n + m)：排序后的数组、查询数组、左右组的暂存数组各一份，树状数组 O(n)
一层的全部修改操作（写法一加一遍撤一遍 / 写法二挪指针）O(n · T)
一层的全部查询检查（每条查询恰好一次）O(m · T)
递归层数O(log n)
题目1 总代价（T = O(log n)）O((n + m) log n log n)

n 和 m 都在 2 × 10⁵ 时，整体二分大约是 (4 × 10⁵) × 18 × 18 ≈ 1.3 × 10⁸ 次基本操作，树状数组的常数很小，可以通过。

九、最后

整体二分就一句话：把「每条查询各自二分」摊成「所有查询一起分」。[vl..mid] 上的操作做一次，全部查询共用，达标往左、不达标往右，log n 层之后每个查询落到唯一一个值上。
