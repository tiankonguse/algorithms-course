贪心：拆数的最大乘积

一根长 n 的竹子砍成若干段，怎么砍乘积最大？如果规定必须砍成 k 段呢？第一题的答案是「能砍 3 就砍 3」，第二题的答案是「尽量平均」。两个答案看着不一样，其实都在回答同一个问题：怎么分，乘积才大。

零、先从小数字看起

给一根长为 n 的竹子，砍成若干段，每段长度都是正整数，求各段长度乘积的最大值。要求至少砍成两段。

把所有砍法枚举一遍当然可以，但 n 稍微大一点就撑不住了：n=10 的写法有 512 种，n=30 是 5.4 亿种，题目里 n 最大到 1000。这条路走不通。

那就先手算几个小的。

规律很扎眼：拆出来的段几乎全是 3，偶尔出现一个 2 或者两个 2。

一、3 这个长度特别划算

先不看总和是多少，只问一句：一段长度为 x 的材料，每单位长度能换来多少乘积？把 x 拆成 m 段等长，乘积是 (x/m)m，每单位贡献 x1/x。这个数和 n 没关系，只跟段长有关。

2 是 1.41421，3 是 1.44225，4 又掉回 1.41421，往后一路走低：5 是 1.37973，6 是 1.34801，10 只剩 1.25893。3 是这一排里最高的。

还有两条能砍掉候选长度：

1）长度 1 纯属浪费。把 1 并到相邻那段上，乘积从 x×1 变成 x+1，只会变大。

2）长度 4 不必单独出现。4 = 2+2，乘积还是 4，所以段长永远不用取 4。

可选长度只剩 2 和 3，而 3 每单位更值钱，所以能砍 3 就砍 3。这个结论就是全部的贪心思路。

二、余数是 1 的时候要拐个弯

把结论落到计算上，看 n 除以 3 的余数：

余 0，全是 3，乘积 3n/3。

余 2，先留一个 2，剩下全是 3。

余 1，这里有个坑。如果按「留一个 1，剩下全是 3」算，那个 1 就白扔了。正确做法是拿一个 3 出来和它凑成 2×2，也就是留下一段 4。比较一下就知道：3×1 = 3 < 4 = 2×2。

所以代码里先算一个尾巴长度 tail：余 0 时取 1（这个 1 表示「没有尾巴」，份数就是 n/3），余 1 时取 4，余 2 时取 2；3 的个数是 (n - tail)/3。

n=2 和 n=3 要单独兜一下。绳子必须至少砍一刀，2 只能 1+1（乘积 1），3 只能 1+2（乘积 2）；按上面的规则算 n=3 会得到 3，那是没砍的结果。

乘积会很快超出整数范围。n=1000 时答案是 3332×4，这个整数有 160 位十进制数字，long long 也装不下。题目要求答案对 1000000007 取模，于是乘法得边乘边取余。

取余这件事顺手也能提速：指数 332 逐次乘要 332 次乘法，快速幂 9 轮、12 次乘法就够了；指数到一百万时（后一题真会出现），逐次乘一百万次，快速幂只要 20 轮、26 次。

// 快速幂：求 x 的 n 次方再对 mod 取余，每一步都取余，中间结果不会溢出
    long long power(long long x, long long n, long long mod) {
        long long ans = 1;
        while (n > 0) {
            if (n & 1) {
                ans = ans * x % mod;
            }
            x = x * x % mod;
            n >>= 1;
        }
        return ans;
    }

    // 砍竹子 II：长 n 的竹子砍成若干段，每段长度都是正整数，求各段乘积的最大值 % (10^9+7)
    int cuttingBamboo(int n) {
        if (n == 2) {
            return 1;
        }
        if (n == 3) {
            return 2;
        }
        long long mod = 1000000007;
        // n % 3 == 0 : 3 * 3 * ... 全是 3
        // n % 3 == 2 : 3 * 3 * ... * 2
        // n % 3 == 1 : 留下一个 3 配 1，换成 2 * 2，其余还是 3
        int tail = n % 3 == 0 ? 1 : (n % 3 == 1 ? 4 : 2);
        int cnt = (tail == 1 ? n : n - tail) / 3;
        return (int)(power(3, cnt, mod) * tail % mod);
    }

三、份数被定死，就尽量平均

第二题换了个限制：数字 n 一定要分成 k 份，每份都是正整数，乘积最大是多少。n 和 k 能到 1012。

答案和上一题不一样了。假设定了只分两份，和是 11，怎么分乘积最大？

1×10 只有 10，2×9 是 18，3×8 是 24，4×7 是 28，5×6 是 30。越平均越大。原因也不难写出来：两份的和固定，x×y = ((x+y)2 − (x−y)2)/4，差值越大减掉的越多。

推广到 k 份，记 a = n/k、b = n%k，那就是 b 份拿 a+1，剩下 k−b 份拿 a。份数自由时那个「能砍 3 就砍 3」在这里不再适用，因为份数已经不许你动了。

拿 n=11 走一遍所有份数，两个答案的关系就清楚了。

k=1 是 11（不拆），k=2 是 30，k=3 是 48（4×4×3），k=4 是 54（3×3×3×2），k=5 是 48，k=6 是 32。份数自由那题的答案是 54，正好是 k=4 这一格。

再看两个大的。n=1012、k=106：a=106、b=0，答案是 106 的 106 次方取模，等于 493118025。n=1012、k=999999999999：a=1、b=1，只有一份是 2，其余全是 1，答案就是 2。

两个快速幂，一次除法，就完事了。

// 一个数字 n 一定要分成 k 份，每份都是正整数，返回最大乘积 % (10^9+7)
    // n 和 k 都能到 10^12，所以只用除法算出「有几份是多 1 的」，其余靠快速幂
    int maxValue(long long n, long long k) {
        long long mod = 1000000007;
        long long a = n / k;
        long long b = n % k;
        long long part1 = power(a + 1, b, mod);
        long long part2 = power(a, k - b, mod);
        return (int)(part1 * part2 % mod);
    }

五、对数器怎么抓错

第二题没有在线测试，只能自己造几个错法，拿随机数据比一遍，看错法被抓住的比例。

分 k 份这题，1 ≤ k ≤ n ≤ 60 一共 1830 组：

错法抓出来的组数比例
k−1 份都给 1，剩下全给最后一份1653 / 183090.33%
每份取 n/k，余数丢掉1569 / 183085.74%
余数全塞进其中一份1379 / 183075.36%

砍竹子那边，n 从 4 到 1000 一共 997 个数：

错法抓出来的个数比例
一味拆成 2994 / 99799.70%
余数是 1 时也留下一个 1333 / 99733.40%

「一味拆 2」漏掉的那 3 个是 n=4、5、7：4=2×2、5=3×2、7=3×2×2，这三种情况下拆 2 恰好也对。

33.40% 看着不高，其实 333 正好是这 997 个数里 n%3==1 的个数。余数是 1 的每一个 n 都被抓住了，一个没漏；基数小只是因为余数不是 1 的时候两个答案本来就相同。

复杂度分析

题目关键操作时间空间
砍竹子 II一次快速幂（指数约 n/3）O(log n)，n=1000 时 9 轮O(1)
分成 k 份两次快速幂（指数到 k）O(log k)O(1)

空间都是常数级：快速幂只维护底数、答案和指数三个变量。分成 k 份那题连数组都不用开，除法直接给出 a 和 b。

如果不用快速幂而是一次次乘，时间是 O(n) 和 O(k)；题目把 n、k 放到 1012 就是为了逼出快速幂，同时顺便说明了取模下必须边乘边取余。

总结

两题的骨架都落在「每单位长度值多少」这一句话上。份数自由时比的是 x1/x，3 赢，于是整根竹子几乎全是 3，只在余数为 1 时把 3+1 换成 2+2；份数定死时比的是均衡度，和固定时越平均乘积越大，于是 b 份拿 a+1、其余拿 a。

取模题的两个习惯也顺手确认了：乘法边乘边取余，幂次用快速幂。下一类贪心题不拆数了，改成在一堆带时间的区间里挑取舍，思路依然来自一次交换论证。
