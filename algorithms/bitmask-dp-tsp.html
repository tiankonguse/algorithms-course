状压 dp：售货员的难题（TSP）

n 个村子，从 1 号村出发，每个村恰好去一次，最后回到 1 号村，求最短路程。这条路要枚举的话是 (n−1)! 种走法。n = 20 时这个数有一亿亿量级，但状态压缩之后只要 2n × n 个状态。

零、只记「走了几个村」是不够的

最直接的动态规划想法是让状态记「已经走了几个村」。立刻会撞墙：走了两个村的路，可能是 1 → 3 → 2，也可能是 1 → 5 → 4。这两个状态记的都是「2 个」，但接下来能去哪些村、还要多少路，完全不一样。

所以状态里必须记住「走过哪些村」，光记一个数量不够。这正是状压的地方：把村庄集合压进一个整数的二进制位。

一、状态是（集合，当前村）

状态记两个量：s 是已经走过的村庄集合，第 i 位为 1 表示第 i 个村走过；i 是现在停在哪个村。因为「已经走过哪些」和「此刻在哪」共同决定接下来怎么走。

f(s, i) 的含义是：走过 s 这些村、现在停在 i，把剩下的村走完再回到 0 号村（商店）的最短路程。两件事定下整个递归：

  1. s 全都置位时，剩下的事就是从 i 回商店，返回 g[i][0]；
  2. 否则枚举每一个没走过的 j，取 g[i][j] + f(s | (1 << j), j) 的最小值。

入口是 f(1, 0)：出发那一刻，0 号村已经在集合里了。

// dp[s][i] : -1 表示没算过
    // s 的第 i 位是 1，表示第 i 个村已经走过；出发时只有 0 号村，即 s = 1
    int f(int s, int i) {
        if (s == (1 << n) - 1) return g[i][0];   // 全走完了，从 i 回 0 号村
        if (dp[s][i] != -1) return dp[s][i];
        int ans = INT_MAX;
        for (int j = 0; j < n; j++) {
            if ((s & (1 << j)) == 0)             // 没走过的村才能作为下一站
                ans = min(ans, g[i][j] + f(s | (1 << j), j));
        }
        return dp[s][i] = ans;
    }

入口写成 f(0, 0) 是个很隐蔽的错。0 号村不在集合里，就会被当成普通村庄再走一遍，「从别的村回 0 号村再出发」这种路线也算进来了。实测在 20000 组随机 n ≤ 8 的有向图上，这个版本只有 5.50% 出错，大部分图上答案碰巧一样，随手造几组数据根本看不出来。

终点那句也有个方向问题。返回的是 g[i][0]，也就是从当前村回商店。写成 g[0][i] 就是「从商店到当前村」，方向反了。这题明确是有向图，A 到 B 和 B 到 A 大多不同，实测在随机有向图上 99.86% 出错。

二、剥掉起始村，省掉一半状态

看表的大小：2n × n 个状态跑不掉。n = 20 时是 220 × 20 项，用 int 存就是 80 MB。而且表里有一大半格子永远走不到。出发时 0 号村必然在集合里，所以只有含 0 号村的集合才有意义，那已经是 2n−1 个；再要求当前村 i 也在集合里，可达的状态只剩 219 × 10.5 ≈ 550 万，实测 n = 20 走满了 498 万，占 80 MB 那张表的不到四分之一。

既然 0 号村一定走过、也一定是最后一站，干脆把它从 s 里拿掉。这样 s 只记录另外 n − 1 个村，状态数从 2n × n 掉到 2n−1 × (n−1)，正好一半。

// n 是不含起始村的村庄数；st[i] : 起始村 -> i，bk[i] : i -> 起始村
    // 起始村一定走过、也一定是最后一站，那就别把它放进 status，
    // 状态数从 2^n * n 直接砍到 2^(n-1) * (n-1)
    int f(int s, int i) {
        if (s == (1 << n) - 1) return bk[i];
        if (dp[s][i] != -1) return dp[s][i];
        int ans = INT_MAX;
        for (int j = 0; j < n; j++) {
            if ((s & (1 << j)) == 0)
                ans = min(ans, g[i][j] + f(s | (1 << j), j));
        }
        return dp[s][i] = ans;
    }

    int solve() {
        int ans = INT_MAX;
        for (int i = 0; i < n; i++) ans = min(ans, st[i] + f(1 << i, i));
        return ans;
    }

代价是要把商店单拎出来存成两张小表：st[i] 是商店到 i，bk[i] 是 i 回商店；中间那些距离换成去掉商店之后的子矩阵。入口改成对所有 i 取 st[i] + f(1 << i, i) 的最小值。改完两版答案完全一致（6000 组随机小图逐组核对过）。

复杂度分析

做法时间空间
状压 dp（含起始村）O(2n · n2)O(2n · n)
状压 dp（剥掉起始村）O(2n−1 · n2)O(2n−1 · n)
枚举全排列O(n!)O(n)

状态数是 2n 个集合乘 n 个当前村，每个状态还要枚举 n 个下一站，所以时间 O(2n · n2)，空间 O(2n · n)。n = 20 时是 220 × 400 ≈ 4.19 × 108 次枚举、80 MB 表。剥掉起始村之后两边的指数各降一位，正好是一半。

递归栈深度不超过 n，可以忽略。

总结

状态里必须同时有「走过哪些村」和「现在在哪个村」。少了前者，不同的路径会被压成同一个状态；少了后者，就没法算下一段路。

入口的集合要把出发村置上位，终点的返回值要是「从当前村回出发村」。这两处都属于「样例能过、换组数据就错」的类型，实测的出错率分别是 5.50% 和 99.86%，一个躲得很深，一个错得很明显，但都得记住。

题面说 A 到 B 和 B 到 A 大多不同，这句话决定了不能把距离矩阵当成对称的来处理。顺手在对称图上验一遍，会把方向写反这种错完全藏起来。

表里有大量走不到的格子：含 0 号村的集合、且当前村在集合里，这两个条件去掉一大半。当内存真的吃紧时，把固定的那几个维度从状态里剔出去，就是最直接的省法。

状压到这里就告一段落了。status 表示「哪些样本可用」「还剩什么没干」「走过哪些地方」，三种语义共用一套写法：设计 status，写尝试的递归，加记忆化，再看能不能压掉一维。
