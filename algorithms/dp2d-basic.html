二维动态规划：从递归到最小路径和

一维动态规划里，一个可变参数就完全决定了返回值，于是能改出一张一维表。参数变成两个，表就变成二维的，改法还是那三步：写递归、加记忆化、改严格位置依赖。这一步不难，难的是把格子之间的依赖关系画清楚，还有最后那次空间压缩。

零、两个可变参数就是一张二维表

一维动态规划的判据是「一个可变参数能完全决定返回值」。参数加到两个，判据不变，只是表从一行变成一片：

  • 表的大小 = 每个可变参数的可能性数量相乘；
  • 时间复杂度 = 表的大小 × 每个格子的枚举代价；
  • 能不能改，取决于这两个参数是不是真的把「之前决策对后续的影响」装完了。

第三条最要紧。参数装完了，改动态规划就是体力活；没装完，硬改出来的表是错的。

一、最小路径和：先把递归写出来

给一个 m 行 n 列的格子，每格一个非负数，从左上角走到右下角，每次只能向右或向下，问走过的数字之和最小是多少。

定义递归：f(i, j) 是从 (0, 0) 走到 (i, j) 的最小路径和。到 (i, j) 的最后一步，要么从上面 (i−1, j) 下来，要么从左面 (i, j−1) 过来，两条路取小的再加本格的值。

// 从 (0,0) 走到 (i,j) 的最小路径和，每次只能向右或向下
    int f1(vector<vector<int>>& g, int i, int j) {
        if (i == 0 && j == 0) {
            return g[0][0];
        }
        int up = INT_MAX;
        int left = INT_MAX;
        if (i - 1 >= 0) {
            up = f1(g, i - 1, j);
        }
        if (j - 1 >= 0) {
            left = f1(g, i, j - 1);
        }
        return g[i][j] + min(up, left);
    }

这就是「两个可变参数完全决定返回值」的标准样子：i 和 j 一给定，答案就定了，跟你是怎么走到 (i−1, j) 的没关系。

二、这份递归慢在哪

慢在重复。f(3, 3) 要 f(2, 3) 和 f(3, 2)，这两个都要 f(2, 2)，而 f(2, 2) 会被从头再算一遍。

实测一下有多夸张。n 行 n 列的网格，格子只有 n² 个，暴力递归的调用次数是这样长的：

n = 13 时格子 169 个，调用 10400599 次，平均每个格子被算 61542 遍。n 每加 1，调用次数大约翻 3.8 倍，格子数才加 2n + 1。

三、记忆化搜索：算过的格子记下来

加一张同形状的 dp 表，初始全填 −1 表示「没算过」。递归开头先看一眼，算过了就直接返回。

int f2(vector<vector<int>>& g, int i, int j, vector<vector<int>>& dp) {
        if (dp[i][j] != -1) {
            return dp[i][j];
        }
        int ans;
        if (i == 0 && j == 0) {
            ans = g[0][0];
        } else {
            int up = INT_MAX;
            int left = INT_MAX;
            if (i - 1 >= 0) {
                up = f2(g, i - 1, j, dp);
            }
            if (j - 1 >= 0) {
                left = f2(g, i, j - 1, dp);
            }
            ans = g[i][j] + min(up, left);
        }
        dp[i][j] = ans;
        return ans;
    }

    // dp 表先全部填 -1，表示「还没算过」
    int minPathSum2(vector<vector<int>>& g) {
        int n = g.size(), m = g[0].size();
        vector<vector<int>> dp(n, vector<int>(m, -1));
        return f2(g, n - 1, m - 1, dp);
    }

改完调用次数从指数级掉到 n·m，多花的空间是那张 n·m 的表。这个版本还留着递归，栈深度是 n + m。

四、严格位置依赖：直接按行按列填

记忆化已经够快了，但它还是递归。把依赖关系画出来就能改成循环：dp[i][j] 依赖 dp[i−1][j]（上）和 dp[i][j−1]（左），两个都在这格的左上方，所以按「第 0 行、第 0 列先处理，其余从上到下、从左到右」的顺序填，轮到谁谁的前驱就已经算好了。

int minPathSum3(vector<vector<int>>& g) {
        int n = g.size(), m = g[0].size();
        vector<vector<int>> dp(n, vector<int>(m));
        dp[0][0] = g[0][0];
        for (int i = 1; i < n; i++) {          // 第 0 列只能从上面来
            dp[i][0] = dp[i - 1][0] + g[i][0];
        }
        for (int j = 1; j < m; j++) {          // 第 0 行只能从左面来
            dp[0][j] = dp[0][j - 1] + g[0][j];
        }
        for (int i = 1; i < n; i++) {
            for (int j = 1; j < m; j++) {
                dp[i][j] = min(dp[i - 1][j], dp[i][j - 1]) + g[i][j];
            }
        }
        return dp[n - 1][m - 1];
    }

图上右边那张表，每个格子标了它是从上面还是从左面来的。顺着蓝色那条路走回去，就是最小路径和 7 对应的那条路：1 → 3 → 1 → 1 → 1。

五、空间压缩：只留一行

二维表有 n·m 个格子，但填 dp[i][j] 只用得到「本行左边的」和「上一行同列的」。也就是说，填第 i 行的时候，第 i−2 行及以上已经完全没用了。

那就别存整张表，只开一个长度 m 的数组，让它轮流当第 0 行、第 1 行……

int minPathSum4(vector<vector<int>>& g) {
        int n = g.size(), m = g[0].size();
        vector<int> dp(m);                     // 先装下想象中二维表的第 0 行
        dp[0] = g[0][0];
        for (int j = 1; j < m; j++) {
            dp[j] = dp[j - 1] + g[0][j];
        }
        for (int i = 1; i < n; i++) {
            dp[0] += g[i][0];                  // dp[0] 左边没格子，只能从上面来
            for (int j = 1; j < m; j++) {
                // dp[j] 还是「上一行的 dp[j]」，dp[j-1] 已经是「本行新算的」
                dp[j] = min(dp[j - 1], dp[j]) + g[i][j];
            }
        }
        return dp[m - 1];
    }

这里有个细节值得盯一眼：dp[j] = min(dp[j - 1], dp[j]) + grid[i][j] 这一行里的两个 dp，dp[j−1] 是本行刚算出来的新值，dp[j] 还是上一行留下的旧值。同一个数组里同时装着两代数据，靠的是 j 从左到右走：左边先被覆盖，右边还没动。

省下来的空间很实在。n = m = 5000 时，二维表要 95.4 MB，滚动数组只要 19.5 KB，差 5000 倍。

速度上也有小幅收益，主要来自缓存：n = m = 1000 时实测记忆化 7.331 ms、二维表 0.609 ms、滚动数组 0.508 ms。

六、不是什么递归都适合改成动态规划

第二题是单词搜索：给一个字符网格和一个词，问能不能在网格里走出这个词，格子不能重复用。

递归很好写，从每个格子出发试四个方向，把走过的格子就地打标记，回溯时还回去。

// 从 (i,j) 出发，这个格子要匹配 w[k]，问 w[k...] 能不能走出来
    bool f(vector<string>& b, int i, int j, string& w, int k) {
        if (k == w.size()) {
            return true;
        }
        if (i < 0 || i == b.size() || j < 0 || j == b[0].size() || b[i][j] != w[k]) {
            return false;
        }
        char tmp = b[i][j];
        b[i][j] = 0;                           // 就地打标记：这个格子本条路径上用过了
        bool ans = f(b, i - 1, j, w, k + 1)
                || f(b, i + 1, j, w, k + 1)
                || f(b, i, j - 1, w, k + 1)
                || f(b, i, j + 1, w, k + 1);
        b[i][j] = tmp;                         // 回溯时一定要还回去
        return ans;
    }

现在问一句：可变参数 i、j、k 能不能完全决定返回值？

确实，看起来只用了三个 int。但「哪些格子已经用过了」这件事根本没进参数，它藏在 board 的临时修改里。同一个 (i, j, k)，走过的路线不同，答案可以不一样。

左边那条路走完了 babb，右边那条到了同一个格子、匹配了同样多的字符，却卡死了。差别只在「(1,1) 这个格子被用掉了没有」。

把「用过哪些格子」也写进状态，参数类型就不再是 int 了。9 个格子的板子，用过集合有 2⁹ = 512 种，状态数从 9 × 9 涨到 9 × 512；板子再大一点，这张表就没法开了。

所以这题的答案是：不改。带路径的递归，回溯就是它的正解，动态规划在这儿帮不上忙。判据也就清楚了：可变参数得是 int 这个量级的简单类型，而且得真把之前决策的影响装完。

七、复杂度分析

做法时间复杂度空间复杂度说明
暴力递归O(2^(n+m))O(n+m)调用次数指数级，实测 n=m=13 要 1040 万次
记忆化搜索O(n·m)O(n·m) + 递归栈 O(n+m)每个格子只算一次
严格位置依赖O(n·m)O(n·m)没有递归开销，缓存友好
空间压缩O(n·m)O(min(n, m))让短的那一边当数组长度

空间压缩不减时间，只把空间从 n·m 降到 min(n, m)。上面这份代码默认按列压，行数小于列数时应该反过来按行压，数组才最短。

八、总结

二维动态规划的四步：写递归，确认两个可变参数能完全决定返回值；加 dp 表改成记忆化；画出格子依赖，改成从简单格子填到复杂格子的循环；最后看依赖是不是只用得到相邻的一两行，是就压成一维数组。

两个容易写错的地方。一是滚动数组里 dp[j] 和 dp[j−1] 分属两代数据，j 的方向一改就全错。二是压缩前先数清楚依赖，用到了「上一行左边」这种斜向格子时，得额外拿一个变量把它存下来，最长公共子序列正好是这种情况。

再往前一步，是那些每个格子的枚举代价不是 O(1) 的题：表的大小 × 枚举代价才是真实复杂度，那一类题的空间压缩也更有讲究。
