目标和与最后一块石头：把 ± 号变成挑子集

两道看起来毫无关系的题，最后落到同一张表上：一张记「凑出某个和有多少种办法」，一张记「不超过某个和最多能凑到多少」。共同点是它们都在问「这个数要不要选进集合里」，也就是 01 背包。

零、目标和：一个等式换掉整个搜索

nums = [1, 1, 1, 1, 1]，target = 3。给每个数前面放 + 或 −，问有多少种放法能得到 3。每个位置两种选择，n = 20 就是 220 约一百万种，n 再大就得换个想法。

把取正号的数记成集合 A，取负号的记成 B，那么：

sum(A) − sum(B) = target　　且　　sum(A) + sum(B) = s（数组总和）

两式相加，B 消掉了：2 * sum(A) = target + s，也就是 sum(A) = (target + s) / 2。

这一步把问题整个换了。原来是「给每个位置挑符号」，现在是「从数组里挑一个子集，让它的和恰好是 (target + s) / 2」。每一种这样的子集，唯一对应一种符号放法（子集里的取正，其余取负），所以计数也相等。

三个能直接返回 0 的情况要提前判掉：target 比 s 还大，够不着；target + s 是奇数，除不开；还有 target 的绝对值超过 s。第三个容易漏，nums 全部取负也到不了 −s 以下。

一、两条路：平移表，或者直接转背包

第一条路不绕那个等式，按原样做记忆化：从左往右，每个位置放 + 或放 −，问剩下这些数能不能凑到 target。中间的累加和可能是负数，数组下标不能为负，于是整体加一个偏移量 s，把 −s 到 +s 搬到 0 到 2s。

整张表要开 (n + 1) × (2s + 1) 个 int。实测 LC494 的规模（n = 20，每个数不超过 1000，s = 12216）下是 513093 格，跑 1.908 毫秒。

// 平移：累加和可能是负数，下标不能为负，整体加个偏移量 s
    int targetSumByShift(vector<int>& nums, int target) {
        int s = 0;
        for (int num : nums) s += num;
        if (target < -s || target > s) return 0;
        int n = nums.size(), m = 2 * s + 1;          // -s ~ +s 共 2s+1 个位置
        vector<vector<int>> dp(n + 1, vector<int>(m, 0));
        dp[n][target + s] = 1;                        // 原本的 dp[n][target] = 1
        for (int i = n - 1; i >= 0; i--) {
            for (int j = -s; j <= s; j++) {
                if (j + nums[i] + s < m) {            // 这一位前面放 +
                    dp[i][j + s] = dp[i + 1][j + nums[i] + s];
                }
                if (j - nums[i] + s >= 0) {           // 这一位前面放 -
                    dp[i][j + s] += dp[i + 1][j - nums[i] + s];
                }
            }
        }
        return dp[0][s];                              // 原本要返回 dp[0][0]
    }

第二条路用上面那个等式，只需要一张长度为 (target + s) / 2 + 1 的一维表。同样的数据下是 8145 格，0.184 毫秒，比平移表少 63 倍的格子。表小这么多，是因为平移表要把「所有可能的累加和」都留着，而背包表只关心小于等于目标的那一段。

// 记取正号的集合为 A，取负号的集合为 B
    // sum(A) - sum(B) = target，而 sum(A) + sum(B) = 数组总和 s
    // 两式相加：2 * sum(A) = target + s，即 sum(A) = (target + s) / 2
    // 于是「凑出 target 的方案数」=「凑出 (target + s) / 2 的子集个数」
    int findTargetSumWays(vector<int>& nums, int target) {
        int s = 0;
        for (int num : nums) s += num;
        if (s < target || ((target & 1) ^ (s & 1)) == 1) return 0;  // 够不着，或奇偶性不对
        return subsets(nums, (target + s) >> 1);
    }

    // 非负数组 nums 里，累加和恰好是 t 的子集有多少个
    int subsets(vector<int>& nums, int t) {
        if (t < 0) return 0;
        vector<int> dp(t + 1, 0);
        dp[0] = 1;                                    // 空集
        for (int num : nums) {
            for (int j = t; j >= num; j--) {          // 同样要从大到小
                dp[j] += dp[j - num];
            }
        }
        return dp[t];
    }

背包版的转移是 dp[j] += dp[j - num]，不是 max。含义是「凑出 j 的办法数」= 原来就有的办法数 + 拿上 num 之后凑出 j 的办法数。初值 dp[0] = 1 代表空集，这一项必须给，否则整张表恒为 0。j 仍然要从大到小，理由和 01 背包一样：每个数只能用一次。

二、最后一块石头：粉碎就是在分正负号

一堆石头，每次挑两块 x ≤ y 一起粉碎，剩下 |y − x|。问最后剩下的石头最小能有多重。

这里有个跳步。把每次粉碎想成「给这两块分配相反的符号」，反复做下去，最后剩下的重量等于 |Σ ± stones[i]|，其中每个石头自己挑正或负。这个等价性不是显然的，本机用真正按规则枚举所有粉碎顺序的暴力程序跑过 3000 组随机样本（n 在 1 到 6），和 |Σ ± | 的结果 0 组不一致。

于是问题变成：把石头分成两堆，让两堆重量差尽量小。一堆的总重量不会超过 sum / 2（超过的话把两堆互换），那就用 01 背包找出「不超过 sum / 2 的最接近的那个子集和」，答案就是 sum − 2 × near。

转移是 dp[j] = max(dp[j], dp[j - num] + num)，dp 全 0 初始化，回答的是「不超过 j」。这正好符合「不超过 sum / 2 的最接近值」这个要求，不需要额外处理装不满的情况。

// 每次粉碎等价于给石头分正负号，最后剩下的重量 = |Σ ± stones[i]|
    // 于是问题变成：把石头分成两堆，让两堆的重量差尽量小
    int lastStoneWeightII(vector<int>& stones) {
        int sum = 0;
        for (int x : stones) sum += x;
        int near = nearSum(stones, sum / 2);
        return sum - near - near;
    }

    // 非负数组 nums 中，累加和不超过 t 但最接近 t 的是多少
    int nearSum(vector<int>& nums, int t) {
        vector<int> dp(t + 1, 0);
        for (int num : nums) {
            for (int j = t; j >= num; j--) {
                dp[j] = max(dp[j], dp[j - num] + num);
            }
        }
        return dp[t];
    }

实测 n = 300、sum = 15382 的随机数据，near 算出 7691，答案 0，耗时 0.744 毫秒。LC1049 的样例 [2, 7, 4, 1, 8, 1]：sum = 23，sum / 2 = 11，near 恰好是 11（2 + 8 + 1），答案是 23 − 22 = 1。

演示二：分两堆，让差尽量小

三、两张表的差别

两题的 dp 定义只差一个字：一个记「有多少种」，一个记「最多多少」。

这个差别决定了初值和转移符号。计数问题要 dp[0] = 1（空集算一种办法）和 +=；最值问题要全 0 初值（什么都不选时价值 0）和 max。把这两套弄混是最常见的错法：计数题用 max，会丢掉所有重复路径，答案偏小；最值题用 +=，会算出一个毫无意义的累加值。

四、复杂度分析

题目做法时间额外空间说明
目标和枚举符号O(2n)O(n)递归栈深度 n，n = 20 就一百万次
目标和平移表O(n · s)O(n · s)表 (n+1)(2s+1) 个 int，s 是数组总和
目标和转 01 背包O(n · t)O(t)t = (target + s) / 2，实测比平移表少 63 倍格子
最后一块石头01 背包O(n · s)O(s)容量 s / 2，转移是 max 不是 +=

两题的复杂度都写成了 O(n · 容量)，这个「容量」在目标和里是 (target + s) / 2，在石头题里是 s / 2。它跟 n 无关，所以这两道题的实际开销取决于数值范围。s = 12216 时表里才八千个格子，跑起来是微秒级；如果每个数能到 109，这张表就开不出来了，得换别的手法。

目标和那题还有个点：方案数会很大，int 装不下。LC494 的约束下（n ≤ 20）最多 220 约一百万，int 够用；数据放宽就要换成 long long。

五、总结

这两道题的关键都是「换一个问法」，换完之后是同一张 01 背包表。

几个要记住的点：

1）目标和里 sum(A) = (target + s) / 2，于是「挑符号的方案数」等于「和为 (target + s) / 2 的子集个数」。target 太大、奇偶性不对、绝对值超过 s，三种情况直接返回 0。

2）计数题用 dp[0] = 1 配 +=，最值题用全 0 初值配 max。混用的话计数题答案偏小，最值题答案毫无意义。

3）累加和可能为负时，平移一个偏移量 s 就能当数组下标用，代价是表长变成 2s + 1。能推出目标值的题（像目标和）用背包表更省。

4）最后一块石头那题，「反复粉碎」和「分正负号」是同一件事，本机 3000 组随机样本实测 0 组不一致。想到这一步，题目就从模拟题变成了背包题。
