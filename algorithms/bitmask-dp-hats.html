状压 dp：戴帽子与账单平衡

帽子有 40 种，欠债的人最多 12 个。这两个数字摆在一起，其实已经告诉你该把谁压进状态里了。这一页讲两道题，它们的关键参数都是「一组人」。

零、40 顶帽子压不进状态

给 n 个人各配一顶帽子，帽子编号 1 到 40，每个人只接受自己喜欢的那些。最直接的思路是「一个人一个人地安排」，安排第 i 个人时得知道哪些帽子已经被挑走了，那就得把 40 顶帽子的占用情况记下来，240 个状态。

换个方向就能活：按帽子编号从 1 扫到 m，状态里记「哪些人已经拿到帽子」。n ≤ 10，状态只有 2n 个。帽子的数量只是让递推多走几轮，它不进状态。

实测的表大小：240 × 4 字节 = 4 TB，本机开不出来；41 行 × 210 列 × 4 字节 = 164 KB。差了七千万倍，而这两个数字来自同一道题。

一、状态是「谁拿到了帽子」

先把输入掉个个儿。hats[hat] 是一个位掩码，第 i 位为 1 表示第 i 个人喜欢这顶帽子，这样到了第 hat 顶帽子时，一句 hats[hat] 就把「能分给谁」全拿出来了。

const int MOD = 1000000007;

    // hats[hat] : 第 hat 顶帽子，能满足哪些人（第 i 位为 1 表示第 i 个人喜欢它）
    // n 是人数，m 是帽子的最大编号
    int numberWays(const vector<vector<int>>& like, int n, int m) {
        vector<int> hats(m + 1, 0);
        for (int pi = 0; pi < n; pi++) {
            for (int hat : like[pi]) hats[hat] |= 1 << pi;
        }
        vector<vector<int>> dp(m + 2, vector<int>(1 << n, -1));
        return f(hats, m, n, 1, 0, dp);
    }

递归是 f(i, s)：i 是当前帽子编号，s 的第 p 位为 1 表示第 p 个人已经有帽子。两个终止条件，两种可能性：

  1. s 全为 1，所有人都戴上了，后面剩多少帽子无所谓，返回 1；
  2. i 超过了 m，帽子用光了还有人光着头，返回 0；
  3. 这顶帽子谁都不给，去 f(i + 1, s)；
  4. 这顶帽子给某一个喜欢它、且还没帽子的人，去 f(i + 1, s | rightOne)。
// 当前来到第 i 顶帽子，s 里第 i 位为 1 表示这个人已经拿到帽子
    // 返回：让所有人都拿到帽子的方案数
    int f(const vector<int>& hats, int m, int n, int i, int s, vector<vector<int>>& dp) {
        if (s == (1 << n) - 1) return 1;   // 人都齐了，后面帽子随便，算一种
        if (i == m + 1) return 0;          // 帽子用光了还有人光着头
        if (dp[i][s] != -1) return dp[i][s];
        int ans = f(hats, m, n, i + 1, s, dp);          // 这顶帽子谁都不给
        int cur = hats[i];
        while (cur != 0) {                              // 依次取出 cur 最右侧的 1
            int rightOne = cur & -cur;
            if ((s & rightOne) == 0) {                  // 这个人还没帽子
                ans = (ans + f(hats, m, n, i + 1, s | rightOne, dp)) % MOD;
            }
            cur ^= rightOne;
        }
        dp[i][s] = ans;
        return ans;
    }

下面这张表是 n = 3、三个人分别喜欢 {1,2}、{2,3}、{1,3} 时的完整 dp。行是帽子编号 i，列是状态 s。

最后一行 i = 4 只有 s = 111 那一格是 1，其余全 0：帽子用完了人还没配齐，那就是没戏。答案在左上角 dp[1][0] = 2，两种方法，分别是「1→p0、2→p1、3→p2」和「1→p2、2→p0、3→p1」。

二、取最右侧的 1，比枚举每个人划算

可能性 4 要枚举「喜欢这顶帽子的人」，写个 for (p = 0; p < n; p++) 判断 hats[i] & (1 << p) 也能过。但这样每顶帽子都要扫满 n 次，而实际喜欢它的人往往只有几个。

用 Brian Kernighan 那套写法，rightOne = cur & -cur 取出最右侧的 1，cur ^= rightOne 把它抹掉，循环次数恰好等于喜欢这顶帽子的人数，一个人不多扫。实测 n = 10、m = 40 的随机数据：每人喜欢 9 顶时，BK 版内层走了 69761 次，for 版走了 317770 次，耗时 0.754 ms 对 1.028 ms；每人喜欢 3 顶时差距拉到 16683 对 258570，十五倍。

三、两个分支，漏一个就错一半以上

可能性 3「这顶帽子谁都不给」看着最不起眼，写漏它的抓取率却是 58.62%（8000 组随机数据）。原因也好懂：最优方案里总有几顶帽子是闲置的，删掉这个分支等于强制每顶帽子都必须发出去。

可能性 4 里那个 (s & rightOne) == 0 也不能省。省掉之后同一个人可以被安排两次，s | rightOne 等于没变，方案数凭空翻倍。实测抓取率 44.58%。

四、账单平衡：状态里装的是「没结清的人」

第二题换了个场景。一堆人互相欠钱，问最少几笔交易能把账全清。先把每个人的净收支算出来：付钱记负，收钱记正，净收支为 0 的人直接扔掉，剩下的人组成 debt 数组。所有人的净收支加起来必然是 0。

// 题目给定人员编号 0 ~ 12，先把每个人的净收支算出来
    // 净收支为 0 的人直接扔掉，剩下的人组成 debt 数组
    vector<int> debts(const vector<vector<int>>& trans) {
        vector<int> help(13, 0);
        for (const auto& t : trans) {
            help[t[0]] -= t[2];
            help[t[1]] += t[2];
        }
        vector<int> debt;
        for (int v : help) if (v != 0) debt.push_back(v);
        return debt;
    }

如果这些人能分成 k 组，每组内部的净收支之和都是 0，那么每组内部自己结清，t 个人的组要 t − 1 笔交易，加起来正好 n − k 笔。所以「最少交易笔数」等价于「最多能分出几个和为 0 的组」。

f(set, sum) 就数这个组数。sum 是 set 里这些人的净收支之和，两个分支：

  1. sum == 0：随便挑一个人划出去，返回 f(set ^ bit, sum − debt[i]) + 1，然后 break；
  2. sum != 0：枚举每个人划出去，取返回值的最大。
// set : 还没结清的人的集合，sum : 这些人的净收支之和
    // 返回：这些人最多能凑出几个「内部和为 0」的小团体
    int f(const vector<int>& debt, int set, int sum, int n, vector<int>& dp) {
        if (dp[set] != -1) return dp[set];
        int ans = 0;
        if ((set & (set - 1)) != 0) {            // 集合里不止一个人
            if (sum == 0) {
                // 这些人自己就能结清，随便挑一个划出去，剩下的自成一组
                for (int i = 0; i < n; i++) {
                    if ((set & (1 << i)) != 0) {
                        ans = f(debt, set ^ (1 << i), sum - debt[i], n, dp) + 1;
                        break;                   // 挑谁都一样，不用再试别人
                    }
                }
            } else {
                for (int i = 0; i < n; i++) {
                    if ((set & (1 << i)) != 0) {
                        ans = max(ans, f(debt, set ^ (1 << i), sum - debt[i], n, dp));
                    }
                }
            }
        }
        dp[set] = ans;
        return ans;
    }

第一条里的「随便挑」是有依据的。假设划出第 i 个人，剩下那些人里已经凑出了 k 个和为 0 的组，还剩下一些零头，零头的和正好是 −debt[i]。把第 i 个人塞回零头里，这一组的和就是 0 了，于是组数变成 k + 1。划谁都走这一步，结果自然一样，所以挑中第一个就 break。

五、两个容易踩的地方

第一个是「净收支为 0 的人要扔掉」。这句话看着只是省时间，实测是正确性要求：2231 组随机数据里，不剔零的版本 100% 把答案算大了，官方样例 [[0,1,10],[2,0,5]] 正解 2 笔，它算出 3 笔。根源在递归的终止条件：集合只剩一个人时直接返回 0 组，这个结论的前提是「这个人的净收支不是 0」。debt 里混进 0 之后，单蹦一个 0 本该算一组（他本来就不用交易），却也被当成 0 组，组数少算了，答案就虚高。

第二个是别用那个流传很广的 O(3n) 写法。它的做法是每个状态枚举自己的所有子集，子集和为 0 就切一刀，总量 Σ C(n,k)·2k = 3n。课上这版只枚举「划出去一个人」，是 2n · n。

n = 13 时两版差 25 倍（0.121 ms 对 3.042 ms），内层枚举次数 24303 对 1586131。n 再往上，3n 那版就扛不住了。

复杂度分析

做法时间空间
帽子：按帽子编号推进的记忆化O(m · 2n · k)O(m · 2n)
帽子：for 循环枚举每个人O(m · 2n · n)O(m · 2n)
账单：划出单人的记忆化O(2n · n)O(2n)
账单：枚举所有子集O(3n)O(2n)

帽子里 k 是「喜欢这顶帽子的人数」的平均值，用 BK 提取时每格只走 k 次而不是 n 次；m ≤ 40、n ≤ 10，状态数 41 × 1024 = 41984，实测随机数据填到 32365 格。

账单那题 n 是剔零之后的人数，最多 12，状态 212 = 4096 个，每个状态枚举 n 次划人，递归深度不超过 n。

总结

帽子那题的取舍是「谁进状态」。40 顶帽子进状态是 4 TB，10 个人进状态是 164 KB，掉个个儿就活了。判断依据很简单：哪一维的规模是指数级的，就别让它进状态。

两道题都有个「什么都不做」的分支，帽子是闲置一顶帽子，账单是划出一个人继续凑。漏掉它的抓取率分别是 58.62% 和 100%（账单那题漏掉就是不去零，直接偏大）。

账单那题最值钱的观察是「和为 0 时划谁都一样」，一个 break 省下 59.11% 的分支，答案还不变。省下的这部分是实打实少走一半多的递归。

状压 dp 到这里，status 已经见过了四种语义：哪些样本还能用、装到哪根桶、走过哪些村子、哪些人还没结清。下一页换个压法，把质因子压进状态。
