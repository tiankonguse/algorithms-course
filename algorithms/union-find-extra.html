并查集的定制信息：集合数与集合标签

并查集只有 father 数组时，能回答的只是「两个点在不在一起」。给它挂两样东西，一个是集合个数 sets，一个是记在代表节点上的标签，它能回答的问题立刻多出一大截。这一讲前两道题就落在这两样上。

零、并查集能记住什么

并查集的固有信息只有 father 数组，find 给出代表节点，union 把两棵树接上。除此之外还可以自己加：

（1）集合个数 sets。初始等于元素个数，每次合并成功就减一。它是「整体有多少块」的直接答案。

（2）代表节点上的标签。开一个和 father 等长的数组，下标只认代表节点。合并时把两边的标签合成一个（按语义决定是或、是加、还是取最大），查询时先 find 再读。

标签只有一条硬规矩：只在代表节点上读写。往非代表节点上写的值，下一次合并就会被盖掉，读出来的是脏数据。

一、移除最多的同行或同列石头

平面上有 n 块石头，坐标都是整数，一个点上最多一块。如果一块石头同行或同列上还有别的石头，这块就能被移除。问最多能移除几块。

把「同行或同列」当成边，石头是点，能互相到达的石头在同一个连通块里。答案就是 n 减去连通块数：每个连通块内部可以一直删到只剩一块，删不掉的那块是块里的任意一块。

为什么一个连通块只留一块：删掉某块之后，剩下的石头之间的同行同列关系一条都没少，块还是连通的，于是还能继续删。删到最后剩一块时，它同行同列上再没有别的石头，删不动了。

二、只连「第一个遇到的」就够了

建边的时候有个省事写法：给每一行、每一列只记「第一次遇到的石头编号」，后面再碰到同一行（或同一列）的石头，就和这个编号合并，而不是和之前所有石头都合并一遍。

这样写对，是因为连通性有传递性。同一行的 a、b、c，连 a-b 和 a-c 之后，b 和 c 已经在同一个集合里，第三条边是多余的。随机生成石头坐标跑了 20000 组，两种写法算出的答案 0 组不同。

代价差得很多。只连第一个，union 调用次数 = 2n − 不同行数 − 不同列数，最多 2n 次。全连的话每条边都要连，边数是 Σ C(行数里石头数, 2) + Σ C(列数里石头数, 2)。n = 10 万块石头摊在 1000 × 1000 的网格里：拆点法 198000 次 union，朴素连边 9991336 条，差 50 倍；网格缩到 400 × 400，边数涨到 24936919 条，125 倍。拆点法在这些规模上跑 1.18 ~ 1.80 ms。

两个坑。第一，行和列必须各用一张表，混用一张 map 的话，行号 3 和列号 3 会被当成同一条线索，石头被错误地连到一起，实测 11.21% 的样例答案会错。第二，扁平化要写成递归的 father[i] = find(father[i])，写成 father[father[i]] 只跳一级，返回的未必是代表节点，实测 2.13% 的样例会算错。

#include <bits/stdc++.h>
    using namespace std;

    // 石头编号 0 ~ n-1，rowFirst / colFirst 记「某行、某列第一次遇到的石头编号」
    unordered_map<int, int> rowFirst, colFirst;
    vector<int> father;
    int sets;

    void build(int n) {
        rowFirst.clear();
        colFirst.clear();
        father.resize(n);
        for (int i = 0; i < n; i++) {
            father[i] = i;
        }
        sets = n;
    }

    int find(int i) {
        if (i != father[i]) {
            father[i] = find(father[i]);
        }
        return father[i];
    }

    void unionSet(int x, int y) {
        int fx = find(x);
        int fy = find(y);
        if (fx != fy) {
            father[fx] = fy;
            sets--;
        }
    }

    int removeStones(vector<vector<int>>& stones) {
        int n = stones.size();
        build(n);
        for (int i = 0; i < n; i++) {
            int row = stones[i][0];
            int col = stones[i][1];
            // 这一行第一次出现 : 记下来；之后再遇到 : 合并
            if (!rowFirst.count(row)) {
                rowFirst[row] = i;
            } else {
                unionSet(i, rowFirst[row]);
            }
            if (!colFirst.count(col)) {
                colFirst[col] = i;
            } else {
                unionSet(i, colFirst[col]);
            }
        }
        return n - sets;
    }

三、找出知晓秘密的所有专家

n 个专家，m 场会议，每场是 (x, y, t)：专家 x 和 y 在时刻 t 开会。0 号专家有个秘密，在时刻 0 也告诉了 firstPerson。开会时只要一方知道秘密，另一方立刻知道，而且同一时刻的传播是瞬时的：一个人在 t 时刻刚知道，就能在同一时刻的另一场会里传出去。所有会议结束后，返回知道秘密的名单。

这里要用的就是标签：开一个 secret 数组，secret[代表节点] 记这个集合里有没有人知道秘密。合并时两边取或：

secret[fy] |= secret[fx]，只要一边有人知道，合并后的整块都知道。

会议按时刻排序，一个时刻一批，每批两步：先把这批会涉及的人全部合并，再把「整块都不知道秘密」的人退回到单独集合（father[a] = a）。

为什么要按时刻分批：同一时刻的传播是瞬时的，(2,3,t) 和 (3,0,t) 两场会里，0 知道，那么 2 也该在同时刻知道。逐条处理的话，第一条会里没人知道就把 2 和 3 拆回去了，第二条会只传到 3，2 就漏了。实测逐条处理有 7.50% 的样例答案不对。

为什么批内要撤回：合并是为了让这一时刻的信息瞬时扩散，扩散完就该散场。这一批里整块都不知道秘密的人，他们之间的合并在这一时刻没有带来任何信息，留着就会污染后面的时刻。实测不撤回有 13.95% 的样例答案不对。

撤回只针对这批会里出现过的人。没参会的人这一批没被 union 动过，不可能混进别人的集合，不用管。

这一步用不上可撤销并查集那套：可撤销并查集要按栈精确还原合并前的形态，这里只需要把不该连的人重新置成单点，被撤掉的集合里没有要留的信息。

#include <bits/stdc++.h>
    using namespace std;

    vector<int> father;
    // 集合的标签信息 : 代表节点 whole 集合是否有人知道秘密
    vector<int> secret;

    void build(int n, int first) {
        father.resize(n);
        secret.assign(n, 0);
        for (int i = 0; i < n; i++) {
            father[i] = i;
            secret[i] = 0;
        }
        // 0 号专家知道秘密，first 在 0 时刻也知道了
        father[first] = 0;
        secret[0] = 1;
    }

    int find(int i) {
        if (i != father[i]) {
            father[i] = find(father[i]);
        }
        return father[i];
    }

    void unionSet(int x, int y) {
        int fx = find(x);
        int fy = find(y);
        if (fx != fy) {
            father[fx] = fy;
            // 标签跟着一起并 : 两边只要有人知道，合并后整块都知道
            secret[fy] |= secret[fx];
        }
    }

    vector<int> findAllPeople(int n, vector<vector<int>>& meetings, int first) {
        build(n, first);
        // 按时刻排序 : O(m * log m)
        sort(meetings.begin(), meetings.end(),
             [](const vector<int>& a, const vector<int>& b) { return a[2] < b[2]; });
        int m = meetings.size();
        for (int l = 0, r; l < m;) {
            // l....r 这些会议都在同一时刻
            r = l;
            while (r + 1 < m && meetings[l][2] == meetings[r + 1][2]) {
                r++;
            }
            for (int i = l; i <= r; i++) {
                unionSet(meetings[i][0], meetings[i][1]);
            }
            // 这一批里，整块都不知道秘密的人 : 退回到单独的集合
            for (int i = l; i <= r; i++) {
                int a = meetings[i][0];
                int b = meetings[i][1];
                if (!secret[find(a)]) {
                    father[a] = a;
                }
                if (!secret[find(b)]) {
                    father[b] = b;
                }
            }
            l = r + 1;
        }
        vector<int> ans;
        for (int i = 0; i < n; i++) {
            if (secret[find(i)]) {
                ans.push_back(i);
            }
        }
        return ans;
    }

四、复杂度分析

指标石头（n 块）秘密（n 人 m 场会）
时间复杂度O(n·α(n))O(m·log m + m·α(n) + n)
额外空间O(n)（father + 两张哈希表）O(n)（father + secret）

石头那题是线性扫一遍，每块石头两次查表加最多两次合并。秘密那题的大头是排序 O(m·log m)，之后每场会常数次并查集操作，最后扫一遍专家收答案。n = 10 万、m = 10 万实测：排序 3.08 ms，合并加撤回 0.72 ms；m = 50 万时排序 14.81 ms、处理 4.80 ms。

五、总结

这两道题的共同点是「并查集 + 一点自己的信息」。石头题只要集合数，答案直接是 n − sets；秘密题要集合标签，secret 跟着合并一起取或，还要在每个时刻结束时把没沾上信息的合并撤掉。

写这类题时最先要想清楚的是标签的合并规则：是或、是加、还是取最大，错了整个答案就偏。合并规则定了，剩下的就是 find 完再读写，别碰非代表节点。

后面两道题会把标签玩得更花：一种让代表节点带上集合的最大值，一种让集合记住「被几个源头盯上」。
