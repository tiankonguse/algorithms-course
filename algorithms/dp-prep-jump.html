预处理数组：休息k分钟的最大会议和

参加会议要花时间，参加完还得休息 k 分钟。dp 转移里「从 i 往后跳到第一个能参加的会议」这段，朴素做法每次往后累加直到时长够 k，最坏 O(n²)。先用双指针把每个位置的「跳转目标」全部扫进一个 jump 数组，转移就只剩 O(1) 查表：这是预处理数组减少枚举的第一种形态。

零、背景

动态规划的优化专题里，有一类做法把「转移时反复算的东西」提前存进数组，转移时直接查表，转移方程本身不动。jump 数组就是最直白的例子：每个位置往后跳到哪里，本来每次都要现算，预处理后一次查表。

一、问题

长度 n 的数组 arr，arr[i] 是第 i 场会议召开的时长，从早到晚排好。参加任意一场会议之后必须休息 k 分钟，休息期间错过的会议只能放弃。返回能参加的会议时长最大累加和。n、arr[i]、k 都到 10 的 6 次方。

例子：arr = {200, 5, 6, 14, 7, 300}，k = 15。参加 200 分钟那场，休息 15 分钟会错过 5、6、14 三场；再放弃 7 分钟那场，参加最后的 300 分钟，总计 500。这是最优解。

二、朴素转移

从后往前填。dp[i] 表示「考虑会议 i 到 n-1 的最大累加和」。会议 i 要么不参加（继承 dp[i+1]），要么参加：参加后必须休息 k 分钟，从 i+1 开始往后累加会议时长，直到累计时长 ≥ k，记停下的位置为 j，那么 [i+1, j) 之间的会议全部错过，下一场能参加的是 j。转移是

dp[i] = max(dp[i+1], dp[j] + arr[i])。找 j 的内层循环每步从 i+1 往后扫，最坏 O(n)，总 O(n²)，n 到 10 的 6 次方跑不动。

三、jump 数组：双指针预处理

观察发现，jump[i] 只依赖 arr 本身，和 dp 无关。用窗口 [l, r) 左闭右开扫一遍：窗口里装的是「从 l 开始往后累加的会议」，sum 是窗口和。r 一直往右挪到 sum ≥ k，此时 jump[l-1]... 不对，精确说：处理 i 时窗口左端是 i+1，r 挪到 sum ≥ k 停住，jump[i] = r，然后窗口左端右移一位（sum 减掉 arr[l]）继续。

窗口左端每步右移一格，右端最多扫到 n，双指针总共 O(n) 步。jump[n-1] 直接置 n，因为最后一个会议后面没有会议可跳。

四、O(n) 填 dp

jump 数组备好之后，倒序填 dp 就只剩 O(1) 查表：

// 预处理数组：jump[i] 表示参加完会议 i 之后，休息够 k 分钟的第一个可参加会议
    // 窗口 [l, r) 左闭右开，sum 是窗口内会议的累加时长
    void prepare(int* jump, const int* arr, int n, int k) {
        for (int i = 0, l = 1, r = 1, sum = 0; i < n - 1; i++, l++) {
            while (r < n && sum < k) {
                sum += arr[r++];
            }
            jump[i] = r;          // 从 i+1 开始累加，第一次达到 k 的位置
            sum -= arr[l];        // 窗口左端右移，去掉会议 l
        }
        jump[n - 1] = n;          // 最后一个会议之后没有会议
    }

主循环：

// dp[i] 表示考虑会议 i..n-1 的最大累加和，从后往前填
    long long compute(const int* arr, const int* jump, int n) {
        vector<long long> dp(n + 1, 0);
        for (int i = n - 1; i >= 0; i--) {
            // 不参加 i：继承 i+1；参加 i：跳到 jump[i]，累加 arr[i]
            dp[i] = max(dp[i + 1], dp[jump[i]] + (long long)arr[i]);
        }
        return dp[0];
    }

复杂度分析

双指针扫一遍 O(n)，倒序填 dp O(n)，总 O(n)。空间 jump 和 dp 各 O(n)。对比朴素 O(n²)：n = 10 的 6 次方时，n² 是 10 的 12 次方量级，预处理把枚举消掉后只剩两个线性循环。

总结

这一题的三步走：先写「找 j 的内层枚举」的朴素转移确认正确性；再发现 jump[i] 与 dp 无关，用双指针窗口提前算好；最后转移里只查表。要点是窗口 [l, r) 左闭右开、sum 减掉的是窗口左端那场会议、jump[n-1] 单独置 n。

下一题炮兵阵地把「预处理」用在另一个地方：行的合法摆法集合，同样是把转移里反复枚举的东西提前定好。
