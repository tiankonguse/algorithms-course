送箱子：不需要单调队列的窗口

这一节的窗口和前面几节形状一样，但转移要的东西不一样：不是窗口里的最大值，而是「总重量」和「码头切换了几次」这两个能一路加减维护的量。既然不用求最值，单调队列就没有用武之地，两个变量加两个指针就够了。这道题的难点反而全在贪心分析上。

零、行程怎么算

有 n 个箱子排好队，第 i 个要去 p 号码头、重 w。马车一次最多装 a 个箱子、总重不超过 b，出发和结束都在仓库（0 号位置）。箱子必须按给定顺序装车、也必须按这个顺序送到。相邻箱子如果去同一个码头，算同一趟。问送完所有箱子最少几趟。

先把一趟的行程数算清楚。一趟从仓库出发，先到第一个箱子对应的码头，之后每遇到一个和前一个不同的码头就多走一段，最后从最后一个码头回仓库：

所以一趟的行程数等于 2 + 相邻箱子码头不同的次数。2 是出发和回来那两段。

一、dp 与「最后一趟」

设 dp[i] 是拉完前 i 个箱子并回到仓库的最少行程。枚举最后一趟装的是 [l, r]（这里 l、r 是箱子下标，r = i − 1）：

dp[i] = dp[l] + trip(l, r)，要求 r − l + 1 ≤ a 且 weight(l, r) ≤ b。

朴素写法是两层循环，对每个 i 枚举 l，每次重算一趟的行程，复杂度 O(n × a)。n 到 10⁵，a 也到 10⁵，跑不动。

但 r 往右挪一格的时候，trip 和 weight 都是增量可算的：新箱子加进来，重量直接加；如果它的码头和前一个不同，行程加 1。左端 l 往右挪一格也一样，反向减回去。这两个量都不需要从窗口里挑最大最小值，所以不需要队列。

// dp[i] : 拉完前 i 个箱子并回到仓库，最少行程数
    int boxDelivering(vector<vector<int>>& boxes, int a, int b) {
        int n = boxes.size();
        vector<int> dp(n + 1, 0);
        dp[1] = 2;                                              // 只装 1 号箱：去一趟回一趟
        int weight = boxes[0][1], trip = 2;                     // 最后一趟的总重量与行程
        for (int l = 0, r = 1; r < n; r++) {
            weight += boxes[r][1];
            if (boxes[r][0] != boxes[r - 1][0]) trip++;         // 换一个码头多一趟
            while (r - l + 1 > a || weight > b || dp[l] == dp[l + 1]) {
                weight -= boxes[l++][1];
                if (boxes[l][0] != boxes[l - 1][0]) trip--;
            }
            dp[r + 1] = dp[l] + trip;                           // 最后一趟装 l..r
        }
        return dp[n];
    }

四个变量：l 是窗口左端，r 是右端，weight 是窗口总重，trip 是这一趟的行程。dp 数组照旧，dp[l] 是 O(1) 取的。

初始化 dp[1] = 2：只装第一个箱子时，出发一趟、送达回仓库一趟。

二、为什么要收缩三次

while 循环有三个条件，前两个是硬约束：个数超了、重量超了，不得不减。第三个 dp[l] == dp[l+1] 才是这题的关键。

把最左边的箱子让给「前面的过程」处理，代价怎么变？原来是 dp[l] + trip(l, r)，变成 dp[l+1] + trip(l+1, r)。trip 那部分不会变大（少一个箱子，码头切换只会减少或者不变）。所以只要 dp[l+1] ≤ dp[l]，这次收缩就不亏。

dp 数组单调不减，dp[l+1] ≥ dp[l] 恒成立，于是「不亏」的条件就收窄成 dp[l+1] == dp[l]。相等意味着什么？意味着多送第 l + 1 个箱子并没有多花行程，它是搭同一趟车走的。既然如此，把它挪进「前面的过程」里不产生额外代价，那就挪。挪走之后窗口更短、更轻，留给后面的箱子更多余量。

反过来，如果 dp[l] < dp[l+1]，说明第 l + 1 个箱子自带一趟车，把它交给前面的过程会让前面多花一趟，这时候千万别挪。所以收缩条件写的是「等于就收缩」，不是「小于等于」也不是「小于」。

这个收缩做完后，窗口左端 l 停在「再往左挪就要多花钱」的位置上，此时 dp[l] + trip(l, r) 就是当前 r 下的最优值，直接写进 dp[r+1]。

boxes = [(码头1, 3), (码头2, 2), (码头1, 1), (码头2, 4)]，a = 3，b = 6。

答案是 6，对应两趟：第一趟送前两个箱子（码头 1、2），第二趟送后两个（码头 1、2）。中间那次收缩把 0 号和 1 号箱子一起推出窗口，重量从 10 降到 5，行程从 5 降到 3。

五、跟暴力对一下

写一份 O(n²) 的暴力：对每个 i 枚举最后一趟的起点 k，重新算重量和行程，取最小值。随机八千组（n ≤ 8，码头数 ≤ 3，单箱重量不超过 b）实测，窗口版与暴力版的结果一次都没对不上。

生成随机数据的时候要注意一件事：单个箱子的重量必须不超过 b，否则这趟永远装不下，窗口会被收缩到空，代码里访问 boxes[l] 就越界了。原题的数据范围保证了这一点。

六、复杂度分析

版本时间空间说明
枚举最后一趟O(n × a)O(n)每个 i 枚举 l，每次重算一趟
双指针窗口O(n)O(n)l、r 各右移 n 次，weight 与 trip 增量维护

空间按题目上限算：n ≤ 10⁵，dp 数组是 int，约 0.4 MB，箱子本身是输入不算在内。窗口那四个变量是 O(1)。

时间是 O(n) 而不是 O(n²)，因为 l 和 r 都只往右走，while 循环虽然写在 r 的循环里面，但 l 全程最多右移 n 次。

七、总结

这题的窗口和前面几节的窗口长得一样，区别只在于「窗口里要什么」。要最值就得上队列，要的是能加减维护的聚合量（重量、切换次数），两个指针加两个变量就够，队列反而是负担。

真正难的部分是收缩的第三个条件。想清楚它只需要回答一个问题：把最左边的箱子交给前面的过程，代价会不会变大？答案是「dp 不增加就不会」，于是条件就是 dp[l] == dp[l+1]。

判断该不该上单调结构，可以先问一句「我要从窗口里查什么」。查最大值、查最优候选，队列和栈才有意义；查总和、查计数，一个变量跟着指针加减就够了。
