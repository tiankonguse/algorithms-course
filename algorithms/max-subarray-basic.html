子数组最大累加和

给一个整数数组，找出一段连续元素，让它们的和最大，这一段必须非空。n = 100000 时所有候选子数组有 5000050000 个，逐个加起来一次 1468 毫秒；同一个问题用动态规划是 0.084 毫秒。差出四个数量级的原因全在状态怎么定义。

零、全部枚举要多少次加法

长度为 n 的数组，子数组个数是 n (n + 1) / 2：开头有 n 种选法，结尾有 n − i 种，加起来就是这个数。每个都从头加一遍的话，加法次数也是这个量级。

实测里（g++ -O2）n = 100000 的暴力要跑 1468.5 毫秒，动态规划跑同一个数组 0.084 毫秒。n 再翻一倍，暴力那边的代价是四倍。

一、状态定义：必须以 i 结尾

关键的一步是给 dp 加上「限制」。dp[i] 表示：子数组必须以 i 位置的数做结尾，往左随意延伸，能拿到的最大累加和。

加上这个限制之后，以 i 结尾的子数组只有两种形态：要么只有 nums[i] 一个数，要么是「以 i − 1 结尾的某个子数组」再接上 nums[i]。第二种形态里，前面那截取到最大不会吃亏，于是转移就一行：

dp[i] = max(nums[i], dp[i - 1] + nums[i])

这里有个新手常踩的坑：答案不是 dp[n - 1]。dp[n − 1] 只管以最后一个数结尾的那些子数组，最优的一段可能停在中间任何位置。答案要在所有 dp[i] 里取最大值。

#include <bits/stdc++.h>
    using namespace std;

    // dp[i]：子数组必须以 i 位置的数做结尾，往左能延伸出来的最大累加和
    int maxSubArray1(const vector<int>& nums) {
        int n = (int)nums.size();
        vector<int> dp(n);
        dp[0] = nums[0];
        int ans = nums[0];
        for (int i = 1; i < n; i++) {
            dp[i] = max(nums[i], dp[i - 1] + nums[i]);
            ans = max(ans, dp[i]);
        }
        return ans;
    }

还有一个细节：数组元素可能为负。max(nums[i], ...) 这个分支不能省，它对应「前面那截是负的，不要了，从 i 重开」。

二、看一遍 dp 表

用题目自带的例子 [-2, 1, -3, 4, -1, 2, 1, -5, 4] 把整张表填出来。

dp 在 i = 6 拿到 6，就是答案；它对应的子数组是 [4, -1, 2, 1]，下标 3 到 6。注意 dp 自己在 i = 3 之后一路被前面的负数往下压（dp[4] = 3、dp[7] = 1），但这些「被压低的值」仍然是「以那个位置结尾」的最优解，不能顺手丢掉。

这张表也解释了为什么必须扫一遍取 max：dp[8] = 5 比答案小。

三、压缩掉 dp 数组

填 dp[i] 只看 dp[i − 1]，再往前的格子一个也用不上。留两个变量就够了：pre 表示刚填好的 dp[i − 1]，ans 维护全局最大值。

// 空间压缩：dp[i] 只用得上 dp[i-1]
    int maxSubArray2(const vector<int>& nums) {
        int n = (int)nums.size();
        int ans = nums[0];
        for (int i = 1, pre = nums[0]; i < n; i++) {
            pre = max(nums[i], pre + nums[i]);
            ans = max(ans, pre);
        }
        return ans;
    }

这里有个容易写错的地方：ans 的初值是 nums[0]，不是 0。写成 0 之后，遇到全负数组 [-5, -2, -3] 会返回 0，而正确答案是 −2：0 对应的是「空子数组」，题面要求非空。实测全负样本上这个写法 5000 / 5000 全错。

四、把左右端点也带回来

题目常常还要返回这一段的开头和结尾。做法是换一种填法：用 pre 表示「当前这一段 [l, r] 的累加和」，右端点 r 一路往右走，走到发现「把前面吸收进来不划算」，就把开头挪到 r 自己。

// 附加问题：还要返回最大累加和子数组的开头 left、结尾 right
    struct Seg { int left, right, sum; };

    Seg extra(const vector<int>& nums) {
        int n = (int)nums.size();
        int left = 0, right = 0, sum = nums[0];
        int l = 0;
        int pre = INT_MIN;   // 保证第一轮一定走「换开头」
        for (int r = 0; r < n; r++) {
            if (pre >= 0) {
                pre += nums[r];        // 吸收前面的累加和有利可图，不换开头
            } else {
                pre = nums[r];         // 前面的累加和无利可图，从 r 重开
                l = r;
            }
            if (pre > sum) {
                sum = pre;
                left = l;
                right = r;
            }
        }
        return {left, right, sum};
    }

演示：换开头的左右指针

判断条件是 pre >= 0：前面的累加和只要非负，接上去就不会更差。写成 pre > 0 结果也一样：实测两者的累加和从头到尾相同，只有 5.40% 的随机样本左右端点不一样（等于 0 的那段要不要挂在前面）。

pre 的初值取 INT_MIN 是有意的：它保证第一轮一定走「换开头」那条分支，让 l 落在 0。它从来不会被加进任何数里，加操作只发生在 pre >= 0 的那条分支上，所以不用担心溢出。换成初值 0 也能跑出同样的 l，但语义上就变味了。

演示：三种写法逐帧对照

另一个关键动作是换开头时的 l = r。漏掉这一行的话，l 永远停在 0。随机样本里最优子数组不从 0 开始的占 44.14%，这些样本全部会返回一个错误的左端点。演示里切到「错版：忘写 l = r」能看到区间一直从 0 开始。

五、常见写法差别有多大

把四种典型错误单独注入实现，各跑 20000 组随机样本（长度 1 到 9，值域 −9 到 12），出错比例如下。

「全程不换开头」和「忘写 l = r」的出错率一模一样，因为它们踩的是同一件事：答案要求的那段并不从下标 0 开始。这两个 bug 在数据随机时才暴露一半，容易让人误以为实现是对的。

反过来，「ans 初值写成 0」在随机数据上只有 7.76% 出错，正好等于这批数据里全负数组的占比。它躲得过去，但躲不过专门构造的样例。

六、复杂度分析

写法时间额外空间
枚举所有子数组O(n²)O(1)
dp 数组版O(n)O(n)
滚动变量版（pre / ans）O(n)O(1)
换开头版（带端点）O(n)O(1)

空间说明：dp 数组那 n 个 int 在 n = 10⁷ 时是 40 MB，滚动变量是两个 int。除了这 40 MB，两者都只读原数组一遍，没有其他结构。实测 n = 10⁷ 时 dp 数组版 7.87 毫秒、滚动版 5.25 毫秒，差距主要来自那 40 MB 的写入。

时间为什么是 O(n)：每个位置做一次 max、一次加法，常数操作数是 2n 左右，与数组的形状无关。

七、总结

要点其实就三条。第一，dp 里那条「必须以 i 结尾」的限制是整个转移的来源，它把「在哪开始」这个问题推给了上一层，转移才退化成一行的 max。第二，答案是所有 dp[i] 的最大值，不是 dp[n − 1]。第三，全负数组是检验 ans 初值的唯一标准样例。

再往下走有两种常见的变形：把首尾接起来变成环形数组，或者把它套在二维数组上找子矩阵。这两种都是在本页这张 dp 表的基础上做文章。
