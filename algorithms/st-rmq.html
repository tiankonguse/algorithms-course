ST 表做区间最值与公约数

静态数组上反复问「这一段里最大的是几」，最直接的答案是线段树。还有个更笨也更快的办法：把每个长度恰好是 2 的幂的区间的答案全算出来存好，查询时拿两段这样的区间盖住询问，一拼就出结果，一次查询 O(1)。

零、问题与一个前提

给定长度 n 的数组，m 次询问 [l, r]，每次要这段里的最大值、最小值或者全体元素的最大公约数。数组全程不改。这叫 RMQ（Range Minimum/Maximum Query）问题。

线段树是通用解：构建 O(n)，单次查询 O(log n)，还能支持修改。数组不改这个前提一加，事情就变了 —— 不需要支持修改，就可以把所有答案预先算好，把查询压到常数时间。

一、可重复贡献：重叠了有什么关系

ST 表能用，靠的是被查询的那个运算有一条性质：把两个有重叠部分的区间的答案再合并一次，得到的还是合并后整个区间的答案。最大值就满足：max(a, b, c) 和 max(max(a, b), max(b, c)) 是一个东西，b 被算了两次不影响结果。最小值、最大公约数、按位与、按位或都是这样。这叫可重复贡献问题。

区间求和就不满足。两段重叠一格，那一格被加两次，答案直接虚高。实测把下面的 max 换成加法、其余一字不动，随机查询里 100% 算错，因为两段永远有重叠，从不例外。

二、查询：两段盖住整个询问

令 p = log2[r - l + 1]，也就是区间长度里那个最大的 2 的幂的指数。取两段长度都是 2 的 p 次方的区间：左段从 l 起，右段到 r 止。

这两段一定能盖满 [l, r]。理由是 2^(p+1) 严格大于区间长度，左段的尾巴 l + 2^p - 1 一定够得到右段的头 r - 2^p + 1 的前面一格。它们还一定有重叠，重叠长度恰好是 2^(p+1) - len：区间长度刚好是 2 的幂时两段完全重合，长度是 2^(p+1) - 1 时只重叠一格。实测二十万次随机查询，重叠长度从 1 到 524286，平均 147061，占区间长度的 44.51%，没有一次不重叠。

重叠这一格在可重复贡献的运算下无所谓，于是查询就两行：

// [l, r] 上的最大值减去最小值，一次查询 O(1)
    int query(int l, int r) {
        int p = log2[r - l + 1];
        int a = max(stmax[l][p], stmax[r - (1 << p) + 1][p]);
        int b = min(stmin[l][p], stmin[r - (1 << p) + 1][p]);
        return a - b;
    }

右边那段的起点写成 r - (1 << p) + 1，加的那个 1 是全场最容易漏的地方。实测 9 万次随机查询，漏掉它有 35.86% 的查询算错。另一个高频错误是 p 取成 log2[len] + 1：多取一档会让两段越出数组右边界，抓取率 72.42%。

三、构建：长度翻倍，一层一层填

要查的是「从 i 起、长度 2 的 p 次方的区间的答案」，记为 st[i][p]。第 0 层就是单个元素，第 p 层由两个第 p−1 层拼出来，前后两半各长 2 的 p−1 次方：

st[i][p] = max( st[i][p-1], st[i + 2^(p-1)][p-1] )

const int MAXN = 50001;
    const int LIMIT = 16;
    int arr[MAXN], log2[MAXN];
    int stmax[MAXN][LIMIT], stmin[MAXN][LIMIT];

    void build(int n) {
        log2[0] = -1;
        for (int i = 1; i <= n; i++) {
            log2[i] = log2[i >> 1] + 1;
            stmax[i][0] = arr[i];
            stmin[i][0] = arr[i];
        }
        for (int p = 1; p <= log2[n]; p++) {
            for (int i = 1; i + (1 << p) - 1 <= n; i++) {
                stmax[i][p] = max(stmax[i][p - 1], stmax[i + (1 << (p - 1))][p - 1]);
                stmin[i][p] = min(stmin[i][p - 1], stmin[i + (1 << (p - 1))][p - 1]);
            }
        }
    }

两层循环的顺序是死的：外层 p 从 1 涨到 log2[n]，内层 i 从 1 走到 n - 2^p + 1。内层那个上界就是「这一段不能越出数组」，越界的格子不会被问到，填不填都行，但写了更省时间。

log2 那张表跟着 i 一起递推填，log2[0] = -1 让 log2[1] 落到 0。它既用于构建的上界判断，也用于查询时定 p，一次填好两处用。

四、换一个运算：区间最大公约数

把 max 换成 gcd，构建和查询的骨架一个字都不用动。原因是 gcd 同样满足可重复贡献：gcd(a, b, c) 等于 gcd(gcd(a, b), gcd(b, c))，中间那个 b 算两次不碍事。

// 换运算不改骨架：把 build 里的 max 换成 gcd，查询一行不动
    int gcd(int a, int b) {
        return b == 0 ? a : gcd(b, a % b);
    }

    void buildGcd(int n) {
        log2[0] = -1;
        for (int i = 1; i <= n; i++) {
            log2[i] = log2[i >> 1] + 1;
            stgcd[i][0] = arr[i];
        }
        for (int p = 1; p <= log2[n]; p++) {
            for (int i = 1; i + (1 << p) - 1 <= n; i++) {
                stgcd[i][p] = gcd(stgcd[i][p - 1], stgcd[i + (1 << (p - 1))][p - 1]);
            }
        }
    }

    int queryGcd(int l, int r) {
        int p = log2[r - l + 1];
        return gcd(stgcd[l][p], stgcd[r - (1 << p) + 1][p]);
    }

这就是 ST 表最实用的一面：认准「运算满足结合律、幂等、可交换」这三条，就能套模板。按位与、按位或同理，把 gcd 换成 & 或者 | 就完事。

五、ST 表与线段树，各自适合什么

两套结构都做了实测，n 从 5 万到 100 万，查询各跑 20 万次。

结论很清楚。查询快一个数量级（10 到 18 倍），构建慢一个数量级（12 到 30 倍），空间贵 4 到 5 倍。数组静态、查询次数压倒性多于构建次数时，ST 表划算；反过来，或者需要支持修改，老老实实用线段树。

还有一个容易忘的限制：ST 表能维护的信息非常有限。它只存「某个区间的答案」，靠两段拼一次出结果，中间过程一概不保留。想在查询里带上「第几大」「出现过几次」这类要跨段统计的信息，ST 表就无能为力了，那是线段树和莫队的地盘。

六、复杂度分析

做法构建时间单次查询空间支持修改
ST 表O(n log n)O(1)O(n log n)不支持
线段树O(n)O(log n)O(n)支持
每次扫一遍O(1)O(n)O(1)支持

空间按题目上限算。第一题 n 等于 5×10⁴，log2[n] 是 15，两个表各 50001 行 × 16 列，共 6.1 MB。第二题 n 等于 1000，一张表 1001 行 × 10 列，不到 40 KB。开数组时列数取 log2[n] + 1 再加一格余量，5×10⁴ 用 16、1000 用 10。

构建那个 O(n log n) 是实打实的：内层跑 n - 2^p + 1 次，p 从 1 到 log2[n]，加起来是 n log n 减 2 的幂之和，量级不变。这也是它构建比线段树慢的原因 —— 线段树的构建只扫一遍，O(n)。

七、总结

ST 表的查询是两段有重叠的区间拼一次：长度取 2 的 p 次方（p 是 log2[len]），左段从 l 起，右段到 r 止。两段必然盖满询问、必然有重叠，重叠在可重复贡献的运算下无所谓。查询 O(1)，构建 O(n log n)，空间 O(n log n)。

适用边界记两条。运算必须可重复贡献，最大值、最小值、gcd、按位与、按位或都行，区间和不行（实测换成加法 100% 算错）；数组必须静态，表一旦填好改一个元素要重填整张。

代码上只有两个地方会写错：右段起点 r - (1 << p) + 1 少写那个 1（35.86% 的查询出错），以及 p 多取一档（72.42% 出错）。把这两处对一遍，剩下就是模板。
