复合结构设计：LRU、中位数与频率栈

上一讲哈希表配数组，管的是「定位 + 随机访问」。这一讲哈希表要配的是能排次序的结构：双链表排「最近使用」，双堆放「两半的分界」，分层栈排「频率优先」，桶链表排「计数的阶梯」。四题都是同一句口诀：哈希表负责 O(1) 找到人，另一半结构负责把次序记对。

零、背景

缓存要淘汰、数据流要取中位数、统计要问最大频率，这些场景的共性是「既能按名字找到东西，又要维护一种次序」。哈希表给前者，但哈希表本身不保序；次序得靠另一个结构扛。

次序的种类决定了结构的选择：淘汰最近最久未用，要的是「位置可变的有序队列」，双链表最合适；动态中位数，要的是「维护两个半区」，堆正好；按频率取栈顶，要的是「按频率分层的栈」；查最大最小计数，要的是「按计数分桶的链表」。

一、LRU：哈希表 + 双链表

题目 2（LeetCode 146）：实现一个缓存，get 和 put 都是 O(1)，容量满了淘汰「最久未使用」的键。

朴素做法：数组里存 (key, value, 最后使用时间)，每次 get/put 全数组扫一遍找键，淘汰时再扫一遍找最旧的。容量 128、20 万次操作实测 21.7 毫秒，键多到几百个时就扛不住了。

组合：哈希表 key → 链表节点，双链表按「最近使用」排：表头最久未用、表尾最近使用。

  • get(key)：哈希表找到节点，把节点移到链表尾，返回值。命中一次就代表刚用过，必须挪
  • put(key, value)：键已存在 → 更新值、移到链表尾；不存在 → 若已满，删链表头（哈希表同步删），新节点挂到链表尾

链表尾是「最近」，链表头是「最久」，所以淘汰永远发生在表头，O(1)。挪动节点要断两边的链、接上新位置，正好是上一讲双链表那套操作。

// LRU：哈希表定位节点，双链表维护访问顺序，表头最久未用、表尾最近使用
    class LRUCache {
    public:
        struct DoubleNode {
            int key, val;
            DoubleNode *last, *next;
            DoubleNode(int k, int v) : key(k), val(v), last(nullptr), next(nullptr) {}
        };

        struct DoubleList {
            DoubleNode *head = nullptr, *tail = nullptr;

            void addNode(DoubleNode *newNode) {
                if (!newNode) return;
                if (!head) {
                    head = tail = newNode;
                } else {
                    tail->next = newNode;
                    newNode->last = tail;
                    tail = newNode;
                }
            }

            void moveNodeToTail(DoubleNode *node) {
                if (tail == node) return;
                if (head == node) {
                    head = node->next;
                    head->last = nullptr;
                } else {
                    node->last->next = node->next;
                    node->next->last = node->last;
                }
                node->last = tail;
                node->next = nullptr;
                tail->next = node;
                tail = node;
            }

            DoubleNode *removeHead() {
                if (!head) return nullptr;
                DoubleNode *ans = head;
                if (head == tail) {
                    head = tail = nullptr;
                } else {
                    head = ans->next;
                    ans->next = nullptr;
                    head->last = nullptr;
                }
                return ans;
            }
        };

        unordered_map<int, DoubleNode *> keyNodeMap;
        DoubleList nodeList;
        int capacity;

        LRUCache(int cap) : capacity(cap) {}

        int get(int key) {
            if (keyNodeMap.count(key)) {
                DoubleNode *ans = keyNodeMap[key];
                nodeList.moveNodeToTail(ans);
                return ans->val;
            }
            return -1;
        }

        void put(int key, int value) {
            if (keyNodeMap.count(key)) {
                DoubleNode *node = keyNodeMap[key];
                node->val = value;
                nodeList.moveNodeToTail(node);
            } else {
                if ((int)keyNodeMap.size() == capacity) {
                    keyNodeMap.erase(nodeList.removeHead()->key);
                }
                DoubleNode *newNode = new DoubleNode(key, value);
                keyNodeMap[key] = newNode;
                nodeList.addNode(newNode);
            }
        }
    };

实测同样 20 万次操作：哈希 + 链表 4.9 毫秒，比朴素快 4.4 倍。键再多也基本不涨，因为哈希表平均 O(1)，链表操作只碰两个节点。

二、数据流中位数：双堆

题目 5（LeetCode 295）：一个数据流不断 addNum，随时可以 findMedian 问当前中位数，两个操作都要快。

朴素做法：维护一个有序数组，插入时二分找位置再搬移。10 万次 addNum 实测 147 毫秒，平均每次插入要搬 2.5 万个元素，n 越大越慢。

组合：两个堆。大根堆放左半，堆顶是左半最大；小根堆放右半，堆顶是右半最小。两个堆的大小差不超过 1。

  • addNum(num)：num 比左堆顶小或相等就进左堆，否则进右堆；两边差 2 时从多的那边挪一个堆顶到另一边
  • findMedian()：两堆一样大，中位数是两堆顶的平均；不一样大，中位数是多的那堆堆顶

为什么是堆：只需要知道分界处的两个值（左半最大、右半最小），不需要整段有序。堆顶恰好就是这两个值，插入和取顶都是 O(log n)。

// 数据流中位数：大根堆放左半、小根堆放右半，两边数量差最多 1
    class MedianFinder {
    public:
        priority_queue<int> maxHeap;                              // 左半，堆顶是左侧最大
        priority_queue<int, vector<int>, greater<int>> minHeap;   // 右半，堆顶是右侧最小

        void addNum(int num) {
            if (maxHeap.empty() || maxHeap.top() >= num) {
                maxHeap.push(num);
            } else {
                minHeap.push(num);
            }
            balance();
        }

        double findMedian() {
            if (maxHeap.size() == minHeap.size()) {
                return ((double)maxHeap.top() + minHeap.top()) / 2;
            }
            return maxHeap.size() > minHeap.size() ? maxHeap.top() : minHeap.top();
        }

        void balance() {
            if (abs((int)maxHeap.size() - (int)minHeap.size()) == 2) {
                if (maxHeap.size() > minHeap.size()) {
                    minHeap.push(maxHeap.top());
                    maxHeap.pop();
                } else {
                    maxHeap.push(minHeap.top());
                    minHeap.pop();
                }
            }
        }
    };

实测 10 万次 addNum + 5 万次查询：双堆 2.1 毫秒，有序数组 147 毫秒，差 71 倍。

三、最大频率栈：分层栈

题目 6（LeetCode 895）：实现一个栈，push 照常，pop 返回「频率最高」的数；频率一样时返回「最近 push」的那个。

普通栈只记一个顺序，管不了频率。朴素做法：每次 pop 全表扫一遍找最大频率，再从 push 序列倒着找第一个。20 万次操作实测 20.7 毫秒，值越多越慢。

组合：按频率分层。cntValues[f] 是频率 f 的一列值（每层内部是栈，后进先出），valueTimes 记每个值当前的频率，topTimes 记当前最高频率。

  • push(val)：值频率 +1，塞进对应那层的栈顶；topTimes 跟着涨
  • pop()：取 topTimes 那一层的栈顶；层空了 topTimes 减一；值的频率 -1

频率一样的数，谁后 push 谁在层内栈顶，pop 时先出，正好满足「同频率取最近」。

// 最大频率栈：按频率分层存值，每层内部是栈，pop 取最高层栈顶
    class FreqStack {
    public:
        int topTimes = 0;
        unordered_map<int, vector<int>> cntValues;   // 频率 -> 该频率的数，后进先出
        unordered_map<int, int> valueTimes;          // 数 -> 当前频率

        void push(int val) {
            int cur = ++valueTimes[val];
            cntValues[cur].push_back(val);
            topTimes = max(topTimes, cur);
        }

        int pop() {
            vector<int> &topVec = cntValues[topTimes];
            int ans = topVec.back();
            topVec.pop_back();
            if (topVec.empty()) {
                cntValues.erase(topTimes--);
            }
            int times = valueTimes[ans];
            if (times == 1) {
                valueTimes.erase(ans);
            } else {
                valueTimes[ans] = times - 1;
            }
            return ans;
        }
    };

实测 20 万次 push/pop：分层 3.8 毫秒，朴素全表扫 20.7 毫秒，快 5.4 倍。频率层数最多是最大频率，栈深加起来正好是元素个数，空间 O(n)。

四、全 O(1) 结构：桶链表

题目 7（LeetCode 432）：键是字符串，支持 inc、dec、getMaxKey、getMinKey，四个操作全 O(1)。

朴素做法：哈希表记每个键的计数，问最大最小计数时全表扫。2 万个键、10 万次操作（含 5000 次查询）实测 2235 毫秒，查询一次扫 2 万键。

组合：桶 + 双向链表。每个桶存「计数相同的键集合」，桶按计数从小到大串成链表；哈希表把键指到它所在的桶。链表两端加哨兵：head 代表计数 0，tail 代表无穷大。

  • inc(key)：键从当前桶挪到计数 +1 的桶；没有这个桶就新建一个插到中间
  • dec(key)：键挪到计数 -1 的桶；计数归零直接从哈希表删掉
  • getMaxKey() / getMinKey()：取链表两端桶里随便一个键

挪键时先看「隔壁桶的计数是不是正好差 1」，是就蹭进去，不是才新建桶。桶空了就摘掉。这样桶的数量永远不超过键的数量，链表上每个操作都是 O(1)。

// 全 O(1) 结构：哈希表指向桶，桶按计数串成双向链表，桶内哈希集合存同计数的键
    class AllOne {
    public:
        struct Bucket {
            unordered_set<string> set;
            int cnt;
            Bucket *last, *next;
            Bucket(string s, int c) : cnt(c), last(nullptr), next(nullptr) {
                set.insert(s);
            }
        };

        void insert(Bucket *cur, Bucket *pos) {
            cur->next->last = pos;
            pos->next = cur->next;
            cur->next = pos;
            pos->last = cur;
        }

        void remove(Bucket *cur) {
            cur->last->next = cur->next;
            cur->next->last = cur->last;
        }

        Bucket *head;
        Bucket *tail;
        unordered_map<string, Bucket *> map;

        AllOne() {
            head = new Bucket("", 0);
            tail = new Bucket("", INT_MAX);
            head->next = tail;
            tail->last = head;
        }

        void inc(string key) {
            if (!map.count(key)) {
                if (head->next->cnt == 1) {
                    map[key] = head->next;
                    head->next->set.insert(key);
                } else {
                    Bucket *newBucket = new Bucket(key, 1);
                    map[key] = newBucket;
                    insert(head, newBucket);
                }
            } else {
                Bucket *bucket = map[key];
                if (bucket->next->cnt == bucket->cnt + 1) {
                    map[key] = bucket->next;
                    bucket->next->set.insert(key);
                } else {
                    Bucket *newBucket = new Bucket(key, bucket->cnt + 1);
                    map[key] = newBucket;
                    insert(bucket, newBucket);
                }
                bucket->set.erase(key);
                if (bucket->set.empty()) {
                    remove(bucket);
                }
            }
        }

        void dec(string key) {
            Bucket *bucket = map[key];
            if (bucket->cnt == 1) {
                map.erase(key);
            } else {
                if (bucket->last->cnt == bucket->cnt - 1) {
                    map[key] = bucket->last;
                    bucket->last->set.insert(key);
                } else {
                    Bucket *newBucket = new Bucket(key, bucket->cnt - 1);
                    map[key] = newBucket;
                    insert(bucket->last, newBucket);
                }
            }
            bucket->set.erase(key);
            if (bucket->set.empty()) {
                remove(bucket);
            }
        }

        string getMaxKey() {
            return *tail->last->set.begin();
        }

        string getMinKey() {
            return *head->next->set.begin();
        }
    };

实测同一份操作：桶链表 11.8 毫秒，朴素全表扫 2235 毫秒，快 189.5 倍。多个键同计数时返回任意一个，题目允许。

五、复杂度分析

结构get / putaddNum / findMedianpush / popinc / dec / 极值
LRU（哈希 + 双链表）O(1)———
中位数（双堆）—O(log n) / O(1)——
频率栈（分层栈）——O(1)—
全 O(1)（桶链表）———O(1)

四题空间都是 O(n)。双堆的堆顶只暴露一个值，是「只要分界不要全序」的典型；桶链表的哨兵让 inc/dec 的边界判断省掉一堆特判。

六、总结

四题放到一起，结构选择看的是「要哪种次序」：

  • 淘汰最久未用 → 双链表，表头就是答案，挪动 O(1)
  • 动态中位数 → 双堆，堆顶就是分界，只维护两个极值
  • 频率优先的栈 → 分层栈，每层一个栈，顶层就是答案
  • 任意键的最大最小计数 → 桶链表，桶按计数排序，两端就是答案

共同点：哈希表永远负责「按名字 O(1) 找到」，次序结构负责「按规则 O(1) 回答」。设计题答得好不好，就看能不能说清「哈希表里存什么、另一半结构维护什么次序、为什么这个次序选这种结构」。
