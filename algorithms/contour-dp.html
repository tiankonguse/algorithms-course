轮廓线 dp：从一行一行到一格一格

网格上做状压 dp，状态通常只装「上一行长什么样」。可这一行内部每个格子怎么选，还得再递归试一遍，代价就跟着 2 的 m 次方又乘了一次。轮廓线 dp 把状态换成一条随扫描位置移动的折线，走到每个格子只做常数次转移。

零、背景

状压 dp 在序列上很顺手：一个整数的第 i 位表示第 i 个样本用没用过，状态数 2 的 n 次方，n 卡在 20 上下。这套做法搬进二维网格就别扭了。

原因出在格子有几个邻居。序列上第 i 个位置只跟第 i−1 个有关，网格上的 (i, j) 要同时看左边和上面。如果一行一行地推进，状态只能表示「上一行」，那本行从左到右每个格子选什么，就只能现场递归枚举。

这个递归是白花的。m = 12 时一行有 2¹² = 4096 种选法，n 行全算下来，代价上界是 n × 2m × 2m = 12 × 4096 × 4096 ≈ 2.0 × 10⁸。轮廓线 dp 做的是同一件事，代价压到 n × m × 2m = 589824。

一、问题

种草的方法数。n × m 的网格，每格是 0 或 1，1 表示这块地能种草。任何两块种了草的地不能上下左右相邻，种多少随意，返回方法数，答案对 100000000 取模。n、m 不超过 12。

决策按行、行内按列扫过去，做 (i, j) 的决定时，需要知道的信息是 (i, j−1) 和 (i−1, j) 有没有种草。右面和下面还没走到，不用管。

二、普通状压 dp 的困境

先写出来最直接的一版：状态 s 表示 i−1 行每列的种草状况，ss 是本行已经定下来的状况，本行靠 dfs 一格一格试。

const int MAXN = 12, MAXM = 12, MOD = 100000000;
    int grid[MAXN][MAXM];
    int dp[MAXN][1 << MAXM];
    int n, m, maxs;

    // 来到 i 行，i-1 行每列的种草状况是 s
    // 返回从 i 行开始到结束有几种方法
    int f(int i, int s) {
        if (i == n) return 1;
        if (dp[i][s] != -1) return dp[i][s];
        int ans = dfs(i, 0, s, 0);
        dp[i][s] = ans;
        return ans;
    }

    // 本行内部只能一个格子一个格子试，ss 是本行已经定下来的状况
    int dfs(int i, int j, int s, int ss) {
        if (j == m) return f(i + 1, ss);
        int ans = dfs(i, j + 1, s, ss);
        if (grid[i][j] == 1 && (j == 0 || get(ss, j - 1) == 0) && get(s, j) == 0) {
            ans = (ans + dfs(i, j + 1, s, set(ss, j, 1))) % MOD;
        }
        return ans;
    }

这张表只有 n × 2m 格，看起来不大。但每一格的求解都要把本行 m 个格子重新枚举一遍，等于给表又乘了一个 2m。

本机 g++ -O2、12 × 12 全 1 网格上量了一遍：这一版递归调用 1099696 次，跑完 5.49 毫秒。数字不算吓人，但它是纯递归，递归函数本身没法被内联掉，换到别的运行时上很容易就翻过去。

三、轮廓线

换个看法。按行优先扫到 (i, j) 的时候，已经定下来的格子是「i−1 行整行」加「i 行的 0 到 j−1 列」。这些格子和没走到的格子之间有一条阶梯形的分界线，这条线就叫轮廓线。

轮廓线长度恒为 m。线以上的部分是 i−1 行，线以下属于 i 行。于是可以用一个 m 位的状态 s 装下它：

1）s 的第 0 到 j−1 位，装 i 行 j 列左侧的决策；

2）s 的第 j 到 m−1 位，装 i−1 行 j 列右侧的决策。

这样一来，(i, j) 需要的两个邻居刚好都在 s 里：左邻是第 j−1 位，上方是第 j 位。走完 (i, j) 就把第 j 位改成这次的决定，然后往右挪一格，轮廓线跟着往前推一步。j 走到 m 时换行，此时 s 整体就是 i 行的状况，直接当 i+1 行的「上一行」用。

位操作还是那三个，取位、置 1、置 0。

// 得到状态 s 中第 j 位的值
    int get(int s, int j) {
        return (s >> j) & 1;
    }

    // 把状态 s 中第 j 位设置成 v，其余位不动，返回新状态
    int set(int s, int j, int v) {
        return v == 0 ? (s & (~(1 << j))) : (s | (1 << j));
    }

轮廓线版的转移就一行，没有 dfs。

int dp[MAXN][MAXM][1 << MAXM];

    // 当前来到 i 行 j 列
    // s 的 [j..m-1] 位表示 i-1 行 j 列右侧的种草状况
    // s 的 [0..j-1] 位表示 i   行 j 列左侧的种草状况
    // 合起来 s 就是一条轮廓线的状况
    int f(int i, int j, int s) {
        if (i == n) return 1;
        if (j == m) return f(i + 1, 0, s);
        if (dp[i][j][s] != -1) return dp[i][j][s];
        int ans = f(i, j + 1, set(s, j, 0));
        if (grid[i][j] == 1 && (j == 0 || get(s, j - 1) == 0) && get(s, j) == 0) {
            ans = (ans + f(i, j + 1, set(s, j, 1))) % MOD;
        }
        dp[i][j][s] = ans;
        return ans;
    }

注意 j == m 那个分支：s 原样传给下一行，什么都不用改。此时 s 的每一位装的都是 i 行的决策，到了 (i+1, 0) 上，它自然就变成「上一行」了。

下面这张图是 j = 2 时的一次推进。s 的二进制按低位在左写，第 2 位就是正上方那格。

这里有个细节：能种的条件里，第 j 位必须为 0。所以「种」这个分支一定真的改了 s，而「不种」这个分支在第 j 位本来就是 0 时 s 不变。两个分支走到的是同一个位置 (i, j+1)，只是 s 不同，这正是它俩能共用一个 dp 表的原因。

五、推进台

选一个网格，点「不种」或者「种」一步一步往前推。右边那排格子就是轮廓线，蓝色是 i 行已经定下来的位，灰色是 i−1 行还没用到的位，橙色框是正要处理的第 j 位。

推进台：一格一格地推轮廓线

「种」这个按钮在三种情况下会变灰：这块地是 0、左邻已经种了、正上方已经种了。变灰就说明这个分支在这条路径上不存在。

六、空间压缩

轮廓线版的 dp 表是 dp[n][m][2m]，m = 12 时是 12 × 12 × 4096 个 int，2.25 MB。看着也还行，但这个 2.25 MB 是跟着 n 走的。

先看清依赖关系：填 dp[j][s] 只用到 dp[j + 1] 这一层，跟 i 无关（i 只在判断 grid[i][j] 时出现）。所以第一维完全可以省掉，只要一层一层往回填。

填表的顺序是倒着的：先把 j = m（换行）那一层用 prepare 铺好，然后 j 从 m−1 一路填到 0，最后把 dp[0] 拷回 prepare，交给上面那一行。i 也是从 n−1 往上走。

int dp[MAXM + 1][1 << MAXM];   // 第一维只有 m+1 行，跟 n 无关
    int prepare[1 << MAXM];        // 下一行开头拿到的初值

    int compute() {
        for (int s = 0; s < maxs; s++) prepare[s] = 1;   // i == n：越界之后算一种
        for (int i = n - 1; i >= 0; i--) {
            for (int s = 0; s < maxs; s++) dp[m][s] = prepare[s];   // j == m：要换行
            for (int j = m - 1; j >= 0; j--) {                      // 本行从右往左填
                for (int s = 0; s < maxs; s++) {
                    int ans = dp[j + 1][set(s, j, 0)];
                    if (grid[i][j] == 1 && (j == 0 || get(s, j - 1) == 0) && get(s, j) == 0) {
                        ans = (ans + dp[j + 1][set(s, j, 1)]) % MOD;
                    }
                    dp[j][s] = ans;
                }
            }
            for (int s = 0; s < maxs; s++) prepare[s] = dp[0][s];    // 本行收尾交给上一行
        }
        return dp[0][0];
    }

prepare 这个名字起得挺准：它是「下面那一行算完之后，留给本行的初值」。一开始全是 1，对应 i == n 时返回 1 那个边界。

空间从 O(n × m × 2m) 降到 O(m × 2m)，m = 12 时是 13 × 4096 个 int，0.20 MB，只有原来的 1/11，而且跟 n 彻底脱钩。

复杂度分析

种草这题三种写法的代价如下，m 是列数，n 是行数，状态数 2m 记作 S。

写法时间复杂度空间复杂度m = 12 时的规模
普通状压 dp + 行内 dfsO(n · S · S)O(n · S)≈ 2.0 × 10⁸，表 12 × 4096
轮廓线 dp（记忆化）O(n · m · S)O(n · m · S)589824 格，2.25 MB
轮廓线 dp + 空间压缩O(n · m · S)O(m · S)整表 589824 格，内存 0.20 MB

空间按题目上限算：m ≤ 12，所以 S = 4096。空间压缩版的表是 dp[13][4096]，加上 prepare[4096]，合计 14 × 4096 个 int，0.22 MB。

七、三种写法的实测

12 × 12 全 1 网格上，轮廓线记忆化版只填了 58556 格，占整张表 589824 格的 9.93%。剩下的格子对应的状态压根到不了，比如「本行相邻两位都是 1」这种 s 在合法路径上不会出现。

空间压缩版没这个便宜，它把整张表都填了一遍，所以在小数据上反而会慢一点：全 1 网格上 1.20 毫秒，记忆化版 0.99 毫秒。它赢的是内存和 n 很大的场景。

换成随机 0/1 网格，12 × 12 上记忆化版只要 0.08 毫秒（到得了的状态只剩 5603 个），空间压缩版 0.41 毫秒。空间压缩真正划算的场景是 n 大、内存卡得紧的题。

总结

轮廓线 dp 的要点：状态装的不是「上一行」，而是扫描位置和已决策区域之间那条长度为 m 的分界线；s 的第 0 到 j−1 位属于本行、第 j 到 m−1 位属于上一行，走到 (i, j) 需要的邻居恰好都在线上；处理完就把第 j 位改成这次的决定，整条线往前推一格。代价从 n · 2m · 2m 降到 n · m · 2m。空间压缩看的是依赖：dp[j] 只依赖 dp[j+1]，于是第一维可以滚掉，行与行之间用 prepare 接力。

往后是这条线的两种变体：状态里每位装 2 个 bit 的染色问题，以及需要额外带一个「被覆盖掉的邻居」的摆放国王。
