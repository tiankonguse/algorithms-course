树上 01 背包：从 O(nm²) 到 O(nm)

选课的先修关系是一棵树，选出来的课必须连成一片：选了某门课，它的先修课也得选。朴素的树上背包要把子树一棵棵并进来，复杂度带一个 m 的平方；把 dfn 序用上，同一个问题能压到 O(nm)。

零、先修关系是一棵树

每门课有一门或没有直接先修课。选了课程 b，就必须先选完它的先修课 a。把「没有先修课」的课挂到一个虚拟的总先修下面，先修关系就成了一棵以虚拟根为根的树。

规则翻译到树上：选了某个节点，它的父亲必须也选。于是选出来的节点集合，必须从虚拟根那里连成一片，中间不能断开。

问题就变成：在树上挑恰好 M 个节点，要求挑出来的部分连成一片并包含根，取学分和最大。

一、朴素做法：把子树一棵棵并进背包

既然约束是「连成一片」，一个自然的想法是让每个节点管住自己下方的挑选：父节点把每个儿子的方案合起来。

定义 f(i, j, k)：只在 i 号节点、以及它下方的前 j 棵子树上挑 k 个连成一片的节点，能拿到的最大学分和。

两个边界先写出来。k 为 0 时一个都不挑，和是 0；j 为 0（没有子树可挑）或 k 为 1（只能挑 i 自己）时，只能拿 i 的学分。

转移看第 j 棵子树挑不挑：不挑，答案来自前 j − 1 棵子树挑 k 个；挑 s 个，答案来自前 j − 1 棵挑 k − s 个，再加上第 j 棵子树挑 s 个。把 s 从 1 到 k − 1 枚举一遍取最大。

写出来会发现，多出来的那层 m 就在这个 s 的枚举里。每个节点、每棵子树、每个 k，都要再枚举一次 s，时间就带上了 m 的平方。

// 只在 i 号节点、以及它下方前 j 棵子树上挑 k 个连成一片的节点，最大和
    int f(int i, int j, int k) {
        if (k == 0) return 0;
        if (j == 0 || k == 1) return nums[i];
        if (memo[i][j][k] != -1) return memo[i][j][k];
        int ans = f(i, j - 1, k);              // 第 j 棵子树一个都不挑
        int v = graph[i][j - 1];
        for (int s = 1; s < k; s++)            // 第 j 棵子树挑 s 个
            ans = max(ans, f(i, j - 1, k - s) + f(v, graph[v].size(), s));
        return memo[i][j][k] = ans;
    }

复杂度是 O(n·m²)：最外层是节点，中间是子树的个数（全树加起来约 n 个），里层是 k 和 s 两层。空间是记忆化的表，规模 O(n·m)。

实测一下这个 m²。n = 300 固定，m 从 50 涨到 300，普通解的耗时是这样的：m = 50 用 9.3 ms，100 用 36.6 ms，200 用 153.2 ms，300 用 359.4 ms。m 每翻一倍，耗时大约翻四倍，正是平方的形状。

二、最优解：把选课搬到 dfn 上

朴素做法慢在「每棵子树都要重新枚举挑几个」。换一个角度：不按子树并，改成按 dfn 顺序做一次 01 背包。

先给整棵树打 dfn 序号，把学分和子树大小都按 dfn 下标存好。注意虚拟根也有一个 dfn，它排在最前面。

定义 dp[i][j]：只在 dfn 从 i 到末尾这些节点里挑 j 个，要求挑出来的部分挂在一个共同的假想父亲下面、连成一片（叫有效结构），能拿到的最大和。

转移只有两条，看 dfn 为 i 的这个节点选不选：

  1. 不选 i。它的整棵子树都不能选了，因为选了子节点就得选父亲。于是这段范围的起点直接跳到 i + sz[i]，dp[i + sz[i]][j]；
  2. 选 i。花掉一个名额，然后从下一个 dfn 接着看，val[i] + dp[i + 1][j - 1]。

两条路取最大就是 dp[i][j]。从 dfn 大的往小的推，右边的状态先算好。

最后把虚拟根交上去：它一定被选（学分是 0），它下方就是有效的结构，答案 = nums[0] + dp[2][m]。

// 打 dfn 序号，val / sz 都按 dfn 下标存
    int f(int u) {
        int i = ++dfnCnt;
        val[i] = nums[u];
        sz[i] = 1;
        for (int ei = head[u]; ei > 0; ei = nxt[ei])
            sz[i] += f(to[ei]);
        return sz[i];
    }

    int compute() {
        f(0);
        // dp[i][j]：dfn 在 i ~ n+1 范围内挑 j 个、还能连成有效结构时的最大和
        for (int i = n + 1; i >= 2; i--)
            for (int j = 1; j <= m; j++)
                dp[i][j] = max(dp[i + sz[i]][j], val[i] + dp[i + 1][j - 1]);
        return nums[0] + dp[2][m];
    }

关键在那个「有效结构」的定义。它把「连成一片」的约束，换成了两条 dfn 上的跳跃：不选就跳过整棵子树，选就往后挪一格。约束消失之后，dp 就退化成普通的 01 背包，两层循环，复杂度就是 O(n·m)。

实测同样的 n = 300：最优解在 m = 300 时用时 0.04 ms，普通解 366.5 ms，差了大约九千倍。m 从 50 涨到 300，最优解只从 0.008 ms 走到 0.013 ms，因为这时固定开销（打 dfn）占了大头，真正的 n·m 两层循环快到看不出来。

复杂度分析

解法时间空间

朴素解多出来的一个 m，来自「每棵子树挑几个」这一层枚举；它的记忆化表按节点和子树编号展开，规模是 O(n·m)。

dfn 版把「选几门」这一维留在 j 上，i 顺着 dfn 扫一遍，两层循环，时间 O(n·m)；dp 表的规模同样是 O(n·m)。

题目里 N 到 300，两解都能过。但 m² 在 n 也到 300 时是 10⁷ 量级，常数再大一点就悬；理解最优解的那种「把约束折进转移」的思路，比记住它的代码更值钱。

总结

树上背包的约束是「选出来的节点连成一片」。朴素做法顺着子树合并，每棵子树都要枚举挑几个，复杂度里带一个 m²。

最优解换个方向：把树拍成 dfn 数组，按 dfn 从后往前做 01 背包。约束被折进两条转移里：不选当前点就跳过它整棵子树，选就往后走一格。

这份做法里，那个「有效结构」的定义是全部关键。定义想清楚了，两层循环就写完了；只想代码不想定义，很容易写成错的。

dfn 序把树上问题变成数组问题，这一手在树上背包、区间 dp、树上统计里反复出现。
