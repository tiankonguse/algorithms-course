next 当转移函数：树上的路径与数位 dp

next 数组最直接的用途是让主串指针不回头：主串指着一格，模式串退到某格，接着比。换两个场景。一棵树的向下路径要和一条链表对上，一个长度为 n 的字符串要落在字典序区间里且不含某个模式串。前者的匹配状态沿树分叉，后者要缩进 dp 的一维。next 在这两处的用法一致：它变成一个函数，给一个字符和当前状态，返回新状态。

零、二叉树中的链表

题目给一棵二叉树和一个单链表，问树里有没有一条一直向下的路径，路径上的值依次等于整条链表。

笨办法是把每个节点都当起点，从它往下逐层和链表比，比不过就换下一个起点。这种写法在随机形状的树上够用：2×105 个节点的随机树、19 个节点的链表恰好存在时，逐起点只有 27 次字符比较，而带着 next 状态走完树反而比了 7800 次。

把树换成一条 2×104 节点的链、链表换成 2000 个节点且永远配不上，比例就翻过来了：逐起点要 3800 万次比较、300 毫秒，带 next 的写法 38001 次、0.18 毫秒。两者的差别在于，「配到哪里」这件事有没有被带到下一个节点。

做法是把「已经匹配上链表的前 i 个」当成状态，沿树往下传。到了某个节点，先拿父亲给的 i 做修正：只要当前值不等于 list[i] 就沿 next 退，退到能接上或者退到 −1 为止。修正完的 i 加一，交给两个孩子。

这里有个和字符串匹配不一样的地方：每个分支各带一份 i。字符串匹配只有一个指针，因为在同一个位置上失配之后就再也不会回到那个位置；树上左右两条路都要试，谁也不能把对方的 i 改掉。递归的参数天然做到了这件事。

链表建 next 表要单独说一句：m = 1 时表里只有 nxt[0] = −1 这一项，没有 nxt[1]。照着 m ≥ 2 的写法去写 nxt[1] = 0 会越界。

// 链表的 next 表建在数组上；链表只有 1 个节点时表里只有 nxt[0] = -1 这一项
    vector<int> listNext(const vector<int>& s, int m) {
        if (m == 1) return vector<int>{-1};
        vector<int> nxt(m, 0);
        nxt[0] = -1;
        nxt[1] = 0;
        int i = 2, cn = 0;
        while (i < m) {
            if (s[i - 1] == s[cn]) nxt[i++] = ++cn;
            else if (cn > 0) cn = nxt[cn];
            else nxt[i++] = 0;
        }
        return nxt;
    }
// cur 是当前节点，i 是父亲传下来的匹配位置；配到 i == m 说明整条链表都串起来了
    bool findInTree(const vector<int>& s, const vector<int>& nxt, TreeNode* cur, int i) {
        if (i == (int)s.size()) return true;
        if (!cur) return false;
        while (i >= 0 && cur->val != s[i]) i = nxt[i];
        return findInTree(s, nxt, cur->left, i + 1) || findInTree(s, nxt, cur->right, i + 1);
    }

    bool isSubPath(const vector<int>& list, TreeNode* root) {
        vector<int> nxt = listNext(list, list.size());
        return findInTree(list, nxt, root, 0);
    }

i 涨到 m 就返回真，这时不必再管当前节点的孩子存不存在：链表最后一个值是在父亲那一层对上的，路径到此为止已经成立。剩下的失败判定落在「走到空指针」上。

状态沿着树往下走

每点一步模拟一次递归调用，右边是这个节点拿到 i 之后做的修正。切到另一组数据看空指针那一支。

写错的地方集中在最后一步：修正完把 i 交下去时忘了加一。这样每个节点都拿着同一个 i 递归，整条链表只能反复匹配它的第一个字符。随机小树上这个错法有 34.58% 与正解不同。

一、找到所有好字符串

题目给两个长度为 n 的字符串 s1、s2 和一个模式串 evil，数出长度 n、字典序落在 [s1, s2] 里且不含 evil 的字符串有多少个，答案对 109 + 7 取余。

「大于等于 s1 且小于等于 s2」不好直接做，拆成两次「小于等于某个上界」相减：先数 ≤ s2 的，再数 ≤ s1 的，两者相减把 < s1 的部分切掉。这样切完 s1 本身也被减掉了，可它是合法的，得补回来一个。漏掉这个加一的错法在随机小数据上有 80.33% 与正解不同。

数「小于等于上界」用数位 dp，状态三个：i 表示填到第几位，j 表示 evil 已经匹配上多长的前缀，free 表示前面填出来的前缀有没有比上界小。free 为 0 时这一位最多只能填到上界那一位，free 为 1 时 26 个字母随便填。

j 这一维靠 next 转移。已经匹配上 evil 的前 j 个字符，下一个字符是 pick 时，新的匹配长度不能只看 j + 1，要从 j 沿 next 一路退到 evil[j] 等于 pick 为止，退不动就退回 −1，表示重新从 evil 的头开始比。

// 已经匹配上 evil[0..j-1]，下一个字符是 pick，返回新的「已匹配长度减一」
    // 沿 nxt 一路退，均摊下来 O(1)
    int jump(char pick, const string& evil, int j) {
        while (j >= 0 && pick != evil[j]) j = nxt[j];
        return j;
    }

返回值是「匹配位置」而不是「匹配长度」，所以填表时要在它后面加一。忘了加一的错法有 52.62% 与正解不同。

// i：填到 s 的第几位；j：evil 已经匹配上的前缀长度；free 为 1 表示前缀已经小于 s
    int f(const string& s, const string& evil, int i, int j, int freeFlag) {
        if (j == m) return 0;
        if (i == n) return 1;
        if (dp[i][j][freeFlag] != -1) return dp[i][j][freeFlag];
        char cur = s[i];
        long long ans = 0;
        if (freeFlag == 0) {
            for (char pick = 'a'; pick < cur; pick++)
                ans += f(s, evil, i + 1, jump(pick, evil, j) + 1, 1);
            ans += f(s, evil, i + 1, jump(cur, evil, j) + 1, 0);
        } else {
            for (char pick = 'a'; pick <= 'z'; pick++)
                ans += f(s, evil, i + 1, jump(pick, evil, j) + 1, 1);
        }
        ans %= MOD;
        return dp[i][j][freeFlag] = ans;
    }

两次上界求解共用同一张 dp 表，中间要清空：dp 的取值依赖上界 s 本身，换了 s 就得重算。

int countGood(int n, const string& s1, const string& s2, const string& evil) {
        buildNext(evil);
        clear();
        long long ans = f(s2, evil, 0, 0, 0);
        clear();
        ans = (ans - f(s1, evil, 0, 0, 0) + MOD) % MOD;
        if (kmp(s1, evil) == -1) ans = (ans + 1) % MOD;
        return ans;
    }

实测取 n = 500、m = 50、一个固定的 evil（'a' 到 'e' 循环 10 遍），答案是 28935498，跑 5.86 毫秒，jump 一共比了 745 万次字符。把 jump 换成「每次重新算一遍最长 border」，同样的答案要 15.46 毫秒、3189 万次比较。

复杂度分析

做法关键操作时间空间
树上的链表，每个节点当起点重比每个起点沿路径比到不等为止最坏 O(n·m)O(h)
树上的链表，next 沿路径传状态每个节点做一次均摊 O(1) 的修正O(n + m)O(h + m)
好字符串，枚举所有字符串26n 个串逐个查 evilO(26n · n)O(n)
好字符串，数位 dp 加 next 转移n·m·2 个状态，每格枚举 26 个字母O(n·m·26·退位步数)O(n·m)

树问题的空间里 h 是树高，链状树上 h 就是 n。好字符串那行的「退位步数」是 jump 内部沿 next 走的平均长度，单次最坏退 m 步；m = 50 时实测平均 5.73 步（745 万次比较摊到 130 万次转移上）。状态数是 n·m·2 = 5 万，转移 130 万次，所以时间实际落在 O(n·m·26) 量级。递归写树时注意栈深度，链状树高到 105 会爆栈，题目规模里 h 只有几千，够用。

总结

树上的链表把「已匹配长度」当成随路径传递的状态，父亲算完修正值再交给两个孩子，每个分支各带一份，i 到 m 就是命中。链表长度为 1 时 next 表只有一项，建表要特判。

好字符串把匹配状态缩进 dp：i、j、free 三个维度，j 的转移由 jump(pick, j) 给出，返回值记得加一。字典序区间的写法是两次上界相减，再把下界那个串本身补回来。

两处写法的代价分别在 O(n + m) 和 O(n·m·26) 量级。链状树加长链表上，逐节点重比要 3800 万次比较，带状态的是 38001 次；n = 500、m = 50 的数位 dp 里，jump 比重新算 border 省掉四分之三的比较。

同一个形状再往前推一步就是 AC 自动机：把 jump 的那张 next 表按字母表预展开，多模式串的匹配也能一次扫完。
