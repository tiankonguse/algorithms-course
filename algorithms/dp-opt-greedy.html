优化枚举：只枚有希望的分支

前面两题的优化来自「转移有规律」。这页两题是另一路：枚举的分支本身可以砍掉一大半：要么大部分分支不可能最优，要么一大堆分支可以成批跳过。

零、自由之路：指到哪里算哪里

轮盘是一圈字符，指针停在 12 点位置，要按顺序拼出 key。每转一格花 1，对准了按一下也花 1，问拼完 key 最少花多少。

状态是 f(i, j)：指针停在轮盘第 i 个位置，要拼出 key[j...]。转移时如果 ring[i] 正好等于 key[j]，按一下就完事；否则要把指针转到某个等于 key[j] 的位置上去。

朴素写法是枚举轮盘上所有等于 key[j] 的位置，逐个算距离取最小。但轮盘是圆的，从 i 出发要够到某个字符，只有两条路值得走：顺时针碰到的第一个、逆时针碰到的第一个。更远的那个同字符位置不可能更优。走到它之前必然先路过近的那个，而在近的那个位置按完按钮之后的状态，跟走远路中途经过它时的状态完全一样，路程却短。

// f(i, j) : 指针停在轮盘 i 位置，要拼出 key[j...]，最小代价
    // where[v] 收集了字符 v 在轮盘上的全部下标，从小到大
    int f(int i, int j) {
        if (j == m) return 0;                                        // key 拼完了
        if (dp[i][j] != -1) return dp[i][j];
        int ans;
        if (ring[i] == key[j]) {
            ans = 1 + f(i, j + 1);                                   // 就在脚下，按一下
        } else {
            int v = key[j] - 'a';
            int jump1 = clockwise(i, v);                             // 顺时针最近
            int d1 = (jump1 > i ? jump1 - i : n - i + jump1);
            int jump2 = counterClockwise(i, v);                      // 逆时针最近
            int d2 = (i > jump2 ? i - jump2 : i + n - jump2);
            ans = min(d1 + f(jump1, j), d2 + f(jump2, j));           // 只需要这两种走法
        }
        dp[i][j] = ans;
        return ans;
    }

找这两个位置要快，所以先把每个字符在轮盘上的下标收集起来。where[v] 天然有序，二分就行。

// where[v] 有序，二分找 > i 的最靠左下标；找不到说明要绕一圈，回到最小下标
    int clockwise(int i, int v) {
        int l = 0, r = (int)where[v].size() - 1, find = -1, m;
        while (l <= r) {
            m = (l + r) / 2;
            if (where[v][m] > i) { find = m; r = m - 1; } else l = m + 1;
        }
        return find != -1 ? where[v][find] : where[v][0];
    }

找不到（说明要绕一圈）时返回 where[v][0] 或最后一个下标，正好对应绕过去的第一站。逆时针那个函数对称着写，找 < i 的最靠右下标。

一、砍掉多少分支

轮盘长 n、key 长 m，状态总数是 n·m，两种写法都一样。差别在每个状态里做了多少事：全枚要扫 n/c 个候选（c 是字符集大小），只枚两个就固定是 2。

ring 长 100、key 长 60 实测：字符集 26 时全枚 0.053 ms、只枚两个 0.018 ms；字符集缩到 2，全枚涨到 1.020 ms，只枚两个还是 0.072 ms。候选总数 300000 对 12000，差 25 倍。

只枚一个方向会怎样？随机 2 万组（轮盘长 1 到 8，key 长 1 到 6）实测，只留顺时针时答案偏大的比例：字符集 2 时 28.80%，字符集 3 时 38.63%，字符集 5 时 45.22%，字符集 10 时 49.31%。字符种类越多，同一个字符在轮盘上出现的位置越分散，两个方向的优劣就越难猜。

二、演示：每一步只看两个候选

下面这个演示把最优路线走一遍。每一步列出顺、逆两个候选，算出「走到那里的距离 + 从那里拼完剩余 key 的代价」，取小的那个。

自由之路：逐字符决策

三、最长子数组：先做一个能二分的数组

给一个可能有正有负的数组 arr 和整数 k，求累加和 ≤ k 的最长子数组长度。数组里有负数，窗口不能简单用双指针。

最直接的写法是枚举所有子数组，O(n²)。换个角度：以第 i 个数结尾的子数组，长度是 i − pre + 1，其中 pre 是开始位置的前一个下标。要求 sum(0..i) − sum(0..pre) ≤ k，也就是 sum(0..pre) ≥ sum(0..i) − k。想让长度最大，就要找最靠左的、满足这个条件的 pre。

前缀和本身乱序，二分不了。但注意：我们要的是「存在某个 ≤ pre 的位置，它的前缀和 ≥ 某个值」。定义 sums[i] 为前 i 个位置里前缀和的最大值，那 sums 单调不降，「存在」这个条件就变成查 sums 这一个单调数组。

// sums[i] : 前 i 个数的所有前缀和里的最大值，i 从 0 开始，所以 sums 单调不降
    int compute1() {
        vector<int> sums(n + 1, 0);
        long long sum = 0;
        for (int i = 0; i < n; i++) {
            sum += nums[i];
            sums[i + 1] = (int)max(sum, (long long)sums[i]);
        }
        int ans = 0;
        long long s = 0;
        for (int i = 0; i < n; i++) {
            s += nums[i];
            int pre = findFirst(sums, (int)(s - k));                 // 最靠左的、前缀和 >= s-k 的位置
            ans = max(ans, pre == -1 ? 0 : i - pre + 1);
        }
        return ans;
    }

这样是 O(n log n)。

四、最优解：把窗口的推进整段化

再往前一步要两个观察。第一个是窗口的加速建立：从 i 开始往右扩，如果后面那一段的和已经是负的，那它整段吞进来只会让总和变小、长度变长，没有理由不吞。于是先把数组从右往左预处理成若干段，每段是「从某处开始的最小和段」：

// minSums[i] : 从 i 开始往后，累加和最小的那段（至少包含 nums[i]）的和
    // minSumEnds[i] : 那段的结束位置，整段可以一次吞进来
    void buildMinSums() {
        minSums[n - 1] = nums[n - 1];
        minSumEnds[n - 1] = n - 1;
        for (int i = n - 2; i >= 0; i--) {
            if (minSums[i + 1] < 0) {                                // 后面那段的和是负的，接过来更划算
                minSums[i] = nums[i] + minSums[i + 1];
                minSumEnds[i] = minSumEnds[i + 1];
            } else {
                minSums[i] = nums[i];                                // 自己单独成段
                minSumEnds[i] = i;
            }
        }
    }

    int compute2() {
        buildMinSums();
        int ans = 0, end = 0;
        long long sum = 0;
        for (int i = 0; i < n; i++) {
            while (end < n && sum + minSums[end] <= k) {             // 一整段一整段地吞
                sum += minSums[end];
                end = minSumEnds[end] + 1;
            }
            if (end > i) {
                ans = max(ans, end - i);
                sum -= nums[i];                                      // 窗口左端走一步
            } else {
                end = i + 1;                                         // 这一段本身就超限，整个跳过
            }
        }
        return ans;
    }

第二个观察是可能性的淘汰：如果从 i 开始连 i 这一段本身都超过了 k，那以 i 开头的窗口根本扩不出来，直接把 i 丢掉，end 推到 i + 1。窗口一旦扩不出来就不再回头，每个位置最多进出一次，总代价 O(n)。

随机数据（元素 −20 到 30，n = 100000）下这套预处理把数组切成 38315 段，平均段长 2.61。段越碎，一次吞掉的越少，但每个位置仍然只被处理一次。

六、写错的地方

位置写法与正确解不一致的比例
compute1sums 不做单调化，直接拿前缀和数组二分19.39%
compute2窗口左端走一步时减 minSums[i]5.17%
compute2窗口扩不出来时不推进 end19.34%
compute2窗口按单元素扩，不按整段28.84%

第一条最隐蔽：前缀和数组本身不单调，二分找到的「最左 ≥ num」没有意义，但在前缀和本身恰好递增的样本上它又是对的，所以只有 19.39% 的样本能抓住。

第三条要留意：窗口扩不出来时如果不写 end = i + 1，end 会停在 i 的位置，下一轮 end > i 永远不成立，答案一直停在 0。

七、代价对比

n = 10000 时暴力枚举 26.16 ms、compute1 0.295 ms、compute2 0.058 ms。n = 1000000 时 compute1 41.268 ms、compute2 5.693 ms，差 7.2 倍。两者都是线性的量级，差的是常数和一个 log。

八、复杂度分析

题目版本时间空间
自由之路枚举全部匹配位置O(n·m·n/c)O(n·m)
自由之路只枚顺逆最近两个O(n·m·log(n/c))O(n·m)
最长子数组枚举全部子数组O(n²)O(1)
最长子数组单调前缀和 + 二分O(n log n)O(n)
最长子数组minSums + 整段窗口O(n)O(n)

自由之路那行的 c 是轮盘字符集大小；二分是在 where[v] 上做的，长度 n/c，所以严格说每个状态是 O(log(n/c))。轮盘短、字符少的时候这个 log 可以忽略，直接线性扫 where[v] 也行。

最长子数组的 O(n) 版本空间是 O(n)：minSums 和 minSumEnds 两个数组。省空间可以把它们并进一次倒着算的过程里，但那样窗口推进时要现场算段，代码会绕。

九、总结

两题的优化都是「看出大部分枚举分支没有价值」。自由之路里，顺着圆走，路过近的同字符位置之后再走到远的那个，状态一样、路程更长，所以远的直接淘汰；最长子数组里，负和段一次吞进来不吃亏，扩不出来的开头直接丢掉。

这类判断属于贪心，写的时候要能说清「为什么被砍掉的那种情况不会更好」，不然只是在碰运气。验证的办法也简单：写一个枚举全部可能性的暴力版，小数据上逐组对拍。这页四个数字里的错误率都是这么量出来的。

动态规划专题里优化枚举的手段还有很多：单调队列、斜率优化、四边形不等式。它们的共同点和这里一样：先写出带枚举的转移，再盯着那段枚举看规律。
