接头密匙：差分序列进前缀树

两把密匙一致，比的是差分的形状。把差分序列压成字符串，插进一棵 12 路前缀树，m 把 b 密匙各查一次前缀计数，答案就挂在节点 pass 上。

零、背景

密匙是一组数字序列。b 和 a 一致的定义：b 的长度不超过 a，并且对每一个位置，b 的相邻差和 a 的相邻差相等。

也就是说，b 的差分序列必须是 a 的差分序列的前缀。密匙 [3,6,50,10] 的差分是 3、44、-40；[3,6] 的差分是 3，是它的前缀，所以 [3,6] 和 [3,6,50,10] 一致。密匙本身的值差多远无所谓，比的是形状。

朴素做法：m 把 b 对 n 把 a，逐对比差分。m=n=1000、每把密匙 100 个数，就是 100 万对，每对最多比 99 个差分。一对比到不等就停，可一旦差分长得像，就得一路比到底。

同一个 a 的差分前缀会被很多 b 反复比对。这个比较能复用吗？

一、差分序列转字符串

[3,6,50,10] 的差分是 3、44、-40，拼成字符串「3#44#-40#」。

# 是分隔符。没有它，「3,44,-40」会连成一串「344-40」，边界读不出来，更危险的是相邻两项会混：差分 [1,23] 和 [12,3] 分别拼成「123」和「123」，变成同一个串，两把密匙被错误地判成一致。

负号单独算一个字符，插树的时候占一条路，路径映射成 11；# 占一条路，映射成 10；数字 0~9 占十条。一共 12 条路。

二、12 路前缀树

把每把 a 密匙的差分串插进树，每把 b 密匙查一次前缀计数：走完 b 的差分串，停在节点的 pass 就是「有多少把 a 和这把 b 一致」。

为什么查前缀而不是查整串：一致的定义就是差分前缀相等，b 的差分串只要在树里找到一条前缀路径即可，后半截不用管，这正是前缀树的活。

单元素密匙没有差分，串是空的，插入时只在根节点 pass 加一；查询空串时走零步，返回根 pass，也就是所有 a 的数量。单元素 b 和任何 a 都一致，答案本来就该是 n，两个边界正好对上。

静态数组的实现和上一讲完全一个套路，只把 26 路换成 12 路，查路的下标换成 path 映射：

// 12 路：'0'~'9' 走 0~9，# 走 10，- 走 11
    static const int MAXN = 2000001;
    static int tree[MAXN][12], pass[MAXN], cnt;

    int path(char c) {
        if (c == '#') return 10;
        if (c == '-') return 11;
        return c - '0';
    }

    // 插入一串差分：沿路走，没路就建，pass 一路累加
    void insert(string word) {
        int cur = 1;
        pass[cur]++;
        for (int i = 0, p; i < word.size(); i++) {
            p = path(word[i]);
            if (tree[cur][p] == 0) {
                tree[cur][p] = ++cnt;
            }
            cur = tree[cur][p];
            pass[cur]++;
        }
    }

    // 数前缀：走完返回 pass；半路没路就是 0
    int prefixCount(string pre) {
        int cur = 1;
        for (int i = 0, p; i < pre.size(); i++) {
            p = path(pre[i]);
            if (tree[cur][p] == 0) {
                return 0;
            }
            cur = tree[cur][p];
        }
        return pass[cur];
    }

用完要 clear 一次：静态数组的节点编号会残留，下次 build 从 1 重新发号，旧的编号还在数组里，会被当成已有路径走错节点。

三、复杂度与实测

时间 O(a 差分总字符数 + b 差分总字符数)：插入和查询都只沿差分串走一遍，每步查路 O(1)。空间 O(树上节点数)，差分值多宽，树就多宽，跟密匙本身的值域无关。

实测（本机 g++ -O2，m=n=1000、每把密匙 100 个数）：

差分随机时，暴力每对比几步就停，0.8ms 跑完，比 Trie 的 8.0ms 还快。暴力的早停沾了随机数据的光。

差分全等时，比如所有密匙都是等差序列，每对都一路比到底：暴力 70.2ms，Trie 3.4ms，二十倍的差距。

差别不在常数，在复杂度形状：暴力是 O(m×n×L)，L 是密匙长度，m=n=1000、L=1e5 时最坏 1e11 次比较；Trie 是 O((a 总字符 + b 总字符)×10)，跟差分长什么样没关系，最坏也就是所有差分都不同、每个字符都新建节点。

复杂度分析

做法时间说明
暴力O(m×n×L)逐对比差分，最坏每对比到底
前缀树O(总差分字符数)插入一次、查询一次，每字符 O(1)

空间 O(树上节点数)，上限是 a 差分总字符数。MAXN 按这个量级开，实测 2000001 在 1000×100 的规模下用了约 62 万节点，够用。

总结

一致判定被拆成两半：把差分序列压成字符串，用 # 和 - 保证分隔和符号不丢失；前缀匹配交给前缀树，查询一次 O(len)。

单元素密匙的空串边界、静态数组的 clear，都是这类静态实现容易漏的细节，漏一个就错一片。
