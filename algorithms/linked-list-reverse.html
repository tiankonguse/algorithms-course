单双链表及其反转

上一讲把数据结构拆成了连续结构和跳转结构两种零件。链表是最纯粹的跳转结构，除了值和一根跳转指针什么都没有。反转它只有十几行代码，却能把「指针到底是个什么变量」这件事问得清清楚楚。

零、背景

单链表在笔试和面试里出现的频率高得不成比例。原因不是它难，而是它刚好卡在一个位置上：写对需要理解内存，写错又非常容易，几行代码里任何一个顺序写反都会挂。

这一讲顺着三个问题往下走：变量里装的是什么，单链表怎么反转，双链表多出来的那根指针怎么处理。反转之外的内容，后面讲栈和队列时还会再碰见。

一、问题

给一个单链表的头节点 head，把整条链反过来，返回新链表的头。原链表的最后一个节点变成新链表的第一个。

双链表的版本多一根往前指的指针，反转时两根都得改。反转链表是单链表版的模版题。

限制很明确：不许新开一条链把值抄一遍，只能在原来的节点上改指针。所以额外空间得是 O(1)。

二、变量里装的是什么

先说一件和语言有关的事。函数拿到的参数永远是副本，区别只在于副本里装的是值还是地址。

装值的时候，在函数里给副本赋值，外面那个变量一点没动。实测：void f(int a){ a = 0; } 调用完外面还是 10。

装地址的时候要分两件事看。给副本本身赋值，照样改不动外面；但通过副本去写它指向的那块内存，外面看得见，因为副本和外面那个变量指向的是同一块内存。

这四条里最容易搞混的是第二条：p = nullptr 是把副本改了，p->val = 6 是顺着副本里那个地址去改内存。前者无效，后者有效。

真想让函数改到调用方的指针本身，得把那个变量本身传进去，也就是引用或者二级指针。实测两种写法调用完外面的指针都变成了 0x0。

void f(int a) { a = 0; }

    void g1(ListNode* p) { p = nullptr; }
    void g2(ListNode* p) { p->val = 6; }

    void g3(int* c) { c = nullptr; }
    void g4(int* c) { c[0] = 100; }

    void g5(ListNode*& p) { p = nullptr; }
    void g6(ListNode** p) { *p = nullptr; }

数组是同一回事：c = nullptr 改不动，c[0] = 100 改得动，实测调用完 c[0] 就是 100。

三、单链表与双链表的定义

单链表的节点只有两样东西：一个值，一个指向下一个节点的地址。双链表多一个指回上一个节点的地址。

struct ListNode {
        int val;
        ListNode* next;
        ListNode(int v) : val(v), next(nullptr) {}
    };

    struct DoubleListNode {
        int val;
        DoubleListNode* last;
        DoubleListNode* next;
        DoubleListNode(int v) : val(v), last(nullptr), next(nullptr) {}
    };

节点是 new 出来的，散落在堆上，谁和谁都不挨着。实测相邻两个节点的地址差是 32、-16、32、48、80 字节，有正有负。

sizeof(ListNode) 实测 16 字节，其中 4 字节是值、8 字节是指针，剩下 4 字节是对齐补出来的；双链表节点 24 字节。

所以「链表」这个词指的不是内存里的形状，而是用指针串出来的逻辑顺序。内存里它们各在各的地方。

四、单链表怎么反转

三个指针就够了：pre 是已经反转好的那一段的头，head 是还没处理的那一段的头，next 用来临时存一下后面是谁。

每轮循环做四件事，一个节点就翻过来了。

ListNode* reverseList(ListNode* head) {
        ListNode* pre = nullptr;
        ListNode* next = nullptr;
        while (head != nullptr) {
            next = head->next;   // 1) 先把后面存下来
            head->next = pre;    // 2) 箭头掉头
            pre = head;          // 3) pre 挪到这一节点
            head = next;         // 4) 处理下一个
        }
        return pre;
    }

实测 n = 6 时四条赋值各执行 6 次，一共 24 次，正好 4n。每个节点的代价是常数，跟它在链上多远无关。

第一步为什么不能省，看这张图。

箭头一改，head->next 里存的就是 pre 了，原来的后继没有任何人记得。所以必须先把后继抄到 next 里，再动手改箭头。

演示　单链表反转，逐个子步骤走一遍
已经反转好的一段 这一步正在动的节点 / 箭头 还没处理的一段

跑一遍就能看出一条不变式：每轮循环结束时，pre 是已反转段的头，head 是未反转段的头，两段拼起来仍然是原来那条链。

循环退出时 head 是空，说明未反转段没了，pre 就是整条链的新头。空链表和单个节点都落在这条不变式里，不用单独判。

五、双链表怎么反转

双链表多了 last，反转时它和 next 要一起掉头，否则新链表顺着 last 走会走歪。

DoubleListNode* reverseDoubleList(DoubleListNode* head) {
        DoubleListNode* pre = nullptr;
        DoubleListNode* next = nullptr;
        while (head != nullptr) {
            next = head->next;
            head->next = pre;
            head->last = next;
            pre = head;
            head = next;
        }
        return pre;
    }

比单链表多一行 head->last = next，实测每节点 5 次赋值，n = 6 时 30 次。

还有另一种写法：每个节点只把 last 和 next 交换一下，然后沿着交换后的 last往后走。实测两种写法赋值次数一样，结果也一样，反向遍历都能走回原序 1 2 3 4 5。

不管哪种写法，反转完都有两条边要检查：新头的 last 是空，新尾的 next 是空。这两条对拍时逐组验过，漏一条链表就是断的。

六、竞赛里通常怎么写

比赛里几乎不写 new Node。一是慢，二是散在堆上的节点没法预估占多少。常见做法是拿数组拼出链表：val[] 存值，nxt[] 存下一个的下标，head 存第一个的下标。

跳转本来只需要一个「指向谁的编号」，而编号天然可以做下标。于是连续结构直接把跳转结构装了进去。

const int MAXN = 1000005;
    int val[MAXN], nxt[MAXN], head = -1, tot = 0;

    void pushFront(int v) {
        val[++tot] = v;
        nxt[tot] = head;
        head = tot;
    }

    int reverseArrList(int head) {
        int pre = -1, cur = head, next;
        while (cur != -1) {
            next = nxt[cur];
            nxt[cur] = pre;
            pre = cur;
            cur = next;
        }
        return pre;
    }

反转的写法和指针版一模一样，只是把空指针换成了 −1。

实测反转二百万个节点：new 出来的链表 1.80 毫秒，静态数组版 0.75 毫秒，直接对数组做 std::reverse 0.50 毫秒。三条都是 O(n)，常数差在寻址上。

顺带一提，静态数组版每个节点只占 8 字节（值 + 下标），new 版是 16 字节，二百万个节点分别是 15 MB 和 30 MB。

七、几个会踩的地方

递归版写出来更短，但栈是 O(n) 的。实测在 macOS 默认栈（8176 KB）下，n = 150000 能跑完，n = 200000 直接段错误。链表长到十万这个量级就别用递归了。

反转后原来的头节点变成尾节点，它的 next 必须是空。漏掉这一步链表会成环，任何一次遍历都停不下来。

函数的返回值是新头 pre，不是原来的 head。反转结束后 head 已经走到空了，拿它当答案会得到一个空链表。

判断循环条件一律用 while (head != nullptr)，别先去判 n == 0 或 n == 1。这两种情况循环体分别执行 0 次和 1 次，结果本来就是对的。

复杂度分析

n 是节点个数。反转过程中的每一步都是常数次赋值，没有嵌套，也没有回头重扫。

八、最后

把四步顺序背下来不难，难的是随时能说出每一步之后内存里是什么样。后面讲栈、队列、邻接表、并查集时都是同一套看法：先认清变量里装的是值还是地址，再谈改哪个有效。
