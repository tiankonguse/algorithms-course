路径上的词频统计

树上一条路径，把路上所有边改成同一种值，最少改几条。答案不用真去走一遍路径：每个点带一份 26 个计数器的前缀和，两端各拿一份、减掉最低公共祖先的两倍，每条查询 26 次加减就结束。

零、背景

上一页的跳表在每一格挂了一个最小值。这一页换一种挂法：不挂在跳表上，挂在每个点自己身上——weightCnt[u][w] 记「从根到 u 的路径上，权值为 w 的边有几条」。它就是数组上的前缀和搬到树上：路径 a 到 b 的词频，等于 a 的前缀、b 的前缀相加，再减掉两份 LCA 的前缀。

为什么是 26：这题的边权只有 1 到 26。26 个计数器看着多，摊到一次查询上只是 26 次数组访问，而路径本身可能有三千多条边。

一、问题

一棵 n 个节点的树，节点编号 0 到 n − 1，每条边带一个 1 到 26 的权值。m 条查询 (a, b)，问 a 到 b 的最短路径上，把所有边变成同一种值最少要改几条。1 ≤ n ≤ 10⁴，1 ≤ m ≤ 2 × 10⁴。

答案的形状一句话就能写出来：路径上有 L 条边，出现最多的那个权值有 mx 条，改 L − mx 条——出现最多的全部留下，其余每条改一次。

难的是 L 和 mx 怎么快速拿到。朴素做法沿父亲指针把路径走一遍、逐条统计，一条查询 O(路径长度)。随机树上平均路径只有十几条边，这个做法其实不慢；可树一旦退化成一条链，n = 10⁴ 时平均路径三千多条边，实测同一批查询，逐条走要 211.6 ms，26 个计数器只要 1.45 ms，差 146 倍。

二、每个点一份前缀计数

DFS 时从父亲往儿子拷一份计数器再加一，根自己那份全零：

const int MAXN = 10001;
    const int MAXW = 26;

    int headEdge[MAXN], edgeNext[MAXN << 1], edgeTo[MAXN << 1], edgeValue[MAXN << 1];
    int tcnt;
    int weightCnt[MAXN][MAXW + 1];

    void dfs(int u, int w, int f) {
        if (u == 0) {
            memset(weightCnt[u], 0, sizeof weightCnt[u]);
        } else {
            memcpy(weightCnt[u], weightCnt[f], sizeof weightCnt[u]);
            weightCnt[u][w]++;
        }
        for (int e = headEdge[u]; e != 0; e = edgeNext[e]) {
            if (edgeTo[e] != f) {
                dfs(edgeTo[e], edgeValue[e], u);
            }
        }
    }

查询时取三个点的计数器做差：

路径上权值 w 的条数 = weightCnt[a][w] + weightCnt[b][w] − 2 × weightCnt[c][w]，c 是 LCA。

逻辑和两点距离公式一模一样：根到 a 与根到 b 在 LCA 以上完全重合，两份相加把这一段算了两次，减两份刚好。26 个权值各做一遍这个减法，同时记下最大值与总和。

三、LCA 一次性算完

查询全部提前给定，这正好是离线场景。Tarjan 算法一趟 DFS 配一个并查集，把 m 条查询全部答完，代价 O(n + m)，比建跳表的 O(n log n) 还省：

1）进入 u，先把所有儿子递归完；
2）然后看挂在 u 上的每条查询 (u, v)：如果 v 已经访问过，这条查询的 LCA 就是 find(v)——v 所在并查集的根，此刻正好指向「u 与 v 的最低公共祖先」；
3）最后把 father[u] 设成自己的父亲，向上归队。

关键在第 2 步：递归完 v 的整棵子树之后、还没退出 u 的父亲之前，并查集里 v 到 u 路径上的点全都指向 u。这时从 v 那头问一次 find，拿到的正是 LCA。

每条查询要在两端各挂一次（addQuery(a, b, i) 与 addQuery(b, a, i)），因为不知道 DFS 会先到哪一头。

四、代码

查询挂链与并查集：

const int MAXM = 20001;

    int headQuery[MAXN], queryNext[MAXM << 1], queryTo[MAXM << 1], queryIndex[MAXM << 1];
    int qcnt;
    bool visited[MAXN];
    int father[MAXN];
    int lcaAns[MAXM];

    void addQuery(int u, int v, int i) {
        queryNext[qcnt] = headQuery[u];
        queryTo[qcnt] = v;
        queryIndex[qcnt] = i;
        headQuery[u] = qcnt++;
    }

    int find(int i) {
        if (i != father[i]) {
            father[i] = find(father[i]);
        }
        return father[i];
    }

    void tarjan(int u, int f) {
        visited[u] = true;
        for (int e = headEdge[u]; e != 0; e = edgeNext[e]) {
            if (edgeTo[e] != f) {
                tarjan(edgeTo[e], u);
            }
        }
        for (int e = headQuery[u]; e != 0; e = queryNext[e]) {
            int v = queryTo[e];
            if (visited[v]) {
                lcaAns[queryIndex[e]] = find(v);
            }
        }
        father[u] = f;
    }

主流程四步：建图、DFS 铺计数器、Tarjan 求出全部 LCA、逐条做 26 次减法。

vector<int> minOperationsQueries(int n, vector<vector<int>> &edges,
                                    vector<vector<int>> &queries) {
        build(n);
        for (auto &e : edges) {
            addEdge(e[0], e[1], e[2]);
            addEdge(e[1], e[0], e[2]);
        }
        dfs(0, 0, -1);
        int m = queries.size();
        for (int i = 0; i < m; i++) {
            addQuery(queries[i][0], queries[i][1], i);
            addQuery(queries[i][1], queries[i][0], i);
        }
        tarjan(0, -1);
        vector<int> ans(m);
        for (int i = 0; i < m; i++) {
            int a = queries[i][0], b = queries[i][1], c = lcaAns[i];
            int allCnt = 0, maxCnt = 0;
            for (int w = 1; w <= MAXW; w++) {
                int wcnt = weightCnt[a][w] + weightCnt[b][w] - 2 * weightCnt[c][w];
                maxCnt = max(maxCnt, wcnt);
                allCnt += wcnt;
            }
            ans[i] = allCnt - maxCnt;
        }
        return ans;
    }

五、复杂度分析

步骤时间复杂度空间复杂度
DFS 铺 26 个前缀计数器O(26n)O(26n)
Tarjan 求全部 LCAO(n + m)O(n + m)
单条查询做 26 次减法O(26)O(1)
合计O(26(n + m))O(26n + m)

按题目上限算：n = 10⁴ 时 weightCnt 占 10⁴ × 27 × 4 ≈ 1.05 MiB，查询挂链 2 × 2 × 10⁴ 个 int 约 0.6 MiB。对照另一种选择：跳表方案要 n × 14 × 4 ≈ 0.54 MiB 的表加 O(log n) 一次查询，n = 10⁴、m = 2 × 10⁴ 的实测里倍增总共 2.56 ms、Tarjan 0.60 ms。查询不追加强制在线时，离线的 Tarjan 又快又省。

六、最后

这一页的三件事：把「数路径上的边」拆成「26 个权值各数一遍」；每个点存一份从根下来的前缀计数，路径词频用三次读数相减得到；查询全给齐时用 Tarjan 一趟 DFS 配并查集把 LCA 一次算完。

树退化成链时，逐条走路径的做法要 146 倍的时间；随机树上平均路径只有 15.77 条边、最长 31，两种做法差距不大，但题面不保证树长什么样，按最坏情况选就对了。

出现最多的权值平均只占 2.63 条边，也就是说 83% 的边都得改——这题真正的「工作量」全在改边上，统计本身便宜得很。
