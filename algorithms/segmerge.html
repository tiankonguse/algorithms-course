线段树的合并：开点权值线段树与势能分析

一个节点配一棵权值线段树，父节点要把所有儿子的信息汇总起来，这是树上统计题反复出现的形状。把儿子的元素逐个插进父亲的树太慢，线段树合并换了个思路：两棵树同位置的节点直接叠在一起。这一页讲合并的三条规则、一次合并的单步过程，以及为什么所有合并加起来的总代价只有 O(n log n)。

零、背景

这一讲的前置是开点线段树和可持久化线段树；题目2 还要并查集，题目3、题目4 还要树上倍增求 LCA 和树上差分。

下节课讲两件事：用合并加速树形 dp 的转移，以及线段树的分裂。这一页和下一页（五道题目）只覆盖合并本身。

一、问题：n 棵小树要合成几棵大树

值域是 1 到 V，一开始有 n 棵权值线段树，每棵里只有很少的元素，用开点的方式存，每棵占 O(log V) 个节点。接下来要按某种顺序把它们两两合并，合并出来的树还要支持查询：区间和、第 k 小、最大词频等等。

树上题目里最常见的形状是：原树每个点 u 有一棵权值线段树，要求 u 的答案时，这棵树里必须已经装好 u 整棵子树的全部信息。于是 u 的树 = 自己的元素 + 所有儿子的树合并的结果。

二、朴素做法为什么慢

最直接的做法是遍历 t2，把里面的每个元素逐个 add 进 t1。一次插入 O(log V)，t2 里元素数是它代表的元素个数，最坏到 O(n)，于是合并一对是 O(n log V)，n 对下来 O(n² log V)，n = 10⁵ 时完全不能接受。

静态的子树统计确实也可以走 dfs 序加主席树，前缀相减就得到子树。但一旦「要汇总的那些元素」不是一个固定的 dfn 区间，比如连通块会随着加边而合并（题目2），或者每个点的信息来自树上差分的四个标记点（题目3、题目4），区间相减这条路就不通了，得换成真正的合并。

三、合并的三条规则

设 t1、t2 是同一段值域 [l, r] 上的两个节点，merge(l, r, t1, t2) 返回合并后的节点：

1，如果 t1 == 0 或者 t2 == 0，直接返回 t1 + t2。空节点可以忽略，不空的那个就是结果，连递归都不用进。

2，如果 t1 和 t2 都不为 0，并且 l == r，说明到了叶子，把 t2 的信息加到 t1 上（计数相加、取最大值……看你维护的是什么），返回 t1。

3，剩下的情况：t1、t2 都不为 0 且区间还能再分。t1 接受 t2 的全部信息并由 t1 当总节点，递归合并左右两对儿子，把返回值挂成 t1 的左、右孩子，最后 up(t1) 重新算自己的信息，返回 t1。

可以发现合并是「就地」的：结果永远是 t1 那棵树长出来的，t2 的节点只会被丢弃或者被挂到 t1 下面。整个过程一个节点都不新建。

具体到这个例子，t1 = {1, 3}、t2 = {2, 3}，值域 1~4。区间 1~2 这一支上，t1 只有叶子 1、t2 只有叶子 2，两边一合并就是规则 1 的「返回 t1 + t2」，一次比较就完事；区间 3~4 这一支两边都有叶子 3，走到规则 2，计数相加变成 2。

四、一次合并的单步过程

下面这个演示把上面那次合并拆成每一步，左边是 t1 当前的树，中间是 t2（被丢弃的节点画成虚线），右边是递归栈和几个计数。点「下一步」跟着走一遍。

merge(t1, t2) 单步演示

t1 = {1, 3}，t2 = {2, 3}，值域 1~4。橙色节点是从 t2 那边过来的，虚线节点是已经被丢弃的。走完可以看到：4 次「两边都不为空」的调用，正好销毁 4 个节点。

完整实现的骨架就是下面两句话：add 是开点插入，merge 是合并。siz 换成别的信息（最大值、词频）时，只要同步改 up 和叶子上的合并动作，merge 的结构一行都不用动。

// 开点线段树：单点增加，i 为 0 表示空节点，用到才开
    int add(int jobi, int l, int r, int i) {
        int rt = i;
        if (rt == 0) {
            rt = ++cntt;
        }
        if (l == r) {
            siz[rt]++;
        } else {
            int mid = (l + r) >> 1;
            if (jobi <= mid) {
                ls[rt] = add(jobi, l, mid, ls[rt]);
            } else {
                rs[rt] = add(jobi, mid + 1, r, rs[rt]);
            }
            up(rt);
        }
        return rt;
    }

    // 线段树合并：t1 吸收 t2，返回合并后的根
    int merge(int l, int r, int t1, int t2) {
        if (t1 == 0 || t2 == 0) {
            return t1 + t2;
        }
        if (l == r) {
            siz[t1] += siz[t2];
        } else {
            int mid = (l + r) >> 1;
            ls[t1] = merge(l, mid, ls[t1], ls[t2]);
            rs[t1] = merge(mid + 1, r, rs[t1], rs[t2]);
            up(t1);
        }
        return t1;
    }

五、树上从叶向根一路合并

合并本身写好了，用起来就是一次后序遍历：递归算完每个儿子，把儿子的树并进自己，然后在这棵汇总好的树上查自己的答案。叶子没有儿子，树里只有自己那一个元素。

查询的时机要留意：必须在所有儿子都并进来之后才查，所以 ans[u] 的赋值放在循环之后。这一句顺序写反了，答案就变成「只统计了部分子树」。

这七个点对应的答案依次是 2 1 0 0 0 0 0，下面题目1 的页面会用同一棵树把细节展开。

六、复杂度分析

值域写成 V（离散化之后 V ≤ n）。先看空间：每棵树是单点插入的开点线段树，占 O(log V) 个节点，n 棵一共 O(n log V)；合并只丢弃节点、从不新建，所以峰值也是 O(n log V)。

时间用势能分析。取势能 Φ = 当前所有线段树的节点总数。一次 merge 调用里如果 t1、t2 都不为 0，返回的一定是 t1，t2 这个节点从此不再被任何指针引用，Φ 至少减 1。Φ 初始是 O(n log V) 且不会增加，所以这类调用的总次数 ≤ O(n log V)。如果有一个为 0，函数 O(1) 就返回了，而这种调用只可能从上面那类调用里成对派生出来（每次递归最多派生 2 个），数量同样是 O(n log V)。

合起来，不管合并的顺序是什么、合并多少对，全部合并行为加起来的总时间是 O(n log V)，加上建树的 O(n log V)，整体 O(n log V)。

V 是值域大小，离散化之后 V ≤ n，所以 O(n log n) 和这里的 O(n log V) 是一回事。数组开多大也从这个数来推：题目1 的 MAXT 取 MAXN * 40，就是给每条根到叶的路径留了足够余量。

七、最后

合并这件事本身只有十几行，真正要紧的是两个认识：一是结果永远长在 t1 上、一个节点都不新建，所以空间可以提前算死；二是「两边都不为空」的调用每发生一次就永久销毁一个节点，于是总次数被初始节点数锁住。有了这两条，剩下的问题就变成「每个点上该维护什么信息」。

下一页拿这一讲的五道题看五种不同的信息：子树里更大的能力值、连通区第 k 小、最大词频、两种树上差分的计数，以及合并时顺手统计的逆序对。
