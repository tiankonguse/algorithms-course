最小的必要团队：顺着决策顺序把方案读出来

从 dp 表读出方案有两种走法。这一题的状态里本来就带着「当前考虑第几个人」，所以还原可以顺着决策的顺序正着走一遍，每到一个 i 就问一次「当初选没选它」。

零、问题

一份需求的技能清单 req_skills，一份备选人员名单 people，people[i] 是第 i 号人掌握的技能列表。要挑出规模最小的团队，让清单上每项技能都至少有一名成员掌握。返回人员编号，顺序任意，题目保证答案存在。

只问最小规模的话，一个整数就够了。现在要把具体是哪几个人也交出来。

一、先把技能压成位

清单里的技能依次编号 0 到 n-1，每个人掌握的技能压成一个 n 位整数 arr[i]，第 k 位是 1 就表示他掌握第 k 项技能。清单里没有的技能直接忽略，它不影响任何判断。

这样「团队掌握了哪些技能」就是若干个 arr 按位或，凑齐全部技能等价于或出来的结果等于 (1 << n) - 1。n 卡在 20 以内的时候这套表示很好用。

二、状态与转移

状态是 (i, s)：现在考虑第 i 号人，已经覆盖的技能集合是 s。f(i, s) 返回「从 i 号人往后挑，把 s 之外还缺的补齐，最少要几个人」。

两个边界：s 已经等于全集，返回 0；人用完了（i == m）技能还没齐，这条路无效，返回一个很大的数。转移就是「不要 i 号人」和「要 i 号人」取小。

    
// arr[i] : 第 i 号人掌握必要技能的状况，用位表示
    // f(i, s) : 用 i.... 这些人把 s 之外还没凑齐的技能补齐，至少要几个人
    int f(int i, int s) {
        if (s == (1 << n) - 1) return 0;               // 技能齐了
        if (i == m) return INT_MAX;                    // 人没了技能还没齐，这条路无效
        if (dp[i][s] != -1) return dp[i][s];
        int p1 = f(i + 1, s);                          // 可能性 1 : 不要 i 号人
        int p2 = INT_MAX;                              // 可能性 2 : 要 i 号人
        int next2 = f(i + 1, s | arr[i]);
        if (next2 != INT_MAX) {                        // 后续有效才 +1，否则会溢出
            p2 = 1 + next2;
        }
        dp[i][s] = min(p1, p2);
        return dp[i][s];
    }

那个 next2 != INT_MAX 的判断不能省。省掉之后 1 + INT_MAX 会溢出成负数，看上去像「选这个人特别划算」，min 一下就把无效方案当成最优解了。

三、还原：再顺着 i 走一遍

表填完之后，dp[i][s] 存的就是 f(i, s)。从 i = 0, s = 0 出发正着走：如果 dp[i][s] 跟 dp[i+1][s] 不一样，说明「不要 i」这条路给不出最优值，当初的决策必然是选了 i 号人。

    
// 顺着 i 从小到大再走一遍：dp[i][s] 比 dp[i+1][s] 小，说明当初选了 i 号人
    int size = f(0, 0);
    vector<int> ans(size);
    for (int j = 0, i = 0, s = 0; s != (1 << n) - 1; i++) {
        if (i == m - 1 || dp[i][s] != dp[i + 1][s]) {  // i 是最后一人时必须选，否则 dp[i+1] 越界
            ans[j++] = i;
            s |= arr[i];
        }
    }

选了之后要把 arr[i] 或进 s，否则下一轮问的还是同一个状态，循环原地打转。走完 m 个位置，答案里正好是 size 个人。

四、i 走到最后一个人时

循环里那个 i == m - 1 是必须的。表只有 m 行（下标 0 到 m-1），i 等于 m-1 时 dp[i+1] 就越界了。语义上也说得通：i 已经是最后一个人而 s 还没凑齐，题目保证答案存在，那这个人必须选。

如果不想写这个特判，可以把表开成 m+1 行，让第 m 行整行留着哨兵值不填。这时 dp[m][s] 是 -1，跟任何真实答案都不等，比较自然成立。

随机样本实测：76.86% 的还原过程会真正用到这个分支，也就是最后一个人确实被选进了团队。这个分支属于常态。

六、写错的地方

位置写法与正确解不一致的比例
还原选了之后不写 s |= arr[i]100.00%
记忆化哨兵用 0 而不是 -1100.00%
还原取人判据写成 dp[i][s] == dp[i+1][s]86.12%

第一条是死循环级别的错：s 不变，循环条件永远不成立，i 一路加到 m 之后要么越界要么退出，答案里塞进一堆不该有的人。

第二条要留意：f 的返回值最小是 1（s 不等于全集时至少要一个人），0 只在「已经凑齐」这个边界出现，而那个边界是在写表之前就返回的，根本不会写进 dp。所以 0 看着像是个安全的哨兵，实际上初始全 0 会让每个状态都被当成「算过了，答案是 0」，一路返回 0。

第三条有 13.88% 蒙对，因为在那些样本里每次判据的结论恰好跟正确写法一致。

七、表有多大

状态数是 (m+1)·2n，但实际会算到的格子远少于这个数：很多 (i, s) 组合根本不会被递归走到。

实测：n = 10、m = 30 时实填 15,504 / 31,744 格（48.84%）；n = 12、m = 40 时 33,230 / 167,936（19.79%）；n = 16、m = 60 时 713,798 / 3,997,696（17.86%），按 int 算整张表是 15.25 MB，耗时 19.34 ms。

人越多、每个人会的技能越少，能走到的状态就越稀疏。这也说明记忆化比「先把整张表递推填满」划算，后者不管用不用得上都得把 2n 全扫一遍。

八、复杂度分析

阶段时间空间
记忆化填表O(m·2n)O(m·2n)
还原方案O(m)O(答案人数)

每个状态只做两次递归加一次 min，是 O(1)，状态数上界 (m+1)·2n，所以填表是 O(m·2n)。空间同量级，这是这题的主要开销。

还原只走 m 步，每步 O(1)，比填表小两个数量级。n = 16、m = 60 那边填表要 19.34 ms，还原走 60 步的量测不出来。

九、总结

凡是状态里带「当前考虑第几个」的 dp，都可以从起点正着走还原：走到一个位置，用「最优值有没有在这一步变小」判断当初的选择。省掉的是倒推时找前驱的那一步。

两个容易翻车的点：判据比较的是 dp[i][s] 和 dp[i+1][s]，别忘了后者在 i 是最后一个时会越界；还有哨兵值必须选一个「答案里不可能出现」的数。

还有一种更难的情况：最优值算出来了，方案本身还带着「字典序最小」之类的附加要求，那时候光靠 dp 表就不够了。
