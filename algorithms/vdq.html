值域分治

把数组一分为二，左右各自递归，再把「跨过半边」的那一半贡献在合并时统一结算 ， 用这个骨架把一类点对计数问题压到 O(n log n)。

零、背景

前面几页处理的都是「给一个结构，支持查询和修改」，回答的是某个区间、某个点上的问题。

这一节换一类：不算查询，而是问「所有点对之间满足某种关系的共有多少对」。点对一共 O(n²) 个，逐个看显然不行，得想办法一次算掉一大批。

一、问题

给一个长度为 n 的数组 a，问里面有多少个逆序对。逆序对指的是满足 i < j 且 a[i] > a[j] 的下标对 (i, j)。

下面这 8 个数里，逆序对一共 8 个，每条弧线是一个。

二、朴素做法

最直接的就是把所有下标对枚举一遍。

long long naive(int a[], int n) {
    long long ans = 0;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            if (a[i] > a[j]) ans++;
    return ans;
}

这是 O(n²)。n = 10⁵ 时是 10¹⁰ 次比较，跑不完。

换个问法：左半边内部的、右半边内部的、以及一个在左一个在右的，能不能分开算？前两种是规模更小的同一个问题，可以递归；第三种得想个办法一次算掉一批。

三、把数组对半切

把区间 [l, r] 从 mid 切开，答案分成三份：[l, mid] 内部的、[mid+1, r] 内部的、以及跨过 mid 的。前两份交给递归。

剩下的问题是「跨过半边」的那份怎么算。如果两个数一个在左一个在右，那么 i < j 自动成立，判断就只剩 a[i] > a[j]。这时候要是左右两段都已经按值排好序，双指针扫一遍就数完了。

归并排序正好把这个条件准备好了：merge 的那一刻，左右两段已经各自有序。于是只要在合并时多写一行。

long long ans = 0;
void merge(int l, int mid, int r) {
    int i = l, j = mid + 1, k = l;
    while (i <= mid && j <= r) {
        if (a[i] <= a[j]) { tmp[k++] = a[i++]; }
        else {
            tmp[k++] = a[j++];
            ans += mid - i + 1;      // 左半边从 i 到 mid 都比 a[j] 大
        }
    }
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= r)   tmp[k++] = a[j++];
    for (int p = l; p <= r; p++) a[p] = tmp[p];
}

为什么是 mid − i + 1：走到 else 分支说明 a[i] > a[j]，而左半边是有序的，所以从 i 到 mid 的每一个都 > a[j]。这些数都还没被取走，每一个都和 a[j] 构成一个逆序对。

反过来，如果 a[i] ≤ a[j] 就把左边的取走，一个数也不加：相等不算逆序，而比 a[j] 小的更不构成。

看最后一次合并（左段 [1,1,3,4]、右段 [2,5,6,9]）中间的那一步。

五、为什么叫「值域」分治

注意上面切的是下标：[l, mid] 和 [mid+1, r]。但结算时用的性质是「两段各自按值有序」，也就是比较的是值的大小。这就是它和值的分界有关的原因。

和前面几页对比一下切的对象：

  • 分块：按下标位置切成一块一块；
  • 莫队：按查询的顺序重排；
  • 这里：递归时按下标切，结算时按值的大小。

骨架是同一个：分、递归、合并时处理跨半边的部分。差别只在于「跨半边那份凭什么能一次算掉」，分块靠块内预处理，莫队靠指针复用，这里靠两段有序。

顺便说一句，第一节列的「两数之和 ≥ X」这类其实不需要分治：它只跟值有关、跟先后顺序无关，排个序再用双指针就是 O(n log n)。分治是用来对付「既要看先后、又要看值」的，逆序对正是这种。

七、代码

#include <bits/stdc++.h>
using namespace std;

const int N = 100005;
int a[N], tmp[N];
long long ans = 0;

void mergeSort(int l, int r) {
    if (l >= r) return;
    int mid = (l + r) / 2;
    mergeSort(l, mid);
    mergeSort(mid + 1, r);

    // 此刻 a[l..mid] 和 a[mid+1..r] 都已经有序
    int i = l, j = mid + 1, k = l;
    while (i <= mid && j <= r) {
        if (a[i] <= a[j]) {
            tmp[k++] = a[i++];
        } else {
            tmp[k++] = a[j++];
            ans += mid - i + 1;     // a[i..mid] 都比 a[j] 大
        }
    }
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= r)   tmp[k++] = a[j++];
    for (int p = l; p <= r; p++) a[p] = tmp[p];
}

int main() {
    int n;
    cin >> n;
    for (int i = 0; i < n; i++) cin >> a[i];
    ans = 0;
    mergeSort(0, n - 1);
    cout << ans << endl;
    return 0;
}

ans 要开 long long：n 个数最多有 n(n−1)/2 对，n = 10⁵ 时约 5 × 10⁹，int 装不下。

八、复杂度分析

递归每次对半切，一共 ⌈log₂ n⌉ 层。每个区间 [l, r] 的合并是 O(r − l + 1)，同一层所有区间的长度加起来正好是 n，所以每层是 O(n)。

项目复杂度说明
朴素（双重循环）O(n²)枚举所有点对
递归层数⌈log₂ n⌉每次对半切
单层所有合并O(n)各区间长度之和为 n
总时间O(n log n)层数 × 每层开销
额外空间O(n)合并用的临时数组 tmp，递归栈 O(log n)

n = 10⁵ 时，朴素要 10¹⁰ 次，归并版约 1.7 × 10⁶ 次，差了将近四个数量级。

九、最后

这套骨架能用的前提是「跨半边那份能在线性时间里算掉」。本例靠的是两段有序加双指针；换一个贡献规则，就得换一个数法。

它解决的是点对计数。如果问题带上区间限制，比如「[L, R] 内有多少逆序对」，单纯这套就不够了，得把树状数组和分治结合起来，也就是 CDQ 分治 ， 那时候分治切的是时间维，跨半边那份交给树状数组去数。

到这里，分块、树状数组、线段树、莫队、后缀数组、BFS、堆、值域分治都过了一遍。它们看着差别很大，做的事其实同一件：只维护回答问题真正需要的那点信息，把其余的代价省掉。
