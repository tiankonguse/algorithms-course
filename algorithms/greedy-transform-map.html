贪心：字母的映射与空位

一次转化会把整个字符串里所有同一个字母一起换掉，一动手就能影响很多位置。所以能不能变过去，只看两件事：映射一致不一致，以及字母表里还剩不剩空位。

零、题目要什么

给两个长度相同的字符串 str1 和 str2。一次转化把所有出现的小写字母 x 换成另一个小写字母 y，作用范围是整串。问零次或多次转化之后 str1 能不能变成 str2。

「所有出现」这四个字是题眼。它同时给出了两个必要条件：str1 里同一个字母的每个位置，转化之后仍然是同一个字母；以及转化过程中常常要先借一个别的字母周转。

一、同一个字母不能对应两个目标

先看第一个条件。str1 里字母 x 出现在好几个位置，不管中间怎么换，这些位置上的字母始终同步变化，最后必须一起落在 str2 的某个字母上。所以 str2 在这几个位置必须是同一个字母。

写法很直接：扫一遍 str1，用一张表记下每个字母上一次出现的位置。再遇到同一个字母时，看 str2 在这两处是不是同一个字母，对不上就返回 false。

例子 leetcode → codeleet：位置 1 和位置 3 都是 e，可是 str2 在位置 1 是 o、在位置 3 是 e，同一个字母要落到两个不同的目标上，返回 false。

注意检查的方向。要问的是「str1 的同一个字母在 str2 里是否一致」，反着问「str2 的同一个字母在 str1 里是否一致」会误伤。反例 ca → bb：str1 的 c 和 a 都要变成 b，这是合法的；反着看时 str2 的 b 对应到 str1 的 c、a 两个字母，会被误判成冲突。这个方向写反的版本在小字母表上有 16.02% 的用例给错答案。

二、字母表里得留一个空位

第二个条件关于顺序。看 aabcc → ccdee，映射是 a→c、b→d、c→e。如果直接按 a→c 下手，串变成 ccbcc，接下来再做 c→e，会把这批新来的 c 一起带走，全串变成 eebee。

办法是先借一个字母表里没用上的字母周转。f 不在 str2 里，它是空的：先把 c 挪到 f，再做 a→c、b→d，最后 f→e，四步到位，中间状态是 aabff、ccbff、ccdff、ccdee。

所以只要字母表里有一个字母不出现在 str2 里，映射一致就能做到。反过来，str2 把 26 个字母全用上时没有空位，除了 str1 本来就等于 str2，其余一律做不到。最典型的是整体平移一位：a→b、b→c、……、z→a，这是个 26 个字母首尾相接的环，第一步就需要一个临时格子，而一个空位也没有。

这里有个细节：两个条件里出现的是字母表大小 26 这个常数。对数器得用同样大小的字母表来对照，把字母表缩到 4 个字母、串长不超过 5 在状态空间里 BFS，那么判断条件里的 26 也要换成 4，两边结论才一致。不换的话，所有「str2 用满字母表」的用例都会对不上。

// 字符串转化：一次转化把 str1 里出现的同一个字母全部换成另一个小写字母，判断能不能变成 str2
    // 先看 str2 用掉了几个字母：26 个全用上时没有多余的字母当周转用的临时格子，只有 str1 本来就等于 str2 才行
    // 再看 str1 里同一个字母出现的每个位置，在 str2 里必须都是同一个字母
    bool canConvert(string str1, string str2) {
        if (str1 == str2) {
            return true;
        }
        int map[26] = {0};
        int kinds = 0;
        for (int i = 0; i < (int) str2.size(); i++) {
            if (map[str2[i] - 'a']++ == 0) {
                kinds++;
            }
        }
        if (kinds == 26) {
            return false;
        }
        for (int i = 0; i < 26; i++) {
            map[i] = -1;
        }
        for (int i = 0, cur; i < (int) str1.size(); i++) {
            cur = str1[i] - 'a';
            if (map[cur] != -1 && str2[map[cur]] != str2[i]) {
                return false;
            }
            map[cur] = i;
        }
        return true;
    }

实测长度 106、str1 可以转化过去的一对字符串，跑完 1.93ms；随机配对因为要在数种类时就返回 false，只用 0.87ms。

四、对数器怎么抓错

这题的暴力没法枚举子集，但状态空间天生就有限：把字母表缩小到 4 个字母、串长限制在 5 以内，每个状态是一个长度 5 以内的串，最多 45 种。从 str1 出发做 BFS，每次挑一个出现过的字母换成 4 个字母里的另一个，看能不能走到 str2。

写法数据出错比例
漏掉「str2 用满字母表」这一条26 个字母的双射（str1 是 abc…z，str2 是它的一个排列）100.00%
漏掉「str2 用满字母表」这一条随机长串（长度 26 到 60）0.00%
检查方向写反（比对 str2 的同一个字母）字母表 a~e、长度不超过 1016.02%
检查方向写反26 个字母的双射0.00%

第一行五千组，每组都是 26 个字母的一个随机排列；第二行十万组；第三行二十万组；第四行与第一行同一批数据。

漏掉字母表那一条的条件之后，随机长串上几乎测不出来：26 个字母随机撒进 40 个位置，平均只覆盖到 17 到 22 种，凑不满 26。要专门构造双射才有 100% 的出错率，而真实数据的长度上限是 104，只要串够长就一定能凑满 26 种，所以这一条在真正的测试里一定会被踩到。

方向写反的版本正好相反，它只在短串、小字母表下出错：这种数据的映射关系密，反着看容易看出「冲突」。串一长、字母表一满，两个方向的判断同时返回 false，反而看不出区别。

只需要两张长度 26 的数组，一张数种类、一张记上次出现的位置，与字符串长度无关。字符串长度到 106 时实测 1.93ms。

总结

判断分两步。str1 里同一个字母出现的每个位置，在 str2 里必须是同一个字母；str2 用满了 26 个字母时，只有 str1 本来就等于 str2 才可行。

第二条的来历是周转：一次转化作用于全部出现，改一个字母族之前往往得先把它挪到别处，而目的串占满字母表时没有别处可挪。整体平移一位那种 26 个字母连成的环就是典型，缺的正是起步用的那一格。

两个容易写错的地方：检查的方向不能反（问的是 str1 的同一个字母，不是 str2 的）；对数器里的字母表大小要和代码里的常数对上，缩表验证时两边一起改。
