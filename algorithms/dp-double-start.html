一来一回，拆成双倍起点

「走一个来回」的题，回程反着看就是第二条同向路径。把一个人去加回，换成两个人从同一个起点同向走到同一个终点，状态多一个人，步数这一维反而能消掉。摘樱桃和上学都是这个套路。

零、背景

摘樱桃要求从 (0, 0) 走到 (n−1, n−1)，再走回 (0, 0)。去程只能向下或向右，回程只能向上或向左，网格里有 -1 的障碍，走过的格子上的樱桃只算一次。

回程那一段，把每一步都反个方向，就是从 (n−1, n−1) 走回 (0, 0) 的路径，变成了另一条从 (0, 0) 到 (n−1, n−1) 的路径。所以「一个人来回」和「两个人同时从左上出发、同时到达右下」是同一件事，两个人捡过的樱桃取并集。

反过来也成立：两条同向路径，第一条正着走、第二条反着走，拼起来就是一个合法的来回。

一、摘樱桃：两个人的状态

状态记成 (a, b, c)：第一个人走到 (a, b)，第二个人走到 (c, d)。两个人步数相同，所以 a + b = c + d，d = a + b − c。第四维由前三维算出来，状态从 n⁴ 压到 n³。

四个后继是两个人各向下或向右的组合：第一个人到 (a+1, b) 或 (a, b+1)，第二个人到 (c+1, d) 或 (c, d+1)。步数同步加 1，d 的公式一直成立。

二、同格只算一次

两个人同时踩到同一个格子，樱桃只算一次，转移里先判 a == c 且 b == d。

障碍格返回 -1；四个后继全 -1 就说明这条路走不通，整个答案是 0。n = 50 时状态数 50³ = 125000，每格常数次转移，跑得动。

全 1 的 n×n 网格答案固定在 4n − 4：两条路径只能在起点和终点重合，各捡 2n − 1 格，并集 4n − 4。n = 50 时实测 196。

// 摘樱桃：把回程反着看，变成第二个人从左上走到右下
    // 状态 (a, b, c)：第一个人到 (a, b)，第二个人到 (c, d)，d = a + b - c
    // 两个人的步数永远相等，第四维被消掉，状态数从 n^4 压到 n^3
    int f(const vector<vector<int>>& grid, int n, int a, int b, int c,
          vector<vector<vector<int>>>& dp) {
        int d = a + b - c;
        if (a == n || b == n || c == n || d == n ||
            grid[a][b] == -1 || grid[c][d] == -1) {
            return -1;
        }
        if (a == n - 1 && b == n - 1) {
            return grid[a][b];
        }
        if (dp[a][b][c] != -2) {
            return dp[a][b][c];
        }
        // 两个人踩到同一个格子，樱桃只算一次
        int cur = (a == c && b == d) ? grid[a][b] : grid[a][b] + grid[c][d];
        int nxt = f(grid, n, a + 1, b, c + 1, dp);
        nxt = max(nxt, f(grid, n, a + 1, b, c, dp));
        nxt = max(nxt, f(grid, n, a, b + 1, c + 1, dp));
        nxt = max(nxt, f(grid, n, a, b + 1, c, dp));
        dp[a][b][c] = (nxt == -1) ? -1 : cur + nxt;
        return dp[a][b][c];
    }

    int cherryPickup(vector<vector<int>>& grid) {
        int n = (int)grid.size();
        vector<vector<vector<int>>> dp(
            n, vector<vector<int>>(n, vector<int>(n, -2)));
        return max(0, f(grid, n, 0, 0, 0, dp));
    }
摘樱桃：双人同步走

「下一步」会让两个人都走一格，信息行给出当前坐标和已捡樱桃数。走到同格时会标出来，那颗樱桃只算一次。

三、上学：x 次往返 = 2x 次单程

第二题：位置 1 到 n−1 各有一块石头，高度 arr[i]。青蛙一次能跳 [1, y] 的任意距离，踩到石头会把它压低 1，压到 0 就不能再踩。每天从 0 跳到 n 再跳回来，共 x 天，求最小的跳跃能力 y。

往返 x 次就是单程 2x 次，2x 次单程共享全部石头的承重。学校位置 n 直接给高度 2x，保证每次单程都能落脚。

四、能力 y 的判定：每个窗口都要接得住

能力 y 够用，当且仅当任意一段长度 y 的窗口里，石头高度总和 ≥ 2x。必要性很直接：2x 次单程都要穿过这段窗口，每次穿过至少落一次脚，窗口里的落点总数 ≥ 2x，而窗口能承受的总次数就是高度和。

充分性靠构造，这里直接用结论：y 够用 ⟺ 所有长度 y 的窗口容量 ≥ 2x。

五、答案不靠二分

对每个左端点 l，找最小的 r 使 sum[l..r) ≥ 2x。r − l 就是从 l 这个位置突破需要的最小能力，答案取所有 l 里的最大值。

l 递增时 r 只增不减，sum 减掉离开的 arr[l]，一趟滑窗 O(n)，连二分都不用。

极端例子：n = 1e5、石头高度全 1、x = 1e9。2x = 2e9 次落脚，每块石头只能承受 1 次，只有学校的 2e9 能兜住，答案就是 1e5，得一步跳到底。

// 上学：x 次往返 = 2x 次单程，每块石头总共能被踩的次数不超过它的高度
    // 位置 n（学校）的高度当 2x，窗口永远能在它那里凑够
    // 对每个左端点 l，找最小的 r 让 sum[l..r) >= 2x
    // 答案就是这些最短窗口长度的最大值，一趟滑窗，不用二分
    long long compute() {
        arr[n] = 2 * x; // 学校的位置提供 2x 次落脚
        long long sum = arr[1];
        long long ans = 0;
        for (int l = 1, r = 2; l <= n; l++) {
            while (sum < 2 * x) {
                sum += arr[r++];
            }
            ans = max(ans, (long long)(r - l));
            sum -= arr[l];
        }
        return ans;
    }
上学：滑窗找最短突破窗口

「下一步」把左端点 l 从 1 推到 n。窗口 [l, r) 会标出来，信息行给出当前和、r − l 和到这一步为止的答案。

复杂度分析

摘樱桃：状态 n³，每个状态 4 次转移，时间 O(n³)；dp 表同样 n³ 个 int，n = 50 时 500 KB。

上学：一趟滑窗，时间 O(n)，空间 O(1)。

做法时间空间
摘樱桃：双人同步走O(n³)O(n³)
上学：滑窗最短突破窗口O(n)O(1)

总结

来回问题先反转回程，把「去加回」变成「两个人同向」。摘樱桃用步数相等消掉一维，状态压到 n³，同格只算一次靠坐标相等判断；上学把 x 次往返拆成 2x 次单程，能力判定收敛成「每个窗口容量够」，滑窗一趟算完。两个题方向相反：一个给状态加人、加同步约束，一个把约束摊到窗口上，共同点是先把「来回」这个形状拆掉。
