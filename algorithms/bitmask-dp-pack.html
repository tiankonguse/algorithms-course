状压 dp：把剩下的活交给 status

把一堆东西分到几个桶里，每个桶的容量都一样，问能不能分完。这类题的可变参数看着有三个：还剩哪些东西、当前桶装了多少、还剩几个桶。其实只有第一个需要进状态，另外两个都能从它算出来。

零、已经用掉多少，除以 limit 就知道走到哪了

status 的语义和上一类题一样：第 i 位是 1，表示第 i 个东西还没被用掉。

先认一个事实：status 一确定，已经用掉的东西总长 S 就确定了：把 status 里为 0 的那些位对应的长度加起来。而递归过程中始终维持一条不变式：每条已经拼满的边长度都恰好是 limit，当前这条边严格不满。于是

S = (k − rest) × limit + cur，其中 0 ≤ cur < limit。这正好是一次带余除法：商就是拼满的边数 k − rest，余数就是当前这条边的长度 cur。

所以 cur 和 rest 都不用进状态，它们是从变量。真正要缓存的就是 status 一个。

一、火柴拼正方形

给一组火柴长度，能不能用每一根恰好一次、不许折断，拼成一个正方形。正方形的四条边长度相等，所以每条边的长度只能是 sum / 4；总和不能被 4 整除就直接返回 false。

递归函数 f(status, cur, rest) 干三件事：

  1. rest == 0 时四条边都拼完了，这时只要 status 也空了，就是成功；
  2. 表里有答案就直接拿；
  3. 否则枚举每一根还没用的火柴：长度加上去不超过 limit 才能放。正好把这条边凑满，就让 cur 归 0、rest 减一；没凑满就让 cur 变大、rest 不动。

第 3 步那两个分支是这道题最容易写漏的地方，漏掉任何一个都会让函数永远返回 false，下面细说。

// limit  每条边规定的长度
    // status 的第 i 位是 1，表示第 i 根火柴还没用
    // cur    当前这条边已经凑出的长度
    // rest   还有几条边没解决
    // cur 和 rest 都由 status 决定，关键可变参数只有 status 一个
    bool f(int status, int cur, int rest) {
        if (rest == 0) return status == 0;
        if (dp[status] != 0) return dp[status] == 1;
        bool ans = false;
        for (int i = 0; i < n; i++) {
            if ((status & (1 << i)) != 0 && cur + a[i] <= limit) {
                if (cur + a[i] == limit) ans = f(status ^ (1 << i), 0, rest - 1);
                else                     ans = f(status ^ (1 << i), cur + a[i], rest);
                if (ans) break;
            }
        }
        dp[status] = ans ? 1 : -1;
        return ans;
    }
bool makesquare(vector<int>& a) {
        int sum = accumulate(a.begin(), a.end(), 0);
        if (sum % 4 != 0) return false;
        limit = sum / 4;
        dp.assign(1 << a.size(), 0);
        return f((1 << a.size()) - 1, 0, 4);
    }

    bool canPartitionKSubsets(vector<int>& nums, int k) {
        int sum = accumulate(nums.begin(), nums.end(), 0);
        if (sum % k != 0) return false;
        a = nums;
        limit = sum / k;
        dp.assign(1 << a.size(), 0);
        return f((1 << a.size()) - 1, 0, k);
    }

记忆化的效果比上一类题更激进，因为只要找到一种合法拼法就立刻返回，剩下的状态根本不用碰。n = 16 的一组可解数据，只访问了 39 个状态；全是等长火柴时更少，16 个状态就完事，每根火柴自己占一条边。反过来，无解的数据得把可达的状态都走一遍，最多能到 14867 个（上限 65536）。

二、划分为 k 个相等的子集

把「4 条边」换成「k 个子集」，递归函数一个字都不用改，只是入口里 sum / 4 变成 sum / k、初值 4 变成 k。

这份状压解是正式解：状态数 2n，每个状态枚举 n 个东西，总共 O(2n · n)。题目给 n ≤ 16，216 × 16 约等于 1.05 × 106 次操作，稳稳过。

这题还有一个不推荐的写法：不做动态规划，纯回溯，把每个数依次放进 k 个集合之一，靠两处剪枝撑着：一条集合满了就不再往里放，以及「这一层已经试过一个累加和相同的集合，换一个结果一样」就跳过。

// group[i] : 第 i 个集合当前的累加和
    // a 已按升序排好，从最大的那根火柴开始放
    bool g(vector<int>& group, int target, int index) {
        if (index < 0) return true;
        int num = a[index];
        int len = group.size();
        for (int i = 0; i < len; i++) {
            if (group[i] + num <= target) {
                group[i] += num;
                if (g(group, target, index - 1)) return true;
                group[i] -= num;
                while (i + 1 < len && group[i] == group[i + 1]) i++;
            }
        }
        return false;
    }

剪枝版在好数据上非常快。n = 16 的一组可解数据它只调用了 296 次，比状压还少；全是等长火柴时 17 次就结束了。问题在于它是「运气型」的：

30 万组随机 n = 16、k = 4 的数据里，剪枝版调用次数最多的一组要 163701 次；把数据改成「14 个 4、一个 5、一个 7」这种无解但处处差一点的形状，它得跑 615209 次，2.76 ms，而状压在同一组数据上只要 0.56 ms。出题人想卡就能造出这种数据，状压则不管数据长什么样都落在 2n × n 以内。

四处写错的代价不一样。前三种错法有一个共同的后果：函数永远返回 false。凑满一条边时忘了 rest 减一，那条边就白拼了，程序会一直找下一条边，永远到不了 rest == 0；忘了把 cur 归零，就认为这条边还要继续凑，一样到不了终点；把「这一位是 1 才能用」写成「这一位是 0 才能用」，从一开始就没有可用的东西。三种都只会说「拼不出」，所以出错率等于答案为 true 的样本占比，52.09%。

第四种不一样：不拦「这条边会超长」的火柴，只是拿 cur + a[i] ≥ limit 时把它减掉 limit、硬塞进下一条边。它会答错一些、答对一些，抓取率 33.18%，这种 bug 更难被发现。

顺便说一句 sum % k != 0 那一句。拿掉它结果完全一样：每条边都不许超过 limit，用光所有东西是不可能的，递归自己会返回 false。它省的是时间：n = 15 的 3000 组随机数据，判这一句总共 23.1 ms，不判 2507.2 ms，差一百倍，因为其中 75.45% 的样本白建了一次 2n 的表。

复杂度分析

做法时间空间
状压解（火柴拼正方形 / k 个相等子集）O(2n · n)O(2n)
纯回溯 + 剪枝（不推荐）最好 O(n)，最坏 O(kn)O(n + k)

状压的时间就是状态数乘每个状态的枚举量，2n 个 status，每个枚举 n 个东西，所以是 O(2n · n)。空间是那张表，用 signed char 存就是 2n 字节；n = 16 时 64 KB，递归栈深度不超过 n。

剪枝版的空间小得多，只有 k 个桶的累加和和递归栈，但它最坏要枚举「每个数放哪个桶」，也就是 kn。n = 16、k = 4 时是 416 ≈ 4.3 × 109，和 216 × 16 ≈ 1.05 × 106 差了四千倍。剪枝把这些开销压下去一大截，但压多少全看数据长什么样，压不到 0，所以它给不出保证。

总结

status 记「哪些东西还没用」，剩下的两个参数（已经拼满几个桶、当前这个桶装了多少）都是它的函数。判断方法在正文里给过了：把已经用掉的总长写出来，除以 limit，商是拼满的桶数，余数是当前桶的长度。

递归里「凑满一个桶」是一个分岔点。凑满时要同时做两件事：当前长度归零、剩余桶数减一。只做一件，函数就会掉进「这个桶永远凑不满」或者「凑满了还要接着凑」的陷阱，最后一律返回 false。

记忆化在「只要找到一个解就返回」的问题上效果特别好，可达的状态往往远少于 2n。代价是它必须诚实：一旦要证明「无解」，可达的状态一个都跑不掉，实测最多的一档走了 14867 个，还是没有顶到 65536。

和「回溯 + 剪枝」比，状压的价值不在快，在于它的上界是算得出来的。剪枝版在一组数据上 296 次调用、在另一组上 615209 次，两个数字差三个数量级，而状压的上下界从写下来那一刻就是固定的。

再往后一步，status 记录的就换成「走过哪些地方」了。
