正则表达式匹配与通配符匹配

两道字符串匹配题，模式串里都有 *，它让前一个字符（正则）或者整串（通配符）重复任意次。转移里因此长出一个完全背包式的枚举。暴力递归在 n = 20 就要跑七千多万次，加上记忆化只剩两百多个状态。

零、两道题

第一道是正则表达式匹配。给你字符串 s 和模式串 p，p 里可能带 . 和 *：. 能变成任意一个字符，* 让它前面那个字符重复任意次，包括 0 次。题面保证 p 不以 * 开头，也不会出现两个 * 挨着（那样写没有意义）。问 p 能不能整个匹配出 s。

第二道是通配符匹配，规则换了两个符号：? 匹配任意一个字符，* 匹配任意一段字符串（长度可以是 0）。同样问 p 能不能匹配出 s。

两道题的骨架完全相同，差别只在 * 的含义。把第一道写对，第二道删掉几行就是答案。

一、把问题写成 f(i, j)

直接看「s 和 p 整串匹配」不好下手，因为 * 的作用范围不确定。把问题缩小一点：f(i, j) 表示「s 从第 i 个字符开始的后缀，能不能被 p 从第 j 个字符开始的后缀完全匹配」。原答案是 f(0, 0)。

这个定义好用的地方在于：每次只决定一件事：p 的第 j 个字符怎么处理，剩下的继续交给后缀。两个参数各自的范围是 0 到 n 和 0 到 m，所以状态总共 (n + 1)(m + 1) 个。

先定一个规矩：调用 f(i, j) 时，p[j] 一定不是 *。因为 * 从不单独出现，它总是跟着前面那个字符一起被处理，我们让指针停在那个普通字符上，一次处理「字符 + 星」这一对。

有了这条规矩，几种情况就能分开写：s 用完了怎么办、p 用完了怎么办、p[j] 后面跟的是不是 *。

f(i, j) = ?　i = n 时：j = m 返回 true；否则看 p[j+1] 是不是 '*'，是就返回 f(i, j+2)
j = m 时（s 还有）：返回 false
p[j+1] 不是 '*'：要求 s[i] 对上 p[j]，然后 f(i+1, j+1)
p[j+1] 是 '*'：见下一节

二、正则的 x*：两种选择

这是全题最关键的一步。假设 p[j] 是某个字符 x，p[j+1] 是 *，也就是「x 可以出现任意次」。此时只有两种选择：

1）让 x* 匹配 0 个字符，整对跳过，去看 f(i, j+2)。这一步处理了「x 一次都不出现」的情况。

2）让 x* 吃掉 s[i] 这一个字符（条件是 s[i] 等于 x，或者 x 就是 .），然后继续看 f(i+1, j)。注意指针 j 没有动，所以这个 x* 还能再吃下一个。

两种选择取或。

f(i, j) = f(i, j+2) || ( (s[i] == p[j] || p[j] == '.') && f(i+1, j) )

第二个分支里指针停在原地，这就是完全背包的味道：一件货物可以被反复挑，每次挑都消耗一个容量、换来一份价值。这里「消耗」的是 s 的一个字符，「换来」的是匹配上一位。上一节讲完全背包时那个 dp[i][j-cost[i]] 里的下标 i，在这里对应的就是「指针不动」。

最容易漏掉的恰恰是第一个分支。漏了它，程序的意思就变成「x* 至少要出现一次」。用两万组随机小样本测，漏掉这个分支有 8.62% 的样本答案错了；反过来，漏掉第二个分支（x* 吃掉 s[i]）有 9.97% 错。两个分支都不能少。

// s[i..] 能不能被 p[j..] 完全匹配出来
    // 调用时保证 p[j] 不是 '*'，'*' 总是跟前面那个字符一起处理
    bool regexF(char s[], char p[], int i, int j) {
        int n = strlen(s), m = strlen(p);
        if (i == n) {                                  // s 用完了
            if (j == m) return true;                   // p 也用完
            // 剩下的 p[j..] 只能是 x* 这种整对的东西，跳掉一对继续看
            return j + 1 < m && p[j+1] == '*' && regexF(s, p, i, j + 2);
        }
        if (j == m) return false;                      // s 还有，p 没了
        if (j + 1 == m || p[j+1] != '*')               // p[j] 后面不是 *，只能对上一个字符
            return (s[i] == p[j] || p[j] == '.') && regexF(s, p, i + 1, j + 1);
        // p[j] 后面是 *，两种选择取或
        bool skip = regexF(s, p, i, j + 2);                                   // x* 匹配 0 个
        bool take = (s[i] == p[j] || p[j] == '.') && regexF(s, p, i + 1, j);  // x* 吃掉 s[i]，还能接着吃
        return skip || take;
    }

上面第一个 if 处理的是「s 已经用完」：如果 p 也恰好用完，匹配成功；否则 p 剩下的部分只能是若干个 x* 这种成对的东西（因为 p[j] 不是 *，两侧也不会出现 **），那就整对跳过去继续看。跳的过程里 j + 1 < m 这个判断不能省，它同时挡住了越界和「p[j] 是光杆字符」两种情形。

三、通配符的 *：更简单

通配符那题的 * 是独立字符，不跟着前一个字符，所以判断简单得多：遇到 *，要么让它吃掉 s[i]（f(i+1, j)，指针还是不动），要么让它一个字符都不吃（f(i, j+1)）。也是两种选择取或。

f(i, j) = f(i+1, j) || f(i, j+1)　（p[j] == '*' 时）

另外两种：? 和普通字符都只对一位，条件不同，走法一样：对上了就 f(i+1, j+1)。

f(i, j) = (s[i] == p[j] || p[j] == '?') && f(i+1, j+1)　（p[j] != '*' 时）

收尾那一条也变简单了：s 用完时，p 剩下的必须全是 *（每个都能匹配空串），所以只要往后看一眼是不是 * 就行。

这题有两种写错的方式也很常见：漏掉 f(i, j+1)（意思是 * 至少吃一个字符），两万组里 11.94% 现形；收尾时忘了看尾巴上的 *（直接判断 i == n 就返回 j == m），8.19% 现形。第二种在 p 以 * 结尾时才暴露，比如 s = "ab"、p = "ab*"。

// s[i..] 能不能被 p[j..] 完全匹配出来
    bool wildF(char s[], char p[], int i, int j) {
        int n = strlen(s), m = strlen(p);
        if (i == n) {                                  // s 用完了
            if (j == m) return true;
            return p[j] == '*' && wildF(s, p, i, j + 1);   // 剩下的只能是若干连续的 *
        }
        if (j == m) return false;                      // s 还有，p 没了
        if (p[j] != '*')                               // 必须一对一
            return (s[i] == p[j] || p[j] == '?') && wildF(s, p, i + 1, j + 1);
        // p[j] 是 *：吃掉一个字符 或 一个都不吃
        return wildF(s, p, i + 1, j) || wildF(s, p, i, j + 1);
    }

四、暴力递归为什么要记忆化

上面的递归看着很干净，但它的调用次数会指数级爆炸。原因是在 x* 那里，两个分支各自往下走，同一条路径会被反复探索很多次，而且子问题大量重叠，同一个 (i, j) 会被从不同路径到达。

实测（s 是 n 个 a，p 是 (n/2) 个 a* 拼上一个必然对不上的 b，所以必须把所有分法都试完才能返回 false）：

n = 10 时七千多次调用还无所谓，n = 20 就涨到七千四百万次，n = 24 是三十一亿次。而加了记忆化之后真正要算的状态只有几十到几百个，同一个 (i, j) 被第二次问到时直接查表返回。这就是为什么这题不能交裸递归。

记忆化的实现只要一个数组，记录三种状态：没算过、算过是 true、算过是 false。用 int 数组存 0 / 1 / 2 就是这个意思，比额外维护一个 visited 数组省事。

五、两张表与填表顺序

把记忆化再推一步，就是自底向上的填表。状态 (i, j) 只依赖 (i+1, j+1)、(i, j+2)、(i+1, j) 这三个方向，都比 (i, j) 「更靠后」。所以 i 从 n 减到 0、j 从 m 减到 0 地填，每个格子用到的东西都已经算好。

第 n 行是边界（s 用完了），要单独先填：dp[n][m] = true，然后 j 从 m − 1 往左走，dp[n][j] = (j+1 < m && p[j+1] == '*' && dp[n][j+2])。通配符那题的边界反过来：尾部连续的一串 * 全是 true，再往左就全是 false。

bool regexMatch(string s, string p) {
        int n = s.size(), m = p.size();
        // dp[i][j]：s[i..] 能不能被 p[j..] 匹配
        vector<vector<bool>> dp(n + 1, vector<bool>(m + 1, false));
        dp[n][m] = true;
        for (int j = m - 1; j >= 0; j--)                // 最后一行：s 已经用完
            dp[n][j] = j + 1 < m && p[j+1] == '*' && dp[n][j+2];
        for (int i = n - 1; i >= 0; i--)                // i 从下往上填
            for (int j = m - 1; j >= 0; j--) {          // j 从右往左填
                if (j + 1 == m || p[j+1] != '*')
                    dp[i][j] = (s[i] == p[j] || p[j] == '.') && dp[i+1][j+1];
                else
                    dp[i][j] = dp[i][j+2] || ((s[i] == p[j] || p[j] == '.') && dp[i+1][j]);
            }
        return dp[0][0];
    }
bool wildMatch(string s, string p) {
        int n = s.size(), m = p.size();
        vector<vector<bool>> dp(n + 1, vector<bool>(m + 1, false));
        dp[n][m] = true;
        for (int j = m - 1; j >= 0 && p[j] == '*'; j--)  // 尾部连续的一串 * 都能匹配空串
            dp[n][j] = true;
        for (int i = n - 1; i >= 0; i--)
            for (int j = m - 1; j >= 0; j--) {
                if (p[j] != '*')
                    dp[i][j] = (s[i] == p[j] || p[j] == '?') && dp[i+1][j+1];
                else
                    dp[i][j] = dp[i+1][j] || dp[i][j+1];
            }
        return dp[0][0];
    }

两张表都是 (n + 1) × (m + 1) 个布尔。实测 n = m = 2000 时正则 5.077 毫秒、通配符 4.059 毫秒；n = m = 10000 时两张表各约一亿格，正则 125.751 毫秒、通配符 134.613 毫秒。比起暴力递归的指数级，这点开销可以忽略。

用 vector<vector<bool>> 存布尔表有个小细节：它是按位压的，读一个格要拆位，比 vector<vector<char>> 慢一些。n = m = 10000 时两者差别在百分之几十的量级，规模小的时候不用管。

三道式的复杂度和字符串长度乘在一起，和字符集大小无关，因为每格只做常数次比较。真要认真抠，暴力递归的调用次数是「不同的 (i, j) 组合被重复走过的次数之和」，最坏情况下的量级接近 2n，n 稍微大一点就没法跑了。

七、总结

两道匹配题的骨架是同一个：f(i, j) 看两个后缀，遇到「可重复」的符号就展开成两个分支。

几个要点：

1）f(i, j) 的规矩是 p[j] 不指向 *。指针停在普通字符上，一次处理「字符 + 星」这对。

2）正则的 x* 有且只有两种选择：跳过（0 次）和吃掉一个字符（指针不动）。漏掉任何一个都有约 9% 到 10% 的样本出错。

3）通配符的 * 同样是两种选择，但它独立成字符，收尾时只要看尾巴上有没有连续的 *。

4）裸递归会指数级爆炸，n = 20 就是七千多万次调用；记忆化之后状态数是 O(n · m)。

5）填表方向：i 从 n 到 0，j 从 m 到 0，先把第 n 行（或者最后那一段连续 *）当边界填好。

把记忆化数组换成 dp 表，就得到自底向上的写法；反过来也能把任何「参数少、值域小」的递归改成表。分组枚举、完全背包、字符串匹配，这一讲的三道式子用的是同一件事。
