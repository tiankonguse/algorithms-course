二分答案配贪心与队列：最多任务

直接给每个任务挑工人，挑一个少一个，局部最优拼不出全局答案。换个思路：先猜「能完成 m 个任务吗」，猜大了缩小、猜小了放大，这就是二分答案。检查 m 用最弱的 m 个任务 + 最强的 m 个工人，分配时吃药名额只花在刀刃上。

零、背景

有 n 个任务和 m 个工人，每个任务要力量 tasks[i]，工人有力量 workers[j]，力量够才能做；还有 pills 片药，每片让一个工人力量加 strength，每个工人最多一片。求最多能完成几个任务。

直接贪心为什么不行：任务和工人两组数，力量大的人能做所有弱任务，但也只有他做得了最强任务；药给谁、哪个工人做哪个任务，牵一发动全身。样例 tasks=[10,15,30]、workers=[0,10,10,10,10]、pills=3、strength=10 里，三个任务最强的是 30，但最强的工人吃药后也只有 20，这个任务谁都做不了：能完成 2 个而不是 3 个。

先猜再验证：能不能完成 m 个任务？能，就试更大的；不能，就试更小的。这个「能/不能」关于 m 单调：能完成 m 个，就一定能完成 m-1 个（少做一个任务更轻松）。所以二分答案成立。

一、二分答案框架

答案范围 [0, min(n, m)]。每次猜 m，检查「能不能完成 m 个」。检查时只关心最弱的 m 个任务和最强的 m 个工人：任何完成 m 个任务的方案，把某个任务换成更弱的、某个工人换成更强的，方案依然成立，所以一定存在一个最优方案只用这两组。

复杂度：排序 O(n log n + m log m)，二分 O(log min(n,m)) 轮，每轮检查 O(k)。排序是最大头。

二、检查 m：贪心 + 双端队列

任务从小到大、工人从小到大都排好序。检查时工人从弱到强扫描，任务按「当前工人能直接做」的条件解锁进队列。队里存的是下标，队内任务按下标（也按力量）递增。

对每个工人，两种情况：

1）队列里存在直接能做的任务（队头 tasks[head] <= workers[i]）：做队头那个。队头是当前队列里最弱的可做任务，做它最省：强的留着，后面还有更弱的工人。这里不吃药。

2）队列里没有能直接做的（连最弱的可做任务都比工人强）：吃药。先解锁「吃药后能做」的任务（tasks[j] <= workers[i] + strength），然后做队尾那个——队尾是队列里最强的任务。药是稀缺资源，只能花在「不吃药绝对做不了」的任务上；做最强的是把最难的啃掉，容易的留给后面的工人。

用掉的药超过 pills，或者队列空了还没任务可做，检查失败。

为什么做队尾不吃药做队头：工人从弱到强，后面来的工人只会更弱。当前工人能不吃药做队头，就让它做，把药省下来；一旦需要吃药，说明眼前的任务全是「不吃药做不了」的，此时做最强的（队尾），队列里剩下的是更弱任务，后面的工人更容易接手。

三、代码

#include <bits/stdc++.h>
    using namespace std;

    // 你可以安排的最多任务数目
    // 排序 + 二分答案 + 贪心，检查时用双端队列维护可解锁任务

    const int MAXN = 50001;
    int taskArr[MAXN];
    int workerArr[MAXN];
    int dq[MAXN];
    int h, t;

    // tasks[tl..tr] 需要力量最小的几个任务
    // workers[wl..wr] 力量值最大的几个工人
    bool f(int tl, int tr, int wl, int wr, int s, int pills) {
        h = t = 0;
        int cnt = 0;
        for (int i = wl, j = tl; i <= wr; i++) {
            for (; j <= tr && taskArr[j] <= workerArr[i]; j++) {
                dq[t++] = j;
            }
            if (h < t && taskArr[dq[h]] <= workerArr[i]) {
                h++;
            } else {
                for (; j <= tr && taskArr[j] <= workerArr[i] + s; j++) {
                    dq[t++] = j;
                }
                if (h < t) {
                    cnt++;
                    t--;
                } else {
                    return false;
                }
            }
        }
        return cnt <= pills;
    }

    int maxTaskAssign(vector<int>& ts, vector<int>& wrk, int pills, int strength) {
        int tsize = (int)ts.size();
        int wsize = (int)wrk.size();
        for (int i = 0; i < tsize; i++) taskArr[i] = ts[i];
        for (int i = 0; i < wsize; i++) workerArr[i] = wrk[i];
        sort(taskArr, taskArr + tsize);
        sort(workerArr, workerArr + wsize);
        int ans = 0;
        for (int l = 0, r = min(tsize, wsize), m; l <= r;) {
            m = (l + r) / 2;
            if (f(0, m - 1, wsize - m, wsize - 1, strength, pills)) {
                ans = m;
                l = m + 1;
            } else {
                r = m - 1;
            }
        }
        return ans;
    }

    int main() {
        int n, m, pills, strength;
        cin >> n >> m >> pills >> strength;
        vector<int> ts(n), wrk(m);
        for (int i = 0; i < n; i++) cin >> ts[i];
        for (int i = 0; i < m; i++) cin >> wrk[i];
        cout << maxTaskAssign(ts, wrk, pills, strength) << endl;
        return 0;
    }

f() 里 j 是任务扫描指针，只往前走：任务已经排好序，每个工人能解锁的任务集是前面工人的超集，不需要回头。每个任务最多入队一次、出队一次，一次检查 O(k)。

实测 n=m=5e4、值域 [1, 1e9]、pills 充足、strength=1e9 的随机数据，整个二分 + 检查 8.21ms；队列总进出 75 万次，正好对应二分 16 轮 × 每轮平均 k=2.3 万 × 进出各一次。

样例：tasks=[3,9,5,4]、workers=[5,6,4]、pills=2、strength=5 答案 3；tasks=[5,4]、workers=[0,0,0]、pills=1、strength=5 答案 1；tasks=[10,15,30]、workers=[0,10,10,10,10]、pills=3、strength=10 答案 2。

总结

「最多完成几个」直接求不好下手，改成「能不能完成 m 个」就变成一道判断题：答案关于 m 单调，二分圈定范围；判断用贪心，贪心的钥匙是「药花在最强任务上」：不吃药做最弱、吃药做最强，双端队列同时支持两头取。

这题的队列只是辅助：任务解锁集单调扩展，队列装着「能做的任务」，两头取恰好对应两种决策。单调队列前两页的候选维持在这里换了个用法：它维护的是可做的任务集，不是最值。
