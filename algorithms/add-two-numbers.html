两个链表相加

上一讲合并两条有序链，结果里的每个节点都是从输入链上摘下来的。这一讲反过来：结果里每一位都是算出来的，输入链上没有现成的节点可摘，只能自己 new。加法还多了一层纠缠：某一位写什么，取决于更低位进上来什么。

零、背景

题目给的是两个逆序存放的数：个位在链头，高位在链尾。这个设定挑得好。加法从个位开始，链表的遍历也从链头开始，逆序把这两件事对齐了，于是顺着 next 走一遍就是竖式加法的全过程。

顺序存放也能做，代价是先把两条链翻过来（上一讲的三指针），本节后面会量一下这笔开销。

一、问题

给两个非空链表，每个节点存一位数字，逆序存放，各表示一个非负整数。求和，用同样的形式返回。原题是 两数相加，n 和 m 都不超过 100。

100 位的规模跑不慢任何写法，会错的全在边界上。怎么算每一位人人都写得出，写不写得对取决于四条边界有没有照顾到。

下图是样例。342 存成 2→4→3，465 存成 5→6→4，和是 807，存成 7→0→8。

二、竖式加法

每一位上做的事都一样：sum = a + b + carry，写进结果的是 sum % 10，进到下一位的是 sum / 10。

这里有个细节值得先说清：a 和 b 都是 0 到 9，carry 最大是 1，所以 sum 最大 19，carry 只会是 0 或 1。末尾补不补那一位，判断写 carry == 1 就够了。

循环条件是「两条链都没走完」的否定，也就是 h1 != nullptr || h2 != nullptr：只要还有一条没走完就得继续。走完的那条按 0 参与计算。

struct ListNode {
        int val;
        ListNode* next;
        ListNode(int v) : val(v), next(nullptr) {}
    };

    ListNode* addTwoNumbers(ListNode* h1, ListNode* h2) {
        ListNode* ans = nullptr;
        ListNode* cur = nullptr;
        int carry = 0;
        while (h1 != nullptr || h2 != nullptr) {
            int a = h1 != nullptr ? h1->val : 0;
            int b = h2 != nullptr ? h2->val : 0;
            int sum = a + b + carry;
            int val = sum % 10;
            carry = sum / 10;
            if (ans == nullptr) {
                ans = new ListNode(val);
                cur = ans;
            } else {
                cur->next = new ListNode(val);
                cur = cur->next;
            }
            h1 = h1 != nullptr ? h1->next : nullptr;
            h2 = h2 != nullptr ? h2->next : nullptr;
        }
        if (carry == 1) {
            cur->next = new ListNode(1);
        }
        return ans;
    }

ans 和 cur 两个指针是这版的全部额外开销：ans 记住头，cur 负责往后挂。

三、四个边界，四条常写的错

这题的难点全在边界上。下面四条各跑 20000 组随机样本（长度 1 到 12 位，最高位非零），错误率是实测出来的。

第一条：循环条件写成 &&。一条链走完就停，长链剩下的高位被整个丢掉。20000 组里错 18343 组（91.72%），因为长度不等的样本恰好也是 91.72%。这条错得极其明显，跑一组就能看见。

第二条：走完的那条不判空就取 val 或 next。这条不会算出错误答案，程序直接段错误。

第三条：忘了循环结束后补最后一位进位。999 + 1 会得到 000。这条阴险得多：20000 组里只错 1190 组（5.95%）。拆开看更清楚：两条链等长时，最高位产生进位的概率是 60.11%；长度不等时只有 1.1%，因为在补 0 的那一段上，进位几乎传不到顶。随手造的短样例基本抓不到它，得专门造一组 999 + 1。

第四条：挂完新节点忘了 cur = cur->next。cur 一直指着第一个节点，每轮覆盖它的 next，最后结果链只剩两个节点。这条在 max(n, m) ≤ 2 时看不出错，20000 组里错 19530 组（97.65%），剩下那 2.80% 全是短到只有一两位的样本。

四条里三条都能靠随机样本抓到，唯独「忘进位」那条抓不到。这正是对数器那一讲说的：随机样本负责覆盖面，极端样例负责补窟窿。

四、虚拟头结点

上一版的 if (ans == nullptr) 是在特判第一个节点，写一次记一次。虚拟头结点把它省掉：在栈上放一个不存值的节点，cur 从它出发，最后返回 dummy.next。

顺带把最后的进位也塞进循环条件里，写成 h1 != nullptr || h2 != nullptr || carry != 0。进位不为 0 时循环多跑一轮，那个节点就在循环里生成了，循环外不用再补。

ListNode* addTwoNumbers2(ListNode* h1, ListNode* h2) {
        ListNode dummy(0);
        ListNode* cur = &dummy;
        int carry = 0;
        while (h1 != nullptr || h2 != nullptr || carry != 0) {
            int a = h1 != nullptr ? h1->val : 0;
            int b = h2 != nullptr ? h2->val : 0;
            int sum = a + b + carry;
            cur->next = new ListNode(sum % 10);
            carry = sum / 10;
            cur = cur->next;
            if (h1 != nullptr) h1 = h1->next;
            if (h2 != nullptr) h2 = h2->next;
        }
        return dummy.next;
    }

两种写法位数一样，区别只在「最后一个进位」放在哪儿处理：一个在循环外补，一个在循环里多跑一轮。虚拟头结点版少一个分支，改起来也不容易漏。

五、能不能省掉那些 new

每一位都得有地方放，new 是省不掉的，除非拿输入链的节点来装答案。做法是挑较长的那条当载体，逐位改写它的 val，只有最后真有进位时才 new 一个。

实测 n = m = 10⁶ 位：新建节点版 16.7 ms，复用版 10.4 ms。省下的 6.3 ms 是一百万次 new 的价钱。

int listLen(ListNode* h) {
        int n = 0;
        while (h != nullptr) {
            n++;
            h = h->next;
        }
        return n;
    }

    ListNode* addInPlace(ListNode* h1, ListNode* h2) {
        int n1 = listLen(h1), n2 = listLen(h2);
        ListNode* cur = n1 >= n2 ? h1 : h2;
        ListNode* other = n1 >= n2 ? h2 : h1;
        ListNode* pre = nullptr;
        int carry = 0;
        while (cur != nullptr) {
            int b = other != nullptr ? other->val : 0;
            int sum = cur->val + b + carry;
            cur->val = sum % 10;
            carry = sum / 10;
            pre = cur;
            cur = cur->next;
            if (other != nullptr) other = other->next;
        }
        if (carry == 1) {
            pre->next = new ListNode(1);
        }
        return n1 >= n2 ? h1 : h2;
    }

代价写在函数名里：输入的链表被改了。调用方如果还要用原来那两个数，得自己先抄一份。笔试里这句话要跟面试官说清楚。

六、递归写法

递归版最短：当前位算完，剩下的交给下一层。终止条件是两条链都空且进位为 0。

ListNode* addRec(ListNode* h1, ListNode* h2, int carry) {
        if (h1 == nullptr && h2 == nullptr && carry == 0) {
            return nullptr;
        }
        int sum = (h1 != nullptr ? h1->val : 0) + (h2 != nullptr ? h2->val : 0) + carry;
        ListNode* node = new ListNode(sum % 10);
        node->next = addRec(h1 != nullptr ? h1->next : nullptr,
                            h2 != nullptr ? h2->next : nullptr, sum / 10);
        return node;
    }

层数等于 max(n, m)，每层一个栈帧。实测 15 万位能跑完，20 万位段错误，和递归反转那次一样，卡在默认 8 MB 的栈上。100 位的原题随便写，真拿它当大整数用就别走这条路。

七、如果链表是顺序存的

高位在头时，个位在链尾，得先把它翻过来才能加。三步：反转两条输入链，相加，再反转结果。反转用上一讲的三指针。

ListNode* reverseList(ListNode* head) {
        ListNode* pre = nullptr;
        while (head != nullptr) {
            ListNode* nxt = head->next;
            head->next = pre;
            pre = head;
            head = nxt;
        }
        return pre;
    }

    ListNode* addInOrder(ListNode* h1, ListNode* h2) {
        return reverseList(addTwoNumbers(reverseList(h1), reverseList(h2)));
    }

实测 n = m = 10⁶ 位：反转两条 7.5 ms，相加 16.7 ms，反转结果 2.6 ms。两次反转占掉总时间的三分之一，这就是「顺序存储」的额外账单。

八、比赛里的数组版

比赛里更常见的写法是静态数组：val[] 存值、next[] 存下标，-1 表示空。下标从 1 开始编号，0 留给「没有」。

好处不只是省掉 new。数组版还能直接按下标跳，做「两条链同时走」之类的动作时不用在脑子里维护指针。

const int MAXN = 1000010;
    int val1[MAXN], nxt1[MAXN];
    int val2[MAXN], nxt2[MAXN];
    int rv[MAXN], rn[MAXN], tot = 0;

    int addArrays(int h1, int h2) {
        int head = -1, tail = -1, carry = 0;
        while (h1 != -1 || h2 != -1) {
            int a = h1 != -1 ? val1[h1] : 0;
            int b = h2 != -1 ? val2[h2] : 0;
            int sum = a + b + carry;
            int id = ++tot;
            rv[id] = sum % 10;
            rn[id] = -1;
            carry = sum / 10;
            if (head == -1) head = id;
            else rn[tail] = id;
            tail = id;
            if (h1 != -1) h1 = nxt1[h1];
            if (h2 != -1) h2 = nxt2[h2];
        }
        if (carry == 1) {
            int id = ++tot;
            rv[id] = 1;
            rn[id] = -1;
            rn[tail] = id;
        }
        return head;
    }

九、一个节点只存一位，是题目规定

不是最优解。一个节点存 9 位（0 到 999999999，int 装得下），节点数降到九分之一，遍历次数跟着降。

实测 10⁶ 位：每位 1 个节点，1000000 个节点，55.3 ms；每位 9 位，111112 个节点，7.0 ms。

这时候 carry 就不止 1 了：sum 最大是 999999999 × 2 + 1 = 1999999999，离 INT_MAX（2147483647）只差不到 1.5 亿，装得下，但没有余量。存 9 位是 int 能撑住的极限，再往上就得换 long long。

复杂度分析

n 和 m 是两条链的长度。每一位最多算一次，最后可能因为进位多算一轮，所以是 O(max(n, m))，写成 O(n + m) 也对。

写法时间额外空间
新建节点（ans / cur 版、虚拟头结点版）O(max(n, m))O(max(n, m))，结果链本身
复用较长的那条链O(max(n, m))O(1)，结果就长在输入链上
递归版O(max(n, m))O(max(n, m))，栈深度
数组版O(max(n, m))O(max(n, m))，预分配的三个数组

时间上没有优化空间，每一位至少要被看一次。能省的只有常数：少 new 一次、少走一趟、一个节点多存几位。

十、最后

写完之后，随机跑几百组只能证明「大多数情况对」。这题真正会错的那一处（忘了最后的进位）在随机样本里的现形率只有 6%，得手动补上 9→9→9 加 1、0 加 0 这两组。剩下的三条边界，找一组两条链不等长的样例就全露出来了。
