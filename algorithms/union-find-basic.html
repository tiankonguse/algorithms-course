并查集：合并与查找的均摊 O(1)

要维护「元素分属哪些集合」，支持合并两个集合、查询两个元素是否同集合。并查集用一棵树存一个集合，两个优化把单次操作压到反阿克曼级别，实践里就是 O(1)。

零、背景

一开始每个元素都在自己的集合里，需要支持三类操作：find(i) 找 i 所在集合的代表元素，isSameSet(a, b) 判两个元素是否同集合，union(a, b) 把两个集合整个合并。

朴素写法是每个集合记成员列表，union 时把一边的全部元素搬进另一边。最坏 O(n)，n 到 10⁶、m 个操作就是 10¹² 次搬运，跑不完。问题在于集合身份是「名单」，没有结构可复用。

一、父亲数组：每个集合一棵树

每个集合存成一棵树，father[i] 指向父节点，根节点指向自己，根就是集合的代表元素。find(i) 沿 father 链一路走到根；isSameSet 就是两个 find 的根相同；union 把一棵树的根挂到另一棵树的根下面。

关键动作只有两个：find 的路径压缩（扁平化）和 union 的按大小合并（小挂大）。这两件事都发生在 find 里，或者说为 find 服务。

二、扁平化：查一次就把路压平

find(i) 沿着链往上走时，把经过的每个节点直接挂到根下面。下次再查这些节点，一步就到根。实现有递归和非递归两种：递归版两行代码，回溯时自然压平；非递归版先把路径收进数组再回写，避免递归深度。

扁平化是必做的优化。没有它，一串 union 能把树挂成深度 n 的长链，find 一次走 n 步；有了它，树越查越平，任何一次 find 的花销都被摊到它压平的那些节点上。

三、小挂大：树高有上限

union 时把 size 小的树挂到 size 大的树下面。size 只记录在根上，合并时根把自己的 size 累加进新根。做了小挂大，树高 ≤ log₂ n，即使没有扁平化也不怕长链；扁平化 + 小挂大一起用，摊下来接近常数。

小挂大是可以省的优化（洛谷 P3367 的递归版就没写），省了也不慢太多，但 n = 10⁶ 的模版题建议留着。实测：1e6 个元素串行 union 成长链，随机 find 十万次平均只跳 1 步，扁平化在第一次查询就把链拍扁了。

四、两个模版

牛客模版：非递归扁平化 + 小挂大，n 上限 10⁶。

#include <bits/stdc++.h>
    using namespace std;

    // 数组实现：father[i] 指向父节点，sz[i] 只在树根有效
    const int MAXN = 1000001;
    int father[MAXN], sz[MAXN], stk[MAXN];
    int n;

    void build() {                        // 每个元素单独成集
        for (int i = 0; i <= n; i++) {
            father[i] = i;
            sz[i] = 1;
        }
    }

    int find(int i) {                     // 非递归扁平化：先沿链收集，再整体压平
        int top = 0;
        while (i != father[i]) {
            stk[top++] = i;
            i = father[i];
        }
        while (top > 0) {
            father[stk[--top]] = i;
        }
        return i;
    }

    bool isSameSet(int x, int y) {
        return find(x) == find(y);
    }

    void unionSet(int x, int y) {         // 小挂大：size 小的树挂到大的下面
        int fx = find(x), fy = find(y);
        if (fx != fy) {
            if (sz[fx] >= sz[fy]) {
                sz[fx] += sz[fy];
                father[fy] = fx;
            } else {
                sz[fy] += sz[fx];
                father[fx] = fy;
            }
        }
    }

洛谷模版：递归扁平化、省略小挂大，n 上限 2×10⁵。查询输出 Y/N，合并不输出。

#include <bits/stdc++.h>
    using namespace std;

    // 递归实现路径压缩，省略小挂大（洛谷 P3367 的写法）
    const int MAXN = 200001;
    int father[MAXN];
    int n;

    void build() {
        for (int i = 0; i <= n; i++) father[i] = i;
    }

    int find(int i) {
        if (i != father[i]) {
            father[i] = find(father[i]); // 一路递归到底，回溯时把路径压平
        }
        return father[i];
    }

    bool isSameSet(int x, int y) {
        return find(x) == find(y);
    }

    void unionSet(int x, int y) {
        father[find(x)] = find(y);
    }

五、复杂度

指标值
单次操作均摊O(α(n))，反阿克曼函数
额外空间O(n)（father 数组 + size/栈）

α(n) 慢到什么程度：n = 10⁸⁰（宇宙原子数量级）时 α(n) 也不超过 6。实测 n = m = 10⁶ 的混合操作（50 万合并 + 50 万查询）只要 21.62ms，写题时直接当 O(1) 用。

六、总结

并查集 = father 数组 + 两件事：find 一路压平（必做），union 小挂大（推荐）。单次操作均摊 O(α(n))，α(n) 在 n 到 10⁸⁰ 时也不超过 6，实践按 O(1)。

模版本身不值钱，值钱的是「维护集合数 sets」这个顺手动作，下一页的情侣牵手和相似字符串组全靠它出答案。
