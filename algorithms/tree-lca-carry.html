跳表上挂的第二份信息：k 步之和与路径回文

跳表的每一格原本只记「跳 2p 步落在谁身上」。只要沿路要统计的量能像最小值那样「两半一拼」就合成出来，它就能挂上去一起倍增。这一页挂两个：编号之和，和一段字符串的正反两个哈希。

零、背景

回顾一下最小值是怎么挂上去的：stmin[u][p] = min(stmin[u][p−1], stmin[跳点][p−1])——2p 步的路拆成前后两个 2p−1 步，各算各的再合并。能这么拆的量都能挂。求和满足（前半的和加后半的和）、字符串哈希满足（H(A‖B) = H(A) × B|B| + H(B)），这两个就是这一页的主角。

挂在跳表上之后，单次查询按 k 的二进制拆成若干段，每段直接读表，不用走完整条路。路径有三千条边时，这就是「走三千步」和「跳十几次」的差距。

一、传球游戏：k 步触球的编号和

n 名玩家编号 0 到 n − 1，receiver[i] 是 i 传给谁（可以传给自己）。选一个起点 x，球传恰好 k 次，f(x) 是这 k+1 个触球者的编号之和（起点算一次，重复触球重复计）。求 f(x) 的最大值。n ≤ 10⁵，k ≤ 10¹⁰。

把 receiver 看成「每个人一个确定的下一站」，从任何点出发往前走，路线完全确定。令 stsum[i][0] = receiver[i]（走一步触到的人，不含自己），递推是

stsum[i][p] = stsum[i][p−1] + stsum[stjump[i][p−1]][p−1]

查询时把 k 拆成二进制，从高位到低位，是 1 的那位跳一次、把那段的和加上：

const int MAXN = 100001;
    const int LIMIT = 34;

    int power, m;
    int kbits[LIMIT];
    int stjump[MAXN][LIMIT];
    long long stsum[MAXN][LIMIT];

    void build(long long k) {
        power = 0;
        while ((1LL << power) <= (k >> 1)) {
            power++;
        }
        m = 0;
        for (int p = power; p >= 0; p--) {
            if ((1LL << p) <= k) {
                kbits[m++] = p;
                k -= 1LL << p;
            }
        }
    }

    long long getMaxFunctionValue(vector<int> &receiver, long long k) {
        build(k);
        int n = receiver.size();
        for (int i = 0; i < n; i++) {
            stjump[i][0] = receiver[i];
            stsum[i][0] = receiver[i];
        }
        for (int p = 1; p <= power; p++) {
            for (int i = 0; i < n; i++) {
                stjump[i][p] = stjump[stjump[i][p - 1]][p - 1];
                stsum[i][p] = stsum[i][p - 1] + stsum[stjump[i][p - 1]][p - 1];
            }
        }
        long long ans = 0;
        for (int i = 0; i < n; i++) {
            int cur = i;
            long long sum = i;
            for (int j = 0; j < m; j++) {
                sum += stsum[cur][kbits[j]];
                cur = stjump[cur][kbits[j]];
            }
            ans = max(ans, sum);
        }
        return ans;
    }

起点自己那份单独加（sum = i），因为表里存的都是「走了之后触到的人」。k = 0 时一个二进制位都没有，f(x) = x，答案 n − 1。

这道题的图可以有环、可以是基环树，跳表照用。倍增只要求「每一步有确定的下一站」，至于是树边还是环边无所谓。这题还有更省内存的基环树做法，跳表版的价值在于模板一行不用改。

代价算一笔账。n = 10⁵、k = 10¹⁰ 时表要 34 层，stjump 13.6 MB 加 stsum（long long）27.2 MB，合计约 40 MB；建表加全部查询实测 38.1 ms。逐步模拟要做 n × k = 10¹⁵ 次加法，同一台机器上 k = 2 万就要 2167 ms，k = 10¹⁰ 根本跑不完。

二、路径回文：正反两个哈希

树上每个点一个小写字母，问 a 到 b 的路径（节点串起来）是不是回文。n、m 都是 10⁵ 量级，路径本身可能很长，把字符串真拼出来再比较，一条查询 O(路径长度)。

换哈希：给路径串算一个多项式哈希，回文等价于「正着读的哈希等于反着读的哈希」。麻烦在于路径要拐弯：先从 a 上爬到 LCA，再从 LCA 下来到 b，两段的顺序一个是从下往上、一个是从上往下。所以表要挂两份：

1）stup[u][p]：u 往上 2p 个点的哈希，从近到远排；
2）stdown[u][p]：同一段点，从远到近排。

递推只差一个拼接顺序：

const int MAXN = 100001;
    const int LIMIT = 18;

    int power;
    int s[MAXN];
    int head[MAXN], to[MAXN << 1], nxt[MAXN << 1], cnt;
    int deep[MAXN];
    int jump[MAXN][LIMIT];
    unsigned long long K = 499;
    unsigned long long kpow[MAXN];
    unsigned long long stup[MAXN][LIMIT];
    unsigned long long stdown[MAXN][LIMIT];

    void dfs(int u, int f) {
        deep[u] = deep[f] + 1;
        jump[u][0] = f;
        stup[u][0] = stdown[u][0] = s[f];
        for (int p = 1; p <= power; p++) {
            int v = jump[u][p - 1];
            jump[u][p] = jump[v][p - 1];
            stup[u][p] = stup[u][p - 1] * kpow[1 << (p - 1)] + stup[v][p - 1];
            stdown[u][p] = stdown[v][p - 1] * kpow[1 << (p - 1)] + stdown[u][p - 1];
        }
        for (int e = head[u]; e != 0; e = nxt[e]) {
            if (to[e] != f) {
                dfs(to[e], u);
            }
        }
    }

查询把路径拆成两段。上坡段从 a 一路跳到 LCA，每跳一段就 up = up × B2^p + stup[from][p]——新的一段接在尾巴上。下坡段反过来，从 b 往上收集，用 stdown 保证收集到的顺序是从远到近，最后 down = stdown[to][p] × Bheight + down 把新段接在头上。两段一拼：

unsigned long long hashPath(int from, int lca, int to) {
        unsigned long long up = s[from];
        for (int p = power; p >= 0; p--) {
            if (deep[jump[from][p]] >= deep[lca]) {
                up = up * kpow[1 << p] + stup[from][p];
                from = jump[from][p];
            }
        }
        if (to == lca) {
            return up;
        }
        unsigned long long down = s[to];
        int height = 1;
        for (int p = power; p >= 0; p--) {
            if (deep[jump[to][p]] > deep[lca]) {
                down = stdown[to][p] * kpow[height] + down;
                height += 1 << p;
                to = jump[to][p];
            }
        }
        return up * kpow[height] + down;
    }

    bool isPalindrome(int a, int b) {
        int c = lca(a, b);
        return hashPath(a, c, b) == hashPath(b, c, a);
    }

两个方向的哈希各算一遍，相等就是回文。这里有个细节：上坡段的终止条件是 deep[jump[from][p]] >= deep[lca]（可以落在 LCA 上），下坡段是 deep[jump[to][p]] > deep[lca]（严格高于 LCA，停在 LCA 的儿子上）。LCA 这个点只能算一次，归上坡段管。

方向写反的代价实测过：n = 10⁵ 的随机树上 10⁵ 条查询，真回文的 29 条里只有 5 条还能判对 YES，83% 的回文被漏掉。诊断线索也很直白——把下坡段换成 stup 后程序照样跑、照样出 YES/NO，只是答案错了。

代价对比（同一批 10⁵ 条查询）：哈希法 96.9 ms 跑完全部；拼串比较在随机树上平均路径只有 21.6 个点、反而只要 64.7 ms，可树一旦退化成链、平均路径 33325 个点，拼串跑 2000 条就用了 144.7 ms，折算全量约 7237 ms，差 87 倍。哈希法慢在每次固定要跳 2 × 18 层，路径短的时候占不到便宜，但它的代价与路径长度无关，按最坏情况选就对了。

四、最后

这一页的三件事：跳表能挂任何「两半一拼」的量，和与多项式哈希都满足；k 步之和把 k 拆成二进制逐位跳，图不是树也照用；路径回文要在跳表上同时存正反两个哈希，上坡段用近到远那份、下坡段用远到近那份，LCA 归上坡段管。

两个实现上的坑都值得记：传球游戏的表是 long long，n × log k 双份就 40 MB，按题目上限先算内存再动手；回文的两个方向写反了不会报错，只会安静地漏掉八成回文，收尾前拿几条手算的回文核对一遍才放心。
