路径最大利润与换根子树

同样是把路径拆成 O(log n) 段，这一节的两个题各有各的别扭处：一个要同时维护正着走和反着走两种利润，拼接时方向不能搞反；另一个是树的根会变，而剖分显然不能每次重做。

零、背景

前面几节查的量都有一个共同点：不管从左往右还是从右往左读，结果都一样。和、最大值、颜色段数都是这样，所以段与段随便拼。

换成一个有方向的量，麻烦就来了。买卖利润是「先买的在前、卖出的在后」，把路径倒过来读，答案不是同一个。这一节先处理这个，再看根会动的那种题。

一、题目6：旅游

洛谷 P3976。n 个城市连成树，每个城市有宝石价格。每次操作给 x、y、v：沿 x 到 y 的最短路，先选一城买入、再选一城卖出，打印最大利润（负数打印 0）；然后沿途所有城市价格增加 v。n、m 不超过 5 × 10⁴。

线段树的每个区间要存四个量：maxv、minv、lprofit、rprofit。前两个好懂；lprofit 是在区间里从左往右走能拿到的最大利润，rprofit 是从右往左走能拿到的最大利润。两个都要留着，因为父区间不知道自己会被正着用还是反着用。

合并左右儿子时，前两个量照常取最值。lprofit 有三个来源：左儿子内部的、右儿子内部的、以及「在左儿子买、在右儿子卖」，也就是右儿子的最大值减左儿子的最小值。rprofit 对称，来源是左儿子的最大值减右儿子的最小值。

路径被拆成多段之后，方向要统一成「从 x 走到 y」。代码用两个数组分别收集两侧的段：

xpath 存 x 侧所有段，段内按 dfn 顺序，也就是从靠近 LCA 的一端到 x；ypath 存 y 侧，同样是从靠近 LCA 的一端到 y。整条旅程 x → LCA → y，就是把 xpath 反着读、再把 ypath 正着读。

三个候选各自对应一种情形：买卖都在 x 侧（这时是从 x 往上，取 xpath 的 rpro）、都在 y 侧（从 LCA 往下，取 ypath 的 lpro）、以及买在 x 侧卖在 y 侧。再没有第四种，因为 y 侧买、x 侧卖表示逆着旅程走，不允许。

区间加 v 时，maxv 和 minv 都要加 v，两个方向的利润不会变（同加同减，差不变），所以标记里不用管它们。

合并四个量：

void up(int i) {
        int l = i << 1;
        int r = i << 1 | 1;
        maxv[i] = max(maxv[l], maxv[r]);
        minv[i] = min(minv[l], minv[r]);
        lprofit[i] = max({lprofit[l], lprofit[r], maxv[r] - minv[l]});
        rprofit[i] = max({rprofit[l], rprofit[r], maxv[l] - minv[r]});
    }

把一段并进已有结果：

void merge(int ans[], int rmax, int rmin, int rlpro, int rrpro) {
        int lmax  = ans[0];
        int lmin  = ans[1];
        int llpro = ans[2];
        int lrpro = ans[3];
        ans[0] = max(lmax, rmax);
        ans[1] = min(lmin, rmin);
        ans[2] = max({llpro, rlpro, rmax - lmin});
        ans[3] = max({lrpro, rrpro, lmax - rmin});
    }

一次查询加一次修改：

void clone(int *a, int *b) {
        a[0] = b[0];
        a[1] = b[1];
        a[2] = b[2];
        a[3] = b[3];
    }

    int compute(int x, int y, int v) {
        int tmpx = x;
        int tmpy = y;
        int xpath[4] = {-INF, INF, 0, 0};
        int ypath[4] = {-INF, INF, 0, 0};
        int cur[4];
        while (top[x] != top[y]) {
            if (dep[top[x]] <= dep[top[y]]) {
                query(cur, dfn[top[y]], dfn[y]);
                merge(cur, ypath[0], ypath[1], ypath[2], ypath[3]);
                clone(ypath, cur);
                y = fa[top[y]];
            } else {
                query(cur, dfn[top[x]], dfn[x]);
                merge(cur, xpath[0], xpath[1], xpath[2], xpath[3]);
                clone(xpath, cur);
                x = fa[top[x]];
            }
        }
        if (dep[x] <= dep[y]) {
            query(cur, dfn[x], dfn[y]);
            merge(cur, ypath[0], ypath[1], ypath[2], ypath[3]);
            clone(ypath, cur);
        } else {
            query(cur, dfn[y], dfn[x]);
            merge(cur, xpath[0], xpath[1], xpath[2], xpath[3]);
            clone(xpath, cur);
        }
        int ans = max({xpath[3], ypath[2], ypath[0] - xpath[1]});
        x = tmpx;
        y = tmpy;
        while (top[x] != top[y]) {
            if (dep[top[x]] <= dep[top[y]]) {
                add(dfn[top[y]], dfn[y], v, 1, n, 1);
                y = fa[top[y]];
            } else {
                add(dfn[top[x]], dfn[x], v, 1, n, 1);
                x = fa[top[x]];
            }
        }
        add(min(dfn[x], dfn[y]), max(dfn[x], dfn[y]), v, 1, n, 1);
        return ans;
    }

二、题目7：遥远的国度

洛谷 P3979。n 个节点的树有点权，初始给定根。三种操作：操作 1 把根换成 x；操作 2 把 x 到 y 的路径全部改成 v；操作 3 打印当前树形态下 u 的子树最小值。n、m 不超过 10⁵。

换根最直观的做法是重新剖分，但一次 O(n) 扛不住 10⁵ 次。实际做法是：始终以 1 号为根剖一次，之后再也不动，回答子树查询时用分类讨论把「换根之后的子树」翻译成若干段原来的区间。

设当前根是 root，问 u 的子树，三种情况：

第一种，root 就是 u。整棵树都是它的子树，直接读线段树根节点的 minv[1]。

第二种，u 不是 root 的祖先。换根没有影响，u 的子树还是原来那一段 [dfn[u], dfn[u] + siz[u] − 1]。判据是 root 不在 u 的原子树里，也就是 dfn[root] < dfn[u] 或者 dfn[u] + siz[u] ≤ dfn[root]。

第三种，u 是 root 的祖先。这时 u 被 root 拽到了下面，它的子树变成「整棵树扣掉 u 的那个包含 root 的儿子」。记这个儿子为 uson，答案是 [1, dfn[uson] − 1] 与 [dfn[uson] + siz[uson], n] 两段的最小值。

找 uson 的办法是 findSon：从 root 沿重链往上跳，看哪一条链的链头父亲正好是 u，那个链头就是要找的儿子；如果跳到与 u 同链，说明 u 到 root 之间只有一条重链，答案就是 son[u]。

这里有个细节：原式 [1, dfn[uson] − 1] 在 dfn[uson] = 1 时是空区间，[dfn[uson] + siz[uson], n] 在越界时也是空的。代码里两个 if 就是在挡这两种空区间，少一个就会查到不该查的位置。

int findSon(int root, int u) {
        while (top[root] != top[u]) {
            if (fa[top[root]] == u) {
                return top[root];
            }
            root = fa[top[root]];
        }
        return son[u];
    }

    int treeQuery(int root, int u) {
        if (root == u) {
            return minv[1];
        } else if (dfn[root] < dfn[u] || dfn[u] + siz[u] <= dfn[root]) {
            return query(dfn[u], dfn[u] + siz[u] - 1, 1, n, 1);
        } else {
            int uson = findSon(root, u);
            int ans = INT_MAX;
            if (1 <= dfn[uson] - 1) {
                ans = min(ans, query(1, dfn[uson] - 1, 1, n, 1));
            }
            if (dfn[uson] + siz[uson] <= n) {
                ans = min(ans, query(dfn[uson] + siz[uson], n, 1, n, 1));
            }
            return ans;
        }
    }

复杂度分析

两题的剖分依旧是那两次 dfs，差别在线段树存了几个量、以及查询要拆成几段。

操作时间说明
dfs1 + dfs2O(n)换根题只剖一次，之后不再重剖
旅游单次操作O(log² n)查询与修改各走一遍路径，各不超过 2 log₂ n + 1 段
换根（操作 1）O(1)只改一个变量，不动剖分结构
路径覆盖O(log² n)区间覆盖标记，标记是重写
子树最小值O(log n)一或两次区间查询，findSon 另需 O(log n)
空间O(n)剖分 7n；旅游题线段树存 4 个量共约 6 × 4n，换根题只有 minv 与标记

旅游题一份信息四个量，合并时要写四条式子，看着啰嗦，但省掉了「为两个方向各查一遍」的开销，仍是每段 O(log n)。
