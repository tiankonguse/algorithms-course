矩阵快速幂：把递推写成矩阵乘

斐波那契的递推是 f(n) = f(n-1) + f(n-2)，一次一步，n 给到 109 就是十亿次加法。把相邻两项打包成一个向量，递推变成乘一个固定矩阵，而矩阵连乘照样能套快速幂，30 轮就出结果。

零、一次一步太慢

O(n) 递推的写法是滚两个变量，每步一次加法加一次取模。实测 106 步 11.05 ms，109 步就是 11 秒，一组数据就把时间吃完了。

先说清楚一点：斐波那契和爬楼梯这两道常见题的数据范围都小到矩阵快速幂显不出优势（n 最大 45 和 37），老老实实递推反而更快。这里练的是「递推写成矩阵」这个动作，真正用得上的地方是后面的 k 阶递推和 k 维状态转移。

一、把递推写成矩阵乘

把相邻两项打包成行向量 v(n) = (f(n), f(n-1))。想让 v(n) 前进到 v(n+1) = (f(n+1), f(n))，只要让 v(n) 右乘一个 2 阶方阵：

(f(n+1), f(n)) = (f(n), f(n-1)) × [[1, 1], [1, 0]]

展开看一眼就懂了。结果的第一个分量 = 1 × f(n) + 1 × f(n-1)，正好是 f(n+1)；第二个分量 = 1 × f(n) + 0 × f(n-1)，就是把 f(n) 原样挪过去。

把这一句连用 n-1 次，中间的状态互相抵消，剩下

(f(n), f(n-1)) = (f(1), f(0)) × Mn-1，M = [[1, 1], [1, 0]]

问题就变成了「求一个固定方阵的 k 次方」，这正是快速幂擅长的事。

二、矩阵乘法与单位矩阵

矩阵相乘照定义来：结果的第 i 行第 j 列，等于左矩阵第 i 行和右矩阵第 j 列对应项相乘再求和。k 阶方阵相乘一次要 k3 次乘加，2 阶是 8 次，6 阶是 216 次。

还有一个角色要补上：单位矩阵。它是对角线为 1、其余为 0 的方阵，任何一个方阵乘上它都不变，A × I = A，所以它就是矩阵世界里的 1。快速幂里 ans 从 1 开始，矩阵版就从单位矩阵开始。

typedef long long ll;
    const int MAXK = 6;
    const ll MOD = 1000000007;

    struct Mat {
    	int r, c;
    	ll a[MAXK][MAXK];
    	Mat(int r_ = 0, int c_ = 0) : r(r_), c(c_) {
    		memset(a, 0, sizeof(a));
    	}
    };

    // 单位矩阵：对角线是 1、其余是 0，它就是矩阵里的 1
    Mat identity(int n) {
    	Mat ans(n, n);
    	for (int i = 0; i < n; i++) {
    		ans.a[i][i] = 1;
    	}
    	return ans;
    }

    // 矩阵相乘：a 的列数必须等于 b 的行数
    Mat multiply(const Mat &x, const Mat &y) {
    	Mat ans(x.r, y.c);
    	for (int i = 0; i < x.r; i++) {
    		for (int k = 0; k < x.c; k++) {
    			for (int j = 0; j < y.c; j++) {
    				ans.a[i][j] = (ans.a[i][j] + x.a[i][k] * y.a[k][j]) % MOD;
    			}
    		}
    	}
    	return ans;
    }

三、矩阵快速幂

代码结构和数的快速幂一模一样，只换了两样东西：把乘法换成矩阵相乘，把起点 1 换成单位矩阵。

// 矩阵快速幂，要求 m 是方阵
    Mat matrixPower(Mat m, long long p) {
    	Mat ans = identity(m.r);
    	while (p > 0) {
    		if (p & 1) {
    			ans = multiply(ans, m);
    		}
    		m = multiply(m, m);
    		p >>= 1;
    	}
    	return ans;
    }

指数 p 每右移一位，m 平方一次，轮数是 p 的二进制位数。整个过程的矩阵相乘次数是 O(log p)。

乘法的方向不能随手调换。矩阵乘法没有交换律，A × B 和 B × A 一般不是一回事。推导时定的是「行向量在左、矩阵在右」，代码里就一直保持这个顺序，别中途改成矩阵左乘。

四、斐波那契与爬楼梯

斐波那契的起点是 v(1) = (f(1), f(0)) = (1, 0)，幂次是 n-1，最后取结果的第一个分量。

// 斐波那契第 n 项，O(log n)
    long long fib(long long n) {
    	if (n == 0) {
    		return 0;
    	}
    	if (n == 1) {
    		return 1;
    	}
    	Mat start(1, 2);			// 状态 (f(1), f(0))
    	start.a[0][0] = 1;
    	Mat base(2, 2);
    	base.a[0][0] = 1; base.a[0][1] = 1;
    	base.a[1][0] = 1; base.a[1][1] = 0;
    	Mat ans = multiply(start, matrixPower(base, n - 1));
    	return ans.a[0][0];
    }

爬楼梯问的是「一次走 1 级或 2 级，走到第 n 级有多少种走法」，递推式还是 f(n) = f(n-1) + f(n-2)，矩阵可以直接复用。差别只在起点：把「站在地面」算作 1 种走法，v(1) = (f(1), f(0)) = (1, 1)。

// 爬楼梯：一次 1 级或 2 级，走到第 n 级的方法数
    long long climbStairs(long long n) {
    	if (n == 0) {
    		return 1;
    	}
    	if (n == 1) {
    		return 1;
    	}
    	Mat start(1, 2);			// 状态 (f(1), f(0))，f(1) = 1、f(0) = 1
    	start.a[0][0] = 1;
    	start.a[0][1] = 1;
    	Mat base(2, 2);			// 和斐波那契同一个矩阵
    	base.a[0][0] = 1; base.a[0][1] = 1;
    	base.a[1][0] = 1; base.a[1][1] = 0;
    	Mat ans = multiply(start, matrixPower(base, n - 1));
    	return ans.a[0][0];
    }

对一下答案：n = 1 只有 1 种，n = 2 是 2 种（1+1、2），n = 4 是 5 种，跟斐波那契错开一位，就是因为起点从 (1, 0) 变成了 (1, 1)。

五、逐轮看一遍

矩阵快速幂逐轮：ans 累积、m 自己平方

m 就是递推矩阵的 2i 次方，橙框标的是这一轮刚平方出来的 m，蓝框是累积到 ans 里的结果。最后 ans 乘上起点向量就是 (f(n), f(n-1))。

复杂度分析

做法关键操作时间空间
滚动变量递推n 次加法加取模O(n)O(1)
矩阵连乘n-1 次 k 阶矩阵相乘O(n · k3)O(k2)
矩阵快速幂log n 次矩阵相乘，每次 k3 次乘加O(k3 · log n)O(k2)

2 阶时 k3 = 8，log2 109 ≈ 30，合起来约 270 次乘加。实测斐波那契第 109 项单次 0.0009 ms（跑 1000 次累计 0.85 ms），同样规模的连乘要 11 秒。省下来的就是那个 n：递推的次数从 n 掉到 log n，代价是每次乘法的常数从 1 涨到 k3，只要 n 一大就稳赚。

总结

固定系数的线性递推可以打包成矩阵乘：把相邻 k 项排成一个行向量，右乘一个 k 阶方阵，前进一格。

方阵的构造有固定套路：第 0 列写递推式的系数，其余列负责把状态往后挪。

矩阵相乘满足结合律，所以中间那些状态可以合并，v(n) = v(1) × Mn-1，而 Mn-1 用快速幂求。

代码把数的快速幂照搬过来，乘号换成矩阵相乘，起点 1 换成单位矩阵。方向别写反，矩阵乘法没有交换律。

k 阶递推只是起点。递推关系本身认不出来、或者状态是一堆互相转移的量时，同一个套路还能继续用。
