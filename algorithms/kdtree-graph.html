K-D 树优化建图

一条边要连向「一片区域里的所有点」，边数就会炸。K-D 树的每个节点本来就代表一个矩形区域，给每个区域加一个虚点，让边连到虚点而不是连到每个点，边数就从 O(n·m) 降到 O(m√n)。

零、背景

图论题里有一类边不是「点到点」，而是「点到一片」：从某个点出发，可以花固定的代价到达某个范围内的任意一个点。这类边如果老实建出来，数量是范围大小乘以边的条数，很快就爆掉。

处理它的办法和优化建图的思路一脉相承：不直接连到终点，而是造一批中间节点，让边通过这些中间节点间接到达终点。线段树优化建图是这么做的，K-D 树优化建图也是，只不过把「区间」换成了「平面上的矩形」。

一、问题

弹跳。一共有 n 个点，编号 1 到 n，给定每个点的坐标 (x, y)。一共有 m 个弹跳装置，装置的参数是 p、t、l、r、d、u：表示在 p 号点花 t 的时间，可以跳到 x 在 [l, r]、y 在 [d, u] 这个矩形里的任意一个点。从 1 号点出发，求到 2、3 … n 号点各自的最短用时。点可以重复经过，装置也可以重复使用。

例子用 6 个点和 3 个装置：

点123456
坐标(2, 8)(5, 9)(8, 7)(3, 4)(6, 5)(9, 2)
装置所在点花费 t能跳到的矩形
11 号3[1, 7] × [3, 9]
21 号5[6, 10] × [1, 6]
35 号2[7, 10] × [6, 10]

二、朴素做法

把每个装置能到达的点都连一条边。装置 1 的矩形里有 4 个点，就连 4 条；装置 2 里有 2 个；装置 3 里有 1 个。看着不多，可 n 到 7 × 10⁴、m 到 1.5 × 10⁵ 时，一个装置覆盖的范围可能是 O(n) 个点，总边数就是 O(n·m)，一亿条边往上，存不下也跑不动。

换个想法：这些边权重都一样（都是这个装置的 t），而且覆盖的是一整个矩形。矩形正好是 K-D 树最擅长描述的东西。

三、给每个区域建一个虚点

先对 n 个点的坐标建一棵静态 K-D 树。这棵树的每个节点不只是代表一个点，它同时代表一个矩形区域，就是它子树里所有点的包围盒。

接下来给每个节点配一个虚点，编号记作 n + 节点编号。虚点连三条边出去：

  1. 连向它自己代表的那个真实点（也就是这个节点上存的中位点）。
  2. 左儿子不为空，就连向左儿子的虚点。
  3. 右儿子不为空，就连向右儿子的虚点。

这三条边都是零代价的。于是从某个虚点出发，顺着树往下走，就能到达它那片区域里的每一个真实点，而且走的总边数只有 O(深度)。

建完之后图里有两种点：真实点只挂着若干弹跳装置，没有出边；虚点没有装置，只有出边。分得这么清楚，dijkstra 的时候就很好处理，出堆的是哪种点，该干什么就确定了。

四、装置只连几个区域

现在看弹跳装置。装置给的也是一个矩形，让这个矩形去和 K-D 树求交，用的是和矩形查询完全一样的过程：

  1. 包围盒和矩形没有交集，整棵剪掉。
  2. 包围盒被矩形完全包住，这个区域里所有点都能到，于是把距离送给这个区域的虚点，直接返回。
  3. 有交集但包不住，看这个节点代表的真实点在不在矩形里（在就更新它的距离），然后往两个儿子递归。

一次展开访问到的节点数是 O(√n) 量级，和矩形查询一样。于是 m 个装置总共产生 O(m√n) 条「虚边」，而不是 O(n·m) 条实边。

五、出堆的时候才展开

还有一个常数优化很值得做：所有弹跳装置一开始都不建边，等 dijkstra 真的弹出某个真实点时，才把这个点挂着的装置当作一次矩形查询展开。

这么做的好处是能用 dist 剪枝。展开到某个节点时，如果 1 号点到这个区域虚点的距离已经不大于本次能给出的距离，那就整棵停住，下面所有点都会被虚点自己沿着建图的边更新到，没必要再送一次。

七、代码

下面是模板题的完整实现。K-D 树在建树的时候顺手把虚点的边建好，装置只在 dijkstra 里展开。

#include <bits/stdc++.h>
using namespace std;

struct Jump {
    int t, l, r, d, u;
};

const int MAXN = 200001;      // 真实点 n 个，虚点也是 n 个
const int INF  = 1 << 30;
int n, m, w, h;

int x[MAXN], y[MAXN], arr[MAXN];
Jump jump[MAXN];

// 静态 K-D 树
int root;
int ls[MAXN], rs[MAXN];
int xmin[MAXN], xmax[MAXN], ymin[MAXN], ymax[MAXN];

// 优化建图，链式前向星
int headg[MAXN], nextg[MAXN], tog[MAXN], cntg;

// 每个真实点拥有的弹跳装置列表
int headj[MAXN], nextj[MAXN], toj[MAXN], cntj;

int dist[MAXN];
bool vis[MAXN];

struct HeapNode {
    int dist;
    int id;

    bool operator<(const HeapNode &other) const {
        return dist > other.dist;
    }
};

priority_queue<HeapNode> heap;

void addEdge(int u, int v) {
    nextg[++cntg] = headg[u];
    tog[cntg] = v;
    headg[u] = cntg;
}

void addJump(int p, int j) {
    nextj[++cntj] = headj[p];
    toj[cntj] = j;
    headj[p] = cntj;
}

void maintain(int i) {
    xmin[i] = min(x[i], min(xmin[ls[i]], xmin[rs[i]]));
    xmax[i] = max(x[i], max(xmax[ls[i]], xmax[rs[i]]));
    ymin[i] = min(y[i], min(ymin[ls[i]], ymin[rs[i]]));
    ymax[i] = max(y[i], max(ymax[ls[i]], ymax[rs[i]]));
}

int compareNode(int i, int j, int dimension) {
    long long v1 = dimension == 0 ? x[i] : y[i];
    long long v2 = dimension == 0 ? x[j] : y[j];
    return v1 == v2 ? 0 : v1 < v2 ? -1 : 1;
}

struct Cmp {
    int dimension;

    bool operator()(int a, int b) const {
        return compareNode(a, b, dimension) < 0;
    }
};

int build(int l, int r, int dimension) {
    if (l > r) {
        return 0;
    }
    int mid = (l + r) >> 1;
    nth_element(arr + l, arr + mid, arr + r + 1, Cmp{dimension});
    int rt = arr[mid];
    ls[rt] = build(l, mid - 1, dimension ^ 1);
    rs[rt] = build(mid + 1, r, dimension ^ 1);
    maintain(rt);
    // 优化建图
    // n + rt 是虚点，表示以 rt 为根的整棵子树
    // 虚点可以到达子树中的所有真实点
    addEdge(n + rt, rt);
    if (ls[rt] != 0) {
        addEdge(n + rt, n + ls[rt]);
    }
    if (rs[rt] != 0) {
        addEdge(n + rt, n + rs[rt]);
    }
    return rt;
}

void heapAdd(int d, int i) {
    if (!vis[i] && dist[i] > d) {
        dist[i] = d;
        heap.push({d, i});
    }
}

void jumpToRectangle(int jl, int jr, int jd, int ju, int jdist, int i) {
    if (i == 0) {
        return;
    }
    // 从 1 号点到当前虚点的最短距离，已经优于 jdist，可以剪枝
    if (dist[n + i] <= jdist) {
        return;
    }
    // 弹跳装置在当前区域之外，可以剪枝
    if (xmax[i] < jl || jr < xmin[i] || ymax[i] < jd || ju < ymin[i]) {
        return;
    }
    // 弹跳装置包括了当前区域，更新 1 号点到当前区域虚点的最短距离
    if (jl <= xmin[i] && xmax[i] <= jr && jd <= ymin[i] && ymax[i] <= ju) {
        heapAdd(jdist, n + i);
        return;
    }
    // 弹跳装置包括了当前点，更新 1 号点到当前点的最短距离
    if (jl <= x[i] && x[i] <= jr && jd <= y[i] && y[i] <= ju) {
        heapAdd(jdist, i);
    }
    jumpToRectangle(jl, jr, jd, ju, jdist, ls[i]);
    jumpToRectangle(jl, jr, jd, ju, jdist, rs[i]);
}

void dijkstra() {
    fill(dist + 1, dist + (n << 1) + 1, INF);
    dist[1] = 0;
    heap.push({0, 1});
    while (!heap.empty()) {
        HeapNode cur = heap.top();
        heap.pop();
        int d = cur.dist;
        int i = cur.id;
        if (!vis[i]) {
            vis[i] = true;
            // 真实点：可能有若干弹跳装置，但一定没有出边
            // 虚点：一定没有弹跳装置，但肯定有出边
            if (i <= n) {
                for (int e = headj[i]; e > 0; e = nextj[e]) {
                    int j = toj[e];
                    jumpToRectangle(jump[j].l, jump[j].r, jump[j].d, jump[j].u, d + jump[j].t, root);
                }
            } else {
                for (int e = headg[i]; e > 0; e = nextg[e]) {
                    heapAdd(d, tog[e]);
                }
            }
        }
    }
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> n >> m >> w >> h;
    for (int i = 1; i <= n; i++) {
        cin >> x[i] >> y[i];
        arr[i] = i;
    }
    for (int j = 1, p; j <= m; j++) {
        cin >> p;
        cin >> jump[j].t >> jump[j].l >> jump[j].r >> jump[j].d >> jump[j].u;
        addJump(p, j);
    }
    xmin[0] = ymin[0] = INF;
    xmax[0] = ymax[0] = -INF;
    root = build(1, n, 0);
    dijkstra();
    for (int i = 2; i <= n; i++) {
        cout << dist[i] << '\n';
    }
    return 0;
}

几个容易忽略的地方。一是数组要开到 2n，虚点占了 n + 1 到 2n 这段编号。二是 dist 初始化只填 1 到 2n，填少了虚点的距离会是 0，剪枝立刻失效。三是比较坐标时用 long long，坐标相乘或者差值大的时候 int 会溢出。

八、复杂度分析

操作时间复杂度
建 K-D 树（顺带建虚点的边）O(n log n)
虚点连边总数O(n) 条
一个装置的一次矩形展开O(√n)，配合 dist 剪枝更快
所有装置的展开总量O(m√n)
dijkstra（优先队列）O((n + m√n) log n)
朴素建图（对照）O(n·m) 条边
额外空间O(n + m)

建图那一行是 O(n) 而不是 O(n log n)：每个节点最多连三条边（自己 + 两个儿子的虚点），n 个节点就是 3n 条。这也是优化建图最实在的收益，边数和点数同阶。

装置的展开是 O(√n)，和矩形查询一个道理。加上 dist 剪枝之后，很多区域连访问都不会访问，实际跑得比这个上界快不少。dijkstra 的堆操作按 O(log n) 算，总时间 O((n + m√n) log n)。

空间上有四份数组：K-D 树的坐标、包围盒与左右儿子 O(n)，建图的边 O(n)，装置列表 O(m)，距离数组 O(n)。合起来 O(n + m)。

九、最后

K-D 树优化建图做的事情，是把「连向一片区域」拆成两步：先把边连到少数几个区域虚点，再让虚点顺着树把距离分下去。代价是多了 O(n) 个点，收益是边数从 O(n·m) 降到 O(m√n)。

这个套路不局限于 K-D 树。线段树优化建图是同一件事的一维版本：区间线段树的每个节点也是虚点，连向区间就等于连向区间里每个位置。判断该用哪种，看边覆盖的是「下标区间」还是「平面矩形」。

它的边界在于维度再高就不好使了。三维以上 K-D 树的剪枝效果明显变差，那时候要么换数据结构，要么回到问题本身找别的性质。
