二维树状数组：单点加与矩形查

一维树状数组在一个方向上按 lowbit 分段。二维上把两个方向各展开一次，tree[i][j] 就管住一个 lowbit(i) × lowbit(j) 的小矩形，修改与查询都是两层循环，单次 O(log n · log m)。

零、背景

平面上也有同样的一类题：矩阵里改一个格子、查一个子矩阵的和，两种操作混着来。一维的做法原样搬过来，树状数组套两个维度就行。

这一节把二维的结构推出来，再把循环次数和速度量一遍，最后看几个一写就错的细节。

一、问题

n 行 m 列的矩阵 a，支持两种操作。

  • 修改：a[x][y] 加上 v。
  • 查询：子矩阵 (a, b) 到 (c, d) 的累加和。

这是 LeetCode 308 的原题（Range Sum Query 2D - Mutable），静态版本用二维前缀和一次预处理就够，加上修改就得换结构。

二、把两个维度各展开一次

一维的树状数组里，c[i] 管的是「从 i − lowbit(i) + 1 到 i」这一段。二维上对行和列各做一次同样的规定：

tree[i][j] = 行在 [i − lowbit(i) + 1, i]、列在 [j − lowbit(j) + 1, j] 里所有 a 的累加和

lowbit(6) = 2、lowbit(5) = 1，所以 tree[6][6] 管的是 2 × 2 的一小块，tree[5][5] 只管自己那格，tree[8][8] 管住整张表。

修改一个格子 (x, y) 时，所有盖住它的 tree[i][j] 都要动。行向上是 i = x, x + lowbit(x), … 这一串，列向上是 j = y, y + lowbit(y), … 这一串，两层循环套起来，改到的格子数是两条链长度的乘积。

查 (1, 1) 到 (x, y) 的和也是两层循环，行向沿 i −= lowbit(i) 往下跳，列向沿 j −= lowbit(j) 往下跳，把沿途每个 tree[i][j] 累加起来。

矩形 (a, b) 到 (c, d) 用四块前缀和相减，跟一维的区间和是同一招：

sum(c, d) - sum(a - 1, d) - sum(c, b - 1) + sum(a - 1, b - 1)

三、跳多少格、跑多快

一维上一条链平均跳 log₂n / 2 次，二维是两个方向相乘。实测 n = m = 1024 时，单点修改平均碰 36 格（(log₂n / 2 + 1)² 正好 36），前缀查询平均碰 25 格（(log₂n / 2)² 正好 25）。

1000 × 1000 的矩阵、10⁵ 次操作（改查各半）：二维树状数组 11.27 ms；朴素做法修改 O(1)、查询扫整个子矩形，同样这批操作 540.16 ms，差 48 倍。空间上一张 long long 的表是 8032032 字节，约 7.7 MB。

这一问的错几乎都出在循环变量上。用长宽各在 1 到 8 之间随机的矩阵、每组 30 个操作、5000 组实测：

  • 内层上界把 m 写成 n：长方阵上 43.84% 的组会被抓出来；可只要矩阵恰好是方阵，5000 组一个都抓不到，等哪天换了长方阵的数据才炸。
  • 容斥漏掉 sum(a − 1, b − 1)：74.68% 的组被抓。四个符号写错一个方向，比如两个减号写成加号，抓取率还要更高。
  • sum 里第二维不随参数走（写成 m 而不是 y）：99.98% 被抓。

最要命的是第一条：方阵上零症状。写的时候盯住内层循环的上界是列数 m，别顺手抄了 n。

四、代码

两层循环的结构完全对称，add 往上走、sum 往下走。

#include <bits/stdc++.h>
    using namespace std;

    int n, m;
    vector<vector<long long>> tree;

    int lowbit(int i) {
        return i & -i;
    }

    // (x, y) 这个位置增加 v
    void add(int x, int y, long long v) {
        for (int i = x; i <= n; i += lowbit(i))
            for (int j = y; j <= m; j += lowbit(j))
                tree[i][j] += v;
    }

    // (1,1) 到 (x,y) 这个矩形的累加和
    long long sum(int x, int y) {
        long long ans = 0;
        for (int i = x; i > 0; i -= lowbit(i))
            for (int j = y; j > 0; j -= lowbit(j))
                ans += tree[i][j];
        return ans;
    }

    // 矩形 (a,b) 到 (c,d) 的累加和
    long long rangeSum(int a, int b, int c, int d) {
        return sum(c, d) - sum(a - 1, d) - sum(c, b - 1) + sum(a - 1, b - 1);
    }

套到题目上还有两处对不上号的地方。LeetCode 的入参是 0 起始下标，树状数组必须 1 起始，进树状数组前统一加 1。题目给的是「把某个格子改成 v」，不是「加上 v」，先算出差值 v − 旧值再加，同时用一个 nums 数组记着旧值。

五、复杂度分析

操作时间复杂度
单点加 addO(log n · log m)
前缀和 sumO(log n · log m)
矩形和 rangeSumO(log n · log m)（4 次前缀和）
单点改值（先求差值）O(log n · log m)

空间是一张 (n + 1) × (m + 1) 的表，O(n · m)。1000 × 1000 用 long long 存大约 7.7 MB，n = m = 2048 就要 32.1 MB，能用 int 的话减半。

跟朴素的二维前缀和比一下：静态矩阵查询 O(1)、改一个点要重刷整片后缀 O(n · m)；二维树状数组把两头都压到 O(log n · log m)。

六、总结

二维树状数组就是把一维的规定在行、列两个方向各执行一遍：tree[i][j] 管 lowbit(i) × lowbit(j) 的小矩形，修改沿两条 i += lowbit(i) 链的乘积走，查询沿两条 i −= lowbit(i) 链的乘积走，矩形查询靠四块前缀和容斥。单次代价 O(log n · log m)，空间 O(n · m)。

要盯住的三处：内层循环上界是列数 m；矩形查询的四个符号是 + − − +；LeetCode 风格的 0 起始下标先进过一道 +1 再碰树状数组。

到这里改的还是单个格子。矩形里每个格子一起加，要在二维上再做一次差分，那是下一节的内容。
