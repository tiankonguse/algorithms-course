优化枚举：DI 序列的有效排列

给一个只含 D 和 I 的字符串，数一数有多少个 0..n 的排列满足相邻的大小关系。排列的全枚举是阶乘级的，但这道题的状态只需要记两个量，而且转移里那层枚举能整段替换成前缀和。

零、暴力：n + 1 个数的全排列

最直接的做法是把 0..n 的所有排列列出来，逐个检查相邻关系。排列总数是 (n+1)!，n = 8 就是 36 万，n = 12 是 62 亿。

这条路走不通，但它给出一个基准：随机小数据上可以用它验证后面的写法对不对。这一页的全部实现对拍，参考值都来自它。

一、状态设计：只需要记「上一个数在剩下数里排第几」

从前往后填。填到第 i 个位置时，前面 i 个数已经用完，还剩 n − i 个数没动。接下来能填什么，只取决于两件事：约束是 D 还是 I，以及上一个数的相对位置。

关键观察在这里：我们不需要知道具体用掉了哪几个数，只要知道「剩下那些数里，有几个比上一个数小」。这个数量决定了下一个数可以选在哪几档。

把这个量记成 less，状态就是 f(i, less)：已经填好第 0..i−1 个位置，上一个位置上的数在当时的未用集合里，有 less 个未用的数比它小。返回值是后面还能排出多少种合法方案。

两件事定下整个递归：

  1. i = n 时位置填满，返回 1；
  2. 否则看 s[i−1]：是 D，下一个数必须比上一个小，可选的 nextLess 落在 [0, less−1]；是 I，下一个数必须比上一个大的，可选的 nextLess 落在 [less, n−i−1]。

那个上界 n−i−1 是「还能选更大的数」的数量加 less 减一。实现里写作从 less 起步、走 n−i−less 步。

// f(s, i, less, n)：i 是当前要填的位置，less 是「还没用过的数里比上一个数小的个数」
    int f(string& s, int i, int less, int n) {
        int ans = 0;
        if (i == n) {
            ans = 1;                                   // 位置填满了，这是一种有效排列
        } else if (i == 0 || s[i - 1] == 'D') {
            for (int nextLess = 0; nextLess < less; nextLess++) {        // 选一个更小的数
                ans += f(s, i + 1, nextLess, n);
            }
        } else {
            for (int nextLess = less, k = 1; k <= n - i - less; k++, nextLess++) {
                ans += f(s, i + 1, nextLess, n);                          // 选一个更大的数
            }
        }
        return ans;
    }

入口是 f(s, 0, n, n)。第 0 个位置没有「上一个数」，less 传什么都不影响分支，传 n 只是让上界算出来正好覆盖全部候选。

二、记下来：状态只有两个维度

i 和 less 加起来就是全部参数，所以 (n+1)² 个格子就够。倒着填：i 从 n 往 0 走，less 每个格子再枚举一遍 nextLess。

// 记忆化：i 和 less 是全部参数，倒着填表，每个格子枚举 nextLess
    const int MOD = 1000000007;
    int numPermsDISequence(string str) {
        string s = str;
        int n = s.size() + 1;
        vector<vector<long long>> dp(n + 1, vector<long long>(n + 1, 0));
        for (int less = 0; less <= n; less++) dp[n][less] = 1;
        for (int i = n - 1; i >= 0; i--) {
            for (int less = 0; less <= n; less++) {
                if (i == 0 || s[i - 1] == 'D') {
                    for (int nextLess = 0; nextLess < less; nextLess++) {
                        dp[i][less] = (dp[i][less] + dp[i + 1][nextLess]) % MOD;
                    }
                } else {
                    for (int nextLess = less, k = 1; k <= n - i - less; k++, nextLess++) {
                        dp[i][less] = (dp[i][less] + dp[i + 1][nextLess]) % MOD;
                    }
                }
            }
        }
        return dp[0][n];
    }

不加记忆化的裸递归是另一回事。同一个 (i, less) 会被从不同路径重复进入，调用次数随长度指数增长：长度 4 时 35 次，度 6 时 693 次，长度 10 时 55706 次，长度 14 时 1.92 亿次。加一张表之后，长度 14 只有 256 个格子。

三、观察：两个分支要的都是区间和

看 D 分支的转移：dp[i][less] 要的是 dp[i+1][0..less−1] 的和。看 I 分支：要的是 dp[i+1][less..n−i−1] 的和。两段都是整区间，也就是前缀和与后缀和。

而 less 每挪一格，区间只多进一个元素。于是同一行从左往右（D 分支）或从右往左（I 分支）推一遍，每格只做一次加法：

D：dp[i][less] = dp[i][less−1] + dp[i+1][less−1]
I：dp[i][less] = dp[i][less+1] + dp[i+1][less]

两处边界要单独立：D 分支的 less = 1 没有 less−1，它直接等于 dp[i+1][0]；I 分支的 less = n−i−1 没有 less+1，它直接等于 dp[i+1][n−i−1]。两处都是从右（左）往左（右）扫的起点。

// D 分支要的是 dp[i+1] 的前缀和，I 分支要的是后缀和，都能用上一格推出来
    const int MOD = 1000000007;
    int numPermsDISequence(string str) {
        string s = str;
        int n = s.size() + 1;
        vector<vector<long long>> dp(n + 1, vector<long long>(n + 1, 0));
        for (int less = 0; less <= n; less++) dp[n][less] = 1;
        for (int i = n - 1; i >= 0; i--) {
            if (i == 0 || s[i - 1] == 'D') {
                dp[i][1] = dp[i + 1][0];                       // dp[i+1][0..less-1] 的前缀和
                for (int less = 2; less <= n; less++) {
                    dp[i][less] = (dp[i][less - 1] + dp[i + 1][less - 1]) % MOD;
                }
            } else {
                dp[i][n - i - 1] = dp[i + 1][n - i - 1];       // dp[i+1][less..n-i-1] 的后缀和
                for (int less = n - i - 2; less >= 0; less--) {
                    dp[i][less] = (dp[i][less + 1] + dp[i + 1][less]) % MOD;
                }
            }
        }
        return dp[0][n];
    }

枚举没了，O(n³) 变 O(n²)。长度 400 时枚举版 55.34 ms、优化版 0.42 ms；长度 800 时是 473.80 ms 对 2.15 ms。

四、写这份转移时的几个坑

D 分支的枚举区间是半开的 [0, less)，写成 [0, less] 就把「没有数比上一个更小」这种情况也算进去了。实测 83.87% 出错。

I 分支的起点是 less 本身。下一个数比上一个大，但它在未用集合里比自己小的个数仍然可以是 less，从 less+1 起步会漏掉这一档。实测 83.72% 出错。

前缀和的递推式很容易顺手写成 dp[i][less−1] + dp[i][less−1]，也就是把要加的那一项也换成了本行的邻居。这样少了 dp[i+1] 的贡献，实测 100% 出错。

复杂度分析

做法时间空间
枚举全排列O((n+1)! · n)O(n)
裸递归（无记忆化）指数级O(n)
记忆化搜索 / 填表枚举O(n³)O(n²)
前缀和与后缀和O(n²)O(n²)

状态数是 (n+1)² 量级，这一点没变。变的是每个格子的枚举代价：从 O(n) 降到 O(1)，整体从 O(n³) 落到 O(n²)。空间上每行只依赖下一行，可以压到一维 O(n)，但两个分支的扫描方向相反，压的时候要留意读写顺序。

总结

这道题里有两层功夫。第一层是状态设计：把「上一个数在剩下数里的排名」当作唯一需要携带的信息，用相对大小关系替掉具体用了哪些数。第二层才是优化枚举：看清两个分支要的都是整段区间之后，一行前缀和、一行后缀和就把内层扫没了。

值得记的数值有两组。裸递归在长度 14 时已经要 1.92 亿次调用，而记忆化之后只有 256 个格子，这就是「状态数少、重复进入多」的典型形状。另一组是三次写法的出错率，D 分支区间开闭 83.87%、I 分支起点 83.72%、前缀和里加错项 100%，都在「闭区间还是开区间」这一档上。

这类「用相对排名替掉具体取值」的手法，在插值、状压、排列计数一类题里都能见到。看到状态需要带一个集合又觉得放不下时，先问一句：后面真的用得上集合的每个元素吗，还是只需要一个排名。
