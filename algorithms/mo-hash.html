莫队 + 哈希与线段树

窗口里能装的比想象的多：一段字符串可以先压成一个整数，一堆「还能配谁」的信息可以交给一棵线段树。只要增删还是 O(log n) 级别，莫队就成立。

零、背景

莫队要求窗口能 O(1) 增删。严格说这是理想情况，实际用的时候，只要一次增删的代价不比指针移动更贵，总复杂度就还能接受。

这一节两道题，一次增删分别是 O(1)（哈希值当整数用）和 O(log n)（线段树上走一条路径）。

一、区间 lcp 达标对

给定一个长度为 n 的字符串 str 和一个参数 k。位置 a 开头和位置 b 开头的两个后缀，如果最长公共前缀的长度 ≥ k，那么 (a, b) 构成一个 lcp 达标对。a、b 必须不同，(a, b) 与 (b, a) 只算一个。

m 条查询，每条给 l r：在 str[l..r] 范围上任选开头位置，打印达标对的数量。

1 ≤ n、k ≤ 3×10⁶，1 ≤ m ≤ 10⁵，n × n × m ≤ 10¹⁵，字符集是 f z o u t s y 七个字母。测试链接：P5112

二、朴素做法

直接按定义来：区间内任取两个开头位置，比较它们往后 k 个字符是否相同。区间长 O(n)，配对 O(n²) 对，每对还要比 O(k) 个字符，单次查询 O(n²k)，完全不可行。

关键的一步是换个说法。lcp ≥ k，等价于「两个开头位置往后的前 k 个字符完全一样」。

于是每个开头位置 i 只剩下一个东西要记：从 i 开始的 k 个字符。把这段串压成一个整数（字符串哈希），问题就变成：窗口里有多少对位置的哈希值相同。

剩下两个细节。一是往后不足 k 个字符的开头位置要舍弃，能用的开头只有 1 到 n-k+1 这些；二是哈希值太大不能直接开数组，先离散化成 1 到 len 的编号。

三、块长不是 √n

窗口里的是编号，增删就是 cnt[x] 加减，答案 curAns 每次加 cnt[x]，标准的 O(1)。

块长这里要重新算。指针移动的总代价是 m 次查询 × 左指针块内摆动 B，加上块数 n/B × 右指针每块扫 n，也就是 mB + n²/B。让两项相等，B 取 n/√m。

本题 n 能到 3×10⁶ 而 m 只有 10⁵，n/√m 约是 3×10⁴，比 √n 的 1700 大得多。块长取错，右指针就要多走十几倍的路。

点「下一步」，看窗口在编号数组上怎么滑。字符串取 ababba，k = 2，三条查询是 [1,4]、[2,6]、[1,6]。

四、题目1 代码

#include <bits/stdc++.h>

    using namespace std;

    struct Query {
        int l, r, id;
    };

    const int MAXN = 3000001;
    const int MAXM = 100001;
    int n, m, k;
    int len, cntq, cntv;
    char str[MAXN];
    Query query[MAXM];

    int base = 499;
    long long basePower[MAXN];
    long long hashValue[MAXN];

    long long val[MAXN];
    long long sorted[MAXN];
    int arr[MAXN];
    int bi[MAXN];

    int cnt[MAXN];
    long long curAns;
    long long ans[MAXM];

    int kth(long long num) {
        int left = 1, right = cntv, ret = 0;
        while (left <= right) {
            int mid = (left + right) >> 1;
            if (sorted[mid] <= num) {
                ret = mid;
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
        return ret;
    }

    bool QueryCmp(Query &a, Query &b) {
        if (bi[a.l] != bi[b.l]) {
            return bi[a.l] < bi[b.l];
        }
        if (bi[a.l] & 1) {
            return a.r < b.r;
        } else {
            return a.r > b.r;
        }
    }

    void add(int x) {
        curAns += cnt[x];
        cnt[x]++;
    }

    void del(int x) {
        cnt[x]--;
        curAns -= cnt[x];
    }

    void compute() {
        int winl = 1, winr = 0;
        for (int i = 1; i <= cntq; i++) {
            int jobl = query[i].l;
            int jobr = query[i].r;
            int id   = query[i].id;
            while (winl > jobl) {
                add(arr[--winl]);
            }
            while (winr < jobr) {
                add(arr[++winr]);
            }
            while (winl < jobl) {
                del(arr[winl++]);
            }
            while (winr > jobr) {
                del(arr[winr--]);
            }
            ans[id] = curAns;
        }
    }

    void prepare() {
        basePower[0] = 1;
        for (int i = 1; i <= n; i++) {
            basePower[i] = basePower[i - 1] * base;
            hashValue[i] = hashValue[i - 1] * base + (str[i] - 'a' + 1);
        }
        for (int l = 1, r = k; r <= n; l++, r++) {
            val[l] = hashValue[r] - hashValue[l - 1] * basePower[r - l + 1];
        }
        for (int i = 1; i <= len; i++) {
            sorted[i] = val[i];
        }
        sort(sorted + 1, sorted + len + 1);
        cntv = 1;
        for (int i = 2; i <= len; i++) {
            if (sorted[cntv] != sorted[i]) {
                sorted[++cntv] = sorted[i];
            }
        }
        for (int i = 1; i <= len; i++) {
            arr[i] = kth(val[i]);
        }
        int blen = max(1, (int)((double)n / sqrt((double)m)));
        for (int i = 1; i <= n; i++) {
            bi[i] = (i - 1) / blen + 1;
        }
        sort(query + 1, query + cntq + 1, QueryCmp);
    }

    int main() {
        ios::sync_with_stdio(false);
        cin.tie(nullptr);
        cin >> n >> m >> k;
        for (int i = 1; i <= n; i++) {
            cin >> str[i];
        }
        len = n - k + 1;
        cntq = 0;
        for (int i = 1, l, r; i <= m; i++) {
            cin >> l >> r;
            if (l <= len) {
                query[++cntq].l = l;
                query[cntq].r = min(r, len);
                query[cntq].id = i;
            }
        }
        prepare();
        compute();
        for (int i = 1; i <= m; i++) {
            cout << ans[i] << '\n';
        }
        return 0;
    }

五、区间最大匹配

给定长度为 n 的数组 a、长度为 m 的数组 b、一个正数 z。a 里的数字 x 和 b 里的数字 y，如果 x + y ≤ z 就构成一个匹配，已经匹配的数字不能重复使用。

q 条查询，每条给 l r：b[l..r] 上的数字，随意选 a 中的数字，打印最多能匹配多少个。

1 ≤ n ≤ 152501，1 ≤ m、q ≤ 52501，1 ≤ a[i]、b[i]、z ≤ 10⁹。测试链接：P4477

六、朴素做法与贪心

一次查询的朴素做法是排序加双指针：a 从小到大、b 的这一段从小到大，用两个指针从两端往中间配，O(n log n + 长度 log 长度)。q 次全做一遍显然超时。

先确定贪心策略：拿到一个 y，就配当前还能用的、不超过 z − y 的最大 x。这个策略是最优的，因为 x 越小越「万能」，把小的留给后面更严苛的 y 不会更差。

问题在于窗口要增删。加一个 y 就得重新找一遍它能配的 x，删一个 y 还得撤销之前的匹配，撤销哪个又取决于当时配的是哪个。

线段树解决的就是这件事。把 a 排序后建树，叶子从左到右对应 a[1..n]，每个结点记三个量：

  • resta：这一段里还没被占用的 a 有多少个；
  • overb：这一段里排队等着、没能配上 a 的 b 有多少个；
  • match：这一段里已经配成的对数。

加入一个 y 时从根往下走：先看右半段最小的 a 能不能配（y + a[mid+1] ≤ z），能就往右走，否则看左半段最小的 a 能不能配，能就往左走。走到叶子时，如果那个 a 还空着就配上，否则说明这一段大的都被占完了，y 只能在这一位排队。

合并两个儿子时，右段排队的 b 之所以排队，是因为它们想要的 a 都被占了；而左段空着的 a 更小，一定也能配这些 b。所以还能再配 min(左段 resta, 右段 overb) 对。

void up(int i) {
    int l = i << 1, r = i << 1 | 1;
    int newMatch = min(resta[l], overb[r]);
    resta[i] = resta[l] + resta[r] - newMatch;
    overb[i] = overb[l] + overb[r] - newMatch;
    match[i] = match[l] + match[r] + newMatch;
}

七、一次增删就是一条路径

加一个 y 走一条从根到叶子的路径，每层 O(1)，代价 O(log n)。删是加的逆过程：叶子上先减排队数，减没了才把匹配撤掉。

这里有个细节：叶子上的账目和最终的配对方案不必一一对应。一个排队的 b 被上层合并消掉之后，它其实已经用左段的空位配走了，账却还留在原来那个叶子上。算法保证的是根结点的 match 正确，具体谁配了谁是账目的事，不需要追究。

莫队的窗口这回不在原数组上滑，而在 b 上滑，窗口里的东西是「这堆 y 在 a 上的匹配情况」，全交给线段树维护。查询的答案就是根结点的 match。

八、题目2 代码

#include <bits/stdc++.h>

    using namespace std;

    struct Query {
        int l, r, id;
    };

    const int MAXN = 152502;
    const int MAXM = 52502;
    const int MAXQ = 52502;
    int n, m, z, q;
    int a[MAXN];
    int b[MAXM];
    Query query[MAXQ];
    int bi[MAXM];

    int match[MAXN << 2];
    int resta[MAXN << 2];
    int overb[MAXN << 2];

    int ans[MAXQ];

    bool QueryCmp(Query &a, Query &b) {
        if (bi[a.l] != bi[b.l]) {
            return bi[a.l] < bi[b.l];
        }
        if (bi[a.l] & 1) {
            return a.r < b.r;
        } else {
            return a.r > b.r;
        }
    }

    void up(int i) {
        int l = i << 1;
        int r = i << 1 | 1;
        int newMatch = min(resta[l], overb[r]);
        resta[i] = resta[l] + resta[r] - newMatch;
        overb[i] = overb[l] + overb[r] - newMatch;
        match[i] = match[l] + match[r] + newMatch;
    }

    void build(int l, int r, int i) {
        if (l == r) {
            match[i] = 0;
            resta[i] = 1;
            overb[i] = 0;
        } else {
            int mid = (l + r) >> 1;
            build(l, mid, i << 1);
            build(mid + 1, r, i << 1 | 1);
            up(i);
        }
    }

    void add(int jobv, int l, int r, int i) {
        if (l == r) {
            if (resta[i] == 1) {
                match[i] = 1;
                resta[i] = 0;
            } else {
                overb[i]++;
            }
        } else {
            int mid = (l + r) >> 1;
            if (jobv + a[mid + 1] <= z) {
                add(jobv, mid + 1, r, i << 1 | 1);
            } else if (jobv + a[l] <= z) {
                add(jobv, l, mid, i << 1);
            }
            up(i);
        }
    }

    void del(int jobv, int l, int r, int i) {
        if (l == r) {
            if (overb[i] > 0) {
                overb[i]--;
            } else {
                match[i] = 0;
                resta[i] = 1;
            }
        } else {
            int mid = (l + r) >> 1;
            if (jobv + a[mid + 1] <= z) {
                del(jobv, mid + 1, r, i << 1 | 1);
            } else if (jobv + a[l] <= z) {
                del(jobv, l, mid, i << 1);
            }
            up(i);
        }
    }

    void prepare() {
        sort(a + 1, a + n + 1);
        int blen = (int)sqrt(m);
        for (int i = 1; i <= m; i++) {
            bi[i] = (i - 1) / blen + 1;
        }
        sort(query + 1, query + q + 1, QueryCmp);
        build(1, n, 1);
    }

    void compute() {
        int winl = 1, winr = 0;
        for (int i = 1; i <= q; i++) {
            int jobl = query[i].l;
            int jobr = query[i].r;
            int id   = query[i].id;
            while (winl > jobl) {
                add(b[--winl], 1, n, 1);
            }
            while (winr < jobr) {
                add(b[++winr], 1, n, 1);
            }
            while (winl < jobl) {
                del(b[winl++], 1, n, 1);
            }
            while (winr > jobr) {
                del(b[winr--], 1, n, 1);
            }
            ans[id] = match[1];
        }
    }

    int main() {
        ios::sync_with_stdio(false);
        cin.tie(nullptr);
        cin >> n >> m >> z;
        for (int i = 1; i <= n; i++) {
            cin >> a[i];
        }
        for (int i = 1; i <= m; i++) {
            cin >> b[i];
        }
        cin >> q;
        for (int i = 1; i <= q; i++) {
            cin >> query[i].l >> query[i].r;
            query[i].id = i;
        }
        prepare();
        compute();
        for (int i = 1; i <= q; i++) {
            cout << ans[i] << '\n';
        }
        return 0;
    }

九、复杂度分析

题目1：n 是串长，m 是查询数，一次增删 O(1)。

操作时间复杂度
预处理哈希与离散化O(n log n)
查询排序O(m log m)
窗口增删一步O(1)
指针总移动（块长 n/√m）O(n√m)
全部 m 次查询O(n log n + n√m)

空间上是哈希数组、值与排序数组各 O(n)，计数与答案 O(n + m)。

题目2：n 是 a 的长度，m 是 b 的长度，q 是查询数，一次增删 O(log n)。

操作时间复杂度
排序 a、建树O(n log n)
查询排序O(q log q)
窗口增删一步（add / del）O(log n)
指针总移动O((m + q)√m)
全部 q 次查询O((m + q)√m log n)

空间上线段树开 4n，加计数数组，O(n)。

十、最后

两题共同的地方是：窗口里维护的不是元素本身，而是元素压出来的一个「摘要」。哈希把一段串压成整数，线段树把一堆匹配关系压成三个计数。

摘要必须支持增量维护，否则莫队滑不动。这也是判断一道题能不能上莫队的第一件事：先问「加进来一个、拿掉一个，答案怎么变」。

下一节的两个题目，摘要换成了值域上的分块和次数桶，增删代价又回到 O(1)，但常数大得多。
