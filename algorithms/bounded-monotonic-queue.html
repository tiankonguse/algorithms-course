多重背包的单调队列优化

二进制分组把每种货物的数量折成 log c，代价还是随 c 涨。单调队列更彻底：它把每种货物的状态按「余数相同」分组，每一组摆在一条线上，于是「从这一格往回数 c 个里挑最大」就变成一个标准的滑动窗口最大值，一趟 O(t) 扫完。要付的代价是理解难度：同一个结论得多绕两个弯才能看明白。

零、问题

还是 P1776：n 种货物、容量 t，每种有重量 w[i]、价值 v[i]、数量 c[i]。

dp[i][j] = maxk=0…c[i]( dp[i-1][j − k·w[i]] + k·v[i] )

朴素做法把 k 从 0 试到 c[i]，复杂度里多一个 c 因子；二进制分组把 c 折成 log c。这一页的目标是把 c 彻底拿掉，做到 O(n · t)。

一、按余数分组，把位置摆到一条线上

先固定第 i 种货物，只看它的 w[i]。容量 j 和 j − w[i] 之间差一个 w[i]，只差一件货。把所有容量按 j mod w[i] 分类：余数相同的那些位置彼此相差整数个 w[i]，正好是一条链。

每条链上的位置是 mod、mod + w、mod + 2w、…。链与链之间互不干扰：dp[i][j] 的转移只会用到同一条链上左侧的位置，绝不会跨到别的余数去。所以整张表可以拆成 w[i] 条互不相干的链，每条单独处理。

二、指标：把 k 提炼成一个只跟位置有关的量

链上的位置写成 j = mod + m·w（m = ⌊j / w⌋）。把它代进转移：

dp[i][j] = m·v + maxt = m−c … m( dp[i-1][mod + t·w] − t·v )

中间那个减掉 k·v 的动作，和「把 j 写成 m·w + 余数」是同一件事。于是括号里剩下的东西只跟位置有关，跟「现在要求的 j 是哪一个」没关系。给它起个名字，叫指标：

value(j) = dp[i-1][j] − (j / w) · v

这里 j / w 是整除，正好等于链上的序号 m（因为 j = mod + m·w 且 0 ≤ mod < w）。重写一遍：

dp[i][j] = (j / w) · v + max{ value(t) : t 在链上且 j − c·w ≤ t ≤ j }

到这一步，问题就变成了：一条线上有一串数，每次问「从当前位置往左数 c + 1 个里的最大值」。这是滑动窗口最大值，单调队列的正业。

三、窗口右移，队列进出

把 j 沿着链从小到大走一遍，窗口 [j − c·w, j] 就跟着往右滑。窗口里的指标要用单调队列维护成递减的，队头永远是窗口内最大的那个。

每一个 j 做两件事：

1）进队：把当前 j 的指标压下去，先把队尾所有不大于它的元素踢掉，再压进去。

2）出队：如果队头的位置已经掉出窗口（queue[l] == j − w·(c+1)），就弹掉。

那两个 1 别漏：窗口是闭区间，最左边允许的位置是 j − c·w；掉出窗口的第一个位置是 j − c·w − w = j − w·(c+1)。如果写成 j − w·c，窗口就少了一格，答案会偏小。

队头的位置 j* 拿到之后，dp[i][j] = value(j*) + (j / w)·v，一趟就算完了。整条链扫一遍，所有 dp[i][·] 都填好，不会回头。

四、空间压缩要从右往左刷

dp[i][j] 读的是 dp[i−1][·]，上一行的左侧格子。压成一维之后，同一件事变成：算 dp[j] 的时候，它左边的那些格子必须还是「上一行」的旧值。办法和 01 背包一样，每一行从右往左刷，右边的先被覆盖，左边的还没动。

具体写法上，每处理一条链，先把链头上 c[i] 个位置的指标塞进队列（它们是窗口最初的成员），然后 j 从链尾往链头走，每走一格就有一个更靠左的位置「新滑进窗口」，同时当前 j 自己用完就滑出。代码里那个 enter 指针指的就是新滑进来的位置，它和 j 一起往左退。

// dp[i][j] 要读上一行左侧的格子，所以压缩后每一行从右往左刷
    // 这样左边的格子还没被本轮覆盖，读到的就是真正的「上一行」
    int mqueue1d(int n, int t, vector<int>& v, vector<int>& w, vector<int>& c) {
        vector<int> dp(t + 1, 0), q(t + 2);
        for (int i = 1; i <= n; i++) {
            auto val = [&](int j) { return dp[j] - j / w[i] * v[i]; };
            for (int mod = 0; mod <= min(t, w[i] - 1); mod++) {
                int l = 0, r = 0;
                for (int j = t - mod, k = 1; j >= 0 && k <= c[i]; j -= w[i], k++) {  // 先塞进 c[i] 个
                    while (l < r && val(q[r - 1]) <= val(j)) r--;
                    q[r++] = j;
                }
                for (int j = t - mod, enter = j - w[i] * c[i]; j >= 0; j -= w[i], enter -= w[i]) {
                    if (enter >= 0) {                        // 新的一格滑进窗口
                        while (l < r && val(q[r - 1]) <= val(enter)) r--;
                        q[r++] = enter;
                    }
                    dp[j] = val(q[l]) + j / w[i] * v[i];
                    if (q[l] == j) l++;                      // 自己用完 c[i] 次，滑出窗口
                }
            }
        }
        return dp[t];
    }

二维版写起来更直白：j 从小到大走，进队之后判一次出队。两者答案完全一样，只是循环方向相反。

// dp[i][j]：只在前 i 种货物里挑、容量不超过 j 的最大价值
    // 同一条 mod w[i] 的链上，给每个位置算一个指标 dp[i-1][j] - (j / w[i]) * v[i]
    // 窗口 [j - c[i] * w[i], j] 里指标最大的那个，就是最划算的取法
    int mqueue2d(int n, int t, vector<int>& v, vector<int>& w, vector<int>& c) {
        vector<vector<int>> dp(n + 1, vector<int>(t + 1, 0));
        vector<int> q(t + 2);
        for (int i = 1; i <= n; i++) {
            for (int mod = 0; mod <= min(t, w[i] - 1); mod++) {   // 按 mod w[i] 同余分组
                int l = 0, r = 0;
                for (int j = mod; j <= t; j += w[i]) {
                    int vj = dp[i - 1][j] - j / w[i] * v[i];
                    while (l < r && dp[i - 1][q[r - 1]] - q[r - 1] / w[i] * v[i] <= vj) r--;
                    q[r++] = j;
                    if (q[l] == j - w[i] * (c[i] + 1)) l++;        // 用够 c[i] 件的滑出窗口
                    dp[i][j] = dp[i - 1][q[l]] - q[l] / w[i] * v[i] + j / w[i] * v[i];
                }
            }
        }
        return dp[n][t];
    }

五、写错的代价

最常踩的坑是忘掉出队那一句。队列只进不出，等于允许无限多件，多重背包就退化成完全背包，两万组随机数据错 60.27%，而且不管价值值域怎么变，误差都是这个数。这一条和「把多重当完全背包做」是同一个错，别当成两个问题。

另一个坑是出队判据里的 c + 1：写成 c 会让窗口少一格，恰好需要拿满 c 件才最优的样本就丢了；写成 c + 2 则多放一件进来，会超数量。

指标本身也容易写歪。dp[i−1][j] 不能换成 dp[i][j]，那样读的是本行已经算过的值，含义完全变了；j / w[i] 必须是整除，不能顺手写成浮点。

六、复杂度分析

做法时间额外空间说明
二进制分组O(t · Σ log c[i])O(t + Σ log c[i])c 每翻一倍多一包，c = 40000 时每种 16 包
单调队列（二维）O(n · t)O(n · t)c 不出现在复杂度里
单调队列（压缩）O(n · t)O(t)外加一个长度 t 的队列数组

两边的实测差距没有理论上那么大，因为二进制的常数很小、单调队列的分组循环有开销。真正拉开的地方是 c 很大：w = 1、c = 40000 时二进制 55.91 ms，单调队列 11.29 ms，差 5 倍。c 只有几百的时候两者基本打平（n = 1000、t = 40000、c ≤ 1000 时 137.62 ms 对 117.70 ms）。所以比赛里更常见的还是二进制分组，单调队列留着对付数量特别大的数据。

七、总结

单调队列把多重背包里那个 c 因子彻底消掉，代价是多绕两个弯。

几个要点：

1）按 j mod w[i] 把容量分成 w[i] 条互不干扰的链，链上位置相差整数个 w。

2）指标 value(j) = dp[i-1][j] − (j / w)·v，把 k 从转移里提出来，剩下的就是滑动窗口最大值。

3）窗口是闭区间 [j − c·w, j]，出队判据用 j − w·(c+1)，那个 1 不能省。

4）压缩版每一行从右往左刷，保证读到的左侧格子还是上一行。

5）忘掉出队 = 完全背包，错 60.27%；这个失误和「当完全背包做」是同一件事。

6）P1776 用二进制分组也能过；单调队列的优势在 c 远大于 n 时才明显。理解不了这页就先跳过，把二进制分组用熟。
