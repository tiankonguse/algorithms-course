得到回文串的最少操作次数

先别管怎么换，先定下来每个字符最终去哪个位置。目标一定，最少的相邻交换次数就等于这个目标排列的逆序对数。

零、背景

给一个只包含小写字母的字符串，每次操作交换相邻两个字符，问最少几次能把它变成回文串。题目保证一定变得了，也就是说出现奇数次的字符最多一个。

「最少几次」这类问法，直接想交换方案是很困难的。换个问法：先定一个目标，每个原位置的字符最终去第几个位置，记成 arr[i]。那么问题就变成把序列 arr 通过相邻交换排成升序要几步。

一、从交换次数到逆序对

一次相邻交换，只会让逆序对数变化 1：交换前是正序就加 1，是逆序就减 1。排成升序时逆序对数是 0，所以从 arr 出发至少要 inv(arr) 步，inv 是 arr 的逆序对数。

这个下界是能达到的。每次挑一对相邻的逆序交换，就是冒泡排序，恰好走 inv 步。于是最少的相邻交换次数就是 inv(arr)。

最少交换次数 = arr 的逆序对数

剩下的问题只有一个：arr 怎么定。

二、定目标：从外往里一对一对配

回文串的约束是对称位置字符相同。于是把原串里的字符两两配对，第一对去最外侧的 1 和 n，第二对去 2 和 n − 1，依次往里。出现奇数次的那个字符单独去正中间。

配对的规则是：从左到右，位置 l 上的字符，跟它右边最靠右的同字符配成一对。下面用 m a m a d 走一遍。

三、第 k 个是谁：树状数组数剩余位置

现在的问题变成：处理到第 l 个位置时，它是「还没安排完的位置」里的第几个。这个序号就是 k，arr[l] = k、arr[r] = n − k + 1。

用树状数组维护「每个位置还剩下没有」，初始全是 1。每安排完一对，只把 r 那个位置减 1，l 那个位置留着不动。

每种字符的位置用链表记下来，头的下标就是最靠右的那一个，弹出即取最右。

// 每种字符一个链表头，pre[j] 存同字符的上一个位置
    void Push(int v, int j) {
    	pre[j] = end[v];
    	end[v] = j;
    }

    // 弹出字符 v 当前最靠右的下标
    int Pop(int v) {
    	int ans = end[v];
    	end[v] = pre[end[v]];
    	return ans;
    }

主循环从左到右走一遍，arr[l] 已经填过的位置直接跳过。

// arr[i] 记录位置 i 的字符最终要去第几个位置
    for (int i = 0, l = 1, r, k; i < n; i++, l++) {
    	if (arr[l] == 0) {
    		r = Pop(s[i] - 'a');
    		if (l < r) {
    			// k 是 l 在「还没安排完的位置」里排第几个
    			k = Sum(l);
    			arr[l] = k;
    			arr[r] = n - k + 1;
    		} else {
    			// l == r，说明这个字符落单，只能去正中间
    			arr[l] = (1 + n) / 2;
    		}
    		// r 这个位置安排完了，从树状数组里剔除
    		Add(r, -1);
    	}
    }

四、数逆序对

arr 填完之后，剩下的是数它的逆序对。用归并分治，左右各自有序后一次双指针扫完，时间是 O(n log n)。

long long Merge(int l, int m, int r) {
    	long long ans = 0;
    	for (int i = m, j = r; i >= l; i--) {
    		while (j >= m + 1 && arr[i] <= arr[j]) {
    			j--;
    		}
    		ans += j - m;
    	}
    	int i = l, a = l, b = m + 1;
    	while (a <= m && b <= r) {
    		help[i++] = arr[a] <= arr[b] ? arr[a++] : arr[b++];
    	}
    	while (a <= m) {
    		help[i++] = arr[a++];
    	}
    	while (b <= r) {
    		help[i++] = arr[b++];
    	}
    	for (i = l; i <= r; i++) {
    		arr[i] = help[i];
    	}
    	return ans;
    }

    long long Number(int l, int r) {
    	if (l >= r) {
    		return 0;
    	}
    	int m = (l + r) / 2;
    	return Number(l, m) + Number(m + 1, r) + Merge(l, m, r);
    }

n = 2000 时整道题实测 0.08 ms，其中绝大部分花在归并分治上。字符串长度到 2000，O(n²) 的数法要四百万次比较，归并分治只要两万多。

总结

这道题分两步走，每步都不难。第一步定目标：从左到右把字符两两配到对称位置，配对时取最靠右的同字符，落单的那个去正中间。第二步算代价：目标排列的逆序对数就是最少相邻交换次数。

中间的衔接是树状数组。它记着「哪些位置还没安排完」，安排完一对只减掉 r，于是 Sum(l) 恰好等于这一对的序号。l 不减是关键，减了就差 1。

「先定目标排列，再数逆序对」这个套路不只用于回文。任何「通过相邻交换把序列变成某个目标形态、问最少几步」的问题，都可以先想清楚目标排列是什么，剩下的交给逆序对。
