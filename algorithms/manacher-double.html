Manacher：最长双回文串

双回文串是能切成两段、每段都是回文的串，要求最长的那个。看起来要枚举所有切法，实际上只要把「以每个位置结尾的最长回文」和「以每个位置开头的最长回文」各算一份，在两个数组上扫一遍就够了。麻烦的地方在于这两个数组不能一边跑一边算：分界点右边的量得等整趟扫完才知道，所以只能在半径数组上正着扫一次、倒着扫一次。

零、题目

给定字符串 s，求 s 的最长双回文子串的长度。双回文子串指的是能分成两段、且两段都是回文的子串，两段都不能为空。比如 "aabb" 可以分成 "aa" 和 "bb"，答案就是 4。|s| ≤ 105。

样例 "baacaabbacabb" 的答案是 12，切法是从第 2 个字符开始的 "aacaabbacabb"，分成 "aacaa" 和 "bbacabb" 两段。"aacaa" 没有更长的单回文，但它拆成两个回文之后有 12 个字符，比整串里最长的单回文更长。

暴力是枚举分界点，再从分界点向两边各扩一次求最长回文，O(m2)。m = 105 就跑不动了。

一、把答案拆成两侧

设分界点在真实串的位置 p（真实下标，表示「前 p 个字符」之后），1 ≤ p ≤ m − 1。定义两个量：

L[p]：以 p 结尾的最长回文长度，也就是最长的 s[a, p) 是回文；

R[p]：以 p 开头的最长回文长度，也就是最长的 s[p, b) 是回文。

左右两段互相不影响，所以固定 p 时能拼出 L[p] + R[p]，答案就是 max(L[p] + R[p])。

为什么这样就够？任意一个双回文子串 t = s[a, b) 被某个 p 切成 s[a, p) 与 s[p, b) 两段回文，那么这个 p 处 L[p] ≥ p − a 且 R[p] ≥ b − p，加起来不小于 |t|，最大值不会比答案小；反过来，L[p] 和 R[p] 各自对应一段真实的回文，拼起来也是合法的双回文串，最大值不会比答案大。两边一夹，等号成立。

二、两个数组怎么从半径数组里扫出来

真实位置 k 对应扩展串下标 2k，也就是第 k 个 '#'，所以 L[p] 就是 Lft[2p]、R[p] 就是 Rgt[2p]，两个数组都只用到偶数下标。

Lft 从左往右扫。j 从 0 开始每次走 2，i 从 0 开始每次走 1。以 i 为中心的回文右端是 i + p[i] − 1，只要 i + p[i] > j 就说明这个回文盖住了 j，那么「以 j / 2 结尾的回文」至少能取到 j − i 这么长，直接写进 Lft[j]，然后 j 往右走一格。

为什么写进去的就是最大值？j 只增不减，而 i 也是从左往右的。第一个盖住 j 的中心，必然是所有盖住 j 的中心里最靠右的那个中心左侧最近的，它对应的左端点最靠左，也就是能给出的最长回文最长。后面那些盖住 j 的中心都更靠右，给不出更长的。

换个角度看更直接：Lft[j] = j − i 里的 i 是「回文能往左伸到多远的那个中心」，j 越大，第一个够到它的 i 就越靠右，差值也越大，和「以 j / 2 结尾的最长回文」是同一个东西。

Rgt 完全对称：i 和 j 都从最右边出发往左走，条件是 i − p[i] < j，也就是回文的左端越过了 j，写 Rgt[j] = i − j。

两趟扫描都是线性的：j 在每趟里只朝一个方向走，总共不超过 n 步，i 也是走过一遍就结束。

三、分界点只能取中间那些

最后一遍扫描 i 从 2 到 n − 3、步长 2。i = 2 对应真实分界点 1，i = n − 3 对应真实分界点 m − 1，正好把「左右两段都非空」这件事卡住。

i = 0 是串的起点，Lft[0] 必然是 0，允许它参与就等于承认「右半段自己算一个双回文串」，而单个回文不是双回文串。i = n − 1 是串末尾，同理。这处的边界看着无关紧要，实际上会把答案放大。"abacaba" 整串是回文，Rgt[0] = 7，边界放宽就会输出 7，而正解是 6（"a" 配 "bacab"）。

四、代码

两趟扫描放在一起，两个数组都开 2n + 1 那么大。

// left[j]：以 j/2 这个位置结尾的最长回文长度，j 只走偶数下标
    // right[j]：以 j/2 这个位置开头的最长回文长度
    void buildLR() {
        for (int i = 0, j = 0; i < n; i++) {
            while (i + p[i] > j) {              // 回文盖住了 j，长度就是 j - i
                Lft[j] = j - i;
                j += 2;
            }
        }
        for (int i = n - 1, j = n - 1; i >= 0; i--) {
            while (i - p[i] < j) {
                Rgt[j] = i - j;
                j -= 2;
            }
        }
    }

最后扫一遍分界点。

// 在每个分界点上把左右拼起来，两边都得非空
    int longestDoublePalindrome(const string &s) {
        manacher(s);
        buildLR();
        int ans = 0;
        for (int i = 2; i <= n - 3; i += 2) {
            ans = max(ans, Lft[i] + Rgt[i]);
        }
        return ans;
    }

五、两个错法

一，j 每次只走 1。20000 组随机串上 0.00% 有差别，这次是真等价：偶数下标拿到的值和不走 1 时完全相同，因为要让 j 走到某个偶数，中间必须先经过它左边那个奇数，而写出那个奇数值的 i 同时也满足写出偶数值的条件；奇数下标的槽位后面根本不会读。白扫一半，答案不变。

二，分界点范围放宽成 [0, n − 1]。这是真错，但随机数据里极难抓到，20000 组随机串只有 0.01% 露头，字符表放大到 26 就是 0.00%。原因是要露头得碰上「整串本身就是回文」这类极端形状。写的时候别指望对拍帮你发现它。

逐个分界点拼双回文串

每点一步换一个分界点：橙框是左边那段，蓝框是右边那段，下面的两行是 Lft 与 Rgt 在偶数下标上的值。切到放宽边界的版本，看 "abacaba" 的答案从 6 变成 7。

六、复杂度分析

做法关键操作时间空间
枚举分界点各自往两边扩每个分界点最多扩 m 次O(m2)O(1)
Manacher + 两趟扫描填 p、扫 Lft、扫 Rgt、扫分界点O(m)O(m)

四趟都是线性的，前两趟把 j 单向推到底，最后那趟是 n / 2 个分界点各看一眼。空间按 |s| ≤ 105 的开法：ss 是 2 × 105 个 char，p、Lft、Rgt 各 2 × 105 个 int，四份加起来约 2.6 MB。n = 105 的随机串实测 1.84 毫秒，全 a 串 0.91 毫秒。题目给的内存是 125 MB，余量很大。

总结

双回文串的答案等于「以每个位置结尾的最长回文」加上「以每个位置开头的最长回文」，在分界点上取最大。

两份数组都在半径数组上扫一遍就出来：Lft 从左往右，j 只走偶数下标，第一个盖住 j 的中心给出的就是最优值；Rgt 方向相反，条件也反过来。

最后的分界点范围要卡在中间，两端各留一个字符。整体 O(m) 时间、O(m) 空间，四趟线性扫描，常数很小。
