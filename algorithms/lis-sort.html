排序之后转 LIS：信封与数对链

俄罗斯套娃信封和最长数对链，题面里都是二维的东西：一个信封有宽和高，一个数对有左端和右端。两道题的解法长得几乎一样，都是先排一次序，把二维压成一维，再跑上一页那个 ends 数组。真正要想清楚的只有两件事：按什么排，以及 ends 里存什么。

零、信封问题：二维怎么压成一维

信封 [w, h] 能装进 [w', h']，条件是 w < w' 且 h < h'，两个方向都得严格小，不允许旋转。

先看宽度这一维。把所有信封按宽度从小到大排，那么「能装」关系里宽度这一侧就自动满足了：排在后面的信封宽度不小于前面的。于是问题只剩高度这一侧，在高度序列上找最长严格递增子序列就行。

等等，这里有个坑：宽度相等的两个信封，谁也装不进谁。可按宽度排序后它们挨在一起，如果高度恰好也是升序，最长递增子序列就会把它们串成一条，答案凭空多出来。

一、同宽的高度必须倒着排

处理办法只有一行：排序时宽度升序，宽度一样时按高度降序排。

a[0] != b[0] ? a[0] < b[0] : a[1] > b[1]

同宽的几个信封高度倒着摆，高度序列在这一段上是下降的，严格递增子序列最多只能从中挑一个。宽度这一侧的约束被排序拿掉了，高度这一侧用倒序补回来。

这个坑写反了不一定会被测出来。实测两万个随机样本（每个样本 2 到 20 个信封）：宽高值域 V = 3 时错版答案不同的占 43.73%，V = 10 时 53.62%，V = 100 时 10.89%，V = 100000 时只有 0.01%。值域一大，宽度撞车的机会就小，写反也能过，等到出一组宽高都小的数据就露馅。

// 俄罗斯套娃信封：宽度升序，宽度一样时高度降序，然后对高度做最长递增子序列
    int maxEnvelopes(int** env, int n) {
        sort(env, env + n, [](int* a, int* b) {
            return a[0] != b[0] ? a[0] < b[0] : a[1] > b[1];
        });
        int ends[100005];
        int len = 0;
        for (int i = 0, find; i < n; i++) {
            find = bs1(ends, len, env[i][1]);
            if (find == -1) {
                ends[len++] = env[i][1];
            } else {
                ends[find] = env[i][1];
            }
        }
        return len;
    }

二、数对链：ends 里存右端点

数对 [a, b] 后面能接 [c, d]，条件是 b < c。问最长能接多长。

思路和信封一样：先按左端点升序排，左端这一侧就自动满足了。接下来在 ends 上做文章，但这次 ends 里存的东西不一样。

上一页的 ends[i] 是「长度为 i + 1 的递增子序列的最小结尾」，这一题直接照搬：ends[i] 记长度为 i + 1 的数对链，结尾（也就是链上最后一个数对的右端点）最小能小到多少。链尾越小，后面能接的数对越多。

处理一个数对 [l, r] 时，在 ends 里找第一个 >= l 的位置：

1）找不到，说明所有链的尾巴都小于 l，这个数对能接在任何一条链后面，长度加一，往 ends 末尾追加 r。

2）找到了下标 f，说明有一条长度为 f 的链尾巴小于 l（就是 ends[f-1]，或者 f = 0 时是空链），可以接上这个数对，得到一条长度为 f + 1、结尾是 r 的链。原来 ends[f] 记的那个尾巴要和 r 取小。

ends[find] = min(ends[find], pairs[i][1])

那个 min 不能省。ends[f] 记录的旧尾巴可能比 r 大，也可能比 r 小，两边都出现过：新数对右端点很大时旧尾巴更小，右端点很小时新尾巴更小。实测两万个随机样本，去掉 min 的答案出错率 56.17%，比一半还高。

// 最长数对链：按左端点升序，ends 里存右端点
    int findLongestChain(int** pairs, int n) {
        sort(pairs, pairs + n, [](int* a, int* b) { return a[0] < b[0]; });
        int ends[100005];
        int len = 0;
        for (int i = 0, find; i < n; i++) {
            find = bs1(ends, len, pairs[i][0]);   // 第一个结尾 >= 左端点的链
            if (find == -1) {
                ends[len++] = pairs[i][1];
            } else {
                ends[find] = min(ends[find], pairs[i][1]);
            }
        }
        return len;
    }

三、数对链还能更省事

这题其实有个更短的写法：按右端点升序排，然后从头到尾扫，能接就接。

为什么是对的？按右端点升序扫，每次遇到的数对都是「当前右端点最小」的那个候选。能接上就接，接不上说明它的左端点不大于当前链尾，而它的右端点又不比当前链尾小，留着它不会比留着当前链尾更好。这就是区间调度的贪心。

// 更省事的写法：按右端点升序，能接就接（活动选择的贪心）
    int findLongestChain2(int** pairs, int n) {
        sort(pairs, pairs + n, [](int* a, int* b) { return a[1] < b[1]; });
        int pre = -2147483648, ans = 0;
        for (int i = 0; i < n; i++) {
            if (pre < pairs[i][0]) {
                pre = pairs[i][1];
                ans++;
            }
        }
        return ans;
    }

实测 n = 200000 时，ends 版 26.85 毫秒，贪心版 22.87 毫秒，答案一致（都是 15691）。差的那点时间是排序的比较函数不同带来的，复杂度同阶，写哪个都行。倒过来想：按左端点排序再贪心是错的，实测两万个随机样本里 33.49% 的答案不对。

四、三种写错的方式

四个数字分别是：信封同宽按高度升序排（错）、数对链去掉 min（错）、数对链把 >= 写成 >（错）、数对链按左端点排序后贪心（错）。样本都是两万组随机小数据。

共同点是它们都只在「有重复」的时候现形：同宽的信封、右端点比旧尾巴小的数对、左端点相等的边界。做这类题时先问一句「排序之后，相等的那部分会不会被串起来」，多数 bug 就躲在这一句里。

五、复杂度分析

题目时间额外空间说明
俄罗斯套娃信封O(n log n)O(n)排序 O(n log n)，之后每个高度一次二分 O(log n)
最长数对链（ends 版）O(n log n)O(n)同左
最长数对链（贪心版）O(n log n)O(1)时间花在排序上，扫描那一段是 O(n)，不额外开 ends

两道题的空间都是 O(n)，ends 数组按 n 开就够，有效长度是答案、最坏是 n。贪心版那栏写 O(1) 是指除了排序之外不再开数组，排序本身的开销看实现，标准库一般是 O(log n) 的栈。

实测（g++ -O2）：信封 n = 100000 时 12.26 毫秒，n = 200000 时 29.25 毫秒；数对链 n = 200000 时 ends 版 26.85 毫秒、贪心版 22.87 毫秒。

六、总结

这两道题是同一个套路：先按其中一维排序，让这一维的约束自动成立，剩下那一维交给 ends 数组。

要记住的点：

1）信封排序是「宽度升序，同宽时高度降序」。同宽降序那一项是为了防止同宽信封被串进同一条链。

2）数对链的 ends 里存的是右端点，替换时写 min，不是直接赋值。

3）数对链还能按右端点排序贪心，代码更短，不用开 ends。

判断排序策略对不对的土办法：想一遍「两个相同的第一维」会不会被串起来。会，就得在第二维上倒着排。
