带修改的区间第 k 小

静态的区间第 k 小只要把询问装进整体二分就够了。一旦带上单点修改，修改本身也得参与分治：把它拆成「删掉旧值、加上新值」两个事件，和查询按时间顺序排在一起，分治时顺着时间扫一遍。

零、从静态到带修改

静态版本里，分治的每个节点要维护的是「一批数值」，判定是数一数这批数落在询问区间里有多少个。带上修改之后，每个询问区间上的数不再是固定的，它取决于这个询问发生在什么时刻。

因此分治的对象要换一下：不再是一批数，而是一条按时间排好的事件序列。事件有两种，一种改变某个位置上的值，一种提问。分治时按时间顺序扫这条序列，序列里的相对顺序就是时间顺序，扫到某个查询时，结构里存下来的正好是「这个时刻之前所有改动造成的、值落在当前值域里的数」。

一、题目2：带修改的区间第 k 小

给定一个长度为 n 的数组 arr，接下来是 m 条操作，每种操作是如下两种类型的一种。操作 1 x y：把 x 位置的值修改成 y。操作 2 x y v：查询 arr[x..y] 范围上第 v 小的值。1 ≤ n、m ≤ 10⁵，1 ≤ 数组中的值 ≤ 10⁹。测试链接：P2617。

这是树套树的模版题：外层树状数组套内层主席树，一次查询 O(log² n)。换成整体二分之后写法短得多，代价是多一个 log 值域。

二、把修改拆成两个事件

初始数组里的每个元素都可以看成一次「在位置 i 加上值 arr[i]」的事件，一共 n 条。一次修改 C x y 拆成两条：在位置 x 删掉旧值、在位置 x 加上新值。删掉这件事和加上没有区别，只是增量取 −1。

于是所有操作统一成一种结构：位置 x、值 y、增量 v。v 是 +1 就是加入，−1 就是删除，查询的 v 另有含义，用 op 区分。

这里有个细节：一次修改必须拆成紧挨着的两条，而且删旧值在前。拆完之后两条之间不能插入查询，否则那个查询看到的数组是「旧值已删、新值未加」的中间状态。

三、分治与判定

值域是整个 0 到 10⁹，分治在这一段上做。当前节点的值域是 [vl, vr]，取 mid，扫描事件序列里属于这个节点的那一段：

遇到加值事件，如果它的值不超过 mid，就把它加到树状数组的位置 x 上，增量是 v，这个事件去左半；否则它对本层毫无影响，去右半。遇到查询事件，用树状数组数一数区间 [x, y] 里当前有多少个数，记成 satisfy，这些数就是「值不超过 mid 的、此刻在区间里的数」。如果 v 不超过 satisfy，第 v 小不超过 mid，去左半；否则第 v 小一定大于 mid，把 v 减掉 satisfy 再去右半。

扫描结束之后要把树状数组还原。还原只针对那些「加进去过的」事件，按原来的增量取反，一遍清干净，下一个节点才能从一个空结构开始。

int lowbit(int i) {
        return i & -i;

主过程和上一节的结构完全一样，差别只在事件有两种。

void compute(int el, int er, int vl, int vr) {
        if (el > er) {
            return;
        }
        if (vl == vr) {
            for (int i = el; i <= er; i++) {
                int id = eid[i];
                if (op[id] == 2) {
                    ans[q[id]] = vl;
                }
            }
        } else {
            int mid = (vl + vr) >> 1;
            int lsiz = 0, rsiz = 0;
            for (int i = el; i <= er; i++) {
                int id = eid[i];
                if (op[id] == 1) {
                    if (y[id] <= mid) {
                        add(x[id], v[id]);
                        lset[++lsiz] = id;
                    } else {
                        rset[++rsiz] = id;
                    }
                } else {
                    int satisfy = query(x[id], y[id]);
                    if (v[id] <= satisfy) {
                        lset[++lsiz] = id;
                    } else {
                        v[id] -= satisfy;
                        rset[++rsiz] = id;
                    }
                }
            }
            for (int i = 1; i <= lsiz; i++) {
                eid[el + i - 1] = lset[i];
            }
            for (int i = 1; i <= rsiz; i++) {
                eid[el + lsiz + i - 1] = rset[i];
            }
            for (int i = 1; i <= lsiz; i++) {
                int id = lset[i];
                if (op[id] == 1 && y[id] <= mid) {
                    add(x[id], -v[id]);
                }
            }
            compute(el, el + lsiz - 1, vl, mid);
            compute(el + lsiz, er, mid + 1, vr);
        }
    }

四、复杂度分析

值域 V 是 10⁹ 量级，log V 大约是 30。分治每层每个事件做一次 O(log n) 的树状数组操作，一共 log V 层。

操作时间复杂度空间复杂度
读入并把修改拆成两个事件O(n + m)O(n + m)：事件数组按 4(n + m) 开，每个事件存 op、x、y、v，查询另存编号；树状数组 O(n)
树状数组单点加、区间求和O(log n)
分治一层（每个事件一次树操作）O((n + m) log n)
整体（值域长度 V，共 log V 层）O((n + m) log n log V)
与树套树对比树套树 O((n + m) log² n)，常数更大

n、m 取 10⁵ 时大约是 2 × 10⁵ × 17 × 30，一亿量级的基本操作，树状数组常数很小，可以通过。

五、最后

带修改的整体二分就多了一件事：修改要变成事件，和查询一起排队。判定用的结构还是树状数组，只是它现在存的是「值落在当前值域里的、此刻存在的数」。下一节把同样的套路搬到树上，判定换成树上点差分。
