路径收集与树的递归判定

三个递归形态：收集路径要恢复现场，验证平衡要后序回传高度，验证搜索树要全局单调。后两题是树型 dp 的沾边用法。

零、背景

上一课处理了遍历和结构验证，这一课处理「路径」和「验证」两类问题。路径题靠递归带一条共享的栈，验证题靠递归把子树的结论逐层汇总。

LeetCode 110 和 98 这两道验证题，在后面的动态规划大章节会用「树型 dp」的正规讲法再讲一遍。这里先把递归骨架立住：子树自底向上传信息，父节点只用自己的两个孩子，就是树型 dp 的原型。

节点定义沿用上一节，带构造器。

一、收集累加和等于 aim 的路径（LeetCode 113）

根到叶一路累加，走到叶就判定一次。递归带着一条 path 栈往下走，进节点时 push，出节点时 pop，命中的路径整条拷贝进答案。

// 收集累加和等于 aim 的所有路径（LeetCode 113）
    struct TreeNode {
        int val;
        TreeNode *left, *right;
    };

    void F(TreeNode* cur, int aim, int sum, vector<int>& path, vector<vector<int>>& ans) {
        if (cur->left == nullptr && cur->right == nullptr) {
            // 叶节点
            if (cur->val + sum == aim) {
                path.push_back(cur->val);
                ans.push_back(path);
                path.pop_back();
            }
        } else {
            // 不是叶节点
            path.push_back(cur->val);
            if (cur->left != nullptr) {
                F(cur->left, aim, sum + cur->val, path, ans);
            }
            if (cur->right != nullptr) {
                F(cur->right, aim, sum + cur->val, path, ans);
            }
            path.pop_back();
        }
    }

    vector<vector<int>> PathSum(TreeNode* root, int aim) {
        vector<vector<int>> ans;
        if (root != nullptr) {
            vector<int> path;
            F(root, aim, 0, path, ans);
        }
        return ans;
    }

pop 这一步看着多余，删掉就出事。path 是所有递归分支共享的一条栈，不恢复现场，回到父节点后栈里残留着刚才那个分支的节点，下一个分支收集到的路径开头全是脏数据。

实测过这个错：忘掉 pop，在有路径命中的 480 组随机树上，80 组答案集合和暴力不一样（16.7%）；逐条路径数，581 条里 101 条被污染（17.4%）。这是「叶节点命中后漏了 pop_back」这一类错误的标准长相，对拍一抓一个准。

累加值也不用从根重新算：sum 参数带着走到当前节点的和，进分支时加当前节点值。判定只看叶：cur 左右都空且 sum == aim，就收集。

二、验证平衡二叉树（LeetCode 110）

朴素做法好想：对每个节点单独算一遍左右子树的高度，比一比。代价是重复劳动。链 n = 10⁴，n(n+1)/2 ≈ 5000 万次高度计算；单趟后序只要 2n + 1 ≈ 2 万次调用。差了两个数量级。

// 验证平衡二叉树（LeetCode 110）
    struct TreeNode {
        int val;
        TreeNode *left, *right;
    };

    bool balance;  // 全局变量，所有调用过程共享

    int Height(TreeNode* cur) {
        if (!balance || cur == nullptr) {
            return 0;
        }
        int lh = Height(cur->left);
        int rh = Height(cur->right);
        if (abs(lh - rh) > 1) {
            balance = false;
        }
        return max(lh, rh) + 1;
    }

    bool IsBalanced(TreeNode* root) {
        balance = true;  // 每次判断开始时重置
        Height(root);
        return balance;
    }

正解是后序一次遍历，顺路把子树高度带回：左右子树的高度各算一次，|左高 − 右高| 超过 1 就把全局布尔 balance 置 false，之后的高度不用再算，递归直接按 0 返回。

这就是树型 dp 的骨架：每个节点只等自己的两个孩子报数，拿到孩子的高度拼出自己的高度，往上递。坏消息（不平衡）靠全局布尔一路带上，省得每层都传引用。

三、验证搜索二叉树（LeetCode 98）

BST 的定义是「整棵左子树全小于根，整棵右子树全大于根」。两个等价刻画：中序遍历严格递增；或者子树回传自己的最小值和最大值，检查左子树的最大值小于根、根小于右子树的最小值。

先看中序迭代版。栈模拟中序遍历，pre 记上一个访问的节点，出现 pre >= 当前就返回 false。

// 验证搜索二叉树（LeetCode 98）
    struct TreeNode {
        int val;
        TreeNode *left, *right;
    };

    // 方法一：中序遍历，看是否严格递增
    bool IsValidBST1(TreeNode* head) {
        if (head == nullptr) {
            return true;
        }
        TreeNode* pre = nullptr;
        vector<TreeNode*> stack;
        while (!stack.empty() || head != nullptr) {
            if (head != nullptr) {
                stack.push_back(head);
                head = head->left;
            } else {
                head = stack.back();
                stack.pop_back();
                if (pre != nullptr && pre->val >= head->val) {
                    return false;
                }
                pre = head;
                head = head->right;
            }
        }
        return true;
    }

    // 方法二：递归回传子树的最小值与最大值
    long long minv, maxv;  // 全局变量：当前子树的最小值、最大值

    bool IsValidBST2(TreeNode* head) {
        if (head == nullptr) {
            minv = LLONG_MAX;
            maxv = LLONG_MIN;
            return true;
        }
        bool lok = IsValidBST2(head->left);
        long long lmin = minv, lmax = maxv;
        bool rok = IsValidBST2(head->right);
        long long rmin = minv, rmax = maxv;
        minv = min(min(lmin, rmin), (long long)head->val);
        maxv = max(max(lmax, rmax), (long long)head->val);
        return lok && rok && lmax < head->val && head->val < rmin;
    }

递归版回传子树的最小值和最大值，父节点用三个数字夹住自己。两个全局变量 minv、maxv 存当前子树的范围，空子树用 LLONG_MAX / LLONG_MIN 占位，这样空孩子永远「夹得住」，不用特判。

边界值必须用 long long：节点值本身可以到 ±2³¹，拿 int 当哨兵，int 的最大值会被真实的节点值顶穿。LeetCode 的判题器里节点值就是这个量级，int 哨兵直接翻车。

为什么要中序而不是只跟父节点比，看一棵陷阱树：

[5,4,6,null,null,3,7]：6 是 5 的右孩子，3 是 6 的左孩子。只跟父节点比，4 < 5 < 6，全过，但它不是 BST，因为 3 落在 5 的右子树里却比 5 小。中序拉直是 4, 5, 3, 6, 7，3 破坏了递增，拒绝。

四、复杂度分析

路径总和 IIO(n + 路径总长)O(h)访问 O(n)，命中路径整条拷贝，最坏 O(n²)

五、总结

路径题的关键是恢复现场：共享的 path 栈进分支前 push、出分支后 pop，命中的整条拷贝。忘了 pop 是这类题最常见的错，对拍能抓。

验证平衡的形态是后序回传高度，坏消息挂全局布尔；验证搜索树的形态是子树 min/max 夹住根，或者中序单调。

110 和 98 的递归结构已经是树型 dp：子树自底向上传信息，父节点只用自己的两个孩子。动态规划章节会把「两个状态、一个转移」的完整套路补上。
