扩展 KMP：z 数组与 e 数组

KMP 回答的是「模式串在主串里出现过没有」，这里问的是另一个问题：一个串的每一个后缀，和它自己的最长公共前缀能有多长。把答案按起点下标排成一个数组，就是 z 数组。求法跟 Manacher 是同一套：记住最靠右的那段匹配，能搬就搬，只在撞到边界时才真的往外比。

零、问题

题目给两个字符串 a 和 b，要两个数组。

z 数组：b 的每一个后缀与 b 自己的最长公共前缀长度。特别地 z[0] 就是 b 的长度。

e 数组：a 的每一个后缀与 b 的最长公共前缀长度。b 有多长，能匹配的长度就封顶在多少。

朴素做法对每个起点往后一位一位地比，最坏要 O(n2)。n = 8000 的随机 3 字母串实测 10.13 毫秒，n 每翻一倍耗时乘 4。

能不能让后面那些起点的比较少做一点？可以，因为前缀比对的结果前面已经算过了。

一、z 数组

z[i] 是 b[i..] 与 b 的最长公共前缀长度。拿 b = "aabaaab" 数一遍：

z[0] 定义成 7。z[1] 从 'a' 起，和前缀开头 'a' 相等，再比第二位是 'a' 与 'a'，第三位 'b' 与 'b' 也相等，第四位 'a' 与前缀的第四个字符 'a' 相等，第五位 'a' 与前缀的 'a' 相等，第六位 'a' 与前缀的 'b' 不等，所以 z[1] = 1。

z[3] 从 "aaab" 起，与前缀 "aab..." 前两位 'a'、'a' 相等，第三位 'a' 与 'b' 不等，z[3] = 2。z[4] 从 "aab" 起，与前缀 "aab" 逐位相等，三位都对完，z[4] = 3。

每个位置单独暴力比对都能得到正确答案，麻烦的地方在于重复劳动。z 数组编出来之后，「b 的某个后缀与前缀重合多长」这件事就变成查表。

二、和 Manacher 同款的加速

从左往右算 z[i]，同时记住一个范围：目前为止匹配长度伸得最远的那一段，它的起点是 c，右端第一个没被覆盖的位置是 r。也就是 b[c..r−1] 已经确认与前缀 b[0..r−c−1] 相等。

来到出发点 i 时：

1）i 没有被 r 包住（i ≥ r）。前面那段覆盖不到 i，只能从 0 开始一位一位比。

2）i 被 r 包住（i < r）。b[i..r−1] 这一段与前缀的 b[i−c..r−c−1] 逐位相等，是被 c 那一段带出来的。所以 b[i..] 与前缀的最长公共前缀，至少和 b[i−c..] 与前缀的一样长，也就是 z[i−c]。

同样只能搬 z[i−c] 和 r − i 里小的那个。z[i−c] 超出 r − i 的部分落在覆盖范围之外，没有保证，得自己比；z[i−c] 没超的部分可以放心搬过来。

初值取 min(r − i, z[i − c])，再交给 while 补差额，i 没被覆盖时初值取 0。写出来和 Manacher 只差几个字符。

// z 数组：b 的每个后缀与 b 自己的最长公共前缀，z[0] 直接定为串长
    const int MAXZ = 20000001;

    int z[MAXZ];

    void zArray(const string &s) {
        int n = (int)s.size();
        z[0] = n;
        for (int i = 1, c = 1, r = 1, len; i < n; i++) {
            len = r > i ? min(r - i, z[i - c]) : 0;
            while (i + len < n && s[i + len] == s[len]) {
                len++;
            }
            if (i + len > r) {
                r = i + len;
                c = i;
            }
            z[i] = len;
        }
    }

注意两个初值都从 1 开始：z[0] 是定义出来的不用比，出发点从 i = 1 起；c 和 r 一开始都给 1，相当于还没有任何一段被确认过，i = 1 会老老实实从头比。

每次 while 成功一圈就把 r 往右推一格，r 只增不减，整趟下来 while 成功执行的次数不超过 n。n = 106 的串 4.06 毫秒，2×106 8.31 毫秒，5×106 23.27 毫秒。

三、e 数组

e 数组问的是 a 的每个后缀与 b 的最长公共前缀。求法和 z 完全一样，只多一条上限：匹配长度不能超过 b 的长度。

借的东西不一样。求 z 时借的是 z[i − c]，因为被比较的是 b 自己和 b 自己；求 e 时 a 与 b 是两个串，被覆盖的区间里有保证的只有「a 的这段与 b 的前缀相等」，所以借的是已经算好的 z[i − c]。方向不能反过来写。

// e 数组：a 的每个后缀与 b 的最长公共前缀，比 z 多一条 len < m 的上界
    int e[MAXZ];

    void eArray(const string &a, const string &b) {
        int n = (int)a.size(), m = (int)b.size();
        for (int i = 0, c = 0, r = 0, len; i < n; i++) {
            len = r > i ? min(r - i, z[i - c]) : 0;
            while (i + len < n && len < m && a[i + len] == b[len]) {
                len++;
            }
            if (i + len > r) {
                r = i + len;
                c = i;
            }
            e[i] = len;
        }
    }

e 的循环从头开始，i = 0 也要算，这一点和 z 不同：z[0] 有定义，e[0] 得老老实实求。

四、权值异或和

题目不要求输出整份数组，只要一个数：对数组 x，位置 i 的权值是 (i + 1) × (x[i] + 1)，整份数组的权值是全部位置权值的异或和。

两个地方要注意。下标从 1 开始数，不是 0；z[0] = n 这一格也在内，忘掉它整个答案就错了。

异或和用 64 位整数接。单格最大接近 2×107 × (2×107 + 1) = 4×1014，三十二位放不下。

// 权值：i 位置的贡献是 (i+1)*(x[i]+1)，整份数组的权值取异或和
    long long eor(const int *arr, int n) {
        long long ans = 0;
        for (int i = 0; i < n; i++) {
            ans ^= (long long)(i + 1) * (arr[i] + 1);
        }
        return ans;
    }

|a| = |b| = 107 的随机 26 字母串，z 与 e 加起来不到 26 毫秒；两个权值分别是 28327782 和 14122929。全 a 串上两个数组完全一样，权值都是 25000001122304。

写的时候有六处容易错。

一，z[0] 不能忘。定义成 0 的话第 0 格差一个数，权值必错，实测 100% 抓得到。

二，加速的参照是 z[i − c]，写成 z[c] 就在借另一个位置的旧值。小字符表上很显眼，字符表取 3 时 61.14%，取 26 时就只剩 13.15%。

三，初值要夹 r − i。只写 z[i − c] 会让半径冲过覆盖范围，字符表 3 时 17.09%，字符表 26 时 0.14%。

四，e 的加速借 z 而不是借 e 自己。写成 e[i − c] 之后参照值来自另一个串的历史，字符表 3 时 29.55%，字符表 26 时 0.55%。

五，权值下标从 0 起算，97.21% 出错。

六，e 数组的 (a, b) 别写反。反了之后算的是 b 的后缀与 a 的最长公共前缀，长度都不一样，89.96% 出错。

五、复杂度分析

做法关键操作时间空间
朴素比对每个起点各自逐位比O(n2)O(1)
z 数组每个起点白拿一段再补扩O(n)O(n)
e 数组借 z 的覆盖范围，比 b 的长度封顶O(n + m)O(n + m)

线性的理由和 Manacher 一样：while 每成功一圈，r 至少右移一格，r 单调不减且最多到 n，所以 while 成功执行的总次数不超过 2n。e 数组多出来的那条 len < m 只是让半径不超过 |b|，不影响摊还。空间上 z 与 e 各按题目上限 2×107 开 int 表，每张 80 MB，两张一共 160 MB，开数组时要照这个数字留。

总结

z 数组是 b 的每个后缀与 b 自己的最长公共前缀，z[0] = n；e 数组是 a 的每个后缀与 b 的最长公共前缀，上限是 |b|。

两套求法共用一套加速：c 是当前匹配伸得最远的起点，r 是它右边第一个没覆盖的位置。i 被 r 包住时，z 借 z[i − c]、e 借 z[i − c]，再夹一个 r − i，剩下的交给 while。

时间 O(n + m)，空间 O(n + m)。n = 8000 上朴素比对 10.13 毫秒、z 数组 0.054 毫秒；n = 107 的规模下两个数组加一起不到 26 毫秒。权值那一份要注意下标从 1 数、且用 64 位接。

把 z 数组拿到手之后，一串周期问题都能变成一次查表，这就是下一节要做的事。
