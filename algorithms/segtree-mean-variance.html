线段树：和与平方和

方差看起来是最不能懒的东西：它要求每个数先减去平均数。可把 Σ(x − m)² 展开之后，表达式里只剩「和」和「平方和」两个汇总量。麻烦的地方在整段加 v 的时候，这两个量一起变，而且更新的先后顺序不能反。

零、背景

区间加是最容易懒的操作，因为它对「和」的影响是确定的：加数乘段长。可这道题问的是平均数和方差，光有和推不出方差。

方差的标准定义是「每个数减去平均数再平方，最后平均」，看着必须把每个数都过一遍。这里有个改写：Σ(x − m)² 展开是 Σx² − 2mΣx + nm²，除以 n 得到 Σx²/n − m²，其中 m = Σx/n。所以只要再维护一个 Σx²，方差就能一次算出来。

难点转到「整段加 v 之后 Σx² 变成多少」。它有闭式，但算的时候要用加之前的那个和。

一、题目

平均数和方差（洛谷 P1471）：长度 n 的数组 arr，三种操作，一共调用 m 次。

  • 操作 1 l r v：把 arr 中 [l, r] 上的每个数字加上 v，v 是实数。
  • 操作 2 l r：输出 [l, r] 上所有数字的平均数。
  • 操作 3 l r：输出 [l, r] 上所有数字的方差。

n 和 m 到 10⁵，输出都保留四位小数。输入里的数可能写成科学计数法的样子，比如 1e-3、-3E1。

二、两个量就够了

节点上存两样东西：这一段的和 sum1、这一段的平方和 sum2。合并就是相加，和普通区间和一模一样。

查询时平均数等于 sum1 除以段长；方差等于 sum2 除以段长，再减掉平均数的平方。整个过程不需要知道段里的任何一个具体值。

const int MAXN = 100001;

    double arr[MAXN];
    double sum1[MAXN << 2];  // 这一段上所有数的和
    double sum2[MAXN << 2];  // 这一段上所有数的平方和
    double addv[MAXN << 2];  // 整段加了多少，还没传给儿子

    void up(int i) {
        sum1[i] = sum1[i << 1] + sum1[i << 1 | 1];
        sum2[i] = sum2[i << 1] + sum2[i << 1 | 1];
    }

    // 整段加 v，长度为 n：平方和先更新，用的是加之前的和
    void lazy(int i, double v, int n) {
        sum2[i] += sum1[i] * v * 2 + v * v * n;
        sum1[i] += v * n;
        addv[i] += v;
    }

    void down(int i, int ln, int rn) {
        if (addv[i] != 0) {
            lazy(i << 1, addv[i], ln);
            lazy(i << 1 | 1, addv[i], rn);
            addv[i] = 0;
        }
    }

    void build(int l, int r, int i) {
        if (l == r) {
            sum1[i] = arr[l];
            sum2[i] = arr[l] * arr[l];
        } else {
            int mid = (l + r) >> 1;
            build(l, mid, i << 1);
            build(mid + 1, r, i << 1 | 1);
            up(i);
        }
        addv[i] = 0;
    }
void add(int jobl, int jobr, double jobv, int l, int r, int i) {
        if (jobl <= l && r <= jobr) {
            lazy(i, jobv, r - l + 1);
        } else {
            int mid = (l + r) >> 1;
            down(i, mid - l + 1, r - mid);
            if (jobl <= mid) {
                add(jobl, jobr, jobv, l, mid, i << 1);
            }
            if (jobr > mid) {
                add(jobl, jobr, jobv, mid + 1, r, i << 1 | 1);
            }
            up(i);
        }
    }

    double query(double *sum, int jobl, int jobr, int l, int r, int i) {
        if (jobl <= l && r <= jobr) {
            return sum[i];
        }
        int mid = (l + r) >> 1;
        down(i, mid - l + 1, r - mid);
        double ans = 0;
        if (jobl <= mid) {
            ans += query(sum, jobl, jobr, l, mid, i << 1);
        }
        if (jobr > mid) {
            ans += query(sum, jobl, jobr, mid + 1, r, i << 1 | 1);
        }
        return ans;
    }

    // 平均数就是区间和除以长度
    double mean(int l, int r, int n) {
        return query(sum1, l, r, 1, n, 1) / (r - l + 1);
    }

    // 方差 = 平方和的平均 - 平均数的平方
    double variance(int l, int r, int n) {
        double a = query(sum1, l, r, 1, n, 1);
        double b = query(sum2, l, r, 1, n, 1);
        double size = r - l + 1;
        return b / size - (a / size) * (a / size);
    }

三、整段加 v 之后

每个数变成 x + v，平方之后是 x² + 2vx + v²。n 个数加起来就是平方和增加 2vΣx + nv²，其中 Σx 是这一段加之前的和。

代码里 sum2 那一行写在 sum1 前面，就是为了保证 sum1[i] 还是旧值。这两行交换过来，公式里的 Σx 变成了加完之后的 Σx + nv，等价于多算 2v²n。

实测：n = m = 16000、每次操作盖住大半段，逐格改数组再重新算平均数和方差的暴力 203.14 ms，线段树 7.02 ms，差 29 倍。n = m = 10⁵ 时 51.89 ms。

平方和的量级要留意。值域 10⁴、长度 10⁵ 时 sum2 最大约 10¹³，double 有 53 位有效位（约 9 × 10¹⁵），装得下。这道题的值域不大，所以直接上 double 没问题；值域再大几个数量级就得换成长整型或者更高精度。

四、复杂度分析

项平均数和方差
建树O(n)
单次区间加O(log n)
单次查询O(log n)
全程总代价O((n + m) log n)
空间O(n)：三个 double 数组（和、平方和、懒标记）加一个存初值的数组

按 n = 10⁵ 开四倍空间，三个长度 4 × 10⁵ 的 double 数组各 3.05 MiB，加上长度 10⁵ 的初值数组 0.76 MiB，一共 9.92 MiB。

这道题还有一段和语言相关的插曲：同一份逻辑用 Java 写会超空间。卡住的是读入那一步，输入里带科学计数法，Java 的 StreamTokenizer 读不了，只能换成 StringTokenizer，而它的内存开销大得多。C++ 这边用 scanf 直接就能读：把 1e-3 2.5e0 -3E1 4.5 -5 读进来求平均数得 −5.5998，正是这五个数的平均。

五、几种写错的样子

每档 4000 组随机操作，四档的 n 分别是 4、8、16、64，操作次数 6 到 14 之间。表里的数字是「错版答案与正解不一样」的比例，方差按四位小数比。

写错的地方n = 4n = 8n = 16n = 64
懒更新里先改和、再算平方和82.20%80.28%80.45%80.00%
忘记把懒标记累积起来69.15%76.40%79.35%83.00%

第一行是顺序问题，误差是 2v²n。加数 v 恰好是 0 的那几次不会产生误差，这种机会在数据里占九分之一左右；剩下的还要靠后面真去查一次才会暴露。两件事叠起来，比例就停在 80% 附近，几乎不随 n 变化，原因是它错在公式本身，跟数据规模没关系。

第二行是懒标记没累积，子节点上留着过期值，只有查询刚好落到那些位置时才显出来。n 越大，一次查询碰到的位置越多，踩中的概率就从 69.15% 涨到 83.00%。

六、总结

方差能被线段树维护，靠的是那次改写：Σ(x − m)² 展开之后只剩和与平方和，两个都是「段上的量」，都能合并。凡是要求「整段上每一个数都参与、但结果只看汇总」的统计量，都可以先试着展开，看它是不是只依赖少数几个可合并的量。

整段加 v 时两个量一起变，而且平方和的新值依赖旧的 sum1。这种「多个量互相依赖」的更新，写的时候把顺序摆对，或者先把旧值接进临时变量再算。

除此之外这道题没有任何新东西：懒标记就是普通的「加了多少」，与区间加的写法完全一样，多出来的只是节点上多存一个量。

最后

两个坑。一是懒更新里 sum2 必须在 sum1 之前算，反过来就是每次多算 2v²n。二是输入里可能有科学计数法，用 scanf("%lf") 直接能读；要是整段读字符串再自己解析，1e-3、-3E1 这些形态都得照顾到。
