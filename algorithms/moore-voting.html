摩尔投票与水王数

一堆数里找出出现次数严格过半的那一个：两两抵消，活下来的就是答案。本门从一张全程不用看正面的选票桌讲起，再看多线程分段投票，以及左右两半水王数相同的划分。

零、背景

水王数指大小为 n 的数组里出现次数大于 n/2 的值。数据里不一定有；有的话至多一个：两个数都过半，加起来就超过 n 了。

最直接的做法是拿一张哈希表数一遍，时间 O(n)，空间随值域走。摩尔投票把空间压到两个变量，时间还是一遍。这个技巧又叫寻找水王算法，是笔试面试里的高频考点，本门从它的原始形态讲起。

一、选票机：全程不看正面的胜负判定

先看一道智力题。一桌选票背面向上摆在桌上，每张正面写着投给谁，背面毫无差别。你有一台机器，可以验证任意两张选票上写的人名是否一样。如果有人得票过半，你要宣告投票成功，并当着众人的面在最后时刻翻开任意一张当选人的选票；没有人过半就宣告失败。全程不许看选票正面。

做法是配对抵消。随便拿两张交给机器：写的一样，两张一起留下一叠，算两份幸存；写的不一样，两张一起扔到桌下，它们至多各消对方一票，过半那个人的优势不受影响。一叠一叠地处理，最后看幸存叠：还有票剩下，剩的全是同一个名字，它就是当选人，随便挑一张留到最后一刻翻开；叠空了，说明全部抵消完，无人过半。

把流程写成一个不变式：每次抵消至少用掉一张非当选人的票，而这样的抵消总共不超过 n 减 c 次（c 是当选人的得票）。所以当选人至少剩下 c 减 (n 减 c) 等于 2c 减 n 张，严格大于 0。幸存叠里只剩一个名字，它不是当选人还能是谁。

「最后时刻才翻开」在这套流程里是自然成立的：从头到尾没有看过任何一张正面，机器只回答「是否一样」。当选人的票一直混在幸存叠里背朝上，直到最后才亮出来。

二、摩尔投票：两个变量走一遍

把选票桌搬到数组上，就是摩尔投票。cand 记当前候选，hp 记幸存叠里的张数。新来一个数：叠空了它自动成为候选，血量置 1；和候选一样就压上去，血量加 1；不一样就抽掉叠里一张，血量减 1。血量归零意味着上一叠全灭，下一个数重新起叠。

#include <bits/stdc++.h>
    using namespace std;

    // 出现次数严格大于 n/2 的数叫水王数, 不存在时返回 -1
    int waterKing(vector<int>& nums) {
        int cand = 0, hp = 0;
        for (int num : nums) {
            if (hp == 0) {
                cand = num;
                hp = 1;
            } else if (num != cand) {
                hp--;
            } else {
                hp++;
            }
        }
        if (hp == 0) {
            return -1;
        }
        // 活下来只是必要条件, 再数一遍真实出现次数
        hp = 0;
        for (int num : nums) {
            if (num == cand) {
                hp++;
            }
        }
        return hp > (int)nums.size() / 2 ? cand : -1;
    }

拿 [2,2,1,1,1,2,2] 走一遍。前两个 2 把血量推到 2，接着两个 1 把血量打回 0，候选作废；第 5 格的 1 起新叠，第 6 格的 2 又把它打空；最后一个 2 再起新叠，血量 1 走完。整趟下来候选换了三回头，最后停在 2。

注意最后一行的数字：最终血量是 1，可 2 在数组里出现了 4 次。血量从来不是出现次数，它只是「抵消之后还剩多少」。中间那次归零重开，把前面攒下的优势一把清零了。

演示：摩尔投票逐格走一遍

点「下一步」逐个元素处理，看候选和血量怎么变、哪些格被配对抵消、哪些格幸存。最后一屏做第二遍计数验证。可以切换五组固定数据或一组随机数据。

三、为什么活下来的是当选人

证明只用一句话：每次「不一样」的比对至多从当选人的份额里拿走一票，而这样的比对总共不超过非当选人的票数。设 x 出现 c 次且 c 大于 n/2，抵消次数至多 n 减 c，所以 x 至少剩下 2c 减 n 张，是正数。幸存的格子全是同一个值，它只能是 x。

这里有个细节：抵消的两张票可以都不是 x。比如 1 和 3 撞在一起互相消耗，x 一票不损失。所以「至多损失一票」这个上界是宽松的，宽松不要紧，剩下正数就够了。

四、幸存者也会骗人

血量大于 0 只说明候选有剩，不说明它过半。值域一多，活下来的候选大半是假的：n=1000 的随机数组跑 20000 组，值域 3 时有 49.59% 的数组血量大于 0，而这些候选里 100% 都没过半；值域 5 时血量大于 0 的比例降到 24.86%，活下来的候选同样全是假水王；值域 100 时只剩 1.01% 的数组有幸存者，也照样是假的。

值域 2 是唯一的例外。二值数据上，血量恰好就是两个值出现次数之差：把数组看成一串加一减一的游走，血量归零时游走回到原点，重新起算不丢信息。所以 hp 大于 0 当且仅当候选过半，20000 组随机数据里一例假的都没有。值域到 3，游走归零时你并不知道前面是谁占优，信息就此丢失。

所以教科书式的摩尔投票后面都跟着一遍计数验证。代码里第二遍循环干的就是这件事。LeetCode 169 的数据保证过半元素存在，验证可以省；通用版不能省。实测删掉第二遍验证，值域 3、n=1000 的随机数组上一半样本答错。

五、并发：分段投票再合并

摩尔投票天然可以并行：把数组切成若干段，每段各自跑一遍摩尔投票，各得一个（候选，血量）二元组，再两两合并。合并规则和投票本身一样朴素：候选相同，血量相加；候选不同，血量相减，血量大的那个当候选。

#include <bits/stdc++.h>
    using namespace std;

    // 合并两段的投票结果: 候选相同血量相加, 不同则血量相减、血量大的当候选
    pair<int, int> mergeVote(pair<int, int> a, pair<int, int> b) {
        if (a.first == b.first) {
            return make_pair(a.first, a.second + b.second);
        }
        return a.second >= b.second ? make_pair(a.first, a.second - b.second)
                                    : make_pair(b.first, b.second - a.second);
    }

合并为什么是对的：投票结果满足一条不变式：对段内任何不等于候选的值 y，y 的出现次数不超过 (段长 减 血量) 除 2。两条不变式一加，合并后的二元组仍然满足它。于是「整段有严格众数」这个性质在合并中保留：只要严格众数存在，合并出来的候选就是它。5000 组随机数组实测，严格众数存在时，合并法与整段顺序跑的候选 0 例不一致。

但（候选，血量）的原值不保证复现。同一组数据，整段顺序跑得到 (2, 2)，四段合并得到 (2, 4)：候选一致，血量不同。5000 组里只有 60.3% 的二元组完全一致，其余是血量归零后的候选垃圾值，或者血量估计不同。并发要的只是候选，血量够用就行。

实测 n=10⁶：单线程 0.770ms，四线程分段加合并 0.250ms，3.08 倍。段数继续加收益会钝化，最后卡在合并那几步和内存带宽上。

六、应用：左右两半的水王数相同

题意：找最小下标 i，把数组切成 nums[0..i] 和 nums[i+1..n-1]，要求两半的支配元素相同：两边都严格过半，而且是同一个值。找不到返回 -1。

先摩尔投票找出候选并数出总次数 m，再从左往右扫划分点，维护 lc（候选在左边的次数）和 rc 等于 m 减 lc。第一个满足 lc 大于 (i+1)/2 且 rc 大于 (n−i−1)/2 的 i 就是答案。扫描是 O(n)，两遍计数也是 O(n)，全程只动了几个变量。

#include <bits/stdc++.h>
    using namespace std;

    // 左右两半的水王数相同, 返回最小划分点, 不存在返回 -1
    int minimumIndex(vector<int>& nums) {
        int cand = 0, hp = 0;
        for (int num : nums) {
            if (hp == 0) {
                cand = num;
                hp = 1;
            } else if (cand == num) {
                hp++;
            } else {
                hp--;
            }
        }
        hp = 0;
        for (int num : nums) {
            if (num == cand) {
                hp++;
            }
        }
        int n = nums.size();
        // lc : 候选在左边的次数, rc : 在右边的次数
        for (int i = 0, lc = 0, rc = hp; i < n - 1; i++) {
            if (nums[i] == cand) {
                lc++;
                rc--;
            }
            if (lc > (i + 1) / 2 && rc > (n - i - 1) / 2) {
                return i;
            }
        }
        return -1;
    }

三个容易踩的地方。第一，两边都必须是候选过半，只查一边会错。第二，整段有水王也不一定有解：[1,2,1] 里 1 出现 2 次确实过半，但切在 0 右边剩 [2,1]、切在 1 左边是 [1,2]，1 在哪半边都不过半。实测值域 2 的随机数组里，有水王的例子中 23.45% 无解，值域 5 时这个比例升到 67.83%。第三，合法划分往往不唯一：n=30、值域 2 的随机数组里 85.3% 有解，其中 83.2% 至少存在两个划分点，题目要最小下标，顺序扫第一个命中的正好就是。

这里有个细节：这道题的扫描自带验证。两个不等式相加，lc 加 rc 大于 n/2，而 lc 加 rc 正是候选的总次数——能找到划分点，候选就一定是水王数；一个都找不到，返回 -1 也不会错。所以题 1 里必不可少的那遍计数验证，在这里可以省。

错法实录：右侧次数忘了从总次数里减，让 rc 跟着 lc 一起涨，5000 组随机数组里 53.06% 答错。lc 和 rc 必须此消彼长：一个从 0 往上爬，一个从总次数往下掉。

演示：划分点扫描

第一先把候选和总次数跑出来，然后逐个划分点看 lc 和 rc 与各自门槛的关系，第一个两边都过的就是答案。可以切换四组固定数据或一组随机数据。

七、复杂度分析

做法时间空间
摩尔投票一遍O(n)O(1)
摩尔投票加验证O(n)O(1)
哈希表计数O(n)O(值域)
分段 t 路投票加合并O(n + t)O(t)
划分左右相同水王O(n)O(1)

摩尔投票的快不在渐近式，在常数：一遍扫描只动两个变量，缓存里连个额外指针都不摸。实测 n=10⁶：有水王的数据 0.567ms 对哈希计数 2.416ms，值域到 10⁶ 时 0.646ms 对 32.452ms。值域越大，哈希表越吃亏。划分题两边都是 O(n)，但朴素实现每个划分点各数一遍是 O(n²)，正解把计数摊成一次扫描。

八、总结

摩尔投票两个变量一遍扫描，背后是配对抵消：严格过半的值一定有幸存，幸存叠里只剩一个名字。血量大于 0 只是必要条件，值域 3 以上的随机数据里活下来的候选几乎全是假水王，第二遍计数验证不能省；二值数据是唯一例外，血量就是次数差。

合并规则「同加异减」保留了严格众数候选，5000 组实测 0 例不一致，四线程 3.08 倍。血量本身只是估计，整段跑与分段合并未必相同，并发只用候选不用血量。

应用侧，左右两半水王数相同一题把候选加前缀计数走一遍即可，O(n) 时间 O(1) 空间；有水王而无解是常态，别把「存在支配元素」当成「一定有划分」。

再把门槛从 n/2 换成 n/k，一个计数器要换成 k−1 个；把投票结果预先存进线段树，静态数组上的区间查询每次只摸 log n 个结点。这两条路都在下一门。
