倍增与 ST 表

一条线上每次只能往右跳，跳 1 步最远到哪是已知的。把跳 2 步、4 步、8 步各能到哪也预先算出来存成一张表，问「从这儿到那儿最少几步」就不用一步一步数了。这张表叫 ST 表（Sparse Table），填它的手法叫倍增。

零、先把二进制的两件小事做对

第一个：给一个正数 x，已知 m 个二进制位一定够表示它，从高位到低位打印每一位。做法是从最高位往下试，能减就减，减不动就是 0。

第二个：求不超过 x 的最大 2 的幂是 2 的几次方。这件事在后面每次查询都要用一次，写法上有个坑。

最顺手的写法是让 power 从 0 往上涨，直到 1 << power 超过 x 为止。x 小的时候它是对的，x 到 2×10⁹ 就出事：power 涨到 31 时 1 << 31 在 int 里是 −2147483648，负数照样满足「小于等于 x」，循环继续；power 到 32，C++ 里移位超过位宽是未定义行为，x86 机器上等价于 1 << (power & 31)，值绕回 1，条件再次成立。这台机器上的实测结果是循环一直涨到 40 次上限都没停。

把 x 先右移一位再比就绕开了：1 << power 最多走到 int 正数的一半，永远不会溢出。

// <= x 的最大 2 的幂，是 2 的几次方
    int floorLog(int x) {
        int power = 0;
        // 判据写成 (1 << power) <= x 会溢出：power 涨到 31 时 1 << 31 是 INT_MIN
        // 再往后 C++ 里移位超过位宽是未定义行为，x86 上绕回 1，循环停不下来
        // 把 x 右移一位再比，1 << power 最多走到 int 的一半，永远不溢出
        while ((1 << power) <= (x >> 1)) {
            power++;
        }
        return power;
    }

每次现算一次幂次太浪费，多数做法是打一张表。log2[0] = -1 是故意写的，这样 log2[1] = log2[0] + 1 = 0 刚好对上，整张表一个循环就出来了。

// log2[i] : 不超过 i 的最大 2 的幂，是 2 的几次方
    void buildLog(int n) {
        log2[0] = -1;
        for (int i = 1; i <= n; i++) {
            log2[i] = log2[i >> 1] + 1;
        }
    }

表里第 i 项是不超过 i 的那个最大 2 的幂的指数，1 到 32 全部与 floor(log2(i)) 一致，实测过。

点「下一步」从最高位往下试，看每一位是够减写 1 还是够不着写 0，右边一栏是剩余的数。可以换五组数据。

一、问题：一条只能往右跳的线

线段上有 n 个点，编号 1 到 n。已知每个点 i 往右跳 1 步最远能到 jump1[i]，并且 i 小于 j 时必有 jump1[i] 不超过 jump1[j]。从任何点出发都能走到第 n 个点。要回答两个问题：

1）怎么造一张表，能查「从 i 出发跳 2 的 p 次方步，最远到哪个点」；

2）从 x 到 y 最少跳几步。

第二个问题用第一张表来答，两个问题一起解决。

二、朴素做法：一步一步挪

第一问的第 0 列就是 jump1 本身，白给。第二问也从这里起步：cur 从 x 出发，每次 cur = jump1[cur]，数到 cur 不小于 y 为止。这个循环的次数就是答案。

跳跃的跨度越大，循环越少；跨度最小是每次只前进 1，那时从 1 到 n 要走 n 减 1 次。实测一组 n 等于 10⁶、平均跨度 3 的数据，一次查询平均要跳 12.36 万次，每次 129 微秒。查询一多，时间全花在这上面。

三、倍增：一次算出 2 的 p 次方步

跳 2 的 p 次方步，等于先跳 2 的 p−1 次方步，落地之后再跳 2 的 p−1 次方步。前后两半长度一样，所以整段行程完全由落地那一刻决定：

st[i][p] = st[ st[i][p-1] ][p-1]

第 0 列是 jump1，第 1 列由第 0 列算，第 2 列由第 1 列算，一路推下去。p 最大取到 floorLog(n) 就够：再往上跳，2 的 p 次方已经超过 n，落点只会是终点。

const int MAXN = 1000001;
    const int LIMIT = 21;
    // jump1[i] : 从 i 号点出发跳 1 步，最远能到达的点
    int jump1[MAXN];
    // stjump[i][p] : 从 i 号点出发跳 2 的 p 次方步，最远能到达的点
    int stjump[MAXN][LIMIT];
    int power;

    void build(int n) {
        power = floorLog(n);
        for (int i = 1; i <= n; i++) {
            stjump[i][0] = jump1[i];
        }
        for (int p = 1; p <= power; p++) {
            for (int i = 1; i <= n; i++) {
                // 跳 2 的 p 次方步 = 先跳 2 的 p-1 次方步，再跳 2 的 p-1 次方步
                stjump[i][p] = stjump[stjump[i][p - 1]][p - 1];
            }
        }
    }

填表的顺序有个讲究：外层枚举 p，内层枚举 i。因为每个格子的值只依赖第 p−1 列，第 p−1 列必须是完整的。反过来写的话，用到的时候那一列还只有一半。

整张表 n 行、floorLog(n) + 1 列。n 等于 10⁶ 时是 2000 万个 int，76.3 MB，构建 97 毫秒。空间是这张表最贵的地方，后面几门会反复提到这个代价。

四、查询：从最大的步长往下试

有了表，第二个问题换个问法：从 x 出发，最多能往前「浪费」多少步还够不着 y。p 从 floorLog(n) 一路降到 0，每档看一眼 st[cur][p]，落点还在 y 左边就真的跳过去，否则这一档不动。走完整个循环，cur 停在「再跳一步就够着 y」的位置上，答案再加 1。

// 从 x 出发，最少跳几步能到 y（x <= y）
    int minSteps(int x, int y) {
        if (x >= y) {
            return 0;
        }
        int cur = x, ans = 0;
        for (int p = power; p >= 0; p--) {
            int next = stjump[cur][p];
            if (next < y) {          // 跳过去还够不着，这一跳就值得走
                ans += 1 << p;
                cur = next;
            }
        }
        return ans + 1;              // 再跳一步才真正落进 y
    }

为什么从大到小就一定对。大步长能走通时，小步长也一定走得通，先试大的不会把路走死；反过来先试小的，可能连着试好几档都「看起来能走」，结果加起来反而超过了该停的位置。二进制拆分的唯一性保证了这个贪心正确：任何步数都能唯一拆成若干个 2 的幂，从大到小试，就是在逐位确定这个拆法的每一位。

循环固定跑 floorLog(n) + 1 次。同一组 n 等于 10⁶ 的数据，倍增每次查询 0.284 微秒，对朴素的 129 微秒是 456 倍。n 等于 10⁵ 时是 15.8 对 0.053 微秒，298 倍。

点「下一步」让 p 从大到小走一遍，橙色是当前正在试的那一格，下方整张表实时对照。可以换五组数据，跨度从 1 到 5。

五、复杂度分析

环节时间空间
log2 打表O(n)O(n)
倍增填表O(n log n)O(n log n)
单次查询最少步数O(log n)O(1)
朴素一步一步挪O(步数)，最坏 O(n)O(1)

空间按题目上限算：n 等于 10⁶ 时表是 10⁶ 行 × 20 列 = 2000 万个 int，76.3 MB。列数取 floorLog(n) + 1，n 等于 2×10⁵ 时是 18 列，10⁶ 时是 20 列，用常量 21 开数组足够。

这张表一旦填好就不能改：改一个 jump1[i]，受影响的格子是 O(log n) 个，重填整张表又是 O(n log n)。所以倍增适合静态数据，这是它最硬的约束。

六、总结

倍增的核心是一句话：跳 2 的 p 次方步等于跳两次 2 的 p−1 次方步。靠这一句把「跳很多步」变成两次查表，填表 O(n log n)，查询 O(log n)。查询时从大到小试步长，靠的是二进制拆分的唯一性。

两个工程细节值得记住。求「不超过 x 的最大 2 的幂」要把 x 右移一位再比，否则 power 到 31 就溢出，循环停不下来；log2 打表从 log2[0] = -1 起步，一个循环填完，比每个位置现算一遍省事得多。

代价是空间：n log n 个格子，n 等于 10⁶ 就是 76 MB，而且表填完不支持修改。同样的「预先算好 2 的 p 次方」搬到数组区间上还能再快一档，那里的查询是 O(1)。
