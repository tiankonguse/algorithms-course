博弈：斐波那契与威佐夫

第一题问「先手第一手至少取几颗才能保证赢」，答案写在 n 的 Zeckendorf 拆分里，就是这个拆分最小的那一项。第二题给两堆石子，答案写在黄金分割比例里。这两条结论在考场上都不好现推，好在都能从一串特殊数上看出来。

零、两题各自要什么

第一题：一共 n 枚石子，先手第一轮可以取走任意多颗，之后每轮至少取 1 颗、至多取上一轮的两倍，取走的数量还不能超过场上剩下的。谁取走最后一颗谁赢。已知先手一定赢，问第一轮至少取几颗才能保证赢。样例里 n=4 的答案是 1，n=7 的答案是 2，n=8 的答案是 8。

第二题：两堆石子，数量任意，每次要么在任意一堆里取走任意多颗，要么在两堆里取走同样多颗，谁取走最后一颗谁赢。给两堆的数量，返回先手能不能赢。

第一题的走法被「上一轮的两倍」这个上限卡着，状态不止是「还剩多少颗」，还得记住上一轮取了多少；第二题的状态是两堆的一对数量，表格是二维的。两题都值得先写暴力打表，答案在表里长得很有规律。

一、斐波那契博弈：减到剩下一项为止

把 n 从 1 到 20 的答案打出来：1、2、3、1、5、1、2、8、1、2、3、1、13、1、2、3、1、5、1、2。规律很明显：n 是 1、2、3、5、8、13 这几个数时答案就是 n 自己，其余的位置答案都比 n 小，而且看着像是把 n 拆开之后剩下的零头。

拆开的方式来自 Zeckendorf 定理：每个正整数都能唯一地写成若干个斐波那契数之和，要求这些数两两不相邻。这里的斐波那契数列取 1、2、3、5、8、13…，从 1 和 2 起步，相邻两项的比值不到 2，隔一项的比值大于 2，这个「不相邻」的限制就是唯一性的来源。

举两个例子：100 = 89 + 8 + 3，下标 11、6、4，两两都不相邻；1000 = 987 + 13。定理说这种拆法只有一种。

结论是：答案就是拆分里最小的那一项。100 拆出 89、8、3，答案是 3；1000 拆出 987、13，答案是 13；n 本身是斐波那契数时，拆开只有一项，答案就是 n，这也解释了打出来的表里 8 和 13 为什么那么突兀。

为什么最小那一项正好是第一手要取的数？两部分的下标至少相差 2，所以 2 乘最小项一定小于前一项。先手取走最小项之后，对手最多只能取 2 倍，够不到前一项那一块；先手再把前一项交出去一点点，同样的不等式一层层往下走，对手始终只能跟在后面，最后一颗落在先手手里。

代码上不需要分类讨论，照着定理贪心就行：反复减掉不超过 n 的最大斐波那契数，循环到剩下 1 或 2，或者某一步剩下的正好是一个斐波那契数。整个 1015 范围内的斐波那契表只有 73 项，减到 1 或 2 为止，减的次数就是拆分里有多少项。1015 的拆分最长，有 18 项，最小项是 3。

// 斐波那契博弈：先手第一轮随便取，之后每人至少取 1 颗、至多取上一轮的两倍
    // 先手一定赢，问的是保证获胜的最小第一手
    // 答案是 n 的 Zeckendorf 拆分里最小的那一项：
    // 反复减掉不超过 n 的最大斐波那契数，最后剩下的那个斐波那契数就是答案
    // n 本身是斐波那契数时拆分只有一项，答案就是 n
    ll fib[105];
    int fsz;

    void buildFib(ll limit) {
        fib[0] = 1;
        fib[1] = 2;
        fsz = 1;
        while (fib[fsz] <= limit) {
            fib[fsz + 1] = fib[fsz] + fib[fsz - 1];
            fsz++;
        }
    }

    // 不超过 n 的最大斐波那契数
    ll maxFibAtMost(ll n) {
        int l = 0, r = fsz, m;
        ll ans = -1;
        while (l <= r) {
            m = (l + r) / 2;
            if (fib[m] <= n) {
                ans = fib[m];
                l = m + 1;
            } else {
                r = m - 1;
            }
        }
        return ans;
    }

    ll minFirstTake(ll n) {
        ll ans = -1, part;
        while (n != 1 && n != 2) {
            part = maxFibAtMost(n);
            if (n == part) {
                ans = part;
                break;
            }
            n -= part;
        }
        return ans != -1 ? ans : n;
    }

实测这个循环一点也不长：n 不超过 1000 时平均减 3.39 次，n 不超过 109 时平均 11.26 次，n 不超过 1015 时平均 19.19 次、最多的一个数减了 29 次。20 万次查询跑完 67.51ms，其中绝大多数时间花在二分上，减的次数本身很少。

二、威佐夫博弈：必败点的坐标里有黄金分割比例

把小的那堆记为 mn、大的记为 mx，用暴力把 0 到 15 的网格全部算出来，必败点是 (0,0)、(1,2)、(3,5)、(4,7)、(6,10)、(8,13)、(9,15)。

看这些坐标的两个性质。第一个：每个正整数恰好出现在这些点里一次，1 在 (1,2)、2 在 (1,2)、3 在 (3,5)、4 在 (4,7)、5 在 (3,5)，没有数重复，也没有数漏掉。第二个：相邻两堆的差值是 1、2、3、4、5、6，第 k 个必败点的差值正好是 k。

把差值叫做 k，那么第 k 个必败点就是 (⌊k·φ⌋, ⌊k·φ⌋ + k)，其中 φ 是黄金分割比例 (1 + √5) / 2 ≈ 1.618。反过来说，判定一个局面是不是必败点，只要算一下 mn 是不是等于 ⌊k·φ⌋。

为什么偏偏是 φ？因为两列楼层数必须恰好铺满所有正整数：小的那一列是 ⌊k·φ⌋，大的那一列是 ⌊k·φ²⌋，两者不重不漏要求 1/φ + 1/φ² = 1，解出来正好是 φ 等于 (1 + √5) / 2。这条性质也解释了上面说的「每个正整数恰好出现一次」。

落地的时候有个坑：φ 是无理数，把上面那个等式直接写成 mn == (int)(k * φ)，只要浮点的精度不够，大数上就会判错。φ 截到 1.618 时，第 233 个必败点 (377, 610) 就已经算错了，截到 1.61803 撑到第 610 个，截到 1.6180339887 撑到第 196418 个。这些出错的位置都是斐波那契数，因为斐波那契相邻两项之比在 φ 两侧来回摆动，恰好卡在临界点上。

躲开浮点的办法是把不等式两边乘 2 再平方。mn ≤ k·φ < mn + 1 乘以 2 变成 2mn − k ≤ k√5 < 2(mn+1) − k，两边都是正数，平方之后就是纯整数比较，一位小数都不用碰。

// 威佐夫博弈：两堆石子，每次可以从任意一堆拿走任意多颗，也可以从两堆里拿走同样多颗
    // 拿走最后一颗的人获胜
    // 必败局面的特征是：较小的一堆 == （两堆差值 × 黄金分割比例）的整数部分
    // 黄金分割比例是无理数，直接拿浮点数乘会在大数上判错
    // 把 mn ≤ kφ < mn+1 两边乘 2 再平方，就换成下面这三项整数比较
    int wythoffGame(int a, int b) {
        long long mn = min(a, b);
        long long mx = max(a, b);
        long long k = mx - mn;
        long long left = (2 * mn - k) * (2 * mn - k);
        long long mid = 5 * k * k;
        long long right = (2 * (mn + 1) - k) * (2 * (mn + 1) - k);
        return (left <= mid && mid < right) ? 0 : 1;
    }

这个写法扫过 0 到 40 的整个网格、再扫过 20029 个必败点（含两堆大小到 1.6×109 的），一处都没错。106 次查询 5.33ms，只有几次整数乘法。

四、对数器怎么抓错

两题的暴力都不算好写。斐波那契博弈的状态要带上「上一轮取了多少」，递归时枚举这一轮的取法；威佐夫博弈老老实实枚举三种走法递归下去，网格小一点就够用。这对拍跑通了，才敢相信那两个结论。

斐波那契博弈拿 n 从 1 到 3000 逐个数和暴力比；威佐夫博弈的小网格是 0 到 300，大数那两行是前面那 20029 个必败点。

威佐夫那两行值得单独说。「φ 只保留到 1.618」在小网格上一次都不错，因为差值 k 最大也就 300，误差还翻不出整数边界；换成大数就一片一片地错，6807 个必败点里错了三分之一。精度不够的错误只在数大的时候露出来，这正是这类题最难缠的地方。

题目关键操作时间空间

总结

斐波那契博弈的答案是 n 的 Zeckendorf 拆分里最小的那一项。能这么定，是因为不相邻的两个斐波那契数之间比值大于 2，而「最多取上一轮两倍」的上限恰好卡在同一个地方，先手取走最小项之后对手永远够不到下一块。

威佐夫博弈的必败点是 (⌊k·φ⌋, ⌊k·φ⌋ + k)，判定写成「较小的一堆等于差值乘 φ 的整数部分」。这个结论落地要用高精度，或者把不等式两边乘 2 再平方换成整数比较，后者在大数上一个都不会错。

两题的结论都很难当场推出来，但都能靠打表看出形状：一题看答案序列和斐波那契数列的对齐方式，一题看必败点的两列坐标。这正是博弈题的常规打法，下一讲把这条路走成通用的：SG 函数和 SG 定理，把找不到规律的博弈也变成可以机械计算的东西。
