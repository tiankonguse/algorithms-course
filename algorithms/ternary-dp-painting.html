三进制状压：三色涂色与合法状态

三色涂色的列数只有 5、行数却到 1000，是状压 dp 最舒服的形状。跟上题相比多出来两件事：先把第一行的合法状态筛一遍，只在合法状态上起步；以及行首那个「没有左邻居」要写成 −1，写成 0 会把红色这一整列的选择都吃掉。

零、背景

状态还是 m 位三进制，每位 0、1、2 对应三种颜色。走到 (i, j) 时，第 j 位是上方格子的颜色，第 j−1 位是左方格子的颜色，选一种跟它俩都不同的涂上去，把第 j 位改掉。

多出来的第一件事是「从哪些状态起步」。全 3m 个状态里，有一大批自己就不合法：左右相邻两格同色。m = 5 时 243 个状态里只有 48 个能用，占 19.8%。先把它们挑出来，后面的转移就不用再为废状态留位置了。

一、问题

用三种不同颜色为网格涂色。m × n 的网格，每格先涂成白，要用红、绿、蓝三色给每个格子上色，相邻格子的颜色必须不同。返回涂色方法数，答案对 1000000007 取模。m 不超过 5，n 不超过 1000。

二、先把第一行筛出来

枚举的方式就是一趟 dfs：第 j 格看左邻选了什么，避开它就行。第 0 格没有左邻，取 −1 表示「谁都能选」。

// 枚举第一行的所有合法状态，存进 first 数组
        // j 是当前列，s 是已经拼好的部分状态，bit = 3 的 j 次方
        void dfs(int j, int s, int bit) {
            if (j == m) {
                first[size++] = s;
            } else {
                int left = j == 0 ? -1 : get(s, bit / 3);
                if (left != 0) dfs(j + 1, set(s, bit, 0), bit * 3);
                if (left != 1) dfs(j + 1, set(s, bit, 1), bit * 3);
                if (left != 2) dfs(j + 1, set(s, bit, 2), bit * 3);
            }
        }

枚举出来的状态数很好算：第 0 格 3 种，之后每格 2 种，一共 3 × 2m−1 个。本机量了一遍：

m 每加 1，合法状态翻一倍、全部状态翻三倍，能被筛掉的比例就越来越大。这也是三进制编码在这题上省力的地方：如果每格给两个 bit，光第一行就要从 4m 里筛。

三、逐格转移，以及那个 −1

第一行由 dfs 负责，主过程从第 1 行第 0 列开始。此时第 j 位装的是货真价实的上方颜色，第 j−1 位是左方颜色。

const int MOD = 1000000007;
        int dp[MAXN][MAXM][MAXS];
        int n, m;

        // 当前来到 i 行 j 列，s 是轮廓线状态，bit = 3 的 j 次方
        // 返回把 (i, j) 及其之后全部涂完的方法数
        int f(int i, int j, int s, int bit) {
            if (i == n) return 1;
            if (j == m) return f(i + 1, 0, s, 1);
            if (dp[i][j][s] != -1) return dp[i][j][s];
            int up = get(s, bit);                       // 上方格子的颜色
            int left = j == 0 ? -1 : get(s, bit / 3);   // 左方格子的颜色，-1 表示没有左邻居
            int ans = 0;
            if (up != 0 && left != 0) ans = (ans + f(i, j + 1, set(s, bit, 0), bit * 3)) % MOD;
            if (up != 1 && left != 1) ans = (ans + f(i, j + 1, set(s, bit, 1), bit * 3)) % MOD;
            if (up != 2 && left != 2) ans = (ans + f(i, j + 1, set(s, bit, 2), bit * 3)) % MOD;
            dp[i][j][s] = ans;
            return ans;
        }

        // 入口：第一行先挑一个合法状态，然后从第 1 行第 0 列开始推进
        int colorTheGrid(int rows, int cols) {
            n = max(rows, cols), m = min(rows, cols);
            size = 0;
            dfs(0, 0, 1);
            int ans = 0;
            for (int i = 0; i < size; i++) {
                ans = (ans + f(1, 0, first[i], 1)) % MOD;
            }
            return ans;
        }

两个边界值在这里分工不同，写混了就错：

1）up 不用判边界。第 0 行的上方是「没有」，但第 0 行压根不走 f，交给 dfs 处理了；

2）left 必须判边界，j = 0 时取 −1。

把 −1 写成 0 是什么后果？0 是红色，于是首列永远涂不了红，少算一大批方案。随机小数据上量了 1493 组，这么写能让 91.49% 的用例答案不对，抓取率高得反常，正说明它一上来就错。

四、n 到 1000 时

dp 表第一维跟着 n 走，n = 1000、m = 5 时是 1001 × 5 × 243 个 int，4.64 MB，本机跑完 8.834 毫秒。够用，但这一维是能省掉的。

省的办法跟上题的空间压缩一样：填 (i, j) 只用到 (i, j+1) 和下一行的开头，所以可以倒着填、只留一层。更进一步是把「一整行状态到下一行状态」的转移看成一个 243 × 243 的矩阵，n 很大时对矩阵做快速幂，代价从 O(n) 降到 O(log n)。这题 n 只有 1000，两种都不必要。

五、推进台

先挑一个第一行状态，再从第 1 行开始一格一格涂。下面的数字是当前位置之后还剩多少种涂法，每次选颜色它都会缩小，涂完最后一格正好是 1。

推进台：三色涂色的逐格推进

三个颜色按钮在跟上方或左方撞色时会变灰，变灰就说明这一格没得选。整个网格涂完之后，上面的数字会停在 1。

复杂度分析

时间 O(n × m × 3m × 3)。状态是 (行、列、轮廓线)，m = 5 时每列 243 个状态，每格试三种颜色各一次。n = 1000、m = 5 的上界是 1000 × 5 × 243 × 3 ≈ 3.6 × 10⁶ 次转移。

空间 O(n × m × 3m)，按题目上限 1001 × 5 × 243 个 int 算，4.64 MB。第一维滚掉之后是 O(m × 3m) = 1215 个 int，可以忽略。

总结

三色涂色把三进制状压的两件小事讲清楚了：起步状态要先用一趟 dfs 筛掉自身不合法的那些，m = 5 时 243 个里只剩 48 个；边界值不能拿真实取值顶替，行首没有左邻要写 −1 而不是 0，写成 0 会让 91.49% 的用例错掉。n 大 m 小时，dp 第一维跟着 n 走的 4.64 MB 可以滚掉，也可以换矩阵快速幂。再往后是同一套编码换个含义：位上装的是这个点还能去几次。
