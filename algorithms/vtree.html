虚树的原理与建树

一次查询只在树上挑了 k 个关键点，却要在整棵 n 个点的树上跑一遍树型 dp，代价是 O(n)。把关键点和它们两两的最低公共祖先抽出来，按 dfn 序排好连成边，就得到一棵只有 O(k) 个点的小树，叫做虚树。dp 搬上去，复杂度里就再也看不到 n。

零、背景

树上有一类查询长这样：每次给出 k 个关键点，问一个只和这 k 个点有关的树形问题。k 很小，但查询次数很多，所有查询给出的关键点总数加在一起也不算大。

直接做的话，一次查询就是一次整树 dfs。n = 10⁵、q = 10⁵ 的时候这个数是 10¹⁰，怎么算都过不去。可真正决定答案的只有那 k 个点，剩下 n - k 个点只是把关键点串起来的「路」。

虚树就是把这些「路」压成一条边：只留下关键点和必要的分叉点，原树上一整条路径在虚树里变成一条边。前置知识是树的 dfn 序、树上倍增求 LCA、树型 dp 和单调栈，这几样前面都单独讲过。

一、问题

输入一棵 n 个点的树，以及 q 条查询。每条查询给出 k 个互不相同的点，称作关键点；其余点称作非关键点。要在这 k 个点上回答一个树形问题，比如「最少切断几条边能让关键点两两不连通」「k 个点两两之间新建通道的代价和」。

数据范围的形状是这一类题的共同特征：n 和 q 都能到 10⁵，但所有查询给出的关键点总数有一个同样量级的上界。也就是说，k 的均值很小，只是查询条数多。

这一讲先解决结构问题：怎么从原树里快速取出一棵只含 O(k) 个点、又能完整表达关键点之间拓扑关系的小树。

二、朴素做法为什么慢

最直接的写法是每条查询在整棵树上重新做一次树型 dp。一次 O(n)，q 条就是 O(nq)。以题 1 为例 n、q 都能到 10⁵，光是这一个乘积就是 10¹⁰。

可以发现，两次查询之间整棵树没有任何变化，非关键点上的 dp 值也是一样的。每次都重算一遍整棵树，等于把完全相同的 O(n) 份无用功重复 q 次。

反过来看一次查询真正需要的：关键点彼此怎么连通、在哪个点分叉、分叉之间隔了多少条边。这三件事只跟关键点和它们的 LCA 有关，和其余 n - k 个点无关。把它们单独抽出来，规模立刻从 n 掉到 k。

三、虚树的定义

给定关键点集合 S，虚树的点集是 S 并上「dfn 序上相邻两个关键点的 LCA」，边则是在按 dfn 排序、去重之后，让每个点和它前一个点取 LCA 连过来。

为什么只要相邻对的 LCA？考虑 dfn 序上第 i 个和第 j 个关键点，i < j，设 L = lca(aᵢ, aⱼ)。aᵢ 落在 L 的某一棵子树里，aⱼ 落在 L 的另一棵子树里（或者某个就是 L 本身）。从 i 走到 j，一定存在第一个「离开 aᵢ 所在子树」的位置 t，那么 aₜ 还在那棵子树、aₜ₊₁ 已经不在，两点的 LCA 恰好就是 L。任意两点的 LCA 都落在相邻对的 LCA 集合里，所以只取相邻对就够了。

四、准备：dfn 序与倍增 LCA

建虚树之前，原树要先做一次 dfs，拿到每个点的深度 dep、dfn 序以及倍增表 stjump。之后每次查询都要按 dfn 排序、并且频繁求 LCA，这两件事都靠这一份预处理。

注意排序的比较函数比较的是 dfn 而不是点的编号，这是虚树里所有「相邻」的含义所在。

bool cmp(int x, int y) {
        return dfn[x] < dfn[y];
    }

    void addEdgeG(int u, int v) {
        nextg[++cntg] = headg[u];
        tog[cntg] = v;
        headg[u] = cntg;
    }

    void addEdgeV(int u, int v) {
        nextv[++cntv] = headv[u];
        tov[cntv] = v;
        headv[u] = cntv;
    }

    void dfs(int u, int fa) {
        dep[u] = dep[fa] + 1;
        dfn[u] = ++cntd;
        stjump[u][0] = fa;
        for (int p = 1; p < MAXP; p++) {
            stjump[u][p] = stjump[stjump[u][p - 1]][p - 1];
        }
        for (int e = headg[u]; e; e = nextg[e]) {
            if (tog[e] != fa) {
                dfs(tog[e], u);
            }
        }
    }

    int getLca(int a, int b) {
        if (dep[a] < dep[b]) {
            swap(a, b);
        }
        for (int p = MAXP - 1; p >= 0; p--) {
            if (dep[stjump[a][p]] >= dep[b]) a = stjump[a][p];
        }
        if (a == b) {
            return a;
        }
        for (int p = MAXP - 1; p >= 0; p--) {
            if (stjump[a][p] != stjump[b][p]) {
                a = stjump[a][p];
                b = stjump[b][p];
            }
        }
        return stjump[a][0];
    }

五、建树方式一：二次排序 + LCA 连边

四步走完就得到虚树：先把关键点按 dfn 排序；再把每个点和它后一个点的 LCA 一起塞进数组；然后整个数组按 dfn 再排一次并去重；最后让排序后的相邻两点 xᵢ、xᵢ₊₁ 连一条 lca(xᵢ, xᵢ₊₁) 指向 xᵢ₊₁ 的边。

去重那一步不能省：LCA 可能和某个关键点重合，也可能几个相邻对算出同一个 LCA。排完序之后相同的编号一定挨在一起，扫一遍留下第一次出现的即可。

排序后的第一个点就是虚树的头。这里有个细节：它不一定是原树的头，只是 dfn 最小的那个关键点；需要原树头参与计算时，要手动把它塞进关键点数组，题 3 和题 4 就是这么做的。

int buildVirtualTree1() {
        sort(arr + 1, arr + k + 1, cmp);
        int len = 0;
        for (int i = 1; i < k; i++) {
            tmp[++len] = arr[i];
            tmp[++len] = getLca(arr[i], arr[i + 1]);
        }
        tmp[++len] = arr[k];
        sort(tmp + 1, tmp + len + 1, cmp);
        int unique = 1;
        for (int i = 2; i <= len; i++) {
            if (tmp[unique] != tmp[i]) {
                tmp[++unique] = tmp[i];
            }
        }
        cntv = 0;
        for (int i = 1; i <= unique; i++) {
            headv[tmp[i]] = 0;
        }
        for (int i = 1; i < unique; i++) {
            addEdgeV(getLca(tmp[i], tmp[i + 1]), tmp[i + 1]);
        }
        return tmp[1];
    }

六、建树方式二：单调栈

第二种做法只排一次序，用栈维护「从当前虚树头走到上一个处理完的点」这一条链。栈里的点按深度递增，栈底最深（dfn 最小）。

每来一个新点 x，先求 lca = lca(x, 栈顶)。只要栈顶下面那个点的 dfn 不小于 lca 的 dfn，说明栈顶这条分支已经走完了，把它和它下面那个点连起来并弹出。弹完之后：如果 lca 不等于栈顶，说明 lca 是个新分叉点，把它和栈顶连起来、用它替换栈顶；最后把 x 压进去。所有点处理完，把栈里剩下的相邻对依次连边。

两种做法建出的虚树完全一样。一般用第一种，理由是流程好记：排序、插 LCA、排序去重、连边，四步不会记错。

int buildVirtualTree2() {
        sort(arr + 1, arr + k + 1, cmp);
        cntv = 0;
        headv[arr[1]] = 0;
        int top = 0;
        stk[++top] = arr[1];
        for (int i = 2; i <= k; i++) {
            int x = arr[i];
            int y = stk[top];
            int lca = getLca(x, y);
            while (top > 1 && dfn[stk[top - 1]] >= dfn[lca]) {
                addEdgeV(stk[top - 1], stk[top]);
                top--;
            }
            if (lca != stk[top]) {
                headv[lca] = 0;
                addEdgeV(lca, stk[top]);
                stk[top] = lca;
            }
            headv[x] = 0;
            stk[++top] = x;
        }
        while (top > 1) {
            addEdgeV(stk[top - 1], stk[top]);
            top--;
        }
        return stk[1];
    }

七、虚树为什么够用

点数是 O(k)：k 个关键点最多补进 k - 1 个 LCA，虚树点数不超过 2k - 1，边数比点数少 1。这和原树多大没有关系。

边的含义要记牢：虚树里一条边 (u, v) 代表原树上 u 到 v 的一条路径，这条路径中间不再有任何虚树上的点。所以边权可以是路径长度、路径上的最小边权、路径边权之和，取决于题目要什么。

还有两处可以按需要调整的开关。一是虚树的头不一定是原树的头，题目要明确以 1 号点为根时（比如「让所有关键点都到不了 1」），就把 1 号点额外塞进关键点数组。二是一般只连「上到下」的单向边，只有需要从下往上传递信息时才连双向，题 5 就是这种情况。

八、复杂度分析

设一次查询给出 k 个关键点，所有查询的 k 之和是 K，原树 n 个点。预处理只做一次，之后每条查询的代价只和 k 有关。

步骤时间复杂度空间复杂度
预处理 dfs：dep、dfn、倍增表O(n log n)O(n log n)
关键点按 dfn 排序O(k log k)O(k)
相邻对求 LCA（k - 1 次）O(k log n)O(1)
二次排序 + 去重O(k log k)O(k)
相邻点连边O(k)O(k)
虚树上跑树型 dpO(k)O(k)
单次查询合计O(k log k + k log n)O(k)
全部 q 条查询O(K log K + K log n)O(K)

口径按 O(k log n) 记，把排序那一项并进去了：k 的量级和 n 同阶时两者差不了多少。单调栈建树只排一次序，省掉的是二次排序的 O(k log k)，LCA 那部分一样。

和不建虚树的 O(nq) 比，差别就在 n 换成了 k。所有查询的关键点总数 K 有上界，这一条是虚树能用起来的前提。

九、最后

虚树的整套动作就三件：按 dfn 序把关键点排开，补进相邻对的 LCA，按相邻关系连边。得到的是一棵 O(k) 个点的小树，原树上一整段路径在这里只是一条带权边。
