打砖块：把时间倒过来感染

每次敲掉一块砖，够不着顶部的砖就会掉。正向模拟每敲一次就要把全网格重新算一遍连通性。反过来做，先把要敲的全敲掉，再一块块补回来，总代价就和网格大小同阶。

零、问题

网格里 1 是砖、0 是空。一块砖稳定，当且仅当它直接在第 0 行，或者它上下左右有一块稳定的砖。依次敲掉 hits 里的位置（那个位置可能本来就是空的），每次敲完会有一些砖失去支撑、立刻消失，问每次掉了几块（被敲掉的那块不算）。

顺着做很自然：敲一块，从顶部 BFS 一遍找出所有还稳的砖，剩下的删掉。k 次敲击就是 k 遍全网格。200×200 的网格敲一万次，实测 2596.87ms，直接超时。

关键一步是意识到「删掉」不好做，「补回来」好做。先把所有要敲的位置一次性处理掉，得到最终状态；再从最后一次敲击倒着往前，把砖一块块补回去。补回去时新增的、够得着顶部的砖，正是那一次敲击会带下来的砖。

一、三种值：没有砖、有砖待定、已经连到顶

网格里的值被赋予了三种含义：0 和负数表示这里没有砖，1 表示有砖但还不知道稳不稳，2 表示已经确认连到顶部。

处理敲击用的是减一而不是置零，因为同一个位置可能本来就是空的：原本是 1 减完变 0，原本是 0 减完变 -1。补回来时统一加一，1 能变回 1、-1 变回 0，worth 判据自然就把「敲了个空位置」这种情况挡掉了。

最开始从第 0 行的每一格出发感染一遍，把所有还连着顶部的砖改成 2。这时候的 1 全是悬空的砖，它们在正向过程里早就掉光了。

int n, m;
    vector<vector<int>> grid;

    // 从 (i,j) 出发，遇到 1 就感染成 2，返回这次新感染了几块
    int dfs(int i, int j) {
        if (i < 0 || i == n || j < 0 || j == m || grid[i][j] != 1) {
            return 0;
        }
        grid[i][j] = 2;
        return 1 + dfs(i + 1, j) + dfs(i, j + 1) + dfs(i - 1, j) + dfs(i, j - 1);
    }

    // 补回来的这块砖够得着顶部吗：自己在第 0 行，或者四邻已经是 2
    bool worth(int i, int j) {
        return grid[i][j] == 1
            && (i == 0
                || (i > 0 && grid[i - 1][j] == 2)
                || (i < n - 1 && grid[i + 1][j] == 2)
                || (j > 0 && grid[i][j - 1] == 2)
                || (j < m - 1 && grid[i][j + 1] == 2));
    }

二、worth：这块砖补回来够得着顶部吗

补回来的砖只有两种稳法：它自己在第 0 行，或者它上下左右有一块已经是 2。四邻都是 0 或者 1 的话，这块砖连同它接出去的一串都还是悬空的，敲掉它什么也不会掉。

判据成立才值得感染，于是有了 worth 这个名字。不成立就不管，这一格保持 1，等以后它旁边出现 2 时再说。

感染返回的是这次新改成的 2 的个数，减掉补回来的这块自己，就是答案。被敲掉的那块题目明说不计数，这个减一是必须的。

vector<int> hitBricks(vector<vector<int>>& g, vector<vector<int>>& hits) {
        grid = g;
        n = grid.size();
        m = grid[0].size();
        vector<int> ans(hits.size(), 0);
        if (n == 1) return ans;   // 只有一行时每块砖都吊在天花板上，答案恒为 0
        // 先把要敲的都敲掉，再倒着一块块补回来
        for (auto& hit : hits) grid[hit[0]][hit[1]]--;
        for (int i = 0; i < m; i++) dfs(0, i);
        for (int i = (int)hits.size() - 1, row, col; i >= 0; i--) {
            row = hits[i][0];
            col = hits[i][1];
            grid[row][col]++;
            if (worth(row, col)) ans[i] = dfs(row, col) - 1;
        }
        return ans;
    }

三、三个容易写错的地方

第一个是省掉 worth 判据，只要补回来是 1 就感染。这样会把悬空的砖也当成稳定的，随机测试里 14.82% 的样本答案偏大。

第二个是忘了减一，把被敲的那块也算进掉落数，随机测试里 69.46% 的样本会错。这个是错得最多的一处，因为它只在有砖掉落时才现形，而大多数敲击什么都没掉。

第三个是开头的单行特判。只有一行时每块砖都吊在天花板上，敲掉任何一块都不会带掉别的，答案恒为全 0。这一句省的是时间：实测去掉它，2000 组单行样本的答案依然全对：补回来的砖四邻要么是 2 要么是空，感染只能扩散到自己，减一之后正好是 0。

演示：先全敲掉，再倒着一块块补回来

四、正向模拟长什么样

为了对照，把顺向做法也写一遍：敲掉一块，从顶部 BFS 找出所有稳定的砖，其余的全部删掉并计数。它和反向做法的答案完全一致，实测 200×200 网格、一万次敲击两边逐项相同，只是慢了三个数量级。

演示：正向模拟，每敲一次重算一遍稳定集合

五、复杂度分析

指标值
时间复杂度O(n×m + k)，网格 n×m、敲击 k 次
额外空间O(n×m)（递归栈，最坏等于砖块总数）
正向模拟O(k×n×m)，200×200 敲一万次实测 2596.87ms

反向做法的总感染量有硬上界：每块砖最多被从 1 改成 2 一次，之后就再也不会进入感染函数。所以全部敲击加起来，感染函数的总执行次数不超过格子数。200×200 满砖、四万次敲击实测 0.79ms，掉落的砖一共 23241 块。

六、总结

倒着做是这题的全部：一次性敲掉所有目标，从顶部感染出「还稳着的」2，再逆序补砖，补的时候新增的 2 就是那一次会掉下来的砖。

三个细节决定对错。用减一而不是置零，好让「敲在空位置上」自己变成 -1 被 worth 挡掉；worth 判据不能省，省了会有近一成半的样本把悬空砖算成稳定的；感染完一定要减一，被敲的那块不计入掉落。

「删操作不好做就反过来做补操作」这个转换不止用在砖块上，凡是一次次删除、每次都要重新算全局连通性的题，都可以先想想倒过来是不是更好写。
