历史最值：给每个格子记一本「到过的最高点」

两个数组 A 和 B 一开始完全一样，每做完一次操作就把 B[i] 更新成 max(B[i], A[i])。于是 B 里存的是每个格子到过的最大值，A 一路涨跌，B 只涨不跌。麻烦在于 A 是懒更新的，任务挂在结点上不往下走，B 就看不到那一段经历过什么。解法是给懒标记再配一个「这一路到过多高」。

零、背景

先想一个朴素做法：拿一个数组 B，每次操作之后扫一遍把 B 更新掉，再对 B 建一棵线段树查最大值。一次操作 O(n)，m 次操作 O(nm)，n 和 m 都是 5×10⁵ 的时候是 2.5×10¹¹，跑不完。

再想一步：B 的更新其实也能懒更新。一段里所有格子都加了 v，那么这段的 B 最大值也跟着抬高 v，一个标记就够了。问题出在「取 min」上：一段里只有最大值那一批掉下去，B 不动（B 只涨不跌），其他格子也不动，于是 B 的标记得区分「最大值的历史」和「其他数字的历史」。

所以每个结点除了累加和、最大值、最大值个数、严格次大值，还要再配三个历史量：这一段上 B 的历史最大值 maxHistory，以及两路增量各自到过的最高点 maxAddTop 和 otherAddTop。

一、题目

两个长度都是 n 的数组 A 和 B，一开始完全一样。任何操作做完都更新 B，B[i] = max(B[i], A[i])。一共调用 m 次操作：

  • 操作 1 l r v：A 在 l 到 r 上每个数加 v
  • 操作 2 l r v：A 在 l 到 r 上每个数变成 min(A[i], v)
  • 操作 3 l r：返回 A 在 l 到 r 上的累加和
  • 操作 4 l r：返回 A 在 l 到 r 上的最大值
  • 操作 5 l r：返回 B 在 l 到 r 上的最大值

其中 n 和 m 都不超过 5×10⁵。

二、六个量怎么分工

「现在」这一组是四个数加两条通道：累加和、最大值、最大值个数、严格次大值，外加 maxAdd 和 otherAdd 两条增量通道。

「历史」这一组是新增的三个。maxHistory 就是这一段上 B 的最大值，up 的时候两个孩子取 max 合并。另外两个是标记的峰值：maxAddTop 记 maxAdd 这一路到目前为止到过的最大值，otherAddTop 同理。

void up(int i) {
        int l = i << 1, r = i << 1 | 1;
        maxHistory[i] = max(maxHistory[l], maxHistory[r]);   // 历史最大照样可以取 max 合并
        sum[i] = sum[l] + sum[r];
        mx[i] = max(mx[l], mx[r]);
        if (mx[l] > mx[r]) {
            cnt[i] = cnt[l];
            sem[i] = max(sem[l], mx[r]);
        } else if (mx[l] < mx[r]) {
            cnt[i] = cnt[r];
            sem[i] = max(mx[l], sem[r]);
        } else {
            cnt[i] = cnt[l] + cnt[r];
            sem[i] = max(sem[l], sem[r]);
        }
    }

    void build(int l, int r, int i) {
        if (l == r) {
            sum[i] = mx[i] = maxHistory[i] = arr[l];   // 一开始 B 和 A 完全一样
            sem[i] = LOWEST;
            cnt[i] = 1;
        } else {
            int mid = (l + r) >> 1;
            build(l, mid, i << 1);
            build(mid + 1, r, i << 1 | 1);
            up(i);
        }
        maxAdd[i] = otherAdd[i] = maxAddTop[i] = otherAddTop[i] = 0;
    }

为什么非得记标记的峰值？看一次「加 3 再加 −6」。整段加 3 时，这段的最大值是 5，加上 3 到过 8；再加 −6 之后当前只剩 2。如果只记当前增量 −3，那么这段的子孙在被下发时只会拿到 −3，历史峰值 8 就丢了。maxAddTop 记的是 3（那一路到过的最高点），下发时它才知道这一段有格子到过 8。

三、一次 lazy 里的六件事

long long maxHistory[MAXN << 2];   // 这一段里 B 的最大值
    long long maxAdd[MAXN << 2];       // 最大值累计加了多少
    long long otherAdd[MAXN << 2];     // 其他数字累计加了多少
    long long maxAddTop[MAXN << 2];    // 历史上 maxAdd 到过的最大值
    long long otherAddTop[MAXN << 2];  // 历史上 otherAdd 到过的最大值

    // 前四个数是「现在」，后两个带 Top 的是「历史以来的峰值」
    void lazy(int i, int n, long long maxAddv, long long otherAddv,
              long long maxUpv, long long otherUpv) {
        maxHistory[i] = max(maxHistory[i], mx[i] + maxUpv);
        maxAddTop[i] = max(maxAddTop[i], maxAdd[i] + maxUpv);
        otherAddTop[i] = max(otherAddTop[i], otherAdd[i] + otherUpv);
        sum[i] += maxAddv * cnt[i] + otherAddv * (n - cnt[i]);
        mx[i] += maxAddv;
        sem[i] += sem[i] == LOWEST ? 0 : otherAddv;
        maxAdd[i] += maxAddv;
        otherAdd[i] += otherAddv;
    }

    void down(int i, int ln, int rn) {
        int l = i << 1, r = i << 1 | 1;
        long long tmp = max(mx[l], mx[r]);
        if (mx[l] == tmp) lazy(l, ln, maxAdd[i], otherAdd[i], maxAddTop[i], otherAddTop[i]);
        else              lazy(l, ln, otherAdd[i], otherAdd[i], otherAddTop[i], otherAddTop[i]);
        if (mx[r] == tmp) lazy(r, rn, maxAdd[i], otherAdd[i], maxAddTop[i], otherAddTop[i]);
        else              lazy(r, rn, otherAdd[i], otherAdd[i], otherAddTop[i], otherAddTop[i]);
        maxAdd[i] = otherAdd[i] = maxAddTop[i] = otherAddTop[i] = 0;
    }

前三个是历史，后四个是现在。注意 maxHistory[i] 那句用的是「当前最大值加上这一次的抬升」，而不是加上累积增量：整段加 3 之后再加 3，历史峰值应该是「原值加 3」和「原值加 6」里更大的那个，maxAddTop 保证第二趟拿到的是 6 而不是 6 减 3。

两个 Top 用 max 累加，不用加法。因为历史峰值是「到过多少」，不是「一共加了多少」：加 3 之后减 1，这一路的峰值是 3，不是 2。

void add(int jobl, int jobr, long long jobv, int l, int r, int i) {
        if (jobl <= l && r <= jobr) {
            // 现在加 jobv，历史峰值也跟着往上抬 jobv
            lazy(i, r - l + 1, jobv, jobv, jobv, jobv);
        } else {
            int mid = (l + r) >> 1;
            down(i, mid - l + 1, r - mid);
            if (jobl <= mid) add(jobl, jobr, jobv, l, mid, i << 1);
            if (jobr > mid) add(jobl, jobr, jobv, mid + 1, r, i << 1 | 1);
            up(i);
        }
    }

    void setMin(int jobl, int jobr, long long jobv, int l, int r, int i) {
        if (jobv >= mx[i]) {
            return;
        }
        if (jobl <= l && r <= jobr && sem[i] < jobv) {
            // 最大值往下掉，历史峰值不动（其他数字本来就有 otherUpv = 0）
            lazy(i, r - l + 1, jobv - mx[i], 0, jobv - mx[i], 0);
        } else {
            int mid = (l + r) >> 1;
            down(i, mid - l + 1, r - mid);
            if (jobl <= mid) setMin(jobl, jobr, jobv, l, mid, i << 1);
            if (jobr > mid) setMin(jobl, jobr, jobv, mid + 1, r, i << 1 | 1);
            up(i);
        }
    }

取 min 命中时传的是 (jobv - mx[i], 0, jobv - mx[i], 0)：最大值那一路往下掉，其他数字一动不动，历史方面只有「最大值现在掉到了 jobv」这件事需要记，而它比之前到过的要低，max 一下毫无影响。

区间加传的是 (jobv, jobv, jobv, jobv)：现在抬 jobv，历史峰值也跟着抬 jobv，两批数字都一样。

四、走一遍看得更清楚

拿 A 等于 [1, 5, 3, 5, 2, 4] 举例，B 一开始和它一样：

  • add(2, 5, 3)：A 变成 1、8、6、8、5、4，B 同步成 1、8、6、8、5、4，A 的最大值和 B 的最大值都是 8，累加和 32
  • add(2, 5, -6)：A 变成 1、2、0、2、-1、4，A 的最大值掉到 4，B 还记着 8，累加和 8
  • setMin(1, 6, 2)：A 变成 1、2、0、2、-1、2，A 的最大值 2，B 的最大值还是 8，累加和 6
  • add(3, 4, 10)：A 变成 1、2、10、12、-1、2，这一轮把位置 3、4 抬过 8，B 的最大值变成 12，累加和 26

第 4 步最能说明 maxAddTop 的用处：位置 4 在前面两趟里经历过「加 3 到 8、再减 6 到 2」，这两趟的标记都还挂在祖先结点上没下去。等它这一趟被访问时，祖先把 maxAddTop 等于 3 一起交下来，它的历史峰值才知道是 8 而不是 2。

所以 down 里两个孩子拿到的参数不一样：最大值等于父亲最大值的那个孩子，走「最大值通道」；另一个走「其他数字通道」。两条通道各带两个值，一共四个，全都要交下去。

五、复杂度分析

项代价
建树O(n)
区间加O(log n)
区间取 minO(log n) 均摊
三种查询O(log n)
空间O(n)：八个四倍数组

按 n 等于 5×10⁵ 算：七个 long long 数组加一个 int 数组，每个长度都是四倍，一共约 114.4 MiB。这是这一族写法里最费空间的一套，八个数组一个都不能省。

实测（g++ -O2，同一份操作跑 5 遍取最好）：n 和 m 都是 5×10⁵ 时 287.936 ms；n 是 5×10⁵、m 是 2×10⁵ 时 124.765 ms。对照的朴素做法是每次操作之后扫一遍更新 B，那要 O(nm)，这个规模下完全跑不动。

时间复杂度和把三个历史量删掉之后一样，多出来的只是常数：每个结点的 lazy 从四个参数变成六个，up 多一句取 max。

六、几种写错的样子

同样每组 3000 个小样本、每个样本最多 60 步，值域分三档：

  • lazy 里不更新 maxHistory：86.67% / 90.77% / 89.70%
  • up 里不算 maxHistory：94.67% / 95.93% / 95.47%
  • maxAddTop 写成 max(maxAddTop[i], maxUpv)，把累积的 maxAdd 丢了：46.60% / 54.80% / 55.90%。这一条是三组里唯一「一半才抓得到」的，因为它只在连续两趟增量方向不同时才现形。
  • 取 min 时把历史那一路的 otherUpv 也传成 jobv - mx[i]：三档都是 0.00%，是真等价。otherAddTop 恒不小于 otherAdd，而取 min 传进来的是个负数，加上去只会更小，max 一下不会改变它。

七、总结

历史最值要求「只涨不跌」的那个数组也能懒更新，于是每个结点除了当前状态还要记三个历史量。关键在 lazy：抬升要同时抬三个历史量，压低对历史毫无影响（B 只涨不跌），两个 Top 用 max 累加而不是加法。

这套结构的核心难点是「标记的峰值」这个概念：maxAdd 是现在欠了多少，maxAddTop 是这一路欠到过多少。下发的时候两个都要交下去，只交前者会丢掉中途的峰值。

最后

一是 lazy 里那三句历史更新必须在改 mx[i] 之前写，顺序反了 mx[i] + maxUpv 就用的是改过之后的值。

二是 down 收尾要把四个标记一起清零，漏掉两个 Top 会让同一次抬升被反复计入历史。

三是取 min 那一路的历史参数是 (jobv - mx[i], 0, jobv - mx[i], 0)，第四位必须是 0，其他数字这一趟没有动过。
