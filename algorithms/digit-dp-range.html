数位 dp：区间与数位和

「统计整数数目」里有两类约束同时出现：下界和上界框出一个区间，数位和又要落在某个范围内。区间那部分靠两次「不超过某个上界」的计数相减解决，数位和则变成状态里的第三个量。麻烦的地方在后面：这个状态必须成体系地挂缓存，否则 22 位数会展开成 10²² 条路径。

零、两个约束互相独立

题目给两个数字串 num1、num2（长度可以到 22）和两个整数 min_sum、max_sum，问有多少个 x 满足 num1 ≤ x ≤ num2 且数位和落在 [min_sum, max_sum]。

把这两件事分开看。区间是「x 落在哪一段」，跟数位本身无关；数位和是「边走边累加的量」，跟上下界无关。前者用减法，后者进状态。

一、区间拆成两个上界

记 F(m) 表示 0 到 m 之间、数位和落在区间内的个数。那么 [num1, num2] 里的答案就是 F(num2) − F(num1 − 1)。

但这里 num1 是长度 22 的数字串，做「减一」要处理一长串退位，代码很难看。换成 F(num2) − F(num1) + [num1 自己合法] 一样对：减掉的是「小于 num1」的那部分，把 num1 单独判断一次补回来就行。

这里有个细节：两次调用都把同一个缓存表用一遍是不行的。第一趟沿着 num2 建的是「贴着 num2」那一套状态，第二趟的上界换成了 num1，同一个 (i, sum, free) 代表的含义已经不同。所以每次换 num 都要把表清成 −1，代码里就是两次 build()。

// 数位和落在 [minSum, maxSum] 的整数个数，区间等于「上界以内的」减「下界以内的」
    int count(string num1, string num2, int minSum, int maxSum) {
        mn = minSum; mx = maxSum;
        s = num2; len = num2.size(); build();    // dp[i][sum][free] 全部清成 -1
        int ans = f(0, 0, 0);
        s = num1; len = num1.size(); build();    // 换成下界，缓存要重来
        ans = (ans - f(0, 0, 0) + MOD) % MOD;
        if (check(num1)) ans = (ans + 1) % MOD;  // 减掉的是「小于 num1」，num1 自己得补回来
        return ans;
    }

补 num1 自己那一句很容易漏。实测随机 2 万组里，漏掉它有 44.05% 会与正确解不一致，而且只在「num1 自己合法」时才对不上，所以样例里未必撞得到。

二、状态里多一个 sum

自由标记 free 还是老样子两态，多出来的量是「已经决定的那些位的数位和」。递归写成 f(i, sum, free)：从最高位走到第 i 位，前面决定的位和是 sum。

转移和上一题一样分两支。贴着上界时，这一位能填 0 到 cur：填小于 cur 的走 free = 1，填等于 cur 的继续贴着。已经自由时，0 到 9 随便填，而且每个选择都把 sum 加进下一层。

// 从最高位走到第 i 位，已决定的数位和是 sum；free == 1 表示前缀已经比 s 小
    int f(int i, int sum, int free) {
        if (sum > mx) return 0;                     // 上界剪枝：再加只会更大
        if (sum + (len - i) * 9 < mn) return 0;     // 下界剪枝：剩下全填 9 也够不到
        if (i == len) return 1;
        if (dp[i][sum][free] != -1) return dp[i][sum][free];
        int cur = s[i] - '0', ans = 0;
        if (free == 0) {
            for (int pick = 0; pick < cur; pick++) ans = (ans + f(i + 1, sum + pick, 1)) % MOD;
            ans = (ans + f(i + 1, sum + cur, 0)) % MOD;
        } else {
            for (int pick = 0; pick <= 9; pick++) ans = (ans + f(i + 1, sum + pick, 1)) % MOD;
        }
        return dp[i][sum][free] = ans;
    }

状态的规模很好数：i 有 len 种，sum 有 max_sum + 1 种，free 两种。len = 22、max_sum = 400 时上界是 22 × 401 × 2 = 17644 个。实际能走到的更少，实测只有 2102 个，因为很多 sum 根本到不了。

三、两条剪枝，下界那条不能省

函数开头有两行提前返回。第一行是 sum > max：数位和只会变大，超了上界整支可以扔掉。第二行是 sum + (len − i) × 9 < min：剩下的位全部填 9 都够不到下界，也可以扔掉。

第二条容易被当成「优化」顺手删掉，后果却比想象的大。原因是终点的返回写的是 if (i == len) return 1，它没有检查 sum 是否达到 min。下界完全靠这条剪枝在中间挡：能走到终点的路径，一定满足了 sum + 0 ≥ min。删掉以后所有「够不到下界」的状态都会被算成合法，实测 89.98% 的随机样本答案偏大。

第一行剪枝则是兜住上界的，因为终点也不检查 sum 是否超过 max。

写法与正确解不一致的比例为什么会错
漏掉 sum + 剩余位×9 < min 那条剪枝89.98%终点不检查下界，剪枝一撤，够不到 min 的状态全被算进来
贴着上界时，等于 cur 也走自由分支97.42%后面每一位都当成随便填，答案整片偏大
状态只记 (i, sum)，漏掉 free92.98%同一层里「贴着」和「已自由」的计数被混成一个
区间少补 num1 自己44.05%算成了 (num1, num2]

五、挂不挂缓存

不挂缓存的调用次数是 11111、111111、1109851……基本就是 10 的次幂，每多一位乘 10；挂上之后实填的状态数只从 58 爬到 259，每多一位多 41 个（正好等于 max_sum + 1）。

把规模推到题目上限：num2 取 22 个 9、max_sum = 400，实填 2102 个状态，0.048 ms 跑完。同一个输入不挂缓存要展开 10²² 条路径，这两者之间没有折中，必须挂。

六、复杂度分析

写法时间空间说明
不挂缓存O(10^len)O(len)每一层十个分支全展开，len = 22 时不可用
挂缓存O(len · max_sum · 10)O(len · max_sum)状态数是 len × (max_sum+1) × 2，每个状态摊十次转移
两次调用同上，常数乘 2同上上界换人时缓存要重建

注意这里的复杂度里没有 num2 的大小，只有它的位数。这是数位 dp 和一般 dp 最大的区别：状态数由「位数」和「过程量」决定，跟数值本身无关。

七、总结

区间的处理是两次上界以内的计数相减。下界做「减一」太麻烦，就减 F(num1) 再把 num1 单独判一次补回来，这一步漏了只会在 num1 自己合法时出错。

过程量（这里数位和）直接加进状态，代价是状态数乘上它的取值范围。位数乘过程量再乘 free 的两态，就是仓库的总容量。

剪枝和终点条件要配套读。sum > max 和 sum + 剩余位×9 < min 这两行是把上下界挡在中间的，终点那句 return 1 什么都没检查。它们属于正确性的一部分，不能当成可以省掉的优化。

最后是缓存。位数一多，「展开所有可能」和「填一张状态表」的差距是数量级级别的，这题里差 10²² 倍。
