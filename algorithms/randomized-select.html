随机选择算法

给一个无序数组，找第 K 大的元素。排序后取是 O(n log n)，但题目要求 O(n)。快排的 partition 把数组分成小于、等于、大于三段，等于段已经在最终位置上了。如果答案落在等于段里，直接返回；否则只需要去左边或右边一边找。每轮 partition 扔掉一半以上的元素，总代价就是 n + n/2 + n/4 + … = O(n)。这就是随机选择算法，LeetCode 215 的标准解法。

零、背景

先看一个反直觉的事实。找数组里的最大值，扫一遍就行，O(n)。找第二大呢？扫一遍也能搞定，维护两个变量。找第 K 大呢？K 大一点，比如 K=n/2（中位数），直觉上是不是得排个序？

排序确实能做，O(n log n)。但排序把所有元素的位置都确定了，而我们只关心一个位置的元素，第 K 大那个。多做了 n-K 个元素的定位工作，这些都是浪费。能不能只把答案那个位置的元素定下来，不管其他元素的顺序？

上一讲的快排 partition 正好提供了这个能力。选一个数 x，一轮 partition 之后，等于 x 的元素已经在它们最终排序后的位置上了。如果第 K 大的位置落在等于段里，答案就是 x；如果在左边，就只去左边找；右边同理。每轮只走一侧，这就是随机选择的核心。

一、问题定义

给定整数数组 nums 和整数 k，返回数组中第 k 个最大的元素。注意是排序后的第 k 大，不是第 k 个不同的元素。比如 [3,2,1,5,6,4]，k=2，答案是 5。

题目明确要求时间复杂度 O(n)。排序做法 O(n log n) 在 n=10⁶ 时约 43ms，随机选择约 7ms，差 6 倍。n 越大差距越明显。

二、朴素做法：排序后取

最直接的做法是排完序取第 n-k 个元素。代码三行，但代价是 O(n log n)。n=100 万时 std::sort 约 43ms，随机选择约 7ms。如果只查一次，这个差距可能无所谓；但如果这个操作嵌在更大的算法里被反复调用（比如分治、数据流中位数），O(n) 和 O(n log n) 的区别就大了。

还有一个思路是用堆。维护一个大小为 k 的小根堆，遍历数组，比堆顶大就替换。时间 O(n log k)，当 k 接近 n/2 时就是 O(n log n)，不比排序好。k 很小（比如 k=1 找最大值）时堆是 O(n)，但那已经退化成扫一遍了。

三、核心思想：partition 后只走一侧

快排的 partition 把 [l,r] 分成三段：[l, first-1] 全小于 x，[first, last] 全等于 x，[last+1, r] 全大于 x。等于段的元素已经在它们排序后的最终位置上了。first 到 last 这些下标，排序后的值就是 x。

我们要找的是排序后下标 idx 位置的值（第 k 大对应 idx = n-k）。三种情况：

1）idx < first：答案在左边，只递归 [l, first-1]。

2）idx > last：答案在右边，只递归 [last+1, r]。

3）first ≤ idx ≤ last：答案就是 x，直接返回。

和快排的区别就在这里：快排左右都要递归，选择只递归一侧。每轮 partition 处理的元素数是当前区间长度，下一轮至少扔掉等于段的元素。如果 x 选得好（接近中位数），每轮扔掉一半，总代价 n + n/2 + n/4 + … = 2n = O(n)。

四、荷兰国旗 partition

partition 用上一讲的荷兰国旗版本。三个指针 first、last、i：first 是小于区的末尾+1，last 是大于区的开头-1，i 是当前扫描位置。扫描规则三条：等于 x 时 i++；小于 x 时和 first 交换、first++ 和 i++；大于 x 时和 last 交换、last--（i 不动，因为换过来的元素还没看）。

first 和 last 是全局变量（或引用参数），partition 结束后等于段的边界就在这两个变量里。选择算法只走一侧，不需要像快排那样递归前用临时变量保存 first/last，因为下一轮只用到其中一个边界，另一个直接覆盖也没关系。

int first, last;

    void partition(vector<int>& arr, int l, int r, int x) {
        first = l;
        last = r;
        int i = l;
        while (i <= last) {
            if (arr[i] == x) {
                i++;
            } else if (arr[i] < x) {
                swap(arr[first++], arr[i++]);
            } else {
                swap(arr[i], arr[last--]);
            }
        }
    }

五、随机选择算法

主循环很简单：l 和 r 是当前区间，每次在 [l,r] 里随机选一个位置的值当 pivot，跑 partition，然后根据 idx 和 first/last 的关系缩小区间。落在等于段里就返回 arr[idx]。

随机选 pivot 这一步是必须的。固定选 arr[l] 或 arr[r]，遇到已排序数组会退化：每轮 pivot 是最小（或最大）值，等于段只有一个元素，区间只缩小 1，总代价 n + (n-1) + (n-2) + … = O(n²)。随机选之后，期望上每轮能扔掉相当比例的元素，复杂度收敛到 O(n)。

第 k 大转成下标 idx = n - k。比如 n=6、k=2，idx=4，排序后下标 4 的元素就是第 2 大（下标 0 是最大）。

int randomizedSelect(vector<int>& arr, int idx) {
        for (int l = 0, r = arr.size() - 1; l <= r; ) {
            int pivot = arr[l + rand() % (r - l + 1)];
            partition(arr, l, r, pivot);
            if (idx < first) {
                r = first - 1;
            } else if (idx > last) {
                l = last + 1;
            } else {
                return arr[idx];
            }
        }
        return -1;
    }

    int findKthLargest(vector<int>& nums, int k) {
        return randomizedSelect(nums, nums.size() - k);
    }

六、为什么期望 O(n)

定性理解：每轮 partition 处理 m 个元素，随机选的 pivot 有 50% 的概率落在中间 50% 的位置（即至少有 1/4 的元素比它小、至少有 1/4 的元素比它大）。这时下一轮区间长度最多是 3m/4。平均每两轮区间缩到 3/4，总代价 m + 3m/4 + (3m/4)² + … 是等比级数，和为 m / (1 - 3/4) = 4m = O(n)。

递归深度也是 O(log n) 的期望。实测 n=10 万时平均深度 21.5 层（log₂n≈16.6），2000 组里最大 38 层。对比固定 pivot 在已排序数组上的 n 层深度，随机化把深度从 O(n) 降到了 O(log n)，不会爆栈。

七、为什么必须随机

固定选 arr[l] 当 pivot，已排序数组上每轮等于段只有 1 个元素，区间缩小 1，总比较次数是 O(n²)。实测 n=10000 时固定 pivot 比较 167 万次，随机 pivot 只有 5.6 万次，差 30 倍。n=50000 时差 100 倍以上。

有人会说「我用三数取中（选 arr[l]、arr[mid]、arr[r] 的中位数）不就行了」。三数取中对已排序数组有效，但对手可以构造一种数组让三数取中每次都选到极端值：只要知道你选哪三个位置，就能在那三个位置上放极端值。随机选就没有这个弱点：对手不知道你会选哪个位置。

当然，随机也有极小概率连续选到极端值，导致某一轮区间几乎没缩小。但概率是指数级衰减的：连续 20 轮都选到最差的 10% 位置，概率是 0.1²⁰，比宇宙中微子正好穿过你电脑的概率还低。工程上完全可以忽略。

八、BFPRT：不随机也能 O(n)

随机选择的 O(n) 是期望复杂度，最坏情况仍然是 O(n²)（虽然概率极低）。有没有确定性的 O(n) 选择算法？有，BFPRT 算法（由 Blum、Floyd、Pratt、Rivest、Tarjan 五位大牛提出）。

核心思路：不用随机选 pivot，而是用一个确定性的方法选一个「保证不太差」的 pivot。把数组每 5 个分成一组，每组取中位数，再递归地取这些中位数的中位数当 pivot。可以证明这个 pivot 至少比 30% 的元素大、至少比 30% 的元素小，所以每轮至少扔掉 30% 的元素，递归式 T(n) = T(n/5) + T(7n/10) + O(n)，解出来是 O(n)。

但 BFPRT 常数很大（分组、排序每组、递归找中位数的中位数），工程上几乎没人用。随机选择实现简单、常数小、实际表现好，是面试和比赛的标准写法。BFPRT 更多是理论意义上的「确定性 O(n) 存在性证明」。

空间复杂度 O(1)：迭代写法只用几个指针变量，partition 是原地交换，没有额外数组。递归写法的话栈深度期望 O(log n)、最坏 O(n)，所以迭代版更安全。

总结

随机选择算法的要点：

1）核心是快排的 partition + 只走一侧。等于段已经在最终位置，答案落在等于段就直接返回，否则只去左边或右边。

2）每轮至少扔掉等于段的元素，随机 pivot 期望上每轮扔掉约一半，总代价 n + n/2 + n/4 + … = O(n)。实测约 5.7n 次比较。

3）必须随机选 pivot。固定选位置在已排序数组上退化成 O(n²)，三数取中可以被构造数据针对，随机选没有这个弱点。

4）迭代写法空间 O(1)，递归深度期望 O(log n) 不会爆栈。

5）BFPRT 是确定性 O(n)，但常数大、实现复杂，工程上用随机选择就够了。

这一讲是 partition 的第二个应用（第一个是快排）。后面讲堆、讲 Top-K 问题时，还会反复用到「不需要全排序，只找前 K 个」的思路，随机选择是这个思路的基础。
