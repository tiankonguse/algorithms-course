字符串哈希：滑动窗口下的两个匹配问题

两道题都在一个长串上取等长的一段去比。第一道先把 a 拼到够长，再滑一个窗口找 b；第二道要同时比好几段，麻烦在于起点有字数那么多种对齐方式，硬枚举会多乘一个长度。两题都靠「取一段的哈希值是 O(1)」这一步收场。

零、两道题

题 4（LeetCode 686）：给两个字符串 a 和 b，问 a 最少重复叠加几次能让 b 成为子串，做不到返回 -1。"abc" 叠加 0 次是空串，1 次是 "abc"，2 次是 "abcabc"。

题 5（LeetCode 30）：给字符串 s 和等长的单词表 words，找出 s 里所有「串联子串」的起始下标。串联子串指 words 里每个词各用一次、任意顺序接起来的串。words = {ab, cd, ef} 时，"abcdef"、"cdabef" 算，"acdbef" 不算。

一、题 4：先拼到 k+1 份

设 a 的长度是 n，b 的长度是 m，k = ceil(m / n)。b 至少要 k 份 a 才装得下，所以把 a 重复 k+1 份拼成一个长串，在里面滑一个长度 m 的窗口逐个比哈希值。

为什么拼 k+1 份就够：k+1 份里都找不到 b，说明这段长串里没有任何一个位置能对上 b。再往后加份数只是把同一张图案接得更长，新的窗口要么是已经看过的，要么跨过更长的一段但它仍然落在这张周期图案里，所以还是对不上。扫完这个长串没命中，答案就是 -1。

命中之后回答几份，看窗口右端 r 落在哪：r 小于 n × k，说明这一段整个落在前 k 份里，返回 k；否则这段跨过了 k 份的边界，要 k+1 份。

// 重复叠加 a，最少几次能让 b 成为子串，做不到返回 -1
    const int MAXN = 30005;

    char s[MAXN];
    unsigned long long pw[MAXN], hs[MAXN];

    void build(int n) {
        pw[0] = 1;
        for (int i = 1; i < n; i++) {
            pw[i] = pw[i - 1] * base;
        }
        hs[0] = s[0] - 'a' + 1;
        for (int i = 1; i < n; i++) {
            hs[i] = hs[i - 1] * base + s[i] - 'a' + 1;
        }
    }

    unsigned long long getHash(int l, int r) {
        unsigned long long ans = hs[r];
        if (l > 0) {
            ans -= hs[l - 1] * pw[r - l + 1];
        }
        return ans;
    }

    int repeatedStringMatch(const string &a, const string &b) {
        int n = a.size(), m = b.size();
        int k = (m + n - 1) / n;          // m / n 向上取整
        int len = 0;
        for (int c = 0; c <= k; c++) {
            for (int i = 0; i < n; i++) {
                s[len++] = a[i];
            }
        }
        build(len);
        unsigned long long h2 = b[0] - 'a' + 1;
        for (int i = 1; i < m; i++) {
            h2 = h2 * base + b[i] - 'a' + 1;
        }
        for (int l = 0, r = m - 1; r < len; l++, r++) {
            if (getHash(l, r) == h2) {
                return r < n * k ? k : (k + 1);
            }
        }
        return -1;
    }

这道题只能返回 k 或者 k+1，不存在要更多份的情况：k+1 份已经是周期串的两轮以上，再长也不会生出新图案。反过来，值也不可能是 1 到 k-1，因为 k-1 份的长度还不到 m。

三个容易写错的地方：循环写成只拼 k 份，跨边界的那批用例直接找不到；命中之后不看 r 和 n × k 的关系，一律返回 k，同样漏掉 k+1 那批；边界条件写成 r <= n * k，把刚好落在边界上的窗口判成了 k+1。

实测这道题很快：|a| = 20、|b| = 9990 的随机数据 0.044 毫秒，|a| = 1、|b| = 9999 拼到一万个字符再扫一遍也只要 0.087 毫秒。

二、题 5：同余分组加滑动窗口

朴素的思路是枚举 s 里每个起点，往后取 wordNum 个词，和 words 的词频表比一比。取词是 O(wordNum × 词长)，枚举起点是 O(n)，乘起来是 O(n × m)，在 n = m = 104 的规模上要跑几十毫秒。

第一处优化：起点其实只有 词长 种。串联串的第一个词必然从 init + j × 词长 这类位置开始，init 取 0 到 词长−1。以 init 把下标分成 词长 组，每组内部相邻位置正好差一个词长，组内滑窗时窗口的进、出都落在词边界上，不用重新切词。

第二处优化：窗口每挪一个词长，只出去一个词、进来一个词，词频表可以增量维护。为了不每次都比整张表，用「欠债」记账：

1）建第一个窗口时，每放进一个词，win[cur] 加一；如果 win[cur] <= need[cur]，说明这个词是 words 需要的，欠的个数减一。

2）窗口挪一格：出去的词 win[out] 减一，减完如果 win[out] < need[out]，说明这个位置空出来了，欠的个数加一；进来的词 win[in] 加一，加完如果 win[in] <= need[in]，欠的个数减一。

3）debt == 0 时，窗口里每个词的数量都不多于 words 需要的数量，而窗口总长度又恰好是 words 的总长，两边只能完全相等，这一格就是答案。

窗口里存的是哈希值，不是字符串，所以比较词频就是在比较整数。单个词的哈希值用 hashStr 直接乘出来，不用建数组：

// 左闭右开版本：getHash(l, r) 返回 s[l...r-1] 的哈希值，和闭区间版本差一格
    const int MAXN = 10001;

    unsigned long long pw[MAXN], hs[MAXN];

    void build(const string &str) {
        pw[0] = 1;
        for (int i = 1; i < MAXN; i++) {
            pw[i] = pw[i - 1] * base;
        }
        hs[0] = str[0] - 'a' + 1;
        for (int i = 1; i < str.size(); i++) {
            hs[i] = hs[i - 1] * base + str[i] - 'a' + 1;
        }
    }

    unsigned long long getHash(int l, int r) {
        unsigned long long ans = hs[r - 1];
        if (l > 0) {
            ans -= hs[l - 1] * pw[r - l];
        }
        return ans;
    }

    // 不借外面任何数组，单独算一个字符串的哈希值
    unsigned long long hashStr(const string &str) {
        if (str.empty()) {
            return 0;
        }
        unsigned long long ans = str[0] - 'a' + 1;
        for (int i = 1; i < str.size(); i++) {
            ans = ans * base + str[i] - 'a' + 1;
        }
        return ans;
    }

主过程按 init 分组，每组先把第一个窗口装起来，再一格一格挪：

// 返回 s 中所有串联子串的起始下标
    vector<int> findSubstring(const string &s, const vector<string> &words) {
        vector<int> ans;
        unordered_map<unsigned long long, int> mp;
        for (const string &w : words) {
            mp[hashStr(w)]++;
        }
        build(s);
        int n = s.size();
        int wordLen = words[0].size();
        int wordNum = words.size();
        int allLen = wordLen * wordNum;
        unordered_map<unsigned long long, int> win;
        for (int init = 0; init < wordLen && init + allLen <= n; init++) {   // 同余分组
            int debt = wordNum;
            // 第一个窗口：从 init 开始装 wordNum 个词
            for (int l = init, r = init + wordLen, part = 0; part < wordNum;
                 l += wordLen, r += wordLen, part++) {
                unsigned long long cur = getHash(l, r);
                win[cur]++;
                if (win[cur] <= mp[cur]) {
                    debt--;
                }
            }
            if (debt == 0) {
                ans.push_back(init);
            }
            // 之后每步窗口进一个、出一个
            for (int l1 = init, r1 = init + wordLen, l2 = init + allLen, r2 = init + allLen + wordLen;
                 r2 <= n; l1 += wordLen, r1 += wordLen, l2 += wordLen, r2 += wordLen) {
                unsigned long long out = getHash(l1, r1), in = getHash(l2, r2);
                win[out]--;
                if (win[out] < mp[out]) {
                    debt++;
                }
                win[in]++;
                if (win[in] <= mp[in]) {
                    debt--;
                }
                if (debt == 0) {
                    ans.push_back(r1);
                }
            }
            win.clear();
        }
        return ans;
    }

实测 n = 10000、词长 3、词数 20 的数据，随机串上 0.435 毫秒；把 100 份标准串联埋进去，找到 102 个起手也只要 0.416 毫秒。同样这份数据用「每个起点取词比词频表」的暴力写，35.82 毫秒，哈希版快 84 倍。

三个易错点：滑动只在 init = 0 这一组做，漏掉另外 词长−1 组，答案会少一批（实测在 n ≤ 24、词长 2 的随机数据上 10.56% 的用例出错）；第一个窗口装完忘了立即判一次 debt == 0，从 0 号位置开始的答案会漏；出去的词减完判断写成 win[out] <= need[out]，多算了一次欠债，这个错法在随机数据上 37.91% 到 60.87% 被抓到。

重复叠加：窗口滑一遍

把 a 重复 k+1 份拼好，窗口从下标 0 开始一格一格挪。橙色竖线是 k 份与 k+1 份的分界 n × k，命中的窗口如果压过这条线，答案就是 k+1。

同余分组：一格一格挪窗口

选一组 init，先把第一个窗口的词戳进词频表，再一格一格地出一个、进一个。看债怎么涨落，以及 debt == 0 出现在哪几格。

三、复杂度分析

做法关键操作时间空间
题 4　暴力逐次拼接每个份数都从头 find 一遍O(m2/n) 起O(m)
题 4　哈希滑窗拼 k+1 份，再滑一遍O(n + m)O(n + m)
题 5　枚举起点每个起点取 wordNum 个词比词频O(n × 总词长)O(总词长)
题 5　同余分组滑窗词长 组各自滑到底，每步进出各一次O(n + m)O(词数)

题 4 拼出来的长串长度是 n × (k + 1)，而 k = ceil(m/n)，所以是 O(n + m)；扫描同样是 O(n + m)。题 5 一共要滑 词长 组、每组滑 n / 词长 格，加起来 O(n) 步，每步只做常数次哈希查询与表更新；建 words 词频表是 O(m)，建 s 的哈希数组是 O(n)，总复杂度与单词个数、单词长度都无关。空间上题 4 要开 n × (k+1) 个字符，题 5 的两张表各有不超过 words 种类那么多个键。

总结

题 4 的答案是 k 或者 k+1，k = ceil(m/n)；拼到 k+1 份扫一遍，找不到就是 -1。

题 5 的起点只有 词长 种对齐方式，按 init 分组之后组内滑窗的进出都落在词边界上。

词频表用欠债记账，进一个、出一个各更新一次，debt == 0 就是答案，不必每次比整张表。

两题都是 O(n + m)：一题的复杂度和 a、b 的长度成线性，另一题和单词个数、单词长度都无关。哈希在这里换掉的是「切词」和「取词」这两步的代价。
