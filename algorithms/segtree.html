线段树

一个节点管一段区间，对半分下去直到单个元素。查询、单点修改、区间修改都顺着这棵树往下走，都是 O(log n)。

零、背景

树状数组那一节把查询和修改都压到了 O(log n)，代码还短。那为什么还要再学一个线段树？

因为树状数组有两个绕不过去的坎，而线段树恰好都能跨过去。

一、问题

还是同一个问题。长度为 n 的数组 a，支持两种操作。

  • 查询：求区间 [l, r] 的和。
  • 修改：把某个 a[i] 加上 delta，或者把一整段 [l, r] 都加上 delta。

两种操作交替出现，一共 m 次。

举例数据照旧，n = 16。

a = [3, 1, 4, 1, 5, 9, 2, 6, 5, 3, 5, 8, 9, 7, 9, 3]

二、树状数组做不到的两件事

第一件，整段区间一起加。树状数组只能一个点一个点地改，要把 a[2..100] 都加 10，就得改 99 次，退化成 O(n log n)。

第二件，求区间最大值。树状数组靠前缀和相减得到区间和，而最大值减不掉，两个前缀最大值相减什么都不是。

可以发现，这两件事的共同点是「区间要当成一个整体来操作」。树状数组的 c[i] 管的是 [i − lowbit(i) + 1, i] 这种固定段，形状由下标决定，改不了。

线段树的思路不一样。它的节点管哪一段是自己说了算的，对半分下去，天然就能表示任意区间。

三、结构：把区间建成二叉树

线段树用一个节点表示一段区间，然后不断对半分，直到切成单个元素。

根管 [1, n]，存的是整个数组的和。叶子管 [i, i]，存的是 a[i]。中间节点管 [L, R]，取 mid = (L+R)/2，左儿子管 [L, mid]，右儿子管 [mid+1, R]，它的值就是左右儿子之和。

把这棵树的区间一层层铺开画，是这样。

节点不用指针，直接躺在数组里：节点 p 的左儿子是 2p，右儿子是 2p+1，根是 1 号。

下面就是 n = 16 的这棵树。点任意一个节点，看它管着哪一段、存的和是多少。

四、建树

建树是个递归。把 [1, n] 交给根，一路对半分下去，叶子直接取数组里的数，回来的时候每个内部节点把左右儿子的和加起来。

void build(int p, int l, int r) {
    if (l == r) { sum[p] = a[l]; return; }   // 叶子：直接取
    int mid = (l + r) >> 1;
    build(p * 2, l, mid);              // 左儿子管 [l, mid]
    build(p * 2 + 1, mid + 1, r);      // 右儿子管 [mid+1, r]
    sum[p] = sum[p * 2] + sum[p * 2 + 1];   // 内部节点 = 左右之和
}

每个节点只填一次，整棵树一共约 2n 个节点，所以建树是 O(n)。

五、区间查询

查 [ql, qr] 的和，从根开始，每到一个节点就看一下它和查询区间的关系，三种情况。

  • 完全包含：[L, R] 整个落在 [ql, qr] 里面，直接返回 sum[p]，不再往下。
  • 完全不相交：和 [ql, qr] 一点重叠都没有，返回 0。
  • 部分相交：一半在里面一半在外面，往左右儿子递归，把两边加起来。

以 [2, 12] 为例，最后被整段取走的是这四个节点。

演示 ②　区间查询 [l, r]：完全包含 / 部分相交 / 完全跳过
2
12
完全包含（直接取 sum） 部分相交（继续递归） 完全跳过

每层最多只有 2 个部分相交的节点需要往下钻，其余要么整段取、要么整段跳，所以一次查询只访问 O(log n) 个节点。

六、单点修改

把 a[i] 加上 delta，从根出发，每层判断 i 落在左半边还是右半边，一路下到叶子改掉它，回程把经过的每个内部节点重新用「左 + 右」算一遍。

演示 ③　单点修改 a[i]：根 → 叶子的路径
5
被改的叶子 a[i] 回程要重算的节点

树高是 O(log n)，从根到叶子最多走 O(log n) 步，单点修改也是 O(log n)。

七、区间修改与懒标记

现在回到树状数组做不到的第一件事：把 [ql, qr] 整段每个数都加上 delta。

逐个下到每个叶子改一遍，一次就是 O(n)，太慢。

可以发现，区间修改和区间查询的形状是一样的，也是一层层去找「完全被覆盖」的节点，找到就停。区别在于找到之后不是读，而是改：整段的和加上 delta × 区间长度，然后在这个节点上记一笔「还欠着每个元素 delta 没传下去」，也就是 lazy[p] += delta。

以 [3, 14] 加 2 为例，两种做法的差别是这样。

以后真正要访问这个节点的儿子时，才把欠的账下传给儿子，自己清零，这一步就是 pushdown。先记着，等要用再还。

八、代码

#include <bits/stdc++.h>
using namespace std;

const int N = 16;
int a[N + 1] = {0, 3,1,4,1,5,9,2,6,5,3,5,8,9,7,9,3};
int n = N;

int sum[4 * N];       // 每个节点的区间和
int lazy[4 * N];      // 懒标记：还欠着整段加的 delta

// 建树：把 [l,r] 的区间和算到节点 p 上
void build(int p, int l, int r) {
    if (l == r) { sum[p] = a[l]; return; }   // 叶子
    int mid = (l + r) >> 1;
    build(p * 2, l, mid);
    build(p * 2 + 1, mid + 1, r);
    sum[p] = sum[p * 2] + sum[p * 2 + 1];
}

// 下传懒标记：把节点 p 积压的增量传给两个儿子
void pushdown(int p, int l, int r) {
    if (lazy[p] == 0) return;
    int mid = (l + r) >> 1;
    sum[p * 2]     += lazy[p] * (mid - l + 1);   // 左儿子整段加
    lazy[p * 2]    += lazy[p];
    sum[p * 2 + 1] += lazy[p] * (r - mid);       // 右儿子整段加
    lazy[p * 2 + 1] += lazy[p];
    lazy[p] = 0;                                  // 账还清，清零
}

// 查询：[ql, qr] 的和
int query(int p, int l, int r, int ql, int qr) {
    if (ql <= l && r <= qr) return sum[p];   // 完全包含，直接取
    if (qr < l || r < ql) return 0;              // 完全不相交
    pushdown(p, l, r);                             // 部分相交：先下传再往下
    int mid = (l + r) >> 1;
    return query(p * 2, l, mid, ql, qr)
         + query(p * 2 + 1, mid + 1, r, ql, qr);
}

// 单点修改：a[pos] += delta
void update(int p, int l, int r, int pos, int delta) {
    if (l == r) { sum[p] += delta; return; }    // 找到叶子
    int mid = (l + r) >> 1;
    if (pos <= mid) update(p * 2, l, mid, pos, delta);
    else            update(p * 2 + 1, mid + 1, r, pos, delta);
    sum[p] = sum[p * 2] + sum[p * 2 + 1];          // 回程重算
}

// 区间修改：把 [ql, qr] 整段加 delta
void update_range(int p, int l, int r, int ql, int qr, int delta) {
    if (ql <= l && r <= qr) {                     // 完全包含：整段加，记账
        sum[p] += delta * (r - l + 1);
        lazy[p] += delta;
        return;
    }
    if (qr < l || r < ql) return;                  // 完全不相交
    pushdown(p, l, r);                             // 部分相交：先下传再递归
    int mid = (l + r) >> 1;
    update_range(p * 2, l, mid, ql, qr, delta);
    update_range(p * 2 + 1, mid + 1, r, ql, qr, delta);
    sum[p] = sum[p * 2] + sum[p * 2 + 1];
}

int main() {
    build(1, 1, n);
    cout << query(1, 1, n, 1, 8) << endl;       // 31
    update(1, 1, n, 5, -2);                       // a[5]：5 → 3
    cout << query(1, 1, n, 1, 8) << endl;       // 29
    update_range(1, 1, n, 2, 4, 10);              // a[2..4] 都加 10
    cout << query(1, 1, n, 1, 8) << endl;       // 59
    return 0;
}

九、复杂度分析

线段树是一棵约 2n 个节点、高约 log n 层的二叉树。查询和修改都只顺着树往下走，每层最多访问常数个部分相交的节点。

操作时间复杂度
建树 buildO(n)
区间查询 queryO(log n)
单点修改 updateO(log n)
区间修改 update_rangeO(log n)
m 次操作总计O(n + m log n)

空间上用数组存整棵树。对半分到最后一层要留够余量，通常直接开 4n，额外空间 O(n)，常数是 4。比树状数组的 O(n) 大一圈，换来的是区间修改和区间最值这些能力。

三个工具放一起看：分块 O(√n)，树状数组 O(log n) 但只能单点改，线段树 O(log n) 且什么区间操作都能做。

十、最后

线段树和树状数组的取舍很清楚。求和、只改单点，用树状数组，代码短、常数小。要做区间修改、求区间最大值，或者换成别的不能相减的运算，就得上线段树。

把节点里存的「和」换成「最大值」，查询和单点修改只要把加号换成取较大者就行，其余一概不动。区间修改也能照搬懒标记，整段一起加 delta 时，最大值也跟着加 delta。
