贪心：数一遍再拼最大的回文

回文数左右两边一模一样的镜像，所以它长什么样完全由左半边决定。要让整数最大，就把能成对的数字从 9 往 1 一个个往左半边摆，摆得下就摆。

零、题目要什么

给一个只由数字组成的字符串 num，数字可以重新排列。找出用它里面的数字能拼出的最大回文整数，以字符串形式返回。不要求用完所有数字，但至少要用一个。这个整数不能有前导零。

一、回文只有一个自由的部分

一个回文数是「左半边 + 至多一位中点 + 左半边的镜像」。中点可以有也可以没有，剩下两个部分共用一个内容，所以真正要做决定的只有左半边。

整数比较大小是先比位数再比字典序。给定了用哪些数字之后，位数由「成对的个数」决定，把每一对都放进左半边就能拿满位数，不放只会更短。位数定下来之后，左半边从高到低字典序越大，整个数就越大。

于是每条规则都指向同一个动作：从 9 开始往 1 走，每个数字能凑出几对就往左半边放几对。9 放在最前面，整个数就最大。

二、中点挑最大的奇数

数字出现的次数是奇数时，成对放完会剩一个，这个余数就是中点位的候选。中点只能有一个，所以从 9 往下扫的时候，遇到的第一个出现奇数次的数字就是它。后面即使还有别的奇数，也只能白白扔掉，因为多一个中点就不对称了。

这一步的顺序很关键。9 到 1 是降序，第一个碰上的奇数自然是最大的奇数，用不着额外比较。写成升序或者随手挑一个，都会拼出更小的答案。

三、0 只能跟在队尾

0 的成对字符不能摆在左半边最前面，否则拼出来的整数变成 0011 这种带前导零的样子，不合法。所以 0 要单独处理：只有左半边已经站着 1 到 9 的成对字符之后，0 的对子才允许接在后面。

那么 1 到 9 一对都凑不出来的时候呢？这时候左半边是空的，整个回文只能是一位：出现过奇数次的数字里最大的那个（上面算出的中点），一个奇数都没有就返回 0。num 里全是 0 就落在这条分支上，返回的是一位 0，而不是把它成对的 0 全拼出来。

漏掉「0 要等 1 到 9 先站住」这条，抓取率取决于数据里有多少个 0。字母表只有 {0, 1} 时 18.48% 的用例会拼出带前导零的答案，扩到 {0, 1, 2} 降到 10.60%，扩到 {0, 1, 2, 3, 4} 只剩 6.33%。字母表一大，成对的非零数字争着出头，0 反而没机会跑到最前面。

// 最大回文数字：回文数只看两半，左半边从大到小摆同样的字符
    string largestPalindromic(string num) {
        int n = num.size();
        vector<int> cnt(58, 0);
        for (char a : num) {
            cnt[a]++;
        }
        string ans(n, 0);
        int leftSize = 0;
        char mid = 0;
        // '1' 到 '9'：出现奇数次的数字里挑最大的一个留作中点，其余成对地放进左半边
        for (char i = '9'; i >= '1'; i--) {
            if ((cnt[i] & 1) == 1 && mid == 0) {
                mid = i;
            }
            for (int j = cnt[i] / 2; j > 0; j--) {
                ans[leftSize++] = i;
            }
        }
        if (leftSize == 0) {
            // 没有任何 1~9 的成对数字，答案只能是一位
            if (mid == 0) {
                return "0";
            } else {
                return string(1, mid);
            }
        }
        // 左半边已经站着非零数字了，'0' 才能成对地跟进来
        for (int j = cnt['0'] / 2; j > 0; j--) {
            ans[leftSize++] = '0';
        }
        int len = leftSize;
        if (mid == 0 && (cnt['0'] & 1) == 1) {
            mid = '0';
        }
        if (mid != 0) {
            ans[len++] = mid;
        }
        // 左半边逆序拷贝到右半边
        for (int i = leftSize - 1; i >= 0; i--) {
            ans[len++] = ans[i];
        }
        return ans.substr(0, len);
    }

整个函数只扫三趟：数一遍 num 的字符，从 9 到 1 放左半边，最后把左半边逆序拷到右边。106 位数字跑完 0.96ms。

四、一位一位拼出来

从 9 扫到 0

每点一次「下一步」处理一个数字：先看它是不是最大的奇数、要不要留下一个当中点，再把剩下的成对字符放进左半边。

五、对数器怎么抓错

暴力可以老老实实枚举：把 num 按数字排序，枚举它的每一个非空子集，对每个子集枚举全部互不相同的排列，是回文且没有前导零就拿来比大小。串长控制在 6 以内，这个量级完全跑得动。

写这个暴力时踩过一次：为了卡掉前导零，我写的是「第一位是 0 就跳过」，结果 num 是单个 0 时它返回空串，正解返回 0。单字符的 0 是合法答案，例外得单独放行，改成「第一位是 0 且长度大于 1 才跳过」。

总结

回文只有左半边需要决定。从 9 往 1 扫，出现次数除以 2 就是能放进左半边的对数，对数放在越靠前的位置，整个数越大。

出现奇数次的数字里，最大的那个留作中点，多出来的余数直接丢掉。0 的对子要等左半边有了非零数字才能跟进来，一对非零数字都凑不出时答案退化成一位。
