HH 的项链：离线查询与树状数组

区间里有多少种不同颜色，等价于区间里有几个位置是「这种颜色最后一次出现」。把后者标成 1、其余标成 0，答案就变成一次区间和。

零、背景

一共有 n 个位置，每个位置一种颜色，m 条查询，每条问 arr[l..r] 上有多少种不同颜色。n 和 m 都到 10⁶。

这个规模下，每条查询单独扫一遍是不行的。实测 n = m = 2000 的暴力要 0.70 ms，两边的规模各放大 500 倍，照 O(n · m) 外推是 175 秒左右。而下面这个做法在 n = m = 10⁶ 上实测 68.52 ms。

一、问题

arr = [1, 2, 1, 3, 2, 1]    查询 [2, 5]

区间 [2, 5] 是 [2, 1, 3, 2]，出现过 1、2、3，答案是 3 种。

颜色种类这个量不能直接做减法。知道 [1, 5] 有 3 种、[1, 1] 有 1 种，推不出 [2, 5] 有几种，因为减掉的那种可能还在右边出现。这是它跟「区间和」最不一样的地方。

二、关键观察：只认最后一次出现

换个数法。在一段区间里，每种颜色可能出现很多次，但只在它最后一次出现的位置上计一次数，总数还是颜色种数。

于是给每个位置定一个标记：如果这个位置的颜色，在「从 1 到当前右端点」这一段里是最后一次出现，就标 1，否则标 0。区间 [l, r] 上的标记之和，恰好就是这段里的颜色种数。

标记依赖右端点：r 往右挪一格，新进来的那种颜色会把上一次的标记抢走。所以每条查询必须配它自己的 r。

三、离线：把查询按右端点排序

所有查询一起处理，按 r 从小到大排。指针 s 从 1 出发只往右走，走到 r 时，标记数组正好是「右端点为 r」时该有的样子，此时求一次 [l, r] 的区间和就是这条查询的答案。

维护标记只需要一个 last 数组：last[c] 记颜色 c 当前最靠右的位置。s 走到新位置时，把旧位置的标记减 1、新位置的标记加 1。

void Add(int i, int v) {
    	while (i <= n) {
    		tree[i] += v;
    		i += Lowbit(i);
    	}
    }

    int Sum(int i) {
    	int ans = 0;
    	while (i > 0) {
    		ans += tree[i];
    		i -= Lowbit(i);
    	}
    	return ans;
    }

    int Range(int l, int r) {
    	return Sum(r) - Sum(l - 1);
    }
// 查询按右端点从小到大排序，s 指针只往右走
    void Compute() {
    	sort(query.begin() + 1, query.end(), [](const vector<int>& a, const vector<int>& b) {
    		return a[1] < b[1];
    	});
    	for (int s = 1, q = 1, l, r, id; q <= m; q++) {
    		r = query[q][1];
    		for (; s <= r; s++) {
    			int color = arr[s];
    			if (last[color] != 0) {
    				// 这种颜色上一次出现的位置作废
    				Add(last[color], -1);
    			}
    			// 最新一次出现的位置生效
    			Add(s, 1);
    			last[color] = s;
    		}
    		l = query[q][0];
    		id = query[q][2];
    		ans[id] = Range(l, r);
    	}
    }

四、容易写漏的两处

第一处是「减去旧标记」那一行。只加不减的话，标记数组全是 1，回答的就变成区间长度。随机 2000 组数据实测，75.00% 的查询会答错。

第二处是 last 数组的开法。它按颜色值域开，题目里 arr[i] 到 10⁶，所以是 10⁶ 个 int，约 4 MB。颜色值域大于 n 的题要先离散化，或者直接换成哈希表。

还有个写法上的坑：排序比较器要按 a[1] < b[1] 写，别写成相减，相减在右端点接近 int 边界时会溢出。同时每条查询要带上自己的原始编号，答案按编号回填。

n = m = 10⁶ 时实测 68.52 ms，其中排序 46.26 ms、扫描 22.26 ms。空间上树状数组和 last 各约 4 MB，查询数组三条 int 一组约 12 MB。

总结

这题的分水岭在「标记」这一步。直接数颜色做不了减法，改成数「每种颜色的最后一次出现」之后，标记数组是区间可加的，剩下的就是区间求和。

标记依赖右端点，所以查询必须按 r 排序、指针只能往右走。这是离线处理最常见的形态：不改变答案，只重排处理顺序，换来一次线性扫描。last 数组是维护标记的全部，旧位置减 1、新位置加 1，漏掉减 1 那行，答案会退化成区间长度。

同样的思路还能用在「区间内出现恰好一次的数」「区间内不同数字的和」这类题上，差别只在标记 1 换成标记什么、以及条件从「最后一次」换成什么。
