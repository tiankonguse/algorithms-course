Tarjan 算法离线求 LCA

m 条查询一次给全的时候，不必为每条查询单独爬一次树。一趟 dfs 顺手维护并查集，走完一遍全部 m 条查询都有答案，总代价 O(n + m)。代价是必须离线：查询不能一条一条来。

零、背景

上一节的跳表是在线的，来一条答一条，代价 O((n + m) log n)。m 和 n 同阶到 5 × 10⁵ 时，log n 那一项是 19 次判断乘 10⁶，不算便宜。

换个问法：如果一开始就把 m 条查询全拿到手，能不能一次遍历全答完？Tarjan 1979 年给出的做法是能，而且总代价是线性的。它把「并查集」这个原本用来合并集合的结构，用在了树的一次后序遍历上。

一、问题

题目还是最近公共祖先：n 个点、n − 1 条边、指定根 root，m 条查询 u v，打印每条的最低公共祖先。n、m 上限都是 5 × 10⁵。m 条查询在输入里一次给全。

朴素参照：每条查询都从 u、v 往上爬到根，标记经过的点，第一次重合就是答案。一次 O(n)，m 条就是 O(nm)，n = m = 5 × 10⁵ 时是 2.5 × 10¹¹ 次操作。

二、一趟 dfs 里发生了什么

dfs 停在某个点 u 上的时刻，整棵树被切成三类：u 的祖先们（在递归栈上，还没退场）、u 已经走完的子树、以及还没走到的部分。并查集里维护的正是「已经走完的部分」。

规矩是四条：

1）来到 u，把 visited[u] 置成真。

2）u 的每棵子树走完，就把那棵子树并进 u，集合头设成 u。

3）u 的所有子树都走完之后，处理挂在 u 上的每一条查询 (u, x)。

4）如果 x 已经访问过，答案就是 x 所在集合的头；x 没访问过就什么都不做，等 dfs 走到 x 时由 (x, u) 那一条来答。

三、为什么 find(x) 就是答案

设 u 的所有子树都走完了，此时处理查询 (u, x)，且 x 已经访问过。x 只可能在两个位置：u 的祖先，或者 u 的某棵已经走完的子树里。

如果 x 在 u 的祖先那一列上，那它还在递归栈里，从来没被并进谁，father[x] = x，find(x) = x。而 u 在 x 的子树里，LCA(u, x) 正是 x。

如果 x 在 u 的某棵已走完的子树里，那条子树被并进 u 了，find(x) 顺着 father 爬上来必然停在 u。而 LCA(u, x) 就是 u。

还有一种情况：x 既不是 u 的祖先也不在 u 的子树里，但已经访问过。那 x 一定在某个更早走完的分支上，find(x) 会停在 u 和 x 分叉的那个节点，也正好是 LCA。所以三句话其实是一句：find(x) 停在哪里，哪里就是 LCA。

四、查询要挂两次

一条查询 (u, v) 要在 u 的链表上挂一条 (v, 编号)，也要在 v 的链表上挂一条 (u, 编号)。谁后访问到，谁负责写答案。

void addEdge(int u, int v) {
        edgeNext[tcnt] = headEdge[u];
        edgeTo[tcnt] = v;
        headEdge[u] = tcnt++;
    }

    // 一条查询要挂两次：在 u 的链上挂 (v, i)，在 v 的链上挂 (u, i)
    // dfs 到谁就查谁的链，先到的那一侧发现对面还没访问过，就等对面来处理
    void addQuery(int u, int v, int i) {
        queryNext[qcnt] = headQuery[u];
        queryTo[qcnt] = v;
        queryIndex[qcnt] = i;
        headQuery[u] = qcnt++;
    }

存储结构和树边完全一样，也是链式前向星，只是多一个 queryIndex 记这条查询在答案数组里的下标。所有数组一起声明：

const int MAXN = 500001;

    // 树边：链式前向星
    int headEdge[MAXN], edgeNext[MAXN << 1], edgeTo[MAXN << 1], tcnt;

    // 查询也用同一套结构存：headQuery[u] 挂的是「和 u 有关的所有查询」
    // queryTo 是这条查询的另一个端点，queryIndex 是它在答案数组里的下标
    int headQuery[MAXN];
    int queryNext[MAXN << 1], queryTo[MAXN << 1], queryIndex[MAXN << 1], qcnt;

    bool visited[MAXN];     // 这个点 dfs 是否已经到过
    int father[MAXN];       // 并查集
    int ans[MAXN];          // 第 i 条查询的答案

五、并查集与路径压缩

father 数组一开始每个点指向自己，合并就是把一棵子树的根指过去。find 顺路把路径压平：

// 并查集找头节点，顺路把路径压平
    int find(int i) {
        if (i != father[i]) {
            father[i] = find(father[i]);
        }
        return father[i];
    }

    // 当前来到 u 节点，u 的父亲是 f
    void tarjan(int u, int f) {
        visited[u] = true;
        // 先把所有子树走完，每走完一棵就把它并进 u
        for (int e = headEdge[u], v; e != 0; e = edgeNext[e]) {
            v = edgeTo[e];
            if (v != f) {
                tarjan(v, u);
                father[v] = u;
            }
        }
        // 子树都并完了，再处理挂在 u 上的查询
        for (int e = headQuery[u], v; e != 0; e = queryNext[e]) {
            v = queryTo[e];
            // v 已经访问过，说明 v 在某个已经走完的集合里
            // 那个集合的头节点就是 u 和 v 的最低公共祖先
            // v 没访问过就什么都不做，等 dfs 走到 v 时处理 (v, u) 那一条
            if (visited[v]) {
                ans[queryIndex[e]] = find(v);
            }
        }
    }

路径压缩这一步省不掉。链形数据上 father 会拉成一条长链，不压缩的话一次 find 就是 O(n)。压缩之后，均摊代价是反阿克曼级别，实际计算里当常数看。

六、两版代码

递归版照着四步写，最短。注意合并动作写在「子树回来之后」：

// 并查集找头节点，顺路把路径压平
    int find(int i) {
        if (i != father[i]) {
            father[i] = find(father[i]);
        }
        return father[i];
    }

    // 当前来到 u 节点，u 的父亲是 f
    void tarjan(int u, int f) {
        visited[u] = true;
        // 先把所有子树走完，每走完一棵就把它并进 u
        for (int e = headEdge[u], v; e != 0; e = edgeNext[e]) {
            v = edgeTo[e];
            if (v != f) {
                tarjan(v, u);
                father[v] = u;
            }
        }
        // 子树都并完了，再处理挂在 u 上的查询
        for (int e = headQuery[u], v; e != 0; e = queryNext[e]) {
            v = queryTo[e];
            // v 已经访问过，说明 v 在某个已经走完的集合里
            // 那个集合的头节点就是 u 和 v 的最低公共祖先
            // v 没访问过就什么都不做，等 dfs 走到 v 时处理 (v, u) 那一条
            if (visited[v]) {
                ans[queryIndex[e]] = find(v);
            }
        }
    }

要改成迭代，得先把合并动作的时机挪一挪：把「儿子回来后 father[v] = u」改成「u 自己收尾时 father[u] = f」。两句等价，因为在 u 的查询处理完之前，u 都还是自己这个集合的头。

// 把递归版里「儿子回来之后 father[v] = u」改成「u 自己收尾时 father[u] = f」
    // 两句等价：u 的查询处理完之前，u 都还是自己这个集合的头
    // 但改完之后合并动作全部集中在「一个点要退场」的时刻，迭代版才好写
    void tarjan(int u, int f) {
        visited[u] = true;
        for (int e = headEdge[u], v; e != 0; e = edgeNext[e]) {
            v = edgeTo[e];
            if (v != f) {
                tarjan(v, u);
            }
        }
        for (int e = headQuery[u], v; e != 0; e = queryNext[e]) {
            v = queryTo[e];
            if (visited[v]) {
                ans[queryIndex[e]] = find(v);
            }
        }
        father[u] = f;
    }

七、迭代版

栈里压三样：u、f、e。e = −1 是第一次来到 u，e = 0 是 u 的边都走完了。处理查询和合并都放在 e = 0 那一支，正好对应改写版里「收尾」的时刻。

// 栈里压三样：u 当前处理的点、f 它的父亲、e 处理到几号边了
    // e == -1 表示 u 的边一条没处理，e == 0 表示 u 的边都处理完了
    int ufe[MAXN][3];
    int stackSize, u, f, e;

    void push(int uu, int ff, int ee) {
        ufe[stackSize][0] = uu;
        ufe[stackSize][1] = ff;
        ufe[stackSize][2] = ee;
        stackSize++;
    }

    void pop() {
        --stackSize;
        u = ufe[stackSize][0];
        f = ufe[stackSize][1];
        e = ufe[stackSize][2];
    }
void tarjan(int root) {
        stackSize = 0;
        push(root, 0, -1);
        while (stackSize > 0) {
            pop();
            if (e == -1) {
                visited[u] = true;             // 第一次来到 u
                e = headEdge[u];
            } else {
                e = edgeNext[e];               // 回来一次，往下挪一条边
            }
            if (e != 0) {
                push(u, f, e);                 // 这条边还要接着用
                if (edgeTo[e] != f) {
                    push(edgeTo[e], u, -1);
                }
            } else {
                // e == 0：u 的所有子树都走完并完了，正是递归版里处理查询的时刻
                for (int q = headQuery[u], v; q != 0; q = queryNext[q]) {
                    v = queryTo[q];
                    if (visited[v]) {
                        ans[queryIndex[q]] = find(v);
                    }
                }
                father[u] = f;                 // u 退场，并进父亲
            }
        }
    }

find 也别递归。顺着 father 一路把经过的点记进临时栈，回头统一改指向：

// 找头节点也别递归：顺着 father 一路记下来，回头再统一改指向
    int ufstack[MAXN];

    int find(int i) {
        int size = 0;
        while (i != father[i]) {
            ufstack[size++] = i;
            i = father[i];
        }
        while (size > 0) {
            father[ufstack[--size]] = i;
        }
        return i;
    }

八、实测对照

同一棵树、同一组查询，跳表和 Tarjan 各跑一遍。跳表分两段计时：建表（一次 dfs 填 deep 和跳表）和 m 次查询；Tarjan 是一次全程（含 dfs 和全部查询）。

树形n = m跳表建表跳表查询Tarjan 全程总耗时之比
链1 × 10⁵1.84 ms5.73 ms4.78 ms1.58
星5 × 10⁵4.35 ms93.04 ms14.17 ms6.87
随机5 × 10⁵20.44 ms116.32 ms44.69 ms3.06
完全二叉5 × 10⁵8.16 ms124.58 ms25.07 ms5.29

find 的调用次数也量过：链上 n = m = 6 × 10⁴ 时共 12 万次，平均每条查询 2.00 次；星、随机、完全二叉都是平均 1.00 次。差别来自形状：链上任意两点都互为祖孙，两侧都会命中，各算一次；其余树形里大部分点对没有祖孙关系，只有后访问那一侧会触发。

顺带量了「一条查询被写两次答案」的情况（两点互为祖孙时两侧都会写）：星、随机、完全二叉、毛虫四种形状各 10 万条查询里，被写两次的分别有 3、37、26、47 条，两次写入的值全部一致，0 例打架。链上则是 6 万条全部被写两次，同样 0 例不一致。所以「重复写入」不用担心，也不用特判。

九、几处容易写错的地方

把几种改写单独注入，跑随机小数据（n = m，m 条随机查询），看有多少条答案和正解不一致：

写法n = 8n = 20n = 60n = 200
把查询挪到进子树之前处理0.00%0.00%0.00%0.00%
递归之前就 father[v] = u53.73%62.32%64.87%67.38%
处理查询之前就 father[u] = f100.00%100.00%100.00%100.00%
不判 visited 直接答0.00%0.00%0.00%0.00%
查询只挂一侧14.62%22.69%28.59%31.26%

两行 0.00% 值得单独说：这两种写法给出的答案全部正确，属于等价改写，理由写在下面两小段，也都补了几十万条查询的实测。

「查询挪到进子树之前」：在 u 的入口处理查询时，u 的子树一个都还没走，此时已访问的点只有两类，祖先（father 还是自己，find 就是它本人）和更早走完的分支（已经并到分叉点，find 停在分叉点）。两种情况下 find 给出的都是 LCA，和后处理的答案逐条相同。实测跑了 40 万条查询，0 条不一致。

「不判 visited」：少了判断会写出错的值，但因为查询挂了两次，后访问那一侧还会再写一次，而那一次的时刻正好是并查集状态正确的时刻，把错值盖掉了。实测 39 万条查询，同样 0 条不一致。这条只在「挂两次」的前提下成立，只挂一次就会大面积漏答。

反过来，「处理查询之前就 father[u] = f」是四档全 100%。u 提前并进了父亲，查询 (u, x) 里 x 若在 u 的子树里，find(x) 会一路爬到 f 而不是停在 u，答案整片偏上。

十、复杂度分析

步骤时间复杂度空间复杂度
建图与挂查询O(n + m)O(n + m)
一趟 dfs 走完全部点O(n)O(n)
并查集的合并与 findO((n + m) α(n))O(n)
整体O(n + m)O(n + m)

α 是反阿克曼函数，任何实际规模下不超过 5，当常数看。空间按题目上限 n = m = 5 × 10⁵ 算：树边 next/to 7.63 MB、查询表 next/to/index 11.44 MB、两个 head 各 1.91 MB、father 1.91 MB、ans 1.91 MB、visited 0.48 MB，加迭代版栈 ufe 5.72 MB，合计约 32.91 MB，比跳表的 47.69 MB 还省一些。

代价写在最后：这套办法必须一次拿到全部查询。查询和树交替到来、或者答案会影响后续输入的题，只能用跳表或者树链剖分。

十一、总结

Tarjan 求 LCA 的核心是一句话：dfs 停在 u 上时，并查集里「已经走完的部分」的头节点恰好就是 u 和 that 部分的 LCA。三件事值得记住：查询必须挂两次，先访问的一侧跳过、后访问的一侧写答案；合并动作要放在查询之后（递归版写在儿子回来后，改写版写在自己收尾时）；递归版在链形数据上会爆栈，n 到 5 × 10⁵ 要交迭代版。

离线换来的线性代价在查询量大时很划算，实测比跳表快 1.6 到 6.9 倍。后面还会看到同一个 Tarjan 名字出现在强连通分量、割点割边上，骨架都是这趟 dfs 加一个栈。
