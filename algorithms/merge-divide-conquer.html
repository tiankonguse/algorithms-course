归并分治：小和与翻转对

归并排序的 merge 过程不只能排序。两个有序段并排放在一起时，指针单调前移的特性可以顺手统计很多东西。这一讲用两道经典题把「归并分治」的判据和写法讲透。

零、背景

上一讲把归并排序本身讲完了：分两半、各自排好、再用 merge 合成整体。merge 里两个指针 a 和 b 各走各的，谁小取谁，全程不回头。

这个「不回头」很值钱。如果一道题的答案可以拆成「左半自己的答案 + 右半自己的答案 + 跨越左右产生的答案」，而跨越左右那部分恰好能在两个段各自有序时用单调指针算出来，那归并排序的框架就能直接套上去，排序只是顺带的副产品。

这套思路叫归并分治。下面先给判据，再用两道题落地。

一、归并分治的四条判据

拿到一道题，按下面四条依次问自己：

1）大范围上的答案，等不等于左部分的答案加右部分的答案，再加跨越左右产生的答案？

2）算跨越左右那部分时，如果加上「左、右各自有序」这个设定，会不会获得计算上的便利？

3）以上两条都成立，这道题很可能能用归并分治解决。

4）求解时只需要在归并排序的过程里插入一段统计代码，因为要让左右各自有序才能获得便利。

第 2 条是核心。「有序」带来的便利通常是指针单调：一个指针只管往右走，不需要回退，所以统计阶段的总代价是 O(n) 而不是 O(n²)。整道题的复杂度就和归并排序一样，是 O(n log n)。

有些归并分治的题也能用线段树、树状数组做，复杂度同样最优。那些数据结构后面会讲，这里先把最朴素的归并框架吃透。

二、小和问题

给定一个数组，对每个元素，把它左边所有小于等于它的数加起来，再把每个元素的结果累加，得到的总和叫「小和」。

拿 s = [1, 3, 5, 2, 4, 6] 算一遍：

s[0]=1，左边没有数，贡献 0。

s[1]=3，左边小于等于 3 的是 1，贡献 1。

s[2]=5，左边小于等于 5 的是 1、3，贡献 4。

s[3]=2，左边小于等于 2 的是 1，贡献 1。

s[4]=4，左边小于等于 4 的是 1、3、2，贡献 6。

s[5]=6，左边小于等于 6 的是 1、3、5、2、4，贡献 15。

小和 = 0 + 1 + 4 + 1 + 6 + 15 = 27。

暴力做法是两层循环：对每个 j，扫一遍左边所有 i，a[i] ≤ a[j] 就累加。时间 O(n²)，n = 50000 时实测约 99 毫秒。n 再大就撑不住了。

三、小和的归并解法

用归并分治的四条判据套一下。

第 1 条：整个数组的小和 = 左半内部的小和 + 右半内部的小和 + 「左半元素和右半元素之间」产生的小和。前两部分递归解决，第三部分是跨越左右的答案。

第 2 条：算跨越左右的小和时，如果左半和右半各自有序，会发生什么？对右半的每个元素 a[j]，左半里所有小于等于 a[j] 的元素一定排在最前面。用一个指针 i 从左半头部开始往右走，遇到 a[i] ≤ a[j] 就把 a[i] 加进 sum、i 前移；遇到第一个大于 a[j] 的就停。这一轮的 sum 就是 a[j] 贡献的跨左右小和。

关键是 i 不回头。处理完 a[j] 再处理 a[j+1] 时，a[j+1] ≥ a[j]（右半有序），所以之前已经加进 sum 的那些元素仍然满足条件，i 从当前位置继续走就行。整个统计阶段 i 和 j 加起来最多走 n 步，代价 O(n)。

统计完之后，照常做 merge 把左右合成一个有序段，返回给上一层。整个过程就是归并排序多了一段统计代码。

有个溢出的坑。小和的结果可能很大：n = 100000、所有元素都是 10⁹ 时，小和约为 5×10¹⁸，远超 int 的上限 2.1×10⁹。返回值必须用 long long。课程代码里 merge 函数的 sum 变量写成了 int，在数值大时也会溢出，稳妥起见改成 long long。

long long merge(int l, int m, int r) {
        long long ans = 0;
        for (int j = m + 1, i = l; j <= r; j++) {
            long long sum = 0;
            while (i <= m && arr[i] <= arr[j]) {
                sum += arr[i++];
            }
            ans += sum;
        }
        int i = l, a = l, b = m + 1;
        while (a <= m && b <= r)
            help[i++] = arr[a] <= arr[b] ? arr[a++] : arr[b++];
        while (a <= m) help[i++] = arr[a++];
        while (b <= r) help[i++] = arr[b++];
        for (i = l; i <= r; i++) arr[i] = help[i];
        return ans;
    }

递归部分和归并排序一模一样，只是多返回了 merge 的统计值：

long long smallSum(int l, int r) {
        if (l == r) return 0;
        int m = (l + r) >> 1;
        return smallSum(l, m)
             + smallSum(m + 1, r)
             + merge(l, m, r);
    }

n = 50000 时，归并版实测约 3.5 毫秒，暴力版约 99 毫秒，差 28 倍。n 越大差距越明显。

四、翻转对

给定数组 nums，如果 i < j 且 nums[i] > 2 × nums[j]，就把 (i, j) 称作一个翻转对。返回数组中翻转对的数量。

这道题和小和同属归并分治，但统计的方向反过来了。小和是「对每个右元素，看左半有多少满足条件」；翻转对是「对每个左元素，看右半有多少满足条件」。

为什么方向反过来？因为条件是 nums[i] > 2 × nums[j]，i 在左、j 在右。如果对每个右元素 j 去看左半有多少 i 满足，左半的指针仍然可以单调前移（左半有序，a[i] 越大越容易满足），其实也能做。但课程里选的是对每个左元素 i 去数右半，两种写法都对，下面按课程的写法讲。

左半和右半各自有序后，对每个左元素 a[i]，用指针 j 从右半头部开始走，遇到 a[i] > 2 × a[j] 就 j 前移，直到条件不满足。此时 j 走过的格子数就是这个 a[i] 贡献的翻转对数量。

j 同样不回头：下一个 a[i+1] ≥ a[i]（左半有序），之前满足条件的右元素仍然满足，j 从当前位置继续走。

这里有个必须注意的溢出。2 × nums[j] 可能超出 int 范围：nums[j] = 1.5×10⁹ 时，2 × nums[j] = 3×10⁹，用 int 算会溢出成负数 -1294967296，比较结果完全错误。必须把两边都强转成 long long 再比：(long long)a[i] > (long long)a[j] * 2。

五、翻转对的代码

merge 函数的统计阶段遍历左半，j 单调前移：

int merge(int* arr, int l, int m, int r) {
        int ans = 0;
        for (int i = l, j = m + 1; i <= m; i++) {
            while (j <= r && (long long)arr[i] > (long long)arr[j] * 2)
                j++;
            ans += j - m - 1;
        }
        int i = l, a = l, b = m + 1;
        while (a <= m && b <= r)
            help[i++] = arr[a] <= arr[b] ? arr[a++] : arr[b++];
        while (a <= m) help[i++] = arr[a++];
        while (b <= r) help[i++] = arr[b++];
        for (i = l; i <= r; i++) arr[i] = help[i];
        return ans;
    }

递归部分和小和完全同构：

int counts(int* arr, int l, int r) {
        if (l == r) return 0;
        int m = (l + r) >> 1;
        return counts(arr, l, m)
             + counts(arr, m + 1, r)
             + merge(arr, l, m, r);
    }

n = 50000 时，归并版实测约 3.2 毫秒，暴力版约 2972 毫秒，差 931 倍。翻转对的暴力是两层循环里还带一次乘法，比小和的暴力更慢，归并的优势更明显。

六、两种统计的方向

小和和翻转对放在一起看，最容易混淆的是统计阶段指针的方向。

小和的条件是 a[i] ≤ a[j]，i 在左、j 在右。课程写法是「外层遍历右元素 j，内层指针 i 在左半单调前移」。因为右半有序，j 增大时阈值 a[j] 也增大，i 不需要回退。

翻转对的条件是 a[i] > 2 × a[j]。课程写法是「外层遍历左元素 i，内层指针 j 在右半单调前移」。因为左半有序，i 增大时 a[i] 也增大，能满足条件的右元素只会更多，j 不需要回退。

两种写法的共同点是：被遍历的那一侧有序，导致阈值单调变化，另一侧的指针因此只进不退。统计阶段总代价 O(n)，叠上 log n 层递归就是 O(n log n)。

方向选反了会怎样？比如小和改成「外层遍历左元素 i，内层看右半有多少 j 满足 a[i] ≤ a[j]」。右半有序，对每个 i 可以二分找到第一个大于等于 a[i] 的位置，代价变成 O(n log n) 每层，总复杂度 O(n log²n)。也能做，但多了一个 log 因子。归并分治追求的是用单调指针把每层压回 O(n)。

复杂度分析

算法时间空间说明
小和（暴力）O(n²)O(1)两层循环，n=50000 约 99ms
小和（归并分治）O(n log n)O(n)help 数组，n=50000 约 3.5ms
翻转对（暴力）O(n²)O(1)两层循环带乘法，n=50000 约 2972ms
翻转对（归并分治）O(n log n)O(n)help 数组，n=50000 约 3.2ms

两道题的额外空间都是 O(n)，来自 merge 用的 help 数组。递归栈深度是 O(log n)，和归并排序一致。

总结

归并分治的核心是四条判据，其中最关键的一条是「左右有序后，跨越左右的答案能不能用单调指针在 O(n) 内算出来」。能，就套归并排序的框架，排序只是副产品。

小和问题：外层遍历右元素，左指针 i 单调前移累加 sum，返回值必须 long long。

翻转对：外层遍历左元素，右指针 j 单调前移计数，2 × a[j] 必须强转 long long 防溢出。

两道题的统计方向相反，但道理一样：被遍历侧有序导致阈值单调，另一侧指针只进不退。写代码时先想清楚「外层遍历哪一侧、另一侧的指针为什么不需要回退」，再动手。

归并分治还能解决更难的问题，比如二维平面上最近点对，那是后面的内容。下一讲换随机快速排序。
