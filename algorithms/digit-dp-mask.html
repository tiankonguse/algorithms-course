数位 dp：把用过的数字装进 status

「每一位都互不相同」这个约束和前面几题不一样。前面几题管的是「这一位不能超过某个数」，这里管的是「这个数字之前有没有出现过」。十进制只有 10 个数字，用过的那些正好塞进一个整数的低 10 位。有了这个 status，剩下还有几位能自由排，可以用排列数直接乘出来，不必逐位递归。

零、状态里装一个集合

题目给一个正整数 n，问 [1, n] 里每一位都互不相同的正整数有几个。n 最大到 10⁹ 减一，逐个数判断是 10⁹ 级别，不行。

拆成数位看，每个数是一个不超过 10 位的串。约束落在「用过的数字」上：填到某一位时，候选数字是「0 到 9 里没被前面用过的那些」。所以状态里除了走到第几位，还要知道用过哪些。

用过的数字最多 10 个，拿一个整数的第 d 位表示「数字 d 用过了」。前缀是 1、3、5 时，status 的第 1、第 3、第 5 位是 1，其余是 0。

状态空间的容量一眼可见：len × 2¹⁰ × 2。len 到 10 也只是二十万个格子，比前一题的数位和状态还小。

一、剩下的位能自由排，就先算出来

记 cnt[i] 为「前缀已经确定（非空，一共 len−i 位），还剩 i 位要填，有几种填法」。前缀用掉了 len−i 个数字，可选数字还剩 10−(len−i) 个，往后每填一位可选数减一个，所以

cnt[i] = cnt[i−1] × (10 − len + i)，边界 cnt[0] = 1。

以 len = 4 为例：cnt[1] = 7（前缀 3 位已定，最后一位还有 7 个数字可选），cnt[2] = 8×7 = 56，cnt[3] = 9×8×7 = 504。

这张表和第一页那个「9·9·8·…」是同一类乘积，区别在于这里的起点跟着「前缀已经用掉几个数字」走，而第一页的首位固定不能用 0。

二、位数比 len 少的数先单独收

链只负责位数正好等于 len 的那些数，位数更少的得另外算。1 位数是 1 到 9，共 9 个；k 位数首位 9 种，后面每位可选数递减，一共 9·9·8·…·(10−k+1) 个。k 从 2 累加到 len−1。

最高位那一层也能顺手处理：最高位可以在 1 到 first−1 里选（first 是 n 的最高位），每一位选完后面全是自由的，各贡献 cnt[len−1]。

// cnt[i]：前缀已经确定（共 len - i 位，非空），还剩 i 位自由排，有几种
    // len = 4 时：cnt[3] = 9*8*7，cnt[2] = 8*7，cnt[1] = 7，cnt[0] = 1
    vector<int> cnt(len, 0);
    cnt[0] = 1;
    for (int i = 1, k = 10 - len + 1; i < len; i++, k++) {
        cnt[i] = cnt[i - 1] * k;
    }
    int ans = 0;
    if (len >= 2) {
        ans = 9;                                 // 1 位数：1 到 9
        for (int i = 2, a = 9, b = 9; i < len; i++, b--) {   // 2 位、3 位 … 全部累加
            a *= b;
            ans += a;
        }
    }
    int first = n / offset;                      // n 的最高位
    ans += (first - 1) * cnt[len - 1];            // 最高位选 1 到 first - 1，低位随便排
    ans += f(n, len - 1, offset / 10, 1 << first); // 最高位就选 first，往下走
    return ans;

三、逐位走，status 一路带着

剩下的就是那条贴着 n 的链。走到第 i 位时，n 的这一位是 first，状态是 status：

1）从 0 到 first−1 里挑没被用过的数字，每个后面 len−1 位自由，贡献 cnt[len−1]。

2）如果 first 自己没被用过，就带着 status | (1 << first) 往下走一位。

3）first 已经被用过，链就断了，返回 0。

// 前缀已经和 n 完全相同，还剩 len 位；status 是前缀已经用掉的数字集合
    int f(int n, int len, int offset, int status) {
        if (len == 0) return 1;                     // n 自己
        int ans = 0;
        int first = (n / offset) % 10;               // n 当前这一位
        for (int cur = 0; cur < first; cur++) {
            if ((status & (1 << cur)) == 0) ans += cnt[len - 1];
        }
        if ((status & (1 << first)) == 0) {           // 这一位和 n 一样，但数字得没用过
            ans += f(n, len - 1, offset / 10, status | (1 << first));
        }
        return ans;
    }

拿 n = 987 走一遍。最高位是 9，1 到 8 各贡献 cnt[2] = 72，共 576；9 没被用过，继续。第二位是 8，status 里只有 9，0 到 7 都没用过，各贡献 cnt[1] = 8，共 64；8 继续。第三位是 7，0 到 6 各贡献 cnt[0] = 1，共 7；7 继续，走完最后一位，987 自己再加 1。链上合计 648。

再加上位数更少的 9 + 81 = 90，总共 738。

四、反过来的那一问

「至少有 1 位重复的数字个数」不用另写一遍。区间 [1, n] 里要么每一位都不同，要么至少有两位重复，两者互补，所以答案是 n − (每一位都不同的个数)。同一份 countSpecialNumbers 直接复用。

两个题目名字不同、链接不同，落到的代码是同一段，这是这题的一个特点。

五、写错的地方

随机 2 万组小数据（n 不超过 300000）实测的抓取率：

写法与正确解不一致的比例为什么会错
cnt 的系数写成 10 − i98.15%少算了「前缀已经用掉几个」这个偏移，位数越多差得越远
漏掉 (first − 1) × cnt[len − 1] 这一项63.10%只剩「和 n 同前缀」这一条链，最高位比 first 小的数全丢了
递归时忘了把当前位并进 status80.11%同一个数字会被重复使用，长数字里重复的都被当成了合法的

第一条错法值得多看一眼：cnt[i] = cnt[i−1] × (10 − i) 看着很像「每填一位少一个数字」，但它少算了前缀已经占掉的数量。len = 4 时算出来是 9、72、504，正确值是 7、56、504，只有最后一项恰好撞上。

七、三种写法的代价

同一台机器实测（g++ -O2）：

写法耗时随 n 的变化状态数
枚举 1 到 nn=10⁷ 时 53.4 ms，线性增长不适用
直接排列组合n=10⁹ 也是 0.0000 ms（量不出来）只开一张 len 项的 cnt 表
成体系的记忆化（status + free）同样是微秒级len=9 时实际访问 4089 个状态，上界 9×1024×2 = 18432

两条数位 dp 路线都够用。直接排列组合走的是「能算的地方就用乘法算掉」，只在一条链上递归，代码短、常数小；带 status 的记忆化版本把 (i, status, free) 全挂进表里，写起来更机械，遇到新约束加维度就行。这题两种写法都跑得飞起，选哪个看顺手。

八、复杂度分析

写法时间空间说明
枚举O(n log n)O(1)每个数拆一遍位
直接排列组合O(len · 10)O(len)链上每一位最多看十个数字，cnt 表 len 项
记忆化 status 版O(len · 2¹⁰ · 10)O(len · 2¹⁰)状态数是位数乘掩码数乘 free 两态

两条 dp 路线的复杂度里都只有 len，没有 n。掩码那一维是常数 2¹⁰，所以 status 版的复杂度实际写成 O(len) 也不过分，只是常数比直接乘的那版大一个量级。

九、总结

约束可以分成两类：一类是「这一位不能超过某个数」，用 free 管；一类是「这个数字之前有没有出现过」，用 status 这样的集合管。两类可以同时挂在状态里。

集合的大小决定这一维的容量。数字只有十种，status 就是一维 1024；字母是 26 种，同样的写法就要 2²⁶，那时候得换成别的记法。

能自由排的位数不要逐位递归，提前算一张「还剩 i 位、前缀已定」的表，链上每位乘一下就行。表里那个「前缀已定几位」的偏移最容易写漏，它是 10 − len + i 而不是 10 − i。

最后一件事是互补。问「至少有一位重复」时不用重写，拿总数减掉「全不重复」更快，也少一处出错的地方。
