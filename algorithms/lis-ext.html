分组与前后缀：K 递增与一次修改机会

这一页两道题都不是直接问最长递增子序列。第一道要先把数组按下标模 k 切成 k 组，第二道要先预处理出「从每个位置往右能接多长」。ends 数组还是那个 ends 数组，只是用在了另外两个切面上：一个是分组，一个是前后缀。

零、K 递增：把数组按下标切开

数组 arr 被称为 K 递增，条件是每个 i >= k 都满足 arr[i-k] <= arr[i]。一次操作可以把任意一个位置改成任意正整数，问最少改几个。

先看这个条件在说什么。它只把下标差恰好为 k 的两个位置绑在一起，于是整个数组按下标模 k 分成 k 组，组内互相关，组间毫无关系。

于是原问题变成 k 个独立的小问题：每组各自要变成不下降的，把各组的最少修改次数加起来就行。

一、改一个数等于把它从序列里拿掉

某一组有 size 个数，要让它整体不下降，最少改几个？

答案是 size - 最长不下降子序列长度。这个式子两头都要说清楚。

先说为什么够。留下一条最长不下降子序列，其余那些位置每一个都改成「它前面留下来的那个数」。改完之后整组不下降：留下的那些位置本来就单调，被改的位置又都等于前一个留下的数。改的次数正好是 size 减去留下来的个数。

再说为什么少不了。假设只改了 m 个位置，那么剩下 size − m 个位置原封不动，它们必须自己构成一条不下降子序列，所以 size − m 不会超过最长不下降子序列的长度，m 也就不会小于 size 减它。

这里有个细节：题目允许改成任意正整数，这个「任意」是上式成立的前提。要是只允许改成某个固定值，留下的序列和改出来的值之间还得再对齐，式子就不对了。

// 使数组 K 递增：按下标模 k 分成 k 组，每组改掉「不在最长不下降子序列里」的数
    int kIncreasing(int* arr, int n, int k) {
        int nums[100005], ends[100005];
        int ans = 0;
        for (int i = 0, size; i < k; i++) {
            size = 0;
            for (int j = i; j < n; j += k) {
                nums[size++] = arr[j];
            }
            int len = 0;
            for (int t = 0, find; t < size; t++) {
                find = bs2(ends, len, nums[t]);      // 不下降，用 bs2
                if (find == -1) {
                    ends[len++] = nums[t];
                } else {
                    ends[find] = nums[t];
                }
            }
            ans += size - len;
        }
        return ans;
    }

二分用的是 > 的那个版本（bs2），因为组内要的是不下降。写成 >= 的 bs1 就变成求严格递增，答案只会偏大。实测两万组随机样本：值域 V = 3 时错版答案不同的占 86.41%，V = 10 时 67.37%，V = 100 时 13.30%，V = 10⁶ 时 0%。

二、一次修改机会：先预处理 right

第二题：长度 n 的数组 arr，给定 k，只允许一次把连续的 k 个数全改成同一个值（这次机会也可以不用），问最长不下降子序列最长能有多长。

那 k 个连续的数被改成一个值 v，它们一定全都相等，所以这一段自己贡献 k 长度是稳的。剩下的问题在前缀和后缀怎么接上去：前缀要接到 <= v 的位置，后缀要从 >= v 的位置开始。

后缀这部分可以先预处理出来。定义 right[j]：一定以 arr[j] 做开头时，arr[j...] 上最长不下降子序列有多长。

怎么算？从右往左扫。倒着看的时候，「从 arr[j] 出发向右不下降」就变成了「从右往左走到 arr[j] 时不上升」，于是用一个降序的 ends 数组，找第一个 < num 的位置。

// right[j]：一定以 arr[j] 做开头时，arr[j...] 上最长不下降子序列的长度
    // 从右往左看，就变成「以 arr[i] 做结尾的最长不上升子序列」
    // ends[0..len-1] 降序，找 < num 的最左位置，不存在返回 -1
    int bsDesc(int* ends, int len, int num) {
        int l = 0, r = len - 1, m, ans = -1;
        while (l <= r) {
            m = (l + r) / 2;
            if (ends[m] < num) {
                ans = m;
                r = m - 1;
            } else {
                l = m + 1;
            }
        }
        return ans;
    }

    void buildRight(int* arr, int* right, int* ends, int n) {
        int len = 0;
        for (int i = n - 1, find; i >= 0; i--) {
            find = bsDesc(ends, len, arr[i]);
            if (find == -1) {
                ends[len++] = arr[i];
                right[i] = len;
            } else {
                ends[find] = arr[i];
                right[i] = find + 1;
            }
        }
    }

right 数组一算出来，答案就是枚举被改的那一段。

三、从左到右拼答案

被改的区间长度恒为 k，设它是 [i, j-1]，那么 j = i + k。随着 i 从 0 开始右移，j 也跟着右移。

扫描过程中 ends 维护的是「前缀 arr[0...i-1] 上的最长不下降」那一套东西。轮到某个 j 时，需要知道前缀里能接在 <= v 位置的最长长度，也就是 ends 里不超过 v 的格子有几个。

ends 是不降序的，找第一个 > v 的位置 find，答案段长度就是 find（find = -1 时是 len）。这正是 bs2 干的事。

v 取多少最好？前缀要求 <= v，后缀要求 >= v，v 取 arr[j] 恰好两边都不吃亏：前缀那边能用的格子数只增不减，后缀那边 right[j] 本身就是「以 arr[j] 开头」的长度。于是这一轮的答案就是 left + k + right[j]。

// 枚举被改的区间 [i, j-1]，长度恒为 k，改成某个值 v
    // 前缀取到 <= v 的最长不下降，后缀从 arr[j] 起，v 取 arr[j] 最优
    int compute(int* arr, int* right, int* ends, int n, int k) {
        int len = 0, ans = 0;
        for (int i = 0, j = k, find, left; j < n; i++, j++) {
            find = bs2(ends, len, arr[j]);
            left = find == -1 ? len : find;              // 前缀里 <= arr[j] 的最长长度
            ans = max(ans, left + k + right[j]);
            find = bs2(ends, len, arr[i]);
            if (find == -1) {
                ends[len++] = arr[i];
            } else {
                ends[find] = arr[i];
            }
        }
        ans = max(ans, len + k);   // 改最后一段
        return ans;
    }

循环结束后还要补一句 ans = max(ans, len + k)。它对应的是「被改的那一段在数组最末尾」：此时没有后缀，前缀长度就是整个 ends 的有效长度 len。少了这一句，所有最优解落在尾部的数据都会答错。

另外 k >= n 时整个数组都能改掉，直接返回 n。

四、复杂度分析

题目时间额外空间说明
使数组 K 递增O(n log n)O(n)k 组总长 n，每组一次扫描，每元素一次二分
一次修改机会O(n log n)O(n)right 数组一遍 O(n log n)，扫描一遍 O(n log n)

两道题的时间都是 O(n log n)，主导项是二分。实测（g++ -O2）：K 递增 n = 100000、k = 100 时 1.22 毫秒，n = 200000、k = 500 时 2.19 毫秒；一次修改机会 n = 100000、k = 33333 时 3.72 毫秒，n = 200000、k = 66666 时 8.33 毫秒。

空间上，K 递增只需要一个 ends 数组，分组的元素可以边取边处理。一次修改机会要额外开一个 right 数组，长度 n。

五、总结

两道题的思路是同一个：直接问的东西不好下手，就先把它切成能套 ends 数组的形式。

要记住的点：

1）K 递增按下标模 k 分组，组间独立；组内答案是「组大小减去最长不下降子序列长度」，这个式子依赖「可以改成任意值」。

2）二分用 > 的那个版本，因为要求的是不下降。

3）一次修改机会那题，right[j] 是从右往左用降序 ends 算出来的「以 arr[j] 开头的最长不下降」。

4）扫描结束后别漏掉 len + k，它对应改最后一段。

再往后，最长递增子序列还有一个「有多少条」的版本，那个要上树状数组，因为光靠 ends 记不住条数。
