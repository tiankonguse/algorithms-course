区间最值操作：最大值、最大值个数、严格次大值

「整段加 v」能用懒标记，是因为段里每个数的变化量都相同；「整段改成 min(v, x)」不一样，大于 x 的数掉到 x，其余的原地不动，一个标记说不清谁动了。补两个量就又能懒更新了：除了最大值，还得知道最大值有几个、严格次大值是多少。x 卡在次大值和最大值之间时，动的恰好是最大值那一批，一步改完。

零、背景

懒标记能成立，靠的是「整段里每个数受到的影响一样」。区间加满足，区间覆盖也满足（每个数都被改成同一个值）。区间取 min 一眼看上去不满足：变多少取决于这个数本身比 x 大还是小。

想一步改完，就得回答「这一段里大于 x 的数有几个、它们的和是多少」。x 每次都不一样，没法预处理出来。于是退一步，只维护三个量：最大值、最大值的个数、严格次大值。

这三个量在一种情况下够用：x 严格大于次大值。此时大于 x 的数恰好就是等于最大值的那 cnt 个，累加和减掉 (max - x) × cnt，最大值记成 x，次大值一个都没动。改完之后这一段依然自洽：新的最大值是 x，还是严格大于次大值。

反过来，一旦 x 不大于次大值，说明这一段里至少有两种不同的值要被削平，三个量描述不了结果，只能往下递归，把问题拆小。

这套剪枝配上势能分析，是吉如一在国家集训队论文里给出的结构，通常叫吉司机线段树。

一、题目

第一题，长度为 n 的数组，三种操作一共调用 m 次：

  • 操作 0 l r x：把 l 到 r 的每个数 v 更新成 min(v, x)
  • 操作 1 l r：查询 l 到 r 的最大值
  • 操作 2 l r：查询 l 到 r 的累加和

要求做到 O(n log n + m log n)。

第二题在它上面加一种操作，一共四种：操作 0 是区间加 x，操作 1 是区间取 min，操作 2 查最大值，操作 3 查累加和。

二、一个结点上装三个量

除了累加和，每个结点还要记三个：最大值 mx、最大值的个数 cnt、严格次大值 sem。只有一个数字的时候没有次大值，记成一个足够小的哨兵 LOWEST。

long long sum[MAXN << 2];
    int mx[MAXN << 2];    // 最大值
    int cnt[MAXN << 2];   // 最大值出现了几次
    int sem[MAXN << 2];   // 严格次大值，没有就记 LOWEST

    void up(int i) {
        int l = i << 1, r = i << 1 | 1;
        sum[i] = sum[l] + sum[r];
        mx[i] = max(mx[l], mx[r]);
        if (mx[l] > mx[r]) {          // 最大值在左边，右边全体都能当次大值的候选
            cnt[i] = cnt[l];
            sem[i] = max(sem[l], mx[r]);
        } else if (mx[l] < mx[r]) {   // 反过来
            cnt[i] = cnt[r];
            sem[i] = max(mx[l], sem[r]);
        } else {                      // 两边并列，个数要加起来
            cnt[i] = cnt[l] + cnt[r];
            sem[i] = max(sem[l], sem[r]);
        }
    }

    // 把整段的最大值压到 v（调用方保证 sem < v，不会颠覆次大值）
    void lazy(int i, int v) {
        if (v < mx[i]) {
            sum[i] -= (long long)(mx[i] - v) * cnt[i];
            mx[i] = v;
        }
    }

    void down(int i) {
        lazy(i << 1, mx[i]);
        lazy(i << 1 | 1, mx[i]);
    }

合并三个分支看着啰嗦，其实就一句话：最大值从哪边来，cnt 就继承哪边，另一边全体（它的最大值加上它的次大值）都有资格竞争次大值；两边相等时 cnt 相加。

void build(int l, int r, int i) {
        if (l == r) {
            sum[i] = mx[i] = arr[l];
            cnt[i] = 1;
            sem[i] = LOWEST;      // 只有一个数，没有次大值
        } else {
            int mid = (l + r) >> 1;
            build(l, mid, i << 1);
            build(mid + 1, r, i << 1 | 1);
            up(i);
        }
    }

三、setMin 的三种情形

进到一个结点，先比较 x 和最大值：x 不小于最大值，说明连最大的那个数都不用动，整段直接返回。

再看能不能一步改完：任务把这个结点全包住，而且次大值严格小于 x。这时落进前面说的那种情况，调一次 lazy 就完事。

剩下的一律往下走：要么任务只盖住一部分，要么 x 已经压到次大值上了。

void setMin(int jobl, int jobr, int jobv, int l, int r, int i) {
        if (jobv >= mx[i]) {          // 连最大值都够不着，整段一个数都不用动
            return;
        }
        if (jobl <= l && r <= jobr && sem[i] < jobv) {
            lazy(i, jobv);            // 只有最大值被削下去，次大值还在上面顶着
        } else {
            down(i);                  // 任务没全包，或者 jobv 已经压到次大值了
            int mid = (l + r) >> 1;
            if (jobl <= mid) setMin(jobl, jobr, jobv, l, mid, i << 1);
            if (jobr > mid) setMin(jobl, jobr, jobv, mid + 1, r, i << 1 | 1);
            up(i);
        }
    }

注意 lazy 里那句 if (v < mx[i])。down 会把父结点的最大值无条件发给两个孩子，孩子的最大值可能比它还大（这时不用动），也可能恰好相等（这时要削），判断交给 lazy 自己。

在 [5, 2, 9, 1, 7, 3] 上做一次 setMin(2, 5, 4)：位置 3 的 9 和位置 5 的 7 掉到 4，结果是 5、2、4、1、4、3，累加和从 27 变成 19，最大值从 9 变成 5。结点 [4, 5] 的三个量变成累加和 5、最大值 4、个数 1、次大值 1；它的两个叶子还没收到通知，位置 5 那个叶子上写的仍是旧值 7。

四、剪枝的代价怎么算

正确性来自一个不变式：lazy 只在 sem < jobv 时被调用，改完之后 mx 变成 jobv，sem 还是原来那一批值，依然满足 mx > sem。三个量前后都自洽，up 才合并得出正确的父亲。

代价靠势能分析。往下走一层，必然是因为 x 不大于次大值，这一次递归会把「这一段里不同的值的种类」往下压：改完之后，原来的最大值和次大值合并成了同一个值。种类数压到底就不用再压了，所以总下钻次数是能估出来的。

实测一次 setMin 摸到多少个结点（每次操作随机区间、随机 x，各跑两万次）：

  • n 是 1024（树高 10），平均 2.17 个，中位数 1，最多 775
  • n 是 65536（树高 16），平均 16.97 个，中位数 5，最多 58687
  • n 是 10⁶（树高 20），平均 212.28 个，中位数 7，最多 525179
  • n 是 10⁶、值域收到 10⁶，平均 207.56 个，中位数 6

中位数 7 和平均值 212 差了三十倍，原因就是势能：绝大多数操作只在根附近走几步，均值被最初那几次「把整段铺开」的下钻拉高了。

三种情形按结点访问计次（n 是 10⁶ 那一档，两万次 setMin 一共摸了 4245692 个结点）：整段无效直接返回 145832 次，命中懒更新 1964978 次，继续下钻 2134882 次。下钻和命中懒更新几乎各占一半，直接返回的只有百分之三点四，势能省掉的正是继续下钻的那一半。

值域那一行也说明问题：收到 10⁶ 之后平均只从 212.28 变成 207.56，几乎没动。访问多少结点取决于「不同的值被合并掉多少」，不取决于值本身有多大。

五、再叠一层区间加

第二题多出来的操作 0 是区间加。麻烦在于：整段加会把所有数一起抬，包括次大值，这会破坏「最大值那一批」和「其他」之间的差值关系。这时最大值不能再当懒标记用了，得把两种增量分开记。

于是每个结点挂两个标记：maxAdd 记最大值累计加了多少，otherAdd 记其他数字累计加了多少。整段加 v 时两个都加 v；取 min 命中时只有最大值往下掉，所以 maxAdd 加 jobv - mx[i]、otherAdd 加 0。

// 和第二节的 up 一样，最大值和次大值换成 long long，防止累加溢出
    void up(int i) {
        int l = i << 1, r = i << 1 | 1;
        sum[i] = sum[l] + sum[r];
        mx[i] = max(mx[l], mx[r]);
        if (mx[l] > mx[r]) {
            cnt[i] = cnt[l];
            sem[i] = max(sem[l], mx[r]);
        } else if (mx[l] < mx[r]) {
            cnt[i] = cnt[r];
            sem[i] = max(mx[l], sem[r]);
        } else {
            cnt[i] = cnt[l] + cnt[r];
            sem[i] = max(sem[l], sem[r]);
        }
    }
long long maxAdd[MAXN << 2];    // 最大值一共被加了多少
    long long otherAdd[MAXN << 2];  // 其他数字一共被加了多少

    // maxAddv 给最大值，otherAddv 给剩下的
    void lazy(int i, int n, long long maxAddv, long long otherAddv) {
        sum[i] += maxAddv * cnt[i] + otherAddv * (n - cnt[i]);
        mx[i] += maxAddv;
        sem[i] += sem[i] == LOWEST ? 0 : otherAddv;
        maxAdd[i] += maxAddv;
        otherAdd[i] += otherAddv;
    }

    void down(int i, int ln, int rn) {
        int l = i << 1, r = i << 1 | 1;
        // 拿两个孩子比出来的最大值，不能拿 mx[i]
        // mx[i] 可能已经被自己挂着的懒任务改过了
        long long tmp = max(mx[l], mx[r]);
        if (mx[l] == tmp) lazy(l, ln, maxAdd[i], otherAdd[i]);
        else              lazy(l, ln, otherAdd[i], otherAdd[i]);
        if (mx[r] == tmp) lazy(r, rn, maxAdd[i], otherAdd[i]);
        else              lazy(r, rn, otherAdd[i], otherAdd[i]);
        maxAdd[i] = otherAdd[i] = 0;
    }

down 里有个必须想清楚的地方：判断「哪个孩子是最大值」要拿两个孩子比出来的结果，不能拿 mx[i]。父结点的最大值可能已经被自己挂着的懒任务改过了，拿它去比会把不该动的孩子也标成最大值。

void add(int jobl, int jobr, long long jobv, int l, int r, int i) {
        if (jobl <= l && r <= jobr) {
            lazy(i, r - l + 1, jobv, jobv);   // 所有数字一视同仁
        } else {
            int mid = (l + r) >> 1;
            down(i, mid - l + 1, r - mid);
            if (jobl <= mid) add(jobl, jobr, jobv, l, mid, i << 1);
            if (jobr > mid) add(jobl, jobr, jobv, mid + 1, r, i << 1 | 1);
            up(i);
        }
    }

    void setMin(int jobl, int jobr, long long jobv, int l, int r, int i) {
        if (jobv >= mx[i]) {
            return;
        }
        if (jobl <= l && r <= jobr && sem[i] < jobv) {
            // 只有最大值往下掉 jobv - mx[i]，其他数字一个都不动
            lazy(i, r - l + 1, jobv - mx[i], 0);
        } else {
            int mid = (l + r) >> 1;
            down(i, mid - l + 1, r - mid);
            if (jobl <= mid) setMin(jobl, jobr, jobv, l, mid, i << 1);
            if (jobr > mid) setMin(jobl, jobr, jobv, mid + 1, r, i << 1 | 1);
            up(i);
        }
    }

在 [5, 2, 9, 1, 7, 3] 上跑一遍：先 add(1, 3, 2)，结点 [1, 3] 上记下 maxAdd 2、otherAdd 2，两个孩子都还是旧值；再 setMin(2, 5, 6)，走到 [4, 5] 时命中，它上面留下 maxAdd −1、otherAdd 0，也就是「最大值那一格减 1，其他格子不动」。走完逐位是 7、4、6、1、6、3。

六、复杂度分析

项第一题（取 min + 查 max + 查 sum）第二题（再加区间加）
建树O(n)
区间取 minO(log n) 均摊（势能分析，单次最坏 O(n)）
区间加无此操作O(log n)
区间查询O(log n)
空间O(n)：四个四倍数组O(n)：六个四倍数组

按题目上限算：第一题 n 是 10⁶，累加和用 long long、另外三个用 int，四倍数组一共约 76.3 MiB。第二题 n 是 5×10⁵，累加和、最大值、次大值和两个标记都用 long long，个数用 int，一共约 83.9 MiB。

实测耗时（g++ -O2，同一份操作跑 5 遍取最好）：第一题 n 是 10⁶、m 是 2×10⁵ 时 58.525 ms，同样规模的逐格暴力按前 2000 次操作外推要 10869.8 ms，差约 186 倍。第二题 n 是 5×10⁵、m 是 5×10⁵ 时 207.286 ms，暴力外推 19663.3 ms，差约 95 倍；m 是 2×10⁵ 时 89.817 ms。

这里要提醒一句：均摊不等于最坏。单次操作确实可能摸到 O(n) 个结点（实测最多一次摸了 833135 个），只是摊到整段操作序列上被势能吃掉了。卡时间的题要留意数据形状。

七、几种写错的样子

每组 3000 个小样本、每个样本最多 60 步，值域分 5、200、50000 三档，抓到不一致的比例：

  • lazy 里忘乘 cnt：77.00% / 74.37% / 74.43%
  • up 里次大值取 min 而不是 max：90.33% / 94.67% / 94.17%
  • up 里最大值个数取 max 而不是相加：75.90% / 75.30% / 75.73%
  • 下钻前不调 down：25.83% / 34.83% / 34.83%
  • 第二题 down 里拿 mx[i] 判断哪个孩子是最大值：90.57% / 92.67% / 92.37%
  • 第二题取 min 命中时把其他值也一起动（otherAddv 传了 jobv - mx[i]）：90.53% / 92.87% / 94.10%
  • 第二题整段加只改最大值（otherAddv 传 0）：97.07% / 97.53% / 98.03%

有几处看着像 bug，其实等价，随机数据一组都抓不到：

  • 剪枝条件写成 jobv > mx[i]（少了等号）：三档都是 0.00%。jobv 等于最大值时，lazy 里 v < mx[i] 不成立，什么都不做，和直接返回一模一样。
  • 命中条件写成 sem <= jobv：三档都是 0.00%。次大值刚好等于 jobv 时，非最大值的那些数本来就不大于 jobv，压下去也不会动它们。
  • 第二题 sem 不判 LOWEST 直接加：这一条不是等价，是崩。LOWEST 加上负数会溢出，次大值变成一个很大的数，sem < jobv 永远不成立，递归一路走到叶子下面，数组越界，进程段错误。

八、总结

区间取 min 能不能一步改完，取决于 x 是否严格大于次大值。这就逼着每个结点多记两个量：最大值的个数和严格次大值。三个量一起维护，命中时改一次 lazy，不命中就往下拆，靠势能把总代价压回 O(log n) 均摊。

第二题叠上区间加之后，最大值不再能兼任懒标记，改成 maxAdd 和 otherAdd 两条通道。down 时用两个孩子比出的最大值决定谁走哪条通道，这一步是这类写法最容易错的地方。

同样的思路换个方向就得到区间取 max：把三个量换成最小值、最小值个数、严格次小值，判断和合并都照抄这一套。

最后

一是 LOWEST 必须比所有可能出现的值都小，否则叶子结点会被继续下钻，数组直接越界。

二是 sem[i] += otherAddv 那句要跳过 LOWEST，哨兵不是数，不能参与加法。

三是 down 里判断最大值归属要用两个孩子比出来的值，用 mx[i] 是错的，而且错得很隐蔽：十次里有九次能抓到，还有一次能过。
