二分答案进阶：碎片拼接与回合限制

前三页的 f 都是「直接算」，这页三个题的 f 要先想清楚一个贪心策略：电池怎么分配、顾客怎么计数、每回合挑哪个动作。f 想歪了，二分再标准也白搭。

零、背景

「同时运行 N 台电脑」的 f 要想明白大电池和小电池的分工；「计算等位时间」的 f 要把接待人数算对，差一个 +1 答案就偏；「刀砍毒杀怪兽」的 f 每个回合要比较刀和毒哪个收益大。三个题全在 f 里藏了贪心。

一、同时运行 N 台电脑的最长时间

n 台电脑，m 块电池，第 i 块电池电量 batteries[i]。一块电池同一时刻只能给一台电脑供电，电脑随时可以换电池（换电池不损耗电量）。求 n 台电脑能同时运行的最长时间。

给定时间 t，问能不能做到：所有电脑运行满 t 分钟。核心观察在电池分类。电量 > t 的电池，一块就能顶一台电脑跑完全程 t，这种电池单独挑出来当「全程电池」，一块消耗掉一台电脑。电量 ≤ t 的电池，单块撑不满一台电脑，但换电池没有损耗，所有碎片电量可以随便拼给剩下的电脑，只要碎片总电量 ≥ 剩余电脑数 × t。

f(t) 一遍扫完：x > t 时 n--（顶一台），否则 sum += x（进碎片池）；任意时刻 sum ≥ n × t 就返回 true。以 [3,3,3]、n=2 为例：t=4 时没有电池 > 4，碎片 9 ≥ 2×4=8，能跑；t=5 时碎片 9 < 2×5=10，不能跑。答案 4。[1,2,4,7]、n=2：t=7 时电池 7 不严格大于 7，也进碎片池，碎片 1+2+4+7=14 ≥ 2×7=14，能跑，答案 7。

还有个一眼看不出的优化：当 sum > max(batteries) × n，说明答案比每块电池都大，所有电池都只能当碎片，答案直接是 sum / n，不用二分。[3,3,3]、n=2：sum=9，max×n=6，9 > 6，答案直接 9/2=4。[3,3,3,3,3]、n=3：sum=15，max×n=9，答案 15/3=5。

演示 1 · 电池分配逐块：给定时间 t，大电池顶一台电脑，小电池进碎片池

    // n 台电脑共同运行 time 分钟，能不能做到
    bool f(vector<int>& batteries, int n, long time) {
        long sum = 0;
        for (int x : batteries) {
            if (x > time) {
                n--;                             // 一块电池顶一台电脑跑全程
            } else {
                sum += x;                        // 碎片电量
            }
            if (sum >= (long)n * time) {
                return true;
            }
        }
        return false;
    }

    long maxRunTime(int n, vector<int>& batteries) {
        int mx = 0;
        long sum = 0;
        for (int x : batteries) {
            mx = max(mx, x);
            sum += x;
        }
        if (sum > (long)mx * n) {
            // 最大电池也小于答案，全是碎片，只被总量限制
            return sum / n;
        }
        long ans = 0;
        for (long l = 0, r = mx; l <= r;) {
            long m = l + ((r - l) >> 1);
            if (f(batteries, n, m)) {
                ans = m;
                l = m + 1;
            } else {
                r = m - 1;
            }
        }
        return ans;
    }

复杂度 O(m log sum)，m 是电池数。f 里 sum 是 long，n × time 也可能超 int，别省。

二、计算等位时间

n 个服务员，第 i 个服务员完成一次服务要 arr[i] 分钟。顾客 0 时刻到店，服务员一空就接下一个。你是第 w + 1 个顾客（前面还有 w 个人在排队或正在被服务），问你要等多久才轮到。

给定总时间 time，第 i 个服务员能接待多少个人？time / arr[i] 个完整服务，加上正在服务的那个，共 time / arr[i] + 1 个。所有服务员加起来就是 time 分钟内接待的总人数。你是第 w + 1 个，所以总人数 ≥ w + 1 时你已经被接待，达标。

这个 +1 特别容易漏。接待人数 = 已完成 + 正在进行的：0 时刻每个服务员都能立刻接第一个（+1 就是它），time 时刻在服务的那个也算「已经接待」。拿 [2, 3] 两个服务员验证：w=0 时答案 0（0 时刻就有空闲服务员），w=1 时答案 0（两人同时开工，第二个 0 时刻就轮到你？不，你是第 2 个，0 时刻被第 2 个服务员接待，等 0 分钟），w=2 时答案 2（前两人各占一个服务员，第 3 个要等 2 分钟的服务员做完第一个）。

f 单调不减，答案是最小达标时间。二分范围 [0, min(arr) × w]：最快的服务员 min(arr) 分钟一个，前面 w 个人全部最坏情况都压他身上，等的时间不会超过这个上界。注意 min × w 用 long，min 和 w 都到 10⁹ 量级会爆 int。

演示 2 · 等位二分逐帧：f(m) = 服务员们工作 m 分钟接待的总人数（含正在服务的）

    // 服务员工作 time，能接待的客人数（完成的 + 正在开始的都算）
    long f(vector<int>& arr, long time) {
        long ans = 0;
        for (int num : arr) {
            ans += time / num + 1;
        }
        return ans;
    }

    // 二分你要等的时间，你是第 w + 1 个客人
    int waitingTime(vector<int>& arr, int w) {
        int mn = INT_MAX;
        for (int x : arr) {
            mn = min(mn, x);
        }
        long ans = 0;
        for (long l = 0, r = (long)mn * w; l <= r;) {
            long m = l + ((r - l) >> 1);
            if (f(arr, m) >= (long)w + 1) {      // 已经接待了 w + 1 人，轮到你
                ans = m;
                r = m - 1;
            } else {
                l = m + 1;
            }
        }
        return (int)ans;
    }

复杂度 O(n log(min × w))。这题是某公司连考两个月的经典题，另一份源码里带 +1 的判定和 LeetCode 2187「完成旅途的最少时间」只差一个细节：2187 的 f 是 Σ(time / arr[i])，不加 +1，因为「完成旅途」只数已完成、不算正在进行的。两个题摆一起，+1 的意义就清楚了。

三、刀砍毒杀怪兽

怪兽 hp 血，n 个回合。第 i 回合（从 1 数）你可以二选一：刀砍，立即造成 cuts[i] 伤害；毒杀，此后每个回合造成 poisons[i] 伤害，多种毒叠加。n 个回合结束后不能再行动，但已经下的毒继续每回合扣血，直到血量耗尽。问最快第几个回合杀死怪兽。

给定 limit，问 limit 回合内能不能杀死。第 j 回合如果刀砍，立刻扣 cuts[j]；如果下毒，毒会一直持续到第 limit 回合，共 (limit - j) 次扣血，总伤害 (limit - j) × poisons[j]。每回合选收益更大的动作，伤害累计到 hp ≤ 0 就死。

动作只有前 min(n, limit) 个回合能选：limit 超过 n 时，后面回合没有新动作，只能靠毒磨。答案可以比 n 大：[1,1] 的刀、[2,2] 的毒打 hp=100，两回合的毒每回合扣 2，n=2 后继续磨，答案 27，超过回合数 2。所以二分范围要开到 [1, hp + 1]，不是 [1, n]。

单调性：limit 越大，可用回合越多、每份毒的持续回合越长，越可能杀死，答案是最小 limit。样例：cuts=[5,4,3,2,1]、poisons=[1,2,3,4,5]、hp=10，答案 3（第 1 回合刀 5、第 2 回合刀 4、第 3 回合刀 3，第 3 回合死）。

演示 3 · 回合收益逐帧：每回合在刀砍和毒杀总伤害里挑大的，累计到 hp ≤ 0

    // limit 回合内能不能杀死怪兽
    bool f(vector<int>& cuts, vector<int>& poisons, long hp, int limit) {
        int n = min((int)cuts.size(), limit);
        for (int i = 0, j = 1; i < n; i++, j++) {
            // 第 j 回合：刀砍立即扣 cuts[i]；毒杀此后每回合扣 poisons[i]
            // 到 limit 回合共扣 (limit - j) 次，取收益更大的那个动作
            hp -= max((long)cuts[i], (long)(limit - j) * poisons[i]);
            if (hp <= 0) {
                return true;
            }
        }
        return false;
    }

    // 二分死亡回合，范围 [1, hp + 1]
    int cutOrPoison(vector<int>& cuts, vector<int>& poisons, long hp) {
        int ans = INT_MAX;
        for (int l = 1, r = (int)hp + 1; l <= r;) {
            int m = l + ((r - l) >> 1);
            if (f(cuts, poisons, hp, m)) {
                ans = m;
                r = m - 1;
            } else {
                l = m + 1;
            }
        }
        return ans;
    }

复杂度 O(n log hp)。f 里 (limit - j) × poisons[j] 用 long 乘，hp 到 10⁹ 时这个乘积也可能超 int。

四、复杂度分析

题目时间复杂度额外空间f 的贪心
同时运行 N 台电脑的最长时间O(m log sum)O(1)大电池顶一台、碎片电量求和
计算等位时间O(n log(min × w))O(1)Σ(time / arr[i] + 1)，含正在服务的
刀砍毒杀怪兽O(n log hp)O(1)每回合取 max(刀伤, 毒的总持续伤)

三题都是「最小达标值」二分。f 的贪心各自成立：电池题靠「换电池无损耗」把碎片归并，等位题靠「正在服务的也算接待」，怪兽题靠「动作绑定回合、每回合取最优」。

五、总结

电池题：电量 > t 的电池顶一台电脑全程，其余碎片总电量补剩下电脑的 n × t；当 sum > max × n 时答案直接 sum / n。

等位题：f(time) = Σ(time / arr[i] + 1)，+1 是 0 时刻就能接的每一个和正在服务的每一个；范围上界 min × w，乘法用 long。

怪兽题：动作绑死回合，第 j 回合毒伤 (limit - j) × poisons[j]，每回合取 max；答案可以超过 n，范围 [1, hp + 1]。

二分答案的边界到这页够用了：范围、单调、f、二分四步，f 里要防溢出、要贪心、要小心 +1。后面遇到「求最大最小但直接算不出来」的题，先想这四步。
