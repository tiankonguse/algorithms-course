按深度分桶的子树查询

前面统计的维度是颜色。这一节换成深度：桶的下标是节点到根的层数。两道题都问「子树里指定距离上有什么」，一个要不同名字的数量，一个要表亲的个数。

一、题目4：不同名字数量

一共有 n 个节点，编号 1 到 n，给定每个节点的名字和父亲节点编号，名字是 string 类型，如果父亲节点编号为 0，说明当前节点是某棵树的头节点。注意 n 个节点组成的是森林结构，可能有若干棵树。一共有 m 条查询，每条查询 x k：以 x 为头的子树上，到 x 距离为 k 的所有节点中，打印不同名字的数量。1 ≤ n、m ≤ 10⁵。测试链接：CF246E。

把「到 x 距离为 k」翻译成深度：x 的深度是 dep[x]，那么这些节点的深度正好是 dep[x] + k。于是问题变成「子树 x 里，深度为 dep[x] + k 的节点一共有几种名字」。

统计结构就是一个数组 depSet，depSet[d] 是一个集合，装当前已经贡献的节点里深度为 d 的那些名字编号。名字先离散化成 int，集合用 unordered_set，加入是 O(1)，删除是 O(1)，查大小是 O(1)。

void addId(int deep, int id) {
        depSet[deep].insert(id);
    }

    void removeId(int deep, int id) {
        depSet[deep].erase(id);
    }

    int sizeOfDeep(int deep) {
        if (deep > n) {
            return 0;
        }
        return (int)depSet[deep].size();
    }

dfs2 的骨架还是那六步，查询挂在节点上用前向星存起来，第 5 步统一回答。森林的处理方式是：每个根各跑一次 dfs1 和 dfs2，根的父亲传 0。

void dfs2(int u, int keep) {
        for (int e = headg[u], v; e > 0; e = nextg[e]) {
            v = tog[e];
            if (v != son[u]) {
                dfs2(v, 0);
            }
        }
        if (son[u] != 0) {
            dfs2(son[u], 1);
        }
        addId(dep[u], id[u]);
        for (int e = headg[u], v; e > 0; e = nextg[e]) {
            v = tog[e];
            if (v != son[u]) {
                effect(v);
            }
        }
        for (int i = headq[u]; i > 0; i = nextq[i]) {
        	ans[ansiq[i]] = sizeOfDeep(dep[u] + kq[i]);
        }
        if (keep == 0) {
            cancel(u);
        }
    }

这里有个细节：depSet 要在 dfs1 之后才 resize，因为 n 是这时才知道深度最多到 n。另外 sizeOfDeep 里那个 deep > n 的判断不能省，查询的 k 可能大得让 dep[u] + k 越过 n。

二、题目5：表亲数量

一共有 n 个节点，编号 1 到 n，给定每个节点的父亲节点编号，父亲节点为 0 说明当前节点是某棵树的头。注意 n 个节点组成的是森林结构。一共有 m 条查询，每条查询 x k：如果 x 往上走 k 的距离没有祖先节点，打印 0；如果 x 往上走 k 的距离能找到祖先节点 a，那么从 a 往下走 k 的距离，除了 x 之外可能还有其他节点，这些节点叫做 x 的 k 级表亲，打印这个表亲的数量。1 ≤ n、m ≤ 10⁵。测试链接：CF208E。

把定义拆开看：x 的 k 级表亲，就是「x 的 k 级祖先 a」的「k 级后代」里去掉 x 自己。而 a 的 k 级后代正好是 a 的子树里深度为 dep[x] 的那些节点（dep[a] + k = dep[x]）。所以

节点 u 的 k 级表亲数量 = u 的 k 级祖先的 k 级后代数量 − 1

右边那个「k 级后代数量」正是上一题问的东西，只是把「几种名字」换成了「几个节点」。于是这一题的做法浮出水面：读入查询时先不管，用倍增表把 x 的 k 级祖先 a 算出来，把这条查询挂到 a 头上，问「a 的子树里深度 dep[x] + 0 的节点有几个」，减一就是答案。

k 级祖先用倍增表算。stjump[u][p] 是 u 往上 2^p 步到的点，dfs1 时顺手填好，查询时把 k 二进制拆开跳。

int kAncestor(int u, int k) {
        for (int p = MAXP - 1; p >= 0; p--) {
            if (k >= (1 << p)) {
                k -= (1 << p);
                u = stjump[u][p];
            }
        }
        return u;
    }

读查询的时候就把转化做完：算出 a，如果 a 是 0 说明没有这么远的祖先，答案直接是 0（连查询都不用挂）；否则把「查询结果存到第 i 条」和「要问的深度偏移 k」一起挂到 a 的查询链上。

    for (int i = 1, u, k, kfather; i <= m; i++) {
            cin >> u >> k;
            kfather = kAncestor(u, k);
            if (kfather != 0) {
                addQuestion(kfather, i, k);
            }
        }

dfs2 里第 5 步回答：depCnt[dep[u] + k]，其中 depCnt 是这一题的桶，装的是节点个数而不是名字集合。输出时减一，减出来是负数或 0 就打印 0。

void dfs2(int u, int keep) {
        for (int e = headg[u], v; e > 0; e = nextg[e]) {
            v = tog[e];
            if (v != son[u]) {
                dfs2(v, 0);
            }
        }
        if (son[u] != 0) {
            dfs2(son[u], 1);
        }
        depCnt[dep[u]]++;
        for (int e = headg[u], v; e > 0; e = nextg[e]) {
            v = tog[e];
            if (v != son[u]) {
                effect(v);
            }
        }
        for (int i = headq[u]; i > 0; i = nextq[i]) {
        	ans[ansiq[i]] = depCnt[dep[u] + kq[i]];
        }
        if (keep == 0) {
            cancel(u);
        }
    }

注意 depCnt[dep[u] + k] 里的 u 是查询挂到的那个祖先 a，而 dep[u] + k 正好等于原来那个 x 的深度，所以这一层里一定包含 x 自己，减一之后不会是负数。真正会输出 0 的情况是 k 级祖先根本不存在，那一开始就没挂查询。

复杂度分析

环节题目4 不同名字题目5 表亲数量
dfs1 + 倍增表O(n)O(n log n)
查询预处理挂链 O(m)倍增跳一次 O(m log n)
dfs2 全部调用O(n log n)O(n log n)
单次贡献 / 撤销O(1)（哈希集合）O(1)
单次查询O(1)O(1)
空间O(n)O(n log n)（倍增表）

题目 4 的 depSet 总共只会装下子树里的节点，每个节点被加进去的次数还是 O(log n) 次，所以总代价 O(n log n)。题目 5 多了一张 n × log n 的 stjump 表，空间 O(n log n)。

最后

深度桶解决的是「子树里指定距离」这一类。再往后问的是路径：两个点之间的路径上有什么。下一节两道题，一道把路径判重排回文转化成异或前缀，一道在会加边的森林上问路径第 k 小。
