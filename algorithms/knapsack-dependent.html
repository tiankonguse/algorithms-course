有依赖的背包：一组主附件的五种可能

想买打印机得先买电脑。这种「买 B 必须先买 A」的约束，让每件货物从「要或不要」变成「不要、只要主件、主件加附件一、主件加附件二、全都要」五种可能。转移方程从两行变成五行，其余部分一点没动。

零、先把物品分成主件和附件

每件商品有三个信息：价格 v、重要度 p、归属 q。q = 0 表示它自己是主件，q = 某个编号表示它是那个编号主件的附件。价格就是花费，价格乘重要度是收益，题目问总钱数 n 之内最大能拿多少收益。

题目给了两个限制，让这件事好办很多：每个主件最多两个附件，附件不会再有附件。于是「一组主件 + 它的附件」这个整体只有四种买法：只要主件、主件配附件一、主件配附件二、两个附件一起。加上「整个都不要」，一共五种。

这五种彼此互斥，也就是说每一组最多只能选其中一种。这一点很关键：它保证我们可以把一组当成一个「复合货物」来处理，而不是分别处理主件和附件。

如果主件最多有 k 个附件，可能的组合就是 2k 种，加上「都不要」是 2k + 1 种。k = 2 时是 5，这也就是这题为什么能一行一行写死五个 max。k 再大就得用内层循环枚举子集了。

一、严格位置依赖：只给主件开一行

定义 dp[i][j]：只考虑编号 1 到 i 之间的主件及其附件，花费不超过 j 时的最大收益。

这里有个下标上的麻烦。附件自己不开行，所以 i 走到一个附件编号时，dp[i] 这一行是没有内容的。解决办法是用一个变量 p 记住「上一个主件是第几号」，遇到主件时才填 dp[i]，而且填的时候读的是 dp[p] 而不是 dp[i-1]。

p 的初值是 0，对应「一件商品都没有」那一行，整行 0。填完一个主件之后把 p 更新成当前 i。最后答案取 dp[p][n] 而不是 dp[m][n]，因为 m 号商品很可能是一个附件。

// 只给主件开一行。p 记的是「上一个主件的行号」
    int dependent2d(vector<int>& v, vector<int>& p, vector<int>& q, int n) {
        int m = (int)v.size() - 1;                       // 物品编号 1~m，数组开 m+1 个位置
        vector<vector<int>> fans(m + 1);
        for (int i = 1; i <= m; i++) {
            if (q[i] != 0) fans[q[i]].push_back(i);    // i 是 q[i] 号主件的附件
        }
        vector<vector<int>> dp(m + 1, vector<int>(n + 1, 0));
        int pre = 0;
        for (int i = 1; i <= m; i++) {
            if (q[i] != 0) continue;                   // 附件不单独开行
            int f1 = fans[i].size() >= 1 ? fans[i][0] : -1;
            int f2 = fans[i].size() >= 2 ? fans[i][1] : -1;
            for (int j = 0; j <= n; j++) {
                dp[i][j] = dp[pre][j];                               // 可能性 1：整个主件都不要
                if (j - v[i] >= 0) {
                    dp[i][j] = max(dp[i][j], dp[pre][j - v[i]] + v[i] * p[i]);        // 只要主件
                }
                if (f1 != -1 && j - v[i] - v[f1] >= 0) {
                    dp[i][j] = max(dp[i][j],                                          // 主件 + 附件 1
                                   dp[pre][j - v[i] - v[f1]] + v[i] * p[i] + v[f1] * p[f1]);
                }
                if (f2 != -1 && j - v[i] - v[f2] >= 0) {
                    dp[i][j] = max(dp[i][j],                                          // 主件 + 附件 2
                                   dp[pre][j - v[i] - v[f2]] + v[i] * p[i] + v[f2] * p[f2]);
                }
                if (f1 != -1 && f2 != -1 && j - v[i] - v[f1] - v[f2] >= 0) {
                    dp[i][j] = max(dp[i][j],                                          // 主件 + 两个附件
                                   dp[pre][j - v[i] - v[f1] - v[f2]]
                                   + v[i] * p[i] + v[f1] * p[f1] + v[f2] * p[f2]);
                }
            }
            pre = i;
        }
        return dp[pre][n];
    }

二、空间压缩

和 01 背包同样的道理，dp[i] 只依赖 dp[p]，压缩成一维之后 j 从 n 降到 v[i]。压缩版反而比二维版更好写：不需要 p 这个变量，因为 j 倒着走，dp[j - 花费] 里存的天然就是「上一个主件处理完」的值。

循环的下界写 j >= v[i] 就够，也就是只判断主件买不买得起。三个附件的分支各自再判一次总花费，因为附件可能把总花费顶到 j 以上。

// 压缩成一维。j 从大到小，dp[...] 里存的还是「上一个主件结束时」的值
    int dependent1d(vector<int>& v, vector<int>& p, vector<int>& q, int n) {
        int m = (int)v.size() - 1;                       // 物品编号 1~m，数组开 m+1 个位置
        vector<vector<int>> fans(m + 1);
        for (int i = 1; i <= m; i++) {
            if (q[i] != 0) fans[q[i]].push_back(i);
        }
        vector<int> dp(n + 1, 0);
        for (int i = 1; i <= m; i++) {
            if (q[i] != 0) continue;
            int f1 = fans[i].size() >= 1 ? fans[i][0] : -1;
            int f2 = fans[i].size() >= 2 ? fans[i][1] : -1;
            for (int j = n; j >= v[i]; j--) {
                dp[j] = max(dp[j], dp[j - v[i]] + v[i] * p[i]);
                if (f1 != -1 && j - v[i] - v[f1] >= 0) {
                    dp[j] = max(dp[j], dp[j - v[i] - v[f1]] + v[i] * p[i] + v[f1] * p[f1]);
                }
                if (f2 != -1 && j - v[i] - v[f2] >= 0) {
                    dp[j] = max(dp[j], dp[j - v[i] - v[f2]] + v[i] * p[i] + v[f2] * p[f2]);
                }
                if (f1 != -1 && f2 != -1 && j - v[i] - v[f1] - v[f2] >= 0) {
                    dp[j] = max(dp[j], dp[j - v[i] - v[f1] - v[f2]]
                                       + v[i] * p[i] + v[f1] * p[f1] + v[f2] * p[f2]);
                }
            }
        }
        return dp[n];
    }

实测 P1064 的规模（m = 60 件商品，n = 3200 元）：压缩版 0.081 毫秒。这个规模二维表要 60 × 3200 个 int，其实也开得出来，但没必要。

三、把附件当独立货物会怎样

最容易犯的错是嫌麻烦，把所有商品一起丢进 01 背包里跑。这样算出来的答案一定不小于正解（正解的每一种买法在错版里都合法），但它会给出一批现实中买不到的组合。

实测两万组随机样本（商品数 1 到 6，钱数 1 到 60），错版有 19.77% 的样本答案和正解不同，平均虚高 3.99 倍。这个抓取率比 01 背包方向写反那次低，因为随机数据里附件能被选中、而主件恰好买不起的情况不算常见。

要让它现形，把这个情况单独造出来就行：电脑价格 500、重要度 4（收益 2000），打印机价格 100、重要度 5（收益 500），只给 300 元。合法的最优是 0（买不起电脑，打印机不许单买），错版会报 500。

上面那组演示数据里也有一个现成的例子：n = 20 时正解 62（电脑加两个附件，或者电脑加书柜），错版算出 86，它买的是电脑、打印机、扫描仪和图书，可图书是书柜的附件，书柜根本没买。

四、P1064 那个样例走一遍

价格 800 重要度 2 的电脑（收益 1600），带两个附件：价格 400 重要度 5（收益 2000）和价格 300 重要度 5（收益 1500）。另有书柜 400 × 3 = 1200、工作椅 500 × 2 = 1000 两个无附件主件。总钱数 1000。

电脑那一组里，「主件 + 附件一」要 1200 元，超出 1000，直接不成立；「主件 + 附件二」要 1100，也超了。所以第一步只有「只要电脑」这一种买法生效，dp[1000] 变成 1600。最后加上工作椅的 1000，得到 2200。

错版在这个样例上算出 3500，它把 400 × 5 = 2000 的附件和 300 × 5 = 1500 的附件都单独算进去了，可是那两件是电脑的附件。

五、复杂度分析

做法时间额外空间说明
枚举所有买法O(2m)O(1)m 个商品各选或不选，再检查合法性
二维表O(m · n)O(m · n)只给主件填行，附件那些行空着
空间压缩O(m · n)O(n)每个主件最多 5 次取 max，实测 0.081 毫秒

时间那栏严格说是 O(主件个数 × n × 5)，5 是每个主件的展开数。它是常数，所以写成 O(m · n)。如果每个主件最多 k 个附件，这一项变成 2k，复杂度就是 O(主件数 × n × 2k)。

空间压缩版把 m 那一维去掉了，n + 1 个 int 就够。P1064 的 n = 3200，一维表 12.8 KB，二维表 60 × 3200 × 4 字节约 0.77 MB，都不算大，但压缩版代码明显更短。

六、总结

这题的全部变化就是把「一件货物的两种可能」换成「一组货物的五种可能」，转移从两个 max 变成五个 max。

几个要记住的点：

1）附件不开 dp 行，用变量 p 记住上一个主件的行号；二维版读 dp[p][...]，最后返回 dp[p][n] 而不是 dp[m][n]。

2）五种可能彼此互斥，所以可以一组一组地刷；也正因为互斥，压缩版 j 倒着走不会互相污染。

3）每个附件分支要单独判一次总花费，循环下界只判主件是不够的。

4）把附件当独立货物是这里最常见的错法，实测 19.77% 的随机样本会现形，抓不到的时候造一个「买不起主件但买得起附件」的数据就行。
