线段树：连续区段与区间合并

区间和能懒，是因为两个子区间的和加起来就是父区间的和。问「最长的连续 1 有多长」就没这么顺：答案可能整个跨在接缝上，光知道左右两边各自多长是拼不出来的。要让合并重新成立，每个结点上得多存两个量。

零、背景

先看区间和为什么能合并。父区间的和等于左儿子的和加上右儿子的和，这条式子跟被问的区间长什么样没关系，所以懒标记、递归、查询全都照旧。

把问题换成「这一段里最长的一串连续 1 有多长」，这条式子立刻断掉。举个数：左半边是 1011，右半边是 1101。左半边自己最长 2，右半边自己最长 2，拼起来是 10111101，最长 4。第三个候选比前两个都大，而它既不属于左边也不属于右边。

想知道跨接缝那一段有多长，只需要两个信息：左半边贴着接缝的尾部连着几个 1，右半边贴着接缝的头部连着几个 1。这两个量在子结点上本来没有被维护，所以要加。加完之后，父结点的三个量都能从儿子的三个量推出来，合并这件事就重新成立了。

这条思路不只用来数 1。任何「答案可能跨过两个子区间的接缝」的题，都可以试着补这两个量，换的只是具体在数什么东西。

一、问题

序列操作（洛谷 P2572）：长度 n 的 01 数组 arr，下标从 0 开始，一共 m 次操作。

  • 操作 0 l r：把 [l, r] 上的数全改成 0。
  • 操作 1 l r：把 [l, r] 上的数全改成 1。
  • 操作 2 l r：把 [l, r] 上的数取反。
  • 操作 3 l r：问 [l, r] 上有几个 1。
  • 操作 4 l r：问 [l, r] 上连续 1 的最长子串长度。

n 和 m 都到 10⁵。区间重置和区间取反都要能懒，而「连续 1 最长」这个问法一次要牵扯到两组数，因为取反会把 0 的那组弄脏，所以结点上要存的东西比普通线段树多。

二、结点上放三个量

对某一段区间，记三个量：这一段里连续 1 的最长子串长度 len、从最左边开始连续 1 的最长前缀 pre、贴到最右边连续 1 的最长后缀 suf。数组 1 0 1 1 0 0 1 1 上，这三个量分别是 2、1、2。

取反会把 0 和 1 的角色换过来，所以连续 0 的那三个量也要存。一共六个，再加一个「这一段的 1 的个数」给操作 3 用。

const int MAXN = 100001;

    int arr[MAXN];
    int sum1[MAXN << 2];                                   // 这一段里 1 的个数
    int len0[MAXN << 2], pre0[MAXN << 2], suf0[MAXN << 2];  // 连续 0：最长子串、最长前缀、最长后缀
    int len1[MAXN << 2], pre1[MAXN << 2], suf1[MAXN << 2];  // 连续 1：同样是三个量
    int change[MAXN << 2];                                 // 这一段被整段重置成了什么
    bool hasSet[MAXN << 2];                                // 这一段挂着重置任务
    bool hasFlip[MAXN << 2];                               // 这一段挂着取反任务

    // ln、rn 是左右儿子的长度，算前缀和后缀的时候要用
    void up(int i, int ln, int rn) {
        int l = i << 1, r = i << 1 | 1;
        sum1[i] = sum1[l] + sum1[r];
        len0[i] = max(max(len0[l], len0[r]), suf0[l] + pre0[r]);
        pre0[i] = len0[l] < ln ? pre0[l] : pre0[l] + pre0[r];
        suf0[i] = len0[r] < rn ? suf0[r] : suf0[l] + suf0[r];
        len1[i] = max(max(len1[l], len1[r]), suf1[l] + pre1[r]);
        pre1[i] = len1[l] < ln ? pre1[l] : pre1[l] + pre1[r];
        suf1[i] = len1[r] < rn ? suf1[r] : suf1[l] + suf1[r];
    }

三、合并：三个候选里取最大的

父区间的 len 有三个来源：左儿子内部的、右儿子内部的、以及跨过接缝的。跨接缝那一段长度正好是左儿子的 suf 加上右儿子的 pre。三者取最大就是答案。

pre 分两种情况。如果左儿子的 len 小于左儿子的长度，说明左儿子不是整段都是 1，那么父区间的 pre 就等于左儿子的 pre。反过来，左儿子整段都是 1，父区间的 pre 就能一直伸进右儿子，等于左儿子长度加上右儿子的 pre。suf 对称。

判断「左儿子整段都是 1」的时候，代码里写的是 len0[l] < ln，而不是 pre0[l] < ln。这两种写法完全等价：pre0[l] 不会超过 len0[l]，而 pre0[l] 等于 ln 就意味着前 ln 个全是 0，也就说明 len0[l] 至少是 ln。反过来同样成立。实测两种写法跑 3000 组随机数据，返回的三元组一个数都不差。

四、取反：六个量整体换边

整段取反之后，原来的 0 变成 1、1 变成 0。所以连续 1 的三个量正好是取反前连续 0 的三个量，连续 0 的三个量正好是取反前连续 1 的三个量。sum 变成段长减它。这件事不需要看段里的任何一个具体值，在懒标记层面就能一次做完。

// 整段重置成 v，v 只有 0 和 1
    void setLazy(int i, int v, int n) {
        sum1[i] = v * n;
        len0[i] = pre0[i] = suf0[i] = v == 0 ? n : 0;
        len1[i] = pre1[i] = suf1[i] = v == 1 ? n : 0;
        change[i] = v;
        hasSet[i] = true;
        hasFlip[i] = false;      // 重置把前面挂着的取反任务一起吃掉了
    }

    // 整段取反：0 和 1 的六个量互换，和变成 n 减它
    void flipLazy(int i, int n) {
        sum1[i] = n - sum1[i];
        swap(len0[i], len1[i]);
        swap(pre0[i], pre1[i]);
        swap(suf0[i], suf1[i]);
        hasFlip[i] = !hasFlip[i];
    }

    // 重置先下发。顺序摆对，重置和取反叠在一起才不会算乱
    void down(int i, int ln, int rn) {
        if (hasSet[i]) {
            setLazy(i << 1, change[i], ln);
            setLazy(i << 1 | 1, change[i], rn);
            hasSet[i] = false;
        }
        if (hasFlip[i]) {
            flipLazy(i << 1, ln);
            flipLazy(i << 1 | 1, rn);
            hasFlip[i] = false;
        }
    }

顺序上有一处不能含糊：重置把这一段整体定死成 0 或 1，之前挂着的取反任务就没意义了，所以 setLazy 里要把 hasFlip 清掉。少了这一句，重置和取反叠在同一个结点上时会多翻一次。

实测：每档 3000 组随机操作，n 取 4、8、16、64 四档。取反时忘了把六个量互换，四档分别有 81.97%、84.93%、86.80%、88.17% 的数据答案会错；取反时忘了改 sum，四档是 82.03%、84.80%、87.47%、90.10%；重置时不清 hasFlip，四档是 51.40%、76.83%、89.57%、96.80%。第三种随 n 上升得最明显，因为段越长，重置与取反落在同一个结点上的机会越多。

五、查询时也要做一次合并

问「[l, r] 上最长的一段 1」，递归到某个结点时会碰上区间只盖住一半的情况。这时左右两边都要查，查回来的两个三元组要按同一套规则合并。

有一处细节跟 up 不一样。up 里左右儿子的长度是固定的，而查询里左半边真正被问到的可能只是它的一部分。所以 pre 的判据要把「左半边全被问到」换成「左半边被问到的部分全是 1」，被问到的长度是 mid - max(jobl, l) + 1；suf 那边是 min(r, jobr) - mid；len 那行不用改。

// 区间重置，jobv 是 0 或 1
    void update(int jobl, int jobr, int jobv, int l, int r, int i) {
        if (jobl <= l && r <= jobr) {
            setLazy(i, jobv, r - l + 1);
        } else {
            int mid = (l + r) >> 1;
            down(i, mid - l + 1, r - mid);
            if (jobl <= mid) {
                update(jobl, jobr, jobv, l, mid, i << 1);
            }
            if (jobr > mid) {
                update(jobl, jobr, jobv, mid + 1, r, i << 1 | 1);
            }
            up(i, mid - l + 1, r - mid);
        }
    }

    // 区间取反
    void flip(int jobl, int jobr, int l, int r, int i) {
        if (jobl <= l && r <= jobr) {
            flipLazy(i, r - l + 1);
        } else {
            int mid = (l + r) >> 1;
            down(i, mid - l + 1, r - mid);
            if (jobl <= mid) {
                flip(jobl, jobr, l, mid, i << 1);
            }
            if (jobr > mid) {
                flip(jobl, jobr, mid + 1, r, i << 1 | 1);
            }
            up(i, mid - l + 1, r - mid);
        }
    }

    // 区间里 1 的个数
    int querySum(int jobl, int jobr, int l, int r, int i) {
        if (jobl <= l && r <= jobr) {
            return sum1[i];
        }
        int mid = (l + r) >> 1;
        down(i, mid - l + 1, r - mid);
        int ans = 0;
        if (jobl <= mid) {
            ans += querySum(jobl, jobr, l, mid, i << 1);
        }
        if (jobr > mid) {
            ans += querySum(jobl, jobr, mid + 1, r, i << 1 | 1);
        }
        return ans;
    }

    // 区间里最长的连续 1，返回三个量：最长子串、最长前缀、最长后缀
    array<int, 3> queryLongest(int jobl, int jobr, int l, int r, int i) {
        if (jobl <= l && r <= jobr) {
            return {len1[i], pre1[i], suf1[i]};
        }
        int mid = (l + r) >> 1;
        down(i, mid - l + 1, r - mid);
        if (jobr <= mid) {
            return queryLongest(jobl, jobr, l, mid, i << 1);
        }
        if (jobl > mid) {
            return queryLongest(jobl, jobr, mid + 1, r, i << 1 | 1);
        }
        array<int, 3> L = queryLongest(jobl, jobr, l, mid, i << 1);
        array<int, 3> R = queryLongest(jobl, jobr, mid + 1, r, i << 1 | 1);
        int len = max(max(L[0], R[0]), L[2] + R[1]);
        // 左边这一段里，真正被问到的只有 mid - max(jobl, l) + 1 个位置
        int pre = L[0] < mid - max(jobl, l) + 1 ? L[1] : L[1] + R[1];
        // 右边同理，被问到的是 min(r, jobr) - mid 个位置
        int suf = R[0] < min(r, jobr) - mid ? R[2] : L[2] + R[2];
        return {len, pre, suf};
    }

这里有个容易让人不放心的点：这两处修正到底有没有用。把 pre 的判据换回整个左半边的长度、把 suf 的换回整个右半边的长度，答案一个字都不变。实测 3000 组随机查询，n 取 4、8、16、64，两种写法返回的 len 全部相同；但如果连 pre、suf 也一起比，四档分别有 34.37%、61.13%、75.17%、85.43% 的数据能看到差别。

原因在于三元组里只有两个位置会被拿去算答案。算 len 的那一行用的是左半边的后缀和右半边的前缀，左半边的前缀与右半边的后缀只往上传递、不参与任何一次取最大值。一个结点在链条上扮演的角色是固定的：它作为左半边时前缀没人用，作为右半边时后缀没人用。所以被问到的那一小段前缀算错，也传不到最终答案里去。

既然不影响正确性，随手写一时也不会出问题。但不建议。min(r, jobr) - mid 这一处如果换成整个右半边长度，一旦以后想把这个三元组拿去算别的东西，埋着的错就会冒出来。以「被问到的长度」为准来写，是对这件事本身的准确描述。

六、复杂度分析

项序列操作
建树O(n)
区间重置 / 区间取反O(log n)
问 1 的个数 / 问最长连续 1O(log n)
全程总代价O((n + m) log n)
空间O(n)：八个四倍长度的 int 数组、两个 bool 数组，再加一个存初值的数组

按 n = 10⁵ 开四倍空间：四个字节的整型数组八个、布尔数组两个，四倍长度这一部分约 12.97 MiB，再加上存初值的数组 0.38 MiB，一共约 13.35 MiB。

实测开销，g++ -O2，跑热之后取的值：n = m = 10⁵ 全部取随机小区间（长度在 1 到 n/4 之间均匀取，平均是 n 的八分之一）30.3 ms；全部取四分之一长的区间 30.9 ms；全部取 90% 长的区间 28.8 ms。三档相差不到一成，区间长短本身不是自变量，耗时看的是走到多深、碰到多少个结点。

和逐格暴力比：n = m = 10⁵、每次查询都盖满整段，线段树 0.16 ms，逐格数一遍的暴力 7608 ms，差约五万倍。整段查询在根上一步就命中，暴力的代价却仍然随区间长度线性涨。

写错的地方n = 4n = 8n = 16n = 64

取反时忘了改 sum82.03%84.80%87.47%90.10%

第一行最容易被抓住，因为它改的是结点上真会被查询读走的那三个量。第三行随 n 明显上升：段越长，一次重置和一次取反落在同一个结点上的概率越高，标记叠起来的机会就越多。

第四、五行都是 0.00%，性质却不同。第四行的三元组其实是错的（把 pre、suf 也比一遍，n = 64 时有 85.43% 的数据能看到差别），只是错的那两个位置永远不参与 len 的计算。第五行是真正的等价，连三元组都完全一致。

八、总结

「最长的连续 1」这类问题能被线段树维护，靠的是把答案拆成三份：左儿子内部的、右儿子内部的、以及跨接缝的。跨接缝那份的代价是两个额外的量，加上它们之后合并重新成立。

换别的题时骨架不变：三个量的定义换一下、合并时跨接缝的条件换一下、查询时合并的方式换一下。判断一个题能不能套这副骨架，看两点就够了：答案能不能只看三个量就定下来，以及一个区间的结果能不能和另一个区间的结果拼成合并后的结果。

这道题额外多出来的是取反。取反让 0 和 1 的角色互换，于是六个量必须成对地存在，并在取反时整体换边。写的时候把这六件事列清楚，剩下的就是普通线段树。

最后

三点。一是取反要同时做三件事：sum 改成段长减它、连续 0 和连续 1 的六个量整体互换、取反标记翻转。少任何一件都会错，前两件在八成以上的数据上立刻现形。

二是重置和取反叠在同一个结点上时，重置优先，setLazy 里必须把取反标记清掉，down 里也是先下发重置再下发取反。

三是查询合并里 pre、suf 的判据要用「被问到的长度」，而不是整个子区间的长度。这一处写错不影响本题答案，但它才是对「这一段里被问到的到底是什么」的准确描述。
