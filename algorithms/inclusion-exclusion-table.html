容斥原理与打表查询

算「恰好」很难，算「至少」往往很容易。容斥原理就是把若干个「至少」加加减减，凑出那个「恰好」。这一讲看两道需要先打一张表、再靠容斥做到 O(1) 查询的题。

零、先算宽松的，再减回去

两个集合的并集怎么数？各自数一遍，重叠的部分被算了两次，减掉一次：

|A ∪ B| = |A| + |B| − |A ∩ B|。

三个集合顺着推：单着的加一遍、两两交的减一遍、三个都交的被加了三次又减了三次，得补回来一次。

|A ∪ B ∪ C| = |A| + |B| + |C| − |A∩B| − |A∩C| − |B∩C| + |A∩B∩C|。

推广到 k 个集合，奇数个相交取加号、偶数个相交取减号，一共 2k − 1 项。题目里的 k 很小（这一讲是 4），所以枚举子集完全可行。

公式谁都会背，落到题上难的是「设计出一套能快速回答若干个集合交集数量的查询系统」。公式谁都会写，交集数量怎么 O(1) 拿到才是题眼。常见做法有两类：打一张表，每次查询在这张表上做容斥（下面两道题）；或者压根不需要查询，把容斥的式子直接化成一个公式（下一页那道题）。

一、最大公约数为 1 的子序列数量

给你一个数组，问有多少个非空子序列的最大公约数恰好是 1。n 到 105，答案对 1000000007 取模。

枚举子序列是 2n 条路，直接出局。换个问法：gcd 恰好等于 i 的子序列有多少，记成 dp(i)。

「恰好等于 i」依然不好数，但「是 i 的倍数」好数得离谱：把所有能被 i 整除的元素挑出来，它们任意组合出的非空子序列，gcd 一定是 i 的倍数。设这样的元素有 counts 个，数量就是 2counts − 1。

于是容斥就现成了：gcd 是 i 的倍数的那些子序列里，去掉 gcd 恰好是 2i、3i、4i…… 的，剩下的就是 gcd 恰好是 i 的。

dp(i) = 2counts(i) − 1 − dp(2i) − dp(3i) − dp(4i) − …

i 从大到小算，减号右边的 dp 都比 dp(i) 先算完。

// cnt[x] 是 x 出现的次数，pow2[k] 是 2 的 k 次方
    // dp[i] 是「gcd 恰好等于 i」的非空子序列数量
    long long compute(int V) {
        for (int i = V; i >= 1; i--) {
            long long counts = 0;
            for (int j = i; j <= V; j += i) {   // i 的倍数一共出现多少次
                counts += cnt[j];
            }
            dp[i] = (pow2[counts] - 1 + MOD) % MOD;   // gcd 是 i 的倍数的子序列
            for (int j = 2 * i; j <= V; j += i) {     // 容斥掉 gcd 是 2i、3i... 的
                dp[i] = (dp[i] - dp[j] + MOD) % MOD;
            }
        }
        return dp[1];
    }

counts(i) 怎么批量算？对 i 的每个倍数 j 去加 cnt(j)，一共 Σ v/i 次。v = 105 时这个和是 1166750，容斥那层再来一遍，合起来约 233 万次操作。实测 v = n = 105 的随机数据跑 3.637 毫秒。

拿 [6, 10, 15] 走一遍，三个数两两互质、三个放一起 gcd 才是 1，答案应该是 1。

两处写错的高频点。第一处是干脆不做容斥，直接拿 2counts(1) − 1 当答案，那等于「所有非空子序列」，抓取率随值域上升：V = 6 时 97.03%、V = 12 时 99.13%、V = 30 时 99.53%。第二处是容斥那层的循环从 j = i 起步，刚写进表的 2counts − 1 被自己减掉，最大的那个 i 先变成 0，接着一路往下全变成 0，最后答案也是 0，只有正确答案本来就是 0 时才碰对，抓取率 85.27%。

扩展问题「gcd 恰好是 k」也不用重做：只保留能被 k 整除的数，全都除以 k，然后当作 gcd 为 1 来算。比如 [4, 6, 8, 12]、k = 2，除完是 [2, 3, 4, 6]，答案是 6。

二、多次查询购买方法

四种硬币面值固定，每次购物给出每种硬币各带了几枚、以及这次必须花掉多少钱，问有多少种花法。查询次数到 1000。

每次查询都做一遍带限制的背包显然来不及。先忘掉限制：四种硬币无限供应，花掉 i 元的方法数记成 dp(i)，这是最基础的完全背包，一趟就填完。

现在把限制加回来。第 j 种硬币超量，意思是它至少被用了 cnt(j) + 1 枚。那先把这 cnt(j) + 1 枚的钱 value(j) · (cnt(j) + 1) 花掉，剩下的钱随便怎么花都行，方案数是 dp(s − value(j) · (cnt(j) + 1))。

四种硬币各自可能超量，超量的集合有 24 − 1 = 15 种，容斥一套就得到「至少有一种超量」的方案数，再用总数减掉它。

// 无限制的完全背包：dp[i] 是花掉 i 元的方法数
    void build(int limit) {
        dp[0] = 1;
        for (int i = 0; i <= 3; i++) {
            for (int j = value[i]; j <= limit; j++) {
                dp[j] += dp[j - value[i]];
            }
        }
    }

    // 一次查询：枚举 15 个非空子集做容斥
    long long query(int s) {
        long long illegal = 0;
        for (int status = 1; status <= 15; status++) {
            long long t = s;
            int sign = -1;
            for (int j = 0; j <= 3; j++) {
                if (((status >> j) & 1) == 1) {          // 第 j 种硬币超量
                    t -= (long long)value[j] * (cnt[j] + 1);
                    sign = -sign;                        // 奇数个 1 取正，偶数个取负
                }
            }
            if (t >= 0) {
                illegal += dp[t] * sign;
            }
        }
        return dp[s] - illegal;
    }

这里是按「超量了几枚的奇偶」定符号：子集里有奇数个 1 就加到非法量上，偶数个 1 就减掉。代码里 sign 从 −1 起步，每遇到一个 1 翻一次号，就是这个意思。

一次查询是 15 × 4 = 60 次运算，跟 s 多大没关系。实测 LIMIT = 105 建表 0.177 毫秒，接着跑 1000 次查询累计 0.0662 毫秒，单次 66 纳秒。对照四重循环枚举的暴力：s = 20 时 0.0008 毫秒、s = 60 时 0.0040 毫秒、s = 200 时 0.0827 毫秒，一路按 s 的三次方往上长，s 到 105 想都不用想。

两个数字值得记：dp(100000) = 1667116705001，早就超出 int 的上限 2147483647，这张表必须用 long long；另外 sign 写反的抓取率是 66.00%，超量门槛漏掉那个 +1（写成 cnt(j) 而不是 cnt(j) + 1）的抓取率是 41.38%。后者更隐蔽，因为它只在「刚好用完某一种硬币」的边界上现形。

三、逐帧看一遍

gcd 为 1 的子序列：从大到小逐格填表

每一格先数 i 的倍数出现了几次，拿 2 的幂算「至少」，再减掉 dp(2i)、dp(3i)…… 切版本看漏掉容斥会差在哪。

硬币购物：15 个子集逐个展开

每一格是一个非空子集，t 是扣掉超量部分后剩下的钱，t < 0 说明这个子集在当前金额下不可能出现，直接跳过。

Σi=1..v v/i = v · H(v) ≈ v · ln v，v = 105 时是 1166750，两层加起来约 233 万次操作，实测 3.637 毫秒。空间是三张 O(v) 的表，v = 105 的 long long 表约 0.8 MB。硬币那张 dp 表 LIMIT = 105 建表 0.177 毫秒，之后每次查询固定 60 次运算、与金额无关，查询次数拉到 1000 也只花 0.0662 毫秒。

总结

容斥的套路是：把「恰好」放宽成「至少」，这个量通常好算；再按子集个数的奇偶加加减减，把多算的部分扣掉。

gcd 那道题把「至少」落在 2counts − 1 上，counts 是一个数的倍数出现几次，靠枚举倍数批量算出来；减掉的是 gcd 恰好等于 2i、3i 的那些层，所以 i 必须从大到小填。

硬币那道题把「至少」落在 dp 表上：第 j 种硬币超量，等价于先花掉 value(j) · (cnt(j) + 1)，剩下的随便花，于是 15 个子集就能把非法方案数算清楚，一次查询 O(1)。

两个高频错处在两道题里是同一类：容斥那一层要么整个漏掉（gcd 题抓取率 97%~99%），要么符号写反（硬币题 66.00%）。超量门槛上的那个 +1 也别忘了，漏掉它只在边界上现形。
