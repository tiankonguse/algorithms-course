状态压缩：炮兵阵地

n 行 m 列网格里摆炮兵，攻击范围是十字型（上下左右各两格），互不攻击的前提下摆最多。m ≤ 10，每行可以压成一个二进制状态；「行内合法状态」与当前行的地形、与上两行的状态都无关，预处理数组先把全部合法状态筛出来，转移时只在这些状态里枚举，配滚动数组把空间压到两行。

零、背景

状态压缩 DP 的常见预处理：把「反复计算且与位置无关」的量提前算好。炮兵阵地的行内合法状态集合就是这种量：同一行两个炮兵列差 ≥ 3 这件事和行号、和地形都没关系，n 行都在用同一张状态表。

一、问题

n × m 的网格，P 表示可以摆炮兵，H 表示不能摆。炮兵的攻击范围是十字型：自己所在的行和列，左右、上下各两格。任何两个炮兵不能互相攻击，返回最多能摆几个。n ≤ 100，m ≤ 10。

二、每行压成一个状态

一行只有 m ≤ 10 个位置，用一个 m 位二进制数表示这一行的摆法：第 j 位是 1 表示第 j 列摆炮兵。同行两个炮兵不能互相攻击，意味着它们的列差至少是 3（攻击范围是左右两格）。合法行状态满足：任何两个 1 的位之间至少隔着两位 0。

三、预处理：DFS 生成合法状态

从第 0 列开始 DFS：这一列要么不摆（跳到下一列），要么摆（那么 j+1、j+2 列都不能摆，直接跳到 j+3）。所有合法行状态装进 sta 数组。m = 10 时一共有 60 个，行数再多也只有这 60 种要枚举。

// 预处理：DFS 生成所有"行内互不攻击"的状态
    // 同一行摆两个炮兵的列差至少是 3（攻击范围是左右各两格）
    void prepare(int j, int s) {
        if (j >= m) {            // 一行的 m 个位置都决定完了
            sta[k++] = s;        // s 是一个合法行状态
        } else {
            prepare(j + 1, s);                       // 第 j 列不摆
            prepare(j + 3, s | (1 << j));            // 第 j 列摆，j+1、j+2 不能摆
        }
    }

四、滚动数组转移

第 i 行摆法 a 会攻击到第 i-1 行的同行位置，也会攻击到第 i-2 行的同行位置，所以状态里要记住上两行。用 memo[a][b] 表示「上一行状态 a、上上行状态 b 时的最大炮兵数」，滚动更新：

// cnt(i, s)：状态 s 在 grid 的第 i 行上实际能摆的炮兵数
    int cnt(int i, int s) {
        int ans = 0;
        for (int j = 0; j < m; j++) {
            if (((s >> j) & 1) && grid[i][j] == 1) ans++;
        }
        return ans;
    }

    // 滚动数组：memo[a][b] 表示上一行状态 a、上上行状态 b 时的最大炮兵数
    int compute() {
        for (int a = 0; a < k; a++) memo[a][0] = cnt(0, sta[a]);
        for (int i = 1; i < n; i++) {
            for (int a = 0; a < k; a++) {            // 当前行状态
                int c = cnt(i, sta[a]);
                for (int b = 0; b < k; b++) {        // 上一行状态
                    dp[a][b] = 0;
                    if ((sta[a] & sta[b]) == 0) {    // 当前行与上一行不互攻
                        for (int cc = 0; cc < k; cc++) {
                            // 上上行也与这两行都不互攻
                            if ((sta[b] & sta[cc]) == 0 && (sta[a] & sta[cc]) == 0) {
                                dp[a][b] = max(dp[a][b], memo[b][cc] + c);
                            }
                        }
                    }
                }
            }
            swap(memo, dp);
        }
        int ans = 0;
        for (int a = 0; a < k; a++)
            for (int b = 0; b < k; b++)
                ans = max(ans, memo[a][b]);
        return ans;
    }

cnt(i, s) 算状态 s 在第 i 行实际能摆几个：只统计那些地形是 P 的位置。转移的三重枚举 a、b、c 分别是当前行、上一行、上上行状态，两两按位与为 0 才不互攻。

复杂度分析

合法状态数 k ≤ 60。每行转移三重枚举 a、b、c，是 O(k³) = 216000 次，乘 n = 100 行约 2 千万，能过。空间：滚动数组 memo/dp 各 k×k，O(k²)，与 n 无关。

如果把合法状态全拿去和 grid 逐行逐格检查而不预筛，复杂度不会变差，但 60 个状态是预筛后才会有的量：直接枚举 2 的 m 次方个状态，里面大多数行内就互攻，白算。预筛是省常数也是省理解成本。

总结

炮兵阵地的套路：行状态二进制化；行内合法状态用 DFS 一次生成（摆在第 j 列就跳到 j+3）；cnt 只在 P 地形上计数；转移记住上两行（memo[a][b]）并滚动。和逐格枚举比，m 维从 2^m 缩到 ≤ 60 个候选。

下一题还原数组的预处理换了一种量：把「枚举填的数字」的连续段改成前缀和，枚举从 O(m) 变 O(1)。
