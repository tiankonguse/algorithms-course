树上边差分：把标记挪到边上

点差分管点权，边权是另一套口径：标记仍然打在点上，收拢时压到孩子那条边上，lca 处从减一次变成减两次。实战两道，一道数切断边的方法数，一道把边差分包进二分答案。

零、背景

点差分收拢时，每个点把子节点的 num 并进来。边差分只改一句话：并之前，先把 num[v] 加到 v 到父亲那条边的权重上。这样每条边拿到的数，就是它被多少条路径覆盖。

一、边差分

打标：(x, y) 路径上的边全部加 v，只改三个点：

num[x] += v;  num[y] += v;  num[lca] -= 2 * v;

为什么 lca 处是两次？盯住一条边看。设边是 (p, c)，c 是 p 的儿子。这条边被路径覆盖，当且仅当 x、y 中恰有一个落在 c 的子树里。收拢之后 num[c] 等于 c 子树内标记之和，也就是 v ×（[x 在 c 子树] + [y 在 c 子树] − 2×[lca 在 c 子树]）。x、y 都在 c 子树时，lca 是它俩的公共祖先、深度不低于 c，一定也在 c 子树里，正好减成 0；恰一个在时 lca 不在，剩一个 v；lca 上方的边，x、y、lca 三个都在，也减成 0。

点差分要在 lca 与 lca 的父亲处各减一次，是因为点自己也要计数，得给 lca 留住一个 v、把 lca 上方的点清零。边差分眼里只有边，lca 这个点不参与计数，减两次就够。

代码与点差分的差别就在收拢函数里多一行：

// 树上边差分：一条路径 (u, v) 的边全部加 val，lca 处要减两个 val
    void addPath(int u, int v, int val) {
        int l = lca(u, v);
        num[u] += val;
        num[v] += val;
        num[l] -= 2 * val;
    }

    // 后序累加：边 (u, v) 被路径覆盖的次数就是子节点 v 收拢到的数
    void collect(int u, int f) {
        for (int e = head[u]; e != 0; e = nxt[e]) {
            if (to[e] != f) collect(to[e], u);
        }
        for (int e = head[u], v; e != 0; e = nxt[e]) {
            v = to[e];
            if (v != f) {
                weight[e] += num[v];
                num[u] += num[v];
            }
        }
    }

二、使图不连通的方法数

POJ 3417。n 个点，n−1 条老边连成一棵树，再额外加 m 条新边。可以切断两条边让图不连通，切的必须是一条老边加一条新边，求方法数。

切老边 e，树分成 A、B 两块。再切新边 g 之后图还不连通，等价于 g 是唯一跨 A-B 的新边，或者压根没有新边跨 A-B。新边 g 跨 A-B，说的就是 g 在树上的那条路径经过 e。所以设 k 是经过 e 的新边条数：k = 0 时切哪条新边都行，m 种；k = 1 时只能切那一条，1 种；k ≥ 2 时切掉一条还剩别的跨着，0 种。把每条新边当成一条路径做边差分，收拢时逐边读 k，累加贡献就是答案。

收拢时顺便把贡献算了：

// 使图不连通：老边被 k 条新边路径覆盖时，能配的新边数是 m、1、0
    void collect(int u, int f) {
        for (int e = head[u]; e != 0; e = nxt[e]) {
            if (to[e] != f) collect(to[e], u);
        }
        for (int e = head[u], v; e != 0; e = nxt[e]) {
            v = to[e];
            if (v != f) {
                int k = num[v];
                if (k == 0) ans += m;
                else if (k == 1) ans += 1;
                num[u] += num[v];
            }
        }
    }

漏标一个 v 会怎样？把 lca 处写成 −v（照点差分的口径抄过来），lca 上方的老边会多算一次覆盖，k 乱报。实测两万组随机小数据，这个错法 39.89% 的组答案不对。性能上边差分与点差分同阶，n = m = 10⁵ 实测 27.4ms，n = m = 3×10⁵ 实测 148.9ms。

三、运输计划

洛谷 P2680。n 个点的树，n−1 条边各带正权；m 个运输计划 (a, b)，代价是沿途边权和，计划之间互不干扰。只能把一条边的权值改成 0，让所有计划代价的最大值尽量小，求这个最小值。

二分答案。判定 limit 是否可行：先用 tarjan 顺路求出每个计划的代价与两端点的 lca，代价超过 limit 的计划就是必须照顾的一批，设它们有 beyond 个。对这些计划做一次边差分，收拢后 num[u] 是边 (父亲(u), u) 被多少个超限计划经过。要判定成功，需要找到一条边同时满足两件事：被所有超限计划经过（num[u] == beyond），并且权值不小于 maxCost − limit。

两件事各自的道理。经过所有超限计划：只要有超限计划不经过被清零的边，它的代价纹丝不动，还是超限。权值够长：代价最大的那个计划一定超限（limit 小于 maxCost 时），清零之后它要降到 limit 以下，省下的就必须有 maxCost − limit 那么多。反过来这两条也充分：每条超限计划都省下 w，新代价不超过 maxCost − w ≤ limit；没超限的计划只会更小。

判定的主体就两个函数：

// 运输计划：二分 limit，超限计划做边差分，找一条被所有超限计划共用且足够长的边
    bool check(int limit) {
        atLeast = maxCost - limit;
        for (int i = 1; i <= n; i++) num[i] = 0;
        beyond = 0;
        for (int i = 1; i <= m; i++) {
            if (cost[i] > limit) {
                num[quesu[i]]++;
                num[quesv[i]]++;
                num[lca[i]] -= 2;
                beyond++;
            }
        }
        return beyond == 0 || dfs(1, 0, 0);
    }

    bool dfs(int u, int f, int w) {
        for (int e = head[u], v; e != 0; e = nxt[e]) {
            v = to[e];
            if (v != f && dfs(v, u, weight[e])) return true;
        }
        for (int e = head[u], v; e != 0; e = nxt[e]) {
            v = to[e];
            if (v != f) num[u] += num[v];
        }
        return num[u] == beyond && w >= atLeast;
    }

忘查权值那一项会怎样？只找「被所有超限计划经过」的边，找到的往往不够长，limit 报得偏低。实测两万组随机小数据，这个错法 56.60% 的组答案偏小。整题的性能：预处理一次 tarjan 拿到全部代价，二分 log maxCost 轮，每轮重新打标加一次dfs，n = m = 3×10⁵ 实测 123.2ms。

四、复杂度分析

环节时间空间
使图不连通：m 条新边差分 + 收拢读数O((n + m) log n)O(n + m)
运输计划：tarjan 求代价与 lcaO((n + m) log n)
运输计划：二分 log maxCost 轮，每轮打标加一次 dfsO((n + m) log maxCost)

空间按题目上限算。两道题都是 n 到 3×10⁵：链式前向星正反两份边、新边或计划的链式结构、并查集、num 各一条同规模 int 数组，几十 MB 量级。递归深度仍是老问题，链上等于 n，本机 8MB 栈下 10⁵ 层能过、1.5×10⁵ 层段错误， tarjan 那种两轮递归建议直接写迭代。

五、总结

要点三条。其一，边差分与点差分的打标只差在 lca 处减一次还是减两次，差别来自「点自身算不算数」：点算数，lca 处减一次、lca 父亲处再减一次；点不算数，lca 处减两次就够。其二，收拢时把 num[v] 压到孩子边上再并入父亲，一条边被多少路径覆盖就摆在边上，这是「切断哪条边」类题目的抓手。其三，运输计划把边差分当判定用：超限计划的公共边加上足够长的权值，两个条件各自对应必要性与可行性的一半，合起来才是完整判定。

差分到这儿，点权和边权两个口径都齐了。往后遇到「路径修改、批量查询」先想差分；遇到「只改一处、问最优」先想二分加差分，二分的判定往往就是「有没有一条边同时满足两个条件」。

六、最后

三个模板背下来之后，真正花时间的是翻译。3417 的「一条老边一条新边」要翻成「老边被新边路径覆盖几次」，运输计划的「最大值尽量小」要翻成「二分 limit 加公共边判定」。翻对了，代码都是现成的。
