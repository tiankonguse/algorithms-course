从 1 到 n 里挑 k 个数：连 dp 都摆不下的构造

1 到 n 里挑 k 个数组成 A，剩下的组成 B，要求两堆的和相差不超过 1。这题长得像背包，数据量一报就装不下了：n 到 106，状态空间是 1.25×1014 个。剩下的只有一条路，把答案直接算出来。

零、题目

给两个正整数 n 和 k，1 到 n 每个数都能用。从里面挑 k 个数放进集合 A，剩下的进集合 B。

希望 A 的和与 B 的和相差不超过 1。能做到就返回 A 挑的那 k 个数（任何一种方案都算对），做不到返回空数组。

n 最大 106，k 从 1 到 n。所有数字的和是 total = n(n+1)/2，n = 106 时是 500000500000。

先说结论：最后写出来的代码里，一行 dp 都没有。

一、先算 01 背包的账

最像的做法是背包：dp[i][j] 表示前 i 个数里选若干个凑出和 j 行不行，再补一维记「选了几个」。目标是总量的一半。

把数字代进去：k 这一维 5×105，和的这一维 2.5×1011，乘起来 1.25×1014 个状态。就算每个状态只占一个 bit，也要十几 TB。

这是「数据量猜解法」里最干脆的一类：不用优化状态，不用滚动数组，这个思路整个放弃。

二、可达的和是一整段连续区间

换个角度想。从 1 到 n 里挑 k 个数，和最小是挑最小的 k 个：minK = 1 + 2 + ... + k = k(k+1)/2。

和最大是挑最大的 k 个：(n-k+1) + ... + n = minK + k(n-k)。两个极端之间差 k(n-k)。

关键观察：这两个极端之间的每一个整数都能凑出来。把当前选中的 k 个数写成递增的 x[1] < x[2] < ... < x[k]，每次找最靠右的那个还有空位的数把它加 1，和就稳定地加 1，一直到全部顶到最大值为止。

所以「哪些和可达」这个问题根本不用 dp 算：可达的和恰好是 [minK, minK + k(n-k)] 里所有整数。n 从 2 枚举到 40、k 全枚举，用恰好 k 个数的背包逐格验证过，这一段里没有断点。

题目要两堆差不超过 1，也就是 A 的和只能是 floor(total/2) 或 total/2 + 1（total 为奇数时两个都试，为偶数时只有一个）。落在这个区间里就有解，落外面就返回空数组。

顺带解释一个看起来多余的写法：代码里先试 total/2，失败了才试 total/2 + 1。因为可达和是连续的，这两个相邻的数要么都在区间里、要么都不在，唯一会分开的就是恰好卡在边界上的那一小撮 (n,k)。

实测这个「只试 floor」的写法，在 n 不超过 60 的全部 1829 组 (n,k) 里只错 1 组，0.05%。

三、怎么把和抬上去

区间的事解决了，接下来要真的造出这个集合。起点取最小的 k 个：1, 2, ..., k，和是 minK。还差

need = target - minK。

注意 need 不超过 k(n-k)。把它拆成两部分：

1）末尾若干个「顶到最大」。把最后 rs 个数换成整个数组里最大的 rs 个数，即 n-rs+1, ..., n，和一次增加 rs × (n-k)。先按 rs = need / (n-k) 取整数部分。

2）剩下的零头 rem = need % (n-k)。把中间那个还空着的数往上抬 rem，就是 mid = (k - rs) + rem。

抬完仍然严格递增：下面的左段最大是 k-rs-1，中间的 mid 至少是 k-rs，上面右段的起点是 n-rs+1，而 mid < n-rs+1 是成立的。

于是 A 就是 {1..ls} ∪ {mid} ∪ {n-rs+1..n}，其中 ls = k - rs - 1（rem 为 0 时没有中间那个数，ls = k - rs）。整个过程 O(k)。

四、代码

入口负责试两个目标值：

// 所有数字的和是 total，两堆相差不超过 1，说明 A 的和只能是 total/2 或 total/2+1
    long long total = (n + 1) * n / 2;
    vector<int> ans = generate(total / 2, n, k);
    if (ans.empty() && (total & 1) == 1) {
        ans = generate(total / 2 + 1, n, k);
    }

构造部分就是上面那三段。两个地方要留心：判断必须写在除法之前（k == n 时 n-k 是 0）；总量要用 64 位算。

// 从 1~n 里挑 k 个凑出 want，凑不出就返回空数组
    vector<int> generate(long long want, long long n, long long k) {
        long long minK = (k + 1) * k / 2;                 // 最小的 k 个：1+2+...+k
        long long range = n - k;
        if (want < minK || want > minK + range * k) {
            return {};                                    // 这一段里没有任何一个和凑得出来
        }
        if (range == 0) {                                 // k == n，只有 1~n 这一种挑法
            vector<int> all(k);
            for (int i = 0; i < k; i++) { all[i] = i + 1; }
            return all;
        }
        long long need = want - minK;                     // 比「最小的 k 个」还要多出多少
        int rs = need / range;                            // 末尾有几个被顶到最大
        int rem = need % range;
        int mid = (k - rs) + rem;                         // 中间单独贡献的那一个
        int ls = k - rs - (rem == 0 ? 0 : 1);             // 开头原样保留的个数
        vector<int> ans(k);
        for (int i = 0; i < ls; i++) { ans[i] = i + 1; }
        if (rem != 0) { ans[ls] = mid; }
        for (int i = k - 1, j = 0; j < rs; i--, j++) { ans[i] = n - j; }
        return ans;
    }

可达区间与目标点

七、写错的地方

1）从大到小贪心：能塞就塞，塞不满 k 个就当无解。这个做法在 n 不超过 60 的全部 1829 组 (n,k) 里错 65.50%。反例很好找：n = 6, k = 3 时它先拿 6 再拿 5，和已经到 11，第三个再也塞不进去，于是判无解；而 {1,3,6} 的和是 10，另一堆 11，相差正好 1，是有解的。

2）总量用 32 位算。(n+1) * n / 2 在 n = 106 时会先溢出再除二，得到 -363189984，正确答案是 500000500000。后面按这个负数去算 need，越界是轻的。

3）范围判断写在除法之后。k == n 时 n-k 是 0，先除就崩。判断挪到前面，这一支直接返回空数组，除零那一行根本走不到。

4）不做范围判断直接构造。这类写法的抓取率看着只有 0.05%，因为通过检查的那些答案是对的；它真正的问题是剩下的情况会越界写数组，判题直接崩掉。

结构校验：n 从 2 到 400、k 全枚举共 80199 组，有解的 33112 组全部满足「恰好 k 个数、互不相同、都在 1 到 n 之内、和正好是目标值」。小范围另有暴力枚举 104 组对照过。

九、总结

这道题最值得记的是停下来的位置。写 dp 之前先把状态数算出来，看到 1014 就该整条路放弃，别去想怎么把第二维压小。换成「可达的和是一段连续区间」之后，问题从「凑数」变成了「制造一个数」，O(k) 解决。

三页走到这里，同一条思路出现了三次：先把想法的表格子数算出来，再决定用哪一维做状态、换不换做法、或者干脆不写 dp。
