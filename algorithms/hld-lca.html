重链剖分求 LCA 与路径最值

上一节的路径拆分里，「处理一段」这个动作可以换成别的。换成什么都不做，链头一路跳上去就是求 LCA；换成查最大值，同样的拆分就回答路径最值。这一节看这两个。

零、背景

求 LCA 的主流写法是倍增：预处理 O(n log n)，单次 O(log n)。重链剖分顺手就能给另一种 O(log n) 的做法，预处理只有 O(n)，常数也小一圈。

更实际的一点是，剖分本来就为路径查询而做。既然 top、dep、fa 已经在手上，就没必要再维护一张倍增表。

一、把「处理一段」换成「跳过一段」

路径拆分的循环是这样的：两点链头不同时，取链头更深的那一侧，把 [dfn[top], dfn[x]] 处理掉，然后 x = fa[top[x]]。

求 LCA 时不需要这一段的信息，直接扔掉即可。循环结束的条件是两点链头相同，这时两点在同一条重链上，同一条链上的点是一条竖线，祖先关系由深度决定，浅的那个就是 LCA。

可以发现循环里比较的是链头的深度，不是点自己的深度。链头更深的那一侧，整条链都在 LCA 底下，一定可以整段扔掉。

跳的时候是 x = fa[top[x]]，一次跳过整条链。这也是它比倍增快的原因：倍增一次只跳 2 的幂步，这里一次跳一整条重链。

int lca(int a, int b) {
        while (top[a] != top[b]) {
            if (dep[top[a]] <= dep[top[b]]) {
                b = fa[top[b]];
            } else {
                a = fa[top[a]];
            }
        }

二、题目2：重链剖分解决 LCA

洛谷 P3379。n 个节点、m 次询问，给定根，每次打印 a 和 b 的最低公共祖先。n、m 不超过 5 × 10⁵。

这个规模下 O(n log n) 的预处理也是可以的，但重链剖分的预处理只有两个 dfs，代码短、常数小。单次查询 O(log n)，5 × 10⁵ 次很轻松。

三、题目3：路径最大值与累加和

洛谷 P2590。n 个节点、m 条操作，每个节点有点权。CHANGE x y 把 x 的权改成 y，QMAX x y 打印路径最大值，QSUM x y 打印路径累加和。n 不超过 3 × 10⁴，节点权值在 −30000 到 +30000。

拆路径的骨架不用动，改的是两处。一是修改从区间加变成单点修改：dfn[u] 这个位置直接改写，没有标记要发。二是线段树每个节点同时存 max 与 sum，up 的时候各并各的。

这里有个细节：权值是负的，路径最大值的初值必须是一个比所有权值都小的哨兵，不能图省事写成 0。写成 0 的话，一条全是负数的路径会输出 0。

复杂度分析

两题共用一套剖分，差别只在线段树里存了什么、以及单次操作是区间还是单点。

操作时间说明
dfs1 + dfs2O(n)求 LCA 时 dfs2 只填 top，仍是 O(n)
单次 LCAO(log n)每侧最多跨 log₂ n 条轻边，一次跳一整条重链
单点修改O(log n)线段树上一条路径，叶子改写后回溯
QMAX / QSUMO(log² n)不超过 2 log₂ n + 1 段，每段一次区间查询
空间O(n)只求 LCA 时不发 dfn，六个剖分数组共 6n；带线段树再加 4n

P3379 的 n = 5 × 10⁵，单次查询最多跳约 20 次，比倍增的 19 次预查询略少，而且没有二维数组，缓存友好。
