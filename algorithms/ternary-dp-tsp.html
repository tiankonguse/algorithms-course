三进制状压：每点最多两次的 TSP

普通 TSP 的状态位只记「去过没有」，一位二进制够用。允许每个点去两次，位上就得装 0、1、2 三个值，状态数从 2 的 n 次方变成 3 的 n 次方。n = 10 时是 59049，用两个 bit 装同样的信息是 4 的 10 次方 1048576，差 17.8 倍。

零、背景

二进制版 TSP 的状态 dp[i][s] 里，s 的第 j 位只有两种取值：去过或者没去过。这个「去过没有」是二值信息，二进制天生合适。

把限制放宽到「每个点最多到达两次」，第 j 位要记的就变成了三值信息：还能去 0 次、1 次、2 次。三进制一位正好装下。

一、问题

节点最多经过两次的 TSP。n 个地点由 m 条无向带权边连起来，任选一点出发，目标是经过所有点，最后不必回到出发点，每个点最多到达两次。返回最小总路程。n 不超过 10，m 不超过 100。

跟标准 TSP 的差别只有一句「最多两次」。它的作用是允许你借道：走到某个点不为别的，只为从它身上跨过去。

二、状态怎么装

s 的第 j 位记 j 点「还需要被访问几次」。走到 j 一次就把这一位减 1，减到 0 说明这个点不用再去了。全部位都是 0 的时候，所有点都访问过，任务完成。

终态有 2n 个：每个点最终被访问 1 次还是 2 次，都得算上。n = 10 时是 1024 个。枚举它们同样是一趟 dfs。

// 枚举「每个点都被访问过」的全部状态：第 i 位是 1 或 2
        // 1 表示这个点最终被访问 1 次，2 表示被访问 2 次
        void dfs(int i, int bit, int s) {
            if (i == n) {
                complete[size++] = s;
            } else {
                dfs(i + 1, bit * 3, s + bit);
                dfs(i + 1, bit * 3, s + 2 * bit);
            }
        }

起点在哪还不知道，所以枚举完终态还要再枚举起点，把起点那一次额度先扣掉。

三、转移

f(i, s) 的定义是：现在停在 i 点，s 里记的那些访问额度还没用完，把这些额度走完的最小代价。s 全是 0 时返回 0，什么也不用做了。

转移枚举「下一步走到哪」：如果 j 点还有额度（第 j 位大于 0），就可以走过去，用掉它一次，代价是 graph[i][j] 加上从 j 继续走完 s − 3^j 的代价。

const int INF = 0x3f3f3f3f;
        int dp[MAXN][MAXS];
        int graph[MAXN][MAXN];
        int n, m;

        // 当前停在 i 点，s 的第 k 位表示 k 点还需要被访问几次
        // 返回把 s 里记的这些访问全部走完的最小代价
        int f(int i, int s) {
            if (s == 0) return 0;
            if (dp[i][s] != -1) return dp[i][s];
            int ans = INF;
            for (int j = 0, bit = 1; j < n; j++, bit *= 3) {
                if ((s / bit) % 3 > 0) {          // j 点还有额度，下一步走到它
                    int pre = f(j, s - bit);
                    if (pre != INF && graph[j][i] != INF) {
                        ans = min(ans, pre + graph[j][i]);
                    }
                }
            }
            dp[i][s] = ans;
            return ans;
        }

        // 入口：任选起点 i，起点算访问过一次，从 complete 里减掉
        int compute() {
            int ans = INF;
            for (int k = 0; k < size; k++) {
                for (int i = 0, bit = 1; i < n; i++, bit *= 3) {
                    ans = min(ans, f(i, complete[k] - bit));
                }
            }
            return ans == INF ? -1 : ans;
        }

转移写在循环里是 f(j, s − bit) + graph[j][i]，看着像「从 j 走回 i」，其实是把加法两边调了个个儿。图是无向的，graph[j][i] 和 graph[i][j] 同一个值，两种读法都成立。

这里有个细节：s − bit 减的一定是 j 那一位的权，不是 i 的。写混了答案立刻就不对，300 张随机图上 100% 现形。

四、允许两次会短多少

每点最多一次的那个版本，要求的其实是一条哈密顿路径：每个点恰好走一次的走法。这个限制很硬，很多图上压根不存在。

放宽到两次之后，要求的变成一条覆盖所有点的最短游走。借道是允许的，于是割点多的图上差距会非常大。

本机随机生成连通图量了一遍，两次版比一次版更短的比例：

n一次版无解两次版更短
50.00%22.90%
60.00%33.70%
70.00%39.20%
80.00%45.60%

随机图连通性都不错，一次版总是有解，但代价普遍更高，n 越大越明显。星形图是另一个极端：中心连着 3 个叶子时一次版直接无解，两次版答案是 40；叶子加到 4 个，两次版也无解了，因为中心要被经过 3 次。

五、走一遍

选一张图，点「下一步」沿最优路径走。右边那排是状态 s 的各位，写的是这个点还能去几次；走过的边会加粗，当前所在的点用橙色圈出来。

走一遍：状态位与最优路径

第 3 个预设是个反例：中心连 4 个叶子，中心必须被经过 3 次才走完全部叶子，超过题目给的两次，所以两次版也返回 −1。这时候按钮会一直灰着。

六、实测

dp 表是 dp[10][59049]，590490 个 int，2.25 MB。记忆化只填到 393650 个，占 66.7%。

两种写错的方式各跑了 300 张随机图，抓取率都是 100%：s − bit 减错位置，以及 ans 初值写成 0 而不是无穷大。后者比较隐蔽，因为它在图不连通时同样给出 0，看着像个合理答案。

复杂度分析

时间 O(n2 × 3n)。状态是 (当前所在点, 剩余额度状态)，一共 n × 3n 个，每个状态枚举 n 个后继。n = 10 时是 10 × 59049 × 10 ≈ 5.9 × 106 次转移。

空间 O(n × 3n)，按题目上限 n = 10 算，10 × 59049 个 int，2.25 MB。枚举终态的 complete 数组是 2n = 1024 个 int，可以忽略。

做法时间空间
枚举所有走法（回溯）O(n!)O(n)
每点最多一次（二进制状压）O(n2 × 2n)O(n × 2n)
每点最多两次（三进制状压）O(n2 × 3n)O(n × 3n)
每点最多两次（两 bit 一格）O(n2 × 4n)O(n × 4n)

总结

状态位的取值数跟着「这一格有几种情况」走：去过没有是二值，还能去几次是三值，三进制一位就够，不必给每格分两个 bit。代价是取位从位运算变成一次除法加一次取模，换来 3n 对 4n 的状态数，n = 10 时差 17.8 倍。语义上把 s 定义成「还没走完的额度」，终止条件就落在 s 等于 0 上，转移枚举下一步去哪、扣掉那一位。三进制这一套在网格题里装的是颜色和人，在图论题里装的是次数，取位和置位两个函数一个字都不用改。
