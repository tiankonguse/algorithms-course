区间 dp：受限的划分点与配对计数

划分点的取法有讲究：合并石头里它只能每隔 k−1 个位置取一次；配对计数里，两个端点配上之后还要回头数一数内部有几个同类字符。这一页两题各挡一个坑。

零、划分点上的两种约束

接下来两道题，难点都落在转移的附加条件上。

合并石头里，一段石头最终能并成几份，是被数量关系定死的，跟你怎么切无关。于是枚举划分点时不能随便跳，只能按固定步长走，跳错一步就切出了不合法的一边。统计不同回文子序列里，端点相等时也不能直接抄子区间的答案，中间夹着几个相同的字符决定了要去掉多少，得先知道「内部最近的同字符在哪」。一边是划分点被限制，一边是端点配对之后还要多看一层。

一、合并石头

有 n 堆石头排成一排。每次把连续 k 堆并成 1 堆，代价是这 k 堆石头数之和。问把所有石头并成 1 堆的最低总代价；并不成 1 堆就返回 −1。

样例：[3, 2, 4, 1]、k = 2 得 20；[3, 5, 1, 2, 6]、k = 3 得 25。

先回答一个问题：最后能不能并成 1 堆？每次合并把堆数减少 k−1，从 n 堆减到 1 堆，一共要减少 n−1，所以必须 (n−1) % (k−1) == 0，否则直接返回 −1。这条判定把一半的工作省了。

状态：dp[l][r] 表示把 [l, r] 这一段的石头合并到不能再合并（份数已经是确定的那个值）所需的最小代价。

转移：枚举划分点 m，左段 [l, m] 并到 1 份，右段 [m+1, r] 并好，再把这条缝两边的代价加起来。关键在于 m 的步长，它每次只能跳 k−1。这样才能保证左段恰好是 1 份、右段的份数也对得上。

另外，如果 [l, r] 这一段最终能并成 1 份（条件是 (r−l) % (k−1) == 0），那最后还得把整段并一次，代价是整段的和，加上去。

步长这一步值多少，数一数枚举次数就清楚。以 n = 100 为例，每个区间里如果逐个位置试，一共要试约 16.7 万次；改成每次跳 k−1，k = 4 时降到 5.7 万次，k = 10 时只剩 2.1 万次。枚举规模从 O(n) 掉到 O(n / (k−1))。

// 每次把连续 k 堆并成 1 堆，代价是这 k 堆之和，求并成 1 堆的最低成本
    int mergeStones(const vector<int>& stones, int k) {
        int n = stones.size();
        if ((n - 1) % (k - 1) != 0) return -1;      // n-1 除不尽 k-1，永远合不成 1 堆
        vector<int> pre(n + 1, 0);
        for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + stones[i];
        vector<vector<int>> dp(n, vector<int>(n, 0));
        for (int l = n - 2; l >= 0; l--) {
            for (int r = l + 1; r < n; r++) {
                int ans = INT_MAX;
                for (int m = l; m < r; m += k - 1) { // 划分点每次跳 k-1
                    ans = min(ans, dp[l][m] + dp[m + 1][r]);
                }
                if ((r - l) % (k - 1) == 0) {        // 这一段最终能并成 1 份，加一次合并代价
                    ans += pre[r + 1] - pre[l];
                }
                dp[l][r] = ans;
            }
        }
        return dp[0][n - 1];
    }

把 m += k−1 写成 m += 1，k = 2 时看不出差别（步长本来就是 1），但只要 k ≥ 3，实测 100% 的随机数组都会算错，因为多出来的那些划分点切出的左右两边，份数根本不守恒。

二、统计不同回文子序列

给一个字符串，数一数它有多少个不同的非空回文子序列，答案对 10⁹ + 7 取模。子序列只要求字符相对顺序不变，不用连续；「不同」指内容不同。

先把问题拆开。任取区间 [i, j]，两端字符分别是 s[i] 和 s[j]。

两个字符不同时，回文子序列要么不碰 j，要么不碰 i，两者相加再减去都不碰的部分（容斥）：dp[i][j] = dp[i][j−1] + dp[i+1][j] − dp[i+1][j−1]。

两个字符相同时，情况细一层：把 s[i] 和 s[j] 当一对括号，中间任何回文子序列都能被它们包起来，外面还能单独放这两个字符。要看的是「i 右边最近的一个同字符」和「j 左边最近的一个同字符」在哪：

把 left[i]（i 左边最近的同字符）和 right[i]（i 右边最近的同字符）预处理出来，三支一眼就能分清，转移是 O(1) 的。

const int MOD = 1000000007;

    // 统计 s 里不同的非空回文子序列个数
    int countPalindromic(const string& str) {
        int n = str.size();
        vector<int> last(256, -1), left(n), right(n);
        // left[i]：i 左边最近一个和 s[i] 同字符的位置，没有就是 -1
        for (int i = 0; i < n; i++) { left[i] = last[str[i]]; last[str[i]] = i; }
        fill(last.begin(), last.end(), n);
        // right[i]：i 右边最近一个和 s[i] 同字符的位置，没有就是 n
        for (int i = n - 1; i >= 0; i--) { right[i] = last[str[i]]; last[str[i]] = i; }
        vector<vector<long long>> dp(n, vector<long long>(n, 0));
        for (int i = 0; i < n; i++) dp[i][i] = 1;
        for (int i = n - 2; i >= 0; i--) {
            for (int j = i + 1; j < n; j++) {
                if (str[i] != str[j]) {
                    dp[i][j] = dp[i][j - 1] + dp[i + 1][j] - dp[i + 1][j - 1] + MOD;
                } else {
                    int l = right[i], r = left[j];
                    if (l > r)        dp[i][j] = dp[i + 1][j - 1] * 2 + 2;   // 里面没有同字符
                    else if (l == r)  dp[i][j] = dp[i + 1][j - 1] * 2 + 1;   // 里面恰好一个
                    else              dp[i][j] = dp[i + 1][j - 1] * 2 - dp[l + 1][r - 1] + MOD;
                }
                dp[i][j] %= MOD;
            }
        }
        return (int)dp[0][n - 1];
    }

端点相同时若不看内部、直接套容斥公式（把「同色」当「不同色」处理），答案是错的。长度 2 时还看不出问题，长度 4 就错 33.9%，长度 10 错 66.4%。

三、复杂度分析

量规模说明
合并石头状态O(n²)就是普通的二维表
合并石头时间O(n³ / k)划分点步长 k−1，n=1000、k=38 时 3.65 ms
回文子序列状态O(n²)二维表；预处理 left/right 是 O(n)
回文子序列时间O(n²)每格常数次比较，n=1000 时 2.08 ms
空间O(n²)石头一份 int 表 + 前缀和；回文一份 long long 表 + 两个数组

合并石头仍然是 O(n³)，只是枚举摊到每个格子上的次数被 k−1 压下去了；回文子序列靠 left/right 把端点相同的那些格子做到 O(1)，整体就停在 O(n²)。

四、总结

  1. 合并石头先判 (n−1) % (k−1)，判完再动 dp；划分点步长必须是 k−1，否则切出的两边份数不守恒。
  2. 合并代价只在「这一段能并成 1 份」时加，条件也是 (r−l) % (k−1) == 0。
  3. 回文子序列里两端相同时要分「内部没有 / 恰有一个 / 不止一个同字符」三支，靠预处理的前驱后继判定，不能拿容斥硬套。

换个题面时，先看它落在哪一类：端点之间有关系的用配对，划分点被份数卡住的按步长跳，状态不够用的就加一维。转移的形状基本就定了。
