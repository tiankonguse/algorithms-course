前缀/后缀最值加速：粉刷房子III

相邻同色的房子组成一个街区，要把一条街恰好涂成 t 个街区。dp 枚举当前房子的颜色时，要从「所有比它小的颜色」和「所有比它大的颜色」里取最小值，这又是两段区间最值。预处理好前缀最小值和后缀最小值，枚举颜色的 O(c) 段压成 O(1) 查表。

零、背景

还原数组那题是区间求和用前缀和；这一题是区间取 min 用前缀/后缀最值。两类预处理数组形态不同，同一个思路：转移里反复枚举的连续段，预先算成一个数组元素。

一、问题

n 栋房子排成一排，每栋要涂 1..c 中的一种颜色。相邻两栋同色算同一个街区，街区编号按位置从左到右。有些房子已经涂好了（house[i] 非 0），没涂的每栋涂颜色 v 要花 cost[i][v]。返回把整条街涂成恰好 t 个街区的最小花费，做不到返回 -1。n ≤ 100，c ≤ 20，t ≤ n。

二、状态设计

从左往右涂。决定第 i 栋房子时，街区数是否 +1 取决于第 i-1 栋的颜色，所以状态要带「前一栋的颜色」。用 dp[j][v] 表示「1..i 栋房子凑出 j 个街区，且第 i+1 栋的颜色是 v」的最小花费。v 是右侧邻居的颜色而不是自己，这样第 i 栋涂色时，街区数 j 里还没算上「第 i 栋和第 i+1 栋是否同色」这一刀。

v = 0 是「右侧虚拟房」：第 i+1 栋不存在时用它占位。最后答案是 dp[t][0]：右侧没有真实邻居，虚拟房和它不同色，自动多算一个街区，所以主循环前 t 先加 1。

三、朴素转移

第 i 栋房子涂色 v：

  • 如果 house[i] 已定且等于 v，继承 memo[j][v]（和右侧同色，街区数不变）或 memo[j-1][v]（不同色，开新区）里的较小值。
  • 如果没定，颜色 v 的花费来自三段：所有比 v 小的颜色（开新区）、所有比 v 大的颜色（开新区）、以及自身颜色 v（和右侧同色，街区数不变）。前两段是区间 min。

对每个 (j, v) 枚举颜色，单格 O(c)，总 O(n·t·c)。c ≤ 20 其实也能过，但预处理后总复杂度降到 O(n·t·c)，数据范围放大后同样成立。

四、前缀/后缀最值预处理

注意 cost 只对未涂色的房子累加，已涂色房子没有花费。每层每格重建两张表：

// 预处理：pre[s] 是 dp[i-1][j-1][1..s] + cost[i][1..s] 的最小值
    //         suf[s] 是 dp[i-1][j-1][s..c] + cost[i][s..c] 的最小值
    // 枚举颜色 color 的 O(c) 段被这两张表拆成 O(1) 查询
    void build(int i, int j) {
        pre[0] = suf[c + 1] = NA;
        for (int v = 1; v <= c; v++) {
            pre[v] = pre[v - 1];
            if (memo[j - 1][v] != NA) {
                pre[v] = min(pre[v], memo[j - 1][v] + cost[i][v]);
            }
        }
        for (int v = c; v >= 1; v--) {
            suf[v] = suf[v + 1];
            if (memo[j - 1][v] != NA) {
                suf[v] = min(suf[v], memo[j - 1][v] + cost[i][v]);
            }
        }
    }

主流程（n 栋房子 + 虚拟房，j 的上限 t 已经加过 1）：

int compute() {
        for (int v = 0; v <= c; v++) memo[0][v] = dp[0][v] = NA;
        for (int j = 1; j <= t; j++)
            for (int v = 0; v <= c; v++)
                memo[j][v] = (j == 1 ? 0 : NA);
        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= t; j++) {
                build(i, j);                        // 每一层重建前缀/后缀最值
                for (int v = 0; v <= c; v++) {      // v 是 i+1 号房的颜色
                    int ans = NA;
                    if (house[i] != 0) {
                        if (house[i] == v) ans = memo[j][house[i]];
                        else ans = memo[j - 1][house[i]];
                    } else {
                        if (v == 0) ans = suf[1];   // 右侧虚拟房，必开新区
                        else {
                            ans = min(pre[v - 1], suf[v + 1]);
                            if (memo[j][v] != NA) ans = min(ans, memo[j][v] + cost[i][v]);
                        }
                    }
                    dp[j][v] = ans;
                }
            }
            swap(memo, dp);
        }
        return memo[t][0];
    }

复杂度分析

朴素 O(n·t·c²)，优化后每层对每个 j 建两张长度 c 的表（O(c)），再对每个 v 查表（O(c)），总 O(n·t·c)。空间 memo/dp 各 (t+1)×(c+1)，O(t·c)。

总结

这一题的状态比直觉多一个维度：dp[j][v] 记的是「第 i+1 栋的颜色 v」，让第 i 栋的街区数变化当场可判；v = 0 的虚拟房统一了「最右边没有邻居」的情况，代价是 t 预先 +1。加速部分和还原数组对称：那次区间求和，这次区间取 min，都是 pre/suf 数组。

最后一题挖砖块换了个更隐蔽的预处理：转移枚举的是「上一列挖几块」，预处理列的后缀最大值把这段枚举也压掉，还顺带压缩了空间。
