删一条边加一条边，让重心只剩一个

一棵树允许有两个重心，中间那条边把树分成两半。现在允许先删一条边、再加一条边，要求改完还是一棵树、并且重心唯一。单重心时把重心的某条边删掉再加回来就行，双重心时把一侧的一个叶子摘下来，挂到另一侧的重心上。

零、背景

先回顾两个重心长什么样。两个重心一定相邻，把它们之间那条边剪断，两侧各有 n/2 个点，n 必然是偶数。两侧点数相等，所以两个点都刚好满足「每块不超过一半」。

要把重心变成一个，用不着把树改得面目全非：让其中一侧少掉一个点、另一侧多掉一个点，多出来那一侧的重心就单独达标了。

一、问题

删增边使其重心唯一：一棵 n 个点的树，先删一条边，再加一条边，改完仍是树，且重心唯一。打印两行，第一行是删掉的那条边的两个端点，第二行是加上的那条边的两个端点。有多解时打印任意一组。3 ≤ n ≤ 10⁵，多组数据。

题目保证一定有解，这一点值得留意：n = 2 时两个点互为重心，删掉唯一那条边之后只能再加回来，永远还是两个重心，所以下界是 3。

二、单重心：删一条再加回同一条

重心本来就只有一个时，最简单的事就是不做改变：删掉重心连着的任意一条边，再把这条边原样加回去。树一个字节都没变，重心当然还是唯一的那一个。代码里取 to[head[center]]，也就是重心邻接表里的第一个邻居。

实测 2473 组单重心的随机树（n 取 4 到 20），这么处理 100% 保持重心唯一。

换个做法就没这么稳了：同样是这些树，随机删一条边、再随机跨两侧加一条别的边，只有 88.80% 保持唯一，剩下 11.20% 会把唯一的重心变成两个。相比之下「删了再加回同一条」既省事又稳。

三、双重心：摘一个叶子挂到对面

设两个重心是 a 和 b。做法：从 b 出发、不许走回 a，一路扎到某个叶子 leaf（顺带记下它的父亲），把 leaf 从父亲那里摘下来，改挂到 a 上。

为什么这样一定行。原来 a、b 两侧各 n/2 个点。摘掉 leaf 之后，b 侧剩 n/2 − 1 个点，leaf 落单；把 leaf 挂到 a 上，a 侧变成 n/2 + 1 个点。新树上重新数一遍：

1）a 的各个方向：b 方向是 n/2 − 1，leaf 方向是 1，其余儿子方向都装在这 n/2 + 1 个点里且不超过 n/2 − 1。最大的是 n/2 − 1，小于一半，a 是重心。
2）b 朝 a 的那一块是 n − (n/2 − 1) = n/2 + 1，超过一半，b 出局。
3）任何别的点 x，它朝 a 的那一块至少是 n/2 + 1（整个 a 侧加上 leaf），也超过一半，全部出局。

于是 a 成了唯一重心。这里还顺手解释了题目为什么要求 n ≥ 3：n = 4 起 b 侧才有一个 b 之外的叶子可摘，n = 2 时 b 侧就它孤零零一个点，摘无可摘。

四、代码

找重心那趟 dfs 和上一页「教父」那一份完全一样，把每个点的 maxsub 留下来：

// 这一次不急着挑，把每个点的答案留在 maxsub 里
    void dfs(int u, int f) {
        sz[u] = 1;
        maxsub[u] = 0;
        for (int e = head[u], v; e != 0; e = nxt[e]) {
            v = to[e];
            if (v != f) {
                dfs(v, u);
                sz[u] += sz[v];
                maxsub[u] = max(maxsub[u], sz[v]);
            }
        }
        maxsub[u] = max(maxsub[u], n - sz[u]);
    }

找叶子只要「一路扎到底」，不许走回父亲，遇到没有别的边可走的点就记下来：

// 从 u 出发、不许走回 f，一路扎到第一个叶子
    // 哪一组都行，我们只要「某个叶子和它的父亲」
    void find(int u, int f) {
        for (int e = head[u]; e != 0; e = nxt[e]) {
            if (to[e] != f) {
                find(to[e], u);
                return;
            }
        }
        leaf = u;
        leafFather = f;
    }

主流程按重心个数分两支：

// 返回重心的数量，顺手把重心填进 centers
    int centerCnt() {
        int m = 0;
        for (int i = 1; i <= n; i++) {
            if (maxsub[i] <= n / 2) {
                centers[m++] = i;
            }
        }
        return m;
    }

    // 只有一个重心：删掉它的一条边，再把这条边加回来
    // 有两个重心：把第二个重心那侧的一个叶子摘下来，挂到第一个重心上
    if (centerCnt() == 1) {

        printf("%d %d\n", centers[0], to[head[centers[0]]]);
    } else {
        find(centers[1], centers[0]);
        printf("%d %d\n", leafFather, leaf);
        printf("%d %d\n", centers[0], leaf);
    }

五、加边接错一侧会怎样

最容易写错的是第二行：把 leaf 接回了它原来那一侧重心 b。删边之后 leaf 是孤立的，把它接回 b，等于原样把树拼回去，两个重心一个没少。

实测 2000 组「两棵等大的树连一条边」构造出来的双重心样本：把 leaf 接回 b 时 2000 组全部不合格；删掉 a、b 之间那条边再加回来，也是 2000 组全部不合格。

反过来，从哪一侧找叶子倒真的无所谓：同样 2000 组里，改成从 a 那侧摘叶子、挂到 b 上，0 组失败。两侧结构对称，选哪边都能达到「一边少一个、一边多一个」的效果，条件是接回对面那个重心。

复杂度分析

一趟 dfs 求 sz 与 maxsub，一趟扫描数重心，双重心时再多走一趟找叶子，都是 O(n)。

环节时间空间
dfs 求 sz 与 maxsubO(n)O(n)
扫一遍数重心O(n)
双重心时找叶子O(n)
合计O(n)

空间按题目上限 n = 10⁵ 算：head 100001 个 int 约 0.4 MB，nxt、to 各 200002 个共约 1.6 MB，sz、maxsub 各 100001 个约 0.8 MB，合计不到 3 MB。centers 开两个就够，重心最多两个。

总结

要点三条。其一，单重心时删掉它的一条边再加回同一条，树没变、重心照旧唯一，2473 组实测 100% 成立，而随机改别的边有 11.20% 会破坏唯一性。其二，双重心时从另一侧摘一个叶子挂到这个重心上，一侧少一个、一侧多一个，新重心唯一落在接的那一侧，2000 组构造样本全部通过。其三，加边必须接到对面那个重心上，接回原来那一侧等于把树拼回原样，2000 组全部不合格。

n ≥ 3 这个下界卡得很准：n = 2 时两侧各一个点，没有叶子可摘，这道题在这个规模上无解。

六、最后

这道题本身不难，难在看出「两个重心相差的只是一个点」。把那个点从一侧搬到另一侧，两边的大小关系立刻分出胜负，重心就唯一了。这种「差一个点就分出胜负」的手感在树上问题里反复出现，点分治挑重心时也在用同一份直觉。
