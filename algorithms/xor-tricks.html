异或运算的巧用

异或就是无进位加法：同一位上两个 1 相加，结果 0，进位丢掉。这一讲从六个问题看它怎么用：交换两个数、不用比较求最大值、找缺失的数字、找出现奇数次的数、找出现少于 m 次的数。

零、背景

先看一个袋子问题。袋子里 a 个白球、b 个黑球，每次拿 2 个，按规则放回 1 个：拿 2 白或 2 黑就放 1 白，拿 1 白 1 黑就放 1 黑。拿到最后一定只剩 1 个球。问最终是黑球的概率，用 a、b 表达。

答案干脆得吓人：黑球数为偶数，最终是白球，概率 100%；黑球数为奇数，最终是黑球，概率 100%。跟白球数量一点关系都没有。

这题是陷阱，但陷阱底下埋着真东西：黑球数量的奇偶性从头到尾不变。这个性质就是异或。

一、异或运算的性质

异或（^）有四条性质，第 1 条是根，其余都能从它推出来：

1）异或就是无进位相加。同一位相加，1 和 1 得 0，进位丢掉，所以也叫按位异或。

2）满足交换律、结合律。同一批数，不管以什么顺序异或，结果都一样。这直接由「逐位无进位相加」得到：每一位的结果只依赖这一位上有奇数个还是偶数个 1。

3）0 ^ n = n，n ^ n = 0。前者是加 0 不动，后者是同一位两个 1 抵消成 0。

4）整体异或和是 x，其中一部分的异或和是 y，剩下那部分的异或和就是 x ^ y。这条由 2）、3）推出，是出题最多的一条，区间上异或和的问题全靠它。

性质 3 是后面所有题的工作台：一个数异或自己两次，等于没出现过。偶数次出现的数在整体异或里全部消失，只留下奇数次的那个。

二、黑白球：黑球数的奇偶性不变

回头看袋子问题。三种拿法对黑球数量的影响：

拿 2 个白球，放 1 个白球：黑球数不变。拿 2 个黑球，放 1 个白球：黑球数减 2。拿 1 白 1 黑，放 1 个黑球：黑球数减 1 加 1，还是不变。

黑球数量的变化只有 0 和 -2，全是偶数。奇偶性钉死不动。最后只剩 1 个球，黑球数是 0（偶数）就是白球，是 1（奇数）就是黑球。所以 b 是偶数，最终必为白；b 是奇数，最终必为黑。白球数量的变化不影响结论，它可以是任意值。

写了个模拟程序验证：十组 (a, b) 组合各跑 5000 次随机拿球，结果和结论完全一致，b 偶的组 5000 次全白，b 奇的组 5000 次全黑。这种「某种量只按偶数步变化」的思路，和异或消去的道理是同一个：变化偶数次就回到原点。

三、交换两个数

不用第三个变量交换两个数，三步异或：

a = a ^ b；b = a ^ b；a = a ^ b。

展开看：第一步后 a 存的是 a^b。第二步 b = (a^b)^b = a，b 拿到了原来的 a。第三步 a = (a^b)^a = b，a 拿到了原来的 b。每一步都靠「异或同一个数两次就消失」。

这里有个细节：数组版交换 arr[i] 和 arr[j] 时，如果 i == j，第一步就把 arr[i] 异或成 0，后面两步救不回来。实测 swap(arr, 0, 0) 之后 arr[0] 变成 0。所以这种写法知道即可，工程里用 std::swap，它内部处理了这种边界。

// 变量版：三步异或，不借第三个变量
    void SwapVal(int& a, int& b) {
        a = a ^ b;
        b = a ^ b;
        a = a ^ b;
    }

    // 数组版：i 和 j 相同会把自己异或成 0，所以知道即可，不推荐用
    void SwapArr(int arr[], int i, int j) {
        arr[i] = arr[i] ^ arr[j];
        arr[j] = arr[i] ^ arr[j];
        arr[i] = arr[i] ^ arr[j];
    }

四、不用比较求最大值

要求不用任何判断语句和比较操作，返回两个数的最大值。先造两个小工具：flip(n) 把 0 变 1、1 变 0；sign(n) 取符号位，非负返回 1，负数返回 0。

第一版思路：c = a - b，c 非负说明 a 大，c 为负说明 b 大。returnA = sign(c)，returnB = flip(returnA)，答案 = a * returnA + b * returnB。c 非负时 returnA = 1 选 a，c 为负时 returnB = 1 选 b。

这版有坑：a - b 会溢出。实测 GetMax1(INT_MIN, INT_MAX)：c 溢出成 1，sign 判成非负，返回了 a，也就是 INT_MIN，正确答案是 INT_MAX。拿 12 组边界对（含 INT_MIN/INT_MAX、INT_MAX/INT_MIN、0/INT_MIN 这类）测，4 组出错，错的全是 a - b 超出 int 范围的组合。值域 ±10⁵ 的随机 3000 组反而不错，因为碰不到溢出。

第二版处理溢出：先记 sa、sb 是 a、b 自己的符号，sc 是 c 的符号。diffAB = sa ^ sb，符号不一样时取 1。符号不一样时，a - b 不可能溢出：同号做差，差的绝对值不超过两个数绝对值的较大者，还在 int 里。所以符号不同，直接看 sa 就能定：sa = 1 说明 a 非负、b 为负，a 大。符号相同，a - b 才可能溢出，这时看 sc。

returnA = diffAB * sa + sameAB * sc：diffAB = 1 时取 sa，sameAB = 1 时取 sc。实测这版 3012 组（含全部边界）全对。

// n 必须是 0 或 1：0 变 1，1 变 0
    int Flip(int n) {
        return n ^ 1;
    }

    // 非负数返回 1，负数返回 0
    int Sign(int n) {
        return Flip((uint32_t)n >> 31);
    }

    // 有溢出风险的版本：c = a - b 溢出了，符号位就不可信
    int GetMax1(int a, int b) {
        int c = a - b;
        int returnA = Sign(c);
        int returnB = Flip(returnA);
        return a * returnA + b * returnB;
    }

    // 没有问题的版本：符号不一样时看 a 的符号，一样时看 c 的符号
    int GetMax2(int a, int b) {
        uint32_t c = (uint32_t)a - (uint32_t)b;
        int sa = Sign(a);
        int sb = Sign(b);
        int sc = Flip(c >> 31);
        int diffAB = sa ^ sb;
        int sameAB = Flip(diffAB);
        int returnA = diffAB * sa + sameAB * sc;
        int returnB = Flip(returnA);
        return a * returnA + b * returnB;
    }

五、找到缺失的数字

数组长度 n，装着 [0, n] 里缺了一个之后的数。要找出缺的是谁。

把两边的数全异或起来：eorAll 异或 0 到 n 的全部整数，eorHas 异或数组里的数。出现两次的数在两边各出现一次，异或抵消，只有缺失的那个数只在 eorAll 里出现一次，答案就是 eorAll ^ eorHas。

不用额外空间，一趟 O(n) 扫完。异或在这里替代了「集合差」：两边都有的元素成对消掉，单出来的就是要找的。

// nums 是 [0, n] 里缺了一个数之后的样子，长度是 n
    int MissingNumber(int nums[], int n) {
        int eorAll = 0, eorHas = 0;
        for (int i = 0; i < n; i++) {
            eorAll ^= i;      // 0 ^ 1 ^ ... ^ (n-1)
            eorHas ^= nums[i];
        }
        eorAll ^= n;          // 补上最后一个数 n
        return eorAll ^ eorHas;
    }

六、一种数出现奇数次

数组里只有一种数出现奇数次，其余都出现偶数次，返回出现奇数次的数。

全部异或一遍。偶数次出现的数两两抵消，剩下的就是那个奇数次的数。三行代码，时间 O(n)，空间 O(1)。

这个结论值得单独确认一次：五百万个随机数整体异或，实测 0.51 毫秒。异或一趟的代价低到可以忽略，后面几题都建立在「扫一遍异或」这个动作上。

// 一种数出现奇数次，其余都出现偶数次，返回出现奇数次的数
    int SingleNumber(int nums[], int n) {
        int eor = 0;
        for (int i = 0; i < n; i++) {
            eor ^= nums[i];
        }
        return eor;
    }

七、两种数出现奇数次

数组里有两种数出现奇数次，其余都出现偶数次，要同时返回这两种数。

全部异或一遍，得到 eor1 = a ^ b。a 不等于 b，所以 eor1 至少有一位是 1。这一位在 a、b 里一个是 1 一个是 0，正好把 a、b 区分开。

怎么取这一位？Brian Kernighan 算法：rightOne = eor1 & (-eor1)，提取出二进制里最右侧的 1。原理是取反加一之后，低位的 0 全变成 1，只有最右侧那个 1 的位置上两边都是 1。

按 rightOne 把数组分成两组：这一位是 0 的一组，是 1 的一组。a、b 必然分在不同组，偶数次出现的数在同一组内还是成对出现，两组各自异或，分别得到 a 和 b。b 也可以直接算：eor1 ^ a。

拿 {1, 2, 3, 4, 5, 1, 3, 5} 走一遍：eor1 = 2 ^ 4 = 6，二进制 110，rightOne = 2，二进制 010。这一位是 0 的组是 {1, 4, 5}，异或得 4；是 1 的组是 {2, 3}，异或得 2。答案 4 和 2，正好是出现奇数次的两种数。

// 两种数出现奇数次，其余都出现偶数次，把这两种数放进 a、b
    void SingleNumbers(int nums[], int n, int& a, int& b) {
        int eor1 = 0;
        for (int i = 0; i < n; i++) {
            eor1 ^= nums[i];       // 异或完全部，剩下 a ^ b
        }
        // Brian Kernighan：提取二进制里最右侧的 1
        unsigned int rightOne = (unsigned int)eor1 & (-(unsigned int)eor1);
        int eor2 = 0;
        for (int i = 0; i < n; i++) {
            if (((unsigned int)nums[i] & rightOne) == 0) {
                eor2 ^= nums[i];   // 这一位是 0 的那一组
            }
        }
        a = eor2;
        b = eor1 ^ eor2;
    }

八、一种数出现少于 m 次

数组里只有一种数出现次数少于 m 次，其余都恰好出现 m 次，返回出现次数少于 m 次的数。m 是任意正整数，m = 3 就是 LeetCode 137。

异或只在 m = 2 时好使，m 不等于 2 时偶数次消不掉。换个思路：统计每一位上 1 的个数。出现 m 次的数，在每一位上贡献的 1 的个数是 m 的倍数（每一位都要么贡献 0 个要么贡献 m 个）。全部数统计完，某一位上 1 的总数模 m 不等于 0，说明少于 m 次的那个数在这一位上是 1。

所以开一个 32 长度的 cnts 数组，cnts[k] 记第 k 位上有多少个 1，扫完对 m 取模，余数非零的位在答案里置 1。

拿 m = 3 举个例子，数组 [3, 3, 1, 3, 1, 2, 2, 2]：3 出现 3 次，2 出现 3 次，1 出现 2 次，答案应该是 1。统计每一位：第 0 位上 1 的个数是 5（三个 3 各 1 个，两个 1 各 1 个），5 模 3 余 2，答案第 0 位置 1；第 1 位上 1 的个数是 6（三个 3 各 1 个，三个 2 各 1 个），6 模 3 余 0，不置位。答案 1，正确。

通用方法实测过 m = 3 和 m = 4，各 2000 组和 1000 组随机数据对拍全通过。复杂度 O(32n)，常数是 32，但空间只有 32 个 int。

// 只有一种数出现次数少于 m 次，其余都出现 m 次，返回那种数
    int FindLessM(int arr[], int n, int m) {
        int cnts[32] = {0};          // cnts[k]：第 k 位上 1 的个数
        for (int i = 0; i < n; i++) {
            for (int k = 0; k < 32; k++) {
                cnts[k] += (arr[i] >> k) & 1;
            }
        }
        int ans = 0;
        for (int k = 0; k < 32; k++) {
            if (cnts[k] % m != 0) {
                ans |= 1 << k;
            }
        }
        return ans;
    }

六道题全是一趟扫描，额外空间都是常数。区别只在扫的时候做了什么：异或消去，符号判断，还是逐位计数。

十、总结

这一讲的六个问题，共用一套「异或消去」的思路，几个要点：

第一，异或是无进位相加，逐位独立，所以同一批数怎么异或结果都一样。第二，n ^ n = 0 让偶数次出现的数全部消失，奇数次的那个留下来。第三，整体异或和拆出部分异或和，剩下那部分用 x ^ y 就能拿回来，区间问题、树上的异或路径问题都靠这条。第四，m 不等于 2 时异或消不掉，改数每位上 1 的个数再模 m。

Brian Kernighan 提取最右侧 1 这个动作，后面还会反复出现：树状数组的低位、Nim 博弈的必胜策略，都从它开始。下一讲继续在位运算上做文章。
