随机快速排序

快速排序的核心是 partition：选一个数 x，把比 x 小的放左边、比 x 大的放右边，再对左右递归。选固定位置当 x，已排序数组每次只搞定一个元素，时间退化成 O(n²)；随机选一个位置当 x，期望时间收敛到 O(n log n)。荷兰国旗优化把等于 x 的元素一次全部搞定，全相等数组从 O(n²) 变成 O(n)。

零、背景

先看一个具体的坑。数组已经排好序了，比如 [1,2,3,4,5,6,7]，如果每次选最右边的元素当 x，第一轮 x=7，partition 之后 7 在最后，左边还是 [1,2,3,4,5,6]；第二轮 x=6，6 又在最后，左边 [1,2,3,4,5]。每一轮只搞定一个元素，n 个元素要 n 轮，每轮扫 n 个元素，总共 n(n-1)/2 次比较，O(n²)。

快排本身没问题，选 x 的方式才是坑。如果 x 是随机选的，大概率选到中间位置的数，左右各分一半，递归深度就是 log n，每层总共处理 n 个元素，总时间 O(n log n)。随机这一下常数时间不小，但只有这一下随机，才能在概率上把复杂度收敛住。

还有一个坑：大量相等元素。数组里全是同一个数，经典版 partition 每次只把一个 x 放到分界处，剩下的全是 <=x，还是只搞定一个，递归深度 n，直接爆栈。荷兰国旗优化把等于 x 的全部放到中间，一次搞定，递归只处理小于和大于的部分，全相等数组一轮就结束。

一、经典版 partition（两段划分）

经典版把数组分成两段：<=x 放左边，>x 放右边。用一个指针 a 跟踪 <=x 区域的末尾，遍历整个区间，遇到 <=x 的就和 a 位置交换、a 往前走。

这里有个细节：partition 结束后要确保 x 在分界处。遍历过程中用 xi 记录任意一个 x 在 <=x 区域里的位置，最后把 xi 和 a-1 交换，x 就到了 <=x 区域的最后一个位置，也就是分界处。返回 a-1，递归左边 [l, mid-1]、右边 [mid+1, r]。

经典版的代码不长，但有个致命弱点：全相等数组。每次 partition 只把一个 x 放到分界处，剩下的 n-1 个全是 <=x，递归左边还是 n-1 个元素，深度 n-1。n=10000 时递归深度 9999 层，macOS 默认栈 8176KB、约 32 字节一帧，26 万层就段错误了，一万层虽然能过但已经很危险。

int partition1(int arr[], int l, int r, int x) {
        int a = l, xi = 0;
        for (int i = l; i <= r; i++) {
            if (arr[i] <= x) {
                swap(arr[a], arr[i]);
                if (arr[a] == x) xi = a;
                a++;
            }
        }
        swap(arr[xi], arr[a - 1]);
        return a - 1;
    }

二、荷兰国旗优化（三段划分）

荷兰国旗优化把数组分成三段：x 放右边。三个指针 first、last、i：first 是 x 区域的开头-1，i 是当前扫描位置。

扫描规则只有三条：arr[i]==x 时 i 往前走（已经在中间区）；arr[i]x 时和 last 交换、last 往后退（换到右边区，i 不动因为换过来的元素还没看）。

partition 结束后，first 到 last 之间全是等于 x 的元素，已经在最终位置上了，不需要再处理。递归只处理左边 [l, first-1] 和右边 [last+1, r]。全相等数组时，一轮扫描后 first=l、last=r，左右都是空区间，递归直接结束，深度只有 1。

void partition2(int arr[], int l, int r, int x) {
        first = l;
        last = r;
        int i = l;
        while (i <= last) {
            if (arr[i] == x) {
                i++;
            } else if (arr[i] < x) {
                swap(arr[first++], arr[i++]);
            } else {
                swap(arr[i], arr[last--]);
            }
        }
    }

三、随机选 pivot 与递归驱动

递归驱动的逻辑很简单：如果区间只有一个元素或空，直接返回；否则在 [l, r] 里随机选一个位置，取它的值当 x，跑荷兰国旗 partition，拿到 ==x 区域的左右边界 first 和 last，再递归左边和右边。

有个容易踩的坑：first 和 last 是全局变量（或者类的静态变量），递归调用会覆盖它们。所以 partition 之后要用临时变量 left 和 right 把 first、last 存下来，再传进递归。代码里注释写的「为了防止底层的递归过程覆盖全局变量」就是这个意思。

void quickSort2(int arr[], int l, int r) {
        if (l >= r) return;
        int x = arr[l + rand() % (r - l + 1)];
        partition2(arr, l, r, x);
        int left = first, right = last;
        quickSort2(arr, l, left - 1);
        quickSort2(arr, right + 1, r);
    }

四、为什么荷兰国旗版更好

最直接的对比是全相等数组的递归深度。经典版 n=10000 时深度 9999 层，荷兰国旗版只有 1 层。差别是实打实的：经典版会爆栈，荷兰国旗版一轮结束。洛谷上经典版甚至因为递归开太多层会爆栈导致出错，课程代码里注释直接写了「不推荐」。

随机数据下两者差别不大，递归深度都在 log n 附近（n=10000 时约 29-30 层）。荷兰国旗版的交换次数更多一些（n=10000 随机数据：经典版 89407 次交换，荷兰国旗版 156161 次），因为等于 x 的元素也会被交换，但换来的是全相等场景不爆栈，这笔买卖划算得很。

五、复杂度分析与对比

时间复杂度：随机 pivot 的期望是 O(n log n)。最坏情况还是 O(n²)，但概率极低，每次都选到最小或最大元素的概率是 2/n!，可以忽略。空间复杂度：递归栈的期望深度是 O(log n)，最坏 O(n)。

和归并排序对比：快排是原地排序（不需要额外数组），但不稳定（交换会打乱相等元素的相对顺序）；归并排序稳定，但需要 O(n) 的额外空间。实际计时 n=100 万时，快排约 58-66ms，std::sort 约 43ms。std::sort 不是纯快排，是 introsort：快排递归深度超过 log n 时切到堆排序，小区间切到插入排序，比纯快排稳。

比较次数上归并比快排少一些（n=10000 时归并 120400 次 vs 快排 162842 次），因为归并每次比较都锁定一个元素的位置，快排的 partition 里等于 x 的元素会被重复比较。但快排是原地交换、缓存友好，实际跑起来不一定比归并慢。

七、总结

1. 随机选 pivot 是快排的灵魂，固定位置选 pivot 在已排序数组上会退化成 O(n²)。

2. 荷兰国旗优化把等于 pivot 的元素一次全部搞定，全相等数组递归深度从 n 降到 1，经典版会爆栈的场景它一轮结束。

3. partition 之后要用临时变量存 first/last，递归调用会覆盖全局变量。

4. 快排原地但不稳定，归并稳定但需要 O(n) 额外空间，各有适用场景。

5. 标准库的 std::sort 是 introsort，不是纯快排，递归过深切堆排序、小区间切插入排序。
