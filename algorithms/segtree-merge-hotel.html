线段树：树上二分找最左合法区段

有一类查询是「给你一个区间，回答它里面的某个量」。这道题反过来：给你一个要求，回答落在哪个位置。要求是「至少有连续 x 个空房」，而且要在所有满足条件的位置里挑最靠左的那个。这种查询可以在树上一次二分走到底，不用把整棵树扫一遍。

零、背景

带区间的查询有一个共同点：被问的范围是给定的，递归方式也就是「区间和当前结点有交集就两边都看」。

换一种问法：手头有一个判据，要回答满足判据的位置在哪，还要最靠左。这时没法先给出区间，得从根开始往下测。做法是先看左儿子满不满足，满足就往左走；左儿子不满足，就看「左儿子的后缀接上右儿子的前缀」这一段满不满足，满足就停在接缝上；两边都不行，说明答案只能在右儿子里，往右走。每次往下都只走一个儿子，所以走到底只要 O(log n) 步。

能这样走的前提是有一个单调性：一个结点如果都不满足判据，它的儿子更不可能满足。这道题的判据是「最长的一串空房长度不小于 x」，父结点的这个值等于三个候选里的最大，其中两个就是左右儿子的值，所以父结点不满足就意味着两个儿子都不满足。单调性成立，树上二分才成立。

一、题目

旅馆（洛谷 P2894）：n 个房间排成一排，编号 1 到 n，一开始都是空房。两种操作，一共调用 m 次。

  • 操作 1 x：找出一段至少连续 x 个空房的区域。有多个满足条件的区域时取最靠左的那个，输出它的最左编号，并从那里开始安排 x 个人入住。找不到就输出 0，不做任何改动。
  • 操作 2 x y：从 x 号房间开始往下数 y 个房间，一并清空。

1 ≤ n, m ≤ 50000。操作 2 有清空动作，所以需要懒标记；操作 1 是边查边改。

二、结点上放三个量

三个量的定义跟数连续 1 时一样，只是把「1」换成了「空房」：len 是这一段里最长的一串空房长度，pre 是从最左边开始连着多少个空房，suf 是贴到最右边连着多少个空房。

const int MAXN = 50001;

    int len[MAXN << 2];      // 这一段里最长的一串空房有多长
    int pre[MAXN << 2];      // 这一段里，从最左边开始有多少个空房
    int suf[MAXN << 2];      // 这一段里，贴到最右边有多少个空房

    // 三个量和「连续 1」那套写法只差一个符号
    void up(int i, int ln, int rn) {
        int l = i << 1, r = i << 1 | 1;
        len[i] = max(max(len[l], len[r]), suf[l] + pre[r]);
        pre[i] = len[l] < ln ? pre[l] : pre[l] + pre[r];
        suf[i] = len[r] < rn ? suf[r] : suf[l] + suf[r];
    }

懒标记也简单，只有一种：整段设置成 0（全空）或者 1（全住满）。设置之后三个量都是确定的，pre 和 suf 也不用额外算。

int change[MAXN << 2];   // 这一段被整段设置成了什么
    bool hasSet[MAXN << 2];  // 这一段挂着整段设置的任务

    // 整段设置成 v：0 是全空，1 是全住满
    void setLazy(int i, int v, int n) {
        len[i] = pre[i] = suf[i] = v == 0 ? n : 0;
        change[i] = v;
        hasSet[i] = true;
    }

    void down(int i, int ln, int rn) {
        if (hasSet[i]) {
            setLazy(i << 1, change[i], ln);
            setLazy(i << 1 | 1, change[i], rn);
            hasSet[i] = false;
        }
    }

    void update(int jobl, int jobr, int jobv, int l, int r, int i) {
        if (jobl <= l && r <= jobr) {
            setLazy(i, jobv, r - l + 1);
        } else {
            int mid = (l + r) >> 1;
            down(i, mid - l + 1, r - mid);
            if (jobl <= mid) {
                update(jobl, jobr, jobv, l, mid, i << 1);
            }
            if (jobr > mid) {
                update(jobl, jobr, jobv, mid + 1, r, i << 1 | 1);
            }
            up(i, mid - l + 1, r - mid);
        }
    }

三、查询：三条路里挑一条

设当前走到 [l, r]，中点是 mid，要找长度不小于 x 的一串空房。三条路按顺序试：

  1. len[左] ≥ x：左儿子自己就装得下，答案一定在左半边里，往左走。
  2. suf[左] + pre[右] ≥ x：左半边装不下，但跨过接缝的那一段够长。答案的起点被接缝定死，就是 mid - suf[左] + 1，直接返回。
  3. 都不行：答案在右半边里，往右走。

第二条里为什么起点是 mid - suf[左] + 1？跨接缝的那一段由两部分拼成：左半边贴到 mid 的一段，加上右半边从 mid + 1 开始的一段。要让总长最大，只能取满左半边的后缀，所以起点就是那段后缀的最左一格，也就是 mid - suf[左] + 1。它同时也是所有跨接缝的候选里最靠左的起点。

// 在 l..r 里找出长度不小于 x 的一串空房，返回最靠左的起点
    // 潜台词：调用之前已经确认过 l..r 里一定有
    int queryLeft(int x, int l, int r, int i) {
        if (l == r) {
            return l;
        }
        int mid = (l + r) >> 1;
        down(i, mid - l + 1, r - mid);
        if (len[i << 1] >= x) {                    // 左儿子自己就能装下
            return queryLeft(x, l, mid, i << 1);
        }
        if (suf[i << 1] + pre[i << 1 | 1] >= x) {  // 只能跨过接缝
            return mid - suf[i << 1] + 1;
        }
        return queryLeft(x, mid + 1, r, i << 1 | 1);
    }

调用之前先比一次 len[1] 和 x。根都不满足就直接输出 0，不进递归，这样递归里面就不用再处理「找不到」这种情况。

四、为什么选出来的就是最左

三条路的顺序由答案的分布定下来：要么在左半边、要么跨接缝、要么在右半边，这三类互不重叠，而且按位置从前到后正好是这个顺序。三条路按这个顺序试，第一次走通的那一类里的起点，就比后面所有类里的起点都靠左。

既然回答了「在哪一类」，还要保证在那一类内部挑的是最靠左的。第一类交给左儿子递归，递归里同样按这个顺序试，归纳下去必然拿到这一类里最靠左的。第二类的起点由 suf[左] 唯一确定，没有别的选择。第三类交给右儿子，同理。

这里有一处容易写反：不能先判接缝。如果左儿子自己就有满足条件的区段，那个区段整段都在左半边，起点一定小于任何跨接缝的起点；先判接缝会把答案往右推。实测把顺序换过来，n = 4、8、16、64 四档分别有 6.70%、8.10%、8.63%、9.60% 的随机数据答案会偏。比例不高，因为随机数据里 x 往往偏大，左儿子常常装不下，这时候两种顺序的结果一样。

五、入住就是把那一段占上

找到起点之后，安排入住就是对 [left, left + x - 1] 做一次整段设置成 1，跟操作 2 用的是同一个函数，只是设置的值不同。

操作 2 的右端点在代码里写成了 min(x + y - 1, n)。实测把 min 去掉，答案一个都不变：线段树本身的区间范围就是 [1, n]，递归到边界时任何超出 n 的右端点都会在那一层被当成整段命中，多出来的部分落不到任何结点上。留下来的 min 是把这个意图写清楚，不是正确性必需的。

六、复杂度分析

项旅馆
建树O(n)
操作 1（找位置 + 入住）O(log n)：树上二分一路走到底，再对找到的那一段做一次整段设置
操作 2（清空一段）O(log n)
全程总代价O((n + m) log n)
空间O(n)：四个四倍长度的 int 数组、一个 bool 数组

按 n = 50000 开四倍空间，四倍长度部分是 200004 个结点，约 3.24 MiB。

树上二分走到底要多少步：n = 50000 时是 17 个结点，n = 100000 时是 18 个。而逐格扫描一次查询，最坏要把 n 个起点各试一遍，n = 50000 就是五万步。

实测开销，g++ -O2：n = m = 50000 时 5.82 ms；n = m = 20000 时 2.11 ms，同样输入的逐格暴力要 3893.18 ms，差约 1845 倍。暴力的每一次查询都在做「枚举起点、检查这一段有没有人」，检查的总量随 n 和 x 一起涨。

第一行比例低，是因为随机数据里 x 是在 1 到 n 之间均匀取的，x 一大，左儿子就装不下，接缝那一条也常常不成立，两种顺序于是走同一条路。把 x 全取 1 之后，n = 4、8、16 三档升到 14.80%、22.57%、22.00%；n = 64 反而只有 6.20%，操作步数一样多，房间越多被清掉的也越多，接缝那一段空房常常一直拖到最左边，错版返回的位置恰好就是最左的那间。即便只有几个百分点，它仍然是一条实打实的错：顺序换掉之后返回的位置会往右偏，而不是偶发的边界抖动。

第三行必错，因为起点算错一格，后面 update 占的位置也跟着错一格。第四行是 0.00%，属于真等价：区间操作的右端点会被线段树自己的范围截住。

八、总结

这道题的查询跟「给定区间求量」的方向相反：这里是给定判据求位置。能反过来求的前提是判据在结点上有单调性：父结点不满足就说明两个儿子都不满足。有了单调性，从根往下每次只走一个儿子，走到底就是 O(log n) 步。

三条路的顺序决定答案是否最靠左。左儿子优先，接缝其次，右儿子最后，这正好是位置从前到后的顺序。这条顺序本身不复杂，真正要记住的是「不能反过来」。

三个量、一套懒标记、一个树上二分，合起来就是这道题的全部。三个量换成别的定义之后，同一套走法还能回答更多形式的查询。

最后

三点。一是三条路的顺序不能动，左儿子排第一；接缝的起点算完就直接返回，不要再往下递归。

二是接缝起点是 mid - suf[左] + 1，减号后面那个 + 1 不能省，它表示后缀的最左一格。

三是操作 1 要先把 len[1] 和 x 比一次，根都不满足就直接输出 0。少了这一步，递归里会出现「整棵树都找不到」的情况，得额外处理。
