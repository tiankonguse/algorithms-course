贪心：最慢的那一处说了算

一道题让最慢的两个人一起过河，一道题让最挤的那台洗衣机定节奏。两题的答案都长在「最紧的那一处有多紧」上。

零、两道题各自要什么

第一题：n 个人在河这边，船最多坐两人。一个人划船用他自己的渡河时间，两个人划船用两人中较大的那个。求所有人到对岸的最少总时间。

第二题：n 台机器排成一排，每一步可以选任意多台，同时各送一件衣服给相邻的一台机器。求让所有机器衣服数相等的最少操作步数，做不到返回 -1。

两题的答案都由最紧的那一处定：过河题里每一步的时间是船上最慢的那个人，洗衣机题里每一步的吞吐由最挤的位置决定。算出每一处的紧度取最大，就是答案。

一、过河问题：把最慢的两个人送过去，只有两种做法

先把渡河时间排序。最慢的那个人一定要过河，他过河那一趟的时间跑不掉。麻烦的是船的位置：他过去之后船在东岸，还得有人把船划回来接剩下的人，来回的成本落在谁头上，决定了总时间。

处理最慢的两个人时，能想到的做法只有两种。拿 [1,2,5,10] 里要送 5 和 10 过去举例：

做法一：最快的 1 把船划回来，再陪最慢的 10 一起过去。多花 a[0] + a[i]。

做法二：最快的 1 划回来，最慢的 5 和 10 一起过去，第二快的 2 再把船划回来，最后 1 和 2 一起过去。多花 a[0] + 2×a[1] + a[i]。

状态就定成「下标 0 到 i 的人都过了河」，转移从 i-1 和 i-2 两个方向来，取小的：

dp[i] = min(dp[i-1] + a[i] + a[0], dp[i-2] + 2×a[1] + a[i] + a[0])

前三个位置单独给：一个人用时 a[0]；两个人一起过去用时 a[1]；三个人用时 a[0] + a[1] + a[2]，也就是 1 陪 2 过去、1 回来、1 再陪 3 过去。

走一遍 [1,2,5,10]：dp[0] = 1，dp[1] = 2，dp[2] = 1+2+5 = 8。i 到 3 时两个候选是 8 + 10 + 1 = 19 和 2 + 2×2 + 10 + 1 = 17，取 17。

这里有个细节：做法二里来回跑的是第二快的人，常数是 2×a[1]。写成 2×a[0] 时随机数据上有 69.11% 的用例答案会变，这是最容易写错的一处。

// 过河问题：一次最多坐两人，划船时间取两人渡河时间的最大值，求所有人过河的最少总时间
    // 排序后按人数从小到大记账，每一步只考虑「把最慢的两个人送过去」的两种做法
    // 做法一：最快的人把船划回来陪最慢的过去；做法二：最快的两人先过去，最慢的两人一起过去，第二快的人把船划回来
    int minCost(vector<int> nums) {
        int n = nums.size();
        sort(nums.begin(), nums.end());
        vector<int> dp(n, 0);
        if (n >= 1) {
            dp[0] = nums[0];
        }
        if (n >= 2) {
            dp[1] = nums[1];
        }
        if (n >= 3) {
            dp[2] = nums[0] + nums[1] + nums[2];
        }
        for (int i = 3; i < n; i++) {
            dp[i] = min(dp[i - 1] + nums[i] + nums[0], dp[i - 2] + nums[1] + nums[1] + nums[i] + nums[0]);
        }
        return dp[n - 1];
    }

实测 n = 105、渡河时间随机 1 到 106，答案是 24963489707，跑完 5.94ms。累加和的类型要留意：n = 105、每人 106 时总和能到 1011，答案得用 64 位整数装。

二、超级洗衣机：每台机器左右各缺多少

先算平均值。总衣服数除不尽机器数，直接返回 -1。

最终每台都是平均值这件事可以当作已知，那么每台机器的差额也是固定的：多了得往外送，少了得从外面收。一次操作里每台机器最多送出一件，也最多收进两件，左边一台右边一台。

扫到第 i 台时看两侧的缺口。左边 i 台一共该有 i×avg 件、实际有 leftSum 件，差值就是左边的缺口；右边同理。两边都缺（都为正）时，左边要往右送、右边要往左送，一步最多进两件，这一处的紧度是两者之和；只有一边缺时，紧度是两边绝对值的较大者。

答案取所有位置里最紧的那个。任何一步里，最挤的位置都得按自己的节奏来，整体不可能比它更快。

这里有个细节：漏掉「两边都缺」这一支时，随机数据上只有 1.70% 的用例会算错（值域 0 到 100 时是 2.91%）。反例 [5,2,7,1,5] 正解是 3，漏掉这一支的写法给 2。

// 超级洗衣机：每一步可以选任意多台机器，各送一件衣服给相邻机器，求让每台衣服数相等的最少步数
    // 总和除以台数就是每台的目标值，除不尽直接返回 -1
    // 扫到第 i 台时，左边一共缺 leftNeed 件、右边一共缺 rightNeed 件；两边都缺时只能各送一件进来，瓶颈是两者之和
    int findMinMoves(vector<int> arr) {
        int n = arr.size();
        int sum = 0;
        for (int i = 0; i < n; i++) {
            sum += arr[i];
        }
        if (sum % n != 0) {
            return -1;
        }
        int avg = sum / n;
        int leftSum = 0;
        int leftNeed = 0;
        int rightNeed = 0;
        int bottleNeck = 0;
        int ans = 0;
        for (int i = 0; i < n; leftSum += arr[i], i++) {
            leftNeed = i * avg - leftSum;
            rightNeed = (n - i - 1) * avg - (sum - leftSum - arr[i]);
            if (leftNeed > 0 && rightNeed > 0) {
                bottleNeck = leftNeed + rightNeed;
            } else {
                bottleNeck = max(abs(leftNeed), abs(rightNeed));
            }
            ans = max(ans, bottleNeck);
        }
        return ans;
    }

实测 n = 106、每台随机 0 到 100，答案是 952329，跑完 1.13ms。整趟只有一个平均值加一次扫描，没有排序也没有堆。

三、两个演示

过河问题：每一轮两种做法取小

排序之后从小到大处理，每一轮记下两个候选各要多少时间。

超级洗衣机：最挤的那一台

每一位算左边缺口、右边缺口，再看这一处的紧度。

四、对数器怎么抓错

两题的暴力都好写。过河题的暴力是状态压缩加 Dijkstra，状态是「西岸还剩哪些人 + 船在哪一侧」，转移是船上的一两个人划到对岸，边权取这趟的最大时间。洗衣机题的暴力在小数组上做 BFS，每台机器三种动作（不动、送左、送右），逐层扩到「每台都等于平均值」这个状态。

题目写法随机数据出错比例
过河问题只用「最快的人来回接送」这一种做法66.00%
过河问题做法二的常数写成 2×a[0]69.11%
超级洗衣机紧度只取 max(|左缺|, |右缺|)，漏掉两边都缺1.70%（值域 0~100 时 2.91%）
超级洗衣机只数「单台超出平均值多少」，取最大超量6.24%（值域 0~2 时 3.27%）

过河题二十万组随机数据，人数 2 到 10、时间 1 到 30；洗衣机题二十万组，台数 1 到 8、每台 0 到 8，另有一组把值域从 2 拉到 100 的对照。

「只用做法一」这一版几乎处处出错，因为它从来不让最慢的两个人一起走，而数据里有大把人适合这种做法。常数写成 2×a[0] 更隐蔽一些，只有在第二快和最快差得远时才现形，所以数据范围一大出错比例就上去了。

洗衣机那两条抓取率都低。漏掉「两边都缺」要求中间那台同时被左右夹击，值域太小的时候这种缺口凑不出来，值域 0 到 2 时一次都抓不到，拉到 0 到 100 也只有 2.91%。

复杂度分析

题目关键操作时间空间
过河问题排序 + 一趟 dp，每个位置两次取候选O(n log n)O(n)
超级洗衣机求一次总和 + 一趟扫描O(n)O(1)

过河题的时间全在排序上，dp 本身是线性的；dp 数组长度 n，不过每个位置只用到前两个值，写成一维数组已经够省。洗衣机题除输入数组外只用几个整数变量。实测 n = 105 的过河题 5.94ms，n = 106 的洗衣机题 1.13ms。

总结

过河题的每一轮只有两种做法：最快的人划回来陪最慢的过去，多花 a[0] + a[i]；或者最快的人划回来、最慢的两人一起过去、第二快的人再把船划回来，多花 a[0] + 2×a[1] + a[i]。状态按「已经处理完前几个人」推，两个候选取小，前三个位置单独初始化。

洗衣机题把「每台最终都是平均值」当已知，扫到每一位算左边缺口和右边缺口：两边都缺时这一步最多进两件，紧度是两者之和；只有一边缺时紧度是绝对值较大者。全部位置取最大就是答案。

两题都不模拟过程。过河题算出的是几趟划船的时间总和，洗衣机题算出的是最挤那一处需要的步数，答案都是一趟扫描里的最大值，其中过河题先排序。
