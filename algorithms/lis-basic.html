最长递增子序列：ends 数组与二分

给一个数组，找出一个子序列（下标递增即可，不要求连续），让它的值严格递增，问最长能有多长。n = 100000 时，最朴素的动态规划要跑 9634 毫秒，换个记法之后同一个答案是 1.614 毫秒。两个做法算的是同一个东西，差别只在「中间记录下来什么」。

零、朴素做法与它的代价

最直接的思路是给 dp 加一个限制：dp[i] 表示子序列一定以 nums[i] 做结尾时，最长能有多长。

加上这个限制之后，转移就是把前面所有比它小的位置扫一遍：

dp[i] = 1 + max{ dp[j] }　其中 j < i 且 nums[j] < nums[i]

答案是整张 dp 表的最大值，不是 dp[n-1]。最长那条的结尾可以停在任何位置。

// 朴素做法：dp[i] 表示「一定以 nums[i] 结尾」的最长递增子序列长度
    // 时间复杂度 O(n^2)
    int lengthOfLIS(int* nums, int n) {
        int dp[100005];
        int ans = 0;
        for (int i = 0; i < n; i++) {
            dp[i] = 1;
            for (int j = 0; j < i; j++) {
                if (nums[j] < nums[i]) {
                    dp[i] = max(dp[i], dp[j] + 1);
                }
            }
            ans = max(ans, dp[i]);
        }
        return ans;
    }

代价全在那个内层循环上：每个 i 都要回头看 i 个 j，总比较次数是 n (n − 1) / 2。实测（g++ -O2）n = 10000 时 108.5 毫秒，n = 30000 时 835.9 毫秒，n = 100000 时 9634 毫秒。n 翻三倍，时间翻十倍，这就是 O(n²)。

慢在哪？可以发现，dp[i] 只关心「前面各种长度的递增子序列，结尾最小是多少」这一件事，可代码却把每个 j 都重新问了一遍。把这些答案单独记下来，就能二分。

一、ends 数组：按长度记最小结尾

换个记录方式。ends[i] 记的是：长度为 i + 1 的递增子序列，它的结尾最小能小到多少。

这个定义有两个立刻能用的性质。第一，ends 数组本身严格递增：长度更长的子序列，结尾不可能比长度更短的那个还小，否则把长序列砍掉尾上多出来的元素，就得到一个更短的序列且结尾更小，矛盾。第二，ends[len-1] 越小越好，因为它后面还能接的数更多。

扫描到新数 num 时只做一件事：在 ends 里找第一个 >= num 的位置。找到了，就把它顶掉，因为同样长度下 num 是更小的结尾；找不到，说明 num 比所有结尾都大，长度可以加一，把 num 接到末尾。

len = ends 的有效区长度，答案就是 len

二、二分找那个位置

ends 严格递增，找「第一个 >= num 的位置」是标准二分，找不到返回 -1。

// ends[0..len-1] 严格升序，找 >= num 的最左位置，不存在返回 -1
    int bs1(int* ends, int len, int num) {
        int l = 0, r = len - 1, m, ans = -1;
        while (l <= r) {
            m = (l + r) / 2;
            if (ends[m] >= num) {
                ans = m;
                r = m - 1;
            } else {
                l = m + 1;
            }
        }
        return ans;
    }

每次扫描一个 num 只花 log₂(len) 次比较。实测总比较次数：n = 1000 时 5.18 n，n = 100000 时 8.60 n，n = 1000000 时 10.29 n。注意它跟 log₂n 不是一个数，因为二分的范围是 ends 的有效长度 len，不是 n。

// 最优解：ends[i] 记录「长度为 i+1 的递增子序列」的最小结尾
    // 时间复杂度 O(n * logn)
    int lengthOfLIS(int* nums, int n) {
        int ends[100005];
        int len = 0;
        for (int i = 0, find; i < n; i++) {
            find = bs1(ends, len, nums[i]);
            if (find == -1) {
                ends[len++] = nums[i];   // 比所有结尾都大，长度 +1
            } else {
                ends[find] = nums[i];    // 顶掉第一个 >= 它的结尾
            }
        }
        return len;
    }

数组长度随 n 增长得比 log n 慢得多。随机排列的 LIS 长度大约是 2√n，实测 n = 1000000 时是 1995，理论值 2000。

演示一：ends 数组逐帧推进

三、严格递增与不下降只差一个等号

把题面换成「最长不下降子序列」，也就是允许相等，整套东西一行都不用改，只把二分里的比较符号从 >= 换成 >。

// ends[0..len-1] 不降序，找 > num 的最左位置，不存在返回 -1
    int bs2(int* ends, int len, int num) {
        int l = 0, r = len - 1, m, ans = -1;
        while (l <= r) {
            m = (l + r) / 2;
            if (ends[m] > num) {
                ans = m;
                r = m - 1;
            } else {
                l = m + 1;
            }
        }
        return ans;
    }

道理很直接：用 >= 时，等于 num 的结尾会被顶掉，相等的两个数凑不到一条序列里，得到的就是严格递增；用 > 时，相等的结尾留着，num 顶掉的是第一个比它大的，相等的两个数就能挨着放。

// 最长不下降子序列：只把 bs1 换成 bs2，其余一行不动
    int lengthOfLNDS(int* nums, int n) {
        int ends[100005];
        int len = 0;
        for (int i = 0, find; i < n; i++) {
            find = bs2(ends, len, nums[i]);
            if (find == -1) {
                ends[len++] = nums[i];
            } else {
                ends[find] = nums[i];
            }
        }
        return len;
    }

这个等号是本题最容易写反的地方，而且写反了不一定能被测出来。实测两万个随机样本（n 在 1 到 20，值域 V 可变）：V = 3 时两个写法答案不同的比例 86.78%，V = 5 时 80.01%，V = 10 时 63.81%，V = 50 时 20.30%，V = 1000 时只有 1.10%，V = 10⁶ 时 0%。

也就是说，样本里重复值越多，这个 bug 越容易现形；数据值域一大，两个写法几乎总给出同一个答案，交上去也能过，等到有人造一组重复值就挂了。所以别靠测，把符号和题面对着看一遍。

演示二：值域越大，写反等号越难被测出来

四、ends 里存的那串数，通常不是一条真的子序列

这里有个细节，很多人学完就顺手当结论用错了：ends 数组只有长度是对的，把它从头到尾读出来，往往并不是原数组的一个子序列。

反例小到三个数就够。数组 [2, 3, 1]，ends 最后停在 [1, 3]：1 在下标 2，3 在下标 1，顺序是反的，原数组里根本不存在「先 1 后 3」这个子序列。长度 2 是对的（最长的确是 2），内容却是拼出来的。

原因是 ends 的各个位置来自不同时刻的更新，它们之间没有「同一次扫描里被一起选中」这层关系。题目只要长度，那就够用；真要把那条子序列打印出来，得另外记前驱。

五、复杂度分析

做法时间额外空间说明
朴素 dpO(n²)O(n)dp 表 n 个 int，每个 i 扫一遍 j < i
ends + 二分O(n log n)O(n)ends 数组最多 n 格，每格一次二分 log₂(len)

空间那栏是 O(n) 而不是 O(log n)：ends 的有效长度是答案，最坏情况（整个数组严格递增）它就是 n，所以得按 n 开。push 进 vector 也一样，容量按 n 给。

时间那栏严格说是 O(n log L)，L 是答案长度，不过 L ≤ n，写成 O(n log n) 没毛病。实测 n = 10⁶ 的总比较次数 10.29 n，比 log₂n = 19.9 小不少，因为二分的范围一直是 len。

六、总结

这题的全部技巧就一句话：把「以谁结尾」换成「长度是多少、结尾最小是多少」。换完之后，答案变成 ends 的长度，维护变成一次二分。

几个要记住的点：

1）严格递增用 >= 的二分，不下降用 > 的二分，其余代码完全一样。写反了在小值域数据上一测就现形，在大值域数据上测不出来。

2）ends 数组只有长度可信，内容拼不成一条子序列，别拿它当答案输出。

3）ends 的有效长度就是答案，不用另外记 ans。
