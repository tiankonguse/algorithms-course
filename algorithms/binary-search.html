二分搜索

有序数组里找一个数，从头扫一遍要 n 次，二分只要 log n 次。省下来的代价来自一个信息：数组是有序的，比完中间那个就能扔掉一半。

零、背景

给一个已经排好序的数组，问某个数在不在里面。这是最基础的一个查询动作，后面的离散化、区间统计、二分答案都会反复用到它。

它值得单独讲一遍，不是因为代码长，四个函数加起来不到六十行，而是因为边界的写法很容易错，而且错了不会立刻崩，只在某几个特定长度的数组上给出错答案。

一、三种问法

同一个有序数组，问题可以有三种说法。

  1. num 在不在数组里，返回是或否
  2. 找 >= num 的最左位置
  3. 找 <= num 的最右位置

后两种要返回下标，找不到的时候统一返回 -1。

第一种其实不用单独写：拿到 >= num 的最左位置，再看那个位置上的值是不是 num 就够了。不过它最好写，先拿它把二分的骨架讲清楚。

数组里有重复值时，三种问法的答案会明显分岔。9 出现了三次，问「在不在」只能得到「在」，问「最左」得到 4，问「最右」得到 6。

二、朴素做法

从头扫到尾，找到了就返回。这份代码甚至不需要数组有序。

// 从头到尾扫一遍，arr 有序无序都能用
    bool existLinear(int arr[], int n, int num) {
        for (int i = 0; i < n; i++) {
            if (arr[i] == num) {
                return true;
            }
        }
        return false;
    }

    // 找 >= num 的最左位置，不存在返回 -1
    int leftLinear(int arr[], int n, int num) {
        for (int i = 0; i < n; i++) {
            if (arr[i] >= num) {
                return i;
            }
        }
        return -1;
    }

它的代价是线性的。实测一下：长度为 n 的数组，把「命中第 i 个位置」和「压根不存在」这 n+1 种情况平均起来，比较次数是

( 1 + 2 + … + n + n ) / ( n + 1 ) ≈ n / 2 + 1

数组稍微长一点就很可观。

三、存在性二分

二分的全部动作就三行：看中间，比大小，扔一半。

设 l 和 r 是当前还没排除的区间两端，m 是中间位置。拿 arr[m] 和 num 比，只有三种结果：

  • 相等，找到了，直接返回
  • arr[m] > num，数组有序，m 右边只可能更大，答案只可能在 m 左边，于是 r = m - 1
  • arr[m] < num，同理答案只可能在 m 右边，l = m + 1
// 保证 arr 有序，判断 num 是否存在
    bool exist(int arr[], int n, int num) {
        if (n == 0) {
            return false;
        }
        int l = 0, r = n - 1, m = 0;
        while (l <= r) {
            m = (l + r) / 2;
            if (arr[m] == num) {
                return true;
            } else if (arr[m] > num) {
                r = m - 1;
            } else {
                l = m + 1;
            }
        }
        return false;
    }

这里有个细节值得停一下：r = m - 1 和 l = m + 1 里的那个 1 不能省。m 这个位置刚刚比过，它已经在三种情况里被判定过了，不可能再是答案。

写成 r = m 会怎样？区间长度不再减半。取 l = 0, r = 1，算出 m = 0，如果 arr[0] > num，r 被赋成 0，下一轮还是 l = 0, r = 0, m = 0，还是同一个判断，还是 r = 0。循环永远出不来。

图上每一行是一次循环。蓝色是这一轮还活着的区间，实心那一格是 m，灰色是已经被排除的位置。五轮之内必然结束，因为区间长度每轮减半，16 → 8 → 4 → 2 → 1。

四、找 >= num 的最左位置

换一个问题，思路要跟着变。现在不能一命中就返回了：9 命中的是位置 5，但最左的那个 9 在位置 4。

做法是把「返回」换成「记账」：命中就先把 m 记进 ans，然后把右端点压到 m - 1，继续往左找还有没有更早的命中。

// 保证 arr 有序，找 >= num 的最左位置，不存在返回 -1
    int findLeft(int arr[], int n, int num) {
        int l = 0, r = n - 1, m = 0;
        int ans = -1;
        while (l <= r) {
            m = l + ((r - l) >> 1);
            if (arr[m] >= num) {
                ans = m;
                r = m - 1;
            } else {
                l = m + 1;
            }
        }
        return ans;
    }

循环结束的条件还是 l > r，此时区间里一个位置都不剩了。ans 留着最后一次命中的位置，也就是最左的那个。

为什么最后一次就是最左的？因为每命中一次就把 r 压到 m - 1，后面再命中的位置一定严格小于当前的 m，ans 只会往左挪。

ans 的初值是 -1。一次都没命中，说明整个数组都小于 num，返回 -1 正好表示不存在。

五、找 <= num 的最右位置

和上一节完全镜像。判断条件从 >= 换成 <=，命中之后不再往左压，而是往右压 l = m + 1。

// 保证 arr 有序，找 <= num 的最右位置，不存在返回 -1
    int findRight(int arr[], int n, int num) {
        int l = 0, r = n - 1, m = 0;
        int ans = -1;
        while (l <= r) {
            m = l + ((r - l) >> 1);
            if (arr[m] <= num) {
                ans = m;
                l = m + 1;
            } else {
                r = m - 1;
            }
        }
        return ans;
    }

两份代码结构一模一样，只有判断符号和两个分支里的赋值方向相反。写的时候容易手滑，把 findLeft 复制过来改一半，比较安全的办法是先写一份跑对，再照着改符号，改完拿一个小数组验两个方向。

把两个函数拼起来，可以直接问出「等于 num 的那一段」。

// 等于 num 的那一段：左端 = findLeft(num)，右端 = findRight(num)
    // 左端是 -1 或者 arr[left] != num 时，说明 num 不存在
    int left = findLeft(arr, n, num);
    int right = findRight(arr, n, num);
    int cnt = (left == -1 || arr[left] != num) ? 0 : right - left + 1;

左端点为 -1，或者左端点上的值不等于 num，都说明 num 不在数组里。个数就是 right - left + 1。

六、中间位置的两种写法

m = (l + r) / 2 和 m = l + ((r - l) >> 1) 在数学上是一回事，在计算机里不是。

int 能表示的最大值是 2147483647。l 和 r 各自都没超，但 l + r 可能超，超了之后会变成一个负数，再除以 2 还是负数。拿负数去当下标，接下来发生什么就不一定了。

第二种写法先做减法。r - l 是区间长度，一定非负也不会溢出，右移一位是除以 2，最后加回 l。全程没有一个中间值超过 r。

顺带说一句，>> 1 和 / 2 对非负数是等价的，这里写右移只是习惯。真正起作用的是「先减后加」这个顺序。

七、二分不一定发生在有序数组上

到这里为止，二分都依赖「数组有序」。但这个依赖可以放宽：真正需要的不是有序，是能判断「答案在哪一侧」。

看一道题。数组相邻两个值保证不相等，两端外面当作负无穷，要求找出任意一个峰值，严格大于左右邻居的元素，复杂度要 O(log n)。

数组整体没有序，可它仍然能二分，理由是：站在位置 m 上，只看 m 和 m + 1 这两个值，就能确定哪一侧一定有峰值。

  • arr[m] < arr[m + 1]，右边在往上走。从 m+1 开始一路向右，值要么一直涨到某处开始跌，那个转折点就是峰值；要么一路涨到最右端，最右端自己就是峰值（它右边是负无穷）。右边必有。
  • arr[m] > arr[m + 1]，左边在往上走。对称地，m 及其左边必有峰值。

于是每次都能扔掉一半。代码里先把两个端点单独判掉，端点只需要比一个邻居，剩下的内部区间就是一个标准的二分。

// 相邻值不相等，nums[-1] = nums[n] = 负无穷，返回任意一个峰值下标
    int findPeakElement(int arr[], int n) {
        if (n == 1) {
            return 0;
        }
        if (arr[0] > arr[1]) {
            return 0;
        }
        if (arr[n - 1] > arr[n - 2]) {
            return n - 1;
        }
        int l = 1, r = n - 2, m = 0, ans = -1;
        while (l <= r) {
            m = (l + r) / 2;
            if (arr[m - 1] > arr[m]) {
                r = m - 1;
            } else if (arr[m] < arr[m + 1]) {
                l = m + 1;
            } else {
                ans = m;
                break;
            }
        }
        return ans;
    }

三个分支的写法和前面不一样：这里不是「命中就记账」，而是「命中就 break」，因为找到任意一个就够，ans 也不需要初值 -1 之外的含义。内部区间 [1, n-2] 的每个位置左右都有邻居，所以 arr[m-1] 和 arr[m+1] 都能安全访问。

复杂度分析

三个二分函数的循环体都是常数时间，循环次数取决于区间什么时候变空。

每轮区间长度从 len 变成大约 len / 2，从 n 降到 1 需要 log₂ n 轮，再走一轮区间变空结束，所以最多 ⌈log₂ (n + 1)⌉ 次。实测值列在上面那张表里：n = 10⁶ 时是 20 次。

操作时间复杂度空间复杂度说明
线性扫描查找O(n)O(1)平均约 n/2 次比较，不要求数组有序
存在性二分O(log n)O(1)每轮砍一半，命中可提前返回
找最左 / 最右位置O(log n)O(1)不能提前返回，走满 ⌈log₂(n+1)⌉ 轮
峰值查找O(log n)O(1)数组无序，靠「哪侧必有峰值」砍一半

空间这边没什么可说的，四个函数都只用 l、r、m、ans 几个标量，和数组长度无关，是 O(1)。

最后

二分搜索的代码很短，值钱的是它背后的那句话：只要能判断答案落在哪一侧，就能每次扔掉一半。

有序数组只是满足这个条件的最简单的一种情形。等后面见到「二分答案」，在一个单调的判定函数上二分一个数值，用的还是同一句话，只不过被扔掉的一半不再是数组下标，而是答案的取值范围。
