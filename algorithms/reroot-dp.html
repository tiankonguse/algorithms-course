换根 dp：两趟 dfs 算出每个点做根的答案

树形 dp 的答案常常要指定谁做根。只问一个根时一趟 dfs 就完事，题目要是问「每个点各做一次根，答案分别是多少」，逐个点重算是 O(n²)。换根 dp 把它压成两趟遍历：第一趟固定 1 号做根收集子树信息，第二趟沿边把答案递给儿子，递一次 O(1)。

零、背景

深度、子树大小、到叶子的距离，这些都是相对根才有的量。根一换，全树的深度整体跟着变，所以「换根」听起来像是把整棵树重新算一遍。

但相邻的两个根只差一条边的方向。以 u 做根和以它的儿子 v 做根，全树被边 (u, v) 切成两半，两半之间的相对关系一点没变，变的是两边各自的深度偏移。想清楚这一点，换根就从「重算」变成了「改一个数」。

一、问题

洛谷 P3478 最大深度和。n 个点的一棵树，找一个节点，使得以它做根时它到所有节点的深度之和最大；有多个节点并列，返回编号最小的那个。n 到 10⁶。

根的深度算 0，它到自己的距离是 0。这正是最直观的一个「答案依赖根」的量，拿它开刀最合适。

二、先把一个根算出来

固定 1 号做根。对每个点 u，记两件事：sz[u] 是 u 的子树大小，sumv[u] 是 u 的子树内所有点相对 u 的深度之和。u 自己贡献 0，儿子的子树整体下沉一层，所以

sumv[u] += sumv[v] + sz[v];    // v 子树里每个点都比在 v 那里深一层

后序位置合并，一趟 dfs 收完，sumv[1] 就是 1 号做根时的深度和。图 1 是一棵九个点的小树，角上标的是深度。

三、换一次根差多少

把根从 u 挪到相邻的 v，只有边 (u, v) 反了方向。v 那一侧的 sz[v] 个点原来要绕过 u，现在直接挂在根底下，每个都浅了一层；剩下的 n − sz[v] 个点原来挂在根底下，现在要多经过 u，每个都深了一层。于是

dp[v] = dp[u] - sz[v] + (n - sz[v]);

这里有个细节值得停下来看一眼：sz[v] 是「以 1 号做根时 v 的子树大小」，而换根之后 v 的子树明明变成了整棵树。公式用的还是原来那个 sz[v]，因为「v 那一侧有几个点」这个划分只取决于删掉哪条边，跟根站在哪一侧无关。所以第二趟里 sz 数组一次都不用改。

从这条式子还能顺手读出两件事。其一，dp[v] − dp[u] = n − 2 × sz[v]，所以只有当 v 那一侧的点数不到一半时，把根换过去才会让答案变大。其二，转移只用到 sz[v] 和 dp[u]，都是已知量，一次 O(1)。

四、两趟 dfs

第一趟定根收信息，第二趟从上往下派答案。第二趟的每一次递归，父亲的答案都已经算好了，正好用来算儿子的。

const int MAXN = 1000001;
    int n, head[MAXN], nxt[MAXN << 1], to[MAXN << 1], cnt;
    int sz[MAXN];
    long long sumv[MAXN], dp[MAXN];

    void addEdge(int u, int v){
        nxt[++cnt] = head[u]; to[cnt] = v; head[u] = cnt;
    }

    // 第一趟：以 1 为根，收集每棵子树的大小与子树内的深度和
    void dfs1(int u, int f){
        sz[u] = 1;
        sumv[u] = 0;
        for (int e = head[u], v; e != 0; e = nxt[e]){
            v = to[e];
            if (v != f){
                dfs1(v, u);
                sz[u] += sz[v];
                sumv[u] += sumv[v] + sz[v];
            }
        }
    }
// 第二趟：已知 u 做根的答案，沿边把根交给 v
    // v 那侧 sz[v] 个点各浅了一层，另外 n - sz[v] 个点各深了一层
    void dfs2(int u, int f){
        for (int e = head[u], v; e != 0; e = nxt[e]){
            v = to[e];
            if (v != f){
                dp[v] = dp[u] - sz[v] + (n - sz[v]);
                dfs2(v, u);
            }
        }
    }

    // 主流程：两趟遍历加一次扫描
    dfs1(1, 0);
    dp[1] = sumv[1];
    dfs2(1, 0);
    int ans = 1;
    for (int i = 2; i <= n; i++){
        if (dp[i] > dp[ans]) ans = i;      // 严格大于，编号小的自然留下来
    }

两趟都是 O(n)，加上最后扫一遍最大值，总共三次线性扫描。题目要编号最小的，扫描时用严格大于比较，先扫到的就留下来了。

六、递归改成迭代

第一趟的递归深度等于树高。n = 10⁶ 的链上树高就是 10⁶，栈撑不住：本机 g++ -O2、8MB 栈下实测，86000 层的链正常返回，87000 层直接段错误，一帧约 97 字节。随机生成的树就温和得多，n = 10⁶ 时实测最大深度只有 32 层，但题目不会保证这一点。

改法和所有的递归转迭代一样：自己压一个栈，栈里除了节点和父亲，还要记「下一条该走哪条边」，这样弹回来才能接着上次的地方走。

// 迭代版：栈里每个元素记 (节点, 父亲, 下一条要走的边)
    // e == -1 表示刚进这个点，否则表示上一条边已经处理完
    int ufe[MAXN][3], top;

    void dfs1(int root){
        top = 0;
        ufe[top][0] = root; ufe[top][1] = 0; ufe[top][2] = -1; top++;
        while (top > 0){
            top--;
            int u = ufe[top][0], f = ufe[top][1], e = ufe[top][2];
            e = (e == -1) ? head[u] : nxt[e];
            if (e != 0){
                ufe[top][0] = u; ufe[top][1] = f; ufe[top][2] = e; top++;
                int v = to[e];
                if (v != f){ ufe[top][0] = v; ufe[top][1] = u; ufe[top][2] = -1; top++; }
            } else {
                // 边全走完，儿子的信息都收齐了，这里就是后序位置
                sz[u] = 1;
                sumv[u] = 0;
                for (int ee = head[u], v; ee != 0; ee = nxt[ee]){
                    v = to[ee];
                    if (v != f){ sz[u] += sz[v]; sumv[u] += sumv[v] + sz[v]; }
                }
            }
        }
    }

e == -1 是刚进这个点的信号，取第一条边；否则取 nxt[e]。取到的边有效就把自己（带着这条边）压回去再压儿子，取完了说明儿子的信息都收齐了，这里就是原来递归的后序位置。第二趟同理，只是把合并换成一句转移。

七、复杂度分析

环节时间空间
第一趟收集（dfs1）O(n)O(n)
第二趟换根（dfs2）O(n)
扫最大值O(n)
合计O(n)
逐个点重新遍历（朴素）O(n²)O(n)

空间按题目上限 n = 10⁶ 算。链式前向星的 nxt、to 各 2n 个 int，head、sz 各 n 个 int，sumv、dp 各 n 个 long long，合计约 2×2×10⁶×4 + 4×10⁶×8 = 48MB。迭代版再添一个 ufe 的 n×3 个 int，约 12MB。深度和本身能到 O(n²) 量级（链上约 n²/2），所以两个答案数组必须是 long long。

实测：随机树 n = 10⁵ 换根全程 6.22ms，n = 10⁶ 是 115.96ms。朴素做法每换一个根重跑一次 bfs，n = 2000 就要 11.78ms，n = 8000 涨到 212.57ms，翻两番点数涨四倍时间，典型的二次曲线；n = 10⁶ 时它要做 10¹² 次访问，换根只做 2×10⁶ 次。

八、总结

要点三条。其一，换根能省事的前提是「相邻的两个根只差一条边」，于是转移只在这条边的两侧做整体偏移，代价 O(1)。其二，sz 这类子树信息只在第一趟算一次，第二趟只读不改，因为「删掉某条边之后两半各是多少」跟根站在哪无关。其三，两次遍历的方向相反，第一趟自底向上收，第二趟自顶向下派，第二趟的每一步都依赖父亲已经算完，顺序不能颠倒。

会不会换根，判断标准就是「父亲做根的答案已知时，儿子的答案能不能 O(1) 加工出来」。下面几页里的题目，转移从一句话变成几句话，骨架始终是这两趟。

九、最后

写的时候有两处容易写错。第一处是sumv[u] += sumv[v] + sz[v] 里的 + sz[v]，漏掉就变成统计子树内的点数和而不是深度和，小数据上看着也像回事。第二处是第二趟把 sz[v] 当成「以 v 做根时 v 的子树大小」去重算，其实它一直是第一趟那个值。拿图 1 这棵树手推一遍，dp[8] = 31 对上了再交。
