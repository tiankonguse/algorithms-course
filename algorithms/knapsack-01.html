01 背包：二维表与空间压缩

容量 t 的背包，n 件货物，每件有花费 cost[i] 和价值 val[i]，每件最多拿一次，问不超过容量时能拿到的最大价值。这个问题的转移方程只有一行，压缩之后只剩一层循环，而压缩时循环方向写反，答案是 40 而不是 15，编译期一句话都不会说。

零、每件货物只有两种可能

枚举所有拿法要 2n 次，n = 30 就过十亿了。换个问法：只在前 i 件里挑，花费不超过 j，最大价值是多少。记成 dp[i][j]。

填 dp[i][j] 时，第 i 件货物只有两个下场。不拿它，那答案跟前 i − 1 件一样，是 dp[i-1][j]；拿它，得先在前 i − 1 件里腾出 cost[i] 的空间，是 dp[i-1][j-cost[i]] + val[i]。两种取大的那个。

dp[i][j] = max(dp[i-1][j], dp[i-1][j-cost[i]] + val[i])

这里有个细节值得停一下：一旦把限制写成「只在前 i 件里挑」加「花费不超过 j」，这个 max 就是完整的，没有第三种情况。因为第 i 件确实只有拿与不拿两种，而拿了之后剩下的子问题（前 i − 1 件、容量 j − cost[i]）和原问题是同一个形式。

答案是 dp[n][t]。表里 j 那一维是「不超过」，所以 dp[i][j] 随 j 单调不减，这一条后面判断自己写得对不对时用得上。

// dp[i][j]：只在前 i 件里挑，花费不超过 j 时的最大价值
    // 第 i 件（花费 cost[i]、价值 val[i]）：要 或 不要
    int knapsack2d(vector<int>& cost, vector<int>& val, int t) {
        int n = cost.size();
        vector<vector<int>> dp(n + 1, vector<int>(t + 1, 0));
        for (int i = 1; i <= n; i++) {
            for (int j = 0; j <= t; j++) {
                dp[i][j] = dp[i - 1][j];                       // 不要第 i 件
                if (j - cost[i - 1] >= 0) {
                    dp[i][j] = max(dp[i][j],                   // 要第 i 件
                                   dp[i - 1][j - cost[i - 1]] + val[i - 1]);
                }
            }
        }
        return dp[n][t];
    }

注意下标：货物在代码里存成 0 基准的 cost[i-1]，i 从 1 走到 n，第 0 行整行是 0，表示「一件都没有时价值是 0」。

一、空间压缩：j 必须从大到小

看转移方程里 dp[i] 这一行只依赖 dp[i-1] 那一行，i − 2 及更早的行用完就再也没人看了。于是可以只留一维数组，让 dp[j] 表示「当前处理过的货物里，花费不超过 j 的最大价值」。

关键是刷新顺序。dp[j] 要用到的 dp[j-cost[i]] 必须是上一轮的值，也就是还没考虑第 i 件时的样子。j 从大到小走，j-cost[i] 一定比 j 小，它还没被本轮碰过，读到的是旧值。反过来从小到大走，j-cost[i] 已经在本轮被写过了，读到的其实是「已经拿过一次第 i 件」的结果，再往上加 val[i]，等于把同一件货物拿了两次。

上面的例子只有两件货物：cost = [3, 2]，val = [5, 10]，t = 8。倒序那行最后停在 15，也就是两件都拿（花费 5）；正序那行停在 40，是把 cost = 2 的那一件拿了四次。真实世界里没有四次可拿，40 这个数纯属循环方向给的。

// 空间压缩：只剩一维 dp[j]，j 必须从大到小刷
    // 小下标先动，dp[j - cost[i]] 就会被本轮写脏，同一件被拿第二次
    int knapsack1d(vector<int>& cost, vector<int>& val, int t) {
        int n = cost.size();
        vector<int> dp(t + 1, 0);
        for (int i = 0; i < n; i++) {
            for (int j = t; j >= cost[i]; j--) {
                dp[j] = max(dp[j], dp[j - cost[i]] + val[i]);
            }
        }
        return dp[t];
    }

循环的下界直接写 j >= cost[i] 就行，比 cost[i] 小的 j 根本放不下这一件，值不变，可以整个跳过。二维版本里那个 if (j - cost[i-1] >= 0) 判的是同一件事。

演示一：填表台（二维表 / 压缩倒序 / 压缩正序）

二、两种写反的方式，以及它们的代价

循环方向写反是第一种。实测两万组随机样本（n 在 1 到 6，t 在 1 到 30），正序版本有 68.89% 的样本答案和正解不同，平均虚高 3.70 倍。放大容量更离谱：t = 1000 时正解 132，正序版本算出 10000。

错版答案只会偏大，不会偏小。它算的是「每件货物能拿无限次」的最优解（那是另一道题，叫完全背包），这个解的集合包含所有合法拿法，所以最大值不可能更小。想自查的话，扫一遍最终的 dp 数组看它是否单调不减，是个便宜的办法。

第二种是把初始化写错。上面那套写法回答的是「不超过 t 的最大价值」，dp 全填 0，含义是「什么都没拿时价值 0」，所有容量都合法。如果题面问的是「恰好花光 t 时的最大价值」，0 初始化就全错了：它会拿不满的容量当成合法答案报出来。实测两万组，0 初始化版有 79.78% 回答得跟真答案不一样。

具体到一个例子：cost = [3, 4]，val = [5, 6]，t = 5。恰好装满只有一种拿法（拿 cost = 3 的那件），答案是 5；0 初始化版报 6，那是「不超过 5」的答案。要答「恰好」，得把 dp 初值设成一个极小的负数，只留 dp[0] = 0，转移时先判断来源格子是不是可达。

题面怎么问就怎么初始化，这一步没有通用答案。01 背包的模板题（比如采药）问的是「不超过」，所以 0 初始化是对的。

三、夏季特惠：把约束换算成容量

换一道看起来完全不像背包的题。预算 X 元，n 个游戏都在打折，第 i 个原价 ai、现价 bi、买了能获得快乐值 wi。允许最终总花费超过预算，只要「获得的总优惠金额不低于超出预算的总金额」就不算吃亏。问不吃亏的前提下快乐值最大能到多少。

先把「不吃亏」写成一个不等式。买了集合 S，总花费是 Σb，超出预算的部分是 Σb − X（没超就算 0），总优惠是 Σ(a − b)。要求：

Σ(ai − bi) ≥ Σbi − X　　⟺　　Σ(ai − 2bi) ≥ −X

右边是 −X，跟 S 无关，可以整体搬到左边。记 well[i] = a[i] - 2*b[i]，约束变成 Σwell ≥ −X。

接下来是这一步题眼。well ≥ 0 的商品，买了只会让左边更大，约束永远不会被它破坏，它是白送的快乐值，直接买，同时把预算加上 well（相当于这件商品把预算变大了）。真正需要挑的是 well < 0 的商品：买它要花掉 −well 点「预算额度」，换来 wi 的快乐值。这就是一件货物的两个属性。

于是剩下的部分是标准 01 背包：容量是扩过之后的 X，货物是那些 well < 0 的商品，花费是 −well，价值是 wi。最后别忘了把必买那批的快乐值加回去。

// 第 i 件：原价 a[i]、现价 b[i]、快乐值 w[i]
    // 买了它，总花费多 b[i]，总优惠多 a[i] - b[i]
    // 「不觉得吃亏」要求：总优惠 >= 超出预算的部分
    //   总优惠 - 总花费 >= -X
    //   Σ(a[i] - 2*b[i]) >= -X      记 well[i] = a[i] - 2*b[i]
    // well >= 0 的商品：买了只会让左边更大，白送的快乐值，必买，且预算 += well
    // well <  0 的商品：才是真正要挑的货物，花费 = -well，价值 = w[i]
    long long buyGames(vector<int>& a, vector<int>& b, vector<long long>& w, int x) {
        int n = a.size();
        vector<int> cost;
        vector<long long> val;
        long long ans = 0;
        for (int i = 0; i < n; i++) {
            int well = a[i] - b[i] - b[i];
            if (well >= 0) {
                x += well;          // 这件商品相当于把预算变大了
                ans += w[i];
            } else {
                cost.push_back(-well);
                val.push_back(w[i]);
            }
        }
        vector<long long> dp(x + 1, 0);
        for (int i = 0; i < (int)cost.size(); i++) {
            for (int j = x; j >= cost[i]; j--) {
                dp[j] = max(dp[j], dp[j - cost[i]] + val[i]);
            }
        }
        return ans + dp[x];
    }

实测 n = 500、X = 100000 的随机数据：330 件（66.0%）是必买商品，真正进背包的只有 170 件，预算从 100000 涨到 190699，耗时 15.835 毫秒。如果把「必买」这批直接扔掉不买，会少掉 159826909 点快乐值。x += well 这一行是约束推出来的，删掉它答案就错了。

四、复杂度分析

做法时间额外空间说明
枚举子集O(2n)O(1)n = 30 就过十亿次，只适合做对拍的参考
二维表O(n · t)O(n · t)(n+1)(t+1) 个 int，n = 2000、t = 20000 时 152.7 MB
空间压缩O(n · t)O(t)只留 t+1 个 int，同上规模 0.1 MB，实测 21.029 毫秒

时间那一栏两种写法一样，都是 n 趟 × 每趟最多 t 格。差别全在空间：n = 2000、t = 20000 时二维表 66.047 毫秒、152.7 MB，压缩版 21.029 毫秒、0.1 MB。压缩版更快的另一个原因是它跳过了 j < cost[i] 那一段，二维版每一格都要走一遍 dp[i-1][j] 赋值。

n = 5000、t = 100000 的规模，二维表需要 1907.7 MB，本机根本开不出来；压缩版 242.592 毫秒跑完。所以空间压缩在这道题里决定了能不能提交：二维表压根开不出来。

夏季特惠那题的复杂度跟上面同一套：O(n · X')，X' 是扩完之后的总预算，额外空间 O(X')。

五、总结

01 背包的骨架就三句话：定义「前 i 件、容量 j」，转移时把第 i 件拆成拿与不拿，压缩之后 j 一定倒着走。

几个容易写错的点：

1）压缩版的 j 必须从 t 降到 cost[i]。写反了算的是「每件能拿无限次」，答案只会偏大，实测两万组随机样本里 68.89% 现形。

2）dp 初值按题面来。「不超过 t」全填 0；「恰好花光 t」要用极小负数初始化并只留 dp[0] = 0。用错初始化，两万组里 79.78% 答错。

3）二维表那行的 dp[i][j] = dp[i-1][j] 不能省，它对应「不拿」这种可能，只写 max 里那一项等于强制每件都拿。

4）遇到约束不像容量的题（像夏季特惠），先把不等式整理成「Σ某项 ≤ 常数」的形状，再去找哪一项是花费、哪一项是价值。
