01Trie 上的异或极值

上一页的线性基解决的是「整张图随便走」的极值。这一页换成 01Trie，它解决的是另一个方向的问题：从一堆数里挑一个，和给定的 x 异或出最大值。两道题，一道把这个查询套进时间轴线段树分治（用可持久化 Trie 做区间版本差），一道根本不需要分治，数据规模本身就是提示。

零、背景

前置是可持久化前缀树。可持久化线段树那套「版本差 = 区间信息」的思路在 01Trie 上照常成立：按商店编号依次插入商品价格，root[i] 是插入前 i 个商店之后的版本，query(x, root[l-1], root[r]) 就是在「只有商店 l 到 r 的商品」这个集合里找与 x 异或的最大值。

01Trie 的查询规则只有一条：从最高位往下走，每一步优先走「和 x 当前位相反」的儿子，那一分支能让异或值的这一位变成 1；相反的分支不存在，才走同向的。

一、题目6 火星商店

有 n 个商店，每个商店只有一种初始商品，给出每个商店的初始商品价格。有 m 条操作：操作 0 s v 会让天数 +1，第 s 号商店在这一天新增一件价格为 v 的商品；操作 1 l r x d 询问，只能在商店 [l, r] 里挑，只能挑初始商品或最近 d 天内出现的新商品，挑一件，打印价格 ^ x 的最大值。注意只有操作 0 能让天数 +1。数据范围 0 ≤ 所有数据 ≤ 10⁵（测试链接：https://www.luogu.com.cn/problem/P4585）。

朴素做法是每个询问把 [l, r] 里的所有商品扫一遍：初始商品可以预处理，但新商品会越积越多，一个商店可能被操作 0 打进上千件商品，询问一多就爆炸。

把限制拆开看，其实是两个维度：商店维度（l ≤ 商店 ≤ r）和时间维度（商品出现日期 ≥ 当前天数 - d + 1）。初始商品没有时间限制，新商品没有初始价格身份，两类的约束不一样，所以分开处理。

初始商品：按商店编号 1 到 n 建前缀可持久化 01Trie（价格不超过 10⁵，BIT 开到 16）。每个操作 1 先直接用版本差吃掉初始商品的部分：query(x, root[l-1], root[r])。

新商品：每件新商品有出现日期 tim（就是它那条操作 0 时的天数），购买限制「d 天内出现」等价于 tim ∈ [当前天数 - d + 1, 当前天数]。于是把时间 1 到 t 建成线段树：新商品沿根到叶的路径挂（它只在一个时刻出现），购买挂在覆盖自己时间区间的那些节点上。这样任何一个节点上，挂着的购买和挂着的商品在时间维度上天然匹配。

1.1 可持久化 01Trie 的插入与版本差查询

插入和可持久化线段树一模一样：新版本复制旧版本的根，沿途只新建走到的那些节点，pass 计数加 1。查询时 u、v 是同一位置的旧、新两个版本，pass[v][分支] > pass[u][分支] 说明这段商店区间里存在走这个分支的商品。

    
int insert(int num, int i) {
        int rt = ++cntt;
        tree[rt][0] = tree[i][0];
        tree[rt][1] = tree[i][1];
        pass[rt] = pass[i] + 1;
        for (int b = BIT, path, pre = rt, cur; b >= 0; b--, pre = cur) {
            path = (num >> b) & 1;
            i = tree[i][path];
            cur = ++cntt;
            tree[cur][0] = tree[i][0];
            tree[cur][1] = tree[i][1];
            pass[cur] = pass[i] + 1;
            tree[pre][path] = cur;
        }
        return rt;
    }

    int query(int num, int u, int v) {
        int ansv = 0;
        for (int b = BIT, path, best; b >= 0; b--) {
            path = (num >> b) & 1;
            best = path ^ 1;
            if (pass[tree[v][best]] > pass[tree[u][best]]) {
                ansv += 1 << b;
                u = tree[u][best];
                v = tree[v][best];
            } else {
                u = tree[u][path];
                v = tree[v][path];
            }
        }
        return ansv;
    }

1.2 两类挂法

新商品只在一个时刻出现，但为了让「商品挂在的所有祖先节点」都能看到它，代码里沿着根到叶的整条路径都 addInfoP 一次（addProduct 先给当前节点挂上再往下递归）。购买则用普通的区间拆分挂到 O(log t) 个节点上。

    
void addProduct(int jobi, int pi, int l, int r, int i) {
        addInfoP(i, pi);
        if (l < r) {
            int mid = (l + r) >> 1;
            if (jobi <= mid) {
                addProduct(jobi, pi, l, mid, i << 1);
            } else {
                addProduct(jobi, pi, mid + 1, r, i << 1 | 1);
            }
        }
    }

    void addBuy(int jobl, int jobr, int bi, int l, int r, int i) {
        if (jobl <= l && r <= jobr) {
            addInfoB(i, bi);
        } else {
            int mid = (l + r) >> 1;
            if (jobl <= mid) {
                addBuy(jobl, jobr, bi, l, mid, i << 1);
            }
            if (jobr > mid) {
                addBuy(jobl, jobr, bi, mid + 1, r, i << 1 | 1);
            }
        }
    }

1.3 节点内的处理

dfs 到一个节点：先把挂在这里的新商品收集起来、按商店编号排序，重建一棵局部可持久化 Trie（每个节点都从 cntt = 0 重新开点，上一层的节点直接废弃，内存可以反复利用）。然后对每个挂在这里的购买，二分出商店区间 [pre+1, post]，用版本差查询，和已有答案取 max。

    
void dfs(int l, int r, int i) {
        int pcnt = 0;
        for (int e = headp[i]; e > 0; e = nextp[e]) {
            product[++pcnt].s = s[pid[e]];
            product[pcnt].v = v[pid[e]];
        }
        sort(product + 1, product + pcnt + 1, ProductCmp);
        cntt = 0;
        for (int k = 1; k <= pcnt; k++) {
            root[k] = insert(product[k].v, root[k - 1]);
        }
        for (int e = headb[i], id, pre, post; e > 0; e = nextb[e]) {
            id = bid[e];
            pre = lower(pcnt, sl[id]) - 1;
            post = upper(pcnt, sr[id]);
            ans[id] = max(ans[id], query(x[id], root[pre], root[post]));
        }
        if (l < r) {
            int mid = (l + r) >> 1;
            dfs(l, mid, i << 1);
            dfs(mid + 1, r, i << 1 | 1);
        }
    }

prepare 里注意两件事：root 数组先装初始商品（root[i] = 插入商店 i 后的版本），每个操作 1 先把初始商品部分的答案算进 ans[i]，再把新商品部分挂到时间树上。

    
void prepare() {
        for (int i = 1; i <= n; i++) {
            root[i] = insert(arr[i], root[i - 1]);
        }
        for (int i = 1; i <= m; i++) {
            if (op[i] == 0) {
                addProduct(tim[i], i, 1, t, 1);
            } else {
                ans[i] = query(x[i], root[sl[i] - 1], root[sr[i]]);
                int start = max(tim[i] - d[i] + 1, 1);
                if (start <= tim[i]) {
                    addBuy(start, tim[i], i, 1, t, 1);
                }
            }
        }
    }

复杂度：每件新商品挂在 O(log t) 个节点上，每个节点重建 Trie 是「节点上新商品数 × (BIT + 1)」，全部分摊下来是 O(新商品数 · log t · BIT)；每个购买挂在 O(log t) 个节点，每个挂点花 O(log 商品数 + BIT)。整个 dfs 结束时所有节点的答案都已并入，操作 1 的输出就是 ans[i]。

二、题目7 最小异或查询

黑板上初始为空，q 条操作：操作 1 x 写上一个数字 x（同一种数字可以出现多次）；操作 2 x 擦掉一个 x（保证存在）；操作 3 打印黑板上任意两个数的最小异或值（保证至少两个数）。数据范围 1 ≤ q ≤ 3 · 10⁵，0 ≤ x ≤ 2³⁰（测试链接：https://www.luogu.com.cn/problem/AT_abc308_g）。

先看数据量：q 是 3 · 10⁵，每次操作都要有输出的话，单次操作只付得起 O(30) 左右。线段树分治解决的是「元素的生效区间」这类问题，这里的插入和删除都是单点的、生效期无法预先知道，分治没有用武之地。

能这么便宜的原因在于：一次插入或删除只影响 01Trie 上一条根到叶的路径。于是把树建得不动态，节点只增不减，每个节点放一个 pass 计数，插入 +1、删除 -1，然后沿叶子到根把两个辅助值重算一遍。

每个节点维护两个值：mineor[i] 是这个子树里任意两个数的最小异或值（子树里不足两个数时为 INF），only[i] 是子树里恰好有一个数时那个数是多少（否则 0）。

重算的关键在四个分支。设左右儿子是 l、r：

1，pass[i] < 2：子树里不足两个数，mineor = INF。

2，pass[l] == 1 且 pass[r] == 1：唯一的一对数分在两侧，mineor = only[l] ^ only[r]。

3，恰好一侧为空：mineor = 另一侧的 mineor。

4，两侧都有数且至少一侧 ≥ 2：mineor = min(mineor[l], mineor[r])。

第 4 种情况为什么不用算跨侧的对？设节点在 trie 的第 level 层，同侧的两个数共享这个节点，它们的异或值在 level 这一位及以上全是 0，所以必然小于 2^level；跨侧的一对数在这一位不同，异或值恰好含这一位的 1，必然 ≥ 2^level。也就是说，只要有一侧能自己配出对，那个对就严格小于任何跨侧的对。

一次插入或删除落到某个叶子上，从这里到根最多 BIT + 1 层，每层按上面四个分支重算，单次操作 O(30)。查询操作 3 直接读 mineor[根]。

    
int change(int x, int changeCnt) {
        int cur = 1;
        pass[cur] += changeCnt;
        for (int b = BIT, path; b >= 0; b--) {
            path = (x >> b) & 1;
            if (tree[cur][path] == 0) {
                tree[cur][path] = ++cnt;
                fa[tree[cur][path]] = cur;
            }
            cur = tree[cur][path];
            pass[cur] += changeCnt;
        }
        return cur;
    }

compute 先用 change 把 x 的计数 ±1 并拿到叶子，从叶子往根逐层重算 mineor 与 only：

    
void compute(int x, int changeCnt) {
        int bottom = change(x, changeCnt);
        mineor[bottom] = pass[bottom] >= 2 ? 0 : INF;
        only[bottom] = pass[bottom] == 1 ? x : 0;
        for (int i = fa[bottom], l, r; i > 0; i = fa[i]) {
            l = tree[i][0];
            r = tree[i][1];
            if (pass[i] < 2) {
                mineor[i] = INF;
            } else if (pass[l] == 1 && pass[r] == 1) {
                mineor[i] = only[l] ^ only[r];
            } else if (pass[l] == 0 ^ pass[r] == 0) {
                mineor[i] = pass[l] == 0 ? mineor[r] : mineor[l];
            } else {
                mineor[i] = min(mineor[l], mineor[r]);
            }
            if (pass[l] + pass[r] == 1) {
            	only[i] = pass[l] == 1 ? only[l] : only[r];
            } else {
            	only[i] = 0;
            }
        }
    }

主流程很短：操作 3 直接输出 mineor[1]，操作 1、2 分别以 ±1 调 compute。注意 pass 用的是加在沿途每个节点上的计数，删除时减回去，节点结构完全不动。

    
    int q;
        cin >> q;
        for (int i = 1, op, x; i <= q; i++) {
            cin >> op;
            if (op == 3) {
                cout << mineor[1] << '\n';
            } else {
                cin >> x;
                if (op == 1) {
                    compute(x, 1);
                } else {
                    compute(x, -1);
                }
            }
        }

四、最后

两道题一个用分治一个不用，判据是同一句话：元素的生效区间能不能预先算出来。火星商店的新商品有明确的「出现日期 + 有效期」，分治把它们对齐；黑板上的数活到删除为止、删除随时发生，硬套分治反而做不出区间，老老实实维护计数才是正路。

查询侧都是「版本差 = 区间信息」：可持久化 Trie 的 root[r] 减 root[l-1] 得到区间版本，插入沿叶到根重算 pass、mineor、only，查询 O(1) 读根节点。
