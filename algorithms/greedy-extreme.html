贪心：把候选存起来，每次动最大的

一道题要反复把当前最大的那个数折半，一道题要把路过的加油站攒起来、缺油时才用。两道题的答案都长在一句「每次都拿最大的那个」上。

零、两道题各自要什么

第一题：给一个正整数数组 nums。对任意元素可以做任意次两类操作，偶数可以除以 2，奇数可以乘以 2。数组的偏移量是任意两个元素差值的最大值，求操作之后能得到的最小偏移量。

第二题：车从起点出发去 target 英里外的目的地，每英里耗 1 升油，最初有 startFuel 升，油箱容量无限。沿途有加油站 stations[i] = [position, fuel]，车开到就能把这站的油全部搬进油箱。求最少加油几次，到不了返回 -1。

两题各需要一个容器，第一题要随时拿出最大值和最小值，第二题只要每次拿出最大值。两题都不追求严格证明，关键观察摆出来之后，用对数器跑一遍最省事。

一、最小偏移量：奇数先乘 2，再反复折半最大值

先把每个数能变成什么想清楚。偶数 x 一直折半，会依次得到 x/2、x/4……直到一个奇数核 o，再往下就除不尽了。从 o 出发只能乘 2 回到 2o，那是折半路上已经出现过的值。所以一个数能取的只有 o × 2k 这一族，其中 o 是它的奇数核。

奇数那一族里只有两个成员：x 和 2x。把 x 乘 2 就站到了这一族的顶端，之后每折半一次走一格。偶数本来就在自己那一族的顶端。所以第一步统一处理：奇数乘 2，让所有数都站在自己可达范围的最大值上。

接下来每一步只剩一个值得做的动作，把当前最大值除以 2。理由很直接：想让最大值变小，唯一的手段就是折半，而折半之后那个新值还要参与比较，只有折半最大值才有可能同时压低上界。

用一个例子走一遍。nums = [1,2,3,4]，奇数 1 和 3 先乘 2，数组变成 [2,2,6,4]，区间是 6 减 2 等于 4。最大值 6 是偶数，折半成 3，数组变成 [2,2,3,4]，区间 4 减 2 等于 2。最大值 4 折半成 2，数组变成 [2,2,3,2]，区间 3 减 2 等于 1。现在最大值 3 是奇数，折不了，停下，答案是 1。

复杂度上有一个容易忽略的地方：每次折半最大值都会把它降下来，但被降下来的那个值可能顶掉最小值的位置，所以容器得同时支持取最大、取最小和插入。用有序表（C++ 的 multiset）最省事，循环里每次都重新读一遍两端的差。

// 数组的最小偏移量：偶数可以除以 2，奇数可以乘以 2，操作任意次，求最小的「最大值减最小值」
    // 奇数先全部乘 2 变成偶数；之后每一步只有「把最大值除以 2」这一种能缩小差距的操作
    // 用有序表同时拿到最大值和最小值
    int minimumDeviation(vector<int> nums) {
        multiset<int> st;
        for (int num : nums) {
            st.insert(num % 2 == 0 ? num : num * 2);
        }
        int ans = *st.rbegin() - *st.begin();
        while (ans > 0 && *st.rbegin() % 2 == 0) {
            int mx = *st.rbegin();
            st.erase(prev(st.end()));
            st.insert(mx / 2);
            ans = min(ans, *st.rbegin() - *st.begin());
        }
        return ans;
    }

停止条件是「最大值是奇数」或者「所有数相等」。数组里全是 2 的幂时，初始最大值和最小值的比值就是 1，一次循环都不需要，实测 n = 105 个 229 用 13.4ms，循环 0 次；换成 105 个随机值，循环 23365 次，用 39.0ms。

这条贪心对不对？直接跑对数器：暴力把每个数的可达值全部展开、枚举所有组合取最优，小数组上跑了几千组，答案一直对得上。下面第四节列了几种常见改法的出错比例。

二、最低加油次数：路过的站先攒着

「在哪些加油站停下来加油」这个选择一旦事前决定就很麻烦：站的数量是指数级的，早期少加一桶油可能让后面多跑一段路。把决策推迟：先开车往前，路过的每一个加油站都记进袋子，只有真的开不动了才从袋子里拿一桶油。

袋子里为什么只有路过的站？因为还没开到的站够不着。袋子用什么装？每到「油不够开到下一站」的时候，车已经在当前位置，袋子里是所有可选油量的集合，加一次油的效果只有两个：加油次数加一、能开的距离增加。次数固定时，加最大的那桶显然能开得最远，所以袋子取最大值，也就是一个大根堆。

拿样例 target = 100、startFuel = 10、stations = [[10,60],[20,30],[30,30],[60,40]] 走一遍。起点油量 10，开到 10 英里处剩 0，到站后袋子装进 60 升。继续开到 20 英里前油正好见底，袋子拿出 60，油量变成 70，这是第 1 次加油；到 20 英里处袋子收 30。30 英里处再收 30，60 英里处收 40。四个站都过了，油量 70 还差 30 到目的地，袋子拿出最大的 40，油量 110，第 2 次加油，到了。

最后这段「所有站都过了，再从袋子里捞」是代码里单独一层循环，最容易漏。漏掉它的写法在两万组随机数据上出错 13% 左右。

// 最低加油次数：油箱容量无限、每英里耗 1 升，求开到 target 的最少加油次数
    // 把路过的加油站全部攒进一个大根堆，只在油不够开到下一站时，取出最满的那一桶
    int minRefuelStops(int target, int startFuel, vector<pair<int, int>> stations) {
        if (startFuel >= target) {
            return 0;
        }
        priority_queue<int> heap;
        long long to = startFuel;
        int cnt = 0;
        for (auto& s : stations) {
            int position = s.first;
            int fuel = s.second;
            if (to < position) {
                while (!heap.empty() && to < position) {
                    to += heap.top();
                    heap.pop();
                    cnt++;
                    if (to >= target) {
                        return cnt;
                    }
                }
                if (to < position) {
                    return -1;
                }
            }
            heap.push(fuel);
        }
        while (!heap.empty()) {
            to += heap.top();
            heap.pop();
            cnt++;
            if (to >= target) {
                return cnt;
            }
        }
        return -1;
    }

实测 target = 106、9999 个站每 100 英里一个、每站 1 到 400 升、起步 100 升，答案是 2932 次，跑完只要 0.19ms。加油站数量取到 104 量级时，每个站进堆一次、最多弹出一次，代价全是堆操作。

四、对数器怎么抓错

覆盖率的量法：批量生成随机小数据，把两种写法都跑一遍，数答案不一样的比例。第一题的暴力是枚举每个数的可达值组合，第二题的暴力是枚举「用哪些站加油」的所有子集。

题目写法小中大
最小偏移量奇数不乘 2，直接放进有序表28.51%31.64%29.55%
最小偏移量折半最大值时不看奇偶48.12%72.33%80.22%
最小偏移量中途不更新答案0.00%6.74%11.24%
最低加油次数袋子换成小根堆0.19%15.73%24.91%
最低加油次数见站就加油0.12%10.51%15.69%
最低加油次数收尾不再榨一次袋子2.39%14.10%13.14%

第一题三档值域是 4 / 10 / 106，第二题是三档加油站油量上限 1~150 / 1~250 / 1~400，其中可到达的数据分别占 2.41%、23.52%、35.77%。

「中途不更新答案」在小值域上抓不到，因为小值域里折一两次半所有数就相等了，区间变成 0，答案在任何时刻取都一样。「袋子换成小根堆」的出错比例随油量上限上升，因为油量差距越大，拿错一桶的代价越明显；反过来「收尾不再榨袋子」在小数据上反而更容易被抓到，数据小的时候目的地常常就差最后一桶油。

复杂度分析

题目关键操作时间空间
最小偏移量有序表插入 / 删除，循环次数等于折半次数O((n + T) log n)，T 是总折半次数O(n)
最低加油次数每个站进堆一次，最多弹出一次O(m log m)，m 是加油站数O(m)

第一题的 T 上界是 n 乘每个数的 2 因子个数，值到 109 时单个数的上限是 30，实测随机数据只有 23365 次。第二题的时间全在堆上，9999 个站用了 0.19ms。

总结

最小偏移量那题先把每个数的可达范围看清楚：它就是奇数核乘 2 的若干个幂，所以奇数先乘 2 站到顶端，之后每一步折半最大值。每一步都不会让区间变大，停下时最大值已经是奇数，再没有能压低上界的操作。容器要能同时取最大和取最小，因为有数被折半之后可能成为新的最小值。

最低加油次数那题把「在哪些站加油」推迟到必须加油的那一刻：路过的站全部进大根堆，缺油时取最满的一桶。收尾阶段单独一层循环，所有站都过了还得再榨一次袋子。两题的形式一样，候选放进一个有序容器，每次只动其中最大的那个。
