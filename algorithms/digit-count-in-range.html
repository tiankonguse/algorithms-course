按位算贡献：区间里某个数码出现了多少次

这道题换了个角度：不数有哪些数满足条件，改成盯着每一个数位问「这一位上出现过多少次 d」。每一位只算一次乘法加一次判断，二十位数也就二十次。角度一换，复杂度从「跟区间长度成正比」变成「跟位数成正比」。

零、题目

给两个正整数 a 和 b，求 [a, b] 上所有整数里，数码 d 出现了多少次。三个变体问的是同一件事：只问一个 d、问每个数码各多少次、只问 1 的个数。

区间照样拆成 count(b, d) − count(a−1, d)，问题变成求 [1, num] 上数码 d 出现的次数。注意下界是 1 不是 0，这个区别在 d = 0 的时候会咬人。

一、盯着一个位看

以 num = 30583、d = 5 为例。看百位那一位（权是 100）：

把 num 按某一位切成三段：左边的 left、这一位上的 cur、右边的 right（right 是 10 的幂，同时也就是右边那一块的取值个数）。

left 和 right 一乘，就是「左边随便取、右边随便取」时这一位上出现 d 的次数：left × right。左边能从 0 取到 left − 1，一共 left 种；右边能取 0 到 right − 1，一共 right 种。

剩下的是左边取到 left（也就是贴着 num 的左边那一段）时，这一位还能不能取到 d。分三档：

1）cur < d：这一位最大才 cur，够不着 d，没有额外贡献。

2）cur > d：这一位能取一个完整的 d，右边随便取，额外加 right。

3）cur == d：这一位取 d 时，右边只能取到 num 的低位部分，额外加 num % right + 1。

30583 上五位的贡献依次是 3058、3060、3084、3000、0，加起来 12202。最后一档是 0，因为最高位是 3，比 5 小，这一位上根本取不到 5。

二、d 是 0 的时候，left 要减一

数字不写前导零，所以「左边全是 0」那一大档里，这一位的 0 是不算数的。left 要减 1，把这一档去掉。

num = 13、d = 0 这个例子最直观：1 到 13 里只有 10 带一个 0，答案是 1。不减 left 的话，个位那一档算 left = 1、cur = 3，贡献 left × right + right = 1 + 1 = 2；十位那一档算 left = 0、cur = 1，贡献 0 + right = 10；加起来 12，凭空多出 11 个 0，全是 01、02、…、09 这些被当真数字写出来的前导零。

三、代码

整个函数就是一个循环，每次砍掉最低位，right 乘 10。

// 统计 1 ~ num 范围上所有的数中，数码 d 出现了多少次
    // 注意是 1 ~ num 范围，不是 0 ~ num 范围
    ll count(ll num, int d) {
        ll ans = 0;
        // left  : 当前位左边的情况数
        // right : 当前位右边的情况数（10 的幂）
        // cur   : 当前位的数字
        for (ll right = 1, tmp = num, left, cur; tmp != 0; right *= 10, tmp /= 10) {
            left = tmp / 10;
            cur = tmp % 10;
            if (d == 0) {
                left--;                   // 前导零不算数，最高位那一档要去掉
            }
            ans += left * right;
            if (cur > d) {
                ans += right;             // 左边取到 left 时，这一位还能取一次 d
            } else if (cur == d) {
                ans += num % right + 1;   // 左边只能取到 num 的低位部分
            }
        }
        return ans;
    }

循环条件是 tmp != 0，所以 num = 0 直接返回 0，正好对应「1 到 0 是空区间」。三个变体共用这一个函数：

// 题目 4-1：求 [a, b] 上数码 d 出现的次数
    int digitsCount(int d, int a, int b) {
        return count(b, d) - count(a - 1, d);
    }

    // 题目 4-2：求 [a, b] 上每个数码各出现多少次，逐个调用 count 即可
    void solveAll(ll a, ll b) {
        for (int i = 0; i < 9; i++) {
            cout << digitsCount(i, a, b) << " ";
        }
        cout << digitsCount(9, a, b) << "\n";
    }

    // 题目 4-3：小于等于 n 的非负整数中数字 1 出现的个数
    // 0 里面没有 1，所以 1 ~ n 和 0 ~ n 的答案一样
    int countDigitOne(int n) {
        return count(n, 1);
    }

四、写错的地方

三种错法各跑两万组随机区间（a、b 在 10⁵ 以内，d 随机）。

漏掉 cur > d 那一档，79.17% 的样本会错，答案平均偏小 49%。漏掉 cur == d 时该加 num % right + 1 而写成加 right，56.70% 会错。

d = 0 不减 left 这一档在混合数据上只有 5.99%，看着不高，那是因为随机取 d 时只有十分之一是 0。单独取 d = 0 再跑两万组，现形率升到 59.19%；反过来只取 d 从 1 到 9，这一档是 0.00%，因为它压根不会被执行到。

具体反例：[1, 13] 上 d = 0，正解 1，不减 left 给 12；[1, 100] 上 d = 1，正解 21，把 num % right + 1 写成 right 给 120；[1, 30583] 上 d = 5，正解 12202，漏掉 cur > d 给 12192。

七、边界与代价

下界是 1 不是 0，这一点在 d = 0 时必须想清楚。count(0, d) 返回 0，因为 1 到 0 是空区间。

「小于等于 n 的非负整数中 1 的个数」这一问的区间是 [0, n]，比 [1, n] 多一个 0。0 里面没有数字 1，所以两个区间的答案一样，count(n, 1) 可以直接用。换成问 0 的个数就不能这么干了，0 本身就带一个 0。

1 到 100 上十个数码的次数是 11、21、20、20、…、20；1 到 1000 上是 192、301、300、…、300。1 那个数码总是多一点，因为最高位那一段只有它能取到。

八、复杂度分析

项目值
单次 countO(log₁₀ num)，就是 num 的位数，20 位也只要 20 次循环
区间查询两次 count，O(log₁₀ b)
十个数字一起查十次区间查询，还是 O(log₁₀ b)，常数翻十倍
额外空间O(1)，只用几个变量

空间这一项没什么可说的，全程没有数组。时间上，num 到 10¹⁸ 也只有 19 次循环，实测单次 0.000011 毫秒量级。

九、总结

数数的题换个问法：不问「哪些数满足条件」，改问「这一位上出现过多少次 d」。前者跟区间长度成正比，后者只跟位数成正比。

拆位之后核心是 left × right 这一项，它表示「左边和右边都随便取」。贴着上界的那一段单独处理，按 cur 和 d 的大小分三档。

d = 0 要减一个 left，减掉的是前导零那一档。这一处漏了在随机数据上只现形 6%，单测 d = 0 才容易抓到。

下界是 1 而不是 0。题目问 [0, n] 时要自己确认 0 这个数会不会影响答案。问 1 的个数没事，问 0 的个数就不行。
