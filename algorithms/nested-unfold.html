嵌套展开：字符串解码与原子计数

上一页的 where 框架，这一页连着用两遍：字符串解码把子段重复 cnt 遍拼起来，分子式把括号里的计数乘倍并进总表。

零、背景

解码的规则：「3[a2[c]]」→「accaccacc」。数字后跟方括号，方括号里的内容重复数字那么多次，括号可以嵌套。输出经常比输入长一大截：「100[leetcode]」13 个字符的输入，展开出 800 个字符。

原子计数：「K4(ON(SO3)2)2」→「K4N2O14S4」。元素首字母大写、可带小写（O、Mg 各算一个元素，SO3 里 S 和 O 分开数）；括号后跟数字，括号内所有计数乘倍；最终按字典序输出。

两题和表达式求值共享同一个骨架：遇到嵌套开始就递归，内层返回后从 where + 1 继续。差别只在「内层的结果拿来怎么用」。

一、字符串解码

f(i) 解析到 ']' 或结尾停。段内三件事：字母拼进 path；数字累进 cnt；遇到 '[' 调下级 f，把返回的子段重复 cnt 遍拼上，然后 i = where + 1、cnt 清零。

#include <bits/stdc++.h>
    using namespace std;

    // 全局 where：记录当前这一段解析停在哪，返回前更新
    int where = 0;

    string repeat(int cnt, const string& str);

    // s[i..] 开始解析，遇到字符串结尾或 ']' 停止
    // 返回自己负责的这一段的字符串结果
    string f(const string& s, int i) {
        string path;
        int cnt = 0;
        while (i < (int)s.length() && s[i] != ']') {
            if ((s[i] >= 'a' && s[i] <= 'z') || (s[i] >= 'A' && s[i] <= 'Z')) {
                path += s[i++];
            } else if (s[i] >= '0' && s[i] <= '9') {
                cnt = cnt * 10 + s[i++] - '0';
            } else {
                // 遇到 '['，cnt 是这段重复的次数
                path += repeat(cnt, f(s, i + 1));
                i = where + 1;
                cnt = 0;
            }
        }
        where = i;
        return path;
    }

    // 把 str 重复 cnt 遍
    string repeat(int cnt, const string& str) {
        string res;
        for (int i = 0; i < cnt; i++) res += str;
        return res;
    }

    string decodeString(const string& str) {
        where = 0;
        return f(str, 0);
    }

cnt 用完必须清零。不清零的话，「2[a]3[b]」读到第二个 '[' 时 cnt 已经是 23，输出 23 个 b。2 万组随机实测错 15.97%。

每字符恰好访问一次，输出另算：n = 50 万字符的输入（含 10 万次重复段）1.58ms，拼出 60 万字符。递归深度 = 括号层数 + 1：「3[z]2[2[y]pq4[2[jk]e1[f]]]ef」四层嵌套递归 4 层，展开 61 字符。

还有个同款错法：'[' 段处理后 i = where 忘了 +1，'[' 之后的内容整段被丢，2 万组实测错 34.56%。

二、原子计数

f(i) 解析到 ')' 或结尾停。段内三样历史：name 是当前元素名，cnt 是当前数字，pre 是括号内返回的有序表。遇到新的大写字母或 '('，先把历史并进 ans。

fill 分两支：name 非空 → ans[name] += cnt，cnt 没写按 1；pre 非空 → pre 里每个元素 ×cnt 并入 ans。

#include <bits/stdc++.h>
    using namespace std;

    // 全局 where：记录当前这一段解析停在哪，返回前更新
    int where = 0;

    void fill(map<string, int>& ans, const string& name, const map<string, int>* pre, int cnt);

    // s[i..] 开始解析，遇到字符串结尾或 ')' 停止
    // 返回自己负责的这一段的有序表（元素 -> 个数）
    map<string, int> f(const string& s, int i) {
        map<string, int> ans;
        string name;                 // 之前收集到的元素名，历史一部分
        map<string, int> sub;        // 之前收集到的括号内有序表，历史一部分
        bool hasSub = false;
        int cnt = 0;                 // 历史要翻几倍
        while (i < (int)s.length() && s[i] != ')') {
            if ((s[i] >= 'A' && s[i] <= 'Z') || s[i] == '(') {
                fill(ans, name, hasSub ? &sub : nullptr, cnt);
                name.clear();
                hasSub = false;
                cnt = 0;
                if (s[i] >= 'A' && s[i] <= 'Z') {
                    name += s[i++];
                } else {
                    // 遇到 '('，递归处理括号里的那段
                    sub = f(s, i + 1);
                    hasSub = true;
                    i = where + 1;
                }
            } else if (s[i] >= 'a' && s[i] <= 'z') {
                name += s[i++];
            } else {
                cnt = cnt * 10 + s[i++] - '0';
            }
        }
        fill(ans, name, hasSub ? &sub : nullptr, cnt);
        where = i;
        return ans;
    }

    // 把 name 或 pre 里已经算好的那部分并进 ans
    // cnt 为 0 表示没写数字，按 1 倍算
    void fill(map<string, int>& ans, const string& name, const map<string, int>* pre, int cnt) {
        if (name.empty() && pre == nullptr) return;
        cnt = cnt == 0 ? 1 : cnt;
        if (!name.empty()) {
            ans[name] += cnt;
        } else {
            for (auto& kv : *pre) {
                ans[kv.first] += kv.second * cnt;
            }
        }
    }

    string countOfAtoms(const string& str) {
        where = 0;
        map<string, int> total = f(str, 0);
        string ans;
        for (auto& kv : total) {
            ans += kv.first;
            if (kv.second > 1) ans += to_string(kv.second);
        }
        return ans;
    }

遇到 '(' 调 f(i + 1) 拿括号内整张表，跟在 ')' 后面的数字就是这层的 cnt，段结束时 fill 把整张表乘倍并进来。map 按键排序，最后遍历拼出「K4N2O14S4」。

每字符访问一次，常数看元素种数：n = 2×10⁶ 的分子式（20 万个括号组）42.2ms，时间主要花在有序表合并上。

最容易写错的在 fill 的 pre 分支：忘了乘 cnt。「K4(ON(SO3)2)2」会得「K4NO4S」（N 2→1、O 14→4、S 4→1），2 万组实测错 57.32%；i = where 忘 +1 错 69.02%。

三、复杂度分析

题目时间额外空间说明
字符串解码O(n)O(n)每字符一次；path 与递归栈，输出长度另算
原子计数O(n)O(n)每字符一次；有序表合并常数看元素种数

解码的输出长度可能远超输入，那是输出本身的大小，解析仍然是 O(n)。

四、总结

同一套 where 框架解三题：终止符分别是 ')'、']'、')'，内层结果一个拿来合并、一个拿来重复、一个拿来乘倍并表。

两个高频错点：'[' / '(' 段处理后 i = where 忘 +1，尾巴整段丢；段内计数处理完不清零或不乘倍。

这套「全局 where + 递归分段」在后面的括号匹配、表达式、JSON 解析类题目里还会反复出现。
