雅加达的摩天楼：状态重定义与规模分析

前面四道题都是「小规模预处理、大规模暴力」，手段是定制出来的。这一道题没有任何手段可定制，根号分治只用来做一件事：把状态规模数清楚，看明白 BFS 为什么不会爆。

零、背景

题目 5 到题目 7 是这一讲的后半段。题目 5 是纯粹的规模分析，题目 6 和题目 7 要用到单调性加二分答案。这一页先看题目 5。

它需要两件前置：分层图最短路那讲的思路，以及最朴素的 BFS。分层图那套「把能力当成一层」的想法，在这里换了个形式出现。

一、问题

有 n 个大楼，编号 0 到 n − 1，有 m 只狗子，编号 0 到 m − 1。每只狗子有两个参数，idx 表示狗子的初始大楼，jump 表示狗子的跳跃能力。狗子在 i 位置，可以来到 i − jump 或 i + jump，向左向右自由跳跃，但不能越界。

0 号狗子有消息希望传给 1 号狗子，所有狗子都可帮忙，返回至少跳跃几次，无法送达打印 −1。1 ≤ n、m ≤ 30000。测试链接：洛谷 P3645。

输入里第 1 只狗子是 0 号狗子，它的 idx 是起点；第 2 只狗子是 1 号狗子，它的 idx 是终点。中间的传递过程可以换狗，换狗不消耗跳跃次数，只有真正跳一次才算一步。

二、直接建图会爆在哪里

最自然的想法是把大楼当成图的点。一只狗子在位置 i 能跳到 i ± jump，jump 是它自己的能力，跟位置无关，所以看起来每个位置都能配每一种 jump。状态就是 (位置, 跳跃能力)，一共 n × m 个。

n 和 m 都是 3 × 10⁴ 时，这个数是 9 × 10⁸，边数还要再乘 2，存不下也搜不完。得看看这些状态里到底有多少是真能出现的。

三、按跳跃能力分两类

先用根号分治的老办法估一下量级。取分界线 B = √n，把狗子按跳跃能力分成两拨。

jump 不超过 B 的狗子，能用的 jump 值只有 B 种，状态是 (位置, jump)，一共 n·B 个，每个状态往左右各跳一次，BFS 的代价是 O(n·B)。

jump 大于 B 的狗子不进状态，直接跳。每次至少前进 B，一栋楼最多被跳到 n/B 次，m 只狗子全部算上是 O(m·n/B)。

两边加起来是 O(n·B + m·n/B)，B 取 √n 就是 O(n√n)，n = 3 × 10⁴ 时大约 5 × 10⁶，可以过。这是这道题的经典写法，也是分层图最短路那套思路的直接应用。

四、再收紧一步：jump 只能从楼上拿

上面那个估法还是把状态当成了 n·B 个。实际上一个状态 (idx, jump) 要成立，得有人把 jump 这个能力交到 idx 这栋楼上，而交能力的动作只有一种：走到这栋楼，把这栋楼上的狗子都叫醒。

因此 idx 这栋楼能配的 jump 值，只可能是站在 idx 上的那几只狗子的能力。所有楼加起来，状态总数不超过 m。

代码里用两条规则把这个约束落下去。第一条是唤醒：走到某栋楼时，把这栋楼上的狗子一次性全部入队，记成 trigger。第二条是去重：一个状态 (idx, jump) 只入队一次，用 vis[idx] 这个 bitset 的第 jump 位来判重。

这里有个细节：唤醒动作是每栋楼只做一次的。第一次走到 idx 时把链表遍历一遍，随即把 head[idx] 置 0，之后再走到这栋楼就什么都不用做了。每条链表总共只被遍历一次，m 只狗子的链表加起来是 O(m)。

入队的元素是三元组 (idx, jump, time)，time 是到达这栋楼已经跳了几次。出队时先看 idx ± jump 里有没有终点，有就返回 time + 1，因为再跳一步就到了；否则往左右各走一步，走到新楼时做一次唤醒。

注意换狗不花时间：唤醒出来的状态沿用当前这栋楼的 time，只有跳跃才让 time 加一。这就是题目里「所有狗子都可帮忙」的含义。

    
void trigger(int idx, int time) {
        for (int e = head[idx], jump; e; e = nxt[e]) {
            jump = to[e];
            if (!vis[idx].test(jump)) {
                vis[idx].set(jump);
                que.push_back({idx, jump, time});
            }
        }
        head[idx] = 0;
    }

    void extend(int idx, int jump, int time) {
        trigger(idx, time);
        if (!vis[idx].test(jump)) {
            vis[idx].set(jump);
            que.push_back({idx, jump, time});
        }
    }
    
int bfs(int s, int t) {
        if (s == t) {
            return 0;
        }
        for (int i = 0; i < n; i++) {
            vis[i].reset();
        }
        que.clear();
        trigger(s, 0);
        while (!que.empty()) {
            Node cur = que.front();
            que.pop_front();
            int idx = cur.idx;
            int jump = cur.jump;
            int time = cur.time;
            if (idx - jump == t || idx + jump == t) {
                return time + 1;
            }
            if (idx - jump >= 0) {
                extend(idx - jump, jump, time + 1);
            }
            if (idx + jump < n) {
                extend(idx + jump, jump, time + 1);
            }
        }
        return -1;
    }

判重的 vis 是 bitset<MAXN> vis[MAXN]，按楼开一个 bitset，第 jump 位表示这个 (楼, 跳跃能力) 有没有出现过。jump 的值域是 n，所以总空间是 n²/8 个字节。n = 3 × 10⁴ 时大约 112 MB，用 bool 的二维数组则是 900 MB，bitset 这层压缩是必须的。

五、复杂度分析

代价分成三块：状态数、每条链表的遍历、vis 的初始化。

操作时间复杂度空间复杂度
建链表（每只狗子头插一次）O(m)O(n²/8 + m)：vis 按楼开 bitset，链表与队列 O(m)
vis 初始化（n 个 bitset 逐个 reset）O(n²/64)
trigger 唤醒（每栋楼的链表只遍历一次）O(m) 均摊
BFS 主循环（每个状态出队一次、扩两个方向）O(m)

总代价是 O(n²/64 + m)。n = 3 × 10⁴ 时前一项大约 1.4 × 10⁷，是这几项里最大的，也仍然是常数很小的一次扫描。经典根号分治写法是 O(n√n)，量级相近但要多写一层分类；这里靠状态重定义直接省掉了那一层。

六、最后

这道题没有预处理表，根号分治只剩下规模分析这一件事：先按 jump 与 √n 的关系估出 O(n√n) 的经典代价，再看清楚「能力只能从楼上拿到」这个约束，把状态数压到 m。

下一节看最后两道题。它们要回答所有 k 的答案，靠的是答案本身的单调性：k 变大时答案变小，而且变化次数不超过 √n 量级，于是小规模直接算、大规模用二分答案跳着算。

《完》
