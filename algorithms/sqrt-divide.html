根号分治：小步长查表、大步长暴力

一个操作的代价跟某个参数 x 有关：x 小的时候要走很多步，x 大的时候走不了几步。以 √n 为界把 x 切成两类，小的预处理成表，大的直接枚举，两边都落在 √n 量级。这一讲一共七道题，这一页讲原理和前两道。

零、背景

分块专题的前三节是把数组切成块，整块打标记、零散元素单独处理。这一节换个角度：不动数组，改切「操作的规模」。

前置只有两样：分块基础，卡常技巧。后面几页会用到等差数列差分、分层图最短路和二分答案法，用到的时候再提。

整讲七道题分成三种形态。题目 1 到题目 4 是「小规模预处理、大规模暴力枚举」，题目 5 只有复杂度的分析、没有手段的定制，题目 6 和题目 7 是「小规模动态规划、大规模靠单调性加二分答案减少计算量」。这一页覆盖原理和前两道题。

一、根号分治的原理

先说清楚它要解决的问题形状。操作里带一个参数 x，执行时要按 x 步进来枚举一遍，比如「下标每次加 x，把碰到的位置累加起来」。枚举次数是 n/x。

x 越小，枚举次数越多，x = 1 时要扫整个数组；x 越大，枚举次数越少，x 超过 √n 之后次数连 √n 都不到。麻烦只在 x 小的那半边。

取一个分界线 B。x 不超过 B 的操作只有 B 种参数，每种参数把答案整个预处理出来，之后查询是 O(1)。x 大于 B 的操作不去预处理，直接枚举，代价 n/x 小于 n/B。

代价因此分成两块：预处理是 B 种参数各扫一遍数组，O(n·B)；单次查询是 O(n/B)，做 m 次就是 O(m·n/B)。B 取 √n 时两块都在 n√n 量级，这就是名字的来历。n 和 m 不同阶的时候，令 n·B = m·n/B 解出 B = √m 更精细，本讲七道题里 n 和 m 同阶，一律取 √n。

可以发现这套做法和数组分块没有必然关系，它切的是参数的值域。题目里「参数」可能藏在各种地方：模数的大小、步长的大小、跳跃能力的强弱、划分的要求 k。认出这个参数是这类题的第一步。

二、题目1：哈希冲突

给定一个长度为 n 的数组 arr，接下来有 m 条操作，操作格式如下。

  • 操作 A x y：下标 % x == y 的所有位置，把值累加起来，打印结果。
  • 操作 C x y：把 arr[x] 的值改成 y。

1 ≤ n、m ≤ 1.5 × 10⁵。测试链接：洛谷 P3396。

这里的参数就是 x。查询的朴素写法是从 y 开始每次加 x 扫过去，代价 n/x，x = 1 时一次查询就要扫整个数组，m 条操作下来是 O(n·m)，直接超时。

按根号分治拆开。x 不超过 B 时，把每个余数类的和预先算出来，记成 dp[x][y]，表示所有下标对 x 取模等于 y 的那些位置的值之和。预处理是 x 从 1 到 B、每个 x 扫一遍数组，O(n·B)。

查询因此分两条路。x 不超过 B 时直接返回 dp[x][y]，O(1)。x 大于 B 时从 y 开始每次加 x 扫一遍，次数不超过 n/B，即 O(√n)。

修改要维护这张表。arr[i] 的变化量记成 delta，对每个 x 从 1 到 B，只有 dp[x][i % x] 这一格受影响，加上 delta 即可，代价 O(B)。这里有个细节：修改只碰 B 个格子，跟数组长度无关，这就是为什么预处理表能一直保持正确。

    
void prepare() {
        blen = (int)sqrt(n);
        for (int x = 1; x <= blen; x++) {
            for (int i = 1; i <= n; i++) {
                dp[x][i % x] += arr[i];
            }
        }
    }
    
long long query(int x, int y) {
        if (x <= blen) {
            return dp[x][y];
        }
        long long ans = 0;
        for (int i = y; i <= n; i += x) {
            ans += arr[i];
        }
        return ans;
    }

    void update(int i, int v) {
        int delta = v - arr[i];
        arr[i] = v;
        for (int x = 1; x <= blen; x++) {
            dp[x][i % x] += delta;
        }
    }

预处理里两层循环的写法值得留意：外层是 x，内层扫下标 i，这样 dp[x][i % x] 的内存访问是连续的。反过来写也可以，但常数会差一些，那讲的卡常技巧主要就落在这些地方。

三、题目2：数组查询

给定一个长度为 n 的数组 arr，接下来有 q 条查询，查询格式如下。

查询 p k：p 不断变成 p + arr[p] + k，直到 p > n 停止，打印操作次数。1 ≤ n、q ≤ 10⁵，1 ≤ arr[i] ≤ n。测试链接：CF797E。

这里的参数是 k。arr[p] 至少是 1，所以每一步至少前进 k + 1，走的步数不超过 n/k。k 大就直接模拟，k 小的时候步数能到 n 级别，得另想办法。

k 不超过 B 时预处理。记 dp[p][k] 为「从位置 p 出发、参数固定为 k，还要走几步」。倒着算：从 p 走一步到 p + arr[p] + k，如果新位置已经超过 n，答案就是 1，否则是 1 + dp[p + arr[p] + k][k]。p 从 n 到 1 枚举，用到的状态都已经算好。

预处理的表是二维的，dp[p][k] 一共 n·B 个 int。n = 10⁵、B 取 316 时大约 1.2 × 10⁷ 个整数，几十 MB，题目给的空间够用，但这个量级要心里有数，别把 B 随手放大。

    
void prepare() {
        blen = (int)sqrt(n);
        for (int p = n; p >= 1; p--) {
            for (int k = 1; k <= blen; k++) {
                dp[p][k] = 1 + (p + arr[p] + k > n ? 0 : dp[p + arr[p] + k][k]);
            }
        }
    }
    
int query(int p, int k) {
        if (k <= blen) {
            return dp[p][k];
        }
        int ans = 0;
        while (p <= n) {
            ans++;
            p += arr[p] + k;
        }
        return ans;
    }

查询和题目 1 的形状完全一样：k 不超过 B 就取 dp[p][k]，否则 while 循环模拟，循环次数不超过 n/B。

四、复杂度分析

两道题的形状相同，差别只在预处理的那张表的大小和形状。表里的时间都按 B = √n 代入。

操作时间复杂度空间复杂度
题目1 预处理 dp[x][y]（x ≤ B，每个扫 n 个位置）O(n·B) = O(n√n)O(n + B²)：dp 表按余数类开，B² 个格子
题目1 查询 A x y（x ≤ B 取表 / x > B 跳着扫）O(1) / O(n/x) ≤ O(√n)
题目1 修改 C x y（扫 B 个余数类）O(B) = O(√n)
题目2 预处理 dp[p][k]（p 从 n 倒推，k ≤ B）O(n·B) = O(n√n)O(n·B)：n 个位置各存 B 个 k 的答案
题目2 查询 p k（k ≤ B 取表 / k > B 模拟）O(1) / O(n/k) ≤ O(√n)

两道题的总代价都是 O((n + m)√n)。n、m 都在 10⁵ 量级时大约是 3 × 10⁷ 次基本操作，C++ 里稳过。

五、最后

根号分治的套路就三步：认出那个决定代价的参数 x，x 小的那半边预处理成表，x 大的那半边直接枚举。前两道题的 x 分别是模数和步长，表分别是「余数类的和」和「从每个位置出发的步数」。

下一节看两道预处理表更精巧的题：等差数列求和要把后缀和叠两层，初始化要在模 x 的意义上做前缀和后缀，还要再套一层数组分块。
