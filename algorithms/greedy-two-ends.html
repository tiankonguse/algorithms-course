贪心：两端扫出的边界

一道题问「哪一段是乱的」，一道题问「两个区间最长能多长」。两道题都没有排序、没有堆、没有替换，答案只落在几个下标上：从左往右扫一遍，再从右往左扫一遍，边界就自己露出来了。

零、问题的一面

先看第一题。给一个整数数组，找一个最短的连续子数组，把它升序排好之后整个数组变成升序，返回这个子数组的长度。

拿 nums = [2, 6, 4, 8, 10, 9, 15] 走一遍。整串明显是乱的：6 排在 4 前面，10 排在 9 前面。把下标 1 到 5 这一段排好，整串就顺了，答案 5。

第二题换个问法。给一个 01 串，找两个区间，让两个区间里 0 的个数相等、1 的个数也相等。两个区间可以重叠，左右端点不能完全一样。求这两个区间最长能取多少。

两道题都没有「选谁」的余地，能用的只有下标。那就先想一件事：一个位置该不该动，它自己是不是就能判断。

一、一个位置达不达标，自己就能判断

第一题里，位置 i 该不该被卷进排序段，看两件事就够了。

1）它左边出现过的最大值如果比它大，那这个「大个子」必须挪到它后面去，位置 i 一定在段里。

2）它右边出现过的最小值如果比它小，那它必须挪到那个「小个子」前面去，位置 i 也一定在段里。

两条判据都是拿一侧的极值做比较，而极值一次扫描就能带着走。

正着扫，维护「左边见过的最大值 mx」：一旦 mx > nums[i]，就把 right 记成 i。扫完 right 就是最右边那个不达标的位置。

倒着扫，维护「右边见过的最小值 mn」：一旦 mn < nums[i]，就把 left 记成 i。扫完 left 就是最左边那个不达标的位置。

还是那组数据。正扫到下标 2 时左边最大值是 6，比 4 大，right 记 2；到下标 5 时左边最大值是 10，比 9 大，right 改成 5。反扫到下标 4 时右边最小值是 9，比 10 小，left 记 4；到下标 1 时右边最小值是 4，比 6 小，left 改成 1。答案 5 − 1 + 1 = 5。

两个计数器的初值要挑好。right 从 −1 开始、left 从 n 开始，整串本来就有序时两边都不会被改写，相减得到负数，取 max(0, …) 之后正好是 0。若把 right 和 left 都初始化成 0，有序数组会被算成 1。

// 最短无序连续子数组：把这一段升序排好之后整个数组有序，返回最短长度
    int findUnsortedSubarray(vector<int>& nums) {
        int n = nums.size();
        // 从左往右：左边出现过比它大的数，这个位置就不达标
        int right = -1;
        int mx = INT_MIN;
        for (int i = 0; i < n; i++) {
            if (mx > nums[i]) {
                right = i;
            }
            mx = max(mx, nums[i]);
        }
        // 从右往左：右边出现过比它小的数，这个位置就不达标
        int left = n;
        int mn = INT_MAX;
        for (int i = n - 1; i >= 0; i--) {
            if (mn < nums[i]) {
                left = i;
            }
            mn = min(mn, nums[i]);
        }
        // 已经有序时 right 停在 -1，max 兜住 0
        return max(0, right - left + 1);
    }

二、夹出来的这一段为什么最短

先把「必须包含」这一半说清楚。如果存在下标 j < i 满足 nums[j] > nums[i]，这是一对逆序。排序只动了一段 [l, r]：要是 i 和 j 没有同时落在里面，这两个数的前后关系不会变，逆序照旧，整串不可能有序。所以每一对逆序 (j, i) 都要求 l ≤ j 且 i ≤ r。

右边这条对着所有逆序用一遍：i 可以取任何一个「左边有人比它大」的位置，最靠右的那个就是 right，于是 r ≥ right。左边这条同理：j 可以取任何一个「右边有人比它小」的位置，最靠左的是 left，于是 l ≤ left。两条一合，任何合法答案的长度都不小于 right − left + 1。

再补上「够用」这一半：把 [left, right] 排好，整串确实有序。

left 左边的每个位置 j 都满足「右边没有比它更小的数」，否则它就比 left 更靠左还是个不达标位置，而 left 是最左的那个。既然右边全不比它小，左边的片段自己就是非降的，而且每个数都不大于 [left, right] 里的任何一个。

right 右边每个位置 k 都满足「它左边的数没有一个比它大」，否则它自己就是不达标位置，而 right 是最右的那个。同样的道理，右边的片段非降，而且不小于中间任何一个数。

三段接起来：左边非降且整体不大于中间，中间排好之后非降且整体不大于右边，右边非降。整串有序，长度就是 right − left + 1。上下界撞在一起，这就是最短的那一段。

三、两个 0/1 计数相等的区间

第二题换了个问法，但答案照样只跟几个下标有关。先看一个最简单的构造。

如果同一个字符出现在 p 和 q 两个位置（p < q），那就取区间 A = [p, q−1]、区间 B = [p+1, q]。两个区间长度都是 q − p，而且 B 相对 A 少了一个 p 位置的字符、多了一个 q 位置的字符，这两个字符相同，于是 0 的个数和 1 的个数都一模一样。左右端点也不完全一样，合法。

把这个构造用在两个字符上：p 取最左的 0、q 取最右的 0，得到长度 rightZero − leftZero；换成 1，得到 rightOne − leftOne。两边取大，答案至少是这么多。

四、为什么不能更长

反过来要说明：最长的那一对区间，一定能写成上面那种「起点差 1」的形状。

设两个区间长度都是 L，起点分别是 a 和 b，a < b，两个区间里 0 的个数相同。长度为 L 的区间一共有 n − L + 1 个，按起点排队，记 Z(s) 为起点 s 的那个区间里 0 的个数。相邻两个区间只差「移出一个、移入一个」，所以 Z(s+1) − Z(s) 只会是 −1、0、1。

在所有满足 Z(a) = Z(b)、a < b 的对里，挑 b − a 最小的那一对。假如 b − a ≥ 2，那么 a 到 b 之间任何两个位置 s < t 都不能有 Z(s) = Z(t)，否则 (s, t) 也是一对合法区间，而且更近，跟「最小」矛盾。也就是说这段里的 Z 两两不同。

可是首尾又相等，折线得出去再回来。每一步只变 1，中途掉头就必然要再经过之前走过的取值，两两不同就维持不住。只往一个方向走的话首尾又不可能相等。所以 b − a 只能是 1。

代进 b = a + 1：Z(a) = Z(a+1) 说明移出的 a 位置和移入的 a+L 位置字符相同。所以能取到的长度 L，一定等于「某个字符最右出现的位置减去它最左出现的位置」。两个字符各试一次取大的，就是上界。

两边一夹，答案就是 max(rightZero − leftZero, rightOne − leftOne)。当某个字符在串里只出现一次或者干脆没出现时，它这一项是 0，不会干扰取大。

// 两个区间里 0 的个数相等、1 的个数也相等，返回区间最长能取多少
    int maxSameZerosOnes(vector<int>& arr) {
        int n = arr.size();
        int leftZero = -1, rightZero = -1, leftOne = -1, rightOne = -1;
        for (int i = 0; i < n; i++) {
            if (arr[i] == 0) { leftZero = i; break; }
        }
        for (int i = 0; i < n; i++) {
            if (arr[i] == 1) { leftOne = i; break; }
        }
        for (int i = n - 1; i >= 0; i--) {
            if (arr[i] == 0) { rightZero = i; break; }
        }
        for (int i = n - 1; i >= 0; i--) {
            if (arr[i] == 1) { rightOne = i; break; }
        }
        return max(rightZero - leftZero, rightOne - leftOne);
    }

五、两个演示

演示 A　两遍扫描各记一次不达标位置

蓝色格子是这一遍扫下来判定达标的位置，橙色是判定不达标的位置。两遍都走完之后再看橙色最左和最右差了多少。

演示 B　四个下标定出最长的一对区间

绿色格子是刚刚定下来的那个下标。四个都定好之后，答案行会写出最长的长度，以及一对真正达到这个长度的区间。

六、对数器怎么抓错

第一题 2 万组随机数据，n 不超过 12：

错法值域 3值域 1000
只正着扫一遍，left 拿第一个不达标的位置87.41%93.20%
反扫的判据写成 mn > nums[i]87.41%93.37%

第二种错法是把 «右边最小值小于我» 写成了 «大于我»，听起来只是符号颠倒，实际九成以上的数据都能抓出来。第一种错法更常见：只扫一遍就想同时定出左右边界，等于把「最左的不达标位置」默认成了「第一个遇到的不达标位置」，中间隔着几个达标位置时就错。

第二题 2 万组随机数据，n 不超过 60：

错法0 的密度 1/21/10
只看 0 那一边，忘了 1 也能给出更长的答案42.14%96.88%
在两个候选长度上再减一格100.00%100.00%

第一行的规律值得记一下：0 越稀，只算 0 那一边就越容易错过更长的答案。全 0 或全 1 这种极端串反而不会错，因为缺失的那一项是 0。

复杂度分析

题目关键操作时间空间
最短无序连续子数组两次线性扫描，各带一个极值O(n)O(1)
两个 0/1 计数相等的区间四次线性扫描找四个端点O(n)O(1)

第一题 n = 106 实测 3.31ms。同规模下把数组拷一份排序再逐位比对要 57.47ms，因为排序的 O(n log n) 全花在了找边界之外的地方。

第二题 n = 107、随机 01 串实测不到 0.0001ms：四个循环都是遇到第一个目标就 break，通常走几步就停。构造最坏的形状（前半全 1、后半全 0）也就 2.48ms，仍然是 O(n)，只是常数上把四个循环都跑满了。

总结

两道题的解法都没离开下标。第一题把「这个位置达不达标」拆成两个可以边扫边维护的极值判据，右边界和左边界各扫一遍就定了；再用逆序对说明任何合法区间都必须盖住这两个边界，最短性就闭环了。

第二题的关键是发现两个区间长度必然相等，于是可以只看 0 的个数，再把「最优解可以取成起点差 1」证出来，答案就落到同一个字符的最左最右两次出现上。

处理这类题有个可以复用的习惯：先问「每个位置自己能不能判断」，再问「哪些位置是任何答案都绕不开的」。把这两个问题回答清楚，扫描的方向和计数器的初值基本上就跟着定下来了。
