线段树：值域的离散化

线段树的下标是「第几个位置」，可有的题给的位置是坐标本身。坐标能大到一亿，真正被用到的端点却只有两千个。把端点收进一张表、排个序、去重，以后所有操作都先二分换成下标，线段树就开得出来了。

零、背景

掉落的方块这道题，方块的左边界 left 能到 10⁸，边长能到 10⁶。按坐标直接建树，右端点最大是 10⁸ + 10⁶ − 1，值域跨度 101000000。一个 int 数组就是 385.3 MB，线段树按四倍开是 1541.1 MB。开不出来。

可方块最多只有 1000 个，每个方块只贡献两个端点，加起来 2000 个。这 2000 个坐标之外的位置，从来没有任何一次操作会去问它。

一、问题

方块一个一个从高处垂直落下，左边界贴着 left 那条线往下走，碰到已经落稳的方块的顶边或者 x 轴就停住，然后固定不动。擦着侧面过去不算碰撞。每次落下之后，问整体最高处是多少。

第 i 块方块落地后，它的顶面高度是「落点范围内已有的最高顶面」加上自己的边长。所以这题要的是区间最大值，落稳之后是区间重置成同一个高度。这两个操作上一段的线段树都有，缺的只是下标从哪来。

二、把坐标换成下标

收集：每个方块把自己的左端点 left 和右端点 left + len − 1 都丢进表里。排序、去重，表就成了从 1 开始的坐标字典。

定位：要把一个坐标 v 换成下标，就在表里二分找第一个 ≥ v 的位置。因为所有操作用到的端点都在表中，这个二分一定找得到。

// 把每个方块的左右端点收进 xs，排序去重
    // 返回去重后的点数 n，xs[0..n-1] 就是离散化后的坐标表
    int collect(const vector<pair<int, int>>& pos, vector<int>& xs) {
        xs.clear();
        for (auto& p : pos) {
            xs.push_back(p.first);              // 左端点
            xs.push_back(p.first + p.second - 1); // 右端点（闭区间）
        }
        sort(xs.begin(), xs.end());
        xs.erase(unique(xs.begin(), xs.end()), xs.end());
        return (int)xs.size();
    }
// 在 xs 里找第一个 >= v 的位置，返回 1 开始的名次
    int rankOf(const vector<int>& xs, int v) {
        int l = 0, r = (int)xs.size() - 1, ans = 0, m;
        while (l <= r) {
            m = (l + r) >> 1;
            if (xs[m] >= v) { ans = m; r = m - 1; }
            else l = m + 1;
        }
        return ans + 1;
    }

这里有个细节值得停一下：为什么右端点要写 left + len − 1，不是 left + len。方块的边长是 len，它占住的是 x 轴上连续 len 长的一段，左闭右开就是 [left, left + len)。题目说擦过侧边不算碰撞，也就是两块只有共用一个点才算碰上，写成闭区间 [left, left + len − 1] 正好对应这个判据。

三、主流程

有了下标，剩下就是上一段的模板：查询 [l, r] 的最大值当落点高度，加上边长得到新顶面，再把 [l, r] 整段重置成这个高度。

vector<int> fallingSquares(const vector<pair<int, int>>& pos) {
        vector<int> xs;
        int n = collect(pos, xs);
        build(1, n, 1);                 // mx、change、update 全部清零
        vector<int> ans;
        int best = 0;
        for (auto& p : pos) {
            int l = rankOf(xs, p.first);
            int r = rankOf(xs, p.first + p.second - 1);
            int h = query(l, r, 1, n, 1) + p.second; // 落点高度 + 自身边长
            best = max(best, h);
            ans.push_back(best);
            update(l, r, h, 1, n, 1);   // 整段重置成新高度
        }
        return ans;
    }

演示：一块一块往下落

选一组数据，每点一次「下一块」落一块，橙色框是本块占住的离散区间，虚线是它的落点高度。

整套做下来，1000 个方块、坐标散在 10⁸ 内，从离散化到建树到全部更新查询一共 0.257 ms，最终高度 11601969。离散化后的数组只占 31.2 KB。

四、去重能压多少，看值域

去不掉重复端点的话，离散化只是把跨度从一亿降到两千。去掉之后能再降一截，降多少取决于坐标有多挤。

坐标散得越开，去重越没用，但跨度压缩那一下已经把问题从「开不出数组」变成了「两千个点的模板题」。1000 个方块丢进 10⁸ 的坐标里，实测 2000 个端点一个都没重复。

五、下一题：漏出一点也算

贴海报。一面长度 n 的墙，m 张海报，每张给出 [x, y]，贴上去会盖住前面贴的。全部贴完，问还能看见几张，哪怕只漏出一点都算。n 和坐标能到 10⁷，m 到 10³。

照搬上一节的做法：把每张海报的两个端点收进去，排序去重，二分换下标，然后区间覆盖。问题出在「漏出一点」这四个字上。

上一题问的是最大值，只有真的有方块落在那段区间上，答案才会变，所以只留端点足够。这一题问的是「有没有一段墙被某张海报露出来」，墙是连续的，端点之间的那些位置也算墙。

六、补一个中间点

看这个例子：墙长 10，三张海报依次是 [1,10]、[1,3]、[5,10]。

真值：第 1 张被后两张盖住了吗？第 2 张盖住 1 到 3，第 3 张盖住 5 到 10，位置 4 只有第 1 张盖着。所以第 1 张在位置 4 漏出来了，答案是 3。

只留端点的话，坐标表是 {1, 3, 5, 10}。位置 4 不在表里，它两侧的表项是 3 和 5，而 3 被第 2 张盖着、5 被第 3 张盖着，看上去第 1 张一点都没露。算出来是 2。

补的方法很直接：去重之后扫一遍相邻两项，只要 num[i−1] + 1 < num[i]，就把 num[i−1] + 1 也加进表，最后重新排序去重。

// 去重之后，凡是相邻两点之间还隔着东西，就把 num[i-1]+1 补进来
    // 补完再排一次序、再去一次重
    int collect(vector<int> raw, vector<int>& num) {
        sort(raw.begin(), raw.end());
        raw.erase(unique(raw.begin(), raw.end()), raw.end());
        num = raw;
        for (int i = 1; i < (int)raw.size(); i++) {
            if (raw[i - 1] + 1 < raw[i]) num.push_back(raw[i - 1] + 1);
        }
        sort(num.begin(), num.end());
        num.erase(unique(num.begin(), num.end()), num.end());
        return (int)num.size();
    }

这样补够不够？够。相邻两个端点之间不会有任何海报开始或结束，所以这一整段被哪些海报盖着是均匀的，拿其中一个整数位置当代表就行。需要注意的代表和被它隔开的两个端点不是一回事：端点 3 上第 2 张还盖着，位置 4 上第 2 张已经结束了。这正是要单独补一个点的原因。

代价是表会变长。m = 1000 张海报、坐标散在 10⁷ 内，去重后 2000 个点，补完中间点变成 3999 个，多出 99.95%。点数翻倍，四倍数组也才 64 KB，比墙长 10⁷ 直接开数组的 38.1 MB 划算得多。

七、该维护什么信息

直接维护「这一段上有几张海报能看见」看着最贴题，可两张海报拼在一起时，各自可见的部分可能重叠，也可能被第三张切断，这个数合不起来。

换个问法：维护「这一段是不是被同一张海报完全盖住」。节点上记一个编号，非 0 就是整段都是这张海报，0 表示没有海报或者这一段上的海报不统一。覆盖是能合并的：一张海报把整段盖住，就是这一个编号说了算；没盖全就往下发，让两个孩子各自回答。

// poster[i] != 0 表示节点 i 的整段被同一张海报盖住，值是海报编号
    // poster[i] == 0 表示没海报，或者这一段上的海报编号不统一
    void down(int i) {
        if (poster[i] != 0) {
            poster[i << 1] = poster[i];
            poster[i << 1 | 1] = poster[i];
            poster[i] = 0;
        }
    }

    void update(int jobl, int jobr, int jobv, int l, int r, int i) {
        if (jobl <= l && r <= jobr) { poster[i] = jobv; return; }
        down(i);
        int mid = (l + r) >> 1;
        if (jobl <= mid) update(jobl, jobr, jobv, l, mid, i << 1);
        if (jobr > mid)  update(jobl, jobr, jobv, mid + 1, r, i << 1 | 1);
    }

    // 最后统计：一路 down 到每个叶子，按编号去重计数
    int query(int l, int r, int i) {
        if (l == r) {
            if (poster[i] != 0 && !visited[poster[i]]) {
                visited[poster[i]] = true;
                return 1;
            }
            return 0;
        }
        down(i);
        int mid = (l + r) >> 1;
        return query(l, mid, i << 1) + query(mid + 1, r, i << 1 | 1);
    }

最后统计时一路 down 走到每个叶子，按编号去重计数。这一步会把整棵树走一遍，所以是 O(点数)。好在整个过程只问这一次。

八、复杂度分析

记 m 是操作次数，k 是离散化后的点数（贴海报的题里 k ≤ 2m + 补点，最多翻一倍）。

环节时间说明
收集加排序去重O(m log m)2m 个端点排序，去重是线性扫一遍
每次坐标转下标O(log k)表上二分
掉落的方块整体O(m log k)m 次查询加 m 次范围重置
贴海报整体O(m log k + k)m 次覆盖，最后一次遍历整棵树统计
空间O(k)线段树四倍开，掉落的方块是 max / change / update 三个数组

掉落的方块里 k ≤ 2000，贴海报里 k ≤ 4000 上下，两个都是常数级的数组开销。不开离散化的话，前者要 1541.1 MB，后者要 38.1 MB。

十、总结

离散化做的是把「坐标」和「下标」分开：真正要建树的是第几个用到的位置，不是坐标本身。收集全部端点、排序去重、二分换下标这三步走完，值域多大都不影响数组开多大。

掉落的方块里这套完全够用，因为问的是最大值，端点之外没有额外的信息要区分。贴海报问的是连续墙面上有没有露出一段，端点之间那段必须有代表，所以补一个中间点才对。这两题放一起正好把离散化的边界划清楚：端点够不够，取决于你要区分的东西是不是只发生在端点上。

再往下遇到「维护不了就换一个能合并的信息」，贴海报已经给了一个样板：可见数合不起来，改成维护整段是否被同一张盖住，最后遍历一次统计。

最后

两个容易忘的点。一是 rank 的二分要找第一个 ≥ v 的位置，写成第一个 > v 之后，正好落在端点上的查询会整体偏移一格，小数据上抓得挺准、大数据上几乎抓不到，属于最难发现的一类。二是贴海报的坐标表要把墙的右边界也放进去，不然最后一次查询的右端点排不出下标。
