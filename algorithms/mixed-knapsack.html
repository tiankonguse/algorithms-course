混合背包：01、完全、多重混在一道题里

真实题目很少只考一种背包。观赏樱花那道题里，同一棵树可以「只看一遍」「最多看 c 遍」「想看多少遍看多少遍」；找零那道题里，同一种面值可能只有一张、可能有一小叠、也可能多到用不完。把「每种的可用次数」这件事分成三条路，各走各的处理方式，一张表就能同时容下三种模型。

零、两种混合的方式

这里有两道题，混合的粒度不一样。

观赏樱花（洛谷 P1833）：每种树的次数 cnt 给 0 表示无限、给正数表示上限。做法是把无限当成一个足够大的次数，这样每种都变成多重背包，再统一二进制分组转成 01 背包。整题走一条流水线。

找零（POJ 1742）：每种货币有面值 val[i] 和数量 cnt[i]，问 1 到 m 里能凑出多少个数。做法是在同一趟循环里按情况分三支：只有一张走 01，张数够填满容量就走完全，其余走多重。三种模型互不干扰，只共用一个 dp 数组。

把三种模型的转移方向摆在一起看，区别其实只有「内层 j 往哪边走」和「要不要分组」：01 背包倒序、完全背包正序、多重背包按余数分组后在窗口里取或。

一、樱花：先把时刻换成分钟

这道题的输入是「现在时间」和「上学时间」两个 hh:mm 的时刻，背包容量是两者之差，单位是分钟。换算本身很短，但有个细节值得说一句：当开始的分针比结束的分针大（6:50 到 7:00 这种），代码里会先把结束时刻借位一小时再减。借不借位结果其实一样，因为「借 1 小时给 60 分钟」恰好抵消了。

// 输入格式是 6:50 7:00 3，先把两个时刻各自换算成当天第几分钟
    // 两个时刻之差就是背包容量（单位：分钟）
    int readCapacity() {
        string a, b;
        int n;
        cin >> a >> b >> n;
        int h1 = stoi(a.substr(0, a.find(':')));
        int m1 = stoi(a.substr(a.find(':') + 1));
        int h2 = stoi(b.substr(0, b.find(':')));
        int m2 = stoi(b.substr(b.find(':') + 1));
        if (m1 > m2) {              // 分针借位：7:00 看成 6:60
            h2--;
            m2 += 60;
        }
        return (h2 - h1) * 60 + (m2 - m1);
    }

换算完，容量就是 10 分钟，剩下的完全是背包问题。

二、「无限」换成一个够大的次数

cnt = 0 的语义是「想看多少遍就看多少遍」。二进制分组处理不了无穷，得换成一个有限的数。选多大的数合适？看容量：本题容量不超过 1000 分钟，每棵树的耗费时间都 ≥ 1，所以任何一棵树看够 1001 次都装不进背包。既然装不下，把它排到 1001 次和排到无穷次的结果一样。

这个「够大」有明确的下界，由「一次的花费下界」和「容量上界」一起定出来：次数上限 ≥ ⌈容量 / 最小花费⌉ 就够了。本题最小花费是 1，容量是 1000，所以 1001。

// cnt == 0 表示可以无限看：把数量换成一个「够大」的数，再走二进制分组
    // 容量 t <= 1000，任何一棵树看超过 1000 次都不可能装下，所以 1001 就够了
    int cherry(int n, int t, vector<int>& cost, vector<int>& val, vector<int>& cntIn) {
        const int ENOUGH = 1001;
        vector<int> nv(1), nw(1);
        for (int i = 1; i <= n; i++) {
            int cnt = (cntIn[i] == 0 ? ENOUGH : cntIn[i]);
            for (int k = 1; k <= cnt; k <<= 1) {
                nv.push_back(k * val[i]);
                nw.push_back(k * cost[i]);
                cnt -= k;
            }
            if (cnt > 0) {
                nv.push_back(cnt * val[i]);
                nw.push_back(cnt * cost[i]);
            }
        }
        int m = nv.size() - 1;
        vector<int> dp(t + 1, 0);
        for (int i = 1; i <= m; i++)
            for (int j = t; j >= nw[i]; j--)
                dp[j] = max(dp[j], dp[j - nw[i]] + nv[i]);
        return dp[t];
    }

用题目样例验证一下：6:50 7:00、三棵树（耗费 2 价值 1 无限、耗费 3 价值 3 一件、耗费 4 价值 5 四件）。容量 10 分钟，最优是赏第一棵一次（2 分钟、1 点）加第三棵两次（8 分钟、10 点），合计 11 点，和样例输出一致。

三、找零：三条分支的判据

找零的 dp[j] 只记「能不能凑出 j」。每种货币进来时看两个数就能决定走哪一支：

1）cnt[i] == 1，只有一张，走 01 的倒序循环。倒序是为了让本轮刚写过的 dp 不被同一张纸币再用一次。

2）val[i] × cnt[i] > m，所有张数加起来都超过容量上界 m。这意味着在 1..m 这个范围内，「数量不够」这个限制永远碰不到，等价于无限张，直接走完全背包的正序循环。

3）剩下的才是真的多重背包，需要同余分组处理。

第二条判据是这道题的关键。它把「数量够多」的情况甩给完全背包，省掉了分组，只剩那些张数不多的货币才需要走慢路径。实测两组数据看这条判据的分量：容量 m = 20 时，「把多重全当完全」只错 2.68%，因为大部分货币本来就满足 val×cnt > m，走的就是完全分支；m 涨到 500 就变成错 67.36%，这时很多货币的张数不够填满容量，当完全做就会超量。反过来「把多重全当 01」（每种只用一张）错得更狠，m 越大越接近 100%，一张纸币根本凑不出几个数。

四、多重那一路：窗口里数 true

多重背包要不要按二进制分组，这里有个更省的做法。找零问的是「能不能凑出」，没有价值可谈，是一个布尔问题。要知道 dp[j] 能不能被当前货币凑出来，只需看窗口 [j − c·v, j − v] 里有没有一个是 true 的。有的话，从那个数再加一张就到 j 了。

于是维护一个计数 trueCnt，它记录窗口里 true 的个数。j 沿同余链从右往左走一格，窗口也左移一格：最右边出去的那个如果是 true 就减一，最左边新进来的那个如果是 true 就加一。整条链扫一遍，每个位置的判断都是 O(1)。

循环里两个下标要分清。第一个循环只数「链尾 c[i] + 1 个位置」里的 true，这是最初那个窗口；第二个循环里 l = j − val[i]·(cnt[i] + 1) 指向的是新滑出窗口的那一格，l ≥ 0 时才参与计数。两个循环的上界和下界都是 c[i] + 1 的量级，这也是为什么窗口大小是 c + 1 而不是 c：凑出 j 需要从某个已经凑出的数加一张，那个数最远只能是 j − c·v。

// dp[j]：手上的钱能不能正好凑出 j
    // 每种货币按「只有一张 / 有上限 / 够填满容量」分成三条路走
    int coins(int n, int m, vector<int>& val, vector<int>& cnt) {
        vector<char> dp(m + 1, 0);
        dp[0] = 1;
        for (int i = 1; i <= n; i++) {
            if (cnt[i] == 1) {
                for (int j = m; j >= val[i]; j--)                  // 01：倒序
                    if (dp[j - val[i]]) dp[j] = 1;
            } else if (val[i] * cnt[i] > m) {
                for (int j = val[i]; j <= m; j++)                  // 张数够填满容量，当完全背包：正序
                    if (dp[j - val[i]]) dp[j] = 1;
            } else {
                for (int mod = 0; mod < val[i]; mod++) {           // 同余分组，窗口里数有多少个 true
                    int trueCnt = 0;
                    for (int j = m - mod, k = 0; j >= 0 && k <= cnt[i]; j -= val[i], k++)
                        trueCnt += dp[j] ? 1 : 0;
                    for (int j = m - mod, l = j - val[i] * (cnt[i] + 1); j >= 1; j -= val[i], l -= val[i]) {
                        if (dp[j]) trueCnt--;
                        else if (trueCnt != 0) dp[j] = 1;
                        if (l >= 0) trueCnt += dp[l] ? 1 : 0;
                    }
                }
            }
        }
        int ans = 0;
        for (int i = 1; i <= m; i++) ans += dp[i] ? 1 : 0;
        return ans;
    }

五、两种做法的耗时

同一个「多重」问题有三种写法：窗口计数、单开一个 used[] 数组记录「这一种货币已经用了几张」、以及每个位置都回头重扫最多 c 个格子。前两种都是 O(n·m)，重扫那个是 O(n·m·c)，在 c 大时直接退化。实测 n = 50、m = 100000、每种面值 11 到 60、每种 1000 张：窗口计数 8.00 ms，used 计数 3.20 ms，每格重扫 71.20 ms。窗口计数比 used 计数慢在常数上（多一趟分组循环），但省下一个数组；重扫慢了将近 9 倍，是三者里唯一会被卡掉的写法。

六、复杂度分析

题做法时间额外空间
樱花完全转多重、再二进制分组O(t · Σ log c[i])O(t)

樱花的复杂度里 t ≤ 1000，log 项也小，随便怎么写都过。找零的 m 最大 100000、n 最大 100，窗口计数版刚好卡在 107 这个量级上，缺了分支判据或窗口优化，那道题都过不了。

七、总结

混合背包的处理套路是「先按每种的可用次数分路，再各走各的」。

几个要点：

1）cnt = 0 或 cnt 很大，本质是「限制碰不到容量上限」，直接当完全背包（正序）。

2）cnt = 1 走 01（倒序）；cnt 不大不小才需要多重背包那一套。

3）判「能不能当完全」的依据是 val · cnt 与容量 m 的大小关系，不是 cnt 本身。

4）布尔型多重背包（只问能不能凑出）可以用窗口计数，O(1) 平移，比每格重扫快一个数量级。

5）数值问题里的「无限」总要先落成一个有限的数，取值由容量与最小花费共同决定。

6）算时刻差、坐标差这类输入，先统一单位再当容量用。
