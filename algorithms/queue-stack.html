队列和栈

上一讲把链表当容器原地重排。这一讲给容器定规矩：队列、栈，以及刷题时真正在用的数组实现。环形队列的数组实现是笔试面试的高频考点，这一讲最后单独过一遍。

零、背景

队列、栈、双端队列可以组成非常多重要的数据结构。后面要讲的单调栈、单调队列、BFS，底座都是这两个容器。这一讲不求多，只求把三样东西写对：队列的数组实现、栈的数组实现、环形队列。

一、队列：先来先走

队列是 FIFO。offer 把数加到尾巴，poll 从头拿，peek 只看头不弹出。排队买奶茶，先到的先走。

队列在两头动：进在尾巴，出在头。

二、栈：后来先走

栈是 LIFO。push 进顶，pop 出顶，peek 看顶。叠盘子，后放的先拿。

栈只在一头动。这一个差别，让栈的数组实现比队列少一个变量。

三、队列的数组实现

直接用标准库的 std::queue 也能排队，但底层是 deque，分段分配、常数略大。刷题时更常见的写法是数组加两个下标，一条连续内存，空间完全可控。手写数组版就是下面这段。

C++ 这边对应关系一样：std::queue 底层是 deque（分段数组），手写数组版就是下面这段。

#include <bits/stdc++.h>
    using namespace std;

    // 数组版队列：l、r 两个下标，[l, r) 是活区间
    struct ArrayQueue {
        int* q;
        int l, r;            // 活区间 [l, r)，元素都在这里
        ArrayQueue(int n) {  // n = 加入总次数上限，必须提前明确
            q = new int[n];
            l = r = 0;
        }
        bool isEmpty() const { return l == r; }
        void offer(int x) { q[r++] = x; }   // 从尾巴进
        int poll() { return q[l++]; }       // 从头出
        int head() const { return q[l]; }   // 只看头，不弹出
        int tail() const { return q[r - 1]; }
        int size() const { return r - l; }
    };

[l, r) 是活区间，元素全在 q[l] 到 q[r-1] 里。offer 写 q[r++]，poll 读 q[l++]，head 是 q[l]，tail 是 q[r-1]，size 是 r - l，空不空看 l == r。

poll 不是真删除，只是 l 往前走一步。被拿走的格子再也回不来。

这就是构造函数为什么收一个 n，注释里写的还是「加入总次数」，不是「同时在队列里的个数」。塞满再取空，l 和 r 都跑到 n，size 是 0，但一个数也加不进，再 offer 就越界。实验（容量 8，8 次 offer 再 8 次 poll）：l=8, r=8, size=0，队列已经废了。

所以数组队列的适用范围是「加入总次数有上限」。BFS 里每个点入队一次，点的总数就是上限，正好够用。

四、栈的数组实现

数组版栈比标准库还省事：一个 size 变量就够，上限是「同时在栈里的元素个数」。

#include <bits/stdc++.h>
    using namespace std;

    // 数组版栈：一个 size 就够，弹出后空间可以复用
    struct ArrayStack {
        int* s;
        int size;            // 栈内元素个数
        ArrayStack(int n) {  // n = 同时在栈里的元素个数上限
            s = new int[n];
            size = 0;
        }
        bool isEmpty() const { return size == 0; }
        void push(int x) { s[size++] = x; }
        int pop() { return s[--size]; }
        int peek() const { return s[size - 1]; }
    };

push 写 s[size++]，pop 读 s[--size]，peek 读 s[size-1]，空不空看 size == 0。

差别在复用：弹出之后 size 回退，再 push 直接覆盖同一个格子。容量 8 的栈，push 满、取空、再 push，一万轮下来一直正常，空间是原样复用的。队列做不到，因为队列的 l 只往前走。

五、环形队列：高频考点

数组队列的空间用一次就丢，环形队列让 l 和 r 到末尾跳回 0，把格子循环起来。原题是 622. 设计循环队列。

#include <bits/stdc++.h>
    using namespace std;

    // 环形队列（数组实现），测试链接 https://leetcode.cn/problems/design-circular-queue/
    class MyCircularQueue {
    public:
        int* q;
        int l, r, size, limit;

        MyCircularQueue(int k) {
            q = new int[k];
            l = r = size = 0;
            limit = k;
        }

        // 满则不做，返回 false；否则加入 value，返回 true
        bool enQueue(int value) {
            if (isFull()) {
                return false;
            }
            q[r] = value;
            r = r == limit - 1 ? 0 : (r + 1);  // r++，到末尾跳回 0
            size++;
            return true;
        }

        // 空则不做，返回 false；否则弹出头部，返回 true
        bool deQueue() {
            if (isEmpty()) {
                return false;
            }
            l = l == limit - 1 ? 0 : (l + 1);  // l++，到末尾跳回 0
            size--;
            return true;
        }

        // 返回队头（不弹出），空返回 -1
        int Front() {
            if (isEmpty()) {
                return -1;
            }
            return q[l];
        }

        // 返回队尾（不弹出），空返回 -1
        int Rear() {
            if (isEmpty()) {
                return -1;
            }
            return q[r == 0 ? limit - 1 : (r - 1)];
        }

        bool isEmpty() { return size == 0; }
        bool isFull() { return size == limit; }
    };

三处细节，写错一处就错。

  • 回绕：r = r == limit - 1 ? 0 : r + 1，l 同理。等价于 (r + 1) % limit，但竞赛里普遍写三元式，省一次取模。
  • 为什么用 size 判空满：环上 l == r 既可能是空也可能是满，两个下标分不开。size 从 0 涨到 limit，空满一目了然。
  • Rear 的坑：r 永远指向下一个空位，所以最后一个元素在 r - 1；r == 0 时回绕到 limit - 1。

实验（limit = 4）：enQueue 1、2、3、4 之后 full，l=0, r=0, size=4，l 和 r 撞在一起，但队列是满的。deQueue 两次，l 到 2。再 enQueue 5、6：5 落在 q[0]，6 落在 q[1]，r 从 0 走到 2。Front 是 3，Rear 是 6。这时再 enQueue 7，返回 false。

六、复杂度分析

实现单次操作空间上限是什么
数组队列O(1)O(n)加入总次数 ≤ n，空间不回收
数组栈O(1)O(n)同时在栈内 ≤ n，空间复用
环形队列O(1)O(k)容量 k，空间循环使用
std::queue / std::stackO(1) 均摊O(当前元素数)不预设上限，靠扩容或分块分配

队列批量进批量出（BFS 的典型形状），1e7 进 + 1e7 出：数组版 7.0ms，std::queue 23.4ms，差 3.3 倍。但别把「数组版更快」当结论到处说。浅层随机 push/pop，两者几乎一样（76.85ms 对 76.90ms，都卡在分支预测上，不在内存上）。数组实现真正的价值是空间可控：不 new 节点、不碎片化，而且环形队列只能从数组版长出来。

环形队列写对的标准很简单：满的时候 enQueue 返回 false，空的时候 deQueue 返回 false，Front 和 Rear 不越界。下面这个操作台把随机序列跑几十轮，盯住这三条，写错一个立刻现形。

七、总结

这一讲就三件事，写完代码对照着过一遍。

  • 数组队列：poll 只是 l++，被取走的格子回不来。能用它的前提是「加入总次数 ≤ n」。
  • 数组栈：pop 后 size 回退，空间原样复用。上限是「同时在栈里的元素个数 ≤ n」。
  • 环形队列：l、r 到末尾跳回 0；空满只看 size；Rear 取 r - 1，r == 0 时回绕到 limit - 1。

单调栈、单调队列、BFS 的数组实现，都是这三段代码换个动作。写之前先想清楚上限是什么：队列是加入总次数，栈是同时在栈内，环形队列是容量。
