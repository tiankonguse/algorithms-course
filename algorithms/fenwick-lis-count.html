最长递增子序列的个数

ends 数组只留「每个长度的最小结尾」，个数信息被它丢掉了。把状态从「以哪个位置结尾」换成「以哪个值结尾」，长度和个数就能一起塞进树状数组，一次前缀查询顶替一整趟前驱枚举。

零、背景

求最长递增子序列的长度，ends 数组加二分就够了，时间 O(n log n)。现在多问一句：最长的那些一共有几条。

ends 数组给不出这个答案。它每个长度只留一个最小结尾，同一个长度下可能有好几种选法，那些选法在 ends 里是合并成一条的。要数个数，得换一个状态定义。

一、问题

给一个未排序的整数数组，返回最长递增子序列的个数。下面这个例子答案是 2。

nums = [1, 3, 5, 4, 7]
长度 4 的递增子序列：[1, 3, 5, 7] 和 [1, 3, 4, 7]，共 2 条

注意 [1, 3, 4, 7] 里的 4 在 5 后面，两条序列选的是不同的位置，都算。

二、朴素做法：以位置结尾的 dp

最直接的记法是按位置记。dp[i] 是以 i 结尾的最长递增子序列有多长，cnt[i] 是这样的序列有几条。填 i 时枚举所有 j < i，看 nums[j] 能不能接在前面。

// 以 i 位置结尾的最长递增子序列：长度 dp[i]、个数 cnt[i]
    // 时间复杂度 O(n^2)
    int FindNumberOfLIS(const vector<int>& nums) {
    	int n = nums.size();
    	vector<int> dp(n, 1);
    	vector<long long> cnt(n, 1);
    	for (int i = 0; i < n; i++) {
    		for (int j = 0; j < i; j++) {
    			if (nums[j] < nums[i]) {
    				if (dp[j] + 1 > dp[i]) {
    					dp[i] = dp[j] + 1;
    					cnt[i] = cnt[j];
    				} else if (dp[j] + 1 == dp[i]) {
    					cnt[i] += cnt[j];
    				}
    			}
    		}
    	}
    	int best = *max_element(dp.begin(), dp.end());
    	long long ans = 0;
    	for (int i = 0; i < n; i++) {
    		if (dp[i] == best) {
    			ans += cnt[i];
    		}
    	}
    	return (int)ans;
    }

这个写法在 n = 2000 时实测 6.18 ms，题目范围完全够用。可它是 O(n²)：n = 2 × 10⁴ 时涨到 360.97 ms，n = 10⁵ 时是 8802.73 ms，已经接近 9 秒。同一个规模下树状数组版是 13.87 ms。

慢在「枚举所有 j < i」这一趟。真实需要的只有一件事：在所有能接在 nums[i] 前面的元素里，最长的那条有多长、有几条。

三、把「以位置结尾」换成「以值结尾」

换个角度记。扫到 nums[i] 时，前面扫过的元素都已经记下来了。能接在 nums[i] 前面的，就是那些值严格小于 nums[i] 的元素，跟它们在哪个位置无关。

于是状态定义成：以值 v 结尾的最长递增子序列，长度是多少、个数是多少。值有 10⁹ 种可能，照例先离散化成 1 到 m 的排名。

每个值上要存两个量，所以开两棵树：treeMaxLen 存长度，treeMaxLenCnt 存个数。位置和值一一对应，两棵树共用同一个下标。

四、合并规则：长度取最大，个数跟着走

树状数组的每个节点代表一段值域。一个值被 add 进来时，它会往上更新所有覆盖它的节点；一个查询往下走，把经过的节点合并起来。合并规则要自己定。

这里的规则是先看长度：长度更大就直接顶替，长度相等就把个数加起来。

// 查询：结尾数值 <= i 的最长递增子序列，长度是多少、个数是多少
    void Query(int i) {
    	maxLen = maxLenCnt = 0;
    	while (i > 0) {
    		if (maxLen == treeMaxLen[i]) {
    			// 长度打平，个数要累加
    			maxLenCnt += treeMaxLenCnt[i];
    		} else if (maxLen < treeMaxLen[i]) {
    			maxLen = treeMaxLen[i];
    			maxLenCnt = treeMaxLenCnt[i];
    		}
    		i -= Lowbit(i);
    	}
    }
// 更新：以数值 i 结尾的最长递增子序列，长度达到了 len，个数增加了 cnt
    void Add(int i, int len, long long cnt) {
    	while (i <= m) {
    		if (treeMaxLen[i] == len) {
    			treeMaxLenCnt[i] += cnt;
    		} else if (treeMaxLen[i] < len) {
    			treeMaxLen[i] = len;
    			treeMaxLenCnt[i] = cnt;
    		}
    		i += Lowbit(i);
    	}
    }

最后一步是把整棵树的信息合并成答案，也就是 Query(m)。注意 query 从 m 开始往下跳，走的是「所有值」这个范围。

// 时间复杂度 O(n * logn)
    long long FindNumberOfLIS(vector<int>& nums) {
    	int n = nums.size();
    	sorted.assign(n + 1, 0);
    	for (int i = 1; i <= n; i++) {
    		sorted[i] = nums[i - 1];
    	}
    	sort(sorted.begin() + 1, sorted.end());
    	m = 1;
    	for (int i = 2; i <= n; i++) {
    		if (sorted[m] != sorted[i]) {
    			sorted[++m] = sorted[i];
    		}
    	}
    	for (int num : nums) {
    		int i = Rank(num);
    		Query(i - 1);
    		if (maxLen == 0) {
    			// 结尾数值更小的子序列一条都没有，那就是长度 1、个数 1
    			Add(i, 1, 1);
    		} else {
    			// 接在最长的那些后面，长度 +1，个数直接继承
    			Add(i, maxLen + 1, maxLenCnt);
    		}
    	}
    	Query(m);
    	return maxLenCnt;
    }

五、两个容易写错的地方

第一个是刚才说的并列长度。同一条最长路径可能来自好几个不同的结尾值，个数要累加而不是覆盖。

// 漏掉长度相等那一支：并列的最长长度被丢掉，个数只留最后碰到的那一个
    void Query(int i) {
    	maxLen = maxLenCnt = 0;
    	while (i > 0) {
    		if (maxLen < treeMaxLen[i]) {
    			maxLen = treeMaxLen[i];
    			maxLenCnt = treeMaxLenCnt[i];
    		}
    		i -= Lowbit(i);
    	}
    }

第二个是个数的类型。个数增长得非常快，用 int 存会溢出。随机 2000 组数据（值域 500，n 在 300 到 2000 之间）实测，1.25% 的用例答案超过 int 的上界 2147483647，最大的一组达到 76482840384。n = 2 × 10⁴ 时答案能到 7.7 × 10¹⁸，已经逼近 long long 的上界 9.22 × 10¹⁸。题目把 n 限制在 2000 以内，跟这件事不无关系。

还有一处：离散化之后查询的是 Rank(num) − 1，求的是严格小于。递增子序列要求严格递增，跟自己相等的值不能接。

项目时间空间
离散化（排序 + 去重）O(n log n)O(n)

两棵树按值的种类数 m 开，m ≤ n。相比 O(n²) 的 dp，省掉的是「枚举所有前驱」那一层。实测 n = 10⁵ 时 dp 版 8802.73 ms，树状数组版 13.87 ms。

总结

这题的关键一步是把状态从「以位置结尾」换成「以值结尾」。换了之后，「所有能接在前面的元素」从一堆下标变成了一段前缀，最大值查询就交给树状数组。

两棵树必须一起动：长度更大时顶替并重置个数，长度相等时只累加个数。漏掉相等那一支，答案会偏小，值域 500 时随机数据有一半以上的用例会错。个数用 long long，n = 2 × 10⁴ 时它就能涨到 7.7 × 10¹⁸。

「长度 + 个数」只是其中一种信息。换成「长度 + 最小字典序的方案」、换成「价值 + 方案数」，合并规则按同样的思路重新定一遍就行。
