排序算法总结

八种排序各有各的脾气：有的稳定有的不稳定，有的快有的慢。这一讲把选择、冒泡、插入、归并、快排、堆排、计数、基数放一张表里对完，回答一个实际问题：手上的排序任务，到底用哪个。

零、背景

n=100 万的随机数组，插入排序要 72 秒，计数排序只要 2.5 毫秒，差三万倍。同样是「把数组排好序」，选错做法的代价可以这么大。

前面几节课，从选择冒泡插入一路讲到基数排序，每种排序单独成篇。谁快谁慢、谁稳谁不稳，散在各页。这一讲把它们摆在一起对一遍，顺带把「什么场景用哪个」说清楚。

对完你会发现，排序世界里没有万能算法。每个排序都拿一些东西换了另一些东西，换什么、换多少，看场景。

一、稳定性

稳定性说的是值相同的元素排序之后相对次序变不变。数组 [5(a), 5(b), 2]，有的排序把它排成 [2, 5(a), 5(b)]，两个 5 的先后没动；有的排序排成 [2, 5(b), 5(a)]，5(b) 跑到了 5(a) 前面。

对 int 这类基础类型，稳定性毫无意义，两个 5 谁先谁后结果一样。对对象有意义：员工数组先按工号排好，再按年龄排，年龄相同的人工号顺序要保持住，因为后面可能还要按工号接着用。稳定性保住的是之前排过的次序。

八种排序的稳定性分布很干脆：冒泡、插入、归并、计数、基数稳定，选择、快排、堆排不稳定。

不稳定的三种各有各的原因。选择排序是跨元素交换：第 i 轮把最小值换到位置 i，这一交换会跳过中间的元素。[5(a), 5(b), 2] 第一轮把 2 换到位置 0，5(a) 被顶到位置 2，5(a) 和 5(b) 就反了。快排的 partition 靠交换划三段，相等的元素在交换里互相越过。堆排序的建堆和「堆顶换到堆尾」全是远距离交换，稳定无从谈起。

实测也印证。给每个元素带上原始下标，随机数据跑 2000 组：选择、快排、堆排在 n≥100 时 100% 不稳定；冒泡、插入、归并、计数、基数 0 组不稳定。n=10 的小数组里选择排序还有约三分之一的组碰巧稳定，数据一长、重复值一多就全乱。

怎么判断一个排序稳不稳定？写个验证器：元素带上原始下标 idx，排序只比 v，排完检查同值段里 idx 是否仍然递增。代码就几行：

// 给元素带上原始下标，排序只比 v，最后检查同值段里 idx 是否仍然递增
    struct E { int v, idx; };

    bool isStable(const vector<E>& a) {
        for (int i = 0; i < (int)a.size(); ) {
            int j = i;
            while (j < (int)a.size() && a[j].v == a[i].v) j++;
            for (int k = i + 1; k < j; k++)
                if (a[k].idx < a[k - 1].idx) return false;
            i = j;
        }
        return true;
    }

演示：稳定性检查器

选一个排序算法和一组数据，点「下一步」看它怎么排。每格是值 + 原始下标，末帧检查同值元素的相对次序：保持标绿，被打乱标红。

二、八种排序一张表

时间、空间、稳定性，一张表列完：

复杂度按平均、期望口径。快排的 O(n log n) 是概率意义上的期望，最坏退化 O(n²)，随机选 pivot 之后退化概率低到可以忽略，之前讲随机快排时说过。计数和基数的 O(n) 吃数据：值域多大，计数数组就多长。

比较次数能看出这些排序的常数差别。n=10000 随机数组实测：

选择恒为 n(n-1)/2 = 49995000，跟数据长什么样没关系。冒泡最坏也这么多，带提前停止标记在随机数据上也省不了几个，实测 4999 万上下，因为随机数据里「已经有序的尾部」出现得太晚。插入约 2500 万。归并约 12 万，快排约 15 万，堆排约 23.5 万。

归并比快排少、快排比堆排少，差在常数上。归并每次比较锁定一个元素的最终位置；快排 partition 里等于 x 的元素会被重复比较；堆排的调整路径本身最长。但比较次数少不等于跑得快：归并要额外 O(n) 的数组，快排原地交换、缓存友好。n=100 万实测，归并 44.8ms，快排 58.9ms，归并反而快一点，差距不大。

三、比较排序的极限

基于比较的排序有个绕不开的下界：Ω(n log n)。n 个元素的全排列有 n! 种，一次比较最多把候选一分为二，至少 log₂(n!) ≈ n log₂n 次比较才分得开。这是信息论给的天花板，与算法聪明不聪明无关，讲基数排序时已经提过。

时间被卡死，能优化的只剩空间和稳定性。于是有个问题：有没有 O(n log n) 时间、O(1) 额外空间、还稳定的排序？

目前没有。归并稳定但空间 O(n)；堆排空间 O(1) 但不稳定；快排空间 O(log n) 也不稳定。三样全占的排序到现在也没找到。TimSort 也不行：它稳定、实践里额外空间通常很小，但空间指标的严格上界就是 O(n)。

希尔排序是加步长的插入排序，先排间隔为 gap 的元素再缩小 gap。不稳定，工程里用得少，知道有这回事就行。

结论是排序世界没有免费午餐，每一项指标都是拿别的换来的。

四、怎么选

选型看你在乎什么，几条路对应几种场景：

数据量非常小，用插入排序。实测 n≤128 时插入比快排快两倍左右：20 万次 n=16 的排序，插入 23.5ms，快排 69.5ms。实现又简单，std::sort 内部对小区间用的就是插入排序。

不在乎稳定性，用随机快排。n=100 万实测 58.9ms，原地、缓存友好，常数小。

要稳定、不在乎额外空间，用归并排序。实测 44.8ms，比快排还快。

要 O(1) 空间、不在乎稳定性，用堆排序。87.2ms，慢一些但空间恒定。

值域小、又是非负整数，用计数和基数排序。2.5ms 和 9.7ms，快一个数量级，但只吃这种规整的数据。

工程里不自己造，直接用 std::sort。它是 introsort：快排为主，递归太深切到堆排，小数组切到插入排序。实测 42.5ms，各方面均衡，不保证稳定。

五、复杂度分析

汇总成一张复杂度表，按平均、期望口径：

算法时间空间稳定性
选择排序O(n²)O(1)无
冒泡排序O(n²)O(1)有
插入排序O(n²)O(1)有
归并排序O(n log n)O(n)有
随机快排O(n log n)*O(log n)无
堆排序O(n log n)O(1)无
计数排序O(n+M)O(M)有
基数排序O(n·bits)O(n+BASE)有

* 随机快排按期望口径，最坏退化 O(n²)。

数据量小的时候，O(n²) 和 O(n log n) 的差距还没拉开，常数和实现的简单程度反而主导；数据量一大就不同了。n=10000 时插入 6.96ms、归并 0.28ms，差 25 倍；n=100 万时插入 72 秒、归并 44.8ms，差 1600 倍。O(n²) 的排序只适合小数据，这是它唯一的舞台。

六、总结

排序这一大块到此收工，要点如下：

第一，稳定性等于同值元素相对次序不变。冒泡、插入、归并、计数、基数稳定，选择、快排、堆排不稳定。判断方法：元素带下标，排完检查同值段。

第二，八种排序的时间、空间、稳定性一张表背下来，选型直接查表。

第三，比较排序有信息论下界 Ω(n log n)；O(n log n) 加 O(1) 空间加稳定，目前不存在，别去找。

第四，选型口诀：小数据插入，大数据看稳定性。要稳用归并，不要稳用快排，空间紧用堆排，数据规整用计数基数。工程默认 std::sort。

接下来不再比大小了，进入位运算：异或那套不用比较，也能干出排序干不了的事。
