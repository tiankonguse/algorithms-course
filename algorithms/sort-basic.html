选择、冒泡、插入排序

三个 O(n²) 的原地排序。它们几乎不会出现在正式代码里，但「循环里维护的是哪一段」「交换相邻两项到底算几次」「相等的值会不会被调包」这几件事，在这三个例子上看一遍就懂。

零、背景

入门就讲这三种排序，不是因为好用。真要排序，直接 sort 就够了。

它们的用处是简单到一眼看穿。每一层循环分别在干什么、循环结束那一刻数组满足什么性质，都能一句话说完。把这三段代码看熟，后面再遇到「左右两边往中间凑」「左边一段已经有序」这类描述就不用重新推。

另一层用处是当参照物。后面讲对数器时会反复出现「写一个笨但肯定对的程序去验证」，那个笨程序往往就是这三个之一。

一、问题

给一个长度为 n 的 int 数组，把它重排成非降序：任意 i < j 都满足 arr[i] <= arr[j]。

本讲的三种写法都是原地排序：除了交换用的那个临时变量，不再申请别的空间。

二、先把交换写好

三个都要用到交换，先单独拎出来。

void swapValue(vector<int>& arr, int i, int j) {
        int tmp = arr[i];
        arr[i] = arr[j];
        arr[j] = tmp;
    }

传的是下标，不是值。这里顺便说一句：即使 i 和 j 相等，这个函数也是安全的，中间变量已经把原值存住了。选择排序会频繁碰到「自己和自己换」。

三、三种「区间想法」

这三种排序真正的区别，在于「已经弄好的那一段」放在数组的哪一侧。

  • 选择排序：i ~ n-1 上找最小值放到 i 位置，然后 i+1 ~ n-1 上继续
  • 冒泡排序：0 ~ end 上相邻位置较大的数滚下去，最大值最终来到 end 位置，然后 0 ~ end-1 上继续
  • 插入排序：0 ~ i-1 已经有序，新来的数从右往左滑到「左边不再比它大」的位置

这里有个细节：选择排序留下的前缀是最终形态，一个字都不会再动；冒泡排序留下的后缀同样是最终形态。插入排序留下的前缀只是「有序」，后面来的更小的数会把其中一段整体往右顶。

下面按这三个顺序各看一遍，例子都用同一个数组 [5, 2, 9, 1, 7, 3]，这样三种方法的「第一步」可以直接对着比。

四、选择排序

void selectionSort(vector<int>& arr) {
        int n = (int)arr.size();
        if (n < 2) return;
        for (int i = 0; i < n - 1; i++) {
            int minIndex = i;
            for (int j = i + 1; j < n; j++) {
                if (arr[j] < arr[minIndex]) minIndex = j;
            }
            swapValue(arr, i, minIndex);
        }
    }

外层 i 从 0 跑到 n-2。最后一轮右边只剩一个元素，没有再扫的必要，所以是 n-1 轮而不是 n 轮。

内层做一次线性扫描，只把「最小值所在的下标」记下来，扫完才换一次。比较条件是严格的 <，相等时保留先遇到的那个，这个选择后面讲稳定性时会再提。

拿例子跑第一轮：minIndex 从 0 出发，扫到下标 3 时遇到值 1，把它换到位置 0，数组变成 [1, 2, 9, 5, 7, 3]。第二轮 minIndex 一开始就是 1，扫完还是 1，于是位置 1 和位置 1 换了一次，这就是前面说的自交换，代码不做判断。

五、冒泡排序

void bubbleSort(vector<int>& arr) {
        int n = (int)arr.size();
        if (n < 2) return;
        for (int end = n - 1; end > 0; end--) {
            for (int i = 0; i < end; i++) {
                if (arr[i] > arr[i + 1]) swapValue(arr, i, i + 1);
            }
        }
    }

end 从 n-1 到 1。每轮把 0 ~ end 上相邻的两个数比一遍，大的往右挪，一串比较下来最大值一定漂到 end。

同一个例子：end = 5 时，9 在位置 2，比旁边的 1、7、3 都大，于是连挪三格到位置 5，数组变成 [2, 5, 1, 7, 3, 9]。

可以看出，一趟跑下来一次交换都没发生的话，说明整个数组已经有序了，没必要继续。加一个标记就能提前停：

bool sorted = true;
    for (int i = 0; i < end; i++) {
        if (arr[i] > arr[i + 1]) {
            swapValue(arr, i, i + 1);
            sorted = false;
        }
    }
    if (sorted) break;

加了这段之后，本来就有序的数组只跑一趟就结束，退化成 O(n)。注意这个「提前停止版」和不带标记的版本代价不一样，下面复杂度分析里分开写。

六、插入排序

void insertionSort(vector<int>& arr) {
        int n = (int)arr.size();
        if (n < 2) return;
        for (int i = 1; i < n; i++) {
            for (int j = i - 1; j >= 0 && arr[j] > arr[j + 1]; j--) {
                swapValue(arr, j, j + 1);
            }
        }
    }

i 从 1 到 n-1。左边 0 ~ i-1 已经有序，把 arr[i] 依次和左边的数比，只要左边更大就换一次，一直滑到左边不再比它大。

同一个例子的第一步：i = 1 时 2 比 5 小，换一次得到 [2, 5, 9, 1, 7, 3]；接着 i = 3 时那个 1 会一路滑到最左边。

「不停和左边交换」这个写法短，代价是每次挪位要做三次赋值。更常见的写法是先把当前数取出来，左边比它大的统统右移一格，空出来的位置最后放进去：

void insertionSort(vector<int>& arr) {
        int n = (int)arr.size();
        for (int i = 1; i < n; i++) {
            int cur = arr[i];
            int j = i - 1;
            while (j >= 0 && arr[j] > cur) {
                arr[j + 1] = arr[j];
                j--;
            }
            arr[j + 1] = cur;
        }
    }

两个版本的结果完全一样，赋值次数的差别不小。还是上面那个例子：交换版一共 8 次交换，等于 24 次赋值；移位版只有 13 次赋值（其中 5 次是把当前数放回去）。

八、三种算法放在一起比

把刚才的数对齐了看：

比较次数交换次数最好情况稳定性
选择排序n(n-1)/2，恒定n-1 次（含自交换）无，任何输入都一样不稳定
冒泡排序（不带标记）n(n-1)/2，恒定逆序对数已排好时 0 次交换稳定
冒泡排序（带提前停止）最好 O(n)，最坏同上逆序对数已排好时跑一趟即停稳定
插入排序逆序对数 + (n-1)逆序对数已排好时比较 n-1 次、交换 0 次稳定

交换次数这一列最值得记：冒泡和插入每换一次，恰好消掉一个逆序对，一个不多一个不少，所以它们的交换次数都等于数组的逆序对数。逆序对最多 n(n-1)/2 个，这就是两者最坏情况的下界来源。

选择排序反过来：交换次数被压到线性，因为每轮只换一次。代价是它必须老老实实把剩下的整段扫一遍，所以比较次数被钉死在 n(n-1)/2，连运气好的时候都没有。

稳定性看最后那一列。所谓稳定，是说值相等的两个元素，排序后还保持原来的先后顺序。

选择排序吃亏在「跨距离交换」：它把最小值直接甩到 i 位置，中间的元素会被挤到后面去，两个相等的值很容易就在这一次甩的过程中换了先后。冒泡和插入只交换相邻的那两个，而且只在严格大于时才动手，相等的值不会被跨过去，所以稳定。

九、复杂度分析

三个算法都只有常数个变量，没有递归、没有辅助数组。

算法最好时间平均时间最坏时间额外空间
选择排序O(n²)O(n²)O(n²)O(1)
冒泡排序（不带标记）O(n²)O(n²)O(n²)O(1)
冒泡排序（带提前停止）O(n)O(n²)O(n²)O(1)
插入排序O(n)O(n²)O(n²)O(1)

把 demo 里的具体数字对上，[5, 2, 9, 1, 7, 3] 一共 8 个逆序对：选择排 15 次比较、5 次交换（含 1 次自交换）；冒泡（不带标记）15 次比较、8 次交换；插入 13 次比较、8 次交换。n = 6 时 n(n-1)/2 = 15。

空间上都只用到一个临时变量，排序过程在原来的数组上完成，额外空间 O(1)。

十、最后

这三个算法的价值不在速度，在于它们把「维护一段区间」这件事拆到了最简：一个指针确定边界，一个指针在边界内扫。

真要写成生产过程的代码，三选一的话通常是插入排序，小规模数据上它最快，且天生适配「新增一个元素后重新变有序」的场景，后面有些题就恰好需要这个性质。
