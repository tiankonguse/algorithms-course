轮廓线 dp：贴瓷砖与相邻不同色

轮廓线的骨架不变，换一道题要重新定的是「一位装什么」。种草那题一位装种没种；贴瓷砖的决策会跨两行，一位装的是这个位置有没有被上一行伸下来的竖砖占住；染色题每个格子有 k 种取值，一位装不下，得给每个格子留两位。

零、背景

先看清轮廓线 dp 里到底哪两样东西是固定不变的：一是状态长度恒为 m，二是处理 (i, j) 时要用到的邻居都在状态里。剩下的是编码，编码完全取决于题目。

种草那题每个格子只有「种 / 不种」两种决定，一位刚好。贴瓷砖不一样：横砖只在本行内占两格，竖砖要占到下一行去，本行做决定的时候，那个影响得记到状态里带下去。

一、贴瓷砖

n 行 m 列的一块空白区域，用无限多块 1 × 2 的瓷砖严丝合缝地铺满，返回铺法数。n、m 不超过 11。

编码这么定：s 的第 j 位是 1，表示 (i, j) 已经被上一行伸下来的竖砖占住了。于是走到 (i, j) 只有三种情形。

第二种情形里那个 i + 1 < n 的判断不能省。最后一行再竖着放，砖就伸出网格了，那份方法数得扔掉。第三种情形的 get(s, j + 1) == 0 同理：右边那格已经被上一行的竖砖占了，横砖铺不进去。

long long dp[MAXN][MAXM][1 << MAXM];

    // s 的第 j 位是 1：表示 (i, j) 已经被上一行伸下来的竖砖占住了
    // 返回从 (i, j) 往后有几种铺法
    long long f(int i, int j, int s) {
        if (i == n) return 1;
        if (j == m) return f(i + 1, 0, s);
        if (dp[i][j][s] != -1) return dp[i][j][s];
        long long ans = 0;
        if (get(s, j) == 1) {
            ans = f(i, j + 1, set(s, j, 0));               // 位置已被占，清掉标记往右走
        } else {
            if (i + 1 < n) ans = f(i, j + 1, set(s, j, 1));             // 竖着放
            if (j + 1 < m && get(s, j + 1) == 0) ans += f(i, j + 2, s); // 横着放
        }
        dp[i][j][s] = ans;
        return ans;
    }

空间压缩版跟种草那题一个形状，只有一处不同：横着放要读 dp[j + 2]，所以第一维得留 m + 2 层。

long long dp[MAXM + 2][1 << MAXM];   // 横着放要用 dp[j+2]，所以留 m+2 层
    long long prepare[1 << MAXM];

    long long compute() {
        for (int s = 0; s < maxs; s++) prepare[s] = 1;
        for (int i = n - 1; i >= 0; i--) {
            for (int s = 0; s < maxs; s++) dp[m][s] = prepare[s];
            for (int j = m - 1; j >= 0; j--) {
                for (int s = 0; s < maxs; s++) {
                    long long ans = 0;
                    if (get(s, j) == 1) {
                        ans = dp[j + 1][set(s, j, 0)];
                    } else {
                        if (i + 1 < n) ans = dp[j + 1][set(s, j, 1)];
                        if (j + 1 < m && get(s, j + 1) == 0) ans += dp[j + 2][s];
                    }
                    dp[j][s] = ans;
                }
            }
            for (int s = 0; s < maxs; s++) prepare[s] = dp[0][s];
        }
        return dp[0][0];
    }

这题的答案有个很干脆的规律：n × m 是奇数时一定是 0。每块砖盖 2 格，总面积必须是偶数，11 × 11 grids 铺不出来。实测 3 × 3、5 × 5、7 × 7、9 × 9、11 × 11 全是 0。

顺手量了一下朴素回溯的代价：不用状压、直接一格一格试放，8 × 8 要 282.56 毫秒，9 × 9 要 24.3 秒。轮廓线版在这两个规模上分别是 0.016 毫秒和 0.052 毫秒。差了四个数量级还不止。

二、铺砖台

选一个规模，点「竖放」「横放」或者「被占，继续」把瓷砖一块一块铺上去。蓝砖是竖着放的，绿砖是横着放的，右边那排格子是轮廓线。

铺砖台：一块一块地铺，看轮廓线怎么动

三个按钮同时只会亮一个或者两个。s[j] 是 1 的时候只有「被占，继续」能点；s[j] 是 0 的时候，「竖放」要 i + 1 < n，「横放」要 j + 1 < m 且 s[j+1] = 0。

三、相邻不同色

n 行 m 列，k 种颜色，相邻格子上、下、左、右都不能同色。第 0 行和第 n−1 行的颜色已经给定且保证合法，只有第 1 到 n−2 行能自己定，返回染色方法数，对 376544743 取模。k 是 2 到 4。

这次一个格子有 k 种取值，一位装不下。做法很直接：每个格子给 2 位，第 j 格的颜色放在 s 的第 2j 和 2j+1 位上。

const int MOD = 376544743;
    int start[LIMIT1], end[LIMIT1];
    int dp[LIMIT2 + 1][1 << (LIMIT2 << 1)];
    int prepare[1 << (LIMIT2 << 1)];

    // 一个格子占 2 位：第 j 格的颜色放在 s 的第 2*j、2*j+1 位
    int get2(int s, int j) {
        return (s >> (j << 1)) & 3;
    }

    // 把第 j 格的颜色改成 v（0..k-1），其余格子不动
    int set2(int s, int j, int v) {
        return (s & (~(3 << (j << 1)))) | (v << (j << 1));
    }

取位和置位的写法跟一位版完全同构，只是把 1 换成 3、把 j 换成 2j。这里有个容易写错的地方：3 << (j << 1) 的括号一个都不能省，j << 1 才是位偏移。

四、k 等于 2 的时候

k = 2 时题目数据给到 n ≤ 10⁷、m ≤ 10⁵，dp 做不动，也不用做。两种颜色加上四邻不同色，整张网格的颜色是被第 0 行完全锁死的：第 1 行只能是第 0 行逐格取反，第 2 行又变回来，一路交替下去。

于是第 n−1 行长什么样由 n 的奇偶决定。n 是奇数时它必须和 start 完全相同，n 是偶数时必须逐格不同。对不上就是 0，对上了就只有 1 种。

// k == 2 时整张网格的颜色被第 0 行锁死，一行都不用 dp
    int special() {
        if ((n & 1) == 0) {
            for (int j = 0; j < m; j++) if (start[j] == end[j]) return 0;
        } else {
            for (int j = 0; j < m; j++) if (start[j] != end[j]) return 0;
        }
        return 1;
    }

这一支的代价是 O(m)，跟 n 一点关系都没有。真正要跑 dp 的是 k = 3 和 k = 4，数据收到 n ≤ 100、m ≤ 8。

五、染色的填表

转移比种草多一层：每个格子要把 k 种颜色都试一遍，只有跟左边、上面都不同的才往下走。

for (int s = 0; s < maxs; s++) {
        prepare[s] = different(s, endStatus) ? 1 : 0;   // 最后一行要和 end 逐格不同
    }
    for (int i = n - 2; i >= 1; i--) {
        for (int s = 0; s < maxs; s++) dp[m][s] = prepare[s];
        for (int j = m - 1; j >= 0; j--) {
            for (int s = 0; s < maxs; s++) {
                int ans = 0;
                for (int c = 0; c < k; c++) {
                    // 左边（本行 j-1 列）和上面（i-1 行 j 列）都不能同色
                    if ((j == 0 || get2(s, j - 1) != c) && get2(s, j) != c) {
                        ans = (ans + dp[j + 1][set2(s, j, c)]) % MOD;
                    }
                }
                dp[j][s] = ans;
            }
        }
        for (int s = 0; s < maxs; s++) prepare[s] = dp[0][s];
    }
    return dp[0][startStatus];

这里有个能算出来的细节：一个格子实际能选的颜色数取决于左边和上面同不同色。两者同色时是 k − 1 种，不同色时是 k − 2 种。随机状态下两者同色的概率是 1/k，所以平均分支数是 (k − 1) / k + (k − 2)(k − 1) / k，k = 3 时实测 1.688，k = 4 时 2.250。

这一题是空间压缩必须掌握的理由。不压缩的表是 dp[n][m][4m]，n = 100、m = 8 时是 100 × 8 × 65536 个 int，200 MB；压缩后是 dp[9][65536]，2.25 MB，差 89 倍。不压缩的版本在线上会直接因为内存被判掉。

复杂度分析

两道题都用 S 表示状态数：贴瓷砖 S = 2m，染色 S = 4m。

题目时间复杂度空间复杂度规模上限
贴瓷砖O(n · m · S)O(m · S)S = 2¹¹ = 2048，表 13 × 2048 个 long long，0.21 MB
染色（k = 2）O(m)O(m)只扫一遍 start 和 end
染色（k ≥ 3）O(n · m · S · k)O(m · S)S = 4⁸ = 65536，表 9 × 65536 个 int，2.25 MB

空间按题目上限算。贴瓷砖因为横着放要读 dp[j+2]，第一维是 m + 2 = 13 层；染色只用到 dp[j+1]，m + 1 = 9 层就够。

总结

这两道题讲的是同一件事的两头：贴瓷砖说明「一位装什么」由决策的跨度决定，竖砖跨行所以要把占位记进状态；染色说明一个格子取值多了就得给多位，状态数跟着从 2 的 m 次方涨到 4 的 m 次方。还有两处边界是写的时候最容易漏的：最后一行不能竖着放，横砖的右边那格必须空着。

再往后是轮廓线 dp 里最麻烦的一类：需要的邻居里有一个已经被轮廓线自己覆盖掉了，只能单独当参数往下传。
