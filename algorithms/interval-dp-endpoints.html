区间 dp：在两端点上做决策

两个可变参数不一定代表两个串，也可以代表同一段区间的左右端。参数换了，格子的依赖图形状跟着换：每个格子要看它里层的一整圈。这一页两道题都属于最窄的一类，答案只由两端的字符决定。

零、两个参数的另一种取法

二维 dp 的两个参数一般是两个串各自走到了第几个字符。还有另一种取法：两个参数都是下标，圈住同一个串（或同一个数组）的一段，f(l, r) 表示「只在 s[l..r] 这一段上做文章」。

这一段的长度是 r − l + 1。往回走的时候区间只会变短，所以 f(l, r) 顶多依赖 f(l+1, r)、f(l, r−1)、f(l+1, r−1) 这类更小的区间，绕不回自己。把 l 从大到小、r 从小到大铺成两层循环，每个格子轮到时，它要用的格子都已经填好了。

区间上的可能性有两种常见的展开方式：

  1. 在两端点上讨论。先盯着 s[l] 和 s[r]，由它们相等与否派生更短的区间。
  2. 在区间里挑一个划分点 m。把 [l, r] 切成 [l, m] 和 [m, r]，两边各自算完再拼起来。

这一页走第一种，两道题都只会派生 l+1、r−1 这种紧挨着的邻区间。

一、让字符串成为回文串的最少插入次数

给一个字符串 s，每次可以在任意位置插入任意字符，问最少插几次能把它变成回文串。zzazz 一次都不用插，mbadm 插 2 次，leetcode 插 5 次。

状态：f(l, r) 表示只把 s[l..r] 这一段变成回文串，最少插几个字符。

看两端的字符，只有两种情况。

1）s[l] == s[r]。这两个字符正好配上。中间那些字符怎么补，都不会影响它们俩配对，于是问题缩成 f(l+1, r−1)。

2）s[l] != s[r]。两端配不上，至少得动一个。要么在最右边补一个和 s[l] 相同的字符，让左端有伴，问题缩成 f(l+1, r)；要么在最左边补一个和 s[r] 相同的，问题缩成 f(l, r−1)。两条路都要付一次插入，取小的那个再加 1。

边界：l == r 时单个字符本身就是回文，返回 0；l + 1 == r 时两个字符相等返回 0、不等返回 1。

// s[l..r] 范围内的字符要变成回文串，最少插入几个字符
    int f(const string& s, int l, int r) {
        if (l == r) return 0;
        if (l + 1 == r) return s[l] == s[r] ? 0 : 1;
        if (s[l] == s[r]) return f(s, l + 1, r - 1);
        return min(f(s, l, r - 1), f(s, l + 1, r)) + 1;
    }

    int minInsertions(const string& s) {
        return f(s, 0, (int)s.size() - 1);
    }

拿 abca 走一遍：s[0] 和 s[3] 都是 a，直接跳进 f(1, 2)；b 和 c 不相等，两个分支各付一次插入，答案 1。补法是在 c 右边插一个 b，得到 abcba。

二、把这张表铺开

两个参数都是下标，而且 l ≤ r，所以这张表只有右上半个三角有用。r − l 从 1 开始往上长：长度 1 的区间全是 0（单个字符）；长度 2 的区间由两个字符是否相等决定。

剩下的格子按 r − l 从小到大填。写成两层循环就是 l 从 n−3 递减到 0、r 从 l+2 递增到 n−1。这样 dp[l][r−1]（同一行左边）和 dp[l+1][r]（下一行右边）都已经算过，dp[l+1][r−1] 在下一行的更左边，更早就有了。

暴力那份递归慢在哪？把字符串取成每个字符都不同的最坏形状，调用次数是 2n−1 − 1：n=4 时 7 次，n=8 时 127 次，n=14 时 8191 次。n 每加 2，调用量翻四倍。可真正不同的状态只有 n(n+1)/2 个，n=14 时才 105 个。铺表就是把 8191 次调用压成 105 个格子。

int minInsertions(const string& s) {
        int n = s.size();
        vector<vector<int>> dp(n, vector<int>(n, 0));
        for (int l = 0; l < n - 1; l++) {           // 长度 2 的区间
            dp[l][l + 1] = s[l] == s[l + 1] ? 0 : 1;
        }
        for (int l = n - 3; l >= 0; l--) {          // 区间左端从右往左推
            for (int r = l + 2; r < n; r++) {       // 右端从左往右推
                if (s[l] == s[r]) dp[l][r] = dp[l + 1][r - 1];
                else dp[l][r] = min(dp[l][r - 1], dp[l + 1][r]) + 1;
            }
        }
        return dp[0][n - 1];
    }

三、空间压缩：斜角那个格子要留一手

三层依赖里有两层是「同一列」的邻居，只留一行也能取到：dp[l][r−1] 是本轮刚填过的左边一格，dp[l+1][r] 是这一格被覆盖之前的旧值。麻烦的是 dp[l+1][r−1]，它在下一行的左边，本轮早被覆盖掉了。

用一个变量 leftDown 接住它。每一轮进内层循环前，leftDown = dp[l+1] 就是 dp[l+1][l+1]；之后每填完一格，把覆盖前的旧值赋给它，它便一路跟着变成 dp[l+1][r−1]。顺序不能反，先备份再覆盖。

int minInsertions(const string& s) {
        int n = s.size();
        if (n < 2) return 0;
        vector<int> dp(n, 0);                       // dp[r] 依次代表 dp[cur][r]
        dp[n - 1] = s[n - 2] == s[n - 1] ? 0 : 1;
        for (int l = n - 3; l >= 0; l--) {
            int leftDown = dp[l + 1];               // 上一轮还留着的 dp[l+1][l+1]
            dp[l + 1] = s[l] == s[l + 1] ? 0 : 1;
            for (int r = l + 2; r < n; r++) {
                int backUp = dp[r];                 // 先存下上一轮的 dp[l+1][r]
                dp[r] = (s[l] == s[r]) ? leftDown : min(dp[r - 1], dp[r]) + 1;
                leftDown = backUp;
            }
        }
        return dp[n - 1];
    }

代价是两趟都跑 n²/2 个格子，只省了内存。字符串取 2000 长：二维表 4.73 ms、16 MB，滚动数组 3.33 ms、8 KB。省下的是内存，顺带因为缓存更友好快了一点。

还有个恒等式可以用来验算：最少插入次数等于 n 减去最长回文子序列的长度。最长回文子序列本身就要在区间上 dp，两边是同一套路子。随机 1200 组小串（最长 11 位，最长回文子序列用枚举全部子序列的暴力算）逐组核算，两边完全一致。

四、预测赢家：对手的选择夹在中间

给一个数组，两个人轮流从两端取一个数加进自己的分数，先手先取，两人都让自己的分数最大。先手分数不低于后手就算先手赢。

[1, 5, 2] 先手赢不了，[1, 5, 233, 7] 能赢。第二个数组里先手的第一步是关键：取 7 或者取 1 都行，取 1 时对手只剩 7 和... 顺着 dp 走一遍就清楚了。

状态：f(l, r) 表示在 nums[l..r] 上继续玩、轮到当前这位玩家时，他能拿到的总分。这个定义对两个人通用：谁轮到，谁就套这个 f。

转移：当前玩家只有两个选择。

取 nums[l] 之后，对手变成 [l+1, r] 上的「先手」。对手接下来也会取走一端：取 nums[l+1]，当前玩家就落在 [l+2, r] 上重新当先手，得 f(l+2, r)；取 nums[r]，当前玩家落在 [l+1, r−1] 上，得 f(l+1, r−1)。对手想让当前玩家拿得少，所以这两个里 取小的。这一支能拿到 nums[l] + min(f(l+2, r), f(l+1, r−1))。

取 nums[r] 对称，能拿到 nums[r] + min(f(l+1, r−1), f(l, r−2))。两支持大的，就是当前玩家的最优。

夹在中间的那个 min 是这道题的分界线。写成 max 就等于假设对手也在帮自己，随机数据上约 17% 的数组会算错，而且这个比例跟数值范围几乎无关（V=2 → 16.73%，V=106 → 17.65%）。

// nums[l..r] 上继续玩，轮到先手；返回先手最后拿到的总分
    // 两人都绝顶聪明
    int f(vector<int>& nums, int l, int r) {
        if (l == r) return nums[l];
        if (l == r - 1) return max(nums[l], nums[r]);
        int p1 = nums[l] + min(f(nums, l + 2, r), f(nums, l + 1, r - 1));
        int p2 = nums[r] + min(f(nums, l + 1, r - 1), f(nums, l, r - 2));
        return max(p1, p2);
    }

    bool predictTheWinner(vector<int>& nums) {
        long long sum = 0;
        for (int x : nums) sum += x;
        return 2LL * f(nums, 0, (int)nums.size() - 1) >= sum;
    }

铺表和上一题同形：长度 1、长度 2 的区间先填好，然后 l 倒序、r 正序。

bool predictTheWinner(vector<int>& nums) {
        int n = nums.size();
        long long sum = 0;
        for (int x : nums) sum += x;
        vector<vector<int>> dp(n, vector<int>(n, 0));
        for (int i = 0; i < n - 1; i++) {
            dp[i][i] = nums[i];                     // 长度 1
            dp[i][i + 1] = max(nums[i], nums[i + 1]);   // 长度 2
        }
        dp[n - 1][n - 1] = nums[n - 1];
        for (int l = n - 3; l >= 0; l--) {
            for (int r = l + 2; r < n; r++) {
                dp[l][r] = max(nums[l] + min(dp[l + 2][r], dp[l + 1][r - 1]),
                               nums[r] + min(dp[l + 1][r - 1], dp[l][r - 2]));
            }
        }
        return 2LL * dp[0][n - 1] >= sum;
    }

最后比的是先手分数和后手分数。取总分 sum，先手分数超过一半就赢，恰好等于一半也算赢，所以判断写 2 * first >= sum。这里的等号有实际内容：把「平局也算赢」写成严格大于，值域小的时候错得很多（V=2 → 21.76%），值域一大平局几乎不出现，错误率掉到 0（V=106 → 0.00%）。测试数据小的时候，这个错法一点都不现形。

五、长度是偶数时，这道题不用算

先把数组按下标的奇偶分成两组。长度是偶数时两组一样多，先手看到两组的总和之后，记住大的那一组，之后每一步都取对手刚取走的那一端，就能把这一组完整拿走（对手取一次，剩下的两端奇偶性相同，先手取同一边即可）。于是先手至少拿到两组里较大的那份，也就是总和不低于一半。

随机验证：长度取偶数、值域分别取 2、5、50、106，各 20000 组，先手全部赢（含平局）。值域为 2 时有 2293 组平局，值域到 106 时一组平局都没有。

长度是奇数时这个分组不成立，两组差一个元素，只能老老实实 dp。约束本身很小（n ≤ 20），两种写法都够快；记住这条结论是为了在读完题时就知道答案必为 true。

六、复杂度分析

量规模说明
状态数O(n²)只有 l ≤ r 的一半，约 n²/2 个
单格代价O(1)两道题每格都只看常数个格子
时间O(n²)铺表两重循环
空间O(n²) → O(n)二维表 n² 个 int；压缩后只留一行
暴力O(2n)回文插入 2n−1−1 次；预测赢家约 2n/3 次

两道题的空间压缩都只把最外层那一维砍掉，代价是依赖方向必须能对上：这一页的两个 dp 都只往「更短的区间」看，所以压缩之后用变量补住斜角那一格就够。

七、总结

这一页要带走三件事：

  1. 参数换成一段区间的左右端点之后，循环顺序固定是 l 倒序、r 正序，保证区间长度单调增长。
  2. 两端点讨论型的状态只派生 l+1、r−1 附近的短区间，转移里那个 min 或 max 由「谁在选」决定，不是随手写的。
  3. 二维 dp 压缩时，能覆盖的邻居照旧读一维数组，斜角那个格子用一个变量接力带过来。

下一类是划分点型：不再只盯两端，而是在区间里枚举一个 m，把区间切开。
