环形最大子数组与子矩阵最大累加和

上一页那张「以 i 结尾」的 dp 表，换两个容器照样能用。把数组首尾接起来，答案就可能绕过接口，多出一种形态；把二维数组按行区间压扁，每一对上下边界都退化成一次一维问题。两题都只用到一个结论：以 i 结尾的最大（最小）子数组能一次扫出来。

零、环形数组：答案多了第二种形态

下标 0 和 n − 1 连在一起之后，子数组可以跨过接口。跨接口的那段子数组，剩下没选中的元素恰好也是一段连续区间：一段「不跨接口的最小子数组」。

于是环形答案只在两种形态里挑大的：

答案 = max(不跨接口的最大子数组, 全部元素之和 − 不跨接口的最小子数组)

第二种形态什么时候真的赢？实测（值域 −9 到 12 的随机数组）：n = 5 时 31.04% 的样本要靠绕过去才能拿到最大值，n = 10 时 49.99%，n = 20 时 61.49%，n = 50 时 74.52%。数组越长，绕过去越占便宜。

两种形态一次循环就能同时算出来：维护 maxpre / maxsum 的同时，把同样的式子取 min 跑一遍。

#include <bits/stdc++.h>
    using namespace std;

    int maxSubarraySumCircular(const vector<int>& nums) {
        int n = (int)nums.size();
        int all = nums[0], maxsum = nums[0], minsum = nums[0];
        for (int i = 1, maxpre = nums[0], minpre = nums[0]; i < n; i++) {
            all += nums[i];
            maxpre = max(nums[i], nums[i] + maxpre);   // 以 i 结尾的最大子数组
            maxsum = max(maxsum, maxpre);
            minpre = min(nums[i], nums[i] + minpre);   // 以 i 结尾的最小子数组
            minsum = min(minsum, minpre);
        }
        // 环形答案 = max(不跨接口的最大子数组, all - 最小子数组)
        // all == minsum 说明整个数组都是最小子数组，减完剩空数组，此时只能取 maxsum
        return all == minsum ? maxsum : max(maxsum, all - minsum);
    }

一、退化情形：减完剩个空数组

这行代码里藏着一个坑：all == minsum 的判断。

拿 [-3, -2, -3] 看：全部元素之和是 −8，最小子数组也是整个数组（−8）。all − minsum = 0，对应的是「一个元素都不选」。可题面要求子数组非空，正确答案是 −2。

整个数组自己就是最小子数组，当且仅当所有元素都拴在一条负链上，这种情况减完一定是空集。所以一旦 all == minsum，只能退回 maxsum。

实测两组错法（20000 组随机，值域 −9 到 12）：漏掉这个判断错 7.77%，恰好等于随机数据里全负数组的占比 7.76%，出错的样本就是它们；只算 all − minsum 的错得多，37.09%。

演示：maxsum 与 minsum 同步推进

二、子矩阵：把一段行压成一行

二维版本问的是：选一个矩形区域，让里面所有数之和最大。暴力枚举上下左右四个边界是 O(n²m²)，就算拿前缀和把每个矩形的求和降到 O(1)，矩形个数本身也是 n²m² 个。

换个想法：先枚举矩形的上边界 up 和下边界 down。这两条边界之间夹着的若干行，可以按列求和压成一个一维数组 nums：nums[j] 就是 up..down 这些行在第 j 列的累加和。在这条压出来的数组上找「和最大的一段」，就是上一页那个带左右端点的附加问题。

压行有个讲究：枚举 up 从 0 到 n − 1，down 从 up 往下走时，nums[j] += grid[down][j] 只做累加；可一旦换 up，nums 必须清零重来。漏掉清零，上一组行的影响全留在里面，实测 58.33% 的随机矩阵答案直接错。还有一处顺序：先把 nums[r] 加上 grid[down][r]，再去更新 pre；反过来写的话，每一列都用的是「上一行加完」的旧值，错误率 67.60%。

#include <bits/stdc++.h>
    using namespace std;

    struct Rect { int up, left, down, right, sum; };

    Rect getMaxMatrix(const vector<vector<int>>& grid) {
        int n = (int)grid.size();
        int m = (int)grid[0].size();
        int maxv = INT_MIN;
        int a = 0, b = 0, c = 0, d = 0;
        vector<int> nums(m, 0);
        for (int up = 0; up < n; up++) {
            fill(nums.begin(), nums.end(), 0);
            for (int down = up; down < n; down++) {
                // nums 存 up..down 这些行压出来的一维数组，套第一题的附加问题
                int l = 0, pre = INT_MIN;
                for (int r = 0; r < m; r++) {
                    nums[r] += grid[down][r];
                    if (pre >= 0) {
                        pre += nums[r];
                    } else {
                        pre = nums[r];
                        l = r;
                    }
                    if (pre > maxv) {
                        maxv = pre;
                        a = up; b = l; c = down; d = r;
                    }
                }
            }
        }
        return {a, b, c, d, maxv};
    }

演示：逐对上下边界压行

数一数工作量：n 行的方阵，(up, down) 对有 n (n + 1) / 2 个，每一对做一次 O(n) 的一维扫描，合计 O(n³)。实测 100×100 的随机矩阵 0.40 毫秒（暴力枚举要数 25502500 个矩形），200×200 是 3.40 毫秒，300×300 也只要 11.71 毫秒。

三、复杂度分析

问题时间额外空间
环形最大子数组O(n)O(1)
子矩阵最大累加和（n×m）O(n²m)O(m)
子矩阵最大累加和（n×n）O(n³)O(n)

空间说明：环形那题只有几个标量变量；子矩阵压行需要一个长度为列数 m 的一维数组，行区间信息全靠 up / down 两个下标，不复制任何行。

四、总结

两题是同一个套路的两次落地。环形题把「绕过接口」翻译成「全体减最小」，要多留一个心眼给空数组：all 等于 minsum 时只能取不跨接口的答案。子矩阵题把「枚举矩形」翻译成「枚举行区间加一维问题」，n 行方阵从 n⁴ 压到 n³，靠的就是压行之后直接复用「以 i 结尾」的那张表。

下一类扩展往「选不选」上走：不能选相邻元素的最大累加和，环形版本和它的二分答案变体，是另外三道常客题。
