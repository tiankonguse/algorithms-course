基数排序

排序不一定要比大小。基数排序从低位到高位，每轮按当前位的数字把元素分进几个桶，排完最高位整个数组就有序。时间 O(n·bits)，额外空间 O(n)，而且稳定。代价是它只吃「能按位拆开」的数据。

零、背景

n=100 万的随机数组，基数排序约 16ms，std::sort 约 45ms，快了快三倍。整个排序过程一次大小都没比过。

之前的归并、快排、堆排序都在干同一件事：拿两个元素比大小，按结果决定谁先谁后。基数排序换了个思路，它不问 5 和 3 谁大，只看每一位上是几，把数字按位分进桶里。

代价是挑数据。它要求样本是非负整数，还得有进制。这一讲把实现细节讲透，最后说清楚这个限制从哪来。

一、基于比较 vs 不基于比较

比较排序只需要定义好「怎么比」：给两个对象一个 < 就行，数字、字符串、结构体都能排，很通用。但它有一个绕不开的下界 O(n log n)：一次比较最多拿回 1 bit 信息，n 个元素的全排列有 n! 种，信息论上至少需要 log₂(n!) ≈ n log₂n 次比较才分得开。归并、快排、堆排序全在这个家族里。

不基于比较的排序不比较，直接看数据本身。计数排序是最直白的一个：开一个值域那么长的数组，数每个值出现几次，再按值从小到大倒出来。

计数排序快得吓人。n=100 万、值域 10 万时只要 1.5ms，比基数排序和 std::sort 都快。但它的数组长度必须顶到值域，值域 1 亿要 400MB，10 亿要 4GB，机器直接开不下。数值一大，计数排序立刻歇菜。

基数排序就是为了绕开这个问题：值域大不要紧，一次只看一位，把大值域拆成「每一位的小值域」。一位的取值只有 BASE 种，计数数组只要 BASE 长。一句话：计数排序是「值域有多宽，数组就有多长」，基数排序是「把值域按位拆开，让数组长度回到 BASE」。

二、数字提取某一位

基数排序的第一步，是能把「某一位」抠出来。给定 offset=1、10、100、…，当前位就是 (x / offset) % BASE。以 BASE=10、x=724 为例：offset=1 取到个位 4，offset=10 取到十位 2，offset=100 取到百位 7。

offset 每轮乘一次 BASE，从个位一路走到最高位。排几轮取决于最大的数有几位，Bits(max) 用一个 while 数出来：max=999 → 3 轮，max=1000 → 4 轮（进位了，谁也没法省），max=999999999 → 9 轮，max=2^31-1 → 10 轮。

// 返回 number 在 BASE 进制下有几位
    int Bits(int number) {
        int ans = 0;
        while (number > 0) {
            ans++;
            number /= BASE;
        }
        return ans;
    }

三、一轮完整流程

一轮做四件事：计数、前缀和、放置、拷回。拿 [17, 13, 25, 100, 72] 的个位轮走一遍。

计数：统计每个数字出现几次。五个数的个位是 7、3、5、0、2，cnts = [1,0,1,1,0,1,0,1,0,0]。

前缀和：把 cnts 改成累加形式，cnts[i] 变成「个位数字 ≤ i 的元素个数」，得到 [1,1,2,3,3,4,4,5,5,5]。这一步之后，cnts[i] 同时就是「数字 i 放置区间的右边界」。

放置：从后往前扫 arr，每遇到一个元素就 --cnts[digit] 拿位置。arr[4]=72 个位 2，--cnts[2]=1，72 放进 help[1]；arr[3]=100 个位 0，--cnts[0]=0，100 放进 help[0]；arr[2]=25 个位 5，--cnts[5]=3，25 放进 help[3]；arr[1]=13 个位 3，--cnts[3]=2，13 放进 help[2]；arr[0]=17 个位 7，--cnts[7]=4，17 放进 help[4]。help = [100, 72, 13, 25, 17]，按个位 0、2、3、5、7 排好了。

拷回：arr ← help，个位轮结束。高位轮重复同样四步。

为什么从后往前放？这是稳定性的关键，下一节展开。先看完整代码。

// arr 里保证没有负数；bits 是最大值在 BASE 进制下的位数
    void RadixSort(vector<int>& arr, int n, int bits) {
        for (int offset = 1; bits > 0; offset *= BASE, bits--) {
            // 1. 统计当前位每个数字出现几次
            fill(cnts.begin(), cnts.end(), 0);
            for (int i = 0; i < n; i++) {
                cnts[(arr[i] / offset) % BASE]++;
            }
            // 2. 前缀和：cnts[i] 变成「该位数字 <= i」的元素个数
            for (int i = 1; i < BASE; i++) {
                cnts[i] += cnts[i - 1];
            }
            // 3. 从后往前放，help 里当前位数字相同的部分保持原序
            for (int i = n - 1; i >= 0; i--) {
                help[--cnts[(arr[i] / offset) % BASE]] = arr[i];
            }
            // 4. 拷回 arr
            for (int i = 0; i < n; i++) {
                arr[i] = help[i];
            }
        }
    }

四、稳定性

从低位到高位（LSD）的基数排序，正确性建立在「每一轮都稳定」上。个位排完后，相同个位的元素里保持着原顺序；十位轮必须把这份「个位的顺序」原样保住，否则低位信息就丢了。一轮轮叠上去，最后整体才是「先按低位、再按高位」的字典序。

稳定靠放置方向配合。前缀和给出的是右边界，从后往前扫、每次 --cnts 递减放，同数字的元素「后出现的放得更靠后」，原顺序保持。这是课程代码的写法。

把遍历方向写成从前往后就坏了。同数字的元素会倒着放：先扫到的反而放得靠后。2000 组小值域随机数组实测，94.3% 的组顺序乱掉。排序结果还是对的（每组都按值有序），只是相等元素的相对顺序被打乱，基数排序的整体正确性也就没了。

什么时候用得上稳定？先按班级排、再按成绩排，想得到「同成绩里按班级有序」，第二趟排序必须稳定。基数排序本身就是「先按低位、再按高位」地叠稳定排序。

五、负数与其它进制

基数排序要求非负整数。C++ 的除法取模对负数不给面子：-7/10=0，(-7)%10=-7，digit 直接算成 -7，cnts[-7] 越界访问，程序当场崩。

预处理把整个数组平移成非负：所有数减去最小值，排完再加回来。min=-12 时，-12 变 0，3 变 15。排序过程只认平移后的值，相对大小没变。

const int BASE = 10;
    vector<int> help, cnts;

    void SortArray(vector<int>& arr) {
        int n = (int)arr.size();
        if (n <= 1) return;
        help.assign(n, 0);
        cnts.assign(BASE, 0);
        // 所有数减去最小值，转成非负数组
        int minv = arr[0];
        for (int i = 1; i < n; i++) minv = min(minv, arr[i]);
        int maxv = 0;
        for (int i = 0; i < n; i++) {
            arr[i] -= minv;
            maxv = max(maxv, arr[i]);
        }
        // 最大值有几位，就排几轮
        RadixSort(arr, n, Bits(maxv));
        // 还原
        for (int i = 0; i < n; i++) {
            arr[i] += minv;
        }
    }

两个细节。一是溢出：min=-2^31、数组里又有 2^31-1 时，2^31-1 - (-2^31) = 2^32-1，超出 int 上限，算出来是 -1，排序全错。题目数据保证不溢出时才能放心用 int，否则照注释改成 long。

二是全相等：max-min=0，Bits(0)=0，while 一次不进，0 轮直接结束。数组本来就有序，这轮省得合理。

BASE 可以换成任何进制，轮数与空间在 BASE 上此消彼长。max=10^9 时 BASE=2 要 30 轮，BASE=10 要 10 轮，BASE=16 只要 8 轮；但 cnts 也要跟着变长，从 8 字节到 64 字节。BASE 小轮数多、每轮便宜；BASE 大轮数少、每轮贵一点，BASE=16 的 cnts 也只有 64 字节，随便开。

六、复杂度分析

每轮扫三遍数组加一遍 cnts：n 次计数、BASE-1 次前缀、n 次放置、n 次拷回，共 3n+BASE-1 次操作，O(n+BASE)。bits 轮，总时间 O(bits·(n+BASE))。

bits = ⌊log_BASE(max)⌋ + 1。值域 10^9 时十进制 9~10 轮，所以「O(n·bits)」在 int 范围内就是大约 10n 次操作。n=10^6 时约 3000 万次，比较排序的 n log₂n 要 2000 万次比较，量级相同、常数还更小，实测也确实更快。

速度实测（g++ -O2，随机 0~10^9 数据）：n=10^4 基数约 0.2ms vs std::sort 约 0.4ms；n=10^5 约 2ms vs 5ms；n=10^6 约 16ms vs 45ms。

值域对时间的影响（n=10^6）：V=10^3 约 5ms（3 轮），V=10^6 约 9ms（6 轮），V=10^9 约 13ms（9 轮）。轮数翻三倍，时间也翻近三倍，每轮的常数是死的。

指标值说明
时间复杂度O(bits·(n+BASE))值域固定时约 O(n)，int 范围内约 10n 次操作
额外空间O(n+BASE)help 数组 n 格 + cnts 数组 BASE 格
稳定性稳定每轮从后往前放，同数字保持原序
适用范围能按位拆的对象非负整数（平移后可含负数）、固定进制

但这份快只属于「排 int」。换排序字符串、结构体，按位拆这套就使不上，得先把对象编码成整数，编码本身的代价常常比排序还贵。比较排序没有这个前置成本。基数排序是「数据特征换速度」：数据越规整，它越快；数据越自由，它越没用。

七、总结

基数排序不比较大小，按位分桶：每轮计数、前缀和、从后往前放置、拷回，四步循环。要点如下：

第一，稳定靠放置方向。前缀和给右边界，从后往前扫、递减放，同数字的原顺序才保得住；遍历方向一反过来，94% 以上的数据会乱序。

第二，负数平移处理，减最小值再还原；平移会溢出时（INT_MIN 和 INT_MAX 同现）改用 long。

第三，轮数由最大值位数决定，BASE 越大轮数越少、cnts 越大，空间时间在 BASE 上此消彼长。

第四，复杂度 O(bits·(n+BASE))，值域固定时线性，比比较排序快，但只吃「能按位拆的对象」。

基数排序之后，后缀数组、桶排序里那套「按位拆 + 稳定叠」还会反复出现，这一讲是把地基打上。
