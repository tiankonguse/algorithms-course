Morris 求最小高度与最近公共祖先

前两节的题都只要「到达时顺手记一笔」。这两道要维护跨节点的信息：最小高度得自己在 Morris 里把层数造出来，最近公共祖先得一路把候选往上抬。两道都能做到 O(1) 额外空间，代价是代码绕得多一些，LCA 那道还要多跑十几趟遍历。

零、背景

递归写法里，层数、路径、父节点这些信息要么在函数参数里，要么在系统栈里，伸手就能拿到。Morris 遍历把这些全拿走了，只剩一个 cur 指针在树上跳。想回答跟「深度」或「祖先」有关的问题，就得自己想办法把信息重新造出来。

下面两道题正好代表两种造法：一种是跟着走的变量，一种是往上抬的候选。

一、最小高度：自己造一个层数

最小高度是根到最近叶子的节点数。递归版把深度当参数往下传，到叶子就更新答案。Morris 里没有这个参数，用一个整型变量跟着走就够。

记 preLevel 为「上一个被到达的节点」所在的层数。这个不变量要卡准：进循环时它等于 level(cur) − 1，往左或往右走一层就 preLevel++。第二次到达是个例外，那时上一个被到达的节点是 mostRight，所以 preLevel 等于 level(mostRight)，而 level(mostRight) = level(cur) + rightLen，rightLen 就是 cur 左子树右边界上的节点数。

叶子判定落在 mostRight 身上。mostRight 是 cur 左子树的最右节点，它一定没有右孩子；再看它有没有左孩子，就知道它是不是叶子。是叶子就用 preLevel 去更新答案，因为此刻 preLevel 正好是它的层数。

// 最小高度 = 根到最近叶子的节点数
    // preLevel 是「上一个被到达的节点」所在的层数，进循环时等于 level(cur) - 1
    int minDepth(TreeNode* head) {
        if (head == nullptr) {
            return 0;
        }
        TreeNode* cur = head;
        TreeNode* mostRight = nullptr;
        int preLevel = 0;
        int rightLen;                                   // cur 左子树右边界上有几个节点
        int ans = INT_MAX;
        while (cur != nullptr) {
            mostRight = cur->left;
            if (mostRight != nullptr) {
                rightLen = 1;
                while (mostRight->right != nullptr && mostRight->right != cur) {
                    rightLen++;
                    mostRight = mostRight->right;
                }
                if (mostRight->right == nullptr) {      // 第一次到达，往左下一层
                    preLevel++;
                    mostRight->right = cur;
                    cur = cur->left;
                    continue;
                } else {                                // 第二次到达，刚从左树爬回来
                    // mostRight 是左树最右节点，它没有右孩子；再看有没有左孩子就知道是不是叶子
                    if (mostRight->left == nullptr) {
                        ans = min(ans, preLevel);
                    }
                    preLevel -= rightLen;               // 从 mostRight 退回 cur 的层数
                    mostRight->right = nullptr;
                }
            } else {
                preLevel++;                             // 往右下一层
            }
            cur = cur->right;
        }
        // 整棵树的最右路径是最后一条没被处理过的右边界
        rightLen = 1;
        cur = head;
        while (cur->right != nullptr) {
            rightLen++;
            cur = cur->right;
        }
        if (cur->left == nullptr) {                     // 最右节点是叶子才纳入统计
            ans = min(ans, rightLen);
        }
        return ans;
    }

收尾那段不能漏。整棵树的最右路径不属于任何节点的左子树，没有第二次到达来触发它，只能循环结束后单独走一遍。实测漏掉这段会怎样：2 万组随机小树（n 取 1 到 9）里只有 36.05% 对不上，因为最右路径常常不是最短的那条，漏了也蒙对。

另外两个错法更狠。preLevel -= rightLen 少减 1，层数就一路偏高，抓取率 72.84%。漏掉 mostRight->left == nullptr 这个判断，等于把「左子树是一条右链」的非叶子也当叶子统计，抓取率 82.03%。

二、最近公共祖先：把候选往上抬

先序里 o1 和 o2 谁先出现，记为 left。如果它俩有祖先关系，答案直接就是那个祖先，先判掉。

剩下的是分叉的情形。Morris 主循环里第二次到达 cur 时，说明 cur 的左子树刚走完。这时候看 left 在不在 cur 左子树的右边界上：在，说明 left 那一支已经走到头了，该往上抬了。

抬之前先确认一件事：left 的右子树里有没有另一个目标。有，说明两个目标分别落在 left 的左子树和右子树里，left 就是分叉点，答案定下来；没有，left 只是这一支的末端，把它抬成 cur 继续往上找。

这里有个细节：检查的是 left->right 而不是 cur->right。cur 的右子树还没走，里面某些右指针可能正处在被借用的状态，这时候进去查会出错。left 的右子树已经走完，指针都是干净的。

// left 是 o1、o2 里先序更靠前的那个，一路往上抬，最后还站着的那个就是答案
    TreeNode* lowestCommonAncestor(TreeNode* head, TreeNode* o1, TreeNode* o2) {
        // 谁是谁的祖先，直接返回
        if (preOrderFind(o1->left, o1, o2) != nullptr || preOrderFind(o1->right, o1, o2) != nullptr) {
            return o1;
        }
        if (preOrderFind(o2->left, o1, o2) != nullptr || preOrderFind(o2->right, o1, o2) != nullptr) {
            return o2;
        }
        TreeNode* left = preOrderFind(head, o1, o2);
        TreeNode* cur = head;
        TreeNode* mostRight = nullptr;
        TreeNode* lca = nullptr;
        while (cur != nullptr) {
            mostRight = cur->left;
            if (mostRight != nullptr) {
                while (mostRight->right != nullptr && mostRight->right != cur) {
                    mostRight = mostRight->right;
                }
                if (mostRight->right == nullptr) {
                    mostRight->right = cur;
                    cur = cur->left;
                    continue;
                } else {                                // 第二次来到 cur
                    mostRight->right = nullptr;
                    if (lca == nullptr) {
                        // left 站在 cur 左树的右边界上，说明它那一支已经走到头了
                        if (rightCheck(cur->left, left)) {
                            // 另一个目标在 left 的右树里，left 就是分叉点
                            if (preOrderFind(left->right, o1, o2) != nullptr) {
                                lca = left;
                            }
                            left = cur;                 // 把候选抬到 cur
                            // 这里查的是 left 不是 cur：cur 右树上的右指针可能还没还原
                        }
                    }
                }
            }
            cur = cur->right;
        }
        return lca != nullptr ? lca : left;             // 走完还没定，left 一定是答案
    }

    // 以 head 为头的树做先序，o1 和 o2 谁先撞上就返回谁
    TreeNode* preOrderFind(TreeNode* head, TreeNode* o1, TreeNode* o2) {
        TreeNode* cur = head;
        TreeNode* mostRight = nullptr;
        TreeNode* ans = nullptr;
        while (cur != nullptr) {
            mostRight = cur->left;
            if (mostRight != nullptr) {
                while (mostRight->right != nullptr && mostRight->right != cur) {
                    mostRight = mostRight->right;
                }
                if (mostRight->right == nullptr) {
                    if (ans == nullptr && (cur == o1 || cur == o2)) {
                        ans = cur;
                    }
                    mostRight->right = cur;
                    cur = cur->left;
                    continue;
                } else {
                    mostRight->right = nullptr;
                }
            } else {
                if (ans == nullptr && (cur == o1 || cur == o2)) {
                    ans = cur;
                }
            }
            cur = cur->right;
        }
        return ans;
    }

    // 顺着右指针走一条右边界，看 target 在不在上面
    bool rightCheck(TreeNode* head, TreeNode* target) {
        while (head != nullptr) {
            if (head == target) {
                return true;
            }
            head = head->right;
        }
        return false;
    }

循环结束时 lca 可能还是空，这不要紧，此时 left 一定就是答案：它能一路被抬到根而始终没在右子树里撞上另一个目标，说明两个目标都在它的子树里且它是最低的那一个。

代价要说清楚。每次检查 left->right 都要跑一趟完整的 Morris 先序，一趟是 O(n)。实测随机树 n = 10⁵ 上平均要跑 14.24 趟，n = 2×10⁴ 的 300 对里最多 21 趟、最少 1 趟；完全二叉树上平均 11.83 趟，左偏链上平均 2.04 趟（链上两个点总有祖先关系，开头就判掉了）。

于是单次查询的耗时是递归版的三倍多：n = 10⁵ 的随机树上 Morris 版 2.55ms、递归版 0.85ms；n = 10⁶ 上 62.48ms 对 17.80ms。这道 Morris 版 LCA 的价值全在 O(1) 的空间上，时间上它是吃亏的。

复杂度分析

算法时间额外空间说明
Morris 求最小高度O(n)O(1)只多 preLevel、rightLen、ans 三个变量
Morris 求最近公共祖先O(n) × 检查次数O(1)每次检查是一趟完整 Morris 先序，实测十几趟
递归求最小高度 / LCAO(n)O(h)系统栈，链上 n 层会崩

最小高度的时间是标准的 O(n)：一趟 Morris 遍历 O(n)，加上收尾时顺着最右路径走一遍，也是 O(n)。

LCA 那栏写成「O(n) 乘检查次数」，是因为 preOrderFind 每次调用都从头走一遍 Morris 先序。检查次数跟树的形状和两个目标的位置有关，随机树上稳定在十几趟，不是 n 级别的量，但也没有一个好看的常数上界。真要卡时间，这道题该用递归版。

空间上两道都是严格的 O(1)。最小高度多三个整型变量，LCA 多 left、lca 两个指针和一个 bool，都不随 n 或树高变化。

总结

Morris 遍历拿走了递归参数和栈，要用它解跟深度、祖先有关的题，就得把信息自己造出来。最小高度造的是一个跟着走的层数，LCA 造的是一个往上抬的候选。

要点列一下：preLevel 进循环时等于 level(cur) − 1，第二次到达时等于 level(mostRight)，退回 cur 要减 rightLen；叶子判定看 mostRight 有没有左孩子；整棵树的最右路径没有第二次到达触发，收尾必须单独走一遍。LCA 那边，left 是先序里更靠前的目标，第二次到达且它站在 cur 左树的右边界上时，先查它的右树再决定抬不抬。

这两道做完，Morris 遍历能覆盖的范围就清楚了：信息能在两次到达之内凑齐的题它能做，必须回到一个节点三次的做不了，勉强能做但要多跑十几趟的就要掂量一下时间。选它之前先想清楚自己缺的到底是空间还是时间。
