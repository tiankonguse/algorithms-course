布隆过滤器：位数组回答「在不在」

要把 100 亿条数据放进一个判重系统，原样存下来要 1 TB。布隆过滤器只开一个位数组，用几个哈希位置当指纹，把失误率压到万分之一，代价是它只会认错、不会漏掉，而且删不掉元素。这一页把结构、公式和实测都过一遍。

零、1 TB 的数据压成 24 GB

100 亿条数据，每条 100 字节，原样存下来是 1TB。布隆过滤器给出的方案是：开一个 1917 亿 bit 的位数组，也就是 23.96 GB，再准备 13 个哈希函数，就能回答「某条数据在不在这个集合里」，失误率 1.0013×10-4。

省下来的空间是数量级的。代价也很明确：它会时不时把一条从没插过的数据判成「在集合里」。

一、位数组加 k 个哈希位置

结构就两样东西：一个长度 m 的位数组，初始全是 0；以及 k 个哈希函数，每个都把样本映射到 0 到 m−1 之间的一个位置。

插入时对样本算 k 个位置，全置 1。查询时算同样 k 个位置，只要有一个是 0，说明这个样本一定没插过；全是 1，才判成「在集合里」。

// 位数组 + k 个哈希位置，插入置 1，查询全是 1 就判「在」
    struct Bloom {
        vector<u64> bits; size_t m; int k;
        Bloom(size_t m_, int k_) : bits((m_ + 63) / 64, 0), m(m_), k(k_) {}

        void add(const string& s) {
            u64 h1 = md5_64(s), h2 = md5_64(s + "#salt") | 1ull;
            for (int i = 0; i < k; i++) {
                size_t p = (h1 + (u64)i * h2) % m;   // 两个哈希凑出 k 个位置
                bits[p >> 6] |= 1ull << (p & 63);
            }
        }

        bool query(const string& s) const {
            u64 h1 = md5_64(s), h2 = md5_64(s + "#salt") | 1ull;
            for (int i = 0; i < k; i++) {
                size_t p = (h1 + (u64)i * h2) % m;
                if (!((bits[p >> 6] >> (p & 63)) & 1)) return false;
            }
            return true;   // 全 1 只能说「可能在」
        }
    };

实现里不一定要真的写 k 个哈希函数。两个独立的哈希值 h1、h2 足够凑出 k 个位置：第 i 个位置取 h1 + i×h2 对 m 取余，只要 h2 是奇数，这些位置基本不会重复。

二、失误只有一种方向

查询会出两种偏差，布隆过滤器只占一种。

假阴性，也就是「插过却查不到」，不会发生。插入时把它的 k 个位置全置了 1，而位数组只会从 0 变 1，不会从 1 变回 0，所以这几个位置永远是 1，查询一定会命中。

假阳性，也就是「没插过却说在集合里」，会发生。这个样本的 k 个位置恰好都被别的样本置成了 1，它就冒充成功。位数组塞得越满，这种巧合越容易发生。

三、由 n 和 p 反推 m 与 k

工程上真正要回答的问题是：给定样本数 n 和目标失误率 p，位数组要开多大、哈希函数要配几个。三行公式就能算出来。

// 三个公式：由样本数 n 和目标失误率 p 反推位数组长度 m 与哈希个数 k
    long double L2 = logl(2.0L);
    long double m = -n * logl(p) / (L2 * L2);      // 需要多少个 bit
    int k = (int)floorl((m / n) * L2 + 0.5L);      // 需要几个哈希函数
    long double ptrue = powl(1.0L - expl(-n * k / m), k);   // 真实失误率

第一条公式来自「位数组里 1 的比例正好让每个位置的碰撞概率降到最低」，第二条公式是在这个最佳比例下解出哈希个数。第三条公式是把取整之后的 m 与 k 代回去，得到真实失误率。取整总会让真实值比目标略差一点，所以第三步要用扩大之后的 m 重算一次。

看第一行：100 亿条数据、失误率万分之一，占 23.96 GB。同样的失误率再要一个数量级，空间直接跳到 29.95 GB。失误率每降一个数量级，位数组长大致乘以 log 的变化倍数，这个账要提前算清楚，别等系统上线才发现内存不够。

另一个容易被忽略的点：公式里只出现样本数 n 和目标失误率 p，没有样本长度。1 亿条 100 字节的 URL 和 1 亿条 10 字节的串，用到的位数组一样大。样本长度只在算哈希时影响时间，不影响空间。

四、k 取多少最好

k 太小，每个样本占的位置少、容易被人冒充；k 太大，位数组被置 1 的速度变快、每一步反而更容易撞上。存在一个最优值，就是上面第二条公式给出的 (m/n)·ln2。

固定 n = 106、m = 9585058（按 p = 1% 算出来的），把 k 从 1 扫到 20：

五、实测对得上公式

公式是不是准，跑一遍就知道。取 n = 106、p = 1%，公式给出 m = 9585058 bit（1.20 MB）、k = 7。插入 100 万个样本，再用 1000 万个没插过的样本去查：

布隆过滤器实验台

位数组按顺序铺开，深色格子是 1。逐条插入样本看它点亮哪些位置，再挑一个没插过的串查询，看 k 个位置是不是全被点亮。

六、用不了的几件事

布隆过滤器只能回答「在不在」，不能把元素取出来，也不能返回元素个数。它整张位数组里存的只是指纹，原始数据一个字节都没留。

也不能删元素。把某个元素的 k 个位置清成 0，会连带影响其他元素：那些位置可能是别的样本置的，清掉就让对方变成了假阴性，而假阴性是自己承诺过不会出现的。要支持删除就得换成计数版本，每个位置用一个计数器代替 1 个 bit，空间立刻涨几十倍。

用之前还要接受一件事：它的失误率是你自己选的，选错了没得挽回。位数组一旦开好，样本数超过 n 之后失误率会沿着公式往上爬。所以拿它做黑名单、爬虫去重这类系统时，n 一般按未来几年的最大规模估，宁可开大一点。

复杂度分析

操作时间空间
插入一个样本O(k)，k 个哈希 + k 次置位O(1) 额外
查询一个样本O(k)O(1) 额外
整个结构—O(m) bit，与样本长度无关
n 个样本、目标失误率 p 需要的位数—m = −n·ln p / (ln2)2，约 1.44·n·log₂(1/p) bit

算哈希本身是 O(样本长度)，位数组的访问是常数次。所以布隆过滤器一次查询的代价比哈希表还低，空间更是低一个数量级，差距全在「允许偶尔认错」这一条上。

总结

布隆过滤器用一个位数组和 k 个哈希位置回答「在不在」。插入时把 k 个位置置 1，查询时只要有一个是 0 就判「不在」。位数组只会从 0 变 1，所以假阴性不会出现；假阳性会，它就是把「k 个位置恰好都被别人占了」误读成「这个样本在集合里」。

参数由三个公式定：m = −n·ln p / (ln2)2，k = (m/n)·ln2，再把取整后的 m、k 代回去算真实失误率。100 亿条、失误率万分之一需要 1917 亿 bit，也就是 23.96 GB，配 13 个哈希函数；失误率再降一个数量级，空间涨到 29.95 GB。位数与样本长度无关，只与样本个数和失误率有关。

实测 n = 106、p = 1% 时位数组 1.20 MB、k = 7，插入 100 万个样本后查 1000 万次，假阴性 0、实测失误率 1.0076%，与公式的 1.0039% 基本重合。固定 m 扫 k，失误率是 U 形曲线，最低点落在公式给出的位置上。它不能删元素、不能取回数据，这两条在选型时就要接受。
