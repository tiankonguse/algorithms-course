根据数据量猜解法

题目给的数据范围不是摆设。把复杂度代进去算出操作次数，和 1 秒能做的次数一比，方法行不行当场就有答案。范围写成 n ≤ 10，通常就是在明着说：把顺序全试一遍。

零、背景

一场笔试通常给 1 到 2 秒。这段时间里 C++ 能做多少次「基本操作」？经验值是 1e7 到 1e8，其他语言同量级。这个数字换台机器也差不了多少。

先看本机实测的三个微内核（g++ -O2）：依赖链上的乘加 1e9 次花 781ms，数组读加比较加分支 1e9 次花 340ms，取模 1e9 次花 893ms。三个都在 1e9 上下，比 1e8 高出一个量级。

别急着把预算改成 1e9。再看几个真正在跑的算法：std::sort 每秒完成 4.6e8 次比较，枚举全排列每秒 5e8 个，后面那道技能题的搜索每秒走 3.2e8 个节点。真实算法每走一步都要访存、比大小、写回数组，常数是微内核的几倍到几十倍。再加上比赛评测机比本机慢两三倍是常事，1e8 这个口径正好把这些都兜住。

一、折成操作次数

复杂度说的是「操作次数关于入参规模的函数」。把规模代进去，得到的就是操作次数。用之前要确认两件事。

1）题目得给入参范围。正式笔试和比赛一定会给，面试里要主动跟面试官确认，别自己猜。

2）对自己的复杂度得估准。「大概是 O(n log n)」不够用，要能写出确切的式子，包括内层循环跑几次、常数有多大。

举个例子。入参 n ≤ 1e5，你想用 O(n²) 的做法，操作次数就是 1e5 × 1e5 = 1e10，预算 1e8，超了 100 倍。这一眼就能看出来要换方法，不用等写完再收一个超时。

读法很直接：n 那一栏划到哪一行，那一行往右还打勾的复杂度就是候选。n ≤ 25 出现在题目里，别想别的，先算 2^n；n ≤ 5000 就去看 n²；n ≤ 1e5 去看 n√n；n ≤ 1e6 去看 n log n。

表里每一行其实都对应一笔差不多的操作预算。11! = 3.99e7，2^25 = 3.36e7，5000² = 2.5e7，1e5 × 316 = 3.16e7，1e6 × 19.9 = 1.99e7。全都落在 2.5e7 到 4e7 之间，也就是 1e8 的三分之一左右。剩下那三分之二就是留给常数和慢机器的。

三、表只能当参考

第一个原因是多入参。表按单个 n 画，实战里常常是 O(n·m)、O(n+m)、O(n·k)。一棵 1e3 个点的树做 n² 的树型 dp 是 1e6 次，很轻松；两个长度 1e5 的数组求交集，排个序再扫一遍是 3.4e6 次，也很轻松。真正要算的是所有入参乘起来之后落在哪个量级。

第二个原因是每一步的价钱不一样。同样叫「一次操作」，排序里的一次比较每秒能走 4.6e8 次，取模每秒 1.12e9 次，链表跳一步和数组读一格又差好几倍。同样是 1e7 次操作，落在这三种内核上耗时能差十倍。

所以这张表正确的用法是给个方向：先按复杂度估出操作次数，再乘一个自己掂量过的常数，最后跟 1e8 比。反过来，用它去卡「n 到底能不能到 1e5、1e6」意义不大，差一档的量级本来就在误差里。

四、n ≤ 10 在说什么

来看一道题。你有 n 个技能打一只怪，每个技能最多放一次。i 号技能的伤害是 x[i]；当怪兽剩余血量不高于 y[i] 时，这个技能打双倍伤害。已知怪兽有 m 点血，问最少用几个技能能把它打死（血量降到 0 以下）。范围：n ≤ 10，m、x[i]、y[i] ≤ 1e6。

n ≤ 10 就是全部的信号。10! 是 3,628,800，把释放顺序全部试一遍在 1e8 以内，正好卡在预算里面。看到这个范围还去推贪心或者 dp，属于跟出题人对赌。

这里有个细节：搜索的对象是顺序，不能换成集合。技能打多少伤害，取决于「放它的时候怪兽还剩多少血」，所以同一组技能换个顺序，结局会不一样。

m = 112，三个技能分别是 s1 伤害 24 / 双倍阈值 101、s2 伤害 11 / 阈值 18、s3 伤害 73 / 阈值 24。s3 先手：112 − 73 = 39，39 ≤ 101，s1 打双倍 48，怪兽倒地，两个技能解决。换 s1 先手：112 − 24 = 88，88 > 18，s2 只打 11 剩 77，77 > 24，s3 打 73 剩 4。三个技能用完，怪兽还在。

搜索的写法是 f(i, r)：已经放了 i 个技能、怪兽还剩 r 点血，返回最少还要几个技能。枚举第 i 个位置放谁——把 j 号技能换到 i 位置，递归，回来再换回去试下一个，就是最普通的 swap 回溯。剪枝极简单：r ≤ 0 直接返回 i。

节点数的实测和表里对得上。最坏情况（所有技能加起来也打不死）n = 10 要走 9,864,101 个节点，正好约等于 e·10!；n = 11 涨到 108,505,112 个节点、331ms；n = 12 是 1.3e9 个节点、3.96s。n ≤ 11 能过、n = 12 会超，这就是表里 n! 那一行说的意思。

五、代码

搜索函数和输入部分分开写。技能数量最多 10 个，伤害和阈值各开 11 长度的数组就够。

int n;                    // 技能数
    int dmg[11];              // dmg[i]：i 号技能的伤害
    int thr[11];              // thr[i]：怪兽血量降到 thr[i] 及以下时，这个技能打双倍

    // 已经放了 i 个技能、怪兽还剩 r 点血，返回把怪打死最少还要几个技能
    int f(int i, int r) {
        if (r <= 0) return i;              // 打死了，一共用了 i 个
        if (i == n) return INT_MAX;        // 技能放完还没死，这条路无效
        int ans = INT_MAX;
        for (int j = i; j < n; j++) {      // 把 j 号技能换到第 i 个位置试一遍
            swap(dmg[i], dmg[j]);
            swap(thr[i], thr[j]);
            int hit = (r > thr[i]) ? dmg[i] : dmg[i] * 2;
            ans = min(ans, f(i + 1, r - hit));
            swap(dmg[i], dmg[j]);          // 换回来，再试下一个
            swap(thr[i], thr[j]);
        }
        return ans;
    }
int main() {
        int t;
        scanf("%d", &t);
        while (t--) {
            int m;
            scanf("%d %d", &n, &m);
            for (int i = 0; i < n; i++) scanf("%d %d", &dmg[i], &thr[i]);
            int ans = f(0, m);
            printf("%d\n", ans == INT_MAX ? -1 : ans);
        }
        return 0;
    }

六、总结

要点列一下。

1 秒的预算取 1e8 次基本操作。真实算法实测在 3e8 到 5e8 之间，微内核能到 1e9 以上，1e8 是留着给慢评测机的保守值。

那张规模表每一行都对应 2.5e7 到 4e7 次操作，约等于预算的三分之一。本机实测能多跑 12 到 64 倍，余量就是这个来源。

表按单个 n 画，多入参的题要自己乘起来算；每一步的价钱也不一样，先算次数再乘常数。

范围提示很直白：n ≤ 10 想阶乘枚举，n ≤ 25 想 2^n，n ≤ 5000 想 n²，n ≤ 1e5 想 n√n，n ≤ 1e6 想 n log n。

下一讲顺着这个思路，看一道范围大到 1e18、却依然能枚举的题——能枚举的原因不在范围本身，在于满足条件的数非常稀疏。
