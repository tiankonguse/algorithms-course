尝试方式与状态压缩

DP 的两笔关键改动：摆盘子按末尾两盘分情况，把 2^n 级的枚举压成线性递推，n 到 5e8 再上矩阵快速幂；过河把上亿的坐标轴压到一万以内，O(n·t) 变 9 万次转移。

零、背景

这两题都来自同一个小专题：怎么试，和状态里存什么。摆盘子示范「尝试方式」：按末尾两盘是否相同分情况，而不是按盘子颜色枚举；过河示范「状态压缩」：坐标轴上没石头的长段不用一格一格存。

一、问题：摆盘子

有 n 个盘子、k 道菜，任意相邻最多两个盘子相同。问有多少种摆法，答案对 1e9 + 7 取模。n 可以到 5e8，k 小。

直接枚举盘子的颜色是 k^n 种，摆不下。这题的入口是末尾两盘的关系：相同，或者不同。只有这两种，各自的计数都能从前面的结果里接出来。

二、末尾两盘分情况

先加一把锁：固定一道菜 X，要求第 1 个盘子不许用 X，记 f(i) 为这种约束下摆 i 个盘子的方法数。按末尾两盘分情况：

1）末两盘不同：去掉最后一盘，剩下 i−1 个盘子的合法排列，f(i−1) 种；最后一盘要和它左边那盘不同，k−1 道菜可选。

2）末两盘相同：这两盘要合起来和再左边那盘不同，去掉这两盘，剩下 i−2 个盘子的合法排列，f(i−2) 种；这两盘共享一道菜，k−1 道菜可选。

所以 f(i) = (f(i−1) + f(i−2)) · (k−1)，f(0) = 1，f(1) = k−1。k = 3 时 f 的前 9 项：1 2 6 16 44 120 328 896 2448。

解锁：对任意一道菜 X，合法的 n 盘排列里第 1 盘恰好是 X 的占 1/k（对称性），所以原题答案 n = 1 时是 k，n ≥ 2 时是 (f(n−1) + f(n−2)) · k。

摆盘子：f 序列与答案
n = 12

「下一步」把 f 从 0 推到当前 n。柱子是 f(0..i)，信息行给出第 i 步的 f(i) 和原题答案 dp(i)。

// 摆盘子：按末尾两个盘子分情况
    // f(i) 表示「第一个盘子不许用某一道菜」时，摆 i 个盘子的方法数
    // 末尾两盘相同 → 去掉两个，新末尾 i-2 不能等于新末尾 i-3 已经保证；
    // 末尾两盘不同 → 去掉一个。两种情况新末尾都有 k-1 种菜可选
    const long long MOD = 1000000007;
    long long f[MAXN];

    long long platesLinear(int n, int k) {
        f[0] = 1;
        f[1] = k - 1;
        for (int i = 2; i <= n; i++) {
            f[i] = (f[i - 1] + f[i - 2]) * (k - 1) % MOD;
        }
        if (n == 1) {
            return k;
        }
        return (f[n - 1] + f[n - 2]) * k % MOD;
    }

三、n 到 5e8：矩阵快速幂

f 的递推是二阶线性常系数，写成矩阵：向量 [f(i), f(i+1)] 乘 base = [[0, s], [1, s]]（s = k−1）得到 [f(i+1), f(i+2)]。初始 [f(0), f(1)] = [1, s]，乘 base 的 n−2 次方就得到 [f(n−2), f(n−1)]。

n = 5e8 时指数 n−2 = 499999998，二进制 29 位，快速幂循环 29 次。实测 k = 3、n = 5e8 答案是 458968814，k = 2 是 440242810，线性版和矩阵版对拍 n ≤ 20 完全一致。

k = 2 时 s = 1，f 就是斐波那契：1 1 2 3 5 8 13 21 34，一个自然对照。

// 摆盘子：n 到 5e8 时 O(n) 跑不动，把递推写成矩阵再快速幂
    // [f(i), f(i+1)] * [[0, s], [1, s]] = [f(i+1), f(i+2)]，s = k - 1
    // 指数 n-2 有 29 位，矩阵平方 29 次，log n 搞定
    const long long MOD = 1000000007;

    long long platesMatrix(int n, int k) {
        long long s = k - 1;
        long long base[2][2] = {{0, s}, {1, s}};
        long long res[2][2] = {{1, 0}, {0, 1}};
        int e = n - 2;
        while (e > 0) {
            if (e & 1) {
                long long t[2][2] = {};
                for (int i = 0; i < 2; i++)
                    for (int j = 0; j < 2; j++)
                        for (int c = 0; c < 2; c++)
                            t[i][j] = (t[i][j] + res[i][c] * base[c][j]) % MOD;
                memcpy(res, t, sizeof(t));
            }
            long long t[2][2] = {};
            for (int i = 0; i < 2; i++)
                for (int j = 0; j < 2; j++)
                    for (int c = 0; c < 2; c++)
                        t[i][j] = (t[i][j] + base[i][c] * base[c][j]) % MOD;
            memcpy(base, t, sizeof(t));
            e >>= 1;
        }
        // 初始向量 [f(0), f(1)] = [1, k-1]，乘完是 [f(n-2), f(n-1)]
        long long a = (res[0][0] + s * res[1][0]) % MOD;
        long long b = (res[0][1] + s * res[1][1]) % MOD;
        if (n == 1) {
            return k;
        }
        return (a + b) * k % MOD;
    }

四、问题：过河

桥从 0 到 n，n 最大 1e7，桥上最多 100 个石子。青蛙一次能跳 [s, t] 的任意距离，踩到石子代价 +1，从 0 出发，可以落在任何位置，求到桥对岸的最小踩石子数。

直接 dp：dp[i] = min(dp[i−t..i−s]) + 踩没踩石子。O(n·t)，n = 1e7、t = 10 就是 1e8 次转移，dp 数组要开 1e7 个 int，时间空间都悬。

五、坐标压缩：safe = 90

石子只有 100 个，问题卡在石头之间的大空白段。s < t 时，空白段足够长之后，落脚位置的可达图案就稳定了：只要有一段连续 t 个位置全部可达，之后每个位置都能从它前面 t 个里挑一个跳过来，图案整体平移，dp 值也跟着平移。

所以两枚石子间距超过某个 safe 就压成 safe。安全上界由最大跳距组合决定：跳距 (s, t) = (9, 10) 时，最大不可达位置是弗罗贝尼乌斯数 9×10 − 9 − 10 = 71，取 safe = 90 一定够。

六、压完的复杂度与 s == t

压完的位置数 nn ≤ m·safe + safe ≤ 100×90 + 90 = 9090，每格 t 次转移，约 9 万次，秒出。

s == t 时每次跳固定距离，只能落在 s 的倍数上，直接数石子位置里有多少个 s 的倍数。实测 n = 10、s = t = 2、石子 [2,4,5,8,10] 答案是 4。长桥 n = 1e7、石子 [100, 2000, 5000000, 9000000] 答案是 0：跳着跳着全躲开了。

过河：压缩后的桥

上面一条轴是原桥，下面一条是压完的坐标轴，石子标橙。「下一步」逐个位置算 dp[i]，信息行给出从哪个位置跳来、踩没踩石子。

// 过河：n 到 1e7，直接对每个位置做 dp 是 O(n * t)，存不下也跑不完
    // 石子在长桥上只有 100 个，关键是石头之间的大段空白怎么跳
    // s < t 时，两枚石子间距超过 safe 就压成 safe：
    // 空白段足够长之后，青蛙能落脚的位置图案就完整了，dp 值只跟「到末尾多远」有关
    int compute() {
        sort(arr + 1, arr + m + 1);
        if (s == t) { // 只能落在 s 的倍数上，直接数
            int ans = 0;
            for (int i = 1; i <= m; i++) {
                if (arr[i] % s == 0) {
                    ans++;
                }
            }
            return ans;
        }
        // s、t <= 10 时 safe = 90 一定够
        // 最大不可达位置来自跳距 {9, 10}，是弗罗贝尼乌斯数 9*10-9-10 = 71
        const int safe = 90;
        arr[0] = 0;
        for (int i = 1; i <= m; i++) {
            where[i] = where[i - 1] + min(arr[i] - arr[i - 1], safe);
            stone[where[i]] = true;
        }
        int nn = where[m] + safe;
        for (int i = 1; i <= nn; i++) {
            dp[i] = MAXN;
        }
        dp[0] = 0;
        for (int i = 1; i <= nn; i++) {
            for (int j = max(i - t, 0); j <= i - s; j++) {
                dp[i] = min(dp[i], dp[j] + (stone[i] ? 1 : 0));
            }
        }
        int ans = MAXN;
        for (int i = where[m] + 1; i <= nn; i++) {
            ans = min(ans, dp[i]);
        }
        return ans;
    }

七、一个怪细节

课上的实验先试过把间距压成 s + t − 1，这是按「从任意位置都能跳」的数法估的。密集石子间距下有真实反例：13.6 万组混合随机错了 8 组，比如 (s, t) = (9, 10) 时 s + t − 1 = 18，可最大不可达位置是 71，18 不够，会漏答案。页面直接用 safe = 90 保底，零错误。

复杂度分析

摆盘子：线性版 O(n)，矩阵版 O(log n)，空间都 O(1)。过河：压完后位置数 ≤ 9090，O(nn·t) ≈ 9×10⁴ 次转移，空间 O(nn)。

做法时间空间
摆盘子：末尾两盘分情况O(n) 或 O(log n)O(1)
过河：坐标压缩 + dpO(9090·t)O(9090)

总结

摆盘子的关键是尝试方式：按末尾两盘是否相同分情况，而不是按颜色枚举；锁住第一盘定义 f 让递推有干净的边界，解锁用对称性乘回去。过河的关键是状态压缩：s < t 时空白段的可达图案会平移，间距压到 90 不丢信息，1e7 的坐标轴缩成 9090。两个题改的是不同的地方，共同点是先问一句「到底什么在决定下一个状态」。
