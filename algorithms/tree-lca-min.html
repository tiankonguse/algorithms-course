最大生成树上的路径最小边

一张公路网，每条路有限重，问 a 到 b 一路上最多能拉多重的货。答案是路径上最小那条边的限重，而这条「最好的路」不必找——先按限重从大到小建一棵最大生成树，答案就落在树上那唯一一条路径里。

零、背景

树上倍增的跳表除了记「往上跳 2p 步落在谁身上」，还能在每一格多挂一份沿路累计的信息。这一页挂的是最小值：stmin[u][p] 存 u 往上跳 2p 步经过的那些边里，最小的权值是几。挂上它之后，树上任意一条路径的最小边一次查询就能拿到。

至于「为什么要最小边」：一辆车从 a 开到 b，载重受限于途中限重最小的那条路。想让载重最大，等价于在 a 到 b 的所有路径里，找「最小边最大」的那条。这类问题叫最大瓶颈路。

一、问题

n 座城市、m 条双向道路，每条路有限重 w。q 条查询 (a, b)，问从 a 到 b 允许的最大载重；到不了输出 -1。1 ≤ n ≤ 10⁴，1 ≤ m ≤ 5 × 10⁴，1 ≤ q ≤ 3 × 10⁴，0 ≤ w ≤ 10⁵。

朴素做法是对每条查询单独找最大瓶颈路：从 a 出发做一遍「优先走限重大的边」的搜索，代价 O(m log n) 一条查询，q = 3 × 10⁴ 时撑不住。实测 n = 2000、m = 8000 的随机图上 2000 条查询，每条现算要 1019 ms，先建最大生成森林再查跳表只要 0.24 ms。

二、为什么取最大生成树

把边按限重从大到小排序，用并查集一条条往里加，能加就加——这就是 Kruskal 求最大生成树，只是排序方向反过来。建出来的树有两条性质直接给出答案：

1）树上 a 到 b 的路径只有一条，它的最小边就是这条路径的瓶颈；
2）原图里任何一条 a 到 b 的路，瓶颈都不会超过它。

第二条用割来证：树上路径里的任意一条边 e，删掉它树就断成两半，a、b 分居两侧。如果原图里有另一条边 f 也跨这个断口、而且 f 的限重比 e 大，那把 e 换成 f 还是一棵生成树，总限重却更大，与「最大」矛盾。所以跨这个断口的每条边限重都不超过 e，而 a 到 b 的任何一条路都得跨过去，路上必然踩到一条不超过 e 的边。每条树边都这样压一遍，任何路径的瓶颈就都不超过树上那条路径的最小边。

省下来的不只是边。n = 10⁴、m = 5 × 10⁴ 的随机图实测，最大生成森林只留 9999 条边，是原图的 20.00%。图的规模小了五分之四，后面的每次跳表访问都跟着便宜。

反过来说，这一步不能省。同样这批数据，把「按输入顺序随便加边不成环」得到的生成森林拿来答查询：1999 条可达的查询里 99.85% 给出与真值不同的答案，而且全部偏低，平均只有真值的 4.85%。随便一棵树上的瓶颈，跟最大瓶颈是两回事。

三、跳表多带一列最小值

建表时多带一张 stmin[u][p]。递推只多一行：跳 2p 步经过的边分成前后两半，各是 2p-1 步，前半段的最小边是 stmin[u][p-1]，后半段从 jump[u][p-1] 接着走，是 stmin[jump[u][p-1]][p-1]，两半取小。

查询时一边跳一边顺手取 min：抬平那一程累积一遍，双向齐跳那一程再累积一遍，最后补上各自最后一格。三段并起来就是完整路径的最小边。

根那一格要单独处理：根没有父亲，把 stmin[root][0] 设成一个大数，它向上所有层的最小值都是这个大数，跳过头也不会把答案污染成 0。

四、森林与并查集

题目没保证图连通。最大生成森林建完之后可能有几棵树，两件事必须跟上：

1）DFS 不能只从 1 号开始，要外层再套一个循环，没访问过的点都当根试一遍；
2）查询先拿并查集判一下 a、b 是否连通，不连通直接返回 -1。Kruskal 用过的 father 数组留着的正是这个信息。

还有一个实现细节：链式前向星的边下标从 1 开始，head 初始化成 0 表示「没有出边」，所以遍历的循环条件是 e != 0。这套写法在前面几页已经反复出现，照抄就行。

五、建树与查询

排序方向是这页唯一的改动：a.w > b.w，从大到小。

const int MAXN = 10001;
    const int MAXM = 50001;

    struct Edge {
        int u, v, w;
    } edges[MAXM];

    int father[MAXN];
    int head[MAXN], nxt[MAXM << 1], to[MAXM << 1], weight[MAXM << 1];
    int cnt;

    int find(int i) {
        if (i != father[i]) {
            father[i] = find(father[i]);
        }
        return father[i];
    }

    void addEdge(int u, int v, int w) {
        nxt[cnt] = head[u];
        to[cnt] = v;
        weight[cnt] = w;
        head[u] = cnt++;
    }

    void kruskal(int m) {
        sort(edges + 1, edges + m + 1,
             [](const Edge &a, const Edge &b) { return a.w > b.w; });
        for (int i = 1; i <= m; i++) {
            int a = edges[i].u, b = edges[i].v;
            int fa = find(a), fb = find(b);
            if (fa != fb) {
                father[fa] = fb;
                addEdge(a, b, edges[i].w);
                addEdge(b, a, edges[i].w);
            }
        }
    }

DFS 带三个参数：当前点、走过来的那条边的权、父亲。根的调用是 dfs(i, 0, 0)，靠 f == 0 分辨「这是根」。

const int LIMIT = 21;
    int power;
    int deep[MAXN];
    int stjump[MAXN][LIMIT];
    int stmin[MAXN][LIMIT];
    bool visited[MAXN];

    void dfs(int u, int w, int f) {
        visited[u] = true;
        if (f == 0) {
            deep[u] = 1;
            stjump[u][0] = u;
            stmin[u][0] = INT_MAX;
        } else {
            deep[u] = deep[f] + 1;
            stjump[u][0] = f;
            stmin[u][0] = w;
        }
        for (int p = 1; p <= power; p++) {
            stjump[u][p] = stjump[stjump[u][p - 1]][p - 1];
            stmin[u][p] = min(stmin[u][p - 1], stmin[stjump[u][p - 1]][p - 1]);
        }
        for (int e = head[u]; e != 0; e = nxt[e]) {
            if (!visited[to[e]]) {
                dfs(to[e], weight[e], u);
            }
        }
    }

查询里三个阶段各取一次 min。注意抬平阶段每跳一次就要累积，不是跳完再算——跳过去的那段路已经走完了。

int lca(int a, int b) {
        if (find(a) != find(b)) {
            return -1;
        }
        if (deep[a] < deep[b]) swap(a, b);
        int ans = INT_MAX;
        for (int p = power; p >= 0; p--) {
            if (deep[stjump[a][p]] >= deep[b]) {
                ans = min(ans, stmin[a][p]);
                a = stjump[a][p];
            }
        }
        if (a == b) return ans;
        for (int p = power; p >= 0; p--) {
            if (stjump[a][p] != stjump[b][p]) {
                ans = min(ans, min(stmin[a][p], stmin[b][p]));
                a = stjump[a][p];
                b = stjump[b][p];
            }
        }
        ans = min(ans, min(stmin[a][0], stmin[b][0]));
        return ans;
    }

七、最后

这一页的三件事：最大瓶颈路的答案挂在最大生成树的路径上，割性质保证没有更好的路；跳表多带一列最小值，递推只是两半取小；图可能不连通，并查集留到最后判连通性，DFS 也要把每棵树的根都试一遍。

同样的框架把 min 换成 max、换成和、换成异或，回答的就是另一批路径统计问题——跳表本身不变，变的是挂上去的那一列。
