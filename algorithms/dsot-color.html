子树上的颜色统计

上一节把框架搭好了，信息统计还只是一个颜色计数数组。这一节换两个稍微复杂一点的统计：一个要同时知道「某个颜色出现几次」和「出现 k 次的颜色有几种」，一个要维护当前的最大出现次数。对应两道题，分别是颜色平衡的子树和主导颜色累加和。

一、题目2：颜色平衡的子树

一共有 n 个节点，编号 1 到 n，给定每个节点的颜色值和父亲节点编号，输入保证所有节点一定组成一棵树，并且 1 号节点是树头。如果一棵子树中存在的每种颜色的节点个数都相同，这棵子树叫颜色平衡树。打印整棵树中有多少个子树是颜色平衡树。1 ≤ n、颜色值 ≤ 2 × 10⁵。测试链接：P9233。

「每种颜色的节点个数都相同」这句话，等价于「颜色种数 × 那个相同的个数 = 子树大小」。但子树里有很多种颜色，该拿哪一种去乘？

这里有个取巧的办法，只需要两个数组。colorCnt[c] 记颜色 c 出现几次，colorNum[k] 记「当前出现 k 次的颜色有几种」。加进一个颜色为 c 的节点时，c 的计数从 k 变成 k + 1，于是 colorNum[k] 减一、colorNum[k+1] 加一。撤销时反过来。两个数组都可以在 O(1) 里维护。

void effect(int u) {
        colorCnt[color[u]]++;
        colorNum[colorCnt[color[u]] - 1]--;
        colorNum[colorCnt[color[u]]]++;
        for (int e = head[u]; e > 0; e = nxt[e]) {
            effect(to[e]);
        }
    }

    void cancel(int u) {
        colorCnt[color[u]]--;
        colorNum[colorCnt[color[u]] + 1]--;
        colorNum[colorCnt[color[u]]]++;
        for (int e = head[u]; e > 0; e = nxt[e]) {
            cancel(to[e]);
        }
    }

判定的时候取节点 u 自己的颜色：colorCnt[color[u]] 是它出现的次数 k，colorNum[k] 是出现这么多次的颜色有几种，两者相乘如果等于子树大小，就说明所有颜色的计数都是 k。反过来，如果有任何一种颜色的计数不是 k，那它要么落在别的 colorNum 桶里、要么让总数变大，乘积一定对不上。

dfs2 的骨架和上一节一字不差，唯一的差别是第 5 步换成这个判定，答对一次全局答案加一。

void dfs2(int u, int keep) {
        for (int e = head[u], v; e > 0; e = nxt[e]) {
            v = to[e];
            if (v != son[u]) {
                dfs2(v, 0);
            }
        }
        if (son[u] != 0) {
            dfs2(son[u], 1);
        }
        colorCnt[color[u]]++;
        colorNum[colorCnt[color[u]] - 1]--;
        colorNum[colorCnt[color[u]]]++;
        for (int e = head[u], v; e > 0; e = nxt[e]) {
            v = to[e];
            if (v != son[u]) {
                effect(v);
            }
        }
        if (colorCnt[color[u]] * colorNum[colorCnt[color[u]]] == siz[u]) {
            ans++;
        }
        if (keep == 0) {
            cancel(u);
        }
    }

取消贡献这次不能整体清零了，因为 colorNum 的多桶结构清零要遍历整个数组。所以这里用的是 effect 的严格逆操作：把计数减回去，两个 colorNum 桶反向调整。这样一来 cancel 一趟的代价和 effect 一样是 O(子树大小)，复杂度不变。

题目 2 的 n 到了 2 × 10⁵，dfs1 和 dfs2 都是一路递归到叶子。C++ 默认栈通常够用；不够时把递归改写成显式栈的迭代版本。

换一棵子树，看判定式怎么变

colorCnt（颜色 → 次数）

colorNum（次数 → 几种颜色）

已经加进桶的节点 在子树里、还没轮到 不在当前子树里 桶里加粗的格子是判定式用到的那两个

在本文那棵 10 个节点的树上跑一遍，颜色平衡的子树是 3、5、6、7、8、9、10 一共 7 个。子树 6 里两个节点都是颜色 2，一种颜色出现 2 次，2 × 1 = 2 等于子树大小；子树 3 里颜色 2 和颜色 3 各出现 1 次，1 × 2 = 2 也等于子树大小。

二、题目3：主导颜色累加和

一共有 n 个节点，编号 1 到 n，给定 n − 1 条边，所有节点连成一棵树，1 号节点为树头。每个节点给定一种颜色值。以 x 为头的子树上，哪种颜色出现最多，那种颜色就是主导颜色，主导颜色可能不止一种。所有主导颜色的值累加起来，每个主导颜色只累加一次，就是该子树的主导颜色累加和。打印 1 到 n 每个节点为头的子树的主导颜色累加和。1 ≤ n、颜色值 ≤ 10⁵。测试链接：CF600E。

统计需要三样东西：colorCnt[c]、当前最大出现次数 maxCnt、当前答案 ans。加进一个颜色 c 时，如果它加完之后的计数正好等于 maxCnt，说明它并列成了主导颜色，ans 加上 c；如果加完之后超过了 maxCnt，说明它独占了主导位置，maxCnt 更新，ans 直接被 c 覆盖。

void effect(int u, int h) {
        colorCnt[color[u]]++;
        if (colorCnt[color[u]] == maxCnt[h]) {
            ans[h] += color[u];
        } else if (colorCnt[color[u]] > maxCnt[h]) {
            maxCnt[h] = colorCnt[color[u]];
            ans[h] = color[u];
        }
        for (int e = head[u], v; e > 0; e = nxt[e]) {
            v = to[e];
            if (v != fa[u]) {
                effect(v, h);
            }
        }
    }

effect 多了一个参数 h。原因是 maxCnt 和 ans 这两个量是「属于当前正在算的那个点」的，轻儿子子树里的节点被重新贡献时，要更新的是祖先 u 的状态，不是它们自己的。

第 2 步走完重儿子回来的时候，重儿子的那套状态可以直接拿过来用。这是树上启发式合并省时间的关键一步：重儿子的子树最大，从头重建它代价最高，直接继承就免了这一趟。

void dfs2(int u, int keep) {
        for (int e = head[u], v; e > 0; e = nxt[e]) {
            v = to[e];
            if (v != fa[u] && v != son[u]) {
                dfs2(v, 0);
            }
        }
        if (son[u] != 0) {
            dfs2(son[u], 1);
        }
        maxCnt[u] = maxCnt[son[u]];
        ans[u] = ans[son[u]];
        colorCnt[color[u]]++;
        if (colorCnt[color[u]] == maxCnt[u]) {
            ans[u] += color[u];
        } else if (colorCnt[color[u]] > maxCnt[u]) {
            maxCnt[u] = colorCnt[color[u]];
            ans[u] = color[u];
        }
        for (int e = head[u], v; e > 0; e = nxt[e]) {
            v = to[e];
            if (v != fa[u] && v != son[u]) {
                effect(v, u);
            }
        }
        if (keep == 0) {
            cancel(u);
        }
    }

cancel 这里又要变回整体清零的写法。原因很直接：maxCnt 记的是最大值，把节点一个个撤回去没法还原「撤销之前的最大值是多少」，除非再维护一个次大值。而按上一节的观察，cancel 被调用时全局统计恰好就是子树 u 的内容，所以直接把经过的颜色计数清零、maxCnt 置 0 就够了。

在示例树上跑完，1 到 10 号的答案依次是 2、2、5、3、1、2、3、3、1、2。子树 3 的答案是 5，因为颜色 2 和颜色 3 各出现一次、并列主导，2 + 3 = 5。

复杂度分析

环节题目2 颜色平衡题目3 主导颜色
dfs2 全部调用O(n log n)O(n log n)
单次贡献 / 撤销O(1)O(1)
答案统计全局一个计数器，O(1)继承重儿子，O(1)
空间O(n)O(n)

两个题的信息统计都是 O(1) 更新，所以总代价由「每个节点被扫几次」决定，也就是上一节那个 O(n log n)。空间上都是两个长度 n 或 n + 1 的 int 数组加上前向星，O(n)。

最后

这两道题的统计都挂在「颜色 → 次数」这一个维度上。下一节换一个维度：把节点按深度分桶，统计的东西变成「某个深度上有几个节点」或者「某个深度上有几种名字」，去回答子树里指定距离的查询。
