博弈：SG 定理的实战

前两页把 SG 的定义、定理和打表流程过了一遍。这两道题是它的正经用法：E&D 游戏里每两堆是一个小组，把两堆都减一之后按位或，数一数最低的那个 0 在第几位，小组的 SG 就出来了；分裂游戏里每颗豆子各算各的，先手要给出字典序最小的第一步，还要数清有多少种赢法。

零、两道题各自要什么

第一题是 E&D 游戏。桌上有 2n 堆石子，编号 1 到 2n，其中 1、2 一组，3、4 一组，依次往下。每组可以这么操作：任取一堆把它移走，再把同组的另一堆分成两堆，操作完组内每堆的石子数都必须大于 0。这意味着被分割的那堆至少要有 2 颗。两个人轮流做，轮到某人时如果所有堆都只剩 1 颗，这个人就输了，问先手能不能赢。

第二题是分裂游戏。n 个瓶子编号 0 到 n-1，第 i 瓶里有 nums[i] 颗糖豆。每轮选三个编号 i、j、k，要求 i < j <= k，从 i 号瓶拿出一颗糖豆，分裂成两颗分别放进 j 号和 k 号。如果 j 等于 k，就等于往同一个瓶子放了两颗。i 号瓶必须有豆子才能选它。轮到某人时所有豆子都堆在 n-1 号瓶里，他无法行动，就输了。先手想知道第一步怎么走能保证赢，要字典序最小的那个方案，还要给出能赢的第一步共有多少种，赢不了就返回 -1 -1 -1。

一、E&D：单组的 SG 是一行位运算

每组的两堆只在组内被搬来搬去，跨组一点都不碰，所以每组都是一个独立的子游戏，整局的 SG 就是各组 SG 异或起来。剩下的问题只有一个小：一组两堆的 SG 怎么算。

把两堆都减掉 1，得到的两个数按位或，再数一数结果里最低的那个 0 在第几位，从 0 数起，这个位数就是答案。写成一个函数就是 lowZero((a - 1) | (b - 1))。

这条闭式是从 SG 表里看出来的。把 1 到 200 的每一对 (a, b) 都算一遍，暴力递归枚举分割和这条位运算 0 处不符。减一是因为两堆都非空，最小值 1 对应二进制的 0 位；或起来之后从低位往上看全是 1 的那一段，长度就是这个局面能往下走的层数。

表里有一片橙色很显眼：两堆都是奇数颗时 SG 恒为 0。理由是两堆都减一以后都是偶数，最低位全是 0，或出来最低位还是 0，mex 直接取 0。这条在纸上就能推，不必查表。

// E&D 游戏：每两堆一组，单组的 SG 值就是 lowZero((a - 1) | (b - 1))
    // lowZero 返回 status 里最低的那个 0 在第几位，从 0 数起
    int lowZero(int status) {
        int ans = 0;
        while (status > 0) {
            if ((status & 1) == 0) break;
            status >>= 1;
            ans++;
        }
        return ans;
    }

    // 整局的 SG 是各组 SG 的异或，非 0 先手胜
    bool edWin(vector<int>& stones) {
        int eor = 0;
        for (int i = 0; i + 1 < (int)stones.size(); i += 2)
            eor ^= lowZero((stones[i] - 1) | (stones[i + 1] - 1));
        return eor != 0;
    }

整局的做法就是逐组取 lowZero 再异或。100 万组随机数据跑下来 20.25ms，每次只有一次减一、一次或和一次找最低 0 位，常数很小。

二、分裂游戏：每颗豆子各算各的

先看一颗豆子。它待在 i 号瓶里，一步能挪到 (j, k)，条件只是 i < j <= k。糖豆之间无差别，所以每颗豆子都是一个一模一样的子游戏，整局的 SG 就是所有豆子各自 g 值的异或。

同一瓶里放几颗豆子，它们的 g 值完全一样，异或两次就抵消了。所以不用看具体颗数，只看每瓶豆子数的奇偶：奇数颗才把 g[i] 异或进去。

单颗豆子的 g 值照定义推。g[i] = mex{ g[j] ^ g[k] : i < j <= k }，从右端往左建，n-1 号瓶是终点，g[n-1] = 0。n = 21 时这张表从 0 到 20 是 38、37、35、32、31、28、26、25、22、21、19、16、14、13、11、8、7、4、2、1、0，没有任何简单公式。

第一步要挑一个让局面变成必败态的走法。当前局面的异或和是 eor，走完一步后变成 eor ^ g[i] ^ g[j] ^ g[k]，要求它等于 0。把所有满足条件的 (i, j, k) 数一遍就是方法数；字典序最小的一步，只要按 i 从小到大、j 从小到大、k 从小到大扫，第一个命中的就是它，不需要比较字符串。

// 分裂游戏：p 号瓶里的一颗豆子能挪到 (j, k)，p < j <= k，n-1 号瓶是终点
    // g[p] = mex{ g[j] ^ g[k] }，从右端往左推
    void build(int n, vector<int>& g) {
        g.assign(n, 0);
        vector<int> appear(n * n + 2, 0);
        for (int p = n - 2; p >= 0; p--) {
            fill(appear.begin(), appear.end(), 0);
            for (int j = p + 1; j < n; j++)
                for (int k = j; k < n; k++) appear[g[j] ^ g[k]] = 1;
            for (int s = 0;; s++) if (!appear[s]) { g[p] = s; break; }
        }
    }

    // 每瓶豆子只看奇偶，第一步的条件是 eor ^ g[i] ^ g[j] ^ g[k] == 0
    // i、j、k 都从小到大扫，第一个命中的就是字典序最小的一步
    string firstMove(vector<int>& nums, int n, int& cnt) {
        vector<int> g;
        build(n, g);
        int eor = 0;
        for (int i = 0; i < n; i++) if (nums[i] % 2 == 1) eor ^= g[i];
        if (eor == 0) { cnt = 0; return "-1 -1 -1"; }
        int a = -1, b = -1, c = -1;
        cnt = 0;
        for (int i = 0; i < n && a == -1; i++) {
            if (nums[i] == 0) continue;
            for (int j = i + 1; j < n; j++)
                for (int k = j; k < n; k++)
                    if ((eor ^ g[i] ^ g[j] ^ g[k]) == 0) {
                        cnt++;
                        if (a == -1) { a = i; b = j; c = k; }
                    }
        }
        return to_string(a) + " " + to_string(b) + " " + to_string(c);
    }

对拍用枚举第一步再递归搜胜负的暴力，小局面跑四千组 0 处不符。几个手算的例子：n = 4、nums = [1,0,0,0]，答案是 0 1 1，方法数 3；n = 3、nums = [1,1,1]，答案是 0 1 2，方法数 1；n = 4、nums = [2,0,0,0] 的异或已经是 0，返回 -1 -1 -1，方法数 0。

建表 n = 21 时只要 0.0192ms，单次查询 100 万次跑下来 1105.28ms，平均一次 1.1 微秒。瓶颈在建 g 表那两层循环，n 一大就该换思路，好在题目把 n 卡在 21。

四、对数器怎么抓错

两题的暴力都好写。E&D 的暴力递归枚举分割，分裂游戏的暴力枚举第一步再递归搜胜负。把常见写错的地方各改一处，看随机数据多久撞见差异。

E&D 每组 2 万组随机数据；分裂游戏 n 取 2 到 20，另有一组专门查字典序。

lowZero 和 lowOne 只在状态是奇数时才给出同一个答案，值域越小越容易撞上一块全是 1 的数，所以出错比例随值域下降，到 104 就彻底分家了。或和与的差别集中在最低位：两个偶数相或只影响高位，相与会把低位抹平，所以这条错法不管值域多大都稳定错 66% 左右。

分裂游戏里「忽略奇偶」这条随值域上升而变高，方向和其他几条相反。原因很直白：豆子数取值域一大，落到偶数的机会就多，本该被异或两次抵消的瓶子被当成一次算进 eor，异或和自然跟着错。把值域收到 3，绝大多数瓶子都是 0 或 1，看奇偶和看「有没有豆子」几乎一样，错得就少。

另外单独量了一条：第一步找字典序最大而不是最小，60.98% 的局面给出不同答案。字典序这件事必须靠循环的扫描方向保证，不能事后补。

复杂度分析

E&D 的整局部分是线性的，100 万组 20.25ms，单组不到 0.05 微秒。分裂游戏建表 n = 21 时 0.0192ms，单次查询 1.1 微秒；n 的规模是题目给死的 21，所以 O(n³) 在这里完全够用。两题的额外空间都很小，E&D 是 O(1)，分裂游戏的 g 表只有 n 项。

总结

E&D 游戏的单组 SG 是 lowZero((a - 1) | (b - 1))，也就是两堆都减一之后按位或，再数最低的那个 0 在第几位。整局按组异或，非 0 先手胜。

分裂游戏把每颗豆子当成独立子游戏，同一瓶里的豆子异或两次抵消，所以只看每瓶数量的奇偶。单颗豆子的 g 值从右端往左推，第一步的条件是 eor ^ g[i] ^ g[j] ^ g[k] == 0，字典序最小靠下标从小到大扫。

两题共同的思路是「先找到最小的一块，把它的 SG 单独算清楚，再用定理拼起来」。E&D 的最小块是两堆，分裂游戏的最小块是一颗豆子；块找对了，剩下的就是异或和数格子这种机械活儿。
