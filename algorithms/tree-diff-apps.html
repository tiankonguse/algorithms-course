点差分应用题：数覆盖与树上选择

模板处理的是「路径加、问点权」，题目不会照着模板问。一道把路径覆盖数当成糖果数，中间多一次减法；一道先用覆盖数算总代价，再在树上做一组带相邻约束的选择。差分部分原样复用，后面接的东西不一样。

零、背景

点差分的打标四步与后序收拢在这里直接当工具用：每条路径四个加减，收拢一次，每个点被几条路径覆盖就摆在 num 里。两道题的工作量都花在「覆盖数之后」。

一、松鼠的新家

洛谷 P3258。n 个点的树，一个长度 n 的点编号数组表示松鼠依次要去的地点。松鼠每走到一个节点都必须拿一个糖果，否则就停下前进；来到最后一个地点时不需要吃糖果。打印每个节点上至少准备多少糖果。

翻译成模板语言：相邻两个地点之间走一条路径，一共 n−1 条路径，每条路径全部点加 1。收拢之后 num[u] 就是 u 被路径覆盖的次数。但覆盖数不等于答案，中间差一次减法。

差在哪？松鼠是连续走的。它抵达 travel[i+1] 那次，同时又是下一段的出发点，不能算两次；最后一段的终点是最后一个地点，不要糖；而出发点 travel[1] 开局就站在上面，反而要准备一颗。三条合起来只有一个修正：答案 = 覆盖数 − 该点在 travel[2..n] 里出现的次数。

为什么减的是 travel[2..n]？覆盖数里，travel[i]（i ≥ 2）作为第 i−1 段的终点被覆盖一次，又作为第 i 段的起点被覆盖一次，减掉后面那次，两次并成一次真实抵达。travel[1] 只在第一段作为起点被覆盖，不减，于是它拿到一颗，正好对应开局就在起点。travel[n] 作为最后一段的终点被覆盖一次，但它是最后一个地点，减掉。

代码只剩一个收尾循环。lca 用 tarjan 离线求，ans[i] 存第 i 段路径的 lca，father[l] 是它的父亲：

// 松鼠的新家：n-1 段路径打差分，累加后减掉每个途经点作为终点的那次重复计数
    void compute(int n) {
        tarjan(1, 0);
        for (int i = 1; i < n; i++) {
            int u = travel[i], v = travel[i + 1];
            int l = ans[i], lf = father[l];
            num[u]++;
            num[v]++;
            num[l]--;
            num[lf]--;
        }
        collect(1, 0);
        for (int i = 2; i <= n; i++) num[travel[i]]--;
    }

漏掉最后那个循环会怎样？实测两万组随机小数据，忘减 travel[2..n] 的答案 100% 偏大，一组都蒙不对。数组里地点重复越少错得越少，但只要有一个点出现两次以上，覆盖数和真实抵达次数就对不上。性能上整棵树加 n−1 次差分与一次收拢都是 O(n)，n = 3×10⁵ 的随机树实测 23.9ms。

二、最小化旅行的价格总和

LeetCode 2646。n 个点的树，每个点有点权 price，再给一组路径，每条路径的代价是沿途点权和，总代价是所有路径代价之和。可以把某些点的点权减半（向下取整），但选中的点不能相邻。求总代价最小能是多少。

第一步还是数次数。每条路径做一次点差分，收拢后 num[u] 是 u 被多少条路径覆盖。总代价可以换个算法：把 price[u] × num[u] 逐个点加起来，比一条路径一条路径地加快得多。某个点减半，省下的是 (price[u]/2) × num[u]。

第二步做选择。在树上挑一个独立集，挑中的点半价，要求节省之和最大。这是树形 dp：每个点记两个状态，no 是不半价时子树的最小代价，yes 是半价时的。转移就两条：no 的孩子取 min(no, yes) 随便挑；yes 的孩子只能取 no，相邻不能同时半价。

dp 的写法没有分支，十来行：

// 旅行价格：no/yes 记当前点不半价/半价时子树的最小代价，yes 的孩子只能取 no
    int no, yes;

    void dp(int u, int f) {
        int noU = price[u] * num[u];
        int yesU = (price[u] / 2) * num[u];
        for (int e = head[u], v; e != 0; e = nxt[e]) {
            v = to[e];
            if (v != f) {
                dp(v, u);
                noU += min(no, yes);
                yesU += no;
            }
        }
        no = noU;
        yes = yesU;
    }

最容易写错的是 yes 那一行。把 yesU += no 写成 yesU += min(no, yes)，等于允许父子同时半价，约束白给。实测两万组随机小数据（点权混奇偶数，跟枚举独立集的暴力对答案），这个错法 95.53% 的组答案偏小。另外 price[u]/2 是整数除法，奇数点权减半会向下取整，暴力也必须用同一个口径，否则对拍会假 FAIL。

三、复杂度分析

环节时间空间
松鼠：n−1 次差分 + 一次收拢O(n)（lca 离线近乎线性）O(n)
旅行价格：q 次差分 + 树上 dpO(n log n + q log n)
合计O(n log n + q log n)

空间按题目上限算。松鼠 n = 3×10⁵：链式前向星正反两份边、查询链、并查集、num、travel，各一条 3×10⁵ 的 int 数组，几条加起来几十 MB。旅行价格的数据范围小得多（n 到 50，路径到 50），开销怎么算都够，真正要盯住的是 dp 的状态别写反。

四、总结

要点两条。其一，点差分在应用题里只负责「数覆盖」，数完之后怎么用全看题目：松鼠要的是覆盖数减掉重复抵达，旅行价格要的是覆盖数加权的总代价。修正项往往藏在题面的口头语里，「每走到一个节点」「最后一个地点不需要」各对应一次加减。其二，旅行价格的后半段是标准树上独立集 dp，no/yes 两个状态的差别只在 yes 分支的孩子不能挑 yes；这个约束同时也是它与普通树形 dp 唯一的分岔。

往后看，边差分把标记从点挪到边上，lca 处要减两次；运输计划那种「只改一条边」的题，差分只用来判断一条边是否被所有超限路径共用，真正定答案的是外面包的二分。

五、最后

两道题都不难，难的是第一次见到时把题面翻译成差分。翻译的抓手就一个：题目如果反复问「经过某个点的次数」「某个点被多少路径覆盖」，先想点差分；问边，先想边差分。抓错手的方向，后面全白写。
