KMP：让主串的指针只往前走

在 s1 里找 s2 第一次出现的位置，最直接的写法是把 s1 的每个位置都当开头试一遍。n = 20 万、m = 1000 时这个写法要比 1.99 亿次字符；KMP 比 20 万次就收工。差出来的这一千倍不在常数上，在于 KMP 从不把 s1 的指针往回挪。

零、暴力把时间花在哪

暴力的逻辑没有错，只是太老实：从 s1[0] 开始试，配不上就从 s1[1] 开始试，一路试到 s1[n−m]。每个开头最多比 m 次，代价是 (n − m + 1) · m 这个量级。

最难受的数据长这样：s1 是一长串 a 接一个 b，s2 是一短串 a 接一个 b。每次尝试都在最后一个字符上才失配，前面比掉的几十个 a 全部作废。实测 n = 200000、m = 1000 时暴力比了 199001000 次、耗时 64.172 ms；n = 106、m = 2000 时比了 1996002000 次、耗时 502.406 ms。

暴力的回退是双份的：s1 的指针退回本次开头的下一个位置，s2 的指针退回 0。KMP 保留了第二份，s2 的指针照样会往回跳；它砍掉的是第一份，s1 的指针从头到尾只增不减。

砍掉第一份需要提前知道一件事：配不上时，s2 该退到哪个位置。这件事的答案就是 next 数组。

一、next 数组到底记了什么

next[i] 描述的是 s2 的前缀 s2[0..i−1]，记的是「这个串的真前缀和真后缀，相等时最长能有多长」。真前缀是不包含自己、从下标 0 开始的一段；真后缀是不包含自己、在下标 i−1 结束的一段。

拿 s2 = "aabaabaaa" 逐个位置看过去，最长相等真前后缀的长度就是这一格的 next 值。

next[1] = 0 是定义推出来的：单字符的真前缀和真后缀都只能是空串，长度为 0。next[0] = −1 跟定义无关，它是个哨兵，只用来表示「s2 的第一个字符就配不上，该推进 s1 了」。

这个定义之所以有用，是因为它同时回答了两件事：失配时 s2 该退到哪，以及退到那里之后前面那些字符为什么不用再比。

二、有了 next，匹配怎么被加速

主流程只有两个指针：x 走 s1，y 走 s2。每一轮三个分支：

1）s1[x] == s2[y]：这一位对上了，x、y 一起 +1；
2）配不上且 y == 0：s2 一个字符都没配上，s1 的这个开头彻底作废，x + 1，y 不动；
3）配不上且 y > 0：y 跳到 next[y]，x 一动不动。

第三个分支就是全部秘密。失配发生在 s2[y] 上时，s2[0..y−1] 这 y 个字符已经和 s1[x−y..x−1] 逐一对上了。要找一个 s2 的前缀，让它正好等于「已配对那 y 个字符」的某段后缀，next[y] 给的就是这个长度。跳过去以后 s2[0..next[y]−1] 与 s1[x−next[y]..x−1] 天然相等，可以直接从 s2[next[y]] 接着比，一个字符都不用回看。

这里有个细节值得盯一眼：整个 while 循环里 x 要么不动，要么 + 1，从来没有减过。这一条是 O(n) 的全部来源，第四节会把它数清楚。

int kmp(string s1, string s2) {
        int n = s1.size(), m = s2.size();
        // x : s1 中当前比对的位置，只增不减
        // y : s2 中当前比对的位置
        int x = 0, y = 0;
        vector<int> next = nextArray(s2);
        while (x < n && y < m) {
            if (s1[x] == s2[y]) {
                x++;
                y++;
            } else if (y == 0) {
                // s2 的第一个字符就配不上，s1 的这个位置彻底作废
                x++;
            } else {
                // y 往前跳，x 不动
                y = next[y];
            }
        }
        return y == m ? x - y : -1;
    }

三、next 数组自己怎么算出来

算 next 用的还是同一套跳跃，只不过这次是 s2 自己和自己匹配。两个变量：i 是当前要填 next[i] 的位置，cn 是「上一个位置的最长匹配长度」，也是这一轮要和 s[i−1] 比对的下标。

1）s[i−1] == s[cn]：接上了，next[i] = cn + 1，i 和 cn 一起 +1；
2）配不上且 cn > 0：cn = next[cn]，同款跳跃；
3）配不上且 cn == 0：没得跳，next[i] = 0，i 单独 +1。

比的是 s[i−1] 和 s[cn]，不是 s[i] 和 s[cn]。i 这个位置的 next 值还没算出来，拿它去比对等于用未知推未知。写成 s[i] 的错法在随机数据上很能藏：字母表 26 个字母、2 万组随机样例里只现形 0.05%，字母表缩到 2 个字母时才升到 14.77%。

// next[i] : s[0..i-1] 上，最长的「相等的真前缀与真后缀」有多长
    // next[0] = -1 是哨兵，表示 s2 的第一个字符就配不上，只能推进 x
    vector<int> nextArray(string s) {
        int m = s.size();
        if (m == 1) {
            return vector<int>{-1};
        }
        vector<int> next(m);
        next[0] = -1;
        next[1] = 0;
        // i  : 当前要求 next 值的位置
        // cn : 当前要和 s[i-1] 比对的下标
        int i = 2, cn = 0;
        while (i < m) {
            if (s[i - 1] == s[cn]) {
                next[i++] = ++cn;
            } else if (cn > 0) {
                cn = next[cn];
            } else {
                next[i++] = 0;
            }
        }
        return next;
    }

四、复杂度分析

不用摊还、不用均摊，从代码层次直接数就行。看主循环三个分支对 (x, y) 的影响：相等分支 x + 1、y + 1；y == 0 分支 x + 1、y 不变；跳跃分支 x 不变、y 至少减 1。取 Φ = 2x − y，三个分支分别让 Φ 增加 1、2、至少 1，也就是每一轮 Φ 严格变多。

Φ 从 0 出发，而 x ≤ n、y ≥ 0 给出 Φ ≤ 2n。所以主循环最多跑 2n 轮，匹配是 O(n)。next 数组同理，取 Φ = 2i − cn、上界 2m，是 O(m)。

上界的实测值：n = 20000、m = 1000 的最坏构造跑了 39000 轮，2n = 40000；字母表 2 个字母的随机文本跑 5000 组，平均 20905 轮、最大 30163 轮，没有一次越过 2n。next 那边 m = 1000 的随机串平均 1415 轮、最大 1548 轮，2m = 2000；最顺的情况是全 a 串，恰好 m − 2 轮，每一轮都走第一个分支。

阶段时间复杂度空间
构造 next 数组O(m)，最多 2m 轮O(m) 存 next
匹配主循环O(n)，最多 2n 轮O(1) 额外
合计O(n + m)O(m)

空间那一栏说的是额外空间：next 数组要 m 个 int，匹配本身只要 x、y 两个变量。空间压缩在这里没什么可做，next 是每次跳跃都要查的，压不掉。

五、KMP 在什么数据上真的快

把图 5 的两半合起来看，结论有点反直觉。最坏构造上 KMP 快 171 倍（64.172 ms 对 0.376 ms），可随机文本上它是慢的：n = 20 万、m = 20、字母表 26 个字母时暴力 0.147 ms、KMP 0.281 ms。字母表越小差距越小，2 个字母时是 0.659 ms 对 0.741 ms。

原因是随机文本上暴力几乎碰不到「深度匹配之后失配」。头一个字符对不上就换下一个开头，期望比较次数是 n 乘上一个收敛得极快的等比级数，V = 26 时约 1.04 n（实测 208076 次，n = 200000）。KMP 却要老老实实比 n 次，还得先把 next 数组建出来。

所以 KMP 值钱的地方在最坏情况有保证，它给出的是上界，不是平均值。在随机英文文本里找一个短模式串，直接调标准库的 find 或者写个暴力都不会吃亏；真正躲不掉的是那种「模式串自己带大量重复」的场景，比如 DNA 序列、二进制串、以及下面第六节里那些错法的构造数据。

六、几种常见的写错方式

随机造 2 万组样例（n ≤ 60、m ≤ 10，一半保证能匹配上），把五种错法分别和暴力对答案，错误率如下。字母表越小越容易现形，这跟第五节说的是同一件事。

错法V = 2V = 4V = 26
失配时把 y 打回 09.95%2.00%0.05%
next 里比对 s[i] 而不是 s[i−1]14.77%2.15%0.05%
next[i] 记成 cn 而不是 ++cn9.95%2.00%0.05%
忘了判 y == m，直接返回 x − y30.56%42.91%50.40%
y == 0 的判断抢在相等判断前面69.44%57.09%49.60%

后两条加起来刚好是 100%，因为它们互补：忘了判 y == m 只在「找不到」时露馅（循环因 x == n 退出，x − y 是个正数，而正确答案该是 −1）；y == 0 抢在前面则只在「找得到」时露馅（y 永远停在 0，s2 的第一个字符一次都没参与比较，函数恒返回 −1）。

第一条值得单独说：把 y 打回 0 跟暴力并不等价。暴力会把 s1 的开头退回 x − y + 1，这个错法把 x 留在原地，等价于把开头定在 x，跳过了一批本该检查的位置。它比暴力慢，还比暴力错。

// 错法：忘了判 y == m，直接返回 x - y
    // 找得到时 x - y 恰好就是答案，找不到时 x == n 而 y < m，返回的是个正数
    int kmpWrong(string s1, string s2) {
        int n = s1.size(), m = s2.size(), x = 0, y = 0;
        vector<int> next = nextArray(s2);
        while (x < n && y < m) {
            if (s1[x] == s2[y]) {
                x++;
                y++;
            } else if (y == 0) {
                x++;
            } else {
                y = next[y];
            }
        }
        return x - y;
    }

七、总结

next[i] 是 s2[0..i−1] 的最长相等真前后缀长度，next[0] = −1 是哨兵。匹配时 s1 的指针只增不减，配不上就让 s2 的指针跳 next[y]，跳过去的那些位置之所以不用重比，是因为 next 的定义保证了它们必然相等。next 数组自己用同一套跳跃构造，比对的是 s[i−1] 与 s[cn]。复杂度 O(n + m) 可以从代码层次数出来：取 Φ = 2x − y，每轮严格增大，上界 2n。最后一条要记住：KMP 保证的是最坏情况，随机文本上它未必比暴力快。

next 数组的用法远不止字符串匹配，它能量出一个串的周期、能找最短循环节、能算 border 的嵌套结构。这一讲先把定义和匹配流程立住，具体题目留在后面讲。
