字符串上的二维动态规划：不同子序列、编辑距离、交错字符串

三个题都是两个串摆成一张表，表的两个下标都是前缀长度。套路一样，难的地方不一样：第一个题想清楚「末尾这个字符用不用」，第二个题多了一个斜向依赖，第三个题的下标要同时看三个串。这一页把三张表和它们的空间压缩写法一次讲完。

零、三个问题，一张表

统计 s 的子序列里有多少个等于 t；把 word1 改成 word2 的最小代价；判断 s3 是不是 s1 和 s2 交错出来的。

三个题都有两个可变参数，而且都是前缀长度。参数定下来，表的大小就是两个长度加一，剩下的问题只有两个：这一格是什么，它从哪些格子来。

一、不同的子序列：末尾这个字符用不用

题目：给两个串 s 和 t，统计 s 的子序列里有多少个等于 t。s = "babgbag"、t = "bag" 时答案是 5。

定义 dp[i][j]：s 前 i 个字符的所有子序列中，有多少个等于 t 的前 j 个字符。看 s 的最后一个字符 s[i−1]，只有两种去留：

  • 不用它，那得在 s 前 i−1 个里凑出 t 的前 j 个，dp[i−1][j] 种；
  • 用它，它必须等于 t[j−1]，剩下的在 s 前 i−1 个里凑 t 的前 j−1 个，dp[i−1][j−1] 种。

两种凑法不重叠（一个用了 s[i−1]，一个没用），直接加起来。

第 0 列全是 1：t 的前 0 个字符是空串，任何 s 前缀都只有一种凑法，什么都不选。第 0 行除了 dp[0][0] 全是 0，空串凑不出非空串。

// dp[i][j] : s 前 i 个字符的所有子序列中，有多少个等于 t 的前 j 个字符
    int numDistinct(string s, string t) {
        int n = s.size(), m = t.size();
        vector<vector<int>> dp(n + 1, vector<int>(m + 1, 0));
        for (int i = 0; i <= n; i++) {
            dp[i][0] = 1;                            // t 是空串，只有「什么都不选」一种
        }
        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= m; j++) {
                dp[i][j] = dp[i - 1][j];             // 不用 s[i-1]
                if (s[i - 1] == t[j - 1]) {
                    dp[i][j] += dp[i - 1][j - 1];    // 用 s[i-1] 去配 t[j-1]
                }
            }
        }
        return dp[n][m];
    }

顺着表里看两格就清楚了。dp[5][2]（s 前 5 个 "babgb"、t 前 2 个 "ba"）是 4，其中 3 个来自上面「不用 g」，1 个来自左上「用 g」，可这一格的 s[i−1] = 'g' 不等于 t[j−1] = 'a'，只能继承上面的 4。最后 dp[7][3] = 5。

这题有个别的地方：答案大得很快。s 和 t 全是 'a'，长 30 和 10，答案是 C(30,10) = 30045015；长 60 和 30 是 C(60,30) = 118264581564861424，long long 还装得下；长 67 和 33 就是 C(67,33) = 14226520737620288370，超过 9223372036854775807，溢出了。所以题目要取模，加号换成 (dp[j] + dp[j−1]) % MOD。

二、从二维表到一维：j 必须倒着走

dp[i][j] 只依赖 dp[i−1][*]，一行就够。压缩之后 dp[j] 装的是上一行的值，不赋值就自动继承，正好对应「不用 s[i−1]」，连赋值语句都省了。

方向是关键。j 从 m 倒着走到 1，算 dp[j] 时 dp[j−1] 还没被这一行碰过，是上一行的 dp[i−1][j−1]。要是正着走，dp[j−1] 已经是这一行刚算出来的，等于把 s[i−1] 用了一次又一次。

实测 8000 组随机样例，正序遍历有 2157 组算错（26.96%）。另外把加号写成 max 也错，8000 组里错 3195 组（39.94%）。「用」和「不用」是两种凑法，得加，取大就少算一大半。

// 空间压缩：j 必须倒着走。dp[j] 不赋值就还是上一行的 dp[j]，正好是「不用 s[i-1]」
    int numDistinct(string s, string t) {
        const int MOD = 1000000007;
        int n = s.size(), m = t.size();
        vector<int> dp(m + 1, 0);
        dp[0] = 1;
        for (int i = 1; i <= n; i++) {
            for (int j = m; j >= 1; j--) {
                if (s[i - 1] == t[j - 1]) {
                    dp[j] = (dp[j] + dp[j - 1]) % MOD;
                }
            }
        }
        return dp[m];
    }

n = m = 3000 实测：二维表（int，带取模）6.71 ms、34 MB；一维 3.29 ms、12 KB。省下的主要是内存。

演示一：不同子序列，二维表与一维数组的逐格填法

三、编辑距离：三个方向，三种代价

题目：把 word1 变成 word2，插入一个字符代价 a，删除一个字符代价 b，替换一个字符代价 c。三种代价相等且都等于 1 时，就是那个最常考的版本。

定义 dp[i][j]：s1 前 i 个变成 s2 前 j 个的最小代价。看两个串的最后一个字符：

  • 相等，它们配在一起不花钱，dp[i][j] = dp[i−1][j−1]；
  • 不等，最后一步动作只有三种：删掉 s1[i−1]，代价 dp[i−1][j] + b；在末尾插入 s2[j−1]，代价 dp[i][j−1] + a；把 s1[i−1] 换成 s2[j−1]，代价 dp[i−1][j−1] + c。

首行首列别写反。dp[i][0] 是把 s1 前 i 个全删光，i × b；dp[0][j] 是从空串插出 s2 前 j 个，j × a。a 和 b 相等时写反看不出来，不等就露馅：实测 8000 组里 a ≠ b 的有 6356 组，写反之后 5017 组算错（78.9%）。

// dp[i][j] : s1 前 i 个变成 s2 前 j 个的最小代价
    // a = 插入一个字符，b = 删除一个字符，c = 替换一个字符
    int editDistance(string s1, string s2, int a, int b, int c) {
        int n = s1.size(), m = s2.size();
        vector<vector<int>> dp(n + 1, vector<int>(m + 1, 0));
        for (int i = 1; i <= n; i++) {
            dp[i][0] = i * b;                        // s2 是空的，全删掉
        }
        for (int j = 1; j <= m; j++) {
            dp[0][j] = j * a;                        // s1 是空的，全插上
        }
        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= m; j++) {
                if (s1[i - 1] == s2[j - 1]) {
                    dp[i][j] = dp[i - 1][j - 1];     // 末尾一样，直接配上，不花钱
                } else {
                    dp[i][j] = min(min(dp[i - 1][j] + b, dp[i][j - 1] + a), dp[i - 1][j - 1] + c);
                }
            }
        }
        return dp[n][m];
    }

horse → ros 在 a = b = c = 1 时答案是 3：h 换成 r、删掉一个 r、删掉 e。把代价换成 a = 5、b = 3、c = 4，同一张表的答案变成 10。插入变贵之后，「删完再插」这条路基本走不通了。

四、编辑距离的空间压缩：leftUp 从哪来

依赖里有左上角这个斜向格子，只留一行时它被覆盖掉了，得拿变量单独存。填 dp[j] 之前把旧值存进 backup，填完之后 backup 就是下一格的左上角。

两个容易写漏的点。一是每行开头 leftUp = (i − 1) * b，第一格的左上角是 dp[i−1][0]。二是别把 leftUp 写成 dp[j−1]，那是拿「左」当「左上」，实测 8000 组里错 6196 组（77.45%）。

// 空间压缩：leftUp 是想象中的 dp[i-1][j-1]，backup 必须在覆盖 dp[j] 之前存
    int editDistanceRoll(string s1, string s2, int a, int b, int c) {
        int n = s1.size(), m = s2.size();
        vector<int> dp(m + 1, 0);
        for (int j = 1; j <= m; j++) {
            dp[j] = j * a;
        }
        for (int i = 1, leftUp, backup; i <= n; i++) {
            leftUp = (i - 1) * b;                    // 这一行开头，左上角是 dp[i-1][0]
            dp[0] = i * b;
            for (int j = 1; j <= m; j++) {
                backup = dp[j];                      // 覆盖前的旧值，下一格的左上角
                if (s1[i - 1] == s2[j - 1]) {
                    dp[j] = leftUp;
                } else {
                    dp[j] = min(min(dp[j] + b, dp[j - 1] + a), leftUp + c);
                }
                leftUp = backup;
            }
        }
        return dp[m];
    }

n = m = 3000 实测：二维表 21.82 ms、34 MB；一维 16.40 ms、11.7 KB。这里时间差得不多，因为一维版多了一个变量的搬运；内存差了三千倍。

五、交错字符串：只依赖上和左

题目：s3 是否由 s1 和 s2 交错组成，两个串内部的顺序都得保持。

定义 dp[i][j]：s1 前 i 个和 s2 前 j 个，能不能交错出 s3 的前 i + j 个。长度为 i + j 的这一格的最后一个字符是 s3[i+j−1]，它只能来自两个地方：

  • 来自 s1[i−1]，要求 s1[i−1] == s3[i+j−1] 且 dp[i−1][j] 成立；
  • 来自 s2[j−1]，要求 s2[j−1] == s3[i+j−1] 且 dp[i][j−1] 成立。

两个都不成立就是 false。长度不等先返回 false，不然连表都填不满。

// dp[i][j] : s1 前 i 个和 s2 前 j 个，能否交错组成 s3 的前 i+j 个
    bool isInterleave(string s1, string s2, string s3) {
        int n = s1.size(), m = s2.size();
        if (n + m != (int)s3.size()) {
            return false;                            // 长度对不上，直接否掉
        }
        vector<vector<int>> dp(n + 1, vector<int>(m + 1, 0));
        dp[0][0] = 1;
        for (int i = 1; i <= n; i++) {               // 只用 s1 的那一列
            if (s1[i - 1] != s3[i - 1]) break;
            dp[i][0] = 1;
        }
        for (int j = 1; j <= m; j++) {               // 只用 s2 的那一行
            if (s2[j - 1] != s3[j - 1]) break;
            dp[0][j] = 1;
        }
        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= m; j++) {
                dp[i][j] = (s1[i - 1] == s3[i + j - 1] && dp[i - 1][j]) ||
                           (s2[j - 1] == s3[i + j - 1] && dp[i][j - 1]);
            }
        }
        return dp[n][m];
    }

这一格只依赖「上」和「左」，没有斜向依赖，压缩时 j 正着走就行：dp[j] 是上一行的（上），dp[j−1] 是这一行刚算的（左）。反过来倒着走会把「左」盖成上一行的值，实测 8000 组里错 2345 组（29.31%）。

// 空间压缩：只依赖「上」和「左」，j 正着走即可，dp[j] 自带上一行的值
    bool isInterleaveRoll(string s1, string s2, string s3) {
        int n = s1.size(), m = s2.size();
        if (n + m != (int)s3.size()) {
            return false;
        }
        vector<int> dp(m + 1, 0);
        dp[0] = 1;
        for (int j = 1; j <= m; j++) {
            if (s2[j - 1] != s3[j - 1]) break;
            dp[j] = 1;
        }
        for (int i = 1; i <= n; i++) {
            dp[0] = (s1[i - 1] == s3[i - 1] && dp[0]);
            for (int j = 1; j <= m; j++) {
                dp[j] = (s1[i - 1] == s3[i + j - 1] && dp[j]) ||
                        (s2[j - 1] == s3[i + j - 1] && dp[j - 1]);
            }
        }
        return dp[m];
    }

n = m = 3000 实测：二维 14.15 ms，一维 4.04 ms。布尔表的二维版本除了慢，还有 9 MB 的 vector<vector<bool>> 开销。

演示三：交错字符串，逐格看能不能到

六、复杂度分析

题目时间复杂度空间复杂度压缩后
不同的子序列O(n · m)O(n · m)O(m)
编辑距离O(n · m)O(n · m)O(m)
交错字符串O(n · m)O(n · m)O(m)

n 和 m 是两个串的长度。三张表都是 (n+1) × (m+1)，每格只做常数次比较和算术，时间都是 O(n · m)。

空间上二维表是 O(n · m)，n = m = 3000 时 int 表 34 MB。三题都只依赖上一行，压成一维后是 O(m)，12 KB 上下。压缩有没有代价？编辑距离那题有：多一个 leftUp 变量要维护，代码比二维版难读，时间也从 21.82 ms 变成 16.40 ms 这个量级的差别（反而更快，因为一维数组对缓存友好）。

七、总结

三道题的表长得很像，写起来却是三个不同的方向：不同子序列的 j 要倒着走（左上被自己覆盖），交错字符串的 j 要正着走（左边就得是这一行的新值），编辑距离两个都不行，只能拿变量把左上角存下来。判断依据只有一个：转移式里 dp[j−1] 该代表上一行还是这一行。

另外两处容易出错：编辑距离的首行首列分别对应删和插，代价参数不同时不能互换；不同子序列的「用」和「不用」要相加，取 max 会少算一大半。后面讲背包动态规划时还会遇到「倒着走」这个手法，到时候会发现是同一件事。
