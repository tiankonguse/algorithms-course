逆元：把除法换成乘法

加法、减法、乘法都能让中间结果直接取余，除法不行。10 / 5 对 3 取余是 2，可 10 % 3 除以 5 % 3 得到 0。要让除法也能在取余的世界里算，得先把除数换成它的逆元。

零、除法这里断了

取余的好处是中间结果永远待在模数以内，不会溢出。加法、减法、乘法都能放心地边算边取余：加完取一次、减完加一个模数再取一次、乘完取一次，最后的结果跟「算完真值再取余」一模一样。

除法没有这个性质。拿 10 / 5 对 3 取余来说，正确做法是先算 10 / 5 = 2 再对 3 取余，答案是 2；如果先把两头各自取余，10 % 3 = 1、5 % 3 = 2，1 / 2 在整数里是 0，答案变成 0。

错得有多频繁？随机造 2000 组满足条件的 (a, b, mod)，「中间取余再相除」有 96.20% 跟真值对不上，几乎每次都翻车。

问题出在整数除法本身会丢信息。1 / 2 的整数商是 0，可真值是 0.5；丢掉的那部分在取余的世界里补不回来。

一、逆元是什么

在模 p 的世界里，「除以 b」这件事等价于「乘以另一个数 x」，只要 x 满足 b · x % p = 1。这个 x 就叫做 b 在模 p 意义下的逆元，记成 inv(b)，它就是 b 的倒数在模 p 里的样子。

拿 p = 13、b = 5 试一下，把 5 乘上 1 到 12 的每个数看看余数落在哪。

12 个余数正好是 1 到 12 各出现一次，一个不重。这两件事合起来就是逆元一定存在的理由：既然 12 个数两两不同又都落在 1 到 12 之间，那 1 必然被某个数取到。

p = 13 时 1 到 12 的逆元依次是：1、7、9、10、8、11、2、5、3、4、6、12。首尾两个数是自己的逆元（1 × 1 = 1、12 × 12 = 144 = 13 × 11 + 1），其余两两配对。

二、费马小定理给出求法

逆元怎么算？枚举 1 到 p − 1 太慢，p 是 109 量级时根本跑不完。费马小定理给了一条近路：p 是质数、b 和 p 互质时，

bp−1 % p = 1　→　b · bp−2 % p = 1　→　bp−2 就是 b 的逆元。

于是求逆元变成求一次快速幂，代价是 O(log p)。mod = 1000000007 时指数是 1000000005，二进制 30 位、其中 15 个 1，对应 29 次平方加 14 次乘法，一共 43 次模乘。实测跑 100 万次求逆元累计 132.996 毫秒，单次约 133 纳秒。

三条前提缺一不可，题目数据都会给足：a / b 必须能整除；mod 必须是质数；b 和 mod 必须互质。

前两条还值得多说一句。a / b 不能整除时，真值那一栏本身就没意义，逆元法算出来的东西也不该拿去比。mod 是合数时，bmod−2 不是逆元：拿 4 到 21 之间的合数当模数跑两万组，逆元法有 70.03% 算错；把里面 b 与 mod 互质的那些挑出来单独看，仍有 52.50% 算错。互质只保证逆元存在，不保证它等于 bmod−2，那一步要的是欧拉定理里的 φ(mod)，而费马小定理只在质数下才有 φ(p) = p − 1。

第三条也好理解：mod = 7、b = 7、a = 14 时，真值是 2，逆元法算出 0，因为 75 % 7 = 0，而 0 乘任何数都是 0。

快速幂是这一讲的地基，顺手放一份：

// 乘法快速幂：b 的 n 次方 % mod
    long long power(long long b, long long n, long long mod) {
        long long ans = 1;
        while (n > 0) {
            if ((n & 1) == 1) {
                ans = (ans * b) % mod;
            }
            b = (b * b) % mod;
            n >>= 1;
        }
        return ans;
    }

求逆元就是拿它算一次 bmod−2，两种写法只差两行：

// 前提：a / b 能整除、mod 是质数、b 与 mod 互质
    // 笨办法：先做除法，最后取余
    long long compute1(long long a, long long b, int mod) {
        return (a / b) % mod;
    }

    // 正解：把除法换成乘以 b 的逆元
    long long compute2(long long a, long long b, int mod) {
        long long inv = power(b, mod - 2, mod);   // 费马小定理
        return ((a % mod) * inv) % mod;
    }

题目 1 就到这里，它是一道理念验证题：造一批满足三条前提的 (a, b, mod)，让两个算法互相印证。

三、求 1 到 n 所有数的逆元

真到用的时候，1 到 n 每个数的逆元往往都要。逐个用快速幂是 O(n log p)，n = 3 × 106 时外推约 300 毫秒，很多题卡在这个常数上。

有一条 O(n) 的线性递推。设 p = k · i + r，其中 k = p / i、r = p % i，两边同时对 p 取余：

k · i + r ≡ 0 (mod p)　→　两边乘 inv(i) · inv(r)　→　k · inv(r) + inv(i) ≡ 0　→　inv(i) = p − k · inv(r) % p。

r = p % i 严格小于 i，所以 inv(r) 在算 inv(i) 之前就已经躺在表里了。这就是它能从左往右一遍扫完的原因，也是它要求 n < p 的原因。

inv(1) = 1 得单独给，公式在 i = 1 时会去查 inv(0)，那是没有定义的东西。

// inv[i] 表示 i 在 % p 意义下的逆元，要求 n < p 且 p 为质数
    void build(int n, int p) {
        inv[1] = 1;
        for (int i = 2; i <= n; i++) {
            // p = (p / i) * i + p % i
            inv[i] = (int)(p - (long long)inv[p % i] * (p / i) % p);
        }
    }

n = 3 × 106、p = 109 + 7 时这条递推跑 4.361 毫秒，逐个快速幂按 n = 105 实测 9.985 毫秒外推到 3 × 106 约 299.5 毫秒，差 69 倍。代价是一张 int 表，n = 3 × 106 时 11.4 MB。

这道题（题目 2）卡常数卡得厉害，连输入输出都得用快读快写。写递推式时三处地方容易写错，都在下面的演示里准备了开关。

第一处是 (long long) 强转。inv[p % i] * (p / i) 两项都能到 107 量级，乘积到 1014，int 装不下。实测漏掉强转之后，p 在 105 附近时 0.00% 的位置出错，p 到 106 时 98.45% 出错，p 到 2 × 107（题目上限 20000528）时 99.99% 出错。小模数下它一声不吭，一上强度就全线崩。

第二处是外面那个 p −。漏掉它，算出来的正好是答案的相反数（模 p 意义下的 p − inv(i)）。随机模数下 100.00% 的样例至少有一个位置对不上，p = 13 时 12 个位置里 6 个错、p = 41 时 16 个里 9 个错。有的位置两个数恰好撞上，靠抽查不容易发现。

第三处是起点。从 i = 1 开始套公式会读到没初始化的 inv(0)，实测 100% 的样例里至少一个位置错。

还有一条边界值得记住：n ≥ p 时会怎样？p = 101、递推到 300 时，从 i = 101 开始每一项的验算 i · inv(i) % p 都不等于 1，一共 200 个。原因是 i > p 之后 p / i = 0、p % i = p，递推退化成 inv(i) = p，也就是 0。题目给的 n < p 就是这个原因。

四、阶乘的逆元与组合数

组合数 C(n, m) = n! / (m! · (n − m)!) 里也有除法，同样要换成乘逆元。逐个求三个阶乘的逆元是三次快速幂，批量查询时太贵。

阶乘的逆元也有一条线性递推，方向反过来：先求出 n! 的逆元，再从右往左走。

1 / i! = (i + 1) / (i + 1)!　→　inv(i) = (i + 1) · inv(i + 1) % mod。

// fac[i] 是 i!，inv[i] 是 i! 的逆元
    void build(int limit, int mod) {
        fac[0] = 1;
        for (int i = 1; i <= limit; i++) {
            fac[i] = (long long)i * fac[i - 1] % mod;
        }
        // 只求一次 n! 的逆元，剩下的从右往左递推
        inv[limit] = power(fac[limit], mod - 2, mod);
        for (int i = limit - 1; i >= 0; i--) {
            inv[i] = (long long)(i + 1) * inv[i + 1] % mod;
        }
    }

整张表只要一次快速幂，剩下全是 O(1) 的乘法。n = 1000 时建表 0.0242 毫秒；给每个阶乘单独求逆元要 1001 次快速幂，实测 0.6583 毫秒，慢 27 倍；杨辉三角预处理 500500 次加法，实测 2.3092 毫秒。

建完之后每次查询是三次查表加两次取模：

// C(n, m) = n! / (m! * (n-m)!)，三次查表 O(1)
    long long C(int n, int m) {
        long long ans = fac[n];
        ans = ans * inv[m] % MOD;
        ans = ans * inv[n - m] % MOD;
        return ans;
    }

实测同样跑 100 万次查询，阶乘逆元累计 0.996 毫秒（单次约 1 纳秒），现算现求（每次 O(m) 次乘法加快速幂）累计 5150.773 毫秒（单次约 51 微秒）。顺带一提，杨辉三角查表只要 0.067 毫秒，比阶乘逆元还快，可它的建表是 O(n2) 的 500500 次加法，n 到 105 就开不出来了。

C(1000, 500) % 1000000007 = 159835829，C(537, 367) % 1000000007 = 787459994。

这里有个坑值得单独说：表长一旦跨过 mod，整张表就作废了。mod = 7 时把表开到 6，组合数全对；开到 7，fac(7) % 7 = 0，逆元从 0 出发往左推，每一项还是 0，于是所有 C(n, m) 全算成 0。n ≥ mod 的组合数得换 Lucas 定理，不在这一讲的范围里。

复杂度分析

做法关键操作时间空间

快速幂的轮数是指数的二进制位数，mod = 109 + 7 时 30 轮。线性递推把 n 个快速幂压成 n 次乘除取模，n = 3 × 106 时 4.361 毫秒对约 300 毫秒。阶乘逆元把 n 次快速幂压成一次，n = 1000 时 0.0242 毫秒对 0.6583 毫秒。空间都是一张 int 或 long long 表，n = 3 × 106 的 int 表 11.4 MB。

总结

加减乘可以边算边取余，除法必须先把除数换成逆元，否则「中间取余再相除」在随机数据上有 96.20% 算错。

逆元是满足 b · x % p = 1 的那个 x，费马小定理给出 bp−2，一次快速幂拿到，133 纳秒一次。前提是 mod 为质数、b 与 mod 互质、a / b 能整除，前两条不满足时它会静悄悄地给出错误答案。

要 1 到 n 每个数的逆元就走线性递推 inv(i) = p − (p / i) · inv(p % i) % p，O(n) 一遍扫完；要阶乘的逆元就先求 n! 的逆元再从右往左推，整张表只要一次快速幂。两处递推都只依赖「前一项」，所以省掉的是那 n 次快速幂。

写递推式时盯住三件事：(long long) 强转、外面那个 p −、i 从 2 而不是 1 起步。另外表长别跨过 mod，跨过去整张阶乘逆元表会全变成 0。

后面讲容斥原理的题会反复用到这里的组合数，那里每次 C(n, m) 都必须是 O(1) 的。
