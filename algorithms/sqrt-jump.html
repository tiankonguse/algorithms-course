答案跳变：最少划分与树上 k 路径

最后两道题要打印 k = 1 到 n 的全部答案。答案关于 k 单调，而且变化次数只有 n/k 量级，于是小规模直接算、大规模用二分答案一次跳过一整段。跳跃的分界线不再是 √n，要带上一个 log。

零、背景

题目 6 和题目 7 的形状是同一个：给定一个要求 k，求出在这个要求下的最优值，而且要把 k 从 1 到 n 的答案全打出来。朴素的做法是把每个 k 都算一遍，代价是 O(n) 乘 n，超时。

根号分治在这里的用法和前四道题不同。它不是「预处理对暴力」的切换，而是「算一次」对「跳一段」的切换：k 小的时候老老实实算，k 大的时候靠二分答案找出答案相同的那一整段，一次跳过去。

能这么跳的前提有两层。第一层是单调性：k 越大要求越松，答案越小。第二层是规模：答案本身是 n/k 量级，k 大到一定程度之后，答案能取到的值就没几个了。

一、题目6：最少划分

给定一个长度为 n 的数组 arr，考虑如下问题的解：数组 arr 划分成若干段子数组，保证每段不同数字的种类不超过 k，返回至少划分成几段。打印 k = 1, 2, 3 .. n 时所有的答案。1 ≤ arr[i] ≤ n ≤ 10⁵。测试链接：CF786C。

固定 k 之后，最优划分用贪心就能拿到：从左到右扫，能往当前段里放就放，放到会超就切一刀。这样切出来的每一段都是「在当前限制下能取的最长段」，段数自然最少。

实现贪心只需要一个 vis 数组。扫到 arr[i] 时，如果它在本段里没出现过，种类数加一；种类数要超过 limit 了，就在 i 这里切一刀，把本段的 vis 清空，种类数重新从 1 开始。清空是 O(段长)，每段只清一次，合起来 O(n)。

    
int query(int limit) {
        int kind = 0, cnt = 0, start = 1;
        for (int i = 1; i <= n; i++) {
            if (!vis[arr[i]]) {
                kind++;
                if (kind > limit) {
                    cnt++;
                    for (int j = start; j < i; j++) {
                        vis[arr[j]] = false;
                    }
                    start = i;
                    kind = 1;
                }
                vis[arr[i]] = true;
            }
        }
        if (kind > 0) {
            cnt++;
            for (int j = start; j <= n; j++) {
                vis[arr[j]] = false;
            }
        }
        return cnt;
    }

这里有个细节：清空 vis 的时候不能 memset，那样一次就是 O(n)。代码里按段清，段与段之间不重叠，总代价还是 O(n)。

二、题目7：树上 k 路径

给你一棵树，一共有 n 个节点，给定 n − 1 条边。树的路径是指从端点 x 到端点 y 的简单路径，k 路径是指路径的节点数正好为 k。整棵树希望分解成尽量多的 k 路径，k 路径的节点不能复用，所有 k 路径不要求包含所有点。打印 k = 1, 2, 3 .. n 时，k 路径最多有几条。测试链接：CF1039D。

固定 k 之后同样有贪心。自底向上看每个节点 u：它往下伸出去的、还没被分配成路径的最长链记成 max1[u]，次长链记成 max2[u]。如果 max1[u] + max2[u] + 1 不小于 k，两条链加上 u 自己就能凑出一条 k 路径，立刻凑掉，u 不再往上贡献；否则把最长链接上 u 继续往上送，长度是 max1[u] + 1。

这个贪心是对的，理由和题目 6 一样是「尽量往上凑」。能凑而不凑，这两条链后面只会更难凑出 k 个点，所以当场用掉不会变差。

处理顺序要保证「儿子的信息先算好」，代码里先 dfs 一次收集 dfn 序，之后每次查询都按 dfn 序倒着扫一遍，O(n) 出答案。每轮结束要把 len、max1、max2 清零，清零也是 O(n)。

    
int query(int k) {
        int cnt = 0;
        for (int i = n, cur, father; i >= 1; i--) {
            cur = dfnOrder[i];
            father = fa[cur];
            if (max1[cur] + max2[cur] + 1 >= k) {
                cnt++;
                len[cur] = 0;
            } else {
                len[cur] = max1[cur] + 1;
            }
            if (len[cur] > max1[father]) {
                max2[father] = max1[father];
                max1[father] = len[cur];
            } else if (len[cur] > max2[father]) {
                max2[father] = len[cur];
            }
        }
        for (int i = 1; i <= n; i++) {
            len[i] = max1[i] = max2[i] = 0;
        }
        return cnt;
    }

三、答案跳变与二分跳跃

两道题都要把 k = 1 到 n 的答案全打印出来，逐个算就是 O(n²)。先看答案能取到几个值。

题目 7 最直接：k 路径的节点不能复用，每条占 k 个点，所以答案一定不超过 n/k。题目 6 稍微绕一点：贪心切出来的相邻两段如果合并，种类数会超过 k，所以相邻两段的种类数之和大于 k；把所有相邻对加起来，左边不超过两倍的总种类数，也就是不超过 2n，于是段数小于 2n/k + 1。

两种情况都说明：k 越大，答案越小，而且小到 n/k 量级。取分界线 B，k 不超过 B 时直接算，代价 O(n·B)。k 大于 B 时答案不超过 C·n/B，也就是说在这一大段里答案最多变 C·n/B 次。

于是可以跳着算。已知 ans[i]，用二分在 [i, n] 里找「答案还等于 ans[i] 的最大位置」，一次就能跳到下一个答案变化的位置。跳跃次数不超过 C·n/B，每次跳跃要二分 O(log n) 轮，每轮一次 O(n) 的查询。

分界线因此不是 √n。总代价是 O(n·B + n²·log n / B)，令两边相等解出 B = √(n·log n)，代回去是 O(n·√(n·log n))。题解里常见的 O(n·√n·log n) 是取 B = √n 不做微调的结果，量级略松一档。

    
int jump(int l, int r, int curAns) {
        int find = l;
        while (l <= r) {
            int mid = (l + r) >> 1;
            int check = query(mid);
            if (check < curAns) {
                r = mid - 1;
            } else if (check > curAns) {
                l = mid + 1;
            } else {
                find = mid;
                l = mid + 1;
            }
        }
        return find + 1;
    }

    void compute() {
        for (int i = 1; i <= blen; i++) {
            ans[i] = query(i);
        }
        for (int i = blen + 1; i <= n; i = jump(i, n, ans[i])) {
            ans[i] = query(i);
        }
    }

题目 7 的跳跃部分和题目 6 一字不差，换掉 query 就能直接用。最后打印时，ans[i] 还是 −1 说明它落在某个平台里，取 ans[i − 1] 填上。

这里有个细节：query 关于 k 单调不增，所以 mid 处的答案只可能等于或者小于 ans[i]，代码里 check > curAns 那个分支按单调性走不到，留着只是写法上的完整。

四、复杂度分析

两道题的 query 都是 O(n)，差别只在一次 query 的常数。跳跃框架完全一致。

操作时间复杂度空间复杂度
题目6 单次 query(limit)（扫一遍，vis 按段清）O(n)O(n)：arr、vis、ans 各 O(n)，题目 7 多一份前向星与 dfn 序
题目7 单次 query(k)（按 dfn 序倒扫 + 清零）O(n)
k ≤ B 的部分（B 次直接 query）O(n·B)
k > B 的部分（跳 n/B 次，每次二分 log n 轮）O(n²·log n / B)
B 取 √(n·log n) 时的总代价O(n·√(n·log n))

n = 10⁵ 时 B 大约是 1300，小 k 那一半是 1.3 × 10⁸ 量级的基本操作，题目 7 的 query 常数比题目 6 大一些，但同一套框架下都能过。

五、最后

这一讲七道题走完，根号分治一共露了三次面。前四道题是「小规模预处理成表、大规模暴力枚举」，题目 5 只做状态规模的估算，最后两道题是「小规模逐个算、大规模二分跳过一整段」。

认出这类题的办法就一条：找一个参数，看操作的代价是不是随它单调变化，再看代价大的那一侧能不能用另一种方式压下去。分界线取 √n 还是 √(n·log n)，取决于两侧代价的具体形式。
