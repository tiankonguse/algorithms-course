状态转移：k 维 1 阶递推

元音序列和出勤记录里，状态是一堆互相转移的量：a 后面只能接 e，缺勤用掉一次就不能再缺，迟到连着三次就作废。把每类状态的数量排成一个向量，规则写成矩阵，n 给到 109 也照样算。

零、从「一个数」到「一堆数」

元音序列这道题：长度 n 的串，每个字母后面允许接哪几个字母是定死的，问合法串有多少个。直接数串会爆，但可以只记「以每个字母结尾的合法串数」，五个数字就够了。

规则摊开就是：a 后面只能跟 e；e 后面跟 a 或 i；i 后面不能跟 i，其余四个都行；o 后面跟 i 或 u；u 后面只能跟 a。

这里矩阵的填法换了另一套：每一行直接由转移规则决定，第 i 行第 j 列是 1 就表示从状态 i 可以一步走到状态 j。整个矩阵由递推表达式一次写出来，不用凑系数。

// 元音序列：状态是「以某个元音结尾的串数」，矩阵每一行写从它出发能去哪
    long long countVowelPermutation(long long n) {
    	Mat start(1, 5);
    	for (int i = 0; i < 5; i++) {
    		start.a[0][i] = 1;		// 长度为 1 时，a、e、i、o、u 各一种
    	}
    	Mat base(5, 5);
    	ll t[5][5] = {
    		{ 0, 1, 0, 0, 0 },		// a 后面只能跟 e
    		{ 1, 0, 1, 0, 0 },		// e 后面跟 a 或 i
    		{ 1, 1, 0, 1, 1 },		// i 后面不能跟 i，其余四个都行
    		{ 0, 0, 1, 0, 1 },		// o 后面跟 i 或 u
    		{ 1, 0, 0, 0, 0 }			// u 后面只能跟 a
    	};
    	for (int i = 0; i < 5; i++) {
    		for (int j = 0; j < 5; j++) {
    			base.a[i][j] = t[i][j];
    		}
    	}
    	Mat ans = multiply(start, matrixPower(base, n - 1));
    	long long ret = 0;
    	for (int i = 0; i < 5; i++) {
    		ret = (ret + ans.a[0][i]) % MOD;
    	}
    	return ret;
    }

起点是长度 1 时候的五个数，a、e、i、o、u 各一种，所以是全 1 向量。答案是五个分量之和：n = 1 得 5，n = 2 得 10，n = 3 得 19。

一、出勤记录：六个状态

这道题的条件是两条：整个记录里缺勤严格少于两天，且不存在连续三天或更长的迟到。合法的状态只需要两个信息描述：已经缺勤几天（0 或 1）、末尾连续迟到了几天（0、1、2）。乘起来正好 6 种组合。

转移规则看着表就能写：放 P 会把末尾迟到清零；放 L 让迟到数加一，加到 3 就不合法；放 A 让缺勤数变成 1，但如果已经缺勤过，就再也没有 A 这条路。表里有几格是空的，对应矩阵里那几格是 0。

// 出勤记录：状态是 (缺勤天数, 末尾连续迟到数)，编号见下表
    // s0(0,0)  s1(0,1)  s2(0,2)  s3(1,0)  s4(1,1)  s5(1,2)
    long long checkRecord(long long n) {
    	Mat start(1, 6);
    	ll s[6] = { 1, 1, 0, 1, 0, 0 };	// 长度为 1 时只有 P、L、A 三种
    	for (int i = 0; i < 6; i++) {
    		start.a[0][i] = s[i];
    	}
    	Mat base(6, 6);
    	ll t[6][6] = {
    		{ 1, 1, 0, 1, 0, 0 },		// 从 s0 出发：放 P、放 L、放 A
    		{ 1, 0, 1, 1, 0, 0 },		// 从 s1 出发
    		{ 1, 0, 0, 1, 0, 0 },		// 从 s2 出发：再迟一次就连续三天，只能放 P 或 A
    		{ 0, 0, 0, 1, 1, 0 },		// 从 s3 出发：缺勤已经用掉，不能再放 A
    		{ 0, 0, 0, 1, 0, 1 },		// 从 s4 出发
    		{ 0, 0, 0, 1, 0, 0 }			// 从 s5 出发
    	};
    	for (int i = 0; i < 6; i++) {
    		for (int j = 0; j < 6; j++) {
    			base.a[i][j] = t[i][j];
    		}
    	}
    	Mat ans = multiply(start, matrixPower(base, n - 1));
    	long long ret = 0;
    	for (int i = 0; i < 6; i++) {
    		ret = (ret + ans.a[0][i]) % MOD;
    	}
    	return ret;
    }

起点是长度 1 时的三个合法记录：P 对应状态 0、L 对应状态 1、A 对应状态 3，各自一种。n = 1 得 3，n = 2 得 8，n = 3 得 19。

三、只看总和会漏掉错误

元音的转移矩阵如果填反了（把「从 i 到 j」写成了「从 j 到 i」，也就是转置），答案是错的。可这个错法只对总和做验证时，n 从 1 取到 200 全部通过，抓取率 0.00%。

原因在式子的形状：起点是全 1 向量，末尾又是对所有分量求和，整个式子形如 1T · Mn-1 · 1。这是个标量，标量的转置等于自己，M 转置过来结果一点不变。

换成逐状态看，错误立刻现形：n = 2 时正解是 (3, 2, 2, 1, 2)，转置版是 (1, 2, 4, 2, 1)；n = 1 到 8 这八个长度里，有 7 个每个分量都对不上。

出勤那边换个错法：把「连续两个 L 之后再接一个 L」这条转移删掉，n 从 1 到 200 抓取率 99.00%，只有最前面两项撞上。所以这类题的验证要么逐状态核对，要么拿小 n 的穷举当参照。

复杂度分析

做法关键操作时间空间
逐位递推n 轮，每轮 k2 次转移O(n · k2)O(k)
矩阵快速幂log n 次 k 阶矩阵相乘，每次 k3 次乘加O(k3 · log n)O(k2)

状态数是题面给的：元音 5 个，出勤 6 个。k = 5 时一次矩阵相乘 125 次乘加，k = 6 时 216 次，log2 109 ≈ 30 轮，总量都在几千次乘加以内。实测元音 n = 109 单次 0.0057 ms，出勤单次 0.0104 ms。顺带一个对照：拿 5 个字母穷举所有串，n = 8 时是 39 万条，n = 10 就是 976 万条，这条路走不远。

总结

状态不只是一个数的时候，把每类状态的数量排成向量，一步转移写成一个方阵，这就是 k 维 1 阶递推。

矩阵逐行由转移规则决定：能一步从 i 走到 j 就填 1，不能就填 0。第 0 列写系数那套是给 1 维 k 阶递推用的，两种填法别混。

起点向量装的是长度 1 时各状态的合法数量，答案通常是把所有分量求和（元音、出勤都是这样）。

转移关系说不清的时候，先画一张「状态 × 动作 → 去向」的表，表列完了矩阵也就写完了。

验证这类题别只看总和。起点全 1、答案求和的时候，矩阵转置过来总和一模一样，得逐状态比对或者拿小 n 的穷举当参照。
