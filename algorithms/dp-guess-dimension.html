贿赂怪兽：状态装钱还是装能力

同一套转移写两遍：一遍让 dp 的两个下标是「怪兽编号 + 钱」，另一遍是「怪兽编号 + 能力」。代码几乎一样，可表能不能开出来，差着好几个数量级。选哪一维，看两个和谁小。

零、一只怪兽，两个选择

从 1 号怪兽走到 n 号。你的能力一开始是 0，当前能力小于第 i 只怪兽的能力 a[i]，就必须花 b[i] 的钱贿赂它；当前能力大于等于 a[i]，可以直接走过去，能力不变。

能走过去的时候也可以照样贿赂，花的钱照样掏，但它会加入你，a[i] 直接累加到能力上。

问通过所有怪兽最少花多少钱。

先看一个小例子。a = [2, 10, 3]，b = [1, 4, 2]。三只怪兽都不贿赂，能力一直是 0，第一只就打不过，所以必须掏钱。

这里有个细节：能走过去而不贿赂，能力不会涨。所以「现在能力够」不等于「以后一直够」，后面还可能碰到更大的怪兽。

一、先想「钱」这一维

最自然的想法是把「花了多少钱」当状态。设 dp[i][j] 是：花的钱不超过 j，通过前 i 只怪兽能达到的最大能力。

为什么记「最大能力」？因为能力只有好处没有坏处：同样的钱能到 100 的能力，就比只到 50 强，以后需要的贿赂只会更少。所以每个钱数下只需要保留最大的那一个能力。

转移两条，二选一取大：

1）不贿赂。dp[i-1][j] >= a[i] 才走得过去，能力不变。

2）贿赂。dp[i-1][j - b[i]] 有解，能力变成 dp[i-1][j - b[i]] + a[i]。

走不通的格子记成一个不可能的数，最后从前往后扫 dp[n][*]，第一个说得通的钱数就是答案。

// dp[i][j] : 花的钱不超过 j，通过前 i 只怪兽，能达到的最大能力
    // 达不到就记成一个不可能的数
    const long long MINF = LLONG_MIN / 4;

    for (int i = 1; i <= n; i++) {
        for (int j = 0; j <= sumB; j++) {
            dp[i][j] = MINF;
            if (dp[i - 1][j] >= a[i]) {                  // 能力够，直接走过去
                dp[i][j] = dp[i - 1][j];
            }
            if (j - b[i] >= 0 && dp[i - 1][j - b[i]] != MINF) {   // 贿赂它，能力累加
                dp[i][j] = max(dp[i][j], dp[i - 1][j - b[i]] + a[i]);
            }
        }
    }
    for (int j = 0; j <= sumB; j++) {
        if (dp[n][j] != MINF) { return j; }              // 第一个说得通的钱数就是答案
    }

第一行 dp[0][j] 全是 0：0 只怪兽都通过了，能力还是 0。这个初值不少写，写成「不可能」会让所有格子都传不下去。

二、压缩成一维，j 必须从大到小

第 i 行只用到第 i-1 行，一维就够。但要记住 dp[j] 在更新前代表「上一只怪兽结束时、钱不超过 j」。

j 从 sumB 往 0 走，读到的 dp[j - b[i]] 还没被本轮改过，是上一只怪兽的值。反过来从小到大走，读到的就是本轮刚写进去的，同一只怪兽会被反复贿赂，答案直接偏小。

// 只留一行：j 从大到小走，用到的 dp[j - b[i]] 还是上一只怪兽留下的
    vector<long long> dp(sumB + 1, 0);
    for (int i = 1; i <= n; i++) {
        for (int j = sumB; j >= 0; j--) {
            long long cur = MINF;
            if (dp[j] >= a[i]) {
                cur = dp[j];
            }
            if (j - b[i] >= 0 && dp[j - b[i]] != MINF) {
                cur = max(cur, dp[j - b[i]] + a[i]);
            }
            dp[j] = cur;
        }
    }

实测这个错法抓得干干净净：两万组随机数据里，正序版本和正确版本答案不同的比例是 100.00%。

三、换一维：把「能力」当状态

现在换个问题问自己：如果钱的范围大得离谱，钱这一维开不出来呢？那就把状态换成能力。

设 dp[j] 是：能力正好是 j，并且已经能通过前面所有怪兽，最少要花多少钱。这次每个能力保留的是「花得最少」的那一个。

转移同样两条，取小：

1）不贿赂。j >= a[i] 时可以直接过，钱不变。

2）贿赂。能力从 j - a[i] 涨上来，代价是 b[i]。

// 换一维：dp[j] 是「能力正好是 j 时，至少得花多少钱」
    vector<long long> dp(sumA + 1, INF);
    dp[0] = 0;
    for (int i = 1; i <= n; i++) {
        for (int j = sumA; j >= 0; j--) {
            long long cur = INF;
            if (j >= a[i] && dp[j] != INF) {              // 打得动就可以不花这笔钱
                cur = dp[j];
            }
            if (j - a[i] >= 0 && dp[j - a[i]] != INF) {   // 打不动必须贿赂，能力涨 a[i]
                cur = min(cur, dp[j - a[i]] + b[i]);
            }
            dp[j] = cur;
        }
    }

这次初值是 dp[0] = 0（0 只怪兽、能力 0、花钱 0），其余是无穷大。收尾也不一样：一边从前往后扫，找第一个有解的钱数；另一边在 dp[*] 里取最小值。

四、选哪一维：看哪个和更小

两套代码开销只跟「状态那个下标的取值范围」有关：钱做状态是 sumB + 1 格，能力做状态是 sumA + 1 格，其中 sumA 是所有 a[i] 的和、sumB 是所有 b[i] 的和。

题目只说 a[i] 的范围很大、b[i] 的范围不大，那就该往钱做状态这条路上想。反过来一样。要盯的是两个「和」有多大，单个数的范围说明不了什么。

拿两组数据量一下，n 都是 1000：

数据甲，a[i] 取 108 到 109、b[i] 取 1 到 100。这时 sumB = 49309，钱做状态的表 49310 格、0.38 MB，跑完 57.7 ms；而 sumA = 548971251697，能力做状态的表要 5.5×1011 格，约 4090 GB，根本开不出来。

数据乙把两个范围对调。这时 sumA = 49008，能力做状态 0.37 MB、25.6 ms 就出结果；钱做状态的表要 3.9×1011 格。

顺带说一句内存。二维版在 n=300、sumB=15898 时表占 36.5 MB、7.7 ms；压缩成一行只有 0.12 MB、3.0 ms。这已经不只是常数倍的差距：n 一大就是能不能开出来的区别。

七、写错的地方

1）压缩版 j 正序遍历，同一只怪兽被反复贿赂。抓取率 100.00%，两万组里一组都躲不掉。

2）「能力够就一律不贿赂」。这个看着像贪心，其实不成立：多花一笔钱换来的能力，可能省掉后面更大的一笔。两万组随机数据里抓出 8.64%。它抓得少不代表它对，只说明随机小数据里很少出现「现在够、以后不够」的弯子。

3）把 dp 里的值声明成 32 位。数据甲里 dp 存的是能力，能累加到 5.5×1011，是 int 上限的 255.6 倍；数据乙里 dp 存的是钱，能累加到 5.2×1011，241.6 倍。

4）第一行初值写错。钱做状态时 dp[0][j] 全是 0，能力做状态时只有 dp[0][0] 是 0。写成同一个不可能值，整张表都传不下去。

四个实现与暴力对拍过 6000 组随机数据（n 不超过 9，三种值域配比），0 处不一致。

八、复杂度分析

状态维度状态数单次转移时间空间
钱（装最大能力）(n+1)×(sumB+1)O(1)O(n·sumB)O(n·sumB)，压缩后 O(sumB)
能力（装最少钱）(n+1)×(sumA+1)O(1)O(n·sumA)O(n·sumA)，压缩后 O(sumA)

空间上压缩版把一维砍掉，时间上一维枚举的次数没变，所以实际能跑多大只由「选中的那个和」决定。上面两组数据里能用的那一维都在 5 万格上下，用不了的那一维都在 1011 格量级。

九、总结

要带走的是三件事。第一，状态维度不唯一：同一道题可以装钱也可以装能力，装哪个由两个和的大小决定。第二，两种定义下「值」的量级也跟着换：装钱时格子里是能力，装能力时格子里是钱，两边都可能到 1011 量级，要用 64 位。第三，压缩成一维以后，枚举顺序由「转移用的是不是本轮的格子」决定，这里必须倒序。

后面两道题会遇到另一种情况：整个 dp 表格都摆不下，只能换一个完全不同的做法。
