离散化

值的范围很大，但真正用到的值没几个。收集起来排序去重，只保留大小关系，大值域就压成了小下标。

零、背景

比赛里经常遇到这类题：给出 n 个区间，问某个位置最多被多少个区间覆盖。

位置的取值范围可能到 10⁹，而 n 只有 10⁵。按位置开数组需要 10⁹+1 个格子，内存直接爆炸。

处理这类问题的常规操作是离散化，也叫坐标压缩。下面用一个具体的问题把它讲清楚。

一、问题

有 n 个会议，第 i 个会议占用 [s_i, e_i) 这段时间，即 e_i 时刻会议室已经空出来了。问最少需要几间会议室。

例如 5 个会议：

  • [5, 12)、[3, 7)、[7, 15)、[12, 20)、[3, 10)

这里用小整数举例，方便画图。真实题目里换成 10⁹ 量级的时间戳，做法完全一样。

二、朴素做法

最顺手的做法是差分。准备一个数组 diff，下标就是时刻，会议起点加 1，终点减 1。

int diff[MAXV + 1];               // 下标就是时刻
for (auto& m : meetings) {
    diff[m[0]]++;                  // 会议开始
    diff[m[1]]--;                  // 会议结束
}

之后从头到尾扫一遍，前缀和的最大值就是答案，复杂度是 O(V + n)，V 是值域大小。

问题在于 V 可能是 10⁹，这个数组开不出来。

三、离散化

可以发现，diff 只会在会议端点处发生变化。

看两个相邻的端点，比如 7 和 10。这中间既没有会议开始，也没有会议结束，所以正在进行的会议数一直是 3。时刻 8 和 9 都不是端点，它们的值和 7 完全一样，属于陪跑。

5 个会议只有 10 个端点，去掉重复的只剩 7 个不同的值。既然如此，就没必要给 10⁹ 个时刻各开一个格子，给这 7 个值各开一个格子就够了。

离散化做的就是这件事：把原始值换成「第几小」，只保留大小关系和相等关系。整个预处理固定三步，收集、排序去重、映射，代码也是这三步的直接翻译。

vector<ll> vals;                      // 排序去重后的所有端点
unordered_map<ll, int> valToIdx;        // 原始值 → 压缩下标

void InitDiscretization(const vector<vector<int>>& meetings) {
    vals.reserve(meetings.size() * 2);   // 每个会议 2 个端点，一次性预留
    for (auto& m : meetings) {
        vals.push_back(m[0]);          // 起点
        vals.push_back(m[1]);          // 终点
    }
    sort(vals.begin(), vals.end());                // 排序
    vals.erase(unique(vals.begin(), vals.end()), vals.end()); // 去重
    for (int i = 0; i < vals.size(); i++) {
        valToIdx[vals[i]] = i;                // 映射：值 → 下标
    }
}

这里有两个细节。reserve 是把空间一次要够，避免 push_back 时反复搬家。unique 不会真的删除元素，它把重复项挤到末尾并返回新结尾，所以要配合 erase 才能真正缩短数组。

四、第一步：收集

不管值长什么样，先把所有会用到的值都塞进数组 vals。拖动滑块，看它是怎么长大的。

演示 ①　收集：每个会议贡献 2 个端点
5
会议起点 s 会议终点 e

会议有 n 个，端点就有 2n 个。这一步只是抄一遍，复杂度 O(n)。

五、第二步：排序去重

排序之后，相同的值必然挨在一起，扫一遍就能把重复的挑出来。点一下按钮，看哪些格子被丢掉。

演示 ②　sort + unique：重复项只留一个
重复项（被挤到末尾后删掉）

去重之后 vals = [3, 5, 7, 10, 12, 15, 20]，长度 k = 7。原来 0 到 10⁹ 的值域，现在只要 7 个格子。

六、第三步：映射

vals 已经有序且互不相同，排在第 i 位就是一个天然编号。于是规定：值为 vals[i] 的端点，压缩后的下标就是 i。

演示 ③　映射表：valToIdx[原值] = 下标
3
当前查的这一对映射

有了映射，原来按值开数组，改成按下标开数组即可：diff[GetIdx(s)]++、diff[GetIdx(e)]--。

查下标有两种写法。一种是哈希表，预处理时把映射存进 unordered_map，之后查询是 O(1)。

// 写法一：哈希表，查询 O(1)，代价是多开一张表
int GetIdx(ll v) { return valToIdx[v]; }

另一种不存哈希表，直接在 vals 上二分，查询是 O(log k)。

// 写法二：二分，不用哈希表，查询 O(log k)
int GetIdxByBinarySearch(ll v) {
    return lower_bound(vals.begin(), vals.end(), v) - vals.begin();
}

查询次数非常多时，哈希表更划算；次数不多时用二分就够了，还能省一份空间。二分版有个前提，v 一定在 vals 里，否则要先判断。

七、回到会议室

把每个会议的 +1 与 −1 打到压缩后的坐标上，再扫一遍求前缀和的最大值。拖动滑块跟着扫。

演示 ④　在压缩后的坐标上做差分扫描
0
同时进行数量最大的时刻 当前扫描位置

答案是 3。[5, 7) 和 [7, 10) 这两段时间里都同时有 3 个会议在进行，所以至少要 3 间会议室。

八、代码

#include <bits/stdc++.h>
using namespace std;
using ll = long long;

vector<ll> vals;                       // 排序去重后的所有端点
unordered_map<ll, int> valToIdx;        // 原始值 → 压缩下标

void InitDiscretization(const vector<vector<int>>& meetings) {
    vals.reserve(meetings.size() * 2);
    for (auto& m : meetings) {
        vals.push_back(m[0]);
        vals.push_back(m[1]);
    }
    sort(vals.begin(), vals.end());
    vals.erase(unique(vals.begin(), vals.end()), vals.end());
    for (int i = 0; i < vals.size(); i++) {
        valToIdx[vals[i]] = i;
    }
}

int GetIdx(ll v) { return valToIdx[v]; }   // O(1) 查下标

int main() {
    vector<vector<int>> meetings = {{5,12},{3,7},{7,15},{12,20},{3,10}};
    InitDiscretization(meetings);

    int k = vals.size();                  // 压缩后只有 7 个坐标
    vector<int> diff(k + 1, 0);
    for (auto& m : meetings) {
        diff[GetIdx(m[0])]++;         // 会议开始：+1
        diff[GetIdx(m[1])]--;         // 会议结束：−1
    }

    int cur = 0, ans = 0;
    for (int i = 0; i < k; i++) {
        cur += diff[i];
        ans = max(ans, cur);
    }
    cout << k << endl;      // 7
    cout << ans << endl;    // 3
    return 0;
}

九、复杂度分析

设 n 为会议个数，端点共 2n 个，去重后 k 个不同的值，k ≤ 2n。

收集是扫一遍，O(n)。排序是 2n 个元素排序，O(n log n)，写成 O(k log k) 也一样。unique 和 erase 各扫一遍，O(k)。建映射是往哈希表塞 k 项，O(k)。

瓶颈在排序，所以预处理的总复杂度是 O(n log n)。之后的差分是 O(n)，扫描是 O(k)。

操作时间复杂度
收集端点 push_backO(n)
排序 sortO(k log k)，即 O(n log n)
去重 unique + eraseO(k)
建映射 valToIdxO(k)（期望）
查下标（哈希表）O(1)（期望）
查下标（lower_bound 二分）O(log k)
预处理总计O(n log n)

空间上，vals 存 k 个值，哈希表存 k 项，都是 O(k)，也就是 O(n)。不建哈希表只用二分的话，额外空间就只有 vals 这一份。对比一下，不离散化需要 O(V)，V 是值域大小，这正是离散化要消灭的开销。

十、最后

离散化本身不解决任何问题，它是个前置工具。把值域压到 O(n)，后面的差分、树状数组、线段树、扫描线才开得下，也才跑得动。

用的时候有一个地方容易错：所有会被用到的值都要收集进来。比如会议室这道题，只收集起点忘了终点，映射出来的下标就是错的。

另外，离散化只保留大小关系和相等关系，两个值之间差了多少会被丢掉。如果题目要求算距离、算区间长度，就不能直接这么压。
