二叉树与三种序的递归实现

一个递归函数什么都不做，只在一棵二叉树上走一圈，每个节点会被遇到三次。把打印语句放在第一次那个位置就是先序，第二次是中序，第三次是后序。三种遍历的代码差别，只有一行语句的位置。

零、背景

前面几讲处理的都是线性结构：数组、链表、栈、队列，节点排成一排，从头走到尾就完事。

二叉树是第一个带分叉的结构：从根出发，每个节点最多往下分两叉。走一遍还是 O(n)，但「走」的顺序有了讲究：同一个节点会被经过三次，你选哪一次输出，就得到不同的序列。

一、节点长什么样

三个字段：值、左孩子、右孩子。没有孩子就写 nullptr。

struct TreeNode {
        int val;
        TreeNode* left;
        TreeNode* right;
        TreeNode(int v) : val(v), left(nullptr), right(nullptr) {}
    };

顺手记一个数：n 个节点的树，指针一共 2n 个。除根以外每个节点被指一次，用掉 n−1 个，剩下 n+1 个全是空。这个 n+1 待会儿要用到。

本节全程用下面这棵 7 个节点的满二叉树做例子，节点值就是 1 到 7，从上到下、从左到右编号。

二、递归序：每个节点到三次

先写一个什么都不做的函数，它只在节点之间移动。

// 递归序：打印语句放在 1 / 2 / 3 哪个位置，就得到哪种序
    void f(TreeNode* head) {
        if (head == nullptr) {
            return;
        }
        // 1  第一次到达 head：先序在这里打印
        f(head->left);
        // 2  第二次到达 head：中序在这里打印
        f(head->right);
        // 3  第三次到达 head：后序在这里打印
    }

把 1、2、3 当成三个柜台，每个非空节点会在这三个柜台前各停一次。可以这么想：进函数算第一次，左子树跑完回来算第二次，右子树跑完回来算第三次，第三次之后这个函数就返回了。

把这棵树完整的递归序排出来，是 21 项（3×7），每一项是这个节点的第几次到达。

三个位置各到达 n 次，这个是对任意树形都成立的，因为它只是「每个非空节点进一次函数、中途被自己的两个递归调用切成三段」。

函数调用的总次数是 2n+1：n 个非空节点各一次，加上 n+1 个空指针各一次（空的那次进去就 return，是递归的出口）。实测把计数器塞进上面那个 f：

节点数 n位置 1位置 2位置 3调用总数其中空调用
111132
444495
7777158
121212122513

每个格子都落在「n」和「2n+1」上，一个不差。

三、打印语句挪个位置，就换了种序

把 cout << head->val 放进 1、2、3 中的一处，其余两处留空，就是三种遍历。

void preOrder(TreeNode* head) {
        if (head == nullptr) {
            return;
        }
        cout << head->val << " ";
        preOrder(head->left);
        preOrder(head->right);
    }

    void inOrder(TreeNode* head) {
        if (head == nullptr) {
            return;
        }
        inOrder(head->left);
        cout << head->val << " ";
        inOrder(head->right);
    }

    void posOrder(TreeNode* head) {
        if (head == nullptr) {
            return;
        }
        posOrder(head->left);
        posOrder(head->right);
        cout << head->val << " ";
    }

三种序把一棵树拍平之后，都是「左子树一段、根一个、右子树一段」这三块，只是排列不同。

对开头那棵 7 节点树实测：

遍历顺序输出根在第几个
先序根 左 右1 2 4 5 3 6 7第 1 个
中序左 根 右4 2 5 1 6 3 7第 4 个
后序左 右 根4 5 2 6 7 3 1第 7 个

中序里根排第 4，恰好是左子树的 3 个节点之后。中序的定义就保证左子树整段排在根前面，所以根的位置 = 左子树节点数 + 1。

四、三种序分别适合干什么

先序：根在最前面，适合「先处理根，再往下传」。序列化一棵树、复制一棵树、从根往下带一个前缀，都用先序。

中序：左子树整段在根左边、右子树整段在根右边。放到二叉搜索树上，左子树全小于根、右子树全大于根，中序输出就是升序。实测 2000 组随机 BST，中序全部有序。

后序：根在最后，两个子树都处理完才轮到自己。求树高、统计子树大小、释放整棵树，都只能用后序。

// 后序：两个儿子的信息都算完了，才轮到自己
    int height(TreeNode* head) {
        if (head == nullptr) {
            return 0;
        }
        return 1 + max(height(head->left), height(head->right));
    }

    // 后序：先放掉两个儿子，最后 delete 自己，不会留下悬空指针
    void freeTree(TreeNode* head) {
        if (head == nullptr) {
            return;
        }
        freeTree(head->left);
        freeTree(head->right);
        delete head;
    }

释放那件事别换成先序：先 delete head，再去访问 head->left，读的是已经还给系统的内存。中序也不行，delete 完根之后右子树就找不着了。

五、代价

时间 O(n)：三个位置各 n 次到达，加上 n+1 次空调用，一共 4n+1 次常数操作。实测 n = 106 的完全二叉树，先序 2.330 ms、中序 2.018 ms、后序 2.239 ms；n 翻一倍时间也翻一倍（10 万 0.199 ms、20 万 0.402 ms、40 万 0.847 ms、80 万 1.749 ms），线性得很干净。

额外空间是 O(h)，h 是树高。这一点容易被想成 O(n)，实际不是：递归栈里装的是「从根到当前节点这条路径」，最深也就是树高。

同样是 100 万个节点，完全二叉树的栈只有 20 层，随机 BST 是 53 层，链是 100 万层。n 一样，空间差五个数量级。链是那个坏情况。

链到底能撑多深？本机 macOS 默认栈 8176 KB，实测把树做成一条左偏链跑递归遍历，260937 层还能正常返回，261000 层直接段错误。合下来每帧约 32 字节。所以遇到可能出现链的题，递归照样能写，先估一下 h 再说。

六、递归就是栈

递归没有用什么魔法，系统替你维护了一个栈。自己把它写出来是这样，以中序为例：

// 递归做的就是这些：显式写出来是一个栈
    void inOrderIter(TreeNode* head) {
        vector<TreeNode*> st;
        TreeNode* cur = head;
        while (cur != nullptr || !st.empty()) {
            while (cur != nullptr) {
                st.push_back(cur);
                cur = cur->left;
            }
            cur = st.back();
            st.pop_back();
            cout << cur->val << " ";
            cur = cur->right;
        }
    }

栈里存的是「左路已经走完、右子树还没处理」的节点，最深就是 h。写出来的版本和递归版跑同一个中序，4500 组随机树（含完全二叉树、左偏链、右偏链、随机 BST）逐组比对，输出完全一致。

所以「递归的额外空间 O(h)」这句话，说的就是这摞格子的高度。

七、复杂度分析

遍历打印顺序时间额外空间根的位置
先序根 左 右O(n)O(h)第 1 个
中序左 根 右O(n)O(h)第 |左| + 1 个
后序左 右 根O(n)O(h)最后 1 个

时间里的 n 是节点数，与树形无关：每个节点到达 3 次、每个空指针进入 1 次，合起来 4n+1 次常数操作，纸面和实测都是线性。

空间里的 h 是树高，与树形强相关。完全二叉树 h = ⌈log₂(n+1)⌉，n = 106 时只有 20；随机 BST 的期望高度约 4.3 ln n（自然对数，n = 106 的渐近值约 60，有限 n 实测 53）；退化成链时 h = n，这时的 O(h) 就是 O(n)，且在本机超过 26 万层会直接把栈用光。

树本身存 n 个节点的空间 O(n) 是省不掉的，这里说的 O(h) 是遍历过程额外要的。

八、总结

几个要点：

  • 三种序是同一个递归骨架，区别只在打印语句放在第几次到达的位置。写的时候先背下 f 的 1/2/3 三个位置，再决定往哪儿塞。
  • 每个非空节点到达 3 次，函数调用总次数 2n+1（n 个非空 + n+1 个空）。空指针那次调用是递归的出口，别漏掉 if (head == nullptr) return;。
  • 时间是 O(n)，额外空间是 O(h) 而不是 O(n)。h 完全取决于树形：完全二叉树 20 层，链 100 万层。
  • 链状树在本机约 26 万层就会把栈用光（8176 KB ÷ 32 字节/帧）。题目里如果出现链，要么改迭代，要么先估 h。
  • 按用途挑：先序复制与序列化，中序在 BST 上得到升序，后序汇总子树信息与释放整棵树。
  • 再往后是自己拿一个栈把三种序重写一遍（下一节），还有给两序重建树、Morris 遍历把 O(h) 压到 O(1)。
