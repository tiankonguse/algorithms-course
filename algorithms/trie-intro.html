前缀树：按前缀建树

词典里 100 万个单词，问「以 app 开头的有几个」。逐词比对要扫一整本词典，哈希表把单词压成整体、前缀信息直接丢了，两个都答不利索。前缀树把每个单词按字符拆成一条条边，走完一个前缀，答案就挂在走到的那个节点上。

零、背景

词典有 100 万词，要查「以某个前缀开头的单词数」。最直接的做法：把每个单词拉出来，比对一遍前缀。

本机实测：100 万词、查 200 次前缀，逐词比对要 0.47 秒。词典再大、查得再密，这个数线性涨，200 次已经摸到半秒，几千次查询就是几十秒。

哈希表答不了这个问题。它能答「apple 出现几次」，因为它把整个单词散列成一个键；可「以 app 开头的有几个」问的是前缀，单词在哈希表里是一整块，前缀信息存进去的时候就没了。为了答一个前缀问题，还是得把所有单词拉出来重新比对。

前缀查询要的是一件事：把「前缀」本身变成查询的索引。前缀树干的正是这个。

一、前缀树

每个单词从根开始，按字符走一条路。第一个字符 a 走 a 路，第二个字符 p 走 p 路，路是字符到字符的边。

建树只有两条规则：没有路就新建一个节点，有路就复用。

插入 app、apple、apply 三个词：前三个字符 app 完全一样，走的是一条路；第四个字符 apple 和 apply 都是 l，还是一条路；到第五个字符 e 和 y 才分叉。

从根走到某个节点，路径上的字符拼起来恰好是一个前缀。树建好之后，「app 这个前缀在词典里存不存在、有多少词经过它」就变成一个节点上的数字。

二、pass 和 end

每个节点挂两个计数器。pass：有多少个单词从这条路经过，也就是「以这个前缀开头的单词数」；end：有多少个单词在这个节点结束，也就是「这个单词出现了几次」。

插 app、apple、apply 各一次：走 a-p-p 的单词有 3 个，第二个 p 的 pass 是 3；app 自己在这个节点结束，end 是 1；apple 和 apply 继续走到 l，l 的 pass 是 2，e 和 y 的 end 各是 1。

查询就两句话：问前缀，走完读 pass；问单词，走完读 end。走到半路发现没有路，答案是 0。

三、类描述实现

最直观的写法：一个节点一个对象。节点里存 pass、end，再加 26 条路。

路的存法有两种。字符范围小，比如 26 个小写字母，用固定数组，下标就是字符减 'a'；字符范围大，比如任意字符、数字，26 个槽位会浪费，用哈希表，键就是字符本身。

插入的每一处都在做同一件事：检查路在不在，不在就建，在就走过去；走过去之后 pass 加一。差别只在「查路」那一步，数组是下标访问，哈希表是查键。

// 节点：pass 是经过次数，end 是结束次数，nexts 是 26 条路
    struct TrieNode {
        int pass;
        int end;
        TrieNode* nexts[26];
        TrieNode() {
            pass = 0;
            end = 0;
            for (int i = 0; i < 26; i++) nexts[i] = nullptr;
        }
    };

    // 插入：没路就新建，有路就复用；沿途 pass++，结尾 end++
    void insert(string word) {
        TrieNode* node = root;
        node->pass++;
        for (int i = 0, path; i < word.size(); i++) {
            path = word[i] - 'a';   // 字符对应成第几条路
            if (node->nexts[path] == nullptr) {
                node->nexts[path] = new TrieNode();
            }
            node = node->nexts[path];
            node->pass++;
        }
        node->end++;
    }

    // word 出现几次：走完返回 end
    int countWordsEqualTo(string word) {
        TrieNode* node = root;
        for (int i = 0, path; i < word.size(); i++) {
            path = word[i] - 'a';
            if (node->nexts[path] == nullptr) {
                return 0;
            }
            node = node->nexts[path];
        }
        return node->end;
    }

    // 以 pre 开头的单词数：走完返回 pass
    int countWordsStartingWith(string pre) {
        TrieNode* node = root;
        for (int i = 0, path; i < pre.size(); i++) {
            path = pre[i] - 'a';
            if (node->nexts[path] == nullptr) {
                return 0;
            }
            node = node->nexts[path];
        }
        return node->pass;
    }

    // 删一次：沿途 pass--，减到 0 就断开；结尾 end--
    void erase(string word) {
        if (countWordsEqualTo(word) > 0) {
            TrieNode* node = root;
            node->pass--;
            for (int i = 0, path; i < word.size(); i++) {
                path = word[i] - 'a';
                if (--node->nexts[path]->pass == 0) {
                    node->nexts[path] = nullptr;
                    return;
                }
                node = node->nexts[path];
            }
            node->end--;
        }
    }

哈希路的版本只换路的容器，其余逻辑原样照搬：

// 路换成哈希表：字符范围大、26 个槽位会浪费时用
    struct TrieNode {
        int pass;
        int end;
        unordered_map<char, TrieNode*> nexts;
        TrieNode() {
            pass = 0;
            end = 0;
        }
    };

    void insert(string word) {
        TrieNode* node = root;
        node->pass++;
        for (char c : word) {
            if (node->nexts.count(c) == 0) {
                node->nexts[c] = new TrieNode();
            }
            node = node->nexts[c];
            node->pass++;
        }
        node->end++;
    }

    // 删词：pass 减到 0 就把键从哈希表里去掉
    void erase(string word) {
        if (countWordsEqualTo(word) > 0) {
            TrieNode* node = root;
            node->pass--;
            for (char c : word) {
                TrieNode* next = node->nexts[c];
                if (--next->pass == 0) {
                    node->nexts.erase(c);
                    return;
                }
                node = next;
            }
            node->end--;
        }
    }

这套写法逻辑最清楚，但每个字符都要 new 一个节点。为什么说它不推荐，下一页给实测数字。

复杂度分析

操作时间说明
insertO(len)走 len 个字符，每步 O(1) 查路
countWordsEqualTo / countWordsStartingWithO(len)走完读 end / pass
eraseO(len)先查一次确认存在，再沿路减计数

空间 O(总字符数 × 字符集大小)：数组路每个节点固定 26 个槽，哈希路按实际用到的字符占键。单词越长、字符种类越多，节点越费。

总结

前缀树把「前缀查询」变成沿树走一趟，代价只跟单词长度有关，跟词典大小无关。

节点上挂什么计数可以按需定制，pass 和 end 是最常见的一对：一个回答前缀数，一个回答出现次数。

类描述实现结构直观，代价是每个字符一次堆分配。下一讲换静态数组，把 new 换成数组下标。
