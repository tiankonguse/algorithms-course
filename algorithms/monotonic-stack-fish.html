大鱼吃小鱼与全 1 子矩形：反向扫描与逐行结算

单调栈的扫描方向不一定是「从左往右、边扫边答」。这一页的两个题一个从右往左扫，把答案一路带回来；一个把矩阵逐行压成一维，复用上一页的柱状图技巧。方向换了，弹栈结算的骨架没换。

零、背景

单调栈适合处理「一个对象只关心右边某个结构」的问题。上一页的两题，答案要的是全局最优，所以从左往右筛候选再结算。这一页的两题，答案和「过程」绑在一起：鱼要算几轮才稳定，矩形要按行累计高度。

先看鱼的题为什么从右往左：每条鱼只吃右边的鱼，那右边的鱼先算好，左边的鱼直接用结果。再看矩形的题为什么逐行：子矩形的底边在哪一行，答案就归那一行结算，行与行之间只共享一个高度数组。

一、大鱼吃小鱼

给定体重数组，每轮每条鱼吃掉右边离它最近、体重比它小的鱼，吃这件事同时发生：A 吃 B 的同时，A 也可能被别的鱼吃；多条大鱼盯上同一条小鱼，这条小鱼被同时吃掉。问多少轮后鱼的数量不再变。

拿 8 3 1 5 6 7 2 4 走一遍。第一轮：8 吃 3，3 吃 1，5、6、7 同时吃 2，4 没人吃，剩下 8 5 6 7 4。第二轮：8 吃 5，5、6、7 同时吃 4，剩下 8 6 7。第三轮：8 吃 6，剩下 8 7。第四轮：8 吃 7，剩下 8。答案 4。

逐轮模拟最坏 O(n²)：每轮要扫一遍找谁吃谁。问题在于一轮里鱼的位置关系会变，反复重扫。而且「同时发生」让每轮之间的关联很隐蔽，直接模拟容易写错边界。

换个方向：从右往左处理每条鱼。处理到 i 时，右边所有鱼都已经算好「它们自己还要活几轮才轮到被吃」，存在栈里。栈里存 (体重, 轮数)，从底到顶体重严格递减。

对 i 号鱼：栈顶比它小的鱼，都会被它吃掉。每弹出一条，轮数 +1（吃这条鱼要花 1 轮），再和被弹那条鱼自己的轮数取 max（那条鱼可能先要活几轮才轮到被吃）。弹完把 (arr[i], curTurns) 入栈，curTurns 就是 i 号鱼「活到被吃要几轮」。答案就是所有 curTurns 的最大值。

演示 1 · 大鱼吃小鱼逐帧：从右往左，弹掉比它小的并累计轮数

// 大鱼吃小鱼：多少轮后鱼的数量固定
    // 栈里存「右边的幸存鱼」：(体重, 它自己被吃掉需要几轮)
    int turns(vector<int>& arr) {
        int n = arr.size();
        int r = 0, ans = 0;
        for (int i = n - 1; i >= 0; i--) {
            int curTurns = 0;
            while (r > 0 && stk[r - 1][0] < arr[i]) {  // 弹掉比 arr[i] 小的，它们被 arr[i] 吃掉
                curTurns = max(curTurns + 1, stk[--r][1]);
            }
            stk[r][0] = arr[i];
            stk[r++][1] = curTurns;   // arr[i] 自己活满 curTurns 轮后才可能被吃
            ans = max(ans, curTurns);
        }
        return ans;
    }

复杂度 O(n)：每条鱼入栈一次、出栈最多一次。空间 O(n) 是栈。

实测 n = 10⁶：递增数组 0 轮（右边全比自己大，没得吃），2.55ms；递减数组 1 轮（第一轮 5 吃 4、4 吃 3……同时发生，一轮全光），4.33ms；随机数组 34 轮，9.17ms。别拿「数组越大轮数越多」当直觉，轮数由右边结构决定，不是由 n 决定。

二、统计全 1 子矩形的数量

给一个 0/1 矩阵，统计元素全为 1 的子矩形有多少个。数据规模 m、n 都 ≤ 150。上一页的「最大矩形」找最大面积，这一题要数个数，先理解上一页再往下读。

核心还是逐行：从上往下扫每一行，维护 height[j]，表示第 j 列从当前行往上连续 1 的个数。扫到第 i 行时，height 数组就是一张柱状图，这一行的答案 = 底边贴在第 i 行的全 1 子矩形个数。

单调栈按列结算。弹出 cur 号柱子时，它的左边界 left 是栈里下一个（高度比 height[cur] 小），右边界是当前 i（高度 ≤ height[i]）。夹出来的区间长度 len = i - left - 1，里面所有连续子段都能作为底边，数量是 len × (len + 1) / 2。

高从哪算起：底边高度只能取 (max(height[left], height[i]), height[cur]] 这一层，比它矮的底边归别的柱子结算，比它高的不可能。所以 cur 的贡献是 (height[cur] - bottom) × len × (len + 1) / 2，bottom 是左右边界高度的较大者。

有个细节和上一页一样：弹出条件用 >=，但只有 height[cur] > height[i] 才结算。相等的柱子弹出不结算，留给更右边的柱子一起算，否则同一批矩形会被数两次。

演示 2 · 全 1 子矩形逐帧：逐行更新 height，每行用单调栈结算

// 统计全 1 子矩形数量：逐行维护 height[]，每行用单调栈结算
    int countFromBottom(int m) {
        int r = 0, ans = 0;
        for (int i = 0; i < m; i++) {
            while (r > 0 && height[stk[r - 1]] >= height[i]) {
                int cur = stk[--r];
                if (height[cur] > height[i]) {      // 相等不结算，留给后面的 i 一起算
                    int left = r == 0 ? -1 : stk[r - 1];
                    int len = i - left - 1;
                    int bottom = max(left == -1 ? 0 : height[left], height[i]);
                    ans += (height[cur] - bottom) * len * (len + 1) / 2;
                }
            }
            stk[r++] = i;
        }
        while (r > 0) {                             // 清算：右边没有更矮的
            int cur = stk[--r];
            int left = r == 0 ? -1 : stk[r - 1];
            int len = m - left - 1;
            int down = left == -1 ? 0 : height[left];
            ans += (height[cur] - down) * len * (len + 1) / 2;
        }
        return ans;
    }
    int numSubmat(vector<vector<int>>& mat) {
        int n = mat.size(), m = mat[0].size();
        fill(height, height + m, 0);
        int ans = 0;
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < m; j++) {
                height[j] = mat[i][j] == 0 ? 0 : height[j] + 1;
            }
            ans += countFromBottom(m);
        }
        return ans;
    }

复杂度 O(nm)：每行每列入栈一次、出栈最多一次。空间 O(m)。

实测 100 × 100 全 1 矩阵：暴力枚举所有子矩形再逐个检查，9.43 秒；单调栈 0.015ms，差六十万倍。150 × 150（题目上限）全 1 时答案 128255625，int 正好放得下，全 1 也只要 0.05ms。

三、复杂度分析

题目时间复杂度额外空间
大鱼吃小鱼O(n)O(n)
统计全 1 子矩形O(nm)O(m)

两题都靠「每个对象入栈一次、出栈最多一次」拿到线性总代价。鱼题从右往左是方向选择，矩形题逐行是维度拆分，骨架都是弹栈即结算。

四、总结

大鱼吃小鱼把「同时发生的吃」拆成从右往左的链：每条鱼的轮数只依赖右边被它吃的鱼，栈顶弹出一条轮数 +1 再取 max，递减数组一轮全光、递增数组零轮，别拿 n 猜答案。

全 1 子矩形把矩阵逐行压成柱状图，每行结算底边贴本行的矩形，公式 (height[cur] - bottom) × len(len+1)/2 一次算清一批；相等不结算，留给更右边。两题都是 052 那套单调栈在扫描方向和统计口径上的变体：同一个栈换个方向扫、换个口径数，就接住两类完全不同的题。
