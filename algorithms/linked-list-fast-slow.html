链表上的快慢指针：相交、回文、入环

一个指针走一步、另一个走两步，这条链的中点在哪、有没有环、环从哪个节点开始，三个问题就都有了答案。这一讲把三道高频题串成一条线，全程不借助任何容器。

零、背景

链表题的难度标签通常是「简单」。用容器做确实简单：把节点全收进数组或者哈希集合，剩下的就是数组题，下标随便跳。

面试时这么答会卡住。对方要的是额外空间 O(1) 的写法，也就是只在指针上做文章。这一讲的三道题，O(1) 空间的核心都是同一件事：让两个指针用不同的速度或者不同的起点走同一条路。

一、两个无环链表的第一个相交节点

两条单向无环链表，从某个节点开始共用后半段，形状是个 Y。返回第一个公共节点，没有就返回空指针。

哈希集合的做法最省事：先把第一条链的节点全塞进集合，再扫第二条，第一个命中的就是答案。代价是 O(n) 的额外空间。

换个角度看这个 Y：两条链一旦相交，尾巴一定是同一个节点。反过来，尾节点不同就绝不可能相交。于是先各走到尾，尾节点地址不同直接返回空。

走到尾的路上顺手把长度差算出来了：a 走完 h1 时 diff++，b 走完 h2 时 diff--，结束时的 diff 就是 len1 − len2。让长的那条先走 |diff| 步，之后两人同步前进，第一次相等处就是交点。

还有个更省事的写法，连长度都不量：两个指针各自把自己的链走完，再接着走对方的。a 走完 h1 跳到 h2，b 走完 h2 跳到 h1，两人的路程都是 len1 + len2，长度差在这条合并路径上自动抵消。不相交时两人会同时变成空指针，也相等，直接返回空。

实测（两条各 100 万个节点的链，人为让它们相交）：长度差法指针移动 4001998 次，走两圈法 2000000 次，哈希法 219.64ms 而前两者是 2.84ms 和 0.93ms。哈希集合的桶数组单独占 12.9 MB。

三种写法在 2 万组随机数据上答案完全一致（含不相交的情况）。

struct ListNode {
        int val;
        ListNode* next;
    };

    // 长度差法：先各走到尾，长链表先走差值步，再同步走
    ListNode* getIntersectionNode(ListNode* h1, ListNode* h2) {
        if (h1 == nullptr || h2 == nullptr) return nullptr;
        ListNode* a = h1;
        ListNode* b = h2;
        int diff = 0;
        while (a->next != nullptr) { a = a->next; diff++; }
        while (b->next != nullptr) { b = b->next; diff--; }
        if (a != b) return nullptr;           // 尾节点不同，一定不相交
        if (diff >= 0) { a = h1; b = h2; } else { a = h2; b = h1; }
        diff = diff < 0 ? -diff : diff;
        while (diff-- != 0) a = a->next;      // 长链表先走
        while (a != b) { a = a->next; b = b->next; }
        return a;
    }
// 走两圈法：各把自己的路走完再走对方的，长度差自动抵消
    ListNode* getIntersectionNode2(ListNode* h1, ListNode* h2) {
        if (h1 == nullptr || h2 == nullptr) return nullptr;
        ListNode* a = h1;
        ListNode* b = h2;
        while (a != b) {
            a = a == nullptr ? h2 : a->next;
            b = b == nullptr ? h1 : b->next;
        }
        return a;   // 不相交时 a、b 同时为 nullptr
    }

二、判断链表是不是回文结构

数组上判断回文很容易，两个下标从两头往中间夹就行。链表没有下标，得先找到中间那个节点。

快慢指针：slow 每次一步，fast 每次两步，fast 走不动时 slow 停在中点。长度为偶数时 slow 停在前半段的最后一个，长度为奇数时停在正中间那个。n 从 2 到 12 逐个量过，slow 停的位置恰好是 ⌈n/2⌉。

这里有个细节：终止条件写成 fast != nullptr && fast->next != nullptr 也能过，只是 slow 换成停在第 ⌊n/2⌋+1 个节点，切断点差了一格。两种写法我都跑过 n = 2 到 12，答案全对。

拿到中点之后：把 slow 之后的半段原地逆序，逆序结束时 pre 停在原链表的尾节点上。然后从 head 往右、从 pre 往左逐对比值。后半段已经逆序，跟着 next 走就是在往左走。比较次数是 ⌈n/2⌉。

长度为奇数时，中间那个节点会自己和自己比一次，必然相等，不用为它写特判。

比完之后要把后半段再逆序一次，把链表恢复成原样。这步不做，函数返回值照样是对的，代价留给了调用方：实测判断完一个 7 节点的回文链表再遍历，只剩 [1,2,3,4]，后半段全丢了。

2 万组随机数据与数组版比对，0 处不一致。

// 找中点 -> 后半逆序 -> 两侧往中间比 -> 恢复
    bool isPalindrome(ListNode* head) {
        if (head == nullptr || head->next == nullptr) return true;
        ListNode* slow = head;
        ListNode* fast = head;
        while (fast->next != nullptr && fast->next->next != nullptr) {
            slow = slow->next;
            fast = fast->next->next;
        }
        // 偶数长度时 slow 停在前半段最后一个，奇数时停在正中间
        ListNode* pre = slow;
        ListNode* cur = pre->next;
        ListNode* next = nullptr;
        pre->next = nullptr;                  // 切断前半段
        while (cur != nullptr) {              // 后半段逆序
            next = cur->next;
            cur->next = pre;
            pre = cur;
            cur = next;
        }
        bool ans = true;
        ListNode* left = head;
        ListNode* right = pre;                // 原尾节点
        while (left != nullptr && right != nullptr) {
            if (left->val != right->val) { ans = false; break; }
            left = left->next;
            right = right->next;              // 后半已逆序，next 就是往左走
        }
        cur = pre->next;                      // 恢复：把后半段再逆序一次
        pre->next = nullptr;
        while (cur != nullptr) {
            next = cur->next;
            cur->next = pre;
            pre = cur;
            cur = next;
        }
        return ans;
    }

三、返回链表的第一个入环节点

先判有没有环。slow 一步、fast 两步，fast 相对 slow 的速度是 1，进了环最多再走 b − 1 步一定追上。没有环时 fast 会先撞到尾部空指针，n = 100 万量级的链，50 万轮之内就停了。

第一次相遇的位置一般不在入环点上。设头节点到入环点要走 a 步，环长 b，相遇时 slow 一共走了 s 步。fast 走的是 2s，两人落在同一个位置，说明多出来的 s 步正好是环长的整数倍，即 s ≡ 0 (mod b)。

slow 的位置也可以写成 a + x（x 是入环点到相遇点的距离，模 b 意义下）。由 a + x ≡ s ≡ 0 (mod b) 得 x ≡ −a (mod b)，也就是从相遇点再走 a 步，正好回到入环点。

所以让 fast 退回 head，两人同速每次各走一步：head 走 a 步到入环点，相遇点走 a 步也到入环点，第二次相遇的地方就是答案。2 万组随机环上跑下来，第二段走的步数恒等于 a，没有例外。

slow 第一次相遇前走的步数有上界 a + b − 1：进环之前走 a 步，进环之后相对速度是 1、最远也就差 b − 1 步。2 万组随机数据 0 次超出，平均是上界的 0.80 倍。极端情况量过两组：a = 100 万、b = 1 走了 100 万步，a = 1、b = 100 万也走了 100 万步，两次都正好卡在上界。

代码里 slow 从 head->next、fast 从 head->next->next 起步，两人起点不同。都写成 head 的话 while (slow != fast) 一次都不进，函数直接把 head 当答案返回了。

// Floyd 判圈：相遇后一个从头走、一个从相遇点走，两人再次相遇处即入环点
    ListNode* detectCycle(ListNode* head) {
        if (head == nullptr || head->next == nullptr || head->next->next == nullptr)
            return nullptr;
        ListNode* slow = head->next;
        ListNode* fast = head->next->next;
        while (slow != fast) {                // 无环时 fast 一定先走到尾部
            if (fast->next == nullptr || fast->next->next == nullptr) return nullptr;
            slow = slow->next;
            fast = fast->next->next;
        }
        fast = head;                          // 两人同速，走 a 步在入环点碰头
        while (slow != fast) {
            slow = slow->next;
            fast = fast->next;
        }
        return slow;
    }

四、复杂度分析

题目时间额外空间说明
相交节点（长度差）O(n + m)O(1)两趟走到尾 + 一趟同步；实测 100 万节点 2.84ms
相交节点（走两圈）O(n + m)O(1)每人最多走 n + m 步；实测 0.93ms，比长度差法还快
相交节点（哈希集合）O(n + m)O(n)100 万节点 219.64ms，桶数组 12.9 MB
回文结构O(n)O(1)找中点 + 两次逆序 + ⌈n/2⌉ 次比较
第一个入环节点O(n)O(1)第一次相遇 ≤ a + b − 1 步，第二段恰好 a 步

三道题的额外空间都是几个指针变量。换来的代价是代码长了：哈希版相交节点只有 8 行，长度差版有 18 行，而这 18 行里每一行写错都能让答案悄悄变掉：不崩，只是结果不对。

五、总结

相交节点：先确认两条链的尾节点是同一个，再用长度差对齐起点。走两圈那版更短，实测也更快。

回文：快慢指针找中点，后半段逆序后从两头往中间比，比完记得再逆序恢复。判断函数改了传入的数据结构，是这一题最容易踩的坑。

入环节点：相遇点和入环点是两个不同的位置。第一次相遇的步数是环长的整数倍，从这个倍数关系能推出「再走 a 步回到入环点」，所以让一个指针退回 head 同步走。
