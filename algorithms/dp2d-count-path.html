枚举型二维动态规划：二叉树计数与最长递增路径

前两页的题，每个格子的枚举代价都是 O(1)，所以「表的大小」就是时间复杂度。这一页两道不一样：一道填一个格子要枚举一圈，另一道干脆写不出严格位置依赖，只能停在记忆化搜索。

零、格子的枚举代价不是 O(1) 时会怎样

二维动态规划的时间是「表的大小 × 每个格子的枚举代价」。前面几题的代价都是常数，乘完还是 n·m。这一节第一题的代价是 O(n)，答案就变成 O(n²·m) 了。

代价一大，空间压缩的写法也要小心：压缩之后「先枚举哪一维」会从「无所谓」变成「写错就全错」。

一、节点数为 n、高度不大于 m 的二叉树个数

有 n 个节点，问有多少种不同结构、高度不超过 m 的二叉树，答案对 10⁹+7 取模。

拆法很直接：树根占掉 1 个节点，剩下 n−1 个分给左右子树。左子树拿 k 个，右子树就拿 n−k−1 个，两边各自的高度都不能超过 m−1。k 从 0 取到 n−1，把每种分法的左右方案数乘起来再加起来。

两个可变参数是 n 和 m，都是小整数，而且它们一给定答案就定了，之前怎么分的不用管。可以改动态规划。

const int MOD = 1000000007;
    const int MAXN = 51;
    long long dp[MAXN][MAXN];                  // 全部初始化成 -1

    // n 个节点、高度不超过 m 的二叉树结构数
    int compute1(int n, int m) {
        if (n == 0) {                          // 空树也算一种
            return 1;
        }
        if (m == 0) {                          // 还有节点却不给高度，办不到
            return 0;
        }
        if (dp[n][m] != -1) {
            return dp[n][m];
        }
        long long ans = 0;
        for (int k = 0; k < n; k++) {          // 左树分 k 个，右树就分 n-k-1 个
            ans = (ans + (long long) compute1(k, m - 1) * compute1(n - k - 1, m - 1) % MOD) % MOD;
        }
        dp[n][m] = ans;
        return ans;
    }

二、严格位置依赖：列在外层，行在内层

看依赖：dp[i][j] 依赖 dp[k][j−1] 和 dp[i−k−1][j−1]，k 从 0 取到 i−1。也就是说它只依赖「上一列」的那些格子，而且行号都比 i 小。

所以填表顺序是：列 j 从 1 到 m，行 i 从 1 到 n，每个格子里再枚举 k。这里 j 必须在外层，因为所有 i 都要用到完整的 j−1 列。

long long dp[MAXN][MAXN];                  // 行 i = 节点数，列 j = 高度上限

    int compute2(int n, int m) {
        for (int j = 0; j <= m; j++) {
            dp[0][j] = 1;                      // 0 个节点：一种（空树）
        }
        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= m; j++) {
                dp[i][j] = 0;
                for (int k = 0; k < i; k++) {
                    dp[i][j] = (dp[i][j] + dp[k][j - 1] * dp[i - k - 1][j - 1] % MOD) % MOD;
                }
            }
        }
        return dp[n][m];
    }

填完的表长这样（行是节点数 i，列是高度上限 j）：

第 0 行全是 1：0 个节点就是空树，一种。第 0 列（除 i=0 外）全是 0：还有节点却不给高度，办不到。右边逐渐稳定下来，因为高度上限超过节点数之后就没约束了。那时候 i 个节点的二叉树总数是第 i 个卡特兰数，实测 n = 1 到 8 分别是 1、2、5、14、42、132、429、1430。

n = m = 50 时实测 0.7323 ms，内层循环一共跑了 63750 次。

三、空间压缩：行必须倒着走

只留一列。dp[i] 表示想象中的 dp[i][j]，填它要用到 dp[k] 和 dp[i−k−1]，而这两个的下标都严格小于 i。

下标比 i 小，这些格子必须还留着「上一列」的旧值。如果 i 从 1 正着走到 n，等算到 dp[i] 时，dp[0..i−1] 已经被本列覆盖过了，全变成了新值。

倒着走就没这个问题：算 dp[i] 时，dp[0..i−1] 还没被本列碰过，全是上一列的旧值。

long long dp[MAXN];                        // dp[i] = 想象中的 dp[i][j]

    int compute3(int n, int m) {
        dp[0] = 1;
        for (int i = 1; i <= n; i++) {
            dp[i] = 0;
        }
        for (int j = 1; j <= m; j++) {         // 先枚举列（高度）
            for (int i = n; i >= 1; i--) {     // 再枚举行，而且必须倒着走
                dp[i] = 0;
                for (int k = 0; k < i; k++) {
                    dp[i] = (dp[i] + dp[k] * dp[i - k - 1] % MOD) % MOD;
                }
            }
        }
        return dp[n];
    }

实测代价：随机取 200 组 (n, m)，i 正序的版本有 40.50% 算错。举两个具体的：n = 4、m = 3 正确答案是 6，正序版算出 14；n = 6、m = 4 正确答案是 44，正序版算出 132。这两个错出来的数恰好是「不限制高度」的答案，因为它把本列刚算好的值当成了上一列的。

四、矩阵中的最长递增路径

给一个整数矩阵，可以上下左右走，只能走到值更大的格子，问最长能走几步（算上起点）。

递归定义也简单：f(i, j) 是从 (i, j) 出发能走出来的最长递增路径长度，等于「所有比它大的邻居里 f 最大的那个 + 1」。

// 从 (i,j) 出发能走出来的最长递增路径长度
    int f1(vector<vector<int>>& g, int i, int j) {
        int n = g.size(), m = g[0].size();
        int next = 0;
        if (i > 0 && g[i][j] < g[i - 1][j]) {
            next = max(next, f1(g, i - 1, j));
        }
        if (i + 1 < n && g[i][j] < g[i + 1][j]) {
            next = max(next, f1(g, i + 1, j));
        }
        if (j > 0 && g[i][j] < g[i][j - 1]) {
            next = max(next, f1(g, i, j - 1));
        }
        if (j + 1 < m && g[i][j] < g[i][j + 1]) {
            next = max(next, f1(g, i, j + 1));
        }
        return next + 1;
    }

两个可变参数 i 和 j 都是 int，也确实决定了返回值。加张 dp 表改记忆化，每个格子只算一次。

int f2(vector<vector<int>>& g, int i, int j, vector<vector<int>>& dp) {
        int n = g.size(), m = g[0].size();
        if (dp[i][j] != 0) {
            return dp[i][j];
        }
        int next = 0;
        if (i > 0 && g[i][j] < g[i - 1][j]) {
            next = max(next, f2(g, i - 1, j, dp));
        }
        if (i + 1 < n && g[i][j] < g[i + 1][j]) {
            next = max(next, f2(g, i + 1, j, dp));
        }
        if (j > 0 && g[i][j] < g[i][j - 1]) {
            next = max(next, f2(g, i, j - 1, dp));
        }
        if (j + 1 < m && g[i][j] < g[i][j + 1]) {
            next = max(next, f2(g, i, j + 1, dp));
        }
        dp[i][j] = next + 1;
        return next + 1;
    }

    int longestIncreasingPath(vector<vector<int>>& g) {
        int n = g.size(), m = g[0].size();
        vector<vector<int>> dp(n, vector<int>(m));
        int ans = 0;
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < m; j++) {      // 每个格子都当一次起点
                ans = max(ans, f2(g, i, j, dp));
            }
        }
        return ans;
    }

暴力版有多慢？取一个蛇形网格（数值沿着路径一路递增，最长路径是 n²），实测调用次数是这样长的：

n = 6 时 46101 次调用，格子只有 36 个。记忆化之后每个格子算一次，n = 200 的随机矩阵实测 0.655 ms。

五、为什么这题写不出严格位置依赖

看依赖：dp[i][j] 依赖「值比 grid[i][j] 大的那些邻居」。这个依赖跟着值的大小走，跟格子的位置没关系。

拿一个蛇形网格举例就清楚了：

dp[2][2]（值是 7）依赖 dp[2][1]（值是 8）。8 这个格子在 7 的左边、同一行。如果按「从左到右、从上到下」的行列顺序填表，算到 dp[2][2] 时 dp[2][1] 确实算过了；但反过来 dp[2][1]（值 8）依赖 dp[1][1]（值 9），而 9 在 8 的上面、行号更小，行列顺序下它也算过了。那是不是就碰巧对了？

确实，对这一格是碰巧对了。但只要把蛇形方向换一下，比如让值沿着「从右下到左上」递增，行列顺序就全反了。根子在于依赖关系本身没有位置上的单调性，换多少次方向都一样。

实测一下照搬「严格位置依赖」的写法会怎样：只让每个格子看上面和左面两个邻居，随机 5000 组小矩阵里 38.74% 的样例答案是错的，蛇形 3×3 的正确答案 9 会被算成 5。

六、那就停在记忆化搜索

这题的正式做法是「记忆化搜索」，或者说从顶到底的动态规划。依赖关系不构成格子位置的拓扑序，那就别硬凑一个填表顺序，让递归自己去展开，靠 dp 表保证每个格子只算一次。

另一条路是把格子按值从小到大排序，再做松弛。实测 200×200 随机矩阵上记忆化 0.655 ms、排序松弛 2.130 ms，记忆化还更快一些，写起来也更短。

这里能得出一条更一般的判据：能改成严格位置依赖的前提是「依赖关系能排成一个顺序，使得每个格子的前驱都排在它前面」。前两页的题天然满足，这一页第一题靠「列在外层、行在内层」满足，第二题则根本不满足。

七、复杂度分析

题做法时间复杂度空间复杂度
二叉树计数记忆化搜索O(n²·m)O(n·m)
二叉树计数严格位置依赖O(n²·m)O(n·m)
二叉树计数空间压缩O(n²·m)O(n)
最长递增路径暴力递归指数级O(n·m)
最长递增路径记忆化搜索O(n·m)O(n·m)
最长递增路径排序 + 松弛O(n·m·log(n·m))O(n·m)

二叉树计数的 n²·m 拆开看：表有 n·m 个格子，每个格子枚举 k 要 O(n)，乘起来是 O(n²·m)。空间压缩把 n·m 降到 n，时间不变。

八、总结

二维动态规划的时间要按「表的大小 × 每个格子的枚举代价」算，别只数格子。二叉树计数这一题每个格子要枚举一圈 k，总时间是 n²·m 而不是 n·m。

空间压缩时先问一句：填 dp[i] 用到的那些下标，是比 i 大还是比 i 小？比 i 小就必须倒着枚举 i，否则本列的新值会把上一列的旧值盖掉。这一题写反的后果是 40% 的样例算错，而且错出来的数看着还挺合理。

最后一题给出了边界：依赖关系没有位置单调性时，就停在记忆化搜索，别硬凑填表顺序。判据是「能不能排出一个顺序，让每个格子的前驱都在它前面」，排不出来就用递归加 dp 表。
