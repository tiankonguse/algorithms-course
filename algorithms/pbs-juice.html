混合果汁：整体二分套线段树二分

整体二分的骨架是固定的：多个询问各自能二分答案，就把这些二分合成一棵分治树。真正决定题目能不能做的是「判定」那一环。混合果汁的判定要在价格轴上做一次贪心，用线段树二分把它压到 O(log n)。

零、整体二分的骨架

先看骨架。假设有 m 个询问，每个询问的答案都能单独二分出来：取一个 mid，判定「答案是不是不超过 mid」，据此把区间砍掉一半。逐个做就是 m 次二分，每次二分都要重新准备一份判定用的状态，代价很容易变成 O(m · log n · 准备代价)。

整体二分的做法是把这 m 次二分叠起来。分治的每一层，所有还没定下来的询问共用同一个 mid，一起判定一次，然后按判定结果分成两堆：判定成立的去左半值域，不成立去右半值域。往下递归时两堆互不干扰，因为每一堆只在自己的值域里继续找。

骨架写下来就是 compute(ql, qr, vl, vr)：ql..qr 是还没确定答案的询问编号，vl..vr 是它们共用的答案值域。取 mid，准备结构，扫一遍询问做判定，按结果把询问重排成左右两堆，然后递归两个子区间。

这一节六道题用的都是这套骨架，差别全在「准备结构」和「判定」上。题目 1 的准备是一次线段树维护，判定是一次线段树二分。

一、题目1：混合果汁

一共有 n 种果汁，每种果汁给定美味度 d、每升价格 p、添加上限 l。制作混合果汁时每种果汁不能超过添加上限，其中美味度最低的果汁决定混合果汁的美味度。一共有 m 个小朋友，给每位制作混合果汁时，钱数不超过 money[i]，体积不少于 least[i]。打印每个小朋友能得到的混合果汁最大美味度，如果无法满足，打印 −1。1 ≤ n、m、d、p、l ≤ 10⁵，1 ≤ money[i]、least[i] ≤ 10¹⁸。测试链接：P4602。

先把单个小朋友的问题看清楚。把果汁按美味度从高到低排序，只用前 k 种时的美味度就是第 k 种的美味度 d[k]。k 越小种类越少、越难满足，k 越大越容易满足，所以「只用前 k 种能不能满足」关于 k 单调，最小的可行 k 就是答案。

于是问题变成对每个小朋友二分 k。判定本身是个小贪心：钱要花在便宜的果汁上，把果汁按价格从低到高拿，每种拿到上限为止，凑够 least 升时花掉的钱就是最小花费，看它是不是不超过 money。

可以看出判定里没有别的选择：价格更低的果汁永远更该买，买满上限再换下一种。总量不够 least 升就直接判定失败。

二、把贪心搬到线段树上

逐个小朋友每次判定都重新排一次价格是 O(n log n)，叠上二分和 m 个询问必然超时。注意到「按价格从低到高」这件事可以预处理：以价格为下标开一棵线段树，叶子 p 上记两个量，suml 是这个价格当前可用的总升数，cost 是把这些升数全买下来的钱，也就是 suml × p。

加入一种果汁就是在它的价格位置上加 l 升，删除就是减 l 升，一次 O(log n)。判定时要的是「买最便宜的 volume 升要多少钱」，这可以在树上从根往下走：如果左儿子的总升数不小于 volume，最便宜的那些升全在左半边，往左走；否则左半边全买下来，记下它的 cost，再去右半边要剩下的 volume 升。

这棵线段树只支持单点加和一次前缀式查询，写法比区间查询还短。

struct Juice {
        int d, p, l;
    };

    bool JuiceCmp(Juice x, Juice y) {
        return x.d > y.d;
    }

    const int MAXN = 100001;
    int n, m;

    Juice juice[MAXN];
    int qid[MAXN];
    long long money[MAXN];
    long long least[MAXN];

    int maxp = 0;
    long long suml[MAXN << 2];
    long long cost[MAXN << 2];
    int used = 0;

    int lset[MAXN];
    int rset[MAXN];

    int ans[MAXN];

    void up(int i) {
        suml[i] = suml[i << 1] + suml[i << 1 | 1];
        cost[i] = cost[i << 1] + cost[i << 1 | 1];
    }

    void add(int jobi, int jobv, int l, int r, int i) {
        if (l == r) {
            suml[i] += jobv;
            cost[i] = suml[i] * l;
        } else {
            int mid = (l + r) >> 1;
            if (jobi <= mid) {
                add(jobi, jobv, l, mid, i << 1);
            } else {
                add(jobi, jobv, mid + 1, r, i << 1 | 1);
            }
            up(i);
        }
    }

    long long query(long long volume, int l, int r, int i) {
        if (l == r) {
            return volume * l;
        }
        int mid = (l + r) >> 1;
        if (suml[i << 1] >= volume) {
            return query(volume, l, mid, i << 1);
        } else {
            return cost[i << 1] + query(volume - suml[i << 1], mid + 1, r, i << 1 | 1);
        }
    }

这里有个细节：叶子上的 cost 不是累加得来的，而是用 suml 乘当前价格算出来的。价格就是线段树的下标，递归到叶子时 l 等于 r，直接乘即可。

三、主过程

果汁按美味度降序排序之后，答案值域就是排序后的下标 1 到 n，再把 n + 1 当成一个「无解」的哨兵。分治时用一个指针 used 记录当前已经加进线段树的果汁数量，进入某层要 mid 种，就把 used 单调移到 mid，多余的删掉。

判定的条件写成两条：线段树根上的总升数不小于 least，且买最便宜的 least 升的花费不超过 money。两条都成立才说明「只用前 mid 种可行」，询问去左半；否则去右半。

void compute(int ql, int qr, int vl, int vr) {
        if (ql > qr) {
            return;
        }
        if (vl == vr) {
            for (int i = ql; i <= qr; i++) {
                ans[qid[i]] = vl;
            }
        } else {
            int mid = (vl + vr) >> 1;
            while (used < mid) {
                used++;
                add(juice[used].p, juice[used].l, 1, maxp, 1);
            }
            while (used > mid) {
                add(juice[used].p, -juice[used].l, 1, maxp, 1);
                used--;
            }
            int lsiz = 0, rsiz = 0;
            for (int i = ql, id; i <= qr; i++) {
                id = qid[i];
                if (suml[1] >= least[id] && query(least[id], 1, maxp, 1) <= money[id]) {
                    lset[++lsiz] = id;
                } else {
                    rset[++rsiz] = id;
                }
            }
            for (int i = 1; i <= lsiz; i++) {
                qid[ql + i - 1] = lset[i];
            }
            for (int i = 1; i <= rsiz; i++) {
                qid[ql + lsiz + i - 1] = rset[i];
            }
            compute(ql, ql + lsiz - 1, vl, mid);
            compute(ql + lsiz, qr, mid + 1, vr);
        }
    }

    int main() {
        ios::sync_with_stdio(false);
        cin.tie(nullptr);
        cin >> n >> m;
        for (int i = 1; i <= n; i++) {
            cin >> juice[i].d >> juice[i].p >> juice[i].l;
            maxp = max(maxp, juice[i].p);
        }
        for (int i = 1; i <= m; i++) {
            qid[i] = i;
            cin >> money[i] >> least[i];
        }
        sort(juice + 1, juice + n + 1, JuiceCmp);
        compute(1, m, 1, n + 1);
        for (int i = 1; i <= m; i++) {
            if (ans[i] == n + 1) {
                cout << -1 << '\n';
            } else {
                cout << juice[ans[i]].d << '\n';
            }
        }
        return 0;
    }

used 的来回移动看着像是会退化，其实不会。同一层里各节点的值域互不重叠，指针在每个节点内的移动距离不超过那个值域的长度，一层加起来是 O(n)，一共 log n 层。每个询问在每层做一次 O(log n) 的线段树查询，m 个询问就是 m · log n · log n。

最后打印时，答案是 n + 1 说明连全部果汁都用上也不够，输出 −1，否则输出 juice[ans].d。

四、复杂度分析

排序一次 O(n log n)，之后是 log n 层分治。每层里果汁加入删除共 O(n) 次、每个询问一次线段树查询，单次树操作 O(log n)。

操作时间复杂度空间复杂度
按美味度排序（只在开头做一次）O(n log n)O(n + m)：果汁数组、小朋友的 money 与 least、答案各 O(n) 或 O(m)，线段树开 4·maxp 个节点存两个 long long
加入或删除一种果汁（线段树单点加）O(log n)
一次判定 query(least)（线段树二分）O(log n)
一层分治（果汁移动 O(n) 次、m 次判定）O((n + m) log n)
整体（共 log n 层）O((n + m) log² n)

n、m 都是 10⁵ 时 log² n 大约是 289，总代价在 6 × 10⁷ 量级，可以通过。

五、最后

题目 1 的判定是一个独立的贪心，靠线段树二分把它压到 O(log n)，整体二分负责把这份代价摊给所有询问。下一节换个形状：操作里带修改，修改本身也要参与分治。
