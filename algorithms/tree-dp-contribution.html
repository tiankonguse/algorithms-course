树型 dp：路径与贡献

前两页的返回值都在描述子树本身。这一页换一种：返回值是一个「余额」，答案在递归返回的路上累加起来。想把这类题写对，先得说清楚某条边到底会被搬几次。

零、一条边会被搬几次

有的树型 dp 里，答案落在所有边的总代价上。这时返回值不承担答案，只负责把子树的状态带给父节点。

下手的第一步是把一条边单独拎出来看：这条边最少要被穿越几次？想清楚它，答案就是把所有边加起来。

硬币题就是这么切的。子树是一个整体，它需要的硬币数和它实际拥有的硬币数之间有差额，差额只能通过连接它的那条边进出。

一、在二叉树中分配硬币

给一棵有 n 个节点的二叉树，第 i 个节点上有 node.val 枚硬币，整棵树一共 n 枚。一次移动把一枚硬币从某个节点挪到相邻节点，求让每个节点恰好有一枚硬币的最少移动次数。

把任意一棵子树看成一个团体：它有 cnt 个节点、sum 枚硬币。cnt − sum 就是这个团体「欠外面」的硬币数，负数表示它多出来的部分。

这些差额硬币只有一条通道：连接这棵子树和它父亲的那条边。一枚硬币过一次要走一步，所以这条边至少要被走 |cnt − sum| 次。

接下来这句是本题的全部价值：把所有边的这个量加起来就够了。每条边的账各记各的，不用为「把左子树的硬币挪去右子树」额外加价，因为那次移动本来就分别记在左、右两条边上。

返回值定成三个量：节点数 cnt、硬币数 sum、以及子树内部已经统计到的移动次数 move。合并时：

  • cnt = 左 cnt + 右 cnt + 1，sum = 左 sum + 右 sum + 自己的硬币；
  • move = 左 move + 右 move + |左 cnt − 左 sum| + |右 cnt − 右 sum|。

两处坑。一是漏掉绝对值，实测 79.91% 出错：欠硬币和攒硬币都要经过这条边，方向不同但次数一样，少一个 abs 就凭空减掉一半。二是忘了把孩子的 move 累加进来，82.02% 出错，只算了自己这两条边，深处的账全丢了。

struct Info {
        int cnt;
        long long sum;
        long long move;
    };

    Info f(Node* x) {
        if (x == nullptr) return {0, 0, 0};
        Info L = f(x->left);
        Info R = f(x->right);
        int cnt = L.cnt + R.cnt + 1;
        long long sum = L.sum + R.sum + x->val;
        long long move = L.move + R.move
            + llabs(L.cnt - L.sum) + llabs(R.cnt - R.sum);
        return {cnt, sum, move};
    }

    long long distributeCoins(Node* root) {
        return f(root).move;
    }

硬币堆在哪里，答案差别很大。同样 15 个节点、15 枚硬币，全堆在链的一端要搬 105 次，全堆在完全二叉树的根只要 34 次。

二、路径总和 III

给一棵二叉树和一个整数 target，统计节点值之和等于 target 的向下路径条数。路径不必从根开始，也不必在叶子结束，只要求方向从上往下。

朴素做法是把每个节点当起点，往下累加，一路上凑到 target 就计数。复杂度 O(n²)。实测在链上 n = 1000 / 2000 / 4000 时分别是 1.465 / 5.588 / 20.815 ms，n 翻倍时间翻四倍，n 到 10⁵ 就是几十秒。

换成前缀和。设 sum 是从根一路走到当前节点的累加和。一条「以 x 结尾」的向下路径，相当于从某个祖先的儿子出发走到 x，它的和等于 sum(x) − sum(祖先)。要让它等于 target，就得有一个祖先的前缀和等于 sum(x) − target。

于是用一个计数器记下当前这条根到 x 的链上每一个前缀和出现的次数。走到 x 时做四件事：加上自己的值、查一遍 pre[sum − target]、把 sum 记进去、递归两个孩子。

离开 x 之前还要做第五件事：把 sum 的计数减回去。不回退的话，x 的兄弟子树、叔叔子树上的节点都会被算成 x 的祖先，实测 65.59% 出错。这一步也是整道题唯一容易漏的地方，因为它不影响递归的正确性，只影响计数器的干净。

计数器要预置 pre[0] = 1。它代表「空前缀」，也就是路径正好从根开始的那种情况。

另一处常见错误是只查 sum == target。那样统计的是「从根走到 x 的整条链」，起点在中间的路径全漏了，72.61% 出错。

unordered_map<long long, int> pre;
    long long ans;

    void f(Node* x, long long target, long long sum) {
        if (x == nullptr) return;
        sum += x->val;
        auto it = pre.find(sum - target);
        if (it != pre.end()) ans += it->second;
        pre[sum]++;
        f(x->left, target, sum);
        f(x->right, target, sum);
        pre[sum]--;
    }

    int pathSum(Node* root, long long target) {
        pre.clear();
        pre[0] = 1;
        ans = 0;
        f(root, target, 0);
        return (int)ans;
    }

换前缀和之后，每个节点只做常数次哈希表操作，时间降到 O(n) 期望。哈希表里最多同时存在 h 个前缀和（当前这条链），所以额外空间是 O(h)。图 4 是两者的对照。

复杂度分析

题目时间空间
在二叉树中分配硬币O(n)O(h)
路径总和 IIIO(n)O(h)

硬币题每个节点进一次出一次，合并是常数次加减和取绝对值，时间 O(n)。路径题每个节点做两次哈希表操作，时间 O(n) 期望；额外空间是当前链上的前缀和，最多 h 个。

两者的递归深度都是树高 h。硬币题的返回值里有三个 long long，栈帧偏大，在左链上实测 86952 层就到顶；路径题同样在 86947 层附近。换成随机树，10⁶ 个节点深度只有 47，随便跑（硬币题一遍 14.996 ms，路径题 21.983 ms）。

总结

「贡献法」的固定动作是：挑一条边或一个点，算它在答案里被计了几次，再把所有贡献加起来。硬币题贡献的是边上搬运的硬币数，每条边恰好 |cnt − sum| 次。

这类题的返回值不承担答案，只负责交出父节点算贡献所需要的那点信息。硬币题交上去的是 cnt 和 sum，move 只是顺路累计的账。

路径计数换到前缀和之后，dfs 就变成了一次「进入时登记、离开时注销」的扫描。凡是这种带生命周期的计数器，都要在离开子树的最后一步把它恢复原样。

前缀和能不能用，取决于路径是否单向。路径方向一旦允许拐弯，从根往下累加的那套前缀和就不成立了，得换别的合并方式。
