解码方法与解码方法 II：切分型一维动态规划

'A' 到 'Z' 编成 1 到 26，一串数字反过来能拆出几种字母组合？这两个题把一维动态规划最常见的形状摆得很清楚：位置 i 上只有「自己单独算」和「拉着 i+1 一起算」两种选择，剩下的就是处理哪些组合合法。

零、把切法画出来

数字串 "226"。第一位可以单独切成 "2"，也可以和第二位凑成 "22"，只要这个两位数不超过 26 就行。每种切法对应一种字母组合：

所以递归的定义一句话就出来了：f(i) 是 s[i...] 这后半段的切分种数。i 位置只有两个分支：单独切一位，走到 f(i+1)；和后面凑两位（前提是凑出来的数在 1 到 26 之间），走到 f(i+2)。两个分支的答案加起来。

#include <bits/stdc++.h>
    using namespace std;

    // s[i...] 这部分有多少种有效切分
    int f1(string& s, int i) {
        if (i == s.size()) return 1;
        int ans;
        if (s[i] == '0') {
            ans = 0;
        } else {
            ans = f1(s, i + 1);
            if (i + 1 < s.size() && ((s[i] - '0') * 10 + s[i + 1] - '0') <= 26) {
                ans += f1(s, i + 2);
            }
        }
        return ans;
    }

    int numDecodings1(string& s) {
        return f1(s, 0);
    }

这版是纯暴力。实测调用次数（全 '1' 的串，每个位置都能凑两位，重复调用最多）：长度 5 是 20 次，长度 10 是 232 次，长度 20 是 28656 次，长度 25 是 317810 次。和斐波那契一个量级地涨。

一、'0' 是死路，不是「跳过」

映射表里没有 0，所以 '0' 不能单独成组，也不能当两位数的开头。碰上它的那一条路直接断掉，返回 0 种。

"11106" 只有两种合法切法：1|1|10|6 和 11|10|6。凡是切出 "06" 的都不算，题目里那句「'6' 和 '06' 在映射中并不等价」说的就是这件事。

实测的错法抓取率（2 万组随机数字串，对照组是枚举所有切法的暴力）：把 '0' 当普通数字继续往后算，41.33% 的样本答案偏大；两位数的判定写成 < 26，2.70% 的样本偏小（只有恰好出现 26 时才现形，所以随机数据不容易抓到，得专门造）；dp[n] 初始成 0 而不是 1，64.02% 的样本直接变成 0。最后那个最狠，也最好查：答案恒为 0 的时候先看边界。

二、从底到顶：dp[n] = 1

f(i) 依赖 i+1 和 i+2，倒着填。边界是 dp[n] = 1：切到末尾时正好切完，算一种方案。这个 1 是整条递推的种子，写漏了后面全是 0。

#include <bits/stdc++.h>
    using namespace std;

    // dp[i] : s[i...] 的切分种数，dp[n] = 1 是那个「切完了」的空串
    int numDecodings3(string& s) {
        int n = s.size();
        vector<int> dp(n + 1, 0);
        dp[n] = 1;
        for (int i = n - 1; i >= 0; i--) {
            if (s[i] == '0') {
                dp[i] = 0;
            } else {
                dp[i] = dp[i + 1];
                if (i + 1 < n && ((s[i] - '0') * 10 + s[i + 1] - '0') <= 26) {
                    dp[i] += dp[i + 2];
                }
            }
        }
        return dp[0];
    }

dp[i] 的含义要一直挂在嘴边：s[i...] 的切分种数，不是 s[0...i] 的。含义定成后者的话，'0' 那句判断就得挪到 i−1 上去写，绕一圈。

三、空间压缩：两个变量

dp[i] 只看 dp[i+1] 和 dp[i+2]，和斐波那契一样，两个变量滚动即可。

#include <bits/stdc++.h>
    using namespace std;

    // 空间压缩：next 是 dp[i+1]，nextNext 是 dp[i+2]
    int numDecodings4(string& s) {
        int next = 1, nextNext = 0;
        for (int i = s.size() - 1, cur; i >= 0; i--) {
            if (s[i] == '0') {
                cur = 0;
            } else {
                cur = next;
                if (i + 1 < s.size() && ((s[i] - '0') * 10 + s[i + 1] - '0') <= 26) {
                    cur += nextNext;
                }
            }
            nextNext = next;
            next = cur;
        }
        return next;
    }

实测（长度 10⁶ 的全 '1' 串，答案会溢出 int，只比时间）：dp 数组版 2.03ms，滚动变量版 0.50ms。省掉的不只是内存，还有一整片顺序写。

四、解码方法 II：'*' 带来的倍数

题目允许 '*'，它可以当 1 到 9 里任意一个数字（不含 0）。这样一来每个位置的两个分支都要乘上一个倍数，「有或没有」变成了「有几种」。

五类组合要分开想。最容易出错的是 '*' 加数字那一类：'*7' 只有 17 合法（27 超过 26），所以倍数是 1；'*3' 有 13 和 23 两种，倍数是 2。另一处是 '*' 加 '*'：11 到 19 九种、21 到 26 六种，一共 15 种，不是 25 也不是 100。

#include <bits/stdc++.h>
    using namespace std;

    // s[i...] 有多少种有效转化（先不取模，看清结构）
    long long f1(string& s, int i) {
        int n = s.size();
        if (i == n) return 1;
        if (s[i] == '0') return 0;
        // i 位置单独转：是 '*' 就有 9 种取法
        long long ans = f1(s, i + 1) * (s[i] == '*' ? 9 : 1);
        if (i + 1 < n) {
            if (s[i] != '*') {
                if (s[i + 1] != '*') {
                    if ((s[i] - '0') * 10 + s[i + 1] - '0' <= 26) ans += f1(s, i + 2);
                } else {
                    if (s[i] == '1') ans += f1(s, i + 2) * 9;   // 11 ~ 19
                    if (s[i] == '2') ans += f1(s, i + 2) * 6;   // 21 ~ 26
                }
            } else {
                if (s[i + 1] != '*') {
                    // '*' 只能取 1 或 2 才可能和后面凑成 <= 26
                    if (s[i + 1] <= '6') ans += f1(s, i + 2) * 2;
                    else ans += f1(s, i + 2);
                } else {
                    ans += f1(s, i + 2) * 15;                    // 11~19、21~26
                }
            }
        }
        return ans;
    }

实测两处错法的抓取率（2 万组随机串，对照组是「枚举 '*' 的所有取值再枚举所有切法」的暴力）：把 '*' 单转的 9 写成 10，22.66% 的样本偏大；把 '*'+'*' 的 15 写成 25，1.89% 的样本偏大（要串里出现连续的 '*' 才现形）。

不取模的话数字涨得飞快：全 '*' 的串，长度 2 是 96，长度 4 是 10431，长度 6 是 1136241，长度 8 是 123775776，长度 10 是 13483456911。所以从递归到 dp 的每一步都要取模。

五、解码方法 II 的填表

递归体照抄成从底到顶，每步取模。dp[i] 还是「s[i...] 的转化种数」。

#include <bits/stdc++.h>
    using namespace std;

    const long long MOD = 1000000007;

    // 把上面那个递归照抄成从底到顶，每步取模
    long long numDecodings3(string& s) {
        int n = s.size();
        vector<long long> dp(n + 1, 0);
        dp[n] = 1;
        for (int i = n - 1; i >= 0; i--) {
            if (s[i] != '0') {
                dp[i] = (s[i] == '*' ? 9 : 1) * dp[i + 1];
                if (i + 1 < n) {
                    if (s[i] != '*') {
                        if (s[i + 1] != '*') {
                            if ((s[i] - '0') * 10 + s[i + 1] - '0' <= 26) dp[i] += dp[i + 2];
                        } else {
                            if (s[i] == '1') dp[i] += dp[i + 2] * 9;
                            if (s[i] == '2') dp[i] += dp[i + 2] * 6;
                        }
                    } else {
                        if (s[i + 1] != '*') {
                            if (s[i + 1] <= '6') dp[i] += dp[i + 2] * 2;
                            else dp[i] += dp[i + 2];
                        } else {
                            dp[i] += dp[i + 2] * 15;
                        }
                    }
                }
                dp[i] %= MOD;
            }
        }
        return dp[0];
    }

样例：'1*' 得 18（单转 9 种 + 合起来 11~19 共 9 种），'2*' 得 15（9 + 6），'**' 得 96（81 + 15），'1*2' 得 20，'*0' 得 2（'0' 只能跟前面的 '*' 凑成 10 或 20）。

压缩版同样是三个变量，注意每轮结束要把 cur 清零：s[i] 是 '0' 时这一轮不改 cur，不清零就会把上一轮的值带下来。

#include <bits/stdc++.h>
    using namespace std;

    const long long MOD = 1000000007;

    // 空间压缩：next = dp[i+1]，nextNext = dp[i+2]
    long long numDecodings4(string& s) {
        int n = s.size();
        long long cur = 0, next = 1, nextNext = 0;
        for (int i = n - 1; i >= 0; i--) {
            if (s[i] != '0') {
                cur = (s[i] == '*' ? 9 : 1) * next;
                if (i + 1 < n) {
                    if (s[i] != '*') {
                        if (s[i + 1] != '*') {
                            if ((s[i] - '0') * 10 + s[i + 1] - '0' <= 26) cur += nextNext;
                        } else {
                            if (s[i] == '1') cur += nextNext * 9;
                            if (s[i] == '2') cur += nextNext * 6;
                        }
                    } else {
                        if (s[i + 1] != '*') {
                            if (s[i + 1] <= '6') cur += nextNext * 2;
                            else cur += nextNext;
                        } else {
                            cur += nextNext * 15;
                        }
                    }
                }
                cur %= MOD;
            }
            nextNext = next;
            next = cur;
            cur = 0;
        }
        return next;
    }

实测（长度 10⁶ 的全 '*' 串，取模版）：dp 数组 4.16ms，滚动变量 3.47ms。这里的分支比题 1 多，压缩省下来的比例没那么夸张，但空间从 O(n) 降到 O(1)。

每个位置只做常数次判断，所以都是 O(n)。两题的差别全在「分支合法吗、合法的话有几种」这件事上，结构一点没变。

七、总结

切分型一维动态规划的定义长一个样：f(i) 是后缀 s[i...] 的答案，i 上枚举「切一位」和「切两位」，两个分支相加。

'0' 的处理是两个题的共同坑：它既不能单独成组，也不能当两位数的开头，碰到就返回 0。边界 dp[n] = 1 是递推的种子，写漏了答案恒为 0。

'*' 把「有没有」改成了「有几种」，倍数是分类讨论出来的：单独 9 种、'1' 接 '*' 9 种、'2' 接 '*' 6 种、'*' 接小数字 2 种、两个 '*' 15 种。把这些倍数摆成一张表，代码就是照抄。
