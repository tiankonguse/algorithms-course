树型 dp：子树信息装进返回值

树上的动态规划有一套固定动作：先想清楚父节点要算出答案，需要子树的哪些信息，把这些信息定义成递归的返回值，父节点再把子树的返回值合起来。难点不在递归，在于第一句话要定几个量。

零、父节点要知道子树的什么

树是一个有向无环图：除了根，每个节点只有一个父亲；从根出发到任何节点，路径只有一条。

在树上做 dp，依赖关系比一般 dp 简单。绝大多数题目都是父依赖子，把子树算完，父节点就有原料了，不用像区间 dp 那样纠结「按什么顺序填表」。

依赖简单不代表题目简单。真正要想的是这一句：父节点要算出答案，需要子树的哪些信息？

它要的通常不止一个量。想知道一棵子树能不能当搜索树，父节点得知道它的最大值、最小值，以及它本身是不是搜索树；想算子树的和，还得知道子树和。要几个量，就把几个量打包进一个结构当返回值。

整理成四步：

  1. 分析父树得到答案，需要子树的哪些信息；
  2. 把子树信息的全集定义成递归返回值；
  3. 通过递归让子树返回全集信息；
  4. 整合子树的全集信息，得到自己的全集信息并返回。

第四步的「整合」是全部功夫所在，前三步只是把话说明白。

一、最大的二叉搜索子树

给一棵二叉树，找到其中最大的二叉搜索树（BST）子树，返回它的节点数。注意子树的定义：选了某个节点当根，它的全部后代必须一起算进来，不能只摘一部分。

朴素做法是枚举每个节点，判一次「以它为根的整棵子树是不是 BST」，取节点数最大的那个。判 BST 要把子树再走一遍，整体 O(n²)。

换四步来。要判断 x 这棵是不是 BST，需要左子树的最大值、右子树的最小值、以及左右两边是不是 BST；要返回「子树里最大 BST 的大小」，还得知道左右子树各自的答案。

于是返回值定成四个量：子树最大值 mx、子树最小值 mn、整棵子树是不是 BST 的 isBst、子树里最大 BST 的节点数 sz。

空节点返回 mx = −∞、mn = +∞、isBst = true、sz = 0。这组哨兵让叶子节点的判断自动成立：叶子的左孩子是空，L.mx < v 变成 −∞ < v；右孩子是空，v < R.mn 变成 v < +∞，两边都是真的。不用为叶子单独写分支。

合并的规则四条：

  1. mx = max(自己的值, 左 mx, 右 mx)，mn 同理取最小；
  2. isBst 要求左是 BST、右是 BST、左 mx 小于自己的值、自己的值小于右 mn；
  3. 自己是 BST 时，sz = 左 sz + 右 sz + 1；
  4. 自己不是 BST 时，sz = max(左 sz, 右 sz)，答案只能从某一边来。

第二条的两个区间比较不能省。只看「左右都是 BST」就宣布自己是 BST，等于默认任意值和左右子树的大小关系都对。实测在值域 ±2 的随机小树上，这处写漏的版本 99.19% 出错。

还有一处细节：哨兵建议用 long long 的极值，别用 int 的。节点值可能取到 int 的边界，拿 INT_MIN 当负无穷时，一个值恰好等于 INT_MIN 的节点会被判成「不小于负无穷」，判断直接反了。

struct Info {
        long long mx;
        long long mn;
        bool isBst;
        int sz;
    };

    Info f(Node* x) {
        if (x == nullptr) return {LLONG_MIN, LLONG_MAX, true, 0};
        Info L = f(x->left);
        Info R = f(x->right);
        long long v = x->val;
        long long mx = max(v, max(L.mx, R.mx));
        long long mn = min(v, min(L.mn, R.mn));
        bool isBst = L.isBst && R.isBst && L.mx < v && v < R.mn;
        int sz = isBst ? L.sz + R.sz + 1 : max(L.sz, R.sz);
        return {mx, mn, isBst, sz};
    }

    int largestBSTSubtree(Node* root) {
        return f(root).sz;
    }

上图这棵树的值是 10、5、1、20、15。整棵树不是 BST，因为左子树里有个 20 比 10 大。但以 5 为根的子树是：1 < 5 < 20，三个节点都合规，所以答案是 3。

二、二叉搜索子树的最大键值和

换一个问法：返回任意一棵 BST 子树的最大键值和。骨架和上一题一样，返回值多一个量 sum，答案字段叫 best。

sum = 左 sum + 右 sum + 自己的值。best 先取 max(左 best, 右 best)，如果自己这棵是 BST，再和 sum 取一次最大。

判断自己是不是 BST 的三个条件和上一题一个字不差，照样不能省。

空节点返回 best = 0，等于承认「空子树」也算一个键值和为零的 BST。所以一棵全是负数的树，这套代码会返回 0：比如 −4 带 −2、−5 两个儿子，单看节点最大值是 −2，返回值是 0。这是哨兵选的，写代码时心里要有数。

漏掉 isBst 判断、直接拿 sum 参与取最大，同样在随机小树上 43.95% 出错。搜索树题目的错法都很像：少一个约束，多算一堆不该算的子树。

struct Info {
        long long mx;
        long long mn;
        long long sum;
        bool isBst;
        long long best;
    };

    Info f(Node* x) {
        if (x == nullptr) return {LLONG_MIN, LLONG_MAX, 0, true, 0};
        Info L = f(x->left);
        Info R = f(x->right);
        long long v = x->val;
        long long mx = max(v, max(L.mx, R.mx));
        long long mn = min(v, min(L.mn, R.mn));
        long long sum = L.sum + R.sum + v;
        bool isBst = L.isBst && R.isBst && L.mx < v && v < R.mn;
        long long best = max(L.best, R.best);
        if (isBst) best = max(best, sum);
        return {mx, mn, sum, isBst, best};
    }

    long long maxSumBST(Node* root) {
        return f(root).best;
    }

三、二叉树的直径

直径是任意两个节点之间最长路径的边数，路径可以不过根节点。这一句「可以不过根」就是全部的难点。

递归要同时带两个量回来：以 x 为头往下走的最大边数 h，和子树内部已有的最长路径 dia。

  • h = max(左 h, 右 h) + 1；
  • dia = max(左 dia, 右 dia, 左 h + 右 h)。

第三项是「跨过 x」的那条路径：左边挑一条最深的、右边挑一条最深的，在 x 处接起来。漏掉它，答案就退化成「子树里最长的那个」，实测 n ≥ 3 的随机树上 100% 出错。

struct Info {
        int dia;
        int h;
    };

    Info f(Node* x) {
        if (x == nullptr) return {0, 0};
        Info L = f(x->left);
        Info R = f(x->right);
        int h = max(L.h, R.h) + 1;
        int dia = max(max(L.dia, R.dia), L.h + R.h);
        return {dia, h};
    }

    int diameterOfBinaryTree(Node* root) {
        return f(root).dia;
    }

同样三行代码，树形一变答案差得很远。左链 n = 7、15、31 时直径是 6、14、30，就是 n − 1；完全二叉树同样节点数是 4、6、8，等于两倍树高。图 5 是这两种极端加上随机树的对照。

复杂度分析

题目时间空间
最大 BST 子树O(n)O(h)
二叉搜索子树的最大键值和O(n)O(h)
二叉树的直径O(n)O(h)

三题都是每个节点进一次、出一次，合并是常数次比较和加法，时间 O(n)。空间是递归栈，深度等于树高 h；链状树 h = n，空间 O(n)。

递归深度是实测过的边界，别不当回事。本机 8 MB 栈下，最大 BST 子树那版在左链上最多撑到 86952 层，65214 层的最大键值和版就到顶了（返回值里有五个 long long，栈帧大），直径和监控那种只返回两个 int 的能到 173906 层。同一个 n = 10⁶ 的随机树，深度只有 47，随便跑。

总结

树型 dp 的四步里，第一步是全部：先定「父节点要知道子树的什么」，剩下的都是把这句话写下来。

返回值可以是一包信息。搜索树家族的标准包是「最大值、最小值、是否 BST」，再按题目加聚合量，加大小就是最大 BST 子树，加和就是最大键值和。

空节点的哨兵要挑得让叶子的判断自动成立：max 取 −∞、min 取 +∞、isBst 取 true。挑错了会冒出一堆本不该有的分支。

最容易漏的是「跨过当前节点」那一项：直径里的 左 h + 右 h、搜索树里的两个区间比较，都属于这种。它不写在代码里，样例照样过，答案就是偏的。

树上做的 dp，依赖的子结构也不一定非得是子树。把树拍成一段连续区间之后，还有另一类转移可以顺着区间走。
