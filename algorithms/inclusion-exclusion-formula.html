容斥化成公式：播放列表的数量

n 首歌里排出长度 l 的播放列表，每首至少放一次，同一首歌要重播得先让 k 首别的歌插进来。容斥在这里不用建任何查询表，直接化成一个能 O(n log l) 算出来的式子。

零、两条规则说了什么

第二条规则换个说法更好用：任意连续 k + 1 个位置里的歌必须两两不同。因为一首歌重播时，它上一次出现的位置离现在至少 k + 1 格，中间夹着 k 首别的歌。

先看一个好算的版本：手里有 m 首歌可选，不要求每首都出现过，只要求满足第二条规则，长度 l 的播放列表有多少个？

第 1 个位置随便挑，m 种。第 2 个位置不能跟第 1 个重复（k ≥ 1 时），m − 1 种。第 p 个位置不能跟前面 min(k, p − 1) 个位置里的任何一首重复，所以是 m − min(k, p − 1) 种。前 k 个位置乘起来是 m · (m − 1) · … · (m − k + 1)，记成 (m)k；从第 k + 1 位往后，每一位都固定是 m − k 种，一共 l − k 位。

f(m) = (m)k · (m − k)l − k。

这个 f(m) 把「每首至少一次」这条漏掉了，它只保证第二条规则。补回来靠容斥。

一、把缺席的歌容斥掉

设 Aj 是「第 j 首歌从头到尾没出现」的播放列表集合。要的是一条 Aj 都不沾的数量，也就是总数减去所有 Aj 的并集。

交集的规模好算：指定 i 首歌不许出现，剩下的 m = n − i 首歌自由发挥，方案数恰好就是 f(m)。选哪 i 首有 C(n, i) 种，于是容斥一套就出来了。

答案 = Σi=0.. (−1)i · C(n, i) · f(n − i)。

i 的上界值得想清楚。m = n − i 首歌要排满 l ≥ n 个位置且满足第二条规则，m 至少得是 k；而 m = k 时 (m − k)l − k = 0l − k = 0，这一项恒为 0（题目给 l ≥ n > k，所以指数是正的）。m 再小更是 0。于是 i 只走到 n − k − 1，代码里写成循环条件 i < n − k。

把 C(n, i) 和 (m)k 都写成阶乘，能看见它们怎么捏成代码里的三次查表：

C(n, i) · (n − i)k = n! / (i! · (n − i)!) · (n − i)! / (n − i − k)! = n! / (i! · (n − i − k)!)。

两个 (n − i)! 正好约掉，剩下 fac(n) · inv(i) · inv(n − i − k)。这正是上一页的阶乘逆元表在这里的用处：每一项三次查表 O(1)。

// 容斥：枚举「有 i 首歌根本没出现」
    long long numMusicPlaylists(int n, int l, int k) {
        long long ans = 0, sign = 1;
        for (int i = 0; i < n - k; i++, sign = sign == 1 ? MOD - 1 : 1) {
            long long cur = sign * power(n - i - k, l - k, MOD) % MOD;
            cur = cur * fac[n] % MOD;           // n!
            cur = cur * inv[i] % MOD;           // 1 / i!
            cur = cur * inv[n - i - k] % MOD;   // 1 / (n-i-k)!
            ans = (ans + cur) % MOD;
        }
        return ans;
    }

表里 fac、inv 的建法就是连续阶乘逆元的线性递推，n ≤ 100 时开到 100 就够。

二、拿动态规划对一遍

这道题还有一条更好想的路：f(i, j) 表示前 i 个位置用了 j 首不同的歌。第 i 个位置要么放一首没出现过的新歌，有 n − j + 1 种挑法；要么放一首老歌，前提是已经用过的 j 首里，最近 k 首不能选，于是有 j − k 种（j ≤ k 时一首都不能重播）。

f(i, j) = f(i − 1, j − 1) · (n − j + 1) + f(i − 1, j) · max(0, j − k)。

// 动态规划参考：f[i][j] 是前 i 个位置用了 j 首不同的歌
    long long musicDP(int n, int l, int k) {
        vector<vector<long long>> f(l + 1, vector<long long>(n + 1, 0));
        f[0][0] = 1;
        for (int i = 1; i <= l; i++) {
            for (int j = 1; j <= n; j++) {
                f[i][j] = f[i - 1][j - 1] * (n - j + 1) % MOD;   // 放一首没出现过的新歌
                if (j > k) {
                    f[i][j] = (f[i][j] + f[i - 1][j] * (j - k)) % MOD;  // 放一首老歌
                }
            }
        }
        return f[l][n];
    }

两个算法在 n = l = 100、k = 50 上给出同一个数 437918130，两万两千组随机参数也全部一致。差别在代价：DP 要填 n · l 个格子，容斥只算 n − k 项。

实测单次调用：n = l = 100、k = 50 时容斥 0.666 微秒、DP 12.3 微秒，差 18 倍。更能说明问题的是 l 继续往上走：n = 100、k = 50 时 l = 10 用 0.0002 毫秒，l = 106 用 0.0034 毫秒，l = 109 还是 0.0055 毫秒，因为项数从头到尾都是 50，只有快速幂的轮数从 4 涨到 30。同一个 l = 109 交给 DP 要 1011 个格子，按 8 字节算是 800 GB。

顺手记两个错法的抓取率。把循环上界写成 i < n，多算进去的那些项里 (n − i − k) 是 0 或者负数，快速幂会算出莫名其妙的值。但这个错法在 k = 0 和 k = 1 时完全看不出来，多出来的那一项底数恰好是 0，整项为零；k = 2 起 100.00% 现形。写对数器时 k 只取 0 和 1 的话，这个 bug 会一路带到考场上。

另一个是 sign 不交替，抓取率 46.00%。

三、逐帧看一遍

容斥逐项累加：每一项是怎么凑出来的

橙格是当前这一项，蓝格是已经加进去的项。走到最后一项时，旁边的动态规划结果会一起列出来对照。

小例子逐条枚举：把 nl 个序列挨个检查一遍

绿色是通过两条规则的序列。规则二查的是「当前这首歌在前面 k 个位置里有没有出现过」。

复杂度分析

做法关键操作时间空间
动态规划填 n × l 个格子，每格 O(1)O(n · l)O(n · l)，可压到 O(n)
容斥 + 阶乘逆元n − k 项，每项一次快速幂 + 三次查表O(n log l + n)O(n)

容斥的项数是 n − k，每项一次快速幂（指数 l − k，轮数 log2(l − k)）加三次查表，加上建阶乘逆元表的 O(n)，总时间 O(n log l + n)。n = l = 100、k = 50 时单次 0.666 微秒，l 拉到 109 也只涨到 0.0055 毫秒。DP 的 n · l 个格子在 l = 109 时是 1011 个，800 GB，开不出来，这才是容斥版真正的价值。

总结

把「一首歌重播之前要有 k 首别的歌」翻译成「任意连续 k + 1 个位置两两不同」，计数就变成前 k 位逐个递减、之后每位 m − k 种，闭式是 f(m) = (m)k · (m − k)l − k。

「每首至少一次」靠容斥补：指定 i 首歌缺席，剩下 n − i 首的方案数正好是 f(n − i)，配上 C(n, i) 和 (−1)i 求和。i 的上界是 n − k − 1，因为 m ≤ k 时那一项恒为 0。

项里那个 C(n, i) · (n − i)k 化简成 n! / (i! · (n − i − k)!)，三次查表拿到，用的正是阶乘逆元那张表。两个算法在两万两千组随机参数上答案一致，容斥胜在 l 能开到 109。

写循环上界时别想当然地写 i < n，k ≤ 1 时它看不出错，k ≥ 2 时 100% 现形。sign 的交替也别忘了。

这一类「先放宽、再容斥」的思路跟上一页的打表查询是同一件事，区别只在中间那个量是查表拿到的还是直接有闭式。
