位运算的常见技巧

一千万次「数二进制里有几个 1」：逐位判断 15.32 毫秒，位运算五步写法 3.16 毫秒。这一讲看六个具体问题：判断 2 的幂、判断 3 的幂、找大于等于 n 的最小 2 的幂、求区间内所有数字的按位与、逆序 32 位二进制、数 1 的个数。前四个靠同一个操作：把最右侧的 1 取出来。后两个靠同一套分治：先两两合并，再四四合并，一路合并到头。

零、背景

int 是 32 个格子，负数用补码存，这些在前面讲过了。这一讲的东西基本都建在一个操作上：n & -n，把 n 最右侧的那个 1 单独取出来，其余位清零。

它的来历不神秘。-n 等于 ~n + 1，看加法过程：n 最右侧那个 1 的左边全部取反，这一位自己还是 1，右边全是 0；~n 加 1 之后，进位一直传到这一位才停。于是 n 和 -n 在这一位上同为 1，左边全部相反（一边是 0 另一边就是 1），右边都是 0。两者一与，只剩那一位。

后面几节会反复用到它。先说清楚一件事：代码里所有位操作都写成 unsigned。有符号数右移补的是符号位，-8 >> 1 是 -4（左边补 1），这不是我们要的「整体右移」；unsigned 的右移才是逻辑右移，左边补 0。

一、判断一个整数是不是 2 的幂

2 的幂写成二进制只有一个 1：1、2、4、8 分别是 1、10、100、1000。所以 n 等于它自己最右侧的那个 1 时，n 就是 2 的幂。

n > 0 这个守卫不能省。int 里一共有 33 个数满足 n == (n & -n)：31 个 2 的幂，加上 0 和 -2147483648。0 满足是因为 0 & 0 = 0；-2147483648 满足是因为它的相反数在补码里绕回自己，n & -n 还是它自己。这两类都不是 2 的幂，靠 n > 0 一次挡掉。

// n & -n 提取出最右侧的 1
    // 2 的幂的二进制里只有一个 1，于是 n == (n & -n)
    bool isPowerOfTwo(int n) {
        return n > 0 && n == (n & -n);
    }

一次取负、一次与、一次比较，O(1)。这个写法有个名字，Brian Kernighan 算法，因为它最早出现在那本《C 程序设计语言》的习题里。

二、判断一个整数是不是 3 的幂

这题用不上位运算，用的是「int 范围内最大的 3 的幂」：3 的 19 次方 = 1162261467，再往上 3 的 20 次方 = 3486784401，已经超过 int 上限 2147483647。

1162261467 的质因子只有 3，它的正约数恰好是 3 的 0 次方到 3 的 19 次方，一共 20 个。所以 n 能整除它，等价于 n 是 3 的某次幂。反过来，n 里只要混了别的质因子，就一定除不尽。

// 1162261467 是 int 范围内最大的 3 的幂，它是 3 的 19 次方
    // 它的质因子只有 3，能整除它的正整数也只有 3 的各次幂
    bool isPowerOfThree(int n) {
        return n > 0 && 1162261467 % n == 0;
    }

底数必须是质数，换成合数就不成立了。int 内最大的 6 的幂是 6 的 11 次方 = 362797056，它的约数里混着 2、3、4、8、9、12 这些数。拿它去判「是不是 6 的幂」，1 到 100000 里有 83 个数会被误判。

三、返回大于等于 n 的最小的 2 的幂

分两步：先把 n - 1 的最高位那个 1 右边全部涂成 1，再加 1 让它进到上一位。01100100（100）涂开成 01111111，加 1 就是 10000000（128）。

涂开靠五句 |=：n >>= 1 复制一份挪一位，现有的 1 就并排了；接着挪 2 位、4 位、8 位、16 位。位移量加起来 1 + 2 + 4 + 8 + 16 = 31，32 位里不论最高位在哪，都能一路传染到最低位。

为什么要先减 1。n 本身就是 2 的幂时，不减 1 会往上翻一格：8 涂开还是 0111 → 1000，加 1 变成 10000 = 16，错了。减了 1，8 变成 7（0111），涂开是 0111，加 1 回到 1000 = 8，对的。

// 返回大于等于 n 的最小的 2 的幂
    // 全程用 unsigned，右移才是逻辑右移（左侧补 0）
    // n 超过 2 的 30 次方时，int 范围内没有答案，返回 0（等价于原实现的「返回最小值」）
    unsigned int near2power(unsigned int n) {
        if (n == 0) {
            return 1;
        }
        n--;
        n |= n >> 1;
        n |= n >> 2;
        n |= n >> 4;
        n |= n >> 8;
        n |= n >> 16;
        return n + 1;
    }

两个边界：n 等于 0 走单独分支返回 1（减 1 会变成 -1）；n 超过 2 的 30 次方时，答案在 int 里装不下，2 的 30 次方加 1 算出来是 2147483648，按 int 读出来是 -2147483648，用 unsigned 接住则是 0（加 1 溢出去的那一位丢掉）。

实测一千万次调用：这个写法 2.50 毫秒，循环左移一位一位去找要 105.52 毫秒。

四、区间 [left, right] 内所有数字按位与的结果

朴素做法是把区间里每个数都 & 一遍。区间长 1000 万时实测 8.89 毫秒，还能忍；区间长度要是 21 亿，就没法算了。

换个角度看结果的样子。区间里的数是 left 一个数一个数加上去的，某一位只要在这一路上出现过 0，这一位的结果就是 0。left 和 right 最高的那个不同位以下，一定既有 0 也有 1：从 left 加到 right，必然跨过 xxxx1000...000 这种形状的数，它后面全是 0，而 right 在那一位上是 1。所以答案就是 left 和 right 的最长公共前缀，后面补 0。

实现顺着这个结论走：让 right 反复减掉自己最右侧的 1，一直减到它不再大于 left。减到最后，right 剩下的就是「公共前缀 + 全 0」。

// 返回区间 [left, right] 内所有数字 & 的结果
    // 每次去掉 right 最右侧的 1，直到 right 不再大于 left
    int rangeBitwiseAnd(int left, int right) {
        while (left < right) {
            right -= right & -right;
        }
        return right;
    }

循环次数最多 31：[0, 2147483647] 就是这个上限，答案是 0。随机区间（长度不超过 2000）实测平均 5.69 次、最多 11 次。[5, 7] 两步就停：7 去掉最右的 1 变 6，还大于 5，再去掉变 4，不大于 5 了，答案是 4。

五、逆序 32 位二进制

最直白的写法是循环 32 次，每次从低位摘一位搬到结果的高位。位运算的写法是分治：先交换相邻的 1 位，再交换相邻的「2 位一组」，接着 4 位、8 位、16 位，五步完成。

掩码是成对出现的：0x55555555 是 0101 0101 …，取每个两位组的低位；0xaaaaaaaa 是 1010 1010 …，取高位；右边那句把它们一个右移一个左移再或起来，两组就换了位置。第二步换 0x33333333（0011 0011 …）与 0xcccccccc（1100 1100 …），后面同理。五步一共 15 次运算。

// 逆序 32 位二进制：先换相邻位，再换相邻 2 位、4 位、8 位、16 位
    unsigned int reverseBits(unsigned int n) {
        n = ((n & 0xaaaaaaaa) >> 1) | ((n & 0x55555555) << 1);
        n = ((n & 0xcccccccc) >> 2) | ((n & 0x33333333) << 2);
        n = ((n & 0xf0f0f0f0) >> 4) | ((n & 0x0f0f0f0f) << 4);
        n = ((n & 0xff00ff00) >> 8) | ((n & 0x00ff00ff) << 8);
        n = (n >> 16) | (n << 16);
        return n;
    }

实测一千万次：这个写法 0.57 毫秒，逐位循环 89.31 毫秒，差 157 倍。差距不来自「运算次数少一半」，而来自循环里那个分支：每次都要猜方向，猜错了流水线就断一次。

六、数二进制里有几个 1

还是分治，把「交换」换成「求和」。第一步每 2 位算出这两位里有几个 1，结果就写回这 2 位里；第二步每 4 位把两个 2 位的和加起来，写回这 4 位；一路加到 32 位，最低那个字段就是答案。

写回去不会串位。k 位一组的和最大是 k：2 位一组最大 2（占 2 位），4 位一组最大 4（占 3 位），8 位一组最大 8（占 4 位），位宽一直够用，不会挤到隔壁组去。

// 返回 n 的二进制中有几个 1
    // 两位一组求和 → 四位一组 → 八位 → 十六位 → 三十二位，五步出结果
    unsigned int cntOnes(unsigned int n) {
        n = (n & 0x55555555) + ((n >> 1) & 0x55555555);
        n = (n & 0x33333333) + ((n >> 2) & 0x33333333);
        n = (n & 0x0f0f0f0f) + ((n >> 4) & 0x0f0f0f0f);
        n = (n & 0x00ff00ff) + ((n >> 8) & 0x00ff00ff);
        n = (n & 0x0000ffff) + ((n >> 16) & 0x0000ffff);
        return n;
    }

    // 汉明距离：两个数二进制位不同的位置有多少个
    unsigned int hammingDistance(unsigned int x, unsigned int y) {
        return cntOnes(x ^ y);
    }

汉明距离（两个数二进制位有多少位不同）就是它的一句话应用：先异或，再数 1。x ^ y 为 1 的位，恰好是 x 和 y 不一样的位。

四种写法各跑一千万次的实测：

1）逐位判断（循环 32 次带 if）：15.32 毫秒。

2）Brian Kernighan（while (n) { n &= n - 1; c++; }）：0.53 毫秒。

3）SWAR 五步（上面那段）：3.16 毫秒。

4）__builtin_popcount：0.51 毫秒。

结果有点反直觉：BK 那个循环比手写的五步还快 6 倍。原因是编译器认得它：n &= n - 1 的循环会被识别成 popcount，直接编译成硬件指令（这台机器是 ARM，生成的是 NEON 的 cnt 指令），跟 __builtin_popcount 同一档。所以别为了少几次运算去写 SWAR。

SWAR 的价值在别处：它没有分支、没有循环，跑多久跟数据长什么样无关。关掉优化再测一遍就看得出来（-O0，一千万次）：SWAR 稳定 36.59 毫秒；BK 随 1 的个数变，数里只有 1 个 1 时 32.15 毫秒，随机数据平均 16 个 1 时涨到 235.08 毫秒；逐位判断 1280.36 毫秒。要写「执行时间不随数据变化」的代码（密码学、实时处理这类），SWAR 那份才有意义。

话说回来，练算法的时候没必要刻意少写条件判断。逐位判断那一版 15.32 毫秒也是能过的，写直白、写自己能看懂的代码更重要。这几份实现当模板存着，看懂就行。

七、复杂度分析

六个问题的代价都在常数级，区别只是常数有多大：

问题朴素做法本节写法运算次数额外空间
判断 2 的幂除 2 数到 1，O(log n)O(1)3 次（取负、与、比较）O(1)
判断 3 的幂反复除 3，O(log₃ n)O(1)1 次取模（n > 0 时）O(1)
最小 2 的幂循环左移，O(log n)O(1)11 次（减 1 + 5 组 |= + 加 1）O(1)
区间按位与O(right − left)O(log V)，最多 31 次≤ 31 次消 1O(1)

空间全是 O(1)：六个实现都只在寄存器里倒腾，不开数组、不递归。区间按位与那题尤其明显，朴素做法只用一个变量存结果，技巧版同样只用一个变量，省的是时间。

八、总结

要点列一下：

1）n & -n 取最右侧的 1，是这一讲的工具箱底座。判断 2 的幂、区间按位与、树状数组的 lowbit 都用它。

2）2 的幂用位运算判，3 的幂用「int 内最大幂整除」判，后者只对质数底成立，6 的幂这么判会误判。

3）涂开五步求最小 2 的幂，先减 1 是关键，不减会把已经是 2 的幂的数往上翻一格。

4）区间按位与 = left 与 right 的最长公共前缀后面补 0，实现上就是反复消掉 right 最右侧的 1。

5）逆序和数 1 是同一套分治，一个交换一个求和，五步都是 15 次运算。

6）跑分要看编译器：BK 那个循环会被识别成 popcount 编成硬件指令，比手写 SWAR 更快。写常规代码用 BK，追求「执行时间不随数据变化」才用 SWAR。

再往后，位运算还有两块更重的用处：状态压缩的动态规划里，一个 int 当集合用；N 皇后那类题里，一个 int 同时表示哪些列、哪些对角线被占住了。这两块留到后面讲。
