哈希表设计：setAll 与 O(1) 随机集合

数据结构设计题不考新结构，考的是把哈希表、数组、链表这些旧零件按需拼起来。这一讲三题的地基都是同一对组合：哈希表负责 O(1) 定位，数组负责按位置访问。区别只在哈希表里存什么：时间戳、下标，还是下标集合。

零、背景

「设计一个结构，几个操作全部 O(1)」是笔试常客。单个结构往往撑不起这种要求：哈希表能 O(1) 查值，但没法按位置随机取；数组能 O(1) 按下标访问，但删中间元素要搬后面的全部。

把两个拼起来就好办了。哈希表记「值 → 位置」，数组按位置存真身，两边各干各擅长的。setAll、随机集合这两类题，都是在给这个组合加一个 O(1) 操作：要么让批量赋值变懒，要么让删除不搬移。

一、setAll 的哈希表

题目 1：普通哈希表的四个操作，外加一个 setAll(v)：把表里所有键的值一次性改成 v，要求每个操作都是 O(1)。

最直白的做法是 setAll 时真的遍历整张表，把每个键的值改掉。这步是 O(n)，表越大越扛不住。实测：2 万个键、10 万次操作（其中约 1 万次 setAll），全量改的总耗时 707 毫秒，其中 setAll 单次平均要碰 2 万个键。

不想真改，就得把「该改成什么」记下来。给每个键的值配一个时间戳，同时记一个全局的 setAllValue 和 setAllTime：

  • put(k, v)：表里存 (v, 当前时间戳)，时间戳自增
  • setAll(v)：只改 setAllValue = v、setAllTime = 当前时间戳
  • get(k)：键的时间戳 > setAllTime 说明是 setAll 之后单独写的，返回自己的值；否则返回 setAllValue

setAll 从 O(n) 变成 O(1)：只动两个变量，一个键都不用碰。get 也只是多一次比较。实测同一份 10 万次操作，懒标记版 3.4 毫秒，快 208 倍。

// setAll 功能的哈希表：值带时间戳，setAll 只记懒标记
    class SetAllMap {
    public:
        unordered_map<int, pair<int, int>> map;   // key -> (value, time)
        int setAllValue = 0;
        int setAllTime = -1;
        int cnt = 0;

        void put(int k, int v) {
            map[k] = {v, cnt++};
        }

        void setAll(int v) {
            setAllValue = v;
            setAllTime = cnt++;
        }

        int get(int k) {
            if (!map.count(k)) {
                return -1;
            }
            auto [v, t] = map[k];
            return t > setAllTime ? v : setAllValue;
        }
    };

这里有个细节：cnt 一直自增，理论上会溢出，但题目的键数和操作数都有限，int 够用。另外 get 一个不存在的键返回 -1，题目约定如此。

二、O(1) 随机集合

题目 3（LeetCode 380）：设计一个结构，支持 insert、remove、getRandom，三个操作全 O(1)。getRandom 要求等概率返回集合里的任意一个元素。

哈希集合能 O(1) 判重、删除，但 getRandom 没办法。哈希表不保序，也没有下标。数组能 O(1) 按下标取，但删中间元素要搬移，平均 O(n)。

组合起来：哈希表记「值 → 下标」，数组按位置存值。

  • insert(val)：表里没有才插。值追加到数组尾，表里记它的下标，返回 true；已存在返回 false
  • getRandom()：arr[rand() % size]，等概率
  • remove(val)：表里有才删。把数组最后一个元素搬到 val 的位置，盖掉它，再弹掉数组尾。表里把被搬走的那个值的下标改成 val 的原下标

删除不搬中间，只搬最后一个，所以是 O(1)。搬完数组尾部多出一个没人要的旧副本，直接弹掉。实测：10 万个数里删 5 万次，交换删除 3.2 毫秒；用数组真删（每次搬平均 5 万个元素、一共 25 亿次搬移）695 毫秒，差 214 倍。

// O(1) 随机集合：map 记值->下标，删除时把末尾元素换过来再弹尾
    class RandomizedSet {
    public:
        unordered_map<int, int> map;   // val -> index
        vector<int> arr;

        bool insert(int val) {
            if (map.count(val)) {
                return false;
            }
            map[val] = (int)arr.size();
            arr.push_back(val);
            return true;
        }

        bool remove(int val) {
            if (!map.count(val)) {
                return false;
            }
            int valIndex = map[val];
            int endValue = arr.back();
            map[endValue] = valIndex;
            arr[valIndex] = endValue;
            map.erase(val);
            arr.pop_back();
            return true;
        }

        int getRandom() {
            return arr[rand() % (int)arr.size()];
        }
    };

还有个边界：要删的恰好是末尾元素时，交换逻辑照走，map[endValue] = valIndex 把末尾值自己的下标改成它自己，再 pop，结果一样对。

三、允许重复的随机集合

题目 4（LeetCode 381）：上一题放款条件，集合允许重复数字。insert 返回「这个值是不是第一次出现」。其余要求不变，全 O(1)。

难点是同一个值有好几个下标，删一个不能把别的也带走。哈希表里存的从「一个下标」升级成「一个下标集合」：map: 值 → set<下标>。

  • insert(val)：值追加到数组尾，下标塞进该值的集合。返回 set.size() == 1，为 true 说明这是第一次出现
  • remove(val)：从该值的下标集合里任取一个（代码取最小下标，行为确定），末尾值搬过来，两边的下标集合各改一下；末尾值和要删的值相同时，直接从集合里删下标，不用搬
  • getRandom()：照旧 arr[rand() % size]

和上一题唯一的差别在 remove 要维护两个集合的增删，搬移动作一模一样：末尾值换到被删位置，集合里删掉旧下标、加进新下标。

// 允许重复的 O(1) 随机集合：map 记值->下标集合，删除时只动一个下标（取最小下标，行为确定）
    class RandomizedCollection {
    public:
        unordered_map<int, unordered_set<int>> map;   // val -> set of index
        vector<int> arr;

        bool insert(int val) {
            arr.push_back(val);
            unordered_set<int> &set = map[val];
            set.insert((int)arr.size() - 1);
            return set.size() == 1;
        }

        bool remove(int val) {
            if (!map.count(val)) {
                return false;
            }
            unordered_set<int> &valSet = map[val];
            int valAnyIndex = *min_element(valSet.begin(), valSet.end());
            int endValue = arr.back();
            if (val == endValue) {
                valSet.erase((int)arr.size() - 1);
            } else {
                unordered_set<int> &endValueSet = map[endValue];
                endValueSet.insert(valAnyIndex);
                arr[valAnyIndex] = endValue;
                endValueSet.erase((int)arr.size() - 1);
                valSet.erase(valAnyIndex);
            }
            arr.pop_back();
            if (valSet.empty()) {
                map.erase(val);
            }
            return true;
        }

        int getRandom() {
            return arr[rand() % (int)arr.size()];
        }
    };

三题的空间都是 O(n)：哈希表一份、数组一份。允许重复版的下标集合加起来也正好是数组长度，没有多余。

五、总结

把三题摆在一起看，套路就一条：哈希表定位置，数组保随机，删除靠交换，批量靠懒标记。

setAll 的关键是别真改，值带时间戳，setAll 只动全局两个变量；随机集合的关键是删除别搬中间，末尾元素换过来。允许重复时，哈希表存下标集合，删一个只动一个下标。

下一讲把数组换成能排次序的结构：LRU 用双链表排「最近使用」，中位数用双堆放两半，频率栈用分层栈，全 O(1) 结构用桶链表。哈希表依然负责定位，只是另一半换了零件。
