区间 dp：分界点是最后一步

分界点也可以是一个「动作」，而不是一个「位置」：最后爆的那个气球、最后执行的那个运算符。这么切出来的两块互不干扰，可顺着题面从第一步开始枚举，反而写不出转移。

零、不能从第一步开始枚举

戳气球这道题是这样的：一排气球，每个上面有个数。戳破第 i 个得 nums[i−1] * nums[i] * nums[i+1] 枚硬币，戳完就没了，左右两边靠过来。数组边界外当作有一个数字为 1 的气球。问最多能拿多少。

样例 [3, 1, 5, 8] 返回 167，[1, 5] 返回 10。

第一反应是枚举「先戳哪个」。设先戳 k，这一下拿到 arr[k−1] * arr[k] * arr[k+1]，看起来很清楚。麻烦在下一步：k 没了之后，k 左边的球和右边的球贴到了一起，k−1 的右边邻居换成了 k+1。左边那一堆怎么爆，会受右边那一堆的影响，两块不能分开算。

换成枚举「这一段里最后爆哪个」。设最后爆的是 k。它爆的时候，这一段的其它球都已经爆完了，所以此刻贴在 k 左右两边的，只可能是这一段外面的那两个球 arr[l−1] 和 arr[r+1]。这一下拿到的钱 arr[l−1] * arr[k] * arr[r+1] 只跟两个边界有关，是个常数。

更重要的是独立性。k 在它爆之前的整段时间里一直都在，它把左边那堆和右边那堆隔开：左边的球永远不会有右边那堆当邻居，反之也一样。于是左边怎么爆和右边怎么爆互不相干，两块子问题真的独立了。

一步之差，一个能拆、一个不能拆。想不出来的时候回头问一句「谁最后完成」，是这类题的通用出口。

一、戳气球

先给数组两端各补一个 1，得到 arr[0..n+1]，arr[0] = arr[n+1] = 1。补完之后，任何一段的气球的两堵墙都变成了真实存在的下标，写转移时不用再特判越界。

状态：f(l, r) 表示 arr[l..r] 这些气球排一个爆的顺序，最多拿多少。前提是 arr[l−1] 和 arr[r+1] 一定还没爆。

转移：枚举这一段里最后爆的那个 k，l ≤ k ≤ r：

f(l, r) = max over k ( arr[l−1] · arr[k] · arr[r+1] + f(l, k−1) + f(k+1, r) )

边界：l > r 是空区间，返回 0。剩下两种边界都能被循环吃掉：k = l 时左边是空区间，k = r 时右边是空区间，两边都返回 0，剩下的就是 arr[l−1] · arr[k] · arr[r+1]，正好是只剩一个气球时的答案。

// arr 两端各补了一个 1，[l..r] 这些气球决定一个打爆顺序，求最大得分
    // 前提：arr[l-1] 和 arr[r+1] 一定还没爆，它们就是这一段的两堵墙
    int f(vector<int>& arr, int l, int r, vector<vector<int>>& dp) {
        if (l > r) return 0;                         // 空区间
        if (dp[l][r] != -1) return dp[l][r];
        int ans = 0;
        for (int k = l; k <= r; k++) {               // 枚举最后打爆的那个气球
            ans = max(ans, arr[l - 1] * arr[k] * arr[r + 1]
                           + f(arr, l, k - 1, dp) + f(arr, k + 1, r, dp));
        }
        return dp[l][r] = ans;
    }

    int maxCoins(vector<int>& nums) {
        int n = nums.size();
        vector<int> arr(n + 2);
        arr[0] = arr[n + 1] = 1;
        for (int i = 0; i < n; i++) arr[i + 1] = nums[i];
        vector<vector<int>> dp(n + 2, vector<int>(n + 2, -1));
        return f(arr, 1, n, dp);
    }

铺表的时候区间长度从 1 长到 n。外层 l 从 n 递减到 1，内层 r 从 l 递增到 n。k 两侧的 dp[l][k−1] 和 dp[k+1][r] 都比当前区间短，已经算过了。

int maxCoins(vector<int>& nums) {
        int n = nums.size();
        vector<int> arr(n + 2);
        arr[0] = arr[n + 1] = 1;
        for (int i = 0; i < n; i++) arr[i + 1] = nums[i];
        vector<vector<int>> dp(n + 2, vector<int>(n + 2, 0));
        for (int l = n; l >= 1; l--) {                       // 区间左端从右往左
            for (int r = l; r <= n; r++) {                   // 右端从左往右
                int ans = 0;
                for (int k = l; k <= r; k++) {
                    int left = (k > l) ? dp[l][k - 1] : 0;
                    int right = (k < r) ? dp[k + 1][r] : 0;
                    ans = max(ans, arr[l - 1] * arr[k] * arr[r + 1] + left + right);
                }
                dp[l][r] = ans;
            }
        }
        return dp[1][n];
    }

写错的地方几乎都出在「先爆」那个直觉上。把它照抄成 dp：arr[k−1] · arr[k] · arr[k+1] 配上独立的左右两段。值域取 1 时 74.89% 的随机数组会算错，值域取 100 时 86.97%，值域 106 时 87.68%。反过来说，气球只有一两个时两个版本必然一样，小数据上试不出来。

这里有个细节很有意思。把邻居换成 arr[k−1]、arr[k+1] 之后，每个 k 算出来的值会完全相同：左边那段的和、右边那段的和、加上中间那个三元组，合起来正好是整个区间的三元组之和，跟切在哪一刀无关。所以这个错法退化成「把区间里每个三元组各加一遍」，压根没在挑顺序。演示里切到「错法」那一版，五个 k 全给同一个数，露馅就在这里。

规模上，记忆化之后每个区间只算一次，共 n(n+1)/2 个状态，每格枚举 k 是 O(n)，整体 O(n³)。n = 300 时状态 45150 个、枚举合计约 454 万次，跑完 2.45 ms；n = 1000 时 205.79 ms。暴力枚举爆的顺序是 n! 量级，n = 10 就已经 3628800 种。

二、布尔运算

给一个只含 0、1、&、|、^ 的表达式。原式没有括号，所有运算符优先级相同，你可以加括号决定先算哪一段。问让整个表达式算出指定结果 result，一共有多少种不同的运算顺序（相邻两个数字加同一个运算符才算一种）。

1^0|0|1 要算出 0，有 2 种；0&0&0&1^1|0 要算出 1，有 10 种。

状态：f(l, r) 返回两个数，一个是这一段能算出 false 的结合方式数，一个是能算出 true 的。表达式一定是合法的范式，s[l]、s[l+2] 这些偶数位是数字，奇数位是运算符。

转移：枚举这一段里最后执行的那个运算符，位置 k 从 l+1 走到 r−1，每次加 2。左段 [l, k−1] 和右段 [k+1, r] 各有一对计数，把两边凑成一对的四种组合各乘一次，落到哪个结果上由运算符决定：

  • &：只有两边都为 true 才是 true，所以 f0 += a·c + a·d + b·c，f1 += b·d。
  • |：只有两边都为 false 才是 false，所以 f0 += a·c，f1 += a·d + b·c + b·d。
  • ^：两边不同为 true，所以 f0 += a·c + b·d，f1 += a·d + b·c。

这里 a 是左段算出 false 的方式数、b 是算出 true 的，c、d 是右段的。

边界：l == r 时只剩一个数字，是 0 就让 f0 = 1，是 1 就让 f1 = 1。

// s[l..r] 是一段合法的布尔表达式，返回 {算出 false 的结合方式数, 算出 true 的结合方式数}
    pair<long long, long long> f(const string& s, int l, int r,
                                 vector<vector<pair<long long, long long>>>& dp,
                                 vector<vector<bool>>& done) {
        if (done[l][r]) return dp[l][r];
        long long f0 = 0, f1 = 0;
        if (l == r) {
            f0 = s[l] == '0' ? 1 : 0;
            f1 = s[l] == '1' ? 1 : 0;
        } else {
            for (int k = l + 1; k < r; k += 2) {        // 枚举最后执行的那个运算符
                auto L = f(s, l, k - 1, dp, done);
                auto R = f(s, k + 1, r, dp, done);
                long long a = L.first, b = L.second, c = R.first, d = R.second;
                if (s[k] == '&') { f0 += a * c + a * d + b * c; f1 += b * d; }
                else if (s[k] == '|') { f0 += a * c; f1 += a * d + b * c + b * d; }
                else { f0 += a * c + b * d; f1 += a * d + b * c; }
            }
        }
        done[l][r] = true;
        return dp[l][r] = {f0, f1};
    }

「最后执行的运算符」这个视角和戳气球是同一件事：它把整段切开，左右两块各自是一段完整的表达式，中间那个运算符不受两边影响。枚举顺序也有讲究，k 每次加 2，因为只有奇数位才是运算符；写成加 1 就会把数字位当运算符，随机数据上 2 个运算符时 60.87% 出错，9 个运算符时 99.38% 出错。

计数上限本身也值得一提。一段表达式有多少种加括号的方式是卡塔兰数：9 个运算符（串长 19）对应 4862 种，而「算出某个结果的方式数」不会超过总方式数，所以串长 19 的答案最大就是 4862，int 绰绰有余。但要是把长度放开，20 个运算符就是 6564120420，int 直接溢出。取 99 个运算符的串跑一遍，答案是 2878516106709193861，得用 long long。

两道题的规模都小。布尔运算串长 19（9 个运算符）时状态只有 55 个、跑完 0.003 ms；串长 199 时 5151 个状态、2.19 ms。

三、复杂度分析

量规模说明
状态数O(n²)戳气球 n=300 → 45150 个；布尔运算串长 199 → 5151 个
单格代价O(n)戳气球枚举最后爆的球；布尔运算枚举最后执行的运算符
时间O(n³)n=300 时 2.45 ms，n=1000 时 205.79 ms
空间O(n²)戳气球 int 二维表；布尔运算每格存一对 long long
暴力O(n!) 或 O(Catalan(n))戳气球 n=10 有 3628800 种爆法；布尔运算 9 个运算符有 4862 种括号法

布尔运算的每格装的是两个数，代价常系数翻倍但阶不变。真正把复杂度抬上去的是每格那层枚举，跟分界点型区间 dp 一样。

四、总结

  1. 当「第一步」会让剩下的部分粘在一起时，换成「最后一步」：它发生时其它元素都已处理完，边界因此固定，两块子问题也就独立了。
  2. 戳气球的状态多了一句前提「两端的墙一定还没爆」，这句话保证了转移里那个乘积是常数。
  3. 布尔运算把状态从「一个数」扩成「一对计数」，枚举的仍然是最后执行的那一步；代价是每格多记一个数，好处是「有多少种方式」这类计数题也能套同一副骨架。

到这里区间 dp 的三类展开都走了一遍：两端点讨论、枚举划分点、枚举最后一步。后面遇到区间上的问题，先判断它属于哪一类，转移的形状基本就定了。
