双向广搜：从数量小的一侧展开

普通 BFS 从起点一层层扩到终点；双向广搜把终点也当起点，两侧同时扩、每轮只扩数量少的一侧，中途一碰就停。展开量从 b^d 压到大约 2·b^(d/2)。

零、背景

单向 BFS 的问题是波前膨胀：起点到终点距离 d、每个词平均 b 个邻居时，第 d 层要展开约 b^d 个状态。很多图的 b 不小（单词接龙里每个词 26×len 个候选），d 到 5、6 层就吃不消。

双向广搜改一个动作：把终点侧也维护一层「目标集」，每轮只从数量少的那一侧展开，展开出的状态去另一侧里查。两个波前各自走一半距离就碰头，展开量从 b^d 掉到 2·b^(d/2)。

它不是新算法，是普通 BFS 的剪枝改造。代价是空间多一倍（两侧的层都要存），换来的是展开量少一个数量级。

一、单词接龙：三个集合的交换

LeetCode 127 题：begin 到 end 每次只差一个字母，中间词都在 wordList 里，问最短转换序列的单词数。数据里词表上千、词长 8，单向 BFS 从 begin 一侧硬扩，展开量很快就爆炸。

双向的做法维持三个集合：smallLevel（数量小的一侧）、bigLevel（数量大的一侧）、nextLevel（本轮从 smallLevel 扩出来的下一层）。初始 smallLevel 只有 begin、bigLevel 只有 end，len 从 2 开始计数（begin 和 end 算两个词）。

每一轮只扩 smallLevel：对每个词逐位换 a~z，换出的词如果命中 bigLevel，说明两侧碰头，直接返回 len；如果换出的词在 dict 里，就把它移出 dict 并塞进 nextLevel（移出是为了防止回头的环）。

整层扩完后做交换：nextLevel 就是这轮之后「小侧的新一层」，但下一轮扩谁还要再比一次大小。比的是 nextLevel 和 bigLevel 谁小：nextLevel 小，smallLevel = nextLevel、bigLevel 不变；nextLevel 大，smallLevel = bigLevel（另一侧成了小侧，下一轮掉头扩它）、bigLevel = nextLevel。这就是「哪侧数量少从哪侧展开」的落地写法。

演示 · hit→cog 双向逐层：黄=小侧、蓝=大侧、绿=本轮新层，命中变红

两个细节值得注意。一是 begin 不需要在 wordList 里，代码直接把它放进 smallLevel，不查 dict；end 必须在 dict 里，不在就直接返回 0。二是命中 bigLevel 的检查放在 dict 检查之前：bigLevel 里的词是「另一侧已经占过的层」，命中就说明路径已经接上，不用管它是不是还在 dict。

#include <bits/stdc++.h>
    using namespace std;

    // 单词接龙：双向 BFS
    // smallLevel 是数量小的一侧，bigLevel 是数量大的一侧，nextLevel 是本轮从小侧扩出的下一层
    // 每轮只扩 smallLevel：换出的词命中 bigLevel 就返回 len，在 dict 里就移除并入 nextLevel
    // 换层时若 nextLevel 比 bigLevel 小，小侧 = nextLevel；否则小侧 = bigLevel（大侧换成 nextLevel）
    int ladderLength(string begin, string end, vector<string>& wordList) {
        unordered_set<string> dict(wordList.begin(), wordList.end());
        if (!dict.count(end)) {
            return 0;
        }
        unordered_set<string> smallLevel, bigLevel, nextLevel;
        smallLevel.insert(begin);
        bigLevel.insert(end);
        for (int len = 2; !smallLevel.empty(); len++) {
            for (const string& w : smallLevel) {
                string word = w;
                for (int j = 0; j < (int)word.size(); j++) {
                    char old = word[j];
                    for (char change = 'a'; change <= 'z'; change++) {
                        if (change != old) {
                            word[j] = change;
                            if (bigLevel.count(word)) {
                                return len;
                            }
                            if (dict.count(word)) {
                                dict.erase(word);
                                nextLevel.insert(word);
                            }
                        }
                    }
                    word[j] = old;
                }
            }
            if (nextLevel.size() <= bigLevel.size()) {
                smallLevel.swap(nextLevel);
            } else {
                smallLevel.swap(bigLevel);
                bigLevel.swap(nextLevel);
            }
            nextLevel.clear();
        }
        return 0;
    }

复杂度：每一层只扩数量小的一侧，总展开量约为 2·b^(d/2)，空间存两侧各 d/2 层，同样压到根号级。比单向的 b^d 少一个数量级；单词接龙这类「两个端点都好找邻居」的题，双向是常规武器。

二、什么时候值得用

双向广搜的定位是剪枝优化，解决的问题是波前膨胀。值得用的条件有两个：图里的边可逆（从终点也能往回扩）、两个端点的波前都会膨胀（单向扩到第 d 层要炸，双向各走 d/2 就稳）。

反过来，如果图不是无向的（从终点往回走不合法），或者终点侧邻居稀少，双向就没有收益，单向就行。判断标准就一句话：两侧都「有的扩」，才轮换着扩。

总结

双向广搜的核心不是「两个 BFS 同时跑」，而是「每轮只扩数量小的一侧」：smallLevel/bigLevel/nextLevel 三个集合轮换，命中另一侧立即返回，展开量从 b^d 降到 2·b^(d/2)。

它解决的是「波前膨胀」这一类性能问题，属于剪枝策略。下一类问题换了个思路：不是优化展开过程，而是让「全量展不开、半量能展开」的题目变得可做，这就是折半搜索。
