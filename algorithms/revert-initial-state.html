恢复到初始状态的最短时间

每一秒把串的前 k 个字符扔掉，末尾补上 k 个任意字符。问最少几秒能让它变回原样。补的字符可以自己挑，所以能不能恢复，看的只是「剩下的那一段和后缀对得上多少」。这件事 z 数组已经算过了。

零、题目

给定一个下标从 0 开始的字符串 word 和一个整数 k。每一秒必须执行两个动作：删掉 word 的前 k 个字符，然后在末尾添加 k 个任意字符。添加的字符不必和删掉的一样。

返回把 word 恢复到初始状态所需的最短时间，这个时间必须大于 0。

第一反应是逐秒模拟。一秒一秒地挪，每挪一次检查整串是不是回到原样。n = 16000 的输入实测 32.26 毫秒，n 每翻一倍耗时乘 4，因为每秒钟光搬字符就是 O(n)。

慢在把「挪动」这件事真的做了。其实不用挪，只要知道挪完之后剩下的那一段和原串的前缀重不重合。

一、什么时候算恢复

挪 t 秒之后，原来下标 t·k 的字符跑到下标 0 的位置上，剩下的 word[t·k .. n−1] 整段往前顶了 t·k 格，后面空出来的 t·k 个位置由我们添加的字符填。

添加的字符是随便选的，所以只要后面的空位还在，就总能把它们填成想要的值。真正要满足的只有一条：挪完之后前 n − t·k 个字符，本来就是原串的前 n − t·k 个字符。

也就是说，word 从下标 i = t·k 起的后缀，与 word 自己的最长公共前缀长度要正好等于 n − i。差一位都不行，因为短了说明中间有字符对不上，而那段字符不是我们能改的。

「后缀与前缀的最长公共前缀长度」这件事，正是 z 数组的定义。于是一段一段挪的模拟，变成一次查表。

二、z 数组扫一遍

对 word 求一遍 z 数组，然后只看 i = k, 2k, 3k, … 这些位置。第一个满足 z[i] = n − i 的 i，答案就是 i / k。

拿 "abacaba"、k = 3 走一遍。n = 7，z = [7,0,1,0,3,0,1]。i = 3 时 n − i = 4，而 z[3] = 0，对不上；i = 6 时 n − i = 1，z[6] = 1，正好相等，答案是 6 / 3 = 2 秒。

i = 6 这一格说的是：挪 6 步之后只剩下最后一个字符 'a'，它和前缀的第一个字符 'a' 相同；剩下的空位由第五秒、第六秒补进去的字符负责。六秒里前两秒补的字符要填的正是 "ab"，选对了整串就回到 "abacaba"。

// 每一秒挪 k 格，剩下的那一段和前缀长得一样就停；都挪完了也停
    int minimumTimeToInitialState(const string &word, int k) {
        int n = (int)word.size();
        zArray(word);
        for (int i = k; i < n; i += k) {
            if (z[i] == n - i) {
                return i / k;
            }
        }
        return (n + k - 1) / k;
    }

三、两个边界

第一个边界是 i 从 k 开始，不是从 0。题目要求时间必须大于 0，i = 0 时 z[0] = n 与 n − 0 恒等，直接返回 0 就违反了这条规定。

第二个边界是每格只查 k 的倍数，不是每一步都查。挪了整数秒之后错位量一定是 k 的整数倍，不落在这些位置上的 i 对应的是某个非整数秒的错位，不是合法答案。逐格查的话即使查到了也说明不了问题。

两个边界都守住了，还剩一种情况：k 的倍数位置上全都不满足。这时候原串的字符会一个不剩地全部被挪出去，整串由补的字符组成，补什么就是什么，必然能恢复。需要的秒数是 n 除以 k 向上取整，写成 (n + k − 1) / k。

"abbabb"、k = 2 就是这种情况：i = 2、i = 4 都对不上，直到第三秒原字符全部挪出，答案 ceil(6 / 2) = 3。

写的时候有四处容易错。

一，兜底的答案写成 n / k 少了向上取整。只有当 n 恰好是 k 的整数倍时两者才相等，随机数据上 67.64% 出错；串越长越容易现形，长随机串上 73.58%。

二，找不到对齐位置时返回 0。它违反了「时间必须大于 0」这一条，而且 0 秒在逻辑上也说不通，随机小串上 88.84% 出错，长串上 99.00%。

三，扫描步长写成 1，每格都查。查到非 k 倍数的 i 时，i / k 这个除法给出的是向下取整的秒数，既不是真实的错位秒数也不是答案。字符表 3 时 31.92% 出错；字符表 26、串长 200 时只剩 2.94%，因为随机长串几乎不会在非 k 倍数的位置碰巧对上。

四，判断写成 z[i] >= n − i。这一处改不改答案一样，实测 0.00% 差异。原因是 z[i] 是后缀与前缀的公共前缀长度，最多只能是后缀自身的长度 n − i，所以 z[i] > n − i 永远不成立，等号两边没有区别。

四、复杂度分析

做法关键操作时间空间
逐秒模拟每一秒搬一次字符并整串比对O(n2 / k)O(n)
z 数组扫一遍求一遍 z，再查 n / k 个位置O(n)O(n)

z 数组本身是线性的，扫描只看 n / k 个位置，两者相加仍然是 O(n)。空间是一张长度 n 的 int 表，n = 106 时 4 MB。逐秒模拟在 n = 16000 上 32.26 毫秒，换成 z 数组之后同样的输入 0.044 毫秒。

总结

挪 t 秒之后能不能恢复，等价于 word 从 i = t·k 起的后缀与前缀的公共前缀长度恰好等于 n − i，也就是 z[i] = n − i。补进去的字符随便选，只要这条成立就能补齐。

扫的时候 i 取 k 的倍数、从 k 开始，第一个命中的 i 除以 k 就是答案；一个都不命中就返回 (n + k − 1) / k，即原字符全部挪出去所需的秒数。

时间 O(n)、空间 O(n)。n = 16000 上逐秒模拟 32.26 毫秒、z 数组 0.044 毫秒。判断那一行写 >= 与写 == 等价，因为公共前缀长度不可能超过后缀自身长度。
