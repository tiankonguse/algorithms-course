最小生成树应用：虚拟源点与离线查询

上一页的两个模版本身不值钱，值钱的是怎么把题目改造成「求最小生成树」。这三题各教一招：虚拟源点、离线查询、最小瓶颈树。

零、背景

应用题的通病是题干不叫「最小生成树」，得自己看出来。判断标准就一条：要在 n 个东西之间建 n-1 条「连接」使整体连通且总代价最小，那就是 MST。

三题覆盖三种变形：多了一种必选的「起点」、查询要求按阈值累积、答案不是总权值而是某条边的权值。

一、水资源分配：把水井变成虚拟源点

n 栋房子，每栋可以打井（成本 wells[i]）也可以接管道（pipes 里列了管道成本），让所有房子都有水的最低总成本。麻烦在于打井是「单点动作」不是「两点连接」，MST 接不上。

变招：加一个虚拟源点 0，把 wells[i] 变成 0 到房子 i+1 的边。现在所有方案都是「两点之间的边」：0 到某房 = 打井，房到房 = 管道。整张图跑 Kruskal，MST 的总权值就是答案：选了几口井、接了哪些管道，算法自己定。

#include <bits/stdc++.h>
    using namespace std;

    // 水资源分配：虚拟源点 0，wells 变成 (0, i) 的边，Kruskal 跑最小生成树
    const int MAXN = 10010;
    int father[MAXN];
    struct Edge { int u, v, w; } edges[MAXN << 1];
    int cnt;

    int find(int i) {
        if (i != father[i]) father[i] = find(father[i]);
        return father[i];
    }

    bool unionSet(int x, int y) {
        int fx = find(x), fy = find(y);
        if (fx != fy) {
            father[fx] = fy;
            return true;
        }
        return false;
    }

    int minCostToSupplyWater(int n, vector<int>& wells, vector<vector<int>>& pipes) {
        cnt = 0;
        for (int i = 0; i <= n; i++) father[i] = i;
        for (int i = 0; i < n; i++) {
            // wells[i] 就是源点 0 到房子 i+1 的边
            edges[cnt++] = {0, i + 1, wells[i]};
        }
        for (auto& p : pipes) {
            edges[cnt++] = {p[0], p[1], p[2]};
        }
        sort(edges, edges + cnt, [](const Edge& a, const Edge& b) {
            return a.w < b.w;
        });
        int ans = 0;
        for (int i = 0; i < cnt; i++) {
            if (unionSet(edges[i].u, edges[i].v)) ans += edges[i].w;
        }
        return ans;
    }

二、边长度限制的路径存在性：离线双指针

一堆查询，每个问 p、q 之间存不存在一条路径，路径上每条边都严格小于 limit。如果按查询顺序做，每个查询都得从头开始连边，O(k×m) 直接超时。

变招：把所有查询按 limit 从小到大排序，边也按长度从小到大排，一个指针 j 只管前进。处理第 i 个查询时，把长度严格小于 limit 的边全部 union 进并查集，然后 isSameSet 就是答案。因为 limit 单调不减，j 永远不会回头，每条边只被连一次，总复杂度 O(m log m + k log k + (m+k) α)。

严格小于的写法要注意：判连通时只连 edges[j][2] < limit 的边，等于 limit 的边不进（路径要求严格小于）。

#include <bits/stdc++.h>
    using namespace std;

    // 检查边长度限制的路径是否存在：离线 + 并查集
    // 边按 dis 排序、查询按 limit 排序，双指针增量连边，答案按原下标回填
    const int MAXN = 100001;
    int father[MAXN];
    struct Query { int p, q, limit, idx; } queries[MAXN];

    int find(int i) {
        if (i != father[i]) father[i] = find(father[i]);
        return father[i];
    }

    bool isSameSet(int x, int y) { return find(x) == find(y); }

    void unionSet(int x, int y) { father[find(x)] = find(y); }

    vector<bool> distanceLimitedPathsExist(int n, vector<vector<int>>& edges,
                                          vector<vector<int>>& qs) {
        sort(edges.begin(), edges.end(),
             [](auto& a, auto& b) { return a[2] < b[2]; });   // 边按长度升序
        int m = edges.size(), k = qs.size();
        for (int i = 0; i < k; i++) {
            queries[i] = {qs[i][0], qs[i][1], qs[i][2], i};
        }
        sort(queries, queries + k,
             [](const Query& a, const Query& b) { return a.limit < b.limit; });
        for (int i = 0; i < n; i++) father[i] = i;
        vector<bool> ans(k);
        for (int i = 0, j = 0; i < k; i++) {
            // j 只前进：把长度严格小于 limit 的边全部连上
            for (; j < m && edges[j][2] < queries[i].limit; j++) {
                unionSet(edges[j][0], edges[j][1]);
            }
            ans[queries[i].idx] = isSameSet(queries[i].p, queries[i].q);
        }
        return ans;
    }

三、繁忙的都市：最小瓶颈树

改造道路尽量少 = 生成树，n-1 条不能再少；在满足前两条的前提下，改造的道路里分值最大的尽量小。这个「最大边最小」的生成树叫最小瓶颈树。

最小生成树一定是最小瓶颈树：如果 MST 的最大边 e 能被换掉（存在一棵最大边更小的生成树），把那条更小的边换进来，MST 的总权值还能更小，矛盾。所以答案就是 MST 的最大边，Kruskal 里直接维护 max 即可，不需要额外算法。

#include <bits/stdc++.h>
    using namespace std;

    // 繁忙的都市：改造道路最少 = 生成树 n-1 条；最大分值最小 = 最小瓶颈树
    // 最小生成树一定是最小瓶颈树，Kruskal 选 n-1 条边，最大边权即答案
    const int MAXN = 301;
    const int MAXM = 8001;
    int father[MAXN];
    int n, m;
    struct Edge { int u, v, w; } edges[MAXM];

    int find(int i) {
        if (i != father[i]) father[i] = find(father[i]);
        return father[i];
    }

    bool unionSet(int x, int y) {
        int fx = find(x), fy = find(y);
        if (fx != fy) {
            father[fx] = fy;
            return true;
        }
        return false;
    }

    int main() {
        ios::sync_with_stdio(false);
        cin.tie(nullptr);
        cin >> n >> m;
        for (int i = 1; i <= n; i++) father[i] = i;
        for (int i = 0; i < m; i++) {
            cin >> edges[i].u >> edges[i].v >> edges[i].w;
        }
        sort(edges, edges + m, [](const Edge& a, const Edge& b) {
            return a.w < b.w;
        });
        int ans = 0, edgeCnt = 0;
        for (int i = 0; i < m; i++) {
            if (unionSet(edges[i].u, edges[i].v)) {
                edgeCnt++;
                ans = max(ans, edges[i].w);
            }
            if (edgeCnt == n - 1) break;   // 选满就停，答案就是最后一条入选边的权值
        }
        cout << (n - 1) << ' ' << ans << '\n';
        return 0;
    }

四、复杂度分析

题目时间复杂度额外空间
水资源分配O((n + m) log(n + m))O(n + m)
边长度限制O(m log m + k log k + (m + k) α(n))O(n + m)
繁忙的都市O(m log m)O(n + m)

水资源的边数是 n（井）+ m（管道），多一个虚拟源点只多 n 条边，Kruskal 照跑。边长度限制的排序是主体，并查集部分 O((m+k) α(n)) 可以忽略。繁忙都市就是模版题，多维护一个最大值。

五、总结

虚拟源点把「单点动作」变成「两点边」；离线双指针让「按阈值累积的查询」复用同一份并查集；最小瓶颈树告诉你「最大边最小」的答案就是 MST 的最大边。

这三招在后面的并查集和图论题里会反复出现：凡是「能连通的最小代价」都可以先想想虚拟源点，凡是「边按长度递增的查询」都可以想想离线排序。
