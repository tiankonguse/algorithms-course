第 k 大与前 k 大：多棵 trie 一起下潜

前面几道题问的都是「最大」，答案只有一条路可走。这一页问的是第 k 大，每一层都要先数一数两边各有多少个，才能决定往哪边拐。两道题，一道让 n 个数各自带游标一起下潜，一道干脆不建可持久化版本，用经典 trie 加二分。

一、题目6：异或运算

数组 x 长度 n，数组 y 长度 m，想象矩阵 mat[i][j] = x[i] ^ y[j]。p 条查询 xl xr yl yr k：打印行在 [xl, xr]、列在 [yl, yr] 这块子矩阵里的第 k 大值。n 到 1000，m 到 3 × 10⁵，p 到 5000，值小于 2³¹。题目链接 P5795。

朴素做法是把这块子矩阵全算出来排序，一次 O(n·m·log)，5000 次直接爆炸。

先看数据状况：n 只有 1000，m 有 3 × 10⁵。两边不对称，就别对称处理，给大的那一列建可持久化 01Trie，root[j] 是插入 y[1..j] 之后的版本；行这一侧只有 1000 个，直接每个行各带一对游标一起走。游标是 xroad[i][0] = root[yl-1]、xroad[i][1] = root[yr]。

每一位先算总数：sum 是所有行在这一位上「能变成 1」的数对个数。sum ≥ k 就说明第 k 大在这一支，所有游标一起走 best 分支，答案这一位填 1；否则所有游标走同向分支，k -= sum。所有行必须走同一边，因为决定这一位的是「总共有多少个数对在这一位上是 1」，不是某一行。

    
int maxKth(int xl, int xr, int yl, int yr, int k) {
        for (int i = xl; i <= xr; i++) {
            xroad[i][0] = root[yl - 1];
            xroad[i][1] = root[yr];
        }
        int ans = 0;
        for (int b = BIT, path, best, sum; b >= 0; b--) {
            sum = 0;
            for (int i = xl; i <= xr; i++) {
                path = (x[i] >> b) & 1;
                best = path ^ 1;
                sum += pass[tree[xroad[i][1]][best]] - pass[tree[xroad[i][0]][best]];
            }
            for (int i = xl; i <= xr; i++) {
                path = (x[i] >> b) & 1;
                best = path ^ 1;
                if (sum >= k) {
                    xroad[i][0] = tree[xroad[i][0]][best];
                    xroad[i][1] = tree[xroad[i][1]][best];
                } else {
                    xroad[i][0] = tree[xroad[i][0]][path];
                    xroad[i][1] = tree[xroad[i][1]][path];
                }
            }
            if (sum >= k) {
                ans += 1 << b;
            } else {
                k -= sum;
            }
        }
        return ans;
    }

两个循环是这个函数的关键：第一个循环数 sum，第二个循环才真正挪游标。不能边数边挪，因为决定走哪边要用的是所有行的总数。

x = [1, 6, 3]、y = [5, 2, 7, 4]，查 xl=1 xr=3 yl=2 yr=4 k=4

橙色是这一行「能变 1」的那一支，浅蓝是走完之后还活着的 y。

二、题目7：前 m 大两两异或值的和

长度 n 的数组 arr，下标 1 到 n。任意两个不同位置的数字异或，顺序不同算同一个。返回前 k 大两两异或值的累加和，对 10⁹ + 7 取模。n 到 5 × 10⁴，值到 10⁹。题目链接 CF241B。

这一题只用到经典 01Trie，一个版本都不需要。做法是先把「有多少个两两异或值 ≥ x」这件事做好，记为 moreEqual(x)，剩下两件事都靠它：二分出第 k 大，再把 ≥ 第 k 大的那些全加起来、减掉多算的。

moreEqual(x) 对每个 arr[i] 单独在 trie 上走一遍。看第 b 位时，x 的这一位如果是 0，那么走「与 arr[i] 相反」的那一支得到的异或值一定比 x 大，可以整支计入，然后自己继续走同向分支；x 的这一位如果是 1，走同向就一定比 x 小，只能往相反的那支走。走到最后，恰好等于 x 的那些也要算进来。

    
long long moreEqual(int x) {
        long long ans = 0;
        for (int i = 1; i <= n; i++) {
            int num = arr[i];
            int cur = 1;
            for (int b = BIT; b >= 0; b--) {
                int path = (num >> b) & 1;
                int best = path ^ 1;
                int xpath = (x >> b) & 1;
                if (!xpath) {
                    ans += pass[tree[cur][best]];
                    cur = tree[cur][path];
                } else {
                    cur = tree[cur][best];
                }
                if (!cur) {
                    break;
                }
            }
            ans += pass[cur];
        }
        if (x == 0) {
            ans -= n;
        }
        return ans / 2;
    }

最后 ans / 2 是因为每个数对被算了两次；x == 0 时还要减掉 n，那是自己和自己配对的 n 个。有了它，第 k 大就是 moreEqual(m) ≥ k 成立的最大 m，二分即可。

求和这一步要按位算贡献。预处理 sum[i][j]：节点 i 的子树里第 j 位是 1 的数有多少个。这样一次就能把「这一整支与 arr[i] 异或出来的所有值」在第 j 位上的总和算出来。

    
void dfs(int i, int h, int s) {
        if (!i) {
            return;
        }
        if (!h) {
            for (int j = 0; j <= BIT; j++) {
                if ((s >> j) & 1) {
                    sum[i][j] = pass[i];
                }
            }
        } else {
            dfs(tree[i][0], h - 1, s);
            dfs(tree[i][1], h - 1, s | (1 << (h - 1)));
            for (int j = 0; j <= BIT; j++) {
                sum[i][j] = sum[tree[i][0]][j] + sum[tree[i][1]][j];
            }
        }
    }
    
long long compute() {
        int kth = maxKth();
        long long ans = 0;
        for (int i = 1, cur; i <= n; i++) {
            cur = 1;
            for (int b = BIT; b >= 0; b--) {
                int path = (arr[i] >> b) & 1;
                int best = path ^ 1;
                int kpath = (kth >> b) & 1;
                if (!kpath) {
                    if (tree[cur][best]) {
                        for (int j = 0; j <= BIT; j++) {
                            if ((arr[i] >> j) & 1) {
                                ans = (ans + ((long long)pass[tree[cur][best]] - sum[tree[cur][best]][j]) * (1LL << j)) % MOD;
                            } else {
                                ans = (ans + ((long long)sum[tree[cur][best]][j]) * (1LL << j)) % MOD;
                            }
                        }
                    }
                    cur = tree[cur][path];
                } else {
                    cur = tree[cur][best];
                }
                if (!cur) {
                    break;
                }
            }
            if (cur) {
                ans = (ans + (long long)pass[cur] * kth) % MOD;
            }
        }
        ans = ans * INV2 % MOD;    
        ans = ((ans - ((moreEqual(kth) - k) * kth) % MOD) % MOD + MOD) % MOD;
        return ans;
    }

compute 里的循环和 moreEqual 是同一个骨架，区别在于：kth 的这一位是 0 时，「与 arr[i] 相反」的那一支全部 ≥ kth，于是把整支的贡献按位累加进答案，自己继续走同向；kth 的这一位是 1 时只走 best。走到底时 pass[cur] 个数恰好等于 kth，直接乘上去。末尾乘 INV2 去掉重复计数，再减掉多算的 (moreEqual(kth) - k) × kth，因为前 k 大只要 k 个，而这里算的是所有 ≥ kth 的。

arr = [1, 2, 3]，数一数 moreEqual(2) 怎么等于 2

x = 2 的二进制是 010，三个数各自走一遍，最后除以 2。

这一支整支计入 继续往下走的分支 这一列还没走到

复杂度分析

BIT = 30（值小于 2³¹）。题6 的 n 记 N（≤ 1000），题7 的 n 记 n（≤ 5 × 10⁴）。

题6 的 MAXT = MAXN * 32，MAXN 取 300001 对着 m 的上界。题7 的 sum[MAXT][BIT+1] 是个二维表，MAXN × 20 的节点数乘 31 列，这是它最费空间的地方；MODULE 取 10⁹+7，除以 2 用 INV2 = 500000004。

最后

七道题排下来，可持久化前缀树本身只学会两个动作：复制一条路径，两个版本相减。真正在变的是「版本按什么排」，按下标、按 dfn、按父亲，以及这一页干脆不排、把 n 个数各自带着游标跑。什么时候这些都不够用，就该轮到别的数据结构上场了。
