优化枚举：买卖股票（上）

股票系列的题面都不绕，值钱的是转移里那层枚举怎么压掉。这一页讲前三道：一次交易、无限次交易、最多两笔。前两道一遍扫过去就完事，第三道的暴力转移是 O(n²)，看一眼转移式就能降成 O(n)。

零、一次交易：记住前面见过的最低价

买入日必须早于卖出日，且只做一笔。枚举卖出日 i，想让 prices[i] − 买入价 最大，买入价就得取 0..i 这一段里的最小值。

最小值可以边扫边更新，于是整个问题就是一次遍历。

// 一次交易：枚举卖出日 i，这天能拿到的最大利润 = 价格[i] - 之前见过的最低价
    int maxProfit(vector<int>& prices) {
        int ans = 0;
        for (int i = 1, mn = prices[0]; i < (int)prices.size(); i++) {
            mn = min(mn, prices[i]);          // mn 是 0..i 的最低买入价
            ans = max(ans, prices[i] - mn);
        }
        return ans;
    }

这里有个细节：mn 的初值取 prices[0]。价格允许取 0，如果把 mn 的初值写成 0，等于凭空允许在第 0 天之前用 0 元买入。价格全为正的随机数据上，这一处实测 91.70% 出错。

另一个容易顺手写错的地方是把「买入在卖出之前」这条约束丢了，退化成全局的最大值减最小值。数据单调递增时它俩答案一样，所以样例经常能过。随机小数据上实测 45.80% 出错，值域越宽越容易暴露。

一、无限次：把每一段上坡加起来

交易次数不限，但同一时刻最多持一股。既然想买随时能买、想卖随时能卖，那么任何一段下跌都不该扛着。价格涨到局部高点就卖，跌到局部低点再买回来，两段之间的落差全是白赚。

把这句话翻译成公式：只看相邻两天，prices[i] > prices[i−1] 就把差记上。

// 无限次交易：每一段上坡都能落袋，下坡直接跳过
    int maxProfit(vector<int>& prices) {
        int ans = 0;
        for (int i = 1; i < (int)prices.size(); i++) {
            ans += max(prices[i] - prices[i - 1], 0);
        }
        return ans;
    }

max(..., 0) 不能省。少了它，下跌段会被当成负收益加进去，实测 94.42% 出错。写了它，一次遍历结束，答案正好是「所有上坡之和」。

这条结论和「用状态机一手持股一手现金」的写法对拍过 2 万组随机数据，完全一致。状态机是另一套思路，这里用不到，但可以拿来验证自己的直觉。

二、最多两笔：先写出会超时的枚举

现在规定最多两笔。直接照着「第二次交易」往下拆：设 dp1[i] 是 0..i 里做一笔交易的最优值（不要求第 i 天卖出），设 dp2[i] 是「两笔交易、并且第二笔在第 i 天卖出」的最优值。

第二笔的买入日设为 j，j ≤ i。第一笔必须在第 j 天之前收干净，也就是 dp1[j]。于是：

dp2[i] = max over j≤i 的 ( dp1[j] + prices[i] − prices[j] )

这个 j 要靠枚举。两层循环套下来是 O(n²)，n = 2×10⁴ 实测 18.80 ms，而下面优化完的版本只要 0.034 ms，差五百多倍。

// 最多两笔：dp1 是 0..i 一笔交易的最优，dp2 是第二次卖出必须在 i
    int maxProfit(vector<int>& prices) {
        int n = prices.size();
        vector<int> dp1(n, 0);
        for (int i = 1, mn = prices[0]; i < n; i++) {
            mn = min(mn, prices[i]);
            dp1[i] = max(dp1[i - 1], prices[i] - mn);
        }
        vector<int> dp2(n, 0);
        int ans = 0;
        for (int i = 1; i < n; i++) {
            for (int j = 0; j <= i; j++) {                       // 枚举第二次的买入日 j
                dp2[i] = max(dp2[i], dp1[j] + prices[i] - prices[j]);
            }
            ans = max(ans, dp2[i]);
        }
        return ans;
    }

三、观察：内层枚举只和 j 有关

把内层的括号拆开看：

dp1[j] + prices[i] − prices[j] = prices[i] + ( dp1[j] − prices[j] )

右边括号里那一项只跟 j 有关。外层 i 往前挪一格，这些值一个都没变，只是候选集合多了一个 j = i。既然要的是最大值，那就没必要每次重算一遍，记一个「到目前为止 dp1[j] − prices[j] 的最大值」就够了。

设 best[i] = max( dp1[j] − prices[j] )，j 取遍 0..i。转移变成一句话：

dp2[i] = best[i] + prices[i]

内层循环没了。这就是这一类优化的全部内容：看清内层枚举在求什么，然后发现这个量在上一格已经算过。

// 观察：内层枚举的式子拆开，dp1[j] - prices[j] 与 j 之后的 i 无关
    int maxProfit(vector<int>& prices) {
        int n = prices.size();
        vector<int> dp1(n, 0);
        for (int i = 1, mn = prices[0]; i < n; i++) {
            mn = min(mn, prices[i]);
            dp1[i] = max(dp1[i - 1], prices[i] - mn);
        }
        vector<int> best(n, 0);                       // best[i] = max(dp1[j] - prices[j]), j in 0..i
        best[0] = dp1[0] - prices[0];
        for (int i = 1; i < n; i++) {
            best[i] = max(best[i - 1], dp1[i] - prices[i]);
        }
        int ans = 0;
        for (int i = 1; i < n; i++) {
            ans = max(ans, best[i] + prices[i]);       // 内层枚举没了
        }
        return ans;
    }

拿 [3,3,5,0,0,3,1,4] 走一遍：

注意 best 的初值是 dp1[0] − prices[0] = −prices[0]，也就是第 0 天买入这一个候选。把它写成 0，等于允许以 0 元买入，实测 57.25% 出错。反过来，best 忘了取前缀最大（只留 dp1[i] − prices[i]）会漏掉「第一笔早早结束」的情况，实测 58.91% 出错。两种写法一个偏高一个偏低，都会被抓出来。

四、合并循环与空间压缩

三个递推都跟着 i 往前走，谁也不等谁，完全可以塞进同一个循环。

再看依赖：dp1[i] 只用到 dp1[i−1] 和前缀最小值，best[i] 只用到 best[i−1]，ans 只跟当前这格比一次。三个数组全是上一格起作用的，那就都不必留。

// 三个量滚动就够了，dp1、best、ans 都可以边算边丢
    int maxProfit(vector<int>& prices) {
        int dp1 = 0, best = -prices[0], ans = 0;
        for (int i = 1, mn = prices[0]; i < (int)prices.size(); i++) {
            mn = min(mn, prices[i]);
            dp1 = max(dp1, prices[i] - mn);
            best = max(best, dp1 - prices[i]);
            ans = max(ans, best + prices[i]);
        }
        return ans;
    }

这是等义改写，不需要新的观察，但它是这题最后交上去的样子：O(1) 空间，一个循环。

复杂度分析

做法时间空间
一次交易（题 1）O(n)O(1)
无限次交易（题 2）O(n)O(1)
最多两笔·枚举第二次买入日O(n²)O(n)
最多两笔·best 数组O(n)O(n)
最多两笔·滚动变量O(n)O(1)

空间一路压到常数。题 1 的答案需要前缀最小值，题 2 只需要相邻两天的差，题 3 的四个量（mn、dp1、best、ans）都是滚动变量。

总结

题 1 的抓手是前缀最小值，题 2 的抓手是「每一段上坡都能落袋」，两道都是一次遍历。

题 3 才是这一页的主角。它的暴力转移里 j 在枚举，但看拆开的式子会发现内层要的东西根本不含 i，于是可以前一个格子算好、当前格子直接读。这套动作在本站其它 dp 题里反复出现：先写出带枚举的转移，再把枚举项单独拎出来看它依赖谁。

还有两处数值得记住。best 的初值写成 0 会错 57%，忘了前缀最大会错 59%，都是「样例能过、随机数据必挂」的类型。mn 初值写成 0 更狠，价格为正时 92% 出错。

后面几道股票题把规则改复杂：交易次数变成参数 k、加手续费、加冷冻期。优化不动的时候，观察的对象会从「内层的 max」换成「状态怎么设」。
