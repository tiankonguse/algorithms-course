贪心：同一个数字出现几次说了算

一道题要还原森林里最少有多少只兔子，一道题要判断一个有序数组能不能拆成长度够长的几条递增序列。两道题都不关心元素在哪，只关心每个值出现了几次。

零、两道题各自要什么

第一题：森林里有兔子，你向兔子们提同一个问题「还有多少只兔子和你颜色相同」，把收到的回答放进数组 answers（可能只问了一部分兔子）。所有兔子都说真话，求森林里最少有多少只兔子。

回答是 x，说明这只兔子所属的颜色一共 x + 1 只，包括它自己。

第二题：给一个已经排好序的正整数数组 nums 和整数 K，判断能不能把它拆成一个或几个长度至少为 K 的不相交子序列，每个子序列都严格递增，并且所有元素都要被某个子序列包含。

两题的输入都是「一袋子数」，位置没有意义，能决定答案的只有每个值出现的次数。

一、森林中的兔子：同一个答案每 x + 1 只抱团

先看一个回答的含义。收到 x，说明这只兔子那一群一共有 x + 1 只，而且这一群里每只兔子都会回答同一个 x。所以一个回答对应不了固定的兔子数，它只说了「我这一群有多大」。

同一种颜色最多能产生 x + 1 个回答 x。收到的 c 个回答 x，至少得由 ⌈c / (x + 1)⌉ 个不同颜色来回答，也就是至少 ⌈c / (x + 1)⌉ × (x + 1) 只兔子。

拿 answers = [1,1,2] 走一遍。两个 1：每组 2 只，2 个回答刚好塞满一组，贡献 2 只。一个 2：每组 3 只，一个回答独占一组，贡献 3 只。合计 5 只。

再看 [3,3,3,3,3]。五个回答 3，每组 4 只，一轮只能装 4 个回答，剩下 1 个要另起一组，所以是 2 组、8 只。漏掉「组数」这一步就会写成 5 只或者 4 只，都不对。

落地只需要排序加一趟扫描：排序之后相同的答案挨在一起，数出每一段的长度 c 和答案值 x，把 ⌈c / (x + 1)⌉ × (x + 1) 加起来。向上取整写成 (c + x) / (x + 1)，加的就是除数减一。

// 森林中的兔子：answers[i] = x 表示这只兔子还在和 x 只同色兔子一起，同色一共 x + 1 只
    // 排序之后同一个答案聚在一起，c 个 x 至少要 ceil(c / (x + 1)) 个颜色类
    // (j - i + x) / (x + 1) 就是「加除数减一」的向上取整
    int numRabbits(vector<int> arr) {
        sort(arr.begin(), arr.end());
        int n = arr.size();
        int ans = 0;
        for (int i = 0, j = 1, x; i < n; j++) {
            x = arr[i];
            while (j < n && x == arr[j]) {
                j++;
            }
            ans += (j - i + x) / (x + 1) * (x + 1);
            i = j;
        }
        return ans;
    }

实测 n = 106、答案值都在 1000 以内时，排完序再扫一遍要 27.1ms，答案是 1313715。整个数组都是 0 的话反而只要 1.34ms，排序遇到全相等的输入几乎不用动。

二、分成递增序列：最多有几个相同值，就至少要几条序列

第二题的元素不能重排，但数组已经有序，位置同样不重要。考虑出现次数最多的那个值，假设出现了 maxCnt 次。严格递增子序列里同一个值最多出现一次，所以这些相等的元素必须分到 maxCnt 条不同的序列里去，序列条数 m 至少是 maxCnt。

m 条序列覆盖 n 个元素，平均每条分到 n / m 个。要让每条都够 K 个，就需要 m ≤ n / K。两个条件合起来，存在合法拆分的条件是

maxCnt ≤ ⌊n / K⌋　等价于　⌊n / maxCnt⌋ ≥ K

为什么这个条件也够用？取 m = maxCnt 条空序列，把数组里的值从小到大依次放进各条序列：同一个值的第一份放第 1 条、第二份放第 2 条，转一圈再从第 1 条开始。这样每条序列里放进去的值都严格递增，而且 n 个元素轮流分配之后，条数之间的差距不超过 1，最短的那条也有 ⌊n / maxCnt⌋ 个元素。

代码里就是先扫一遍求最大词频，再判断 nums.length / maxCnt >= k（整数除法）。数组已经有序，扫描是 O(n)，不需要再排序。

// 将数组分成几个递增序列：判断能否拆成若干条长度至少为 k 的不相交严格递增子序列
    // 相同的数不能进同一条序列，所以序列条数至少是最大词频 maxCnt
    // 条数取到 maxCnt 时每条序列平均分到 n / maxCnt 个数（向下取整），够 k 就一定分得出来
    bool canDivideIntoSubsequences(vector<int> nums, int k) {
        int cnt = 1;
        int maxCnt = 1;
        for (int i = 1; i < (int)nums.size(); i++) {
            if (nums[i - 1] != nums[i]) {
                maxCnt = max(maxCnt, cnt);
                cnt = 1;
            } else {
                cnt++;
            }
        }
        maxCnt = max(maxCnt, cnt);
        return (int)nums.size() / maxCnt >= k;
    }

几个例子：[1,1,1,2,2,3] 在 K = 2 时，最大词频 3，6 ÷ 3 = 2 ≥ 2，可以；K = 3 时 2 ≥ 3 不成立，不行。换成 [1,1,2,2,3,3]，最大词频 2，6 ÷ 2 = 3，K = 3 也行。

四、对数器怎么抓错

兔子题的暴力参考可以直接写：「对每个答案值独立地算出最少要几个颜色类」。递增序列题麻烦一点，暴力要真的去枚举划分方式，好在数组很短的时候可以搜。

题目写法小值域中值域大值域
森林中的兔子每个答案只算一群66.45%30.89%3.85%
森林中的兔子组数向下取整81.58%97.41%99.50%
森林中的兔子逐只回答累加 x + 172.30%68.03%45.72%
分成递增序列不除以最大词频71.57%52.66%20.02%
分成递增序列除完判大于而不是大于等于24.83%22.46%12.24%
分成递增序列见到重复值就判不行48.34%57.35%27.04%

兔子题三档值域是 3 / 6 / 20（回答值都小于数组长度），递增序列题是 4 / 10 / 100，每组都跑两万组随机数据。

「组数向下取整」几乎是必错，因为向上取整那一步的存在感太弱；它随值域变大反而更容易被抓到，值域一大每个答案只出现一两次，向下取整会直接把贡献算成 0。「每个答案只算一群」在回答值很小时几乎全错，回答值一大就很少出错，因为那时每个答案本来就只够凑一组。「见到重复值就判不行」的错误率也随值域上升而下降，值域大了重复本来就少。

总结

兔子题的关键是「一个回答 x 只说明这一群有 x + 1 只」，同一种颜色最多贡献 x + 1 个相同回答；排序之后按答案分段，每段算 ⌈c / (x + 1)⌉ × (x + 1)，向上取整写成 (c + x) / (x + 1)。

递增序列题的判据只有一条：最大词频 maxCnt 决定了序列条数下界，序列条数又要满足 m ≤ n / K，合起来就是 ⌊n / maxCnt⌋ ≥ K。构造时把同一个值的多份轮流分给各条序列，就得到了满足条件的拆分。两题都只看计数，不看元素的位置。
