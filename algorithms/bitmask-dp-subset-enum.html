状压 dp：子集枚举与分配重复整数

m 个顾客，各要若干个相同的整数；数组里至多 50 种不同的值，每种若干个。问能不能同时满足所有人。这题的正解要在位状态上枚举所有子集，那一行循环值得单独记住。

零、贪心先栽一个跟头

最容易想到的做法是贪心：订单从大到小排，每次挑一个还够用的值给它，挑完这个值就归这个顾客了。按「每位顾客拿到的整数都是相同的」这句话照字面理解，一种值似乎只能服务一个顾客。

看 nums = [1,1,2,2,1]、quantity = [2,2,1]。值 1 有 3 个、值 2 有 2 个。订单 2 拿走值 2（剩 0），订单 2 再拿走值 1 里的 2 个（剩 1 个），订单 1 就没值可用了，贪心判「不行」。但把值 1 拆开就行：两个订单各拿 2 个和 1 个，值 2 给另一个订单，三个都满足。

实测 20000 组随机数据，这种贪心有 4.08% 把可行判成不可行，而且错的方向只有这一个：它只会说「不行」，不会说「行」的时候其实不行。问题出在「一种值只能给一个顾客」这个默认上，题目没这句限制。

一、状态是「还有哪些订单没满足」

把顾客压进 status：第 i 位为 1 表示第 i 个顾客的订单还没着落。数组那边按值的种类推进，排序之后相邻的是同一种值，cnt[index] 是这种值的个数。

f(status, index) 的含义是：只用第 index 种以及之后的值，能不能把 status 里这些顾客全搞定。递归里做两件事：

  1. 枚举 status 的每一个非空子集 j，若 sum[j] ≤ cnt[index]，就把这一种值同时分给 j 里这些顾客，递归 f(status ^ j, index + 1)；
  2. 这一种值谁都不给，直接递归 f(status, index + 1)。

第一条是这题的核心：一种值可以切成好几份，同时喂给好几个顾客，只要总数够。正因为要「同时喂好几个」，才需要枚举子集而不是枚举单个顾客。

sum[s] 是顾客集合 s 一共要多少个数，预处理一遍就行，第 i 位那一段直接从小一半的表上平移过来。

// cnt : 排序后每种不同值的个数，n 种
    // sum[s] : 顾客集合 s 一共需要多少个数字
    int m = quantity.size();
    vector<int> sum(1 << m, 0);
    for (int i = 0; i < m; i++) {
        int v = quantity[i], h = 1 << i;
        for (int j = 0; j < h; j++) sum[h | j] = sum[j] + v;
    }

二、枚举一个状态的所有子集

这一行建议直接背下来：

// 枚举 status 的所有非空子集，建议直接记住
    for (int j = status; j > 0; j = (j - 1) & status) {
        // j 就是 status 的一个子集
    }

j 从 status 本身开始，每次 (j − 1) & status。j − 1 把最右侧的 1 变成 0、它右边那些 0 变成 1，再和 status 取与，就把多出来的位抹掉了，剩下的正好是「比 j 小的下一个子集」。整个序列严格递减、不重不漏，最后一个是 0，循环到 0 结束。

// status : 还有哪些顾客的订单没满足（1 表示没满足）
    // index  : 当前轮到第几种值，它有 cnt[index] 个
    bool f(const vector<int>& cnt, const vector<int>& sum, int status, int index,
           vector<vector<int>>& dp) {
        if (status == 0) return true;
        if (index == cnt.size()) return false;
        if (dp[status][index] != 0) return dp[status][index] == 1;
        bool ans = false;
        int k = cnt[index];
        // j 依次取遍 status 的所有非空子集
        for (int j = status; j > 0; j = (j - 1) & status) {
            if (sum[j] <= k && f(cnt, sum, status ^ j, index + 1, dp)) {
                ans = true;
                break;
            }
        }
        if (!ans) ans = f(cnt, sum, status, index + 1, dp);   // 这种值谁都不给
        dp[status][index] = ans ? 1 : -1;
        return ans;
    }

三、3 的 m 次方是从哪来的

把 status 的所有子集各枚举一遍，代价是 2|status|。所有可能的 status 一共 2m 个，其中恰有 C(m, k) 个状态含 k 位。于是总代价是 Σ C(m, k) · 2k，k 从 0 到 m。这个和按二项式定理展开 (1 + 2)m 正好等于 3m。

这里每个状态只枚举非空子集，所以一轮是 3m − 2m；n 种值各来一轮，上界是 n · (3m − 2m)。

实测 m = 10 时一轮的上界是 310 − 210 = 58025，构造一个 n = 10 且无解的硬实例，一共枚举了 272746 次，上界是 580250，只用了不到一半。原因是一旦凑成就 break，实际数据里往往走几步就退出了：一组宽松数据（每种值都很富余）在 m = 10 时只枚举了 33 次。

四、那个子集循环别从 status − 1 起步

有人把初值写成 (status − 1) & status，想着「跳过自己」。这一跳就把「把整份 status 都交给当前这一种值」这个方案丢了。实测 20000 组随机数据，48.20% 的样本答案不同，而且全部是「本来可行、被判成不可行」。

最现成的例子是 nums = [1,1,2,2]、quantity = [2,2]：两个顾客各要 2 个，值 1 有两个、值 2 有两个，各拿各的就行。漏掉整集之后，任何一种值都凑不出「两个顾客一起来」，只能判 false。

复杂度分析

做法时间空间
状压 + 枚举子集O(n · 3m)O(n · 2m)
预处理 sum 数组O(2m)O(2m)
枚举每个顾客的归属O(nm)O(m)

n 是不同值的种类数（≤ 50），m 是顾客数。状态是 n × 2m 个格子，每个格子枚举自己的子集，单层上限 3m − 2m，全表 n · (3m − 2m)。m = 10、n = 10 的硬实例上界 580250，实测走了 272746 次。

空间上 dp 表是 2m × n 个 int，m = 10、n = 10 时 40 KB。递归深度不超过 n。

总结

这题的关键在转移要枚举子集：一种值要同时喂给好几个顾客，枚举单个顾客会把这些方案全漏掉。for (j = status; j > 0; j = (j − 1) & status) 这一行直接记住，别现场推。

初值必须是 status 自己。写成 (status − 1) & status 就丢了「整份交出去」这个方案，实测 48.20% 的样本被误判成不可行。

贪心在这题上不成立，根源是「一种值只能给一个顾客」这个想当然的限制。题目只要求每位顾客拿到的数相同，没说一种值只能服务一位顾客。实测这种贪心 4.08% 报假阴性，而且只报这一种错。

3m 有出处：Σ C(m, k) · 2k 按二项式定理合起来就是它。以后再看到「每个状态枚举自己的子集」，就能直接报出这个量级。
