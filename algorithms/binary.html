二进制与位运算

一个 int 就是 32 个格子。负数为什么长成一串 1？最小的那个负数取绝对值，为什么还是它自己？这几个问题答不上来，程序会在你眼皮底下算错，还不报错。

一、先说个反直觉的

int 能表示的最大正数是 2147483647。

最小负数是 -2147483648。

不对称。负数那边多一个。

因为 0 把正数那边的一个位置占掉了：0 到 2147483647 一共 2147483648 个数，-1 到 -2147483648 也是 2147483648 个，加起来正好 2 的 32 次方，填满。

多出来的这个 -2147483648 后面会咬人。先记着。

二、32 个格子

int 在内存里就是 32 个 0 或 1。最左边是第 31 位（最高位），最右边是第 0 位（最低位），第 i 位是 1 就贡献 2 的 i 次方。

从右往左，第 0 位只值 1，第 30 位值 2 的 30 次方。第 31 位还有个身份：符号位，它是 0 就是非负数，int 的正数范围到 2 的 31 次方减 1 为止，也就是开头那个 2147483647。

拿 78 说事。78 = 64 + 8 + 4 + 2，所以第 6、3、2、1 位是 1，别的全是 0。

符号位是 1 的时候，这一位值的是负的 2 的 31 次方。整串里光它自己一个 1，就是 -2147483648。开头那个多出来的负数，根子在这儿。

一长串二进制看久了眼晕，按 4 位一组切开，每组刚好一个十六进制字符：0b01001110 写成 0x4e，长度缩到四分之一，互相对译还不用借位。调试的时候 printf("%08x") 比打 32 个 0/1 省事得多。

三、把它打印出来

调试时最常干的事，就是把一个数摊成 32 个字符。

void printBinary(int x) {
        unsigned u = (unsigned)x;
        for (int i = 31; i >= 0; i--) {
            cout << ((u & (1u << i)) != 0 ? '1' : '0');
        }
        cout << '\n';
    }

这段代码不长，坑有三个。

写 != 0，别写 == 1。那一位成立时的值是 2 的 i 次方，只有 i = 0 时才正好等于 1。

循环里写 1u << i 而不是 1 << i。1 是 int，往符号位里移一位在 C++ 里是未定义行为。未定义的意思是编译器怎么干都合法，你看着「能跑」纯属运气。

取位之前先转成 unsigned。负数的 >> 会把符号位带进来补左边，unsigned 的右移一定补 0，混着写的时候这个差别最容易咬人。

四、负数为什么是一串 1

-6 在机器里是 1111...11111010。

一点都不像 -6。可它推出来只有一步：先写 6 = 0000...00000110，全部取反得 1111...11111001，再加 1 得 1111...11111010。

于是有两条恒等式：-x = ~x + 1，反过来 ~x = -x - 1。这两条是上面那一步推出来的，记住那一步，它们自己就长出来了。

想验证也容易：x + ~x 每一位都是 1，也就是 -1，所以 ~x + 1 正好是 -x。

这么一安排，-1 就长成了 32 个全 1。把它想成一只只能往前拨的表：从 0 往回拨一格，会一路绕到 1111...1111。这个位图既是 -1，也是无符号的 4294967295，硬件压根不区分，它只管加。

五、图什么

这么排，图的是让电路好造。

补码下两个数相加，不用看谁的符号，也不用比谁大，直接从第 0 位加到第 31 位。

关键是最高位往左甩出去的那个进位。它溢出了 32 位，硬件直接扔掉，剩下的正好是答案。

减法也就退化成加法：a - b 按 a + (-b) 算，电路一行都不用改。

你可能会想：最高位当符号、剩下 31 位照写绝对值，不是好读得多？

确实好读。可那样 0 会冒出两个，+0 和 -0，判等得单独处理；做加法还得先看符号、再比大小、再决定到底是加还是减。补码把这些一口气全免了。

代价是负数看着很怪，最高位永远是 1，光看位图认不出它是几。换到的是加法器里一个条件分支都不用。这笔买卖在硬件上划算得很。

六、开头那个坑

-x = ~x + 1 有一个地方会失效：x 取 int 的最小值。

INT_MIN 是 0x80000000，也就是 -2147483648。它的相反数 2147483648 装不进 int，取反加一之后绕回它自己。所以 -INT_MIN 还是 INT_MIN，取绝对值也一样。

在 DP 里写 abs(a[i] - a[j])，撞上 INT_MIN 结果就是个负数。减法先溢出，abs 再原样返回，两个坑叠一块儿了。

真需要绝对值就先转 long long。long long v = x; v = v < 0 ? -v : v; 这样写，中间结果不会溢出。

七、六种位运算

两个数的第 i 位对在一起，各算各的，互不进位。这就是位运算。|、&、^、~ 分别是或、与、异或、取反，再加两个位移。

写法含义举例
x | y有一位是 1 就是 11010 | 1100 = 1110
x & y两位都是 1 才是 11010 & 1100 = 1000
x ^ y两位不同才是 11010 ^ 1100 = 0110
~x每一位反过来~78 = -79
x << i整体左移 i 位，低位补 078 << 1 = 156
x >> i整体右移 i 位，左边补符号位-6 >> 2 = -2

非负数上有条捷径：<< i 等于乘 2 的 i 次方，>> i 等于除以 2 的 i 次方下取整。

负数别这么用。>> 在负数上是向下取整而不是向零取整，-6 >> 2 得到 -2 而不是 -1。二分里下标都是非负的，不咬人；一旦数可能为负，>> 就和 / 2 分道扬镳了。

C++ 里没有 >>>。想要逻辑右移（左边一律补 0），先转成 unsigned 再移。

还有一对写法特别容易写错：| 和 ||，& 和 &&。后面两个是逻辑运算，只接 bool 值，而且会短路，左边能定结果时右边根本不执行。前面两个是位运算，两侧一定都算。

if (x & mask) 和 if (x && mask) 都能编译通过，行为差得远。写错了编译器一句话都不说。

八、常用的几个组合

下面这几个在题里反复出现。背下来比每次现推快，反正推来推去还是这几行。

int x = 78;                       // 0000...01001110

    int lowbit = x & -x;              // 2，最低的那个 1 单独留下来
    int erased = x & (x - 1);         // 76，把最低的那个 1 抹掉
    int bit    = (x >> 3) & 1;        // 1，第 3 位是多少
    int setOne = x | (1u << 5);       // 110，第 5 位置成 1
    int clrOne = x & ~(1u << 1);      // 76，第 1 位清成 0

    unsigned logicalShift = (unsigned)x >> 2;   // 19，左边补 0 的逻辑右移

x & -x 留下最低的那个 1，其余位全清掉。树状数组的 lowbit 就是它，x += x & -x 一步跳到下一段。

x & (x - 1) 把最低的那个 1 抹掉。循环到 x 变成 0，循环次数就是二进制里 1 的个数：有几个 1 就循环几次，比逐位判省事。

溢出没人替你检查。中间结果一旦跳出范围，答案就已经错了，编译器不报警，运行时也不抛异常。每一步会走到多大自己心里要有数，拿不准就把中间变量开成 long long。

十、复杂度分析

位运算踩在机器字上，一条指令的事。

操作时间复杂度
单次位运算（| & ^ ~、位移）O(1)
打印一个 int 的全部 32 位O(1)（常数 32）
取第 i 位O(1)
把一个数按位拆开处理（值域 V）O(log V)，int 上就是 32 次
逐位构成：01 字典树插入 / 查询O(log V)

空间上没什么可算的，打印只要一个 unsigned 临时变量，O(1)。真把 32 个字符存成字符串也是 O(32)，还是 O(1)。

十一、最后

这一节就干了件事：把一个 int 拆开看了一遍。

后面再撞见「第 i 位表示什么」，不用回头补这一课。

位运算这套结论能成立，全靠定长 32 位加二的补码撑着。换成 64 位，或者换成无符号，很多结论得重新推一遍。
