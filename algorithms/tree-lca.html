最近公共祖先：普通二叉树与搜索二叉树

同一道「两个节点的最近公共祖先」，普通二叉树要递归把整片相关子树搜一遍，搜索二叉树靠值域一路往下走。后者是前者在有序树上白捡的提速。

零、背景

两个节点往上走，第一次碰头的那个节点，叫最近公共祖先（LCA）。同一个节点算自己的祖先，所以 p 是 q 的祖先时，答案就是 p。

LCA 是树上最常用的查询之一。后面的树链剖分、虚树、可持久化前缀树，都把「求两个节点的 LCA」当零件用，只是查询量大了以后，单次 O(n) 的递归扛不住，要换批量或在线版本。

这一课先把单次查询的两种做法讲透。节点定义沿用前面的课，带构造器：

struct TreeNode {
    int val;
    TreeNode *left, *right;
    TreeNode(int v = 0) : val(v), left(nullptr), right(nullptr) {}
};

一、普通二叉树：三分支递归（LeetCode 236）

递归函数回答一个问题：root 这棵子树里，p 和 q 有没有找到，找到了哪一个，还是它俩的 LCA 就在这棵子树里。

三种情况直接返回 root：root 是空、root 就是 p、root 就是 q。第三种情况其实盖住了前两种，写在一起是因为返回的本来就是 root。

// 普通二叉树上的最近公共祖先（LeetCode 236）
    struct TreeNode {
        int val;
        TreeNode *left, *right;
    };

    TreeNode* LowestCommonAncestor(TreeNode* root, TreeNode* p, TreeNode* q) {
        if (root == nullptr || root == p || root == q) {
            // 遇到空、或者 p、或者 q，直接返回
            return root;
        }
        TreeNode* l = LowestCommonAncestor(root->left, p, q);
        TreeNode* r = LowestCommonAncestor(root->right, p, q);
        if (l != nullptr && r != nullptr) {
            // 左树也搜到、右树也搜到，返回 root
            return root;
        }
        if (l == nullptr && r == nullptr) {
            // 两边都没搜到，返回空
            return nullptr;
        }
        // l 和 r 一个空一个不空，返回不空的那个
        return l != nullptr ? l : r;
    }

先搜左子树，再搜右子树。两边都搜到了，说明 p 在一边、q 在另一边，唯一的公共祖先就是 root，返回自己。一边空一边不空，把不空的那边传上来的答案继续往上带。三种收尾画成一张图：

这个写法没有记忆化。p 找到以后，它沿途每个祖先的另一棵子树照样得搜完，因为函数不知道 p 已经找到了，它必须确认另一侧没有 q。探访量就是这么来的：跟 p、q 隔得多远关系不大，跟沿途兄弟子树有多大关系大。

实测一个满二叉树，4095 个节点，p 在最左最深、q 在最右最深，4095 个节点一个不少全探完。p、q 换成第 4 层的近亲，还是探了 3075 个，约 3/4：p 沿途两棵兄弟子树，5 号有 1023 个节点，3 号有 2047 个，全得探一遍。随机树 200 个节点，随机两点平均探 185 个。

链上反而是最快的：n = 100000 的链，p 在第 33334 个、q 在链尾，探访 33334 个节点，找到 p 就停。因为 q 在 p 的下面，p 就是答案，链尾不用再走。

二、搜索二叉树：值域下走（LeetCode 235）

BST 多了一条普通树没有的信息：左子树全小于根，右子树全大于根。从根往下走，每到一个节点，p、q 相对 root 的位置关系就把答案定死了。

// 搜索二叉树上的最近公共祖先（LeetCode 235）
    struct TreeNode {
        int val;
        TreeNode *left, *right;
    };

    TreeNode* LowestCommonAncestor(TreeNode* root, TreeNode* p, TreeNode* q) {
        // root 从上往下走
        // 先遇到 p，p 就是答案；先遇到 q，q 就是答案
        // root 的值落在 p、q 之间，此刻的 root 就是答案
        // root 在 p、q 左侧，往右走；在右侧，往左走
        while (root->val != p->val && root->val != q->val) {
            if (min(p->val, q->val) < root->val && root->val < max(p->val, q->val)) {
                break;
            }
            root = root->val < min(p->val, q->val) ? root->right : root->left;
        }
        return root;
    }

root 的值夹在 p、q 之间，p 和 q 就分列 root 的两棵子树，公共祖先只能是 root。root 比两个都小，答案在右子树，往右走；比两个都大，往左走。谁大谁小不用管，min、max 一包，判断就一行。

先遇到 p 或 q 本身也停：root 就是 p，说明 q 在 p 的子树里，p 是 q 的祖先，答案就是 p。循环条件里写 root 不等于 p 且不等于 q，圈住的正是这个。

走几步由树高决定。随机 BST 10 万节点，平均深度 21、最大深度 45，2 万对随机 p、q 平均只走 3.25 步：随机两点一半概率分列根两侧，根直接是答案。链退化时树高变成 n，p 在第 33334 个、q 在链尾，要走 33333 步，跟普通树一个下场。

三、复杂度分析

题目时间额外空间说明
普通二叉树 LCAO(n)O(h)递归探访相关子树，栈深等于树高
搜索二叉树 LCAO(h)O(1)值域下走，平衡时 h = log n，退化时 h = n

普通树的 O(n) 不是每次都是整棵树，但最坏就是整棵。搜索树把 O(n) 压成 O(h)，代价是输入必须有序。两题共用同一份空间账：递归多深，栈就占多深。

后序递归：先搜左再搜右，返回值逐层往上带

演示二：搜索树 LCA 下走

值域下走：root 夹在 p、q 之间就停，夹不住就朝一侧走

四、总结

普通树 LCA 的骨架是后序三分支：左右都搜到就返回自己，只搜到一边就带那一边。探访量看兄弟子树的大小，p、q 再近也躲不过沿途的兄弟。

搜索树 LCA 靠值域把搜索压到一条路径：root 夹住即停，夹不住就朝一侧走，步数等于树高，额外空间 O(1)。

单次查询到此够用。查询多了以后，Tarjan 离线批量、树链剖分在线跳链，都是给这个 O(n) 递归提速的后话，后面几课会碰到。
