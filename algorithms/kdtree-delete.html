动态 K-D 树（带删除）

K-D 树能一次剪掉一整片区域，可它天生是静态的：建好之后只查不改。要往里插点、删点，就得借替罪羊树的办法，删除只打标记，攒到失衡了再把整棵子树重建一遍。

零、背景

前面说过的数据结构，大多只管一维：树状数组管前缀和，线段树管区间，平衡树管大小顺序。换成平面上的点，问「矩形里有哪些点」，一维的套路就都用不上了。

K-D 树是给二维（以及更高维）准备的一棵二叉搜索树。它每一层换一个维度来切，节点上记着整棵子树的包围盒，查询时能用包围盒一次剪掉一大片。K-D 树那一节讲的是它的静态版本：点一次性给定，之后只查。

这一节要解决的是动起来的情况：点会插进来，也会被删掉。典型场景是下面这道题。

一、问题

射击场。空间里有 n 个靶子，每个靶子是 x 轴范围 [l, r]、y 轴范围 [d, u] 的一个矩形，另外有一个 z 轴的数值。接下来有 m 发子弹，每发给定出发时的 x 和 y，子弹沿 z 轴往前飞，会击中路上遇到的第一个还没消失的靶子，之后靶子和这发子弹一起消失。问每发子弹击中的是哪个靶子，没击中记 0。

例子用 6 发子弹、3 个靶子。子弹的坐标：

子弹编号123456
坐标 (x, y)(3, 7)(8, 2)(5, 5)(1, 9)(9, 6)(6, 1)

三个靶子分别是 A：[0, 2] × [8, 10]，z = 1；B：[4, 9] × [3, 7]，z = 2；C：[0, 4] × [6, 10]，z = 3。

按 z 从小到大看：A 最靠前，它先被子弹打到。它覆盖的矩形里只有 4 号子弹，于是 4 号打中 A，两个一起消失。剩下的靶子再往下算。

二、朴素做法

最直接的是每来一个靶子，把 m 发子弹全扫一遍，找出落在矩形里、编号最小的那发。n 个靶子就是 O(n·m)，10⁵ 的量级下是 10¹⁰，过不去。

换个角度想：子弹被击中就消失，靶子被击中也就没用了。整个过程其实是「矩形里找一个还在的点，然后把它删掉」。查和删交替进行，正好是一棵需要支持删除的二维搜索树的活。

三、K-D 树长什么样

建树的时候，先按 x 排序取中位数，用这个点的 x 坐标把平面竖着切成两半；左右两半再按 y 排序取中位数，横着切；再下一层又回到 x。每一层换一个维度，这就是 K-D 树名字里那个 K。

包围盒是这棵树的关键。一个节点记着它子树里所有点的 x、y 最小值和最大值，也就是能把这棵子树整个框住的那个矩形。查询矩形跟这个框没交集，整棵子树就都不用看了。

本题要的是「矩形里编号最小的子弹」，所以聚合值记 idmin：子树内存活子弹的最小编号。换道题它可能变成点数、最大值、权值和，看问题要什么。

上面那 6 发子弹建出来的树是这样：根是 3 号 (5, 5)，按 x = 5 切；左子树根是 1 号 (3, 7)，按 y = 7 切，它的右孩子是 4 号 (1, 9)；右子树根是 2 号 (8, 2)，按 y = 2 切，两个孩子是 6 号 (6, 1) 和 5 号 (9, 6)。

四、一次矩形查询怎么剪

从根往下走，每到一个节点有四种情况，按顺序判断：

  1. 这棵子树一个存活点都没有，或者它的 idmin 已经不比当前答案更优，直接返回。
  2. 包围盒和查询矩形没有交集，整棵剪掉。
  3. 包围盒被查询矩形完全包住，这一整棵都在里面，直接取它的 idmin，不用往下走。
  4. 有交集但包不住，那就看当前这个点自己有没有落在矩形里，然后往两个儿子递归。

这里有个小优化值得记一下：两个儿子先递归 idmin 更小的那个。答案越早变小，后面那个「idmin 不比当前答案更优」的剪枝就越好使。

五、删除：只打标记

平衡二叉搜索树删点的时候，可以找左子树的最大值或者右子树的最小值来顶替。K-D 树不行，每一层的维度都在换，「后继」这个词在这里没有定义。

所以换个思路：删点的时候不摘掉节点，只把它标成「死了」。节点留在树上继续当路由，只是不再参与答案。这就是懒删除。

配套的规则是：维护信息的时候，死掉的节点自身不贡献坐标、不贡献编号，只把两个孩子的信息并上来。代码里就是 alive[i] 为假时，先把包围盒设成「空」（xmin 取正无穷、xmax 取负无穷），再去并孩子。

墓碑攒多了树会歪，但这不影响正确性，只影响速度，包围盒变大、查询剪不掉。所以下一步要解决的是什么时候把它扶正。

六、什么时候重构

判断平衡只看存活数。设 α = 0.7，只要某个节点满足 0.7 × 存活数 ≥ 大儿子的存活数，就算平衡。不满足，说明这棵子树歪得太厉害。

插入和删除都沿路从下往上更新信息，一旦遇到不平衡的节点就把它记下来（记的是最靠上的那一个）。一次操作结束后，只对这个节点做一次重构：把它子树里还活着的点全部收集出来，重新切分建树，再把新根挂回它父亲身上。

重建是摊还的。一棵子树要被重建，说明它刚被改动过、且失衡严重；下一次再被重建，中间至少得攒进这么多倍的改动。摊到每一次插入删除上，代价是 O(log n)。

七、比较规则要带上编号

这里有个不做就会出错的细节。不带词频压缩的实现里，坐标完全相同的点可能有好几个；而一旦发生过重建，树的结构和最初不一样了。这时候要删某个点，从根往下走该往左还是往右？

答案是让节点编号一起参与比较：先比当前维度的坐标，坐标一样再比节点编号。建树、插入、删除三处用同一个规则，于是无论重构多少次，任意一个点在树上的位置都被这个规则唯一确定，删除时一路比下去就能走到它。

int compareNode(int i, int j, int dimension) {
    int v1 = dimension == 0 ? x[i] : y[i];
    int v2 = dimension == 0 ? x[j] : y[j];
    return v1 != v2 ? (v1 < v2 ? -1 : 1) : (i - j);
}

有了这个规则，删除就不用像平衡树那样先求 rank 再按 rank 找，直接拿节点编号往下比即可。代价是坐标相同的点之间有一个固定的先后，不过这对答案没影响。

九、代码

下面是模板题的完整实现。子弹建 K-D 树，靶子按 z 排序后依次查询，查到就删。

#include <bits/stdc++.h>
using namespace std;

struct Target {
    int l, r, d, u, z, id;
};

bool ZCmp(Target x, Target y) {
    return x.z < y.z;
}

const int MAXN = 100001;
const int INF  = 1 << 30;
int n, m;

Target target[MAXN];

// 子弹的 K-D 树
int x[MAXN], y[MAXN], cntkdt, root;
int ls[MAXN], rs[MAXN];

bool alive[MAXN];      // 节点是否存活
int aliveSiz[MAXN];    // 子树的存活节点数量，平衡性只用它判断

int xmin[MAXN], xmax[MAXN], ymin[MAXN], ymax[MAXN];

int idmin[MAXN];       // 区域内的子弹最小编号

// 替罪羊树的重构
double ALPHA = 0.7;
int top, topFather, topSide, topDimension;
int arr[MAXN], treeSiz;

int bullet;            // 当前查到的最优子弹
int ans[MAXN];

int init(int qx, int qy) {
    cntkdt++;
    x[cntkdt] = qx;
    y[cntkdt] = qy;
    ls[cntkdt] = rs[cntkdt] = 0;
    alive[cntkdt] = true;
    aliveSiz[cntkdt] = 1;
    xmin[cntkdt] = xmax[cntkdt] = qx;
    ymin[cntkdt] = ymax[cntkdt] = qy;
    idmin[cntkdt] = cntkdt;
    return cntkdt;
}

void maintain(int i) {
    int l = ls[i], r = rs[i];
    if (alive[i]) {
        aliveSiz[i] = 1 + aliveSiz[l] + aliveSiz[r];
        xmin[i] = xmax[i] = x[i];
        ymin[i] = ymax[i] = y[i];
        idmin[i] = i;
    } else {
        aliveSiz[i] = aliveSiz[l] + aliveSiz[r];
        xmin[i] = ymin[i] = INF;
        xmax[i] = ymax[i] = -INF;
        idmin[i] = INF;
    }
    if (aliveSiz[l] != 0) {
        xmin[i] = min(xmin[i], xmin[l]);
        xmax[i] = max(xmax[i], xmax[l]);
        ymin[i] = min(ymin[i], ymin[l]);
        ymax[i] = max(ymax[i], ymax[l]);
        idmin[i] = min(idmin[i], idmin[l]);
    }
    if (aliveSiz[r] != 0) {
        xmin[i] = min(xmin[i], xmin[r]);
        xmax[i] = max(xmax[i], xmax[r]);
        ymin[i] = min(ymin[i], ymin[r]);
        ymax[i] = max(ymax[i], ymax[r]);
        idmin[i] = min(idmin[i], idmin[r]);
    }
}

// 先按维度坐标比较，坐标相同时按 kdt 节点编号比较
// 建树、插入、删除使用相同的比较规则
// 即便发生重构，删除时也能确定唯一的方向
int compareNode(int i, int j, int dimension) {
    int v1 = dimension == 0 ? x[i] : y[i];
    int v2 = dimension == 0 ? x[j] : y[j];
    return v1 != v2 ? (v1 < v2 ? -1 : 1) : (i - j);
}

struct Cmp {
    int dimension;

    bool operator()(int a, int b) const {
        return compareNode(a, b, dimension) < 0;
    }
};

int build(int l, int r, int dimension) {
    if (l > r) {
        return 0;
    }
    int mid = (l + r) >> 1;
    nth_element(arr + l, arr + mid, arr + r + 1, Cmp{dimension});
    int rt = arr[mid];
    ls[rt] = build(l, mid - 1, dimension ^ 1);
    rs[rt] = build(mid + 1, r, dimension ^ 1);
    maintain(rt);
    return rt;
}

bool balance(int i) {
    return ALPHA * aliveSiz[i] >= max(aliveSiz[ls[i]], aliveSiz[rs[i]]);
}

void dfs(int i) {
    if (i != 0 && aliveSiz[i] != 0) {
        if (alive[i]) {
            arr[++treeSiz] = i;
        }
        dfs(ls[i]);
        dfs(rs[i]);
    }
}

void rebuild() {
    if (top != 0) {
        treeSiz = 0;
        dfs(top);
        int newRoot = build(1, treeSiz, topDimension);
        if (topFather == 0) {
            root = newRoot;
        } else if (topSide == 1) {
            ls[topFather] = newRoot;
        } else {
            rs[topFather] = newRoot;
        }
    }
}

int add(int insertNode, int u, int fa, int side, int dimension) {
    if (u == 0 || aliveSiz[u] == 0) {
        return insertNode;
    }
    if (compareNode(insertNode, u, dimension) <= 0) {
        ls[u] = add(insertNode, ls[u], u, 1, dimension ^ 1);
    } else {
        rs[u] = add(insertNode, rs[u], u, 2, dimension ^ 1);
    }
    maintain(u);
    if (!balance(u)) {
        top = u;
        topFather = fa;
        topSide = side;
        topDimension = dimension;
    }
    return u;
}

void add(int qx, int qy) {
    top = topFather = topSide = topDimension = 0;
    int insertNode = init(qx, qy);
    root = add(insertNode, root, 0, 0, 0);
    rebuild();
}

void remove(int removeNode, int u, int fa, int side, int dimension) {
    if (u == removeNode) {
        alive[u] = false;
    } else if (compareNode(removeNode, u, dimension) <= 0) {
        remove(removeNode, ls[u], u, 1, dimension ^ 1);
    } else {
        remove(removeNode, rs[u], u, 2, dimension ^ 1);
    }
    maintain(u);
    if (!balance(u)) {
        top = u;
        topFather = fa;
        topSide = side;
        topDimension = dimension;
    }
}

void remove(int removeNode) {
    top = topFather = topSide = topDimension = 0;
    remove(removeNode, root, 0, 0, 0);
    rebuild();
}

void query(int ql, int qr, int qd, int qu, int i) {
    if (i == 0 || aliveSiz[i] == 0 || idmin[i] >= bullet) {
        return;
    }
    if (xmax[i] < ql || qr < xmin[i] || ymax[i] < qd || qu < ymin[i]) {
        return;
    }
    if (ql <= xmin[i] && xmax[i] <= qr && qd <= ymin[i] && ymax[i] <= qu) {
        bullet = min(bullet, idmin[i]);
        return;
    }
    if (alive[i] && ql <= x[i] && x[i] <= qr && qd <= y[i] && y[i] <= qu) {
        bullet = min(bullet, i);
    }
    int l = ls[i], r = rs[i];
    if (idmin[l] < idmin[r]) {
        query(ql, qr, qd, qu, l);
        query(ql, qr, qd, qu, r);
    } else {
        query(ql, qr, qd, qu, r);
        query(ql, qr, qd, qu, l);
    }
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> n;
    for (int i = 1; i <= n; i++) {
        cin >> target[i].l >> target[i].r >> target[i].d >> target[i].u >> target[i].z;
        target[i].id = i;
    }
    xmin[0] = ymin[0] = INF;
    xmax[0] = ymax[0] = -INF;
    idmin[0] = INF;
    cin >> m;
    for (int i = 1, qx, qy; i <= m; i++) {
        cin >> qx >> qy;
        add(qx, qy);
    }
    sort(target + 1, target + n + 1, ZCmp);
    for (int k = 1; k <= n; k++) {
        bullet = INF;
        query(target[k].l, target[k].r, target[k].d, target[k].u, root);
        if (bullet != INF) {
            ans[bullet] = target[k].id;
            remove(bullet);
        }
    }
    for (int i = 1; i <= m; i++) {
        cout << ans[i] << '\n';
    }
    return 0;
}

两处容易写错。一是 0 号节点是哨兵，它的 xmin、ymin 要设成正无穷、xmax、ymax 设成负无穷、idmin 设成无穷，否则空子树会把查询带偏。二是 add 里的 aliveSiz[u] == 0 这一句：走到一棵全是墓碑的子树时，直接把新点挂在它的位置上，省得往下钻。

十、复杂度分析

操作时间复杂度
建树（n 个点，每层 nth_element）O(n log n)
插入一个点（含摊还的重构）O(log n) 摊还
删除一个点（懒删除 + 摊还的重构）O(log n) 摊还
一次矩形查询（随机数据）O(√n)，最坏 O(n)
射击场整体（n 个靶子、m 发子弹）O(n√m)
朴素做法（对照）O(n·m)
额外空间O(m)

建树那一行的由来：每一层对整段做一次 nth_element 是 O(n)，一共 log n 层。别写成排序，否则变成 O(n log² n)。

查询的 O(√n) 是 K-D 树在二维、随机分布数据下的期望量级，严格来说最坏能退化到 O(n)。做题时按 √n 估算就够用，这也是 K-D 树能过 10⁵ 的原因。

空间上按「插入次数」开数组，不是按存活数：墓碑节点一直占位置。本题 m 发子弹开 MAXN = m + 1 就够；如果题目是「先删后插」的修改操作，就要按总操作次数开。

十一、最后

动态 K-D 树的全部技巧其实就两条：删除只打标记让它继续当路由，攒到失衡了整棵重建。前者换来「不用找后继」的简洁，后者把维护复杂度的活一次性摊平。

换成三维也一样，只是维度轮转从 dimension ^ 1 变成 (dimension + 1) % 3，包围盒多一组 zmin、zmax。有一道题是这样的：三维空间里 n 个摄像头，支持改位置和「给定球心和半径，找出球面上恰好有一个摄像头」的查询。改位置就是删旧节点加新节点，查询则用球心到包围盒的最近距离、最远距离来判断「整个盒子都在球面之外」和「整个盒子都在球内」两种情况，各自剪掉。

它的边界也清楚：K-D 树擅长的是矩形（盒子）范围查询，问「最近的点是谁」也能做，但一旦要精确的前 k 个或者带修改的复杂统计，就得换别的工具了。
