数组中两个数的最大异或值

异或结果看每一位，高位能出 1，低位怎么折腾都补不回来。把所有数按位插成 01-Trie，对每个数逐位贪心走「相反的那一位」，一次查询只走 31 步。

零、背景

给一个整数数组，找两个数，让异或结果最大。n 最多 2×10^5，数最大到 2^31-1。

朴素做法两两异或：2×10^5 个数是 4×10^10 对。实测 n=5×10^4 的暴力要 102.6ms，n 翻四倍、时间翻十六倍，外推 n=2×10^5 约 1.6 秒。这只是把 4 千亿次异或跑完，还没算别的。

异或有个好性质：结果的每一位互不影响，第 i 位只由两个数的第 i 位决定。而大小由最高的不同位决定：两个数异或，从高位往下看，第一次出现 1 的那一位，已经决定了结果的大小，低位的所有 1 加起来都填不平这一个 1。

所以问题变成：对每个数 num，在数组里找一个数，让异或结果最大。逐位定：这一位能凑出 1，就不要 0。

一、按位建树

把每个数从高位到低位，按二进制位插成一棵树。树的每个节点只有两条路：0 和 1，这就是 01-Trie。

不用从第 31 位开始。数组最大值决定了最高有效位，前面全是 0 的位不用建，插进去也只会走 0 路。high 取 max 的最高有效位，从 high 往下插。

[5, 25] 两个数：5 的二进制是 00101，25 是 11001，max=25，high=4，从第 4 位开始。5 走 0-0-1-0-1，25 走 1-1-0-0-1，两条路在前两位就分开了。

节点数最坏是 n×31：每个数都走一条全新的路。实测 2×10^5 个随机数插完用了约 290 万节点，静态池按 3000001 开刚好够。这个「刚好」提醒你，MAXN 要按最坏规模算，别按平均值算。

二、贪心查询

maxXor(num) 从 high 往下逐位走：num 这一位是 st，希望遇到 want = st^1（异或出 1）。树里有 want 这条路就走 want，没有就只能走 st。

贪心成立的理由在前面：第 i 位出 1，贡献 2^i，低位的所有 1 加起来是 2^i-1，补不回来。所以每一高位先定死，低位的选择不影响已经定下的高位。

代码很短，静态数组和上一讲一个套路，只是路从 26 条变成 2 条：

static const int MAXN = 3000001;
    static int tree[MAXN][2], cnt, high;

    // 从高位到低位，逐位插成一条路
    void insert(int num) {
        int cur = 1;
        for (int i = high; i >= 0; i--) {
            int p = (num >> i) & 1;
            if (tree[cur][p] == 0) {
                tree[cur][p] = ++cnt;
            }
            cur = tree[cur][p];
        }
    }

    // high 是数组最大值最高有效位的位置，前置的 0 不用建
    void build(vector<int>& nums) {
        cnt = 1;
        int mx = 0;
        for (int num : nums) mx = max(mx, num);
        high = mx ? 31 - __builtin_clz(mx) : 0;
        for (int num : nums) insert(num);
    }

    // num 和树里的某个数异或，最大能到多少
    int maxXor(int num) {
        int cur = 1, ans = 0;
        for (int i = high; i >= 0; i--) {
            int st = (num >> i) & 1;      // num 这一位
            int want = st ^ 1;            // 希望遇到相反的位，异或出 1
            if (tree[cur][want] == 0) {   // 没有相反的位，只能走一样的
                want ^= 1;
            }
            ans |= (st ^ want) << i;      // 这一位的异或结果写进答案
            cur = tree[cur][want];
        }
        return ans;
    }

build 里先找 max 算 high，再把所有数插进去；主流程对每个 num 调一次 maxXor，取最大值。单个 num 的查询 O(high+1)，整体 O(n×31)。

三、哈希表做法

这道题还有一个不用树的写法，同一节课里给了，同样 O(n×31)：从 high 往下枚举目标答案的每一位，维护一个集合，查 better^num 在不在集合里。

思路是反过来的：不逐位走树，而是直接猜答案。第 i 轮假设「答案第 i 位是 1」得到 better，如果存在两个数异或能达成 better，就把这一位写死，否则放弃。

实测它比 Trie 还快：n=2×10^5 时哈希 12.8ms，Trie 39.7ms。代价是难想。Trie 版本是「顺着异或的位结构走」，哈希版本是「反着验证答案」，前者好理解，后者常数小。

复杂度分析

做法时间空间
暴力两两异或O(n²)O(1)
01-TrieO(n×31)O(n×31)
哈希表O(n×31)O(n)

31 是位数上界，数组值域是 2^31-1，所以每个数的插入和查询都是常数步，比 O(n²) 高出一个量级的差距。

总结

最大异或的位贪心只有一条：从最高有效位往下，能走相反位就走相反位。

01-Trie 的路只有 0/1 两条，静态数组开 tree[MAXN][2]，比 26 路的前缀树还省；high 从最高有效位起跳，省掉一整段全是 0 的路径。

哈希做法更快但难想，两种都是 O(n logV)。这一讲是树里查位，下一讲把 Trie 和 DFS 拼起来：二维网格里搜单词。下节课的题目里见。
