时间复杂度和空间复杂度

同一个问题能写出好几种做法，怎么判断哪个更好？不看它跑了几毫秒，看数据量翻十倍的时候代价怎么变。这一讲把这个「怎么看」讲清楚。

零、背景

判断一段代码好不好用，最省事的办法是跑一遍看耗时。这个办法只在数据量固定的时候作数：同一份代码在长度 1000 的数组上跑 3 毫秒，换成长度 100000 的数组可能跑 3 秒，而且变慢的倍数每次都不一样。

机器、语言、编译器都会影响那几毫秒。所以真正要描述的不是「这一次跑了多久」，而是「数据量变大时，代价按什么规律变大」。

这就是时间复杂度。后面每一讲都会用到它，判断一个算法能不能过题，靠的就是它。

一、常数操作

先划一条线：什么叫一步。

加减乘除、比较、赋值、按下标读写数组，这些操作的执行时间都不随数据量变化，叫常数操作。反过来，「从头到尾扫一遍数组」不是常数操作，它的次数和数据量成正比。

把一个流程拆成常数操作之后，剩下要数的就是次数。

这里有个细节：常数操作之间花的时间并不一样。实测一亿次整数除法约 124 毫秒，一亿次数组顺序访问约 25 毫秒，差 5 倍。所以复杂度只管数量级，真正比快慢的时候还是得实测。

二、只留高阶项

数出来的次数表达式往往很长。比如某个流程要 n²/2 + 3n + 5 次。

时间复杂度只留最高阶那一项，系数也丢掉，写成 O(n²)。理由是数据量足够大时，低阶项和系数左右不了「翻十倍会慢多少」这个结论。

下面这张图把四组数据画在同一根条上。蓝色是 n²/2，橙色是 3n + 5，条的总长按两者之和归一。

n 从 10 涨到 10000，橙色的占比从 41.2% 掉到 0.06%，到后来根本看不见。丢掉它不是因为它不存在，而是因为它只在数据量小的时候能左右结论。

等差数列求和公式派上用场也在这儿：任何等差数列的和都符合 a·n² + b·n + c，a、b、c 都是常数。所以里层走成一个等差数列的嵌套循环，一律是 O(n²)，不用去数到底加了多少次。

三、最差情况，还是平均情况

同一个算法在不同输入上代价可以差很多。这时候要分两类看。

流程固定的：看最差

插入排序的流程里没有任何随机行为，输入什么样它就怎么走。这种算法强调最差情况。

逆序数组是它的最坏输入：每个新元素都要一路顶到头。实测 n = 10000 时比较 50004999 次；同样长度的随机数组平均 25021743 次（200 次实验取平均）。

差了两倍，但阶没变，都是 O(n²)。复杂度描述的是增长的级别，不是具体数字。

它的比较次数等于逆序对数加 n − 1。逆序数组有 n(n−1)/2 个逆序对，随机数组平均只有四分之一，数组本来就有序时是 0。所以同一个算法，最好情况 O(n)、最差 O(n²)；平时说它是 O(n²)，指的是最差那一种。

// 插入排序，顺便数比较次数
    // 比较次数 = 逆序对数 + (N - 1)
    long long insertionSort(vector<int>& a) {
        int n = (int)a.size();
        long long cmp = 0;
        for (int i = 1; i < n; i++) {
            for (int j = i - 1; j >= 0 && a[j] > a[j + 1]; j--) {
                cmp++;
                swap(a[j], a[j + 1]);
            }
            cmp++;
        }
        return cmp;
    }

流程里用了随机行为：看期望

再看一个例子：随机生成一个长度为 n、值在 0 到 v−1 之间、且任意相邻两数不相等的数组。做法是每个位置抽一次，抽到和上一个一样就重抽。

// 随机生成长度为 n、值在 0 ~ v-1 之间、且任意相邻两数不相等的数组
    // 每个位置期望抽 v / (v - 1) 次，整体期望 O(N)
    vector<int> makeArray(int n, int v) {
        vector<int> a(n);
        a[0] = rand() % v;
        for (int i = 1; i < n; i++) {
            do {
                a[i] = rand() % v;
            } while (a[i] == a[i - 1]);
        }
        return a;
    }

这个流程的最差情况说不出来：理论上可以一直抽到相同的值，永远出不来。所以最差复杂度没有意义。

能算的是期望。一次就抽中的概率是 (v−1)/v，每个位置期望抽 v/(v−1) 次，n 个位置合起来是 n·v/(v−1)，v 固定时就是 O(n)。

实测值和这个式子对得上。n = 1000 时：v = 2 平均抽 1999 次（式子给 2000），v = 4 平均 1332 次（式子给 1333），v = 100 平均 1010 次（式子给 1010）。

随机快速排序和跳表也是这一类，流程里把随机行为当成正经的一部分，最差情况没有意义，只看平均或者期望。

四、额外空间

空间复杂度说的是「额外」两个字：输入本身占的那份不算，只算算法自己另外申请的。

冒泡排序只用了几个变量，额外空间 O(1)。归并排序要一个和原数组一样大的临时数组，O(n)。

// 归并排序：tmp 从头到尾只有一份，额外空间 O(N)
    // 递归深度 O(logN)，栈上再占 O(logN)
    void mergeSort(vector<int>& a, int l, int r, vector<int>& tmp) {
        if (l >= r) {
            return;
        }
        int m = l + ((r - l) >> 1);
        mergeSort(a, l, m, tmp);
        mergeSort(a, m + 1, r, tmp);
        int i = l, j = m + 1, k = l;
        while (i <= m && j <= r) {
            tmp[k++] = (a[i] <= a[j]) ? a[i++] : a[j++];
        }
        while (i <= m) tmp[k++] = a[i++];
        while (j <= r) tmp[k++] = a[j++];
        for (int p = l; p <= r; p++) {
            a[p] = tmp[p];
        }
    }

tmp 从头到尾只有一份，每层递归共用它，所以额外空间是 O(n) 而不是 O(n log n)。递归深度是 O(log n)，栈上再加 O(log n)。

一个 int 是 4 字节，100 万个 int 就是 4 MB。题面给的空间限制一般是 256 MB 或 512 MB，开数组之前先算一下，别等到评测机上才炸。

五、均摊：动态数组为什么是 O(1)

动态数组（C++ 的 vector 这类）在尾部加一个元素，平均下来是 O(1)。但填满的时候要申请一块更大的空间，把老数据搬过去，那一次是 O(n)。

// 手写一个动态数组：容量不够就翻倍，翻倍后把老数据搬过去
    // 单次 push 最坏 O(N)，但连续 N 次 push 的总代价是 O(N)
    struct DynArray {
        int* data;
        int cap, siz;
        long long copies;

        DynArray() : data(new int[1]), cap(1), siz(0), copies(0) {}

        void push(int v) {
            if (siz == cap) {
                int* bigger = new int[cap * 2];
                for (int i = 0; i < siz; i++) {
                    bigger[i] = data[i];
                }
                copies += siz;
                delete[] data;
                data = bigger;
                cap *= 2;
            }
            data[siz++] = v;
        }
    };

关键在「一共搬了几次」。容量按 2 倍涨，装到第 n 个元素时只扩容了 log₂ n 次，搬运量是 1 + 2 + 4 + ... + 2ᵏ，一个等比数列，和不超过 2n。

所以连续 push n 次的总代价是 O(n)，摊到每一次就是 O(1)。这叫均摊复杂度。

扩容因子取多少都行，只要是一个大于 1 的常数，均摊就是 O(1)，只是常数不同。实测 push 100000 次：2 倍扩容一共搬了 131071 个元素，均摊 1.31 次；1.5 倍搬了 276464 个，均摊 2.76 次。

并查集、单调栈、单调队列、哈希表里都有这个概念：单次操作可以很贵，一连串操作摊下来是常数。

六、别照着代码结构猜

最常见的错是数循环层数。两个反例。

只有一个 while 的冒泡

下面这份冒泡排序把两层 for 换成了单个 while，看着像是 O(n)。

// 只有一个 while 循环，看着像 O(N)
    // 实际是 O(N^2)：end 每减 1，i 都要从 0 重新走一遍
    void bubbleSort(vector<int>& a) {
        int n = (int)a.size();
        if (n < 2) {
            return;
        }
        int end = n - 1, i = 0;
        while (end > 0) {
            if (a[i] > a[i + 1]) {
                swap(a[i], a[i + 1]);
            }
            if (i < end - 1) {
                i++;
            } else {
                end--;
                i = 0;
            }
        }
    }

其实 i 每次走到 end − 1 就归零、end 减 1，走完整整一趟才往下挪一格，和两层 for 是一回事。

实测 n = 6 时进了 while 15 次，正好 n(n−1)/2。下面这张图把走过的每一步摆成格子，行是 end，列是 i。

步长不是 1 的两层循环

两个都是两层循环，代价能差一千倍。

// 看着是两层循环，其实是 O(N * logN)
    // 内层走 N / i 步：N/1 + N/2 + ... + N/N = N * (1 + 1/2 + ... + 1/N)
    long long harmonic(int n) {
        long long cnt = 0;
        for (int i = 1; i <= n; i++) {
            for (int j = i; j <= n; j += i) {
                cnt++;
            }
        }
        return cnt;
    }

    // 同样两层循环，这个才是 O(N^2)：n = 20000 时 2 亿次
    long long quadratic(int n) {
        long long cnt = 0;
        for (int i = 1; i <= n; i++) {
            for (int j = i; j <= n; j++) {
                cnt++;
            }
        }
        return cnt;
    }

上面那个里层 j += i，走 n/i 步，合起来是 n/1 + n/2 + ... + n/n，也就是 n·(1 + 1/2 + ... + 1/n)。括号里是调和级数，收敛到 ln n，所以整体是 O(n log n)。

下面那个里层 j++，每层是等差数列，才是 O(n²)。

实测 n = 20000：前者 201177 次、0.10 毫秒；后者 200010000 次、86.9 毫秒。次数差约 1000 倍，耗时差约 880 倍。

所以时间复杂度只能在对流程充分理解之后分析出来，照代码结构是看不出来的。反过来也一样：有些实现套了好几层循环，复杂度只有 O(n)。

七、常见复杂度一览

从低到高排下来是 O(1)、O(log n)、O(n)、O(n log n)、O(n²)、O(nᵏ)、O(kⁿ)、O(n!)。

按一秒大约能做一亿次简单操作估算，每种复杂度能撑到的 n 大概是这样。

做题时先看数据范围，再倒推该用哪个复杂度：n ≤ 10⁵ 基本要 O(n log n) 或者更好，n ≤ 10³ 时 O(n²) 还来得及，n ≤ 20 就往 O(2ⁿ) 上想。这是判断一个做法能不能过题最快的办法。

八、什么叫最优解

先满足时间复杂度最优，然后在这个前提下尽量少用空间。

时间复杂度差一个级别时，比如 O(n²) 对 O(n log n)，空间上省下的那点东西不值一提。只有在复杂度相同的时候，才去比空间和常数。

最后

这一讲没有新算法，但它决定了后面每一讲怎么评价一个算法。把流程拆成常数操作、只留高阶项、分清楚最差还是期望、额外空间单独算，这四步做完，一段代码的代价就说清楚了。
