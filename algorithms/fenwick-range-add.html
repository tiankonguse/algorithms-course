树状数组：范围加与范围查

整段一起加，在差分数组上就是两个单点修改；再加一张记 (i−1)·d[i] 的表，整段求和也能顺手做掉。两种扩展的单次代价都是 O(log n)。

零、背景

树状数组最基础的用法是单点加、范围查：改一个位置 O(log n)，查一段的和 O(log n)。题目稍微变一变，要的是「把 [l, r] 里每个数都加上 v」，一次改一整段。

树状数组本身一行都不用改，换掉被维护的对象就行：从原数组 a 换成它的差分 d。整段加变成两个单点加，查单点值变成查前缀和，全落在已经会做的那两件事上。

再往下走一步，整段加的同时还要整段求和，那就得多记一张表。这一节把这两步都推一遍，顺带把树状数组的能力边界量出来。

一、树状数组能维护什么

树状数组给的答案是前缀信息，区间答案靠两次前缀相减。能相减的信息才玩得转，比如累加和，prefix[r] − prefix[l−1] 一步就出来。异或和也可以，它自己就是自己的逆运算。

最大值不行。知道 [1, 8] 的最大值和 [1, 3] 的最大值，推不出 [4, 8] 的最大值，减不掉。

硬要用树状数组维护最大值，得接受一条规矩：数值只能往大改。某个位置一旦改小，所有管着它的节点都可能还挂着那个旧的最大值，只能整棵重建。实测 n = 10⁵、10⁵ 次操作里约一半是改小：树状数组重建了 50205 次、累计刷掉 50.2 亿个位置，耗时 37116.87 ms；同一件事交给线段树，7.81 ms。差了 4750 倍。

所以最大值、最小值这类信息直接上线段树。可差分的交给树状数组，理由也很实在：同一个「范围加 + 范围查」，两者开销差一个量级。

两份代码跑出来的答案逐位一致。线段树能维护的信息更多、想起来也更直白，代价是四倍空间和四倍多的时间。

二、范围加、单点查

一维差分的老套路：d[i] = a[i] − a[i−1]，于是 a[i] = d[1] + … + d[i]。给 [l, r] 每个数加 v，在 d 上只有两个位置动。

d[l] += v;  d[r + 1] -= v;

前面这一串只有 l 之后才生效，后面那一串把 r + 1 之后的增量抵消掉，中间正好是 [l, r]。查 a[i] 就是查 d 的前缀和。

树状数组维护的是 d 而不是 a，修改就退化成两个单点加，查询退化成一次前缀和。初始化也照这个规矩来：第 i 个初值当成「给 [i, i] 加 a[i]」，也就是 add(i, a[i]) 与 add(i + 1, −a[i]) 成对写。

这里有个细节：r = n 时那个 −v 要打在 n + 1 上，所以树状数组得开到 n + 1，否则这次修改会静默丢掉。

速度上的差别不用估算，直接量：n = 10⁵、10⁵ 次范围加（区间平均长度 5 万，逐格加总共要碰 50 亿个元素），树状数组 3.013 ms，逐格加 379.463 ms，126 倍。

这一问最容易写错的地方是那两个端点。各跑 2 万组随机序列、每组 20 个操作实测：漏掉 add(r + 1, −v) 的有 87.48% 被抓出来，写成 add(r, −v) 的有 97.79% 被抓出来。前者那 12.5% 为什么溜掉？因为只在 l 之后查过、且没查过区间外的点时，答案恰好都对。

三、范围加、范围查

还想要整段的和。记 D(x) = d[1] + … + d[x]，那么前缀和

S(x) = a[1] + … + a[x]
     = d[1]·x + d[2]·(x−1) + … + d[x]·1
     = Σ d[i]·(x − i + 1)
     = (x + 1)·D(x) − Σ i·d[i]

最后那一项 Σ i·d[i] 也得能查，于是再开一张表。巧的是我们不必真的记 i·d[i]，记 (i − 1)·d[i] 就行：

Σ (i−1)·d[i] = Σ i·d[i] − D(x)
S(x) = (x + 1)·D(x) − ( Σ(i−1)·d[i] + D(x) ) = x·D(x) − Σ (i−1)·d[i]

第二张表里存 (i − 1)·d[i]，写起来就是给 info2 打 (l − 1)·v 和 −r·v，跟 info1 那两个点一一对应。以 x = 5 为例，两种写法算的是同一堆东西。

n = 10⁶ 时的吞吐：1 次范围加要动 4 个树状数组位置，10⁶ 次下来 105.03 ms；范围查要 4 次前缀和，10⁶ 次 38.23 ms。只用一张表的范围加单点查，10⁶ 次修改 49.50 ms。

这一问的错法集中在第二张表上，同样是 2 万组随机序列：info2 写成 l·v（末尾不减 1 那一项也跟着错）99.97% 会被抓，只维护 info1 拿 sum·x 当区间和 91.42%，末端写成 −(r + 1)·v 89.67%。三档都在九成上下，说明随机数据足够把它们揪出来。

四、代码

范围加、单点查，一份树状数组就够。

#include <bits/stdc++.h>
    using namespace std;

    const int MAXN = 500002;
    long long tree[MAXN];
    int n;

    int lowbit(int i) {
        return i & -i;
    }

    // i 位置增加 v
    void add(int i, long long v) {
        while (i <= n) {
            tree[i] += v;
            i += lowbit(i);
        }
    }

    // 1~i 范围的累加和
    long long sum(int i) {
        long long ans = 0;
        while (i > 0) {
            ans += tree[i];
            i -= lowbit(i);
        }
        return ans;
    }

    // 原数组 [l..r] 每个数增加 v：只动差分的两端
    void rangeAdd(int l, int r, long long v) {
        add(l, v);
        add(r + 1, -v);
    }

    // 原数组 i 位置的值：差分的前缀和
    long long query(int i) {
        return sum(i);
    }

范围加、范围查，两张表共用同一套 add / sum，多传一个数组参数。

const int MAXN = 100002;
    long long info1[MAXN], info2[MAXN];
    int n;

    int lowbit(int i) {
        return i & -i;
    }

    void add(long long tree[], int i, long long v) {
        while (i <= n) {
            tree[i] += v;
            i += lowbit(i);
        }
    }

    long long sum(long long tree[], int i) {
        long long ans = 0;
        while (i > 0) {
            ans += tree[i];
            i -= lowbit(i);
        }
        return ans;
    }

    // 原数组 [l..r] 每个数增加 v
    void rangeAdd(int l, int r, long long v) {
        add(info1, l, v);
        add(info1, r + 1, -v);
        add(info2, l, (long long)(l - 1) * v);
        add(info2, r + 1, -(long long)r * v);
    }

    // 原数组 1~x 范围的累加和
    long long prefixSum(int x) {
        return sum(info1, x) * x - sum(info2, x);
    }

    // 原数组 [l..r] 范围的累加和
    long long rangeSum(int l, int r) {
        return prefixSum(r) - prefixSum(l - 1);
    }

五、复杂度分析

两种扩展都是常数次树状数组操作，所以单次还是 O(log n)。把每步跳多少格量出来更直观：n = 2²⁰ 时，前缀查询平均跳 10 次（= log₂n / 2，跳的次数就是 i 的二进制里 1 的个数），单点修改平均跳 11 次；最坏的是 add(1)，21 次，而 sum(n) 只要 1 次。

用法范围加查询空间
单点加、范围查O(log n)O(log n)O(n)，一张表
范围加、单点查O(log n)O(log n)O(n)，一张表（开到 n + 1）
范围加、范围查O(log n)O(log n)O(n)，两张表

建树按初始值逐对打标记是 n 次范围加，O(n log n)；直接按 d[i] = a[i] − a[i−1] 填好再 O(n) 建树更快，两种写法结果一样。

六、总结

范围加这一问，树状数组靠换维护对象（原数组换成差分）就解决了，查询从「查区间」变回「查前缀」。范围查再往下走一步，是给 Σ i·d[i] 单独开一张表，靠 (i − 1)·d[i] 这个写法把公式化简成 x·D(x) − Σ(i−1)·d[i]。

几个容易翻车的点：树状数组要开到 n + 1，r = n 时的 −v 才有地方落；第二张表末端写的是 −r·v，与首端的 (l − 1)·v 差一个 1，写反会全体偏一个 D(x)；可差分这条边界要记牢，最大值往上加还行，改小就得重建。

一维上的花样就这些。把同样的思路放到二维，单点加变矩形加，一次操作要跳的是两个维度。
