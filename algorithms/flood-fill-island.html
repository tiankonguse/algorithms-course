最大人工岛：给每座岛编号

最多把一格 0 改成 1，问能得到的最大岛面积。逐个 0 去试、每次重算连通性会退到 O((n×m)²)，把每座岛编号、记下面积表，第二遍就只剩查表。

零、问题

网格里 1 是陆地、0 是水，上下左右相连的 1 算同一座岛。允许把恰好一格 0 填成 1（也可以不填），问填完之后最大的岛有多大。

最直接的写法是枚举每个 0、填掉、再从这里做一次洪水填充数面积。每个 0 都要扫一遍全网格，n×m 个 0 就是 O((n×m)²)，n=m=100 时是一亿次量级，扛不住。

换个角度：填一个 0 能连出来的岛，等于它四周那几个岛的面积之和再加 1。只要事先知道每座岛的面积，并且能 O(1) 问出「这个格子属于哪座岛」，第二遍就是查表。

一、第一遍：把整座岛改成同一个编号

感染函数照旧，只是这次改成的不是一个固定的标记，而是一个编号，从 2 开始（1 留给「还没编号的陆地」，0 是水）。主循环扫到一个 1，就带着新编号去感染，编号用完自增。

这一步顺手解决了「这个格子属于哪座岛」：编号直接写在格子里，看一眼就知道。

// 第一遍：把整座岛的 1 改成同一个编号（从 2 开始，1 留给还没编号的格子）
    void dfs(vector<vector<int>>& grid, int n, int m, int i, int j, int id) {
        if (i < 0 || i == n || j < 0 || j == m || grid[i][j] != 1) {
            return;
        }
        grid[i][j] = id;
        dfs(grid, n, m, i - 1, j, id);
        dfs(grid, n, m, i + 1, j, id);
        dfs(grid, n, m, i, j - 1, id);
        dfs(grid, n, m, i, j + 1, id);
    }

二、面积表：再扫一遍数编号

编号时没能顺手数面积，因为感染过程是递归散开的，返回值要等四个方向都跑完才拿得到。干脆再扫一遍全网格：格子值大于 1 的，就给 sizes[格子值] 加一。

这一遍顺带把「不填任何格子」的答案算出来，也就是原本最大岛的面积，作为 ans 的初值。题目里的「最多」允许一格都不填。

三、第二遍：每个 0 都试一次

对每个 0，看它上下左右四个格子的编号，把对应的面积加起来再加 1（它自己），拿去更新 ans。四个方向里是 0 的格子表示那边是水，贡献 0。

这里有个必踩的坑：四个方向可能指向同一座岛。绕着一圈陆地的中间那格，上下左右是同一个编号，不去重就会把同一座岛的面积加四遍。

用一个 visited 数组挡一下：先把上方那个编号记成已访问，其余三个方向里遇到已访问的就跳过，算完把四个都清掉。

int largestIsland(vector<vector<int>>& grid) {
        int n = grid.size();
        int m = grid[0].size();
        int id = 2;
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < m; j++) {
                if (grid[i][j] == 1) dfs(grid, n, m, i, j, id++);
            }
        }
        vector<int> sizes(id, 0);
        int ans = 0;
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < m; j++) {
                if (grid[i][j] > 1) ans = max(ans, ++sizes[grid[i][j]]);
            }
        }
        // 第二遍：每个 0 都试一次，四周的岛合并起来有多大
        vector<char> visited(id, 0);
        int up, down, left, right, merge;
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < m; j++) {
                if (grid[i][j] == 0) {
                    up = i > 0 ? grid[i - 1][j] : 0;
                    down = i + 1 < n ? grid[i + 1][j] : 0;
                    left = j > 0 ? grid[i][j - 1] : 0;
                    right = j + 1 < m ? grid[i][j + 1] : 0;
                    visited[up] = 1;
                    merge = 1 + sizes[up];
                    if (!visited[down]) { merge += sizes[down]; visited[down] = 1; }
                    if (!visited[left]) { merge += sizes[left]; visited[left] = 1; }
                    if (!visited[right]) { merge += sizes[right]; visited[right] = 1; }
                    ans = max(ans, merge);
                    visited[up] = visited[down] = visited[left] = visited[right] = 0;
                }
            }
        }
        return ans;
    }

演示：第一遍编号，第二遍算面积表

四、不去重会错得多离谱

最典型的是一圈陆地围着一个 0：上下左右全是 2 号岛，面积 8。正确的合并结果是 1+8 = 9，不去重会算成 1+8+8+8+8 = 33。

随机测试能看出这种撞车有多常见：2 万组 1×1 到 7×7 的随机网格，不去重的写法有 58.31% 给出偏大的答案，平均偏大 20.76。网格越小、陆地越碎，撞上的机会越多。

演示：逐个 0 试填，四个方向查表并去重

五、复杂度分析

指标值
时间复杂度O(n×m)，网格 n 行 m 列
额外空间O(n×m)（sizes 与 visited 数组，长度不超过格子数）
三遍扫描编号一遍、数面积一遍、试填一遍，每遍都是 O(n×m)

编号那一步的递归深度仍然等于岛的大小，全是 1 的网格会有栈压力，必要时换成队列版，逻辑不变。

六、总结

三遍扫描：编号、数面积、试填。编号把「这格属于哪座岛」变成 O(1) 查询，面积表把「这片岛多大」也变成 O(1)，于是枚举每个 0 只剩加法。

去重那一手别省。上方编号先标 visited、其余三个方向遇到已标就跳过、算完四个位置一起清掉，这三行是这题唯一容易写漏的地方，写漏了有将近六成的随机样本会答错。

同样的思路换个问法还能用：把编号留在格子里，任何「这一格属于哪个集合」的信息都能当初值带着走。
