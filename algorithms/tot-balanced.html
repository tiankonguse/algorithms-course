同一道题的两种外层

上一节留下一个疑问：外层换成树状数组会怎么样。这一节拿同一道题写两遍，外层是线段树、内层是平衡树；外层是树状数组、内层是开点权值线段树。两遍都写完，外层的差别就看得清楚了。

零、题目

给定一个长度为 n 的数组，下标 1 到 n，m 次操作，操作有五种：操作 1 查询数字 z 在 [x, y] 中的排名；操作 2 查询 [x, y] 中排第 z 名的数字；操作 3 把 x 位置的数字改成 y；操作 4 查询 z 在 [x, y] 中的前驱，不存在返回 −2147483647；操作 5 查询 z 在 [x, y] 中的后继，不存在返回 +2147483647。n、m ≤ 5 × 10⁴，值永远在 [0, 10⁸] 内。测试链接：P3380。

五种操作里有四种是「数一数」，只有操作 2 是「反查」。这个区别决定了两种写法的复杂度差在哪。

一、题目3：线段树套平衡树

外层按下标建线段树，外层的每个节点内部存一棵平衡树，装着这个节点管辖范围内出现的所有数（带重复）。平衡树用替罪羊树：插入后检查是否失衡，失衡就把整棵中序收集出来重建；删除是惰性的，只把 alive 标记成 false，aliveSiz 只数活着的节点。

操作 1（排名）最自然：外层把 [x, y] 拆成 O(log n) 段，每段在自己的平衡树里数一遍「严格小于 z 的个数」，加起来再加一。

操作 2 就没这么顺了。要找第 z 名，平衡树里能 O(log) 定位，但四棵平衡树各有各的形状，没法合成一次定位。所以只能在外面再套一层二分：二分答案 v，用操作 1 的方式数「小于等于 v 的个数」，看够不够 z 个。多出来的这一层二分是 O(log V)，V = 10⁸。

操作 3（改值）是外层走一条根到叶的路径，路径上每个节点先删旧值再加新值。

void update(int jobi, int jobv, int l, int r, int i) {
        innerRemove(i, arr[jobi]);
        innerAdd(i, jobv);
        if (l < r) {
            int mid = (l + r) >> 1;
            if (jobi <= mid) {
                update(jobi, jobv, l, mid, i << 1);
            } else {
                update(jobi, jobv, mid + 1, r, i << 1 | 1);
            }
        }
    }
int small(int jobl, int jobr, int jobv, int l, int r, int i) {
        if (jobl <= l && r <= jobr) {
            return treeSmall(root[i], jobv);
        }
        int mid = (l + r) >> 1;
        int ans = 0;
        if (jobl <= mid) {
            ans += small(jobl, jobr, jobv, l, mid, i << 1);
        }
        if (jobr > mid) {
            ans += small(jobl, jobr, jobv, mid + 1, r, i << 1 | 1);
        }
        return ans;
    }

    int number(int jobl, int jobr, int jobk) {
        int l = 0, r = 100000000, mid, ans = 0;
        while (l <= r) {
            mid = (l + r) >> 1;
            if (small(jobl, jobr, mid + 1, 1, n, 1) + 1 > jobk) {
                ans = mid;
                r = mid - 1;
            } else {
                l = mid + 1;
            }
        }
        return ans;
    }

number 里的二分就是那多出来的一层：small(jobl, jobr, mid + 1) + 1 > jobk 判断的是「小于等于 mid 的个数不少于 k」，取满足条件的最小 mid。treeSmall 数的是严格小于，所以传 mid + 1。

二、题目4：树状数组套开点线段树

内层从平衡树换成权值线段树之后，「第 z 名」可以在内层直接下潜，不用再二分答案。关键变化在外层：树状数组的每个 root[i] 管的是 (i − lowbit(i), i] 这一小段，查询 [l, r] 变成 prefix(r) − prefix(l − 1)。

真正省事的地方在查询。把 prefix(r) 的 O(log n) 棵树和 prefix(l − 1) 的 O(log n) 棵树一起收集进数组，然后让它们同时下潜：每一层，leftsum 是所有「加树」的左儿子之和减去所有「减树」的左儿子之和，拿它和 k 比一次，然后所有指针一起左移或右移。

这就是代码里 addTree 和 minusTree 两个数组的作用，它们保存的是「当前这一层，各自走到哪个节点」。

int innerAdd(int jobi, int jobv, int l, int r, int i) {
        if (i == 0) {
            i = ++cntt;
        }
        if (l == r) {
            sum[i] += jobv;
        } else {
            int mid = (l + r) / 2;
            if (jobi <= mid) {
                ls[i] = innerAdd(jobi, jobv, l, mid, ls[i]);
            } else {
                rs[i] = innerAdd(jobi, jobv, mid + 1, r, rs[i]);
            }
            sum[i] = sum[ls[i]] + sum[rs[i]];
        }
        return i;
    }

    void add(int i, int cnt) {
        for (int j = i; j <= n; j += lowbit(j)) {
            root[j] = innerAdd(arr[i], cnt, 1, s, root[j]);
        }
    }
int number(int l, int r, int k) {
        cntadd = cntminus = 0;
        for (int i = r; i > 0; i -= lowbit(i)) {
            addTree[++cntadd] = root[i];
        }
        for (int i = l - 1; i > 0; i -= lowbit(i)) {
            minusTree[++cntminus] = root[i];
        }
        return sorted[innerQuery(k, 1, s)];
    }


    int innerQuery(int jobk, int l, int r) {
        if (l == r) {
            return l;
        }
        int mid = (l + r) / 2;
        int leftsum = 0;
        for (int i = 1; i <= cntadd; i++) {
            leftsum += sum[ls[addTree[i]]];
        }
        for (int i = 1; i <= cntminus; i++) {
            leftsum -= sum[ls[minusTree[i]]];
        }
        if (jobk <= leftsum) {
            for (int i = 1; i <= cntadd; i++) {
                addTree[i] = ls[addTree[i]];
            }
            for (int i = 1; i <= cntminus; i++) {
                minusTree[i] = ls[minusTree[i]];
            }
            return innerQuery(jobk, l, mid);
        } else {
            for (int i = 1; i <= cntadd; i++) {
                addTree[i] = rs[addTree[i]];
            }
            for (int i = 1; i <= cntminus; i++) {
                minusTree[i] = rs[minusTree[i]];
            }
            return innerQuery(jobk - leftsum, mid + 1, r);
        }
    }

innerQuery 一次只处理一层，指针的移动是就地改 addTree[i] 和 minusTree[i]。innerSmall 是同一个套路，只是改成「边下潜边累加左边的计数」。

前驱和后继不用单独写：前驱就是「小于 z 的个数」对应的那个名次，后继就是「小于等于 z 的个数加一」对应的名次，都转成了 number。post 里那句 if (v == s) return INF 是因为 v 已经是离散化后的下标，等于 s 说明 z 就是最大值。

四、题目5：动态排名

给定一个长度为 n 的数组，m 次操作：操作 Q x y z 查询 [x, y] 中排第 z 名的数字；操作 C x y 把 x 位置的数字改成 y。n、m ≤ 10⁵，值永远在 [0, 10⁹] 内。测试链接：P2617。

这就是题3 和题4 的阉割版：只剩「第 z 名」和「改值」两种操作，范围更大。结构一字不改，还是树状数组套开点线段树。

唯一的差别在离散化要收哪些值。题4 有前驱和后继，查询里给的数字要参与比较，所以所有操作 1、4、5 的 z 都要收进 sorted；题5 只收初始数组和每条 C 操作的新值就够了。

还有一处要留意：题5 的操作 Q 给的 z 是名次，直接用；题4 的操作 1、4、5 给的 z 是值，要先 kth 成离散下标再传进去。这两个 z 的含义不一样，写的时候容易混。

复杂度分析

外层换掉之后，操作 2 少了一整层二分，这是两种写法最主要的区别。

项目时间空间
题3 操作 1 / 3 / 4 / 5O(log n · log m)O((n + m) log n)
题3 操作 2（第 z 名）O(log n · log m · log V)同上
题4 全部五种操作O(log n · log s)O((n + m) log n · log s)
题5 单次操作O(log n · log s)O((n + m) log n · log s)
离散化O((n + m) log(n + m))O(n + m)

题3 的 log V ≈ 27，是实打实多出来的一层。空间上，题4 的每个元素要进入 O(log n) 棵权值线段树、每棵占 O(log s) 个节点，所以开点数组要开到 (n + m) · log n · log s 量级，代码里 MAXN * 160 就是这么估的。题5 的 n、m 到 10⁵，开的是 MAXN * 130。

最后

两种外层的取舍清楚了：线段树外层能塞任意内层结构（包括平衡树），但区间要拆成两倍的节点；树状数组外层只跳 O(log n) 棵、常数更小，代价是内层必须是能做加减的权值线段树，而且前缀差分天然只适合「可减」的信息。接下来两道题都是后者，一道把信息换成逆序对的增量，一道把下标从数组换成树的 dfn 序。
