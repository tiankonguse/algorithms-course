区间 dp：在范围里找划分点

区间 dp 里步子比较大的一种做法：在区间里挑一个位置把它切开，左右两边各自算完再拼起来。代价是每格要多枚举一层划分点，复杂度从 O(n²) 涨到 O(n³)。

零、划分点型的骨架

状态还是 f(l, r)，但含义从「把这一段的字符变成回文」换成了「把这一段整体处理完」。转移写成：

f(l, r) = min (或 max) over m of ( f(l, m) + f(m, r) + 分界处那一步的代价 )

这里的 m 是一个「在这一段上发生的事情」的落点：某个三角形以它为顶点、某一刀切在它那里。它把 [l, r] 拆成两块互不重叠的子问题，两块都解决完，这一段就解决完了。

和两端点讨论型相比有两个固定差别：

  1. 边界不一样。长度不到 2 的区间没有划分点可选，直接返回 0。
  2. 每格多一层循环。枚举 m 是 O(n)，总的时间复杂度就是 O(n³)。

填表顺序照旧：l 从大到小、r 从小到大。因为两个子区间都比 [l, r] 短，轮到自己时它们已经填好了。

一、多边形三角剖分的最低得分

给一个凸 n 边形，每个顶点有一个值。要把它剖分成 n−2 个三角形（剖分的线只能连顶点，且不能交叉），每个三角形的分数是三个顶点值相乘，问所有三角形的分数之和最低能到多少。

[1, 2, 3] 只有一个三角形，分数 6；[3, 7, 4, 5] 是 144；[1, 3, 1, 4, 1, 5] 是 13。

状态：f(l, r) 表示顶点 l..r 这串点围成的多边形剖完的最低得分。

转移：看这条多边形的边 (l, r)。剖分出来的每个三角形要么贴着这条边，要么不贴；贴着它的那个三角形里，第三个顶点只能是 l+1 到 r−1 里的某一个。设它是 m，那么三角形 (l, m, r) 的分数是 arr[l] * arr[m] * arr[r]，剩下的部分正好是 l..m 和 m..r 两块多边形，各自独立。枚举 m 取最小的那个就行。

边界：r − l ≤ 1 时这点数不足三个，围不出三角形，返回 0。

拿 [1, 3, 1, 4, 1] 这个五边形试三种选法：第三个顶点取 1 得 10 分，取 2 得 8 分，取 3 得 11 分。同样一条边，选不同的顶点，价钱差得不少。

// 顶点 l..r 围成的凸多边形做三角剖分，最低得分
    int f(vector<int>& arr, int l, int r, vector<vector<int>>& dp) {
        if (dp[l][r] != -1) return dp[l][r];
        int ans = INT_MAX;
        if (l == r || l + 1 == r) {
            ans = 0;                                 // 少于三个顶点，剖不出三角形
        } else {
            for (int m = l + 1; m < r; m++) {        // 枚举 l、r、m 组成的那个三角形
                ans = min(ans, f(arr, l, m, dp) + f(arr, m, r, dp) + arr[l] * arr[m] * arr[r]);
            }
        }
        return dp[l][r] = ans;
    }

    int minScoreTriangulation(vector<int>& arr) {
        int n = arr.size();
        vector<vector<int>> dp(n, vector<int>(n, -1));
        return f(arr, 0, n - 1, dp);
    }

把记忆化改成严格位置依赖，注意外层循环从 n−3 开始：长度 0 和长度 1 的区间全是 0，不用填。

int minScoreTriangulation(vector<int>& arr) {
        int n = arr.size();
        vector<vector<int>> dp(n, vector<int>(n, 0));
        for (int l = n - 3; l >= 0; l--) {
            for (int r = l + 2; r < n; r++) {
                dp[l][r] = INT_MAX;
                for (int m = l + 1; m < r; m++) {
                    dp[l][r] = min(dp[l][r], dp[l][m] + dp[m][r] + arr[l] * arr[m] * arr[r]);
                }
            }
        }
        return dp[0][n - 1];
    }

这道题的每格枚举量是 r − l − 1，加起来正好是图上两个子问题之间的分界线数量。n = 50 时状态 1176 个、枚举合计 19600 次，跑完 0.03 ms；n = 300 时 3.76 ms。

剖分的方案数本身是卡塔兰数 Catalan(n−2)：n=8 有 132 种，n=14 有 208012 种，n=50 已经到 1027 量级。枚举方案这条路走不通，得让子问题的答案被复用。

写错的地方也很集中。内层左边那段如果写成 dp[l][m−1]（把 m 从左边那段里挖掉），随机数组上 88% 会算错。这个错误的根源是没想清楚两块子问题的边界：l..m 和 m..r 共享顶点 m，它不是被消耗掉的。

二、切棍子的最小成本

一根长度 n 的棍子，cuts 里列着所有要切开的位置。切的顺序随意，但每次切都要付钱，价钱就是当前这一段的长度。问总成本最低是多少。

样例：n = 7, cuts = [1, 3, 4, 5] 返回 16；n = 9, cuts = [5, 6, 1, 4, 2] 返回 22。注意第二个样例的 cuts 是乱的。

第一步是整理数据：把 cuts 升序排好，再在两头各补一个位置，0 和 n。整理完的数组记作 arr，下标 1..m 是要切的位置，arr[0] = 0、arr[m+1] = n 是这根棍子的两端。

补这两个哨兵的好处是：任何一段的两端都变成了 arr 里相邻的两个下标，算长度不用再做特判。[l, r] 这些切点所在的那一段，长度就是 arr[r+1] − arr[l−1]。

状态：f(l, r) 表示把 arr[l..r] 这些位置全部切完，最少花多少。它的两端边界是 arr[l−1] 和 arr[r+1]。

转移：这一段里先切哪一刀？设切在 k，l ≤ k ≤ r。这一刀要付的钱就是整段的长度 arr[r+1] − arr[l−1]；切完分成两段，左边要切的位置是 arr[l..k−1]，右边是 arr[k+1..r]，两段互不影响。于是

f(l, r) = min over k ( f(l, k−1) + f(k+1, r) ) + arr[r+1] − arr[l−1]

k 在这里是「这一段的头一刀」。选它换来的好处是：切完之后左右两段真的是两段，子问题独立。

边界：l > r 表示这一段没有要切的位置，返回 0；l == r 表示只有一刀，直接返回这段的长度。

// arr[0]=0、arr[m+1]=n 是棍子的两个端点，arr[1..m] 是要切的位置（已排序）
    // 把 arr[l..r] 这些位置全部切完，最少花多少
    int f(vector<int>& arr, int l, int r, vector<vector<int>>& dp) {
        if (l > r) return 0;                         // 没有要切的
        if (l == r) return arr[r + 1] - arr[l - 1];  // 只有一刀，花这一段的长
        if (dp[l][r] != -1) return dp[l][r];
        int ans = INT_MAX;
        for (int k = l; k <= r; k++) {               // 枚举这一刀切在哪
            ans = min(ans, f(arr, l, k - 1, dp) + f(arr, k + 1, r, dp));
        }
        return dp[l][r] = ans + arr[r + 1] - arr[l - 1];
    }

    int minCost(int n, vector<int> cuts) {
        int m = cuts.size();
        sort(cuts.begin(), cuts.end());
        vector<int> arr(m + 2);
        arr[0] = 0;
        for (int i = 1; i <= m; i++) arr[i] = cuts[i - 1];
        arr[m + 1] = n;
        vector<vector<int>> dp(m + 2, vector<int>(m + 2, -1));
        return f(arr, 1, m, dp);
    }
int minCost(int n, vector<int> cuts) {
        int m = cuts.size();
        sort(cuts.begin(), cuts.end());
        vector<int> arr(m + 2);
        arr[0] = 0;
        for (int i = 1; i <= m; i++) arr[i] = cuts[i - 1];
        arr[m + 1] = n;
        vector<vector<int>> dp(m + 2, vector<int>(m + 2, 0));
        for (int i = 1; i <= m; i++) {
            dp[i][i] = arr[i + 1] - arr[i - 1];      // 只切一刀，花这整段
        }
        for (int l = m - 1; l >= 1; l--) {
            for (int r = l + 1; r <= m; r++) {
                int next = INT_MAX;
                for (int k = l; k <= r; k++) next = min(next, dp[l][k - 1] + dp[k + 1][r]);
                dp[l][r] = arr[r + 1] - arr[l - 1] + next;
            }
        }
        return dp[1][m];
    }

严格版有一个小坑：dp[l][k−1] 在 k == l 时下标是 l−1，dp[k+1][r] 在 k == r 时下标是 r+1，两个都落在有效范围之外。它们恰好对应「这边没有切点」的情况，值应当是 0，而整张表本来就是 0 初始化的，所以不用特判。

错法上，漏掉 arr[r+1] − arr[l−1] 这一项是 100% 出错，答案会小一大截，随便一组数据都能看出来。更隐蔽的是忘了排序：第一版记忆化里 arr[r+1] − arr[l−1] 会算出负数，随机数据上 81.31% 出错。列好的 cuts 是乱的，一上手就得排。

整理完之后 m（切点个数）最多 100，n 到 106 也不影响复杂度。n = 106、m = 100 跑完 0.07 ms。

三、两个问题并排看

把两题的骨架摊开，差别只在「m 代表什么」和「两块子问题怎么划」。

项目多边形三角剖分切棍子
区间含义顶点 l..r 围成的多边形切点 l..r 所在的那一段
m 是什么与边 (l, r) 组成三角形的第三个顶点这一段里的头一刀
两块子问题[l, m] 与 [m, r]，共享顶点 m[l, k−1] 与 [k+1, r]，不共享
拼起来的代价arr[l] · arr[m] · arr[r]arr[r+1] − arr[l−1]
边界r − l ≤ 1 返回 0l > r 返回 0，l == r 返回段长

共享和不共享这个差别直接决定边界怎么写。三角剖分里 m 同时属于两块，所以两块都至少要 m 这一个点，区间长度下限是 2；切棍子里 k 被这一刀用掉了，两边都不含它，所以允许 l > r 这种空区间。

四、复杂度分析

量规模说明
状态数O(n²)三角剖分 n = 50 → 1176 个；切棍子 m = 100 → 5050 个
单格代价O(n)枚举第三个顶点 / 枚举头一刀
时间O(n³)50³ 量级毫秒级，300³ 已到 3.76 ms
空间O(n²)两道题都没做压缩，n 的规模本来就小
暴力O(Catalan(n)) 或 O(m!)三角剖分 n=14 有 208012 种；切棍子 m=10 有 3628800 种顺序

这类题不需要空间压缩：枚举划分点让每个格子都依赖整行整列，压掉一维之后斜向的依赖补不回来，硬压反而绕。约束只有 50 和 100，二维表够用。

五、总结

  1. 划分类区间 dp 的固定形状是「枚举分界点 + 两块子问题 + 分界处的代价」，外层 l 倒序、内层 r 正序。
  2. 分界点该不该被两块子问题共享，决定了边界条件，也决定了枚举范围写 l+1..r−1 还是 l..r。
  3. 多一层枚举换来的是 O(n³)，所以这类题的数据规模通常只有几十到几百。看到约束在这个量级，就该往这个方向上想。

下一类把「分界点」用得再刁一些：它不再是某个位置，而是「最后完成的那一步」，顺着讲的顺序反而写不出来。
