树状数组

每个 c[i] 只管 lowbit(i) 那么长的一段。查询沿 i −= lowbit(i) 往下跳，修改沿 i += lowbit(i) 往上跳，两边都是 O(log n)。

零、背景

分块那一节讲的是同一个问题：数组改一改、查一查，两种操作混着来。分块把查询压到 O(√n)，已经能用。

树状数组是另一条路。它借助二进制里的 lowbit，把查询和修改都压到 O(log n)，代码比线段树短得多，是这类题最常见的写法。

下面还是从那个问题出发，把树状数组是怎么设计的推一遍。

一、问题

长度为 n 的数组 a，支持两种操作。

  • 查询：求区间 [l, r] 的和。
  • 修改：把 a[i] 加上 delta。

两种操作交替出现，一共 m 次。

举例还是这一组数据，n = 16。

a = [3, 1, 4, 1, 5, 9, 2, 6, 5, 3, 5, 8, 9, 7, 9, 3]

树状数组的下标一律从 1 开始。这不是习惯问题，lowbit(0) 等于 0，循环会卡死，必须把 0 让出来。

二、朴素做法

第一种写法，查询时从 l 一路加到 r。查询 O(n)，修改 O(1)。

第二种写法，预处理出前缀和 prefix[i] = a[1] + … + a[i]，区间和就是一次减法。

区间和 [l, r] = prefix[r] - prefix[l-1]

查询变成 O(1)，代价落在修改上。a[i] 一变，prefix[i] 到 prefix[n] 全都要跟着改，最坏改 n 个，是 O(n)。

可以发现，两种写法各占一头，一个查询慢，一个修改慢。m 次操作混着来的时候，总有一个方向拖后腿。

那有没有两头都不慢的做法？有。思路是别让每个位置都从头到尾存一遍，改成每个位置只管一段，而且管得有规律。这就是树状数组。

三、lowbit

规律藏在二进制里。先定义 lowbit(x)，表示 x 的二进制里最低位那个 1 所代表的数。

x = 6 = 110₂，最低位的 1 在右起第二位，代表 2，所以 lowbit(6) = 2。x = 12 = 1100₂，lowbit(12) = 4。x = 8 = 1000₂，lowbit(8) = 8。奇数末位一定是 1，所以奇数的 lowbit 都是 1。

代码一行。

int lowbit(int x) { return x & (-x); }

这里的 -x 用的是计算机里的补码，x & (-x) 恰好只把最低位的 1 留下，其余位全清零。可以先把这个公式当成黑盒来用。

四、c[i] 管一段

树状数组另外开一个数组 c，规定 c[i] 存的是 a[i - lowbit(i) + 1] 到 a[i] 这一段的和，长度正好是 lowbit(i)。

例如 lowbit(6) = 2，c[6] = a[5] + a[6]；lowbit(8) = 8，c[8] = a[1] + … + a[8]。把这 16 行铺开画出来是这样。

这样安排之后，可以发现一件有意思的事：c[i] 这一段往左接上 c[i − lowbit(i)]，正好连成更长的一段，不多也不少。后面查询能一路往下减，靠的就是这个。

每个 c[i] 恰好向上贡献给 c[i + lowbit(i)]，整张结构像一棵倒挂的树，所以叫树状数组。下面把这棵树画出来，点一个节点就能看到改 a[i] 时要沿着哪条路向上走。

五、前缀和查询

要求 prefix(i) = a[1] + … + a[i]，从 i 开始，累加 c[i]，然后 i -= lowbit(i)，一直做到 i 变成 0。

为什么对？c[i] 管的正是以 i 结尾、长度 lowbit(i) 的那一段，加完它，剩下没算的就只剩 [1, i − lowbit(i)]，规模一下就小了。接着又是一个同样的问题。

以 i = 13 为例，跳三次就结束。

演示 ③　前缀和 prefix(i)：向下减 lowbit
13
要算的前缀 a[1..i] 累加到的 c 节点

有了前缀和，区间和就是两次查询相减。

int rangeSum(int l, int r) { return query(r) - query(l - 1); }

六、单点修改

改 a[i] 时，凡是管到了 i 的 c 都要跟着动。

规律和查询正好相反，从 i 开始每次 i += lowbit(i)，直到超过 n，这条链上的 c 全部加上 delta。以 i = 5 为例，受影响的是这四行。

七、代码

#include <bits/stdc++.h>
using namespace std;

const int N = 16;
int a[N + 1] = {0, 3,1,4,1,5,9,2,6,5,3,5,8,9,7,9,3};  // 下标从 1 开始
int n = N;
int c[N + 1];                      // 树状数组

int lowbit(int x) {                // 最低位的 1
    return x & (-x);
}

void update(int i, int delta) {   // 单点修改：a[i] += delta
    while (i <= n) {
        c[i] += delta;
        i += lowbit(i);
    }
}

int query(int i) {                 // 前缀和：a[1]+…+a[i]
    int s = 0;
    while (i > 0) {
        s += c[i];
        i -= lowbit(i);
    }
    return s;
}

int rangeSum(int l, int r) {     // 区间和 [l, r]
    return query(r) - query(l - 1);
}

void build() {                      // 预处理：n 次单点修改
    for (int i = 1; i <= n; i++) update(i, a[i]);
}

int main() {
    build();
    cout << rangeSum(1, 8) << endl;  // 31
    cout << query(13) << endl;        // 61
    update(5, -2);                  // a[5]：5 → 3
    cout << rangeSum(1, 8) << endl;  // 29
    return 0;
}

八、复杂度分析

查询每步 i -= lowbit(i)，相当于把 i 的二进制里最低位的 1 消掉，i 里最多 log n 个 1，所以最多跳 log n 次。

修改每步 i += lowbit(i)，进位之后 i 至少翻一倍，最多跳 log n 次就超过 n。

操作时间复杂度
预处理 buildO(n log n)（n 次 update，也可优化到 O(n)）
前缀和 queryO(log n)
区间和（两次前缀和）O(log n)
单点修改 updateO(log n)
m 次操作总计O((n + m) log n)

空间上只多开一个 c 数组，大小和 a 一样，额外空间 O(n)。

三种做法放一起看：朴素查询 O(n)，分块 O(√n)，树状数组 O(log n)。n 越大差距越明显，n = 10⁵ 时 log n 大概 17，√n 是 316。

九、最后

树状数组能成立，靠的是区间和可以相减。prefix[r] − prefix[l−1] 这一步是减法，如果把求和换成求区间最大值，这一步就做不了，只能改成线段树。

另一个边界是它只管单点修改。要整段区间一起加，得配一个差分，那是下一步的内容。
