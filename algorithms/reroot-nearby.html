换根 dp：转移一整套桶，距离 k 内的权值和

前面几页换根时扣掉的都是一个数。这一页要按距离分桶：每个点存一条长度为 k+1 的数组，第 i 格是「距离正好 i」的权值和，换根时整条数组一起递过去。递的过程里还得做一次容斥，否则中间那一段会被数两遍。

零、背景

换根的转移式永远长成「父亲的答案减去这一支的贡献，再补上新的贡献」。当答案是「某个距离上的点权和」这种按距离切开的量时，一次换根会影响所有距离，所以转移的单位从标量变成了整条数组。

换成数组之后，麻烦的地方不再是取 min 或取 max，而是重复计数：父亲那一层的结果里，有一部分点本来就是从自己这边数出去的。

一、问题

洛谷 P3047 Nearby Cows G。n 个点的树，每个点有一个权值。对每个点 u，求树上所有与 u 距离不超过 k 的点的权值之和，一共输出 n 个答案。n 到 10⁵，k 很小，不超过 20。

k 不大这个条件很关键，它的意思是可以把「距离」当成数组下标。

二、第一趟：按距离分桶

固定 1 号做根，记 sum[u][i] 为「u 的子树内，与 u 距离正好 i 的点的权值和」。第 0 格就是自己，更高的格子由儿子的低一格搬过来，因为从 u 到儿子子树里的点，都要先走一步到儿子。

sum[u][0] = val[u];
for (j = 1; j <= k; j++) sum[u][j] += sum[v][j - 1];   // v 是 u 的儿子

图 1 上半是那棵七个点的树和点权，下半是以 1 为根时每个点的整条桶。叶子点的桶只有第 0 格有值，往上是空的。

三、第二趟：换根要减掉重复的一段

记 dp[u][i] 为「u 做根时，整棵树上与 u 距离正好 i 的点的权值和」。现在要用 u 的答案推出儿子 v 的答案，按点在哪一侧分两类。

第一类在 v 的原子树里，从 v 数起来距离正好 i，这就是 sum[v][i]。第二类在 v 的子树外，从 v 走到它必须先跨过 v 到 u 这条边，所以它在 u 眼里只有 i − 1 步远，这批点都在 dp[u][i − 1] 里。

两类直接相加会多算。多出来的是 dp[u][i − 1] 里那批「本来就在 v 子树内」的点：它们在 u 眼里是 i − 1 步，在 v 眼里却只有 i − 2 步，跟第一类要的完全不是同一批。把这批挑出来减掉，它正是 sum[v][i − 2]。

于是换根式比前面几页多出一个减法项：

dp[u][0] = sum[u][0];
dp[u][1] = sum[u][1] + dp[v][0];
dp[u][i] = sum[u][i] + dp[v][i - 1] - sum[u][i - 2];     // i >= 2

第 0 格和第 1 格单独写，是因为 i − 2 会取到负数。图 2 用一个具体例子把减法项的两边摆出来。

四、把桶加起来就是答案

题目要的是「不超过 k」，把每个点那条桶从 0 加到 k 就行。

for (i = 0; i <= k; i++) ans[u] += dp[u][i];

五、代码

// sum[u][i] : 以 1 为根时，u 的子树内与 u 距离恰好 i 的点权和
    // dp[u][i]  : 以 u 做根时，整棵树上与 u 距离恰好 i 的点权和
    void dfs1(int u, int f){
        sum[u][0] = val[u];
        for (int e = head[u], v; e != 0; e = nxt[e]){
            v = to[e];
            if (v != f){
                dfs1(v, u);
                for (int j = 1; j <= k; j++) sum[u][j] += sum[v][j - 1];
            }
        }
    }

    void dfs2(int u, int f){
        for (int e = head[u], v; e != 0; e = nxt[e]){
            v = to[e];
            if (v != f){
                dp[v][0] = sum[v][0];                                        // 自己
                dp[v][1] = sum[v][1] + dp[u][0];                             // 儿子一侧 + u 自己
                for (int i = 2; i <= k; i++){
                    // dp[u][i-1] 里混着「先回到 v 再往外」的那些点，正好是 sum[v][i-2]，减掉
                    dp[v][i] = sum[v][i] + dp[u][i - 1] - sum[v][i - 2];
                }
                dfs2(v, u);
            }
        }
    }

六、桶台

下面按第二趟的顺序逐个点换根，面板里逐项列出每一位是怎么算出来的，减法那一项单独标出来。

桶台：点「下一步」看一整条桶怎么递过去

圈里的数字是点权，角上是该点的答案（桶的各项之和）。橙圈是当前做根的点，绿边是正在换的那条边。

这张图解释了为什么题目要限定 k 很小。桶的个数是 n(k+1)，随机树上 k = 20 时每个桶平均要装几百万个点，靠桶之间的加减才算得动；这也是这道题只能做「距离不超过 k」而不能做「任意距离」的原因。链和星是两端，链上 k 再大也只是一个 O(k) 的窗口，星上 k ≥ 2 就退化成整棵树求和。

七、复杂度分析

环节时间空间
第一趟分桶（dfs1）O(nk)O(nk)
第二趟换根（dfs2）O(nk)
每个点把桶求和O(nk)
合计O(nk)
每个点单独搜一遍（朴素）O(n²)O(n)

空间按题目上限算。n = 10⁵、k = 20 时 sum 与 dp 各 100001 × 21 个 int，单份 8.01MB，两份合计 16.02MB；k = 10 时合计 8.39MB，k = 5 时 4.58MB。答案本身也可能顶到 int 上界：n 个点的权值之和，权值到 10³ 时就是 10⁸ 量级，安全起见答案开 long long。

实测：n = 10⁵、k = 20 时换根全程 10.00ms。朴素做法对每个点各做一次截断到 k 的 bfs，同一份数据要 54357.74ms，五十多秒，差了五千多倍；而且它的复杂度随树形崩得更快，随机树上 k 一大，一次 bfs 扫到的点就是指数级的。

错法抓取率：八千棵小树上，把减法项漏掉的写法有 74.44% 的树答案会变；反过来把第 0、1 格也硬套通式、把下标 −1 和 −2 当成 0，抓到的树是 0 棵，因为这两格本来就该走那条特判，写通式只是绕了一圈。

八、总结

要点三条。其一，换根时「扣掉这一支」这件事在数组上的样子是「扣掉被重复计入的那一段下标」，容斥的下标偏移由「绕路多走了几步」决定：这里绕 u 一步，所以是 i − 2。其二，桶的形状决定了复杂度里的那个 k，题目给出的「k 不大」就是让 O(nk) 成立的许可证。其三，第 0 格和第 1 格几乎总是要单独写，因为它们的偏移量会取到负数，硬套通式要么越界要么静默读 0。

最后一道题会把「留第二大」搬上台面：换根时最长的那条链如果在正在递的这一支里，就得换用次长的。

九、最后

最容易写错的是下标。写 sum[u][i - 2] 的时候要连续问自己两遍：这个 u 是谁、这个 i 是谁。第一趟里 sum[u] 的 u 是当前节点，第二趟里它代表的是「新根 u 的子树」，跟外层那个正在做父亲的 u 是同一个变量名、同一个含义，但对应的点已经变了。对拍的时候把 k 压到 2 到 4，下标错一格的后果会被立刻放大出来。
