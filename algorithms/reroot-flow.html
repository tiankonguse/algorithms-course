换根 dp：边上有容量，被 min 夹住的那一份

前面两道题换根时扣掉的那一份，都是「整棵子树的贡献」，减一个数就完事。这一页的边上带容量，一份贡献要先和这条边取 min 才会真的流出去，于是换根时用来扣减的那一项也得跟着套上同一个 min。式子只多一层括号，但对错的分界线就在这层括号上。

零、背景

深度和那道题的转移是 dp[v] = dp[u] − sz[v] + (n − sz[v])，扣掉的那一份恰好是 sz[v]，因为它就是 v 那一支对整棵树贡献的全部。染色收益那道题同理，扣掉的就是子树大小。

一旦边上有容量，某一支对父亲的贡献就不再是「这一支自己能出多少」，而是「这一支能出多少」和「这条边能吞多少」里小的那个。换根时要从父亲的答案里扣掉这一支，必须扣 min 之后的结果，扣原始值就会把那条边的余量漏在里面。

一、问题

P3585 Accumulation Degree。n 个点的树，每条边有一个容量，代表这条边上最多能流过的水量。选一个点当源点，水从源点出发沿着边一直流到所有叶子（叶子指树上度数为 1 的点），问源点选在哪里能让总流量最大。多组测试数据，n 到 2×10⁵。

源点自己也是度数为 1 的点时不算叶子，它就是出水口。当 n = 1 时答案是 0。

二、先把源点定在 1 号

记 flow[u] 为「以 1 为根时，从 u 流进 u 子树内所有叶子的最大流量」。u 的每一支都是独立的，合起来直接相加，所以只看单个儿子 v：

v 是叶子，它本身就是出水口，能吃多少只看这条边，贡献是整条边的容量 w。v 不是叶子，它自己内部还要往下分，能出的量是 flow[v]，但这条边只允许过 w，所以贡献是两者的最小值。

if (degree[v] == 1) flow[u] += w;                 // v 是叶子，整条边都能吃
else                flow[u] += min(flow[v], w);    // v 还要往下分，两边取小

后序位置合并，一趟 dfs 收完，flow[1] 就是 1 号做源点时的答案。图 1 是七个点的带权树，边上的数字是容量，点旁的数字是 flow。

三、换根：把 u 拆成两半

把源点从 u 挪到相邻的 v，v 的答案由两部分拼成：v 原来那一支（也就是 flow[v]），加上从 u 那一侧流过来的量。后面这部分要算清楚。

以 u 为源点时，u 的答案是所有支路的和，其中 v 这一支贡献的是 min(flow[v], w)。把它减掉，剩下的就是 u 在去掉 v 之后还能出多少水，记作 uOut。这个量再过边 (u, v)，所以真正流到 v 的是 min(uOut, w)。合起来

uOut = dp[u] - min(flow[v], w);
dp[v] = flow[v] + min(uOut, w);

还有一处特判：如果 u 自己是叶子，说明 u 只有 v 这一个邻居，去掉 v 之后 u 就是纯出水口，能出的量没有上限。这时 dp[v] = flow[v] + w，直接加上整条边的容量。

四、叶子点的 dp 值不是真值

上面那个式子里有个不显眼的缺口。v 是叶子时 flow[v] 是 0，于是 uOut = dp[u] − 0，那条边的容量一点没扣掉，算出来的 dp[v] 偏大。拿图 1 那棵树看，6 号是叶子，以 3 为源点时的答案是 10，程序给 6 号算出的 dp[6] = 10 − 0 = 10 再和 6 取 min 得 6；而 6 号真的做源点时，水要过边 (3, 6)，先被这条边的容量卡住，真实值是 min(10 − 6, 6) = 4。

这个偏大不会影响最终答案，理由是叶子永远比不过它的父亲：叶子点的值最多是那条边的容量 w，而它父亲当源点时的答案里必含这一支的 w，所以父亲一定不小于它。最大值要么在非叶子点上取到，要么和某个叶子并列，两种情况都不会被这个偏差带跑。

实测两万棵随机树（n 从 3 到 40，四种树形，边权 1 到 20）：逐个点比对真值，共 433348 个点，偏大的有 57764 个，占 13.33%，而且全部是叶子点，非叶子点一个不差；把这批树的最大值单独比对，算错的是 0 棵。所以判断题交这个写法没问题，但要是题目问「打印每个点做源点的答案」，就得把判断补上。

// 想让每个点的 dp 都是真值，把「v 是不是叶子」的判断搬进 dfs2
    // v 是叶子时：它这一支对 u 的贡献是整条边的容量 w，不是 min(flow[v], w)
    //            而且 v 做根之后自己不再当叶子吃水，不再累加 flow[v]
    void dfs2(int u, int f){
        for (int e = head[u], v, w; e != 0; e = nxt[e]){
            v = to[e]; w = weight[e];
            if (v != f){
                if (degree[u] == 1){
                    dp[v] = flow[v] + w;
                } else {
                    long long c = (degree[v] == 1) ? (long long)w : min(flow[v], (long long)w);
                    long long uOut = dp[u] - c;
                    dp[v] = (degree[v] == 1) ? min(uOut, (long long)w)
                                             : flow[v] + min(uOut, (long long)w);
                }
                dfs2(v, u);
            }
        }
    }

五、模板代码

// degree[u] : 与 u 相连的边数
    // flow[u]   : 以 1 为根时，从 u 流进 u 子树内所有叶子的最大流量
    // dp[u]     : 以 u 做根时，流到整棵树所有叶子的最大流量
    void dfs1(int u, int f){
        flow[u] = 0;
        for (int e = head[u], v; e != 0; e = nxt[e]){
            v = to[e];
            if (v != f) dfs1(v, u);
        }
        for (int e = head[u], v, w; e != 0; e = nxt[e]){
            v = to[e]; w = weight[e];
            if (v != f){
                if (degree[v] == 1) flow[u] += w;                  // v 是叶子，能吃多少全看这条边
                else flow[u] += min(flow[v], (long long)w);        // v 还能往下分，两边取小
            }
        }
    }

    void dfs2(int u, int f){
        for (int e = head[u], v, w; e != 0; e = nxt[e]){
            v = to[e]; w = weight[e];
            if (v != f){
                if (degree[u] == 1){
                    dp[v] = flow[v] + w;                           // 换根后 u 成了叶子
                } else {
                    long long uOut = dp[u] - min(flow[v], (long long)w);   // 先扣掉往 v 走的那一支
                    dp[v] = flow[v] + min(uOut, (long long)w);             // 剩下的从 u 这一侧流过来
                }
                dfs2(v, u);
            }
        }
    }

六、源点台

下面把源点一路挪下去。当前这一支被 min 卡住的时候，式子会显示实际取到的是哪一边；挪到叶子点上时，面板会额外报出真实值。

源点台：点「下一步」看流量怎么被 min 截住

边上的数字是容量，角上是该点当前算出的流量。橙圈是当前源点，绿边是正在换的那条边。叶子点会额外标出真实值。

差别这么大是因为「源头该放在哪」跟树的形状直接相关。链上水从一端出发，一路被每条边卡一遍，最优是把源点放在正中间，两头各走一半，取到的是两条路径容量的较小值；固定在 1 号就只剩下最细的那条边说了算。星则相反，中心一出去就是所有叶子，每条边都完整地贡献，换到叶子上反而只剩一条边。

七、复杂度分析

环节时间空间
第一趟汇总（dfs1）O(n)O(n)
第二趟换根（dfs2）O(n)
扫最大值O(n)
合计（T 组数据）O(T·n)
每个源点重算一遍（朴素）O(n²)O(n)

空间按 n = 2×10⁵ 算。head、degree、flow 各 n 个 int，nxt、to、weight 各 2n 个 int，dp 是 n 个 long long，合计约 3MB。数字都很小，但 n = 10⁶ 的链上第一趟的递归还是会爆栈，阈值和前面几页一样：本机 8MB 栈下约八万六千层。

实测：随机树 n = 10⁵ 换根全程 6.27ms，n = 2×10⁵ 是 8.30ms。朴素做法每个源点重跑一次 dfs，n = 2000 要 20.59ms，n = 4000 是 88.19ms，n = 8000 涨到 392.56ms，翻倍再翻倍，二次方特征很清楚；n = 2×10⁵ 时它要做 4×10¹⁰ 次操作，换根只做 4×10⁵ 次。

再看错法的抓取率。两万棵小树上，把 uOut 里的 min 漏掉写成 dp[u] − flow[v]，有 42.56% 的树答案会变；把「u 是不是叶子」的判断误写成 v，有 19.81% 的树答案会变。

八、总结

要点三条。其一，换根时的转移永远长成「父亲的答案减去这一支的贡献，再补上新的贡献」，边的容量会同时出现在这两处，所以两处都要套 min。其二，当某个方向是「不限量的出水口」时，一般都值得单独写成一条分支，硬塞进统一公式里容易把无穷大算成 0。其三，答案对不等于数据对。这道题只输出一个最大值，叶子上那些偏大的值时时刻刻挂着，却因为「叶子超不过父亲」这一条永远浮不上来；题目一改成输出每个点的答案，同一个写法立刻就错了。

下一道题的转移不再是「扣一个数」，而要一次性扣掉一整组数。

九、最后

最值得抄下来的一条是那个 degree[u] == 1 的特判。它出现的位置是 dfs2 而不是 dfs1，很容易在改写的时候被顺手挪到 dfs1 去，那样 u 是叶子的情形就漏了，n = 2 的数据会直接错。另外这道题是多组数据，每次都要把 head 清到 n + 1，只清到上次的 n 会在下一组更大的数据里读到脏边。
