滑动窗口进阶：环上与计数

窗口不只在「最长/最短」里打转。加油站把窗口放到环上、窗口长度固定为 n；「恰好 k 种」用两个「至多 k 种」相减；「每字符至少 k 次」要先枚举窗口里最多几种字符。三个方向各拆一道题。

零、背景

滑动窗口的骨架不变，变的是三件事：单调性怎么判、窗口信息记什么、答案怎么统计。这一页的三道题分别演示「窗口在环上」「答案靠两个单调函数相减」「窗口种类数要先枚举」。

一、题 4：加油站（LeetCode 134）

环上有 n 个加油站，从 i 开到 i+1 消耗 cost[i]，油箱无限。问从哪个站出发能绕一圈回来，有解保证唯一，否则返回 -1。

把每个站的「余量」gas[i] - cost[i] 算出来，问题变成：找一个长度为 n 的连续段，任意前缀和都 ≥ 0。环形数组用 r % n 展开成 2n 长，窗口 [l, r) 左闭右开，r 每步检查「加上 r 的余量还 ≥ 0 就进」，窗口长度到 n 就返回 l。

关键优化在失败处理：l 出发后开到 r 走不动了（sum 变负），下一个起点不是 l+1，而是直接跳 r+1。理由是：从 l 出发能走到 r，说明 [l, r) 内每个前缀和都 ≥ 0，那从 l+1 出发到 r 的累计值只会更小（少了 l 的余量），到 r 时仍然走不动。中间所有起点都是白试。

实测 20000 组随机 gas/cost，跳 r+1 的写法与暴力逐个起点模拟结果完全一致。每个 r 位置最多被进一次窗口，总 O(n)。n=1e6 随机数据 1.20ms。

一个隐蔽的错法：进入条件 `sum + 余量 >= 0` 写成 `> 0`，恰好余量 0 时不肯进站，随机数据 6.49% 算错。等于 0 的边界最容易在这类「环」题里写错。

二、题 6：K 个不同整数的子数组（LeetCode 992）

数「恰好 k 种不同整数」的子数组。直接维护「恰好 k 种」的窗口很别扭：窗口收缩一下种类就掉到 k-1，下一个 r 进来又可能涨回 k，边界极难伺候。

标准做法是拆成两个单调函数：f(k) 表示「至多 k 种不同整数」的子数组数。至多 k 有单调性：窗口种类超过 k 就收缩 l，收缩到 ≤ k 停止，这时以 r 结尾的子数组里 [l..r]、[l+1..r]、…、[r..r] 全都至多 k 种，共 r-l+1 个，ans += r-l+1。恰好 k = f(k) - f(k-1)。

[1,2,1,2,3]，k=2：f(2)=12，f(1)=5，答案 12-5=7。暴数一遍确实 7 个。

f(k) 里最常写错的是计数：ans += r - l + 1 写成 ans++（每个 r 只算一个子数组），随机数据 77.62% 算错。这行计数是「以 r 结尾、从 l 到 r 的每一段都合法」的浓缩。

n=1e6、k=100 的随机数据 3.88ms。

三、题 7：至少有 K 个重复字符的最长子串（LeetCode 395）

找最长子串，要求里面每种字符都至少出现 k 次。难在「每字符至少 k 次」不是窗口的单调量：窗口扩大可能让一个新字符进来（它的次数从 0 开始，拖后腿），也可能让已有字符凑够 k。窗口大小跟「合法」之间没有单调关系，l 不能随便右移。

课程做法：枚举窗口最多含 require 种字符，require 从 1 到 26。固定 require 后「种类 ≤ require」就是单调约束，窗口收缩有依据；同时用两个计数器 collect（窗口内种类数）和 satisfy（次数 ≥ k 的种类数），satisfy == require 时窗口合法，更新答案。

为什么 26 轮能接受：每轮窗口 l、r 各走 ≤ n 步，总 O(26n)，常数固定。不枚举 require、直接一个窗口跑，随机数据 9.90% 算错，因为「种类数」本身没有单调性，窗口根本不知道什么时候该缩。

n=1e6、k=3 的随机小写串，26 轮枚举 42ms。

四、复杂度与实测

题 4 每个元素进窗口一次，O(n)；题 6 两次 f() 调用各 O(n)，O(n)；题 7 O(26n)。空间都是 O(字符集) 或 O(值域)。

五、代码

题 4 环上窗口：

int CanCompleteCircuit(vector<int>& gas, vector<int>& cost) {
        int n = (int)gas.size();
        for (int l = 0, r = 0, sum = 0; l < n; l = r + 1, r = l) {
            sum = 0;
            while (sum + gas[r % n] - cost[r % n] >= 0) {
                if (r - l + 1 == n) return l;
                sum += gas[r % n] - cost[r % n];
                r++;
            }
        }
        return -1;
    }

题 6 两个单调函数相减：

int NumsOfMostKinds(vector<int>& arr, int k) {
        int n = (int)arr.size();
        vector<int> cnts(n + 2, 0);
        int ans = 0;
        for (int l = 0, r = 0, collect = 0; r < n; r++) {
            if (++cnts[arr[r]] == 1) collect++;
            while (collect > k) {
                if (--cnts[arr[l++]] == 0) collect--;
            }
            ans += r - l + 1;
        }
        return ans;
    }

    int SubarraysWithKDistinct(vector<int>& arr, int k) {
        return NumsOfMostKinds(arr, k) - NumsOfMostKinds(arr, k - 1);
    }

题 7 枚举 require：

int LongestSubstring(const string& str, int k) {
        int n = (int)str.size();
        int ans = 0;
        for (int require = 1; require <= 26; require++) {
            vector<int> cnts(256, 0);
            for (int l = 0, r = 0, collect = 0, satisfy = 0; r < n; r++) {
                cnts[(unsigned char)str[r]]++;
                if (cnts[(unsigned char)str[r]] == 1) collect++;
                if (cnts[(unsigned char)str[r]] == k) satisfy++;
                while (collect > require) {
                    if (cnts[(unsigned char)str[l]] == 1) collect--;
                    if (cnts[(unsigned char)str[l]] == k) satisfy--;
                    cnts[(unsigned char)str[l++]]--;
                }
                if (satisfy == require) {
                    ans = max(ans, r - l + 1);
                }
            }
        }
        return ans;
    }

总结

三题各示范一种「窗口不够用」的解法：环用 r % n 展开成 2n；恰好 k 拆成两个至多 k 相减；每字符至少 k 次先枚举种类数让窗口重新获得单调性。判据没变，还是「l 能不能只进不退」。

滑动窗口维护「窗口内最值」的那类题（比如滑动窗口最大值）需要双端队列，那是【必备】单调队列那一讲的内容。
