线段树：取反与整段染色

一段灯整段取反之后，亮着的盏数从 k 变成段长减 k，一个和就够了。可「这一段有几种颜色」一个计数装不住，直到发现颜色最多 30 种：那它正好塞得进一个 32 位整数，父范围就是两个儿子按位或。

零、背景

线段树的懒更新只有一条要求：整段做完一个操作之后，节点上存的量还能从旧值推出来。区间加之所以好写，是因为和的变化就是加数乘段长，一眼能写出新值。

换个操作，这条要求就不一定还成立。取反和刷色是两个形状完全不同的例子：取反时「一段上亮着几盏灯」这个和本身就能直接改；刷色时要回答「这段上有几种颜色」，一个计数根本装不住。

两道题分别对应懒标记的两个极端：一个是自己撞自己就抵消的操作，一个是后一次把前一次完全盖掉的操作。

一、两道题

  • 开关（洛谷 P3870）：n 盏灯排成一排，初始全灭。操作 0 l r 把 [l, r] 上的灯状态取反，操作 1 l r 查 [l, r] 上有几盏亮着。n、m 到 10⁵。
  • 色板游戏（洛谷 P1558）：L 个色板，初始都是 1 号颜色，一共 T 种颜色，T 不超过 30。操作 C A B c 把 A 到 B 刷成 c 号色，操作 P A B 查 A 到 B 上有几种颜色。L 和操作次数到 10⁵。数据里 A 可能大于 B，读到先交换。

二、取反：一段的和自己够用

设一段长 n、原来亮着 k 盏。整段取反之后亮的变灭、灭的变亮，亮着的盏数正好是 n 减 k。所以节点上只要存这一段的和，整段取反就是把和改写成 n 减 k。

剩下的是标记怎么写。一段被取反两次等于什么都没做，这个性质让标记只需要一个 bool：rev[i] 表示这个范围还欠一次整体取反。下传时把标记转给两个儿子、自己清掉；再来一次取反就把那个 bool 翻回来，两次撞上自然抵消。

#include <bits/stdc++.h>
    using namespace std;

    const int MAXN = 100001;

    // light[i]：i 号范围上有几盏灯亮着
    // rev[i]：这个范围整体要不要取反
    int light[MAXN << 2];
    bool rev[MAXN << 2];

    void up(int i) {
        light[i] = light[i << 1] + light[i << 1 | 1];
    }

    // 整段取反：亮的变灭、灭的变亮，长度为 n
    void lazy(int i, int n) {
        light[i] = n - light[i];
        rev[i] = !rev[i];
    }

    void down(int i, int ln, int rn) {
        if (rev[i]) {
            lazy(i << 1, ln);
            lazy(i << 1 | 1, rn);
            rev[i] = false;
        }
    }

注意 lazy 里只做两件事：把和改成 n 减 k，把标记翻一下。「整段」是说这里不用真的走到儿子那里，儿子的值可以继续是旧的，欠的这一次记在标记里。

void reverse(int jobl, int jobr, int l, int r, int i) {
        if (jobl <= l && r <= jobr) {
            lazy(i, r - l + 1);
        } else {
            int mid = (l + r) >> 1;
            down(i, mid - l + 1, r - mid);
            if (jobl <= mid) {
                reverse(jobl, jobr, l, mid, i << 1);
            }
            if (jobr > mid) {
                reverse(jobl, jobr, mid + 1, r, i << 1 | 1);
            }
            up(i);
        }
    }

    int query(int jobl, int jobr, int l, int r, int i) {
        if (jobl <= l && r <= jobr) {
            return light[i];
        }
        int mid = (l + r) >> 1;
        down(i, mid - l + 1, r - mid);
        int ans = 0;
        if (jobl <= mid) {
            ans += query(jobl, jobr, l, mid, i << 1);
        }
        if (jobr > mid) {
            ans += query(jobl, jobr, mid + 1, r, i << 1 | 1);
        }
        return ans;
    }

查询照常往下走，但只要当前节点有 rev，必须先 down：子节点里存的和是欠着一次取反的旧值，直接读出来就错了。反过来，一整个 [l, r] 正好盖住某个节点时连 down 都不用做，所以每次都是整段操作时会比随机区间快一大截。

实测：n = m = 16000、每次操作盖住大半段，逐格翻转的暴力 90.32 ms，线段树 8.98 ms。n = m = 10⁵ 时线段树 26.98 ms；如果每次都是 [1, n] 整段，只要 9.60 ms。

三、颜色：一个整数装下 30 种

「这段上有几种颜色」为什么不能用计数？因为父范围的种类数不是两个儿子的种类数相加，两边可能撞上同一种颜色，相加就会重复计数。

但题面给了一个很窄的条件：颜色最多 30 种。那就别存种类数，直接存「这段上出现过哪些颜色」：一个 32 位整数，第 c 位是 1 表示 c 号色在这段里出现过。这样一来父范围就是两个儿子按位或，撞上的颜色自动只算一次。

整段刷成 c 号色之后，这段上只剩一种颜色，状况直接变成 1 << c，跟原来是什么颜色没关系。这正是懒标记最便宜的样子：标记不用累积，后一次刷色直接把前一次盖掉。

const int MAXN = 100001;

    // color[i]：i 号范围上的颜色状况，c 号颜色占第 c 位
    // change[i] 和 update[i]：这个范围被整体刷成了哪一号颜色
    int color[MAXN << 2];
    int change[MAXN << 2];
    bool update[MAXN << 2];

    void up(int i) {
        color[i] = color[i << 1] | color[i << 1 | 1];
    }

    void lazy(int i, int v) {
        color[i] = 1 << v;
        change[i] = v;
        update[i] = true;
    }

    void down(int i) {
        if (update[i]) {
            lazy(i << 1, change[i]);
            lazy(i << 1 | 1, change[i]);
            update[i] = false;
        }
    }

    // 一开始所有色板都是 1 号颜色，也就是 0...0010
    void build(int l, int r, int i) {
        if (l < r) {
            int mid = (l + r) >> 1;
            build(l, mid, i << 1);
            build(mid + 1, r, i << 1 | 1);
        }
        color[i] = 2;
        change[i] = 0;
        update[i] = false;
    }

查询拿回来的是状况，题目要的是种类数，所以要数这个整数里有几个 1。

void updateColor(int jobl, int jobr, int jobv, int l, int r, int i) {
        if (jobl <= l && r <= jobr) {
            lazy(i, jobv);
        } else {
            down(i);
            int mid = (l + r) >> 1;
            if (jobl <= mid) {
                updateColor(jobl, jobr, jobv, l, mid, i << 1);
            }
            if (jobr > mid) {
                updateColor(jobl, jobr, jobv, mid + 1, r, i << 1 | 1);
            }
            up(i);
        }
    }

    // 拿到的是状况，问的是颜色种数，所以要数二进制里有几个 1
    int queryStatus(int jobl, int jobr, int l, int r, int i) {
        if (jobl <= l && r <= jobr) {
            return color[i];
        }
        down(i);
        int mid = (l + r) >> 1;
        int status = 0;
        if (jobl <= mid) {
            status |= queryStatus(jobl, jobr, l, mid, i << 1);
        }
        if (jobr > mid) {
            status |= queryStatus(jobl, jobr, mid + 1, r, i << 1 | 1);
        }
        return status;
    }

    int cntOnes(int n) {
        n = (n & 0x55555555) + ((n >> 1) & 0x55555555);
        n = (n & 0x33333333) + ((n >> 2) & 0x33333333);
        n = (n & 0x0f0f0f0f) + ((n >> 4) & 0x0f0f0f0f);
        n = (n & 0x00ff00ff) + ((n >> 8) & 0x00ff00ff);
        n = (n & 0x0000ffff) + ((n >> 16) & 0x0000ffff);
        return n;
    }

这里有个细节：颜色从 1 号开始编号，状况写成 1 << c 的话第 0 位永远是空的，初始的全 1 号色是 0…0010 也就是 2。这不影响答案，但第一次读代码容易以为自己数错了位。

实测：n = m = 16000、T = 30、每次操作盖住大半段，逐格刷色的暴力 143.25 ms，线段树 3.65 ms。n = m = 10⁵ 时 27.33 ms。

演示：掩码合并与颜色种数

演示里只用 5 种颜色（编号 1 到 5），所以树里节点的二进制数写成 6 位，最右边是第 0 位、一直是 0。查询范围里的节点按位或起来，再数几个 1。

四、两种懒标记的形状

两道题把懒标记的两个极端都占了。

取反是自逆的操作：做两次回到原样。所以标记一个 bool 就够，下传完自己清掉，累积起来也只有「奇数次」和「偶数次」两种情况。

刷色是幂等的操作：刷成 c 之后再刷成 d，前一次完全没有意义。所以标记存的是「最后刷成哪一号色」，不需要相加，也不怕累积。

判据是同一个：整段做一个操作之后，节点上的量能不能从旧值 O(1) 算出来。取反能（段长减小），刷色也能（掩码直接换掉），剩下的就是套路。

顺手量一下数 1 的两种写法：10⁷ 次对同一个 30 位掩码求 1 的个数，五次折半的 SWAR 写法 6.36 ms，逐位循环 28.91 ms，差 4.5 倍。查询本身是 O(log n)，这 5 次位运算是常数，但写在最热的那条路上，差别还是能看见。

两题都按 n = 10⁵ 开四倍空间。开关那边和用 int 就够，一段最多 10⁵ 盏灯全亮；色板那边状况是 32 位整数，也是 int。具体是开关 1.53 MiB 加 0.38 MiB，色板 1.53 加 1.53 加 0.38 MiB，都很轻。

color 和 change 为什么各要一份？color 是答案用的状况，change 是标记要下传的颜色号。也可以只留 change，下传时用 1 << change[i] 现算，那样省一个数组、多一次移位。

每档 4000 组随机操作，四档的 n 分别是 4、8、16、64，操作次数 6 到 14 之间。表里的数字是「错版答案与正解不一样」的比例。

取反的两条都随 n 变大更容易被抓到。n 越大，一次操作覆盖的位置越多，「少下传一次」漏掉的量也越大，错起来就越明显。

色板上推只取左儿子这条方向是反的：n 越大反而越难抓。因为 n 大时区间相对很窄，一次查询碰到的节点少，左右两边颜色不同的机会也就小了。

色板「查询不 down」比开关那条更松，也是掩码的性质：颜色状况是做或，丢掉一位不一定改变 1 的个数，那个颜色可能已经被别的段带进来了。取反不一样，丢掉一次就是实打实的数错了。

七、总结

两道题都在做同一件事：给「整段操作之后这一段变成什么样」找一种能直接写出来的存法。取反的存法是和，因为亮灯数就是段长减原值；刷色的存法是掩码，因为父范围的颜色集合就是两个儿子的并集。

懒标记的形状跟着操作的性质走。自逆的操作（取反）用 bool，连做两次抵消；幂等的操作（刷色）用「最后刷成的值」，后一次覆盖前一次。选哪种不用猜，看这个操作连续做两次会怎样。

掩码的位宽是题目给的：颜色不超过 30 种，所以 32 位整数刚好装下。要是颜色上限变成 10⁵，这套写法立刻不成立，得换成别的能合并集合的结构。

最后

两个实现上的坑。一是取反的标记要写成 rev[i] = !rev[i]；写成 rev[i] = true 会变成「一取就永远取」，两次取反不再抵消，只在从没出现重叠的输入上碰巧对。二是色板那题数据里 A 可能大于 B，读进来先交换，不然区间查询会拿着左大右小的范围往下走。
