单词搜索 II：一棵 Trie 找全部单词

3 万个单词，每个都全盘搜一遍二维网格，谁也顶不住。把所有单词插进一棵 Trie，一次 DFS 同时找全部，搜完的子树直接扔掉，实测 12×12 网格、3 万词不到 20 毫秒。

零、背景

网格 board 最大 12×12，单词列表最多 3×10^4 个，每个单词最长 10 个字符。找所有能在网格里拼出来的单词，格子不能重复用。

朴素做法：每个单词单独做一次 DFS。一个词最坏 144 个起点、每个起点四方向走到 10 层，约 10^8 次访问；3 万个词就是 4.5×10^12 次访问。这个量级不用测也知道跑不完。

但单词只有 26 个小写字母。3 万个词的前缀大量重叠，「apple」和「apply」共享前五个字符。把前缀共享掉，一次遍历就能同时照顾 3 万个词。

一、把 words 插成一棵树

26 路前缀树，和 044 的静态数组实现一样，唯一的变化：词尾节点不记 end 计数，直接存整个单词字符串，DFS 走到词尾时取出来就是答案。

共享的效果很直观：3 万词、每词 10 字符，全不同前缀最多 30 万节点；实测（12×12 网格、3 万随机词）插完只有约 4.9 万节点。

静态池要按总字符数开够。实测把 MAXN 开成 10001，3 万词一插就数组越界段错误。别拿「看起来够」当容量，words 总字符数 3×10^5，池子按这个量级开。

二、DFS 走网格

每个格子当起点，dfs(board, i, j, t=1, ans) 往四个方向走。每走一步做三件事：沿网格字符在 Trie 里前进一步；发现子树没有要找的词就返回；走到词尾就收词。

关键细节一个一个说。

第一步先剪枝：t = tree[t][board[i][j]-'a']，如果 pass[t]==0，说明从「这个前缀」往后没有任何要找的词，直接返回。这一步把大量起点挡在门外：起点字符在树里连路都没有，一次递归都不用进。

收词要防重复：同一个单词可能从不同起点、不同路径找到多次，endStr[t] 收完就置空，后找到的不会再收第二次。

格子标记是回溯的骨架：board[i][j] = 0 占住，四个方向递归，回来恢复原字符。不占住，同一个格子会在一条路径里被走两次，违反「不允许被重复使用」。

// words 总字符数上限 3e5，池子开够（实测开 1e4 会越界）
    static const int MAXN = 3000001;
    static int tree[MAXN][26], pass[MAXN], cnt;
    static string endStr[MAXN];   // 走到这个节点的单词，没有就是空串

    void build(vector<string>& words) {
        cnt = 1;
        for (string w : words) {
            int cur = 1;
            pass[cur]++;
            for (int i = 0, p; i < w.size(); i++) {
                p = w[i] - 'a';
                if (tree[cur][p] == 0) {
                    tree[cur][p] = ++cnt;
                }
                cur = tree[cur][p];
                pass[cur]++;
            }
            endStr[cur] = w;      // 词尾节点记住整个单词
        }
    }

    // 从 (i,j) 出发，当前走到 Trie 节点 t，收集到的词放 ans
    int dfs(vector<vector<char>>& board, int i, int j, int t, vector<string>& ans) {
        if (i < 0 || i == board.size() || j < 0 || j == board[0].size() || board[i][j] == 0) {
            return 0;             // 越界或回头路
        }
        char tmp = board[i][j];
        t = tree[t][tmp - 'a'];   // 沿 board 字符在 Trie 里走一步
        if (pass[t] == 0) {
            return 0;             // 这棵子树没有要找的词，剪掉
        }
        int fix = 0;
        if (!endStr[t].empty()) { // 走到词尾，收集，并且只收一次
            fix++;
            ans.push_back(endStr[t]);
            endStr[t].clear();
        }
        board[i][j] = 0;          // 占住这个格子，四方向不许回头
        fix += dfs(board, i - 1, j, t, ans);
        fix += dfs(board, i + 1, j, t, ans);
        fix += dfs(board, i, j - 1, t, ans);
        fix += dfs(board, i, j + 1, t, ans);
        pass[t] -= fix;           // 收走的词从 pass 里减掉，下次不进这棵子树
        board[i][j] = tmp;        // 恢复
        return fix;
    }

主流程对每个格子调一次 dfs。整棵树的 pass 在 build 时已经全部数好，DFS 只是沿着网格字符在树上走，边走边剪。

三、pass -= fix：搜完的子树扔掉

还有一个容易被忽略的剪枝：dfs 返回时把收走的词数 fix 从 pass 里减掉。

看代码最后几行：pass[t] -= fix。含义是「这棵子树里还没找到的词，已经减掉了 fix 个」。等 fix 把 pass 减到 0，以后再有任何路径走到这个节点，第一步的 pass[t]==0 直接返回。

为什么需要它：同一个子树可能被多个起点搜到。第一次搜完把所有词都收走了，第二次再来就是纯浪费时间。pass 减到 0 让第二次连子树都不进。

这是把 Trie 从「静态索引」变成「动态收缩」：不只是查询快，是查完的部分直接消失。

四、复杂度与实测

最坏时间复杂度还是 O(m×n×4^10)，前缀树没改变这个上界，它做的是剪枝和压常数。空间 O(words 总字符数)。

实测（本机 g++ -O2，12×12 网格）：

三字母密集网格、3 万随机词：Trie+DFS 19.8ms，找到 22054 个词。六字母稀疏网格：4.2ms，只找到 240 个。字母越杂，能拼出来的词越少，剪枝越狠。

再看访问量：Trie 整场搜索访问了约 195 万个格子；朴素逐词搜索的最坏访问量是 4.5×10^12，差了 230 万倍。差距主要来自两处：前缀共享（一次 DFS 管 3 万词）和 pass 剪枝（没词的子树、搜完的子树都不进）。

复杂度分析

做法时间空间
朴素逐词 DFSO(words × m×n×4^10)O(词长)
Trie + DFSO(m×n×4^10)，剪枝压常数O(words 总字符数)

时间上界没变，但常数被砍掉几个数量级：pass 剪枝挡掉无路起点，pass-=fix 让查完的子树消失。

总结

把 3 万个词并成一棵树，一次 DFS 全找，是「共享前缀」这个思想最直白的应用。

三个剪枝缺一不可：pass==0 挡无路起点，end 置空防重复收词，pass-=fix 让搜完的子树下次直接跳过。

静态数组池按总字符数开够，这是 044 和这讲共同的教训。前缀树三讲收尾，下一讲换前缀和：把子数组和变成两个前缀和的差。下节课的题目里见。
