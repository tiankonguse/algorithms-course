数位 dp：在每一位上展开

问「1 到 n 里有几个数满足某个性质」，n 可以有几千万位。数位 dp 的摆法是把每个数都当成和 n 一样长的串（不足的高位补前导 0），从高位往低位一位一位决定。状态里最要紧的一个量叫 free，它只有两位：前缀是不是已经比 n 小了。

零、先把数摆成定长的串

朴素想法是枚举 1 到 n 逐个判断。n 到 10⁹ 就已经跑不动了，而这类题的 n 常常是长度 20 以上的数字串，连存进 64 位整数都不够。

换个摆法：把上界 100 看成三个格子，每一位填 0 到 9。所有「位数不超过 3 的数」都对应一个三位的串，缺的高位补 0。于是候选集合就是 000 到 100 这一千个串。

补前导 0 有个直接后果：042 和 42 是同一个数，而 000 对应 0。所以真正写的时候得区分「这一位是数的一部分」还是「还没开始填」，这个区分就是下面两个状态中的 fix。

从高位往低位走，每一位上的处境只有两种：前面决定的位和 n 完全一样，所以这一位不能超过 n 的对应位；或者前面已经有一位比 n 小了，那后面随便填都不会超过 n。这就是 free。

还要留意一件事：候选数字集合是升序的，所以枚举到第一个超过 cur 的数字就可以停，后面的只会更大。

一、先看一题的极端：闭式就算完了

「统计各位数字都不同的数字个数」里，n 表示最多几位，问 0 到 10ⁿ−1 里每一位都不同的数有几个。

这题的上界永远是 10ⁿ−1，也就是 n 个 9，free 从来没有翻过身，所以不需要状态。一位一位数：1 位数 0 到 9 共 10 个；k 位数首位不能是 0，有 9 种，第二位起每放一个数字就少一个候选，第 j 位是 10 − j 种。k 位数一共 9·9·8·…·(10−k+1) 个。

// 统计 0 到 10^n - 1 中「每一位都不同」的数字个数
    int countNumbersWithUniqueDigits(int n) {
        if (n == 0) return 1;                    // 只有 0 自己
        int ans = 10;                            // 1 位数：0 到 9，一共 10 个
        // 2 位：9 * 9，3 位：9 * 9 * 8，4 位：9 * 9 * 8 * 7 …
        for (int s = 9, i = 9, k = 2; k <= n; i--, k++) {
            s *= i;
            ans += s;
        }
        return ans;
    }

代入几个 n：n=0 只有 0 自己，答案 1；n=1 是 10；n=2 是 91；n=3 是 739；n=8 是 2345851。注意乘积的衰减很快，10 − j 在 j 到 11 时会变成 0，所以 n 超过 10 之后答案不再变。

这里有个常见的写错：首位也按 10 种算，等于允许前导 0。n=2 会多算 9 个，n=3 多 81 个，n=8 多出 260649 个，而 n=1 两边一样（一位数本来就允许 0 开头，0 是合法的）。

二、骨架：一个 free 就够

「最大为 N 的数字组合」里 digits 给了一组数字，用它们拼出的、不超过 num 的正整数有几个。这时候上界是具体的数，free 就派上用场了。

递归写成 f(num, offset, len, free, fix)：还有 len 位没决定，free == 1 表示前面已经比 num 小了，fix == 1 表示前面已经选过数字。返回的是「剩下这些位填完，能凑出多少种合法的数」。

每一层的选择分三块。第一块是「这一位先不选」，只有在 fix == 0 时才允许，走掉之后整条链相当于在数一个比 num 短的数。第二块是 free == 0 时枚举 digits：比 cur 小的走完就自由了，等于 cur 的还得继续贴着 num。第三块是 free == 1：每一位都有 m 种选择，而且这些选择彼此独立，所以只递归一次再乘 m。

// digits：允许使用的数字，升序、无重复、不含 0；num 是上界
    // free == 1 表示前缀已经比 num 小，后面随便选；fix == 1 表示已经选过数字
    int f(vector<int>& digits, int num, int offset, int len, int free, int fix) {
        if (len == 0) return fix == 1 ? 1 : 0;   // 一位都没选过的空前缀不算数
        int ans = 0;
        int cur = (num / offset) % 10;           // num 当前这一位
        if (fix == 0) {
            ans += f(digits, num, offset / 10, len - 1, 1, 0);   // 这一位不选，数就比 num 短
        }
        if (free == 0) {
            for (int d : digits) {
                if (d < cur) ans += f(digits, num, offset / 10, len - 1, 1, 1);
                else if (d == cur) ans += f(digits, num, offset / 10, len - 1, 0, 1);
                else break;                      // digits 升序，后面只会更大
            }
        } else {
            ans += (int)digits.size() * f(digits, num, offset / 10, len - 1, 1, 1);
        }
        return ans;
    }

最后一处乘法是整个写法的关键。free == 1 时如果照抄上面那样写 for (int d : digits) 再逐个递归，m 个分支的返回值完全相同，只是白跑 m 次。写成乘法之后，递归树的宽度只剩 1，代价从 m^len 掉回 len·m。

实测调用次数：num = 999999999（9 位）固定，digits 大小从 1 加到 8，调用次数从 55 涨到 118，每个数字稳定加 9；给满 1 到 9 时是 415。

三、另一种写法：把自由的部分先乘出来

上面的递归里，「这一位先不选」和 free 之后的那些分支，本质都在算同一件事：前缀已经确定、后面的位随便填，有几种。这个量可以直接算出来。

记 cnt[i] 为「前缀已经定下、且已经比 num 小，还剩 i 位随便选」的填法数，那它就是 m^i：cnt[0] = 1，往后每多一位乘一个 m。位数比 len 短的数全部对应「某一层开始不选数字」，这些数的每一位都自由，正好把 cnt[1] 到 cnt[len−1] 累起来就行。

剩下的只有一条链：前缀和 num 完全相同。链上任何一位上选了比 cur 小的数字，后面 len−1 位就自由了，贡献 cnt[len−1]；选了等于 cur 的就继续往下走。走到链尾算上 num 自己。

// cnt[i]：前缀已经确定、且已经比 num 小，余下 i 位随便选，有几种填法
    // cnt[0] = 1，cnt[1] = m，cnt[2] = m * m …
    vector<int> cnt(len, 0);
    cnt[0] = 1;
    int ans = 0;
    for (int i = m, k = 1; k < len; k++, i *= m) {
        cnt[k] = i;
        ans += i;                                // 位数比 len 短的部分先全部收进来
    }
    ans += f(num, offset, len);                  // 再补上位数正好是 len 的

    // 只剩「前缀和 num 完全相同」这一条链；链上任何一位选小，余下 len - 1 位就是 cnt[len - 1] 种
    int f(int num, int offset, int len) {
        if (len == 0) return 1;                  // num 自己
        int cur = (num / offset) % 10, ans = 0;
        for (int d : digits) {
            if (d < cur) ans += cnt[len - 1];
            else if (d == cur) ans += f(num, offset / 10, len - 1);
            else break;
        }
        return ans;
    }

两种写法复杂度一样，都是 O(len·m)。差别在代码形状：递归版把 free 和 fix 两维都摆出来，遇到新约束时往上加维度更顺手；组合版把能算的部分提前算掉，主循环只剩一条链，读起来短。

四、写错的地方

随机 2 万组小数据（digits 大小 1 到 4，num 不超过 3000）实测的抓取率：

写法与正确解不一致的比例为什么会错
枚举到 d > cur 时忘了 break88.26%把「这一位比 num 大」的数字也算进了答案
组合版里短位数只累加到 len−2 位99.72%所有 1 位数被漏掉，只有 num < 10 才看不出来
自由分支只递归一次、忘了乘 m75.08%每一位少算 m−1 种，位数越多差得越远
终点不判 fix，一律返回 1100.00%把「一位都没填」的空串也当成一个数

「忘了 break」这条在 digits 只给一个数字时也会错，因为那个数字一旦大于 cur，本来应当整条链返回 0，忘掉 break 就把它算成了 cnt[len−1]。

七、复杂度分析

写法时间空间说明
枚举 1 到 nO(n·len)O(1)每个数都要拆一遍位
递归版数位 dpO(len·m)O(len)free、fix 各两态，链上一共 len 层
组合表版O(len·m)O(len)cnt 表 len 项，主循环一条链

空间都是 O(len)，因为递归深度只有位数这么多，cnt 表也只有位数项。真正把规模撑开的是 n 的位数：len 到 20 也只是二十几层。

八、总结

数位 dp 的要点就三条。

一是把数补成定长串，从高位往低位决定，每一位的处境由 free 标记：前缀已经小了就随便填，还贴着上界就只能填到 cur。

二是补前导 0 之后要分清「空串」和「数的一部分」，这靠 fix 或者「终点判一下有没有选过数字」解决，漏掉就会把 0 多算一次。

三是数字集合升序时，第一个超过 cur 的数字之后就没有合法选择了，忘掉这个 break 是这题最常见的错。

最后一个量可以省掉一层递归：前缀自由以后的位数，每种填法彼此独立，直接乘 m 的幂。这个习惯在后面的题里还会反复出现，那时要乘的换成了一张提前算好的表。
