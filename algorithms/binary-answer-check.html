二分答案的判定函数：溢出与双指针

二分骨架上一讲讲完了，真正费脑子的全在 f 函数。这一讲看两个 f：一个模拟能量时藏着指数增长，不剪枝整数直接溢出；一个数数对时不能两两枚举，得靠双指针。

零、背景

上一讲的两个 f 都是「一遍扫过去算个数」，直来直去。真实题目的 f 往往要扛住两件事：模拟过程会不会爆掉，计数能不能在 O(n) 内做完。

「机器人跳跃问题」的 f 是全程模拟，能量递推式 2E - H 会指数增长，处理不好连整数范围都出不来。「找出第 K 小的数对距离」的 f 是数数对，最笨的写法是 n² 枚举，n 到 10⁴ 就崩。

一、机器人跳跃问题

机器人从第 0 栋楼出发，第 0 栋高度 0。依次跳到第 1..n 栋楼，跳到第 i 栋后根据当前能量 E 和新楼高度 H(i) 结算：若 E < H(i)，失去 H(i) - E 能量；若 E ≥ H(i)，得到 E - H(i) 能量。能量任何时刻不能为负，问最小的初始能量能完成全程。

两个分支分别算：H > E 时 E - (H - E) = 2E - H；H ≤ E 时 E + (E - H) = 2E - H。化简完是同一个式子 E' = 2E - H。这个合并是这一讲第一个坑：如果不化简，写两个分支还容易把符号写反；化简后一眼看清能量怎么变。

f(E) 的模拟：从 E 起步，每栋楼执行 E = 2E - H(i)，中间出现负数就失败。问题出在能量会指数翻倍：E 接近 maxH 时，2E - H 一步就翻倍，很快超出 int。实测全 1 高度、初始能量 2，第 31 步 E 溢出成 -2147483647，被判失败；可真实流程能量全程为正，早该判通关。

解法是剪枝：E ≥ maxH 时直接返回 true。E ≥ maxH 后，下一栋楼高度 ≤ maxH，E' = 2E - H ≥ 2maxH - maxH = maxH，能量只会保持在 maxH 以上，不可能跌回负值。所以「超过最高建筑」是一个充分条件，提前返回不影响正确性，还把指数增长拦在门外。

演示 1 · 机器人二分逐帧：二分初始能量，f 模拟跳跃，能量 ≥ maxH 立即剪枝通关

    vector<int> arr;                             // 建筑高度，arr[0] = 0
    int n;

    // 初始能量 energy，能不能通关
    bool f(int energy, int maxH) {
        for (int i = 1; i <= n; i++) {
            energy = 2 * energy - arr[i];
            if (energy >= maxH) {                // 超过最高建筑，后面必然通关
                return true;
            }
            if (energy < 0) {
                return false;
            }
        }
        return true;
    }

    // 二分初始能量，范围 [0, maxH]
    int compute(int l, int r, int maxH) {
        int m, ans = -1;
        while (l <= r) {
            m = l + ((r - l) >> 1);
            if (f(m, maxH)) {
                ans = m;
                r = m - 1;
            } else {
                l = m + 1;
            }
        }
        return ans;
    }

单调性：初始能量越大越容易通关，答案是最小达标值，二分范围 [0, maxH]。复杂度 O(n log maxH)，n 是建筑数，maxH 是最高楼。没有剪枝时 f 的模拟可能在几轮内溢出，所以剪枝是正确性的一部分，不只是优化。

二、找出第 K 小的数对距离

nums 里任意两个下标 i < j 的距离 |nums[i] - nums[j]|，一共 C(n, 2) 个距离，求排序后第 k 小的那个。n ≤ 10⁴，两两枚举 5×10⁷ 对勉强能算一次，但二分里每轮都枚举就彻底不行。

先把数组排序。排序后问「差 ≤ limit 的数对有几对」，就变成每个位置 l 右侧有多少个数跟它差不超过 limit。这个计数用双指针一趟做完：r 从 l 出发一路右移，直到 arr[r+1] - arr[l] > limit，则 l 与 (l, r] 上每个位置都构成一对，对数加 r - l。

r 的关键性质是不回退：l 右移一位后，arr[l+1] 变大了，跟它差 ≤ limit 的右边界只会更靠右，所以 r 从上一轮的位置继续走就行。l 和 r 各走一遍，O(n)。

f(limit) 单调不减：limit 越大，能配上的对越多。答案 = 第一个使 f(limit) ≥ k 的 limit。以 [1, 3, 1] 为例，排序后 [1, 1, 3]，三个距离是 0、2、2：k = 1 答案是 0，k = 3 答案是 2。再看 [1, 6, 1]，排序后 [1, 1, 6]，距离 0、5、5，k = 3 答案是 5。

演示 2 · 数对计数逐帧：排序后固定 limit，双指针扫一遍统计差 ≤ limit 的对数

    // 排序后，差 <= limit 的数对有几对
    int f(vector<int>& arr, int limit) {
        int ans = 0;
        for (int l = 0, r = 0; l < (int)arr.size(); l++) {
            while (r + 1 < (int)arr.size() && arr[r + 1] - arr[l] <= limit) {
                r++;                             // r 一路不回退
            }
            ans += r - l;                        // l 和 (l, r] 上每个位置都配对
        }
        return ans;
    }

    // 二分距离，范围 [0, max - min]
    int smallestDistancePair(vector<int>& nums, int k) {
        int n = nums.size();
        sort(nums.begin(), nums.end());
        int ans = 0;
        for (int l = 0, r = nums[n - 1] - nums[0]; l <= r;) {
            int m = l + ((r - l) >> 1);
            if (f(nums, m) >= k) {               // 差 <= m 的对数够 k 个，达标
                ans = m;
                r = m - 1;
            } else {
                l = m + 1;
            }
        }
        return ans;
    }

复杂度 O(n log n + n log range)：排序 O(n log n)，二分范围 [0, max - min] 每轮计数 O(n)。range 最大 10⁶ 也就 20 轮。

三、复杂度分析

题目时间复杂度额外空间f 的形态
机器人跳跃问题O(n log maxH)O(1)全程模拟 + 指数剪枝
找出第 K 小的数对距离O(n log n + n log range)O(1)排序 + 双指针计数

两个 f 各留一个教训：模拟型的 f 先看增长会不会爆炸，该剪枝就剪；计数型的 f 先想有没有办法把 n² 降下来，排序常常是第一步。

四、总结

机器人跳跃把两分支化简成 E' = 2E - H 一个式子，能量指数增长，E ≥ maxH 就剪枝，剪枝是必需的一步：没有它，模拟会在几轮内溢出成负数。

第 K 小数对距离把「差 ≤ limit 的对数」做成排序 + 双指针一趟计数，r 不回退是 O(n) 的关键，答案是最小 limit 使对数 ≥ k。

f 函数还可以更狠：有的题 f 内部要贪心分析，靠直觉想清楚「一块电池怎么分配、每个回合选哪个动作」。下一讲三个题全是这种。
