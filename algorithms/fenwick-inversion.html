逆序对与升序三元组：值域树状数组

值域树状数组把「下标」换成「值的排名」，一次前缀查询就能回答「已经扫过的部分里，有多少个数比你小」。逆序对和升序三元组，用的都是这同一句话。

零、背景

数组长度 5 × 10⁵，每个值在 1 到 10⁹ 之间，问有多少个逆序对。值有 10⁹ 种可能，可数组里只有 5 × 10⁵ 个数。

按值开一个计数数组是行不通的，10⁹ 个 int 是 4 GB。真正用到的值不超过 n 个，先把它们压成 1 到 n 的排名，问题就变成了「在排名上做单点加、范围查」，正是树状数组的标准用法。

这一节讲两道题：逆序对数量、升序三元组数量。它们是同一个技巧的两层。

一、问题

如果 i < j 且 arr[i] > arr[j]，那么 (i, j) 就是一个逆序对。下面这组数据有 5 个。

arr = [3, 1, 4, 1, 5]

逐个位置数过去：位置 1 的 3 右边比它小的有两个 1；位置 3 的 4 右边比它小的有一个 1；剩下的位置右边没有更小的。一共 2 + 0 + 1 + 0 + 0 = 3 个，分别是 (1, 2)、(1, 4)、(3, 4)。

所以答案关心的其实是每个位置右边的情况，这一点决定了后面怎么扫。

二、归并分治：一次合并里数跨左右的

把数组对半切，逆序对分成三类：都在左边、都在右边、一个在左一个在右。前两类递归去算，第三类在这次合并里数。

左右两段各自已经有序，于是可以用两个指针一趟扫完。i 从右往左走左段，j 从右往左走右段，只要 arr[i] ≤ arr[j] 就把 j 往左挪，挪不动时 j 右边全是比 arr[i] 小的，一共 j − m 个。

数完之后顺手把两段并成一段有序的，这个排序动作是免费的，它保证上层合并时左右仍是有序的。整个递归就是归并排序，时间是 O(n log n)。

// 归并分治：1) 统计 l~r 范围内的逆序对 2) 统计完让 arr[l..r] 变有序
    long long Merge(int l, int m, int r) {
    	long long ans = 0;
    	for (int i = m, j = r; i >= l; i--) {
    		while (j >= m + 1 && arr[i] <= arr[j]) {
    			j--;
    		}
    		ans += j - m;
    	}
    	int i = l, a = l, b = m + 1;
    	while (a <= m && b <= r) {
    		help[i++] = arr[a] <= arr[b] ? arr[a++] : arr[b++];
    	}
    	while (a <= m) {
    		help[i++] = arr[a++];
    	}
    	while (b <= r) {
    		help[i++] = arr[b++];
    	}
    	for (i = l; i <= r; i++) {
    		arr[i] = help[i];
    	}
    	return ans;
    }

    long long F(int l, int r) {
    	if (l == r) {
    		return 0;
    	}
    	int m = (l + r) / 2;
    	return F(l, m) + F(m + 1, r) + Merge(l, m, r);
    }

三、值域树状数组：查右边有几个比我小

换个问法。从右往左扫，扫到 arr[i] 时，它右边出现过的数都已经记在树状数组里了。要数右边有多少个比它小，就是查排名 1 到 rk − 1 的词频之和。

先把大值压成排名。下面这组数据里有重复值，去重之后 m = 4。

排名的求法是二分。注意判断条件写的是 sorted[mid] >= v，取的是第一个不小于 v 的位置，因为它要找最左的下标。

// 给定原始值 v，返回排名值（排序去重后 1~m 中的下标）
    int Rank(int v) {
    	int l = 1, r = m, mid, ans = 0;
    	while (l <= r) {
    		mid = (l + r) / 2;
    		if (sorted[mid] >= v) {
    			ans = mid;
    			r = mid - 1;
    		} else {
    			l = mid + 1;
    		}
    	}
    	return ans;
    }
int Lowbit(int i) {
    	return i & -i;
    }

    void Add(int i, int v) {
    	while (i <= m) {
    		tree[i] += v;
    		i += Lowbit(i);
    	}
    }

    // 1~i 范围的累加和
    long long Sum(int i) {
    	long long ans = 0;
    	while (i > 0) {
    		ans += tree[i];
    		i -= Lowbit(i);
    	}
    	return ans;
    }

主过程只有五行：从右往左，先查再插。

// 值域树状数组：离散化之后从右往左扫
    long long Compute() {
    	sort(sorted.begin() + 1, sorted.end());
    	m = 1;
    	for (int i = 2; i <= n; i++) {
    		if (sorted[m] != sorted[i]) {
    			sorted[++m] = sorted[i];
    		}
    	}
    	long long ans = 0;
    	for (int i = n; i >= 1; i--) {
    		int rk = Rank(arr[i]);
    		// 右边有多少个数是严格小于 arr[i] 的
    		ans += Sum(rk - 1);
    		// 增加当前数字的词频
    		Add(rk, 1);
    	}
    	return ans;
    }

这里有个细节容易写错。查询写的是 Sum(rk − 1)，不是 Sum(rk)。逆序对要求严格大于，跟自己相等的那些数不算。写成 Sum(rk) 会把相等的对也算进去，答案偏大。

这个错有多隐蔽，取决于数据里有没有重复值。随机 3000 组数据实测：值域 3 时 93.80% 的用例答案就错了，值域 10 时 87.40%，值域 50 时 72.17%，值域 1000 时 13.03%，值域到 10⁶ 时是 0.00%。数据一大、重复值绝迹，错版反而测不出来。

四、两种做法怎么选

时间复杂度都是 O(n log n)，差别在常数、空间和「能不能中途停下来问一句」。

项目归并分治值域树状数组
时间O(n log n)O(n log n)，前面多一次排序
额外数组help 一份sorted、tree 两份
n = 5 × 10⁵ 实测73.56 ms76.61 ms（离散化 23.06 + 扫描 53.55）
中途查询做不到每个位置都能查

实测里树状数组的扫描部分（53.55 ms）其实比归并分治（73.56 ms）快，是离散化那一次排序把它拖慢的。空间上，n = 5 × 10⁵ 时归并分治要 arr 加 help 两份 int，约 4 MB；树状数组要 arr、sorted、tree 三份，约 6 MB。

真正的选择依据在最后一行。归并分治是离线的批量过程，只有全部跑完才有答案。树状数组每扫一个位置就能查出「到当前为止的情况」，后面两道题都要靠这个性质。

五、升序三元组：同一个技巧多垫一层

如果 i < j < k 且 arr[i] < arr[j] < arr[k]，那么 (i, j, k) 是一个升序三元组。要数的是三个位置，扫一遍显然不够。

可以一层一层垫。扫到位置 i 时，维护两个量：以值 v 结尾的升序一元组有几个（就是词频），以值 v 结尾的升序二元组有几个。那么以值 v 结尾的三元组个数，就是「结尾值小于 v 的二元组个数」。

void Add(vector<long long>& tr, int i, long long v) {
    	while (i <= m) {
    		tr[i] += v;
    		i += Lowbit(i);
    	}
    }

    long long Sum(const vector<long long>& tr, int i) {
    	long long ans = 0;
    	while (i > 0) {
    		ans += tr[i];
    		i -= Lowbit(i);
    	}
    	return ans;
    }

    // 时间复杂度 O(n * logn)
    long long Compute() {
    	// 离散化部分和逆序对完全一致，这里省略
    	long long ans = 0;
    	for (int i = 1; i <= n; i++) {
    		int rk = Rank(arr[i]);
    		// 查询以当前值做结尾的升序三元组数量
    		ans += Sum(tree2, rk - 1);
    		// 更新以当前值做结尾的升序一元组数量
    		Add(tree1, rk, 1);
    		// 更新以当前值做结尾的升序二元组数量
    		Add(tree2, rk, Sum(tree1, rk - 1));
    	}
    	return ans;
    }

顺序这件事值得再强调一次。补二元组时查的是 tree1 的前缀，如果 tree1 里还没有当前这个 x，那么造出来的二元组是 (前面某个位置, 当前位置)，合法。如果先把 x 加进 tree1，查出来的前缀里就包含了 x 自己，造出的是 (当前位置, 当前位置)，同一个位置用了两次。随机 3000 组实测，值域 10 时 94.20% 的用例答案会偏大。

另外，n = 3 × 10⁴ 时三元组最多有 C(n, 3) ≈ 4.5 × 10¹² 个，ans 必须用 long long，两棵树存的也是 long long。

复杂度分析

两道题都是一次离散化加一遍扫描。

项目时间空间
离散化（排序 + 去重）O(n log n)O(n)
每个位置的排名O(log n)—
逆序对：单点加 + 前缀查O(log n)O(n) 树 + O(n) sorted
逆序对合计O(n log n)O(n)
升序三元组：每个位置 3 次树操作O(log n)两棵 O(n) 树
升序三元组合计O(n log n)O(n)

归并分治版本的空间是递归栈 O(log n) 加 help 数组 O(n)，不用离散化，也就不需要 sorted。n = 5 × 10⁵ 时递归深度约 19 层，栈不是问题。

总结

这一节的核心是「树状数组的下标可以是值的排名」。离散化把 10⁹ 的值域压成 n 个下标，扫描顺序选从右往左，于是每个位置的答案就是一次前缀和。

归并分治和值域树状数组时间同阶、常数接近，分界点在需不需要在线查询。后面的题都要求「扫到某处就问一句」，那就只能选树状数组。升序三元组是把同一个前缀查询垫了三层，一层管一元组、一层管二元组、答案管三元组，三条语句的先后顺序决定了当前元素会不会被算两遍。

再往后，把「一元组 / 二元组」换成「个数 / 长度和」之类的其它信息，这套分层还能继续扩展。
