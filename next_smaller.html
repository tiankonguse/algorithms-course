下一个更小元素

给一个数组，求每个位置 i 右侧第一个小于 nums[i] 的位置——用单调栈从右向左一遍扫完。

一、从一个问题说起

给定一个长度为 n 的数组 nums，对每个位置 i，要找它右侧第一个小于 nums[i] 的位置 j；如果不存在，就记 -1。

例如下面这个数组（沿用「分块」一节里的同一个例子，便于对比）：

nums = [3, 1, 4, 1, 5, 9, 2, 6]

一个一个看：

  • 位置 0，值 3：右侧第一个 < 3 的是位置 1（值 1），答案 1。
  • 位置 1，值 1：右侧没有任何 < 1，答案 -1。
  • 位置 2，值 4：右侧第一个 < 4 的是位置 3（值 1），答案 3。
  • 位置 3，值 1：右侧没有任何 < 1，答案 -1。
  • 位置 4，值 5：右侧第一个 < 5 的是位置 6（值 2），答案 6。
  • 位置 5，值 9：右侧第一个 < 9 的是位置 6（值 2），答案 6。
  • 位置 6，值 2：右侧第一个 < 2 不存在，答案 -1。
  • 位置 7，值 6：右侧没有元素，答案 -1。

我们关心的是：对所有位置同时给出答案，总共要多久？

二、先试试最朴素的做法

对每个位置 i，都从 i+1 一路向右扫，直到找到比 nums[i] 小的数：

for (int i = 0; i < n; i++) {
    ans[i] = -1;
    for (int j = i + 1; j < n; j++) {
        if (nums[j] < nums[i]) {
            ans[i] = j;
            break;
        }
    }
}

单次查询最坏要走完 n 个元素；总共有 n 个位置要做这件事，所以总耗时是 n × n = O(n²)。

问题在哪？ 朴素做法反复扫描「i 右侧那段」，每次都从零开始——明明之前算过的信息没有留下来，每次都得重新走一遍。

三、换个思路：边走边记「等待答案」的下标

既然每次都要看「i 右侧的第一个更小元素」，那能不能从右往左走，一路上把「还没找到更小元素的下标」维护起来？

关键观察 1：如果我们从右往左处理，已经处理过的位置 j > i 都已经知道自己的答案了。

关键观察 2：对于 j > i，如果 nums[j] 已经 ≥ nums[i]，那 j 永远不可能成为 i 的答案——j 自己「右侧」的第一个更小元素一定也满足 < nums[i]，而且比 j 更近。

于是我们用一个单调栈维护：

  • 栈里只放「还没找到比自己更小的数」的下标。
  • 从栈底到栈顶，对应的值是严格递增的——因为任何更大的元素都不可能被「更小元素」所选。

处理 i 时：

  1. 把栈顶所有 ≥ nums[i] 的下标弹出（它们不可能成为 i 的答案）。
  2. 此时栈顶（如果存在）就是 nums[i] 右侧第一个更小的位置，记为 ans[i]。
  3. 把 i 压入栈中。

把滑条一路拖到最左（i = 0），你会看到整个数组的答案都填出来了，栈里只留下那些「右侧从未出现过更小元素」的下标：

五、复杂度分析

逐个操作看：

  • 入栈：每个位置 i 处理时都会执行一次，共 n 次。
  • 出栈：每个位置至多被弹出一次（弹出后再也不会回到栈里）。
  • 比较：每次比较只在「栈顶」和「当前 nums[i]」之间发生，是 O(1)。

因此整个过程是每个元素最多进栈一次、出栈一次，总耗时严格线性：

操作时间复杂度
遍历 i（从 n-1 到 0）O(n)
所有入栈 / 出栈合计O(n)
整体O(n)

空间方面，栈里最多同时存 n 个下标，再加一个长度 n 的答案数组，额外空间 O(n)。

对比朴素做法的 O(n²)，单调栈把这类「右侧第一个满足条件」的查询从平方降到了线性，是一类非常常用的套路。

六、完整代码

#include <bits/stdc++.h>
using namespace std;

// 示例：与上文同一数组
int nums[] = {3, 1, 4, 1, 5, 9, 2, 6};
int n = sizeof(nums) / sizeof(nums[0]);
int ans[100];                  // 答案：ans[i] = 右侧第一个 < nums[i] 的下标，没有则 -1

void next_smaller() {
    vector<int> st;            // 单调栈，存下标；对应的 nums[st[...]] 严格递增
    for (int i = n - 1; i >= 0; i--) {
        // 1. 弹出栈顶所有 >= nums[i] 的下标（它们不可能成为 i 的答案）
        while (!st.empty() && nums[st.back()] >= nums[i])
            st.pop_back();

        // 2. 此时栈顶（如果存在）就是 i 右侧第一个更小的位置
        ans[i] = st.empty() ? -1 : st.back();

        // 3. 把 i 入栈，留给左侧的位置用
        st.push_back(i);
    }
}

int main() {
    next_smaller();
    for (int i = 0; i < n; i++)
        cout << "ans[" << i << "] = " << ans[i] << endl;
    return 0;
}

七、小结

  • 「右侧第一个满足条件」一类问题，常常可以倒着扫，用单调栈把「等待答案」的下标维护起来。
  • 单调栈的单调性（这里是「值严格递增」）是它能保证线性的根本：每个元素只进出栈一次。
  • 把「小于」换成「大于」「小于等于」，把「右侧第一个」换成「左侧第一个」，套路完全一样——只需调整比较符号和遍历方向。
想一想： 如果改成「右侧第一个大于等于 nums[i] 的位置」，单调栈的弹出条件和单调方向会怎么变？
