## §11 对拍（完整版）

### 课程代码 ≠ 题面直觉，先做语义假设检验

实例：BZOJ2870 的代码会把「单点链」算进答案（虚点复制点权、虚边权 0，u 与自己的虚点配成距离 0 的一对），但只有以 1 为根儿子数 ≥ 2 的点才有虚点，所以 `9-1-9` 的链输出 3（漏单点），而 `5 / 9 1 3 1 7 / 1-2 2-3 1-4 3-5` 输出 9（算了单点）。做法：先写一个假设检验脚本跑几百组小型随机用例，确认代码的真实语义（本例 = max(两点链, 儿子数 ≥ 2 的单点)），再按这个语义写暴力；网上题解的写法与课程代码一致（虚点权值 = 原点权、虚边 0、双指针），页面按课程代码呈现，正文用一句「这里有个细节」点出来即可。

### 强制在线的题（CF757G 等）

不能随机喂原始参数对拍：解码依赖上一轮输出，随机值会解出越界下标把程序跑崩，表现成「code 输出空、brute 输出 0」的假 mismatch。正确做法是**交互编码**——以暴力程序为参考实现，逐条喂解码后的操作、读它的输出当 lastAns、再把 `值 ^ lastAns` 写进输入，最后拿完整输入跑被测程序逐行比对。注意暴力程序的输出要用 `endl` 而不是 `"\n"`，否则管道块缓冲读不到（表现为 readline 卡死）。

### 树状数组上界写成 n 的题

171 课题3（P4093 序列）的树状数组按值开、上界直接用 `n`，而题面只保证「值 ≤ 10⁵」。随机数据里出现 `rv > n` 时 `more()` 的 while 一次都不进，写入被静默丢掉，判出来的是 MISMATCH，但代码逻辑没问题（洛谷数据下 AC）。做法：`vals = [rand(1, n)]`，改完 600 组全 OK；页面正文顺手点明「代码里上界用 n，因为本题值域与 n 同阶」。**先怀疑数据，再怀疑代码**。

### 写对拍器先怀疑自己的生成器（162）

- **节点编号的基准要对齐题面**。P1505（国家集训队旅游）节点是 0 到 n−1，课程代码读进来 `x++`；生成器按 1..n 造路径操作，一半的操作落到越界点上，判出随机 MISMATCH。凡题面写「编号 0 到 n−1」都要在生成器里统一 0 基准。
- **算「子树内」的 DFS 不能只用「上一个访问的点」当父亲**。从 u 出发时起点父亲要给成 `par[u]`（u 是根时给 0），否则 u 的真实父节点会被当成儿子扫进来，子树范围变成整棵树。CF1009F 这类题的答案会整片偏大，而代码是对的。
- 这两条的共同点：MISMATCH 是**成片、随机**出现的，且换种子复现率稳定——那是生成器的形状问题，不是代码的边界问题。

### 性能数字要连同 -O0 一起量（031）

编译器会把整段算法识别成硬件指令，只报优化后的数字容易把结论讲反。031 课实测：clang 把 BK 的 `while (n) { n &= n - 1; c++; }` 识别成 popcount，编成 ARM 的 NEON `cnt` 指令（`g++ -S` 能看到 `cnt.16b`），一千万次 0.53ms，比手写 SWAR 五步的 3.16ms 快 6 倍，跟 `__builtin_popcount` 同档；关掉优化后 SWAR 恒 36.59ms、BK 随 1 的个数从 32.15ms 涨到 235.08ms。两档一起量，才能写出「编译期识别」和「执行时间与数据无关」这两句真正有用的话。顺带：想确认某段代码是否被识别成内在函数，`-S` 后 grep 指令名即可（本机 macOS 上 `g++` 就是 clang）。

### 从 SKILL.md §十 移入的对拍细则（2026-10-14）

与上面 §11 完整版互补（那节讲课程代码语义，这节讲对拍器 / 探针 / 演示数据本身）：

- **写对拍器先怀疑自己的生成器**（162 两条都踩）：节点编号基准对齐题面（P1505 是 0 基准，读入 `x++`，生成器按 1..n 会一半操作越界）；算「子树内」的 DFS 起点父亲要显式给 `par[u]`（u 是根给 0），否则真实父节点被当儿子扫进来、答案整片偏大。**MISMATCH 成片、随机、换种子复现率稳定 = 生成器形状问题，不是代码边界问题**。
- **DAG 最长路 / 最长链的暴力参考必须按拓扑序扫**（072 踩：信封、数对链、K 递增三题的暴力都是「枚举前驱取 max + 1」，随手按输入顺序扫会报成片假 MISMATCH，如 `n=7 2 vs 3`、`k=5 -2 vs 0`）。信封按「宽度升序、同宽高度升序」扫，数对链按右端点升序扫，分组题空组先 `if(size==0) return 0`。**看到 MISMATCH 先确认暴力的枚举顺序是不是一个合法拓扑序，再回头改实现**。
- **错法演示的抓取率随值域单调下降，挑小值域才现形**（072 实测：写反等号 V=3 → 86.78%、V=10 → 63.81%、V=50 → 20.30%、V=1000 → 1.10%、V=10⁶ → 0.00%；信封同宽排序、K 递增选哪个 bs 同规律）。演示里的「错误率」档位要覆盖小值域，别只给一组大随机数据——那样错版和正解答案一样，演示看着像没区别。
- **探针报 FAIL 先怀疑探针自己的参考实现**（108 实测连着踩两次）：① 「范围加 + 单点查」的答案就是差分数组的前缀和，探针又对 `a` 求了一次前缀和当期望，末帧永远差一截；② 探针重放随机算子时从 mulberry32 流里取 `v` 的位置与页面不一致，同一组算子被铺成两条不同的序列。**先用一组手算的固定小用例把「页面末帧打印值」和「参考实现的期望值」对齐，再上随机**；随机算子只写一份生成逻辑给两边共用，别各写一份。
- **演示网格要把哨兵行 / 列一并画进来**（108：二维 `tree` 是 0 基准且带第 0 行第 0 列哨兵，渲染 `a` 用 off=0、`tree` 用 off=1，混用整行显示 0；二维差分的 4 个角会落在第 n+1 行 / 列，网格不铺到 n+2 就出现「图上找不到这个更新点」）。行列的 `py(i) = Y0 + i*CS` 别从 `i-1` 起算，否则第一行 y 为负、`getBBox()` 越界。
- **降序 ends 的二分不是换个符号就行**（072：求「以 arr[j] 开头的最长不下降」时 ends 是降序，要找 `< num` 最左，和升序版找 `>=` 最左不是同一段代码改个比较符）。写这类「倒着扫」的预处理时把方向单独立一个函数（如 `bsDesc`），别复用升序版。
- **性能数字要连同 `-O0` 一起量，别只报 `-O2`**（031 实测：clang 把 BK 的 `while(n){n&=n-1;c++;}` 识别成 popcount 编成 NEON `cnt` 指令（`-S` 能看到），一千万次 0.53ms 比手写 SWAR 3.16ms 快 6 倍；关优化后 SWAR 恒 36.59ms、BK 随 1 的个数 32.15~235.08ms）。想确认是否被识别成内在函数：`-S` 后 grep 指令名。
